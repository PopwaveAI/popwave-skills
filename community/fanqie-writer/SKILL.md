# 番茄爆款小说写作助手 · Fanqie Crafter

为番茄小说平台写作者打造的一站式网文创作技能，同时兼顾「长线不穿帮」与「平台数据化」两大目标：

- **长线连续性工程**：内置 `.learnings/` 记忆系统防止百章长篇的角色/地点/伏笔穿帮，卷级章节规划防写偏，断点续写恢复，关键情节 Mermaid 图解，9 维逻辑审查。
- **番茄平台数据化写法**：用 6 问先锁定「爆款基因」（情绪标签直接决定番茄算法分发），2200-2800 字最佳阅读长度，黄金开篇三版锻造，评论区诱导设计，情绪曲线「压-小扬-压-爆」循环，去 AI 味润色，8 维质量评分。

## 何时使用

- 用户要在番茄小说写/连载一部网文（爽文、虐恋、悬疑、言情、脑洞等任意品类）。
- 用户要求分章节创作、长篇小说、追更续写、章节悬念设计。
- 用户希望章节更「番茄味」：开章抓人、情绪过山车、评论区能吵起来、完读率更高。
- 用户需要长线不穿帮：角色不串、伏笔能收、跨卷不断档。

## 何时不使用

- 用户需求并非番茄小说平台（如晋江、起点、公众号、通用小说创作）→ **不要触发本技能**，改用通用写作流程，避免把番茄专属的算法节奏/评论区诱导强加给不适配的平台。
- 用户只是要写单篇短文、文案、非连载故事 → 用通用写作即可，不必启用长篇工程。

## 第一次使用：从这里开始（v1.29.7 新增 · **陌生用户入口**）

> **这一节写给第一次用本技能的人。** 你不需要懂番茄平台的术语，也不需要先做准备。

### 1. 你只要说一句话

**说出你想写什么就行**，例如：

> 「写一部番茄小说，女主穿越到古代当丫鬟，靠一手好厨艺一步步翻身」
> 「我想写个搞笑的，主角穿越自带 BGM，一响所有人都得跟着晃」
> 「帮我看看这本小说的第 1 章写得怎么样」（有稿子时）

技能会自己往下走，**不会拿一张表让你填**。中间需要你决定的地方，它会**先给你一个成稿 ＋ 依据 ＋ 备选**，你只改你想改的那一项。

### 2. 会给你什么（7 件交付物 · **分四批给你，每批都会停下等你**）

**总共 7 件**——但**不会一次全塞给你**。按下面四批来，**每一批交完就停下**，你说了满意才继续：

| 批 | 交什么 | 你做什么 |
|---|---|---|
| **第 1 批** | `00-大纲`（故事本身）＋ `01-人物档案` ＋ `02-情绪曲线` ＋ `03-黄金开篇` | **看完说满不满意**——哪件不对说哪件 |
| **第 2 批** | `04-章节细纲`（每卷编排 ＋ 逐章写什么） | 过一遍全书走向，确认 |
| **第 3 批** | `第01章`（纯正文，让你先看见实物）＋ `05-文体与写作规则`（这本书具体怎么写） | 读第 1 章，说"可以" |
| **之后** | 第 2 章起，一章一章连着写 | 随时叫停／改方向 |

> **为什么分批**：早先的做法是"7 件做齐再一次交付"，结果**第一批就要等几十分钟**（100 章细纲是最重的活，却排在最前面）。现在**先给你能判断的那四件**——不满意当场就能改，不用等到最后一页。

**每一件都是给人看的**（不是给你看不懂的"施工表"）：

| 件 | 是什么 | 你拿它干什么 |
|---|---|---|
| 1 `00-大纲.md` | **故事本身**——讲什么、谁跟谁、为什么争、最后怎样了 | 通读一遍，确认是你要写的故事 |
| 2 `01-人物档案.md` | 每个角色是谁、想要什么、为什么这么选 | 检查人物是不是你想的样子 |
| 3 `02-情绪曲线.md` | 全书的情绪节奏怎么排（哪章压、哪章爆） | 看节奏会不会太平 |
| 4 `03-黄金开篇.md` | 开篇 50 字三个版本 ＋ 为什么选这一个 | 挑一个，或说"换" |
| 5 `04-章节细纲.md` | **每一卷的编排 ＋ 逐章写什么**——可以当分卷剧情梗概通读 | 快速过一遍全书走向 |
| 6 `05-文体与写作规则.md` | 这本书**具体怎么写**（腔调、称谓、禁忌、单章怎么排） | 觉得哪里不对就改这条 |
| 7 `第01章.md` 等 | **纯正文**，2200-2800 字一章 | 直接读，直接发 |

### 3. 三件你需要知道的事

- **它一次只写一章，但会把全书 100 章排好。** 你可以先看第 1 章，满意了再让它往下写。
- **它不会一次问一堆问题。** 如果你觉得它问得太多、或者问的方式像在让你做题，**直接说"你自己定"**。
- **它对你不懂的地方会让你看懂。** 如果哪个词你看不懂，见下方术语表；技能里也禁止出现"只有内行看得懂"的行话。

### 4. 术语表（看不懂的词在这里查）

| 词 | 白话解释 |
|---|---|
| **完读率／追读率** | 平台统计：多少人点进来、多少人读完了这一章。**读完了才有下一章推荐**，所以开篇几章最重要 |
| **情绪标签** | 平台的分类标签（如"虐恋""爽文""沙雕"）。**它决定平台把你的书推给谁**，所以要在开始就定准 |
| **黄金开篇** | 第 1 章开头那几十个字。读者是否留下，基本在这几十字里决定 |
| **爆点** | 让读者**当场愣一下**的东西——当场就懂、但当场解释不了 |
| **爽点** | 读者**想要的某件事发生了**。本书分五种：碾压／信息兑付／认可／关系兑付／整活兑付 |
| **整活兑付** | 不靠"更强"解决问题，而是"另做一件离谱但说得通的事"把局面搅乱。**笑点类金手指走这一类** |
| **情绪曲线** | 一章内的情绪怎么起伏（压 → 小扬 → 压 → 爆），**一直平＝读者划走** |
| **章末钩子** | 每章最后那一句。作用是**让读者点下一章**——只留问题，不给答案 |
| **伏笔** | 前面埋一句、后面回收。**埋了不收＝挖坑不填**，会被读者骂 |
| **金手指** | 主角的特殊能力／外挂。**没有金手指的题材也要写"替代驱动"**（靠什么让人想看下去） |
| **风格档 A–E** | 文风的可选档位（叙述驱动／心理流／短句碎切／对白驱动／长句对白）。**没有哪一档更好，只看适不适合这本书** |
| **承接测试四问** | 逐句自检：有信息吗／接得上吗／指得清吗／对得上吗。**四类通用错误**（病句／碎句／跳／上下文对不上）都由它兜底 |

### 5. 与上游技能的关系

本技能是 **上游 `fanqie-crafter`（@laoxi/fanqiexiaoshuoxiezuo）的补充层**——**只提供上游没有的能力，不重复它已覆盖的基础流程**。
- **上游可独立使用**；**两者也可以配合**（上游打底、本技能补强）。
- 若你已经装了上游，不必卸载。
- 本技能独有的增量见上方 front matter 的 `description`（7 件制交付／写前排定双门禁／五形态与七轴／爆笑反套路设计法／四问判据／S1–S7 与四个脚本）。

> ⚠️ **交付物共 7 件**（`00`～`05` 六份文件 ＋ **各章正文**）——**每一件的读者都是「人」**，**通篇不得出现 AI 内部内容**：立项底稿 / 套路配方 / 自检留痕 / 章节备注 / 写前准备 / 模板话术 / 技能路径（`references/`、`templates/`、`scripts/`）/ 工序话术（"阶段二产出""立项期 1.3.x""写前钉死"）/ 内部编号（"第 5 套"）——**一律不进交付文件**。

**另有四个"操作底稿"文件**（v1.29.0／v1.29.1 起，专门承接原先挂在交付物里的内部内容）：`立项底稿.md`（原大纲附录 A）、`套路配方与爽点分布.md`（原大纲 6.1 节）、`施工细账_卷N.md`（事件单元表 / 回合表 / 位置排布 / 写作状态 / **各章写前准备与章节备注**）、`交付自检留痕.md`（**各份交付物与各章的自检记录**）。**这四个文件是 AI 的核对区，不进用户视野。**

## 工作流总览

```
用户方向（一句话/题材/灵感）
        ↓
 ① 爆款基因确认（6问 / A 路拆书+适配裁决）+ 提示词完善 → 00-大纲.md(作品基因)
        ↓

    （可选深化：三幕升级路径 → 两难×2 → 道德前提 → 反复拉扯——要深挖动机与主题时填）
        ↓
 ③ 人物与节奏落地 → 01-人物档案（14 维度 + 视角故事线 + 详版人物）/ 02-情绪曲线 + 卷级规划
        ↓
 ✋ **交付闸门 1**：交 `00-大纲` ＋ `01-人物档案` ＋ `02-情绪曲线` ＋ `03-黄金开篇` → **停下，等用户表态**
        ↓（用户说满意）
 ④ 逐卷排 `04-章节细纲`（按卷分节 ＋ 卷内逐章八字段，覆盖全书）
        ↓
 ✋ **交付闸门 2**：交 `04-章节细纲` → **停下，等用户确认**
        ↓（用户说确认）
 ⑤ 写 `第01章`（纯正文）＋ 据实物落 `05-文体与写作规则`
        ↓
 ✋ **交付闸门 3**：交 `第01章` ＋ `05` → **停下，等用户说"可以"**
        ↓（用户说可以，继续）

**整活兑付类的两条判据**：
1. 把这一手念一遍，**它必须是一个"做法"**（他做了什么），不是一句"吐槽／抖机灵"；且**当场有人（读者或场上人）的反应是"啊？这也行？"**。旁白写"众人哄笑"＝零兑付——笑点必须由**一个具体的做法**带出来，不由形容词带出来。

### 1.1.5 基因自洽校验（**AI 的内部动作，不产成对用户的提问**）

**第一原则：初始方向不可偏移**（用户 2026-09-20 拍板，二次回归实测提出）。六问的职责是把用户的意图**结构化**，不是重新定义作品。六问答案与初始方向冲突时，**以方向为准回调**——用户明确表达过方向诉求时（如"要爽的、一章一个打脸"），答案中与该诉求相冲的项必须回调，并在校验记录里写明"按方向回调了哪几项、依据是哪句原话"。不得出现"六问答着答着，作品变成另一本书"。
**2026-09-23 补充**：本校验是 **AI 自己的动作**——发现冲突**就地裁决并写进立项记录**，随 1.3.5 一并交用户过目，**不再把冲突清单抛给用户逐条拍板**（旧版把校验做成了"请用户确认"的场景，是"让用户做选择"的又一入口）。

六问是六次独立选择，答案之间可能互相矛盾，也可能与最初的脑洞方向脱节。B 路首跑实测四项全中：初始方向是"温馨小饭馆"，答案却是"爆笑反套路 + 复仇雪恨 + 老实人黑化"——**已经变成另一本书，技能却一路放行到出大纲**。所以收齐答案后必须逐项校验：

| 检查项 | 触发条件 | 处理 |
|--------|----------|------|
| **方向脱节** | 六问结果与初始方向不是同一类作品；或某几项与方向里的明确诉求相冲（方向要"章章打脸"、标签却是喜剧向） | **按方向回调**，在立项记录里给出「原判断 → 回调后 → 依据的方向原话」三列。回调与用户已明说的项冲突时，**以用户明说的为准** |
| **核心设定无落点** | 方向里的关键设定在候选池里没有对应项（实测：`重生/穿越`——题材项没有，反差点项也没有） | **不为它硬塞最接近的项**。保留设定，**自行补全其规则与限制**（重生时间点 / 能否改命 / 代价）并写入 `00-大纲.md`「六问外补充设定」——避免后续章节各写各的 |
| **题材无落点** | 方向指向的题材在题材包里没有对应项（如"科幻未来"） | **不为它硬塞**——塞错会让 1.3.5 自检去对照一个无关的题材包，**整个题材研究层（能力 3）在该包上直接失效**（2026-09-21 实测：年代文方向在旧 8 项里无落点）。三步：① 写进立项记录"该题材技能暂无专属包" ② 就近归入并**写明借了哪个包的哪几条**（如"科幻未来 → 借玄幻修真的境界体系 + 都市现实的开篇雷区"）③ 记录归属决定，写章时按记录的包对照 |
| **调性冲突** | 情绪标签与核心冲突不同向（喜剧向 × 悲情向、悬疑向 × 情感向等） | 按 `references/emotion-curve.md`「情绪标签与核心冲突冲突时」三路裁决，**AI 自行选定一条并写明理由**（先过该文件的动作化判据：「照标签写出来的一章，能不能同时把冲突推进一格？」） |
| **设定与模板不兼容** | 主角设定＝群像戏（本技能模板按单主角设计） | 按 1.2「群像戏处理」，**AI 自选锚点模式并写明理由** |
| **要素内部矛盾** | 反差点与核心冲突不搭（如"表面摆烂实际卷王"×"生死存亡"） | **AI 自行判定**：真矛盾则回改其中一项并说明；若判定是刻意的反差设计（如"摆烂是外壳、卷王是内核"），写明"这是刻意反差"并放行 |

校验结论与 **AI 的裁决**写入 `00-大纲.md`「立项记录」。**有冲突未裁决不得进 1.2**——这条硬约束直接来自首跑实测：跳过校验会把一份自相矛盾的基因带进全书。

### 1.2 提示词自动完善

在 6 问结果基础上，按 `references/prompt-guide.md` 的优先级，把一句话方向补全为完整创作提示词：
- **必须明确**（原措辞"必须补全"，2026-09-21 修正）：主角人设 + **核心能力 / 金手指（含规则与限制）**、等级/力量体系、第一个冲突与爽点、**核心立意**（一句话价值主张，建议 1 主 1 辅）。**2026-09-23 改：核心立意由 AI 直接定稿**（A 路从拆书提炼、B 路从方向推出），随立项稿一并交用户过目——原写"A 路交用户确认、B 路必须补问一次"，是又多开了一个提问口（两份产物结构不对等的问题，改为**两路都必须写出核心立意**来解决）。
  > **为什么是"必须明确"而不是"必须补全"**：纯现实向题材（年代 / 都市生活 / 种田）**没有金手指**，硬填会产出假设定。此时须写**替代驱动**——"无金手指；靠什么推进"（例："靠手艺与生活常识级的经验差，范围限在自家营生内"）。**写"无"也算完成，但不能留空**（与自检第 2 条逻辑一致：明确的无 ≠ 待定）。2026-09-21 年代文样本实测：规则写"必须补全"、模板却没有对应字段，执行者两头落空。
- **应该补全**：世界观规则、配角框架（至少 1 对手 + 1 盟友）、前三章节奏。
- **可以补全**：名场面、中后期走向、语言风格。

    | | └ **⚠️ 本类有两处判据（v1.29.9 校准，防误伤「剧本内容」）**：**① `待定`／`待补` 可能本身就是书里的剧情词**——2026-09-24 实测：真实试跑样本《第九赛季》的核心设定就是"玩家编号后面跟着**待定**两个字"，于是 **6 处命中全部是它、全部误伤**。**判据**＝周围有没有具体指代：**占位残留**是"这一格还没填"（孤零零一个词、无所指）／**剧情词**有指代与语境（"编号后面跟着两个字：待定"）。**只判前者。** **② `裁决` 作为结论性表述可以留**——如 `02-情绪曲线` 的「**调性裁决**：情绪标签与核心冲突**同向**」是**给作者看的判断结论**；要搬走的是"**自洽裁决／立项裁决**"这类**过程记录**。 |

    **执行三步**：① 机器扫（`grep -n -E '<词表>' <文件>`）→ ② **逐条判定"这条是给读者看的还是给 AI 核对的"**——后者**换文件**（`立项底稿.md` / `套路配方与爽点分布.md` / `施工细账_卷N.md` / `交付自检留痕.md`），**不是擦掉** → ③ 改完复跑确认命中数为 0。
    > **为什么单独设一条**：此前每次都是"改被点名的那一份"，而实际场景是 **7 件里每一件都可能被污染**。2026-09-23 古言样本实测：`00/04/05` 清干净后，`01` 有"档案自检"节、`02` 有整节"检查矩阵"＋技能路径、`03` 有"立项期 1.3.4 产出"、`第01章.md` 更是把三段工序内容焊在正文前后。

15. **★两类「写前排定项」都已落表**（v1.29.6 新增 · **把 v1.25.0 的"位置"与 v1.29.5 的"字数"合并成一条**）——**凡"在第 X 处必须出现 Y"或"这一章要有 N 字"的规则，都是"排"出来的，不是"改"出来的**：

    | 类 | 写前必须落成的表 | 落在哪 | 判据 |
    |---|---|---|---|
    | **位置类** | 爆点（前 300 字）／爽点（前 1/3）各写「**第 __ 字前**」＋**本区上限＝本区实际字数 × 1/3（当场算，禁止抄别章的数）** | `00-大纲.md` 第 4.1 区第 1 章 + `.learnings/施工细账_卷N.md` 的「位置排布」 | 成稿后**只做验收**；超标 → **回细纲重排动作序号**，**不回正文挪句子**（会弄断上下句描述关系＝四问第 4 问） |
    | **字数类** | **逐场字数配额表**（目标字／目标段数／建议拍数），由 `scripts/plan_word_quota.py` 算出 | `.learnings/施工细账_卷N.md` 的写前准备·三 | 写完**逐场对账（甲8）**，合格线＝**每场 ±20% 内**；> +50% 独大切场、< −30% 空场补反应 |

    > **为什么合并**：这两条是**同一条纪律**（「排出来的，不是改出来的」），但此前**一条在模板里、一条在 SKILL.md 里**——**没进 SKILL.md 自检清单的规则＝弱规则**（见「判据入表通则」）。合并后**两类一起被强制检查**，不再有"一条强一条弱"的不对称。
    > **⚠️ 漏做的征兆（任一条出现即回查本项）**：① 写完才发现爆点在第 400 字 → ② 章末总字数 2600 但某一整场只写了 60 字 → ③ 出现"这一段要不要往前挪"的讨论（**回细纲，不挪正文**）。

**★ 交付分四批，每批交完必须停下（v1.29.8 新增 · 硬门禁 · 治「首屏等待过久」）**

> **由来**：用户 2026-09-24 实测反馈——**「已经运行了22分钟了，还没运行好」**。根因＝"7 件做齐再一次交付"：最重的 `04-章节细纲`（100 章 / 900+ 行）排在最前面，用户要等到全部做完才看见第一件东西。
> **用户当场给的节拍（照此执行）**：「**首批可以先给 0，1，2，3 产出给用户看满不满意，如果满意的话接下去出细纲，细纲出完，用户满意，再产出第一章和写作规则，用户说可以，继续，这样才开始写正文章节连续了**」

| 批 | 交付物 | 该批必过的自检 | **停下等什么** |
|---|---|---|---|
| **1** | `00-大纲` ＋ `01-人物档案` ＋ `02-情绪曲线` ＋ `03-黄金开篇` | 1／2／4／6／7／8／9／10／11 ＋ **3·14 逐件（本批 4 件）** | **用户说"满意"或指出要改的项** |
| **2** | `04-章节细纲`（按卷分节 ＋ 卷内逐章八字段，覆盖全书） | 13 ＋ **3·14（本批 1 件）** | **用户确认全书走向** |
| **3** | **`第01章.md`（纯正文）** ＋ `05-文体与写作规则` | 15（位置 ＋ 字数）＋ 甲8 逐场对账 ＋ **3·14（本批 2 件）** | **用户说"可以"** |
| **4** | 第 2 章起，一章一章连续写 | 每章 15 ＋ 甲8 ＋ 乙丙丁四层 | 用户随时叫停／改方向 |

**⚠️ 与上游主干的关系（不是改顺序，是改交付时机——防两份真源）**：上游主干写着「节奏蓝图 → 套路配方 → 爽点分布 → **章节细纲** → 悬念线」，**这个顺序不变**（它是对的：先有节奏与配方，才排得出细纲）。变化的是**交付时机**：

- **闸门 1 只交到**：节奏蓝图 ＋ 套路配方与频率 ＋ 爽点分布 ＋ 悬念线 ＋ **大纲第 6 节的卷级规划**；
- **逐章细纲的"排写"与"交付"一起放到闸门 2**。

**不是把细纲删掉，是把它从"首批必须做完"改成"第二批单独做"。** 执行者读到主干里的"章节细纲"时，一律按此理解——**否则又会退化成"一次做齐"**（这正是 22 分钟的成因）。

**三条硬纪律（缺一即违规）**：

1. **不许跳批、不许提前做下一批。** 第 1 批交完就停——**不要顺手把细纲也排了**（那正是首屏 22 分钟的元凶）。同理，第 2 批交完不要顺手写第 1 章。
2. **下一批必须基于用户确认后的版本。** 用户在第 1 批改了 `00-大纲`，第 2 批的细纲就得照**改后的版本**排——**不许把用户改掉的东西又写回来**。
3. **第 3 批的 `05` 是"据实物落规则"**：写第 1 章时用技能基线规则（`references/prose-rules.md` ＋ 本书暂定的风格档），**第 1 章成稿之后再把这本专属的规则固化成 `05`**——**先有实物再定规则，规则手册才不是空谈**（用户指定顺序：「**再产出第一章和写作规则**」）。

**首批加速三条（都在治"等太久"）**：

- **第 1 批不排逐章细纲**——只出大纲第 6 节的**卷级规划**（每卷范围与内容概要）；逐章留给第 2 批。
- **第 1 批只读必需的 `references/`**（题材包 ＋ 套路库 ＋ 情绪模板 ＋ 已定的风格档四类），**不预先通读全部参考文件**。
- **第 1 批的 `.learnings/` 只落 `立项底稿.md`**；`套路配方与爽点分布` 随闸门 2 补、`施工细账_卷N` 与 `交付自检留痕` 随闸门 3 补。

**每批交付的方式**：把该批文件用 `present_files` 推给用户 ＋ 一段**简短的"这批是什么、看哪里"**说明。**这是交稿审阅，不是等用户答题**——用户看完能说"对"、或"这里改成 X"。若用户在审阅时提出方向调整，**回到 1.3 改全书剧情脉络**，不要在人物与章节层打补丁——骨架错了，补丁越多越乱。

### 3.2 写前分析

**0. 本章兑付物定位（v1.17.0 新增，排在开头设计之前）**：查 `04-章节细纲.md` 的**本章条目第 2 项**（本章兑付物），写下本章读者要拿到的那件东西，并回答「它**推翻**了读者此前的哪一个理解」。判据两条：① **推翻 > 补充**（只补新信息不构成兑付）；② **信息兑付类必须说出口**，位置在本章前 2/3，且**必须比上一章的兑付更狠**（同层＝重复）。答不出本章兑付物 → 本章是过渡章里的水章，回大纲层处理。
> **为什么它排在最前**：2026-09-22 实测，前一版 3.2 只查「开头钩子 / 情绪单元 / 单元 / 回合 / 场景 / 钩子」六项，**没有一项问「读者读完拿到什么」**——六项全过、读者手里仍是空的，这正是“感觉没什么看点”的来源。

1. **开头钩子设计**（最关键）：前 20% 必须有即时冲突/反常/危机，参考 `references/chapter-guide.md`（10 种开头技巧）与 `references/golden-opening.md` 避雷针。前 50 字决定书架页点击率。
2. **情绪单元与套路定位（上游主干，须在开头设计之前核对）**：三步——
   ① 查 `00-大纲.md` 的**节奏蓝图**，认本章属于哪个 **3 章情绪单元**、**该单元的「必须完成的功能」是哪几项、本章负责兑现其中哪一项**（一项都对不上＝水章，回大纲层处理）；
   ② 查 **第 6.1 节套路配方表**，定本章用哪条套路、用哪个变体（**连续 3 章未用到配方里任何一条，回大纲层问"这几章到底在做什么"**）；
   ③ 确认本章在「压-小扬-压-爆」单元中的任务（压/小扬/爆预告），单章内至少 3 次情绪变化（见 `references/emotion-curve.md`）。
   > 2026-09-22 补：①② 两项是上游技能本就有、却从未出现在写前工序上的两道检查。**章内写得再好，落在错误的情绪单元位置上仍是水章。**
3. **事件单元规划（最关键，v1.14.0 新增，**排在回合规划之前**）**：照 `04-章节细纲.md` 的**事件单元表**核对本章 **2-4 个单元**——逐个写清"形态（推力 / 探察 / 代价；**言情与关系向题材把"探察"读作"主动试探"**，动作实例见 `references/scene-beats.md` §七）→ 谁想要什么 → 结果 → 结束状态变了哪一项"。**单元数 < 2 ＝ 本章素材撑不起一章**（回大纲层合并章或引进新单元）；**至少 1 个单元必须是主角主动发起的（探察型）**——全章都由他人推动，读者不会追。方法见 `references/scene-beats.md` §七。
   > **回合数 ≠ 事件数**（v1.14.0 实测教训）：第 1 章 v1.13.3 稿回合已从 1-2 涨到 6，用户仍判"**还是一整章节就在讲一件事，很平凡的一件事而已**"——因为 6 个回合全落在"她送表/他拒收"**同一个单元**内。**分不清"多件事"和"一件事的多个回合"，回合制等于没加。**
4. **回合规划（最关键，v1.13.3 新增）**：照 **`.learnings/施工细账_卷N.md` 的「回合表」**（v1.29.0 起；此前在 `04-章节细纲.md`，**该文件已改为"给人看"的八字段，不再承载回合表**）核对本章 **4-6 个回合**——逐个写清"施压方 → 被压方 → 回应 → 局面变化（筹码/信息/关系/物理变了哪项）"。**相邻回合填不出"和上一回合差在哪"＝同层重复**，回大纲层重排（合并章或引进新回合），**不许在正文里靠描写和对话稀释**。方法见 `references/scene-beats.md`。
5. **首章三项硬指标（仅第 1 章，v1.14.0 新增）**：① 前 300 字 **1 个爆点**（矛盾同框／能力现形／代价前置／倒计时）② 前 1/3 **1 个爽点/准爽点**（碾压／信息兑付／认可；**信息兑付类＝必须说出口，看穿了不说＝零爽点**）③ 主角 **≥1 次主动行动**。见 `references/golden-opening.md` 末节。**三项缺一即返工，不得靠加描写弥补。**
6. **场景规划**：本章需 3-5 个场景，至少一个场景具备本情绪标签特征；**前 300 字过 `references/golden-opening.md` 的三问**（状态改变 / 有人要东西 / 阻力此刻在场）。
7. **章末钩子**：从 `references/hook-techniques.md`（10 种钩子）选类型，且与上一章**轮换**。

### 3.3 撰写

先读 `references/my-methodology.md` 注入作者个人写法锚点（骨架未填时跳过，不得代填）。用 `templates/chapter-template.md` 生成章节。

**⭐ v1.22.0 新增 · 动笔前必做（治「碎／跳」的根，缺一不许写正文）**：按模板「写前准备」区先出两个中间产物——
① **动作链**（治「跳」）：逐场戏列关键动作的物理顺序，相邻两步**显式标注四类过渡**（姿态变更／空间位移／取物／时间跳转）；**标不出过渡的地方就是「跳」**，当场补步骤；
② **信息增量表**（治「碎」）：逐场戏列**每一轮**（一次对白来回／一个叙述回合）改变了什么（新事实／立场变化／关系推进／物理变化）；**写不出增量的那一轮就是「碎」**，删掉或换内容。
依据 `references/prose-rules-supplement.md` **S7.1**。**这不是"写后挑错"，是"写前不给它出现的机会"**——用户 2026-09-23 指出的"gemini 3.8 生成的 `ch001` 没有这类问题"，走的正是这个路子。

**两层分工（2026-09-21 用户拍板）**：写什么——情节、冲突、爽点、钩子——**在大纲层已经定死**，写作期只做兑现；怎么写成字——句、段、描写、用词——走**通用文笔规则**，与形态无关。硬约束：

- **场景层 · 按爽点形态兑现**（与 1.1 的「爽点形态」字段联动；只决定"这个场面写成什么样"，不触碰文笔）：**碾压类**＝写成对手被压过的场面（要当众、要有人看见）；**信息兑付类**＝写成"读者比场上人早一步明白"的时刻；**认可类**＝写成**可见的具体得失**（第一笔钱、第一口新锅、有人点名称赞、日子量得出的变化），**严禁套打脸结构**；**关系兑付类**（2026-09-22 新增）＝写成**一次可指认的关系推进动作**（他主动来了一趟、他把那句话说了、他留下来没走、他先松了手），**严禁用旁白宣布关系变化**（"两人的关系近了一层"＝零兑付）。**判断法两条**：把本章的"爽点"念一遍，① 如果它靠的是"有人被羞辱"，而本书是认可类，就是写错了；② 如果它是情绪或氛围而不是动作，而本书是关系兑付类，同样是写错了。
- **文笔层 · 死线级硬约束（v1.13.0 起，用户拍板"必须"）**：每次动笔写正文，**必须**先通读 `references/prose-rules.md`（《通用小说正文写作规则》，文笔层唯一真源），按叙述策略 A1-A12 与规则 1-42 执行；标"死线"的各项任一不过，**直接重写相关段落，不做局部遮掩**。与剧情/形态无关，全题材一致。
  - **另须遵守 `references/prose-rules-supplement.md`《本地附加条款》**（与用户原文**分开存放以免污染原件**；**冲突时以本文件为准**——它是后下达的、优先级更高的要求）。分三批：
    - **格式类（v1.15.0）· S1 正文零破折号**：`——` / `—` / `–` 三种形态**任一出现在正文即不合格**，须逐处**改写句子**（换标点凑数会撞死线 27/28/29）。**规划类文档（大纲／人物档案／细纲／记忆文件）不受此限**。
    - **执行类（v1.18.0）· S3 信息承载／S4 场景具现／S5 碎句配额**：这三条**不是新规则，是原文条款的「可判定实例」**。起因：用户 2026-09-22 以 4 张截图批「信息走对话做成没信息的短句乒乓球，读者根本读不到东西」「一大堆短句，碎句，跳」「场景事件描述不完整，读者无法在脑内具现」「**全是写作规则文档里的违规项**」——原文只有原则（S3↔第 8/12/27/28/41 条；S4↔第 6/7/27/28/30 条；S5↔第 28/29/31 条），**没有可执行动作**，所以每章执行者都自认达标。三条各自的判据、实测反例（取自《停摆》第 2、3 章）与改法见 supplement。**v1.19.0 曾建 S6「五项及格线」，v1.20.0 已废弃并重写为「风格档位 + 通用硬伤」两层**：用户 2026-09-23 交付 7 本异风格长篇并指正「**那个 txt 只是说在言情上的文笔描述不错，但也有专门写对话文的，不能一刀全割掉，这种不同的方式都可以有的；但病句、碎句、跳、上下句描述错误，这种问题是通用不能有的**」。据此——**风格层不设门槛**（对白占比 0–94%／均段长 12–149／短句率 0–45%／碎句链 0–15／短对白链 0–15 都是正例区间，《停摆》逐项落在包络内，统计不可分），**改为写前「选风格档（A–E）」+ 档内一致性检查**；**硬伤层只保留四类通用错误**（病句／碎句／跳／上下句描述错误），判据＝**承接测试四问**（有新信息吗／接得上吗／指得清吗／对得上吗），**须逐句举证，禁止打勾**。同时**全部风格类阈值一并撤销**（v1.19.0 的「均段长 <16 FAIL」「短句率 ≤25%」「碎句链 >12 FAIL」「短对白链 >8 FAIL」——它们会把用户交付的正例《月光盒子》判为不合格）。**v1.21.0：用户二次确认 + 两词定死口径**——用户把自己那一屏「承接测试四问」表**截图发回**并说「**你看下这些就是通用性错误，任何风格类型的正文里面都不允许出现这些**」，据此把四问确认为**任何风格、任何题材都不可协商的通用底线**；并按用户当日原话把两个最难判的词定死：**碎**＝「**句子短且看不出具体是要干什么，看不出行为模式和逻辑**」（**碎 ≠ 句子短**——判据是「意图可见＋逻辑可见」；对照：同为 12 行连续短对白，《停摆》第 3 章算碎、《宠宠欲动》第 137 章不算，因为那是审讯、答一句对方脸色黑一分）；**跳**＝「**一个情节到下一个情节是跳跃的，没有链接**」（这是**动作级缺环**，不是场景级跳跃；用户原例「我躺在床上睁开了眼睛，打湿毛巾把脸好好地擦了一下，终于清醒过来了」缺了**起身／下床／走到水盆边**；唯一判据动作＝**照着做一遍，中间步骤在不在**）。故四问第 1、2 问改写为「**有信息吗？看得出要干什么吗？**」与「**接得上吗？中间那几步在不在？**」。**「碎／跳」经实测不可"正则化"**（试做的「动作链断层」启发式对用户原例能命中，但 8 本正例 2.4 句/千字 vs《停摆》2.4，**同值不可分**，已撤除正则检测器）。**但判定不需要用户来做——见 v1.22.0 三段闭环（S7）**：**① 写前**出「**动作链**＋**信息增量表**」两个中间产物（治根——"跳/碎"写之前就堵住）；**② 写后**由**模型**跑「**四问自检子流程**」，输出举证表、不合格就地改、复跑至全过（治标——判定主体是模型，不是人）；**③ 上线前**做**污染测试**自证（放过认可样本＋拦下人工污染版）。**v1.21.0 写的"只能人工逐句举证"是错的**——用户 2026-09-23 质疑「**就是你改不掉？然后只能让人工给你一条条指出来？**」，并给出反证：交付的 `ch001` 系 gemini 3.8 生成，**不含**此类通用性问题（说明存在生成端可守的形式）。
      - **必做动作 · 遮蔽测试（S3.2）**：遮住本章所有含引号的行，只读剩下的叙述；**读不出「在哪／谁在场／围绕什么物件／局面变了什么」即为不合格**（说明信息全压在对话里）。脚本报告里的「**遮蔽测试待办段**」会列出所有连续 ≥3 行纯对白的位置，逐段遮读，**禁止打勾**。
      - **已机器化（v1.20.0 收窄为「确定性错误」）**：S1 破折号、ASCII 直引号、**标点错配／标点连用／引号不配对／相邻行重复／叠字错误／半截句／行尾无终止标点**、**正文内含拉丁字母**（v1.26.0 新增），以及**跨章对白逐字复现**（≥3 行与上章末相同）由 `scripts/chapter_stats.py` 直接检出。**风格类指标（对白占比／均段长／均句长／短句率／碎句链／短对白链）一律只报数、不判定**——8 本正例证明它们无法区分好坏。**S3.2 遮蔽测试、S3.4 文书留空栏、S4.1–4.3 场景具现、以及硬伤层的「承接测试四问」——由执行本技能的模型逐段核并给依据（执行者是模型，不是用户）。**
      - **对照风格样本库（v1.20.0 重写）**：写前**先按 `references/benchmark-writing.md` 第三节选风格档（A 叙述驱动／B 长句心理流／C 短句碎切／D 对白驱动／E 对话驱动长句）**，写进章节备注；交付前对照第一节「风格区间包络」确认落在所选档内，并检查**邻章跳档是否超一倍**（跳档无场景边界＝读者会觉得"跳"）。**明令禁止**：不得以"句子太短／段太短／对白太多"为由改文。
- **字数 2200-2800**（番茄最佳阅读长度）。**⚠️ v1.29.5 改口径：写前排配额，写后只做验收——不再"低于 2200 再用扩充技巧补"。**
  - **为什么改**：原口径是**写在写完之后**的，实测第一稿稳定差 **18%-35%**——沙雕样本三次重写的第 1 章初稿分别是 **1486 / 1822 / 1475 字**（目标 2200），每次都要 3-5 轮扩写才达标。**根因不是"描写不够"，是"拍数不够"**（详见 `templates/chapter-template.md` 写前准备·三）。
  - **写前必做**：`python scripts/plan_word_quota.py --total 2250 --scenes 6 --avg-para 20.5 --weights 1,1.2,1.3,1,1,0.8` → 输出逐场配额表，**整表贴进 `.learnings/施工细账_卷N.md` 的写前准备**。
  - **两把尺（实测）**：`字数 = 段数 × 均段字数`，均段字数由风格档决定——叙述驱动（A/B）**26.8 字/段**（古言样本 2436 字 ÷ 91 段）／对白驱动（D）**20.5 字/段**（沙雕样本 2217 字 ÷ 108 段）。故 **2200 字需 82-107 段**，**一拍**（施压→回应→局面变化）≈ **65 字 ≈ 3 段**。
  - **补法**：某场差额 > 20% → **回细纲补「场上另外几个人各自的反应」与对白来回**，**不回正文加形容词**（实测：历次扩写补的全是别人的反应，**没有一次是补描写**）。高于 2800 则删无功能元素（**删元素，不删事件**）。
- **去 AI 味**：**写的时候就避开，别等写完再改**——按 `references/revision-methods.md` 第三节四层诊断执行（词汇层黑名单 / 句式层三种高发模式 / 结构层章间防同构 / 情感层别命名情绪）。对话有角色个性与潜台词（见 `references/dialogue-writing.md`）。去 AI 味是**过审底线**不是加分项（番茄官方四类违规之首即"AI 粗制滥造"）。
- **每章必留钩子**，且钩子类型轮换；章末预留「评论区诱导留白」。

> **六步法**（v1.13.2 建四步 → v1.13.3 补第 1、5 步，即本表“结构与文笔双重自查”中文笔层的执行方式）：
> ① **删减测试**（v1.13.3 新增，死线 35/41 的执行动作）——**机械化，不靠判断力**：列出全章"只出现一次"的细节，逐个问四句（推进动作？改变关系？造氛围？已登记伏笔？），四问全否即删且不许补解释；再把余下句子**逐句试着删掉**，问"删了读者会误读或掉信息吗"，不会就删。**"这句需要"是写作者的主观，删减测试不认主观。**
> ② **逐句回读**——每句问“谁对谁做了什么”，靠回读才理清的句子立即标记重写；
> ③ **逐段追动作**——每段填“上一动作的结束状态 → 下一动作的起点”，关键道具在哪、在谁手上不得跳跃；
> ④ **八类高频病句照表查**（见下）；
> ⑤ **专业逻辑核验**（v1.13.3 新增，第 25 条「职业逻辑」的执行动作）——凡出现工序、术语、行业规矩、器物结构的句子，自问"**这门手艺的从业者会这么说吗**"；（实测反例：「放了一个月的表，机芯不会长出新毛病」——停一个月的表油会凝、轴尖会锈，恰恰长新毛病，行内人一句话否掉，师傅的人设就塌了）
> ⑥ **全章朗读**——读不顺的地方就是问题，不辩解。
>
> **八类高频病句**（来源：第 1 章正文实测；规则第 1/18/24/26/27/28/29 条**均已覆盖却仍漏过**）：
> ① **主语悬空**——承前省略跨过插入语后失去主语（“也没有答”）；② **同一信息说两遍**（“我站着就行”＋“她没坐”）；③ **动作与语义冲突**（“收”＝收起 vs“归位”＝放回）；④ **指代无先行词**（“收那半块机芯”，前文无此物）；⑤ **搭配生硬**（“笑得很短”“等不到下文”）；⑥ **道具位置断链**（表在两方手中来回却缺交接动作）；⑦ **时间／年数不自检**（“铺子开张那年他十二岁”与“31 岁”冲突）；⑧ **视角越界**（“她的眼睛在他脸上停了停”——从外部观察自己）。
>
> **规则里全有，却仍会漏——因为“逐条打勾”时人并不会真的逐句读。举证法与删减测试就是为了把"读"和"删"变成动作。** 自检记录须写成“位置／问题类型／原句／修法”四栏表，无问题写“本轮 0 处”，**不得留空**。
> **两条实测教训必须记住**：① 清单式打勾一定失效，必须留证据；② **列清单时要数条数**——v1.13.3 的漏检不是因为规则不存在，而是因为自检表**只列到第 34 条**，42 条里的第六节整节没进表。**每次列死线清单，先 grep 出总数再列**。

## 创作原则与禁忌

### 产出物硬规则（最高优先级｜2026-09-21 用户拍板，2026-09-23 增补「首稿默认」）

- **① 首稿默认：AI 先出稿，用户后改。提问是例外，不是流程。**（2026-09-23 立，**优先级高于本条以下所有条款，以及 1.0 / 1.1 / `adaptation-decision.md` / `remake-workflow.md` 的全部交互规定**）
  收到任何输入（一句话方向 / 素材文档 / 参考原文），**第一个交付物必须是一份完整草案，不是问题清单**。
  - **由 AI 直接定稿**（每项附「**答案 ＋ 一句依据 ＋ 能换成什么／代价是什么**」）：情绪标签 / 题材 / 主角 / 反差点 / 核心冲突 / 爽点形态 / 章节数建议 / 人物设定 / 金手指规则 / 世界观 / 等级体系 / 反派与配角 / 改造方向 / 差异化方案 / 视角结构 / 书名 / 人名 / 地名 / 章名。
  - **用户的位置是审稿人，不是答题人**：改哪项说哪项，**只重推受影响的下游项**，不要求全盘重来。
  - **技能内所有选项库（12 项反差点 / 10 个题材 / 8 项红灯改造 / 四类爽点形态…）是 AI 的候选池，不是用户的答题卡**。呈现给用户的**必须是"这本书的具体方案"**；池内无合适项时，**AI 必须为这本书现造一项**，不得退化成"从池里挑一个最不别扭的"。
  - **唯一可开问的情形**：用户未提供任何方向信息（如只说"帮我写本番茄小说"）。此时**也不弹选项库**，而是**直接给 2-3 个完整故事方案**（每个含题材 / 主角 / 一句话故事 / 为什么在番茄能行），让用户挑一个或说"都不对"。
  - **判据一句话**：**你准备发出的这条消息，如果用户只能回「A / B / C」，它就是错的形式**；正确的形式是用户看完能回「对」或「这里改成 X」。
  - **「自主」≠「随便定」**（与 2026-09-21「规则外动作」教训的关系）：**每项必须给出依据**（用户原话 / 平台数据 / 题材包 / 拆书证据）。**给得出依据的，自己定；给不出依据的，说明它真的需要用户输入——此时才问，且问的时候要带上你已有的判断和卡在哪。** 09-21 批的是"没有依据就代定"，不是"不许代定"。
  - **为什么立这条**：2026-09-21 用户已批过一次"纯粹是给用户做选择、里面根本不够有实质性的东西"，当时只在 ②③ 末端打了补丁、没修根因；2026-09-23 用户再次指出「**要么你还是不要让用户选了，选来选去还是那几个**」，并给出反证——**上游原版技能收到一句话就能直接重构出大纲/人设/世界观，效果不错**。根因是把**本该 AI 干的创作工作**（六问答案、爽点形态、改造方向、书名人名）误当成了**用户的偏好决策**。**同一个病两次发作，本轮按此原则根治。**
- **② 用户的选择是输入，不是产出**。立项阶段的提问只完成"把用户意图结构化"；交付物必须是 AI 基于这些输入**主动写出的实质内容**——全书剧情脉络全文、人物档案全文、章节细纲全文。**用空表或"待用户填"结项＝立项未完成。**
- **禁止残留模板标记**：交付文档中不得出现 `[ ]` / `待定` / `待补` / `待用户填`。唯一例外是 `references/my-methodology.md` 的个人文风锚点（必须作者本人定），且须写明"为什么必须你定"并给出 2-3 个具体候选辅助决策。
- **独立性验收**：把 `00-大纲.md` 单独交给一个没参与过对话的人，他读完能说清"讲什么、谁跟谁、为什么争、最后怎样了"。做不到就回去补，不要进入章节创作。
- **全书剧情脉络先于一切细节**：主线冲突 → 一段式概括 → 五句话脊椎 → 主要情节点骨架 → 分幕脉络总览（三幕/两难/道德前提/拉扯属**可选深化层**）。**骨架没立住之前不写人物细节、不排情绪曲线、不开章**。顺序颠倒必然返工。

### 写作层禁忌

- **强代入感 + 快节奏**：每章有进展，不连续两章以上无爽点/无冲突。
- **情绪过山车**：每 3 章完成一次「压-小扬-压-爆」；章末钩子强度不低于上一章。
- **展示而非讲述、去 AI 味**：这是番茄读者留存的关键。
- **伏笔呼应**：前文埋的线后文要收；长期伏笔 >30 章未回收即预警。
- **反派不蠢**：衬托不出主角强；金手指有规则限制，不开无限制挂。
