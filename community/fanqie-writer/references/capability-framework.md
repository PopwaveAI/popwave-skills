# 能力底座（capability-framework）

> 定位：本技能的能力索引与自检表。回答两个问题——① 这个技能**凭什么**能写出作品（能力从哪来）；② 哪些能力是真有方法、哪些还停在验收清单、哪些是空的。
> 用法：**不必通读**。当你在某个环节发现"我知道该达到什么标准，但不知道怎么达到"时，来这张表查落点资产。立项（阶段一）与每 5 章复盘（阶段三）各通查一次。
> 提出背景：2026-09-21 用户指出「我们现在还大部分都是空骨架」，并提供 11 条写作能力模型。本文件即该模型的落地形态——**不照抄能力形容词，而是逐条给出触发时机、落点资产与诚实标色**。

## 一、三层定义（本技能的诚实标色口径）

| 层 | 标记 | 定义 | 判据 |
|----|------|------|------|
| **L1 有方法** | ✅ | 有可执行的生成/改写步骤，照着能做出来 | 文档里能找到一条"输入 A → 输出 B"的操作链，而不是停在标准描述 |
| **L2 仅清单** | ⚠️ | 只有验收标准，没有生产方法。知道"什么算好"，不知道"怎么做好" | 通读后能判断好坏，但不能凭空产生内容 |
| **L3 空白** | ❌ | 连验收标准都没有，该能力在技能内无落点 | 全技能检索不到对应内容 |

**L2 是本技能最隐蔽的风险**：它让技能看起来完备（有清单可勾），实际产出仍是"按格子填空"。2026-09-21 用户批评"纯粹就是给用户做选择""里面根本不够有实质性的东西"，根因就在 L2——`quality-checklist.md` 能告诉你这段写得不生动，但没法告诉你**怎么写得生动**。

**本轮（v1.8.0-fork.12）的目标：把 ❌ 清零，把关键 ⚠️ 升为 ✅。**

## 三、调用规则（什么阶段读什么）

| 阶段 | 必读的能力文档 | 说明 |
|------|---------------|------|
| 阶段一立项 | `genre-packs.md`（选题材后）→ `market-trends.md`（判断方向）→ `idea-dedup.md`（防雷同自检） | 选题定调三件套。顺序不能反：先知道这个题材要什么，再判断往哪走，最后确认自己的点子是新的 |
| 阶段二落地 | `character-building.md` + `templates/character-template.md` | 能力 4 已有方法，无需额外读 |
| 阶段三写章 | 3.3 前扫 `revision-methods.md` 第三节（写的时候就避开 AI 痕迹，比写完再改省事） | 去 AI 味分两道：写时避免 + 写后修订 |
| 阶段三写后 | `revision-methods.md`（5 节全过）+ `originality-check.md`（交付前自检） | 修订层能力的唯一入口 |
| 每 5 章 | `feedback-loop.md`（归因 + 动作）+ `market-trends.md`（对照及格线）+ `writing-efficiency.md`（产能与习惯） | 数据驱动的三个动作 |
| 中断恢复 | `writing-efficiency.md` 第四节（断点提速清单） | 阶段六提速 |

## 五、对外与对内的分工（用户写作清单的正确用法）

用户 2026-09-21 提供的 11 条能力模型（"扎实的写作基础 / 多样的创意思维 / 深厚的题材研究能力 / 丰富的人物塑造技巧 / 情感化改写技能 / 逻辑优化技能 / 敏锐的市场洞察力 / 专业的编辑和校对能力 / 写作效率优化 / 反馈与迭代 / 版权与原创性检测"）是**能力宣言语体**——面向读者与买家的产品说明，适合放在：

- **上架展示**：技能 description / 平台介绍页的能力说明
- **PRD 的能力覆盖矩阵**：对外说明能力边界与覆盖情况

它**不适合**直接写进 SKILL.md 正文当作执行指令：这类句子（"要具备敏锐的市场洞察力"）不改变模型的输出行为，只占 context。执行层要的是本文件这种"触发时机 + 落点资产 + 现状"的三列结构。

**两条线各归其位，不要互换位置。**
