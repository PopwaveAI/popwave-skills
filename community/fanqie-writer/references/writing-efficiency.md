# 写作效率优化（writing-efficiency）

> 定位：能力 9「写作效率优化」的落点资产。原状态为空白（`.learnings/` 只记录事实，不做习惯分析）。
> **先说清边界**：本文件优化的是**产出效率**，不是"写得更快"——番茄断更一天流量掉档，效率直接等于收益。但**任何提效手段都不得绕过质量项**（尤其 `audit-checklist.md` 的 P0），快而不过审等于白写。
> 用法：立项后定产能计划时；每 5 章复盘时；中断恢复（阶段六）时。

## 一、产能模型（从平台要求倒排，不是拍脑袋）

### 平台的硬要求（依据 `fanqie-platform-facts.md`）

| 项目 | 要求 |
|------|------|
| 普通全勤 | 日更 **4000 字** + 当月听读分成 ≥500 元 |
| 进阶全勤 | 日更 **6000 字** |
| 请假 | 每本书每月 1 天，须后台打卡 |
| 断更代价 | 有案例日更 6000 掉到 4000，收入当月腰斩 |
| 验证期门槛 | 满 **8 万字** + 连续 3 天日更 4000 字+，后台点「作品推荐」 |
| 首秀门槛 | 满 **10 万字** |
| 社区共识 | 开书前备 **30 章**存稿 |

### 倒排表（单章按 2500 字估算）

| 目标档 | 日更字数 | 每日章数 | 30 章存稿字数 | 达成 8 万字（验证期） | 达成 10 万字（首秀） |
|--------|----------|----------|---------------|----------------------|---------------------|
| 普通全勤 | 4000 | **1.6 章/天** | ≈7.5 万字 | 32 章 | 40 章 |
| 进阶全勤 | 6000 | **2.4 章/天** | ≈7.5 万字 | 32 章 | 40 章 |

**结论（写进 `00-大纲.md` 进度看板）**：
- 首次会话后的目标不是"写完第 1 章"，而是**产出 3-5 章**，验证流程与文风是否稳定。
- **首秀前必须攒够 40 章**（10 万字）。攒稿期建议一次会话产 3 章，分多次会话完成，而不是一次产 40 章——长篇一次写太多必然结构漂移。

## 二、写作习惯档案（个性化建议的依据）

### 怎么取（不用问用户，从已有章节算）
```bash
python scripts/chapter_stats.py --all novels/[书名]/
python scripts/check_chapter_wordcount.py --all novels/[书名]/
```
汇总得到四项"笔法指纹"：

| 指标 | 用途 |
|------|------|
| 平均句长 | 判断偏"短句口语"还是"长句铺陈"。写入 `my-methodology.md` 文风承诺时作数据依据 |
| 对话占比 | 判断作品偏"对白推进"还是"叙述推进"。低于及格线时提示扩容对话 |
| 单章场景数 | 判断是否偏"单场景长描"（番茄完读率风险高） |
| 最长段占比 | 识别"文字墙"倾向，超过阈值即提示拆段 |

### 怎么用（生成个性化建议，而非通用建议）
- 对比**用户自己的历史数据**，不对比行业平均值。**"你上 5 章平均句长 23 字，这 3 章变成了 31 字"比"建议句长 20-25 字"有用得多。**
- 每 5 章节奏报告里附一条**个体趋势**（不是通用清单）。
- 用户改写本技能产出最多的地方，就是他真正的偏好所在 → 写进 `my-methodology.md` 的偏好项。

### 习惯档案的存放
- **单本书**：`references/my-methodology.md`（作者个人写法锚点，跨书保留该文件即可）。
- **跨书习惯库**：首版不做（见 `capability-framework.md` 待补清单），等用户跑通第 2 本书再从真实需求设计。

## 三、批量生产流程（一次会话产 3 章的标准作业）

```
① 确认本章区间在故事结构中的位置（查 00-大纲 三幕划分 + 情绪单元）
      ↓
② 一次性列出这 3 章的章节任务（每章：场景数 / 情绪任务 / 钩子类型 / 本章推进什么）
   ← 关键：钩子类型在这一步就轮换排好，避免写完发现连着三章同型
      ↓
③ 逐章撰写（每章独立完成 3.2 写前分析 → 3.3 撰写）
      ↓
④ 批量跑脚本
   python scripts/format_chapter.py novels/[书名]/      # 整个目录
   python scripts/chapter_stats.py --all novels/[书名]/
      ↓
⑤ 逐章人工过 P0（脚本判不了的项）+ 记忆批量更新
      ↓
⑥ 一次会话结束前：更新 00-大纲 进度看板 + 追加 3 条摘要
```

**批量生产的三个纪律**：
1. **一次不超过 5 章**。超过后文风与结构必然漂移，且修改成本高于重写。
2. **③ 阶段每章必须独立过写前分析**。跳过写前分析直接连写＝结构雷同与钩子重复的根源。
3. **④ 的脚本必须批量跑**。`--all` 能一次性暴露"相邻章骨架重复"，逐章跑看不出来。

## 四、中断恢复提速（阶段六的提速版）

长篇必然中断。恢复时按此清单走，比从头读一遍快得多：

| 步骤 | 命令/动作 | 得到什么 |
|------|-----------|----------|
| 1 | `ls novels/[书名]/第*.md \| tail -3` | 最后写了哪几章（**不要用统计章数反推**——`清穿日常` 实测统计 512 章、实际末章 ch514） |
| 2 | 读最新一章 + `00-大纲.md` 进度看板 | 上一章留了什么钩子、下一章要推进什么 |
| 3 | 读 `.learnings/PLOT_POINTS.md` 的"未回收"区 | 哪些伏笔该收了（>30 章未回收即预警） |
| 4 | 读 `.learnings/CHARACTERS.md` | 角色当前状态（等级/位置/生死），防止已死角色复活 |
| 5 | `python scripts/chapter_stats.py --all novels/[书名]/` | 恢复前先看整体一致性，找出风格已偏离的章 |
| 6 | 检查是否有超期未处理的 `ERRORS.md` 条目 | 别把旧问题带进新章 |

## 五、反效率陷阱（提效的反面）

| 陷阱 | 后果 | 规避 |
|------|------|------|
| 为省时间跳过去 AI 味 | 触发平台"AI 粗制滥造"判定，拒签/下架 | P0 红线不可省，见 `audit-checklist.md` |
| 一次会话产 10 章以上 | 结构漂移、钩子重复、文风趋同 | 单次上限 5 章（见第三节纪律 1） |
| 复用上一章的段落骨架 | 平台专查模板化拼接 | 跑 `chapter_stats.py` 的相邻章骨架重复率 |
| 为凑字数注水 | 触发"空洞水文"违规 | 字数不足用 `content-expansion.md` 扩内容，不是拉长句子 |
| 断更攒稿（停更去写存稿） | 流量掉档不可逆 | 攒稿要在开书前完成，或在连载中以稳定节奏完成 |
| 同时开两本书 | 新书抢老书流量 | 同账号不做双开首秀 |
