# 世界知识库 · 循环填库作战清单

> **本文件 = 循环任务的"单一真源"**。每次定时任务触发，先读本清单，从 §六 的执行栈中选出下一个要做的任务目标，完成后回来把状态打勾、更新 `last_updated`，再提交 git。

---

## 一、质量红线（两条都必须在每一件里成立）

| # | 红线 | 落地检查 |
|:-:|:--|:--|
| Q1 | **维基百科级内容质量** | 事实点 ≥5 条独立来源交叉核验；每条带出处(URL/作品/章节)；无源不入库；冲突不压扁 |
| Q2 | **DND 级内容深度** | 一个对象/战役/位面/神祇 = 一整件（单件 8K-12K 字），不是目录式罗列；采样留痕、待核如实标注 |

> 两条红线的标尺文件：质量对标各类百科词条；深度对标 `IP百科/DND`（规则层速查 + 叙事层深度百科的两层结构）。

---

## 二、服务对象与交付目的（为什么要有这座库）

本库唯一目的是：**给 AI 写网文、人类网文写手、小说作者提供「素材 / 设定 / 考据」的取用源**。每个任务产出的成品，都必须能回答写手现场最想问的三类问题：

1. **素材**：这套体系里有哪些能直接 `lift` 的专名（神祇/法宝/位面/势力/物品）？带注释"写手可 lift"。
2. **设定**：世界观怎么运转（规则层）？这个世界怎么讲故事（叙事层/叙事装置）？
3. **考据**：出处是什么？版本怎么打架？能不能忠于原著复制？有没有版权/专名红线？

**消费方式**：写手在写作时按"速查表 → 深读维度件 → 溯源"三级取用；赛道路线包从本库采源蒸馏（配方层/原料层关系）。

---

## 三、方法论：双线范式（所有 IP/神话必须继承）

所有对象在落第一件前，先按 [`references/双线范式.md`](references/双线范式.md) 做三类判定：

| 情形 | 判据 | 策略 |
|:--|:--|:--|
| **原文主导型** | 大众认知≈原文，二创影响小 | 线1为主，线2从轻 |
| **双线并行型** | 原文已稀释，二创叠层统治认知（封神/克苏鲁/漫威/海贼王/战锤） | 双线等重，独立测绘线 |
| **无原典型** | 无单一原典，靠众包/二创累积（基金会） | 线2为主，线1退化 |

**核心纪律**：线2印象不得冒充线1原典；线1压舱不可移除；版本冲突不压扁；每件带来源留痕。

## 四、包标准结构（每个 IP/体系遵循）

按目标归属（IP百科 or 神话体系）套用对应维护规范；通用骨架如下：

```
{IP或体系}/
├── readme.md            ← 包门面：一句话 + 结构表 + 采源留痕 + 版本冲突 + 双线判定(§三结果)
├── material.json        ← 元数据(id/版本/描述/品类/标签)
├── 规则层或对应事实维度   ← 速查：世界观/势力/力量体系/地理/历史/专名
├── 叙事层或印象测绘       ← 深度：这个世界怎么讲故事 / 大众脑里它成了什么
└── 版权指南.md          ← (IP百科) 可lift清单 / PI规避对照 / 专名雷达
```

> 落位：IP 走 `IP百科/`，神话走 `神话体系/`，史实考据走 `历史资料/`。命中双线范式的强 IP 必须额外产出独立的「印象测绘」件（署名线2，与原典件显性分家）。

## 六、执行顺序与流程（定时任务按此跑）

### 6.1 单次触发流程

1. **读本清单**：确认 `last_updated`，从 §五 按下述优先级取**下一个未完成且未进行中**的任务目标。
2. **优先级排序**：★高优先级板块 → 未完成模块数最少的 IP 先做完 → 同模块按任务数从多到少。**优先 A01-A05（你点名的五大 IP）。**
3. **建包骨架**：`readme.md + material.json`，做双线判定 §三，定包结构 §四。
4. **采源**：一手原文/官方设定/权威百科/深度解说转写，全量留痕（对标 DND 22字幕底料）；冲突不压扁。
5. **落件**：一个任务目标 = 一个维度件，Q1/Q2 红线自检通过后才算完成。
6. **更新清单**：该任务目标打 ✅/标记 done，`last_updated` 更新。
7. **提交 git**：`git add` + 有意义的 commit message。
8. **单次收官**：若本次还剩配额，回到 步骤1 继续；否则停。

### 6.2 任务粒度自检（写完一件问三句）

- 这一件等于 DND 叙事层一整件的深度吗（≥8K 字、有采样留痕）？→ Q2
- 专名/事实都有出处且交叉核验了吗？→ Q1
- 属于双线强 IP 却没建「印象测绘」件？→ 不合格，退回。

### 6.3 记账状态

> 任务标题旁标记：`⬜ 未做` / `🔄 进行中` / `✅ 完成`。已完成的附完成日期与 HEAD commit。本清单用 git 版本管理，每次更新即提交。

## 八、循环任务安全阀

- **不得并行开多个任务**：单次触发只推进一个目标（除非单件不足续作）。
- **禁止凭印象补设定**：无两源交叉的条目宁标「待核」不入库（沿用 DND/封神纪律）。
- **版权/专名**：IP百科每件带 `版权指南.md`，专名进正文前过规避清单。
- **破坏性动作需人工**：删除已 ✅ 的文件、改包结构、动 `references/双线范式.md` 前，先暂停循环等确认。
