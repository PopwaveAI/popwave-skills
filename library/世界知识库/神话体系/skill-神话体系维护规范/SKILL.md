# 神话体系维护规范 skill

> **定位**：本 skill 是 `library/世界知识库/神话体系/` 的**建包与维护规范唯一真源**。任何 agent 要在此库加一个神话子体系包、改既有包、补一篇文档、刷新一批件，都先读本 skill，照规格产出、照门禁入库。
> **基准样本**：`中国-道教仙班/` 首包（四维度结构对齐标杆）。
> **对齐标杆**：维基百科中立纪律（中立观点/可查证性/非原创研究）+ 中国神话学术考据的自源标注习惯——颗粒度「一个神系层级 / 一场源流演变 / 一批专名 = 一整件」。

---

## 一、神话子体系包是什么（做什么）

`世界知识库/神话体系/{子体系}/` 下每个文件夹 = **一个来源相对独立、可自洽的神话子体系事实库（带专名）**，供赛道包（配方层·去专名）与世界构筑采源。

**本库定位**：**写什么背景**。与赛道设定集库（怎么写/某赛道怎么写）是**原料↔配方**关系——本库是带专名的事实料，赛道包是去专名的蒸馏配方。

**⚠️ 一个子体系 = 一个包，禁止合并**。中国神话不是单一体系，而是多套来源独立、内部自洽、又互相冲突的子体系（上古神话/道教仙班/封神演义/民间信仰）。合成一个包会把不同出处、不同专名、不同时间层的设定硬缝在一起，下游取用必乱。子体系粒度以「来源可切分、谱系自洽」为准：`中国-上古神话`、`中国-道教仙班`、`中国-封神演义`、`中国-民间信仰`、`北欧神话`、`希腊神话`、`克苏鲁`……各为独立包。

**文档质量立身之本**：来源归位 + 版本分层 + 事实与建议分家。神话本质是「多源层积」的事实——同一神祇在不同源不同讲法，必须标清出处，绝不混编为单一"真相"。

## 二、包标准结构（四维度）

```
{子体系}/
├── readme.md              ← 包门面：四维度总览 + 采源留痕 + 版本冲突总览 + 子层关系
├── material.json          ← 元数据（id/版本/描述/品类/标签）
├── 谱系.md                ← 神祇/异兽/职司/亲缘/阵营关系速查（事实）
├── 源流与版本.md          ← 体系演化史 + 各源异同/冲突对照表 + 采源记录（事实·神话之魂）
├── 专名物件.md            ← 神器/法宝/名号/机构/官职/圣地 清单（事实，可供直接 lift）
└── 叙事装置.md            ← 可从体系提炼的写作母题/机制（编辑建议·与事实分层）
```

**四维分工**：`谱系`回答「谁是神、怎么排位、什么关系」（随查随用）；`源流与版本`回答「这套体系从哪来、怎么演化、各源怎么打架」（深读、版本冲突是神话的核心事实，不可压扁）；`专名物件`回答「作者能直接拎走哪些专名/物件」（连载取用之最）；`叙事装置`回答「从这套体系能提炼什么写作机制」（果报/劫数/飞升/法相……）。

> ⚠️ 采纳本结构而非 IP百科 的「规则层+叙事层」：神话没有游戏规则，硬立规则层=伪规则；且神话多源冲突无法被两层覆盖，需单立「源流与版本」维度。

## 三、SOP 纲要（怎么产出/怎么维护）

| 步骤 | 场景 | 核心动作 |
|:--|:--|:--|
| **1 定子体系** | 新增一个神话包 | 判断来源可切分、谱系自洽、网文复用价值 → 决定是否单立包（过小合并到相邻包） |
| **2 采源** | 收集可信料 | 官方典籍原文/公版原文 > 权威考据(wiki/学术) > 民俗整理；转写/视频仅作草料 |
| **3 撰写** | 填四维度文档 | 谱系=速查体；源流与版本=事实叙事+冲突表；专名物件=清单体；叙事装置=建议体（标编辑建议） |
| **4 入库检查** | 包完成后验收 | frontmatter齐全 + 版本冲突已标 + 无源不入库(关键事实带URL) + 专名雷达 + 事实/建议分层 + 索引同步 |
| **5 刷新** | 既有包升级/补源 | 定版本号 + readme采源留痕更新 + 逐件过门禁 |

## 四、红线（违反=不合格=不入库）

1. **无源不入库红线**：本库是事实库。神名/隶属/职司/源流写错一格，下游赛道包全歪。每件关键事实点带 `sources`（具体 URL 或公版原文卷次）；无法证实的标「编辑判断」。
2. **版本合并红线**：绝不把多源讲法压成单一"真相"。同一对象异源有出入时，必须进 `源流与版本.md` 冲突表分行列出，标各自出处。混编=不合格。
3. **多源/单源判断红线**：财神、灶神、土地等**多源兼祧**对象，跳包处理（民间信仰包），不得并进道教仙班主谱；道教仙班仅收可归因于道教典籍传承/道藏的谱系。
4. **专名雷达红线**：`专名物件.md` 末节必带「专名雷达」——穷举本件 Product Identity 专名（中英对照），供版权档登记规避；缺节=不合格。
5. **事实与建议分层红线**：`叙事装置.md` 与正文的建议性语句必须标注「编辑建议」；谱系/源流/专名文档本体不夹带"XX更好用/这是爽点"类建议。夹带=不合格。
6. **去口语化红线**：本库文档禁第二人称呼告、禁评价腔/煽情/营销词、禁口语叹词、禁"据说/你猜/忘了说"类口语承接（详见 §五）。

## 五、百科体文风纪律（神话专用）

> 对齐标杆：维基百科五大支柱 + 中国神话考据的自源标注习惯。全库统一执行。

### 5.1 层级：四类文风

| 文风 | 用于 |
|:--|:--|
| **速查体** | 谱系.md / 索引页（表格优先） |
| **事实叙事体** | 源流与版本.md（客观递进：演化→关键事件→现状，时间线+因果） |
| **清单体** | 专名物件.md（条目式，每条目带源） |
| **建议体** | 叙事装置.md（明确标「编辑建议」，供作者取用而非设定） |

### 5.2 动词/人称纪律

| ❌ 口语化（回炉示例） | ✅ 百科体（达标示例） |
|:--|:--|
| 「你要知道，姜子牙封神之后…」 | 「据《封神演义》终卷，姜子牙于岐山封神…」 |
| 「太上老君你想不到吧，其实是…」 | 「据道教传承与《老子想尔注》系统化…」 |
| 「三清可牛了，捏泥人都是他」 | 「三清是道教最高尊神…其位阶在道教神系顶端」 |
| 「就是/无非/说白了」式口语承接 | 删除，改为中性表述 |

**五禁**：禁二称（你/我/咱们/玩家/读者）；禁祈使（你应该/请记住）；禁营销腔（必看/天花板/重磅/惊艳、感叹号连用）；禁口语叹词；禁无来源的定性论断（除非标「编辑判断/某源相传」）。

### 5.3 单页组织纲领

```
① 定义段先行：X是……（客观定义，含领域/归属源）
② 正文递进：起源(源)→演化(时间线)→关键义项→现状
③ 涉及多源矛盾时：进版本冲突区，分行标源
④ 落点：对世界观/网文的意义，允许「编辑建议」分区（与事实分家）
⑤ 附录：专名雷达 + 编辑判断与待核 + sources
```

**对照自检清单**（每条入库前自查）：
- [ ] 首段是「X是……」定义句，非「你在…」
- [ ] 全文无第二人称、无口语承接、无感叹号营销腔
- [ ] 关键事实点带 URL 或公版卷次，无源处标「编辑判断」
- [ ] 异源有出入→进冲突表分行，未压扁成单一真相
- [ ] 编辑建议在「编辑建议」分区，未混进事实正文
- [ ] 末节有专名雷达 + 编辑判断与待核备注

## 六、采源三级制与版本冲突处理

1. **官方优先**：公版原文典籍（山海经/封神演义/道德经/道藏等，`source_type: public-domain`）> 权威考据（wiki/学术/道教协会资料，`wiki`）> 民俗整理（`folklore`，须标「编辑判断」）；frontmatter 带 `source_type`。
2. **转写稿/视频仅作草料**：不入库，只作采源；成稿基于公版原文+权威考据核验后重写。
3. **版本冲突处理**：凡同一对象异源有出入，一律收进 `源流与版本.md` 冲突对照表——「对象 | 源A讲法 | 源B讲法 | 结论(采哪源/留白)」，绝不相交混编。
4. **采样留痕**：包 `readme.md` 必带「采样留痕」块——采了哪些源、各采多少、产出哪些件、缺口是什么，一览可审计。
