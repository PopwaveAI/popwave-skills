# 剧情周期表 · 建设计划

定位：把网文叙事的「剧情原子」（事件级功能节点）系统提炼、分类、入库，做成一张像元素周期表一样可检索的库。plot/write 阶段按需挑原子、自由组合成一条条章纲/链，替代旧的「54 张场景节拍卡」。

---

## 一、标准母版（已定标）

`被轻视.md` 是唯一模板。每张原子卡固定四段，**卡内不写溯源**：

```
frontmatter（id + 族 + 4维tag）
→ 一句话功能义（干什么活 + 服务爽点）
→ 功能骨架（N 个功能位，每步 = 干什么 + 合格线，可开分支选择）
```

模板红线（写卡时守）：
1. **单个节点**：卡是一个原子，不是一条锁死的链。
2. **族按功能义切**，不按场景切（旧 54 张的病根）。
3. **功能位必有合格线**，可开分支（如「起伏评判」的 A/B/C/D 四支），防固化。
4. **不写溯源**：来源统一登记，不混进卡里。

## 二、周期表结构

**纵轴「族」= 功能义**（这个原子对主角情绪/爽点做了什么）。**一个族一个子文件夹**。最终 11 族（定版）：

| 功能族 | 干什么活 | 代表原子（示例） |
|:--|:--|:--|
| 蓄压族 | 让主角被看低/被压迫，攒势 | 被轻视、遇圈误判、威胁压顶、被质疑 |
| 施压族 | 危机逼近，逼主角行动 | 倒计时、追杀、围困、压迫 |
| 战斗族 | 冲突白热化，厮杀对决 | 单挑、群战、越级搏命、生死险胜 |
| 突破族 | 成长兑现 | 首突破、升级、得宝、悟道 |
| 兑底族 | 释放主角真实层级 | 亮底、认知碾压、身份揭示 |
| 反击族 | 蓄压释放 | 打脸、反杀、清除威胁、立威 |
| 情感族 | 关系升温、牵动情绪 | 心动、暧昧、情谊救赎、共鸣 |
| 守护族 | 情感压舱 | 守护软肋、亲情暖线、誓约、牺牲 |
| 探索族 | 探查收集、推进未知 | 打探、潜入、搜刮、解谜 |
| 钩子族 | 制造追读 | 章尾悬念、转场承诺、债务埋设 |
| 转场族 | 过渡收束 | 时间推进、收束、场景切换 |

> **横轴「周期」**暂不做成硬维度。现用 frontmatter 的 `位置tag`（开局/中段/高潮/章尾）临时顶替；等族数量够了，第二期再补「蓄压→兑现→释放」的能量谱系横轴。

### 增长与裂变规则（三种增长，老板 2026-08-28 定）

拆书越多，周期表沿三个方向演化，各有各的规则：

| 遇到的新剧情 | 判定 | 动作 |
|:--|:--|:--|
| 功能义变了（对主角爽点干了新活） | 横向 | 裂变成**新原子卡**（无限欢迎） |
| 功能义没变，现有分支盖不住的新节奏/受力点 | 纵向 | 在对应功能位**加一条分支** |
| 功能义没变，现有分支已覆盖 | — | 只登记溯源，血肉进示例，**不加分支** |

**唯一判定标准 = 功能义变没变**（族按功能义切，分支也按功能义下的受力点切，绝不按场景切）。

**裂变看门狗**：单个功能位分支堆到 **8 条**，视为功能义已分叉，纵向裂成两张更细的卡，不再继续塞分支。

## 三、源书池与红线

**红线（红线中的红线）**：每个原子必须从真实小说剧情提炼，禁止自编。

- 提炼一个原子，**至少从 2 本不同书**找到该功能位的异构血肉，才标「通用赛道」；只在 1 本里出现 = 标「赛道专属」，不冒充通用。
- 逐字原文作提炼原料，可回源 txt 查证；但**溯源不进卡**，集中登记。

## 四、入库 SOP（洗一个原子的标准 6 步）

1. 从源书选定一个「事件功能位」（能用 ≤6 字命名、名字自带功能义）。
2. 摘原文、逐字核对（可回源）。
3. 抽功能位：每步 = 干什么 + 合格线；有多态就开分支（如先扬后抑/整体可惜/直接判死/多轮起伏）。
4. 跨书验证：≥2 本异构血肉，确认「通用」或「赛道专属」。
5. 定族 + 打 4 维 tag（功能/爽点/赛道/位置）。
6. 入库到族目录 + 登记索引与溯源。

## 六、索引与检索（agent 怎么用）

`00-周期表索引.md` 是唯一门面，三个反查入口（按功能族 / 按赛道 / 按爽点）。

agent 检索动作固定 4 步：
```
判功能（这章要什么活）→ 筛族 → 按赛道剔错配 → 挑原子 → 自由组合成链
```

## 八、验收自检（每张卡入库前过）

- [ ] frontmatter 四维 tag 齐、族归类正确
- [ ] 一句话功能义清楚（干什么活 + 服务爽点）
- [ ] 功能位每步有「合格线」，多态已开分支
- [ ] 是单个节点，不是锁死链
- [ ] 卡内无溯源；溯源已登记
- [ ] 从 ≥2 本真书提炼（或已标赛道专属）
- [ ] 新剧情先判「功能义变没变」，再决定加卡 / 加分支 / 只登记
- [ ] 分支未超 8 条上限；超了已纵向裂变
