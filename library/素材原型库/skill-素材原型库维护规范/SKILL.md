# 素材原型库维护规范 skill

> **定位**：本 skill 是 `library/素材原型库/` 的**建卡与维护规范唯一真源**。任何 agent 要在此库加一张卡、改一张卡、新建一个子库，都先读本 skill，照规格产出、照门禁入库。
> **基准样本**：`CP模板/`（最成熟子库，四族 20 张、卡结构 v1 已成型），详见其 `00-索引.md`。
> **与全库基线关系**：本 skill 只定义素材原型库的专属约束；单件≤15KB、frontmatter、命名唯一等全库基线与 `library/readme.md` 指针一致，不在此重复。

---

## 一、素材原型库是什么（做什么）

`素材原型库/{子库}/` 下每个 `.md` = 一张**可直接套用的原型卡**，分三类：`人设原型`（人物脸谱）、`CP模板`（人物与关系组装）、`金手指原型`（挂的机制配方）。

**本库与其它库的本质差异——半成品可错配、非单书溯源**：
- 素材来自**全网写作方法整理 + 爆款作品原型提取**，不是单书拆书，**不设单书溯源**（区别于赛道设定集/世界知识库的源书锚点）。
- 一张卡 = 一个可换壳的半成品：可套人设、可换壳进正文、可错配到别的世界观。禁伪造单书出处。

**抄什么**：可复用的节拍序列 / 可套的模板公式 / 可换壳的组装件。**不缴出**：博主口播腔、营销腔、HTML 视觉稿、无法二创的成品句。

## 二、三个子库 × 卡形态（内容形式的广度与深度）

| 子库 | 回答的问题 | 卡形态 | 当前状态 | 模板 |
|:--|:--|:--|:--|:--|
| `人设原型/` | 写什么人物脸谱 | **人设原型卡**（反差立人 + 动作/选择 + 边界） | 空待填 | `templates/人设原型卡.tpl.md` |
| `CP模板/` | 人物与关系怎么组装 | **CP组装卡**（四族：人设扬长/关系推进/素材清单/架构搭建） | 已成型（20 卡） | `templates/CP组装卡.tpl.md` |
| `金手指原型/` | 给主角挂什么、怎么限制 | **金手指配方卡**（梗×机制×限制×进化） | 空待填 | `templates/金手指配方卡.tpl.md` |

**深度基准**：CP模板 的卡结构 v1 = 全库颗粒度标杆——一张卡 = 适用情境 + 节拍序列（主体，每拍必带「拍义 + 填法标准」）+ 写法要点 + 线效果 + 素材性质。任何新卡（含人设/金手指）都必须对齐这个「可执行节拍」密度，不许退化成"一句建议"。

**新建子库**：横向扩展新卡类型（如"名场面模板"）时，先向本规范注册——在 §三 加一行 + 建同名 `templates/` 模板 + 在 `素材原型库/readme.md` 子库表登一行。不注册 = 不建。

## 三、统一卡结构（模板收敛）

所有卡的骨架统一为 **用法三步 + 卡片节拍 + 族级硬规则**，差异只在「节拍序列」写的是什么（人设写反差节拍、CP 写关系节拍、金手指写机制节拍）。

**用法三步**（每张卡顶部必带）：
1. **选卡**：按情境表对号入座；同类卡可连用推进
2. **落拍**：节拍是必答题——逐拍落位，顺序可微调，节拍不可缺
3. **按拍义填料**：每拍自带「写什么才合格」的标准，照标准填入你自己的角色与语境

**统一卡结构**（对齐 templates/ 三模板）：
```
卡【名】（v{版本}）
> 素材性质：全网素材整理 / 非单书溯源
适用（一句话：什么情境什么任务）
节拍序列（N 拍，主体 = 每拍 拍名 — 拍义：填法标准）
写法要点（一句品味约束）
线效果（一线一行）
素材性质（一行交代来源性质：可用"{公式}"型公式）
```
**族级硬规则**：每个子库/族顶部 3 条硬规则，任何卡不可缺；跨族共享的硬规则（如 CP模板 的"可套用不溯源 / 素材进戏 / 去口播"）必须保留。

## 四、SOP 纲要（怎么产出 / 怎么入库）

> 本 skill 骨架轻：维护动作就四步，全部自含在此。新建子库走 step1；既有子库加卡走 step2→4。

| 步骤 | 场景 | 核心动作 |
|:--|:--|:--|
| **1 判型** | 决定加什么卡 | 判断是 人设/CP/金手指 哪类 → 选取对应 `templates/` 模板；是全新类型 → 走 §二 新建子库注册 |
| **2 套模板** | 产出卡 | 复制模板，按「适用→节拍→要点→线效果→素材性质」填充；节拍必须具体到能"拍->填法"，配 1 条换壳示例（套进另一个世界观演示"可换壳"） |
| **3 入库** | 登记卡 | 写进对应子库目录；更新 `素材原型库/readme.md` 子库表计数；卡文件命名 = 主题化中文名（如 `以爱为囚_现言强制爱拉扯名场面.md`） |
| **4 验收** | 检查可入库 | 对照 §五 红线逐条 + 全库基线（≤15KB/frontmatter/命名唯一）；换壳测试 = 把卡套进一个它没提过的世界观，能否成立 |

## 五、红线（违反 = 不合格 = 不入库）

1. **读取协议红线**：建卡/改卡/建子库前必须读本 skill 全文（`Get-Content -Encoding UTF8 -Raw SKILL.md`）；不读就凭印象建卡 = 卡结构走样 = 不合格。
2. **可套用不溯源红线**：本库素材非单书拆书，**禁伪造单书出处**（不写"据某书某章"）；全网整理 = 内容必须具体到能直接换壳。违反 = 乱编 = 不合格。
3. **素材进戏红线**：节拍/素材/底色本身不是剧情，必须配 **人物目标 + 代价** 才有戏；卡内若没点出"这拍落到谁的目标、要付什么代价" = 不合格。
4. **去口播红线**：零博主口播腔、零营销词、零感叹号连用、零 HTML 视觉稿/双文件；纯技法卡。违反 = 回炉。
5. **模板收敛红线**：新卡必须按对应 `templates/` 模板结构产出（节拍序列为主体 + 每拍带拍义与填法）；自造新结构、退化成一两句建议 = 不合格。
6. **子库注册红线**：全新卡类型（新子库）必须先向本规范注册（§二）并建模板，不能裸建目录。违反 = 断链 = 不合格。

> 格式细节（frontmatter 行数、措辞风格）降级为检查清单，不在此列红线。

## 六、层级与入口（新 agent 怎么"找到规范并知道要做什么"）

**挂在库根，不挂单子库**：素材原型库含多个并列子库（人设/CP/金手指），维护规范管的是整个库——因此放 `素材原型库/skill-素材原型库维护规范/`（与子库平级），对齐 `赛道设定集/skill-赛道包维护规范` 的库根挂法；单子库专属规范（如需）才下沉到该子库内。

**该规范在库体系里的位置**（总索引指针链）：
```
library/readme.md（总索引·入库约束速查表：素材原型库 → 本 skill）
  └─ 素材原型库/readme.md（库索引：子库表 + 入库约束纵沉到本 skill）
       └─ skill-素材原型库维护规范/（本 skill，唯一规范源）
            ├─ SKILL.md            ← 建卡/改卡的唯一标准（你现在在这）
            ├─ templates/          ← 三张卡模板，复制即产出
            └─ ...（配套）
```

**新 agent 上手路径（30 秒定位）**：
1. 打开 `library/readme.md` → 速查表「素材原型库」行 → 看到唯一规范源指向本 skill。
2. 打开 `素材原型库/readme.md` → 看子库表（哪几个子库、哪几个空着要补）+ 入库约束纵沉到本 skill。
3. 读本 skill → 该加卡就套 `templates/` 模板 → 进 step2→4。
4. 不知道卡怎么执行 → 翻 `references/素材进戏与换壳验收.md`。
