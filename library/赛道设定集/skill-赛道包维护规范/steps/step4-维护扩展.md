# Step 4：维护 / 扩展

> 场景：既有包补一份文档、升级一个件、或大改。两人以上协作仍需照本规范，靠 changelog 保持唯一事实链。

---

## 4.1 小维护（补件 / 修一个件）

1. 读目标文件当前 frontmatter 与版本，改动即 `version +0.0.1`。
2. 产出或修改后，过 Step 3 的文档规格与采源真实性两条（frontmatter+溯源字段 / ≤15KB / 无专名 / **新结论带 chXX 锚点或标「推导」**——改内容必回 `源书拆解/` 对证，无锚点新结论不得写入）。
3. 在 `changelog.md` 追加一条：改了什么 + 为什么 + `last_updated`。
4. 不涉及目录/自指路径变动时，索引三处可不同步（除非改包名）。

## 4.2 结构演进（新增目录 / 拆件 / 归档）

- 任何目录级变动：先确认是否仍是「西幻dnd 对齐结构」，偏离需在 SKILL.md §二 同步登记（避免再次漂移）。
- 拆件（超15KB）：新件沿用 `{母件}-{分件}` 命名，`consumers/load_when` 标注，母件改指向。
- 改名/迁移：照 `细分建包与深度补优执行方案.md`，强制走「索引三处同步」红线。

## 4.3 大改（重构一层 / 换标杆源书）

1. 先更新 `changelog.md` 记录意图与大版本号（西幻dnd 走法：3.0.0=角色库重构、3.6.0=战斗表现迁移）。
2. 改后全包过 Step 3 入库检查。

## 4.4 协作守则

- changelog.md = 唯一事实链：任何 agent 上手先读它看包的演进史。
- 版本号三处一致：`SKILL.md` / `skill.json`（若有）/ `CHANGELOG.md`；库内文档则 frontmatter `version` + 文件自身。
- 不确定归属、不用猜——查 `references/西幻dnd-结构标杆.md` 该件是不是存在、规格如何。
