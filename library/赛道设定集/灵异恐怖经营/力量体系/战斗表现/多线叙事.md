## 文件定位

本文件覆盖恐怖经营流中所有多线叙事技法。多线叙事在主角视角为主体前提下，通过POV切换、多地点快切、灵潮级事件呈现等手法，扩展叙事广度、制造信息不对称悬念、侧面定级主角恐怖屋实力、建立员工/鬼怪情感锚点。

**核心原则**：多线叙事不等于平均分配视角——主角视角仍占主体。所有POV切换必须有叙事目的（信息不对称/侧面定级/情感锚点），不是为切而切。

## 二、多线叙事类型详解

### 类型1：多地点快切（降灵期+）

**适用场景**：同一灵潮/事件在不同地点同时产生反应，需要跨空间串联因果链。

**经营段限制**：降灵期+（N5以上）。经营期叙事范围有限，不使用多地点快切。

**切换标记**：

多地点快切必须使用明确的切换标记。

| 切换标记格式 | 使用场景 |
|:--|:--|
| "与此同时。" | 同一时间不同地点的平行事件 |
| "旧城另一头。恐怖屋。" | 远距离切换，强调空间跨度 |
| "……"+地点名 | 省略号过渡后接地点名 |
| "就在这一刻，某处" | 因果串联式切换 |

**核心技法**：
- **同一事件在不同地点同时产生反应**：一个灵潮事件如石入水，涟漪向多个地点扩散
- **因果链跨空间串联**：A地的事件触发B地的反应，B地的反应又影响C地
- **电影蒙太奇效果**：快速切换多个地点的片段，拼凑出灵潮全貌

**原作锚点**：

> 灵潮事件/旧城多处阴气异动/恐怖屋应对三线并行——同一件事（灵潮）同时在多个场景产生连锁，通过快切串联因果，呈现世界级影响。

**渲染要点**：
1. 每次地点切换必须有明确标记（"与此同时""旧城另一头"等），不得无标记切换
2. 每个地点的片段控制在1-3段，不宜过长
3. 各地点片段之间必须有因果关联——同一事件的不同切面
4. 快切顺序按因果链排列：事件源头 → 直接影响区域 → 间接影响区域
5. 降灵期+才用此技法——经营期主角恐怖屋影响力不足以支撑跨空间叙事

**节奏模板**：
```
[地点A：恐怖屋应对] → "与此同时。" → [地点B：全城阴气/游客恐慌] → "旧城另一头。地点C。" → [地点C：灵潮源头] → 切回主角
```

### 类型2：灵潮级事件叙事（reveal_hook章）

**适用场景**：影响多个区域/势力/阶层的灵潮级事件，在reveal_hook章呈现。

**章节限制**：仅用于reveal_hook章。其他章节不使用灵潮级事件叙事。

**事件规模**：
- 影响多个区域（跨城区/跨城市/跨灵界）
- 影响多个势力（灵界势力/恐怖屋产业/游客/普通市民）
- 影响多个阶层（从灵界主宰到最底层游客）

**多层递进展示影响**：

影响按层级从上到下递进展示，每一层呈现不同反应。

| 层级 | 反应类型 | 描写侧重 |
|:--|:--|:--|
| 灵界势力 | 鬼王局势/怨气变化 | 概念级描写，宏观 |
| 恐怖屋产业 | 客流/评级波动 | 数据化描写，个体 |
| 普通游客街坊 | 恐慌/议论/逃离 | 群像描写，情绪化 |
| 普通市民 | 灵异直觉/日常变化 | 群像描写，情绪化 |

**灵潮级事件面板格式**：

```
【灵潮事件】XX
地点：XX
影响：XX
```

**面板示例**：

> 旧城上空的月光诡异地暗下来，街角的流浪猫集体炸毛。行人缩紧了脖子，却没人说得清是哪来的寒意。
>
> 【灵潮事件】旧城阴气骤涨
> 地点：旧城主城区
> 影响：连日灵异事件增加，恐怖屋游客激增但怨气上升，疑似有高星鬼王在酝酿。

**"新闻播报"式笔法**：

用新闻播报式笔法呈现多地点异象——冷静、客观、信息密集。

**示例**：

> 旧城西郊的恐怖屋门口，游客排起长龙却没人进得来。东区旧宅的住户连续三夜听到抓挠声，慌忙报了警却找不到任何痕迹。废品回收站的老王发现，收来的旧家具里，有一张合照的镜面在夜里总映出陌生人影……而在更远的北郊，废弃多年的三线医院大楼，忽然整层亮起灯来。

**渲染要点**：
1. 灵潮级事件叙事仅用于reveal_hook章
2. 影响展示按层级递进（灵界势力→恐怖屋产业→普通游客→市民），不得跳层
3. 灵潮级事件面板弹出后，事件必须在后续5章内对主角产生直接影响
4. 多地点异象用"新闻播报"式笔法——信息密集、冷静客观
5. 因果链必须清晰：A导致B，B导致C，不得断裂

### 类型3：鬼怪POV插入

**适用场景**：切到鬼怪视角，呈现鬼怪不知道自己被盯上/第一次感到心悸的心理状态。

**经营段限制**：全经营段通用。

**核心功能**：制造信息不对称的悬念——读者通过鬼怪视角知道了鬼怪不知道的信息（主角已经盯上它/已经设好困局），产生紧张感。

**插入模式**：
- 切到鬼怪视角写"它不知道自己被主角识破了"
- 或切到鬼怪视角写"它第一次感到心悸/不安"
- 3-5行后切回主角

**原作锚点**：

> 残念在长街游荡——"它生前守在这条街等候，不知为何，今晚它感到一丝不适。"鬼怪视角中的不安，读者知道这是主角逼近的信号，但鬼怪自己不知道——信息不对称悬念。

**信息不对称类型**：

| 类型 | 鬼怪视角内容 | 读者知道的信息 | 悬念效果 |
|:--|:--|:--|:--|
| 不知被盯上 | 鬼怪日常/麻痹/习惯 | 主角已经锁定它 | 紧张期待（何时动手？） |
| 隐约不安 | 鬼怪感到不安但不知原因 | 主角正在逼近/布置 | 悬疑恐惧（会怎样？） |
| 第一次心悸 | 鬼怪遭遇主角后不安 | 主角实力远超预期 | 爽感（识破确认） |

**渲染要点**：
1. 鬼怪POV插入控制在3-5行，快速切回主角
2. 鬼怪视角内容必须与主角行动有因果关联
3. 鬼怪视角语感更"魂性"（执念/本能），与主角冷静专业形成对比
4. 切回主角不需要标记；切入鬼怪视角建议有场景转换引导
5. 鬼怪POV不是展示鬼有多强，而是制造信息不对称——鬼的"安全感"反衬即将到来的危险

### 类型4：游客旁观者视角插入

**适用场景**：主角恐怖屋/行为后切到游客/街坊视角，用他们的恐惧/震惊来侧面定级恐怖屋或主角。

**经营段限制**：全经营段通用。

**核心功能**：侧面定级——不直接说恐怖屋多吓人/主角多强，通过游客反应让读者感受到。

**插入模式**：
- 主角完成某个行为（取证/识破/收服）后
- 切到游客/街坊视角
- 旁观者震惊反应侧面定级
- 2-3行后切回主角

**旁观者反应类型**：

| 反应类型 | 示例句式 | 定级效果 |
|:--|:--|:--|
| 惊吓过度 | "这也太吓人了，我头皮发麻！" | 恐怖屋恐怖程度出认知 |
| 能力质疑 | "这人是真的在找死吧？" | 主角超出凡人范畴 |
| 恐惧反应 | 游客退后/发抖/不敢进 | 恐怖屋威慑力 |
| 经验判断 | "我开了十年鬼屋，没见过真怕成这样的客" | 用老手经验衬托 |

**渲染要点**：
1. 游客视角插入控制在2-3行，比鬼怪POV更短
2. 游客反应必须是"惊吓/惊恐/不可置信"等强烈情绪，不是冷静分析
3. 游客用疑问句/感叹句表达震惊——"这真的是人工做的吗？"比"很恐怖"冲击力大
4. 游客视角不需要切换标记，直接在主角行为后另起段落切入
5. 同一章内游客视角插入不超过2次

### 类型5：员工独立行动线（降灵期+）

**适用场景**：关键员工（徐婉型/某鬼怪）独立行动切POV，建立员工/鬼怪情感锚点。

**经营段限制**：降灵期+（N5以上）。经营期员工独立性有限，不单独开行动线。

**核心结构**：
- 员工视角开场（章节前1/3建立情感锚点）
- 切回主角
- 员工行动线与主角行动线在章节后段交汇

**员工视角开场作用**：
1. **建立情感锚点**：让读者对员工/鬼怪情感投入
2. **信息铺垫**：员工视角提供主角不在场的信息
3. **平行叙事**：员工行动与主角行动平行推进，最终交汇

**原作锚点**：

> 员工视角——"恐怖屋的老板总是深更半夜一个人忙活，她总觉得自己该多帮他一些。"员工视角的热血/关怀建立情感锚点，随后在关键时刻登场与主角交汇。

**渲染要点**：
1. 员工视角开场控制在章节前1/3
2. 必须建立情感锚点——不是单纯信息传递，是让读者关心这个员工
3. 员工行动线必须与主角有交汇点
4. 员工语感与主角区分（更情绪化，取决于性格）
5. 降灵期+才使用此技法

**结构模板**：
```
[员工视角开场：情感锚点+信息铺垫] → [切回主角：主角行动推进] → [双线交汇：员工/鬼怪登场影响主角]
```

### 类型6：灵界存在视角感知（灵界期）

**适用场景**：灵界级别存在的感知——非五官感知，而是怨气/灵潮感应。

**经营段限制**：灵界期（N8+）。降灵期及以下不使用灵界存在视角感知。

**感知方式**：

| 感知类型 | 描写方式 | 与常人感知差异 |
|:--|:--|:--|
| 怨气感应 | "怨气漫过整条街" | 非视觉，概念级感知 |
| 灵潮波动 | "灵潮中传来一阵阵震颤" | 通过灵潮感知 |
| 执念网络 | "无数执念在低语" | 感知情绪，非物理 |
| 概念感知 | "红衣的恨意""鬼王的威压" | 感知概念本身 |

**核心特征**：
- **非五官而是"怨气感应""灵潮波动"**
- **概念级感知**：感知的是概念，不是物理现象——"红衣的恨意"
- **被动感知**：怨气网络内异常自动引起注意，不主动搜索
- **跨城/跨灵界感应**：空间距离不构成障碍

**感知描写示例**：

> 主角立于恐怖屋屋顶，怨气如潮水般向四方蔓延。灵潮网络中，无数低语如同海浪起伏。突然，一道异样波动从极远处传来——那是某尊鬼王在筹备灵潮的痕迹。

**渲染要点**：
1. 灵界存在视角感知用"怨气感应""灵潮波动""执念低语"等专属词汇，不用"看到""听到"
2. 感知内容是"概念的汇聚""气息的变化"，不是物理描写
3. 被动触发——怨气网络内异常自动引起注意
4. 可感知跨城/跨灵界事件，空间不构成障碍
5. 仅灵界期使用此技法
6. 面板可呈现灵界信息（灵潮趋势/鬼王动向/灵域异常），参照灵界期面板格式

## 三、POV切换硬规则

以下场景**必须**切换POV，不是可选项：

| 场景 | 必须切换的POV | 切换时长 | 目的 |
|:--|:--|:--|:--|
| 高潮章鬼王战 | 鬼王视角 | 3-5行 | 呈现鬼王的恐惧/暴怒/误判 |
| 新灵界势力登场 | 该势力视角 | 1段 | 建立势力印象/定调 |
| 主角不在场的关键事件 | 在场者视角 | 事件全程 | 呈现主角不在场时发生的事 |

**切换标志要求**：
- POV切换需有明确标志（场景转换/地点标记/人物焦点转移）
- 快速切回：3-5行后切回主角（降灵期+可延长至1/3章节）
- 切回主角不需要标志；切入非主角视角时建议有引导

**POV切换检查清单**：
- [ ] 高潮章鬼王战是否切了鬼王视角？
- [ ] 新灵界势力登场是否切了该势力视角？
- [ ] 主角不在场的关键事件是否切了在场者视角？
- [ ] 每次POV切换是否有明确叙事目的？
- [ ] POV切换后是否在规定行数内切回主角？

## 四、多线叙事与面板的结合

多线叙事中的面板使用规则：

| 多线类型 | 面板使用 | 格式来源 |
|:--|:--|:--|
| 多地点快切 | 各地点可弹简版状态面板 | 经营段面板文件 |
| 灵潮级事件叙事 | 必弹灵潮级事件面板 | 恐怖事件五段式第六节 |
| 鬼怪POV插入 | 鬼怪视角可弹鬼怪属性简版 | 灵体探知数据文件 |
| 游客旁观者视角插入 | 不弹面板（纯情绪反应） | — |
| 员工独立行动线 | 员工视角可弹员工/鬼怪属性简版 | 经营段面板文件 |
| 灵界存在视角感知 | 可弹灵潮信息面板 | 灵界期面板文件 |

**面板结合红线**：
- 游客旁观者视角插入不弹面板——游客的恐惧是纯情绪反应，不需要数据化
- 灵潮级事件叙事必弹灵潮级事件面板——这是灵潮级事件的标志
- 鬼怪POV插入的鬼怪面板是简版——只需要关键信息
- 非主角视角面板用第三人称（"目标""它"），主角面板用第二人称（"你"）

## 五、各经营段多线叙事能力对照

| 能力 | 经营期(N1-4) | 降灵期(N5-7) | 灵界期(N8+) |
|:--|:--|:--|:--|
| 多地点快切 | 不可用 | 可用 | 可用 |
| 灵潮级事件叙事 | 不可用（非reveal_hook章） | 可用（reveal_hook章） | 可用（reveal_hook章） |
| 鬼怪POV插入 | 可用 | 可用 | 可用 |
| 游客旁观者视角插入 | 可用 | 可用 | 可用 |
| 员工独立行动线 | 不可用 | 可用 | 可用 |
| 灵界存在视角感知 | 不可用 | 不可用 | 可用 |
| POV切换频率 | 低（偶尔切鬼怪/游客） | 中（每3章至少1次非主角视角） | 高（多POV常态化） |

**递进逻辑**：
- 经营期：主角视角为主，偶尔切鬼怪/游客视角制造悬念
- 降灵期：主角视角仍为主体，但多地点快切和员工独立行动线开始使用，POV切换频率上升
- 灵界期：多POV常态化，灵界存在视角感知提供概念级叙事广度

## 六、红线

1. **主角主体红线**：多线叙事不等于平均分配视角——主角视角仍占主体。非主角视角总篇幅不得超过章节篇幅的1/3（降灵期+可放宽至1/2，但主角视角必须仍是主体）。
2. **叙事目的红线**：POV切换必须有叙事目的（信息不对称/侧面定级/情感锚点），不是为切而切。如果切POV对叙事没贡献，则不该切。
3. **灵潮事件面板红线**：灵潮级事件面板只用于reveal_hook章。其他章节不得使用灵潮级事件面板格式。
4. **快速切回红线**：鬼怪POV插入3-5行后必须切回主角，游客视角2-3行后切回。不得在非主角视角停留过久（降灵期+员工独立行动线除外，但章节前1/3后必须切回主角）。
5. **切换标志红线**：POV切换需有明确标志。无标志的POV跳跃=不合格。切回主角时不需要标志。
6. **必切场景红线**：高潮章鬼王战必须切鬼王视角，新灵界势力登场必须切该势力视角1段，主角不在场的关键事件必须切在场者视角。漏切=不合格。
7. **经营段匹配红线**：多地点快切仅降灵期+，员工独立行动线仅降灵期+，灵界存在视角感知仅灵界期。低段使用高段技法=不合格。
8. **信息不对称红线**：鬼怪POV的核心价值是信息不对称——鬼怪视角必须呈现"不知道自己被盯上"或"不知道危险来源"的状态。
