# 剧情库 · 索引（检索协议）

> **定位**：通用包不含任何单书剧情（主线/卷纲/章白描由新书 plot 在项目空间产出）。剧情层参考走本库：plot Step1 产卷纲时、Step2 产幕白描时，按幕功能位+叙事阶段取卡作**幕白描底稿**。
> **判定口诀**：卡片给「槽位化的参考答案」——白描+锚点卡的**结构与节奏可直接继承**，专名与事件血肉必须替换重推。
> **库结构**：`早期/中期/后期/` 三池（按**主角叙事阶段**放置，无并列目录——卷一结构基准RHY-001已入早期池）。池内两级卡片体系：**总卡**（弧概览+幕功能位序列+量级跳档+使用红线，产卷纲读）+**幕件**（幕级全套字段：套路决策/幕定位/剧情白描/六要素/敌人-成长耦合/POV规划/逐区间锚点卡/prose-render交接，产幕白描按幕选读）——**全库卡片粒度统一为幕级**。卡是素材库不是排期表——不按先后顺序，同池内可任取重组。

## 卡片元数据schema

每张卡头部必带：

```
card_id: 弧级三位编号（幕件=弧级编号-M{n}） | 阶段: 早期/中期/后期 | 源类型: 国内源书/都市生态/节奏基准+示范
arc_type: 开局弧/建势力弧/换引擎弧/终局弧/支线弧/一幕完整剧情（幕件=弧类型·幕n功能位）
level_range: 适配境界区间（对齐力量体系阶位）
map: 适配地图类型
tension: 核心张力类型
status: 幕纲级（储备卡：白描+锚点卡可改造为幕纲；OS=都市生态解耦/CN=源书深度匿名化转写/RHY=示范级参考答案）
```

**阶段划分标准**（按主角叙事位置，不按卷号）：早期=都市考生求生/重振家庭立威（凡俗+炼气前）｜中期=建势扩张/隐世初现（修士→金丹元婴型）｜后期=登顶/终局清算+仙凡大撞（化神+）。

## 检索协议（plot 消费流程）

1. **按幕功能位+阶段定位**：当前产出幕的功能位（重生觉醒/打脸立威/规则实装/谷底反弹/建势扩张…）+主角当前叙事阶段，锁定对应阶段文件夹；
2. **两级取卡**：产**卷纲**→读池内总卡（RHY-001/CN-001/CN-002），取幕功能位序列、章幅配比与量级跳档节奏；产**幕白描**→按当前幕功能位+arc_type+level_range+map过滤，选读对应**幕件**（弧卡拆分的-M{n}件）或OS单弧卡1-2张作底稿；
3. **读卡做幕纲改造（三步）**：以卡内「剧情白描+逐区间锚点卡」为幕白描底稿——①**改专名**（示范专名禁直用，新名过《赛道特色/命名规则.md》撞名检查）②**换事件分支**（对接X张力+新世界重推事件）③**遮卡测试**（遮住示范白描，幕白描必须能从X+新世界+新角色推出——原样能推=抄的，回炉）；
4. **留痕**：卷纲/幕白描尾部记「卡片引用记录」（card_id+借鉴维度），供review核查。

## 使用红线

1. **幕纲级改造红线**（所有储备卡）：结构与锚点节奏可直接继承；示范专名与事件分支必须替换。源侧红线——**国内源书卡**（CN）：源书残留情节禁复用（卡内白描为自造示范）；**都市生态卡**（OS）：具名角色与具体剧情分支禁照搬（家族饭局/商战/校门冲突/隐世宗门等都市生态原型为赛道通用语汇可直接利用其"场合规则"，具体人物事件须换）；
2. **总卡-幕件分工红线**：总卡只供卷纲层（功能位序列/章配比/量级跳档），幕件才供幕白描层——禁止把总卡的整弧推进链当单幕底稿直接抄；
3. 单幕引用≤2张卡，禁止整卷拼贴卡片（拼贴=结构可见的复制）；
4. **跨期降级规则**：后期卡前移使用需降档（终局弧可裁段作换引擎弧）；早期卡不复用于后期（境界/舞台不匹配）。
