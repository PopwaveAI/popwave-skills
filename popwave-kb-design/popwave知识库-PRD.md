# popwave 知识库 · 从数据源到前端展示 PRD

- 版本：v1.0
- 日期：2026-08-13
- 作者：pop（为江轩设计）
- 状态：方案稿（数据源范式待定，本文给出推荐方案并标注决策点）

---

## 1. 需求背景

popwave 是网文创作体系，团队已沉淀一批可复用的创作资产：技法卡、文风 DNA、设定包、拆书单元。这些资产目前以 Markdown 文件散落在本地目录 `popwave知识库/` 下，靠一份 `manifest.json` 做索引，没有面向团队/个人的统一消费界面。

当前痛点：

- 资产是「死文件」，只能靠文件管理器翻找，无法按库、按子分类、按赛道快速浏览。
- 没有「公域策展」与「个人私有」的区分，团队沉淀的规范资产和个人创作草稿混在一起。
- 资产元数据（版本、来源、作者、关联）没有统一承载，无法追溯和版本化。
- 参考 WorkBuddy 5.3.11 的「资料库」升级为 AI 原生知识空间，popwave 需要一个能浏览、能检索、能人机双写的知识库前端。

数据源现状：`popwave知识库/` 下已有四库（技法库 33 项、文风库 10 项、拆书库 1 个书单元、设定包库 1 个设定包），**大部分是 md 文件**，但**数据源范式尚未定型**——目录结构、元数据承载方式、索引机制都还有调整空间。本文先定数据源范式，再定前端展示，保证前后端一致。

---

## 2. 需求目标

把「一堆 md 文件」升级为「可浏览、可检索、可协作的双域知识库」，让团队沉淀的资产能被创作者和 AI 高效消费。

定性目标：

- 建立一套稳定的数据源范式，让 md 资产自带元数据、可被脚本索引、可被前端读取。
- 前端实现「公域浏览 + 资产详情」，创作者能按库 → 子分类 → 赛道找到资产并查看内容。
- 双域模型落地：公域（策展资产库）与个人（私有工作台）分离，双向流动。

> 定量指标暂不设定，待数据源范式定型、原型验证后再补。

## 3. 数据源范式（库）

> 这是本 PRD 的核心前置。数据源范式未定型，本节给出**推荐方案**，并标注需要拍板的决策点。

### 3.1 目录结构（沿用现状，微调）

```
popwave知识库/
├── manifest.json          # 聚合索引（由脚本从 frontmatter 生成）
├── README.md
├── 技法库/
│   ├── 六要素/ *.md
│   ├── 剧情模式/ *.md
│   ├── 情境技法/ *.md
│   ├── 设计原则/ *.md
│   ├── 通用技法/ *.md
│   └── *.md               # 散件（爽点引擎、章型定义等）
├── 文风库/
│   ├── 修仙·升级流/ *.md
│   ├── 规则·博弈流/ *.md
│   └── ...                # 按流派分子目录
├── 拆书库/
│   └── 西幻·DND/深渊主宰/  # 书单元 = 一个文件夹（bundle）
├── 设定包库/
│   └── 西幻·DND/深渊主宰-官方设定包/
└── 素材库/                 # 预留，当前为空
```

目录层级语义：

- **库**（一级）：技法库 / 文风库 / 设定包库 / 拆书库 / 素材库，表示资产类型。
- **子分类**（二级）：每个库自己的原生分类。技法库按「六要素/剧情模式/情境技法/设计原则/通用技法/散件」，文风库按「流派」，拆书库/设定包库按「赛道·体系（西幻·DND）」。
- **资产**（叶子）：一个 md 文件（单文件资产）或一个文件夹（bundle 资产，如书单元、设定包）。

### 3.2 元数据承载：推荐「frontmatter + manifest 双轨」

元数据是数据源范式的关键。两种方案对比：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. manifest 集中注册（现状） | 所有资产元数据写在 `manifest.json` | 单一索引、便于校验 | 改资产要同步改 manifest，易失同步 |
| B. md frontmatter 自描述 | 每个 md 文件头部写 YAML 元数据 | 资产自包含、随文件走 | 需要解析器，元数据散落各文件 |

**推荐方案：B 为主、A 为辅。** 每个资产的元数据写在 md 文件头部的 frontmatter（YAML），`manifest.json` 退化为由脚本从 frontmatter 聚合生成的索引，不再手工维护。这样资产自带元数据、可移植，前端和脚本都从 frontmatter 读取。

frontmatter 字段（单文件资产）：

```yaml
---
id: 爽点引擎
lib: 技法库
cat: 散件
version: 1.0.0
tags: [通用, 番茄, 爽感]
desc: 爽感公式与即时奖励循环，驱动读者追读的核心引擎。
author: pop 团队
source: 团队沉淀
---
```

bundle 资产（文件夹）在 `00-说明.md` 的 frontmatter 里声明 `bundle` 字段，列出文件清单与顺序：

```yaml
---
id: 深渊主宰-书单元
lib: 拆书库
cat: 西幻·DND
version: 1.0.0
bundle:
  - 00-说明.md
  - 01-剧情线拆解.md
  - ...
---
```

> **决策点 1**：是否接受「frontmatter 为主、manifest 由脚本生成」？若接受，需要写一个扫描脚本（遍历目录 → 读 frontmatter → 生成 manifest.json）。

### 3.3 命名规范

- 资产 id 唯一，作为前端跳转和关联的键。
- bundle 内文件用 `NN-名称.md` 前缀保证排序（如 `00-说明.md`、`10-标杆样板库.md`）。
- 子分类目录名即该分类的展示名（如 `修仙·升级流`）。

### 3.4 版本与变更

- 每个资产在 frontmatter 维护 `version`。
- 版本变更记录在 `CHANGELOG.md`（每库一份或全局一份）。
- 公域资产版本化；个人 fork 公域资产后维护自己的版本。

### 3.5 双域在数据源层的体现

- **公域**：`popwave知识库/`（团队策展，只读为主，贡献走审核）。
- **个人**：`个人知识库/`（或按用户分目录，如 `个人知识库/<用户名>/`），自由读写。
- 两域共用同一套资产模型与 frontmatter 规范，靠目录归属 + manifest 区分。

> **决策点 2**：个人知识库是独立顶层目录，还是与公域同目录下按用户分子目录？建议独立顶层目录，权限隔离更清晰。

## 4. 资产模型

双域统一抽象为「资产（Asset）」，一套元数据 + 生命周期，前端才能用同一套卡片/详情呈现公域与个人。

### 4.1 资产类型

| 类型 | 说明 | 典型归属 |
|---|---|---|
| 技法卡 | 剧情模式 / 情境技法 / 通用技法 / 设计原则 / 六要素 | 公域为主 |
| 文风 DNA | 按流派沉淀的笔触 DNA | 公域为主 |
| 设定包 | 世界篇 / 驱动篇 / 笔法篇，开盒即写模板 | 公域为主 |
| 拆书单元 | 一本书一个文件夹（bundle） | 公域 + 个人 |
| 个人笔记/草稿/收藏 | 创作过程中的私有产出与引用 | 个人 |

### 4.2 元数据字段

| 维度 | 字段 | 作用 |
|---|---|---|
| 基础 | id / 标题 / 类型 / 内容 | 资产本体 |
| 分类 | 库 / 子分类 / 标签 | 导航与检索 |
| 版本 | version / 历史 / fork 来源 | 公域版本化、个人可 fork |
| 权限 | 公域 / 个人 / 私密 / 链接分享 | 可见性控制 |
| 来源 | 作者 / 贡献者 / 来源文档 | 可追溯 |
| 使用 | 引用次数 / 收藏数 / 最近使用 | 热度与推荐 |

### 4.3 权限与生命周期

- 个人资产：草稿 → 已发布（到公域）→ 可撤回。
- 公域资产：待审 → 已发布 → 已归档。
- 版本演进：公域版本化；个人可 fork 公域资产做私有改造，再回馈公域。

---

## 5. 双域模型

不照搬 WorkBuddy 的「纯个人文档空间」，而是「公域（策展资产库）+ 个人（私有工作台）」双域，双向流动。

- **公域**：团队沉淀、人人可用的规范资产，只读为主、版本化、走审核。
- **个人**：每个创作者/项目的私有空间，自由读写，可「发布」到公域。

双域不是两套割裂系统，而是同一套资产模型下的两种权限与生命周期。公域 → 个人：引用/收藏/复制；个人 → 公域：发布/贡献（审核后入公域）。

## 6. 前端展示

### 6.1 信息架构

| 层级 | 内容 |
|---|---|
| 顶部 | 全局搜索（公域 + 个人统一检索）+ 新建/发布入口 |
| 左侧主导航 | 公域 / 我的 两大域切换 |
| 公域 | 按库导航（技法/文风/设定包/拆书）→ 库内子分类；赛道为可选交叉筛选 |
| 我的 | 我的资产 / 我的收藏 / 我的草稿 / 我发布的 |

### 6.2 页面

| 页面 | 说明 |
|---|---|
| 首页总览 | 全局搜索主入口 + 双域入口卡片 + 公域精选 + 我的最近 + 统计 |
| 公域浏览 | 左侧「库 → 子分类」导航 + 顶部赛道交叉筛选，主区资产卡片网格 |
| 资产详情 | 左侧正文（bundle 显示文件清单）/ 右侧元数据面板 + 引用/收藏/复制 |
| 个人空间 | Tabs 组织「我的资产/收藏/草稿/已发布」 |
| 编辑器 | 人机双写：选中内容 → AI 建议 → 逐条审阅接受/拒绝 |
| 发布 | 公域/私密/链接分享三种可见性 |

### 6.3 前端设计原则

- 双域清晰但统一：同一套资产卡片/详情呈现公域与个人，用「公域/我的」徽章区分来源域。
- 检索优先：全局搜索是主入口，公域 + 个人统一检索。
- 赛道化导航：赛道是跨库交叉标签，用于按题材找资产，不作为主导航。
- 人机双写为底座：AI 可编辑、可审阅，让知识库资产「活」起来。

## 7. 数据流（md → 前端）

```
md 资产（frontmatter 元数据）
   │  扫描脚本
   ▼
manifest.json（聚合索引）
   │  前端 fetch
   ▼
前端渲染（公域浏览 / 资产详情 / 检索）
```

- 扫描脚本遍历目录，读每个资产的 frontmatter，生成 `manifest.json`。
- 前端加载 `manifest.json` 得到资产列表与元数据，用于导航、筛选、检索。
- 进入资产详情时，前端 fetch 对应 md 文件，用轻量 markdown 渲染器展示正文（标题/列表/引用/表格）。
- bundle 资产先展示文件清单，点击文件再 fetch 对应 md。

> **决策点 3**：前端是纯静态（fetch 本地 md + 前端渲染），还是引入构建/后端索引（如搜索服务）？建议 Phase 1-2 用纯静态，检索用前端过滤；数据量大后再上后端索引。

## 8. 功能需求详述

### 8.1 数据源扫描与索引

**功能**：扫描 `popwave知识库/` 目录，读取每个资产的 frontmatter，生成/更新 `manifest.json`。

**业务逻辑**：脚本遍历四库目录。对单文件资产，读取文件头部 YAML frontmatter，提取 id/lib/cat/version/tags/desc 等字段；对 bundle 资产（文件夹），读取 `00-说明.md` 的 frontmatter 中的 bundle 字段，生成文件清单。所有资产汇总写入 `manifest.json`，并做完整性校验（id 唯一、路径存在、字段齐全）。脚本可重复运行，幂等更新索引。

**交互**：命令行运行（如 `python scan.py`），输出扫描统计（各库资产数、新增/变更/缺失项）。前端不直接依赖脚本，只消费 manifest.json。

**字段规则**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | 文本 | 是 | 资产唯一标识 |
| lib | 枚举 | 是 | 技法库/文风库/设定包库/拆书库/素材库 |
| cat | 文本 | 是 | 库内子分类 |
| version | 文本 | 是 | 语义化版本 |
| tags | 数组 | 否 | 标签，含赛道 |
| desc | 文本 | 否 | 一句话摘要 |
| bundle | 数组 | 否 | bundle 资产的文件清单 |

**边界与异常**：frontmatter 缺失或字段不全时，脚本报错并列出问题文件，不静默跳过；id 重复时报错；路径不存在时报错。

### 8.2 公域浏览

**功能**：创作者按「库 → 子分类」浏览公域资产，可叠加赛道交叉筛选。

**业务逻辑**：左侧导航列出四大库，选中某库后展开其子分类（技法库展开六要素/剧情模式/情境技法/设计原则/通用技法/散件，文风库展开流派，拆书库/设定包库展开赛道·体系）。主区以卡片网格展示当前「库 + 子分类」下的资产。顶部赛道筛选（西幻/修仙/都市/末世/悬疑/游戏/规则/进化/民俗/非超自然）作为可选交叉条件，在当前库内按标签过滤。卡片展示类型徽章、标题、一句话摘要、标签、子分类、版本、文件数。

**交互**：点击库 → 展开子分类；点击子分类 → 主区刷新；点击赛道 → 在当前库内过滤；点击卡片 → 进入资产详情。空结果时展示空状态提示。

**状态**：默认进入技法库·全部；子分类选中态、赛道选中态在侧栏和顶部高亮。

**边界与异常**：某库下某赛道无资产时，展示空状态而非空白页。

### 8.3 资产详情

**功能**：查看单个资产的完整内容与元数据，可引用/收藏/复制。

**业务逻辑**：单文件资产直接 fetch 对应 md 并渲染正文；bundle 资产先展示文件清单（每个文件带一句话说明），点击文件再 fetch 渲染。右侧元数据面板展示库、子分类、版本、来源、作者、引用数、收藏数、关联资产。操作按钮：引用到我的（建立关联）、收藏、复制到个人空间。

**交互**：面包屑返回上一级；点击关联资产跳转到对应资产详情；点击操作按钮给出反馈提示。

**边界与异常**：md 文件读取失败（如未通过 HTTP 服务访问）时，展示提示而非空白。

### 8.4 全局检索

**功能**：跨公域 + 个人统一检索资产。

**业务逻辑**：顶部搜索框输入关键词，前端在资产 id/标题/库/子分类/标签中做包含匹配，结果按库分组或平铺展示，每条标注来源域（公域/我的）与类型徽章。支持 ⌘K 快捷键聚焦搜索框。

**交互**：输入即过滤；点击结果进入资产详情；清空关键词回到原视图。

**边界与异常**：无匹配结果时展示空状态；检索范围默认公域 + 个人，可在结果页切换。

### 8.5 个人空间（Phase 3）

**功能**：管理个人资产、收藏、草稿、已发布内容。

**业务逻辑**：Tabs 组织「我的资产/收藏/草稿/已发布」。我的资产是个人私有产出（笔记、草稿、个人拆书、文风偏好）；收藏是引用自公域的资产；已发布是提交到公域并通过审核的内容。个人资产自由读写，可「发布到公域」走审核。

**交互**：Tab 切换列表；点击资产进入详情；发布操作弹确认。

**边界与异常**：个人空间为空时展示引导空状态。

### 8.6 人机双写编辑器（Phase 4）

**功能**：让 AI 编辑知识库资产，逐条审阅后写入。

**业务逻辑**：打开资产进入编辑模式，左侧文档内容，右侧 AI 侧栏。选中任意内容，AI 给出修改建议（以批注/修订呈现），用户逐条「接受/拒绝」，只有接受才写入原文。公域资产编辑走 fork 或建议，不直接改公域原文。

**交互**：选中内容 → AI 建议 → 接受/拒绝 → 写入/忽略。

**边界与异常**：并发编辑冲突需提示；未接受前不落盘。

### 8.7 发布 / 轻应用（Phase 4）

**功能**：资产一键发布为公域、私密或公开链接；HTML 资产可加 CSV 变「会存数据的轻应用」。

**业务逻辑**：发布面板提供三种可见性：发布到公域（走审核）、链接分享（生成公开链接）、仅自己可见。HTML 资产可嵌入 CSV 数据表实现数据双向同步。

**交互**：选择可见性 → 发布 → 生成链接/进入待审。

## 9. 落地路线

| 阶段 | 内容 | 产出 |
|---|---|---|
| Phase 1 | 数据源范式定型 + 扫描脚本 | frontmatter 规范、manifest 生成脚本 |
| Phase 2 | 公域浏览 + 资产详情 | 前端原型（已有一版，需对齐新范式） |
| Phase 3 | 个人空间 + 全局检索 | 双域完整浏览 |
| Phase 4 | 人机双写 + 发布 | 编辑器、发布/轻应用 |

> 建议先做 Phase 1（数据源范式 + 扫描脚本），因为它是前端的数据基础；范式定了，前端原型直接对齐即可。
