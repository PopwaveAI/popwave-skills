## 1. 这个文件夹是什么（定位）

**一句话**：这是「云端知识库」在本地落盘的真源仓库，agent 在此扮演**官方编辑**，负责预制、更新、发布知识资产，供用户在 popwave 按需下载消费。

对应 `知识库系统-PRD.md` 的完整链路是：

```
官方编辑（江轩 + pop / agent） → 本仓库（manifest + 四库资产） → 云端分发 → 用户按需下载 → 项目空间
```

核心定位关键词：

- **官方单向分发**：知识全部由官方一手预制，用户**只消费、不回传**。本仓库永远不接收任何用户产出物入库。
- **内容真源**：本仓库是资产文件的唯一权威来源。`manifest.json` 是唯一总索引，与仓库内实际文件严格一一对应。
- **增强层，非兜底层**：现有 skill 内部技法库（`skills/*/references/`）保持不动，作为离线兜底。本仓库内容是对内置能力的**增强**，二者互不阻塞；云端不可用时专家管线照常运行。
- **目录大而全、内容少而精**：目录与索引一次搭成完整骨架（稳定契约，不随内容增长改动）；内容按顺序逐格填充（可生长的覆盖层）。

## 3. 入库标准（哪些资料能进来）

入库需**同时**满足硬性门槛（形态）与质量门槛（内容），并归属到正确的一库。

### 3.1 硬性门槛（形态）

1. **独立 Markdown 纯文本文件**，命名规范 `{资产名}.md`。必须能被 agent 直接读取，不依赖任何渲染服务。
2. **带标准元数据头**（YAML frontmatter），字段如下：

```yaml
---
id: 资产唯一ID           # 必须与文件名/ manifest 中 id 一致
version: 1.0.0           # 语义化版本
access: free             # 访问级别，v1 统一 free
updatedAt: 2026-08-10    # 上次更新日期
tags: ["通用", "爽感"]    # 赛道/流派/题材标签，供目录检索
---
```

3. **完成 manifest 登记**：新增/修改后同步更新 `manifest.json`，登记 `id / path / version / access / tags`，并递增 manifest 版本号。

### 3.2 质量门槛（内容）——先过「可复用」这一关

- **教方法，不教故事**：资产应沉淀可跨书复用的**方法/框架/原则**，而非某个具体项目的流水账。抹掉具体案例后，剩下的骨架必须依然成立（换皮测试）。
- **抽象层级决定复用性**：教「这一类怎么做」的能入库；教「这一本书某段怎么写的」只能算证据，不满足入库。
- **少而精**：优先在少数高价值格子放入高质量内容，跑通验证后再逐格扩充。不为凑数而低质填充。
- **可消费**：被哪个专家管线（write/plot/seed/research/prose）在什么时机读取，必须明确。说不清消费方的资料不入库。

### 3.3 四库各自入库判定

| 库 | 什么能进 | 什么不能进 |
|:--|:--|:--|
| 技法库 | 可复用的写作技法：爽点引擎、章型定义、节奏微操、微观技法、设计原则、剧情模式、通用技法 | 具体某本书的桥段记录；只对单一项目成立的临时方案 |
| 拆书库 | 标杆书拆解档案，提炼出可迁移的骨架/模式/结构，按赛道归类 | 拆书原始文本、逐章流水、不可迁移的卷幕聚合页（仅作证据不得作消费主条目） |
| 素材库 | 题材深度调研、采风素材，按主题检索，可支撑立项 | 一次性使用的零散素材、无法复用的单项目调研 |
| 文风库 | 书级文风 DNA 档案（书名级 + scene 匹配 + 原文摘录），只描述笔触 | 用 DNA 替换设定/战斗/角色/剧情的越界内容 |

### 3.4 登记规范（manifest 一致性）

- manifest 必须与仓库内实际文件**一一对应**，**禁止登记不存在的资产**。
- 资产 id 全局唯一；`path` 与实际文件路径一致；`version` 与文件元数据头一致。
- `tags` 是检索入口，覆盖赛道/流派/题材，需与消费场景（seed/research 按标签搜索）对齐。

> 注意：`README.md` 与 `文风库/拆书计划.md` 属于**导航/说明类**文件，不视为独立知识资产，`拆书计划.md` 可登记为导航条目，`README.md` 不登记进 manifest。

## 4. 入库流程（如何放进来）

1. 判断资料归属哪一库，通过 3.1 硬性门槛 + 3.2 质量门槛。
2. 生成资产文件（带元数据头），落入对应库路径。
3. 更新 `manifest.json`：登记资产 + 递增 manifest 版本号。
4. 走仓库发布工作流（沿用 `publish.yml` 思路）同步到云端。

---

## 5. 红线（绝对禁止）

- **回传禁令**：任何环节不接收用户产出物入库；项目空间的资产副本不回流缓存、不回传云端。本仓库永远只出不进（官方预制的进，用户的出）。
- **内置保底层不动**：现有 skill 内部技法库保持现状，不因本仓库而不修改、不删除。本仓库是增强，不替代。
- **不得登记不存在资产**：manifest 与实际文件必须严格对应。
- **不得静默降级**：文风 DNA 缺失时不得静默降级，需走外部 DNA 适配而非改剧情。
