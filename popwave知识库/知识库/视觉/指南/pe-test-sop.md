# 漫画测试 SOP（PE Test SOP）

> 画风、排版如何**入库**的唯一门禁。**铁律：任何画风/排版提示词，不经过本 SOP 一张张实测达标，禁止写入基准库。**
> 对应基线库：画风 → `../art-style-baseline.md`（画风PE库）；排版 → `../layout-baseline.md`（排版PE库）。
> 本文件只管"怎么测、怎么记、怎么判、怎么入库"，不写画风内容，也不写排版内容。

## 〇、固定 SOP 铁律（v1.8 新增，老板定调）

> **测试不是每次全新设计，是复用同一套固定脚本跑变体。** 每次测试都现场组装提示词、重定参数 = 不稳定 + 慢。必须走固定 SOP。
>
> **v1.8 关键回归（画风测试素材 = 小说次要视觉锚点）**：老板定调——画风测试**不应用主要人物形象做测试素材**（画风可能满意、但形象不满意，且画风/测试 skill 不是为设计人物而生）；但也**不用与小说无关的中性材料**（ahament 代入感会弱很多）。**画风测试默认用【和小说相关但无关紧要的次要元素**——某个战斗场景/地点（`--scene`）、路人/NPC/龙套（`--side`）。这类元素：和小说强相关 → 保留代入感；无关紧要 → 不承担角色形象验收。**主角/主要角色归 art-bible/oc 环节，用已冻结画风去渲染承担。**

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| 🧪1 | **复用固定脚本 `batch_test.py`** — 画风测试必须用 `../pop-visual-shared/scripts/batch_test.py`（固定模板+并发批量+自动PE日志），禁止现场手写提示词、手动单张生成 | 每次测试变量不隔离、不稳定、慢 |
| 🧪2 | **画风测试默认用小说次要视觉锚点** — `--scene`（战斗场景/地点）+ `--side`（路人/NPC/龙套）注入测试素材，和小说强相关、无关紧要，验证"画风 DNA 是否被执行"。**禁止传 `--character`/`--character-image` 引入主角/主要角色**（画风可能满意但形象不满意，人物形象归 art-bible/oc）；不传则兜底用脚本内置中性素材 | 用主角 → 混入角色形象变量，分不清是画风问题还是形象问题；用与小说无关的中性素材 → ahament 代入感弱 |
| 🧪3 | **默认并发 8 线程** — 批量测变体用 `--concurrency 8`（Seedream 500图/分钟，8线程安全），一次出多张变体；禁止串行逐张跑 | 10张测试从30分钟拖到串行，慢 |
| 🧪4 | **测变体 = 填 `--style-names` 或 `--config`，其余全固定** — 需要测新画风就加画风名/变体，不需要重写脚本或重定参数 | 测试逻辑漂移，无法复现对比 |

**一句话**：画风测试 = `python batch_test.py --style-names "画风A,画风B" --scene "<战斗场景>" --side "<路人>" --out-dir 素材/测试 --seed 20260804`，跑完看 PE 日志 + 图，看"画风"是否达标后入库。**不达标回炉只改一个子维度，再跑同一脚本。**

> 排版测试（M2）与 OC 对齐（M4）因涉及格几何/参考图，暂不纳入 batch_test.py，仍按 §二 控制变量法手工执行。

## 一、核心前提：提示词四层解耦框架

> 老板定调的模型：**提示词是结构化的，管画风、管一页排版、管格内内容、管人设OC对齐的四个模块彼此解耦。**
> 解耦 = 单独改一层，其他三层不动，不因一层改动污染其他层。

每页完整提示词 = 下面 4 个模块 + 共用壳（质量触发词 + 情绪句 + 负面约束）。模块职责分界如下：

| 层 | 代码 | 管什么 | 来源 | 对应 6 段式 PE 落点 |
|:--|:----:|:------|:-----|:-------------------|
| M1 画风 | STYLE | 整体画风底盘（赛璐璐/厚涂/墨线/饱和/分区） | `../art-style-baseline.md` | `Art style:` 段 |
| M2 排版 | LAYOUT | 一页的格子几何（分格百分比/格位/内嵌/叠压） | `../layout-baseline.md` | `Layout:` 段 |
| M3 格内内容 | PANEL | 每个格子里具体画什么（镜头/构图/特效/光影/场景） | `../content-layer.md` | `Panel N:` 段 |
| M4 OC对齐 | OC | 角色长相/服装/发型/眼色与定妆图一致 | `../oc-design-guide.md` + 定妆图 | `Panel N:` 内人物句 + 参考图 |

**四层解耦的直接收益**：
- 换题材 → 只动 M1 的配色占位 + M3 内容，M2/M4 不动。
- 换排版 → 只动 M2，M1/M3/M4 不动。
- M4 一旦定妆图冻结，M3 的人物句只引用冻结锚点，不再重描。

### 1.1 角色定妆照是 M4 的根基，必须对齐 M1 画风

> **铁律：定妆照不是独立画风，必须与 M1 画风基准同源。** 定妆照选错画风 → 图生图时参考图污染一切下游页面 → 全书画风崩坏。

- **定妆照画风 = M1 画风基准（`../art-style-baseline.md` 已入库串）**。禁止用独立/老龄的"角色库风格串"（如早期 Solo Leveling 厚涂串）生成定妆照。
- 定妆照的 PE 同样要入库（见 §四·4.4 定妆照评分表），构成"画风→定妆照→页面"的三层链条。
- 定妆照换画风 = 变更角色版本（v{N+1}），保持五官/服装/发型（角色规格），只换画风底盘串。

## 二、控制变量法测试规则

> 每一轮只测 1-2 个变量，其余模块全部固定。**要提效就加"散布"（同一被测模块多取几个变体），而不是增加变量。**
> **画风（M1）测试强制走 §〇 固定脚本 `batch_test.py`**；排版（M2）/OC（M4）因涉及格几何与参考图，按 2.1 手工控制变量执行。

### 2.1 单轮测试的标准形态

```
固定层（本轮不动）：M1 画风 / M2 排版 / M3 内容 / M4 OC 中，除被测者外的全部
被测层（本轮可动）：1 个模块，取 2~4 个变体（散布）
判定维度：只评被测层对应的维度，其余维度只做"不退化"检查
```

> **画风测试的"固定层"由 `batch_test.py` 内置保证**（固定素材 + 固定模板 + 固定质量触发词），被测层 = 变体列表，一次并发散布 2~4 个画风。这就是"固定 SOP 跑变体"，不是每次全新设计。

### 2.2 常见测试类型

| 测试类型 | 被测层 | 其他层 | 散布示例 | 判定焦点 |
|:---------|:------:|:------|:---------|:---------|
| 画风复现 | M1 | M2/M3/M4 固定 | 赛璐璐 vs 厚涂 vs 赛璐璐+强化墨线 | 画风五维（底色/线稿/饱和/分区/光影） |
| 排版复现 | M2 | M1/M3/M4 固定 | YZ-2 vs YZ-1 vs YZ-8 | 格子几何复现率、位置精度 |
| 内容适配 | M3 | M1/M2/M4 固定 | 同版式不同镜头/构图 | 叙事功能、追读感 |
| OC对齐 | M4 | M1/M2/M3 固定 | 有参考图 vs 纯文字锚点 | 角色一致性 |
| 定妆照对齐 | M1+M4 | M2/M3 固定 | 定妆照画风=元尊V1 vs 其他 | 画风对齐 + 角色规格保持 |

### 2.3 效率策略（散布怎么加 + 并发落地）

- **一轮最多 1 个被测模块，但该模块可一次发散 2~4 个变体**（Seedream 并发生成，成本相同）。
- 变体之间只改被测模块的**一个子维度**（如画风只改"线稿"描述，不连带改"饱和"），保证定位到具体变量。
- 同一轮内不要同时测 M1 和 M2——两个变量同时变，无法归因。
- 轮次之间优先继承上一轮胜出的变体作为本轮固定层，形成收敛链。

**画风（M1）并发落地（固定 SOP + 小说次要视觉锚点只验画风）**：
```powershell
# 从 DNA 库按画风名批量测（传入小说次要素材：战斗场景 + 路人）
python ../pop-visual-shared/scripts/batch_test.py --style-names "国漫玄幻厚涂,暗黑悬疑高对比" --scene "abandoned ancient temple courtyard, cracked stone floor, a single candle-lit altar, drifting dust motes in a beam of light, a torn banner stirring in the wind, no people, no text" --side "an old street vendor in worn robes, weathered face, standing by a wooden stall under a faded awning, neutral expression, no text" --out-dir 素材/测试 --concurrency 8 --seed 20260804

# 自定义变体（JSON 文件，每个变体可精调 dna/constraint/lighting；脚本注入的 scene/side 覆盖变体同名段）
python ../pop-visual-shared/scripts/batch_test.py --config 素材/测试/test_variants.json --out-dir 素材/测试 --concurrency 8
```

> **禁止传 `--character`/`--character-image`**：画风测试不用主角/主要角色（画风可能满意但形象不满意，人物形象归 art-bible/oc）。测试素材 = 小说次要视觉锚点（`--scene` 场景/`--side` 路人），和小说强相关、无关紧要；不传则兜底用脚本内置中性素材。

> 输出：每个变体一张图 + 自动 `pe-log.json`（含固定模板/角色/每个变体完整 prompt，可复现）。**不达标回炉只改变体 JSON 的一个子维度，再跑同脚本，不重写调用。**

## 三、PE 记录规范

> **每一轮测试的完整 PE 必须留档**，这是"可以复现"的根基。禁止只记结论不记 PE。

### 3.1 测试日志（每轮追加）

每条测试记录必须包含：

| 字段 | 说明 |
|:-----|:-----|
| 轮次ID | `R{数字}-{类型}`，如 `R1-排版` |
| 日期 | 测试执行日期 |
| 阶段 | 被测模块（画风/排版/内容/OC） |
| 固定层 | 本轮固定了哪些模块，取值来源 |
| 变体 | 本轮的 2~4 个变体（每个变体给完整 PE 或 PE 差异说明） |
| 参数 | 模型 / 尺寸 / 参考图 / 并发数 |
| 输出 | 每张图路径 |
| 评分 | 按 §四 评分表逐维度打分 |
| 判定 | 通过 / 不通过 / 待调 |
| 结论 | 该变体是否入库，入库到哪个库 |

### 3.2 PE 记录格式（完整提示词必须可复现）

- 每个变体的**完整提示词**（或"在上一变体基础上改哪一句"的 diff）必须落盘。
- 落盘位置：`workspace/{测试目录}/pe-log-{日期}.md`，与生成脚本同目录。
- 入库的 PE 才写入 `../art-style-baseline.md` / `../layout-baseline.md`；未入库的留在日志里。

## 四、评分标准（入库门禁）

### 4.1 画风评分表（M1）

| 维度 | 权重 | 说明 |
|:-----|:----:|:-----|
| 底色 | 20% | 是否达到目标画风的底色类型（赛璐璐平涂/厚涂/纯度） |
| 线稿 | 20% | 书法墨线/粗细顿挫/飞白是否到位 |
| 饱和 | 20% | 高饱和强对比是否符合 |
| 色彩分区 | 20% | 对角色彩分区是否贯穿全页、对角对撞 |
| 光影 | 20% | 戏剧光/体积光是否到位 |
| **总评** | 100% | **≥4.5/5 才可入库** |

### 4.2 排版评分表（M2）

| 维度 | 权重 | 说明 |
|:-----|:----:|:-----|
| 结构复现 | 40% | 格数/格位/相对尺寸是否复现目标模板（≥90%） |
| 位置精度 | 30% | 内嵌/叠压/三列等复杂结构的位置是否精确 |
| 分格清晰 | 30% | 格线/留白是否干净，不糊格 |
| **总评** | 100% | **≥4.5/5 才可入库** |

### 4.3 判定规则

- **两层独立判定**：画风和排版分别打分，分别入库。**画风达标 ≠ 排版达标**，互不自动通过。
- 不达标变体：记录失败原因，调整后的下一轮只能改被测层的一个子维度，禁止一次性大改。
- 入库后：在对应库中标注"已入库 + 验证图 + 轮次ID"，形成可追溯链。

### 4.4 定妆照评分表（M1+M4）

| 维度 | 权重 | 说明 |
|:-----|:----:|:-----|
| 画风对齐 | 30% | 定妆照画风是否与 M1 画风基准一致（赛璐璐/墨线/饱和/分区） |
| 角色规格保持 | 40% | 五官/发型/服装/身形是否与角色规格表一致（≤1处偏差） |
| 双角度连贯 | 20% | front 与 side 是否为同一个人（轮廓/发型/服装连贯） |
| 角色记忆点 | 10% | 标志性特征是否清晰（读者0.3秒认出） |
| **总评** | 100% | **≥4.5/5 才可入库**，成为该角色新版本定妆图 |

> 定妆照达标后，其完整 PE 写入 `../art-style-baseline.md`（定妆照PE区）或角色库冻结提示词，作为后续页面图生图的参考真相源。

## 五、入库流程（GATED）

```
新增画风/排版候选
   │
   ▼
① 从目标作品提取特征（画风五维 / 排版几何）
   │
   ▼
② 组装候选PE（M1 或 M2 变体，其余层固定）
   │
   ▼
③ Seedream 实测（画风用固定脚本，并发散布 ≥2 变体；排版单张手工）
   │
   ▼
④ 按 §四 评分表打分
   │
   ├── 不达标（<4.5）→ 记录失败→ 回到②，只改被测层一个子维度
   │
   └── 达标（≥4.5）→ 记录轮次ID+完整PE+验证图
        │
        ▼
⑤ 写入 ../art-style-baseline.md（画风） 或 ../layout-baseline.md（排版）
        │
        ▼
⑥ 标注：已入库 + 验证图 + 轮次ID + 生成参数
```
