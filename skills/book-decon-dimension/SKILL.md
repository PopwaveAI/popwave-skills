# book-decon-dimension · 单书拆解执行（第零期 T1.2）

> 执行 skill：先做 **L1 批次拆解**（八维全提 + 7 项门禁，每批结束原子写「批次完成标志」），门禁全通过后再做 **L2 六模块成品**（六模块 + 爽点 + 立项 L0-L3 + 根索引与变更记录）。规则参考 `pop-decon-dimension` 复刻而来，但运行时**不读取、不依赖、也不修改** `popwave-skills` 的原 skill；分章产物只从源包取，本 skill 不实现第二套分章。

## 做什么

| 输入 | 来源 | 输出 | 下游 |
|:--|:--|:--|:--|
| 源包路径、已冻结的范围、重点、交付物与档位、输出目录 | `book-decon` 入口传入 | **完整交付**：批次档案 + 每批「批次完成标志」+ L2 六模块成品（含爽点、立项、根索引、变更记录）；**骨架交付**：骨架档案 + 标志 + `骨架/` 三份 | 宿主（按批次完成标志判定收敛）、人工浏览、写作项目导入快照 |

**执行模式**：入口传入路径与范围，本 skill 直接执行。L1 分批精读可派子 agent 回报笔记、由主 agent 汇总写盘；L2 叙事流写作与写盘由主 agent 串行执行。**子 agent 永不写文件**。

**硬流程**：L1 批次拆解（门禁）→ 门禁收敛 → L2 成品整合。**禁止跳过 L1 直接写成品。**（`processingProfile = outline` 时**不走上述两层**，改走「骨架交付」单层规程，见下节；骨架交付不是"更快的六模块"。）

## 两层结构

| 层 | 载体 | 性质 | 检查 |
|:--|:--|:--|:--|
| **L1 事实层** | 版本目录 `_temp/batches/V{n}_B{m}_chXXX-YYY.md` 批次档案 + 同目录同名 `*.批次完成标志.json` | 事件链、八维提取、🔒量化、ch 锚点；内部依托 | **7 项门禁，一条不减；任一项不过即失败** |

## 怎么操作（规程全内联）

### L1 批次拆解（地基）

**Step 1 预扫描（一次，全程共享）**：读本次范围的前 3-5 章原文，提取 5 张术语表并记为临时笔记——人名表、地名表、等级名表、势力名表、物品名表。

**Step 2 生成锚点池**：以术语表为补充检索词，对本次范围的章做联合检索，命中章去重成锚点池。文风维度**不走检索**，按场景定向采样（日常、战斗、情感爆发、环境、严肃、高潮，每种 2-3 章）。

**Step 3 切批**：**唯一依据是源包根的 `批次计划.json`**，不另行切批。口径全仓统一为**约 30 章/批**：质量优先（`processingProfile = deep`）每批不超过 20 章；卷级骨架（`processingProfile = outline`）每卷不超过 40 章；任何档位不超过 40 章上限。批次档案写入版本目录 `_temp/batches/V{n}_B{m}_chXXX-YYY.md`。

**Step 4 分批精读八维提取**：每批读该批连续章节（每章只读一次），按**八维全提**产出笔记，再由主 agent 汇总写入批次档案：

| # | 维度 | 提取内容 |
|:-:|:--|:--|
| 1 | 剧情 | 主线推进、支线铺线、伏笔埋设与回收、卷内转折 |
| 2 | 人物 | 挂行为证据的性格点、新出场角色、弧线 |
| 3 | 力量 | 力量变化、新能力、位阶/数值 |
| 4 | 世界观 | 地理、势力、物品、历史增量 |
| 5 | 爽点 | 名场面、打脸、反转 |
| 6 | 情感 | 关系演变、信任与背叛节点 |
| 7 | 文风 | 笔触、句式、叙事距离、对白风格 |
| 8 | 功能位（原子候选） | 功能义名（≤6 字，不含人名地名）+ 干什么活 + 服务哪个爽点；只做事件级候选标注 |

批次档案结构以 `references/批次档案格式.md` 为准，要点为：批头（批次号、卷号、章范围、卷名、**主角状态快照**）→ 预扫描术语表与锚点池（5 张术语表逐条标条数；锚点池写明总命中章数、三段覆盖、**各模块命中章数**与文风采样章）→ 分场事件链表（每事件一行：事件、转折类型、类型、ch、参与角色、原文定位到段）→ **八维提取子节（缺一不可）** → 关键数据 🔒 块（一行式摘要 + 原文定位，禁止全文引用）→ 爽点与钩子（钩子强度）→ 人物关系变化（仅确有时写）→ 证据自计 → 本批自检（7 项门禁结论须与标志一致）。

**提取纪律**：每条笔记带 `(chXXX)`；量化数值原文有则摘录并标 🔒；原文未展开标「原文未展开」；某维度本批无内容标「本批无XX」是合法标注；**禁止凭记忆或书评补充原文没有的内容**。

**7 项门禁（L1 硬性检查，一条不减；`standard` / `deep` 完整交付专用，骨架交付见下节 6 项）**：

| key | 门禁 | 标准 |
|:--|:--|:--|
| `glossary` | 术语表完整 | 人名、地名、等级、势力、物品 5 表均提取 |
| `anchorPool` | 锚点池覆盖（每批硬底线） | 命中章 ≥ max(20, 本批章数 × 60%)；覆盖开头、中段、结尾；且每个在大纲中有内容的模块至少命中 1 章（防整维空白）。**每批不按模块下限卡**——各模块命中率属 L1 收敛期判定，见 Step 6 |
| `schema` | schema 完整 | 批次档案含八维提取子节；每事件带 ch 锚点 |
| `evidenceDensity` | 证据密度 | 每批证据条目不少于章数的 2 倍 |
| `quantified` | 量化无丢失 | 关键数值 🔒 必须标注，不得省略 |
| `noFabrication` | 不编造 | 无证据且未标「原文未展开」即为编造，禁止 |
| `traceable` | 章节号可回溯 | 所有结论可回到原文对应章 |

**半成品禁令**：任一项门禁不过，直接退回补拆该批，**不得把残缺结果带进 L2**。

**Step 5 每批结束原子写「批次完成标志」**：批次档案写盘后，立刻在同一目录写标志文件。字段、逐项判读口径、`status` 判定与原子写要求见 `references/批次完成标志.md`。要点：

- 字段：`batchId`、`status`（`passed | failed | partial`）、`chaptersCovered`、`evidenceCount`、`checks`（上表 7 项）、`artifacts`、`warnings`；
- 7 项门禁任一项不过 → `status` 为 `failed`，**禁止把该批结果带进 L2**，并回退补拆该批（不影响其它批次的复用）；
- 原子写：先写临时文件再原子替换，杜绝半写状态；标志文件与批次档案同名同目录。

**Step 6 L1 收敛判定**：只有当本次范围内**每一批**的标志都为 `passed`、批次连续覆盖全部范围，才允许进入 L2。宿主同样按标志机械判定，不解析 run 事件内容。任何一批 `failed` 或 `partial` → 停在 L1，先补拆。

**模块命中率在收敛期判定（不按批卡）**：每批只守上面那条硬底线；各模块在本次范围内的锚点命中章占比，在 L1 收敛时按下表判定，不达标先补拆该模块的薄弱区间，而不是把单批判失败。理由：力量体系与世界观属设定释放型，铺垫期单批天然命中偏薄，按批硬卡会误杀整批、把这一维的时序性当成质量事故。

| 模块 | 本次范围 ≥ 20 章 | 不足 20 章（试拆范围） |
| --- | --- | --- |
| 剧情、角色与势力 | ≥ 50% | ≥ 40% |
| 世界观、力量与战斗、赛道特色 | ≥ 25% | ≥ 20% |
| 文风（DNA） | 不按比例：六类场景（日常、战斗、情感爆发、环境、严肃、高潮）各 ≥ 2 章采样 | 同左 |

命中章占比 = 该模块在锚点池中的命中章数 ÷ 本次范围章数；判定结果写进收敛记录，与各批标志一并留痕。该表只作为锚点覆盖的收敛判据，不放宽其它 6 项门禁。

### L2 成品整合（目标）

**Step 7 产出顺序与重点接线**：按 `focusDimensions` 决定六模块的**产出顺序与深度**（被选中的重点对应模块先产出并加深），但**不增不减模块**。默认顺序：

`剧情库（分卷与动力引擎）→ 角色与势力库 → 力量与战斗 → 世界观 → 赛道特色 → 文风DNA → 爽点.md → 立项/ → 索引.md → CHANGELOG.md`

**Step 8 依序产出成品**：**按模板包 `<book-decon-dim-templates 包根>/templates/` 下对应 `.tpl.md` 的「一级小节骨架」产出**（模板未覆盖的文件不得在本步产出），读 L1 批次档案（必要时精读原文）完成叙事流整合并写入。

| 赛道特色 | `名词表.md`、`命名规则.md`、`类型风味基线.md` | 本书独有名词与术语对照；命名机制与格式规律；赛道风味基线（供跨书复刻） |

| 收尾 | `爽点.md`、`立项/`、`索引.md`、`CHANGELOG.md`、`_meta/templates.json` | 爽点：名场面（叙事式）、爽感公式、压力机制、分布密度；立项：`00-L0核心卖点`、`01-L1命运图`、`02-L2命运图plus`、`03-L3全书大纲`、`04-逆向破解`（消费六模块综合，缺一即视为拆书未完成；范围非全书时 L3 记 degrade）；根 `索引.md`：覆盖范围声明 + 六模块导航 + 卷与分卷导航 + 主线/支线/伏笔检索协议 + 降级与待扩展清单；CHANGELOG：变更记录；`_meta/templates.json`：模板 id 与版本、降级与待扩展留痕 |

**L2 成品检查（每模块自检）**：

| # | 检查项 | 标准 |
|:-:|:--|:--|
| 1 | 叙事流具名讲透 | 可当百科读，不是证据清单平铺 |
| 2 | 证据归表尾 | ch 锚点归入表格列或段尾证据行，**正文不内联 chXX** |
| 3 | 量化标 🔒 | 关键数值不省略、不发明 |
| 4 | 与 L1 一致 | 成品证据回溯到批次档案，不自行推翻 |
| 5 | 结构命中 | 命中模板包 `<book-decon-dim-templates 包根>/templates/` 同名 `.tpl.md` 的一级小节骨架（上表仅作速览对应） |
| 6 | 标题洁净 | H1 只留内容词，不挂书名前缀与格式后缀 |
| 7 | 实例可溯 | 表格里填的「实例」必须是原文出现过的串，且挂的 ch 指向的章里真能找到它；**模型先验里的类型文学通用词（本书没写过的词）不得充当实例** |

> 第 7 条的背景：模板要求「每条规律至少有一个书中实例支撑」，但**当该类目在本书天然为空时**（例：本书给招式起名很少），模板没有给出「空」的写法，于是容易顺手填一个同类型小说的常见词充数。判据是硬性的——**该类目在本次范围内不存在实例时，实例列写「本范围无此类实例」，不得为凑格式造一个**；推不出规律时写 `待扩展：{类目}格式规律（原因：样本不足）`。这两种写法都是合法交付，编造实例不是。

**Step 9 收尾与模板留痕**：先定清单，再写它的载体——顺序不可颠倒：

1. `爽点.md`（消费六模块综合）→ `立项/`（L0 → L1 → L2 → L3 → 逆向破解，按序产出）。
2. **定稿降级与待扩展清单**：逐条写出 `targetFile` / `section` / `kind`（`degraded`＝未产出或整篇降级，`pending`＝待扩展）/ `reason`。**这一步产出的清单就是唯一权威源**，后面两份载体照它抄。
3. 根索引 `索引.md`（导航各卷与各模块，与实际产物对齐）：其「降级与待扩展清单」**逐条照抄第 2 步**。
4. `CHANGELOG.md`（变更记录）：其「降级与待扩展」表**逐条照抄第 2 步**。
5. **`_meta/templates.json`（本步最后一件，收口留痕）**：按「模板与稳定契约」节的字段记录本次实际使用的模板 `templateId` 与 `templateVersion`，并把第 2 步那份清单原样写进 `gaps`。

纪律：

- **禁止概述写法**：不得用 `世界观/*`、`力量与战斗/*`、`立项/*` 这类通配或合并写法代替逐条列出——`索引.md` 与 `CHANGELOG.md` 的每一行，都必须能在 `gaps` 里找到同名 `targetFile` + 同 `kind` 的一行，反之亦然（三处逐条相等，不是「大致一致」）。
- 降级与待扩展**不得静默**：三处任一漏登即视为交付不合格。
- 错误顺序（先写 `索引.md`/`CHANGELOG.md`、最后才想清单）必然导致漏登——两份载体写完时清单还不存在，只能凭记忆罗列。

范围非全书时，`立项/03-L3全书大纲.md` 记降级不产出；`立项/01-L1命运图.md` 的终点与最大反转、`立项/02-L2命运图plus.md` 的未覆盖卷一并记入 `gaps`（`kind: pending`）。

部分范围的结果必须在标题与索引中标注覆盖范围；不得把未读章节写成全书结论；跨库沉淀（卖点方向库、剧情周期表）本阶段只生成候选并记录待处理状态，不写入公共库。

### 骨架交付（processingProfile = outline）

**定位：`outline` 是另一种交付物，不是"更快的六模块"。** 它只交付**卷级骨架**，只做**按卷抽样**的粗提取，**不做八维全提、不做 L2 六模块成品、不产出立项**，也不走完整 7 项门禁（骨架用 **6 项骨架门禁**）。骨架未覆盖的章节一律视为**未取证**。凡需要六模块的场景，必须另起一次 `standard` / `deep` 拆解（新建版本）。规程与产出契约的完整版见 `references/骨架交付.md`。

**Step S1 按卷抽样（不得整卷跳过）**：

| 项 | 口径 |
|:--|:--|
| 抽样单位 | **卷**：逐卷抽样，一卷不漏；**不得整卷跳过** |
| 抽样比例 | 每卷抽 **30%–40%** 的章（不足 1 章按 1 章计，按四舍五入取整） |
| 必含章 | 每卷的**首章**、**末章**与**卷末钩子章**必须命中（钩子章与末章重合时视为命中同一章，但须在档案中注明） |
| 剩余名额 | 满足必含章后，按卷内均匀分布补齐至比例下限，优先覆盖卷内转折/高潮段 |
| 声明 | 抽样比例、抽样章清单与**被跳过章节区间**必须写入骨架档案，并在 `骨架/_未取证声明.md` 汇总 |

**Step S2 提取范围（只做卷级骨架，不扩维、不落六模块）**：

| # | 提取项 | 内容 |
|:-:|:--|:--|
| 1 | **卷级九字段骨架**（每卷一套） | 力量范围、动力引擎、战斗系统、地理、势力、危机、敌人生态、矛盾轴、卷末边界 |
| 2 | 主线链 | 卷内主线链条目 + 卷间衔接（下一卷起点承接上一卷卷末边界，卷间必须连续） |
| 3 | 主要角色 | 本卷主要登场角色及其功能 |
| 4 | 力量体系要点 | 本卷力量体系增量要点 |
| 5 | 世界观要点 | 本卷世界观增量要点 |

**Step S3 取证纪律**：

- 每条骨架条目带 `(chXXX)` 锚点（可多章并列）；
- 抽样**未覆盖**的章节如需推断，必须显式标注「**抽样未取证**」，**不得**凭记忆、书评或后文补全；
- 未被抽样的章节内容**不得**写成确定结论；
- 骨架不强制量化 🔒（量化门禁属完整交付）。

**Step S4 骨架 6 项门禁（一条不减，与完整交付是两套）**：

| key | 门禁 | 标准 |
|:--|:--|:--|
| `glossary` | 核心表非空 | **人名 / 势力 / 力量** 3 张核心表非空（骨架不要求 5 表） |
| `outlineCoverage` | 骨架覆盖 | 每卷都有骨架条目；主线链**卷间连续**、无断点 |
| `skeletonFields` | 九字段齐全 | 每卷九字段（力量范围/动力引擎/战斗系统/地理/势力/危机/敌人生态/矛盾轴/卷末边界）齐全 |
| `samplingDeclared` | 抽样声明 | 已声明抽样比例与**被跳过章节区间** |
| `noFabrication` | 不编造 | 无证据且未标「抽样未取证」即为编造，禁止 |
| `traceable` | 可回溯 | 所有结论可回到原文对应章；**允许以「抽样未取证」标注形式回溯** |

**骨架不做 `evidenceDensity` 与 `anchorPool` 的按章比例要求**——没有"每批证据条目 ≥ 章数 × 2""命中章 ≥ max(20, 本批章数 × 60%)"这类按章门槛；结构完整性由 `skeletonFields` 承接，因此骨架也**不设 `schema` 与 `quantified`**。完整交付的 7 项门禁原样保留、不因骨架而减少。

**Step S5 产出契约**：只写版本目录 `骨架/` 下的三份，**不产出六模块与立项**（不写 `剧情库/` 等六模块目录、不写 `爽点.md`、不写 `立项/`）：

| 文件 | 内容 |
|:--|:--|
| `骨架/卷级骨架.md` | 逐卷卷级九字段骨架 + 主线链 + 主要角色 + 力量体系要点 + 世界观要点，条目带 `(chXXX)` |
| `骨架/索引.md` | 分卷导航 + 主线链检索 + 抽样章清单 + 覆盖范围声明 |
| `骨架/_未取证声明.md` | 抽样比例、被跳过章节区间、逐项「抽样未取证」清单 |

**归档单位与命名**：骨架以**卷**为归档单位，骨架档案落 `_temp/batches/V{卷序}_SK_ch{起3位}-{止3位}.md`，同名写 `*.批次完成标志.json`（`batchId` 同档案名）；单卷超过 40 章上限时按 `批次计划.json` 拆成多份同卷骨架档案，卷级九字段在 `骨架/卷级骨架.md` 中**按卷合并**。骨架档案的必填节见 `references/批次档案格式.md`。

**Step S6 复用契约**：

1. 骨架产物**未取证**，**不得作为 L2 证据来源**，也不得当作六模块成品的事实地基；
2. 后续对**同一范围**做精拆（`standard` / `deep`）时**新建版本目录**，并把骨架版本记为**父版本**，在精拆的批次档案与变更记录中**标明"输入为未取证骨架"**；
3. 精拆**不得**直接复制骨架结论充数：骨架条目只作线索，必须回到原文取证后才可写入六模块；
4. 骨架版本自身**不因精拆而被覆盖或改写**，两份版本并存留痕。

### 续拆（在同一批材料上续写）

续拆时**先读、后写**，顺序固定：

1. 读**父版本产物**文件树；
2. 读根索引与各模块索引；
3. 读**变更记录**（父版本 `CHANGELOG.md`）；
4. 读**运行日志**（每批运行日志与逐批「批次完成标志」）；
5. 读 `检查点.json` 与已通过 L1 的批次清单。

然后在**同一批材料上续写**：原文与章节索引沿用，已通过 L1 门禁的章节**不重跑**；批次档案与标志按批补齐。交付物是**完整成品加变更记录**，**不交付增量补丁**。

**父版本为骨架版本时（`processingProfile = outline`）**：骨架产物是**未取证**的，不构成已通过的 L1 事实层——不存在"已通过门禁的章节"可复用，精拆必须**新建版本**、以骨架版本为父版本，在档案中标明「输入为未取证骨架」，并对本次范围**按完整流程重新精读取证**；骨架条目只作线索，不得直接搬进六模块。

与父版本结论不一致时，必须二选一处理并留痕：

| 情形 | 处理 |
|:--|:--|
| **修正** | 新证据推翻了旧结论 → 就地更新成品，并在变更记录写明修正点与依据章节 |
| **冲突** | 两份结论都有证据、无法裁决 → 两份并存并标记来源（父版本 / 本次），在变更记录登记，不静默覆盖 |

退回全量重跑的条件（任一命中）：父版本存在未通过门禁的批次、缺运行日志、Skill 版本变化、源包指纹变化。

### 章节边界：不猜测

L0/L1 遇到**未识别章节边界**时**不自行猜测**：

- 触发线：`manifest.agentArbitrationRequired` 为 `true`、`confidence` < 0.6、`quality.unrecognizedHeadings` 非空、或存在未收敛的缺号/重复/乱序；
- 动作：**停止并转人工确认**（或由入口回退）。不自行合并、不自行拆分、不凭阅读直觉补边界、不改写正文、不写源包；
- 边界修订只允许由分章脚本以 `--revisions` 回灌重跑后生效，本 skill 只消费修订后的源包。

## 红线（断裂级）

1. **门禁不过就进 L2** — 完整交付 7 项门禁任一项失败即 `failed`，禁止携带半成品写成品；失败只补拆对应批次。（骨架交付对应 6 项骨架门禁，未全过即不写 `骨架/` 产物。）
2. **两套门禁各自一条不减** — 完整交付守 **7 项**，骨架交付守 **6 项**；不得按重点、档位或时间压力删减任何一项；**不得用完整 7 项去卡骨架批次，也不得用骨架 6 项去放行六模块**；`focusDimensions` 不得反向裁剪 L1 八维提取。
3. **跳过 L1 直写成品** — 必须走批次精读（直读原文），禁止无证据直接写成品。
4. **凭空发明内容** — 无 ch 锚点且未标「原文未展开」即为编造；禁止凭记忆与书评补充。
5. **量化数值丢失** — 关键数值 🔒 必须标注。
6. **正文内联 chXX** — ch 锚点归表格列或段尾证据行。
7. **单批超限** — 每批不超过 40 章；超出则按 `批次计划.json` 拆批。
8. **未识别边界自行猜测** — 边界未收敛时停止转人工，不猜、不改正文、不写源包。
9. **不写源包、不改正文** — `manifest.json`、`合并章节索引.json`、`指纹.json`、`批次计划.json`、`chapters/` 一律只读。
10. **不引用不存在的路径** — 特别是 `_temp/chapters/` 这类幽灵引用；分章产物只走源包 `chapters/`，批次档案只走版本目录 `_temp/batches/`。
11. **标志不原子写 / 用自然语言代替字段** — 标志必须按 `references/批次完成标志.md` 的字段机械可判读。
12. **续拆覆盖父版本** — 续拆只在新版本目录写，父版本产物与用户已编辑成品不被覆盖。
13. **outline 越界交付** — 骨架交付（`outline`）**不得产出六模块、`爽点.md`、`立项/`**，也不得对外声称"六模块拆解完成"；需要六模块必须**新建版本**另跑 `standard` / `deep`。
14. **骨架充作六模块证据** — 骨架产物**未取证**，不得作为 L2 证据来源或六模块事实地基；后续对同范围精拆须**新建版本**、以骨架版本为**父版本**，并在档案中标明「输入为未取证骨架」，不得直接复制骨架结论充数。
15. **整卷跳过** — 骨架抽样必须逐卷进行，**不得整卷跳过**；必含章（卷首/卷末/卷末钩子章）未命中即不通过 `samplingDeclared` 前不得落 `骨架/` 产物。
16. **脱离模板自造骨架 / 契约变更只改一边** — L2 成品必须按模板包 `<book-decon-dim-templates 包根>/templates/` 对应 `.tpl.md` 的一级小节骨架产出（模板未覆盖的文件不得产出）；改目录名、文件名、一级小节骨架属契约变更，必须**同时**改模板（升 `template_version`）、同步文档与入口核对口径、并在 `CHANGELOG.md` 留痕，只改一边即视为断裂。
17. **降级与待扩展静默** — 未产出、降级、待扩展的文件必须在 `_meta/templates.json` 的 `gaps` 登记，并与根 `索引.md` 降级清单、`CHANGELOG.md` 三处一致；缺 `_meta/templates.json` 视为 L2 未收尾。
