# 批次完成标志 · batch-completion-flag（第零期 T1.2）

> 定位：L1 事实层的**收敛契约**。每个批次结束时由执行 skill 原子写出，宿主据此机械判定「能否进下一批 / 能否进 L2」，**不依赖解析 run 事件内容**。
>
> 本文件管收敛契约与字段：字段与 `apps/desktop/docs/book-deconstruction-prd.md` 第 8 节一致；键名统一 camelCase，出现下划线即为非法。批次档案该长什么样见同目录 `批次档案格式.md`。
>
> **`checks` 按交付物分两套**：完整交付（`processingProfile = standard / deep`）用 **7 项**，骨架交付（`processingProfile = outline`）用 **6 项**。两套键名不同、各自一条不减，**不得混用、不得互判**。

---

## 1. 产出时机与位置

| 项 | 口径 |
|:--|:--|
| 时机 | 该批**批次档案写盘之后、开始下一批之前**；一批一写，不攒批 |
| 文件名 | `<批次档案文件名>.批次完成标志.json`，例：完整交付 `V1_B1_ch001-030.批次完成标志.json`；骨架交付 `V1_SK_ch001-048.批次完成标志.json` |
| 位置 | 与批次档案同目录：版本目录 `_temp/batches/` |
| 数量 | 完整交付：每个 L1 批次恰好一份，批次数与源包 `批次计划.json` 的生效档位一致；骨架交付：每卷恰好一份（单卷超 40 章上限时按 `批次计划.json` 拆成多份同卷标志），`batchId` 与骨架档案同名 |
| 写入方式 | **原子写**：先写同目录临时文件（如 `<名称>.tmp`），再原子替换到目标名；禁止直接覆盖目标文件造成半写状态 |
| 幂等 | 同一批重跑时覆盖同名标志，不追加、不新建第二份 |

**只允许引用真实存在的路径**：`_temp/batches/`（批次档案与标志）、源包 `chapters/`（正文）。**禁止引用 `_temp/chapters/`** 这类不存在的路径。

## 2. 字段

标志的 `checks` 按**交付物分两套**（完整交付 7 项 / 骨架交付 6 项），其余字段两种交付共用。

**完整交付（`processingProfile = standard / deep`）的标志示例**：

```jsonc
{
  "batchId": "V1_B1_ch001-030",
  "status": "passed | failed | partial",
  "chaptersCovered": [1, 30],
  "evidenceCount": 96,
  "checks": {
    "glossary": true,
    "anchorPool": true,
    "schema": true,
    "evidenceDensity": true,
    "quantified": true,
    "noFabrication": true,
    "traceable": true
  },
  "artifacts": ["_temp/batches/V1_B1_ch001-030.md"],
  "warnings": []
}
```

| 字段 | 类型 | 语义 | 约束 |
|:--|:--|:--|:--|
| `batchId` | string | 批次标识，与批次档案文件名一致（`V{卷}_B{批序}_ch{起}-{止}`） | 非空；`V/B` 序号与批次档案对齐 |
| `status` | enum | `passed` / `failed` / `partial` | 判定规则见第 4 节 |
| `chaptersCovered` | number[2] | 本批覆盖的**全书序号闭区间** `[起, 止]` | 起 ≤ 止；落在源包章总数内；与相邻批次连续不重叠 |
| `evidenceCount` | number | 本批证据条目总数（完整交付＝八维条目 + 事件链条目；骨架交付＝骨架条目数） | 非负整数；完整交付用于对照门禁 `evidenceDensity`，骨架交付仅供可见性、**不参与任何门禁** |
| `checks` | object | 该交付物对应门禁的布尔结果，键固定为第 3 节对应那一套 | 完整交付 7 键、骨架交付 6 键，各自齐全、**一条不减**，不得混用 |
| `artifacts` | string[] | 本批产物的路径清单 | 相对版本目录；至少含批次档案；路径必须真实存在 |
| `warnings` | string[] | 不阻断但需可见的质量提示 | 无告警写 `[]`，不写 `null`、不省略 |

**骨架交付（`processingProfile = outline`）的标志示例**：

```jsonc
{
  "batchId": "V1_SK_ch001-048",
  "status": "passed | failed | partial",
  "chaptersCovered": [1, 48],
  "evidenceCount": 24,
  "checks": {
    "glossary": true,
    "outlineCoverage": true,
    "skeletonFields": true,
    "samplingDeclared": true,
    "noFabrication": true,
    "traceable": true
  },
  "artifacts": ["_temp/batches/V1_SK_ch001-048.md"],
  "warnings": []
}
```

`checks` 的键名与门禁一一对应，**不允许改名、合并或省略**：

- **完整交付（7 项）**：`glossary`、`anchorPool`、`schema`、`evidenceDensity`、`quantified`、`noFabrication`、`traceable`；
- **骨架交付（6 项）**：`glossary`、`outlineCoverage`、`skeletonFields`、`samplingDeclared`、`noFabrication`、`traceable`。

两套键集合互斥：骨架标志**不得**出现 `anchorPool` / `schema` / `evidenceDensity` / `quantified`，完整交付标志**不得**出现 `outlineCoverage` / `skeletonFields` / `samplingDeclared`。宿主按交付物校验键集合，多键或少键都视为非法标志。

## 3. 门禁的判读口径（两套）

### 3.1 完整交付（`standard` / `deep`）· 7 项

| key | 门禁 | 通过判据（全部为真才 `true`） | 失败后果 |
|:--|:--|:--|:--|
| `glossary` | 术语表完整 | 人名、地名、等级、势力、物品 5 张术语表均提取且非空 | 退回补拆该批 |
| `anchorPool` | 锚点池覆盖（每批硬底线） | 命中章 ≥ max(20, 本批章数 × 60%)；覆盖开头、中段、结尾；且每个在大纲中有内容的模块至少命中 1 章（防整维空白） | 退回补拆该批 |
| `schema` | schema 完整 | 批次档案含八维提取子节（八节齐全）；每条事件与结论都带 ch 锚点 | 退回补拆该批 |
| `evidenceDensity` | 证据密度 | 本批证据条目数 ≥ 本批章数的 2 倍（即 `evidenceCount ≥ 2 × 本批章数`） | 退回补拆该批 |
| `quantified` | 量化无丢失 | 原文出现的关键数值均已标注 🔒，未省略 | 退回补拆该批 |
| `noFabrication` | 不编造 | 不存在「既无 ch 锚点、又未标『原文未展开』」的条目 | 删除无据条目后补拆 |
| `traceable` | 章节号可回溯 | 所有结论都能回到原文对应章 | 退回补拆该批 |

判定纪律：

- 门禁结果为 **布尔**，不用自然语言描述、不用分数、不用「基本通过」这类模糊表述；
- 无证据的条目不能靠「标了原文未展开」蒙混 `noFabrication`：凡原文确有的结论必须给出 ch 锚点；
- 某维度本批确实无内容时，档案里写「本批无XX」是**合法标注**，不影响 `schema` 与 `noFabrication`。

> **模块命中率不在本项判定。** 各模块在本次范围内的锚点命中章占比属 L1 收敛期判据（见 `SKILL.md` 的 Step 6 表），不按批进入 `checks`。单批因设定铺垫期（力量体系、世界观尚未展开）导致某模块命中偏薄时，本项仍可判 `true`，不得据此把整批判 `failed`；收敛期不达标时补拆的是该模块的薄弱区间，不是重跑整批。

### 3.2 骨架交付（`outline`）· 6 项

| key | 门禁 | 通过判据（全部为真才 `true`） | 失败后果 |
|:--|:--|:--|:--|
| `glossary` | 核心表非空 | **人名、势力、力量** 3 张核心表非空（骨架不要求 5 表） | 退回补抽该卷 |
| `outlineCoverage` | 骨架覆盖 | 每卷都有骨架条目；主线链**卷间连续**、无断点 | 退回补抽该卷 / 补卷间衔接 |
| `skeletonFields` | 九字段齐全 | 每卷九字段（力量范围/动力引擎/战斗系统/地理/势力/危机/敌人生态/矛盾轴/卷末边界）齐全 | 退回补齐该卷九字段 |
| `samplingDeclared` | 抽样声明 | 已声明抽样比例（30%–40%）与**被跳过章节区间**，且必含章（卷首/卷末/卷末钩子章）已命中 | 退回补声明 / 补抽必含章 |
| `noFabrication` | 不编造 | 不存在「既无 ch 锚点、又未标『抽样未取证』」的条目 | 删除无据条目后补抽 |
| `traceable` | 可回溯 | 所有结论都能回到原文对应章；**允许以「抽样未取证」标注形式回溯** | 退回补抽该卷 |

判定纪律（骨架专有）：

- **不做按章比例要求**：**不采用 `evidenceDensity` 与 `anchorPool`**，即没有「证据 ≥ 章数 × 2」「命中章 ≥ max(20, 章数 × 60%)」这类按章门槛；
- **不设 `schema` 与 `quantified`**：结构完整性由 `skeletonFields` 承接，骨架不强制量化 🔒；
- `noFabrication` 的合法免责标注是「**抽样未取证**」（不是完整交付的「原文未展开」）：抽样未覆盖的章节不得写成确定结论，标了「抽样未取证」的推断不判编造；
- **不得整卷跳过**：任一必含章未命中的卷，`samplingDeclared` 判 `false`；
- **不得把骨架门禁当完整门禁用**：骨架批次不因缺 `anchorPool` / `evidenceDensity` 而失败，也不得用完整 7 项去卡骨架批次。

## 4. `status` 判定规则

`passed` 判定**按交付物取对应那一套 `checks`**，只判该套项，另一套项不参与、也不得出现在标志里：

| 交付物 | `processingProfile` | 参与 `passed` 的 `checks` 项 | 项数 |
|:--|:--|:--|:-:|
| 完整交付 | `standard` / `deep` | `glossary`、`anchorPool`、`schema`、`evidenceDensity`、`quantified`、`noFabrication`、`traceable` | 7 |
| 骨架交付 | `outline` | `glossary`、`outlineCoverage`、`skeletonFields`、`samplingDeclared`、`noFabrication`、`traceable` | 6 |

| 取值 | 判定条件 | 宿主可做的动作 |
|:--|:--|:--|
| `passed` | 该交付物对应的 `checks` **全为 `true`**（完整交付 7 项 / 骨架交付 6 项），且 `artifacts` 清单里的文件都真实存在 | 放行：可进下一批；**完整交付**全部批次 `passed` 且范围连续覆盖时可进 L2；**骨架交付**全卷 `passed` 时可交付 `骨架/` 三份产物 |
| `failed` | `checks` 中**任意一项为 `false`** | 阻断：**完整交付**禁止把该批结果带进 L2；**骨架交付**禁止产出 `骨架/` 产物。只补拆 / 补抽该批（卷），已通过批次可复用 |
| `partial` | `checks` 未被击穿，但本批未按范围完整覆盖（完整交付：有章未精读、字段待补；骨架交付：有卷未抽或必含章未命中） | 视为未通过：补到覆盖完整后再判；不得当 `passed` 用 |

补充规则：

- **`passed` 与 `warnings` 可以并存**：有告警不阻断，但告警必须展示给用户，不能悄悄当作通过；
- 出现 `failed` / `partial` 时，**不得**把 `status` 改写成 `passed` 来放行；
- 批次顺序与覆盖：本次范围内每批的标志必须**连续覆盖**且不重叠，缺标志等同未完成该批（骨架交付按**卷**连续覆盖，缺卷标志等同未完成该卷）；
- 门禁失败是**批次粒度**的：补拆该批，不重跑已通过的批次；
- **两套门禁不互判**：完整交付批次只按 7 项判 `passed`，骨架批次只按 6 项判 `passed`；不得因骨架标志缺 `anchorPool` / `evidenceDensity` 而判 `failed`，也不得因完整标志缺 `outlineCoverage` / `skeletonFields` / `samplingDeclared` 而判 `failed`——**键集合与交付物错配本身就是非法标志**，应打回重写而不是换算门禁。

## 5. `artifacts` 与 `warnings` 口径

**`artifacts`**（相对版本目录的路径）：

- L1 批次必含批次档案，例：`_temp/batches/V1_B1_ch001-030.md`；
- 骨架交付必含骨架档案，例：`_temp/batches/V1_SK_ch001-048.md`；`骨架/` 三份产物（`卷级骨架.md`、`索引.md`、`_未取证声明.md`）在卷级收敛后落盘，可列入对应卷标志的 `artifacts`；
- 该批若顺带产出其它事实层文件（如钩子清单、术语表落盘），一并列出；
- 路径必须真实存在；**不得列出源包文件**（源包只读，不是本批产物），也不得指向尚未写出的文件。

**`warnings`**（每条一句话，可机械展示）：

| 常见告警 | 触发示例 |
|:--|:--|
| 证据偏薄 | 某维度本批仅 1 条证据但原文似有更多，待后续批次确认 |
| 设定演变 | 同一定设在不同章存在演变，已在档案中保留时间线 |
| 疑似缺章 | 源包 `flags` 含 `missing-before:N` / `weak-title` 等，本批沿用其标注 |
| 范围声明 | 本次为部分范围，成品的全书级结论仅作推断候选 |

告警**不改变** `checks` 的布尔值，也不改变 `status`，只做可见性。

## 6. 宿主消费方式

- 宿主**只读该文件**判定收敛：`status === "passed"` 才放行；不解析 run 事件文本、不按流式文本长度推算进度；
- 宿主据此维护 `检查点.json` 的 `completedBatches` / `failedBatches` 与产物索引，失败批次单独重试；
- 标志文件是**批次边界**的唯一权威来源；批次边界不允许靠散文判断。

## 7. 常见错误（会导致宿主误判）

| 错误 | 后果 | 正确做法 |
|:--|:--|:--|
| 门禁未过却写 `passed` | 残缺结果进入 L2 | 写 `failed` 并补拆该批 |
| `checks` 缺项、改名或跨套混用 | 宿主无法机械判读 | 按交付物只写对应那套：完整交付 7 键 / 骨架交付 6 键 |
| 用自然语言写「质量良好」代替布尔 | 无法机械判读 | 只写 `true` / `false` |
| `chaptersCovered` 越界或与相邻批重叠 | 覆盖统计与检查点错位 | 用全书序号闭区间，连续不重叠 |
| `artifacts` 指向未写出的文件或源包 | 产物索引失真 | 只列真实存在的本批产物 |
| 非原子写、直接覆盖目标文件 | 出现半写状态被读成非法 | 临时文件 + 原子替换 |
| 同一批写多份标志 | 版本目录出现重复边界 | 一批一份，重跑覆盖同名 |
| 骨架批次照抄完整 7 项（或反之） | 键集合错配，宿主误判 | 骨架只写 6 项，完整只写 7 项，不得跨套 |
| 骨架必含章未命中仍写 `samplingDeclared: true` | 抽样覆盖失真 | 补抽卷首 / 卷末 / 卷末钩子章后再判 |
| 骨架用「原文未展开」代替「抽样未取证」 | 未取证被伪装成已取证 | 抽样未覆盖一律标「抽样未取证」 |
| 引用 `_temp/chapters/` | 幽灵路径，后续读取失败 | 正文只走源包 `chapters/` |

## 8. 与其它契约的关系

| 契约 | 关系 |
|:--|:--|
| `manifest.json` / `合并章节索引.json` | 提供章节清单与全书序号，`chaptersCovered` 的基准；本 skill 只读 |
| `批次计划.json` | 决定批次数与每批章范围，`batchId` 与 `chaptersCovered` 必须与其生效档位对齐 |
| `检查点.json` | 宿主维护，汇总各批标志与产物索引；原子写 |
| 骨架档案 | 骨架批次（`outline`）的标志与其骨架档案同名同级，必填节见 `批次档案格式.md` |
| `骨架/` 三份产物 | 骨架交付（`outline`）的交付物；全卷标志 `passed` 后才允许落盘，且**未取证、不得作为 L2 证据来源** |
| L2 六模块成品 | **只在 L1 全部批次 `passed` 之后才允许开始**；标志是进入 L2 的闸门 |
