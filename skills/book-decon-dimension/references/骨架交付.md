# 骨架交付 · skeleton-delivery（`processingProfile = outline`）

> 定位：拆书**第三种交付物**的规程与产出契约。`processingProfile` 三值中 `standard` / `deep` 交付「六模块完整」，`outline` 交付「**卷级骨架**」。
>
> **`outline` 是另一种交付物，不是"更快的六模块"。** 它只做**按卷抽样**的粗粒度提取（卷级九字段 + 主线链 + 主要角色 + 力量体系要点 + 世界观要点），不做八维全提、不做 L2 六模块成品、不做立项；产物默认**未取证**，只能用于快速判卷、选书与范围决策。需要六模块时必须另行发起 `standard` / `deep` 精拆（新建版本）。
>
> 键名统一 camelCase；门禁键固定为 6 项（见第 6 节）。档案格式见同目录 `批次档案格式.md` 第 3 节；标志字段与 `status` 判定见同目录 `批次完成标志.md`。

---

## 1. 边界（做什么 / 不做什么）

| 项 | 骨架交付（`outline`） | 与完整交付（`standard` / `deep`）的区别 |
|:--|:--|:--|
| 交付物 | `骨架/卷级骨架.md`、`骨架/索引.md`、`骨架/_未取证声明.md` | 六模块 + `爽点.md` + `立项/` + 根索引 + CHANGELOG |
| 读取 | **按卷抽样** 30%–40% 章，必含卷首 / 卷末 / 卷末钩子章 | 逐章精读，每章只读一次 |
| 提取 | 卷级九字段骨架 + 主线链 + 主要角色 + 力量体系要点 + 世界观要点 | 八维全提（剧情 / 人物 / 力量 / 世界观 / 爽点 / 情感 / 文风 / 功能位） |
| 门禁 | **6 项骨架门禁** | 7 项完整门禁 |
| 归档单位 | **卷**（≤40 章） | 批次（约 30 章 / ≤20 章） |
| 证据强度 | 抽查取证，未覆盖部分标「抽样未取证」 | 逐章取证，可回溯到原文对应章 |
| 产物可复用性 | **仅作线索**，不得作为 L2 证据来源 | L2 的唯一事实地基 |

**明确不做**（越界即为红线）：

- 不产出六模块目录（`剧情库/`、`角色与势力库/`、`力量与战斗/`、`世界观/`、`赛道特色/`、`文风DNA/`）；
- 不产出 `爽点.md`、`立项/`（L0-L3 与逆向破解）、不产出根 `索引.md` 与 `CHANGELOG.md`；
- 不做八维全提，不写分场事件链表，不做锚点池与证据密度；
- **不得对外声称"六模块拆解完成"**。

## 2. 触发与分流

| 条件 | 动作 |
|:--|:--|
| `拆解配置.json` 的 `processingProfile == "outline"` | 走本规程 |
| `processingProfile == "standard"` / `"deep"` | 走 `SKILL.md` 的 L1 → L2 完整规程，**不得**改走本规程 |
| 用户要六模块但配置为 `outline` | 停止并说明：需另起 `standard` / `deep` 版本，不在骨架版本上补六模块 |

入口 `book-decon` 的切批唯一依据是源包根 `批次计划.json`；本交付物**以卷为归档单位**，若单卷超过 40 章上限，按 `批次计划.json` 拆成多份同卷骨架档案，卷级九字段在 `骨架/卷级骨架.md` 中**按卷合并**。

---

## 3. 抽样规程（按卷，不得整卷跳过）

| 项 | 口径 |
|:--|:--|
| 抽样单位 | **卷**：逐卷抽样，一卷不漏；**不得整卷跳过** |
| 抽样比例 | 每卷抽 **30%–40%** 的章（不足 1 章按 1 章计，四舍五入取整） |
| 必含章 | 每卷的**首章**、**末章**与**卷末钩子章**必须命中（钩子章与末章重合时视为命中同一章，须在档案中注明） |
| 剩余名额 | 满足必含章后，按卷内均匀分布补齐至比例下限，优先覆盖卷内转折 / 高潮段 |
| 声明 | 抽样比例、抽样章清单、被跳过章节区间必须写入骨架档案，并在 `_未取证声明.md` 汇总 |

---

## 4. 提取规程（只做卷级骨架）

| # | 提取项 | 内容 | 锚点 |
|:-:|:--|:--|:--|
| 1 | **卷级九字段骨架**（每卷一套） | 力量范围、动力引擎、战斗系统、地理、势力、危机、敌人生态、矛盾轴、卷末边界 | 每字段条目带 `(chXXX)` |
| 2 | 主线链 | 卷内主线链条目 + 卷间衔接（下一卷起点承接上一卷卷末边界，**卷间必须连续**） | 带 `(chXXX)` |
| 3 | 主要角色 | 本卷主要登场角色及其功能 | 带 `(chXXX)` |
| 4 | 力量体系要点 | 本卷力量体系增量要点 | 带 `(chXXX)` |
| 5 | 世界观要点 | 本卷世界观增量要点 | 带 `(chXXX)` |

九字段口径沿用 L2「各卷切片」的同名字段语义（见 `SKILL.md` 的 L2 产物结构要点），此处只做**卷级要点**，不做模块化展开、不做证据聚合。

---

## 5. 取证与免责标注

- 每条骨架条目带 `(chXXX)` 锚点（可多章并列）；**量化数值不强制 🔒**（骨架不设量化门禁）。
- 抽样**未覆盖**的章节如需推断，必须显式标注「**抽样未取证**」，**不得**凭记忆、书评或后文补全。
- 未被抽样的章节内容**不得**写成确定结论。
- `traceable` 允许以「抽样未取证」标注形式回溯：要么给出 ch 锚点，要么明确声明该条未取证。

---

## 6. 骨架 6 项门禁（一条不减，与完整交付是两套）

| key | 门禁 | 通过判据 |
|:--|:--|:--|
| `glossary` | 核心表非空 | **人名 / 势力 / 力量** 3 张核心表非空（骨架不要求 5 表） |
| `outlineCoverage` | 骨架覆盖 | 每卷都有骨架条目；主线链**卷间连续**、无断点 |
| `skeletonFields` | 九字段齐全 | 每卷九字段齐全 |
| `samplingDeclared` | 抽样声明 | 已声明抽样比例（30%–40%）与**被跳过章节区间**，且必含章（卷首 / 卷末 / 卷末钩子章）已命中 |
| `noFabrication` | 不编造 | 不存在「既无 ch 锚点、又未标『抽样未取证』」的条目 |
| `traceable` | 可回溯 | 所有结论可回到原文对应章；**允许以「抽样未取证」标注形式回溯** |

**骨架不做 `evidenceDensity` 与 `anchorPool` 的按章比例要求**——没有「每批证据条目 ≥ 章数 × 2」「命中章 ≥ max(20, 章数 × 60%)」这类按章门槛；结构完整性由 `skeletonFields` 承接，因此骨架也**不设 `schema` 与 `quantified`**。完整交付的 7 项门禁原样保留、不因骨架而减少；两套键集合互斥，不得混用。

---

## 7. 产出契约

**只写版本目录 `骨架/` 下的三份**（不产出六模块与立项）：

| 文件 | 内容 | 对应门禁 |
|:--|:--|:--|
| `骨架/卷级骨架.md` | 逐卷卷级九字段骨架 + 主线链 + 主要角色 + 力量体系要点 + 世界观要点，条目带 `(chXXX)` | `skeletonFields`、`outlineCoverage`、`traceable` |
| `骨架/索引.md` | 分卷导航 + 主线链检索 + 抽样章清单 + 覆盖范围声明 | `outlineCoverage`、`samplingDeclared` |
| `骨架/_未取证声明.md` | 抽样比例、被跳过章节区间、逐项「抽样未取证」清单 | `samplingDeclared`、`noFabrication` |

**过程档案与标志**：每卷一份骨架档案 `_temp/batches/V{卷序}_SK_ch{起3位}-{止3位}.md`（必填节见 `批次档案格式.md` 第 3 节），同名写 `*.批次完成标志.json`（`batchId` 同档案名，`checks` 只写骨架 6 键）。三份 `骨架/` 产物在**全卷标志 `passed`** 后落盘。

---

## 8. 复用契约（未取证）

1. **骨架产物未取证，不得作为 L2 证据来源**，也不得当作六模块成品的事实地基；
2. 后续对**同一范围**做精拆（`standard` / `deep`）时**新建版本目录**，并把骨架版本记为**父版本**，在精拆的批次档案与变更记录中**标明「输入为未取证骨架」**；
3. 精拆**不得**直接复制骨架结论充数：骨架条目只作线索，必须回到原文取证后才可写入六模块；
4. 骨架版本自身**不因精拆而被覆盖或改写**，两份版本并存留痕；
5. 骨架交付**不因存在骨架版本而免除**精拆的完整门禁与 L2 交付要求。

---

## 9. 与其它契约的关系

| 契约 | 关系 |
|:--|:--|
| `拆解配置.json` | `processingProfile` 决定是否走本规程；`focusDimensions` 只决定骨架要点的呈现顺序与侧重 |
| `manifest.json` / `合并章节索引.json` | 提供卷边界与章清单，抽样与 `chapter_range` 的基准；只读 |
| `批次计划.json` | 决定单卷超限时的拆分；本规程不自行切批 |
| `批次完成标志.md` | 骨架 6 项门禁与 `status` 判定以此为准 |
| `批次档案格式.md` | 骨架档案必填节以此为准（第 3 节） |
| L2 六模块成品 | 骨架**不是** L2 的事实地基；L2 只能由完整交付的 L1 批次档案支撑 |

## 10. 常见错误

| 错误 | 后果 | 正确做法 |
|:--|:--|:--|
| 把 `outline` 当作"更快的六模块" | 交付物错配，用户拿到残缺六模块 | 明确骨架是另一种交付物，需六模块另起 `standard` / `deep` |
| 整卷跳过未抽样 | `outlineCoverage` / `samplingDeclared` 不过，判 `failed` | 逐卷抽样，一卷不漏 |
| 必含章（卷首 / 卷末 / 卷末钩子章）未命中 | `samplingDeclared` 判 `false` | 补抽必含章后再判 |
| 用「原文未展开」代替「抽样未取证」 | 未取证被伪装成已取证 | 抽样未覆盖一律标「抽样未取证」 |
| 骨架批次写完整 7 项 `checks` | 键集合错配，宿主误判 | 骨架只写 6 键 |
| 骨架产物被当作 L2 证据 | 未取证结论污染六模块 | 骨架只作线索；精拆新建版本并以骨架版本为父版本 |
| 骨架版本里补产出六模块 / 立项 | 越界交付 | 六模块必须新建 `standard` / `deep` 版本 |
