# fanqie-review

番茄完本计划 · 审稿层。只做四件事：章日志、状态更新、批末报告、完本包。

不改写正文，不改章纲；问题回给 `fanqie-write` 或 `fanqie-plan`。

## 输入

- `章纲/ch{NNN}-章纲.md`
- `正文/ch{NNN}.txt`
- `正文/ch{NNN-1}.txt`
- `剧情日志/ch{NNN-1}.md`
- `状态.md`

## 输出

- `剧情日志/ch{NNN}.md`
- 更新后的 `状态.md`
- 每 10 章：批次报告
- 完本：`完本包/`

## 单章审稿

按 `templates/chapter-log.tpl.md` 写章日志，逐项判：

| 项 | 判据 |
| --- | --- |
| 章纲兑现 | 章纲的事件、转折、落点是否都写到；漏一个记问题 |
| 开头 120 字 | 是否有欲求/反常/压力/反馈/主动动作 |
| 场景冲突 | 每场是否有谁要什么、谁挡着、局面变了什么 |
| 人物一致 | 称呼、性格、能力、关系是否与人物卡和上一章一致 |
| 爽点 | 本章兑付物是否兑现；发生、反应、影响是否可见 |
| 章末钩子 | 五型之一；与上一章不同型；强度不低于上一章 |
| 字数 | 2000-2500 汉字 |
| AI 味 | 高频词、排比、总结腔、金句是否清掉 |
| 承接 | 有信息吗、接得上吗、指得清吗、对得上吗 |

问题分级：

- **P0 打回**：章纲漏事件、主线矛盾、人物崩、爽点为零、章末无钩子、字数 <1800。
- **P1 当批修**：钩子同型、AI 味重、场景冲突弱、对白无目的。
- **P2 记录**：文风小问题、可优化细节。

P0 未修，本章不算完成，不进完本统计。

## 批末报告

每 10 章一批，按 `templates/batch-report.tpl.md` 给四块：

1. 本批写了什么：章节范围、核心事件、兑付物。
2. 主线推进到哪：主角目标、对手、伏笔、关系变化。
3. 发现的问题：重复桥段、逻辑断裂、人物不一致、节奏塌陷、AI 味。
4. 下一批计划：章节范围、要兑现的爽点、要埋/收的伏笔、风险。

缺一块，这一批不算完成。

## 完本

按 `templates/completion-package.tpl.md` 出完本包。验收以冻结脚本为准：

- 全书字数 ≥目标。
- 章文件数 = 章日志数。
- phase 7/8。
- 无空章、无缺章。
- 每章 ≥1800 字。

质量清单见 `references/quality-gate.md`；不承诺签约、流量、稿费。

## 状态更新

章日志完成后更新 `状态.md`：

- `current_chapter`、`word_count`、`phase`。
- `hook_type`、`payoff_form`、`paid_off_chapters`。
- `last_confirmed_chapter` 只在用户确认批次后更新，审稿层不自行推进。

## 交接

- P0/P1 问题回 `fanqie-write` 修本章，或回 `fanqie-plan` 重写章纲。
- 批末报告交用户拍板；用户确认后才进入下一批。
- 完本包交用户导出；不做平台提交。
