# 番茄写作专家 v2

一次 run 只交一件主产物。番茄平台的长篇连载写作流程，覆盖卖点卡、立项卡、卷爽点表、单章章纲、单章正文、单章审稿与批末报告。

## 什么时候用

用户说「写番茄小说 / 写下一章 / 续写 / 写章纲 / 审这一章 / 做卖点」时用。不用于晋江、起点、公众号等非番茄需求。

## 本轮怎么开始（每轮固定四步）

1. 读 `状态.md` 的「下一步」，得到任务号与章号。文件不存在时先做 T1。
2. 向用户复述本轮只做哪一件、主产物写到哪个文件。需要用户拍板的，用 popwave_ask_user 一次问完。
3. 只读本任务需要的文件，跑 `python scripts/build_context.py --project <项目目录> --task <任务号> --chapter <章号>` 生成 `任务包.md`。脚本打印每块字数；超预算先删无关块或让脚本重算，不改写原文。
4. 调写作工具时把 `task` 传任务号；不调工具的任务直接落盘。交付后更新状态，再报告。

## 任务表

| 任务 | 做什么 | 主产物 | 工具 | context 上限 |
|:--|:--|:--|:--|--:|
| T1 | 卖点卡：一句话卖点、三个爽点承诺、目标读者、同类差异 | `立项/00-卖点卡.md` | idea | 8000 |
| T2 | 立项卡：题材、主角、金手指与代价、世界规则、主线目标、卷规划、人物卡 | `立项/01-立项卡.md` | idea | 6000 |
| T3 | 卷爽点表：每 5 章一个爽点、兑现章节、升级点 | `卷纲/卷NNN-爽点表.md` | outline | 5000 |
| T4 | 单章章纲：本章目标、冲突、3-5 条事件、转折、章末钩子、卖点兑现 | `章纲/chNNN.md` | outline | 5000 |
| T5 | 单章正文：按章纲写一章，2000-2500 字 | `正文/chNNN.md` + 章日志 | body | 6000 |
| T6 | 单章审稿：连续性、人设、逻辑、节奏、文笔、AI 味、钩子、卖点兑现 | `剧情日志/chNNN.md` 补审稿结论 | 不调 | 9000 |
| T7 | 批末报告：五章一批复盘，下一批改什么 | `批次报告/第NNN批.md` | 不调 | 5000 |

一次 run 只做一行。T4 与 T5 不在同一轮；T5 前必须已有本章章纲。T6 发现硬伤时，本轮只标问题与重写建议，不在同一轮改正文；用户确认重写后才开新一轮 T5，状态标 `rewrite`。

## 文件协议

项目根目录固定这些文件，路径不改名：

- `用户约束.md`：用户说过的字数、视角、禁写项。新增约束追加一行，不覆盖旧行。
- `立项/00-卖点卡.md`：T1 产出，后续所有任务的上游。
- `立项/01-立项卡.md`：T2 产出。
- `卷纲/卷NNN-爽点表.md`：T3 产出。
- `章纲/chNNN.md`：T4 产出。
- `正文/chNNN.md`：T5 产出。
- `剧情日志/chNNN.md`：每章五行日志，T5 收尾与 T6 都写它。
- `剧情快照.md`：≤1500 字，只写当前时点的世界状态、人物状态、未回收伏笔、道具位置、关系变化。是快照，不是章日志合集。
- `状态.md`：已完成任务、下一步（任务号+章号+原因）、更新时间。每轮收尾必须重写。
- `批次报告/第NNN批.md`：T7 产出。

## 上下文配方

- T1：用户原话 + 已有立项（无则空）+ 用户约束 + 题材包。
- T2：卖点卡 + 用户原话 + 题材包 + 当前人物与设定。
- T3：卖点卡 + 立项卡 + 用户约束 + 题材包。
- T4：卖点卡摘要 200 字 + 立项卡 + 本卷爽点表 + 剧情快照 + 出场人物卡 + 用户约束 + 文笔规则摘要 1500 字。
- T5：本章章纲全文 + 剧情快照 + 上一章正文末 1000 字 + 出场人物卡 + 卖点摘要 200 字 + 用户约束 + 文笔规则摘要 1500 字，总目标 5000-6000 字。
- T6：本章正文 + 本章章纲 + 剧情快照 + 卖点卡 + 用户约束。
- T7：本批五章日志 + 卖点卡 + 卷爽点表 + 用户约束。

只读配方列出的文件。不读全书，不读其他章正文，不把 7 份参考文件全读。

## 动笔前必读

- 写正文前读 `references/prose-rules.md` 的「摘要」，需要逐条核对时再读全文。
- 写正文前读 `references/ai-flavor.md`。
- 题材为男频年代/都市/重生时读 `references/genre-男频年代都市重生.md`。
- 任务细则按任务读：T1/T2 读 `references/task-idea.md`；T3/T4 读 `references/task-outline.md`；T5/T6/T7 读 `references/task-write.md`；流程疑问读 `references/run-tasks.md`。

## 交付前硬检查

1. 跑 `python scripts/check_chapter.py --chapter 正文/chNNN.md`，通过字数、AI 高频词、引号与视角检查。
2. 跑 `python scripts/check_state.py --project <项目目录>`，通过状态与文件检查。
3. 主产物写进约定路径，正文不夹带大纲、审稿结论或元信息。
4. `状态.md` 的下一步已改成本轮之后的任务；T5 收尾必须新增章日志并更新剧情快照。

任何一项不通过就改到通过，不把失败写成通过。

## 硬规则

- 章纲与正文分开两轮。用户说「直接写一章」也要先确认有无章纲：没有就本轮只做 T4。
- 字数按 `用户约束.md` 优先；没有约束时正文 2000-2500 字。
- 正文只按章纲写，不自行改剧情；章纲缺口写进日志和状态，不临场补设定。
- 卖点兑现写进章纲，正文必须让读者看见兑现，不靠旁白解释。
- 章节正文落盘后才算完成；只在回复里贴正文不算交付。
