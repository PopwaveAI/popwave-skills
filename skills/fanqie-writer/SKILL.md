# 番茄爆款小说写作助手 · Fanqie Crafter

为番茄小说平台写作者打造的一站式网文创作技能，同时兼顾「长线不穿帮」与「平台数据化」两大目标：

- 长线连续性工程：内置 `.learnings/` 记忆系统防止百章长篇的角色/地点/伏笔穿帮，卷级章节规划防写偏，断点续写恢复，关键情节 Mermaid 图解，9 维逻辑审查。
- 番茄平台数据化写法：用 6 问先锁定「爆款基因」（情绪标签直接决定番茄算法分发），单章字数按题材分档（通用默认 2200-2800；悬疑推理类应 2500-3500；算法边界与卡点位置见 `references/fanqie-platform-facts.md` 第四节·补），黄金开篇三版锻造，评论区诱导设计，情绪曲线「压-小扬-压-爆」循环，去 AI 味润色，8 维质量评分。

## 何时使用

- 用户要在番茄小说写/连载一部网文。
- 用户要求分章节创作、长篇小说、追更续写、章节悬念设计。
- 用户希望章节更「番茄味」：开章抓人、情绪过山车、评论区能吵起来、完读率更高。
- 用户需要长线不穿帮：角色不串、伏笔能收、跨卷不断档。

## 何时不使用

- 用户需求并非番茄小说平台（如晋江、起点、公众号、通用小说创作）→ 不要触发本技能，改用通用写作流程，避免把番茄专属的算法节奏/评论区诱导强加给不适配的平台。
- 用户只是要写单篇短文、文案、非连载故事 → 用通用写作即可，不必启用长篇工程。

## 第一次使用：从这里开始

> 这一节写给第一次用本技能的人。你不需要懂番茄平台的术语，也不用先做准备。

### 1. 你只要说一句话

说出你想写什么就行，例如：

> 「写一部番茄小说，女主穿越到古代当丫鬟，靠一手好厨艺一步步翻身」
> 「我想写个搞笑的，主角穿越自带 BGM，一响所有人都得跟着晃」
> 「帮我看看这本小说的第 1 章写得怎么样」（有稿子时）

已经有半本书了？也一样用——大纲、细纲、人设都在，甚至正文也写了几章，直接说：

> 「续写第 3 章」「**接着写下一章**」「往下写」（项目路径一并给出最好，例如「项目在 `…/novels/书名/`，接着写第 3 章」）

技能会接着往下写：先读已有的大纲、细纲与写作规则，再写该章——不会让你从头再来一遍。找不到你的项目文件时会主动问你要路径，不会闷头乱写。

技能会自己往下走，不会拿一张表让你填。需要你决定的地方，它会先给你一个成稿 ＋ 依据 ＋ 备选，你只改你想改的那一项。

### 2. 会给你什么（7 件交付物 · 分四批给你，每批都会停下等你）

总共 7 件，但不会一次全塞给你。按下面四批来，每一批交完就停下，你说了满意才继续：

| 批 | 交什么 | 你做什么 |
|---|---|---|
| 第 1 批 | `00-大纲`（故事本身）＋ `01-人物档案` ＋ `02-情绪曲线` ＋ `03-黄金开篇` | 看完说满不满意——哪件不对说哪件 |
| 第 2 批 | `04-章节细纲`（每卷编排 ＋ 逐章写什么） | 过一遍全书走向，确认 |
| 第 3 批 | `第01章`（纯正文，让你先看见实物）＋ `05-文体与写作规则`（这本书具体怎么写） | 读第 1 章，说"可以" |
| 之后 | 第 2 章起，一章一章连着写 | 随时叫停／改方向 |

> 为什么分批：早先"7 件做齐再交付"会让第一批等几十分钟。现在先给你能判断的那四件——不满意当场就能改。

每一件都是给人看的（不是给你看不懂的"施工表"）：

| 件 | 是什么 | 你拿它干什么 |
|---|---|---|
| 1 `00-大纲.md` | 故事本身——讲什么、谁跟谁、为什么争、最后怎样了 | 通读一遍，确认是你要写的故事 |
| 2 `01-人物档案.md` | 每个角色是谁、想要什么、为什么这么选 | 检查人物是不是你想的样子 |
| 3 `02-情绪曲线.md` | 全书的情绪节奏怎么排（哪章压、哪章爆） | 看节奏会不会太平 |
| 4 `03-黄金开篇.md` | 开篇 50 字三个版本 ＋ 为什么选这一个 | 挑一个，或说"换" |
| 5 `04-章节细纲.md` | 每一卷的编排 ＋ 逐章写什么——可以当分卷剧情梗概通读 | 快速过一遍全书走向 |
| 6 `05-文体与写作规则.md` | 这本书具体怎么写（腔调、称谓、禁忌、单章怎么排） | 觉得哪里不对就改这条 |
| 7 `第01章.md` 等 | 纯正文，单章字数按题材定（通用 2200-2800，悬疑推理 2500-3500） | 直接读，直接发 |

### 3. 三件你需要知道的事

- 它一次只写一章，但会把全书章节排好。你可以先看第 1 章，满意了再让它往下写。
- 它不会一次问一堆问题。如果你觉得它问得太多、或像在让你做题，直接说"你自己定"。
- 它对你不懂的地方会让你看懂。哪个词看不懂见下方术语表；技能里禁止出现"只有内行看得懂"的行话。

### 4. 术语表（看不懂的词在这里查）

| 词 | 白话解释 |
|---|---|
| 完读率／追读率 | 平台统计：多少人点进来、多少人读完了这一章。读完了才有下一章推荐，所以开篇几章最重要 |
| 情绪标签 | 平台的分类标签（如"虐恋""爽文""沙雕"）。它决定平台把你的书推给谁，所以要在开始就定准 |
| 黄金开篇 | 第 1 章开头那几十个字。读者是否留下，基本在这几十字里决定 |
| 爆点 | 让读者当场愣一下的东西——当场就懂、但当场解释不了 |
| 爽点 | 读者想要的某件事发生了。本书分五种：碾压／信息兑付／认可／关系兑付／整活兑付 |
| 整活兑付 | 不靠"更强"解决问题，而是"另做一件离谱但说得通的事"把局面搅乱。笑点类金手指走这一类 |
| 情绪曲线 | 一章内的情绪怎么起伏（压 → 小扬 → 压 → 爆），一直平＝读者划走 |
| **章末钩子**| 每章最后那一句。作用是**让读者点下一章**——只留问题，不给答案 |
|伏笔| 前面埋一句、后面回收。埋了不收＝挖坑不填，会被读者骂 |
| **金手指**| 主角的特殊能力／外挂。**没有金手指的题材也要写"替代驱动"**（靠什么让人想看下去） |
| 风格档 A–E | 文风的可选档位（叙述驱动／心理流／短句碎切／对白驱动／长句对白）。没有哪一档更好，只看适不适合这本书 |
| 爽点形态（五类） | 读者"想要的事发生了"的五种类型：碾压／信息兑付／认可／关系兑付／整活兑付。一本书选定一类为主，写在 `00-大纲` 第 1 节；五类的判据见正文 1.1 |
| 替代驱动 | 没有金手指的书靠什么让读者追下去（例：一门家传手艺 ＋ 娘留下的半本账册）。与「金手指」二选一，但不能两样都不写 |
| 世界观 | 这本书的世界：时代 ＋ 规矩 ＋ 核心设定 ＋ 绝对禁忌。任何题材都要写（现实题材写"这个行业的规矩"）。见 `00-大纲` 第 4 节 |
| 一句话卖点 | 用一句不超过 25 词的话说清这本书卖什么。见 `00-大纲` 第 1 节 |
| 章末钩子五型 | A 信息差／B 危机逼近／C 关系转折／D 规则异常／E 认知颠覆。相邻两章不许同型 |
| 题材包 | 技能内置的 10 类番茄题材写法要点（读者期待／必备元素／爽点节奏／开篇雷区／反套路要点）。判断结果写成故事语言进 `00-大纲`，不写包号型号 |

| **承接测试四问**| 逐句自检：有信息吗／接得上吗／指得清吗／对得上吗。**四类通用错误**（病句／碎句／跳／上下文对不上）都由它兜底 |

> 收录判据：本表收——① 用户会在 7 件交付物里读到的词（字段名、章节标题里出现的）；② 用户会问到、而技能必须能白话解释的流程词。
> 判据句：这个词，用户会在交付给他的那 7 件文件里读到吗？
> 义务（写死）：新增任何交付物字段／章节标题时，必须回来核一次本表（09-24 之后新增的 `爽点形态`／`世界观四格`／`替代驱动` 等用户可见词一个都没进表，就是反面例）。校验器：`prd/check_glossary.py`（跑打包门禁时一并执行）。

### 5. 哪些题材实测过、哪些还没有（已知边界）

结论先说：技能不挑题材，没实测过的题材照样能用。 它按通用写作规则写，不是给某几个题材硬编码的。
下面这张表是让你知道哪里可能有坑，不是限制你能写什么。

| 题材 | 实测程度 | 意味着什么 |
|---|---|---|
| 古代言情／现代言情／穿越重生／玄幻修真／武侠仙侠／悬疑推理／种田日常／系统流 | ✅ **全流程走通过**（故事设计 → 细纲 → 正文，逐条校过） | 放心用。**种田日常**与系统流已实测（种田走完四批闸门与 3 章正文；系统流走 2 章，规则摊开而编号不进正文）。详见 `prd/全类型覆盖测试矩阵.md`「二·三十」与「二·三十三」 |
| 年代文 | 🟡 只走到故事设计 | 能用，但后半程（细纲、正文）没有实测凭据 |
| 都市现实 | 🟡 只走到故事设计（2026-10-11 补） | 闸门 1 四件齐（`00`／`01`／`02`／`03`），未写正文。它是「身份负担型」与「非能力型金手指」的首个样本——身份是负担不是底牌、全书不揭露；写它时别把"藏着的身份"当底牌用，见 `prd/全类型覆盖测试矩阵.md`「二·三十九」 |

除题材之外，另有三块整块没有实测，用到了请多看一眼：

1. 短篇（一章或几章讲完的故事）——本技能按长篇设计，短篇从未完整跑过；
2.长篇连载 50 章以上——跨章的人物与道具交接，目前只在两本书的各 3 章上验过（一本悬疑、一本种田日常，各 1–3 章），越往后越要留意；
3.「拿一篇现成作品做参照重构」的后半段——从别人的文里拆出结构、重组成自己的一本书：前半段验过，后半段（怎么长成完整一本）没有。

> 为什么写出来：与其让你在没验过的题材上踩坑、以为「技能不行」，不如先说清楚。凡是有实测凭据的部分出了问题，那是真缺陷——直接说，不要自己绕过去。

> 维护提醒：本表的题材分组来自内部测试覆盖矩阵，两处必须同步。

## 项目结构与初始化

收到创作请求后，先建立项目目录（如目录已存在则复用）：

```

## 阶段零：接续已有项目（项目已存在时的唯一入口）

> 为什么单独立一节：用户在平台实测——项目已有大纲／细纲／人设与部分正文，说「续写第 X 章」，结果技能不触发、也不按本书规则写。根因＝此前流程只有"从零立项"入口（A/B/C/D 四路全是"给什么素材来立项"），没有"东西已经在了，接着写"的入口。

### 0.1 判据：什么算「项目已存在」（AI 自行判定，不问用户）

满足任一即走本模式：

- 当前工作区或用户给出的路径下，存在 `novels/[书名]/`，且其中有 `00-大纲.md`／`04-章节细纲.md`／`05-文体与写作规则.md` 任一；
- 存在已写正文（`第01章.md`、`第02章.md` …）；
- 用户话里出现「续写」「接着写」「继续写」「写第 X 章」「下一章」「往下写」。

### 0.2 五步（按序，不许跳）

1. 定位项目：在当前工作区找 `novels/`。找不到就问用户"项目路径在哪"（同 3.1 硬门禁——严禁找不到就用基线规则硬写，也严禁把已有项目当新项目重新立项）。
2. 读全必读清单（＝ 3.1 那 9 份）：`05-文体与写作规则` ＋ `00-大纲` ＋ `02-情绪曲线` ＋ `04-章节细纲` ＋ `.learnings/` 四份 ＋ 最新章。缺 `05` 必须问——没有它，写出来的正文不属于这本书。
3. 报一句现状给用户（一句话交底，不是问答题）：当前写到第 N 章、上一章结尾停在哪、第 N+1 章在细纲里的兑付物与章末钩子是什么。用户看完回"对"或"这里改成 X"。
4. 按 3.2 写前分析 → 3.3 撰写（字数用 `scripts/plan_word_quota.py` 排到每场）。
5. 写完接 3.4 格式与字数 → 3.5 质量审查 → 阶段五 记忆更新（`.learnings/` 四份 ＋ 章日志）。
6. 只动该动的东西：接续模式下只允许——① 新建/覆盖该章正文；② 更新 `.learnings/` 记忆与章日志。未经用户同意，不得改动已交付件 `00-大纲`／`01-人物档案`／`02-情绪曲线`／`03-黄金开篇`／`04-章节细纲`／`05-文体与写作规则`——这些是用户可能已经认可的东西，改它们＝把用户认可的版本又改回去了（与四批闸门第 ② 条纪律同源）。
> 由来：接续写第 2 章时曾顺手改写了 `00-大纲.md` 与 `02-情绪曲线.md`——未经授权。"多改一点"不报错，但会让用户的认可失效。
>
> 与 `3.4`「大纲同步」的边界（两处规则不许打架，此处一次说清）：
> - 允许（最小进度回填，不改内容、只标状态）：在 `00-大纲.md` 的进度看板、`02-情绪曲线.md` 的已用钩子类型这类状态列上标出"第 N 章已完成／用了哪类钩子"。判据：这一笔改动，改的是"进度"，还是"剧情/设定"？只许前者。
> - 需要先问用户：剧情走向、人物设定、细纲内容、文体规则任何实质性改动——哪怕你觉得原样不对。先说明理由并征得同意，再动。

### 0.3 与四批闸门的关系

接续模式下闸门 1／2／3 视为已完成（`00`～`05` 与已写正文都在项目里），直接从"第 4 批：连续写"进入。但仍然守两条纪律：① 一次一章，不许顺手把后面几章一起写完（用户看过再下一篇）；② 用户在第 N+1 章提的改动，第 N+2 章必须照改后的版本走。

### 0.4 与 prose-writer 的关系

装了 `prose-writer` → 把项目路径 ＋「写第 X 章」交给它；没装（平台场景常见）＝本技能自己按 3.2／3.3 写，效果一致——不许因为"该由它写"而停下不动，更不许转交一个不存在的技能。

## 阶段一：爆款基因确认 + 提示词完善

> 9-07/08 三份新规另已改写全链路：全勤门槛近乎翻倍、连载新增品质臻选奖、严打军警/公务员题材。
> **这直接决定"该写多长"——见 1.1 第 6 问。** 更新策略与产能建议须按新规重算（详见该文件第二、三、五节）。

### 1.0 入口分流：AI 自己判路，不问用户

用户给了什么，一眼就看得出来——按已给的东西直接判路，判完就出稿，不问"有没有参考原文"。

| 分流 | 触发（AI 自行判定） | 流程 |
|------|------|------|
| A 路｜有参考原文 | 用户提供了别人的成品 txt / 链接 / 文件路径 | 走 `references/remake-workflow.md` 全程 15 步。适配裁决与差异化改造必须做完（防侵权红线不动），但改由 AI 先出首选方案 ＋ 1-2 个备选 ＋ 各自代价，写进《改造纲领》并明示理由，用户不改即采用 |
| B 路｜只有方向，无原文 | 用户给了一句话 / 题材 / 灵感，没给任何原文 | 1.1 六问（AI 自答，由方向推出六项）→ 1.1.5 基因自洽校验 → 1.2 提示词完善（按 `prompt-guide.md` 补全，必含核心立意）→ 1.3 剧情设计（全书剧情脉络必填 + 上游主干先行）→ 1.3.5 立项确认 → 阶段二。一轮出稿，不分批问 |

爽点形态：立项时必须定下这本书靠什么让读者爽，五选一（可多选；多选时按下方「并重」规则处理，不得两条并排了事）——
碾压类（打脸/逆袭，爽在压过对手）/ 信息兑付类（悬念解谜、重生预知，爽在"我知道/我想到了"）/ 认可类（种田/日常/年代/治愈，爽在手艺被认可、日子可测量地变好）/ 关系兑付类（言情/CP 向，爽在关系向前一步：他先开口、他吃醋、他记得、他松手）/ 整活兑付类（笑点驱动向，爽在"没人想到可以这么干"）。**关系兑付类的唯一判据：读者想要的那句关系确认，落在一个可指认的动作上。念一遍，如果是一个动作（他来了／他喊了她的名字／他把伞留下／他没走），成立；如果只是情绪或氛围（"气氛变暧昧了"），不成立。**整活兑付类的两条判据：
1. 把这一手念一遍，它必须是一个"做法"（他做了什么），不是一句"吐槽／抖机灵"；且当场有人（读者或场上人）的反应是"啊？这也行？"。旁白写"众人哄笑"＝零兑付——笑点必须由一个具体的做法带出来，不由形容词带出来。
2. （一票否决）这一手做完之后，局面必须更乱，不是更整齐。判据句：这一章结束时，比开头更乱还是更整齐？ 更整齐＝写成了"智斗"，读者不笑，而且会滑回打脸爽文。同时：主角必须被动（他不问，是别人自己漏的），"漏话／失态"的人必须自己先慌。详见 `references/emotion-curve.md` 第 3 套的「本类型的引擎：连锁失控」。

> 为什么单列第五类：四类形态的爽感分别建立在"压过别人／比别人早明白／被看见／关系向前一步"上——没有一类装得下"笑"。实测标签＝爆笑反套路时，判定表六行一行都不命中，库与模板里也没有沙雕向配方。这是"沙雕／爆笑反套路从未被测过一遍"的根因。
判定依据是第 1 问的标签与第 4 问的反差点（判定表）：

| 命中条件 | 主形态 |
|---|---|
| 标签＝现实奋斗·生活流，或反差点＝只想把日子过好 | 认可类 |
| 反差点属关系向四项，或题材＝现代言情 / 古代言情 | 关系兑付类 |
| 标签＝脑洞大开，或反差点＝身怀异术却避之不及 | 信息兑付类 |
| 标签＝打脸爽文，或反差点＝隐藏大佬装萌新 / 看似废柴实天赋异禀 / 被虐后觉醒反杀 | 碾压类 |
| 标签＝悬疑惊悚，或核心冲突＝查明真相 | 信息兑付类 |

多形态并存（"并重"）的处理：允许并重，但不得强压用户定主次（那违反"用户的选择是输入"），且必须同时做两件事——
  ① 在 `00-大纲.md` 写明哪一条是明线、哪一条是暗线（并重 ≠ 两条同等用力，而是一条在台前、一条在台后）；
  ② 阶段二套 `emotion-curve.md` 时双轨处理：明线走主形态的节奏周期、暗线走次形态的周期，且两者在同一章内不得争夺同一个落点——一章只能有一个"读者合上章最记得的那一下"。
该字段不是装饰：它直接决定 3.3 撰写时的爽点写法与 `references/emotion-curve.md` 的节奏模板（五类形态各自的周期：碾压类→第 1 套／整活兑付类→第 3 套／关系兑付类→第 5 套／认可类→第 7 套）。

第 4 问的条件追问：原 6 个反差点选项全部描述"能力如何展露"，没有"主角与能力的关系是负面的"落点。悬疑 / 治愈 / 年代 / 虐恋等题材常见"能力是诅咒、主角想摆脱它"的设定，照原选项库只能硬塞。

判定结果写入 `00-大纲.md` 第 1 节「核心能力 / 金手指（含规则与限制）」，并直接影响两处：① `references/emotion-curve.md` 的节奏模板
（负担型不套"打脸爽文"式循环，改"每用一次就失去一点"的消耗曲线）② 3.3 撰写时"爽点"的定义（信息兑现的快感替代碾压快感）。

> 优先级：「能力性质＝负担」与「爽点形态判定表」不是同一维度，同时命中时以爽点形态为准。代价曲线不占节奏位，只作暗线——与主形态并行，不争夺同一个落点。判例：玄幻修真篇（标签＝打脸爽文→碾压类；能力＝负担型）→ 取第 1 套模板，代价曲线按暗线每 10-20 章兑付一次。

当方向里「没有对抗诉求」时：还有一种方向没有敌人——用户原话常见「不要打打杀杀」「不要装逼打脸」「就想看好好过日子」。此时候选池里的反差点全部预设了对抗关系，一个都取不上。
AI 自行判定张力来源并在出稿时说明（候选：能不能被接纳 / 有没有名分 / 生计能否站住 / 人情往来的分寸——取一个为主，或按方向现造），不再向用户追问。

群像戏时第 4 / 第 5 问锚点：第 3 问取「群像戏」时，第 4 问（反差点）与第 5 问（核心冲突）都是"主角视角"字段，AI 先按 1.2 的三种锚点模式自行选定主锚点模式（主锚点制 / 三线并列 / 地点为轴），再按主锚点填这两项，并在六问出稿里标注"该两问为主锚点答案 ＋ 选此模式的原因"。不问用户、不等拍板。

提问执行规则（B 路实测补充）：

- **一次出稿：六项 ＋ 每项依据 ＋ 可替换项，一次性给出，**不分批、不逐问。
- 候选池取不到就现造：见 1.1 取材规则。禁止静默丢弃任何维度——某个维度池里无贴合项时，不是"跳过"，而是为这本书造一项并说明理由。

### 1.1.5 基因自洽校验（AI 的内部动作，不产成对用户的提问）

第一原则：初始方向不可偏移。六问的职责是把用户的意图结构化，不是重新定义作品。六问答案与初始方向冲突时，以方向为准回调——用户明确表达过方向诉求时（如"要爽的、一章一个打脸"），相冲的项必须回调，并在校验记录里写明"按方向回调了哪几项、依据是哪句原话"。不得出现"六问答着答着，作品变成另一本书"。
本校验是 AI 自己的动作——发现冲突就地裁决并写进立项记录，随 1.3.5 一并交用户过目，不把冲突清单抛给用户逐条拍板。

六问是六次独立选择，答案可能互相矛盾，也可能与最初的脑洞方向脱节。所以收齐答案后必须逐项校验：

| 检查项 | 触发条件 | 处理 |
|--------|----------|------|
| 方向脱节 | 六问结果与初始方向不是同一类作品；或某几项与方向里的明确诉求相冲（方向要"章章打脸"、标签却是喜剧向） | 按方向回调，在立项记录里给出「原判断 → 回调后 → 依据的方向原话」三列。回调与用户已明说的项冲突时，以用户明说的为准 |

### 1.2 提示词自动完善

在 6 问结果基础上，按 `references/prompt-guide.md` 的优先级，把一句话方向补全为完整创作提示词：
- 必须明确：主角人设 +核心能力 / 金手指（含规则与限制）、等级/力量体系、第一个冲突与爽点、核心立意（一句话价值主张，建议 1 主 1 辅）。核心立意由 AI 直接定稿（A 路从拆书提炼、B 路从方向推出），随立项稿一并交用户过目。
  > 为什么是"必须明确"而不是"必须补全"：纯现实向题材（年代 / 都市生活 / 种田）没有金手指，硬填会产出假设定。此时须写替代驱动——"无金手指；靠什么推进"（例："靠手艺与生活常识级的经验差，范围限在自家营生内"）。写"无"也算完成，但不能留空（明确的无 ≠ 待定）。
- 应该补全：世界观规则、配角框架（至少 1 对手 + 1 盟友）、前三章节奏。
- 可以补全：名场面、中后期走向、语言风格。

主角设定为「群像戏」时的处理：**三种锚点模式与「三线并列」的模板改写法，见 `references/character-building.md`「群像戏的三种锚点模式」**。
本技能模板按单主角设计——**主锚点制是默认首选**；选定后写入 `00-大纲.md`「主锚点 / 群像说明」，注明选择理由。

将「作品基因（6 问结果 + 一句话卖点 + 黄金开篇 50 字 + 终极钩子）」与「完整创作提示词」写入 `00-大纲.md` 顶部（模板见 `templates/outline-template.md`）。

与上游主干的关系：上游主干写着「节奏蓝图 → 套路配方 → 爽点分布 → 章节细纲 → 悬念线」，顺序不变（先有节奏与配方，才排得出细纲）；变化的是交付时机：

- 闸门 1 只交到：节奏蓝图 ＋ 套路配方与频率 ＋ 爽点分布 ＋ 悬念线 ＋ 大纲第 6 节的卷级规划；
- 逐章细纲的"排写"与"交付"一起放到闸门 2。

不是把细纲删掉，是把它从"首批必须做完"改成"第二批单独做"。执行者读到主干里的"章节细纲"时一律按此理解——否则又会退化成"一次做齐"。

三条硬纪律（缺一即违规）：

1. 不许跳批、不许提前做下一批。 第 1 批交完就停——不要顺手把细纲也排了（那正是首屏 22 分钟的元凶）。同理，第 2 批交完不要顺手写第 1 章。
2. 下一批必须基于用户确认后的版本。 用户在第 1 批改了 `00-大纲`，第 2 批的细纲就得照改后的版本排——不许把用户改掉的东西又写回来。
3. 第 3 批的 `05` 是"据实物落规则"：写第 1 章时用技能基线规则（`references/prose-rules.md` ＋ 本书暂定的风格档），第 1 章成稿之后再把这本专属的规则固化成 `05`——先有实物再定规则，规则手册才不是空谈（用户指定顺序：「再产出第一章和写作规则」）。首批加速三条（都在治"等太久"）：

- **第 1 批不排逐章细纲**——只出大纲第 6 节的**卷级规划**（每卷范围与内容概要）；逐章留给第 2 批。
- 第 1 批只读必需的 `references/`（题材包 ＋ 套路库 ＋ 情绪模板 ＋ 已定的风格档四类），不预先通读全部参考文件。
- 第 1 批的 `.learnings/` 落四件（本节是"哪些底稿随哪一批落"的唯一口径）：`立项底稿.md`（立项账目）＋`立项参数.json`（立项第一步就跑 `scripts/set_word_range.py` 落字数区间——缺它写作期第一道门直接中止）＋`套路配方与爽点分布.md`（取库依据／配方表／兑付档位链／爽点分布统计——闸门 1 要交的就是它）＋`交付自检留痕.md`（本批自检 13 的记录）。`施工细账_卷N.md` 随闸门 3 补。

每批交付的方式：把该批文件用 `present_files` 推给用户 ＋ 一段简短的"这批是什么、看哪里"说明。这是交稿审阅，不是等用户答题。若用户在审阅时提出方向调整，回到 1.3 改全书剧情脉络，不要在人物与章节层打补丁。

## 阶段二：人物 / 情绪曲线　【产出归入「交付闸门 1」：与 `00`／`03` 一起交】

- 人物档案：`templates/character-template.md` → `01-人物档案.md`。
  - 每个主要角色必填 14 维度：人名 / 性别 / 身份 / 性格特点 / 目标 / 动机 / 抱负 / 价值观 / 矛盾 / 顿悟 / 欲望 / 恐惧 / 发展轨迹 / 一句话故事线。次要配角可省 9-11，但恐惧（12）与顿悟（10）不得省——没有恐惧的配角是工具人，没有顿悟的配角到最后仍是工具人。
  - 必须另写「角色视角故事线」：每个主要角色用他自己的视角复述一遍全书（他看到的、他在意的、他做的选择）。14 维度是零件，这一节是装好的成品。检查法：把互为对手的两人的视角故事线并排读，同一件事两种描述都成立。
  - 详版深挖：`character-template.md` 第 3 节——每个主要角色补三块：① 背景故事（须是一件具体的事）② 原生家庭（含"家庭给他的那条看不见的规矩"）③ 形象锚点（年龄体型 / 发型衣物 / 标志性动作或物件）。硬要求：背景故事必须能解释 14 维度里的「矛盾」与「恐惧」，解释不了说明前史是硬加的，重写。
  - 与全书剧情脉络互相咬合：第 3 节剧情脉络里每个关键决定都要能在档案里找到动机；档案里写了动机却没在剧情脉络里兑现的，补进剧情脉络或删掉该动机。
- 保留「一句话传播标签」（身份+反差点+欲望）与「评论区诱导设计」，后者须落到大纲的两次两难与拉扯上。
- 情绪曲线：`references/emotion-curve.md` + `templates/emotion-curve-template.md` → `02-情绪曲线.md`。按六大情绪标签对应节奏模板，规划每 3 章的情绪单元，并预留「评论区诱导」节点（两难选择/信息差/误解不解释/配角高光/规则争议）。每个情绪单元必须挂靠 `00-大纲.md` 第 3.4 节分幕总览的某一幕（若填了 3.5 深化层可细挂到某级冲突升级／某次拉扯／某次两难），挂不上的是水章。`emotion-curve.md` 里的 `[ ]` 清单是自检工具，抄入产出物时改为判定标记。
- 黄金开篇：已于 1.3.4 产出（`references/golden-opening.md` → `03-黄金开篇.md`，选定版已写入 00-大纲第 1 节）。本阶段仅复核：人物档案写完后，回到开篇看它承诺的东西是否与主角的真实动机一致——不一致则以人物档案为准重做三版（开篇承诺是给读者的第一层，主角动机是全书的地基，地基改了，承诺要跟着改）。

## 阶段三：逐章疯狂创作　【拆分：`第01章` ＝ 交付闸门 3；第 2 章起 ＝ 第 4 批连续创作】

> **分工**：正文写作另有独立技能 `prose-writer`（「正文写手」）——通用技能（不绑平台），**2026-10-09 起两边已解耦**：各自一套文件、各自维护，改动互不影响，可单独安装、可配合。**它已安装 → 本阶段撰写交它执行**；**未安装 → 本技能按下列流程自己写，效果一致，不得因此停下**。
> **交接点**：本技能负责到 `04-章节细纲` 与 `05-文体与写作规则`；进逐章写正文时，把项目路径（`novels/[书名]/`）＋「写第 X 章」交给它。
> **边界**：平台专属部分（黄金开篇／悬念钩子／情绪曲线／过审清单／爆点爽点布局／评论区诱导）**不进** `prose-writer`——它只收通用规则；这些平台要求仍由本技能在细纲与写作规则里定死，它照着兑现。

重要：按顺序逐章创作；每完成 5 章，生成节奏报告并询问用户数据反馈（完读率/追读率/评论关键词），据反馈调整后续大纲。报告落盘 `.learnings/节奏报告_第N-M章.md`；不足 5 章而材料可用时可以跑；拿不到后台数据时照出报告，但只做技术层归因 ＋ 显式写明数据层缺失，严禁推测填空（见 `references/feedback-loop.md` §5.1／§5.2）
节奏报告不靠感觉写：归因走 `references/market-trends.md` 第三节数据归因表（定位问题在开篇层/节奏层/承诺层/钩子层/人物层）；闭环走 `references/feedback-loop.md`（主观反馈用四问定位法 + 结论按沉淀去向表落库）；个体趋势与产能走 `references/writing-efficiency.md`。

> 若项目来自 pop 管线（存在 状态.md）或用户点名"用章纲/pop 管线写"，另读 `references/pop-pipeline-bridge.md`（番茄规则与 pop 产物冲突时番茄优先）。

> 找不到文件＝停下问，不许静默退化：上表任何一份读不到（尤其 `05`）——先停下来问用户「项目路径在哪」，拿到路径再继续；严禁「找不到就当没有」用基线规则直接开写。

### 3.2 写前分析

0. 本章兑付物定位：查 `04-章节细纲.md` 的本章条目第 2 项（本章兑付物），写下本章读者要拿到的那件东西，并回答「它推翻了读者此前的哪一个理解」。判据两条：① 推翻 > 补充（只补新信息不构成兑付）；② 信息兑付类必须说出口，位置在本章前 2/3，且必须比上一章的兑付更狠（同层＝重复）。答不出本章兑付物 → 本章是过渡章里的水章，回大纲层处理。
> 为什么它排在最前：旧版 3.2 只查六项，没有一项问「读者读完拿到什么」——六项全过、读者手里仍是空的，这正是"感觉没什么看点"的来源。

1. 开头钩子设计（最关键）：前 20% 必须有即时冲突/反常/危机，参考 `references/chapter-guide.md`（10 种开头技巧）与 `references/golden-opening.md` 避雷针。前 50 字决定书架页点击率。
2. 情绪单元与套路定位（上游主干，须在开头设计之前核对）：三步——① 查 `00-大纲.md` 的节奏蓝图，认本章属于哪个 3 章情绪单元、该单元的「必须完成的功能」本章负责兑现哪一项（一项都对不上＝水章）；② 查第 6.1 节套路配方表，定本章用哪条套路、哪个变体（连续 3 章未用到配方里任何一条，回大纲层问"这几章在做什么"）；③ 确认本章在「压-小扬-压-爆」单元中的任务，单章内至少 3 次情绪变化（见 `references/emotion-curve.md`）。
   ① 查 `00-大纲.md` 的节奏蓝图，认本章属于哪个 3 章情绪单元、该单元的「必须完成的功能」是哪几项、本章负责兑现其中哪一项（一项都对不上＝水章，回大纲层处理）；
   ② 查 第 6.1 节套路配方表，定本章用哪条套路、用哪个变体（连续 3 章未用到配方里任何一条，回大纲层问"这几章到底在做什么"）；
   ③ 确认本章在「压-小扬-压-爆」单元中的任务（压/小扬/爆预告），单章内至少 3 次情绪变化（见 `references/emotion-curve.md`）。
   > ①② 是上游本就有、此前从未出现在写前工序上的两道检查。章内写得再好，落在错误的情绪单元位置上仍是水章。
3. 事件单元规划（最关键，排在回合规划之前）：照 `04-章节细纲.md` 的事件单元表核对本章 2-4 个单元——逐个写清"形态（推力 / 探察 / 代价；言情与关系向题材把"探察"读作"主动试探"，见 `references/scene-beats.md` §七）→ 谁想要什么 → 结果 → 结束状态变了哪一项"。单元数 < 2 ＝ 本章素材撑不起一章（回大纲层合并章或引进新单元）；至少 1 个单元必须是主角主动发起的（探察型）。
   > 回合数 ≠ 事件数：第 1 章稿回合已从 1-2 涨到 6，用户仍判"还是一整章节就在讲一件事"——因为 6 个回合全落在"她送表/他拒收"同一个单元内。分不清"多件事"和"一件事的多个回合"，回合制等于没加。
4. 回合规划（最关键）：照 `.learnings/施工细账_卷N.md` 的「回合表」核对本章的回合（派生量：每单元 1-3 个 → 全章 2-12，典型 4-6；判定只认「每单元至少 1 个真回合」）——逐个写清"施压方 → 被压方 → 回应 → 局面变化（筹码/信息/关系/物理变了哪项）"。相邻回合填不出"和上一回合差在哪"＝同层重复，回大纲层重排。方法见 `references/scene-beats.md`。
5. 首章三项硬指标（仅第 1 章）：① 前 300 字 1 个爆点（矛盾同框／能力现形／代价前置／倒计时）② 前 1/3 1 个爽点/准爽点（碾压／信息兑付／认可；信息兑付类＝必须说出口，看穿了不说＝零爽点）③ 主角 ≥1 次主动行动。见 `references/golden-opening.md` 末节。三项缺一即返工，不得靠加描写弥补。
6. 场景规划：本章需 3-5 个场景，至少一个场景具备本情绪标签特征；前 300 字过 `references/golden-opening.md` 的三问（状态改变 / 有人要东西 / 阻力此刻在场）。
7. 章末钩子：先定五型（A 信息差／B 危机逼近／C 关系转折／D 规则异常／E 认知颠覆），再从 `references/hook-techniques.md`（10 种手法）挑具体做法；标注写「字母 + 中文名」（如 `A 信息差`），且与上一章轮换（相邻章不得同型，跑 `scripts/check_hook_rotation.py` 复核）。

### 3.3 撰写

先读 `references/my-methodology.md` 注入作者个人写法锚点（骨架未填时跳过，不得代填）。用 `templates/chapter-template.md` 生成章节。

新增 · 动笔前必做（治「碎／跳」的根，缺一不许写正文）：按模板「写前准备」区先出三个中间产物（顺序不可颠倒）——
⓪ 本章事件单元表（治「整章就一件事」· 必须最先做）：逐条列「形态（推力／探察／代价）→ 谁想要什么 → 结果 → 结束状态变了哪一项」，数得到 2-4 件才继续；只数到 1 件 → 停手回细纲补事件。两种"假 2-4 件"当场戳破：把同一件事拆成多场、把过程拆成阶段（"他第一次扔"＋"他第二次扔"＝一件事）。≥2 件是"他一个人做一件事"（无对手方）→ 这一章的字数一定补不上，处置＝回细纲配对手方（见 `references/scene-beats.md` §七）。
① 动作链（治「跳」）：逐场戏列关键动作的物理顺序，相邻两步显式标注四类过渡（姿态变更／空间位移／取物／时间跳转）；标不出过渡的地方就是「跳」，当场补步骤；
② 信息增量表（治「碎」）：逐场戏列每一轮（一次对白来回／一个叙述回合）改变了什么（新事实／立场变化／关系推进／物理变化）；写不出增量的那一轮就是「碎」，删掉或换内容。
依据 `references/prose-rules-supplement.md` S7.1。这不是"写后挑错"，是"写前不给它出现的机会"——用户 2026-09-23 指出的"gemini 3.8 生成的 `ch001` 没有这类问题"，走的正是这个路子。
> 为什么把⓪提到写前：甲0「事件单元数」早就立了，但它只写在「写后自检清单」里，写前清单没有它，结果每次都是写完才发现"这一章只有一件事"。实测：第 2 章全部门禁逐条通过，读者一句「全程也不知道在讲什么」——整章只装了一件事却被拆成 6 场。判据在"写后"表里、不在"写前"清单里 ＝ 等到能查它时已经晚了。

两层分工：写什么——情节、冲突、爽点、钩子——**在大纲层已经定死，写作期只做兑现；怎么写成字——句、段、描写、用词——走**通用文笔规则，与形态无关。硬约束：

- 场景层 · 按爽点形态兑现（与 1.1 的「爽点形态」字段联动）：碾压类＝写成对手被压过的场面（要当众、要有人看见）；信息兑付类＝写成"读者比场上人早一步明白"的时刻；认可类＝写成可见的具体得失（第一笔钱、第一口新锅、有人点名称赞、日子量得出的变化），严禁套打脸结构；关系兑付类＝写成一次可指认的关系推进动作（他主动来了一趟、他把那句话说了、他留下来没走、他先松了手），严禁用旁白宣布关系变化。判断法两条：① 靠"有人被羞辱"而本书是认可类＝写错了；② 是情绪或氛围而不是动作而本书是关系兑付类＝写错了。
- 文笔层 · 死线级硬约束：每次动笔写正文，必须先通读 `references/prose-rules.md`（《通用小说正文写作规则》，文笔层唯一真源），按叙述策略 A1-A12 与规则 1-42 执行；标"死线"的各项任一不过，直接重写相关段落，不做局部遮掩。与剧情/形态无关，全题材一致。
  - 另须遵守 `references/prose-rules-supplement.md`《本地附加条款》（与用户原文分开存放以免污染原件；冲突时以本文件为准——它是后下达的、优先级更高的要求）。分三批：
    - 格式类· S1 正文零破折号：`——` / `—` / `–` 三种形态任一出现在正文即不合格，须逐处改写句子（换标点凑数会撞死线 27/28/29）。规划类文档（大纲／人物档案／细纲／记忆文件）不受此限。
    - 执行类· S3 信息承载／S4 场景具现／S5 碎句配额：这三条不是新规则，是原文条款的「可判定实例」。用户 2026-09-22 以 4 张截图批「信息走对话做成没信息的短句乒乓球，读者根本读不到东西」「场景事件描述不完整，读者无法在脑内具现」——原文只有原则（S3↔第 8/12/27/28/41 条；S4↔第 6/7/27/28/30 条；S5↔第 28/29/31 条），没有可执行动作，判据与改法见 supplement。
      - 「风格档位 + 通用硬伤」两层：用户 2026-09-23 交付 7 本异风格长篇并指正「那个 txt 只是说在言情上的文笔描述不错，但也有专门写对话文的，不能一刀全割掉，这种不同的方式都可以有的；但病句、碎句、跳、上下句描述错误，这种问题是通用不能有的」。据此——风格层不设门槛（对白占比 0–94%／均段长 12–149／短句率 0–45%／碎句链 0–15／短对白链 0–15 都是正例区间），改为写前「选风格档（A–E）」+ 档内一致性检查；硬伤层只保留四类通用错误（病句／碎句／跳／上下句描述错误），判据＝承接测试四问，须逐句举证，禁止打勾。全部风格类阈值一并撤销。
      - 两词定死口径：碎＝「句子短且看不出具体是要干什么，看不出行为模式和逻辑」（碎 ≠ 句子短——判据是「意图可见＋逻辑可见」；同为 12 行连续短对白，悬疑样本第 3 章算碎、《宠宠欲动》第 137 章不算，因为那是审讯）；跳＝「一个情节到下一个情节是跳跃的，没有链接」（动作级缺环，不是场景级跳跃；用户原例「我躺在床上睁开了眼睛，打湿毛巾把脸好好地擦了一下，终于清醒过来了」缺了起身／下床／走到水盆边；唯一判据＝照着做一遍，中间步骤在不在）。故四问第 1、2 问改写为「有信息吗？看得出要干什么吗？」与「接得上吗？中间那几步在不在？」。
      - 「碎／跳」不可"正则化"（启发式对用户原例能命中，但正例与样本同值不可分，已撤除检测器）。判定由模型跑三段闭环（S7）：① 写前出「动作链＋信息增量表」（治根）；② 写后由模型跑「四问自检子流程」，输出举证表、不合格就地改、复跑至全过（治标）；③ 上线前做污染测试自证。
      - 必做动作 · 遮蔽测试（S3.2）：遮住本章所有含引号的行，只读剩下的叙述；读不出「在哪／谁在场／围绕什么物件／局面变了什么」即为不合格（说明信息全压在对话里）。脚本报告里的「遮蔽测试待办段」会列出所有连续 ≥3 行纯对白的位置，逐段遮读，禁止打勾。

- **字数按题材分档**——本书区间在立项时定死，落在 `.learnings/立项参数.json`，两个门禁脚本自动读。分档表见 `references/fanqie-platform-facts.md` 四·补（通用 2200-2800／悬疑推理 2500-3500／都市言情 2000-3000／玄幻仙侠 3000-5000；算法侧：<1500 判内容稀疏、>4000 会插广告）。写前排配额，写后只做验收。

    - `--book` 别省：区间查找起点＝`--book` ＞ `--check` 的章节文件 ＞ 当前目录，从起点逐级向上找。一个路径都不给、又不在本书目录下运行时读不到本书口径——旧版会静默回落 2200-2800 且退出码 0；现在读到默认档就中止、退出码 3、不输出表。看到「区间来源未确定」→ 补 `--book`，别手敲数字。接续已有项目且没有该文件时，先按已有正文口径补落盘（`scripts/set_word_range.py`）。
  - 两把尺：`字数 = 段数 × 均段字数`，均段字数由写法决定（不是题材）——叙述驱动 26.8 字/段／对白驱动·长段 20.5／短句市井体 14.9（均取自正例样本）。`--avg-para` 不传按中值 23 算——写一句话一段的市井体时段数会被算少约三分之一。故 2200 字需 82-107 段（区间落 3000 字时约 112-146 段），一拍（施压→回应→局面变化）≈ 65 字 ≈ 3 段。
  - 这个数是"期望值"，不是"越碎越好"的下限：低于档位 25% 以上（如市井体落到 11 字/段以下）＝ 在拆句凑段。自查动作：随手取 3 处连续短段合成一段读一遍——更顺或没差别 → 原本就该是一段。判别句：这一段单独成行，是因为它需要一个停顿，还是因为我想让篇幅看起来更多？实测反例：第 2 章均段长 9.3、55% 的段落不到 10 字，读者判"全是短句子"。
  - 补法：某场差额 > 20% → 回细纲补「场上另外几个人各自的反应」与对白来回，不回正文加形容词（实测扩写补的全是别人的反应）。高于本书区间上限则删无功能元素（删元素，不删事件）。
- **去 AI 味**：避免「此外/然而/强调」等 AI 词汇；长短句交错；对话有角色个性与潜台词（见 `references/dialogue-writing.md`）。
- 去 AI 味 · 本版扩写：写的时候就避开，别等写完再改——按 `references/revision-methods.md` 第三节四层诊断执行（词汇层 / 句式层 / 结构层 / 情感层）。完整禁用清单唯一真源 `scripts/ai-flavor-lexicon.json`：四档——37 个 AI 词 ＋ 3 个语境词 ＋ 4 条句式模板（命中即 FAIL）／认知直述（提示项）／比喻（只报数）。查清单 `python scripts/chapter_stats.py --lexicon`，写后跑 `chapter_stats.py` 即自动机检。去 AI 味是过审底线不是加分项。
- 每章必留钩子，且钩子类型轮换；章末预留「评论区诱导留白」。

> 一句话判据：「读者在兑付前被消耗在哪了？」 —— 答案指向结构 → 回结构层；指向句子 → 才回正文。

> 六步法（本表"结构与文笔双重自查"中文笔层的执行方式）：
> ① 删减测试（死线 35/41 的执行动作）——机械化，不靠判断力：列出全章"只出现一次"的细节，逐个问四句（推进动作？改变关系？造氛围？已登记伏笔？），四问全否即删且不许补解释；再把余下句子逐句试着删掉，问"删了读者会误读或掉信息吗"，不会就删。"这句需要"是写作者的主观，删减测试不认主观。
> ② 逐句回读——每句问"谁对谁做了什么"，靠回读才理清的句子立即标记重写；
> ③ 逐段追动作——每段填"上一动作的结束状态 → 下一动作的起点"，关键道具在哪、在谁手上不得跳跃；
> ④ 八类高频病句照表查（见下）；
> ⑤ 专业逻辑核验（第 25 条「职业逻辑」的执行动作）——凡出现工序、术语、行业规矩、器物结构的句子，自问"这门手艺的从业者会这么说吗"（实测反例：「放了一个月的表，机芯不会长出新毛病」——停一个月的表油会凝、轴尖会锈，恰恰长新毛病）；
> ⑥ 全章朗读——读不顺的地方就是问题，不辩解。
>
> 八类高频病句**（规则第 1/18/24/26/27/28/29 条**均已覆盖却仍漏过）：
> ① 主语悬空——承前省略跨过插入语后失去主语；② 同一信息说两遍（"我站着就行"＋"她没坐"）；③ 动作与语义冲突（"收"＝收起 vs"归位"＝放回）；④ 指代无先行词；⑤ 搭配生硬（"笑得很短""等不到下文"）；⑥ 道具位置断链；⑦ 时间／年数不自检（"铺子开张那年他十二岁"与"31 岁"冲突）；⑧ 视角越界（从外部观察自己）。
>
> 逐条打勾时人不会真的逐句读，举证法与删减测试就是把"读"和"删"变成动作。自检记录写成"位置／问题类型／原句／修法"四栏表，无问题写"本轮 0 处"，不得留空。列死线清单前先 grep 出总数再列。

## 脚本

- `scripts/check_chapter_wordcount.py <章节文件>`（或 `--all <目录>`）：统计正文中文字数，报告是否落在本书区间（口径来自 `.learnings/立项参数.json`，逐章解析——黄金三章选递减结构时第 1-3 章按递减序列放行）；报告逐章打印「来源」，降级到内置默认 2200-2800 会显式告警，并点明那几章的判定不作数。已处理 Windows 控制台编码。
- `scripts/plan_word_quota.py --book <书名目录> --total <本书区间中值> --scenes <场数> [--weights ...] [--avg-para ...] [--check <章节文件>]`：单章字数配额表（写前用）——把「这一章 N 字」翻译成每场目标字／目标段数／建议拍数，写完再用 `--check` 对账。依据＝恒等式 `字数 = 段数 × 均段字数`（见 `references/benchmark-writing.md` 三·均段长）。区间自动读本书立项参数；`--total` 落在区间外会告警；读不到本书口径就中止（退出码 3）且不输出表。
- `scripts/format_chapter.py <文件或目录>`：清理章节文件中间多余 `---` 分隔符，仅保留首尾两个。
- `scripts/check_trigger_coverage.py [SKILL.md路径]`：触发面校验器——查 `description` / `metadata.trigger` 是否覆盖「接续已有项目」的说法（续写／接着写／继续写／写第 X 章／往下写／写正文），跑 12 条用例（正例 8 ＋ 反例 4）。改完 `description` 或 `trigger` 必须跑——触发词写错不会报错，只表现为"该触发时不触发"。

- `scripts/word_range.py`：字数区间的唯一解析入口——优先级＝命令行 `--min/--max` ＞ 本书 `.learnings/立项参数.json` ＞ `--range-config` 分档表 ＋ `--genre` ＞ 内置默认；②的查找起点＝`--book` ＞ 章节文件 ＞ 当前目录，逐级向上找；黄金三章递减结构按章号放行；返回带「来源」标签。上面两个门禁脚本都 import 它。`--selftest` 自带污染测试。
- `scripts/set_word_range.py --book <书名目录> --genre <题材> [--trend descending] [--dry-run] [--force]`：立项落参数——把题材分档写进 `novels/<书>/.learnings/立项参数.json`，数字一律从 `scripts/word-range.json` 取（不让人手敲）。已存在时不覆盖，除非 `--force`。
- `scripts/check_word_range_sync.py [--quiet] [--selftest]`：字数口径双真源校验器——逐项比对 `references/fanqie-platform-facts.md` 四·补的表格与 `scripts/word-range.json`（共 14 项），任一处不一致即退出码 1。`--selftest` 自带污染测试。改过任一侧必须跑——判据是「两边是否一致」，两边一起改成同一个值＝OK。

## 创作原则与禁忌

### 产出物硬规则（最高优先级｜2026-09-21 用户拍板，2026-09-23 增补「首稿默认」）

- ① 首稿默认：AI 先出稿，用户后改。提问是例外，不是流程。（2026-09-23 立，优先级高于本条以下所有条款，以及 1.0 / 1.1 / `adaptation-decision.md` / `remake-workflow.md` 的全部交互规定）
  收到任何输入（一句话方向 / 素材文档 / 参考原文），第一个交付物必须是一份完整草案，不是问题清单。
  - 由 AI 直接定稿（每项附「答案 ＋ 一句依据 ＋ 能换成什么／代价是什么」）：情绪标签 / 题材 / 主角 / 反差点 / 核心冲突 / 爽点形态 / 体量建议（字数与章数） / 人物设定 / 金手指规则 / 世界观 / 等级体系 / 反派与配角 / 改造方向 / 差异化方案 / 视角结构 / 书名 / 人名 / 章名。
  - 用户的位置是审稿人，不是答题人：改哪项说哪项，只重推受影响的下游项，不要求全盘重来。
  - 技能内所有选项库（12 项反差点 / 10 个题材 / 8 项红灯改造 / 四类爽点形态…）是 AI 的候选池，不是用户的答题卡。呈现给用户的必须是"这本书的具体方案"；池内无合适项时，AI 必须为这本书现造一项。
  - 唯一可开问的情形：用户未提供任何方向信息（如只说"帮我写本番茄小说"）。此时也不弹选项库，而是直接给 2-3 个完整故事方案（每个含题材 / 主角 / 一句话故事 / 为什么在番茄能行），让用户挑一个或说"都不对"。
  - 判据一句话：你准备发出的这条消息，如果用户只能回「A / B / C」，它就是错的形式；正确的形式是用户看完能回「对」或「这里改成 X」。
  - 「自主」≠「随便定」：每项必须给出依据（用户原话 / 平台数据 / 题材包 / 拆书证据）。给得出依据的，自己定；给不出依据的，说明它真的需要用户输入——此时才问，且要带上已有的判断和卡在哪。
  - 为什么立这条：用户已两次指出（"纯粹是给用户做选择"；「要么你还是不要让用户选了，选来选去还是那几个」），并给出反证——上游原版技能收到一句话就能直接重构出大纲/人设/世界观。根因是把本该 AI 干的创作工作误当成了用户的偏好决策。
- ② 用户的选择是输入，不是产出。立项阶段的提问只完成"把用户意图结构化"；交付物必须是 AI 基于这些输入主动写出的实质内容——全书剧情脉络全文、人物档案全文、章节细纲全文。用空表或"待用户填"结项＝立项未完成。
- 禁止残留模板标记：交付文档中不得出现 `[ ]` / `待定` / `待补` / `待用户填`。唯一例外是 `references/my-methodology.md` 的个人文风锚点（必须作者本人定），且须写明"为什么必须你定"并给出 2-3 个具体候选辅助决策。
- 「待写」与「待定」的分界：此前各模板写法不一，这里定死——
  `待写` ／ 空栏 ＝「这件事还没到发生的时候」（如第 30 章尚未创作、某条伏笔尚未埋设），在进度类文档里是正常状态，允许保留；
  `待定` ／ `待补` ／ `待用户填` ／ `[ ]` ＝「现在就该由 AI 定的事却空着」，在交付文档里一律不允许。
  判据一句话：这一格是「还没到时候」还是「现在就该有却空着」？前者留，后者补。
- 独立性验收：把 `00-大纲.md` 单独交给一个没参与过对话的人，他读完能说清"讲什么、谁跟谁、为什么争、最后怎样了"。做不到就回去补，不要进入章节创作。
**全书剧情脉络先于一切细节**：主线冲突 → 一段式概括 → 五句话脊椎 → 主要情节点骨架 → 分幕脉络总览（三幕/两难/道德前提/拉扯属可选深化层）。骨架没立住之前不写人物细节、不排情绪曲线、不开章。顺序颠倒必然返工。

### 写作层禁忌

- 强代入感 + 快节奏：每章有进展，不连续两章以上无爽点/无冲突。
- 情绪过山车：每 3 章完成一次「压-小扬-压-爆」；章末钩子强度不低于上一章。
- 展示而非讲述、去 AI 味：这是番茄读者留存的关键。
- 伏笔呼应：前文埋的线后文要收；长期伏笔 >30 章未回收即预警。
- 反派不蠢：衬托不出主角强；金手指有规则限制，不开无限制挂。
