# 上游资产继承清单（治理文件）

> **本文件的作用**：本技能是 SkillHub `@laoxi/fanqiexiaoshuoxiezuo`（v1.0.1，内部名 fanqie-crafter）的 **fork**。
> 用户定的工作方式是——**"在它原有的东西上面加上我们自己的东西"**。
> 因此必须有一份清单回答三件事：**上游有什么 / 我们继承得怎么样 / 我们加了什么**。
> 没有这份清单，迭代会走散：上游现成的好东西被自研内容挤到一边，反过来又在重复造轮子。
> **出处**：2026-09-22 用户指出——「剧情构造这块，原本的那个番茄 SKILL……他那个写的挺好的啊，直接拿过来啊，
> 我不是说了，在它原有的东西上面加上我们自己的东西」。当时本技能在剧情构造上自造了事件单元 / 回合 / 看点三问，
> 而把上游现成的 **十大套路配方** 与 **爽点分布统计** 晾在一边（后者从未接进流程）。

## 五、通用层外溢：`prose-writer`（「正文写手」）（2026-09-24 新增 · 独立技能）

### 5.1 两次指令，一个技能

**第一次（傍晚）**：用户提出「把里面写正文的那个写作模块，专门做个技能出来，让用户每次要求开始写正文的时候，自动开启这个技能」，并定了一条关键定位——「**用户不一定都会用这个技能，人家用别的技能的时候，写正文用我们这个新的写正文的技能，这是两个技能**」。据此建了 `fanqie-prose`。

**第二次（当晚，同一技能的定性被推翻重来）**：用户进一步要求——

> 「名字改一下，改成**正文写手**，它要求是**通用的规则**，**开头必给钩子这种专属番茄的套路不要写进去**，我不是给你发了很多小说案例吗，有**各种各样的开头写法和正文写法**，这个技能就是**独立的正文写作专属技能**，那种**短，碎，跳，上下句描述错误**这种通用型的问题都要规避好，并产出一个不错的正文。」

**⚠️ 这是对第一次定性的修正，不是补充。** 第一次建的是「番茄正文写手」（与本文笔层同源、23 个文件）；第二次要的是「**通用正文写作**」技能——**不带任何平台套路**。故：

| | 第一次（已作废） | 第二次（现行） |
|---|---|---|
| 技能名 | `fanqie-prose`（番茄正文写手） | **`prose-writer`（正文写手）** |
| 定位 | 番茄平台的正文环节 | **通用正文写作，不绑定任何平台** |
| 同名文件 | 23 个（含黄金开篇／钩子／情绪曲线等） | **14 个（只留通用层）** |

### 5.7 为什么是「复制」而不是「移动」

- **移动会破坏 fork 完整性**——上游原版文件（`dialogue-writing.md`／`continuity.md` 等）被搬走，`diff 上游` 会显示整篇删除，违反本文件总则一；

- **代价＝14 个同名文件存两份** → 用 `prose-writer/scripts/sync_check.py` 兜住（**已过污染测试**，四种状态 0/1/1/1/0 全判对）。
