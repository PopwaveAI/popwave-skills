# 修订方法层（revision-methods）

> 定位：能力 5「情感化改写」+ 能力 6「逻辑优化与去 AI 味」+ 能力 8「编辑校对」的落点资产。
> **为什么需要这个文件**：技能原有的是**验收清单**（`quality-checklist.md` 能判断"这段不生动"），但没有**生产方法**（怎么把它改生动）。清单只能发现病灶，不能治病。本文件补的就是这一层。
> 用法：3.3 撰写前扫第三节（**写的时候就避开，比写完再改省事**）；3.4 写后处理五节全过。
> 与外部技能的关系：不依赖 pop 系列。若用户已装 pop-write/sepia，可作为第二道复核，但本技能**自带完整方法层**——上架版不能假设用户装了别的技能。

## 第一节 · 情感化改写（把生硬文字改出情绪）

### 症状识别表（读到这些，说明需要改写）

| 症状 | 典型表现 |
|------|----------|
| 情绪被直接命名 | "她很生气""他很难过""大家都很惊讶" |
| 反应齐刷刷 | 所有人对同一事件反应一致、强度一致 |
| 情绪无着落 | 铺垫了情绪，但下文没有任何具体动作承接 |
| 情绪匀速 | 整章情绪起伏平均，没有峰值 |
| 该留白处说满了 | 关键情绪点用一句总结句讲完，读者没有参与空间 |

### 五种改写手法（照做即可）

**手法 1 · 抽象 → 具体**：把情绪名词换成只有这个人会做的动作。
> 改前：她很生气。
> 改后：她把碗放回桌上，声音不大，但屋里所有人都停了筷子。

**手法 2 · 陈述 → 错位动作**：情绪与动作不同步，比同步更真。
> 改前：听到孩子哭，她立刻跑过去。
> 改后：孩子哭的时候她没动。等她把手里活计收进箱子、盖上盖、扣好锁，才慢慢转过身去。

**手法 3 · 告知 → 留白**：不说破，让读者自己得出结论。
> 改前：他知道，自己这一走，就再也回不来了。
> 改后：他把门虚掩上——从前他走，从不虚掩门。

**手法 4 · 均匀 → 破坏节奏**：长短句交错，用断句制造情绪顿点。
> 改前：她走进院子，看见母亲在洗衣，弟弟在玩泥巴，父亲的房门关着。
> 改后：她走进院子。母亲在洗衣。弟弟在玩泥巴，脸上糊了一半。父亲的房门关着。

**手法 5 · 满 → 欠一点**：情绪最重的地方，少说半句。番茄读者对"被喂满"的段落反应最差。
> 改前：她终于明白了，原来这三年所有的眼泪都白流了，她恨自己太傻，恨他太狠。
> 改后：她终于明白过来。三年。她数了数，然后笑了——笑得跟前几次都不一样。

### 改写三问（改完自查）
1. 这段里有没有**直接命名的情绪词**？能换动作吗？
2. 这段的情绪**能被演出来吗**？还是只能被作者告知？
3. 删掉最后一句，读者还懂吗？懂就删。

## 第二节 · 逻辑优化（把因果理顺）

### 因果链三步检查（逐个场景过）

```
事件 A（发生了什么）
  ↓ 必须有：这个人的动机
行为 B（这个人做了什么）
  ↓ 必须有：行为会导致的结果
结果 C（后来怎样了）
```

**A→B 断裂**＝动机不足（人物为剧情服务）；**B→C 断裂**＝结果不合理（巧合驱动）。两处任一断裂，读者就会说"假"。

### 六种常见逻辑断裂与修法

| 断裂 | 表现 | 修法 |
|------|------|------|
| **动机缺失** | 角色突然翻脸/突然帮忙，前文没铺垫 | 在前 2 章内补一个可观察的理由（不是内心独白，是行为） |
| **信息越界** | 角色知道了他不该知道的事 | 补一条获知路径，或把他知道的事改成猜的 |
| **能力越界** | 金手指做了规则外的事 | 要么改剧情，要么在 `STORY_BIBLE.md` 里补规则（**不可默默破例**） |
| **时间冲突** | 前文说三天后，这章活动排不下 | 回查 `.learnings/PLOT_POINTS.md` 的时间标记，改这章而不是改前文 |
| **巧合驱动** | 关键时刻恰好有人经过/恰好被听见 | 让这个"巧合"在更早的章节埋过一次；埋不了就换解法 |
| **人设失守** | 角色做了不符合性格的事且无解释 | 补解释（下一章内），或改成符合性格的做法（**成长除外，成长需标注**） |

### 结构合理性（章级）
- 本章事件能否**一句话**说清"谁做了什么、导致什么"？说不清＝结构散。
- 本章的转折点是否落在**后半段**？前半段转折＝节奏前置，读者后半段会觉得空。

## 第三节 · 去 AI 味（四层诊断｜**本技能最关键的修订环节**）

> 番茄官方把「AI 粗制滥造」列为四类低质违规之首，纯 AI 生成**永久封禁**。去 AI 味不是润色加分项，是**过审底线**。

### 四层诊断表

| 层 | 症状 | 检查方式 |
|----|------|----------|
| **1 词汇层** | 高频 AI 词、书面套语、四字堆砌 | 可检索，见下方黑名单 |
| **2 句式层** | 排比三连、总分总、段落等长、连接词泛滥 | `chapter_stats.py` 的"连续 3 段等长段落"项 + 人工 |
| **3 结构层** | 章章同构（同开场/同转折/同收尾）、场景骨架重复 | `chapter_stats.py` 的相邻章骨架重复率；人工对比相邻章 |
| **4 情感层** | 情绪被命名、所有人理性克制、情绪无过渡 | 第一节的改写三问 |

### 层 1 · 词汇层：检索替换黑名单

**可直接全局检索并替换/删除**：

```
此外 / 然而 / 总而言之 / 值得注意的是 / 综上所述 / 首先其次最后
强调 / 凸显 / 彰显 / 诠释 / 意味着 / 某种程度上 / 无疑 / 显然
淋漓尽致 / 淋漓尽致地 / 生动地 / 深刻地 / 深刻地意识到 / 不禁 / 不由得
微微一笑 / 嘴角勾起一抹弧度 / 勾起唇角 / 眸光一暗 / 眸色深沉 / 浑身一震
瞳孔骤缩 / 头皮发麻 / 心中一凛 / 心中暗道 / 一丝不易察觉的
复杂的情绪 / 五味杂陈 / 说不清道不明的
```

**替换原则**：不要找同义书面词替换（那还是 AI 味），而是**换成具体动作或直接删掉**。
> 改前：他心中不禁涌起一丝不易察觉的复杂情绪。
> 改后：他把杯子端起来，又放下。水一口没喝。

### 层 2 · 句式层：三种高发模式

| 模式 | 识别 | 改法 |
|------|------|------|
| **排比三连** | "他要的是X，他要的是Y，他要的是Z" | 留两句，第三句换个说法或直接删 |
| **总分总** | 先总述、分三点、再总结 | 砍掉总述与总结，直接从具体动作进 |
| **段段等长** | 连续 3 段字数接近、节奏相同 | 破坏其一：某段砍到 1 行，或并成一段。**这是 `chapter_stats.py` 会判 FAIL 的硬项** |

**连接词纪律**：网文段落之间靠**动作与场景切换**衔接，不靠"因此/于是/接着/然后"。连续两段用连接词起手即需改。

### 层 3 · 结构层：章与章不能长得一样

- **开场轮换**：不得连续 3 章用同一句式起手（如"XX 睁开眼"）。做法：建一个开场类型轮换表（对话起手 / 动作起手 / 环境起手 / 悬念起手），逐章轮换。
- **钩子轮换**：章末钩子类型不连续重复（`hook-techniques.md` 10 种轮换）。
- **转折位不固定**：不要每章都在同一比例处转折，否则读者能预判。

### 层 4 · 情感层：AI 写作最深的指纹

AI 生成文本的情绪特征是**"正确但不动人"**：情绪都写对了，但没有人会为它停下。三个具体表现：
1. 情绪被命名而非被演出（第一节已给五法）
2. **所有人情绪强度一致**——真人不会。有人在哭，有人在算账，有人在想晚饭。
3. **情绪没有过渡**——从愤怒到释然中间必须有一步"没反应过来"或"想岔了"。

### 去 AI 味的边界（三条，防止改过头）

1. **不是把句子改糙**。口语化 ≠ 语病。目标读者是番茄用户，要"顺"不要"野"。
2. **不是删形容词**。是删**无效**形容词（"璀璨/瑰丽"），保留具体的（"掉了漆的铜扣"）。
3. **不破坏人设声音**。市井角色说话可以糙，书生角色不行——去 AI 味要按角色分流。

### 与脚本的对接
跑 `python scripts/chapter_stats.py <章节文件>`，脚本会把词汇层与句式层的可量化项直接判 PASS/WARN/FAIL；层 3、层 4 需人工——**脚本过不了审，人才能**。

## 第四节 · 通俗化（面向番茄读者，45 岁以上占 45.7%）

| 要改的 | 改成 |
|--------|------|
| 长定语从句 | 拆成两个短句 |
| 生僻词、书面雅词 | 常用词 |
| 一句三个信息点 | 一句一个 |
| 人物首次出场只给姓氏 | 补一句能记住的身份特征 |
| 时间跳跃无标记 | 明写"三天后""第二年开春" |
| 圈层梗、网络缩写 | 直说意思 |

**不是降智，是降低阅读成本**。番茄读者在挤地铁、在躺床上、在哄孩子——每一处需要回读的地方都是流失点。

## 第五节 · 校对 SOP（基础版）

> 状态：**基础版**。首次实际返工后按真实短板扩充（已登记在 `capability-framework.md` 待补清单）。

### 五轮固定顺序（每轮只查一类，不要混着查）

| 轮 | 查什么 | 中文特有问题 |
|----|--------|-------------|
| 1 | **错别字与同音误用** | 再做/在座、以后/已后、其他/其它（全文统一） |
| 2 | **虚词与量词** | 的/地/得用法；"一位人""一只牛"类量词错配 |
| 3 | **称谓与一致性** | 同一人在全书中的称呼是否统一（本技能实测样本：索绰罗氏通篇以"大奶奶"出现，人称不能串）；角色名、地名、机构名逐一对 `CHARACTERS.md`/`LOCATIONS.md` |
| 4 | **数字与体例** | 中文数字/阿拉伯数字体例统一；年代、年龄、银钱数目与前文一致 |
| 5 | **标点与格式** | 对白全角引号（ASCII 直引号会让所有统计失真）；`python scripts/format_chapter.py` 先跑，再人工过一遍 |

### 机器先过，人后过
```bash
python scripts/format_chapter.py novels/[书名]/第XX章.md      # 格式与引号自动修
python scripts/check_chapter_wordcount.py novels/[书名]/第XX章.md  # 字数
python scripts/chapter_stats.py novels/[书名]/第XX章.md        # AI 痕迹/对话占比等
```
脚本能修的不占人的注意力，人的注意力留给脚本判不了的（称谓一致性、事实一致性）。

### 一致性自查（对照记忆文件）
- [ ] 本章出现的角色，`CHARACTERS.md` 里都有且状态一致（等级/位置/生死）
- [ ] 本章出现的地点，`LOCATIONS.md` 里都有
- [ ] 本章回收或埋设的伏笔，`PLOT_POINTS.md` 已更新
- [ ] 本章新出现的设定，`STORY_BIBLE.md` 已记录且不与旧规则冲突
