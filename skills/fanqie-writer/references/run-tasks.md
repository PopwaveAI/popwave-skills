# 任务细则与 run 契约

## 一次 run 的边界

一次 run 指用户发出一次写作请求到主 Agent 回复完成。这一轮只做 `状态.md` 里「下一步」声明的那个任务，只交一件主产物。判断锚点：回复里如果出现两个能独立验收的主产物（例如既有章纲又有正文），就违反了契约，拆成两轮。

允许在同一轮的附带动作：读文件、组装任务包、调一次写作工具、主产物落盘、更新 `状态.md`、更新 `剧情快照.md`（仅 T5/T6）、写章日志（仅 T5）。这些不算第二件主产物。

不允许：同一轮连做 T4 与 T5；同一轮连写两章正文；同一轮既写正文又出批次报告；把已完成的立项重做一遍。

## 每轮四步

1. **读状态**：`状态.md` 的「下一步」必须写成 `T5 · ch012 · 章纲已存在` 这种格式。没有 `状态.md` 或「下一步」为空：先做 T1，并在回复里说明这是补建流程，不是新增需求。
2. **声明本轮**：回复开头写「本轮只做 T4 · ch012，主产物 `章纲/ch012.md`」。需要用户选择（题材、主角名、字数区间、是否重写）时，用 popwave_ask_user 一次问完。
3. **组装任务包**：跑 `scripts/build_context.py`，只读配方列出的文件。脚本缺块会报错退出，按报错补文件，不用记忆代替文件。
4. **交付**：调写作工具（`task` 传任务号）或直接写；主产物落盘；重写 `状态.md`；T5 追加章日志与快照；然后报告变更与下一步。

## 状态.md 格式

```md
# 状态

- 已完成：T1、T2、T3（卷001）、T4（ch001-ch011）、T5（ch001-ch011）
- 下一步：T5 · ch012 · 章纲已存在，正文未写
- 更新时间：2026-11-03 14:20
```

「下一步」只能有一个任务号。T6 未通过、需要重写时，写成 `T5 · ch012 · 审稿要求重写：<一句原因>`，并标 `rewrite`。

## 任务之间的关系

- T1 是所有任务的上游。卖点卡不存在时，除 T1 外的任务先停下补 T1。
- T2 依赖 T1。立项卡里的人物卡与金手指代价，是 T4/T5 的固定输入。
- T3 依赖 T1、T2。卷爽点表决定每 5 章要兑现什么，T4 必须从本卷爽点表取本章的兑现点。
- T4 依赖 T3 的本卷切片、剧情快照、人物卡。
- T5 依赖本章章纲。章纲缺失时本轮只能做 T4。
- T6 依赖 T5 的正文与章日志，只给结论与改法，不改正文。
- T7 依赖本批五章的日志与卖点卡，不重新审每一章。

## 失败与中断

- 写作工具返回错误：按错误类型处理。context 超预算 → 重新跑 `build_context.py`，删无关块，不改写原文；工具缺失或非预算错误 → 本轮不重试超过一次，改为主 Agent 自己写，并在回复里写明用了哪个模型。
- 用户中途改需求：本轮已产出的主产物保留，`状态.md` 写清「中断原因 + 下一轮任务」，下一轮从状态继续，不重做已完成部分。
- 已写章节要重写：只重写用户点名的章；旧正文另存 `正文/chNNN.旧.md`；状态写 `T5 · chNNN · rewrite`；不连带重写后续章。

## 交付前检查

1. `scripts/check_chapter.py` 通过（正文任务）。
2. `scripts/check_state.py` 通过（每轮都跑）。
3. 主产物路径与任务表一致，文件名不改。
4. 回复写清：本轮任务、主产物路径、字数或条目数、下一步任务。
