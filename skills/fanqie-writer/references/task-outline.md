# T3 卷爽点表 与 T4 单章章纲

## T3 卷爽点表

卷爽点表把「这一卷读者每 5 章能爽到什么」排成一张可执行的表，不是卷大纲，也不是章纲合集。T3 只交 `卷纲/卷NNN-爽点表.md`。

### 每卷必填

1. **卷目标**：这一卷结束时，主角的处境必须发生什么变化（地位、关系、资源、认知）。
2. **卷级敌人**：谁在阻止主角、他掌握什么、主角不能直接解决他的原因。
3. **爽点单元**：每 5 章一行，写「第 N-N+4 章：谁被压制 → 主角用什么翻盘 → 读者看到什么结果」。
4. **兑现章**：每个爽点写具体兑现章的章号，不写「中段」「后期」。
5. **升级点**：每 2-3 个爽点单元，主角获得什么新能力、新资源或新关系；写清代价。
6. **伏笔登记**：本卷埋什么、计划在哪一卷回收；不埋没有回收计划的伏笔。

### 判断锚点

- 每 5 章有一个可看见的翻盘结果 → 合格；连续 10 章只有铺垫 → 重排。
- 每个爽点都写了兑现章号 → 合格；只写「后续」→ 重写。
- 卷级敌人能解释「主角为什么现在打不过」→ 合格；敌人只是名字 → 补动机与手段。

## T4 单章章纲

章纲是下一轮写正文的唯一剧情依据。T4 只交 `章纲/chNNN.md`，不写正文、不写对白成稿。

### 必填字段

```md
# chNNN <章名>

- 本章目标：主角这一章要拿到/阻止/查明什么
- 本章冲突：谁阻止、代价是什么
- 事件（3-5 条）：
  1. ……
  2. ……
  3. ……
- 转折：哪条信息或哪个动作改变了局面
- 章末钩子：抛出新问题/升级冲突/改变关系/给出新目标，四选一以上
- 卖点兑现：本卷爽点表第 N 单元，读者在本章看到什么结果
- 出场人物：姓名 + 本章状态
- 时间与地点：与上一章间隔多久、在哪里
- 字数：2000-2500（用户约束优先）
```

### 判断锚点

- 事件 3-5 条，每条都能独立写成一场戏 → 合格；事件是「主角思考」「气氛紧张」→ 重写。
- 章末钩子给出新信息或新目标 → 合格；钩子只是「他握紧了拳头」→ 重写。
- 卖点兑现能对应到卷爽点表某一行 → 合格；写「本章很爽」→ 重写。
- 出场人物都有本章状态 → 合格；只列名字 → 补状态。

## 写作要求

- 章纲写「发生什么」，不写「怎么写」。不写环境描写、心理描写和成段对白。
- 本章事件必须服务本章目标；与目标无关的支线删除或移到后续章。
- 用户约束里的禁写项写进章纲的「本章冲突」或「事件」约束，不让正文阶段才发现。
- T3/T4 调 `popwave-write-outline` 时，`task` 分别传 `T3`、`T4`，context 按 SKILL.md 配方组装。
