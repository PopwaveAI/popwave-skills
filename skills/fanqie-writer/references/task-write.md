# T5 正文、T6 审稿、T7 批末报告

## T5 单章正文

T5 只交 `正文/chNNN.md`，并追加 `剧情日志/chNNN.md`、更新 `剧情快照.md` 与 `状态.md`。其中正文是主产物，其余三件是收尾必做项。

### 输入顺序

1. 本章章纲全文：剧情只按它写，不自行改主线、不临场补设定。
2. 剧情快照：人物当前状态、未回收伏笔、道具位置、关系变化。
3. 上一章正文末 1000 字：只取末尾，保持语气与场景衔接，不读整章。
4. 出场人物卡：只取本章出场的人。
5. 卖点卡摘要 200 字 + 本章兑现点。
6. 用户约束：字数、视角、禁写项。
7. 文笔规则摘要 1500 字。

### 写法

- 开头三句内进入本章冲突，不写天气、起床、照镜子、上回回顾。
- 每场戏只做一件事：推进目标、制造冲突、揭示人物或埋/收伏笔。
- 台词推动情节或揭示人物；删掉寒暄、重复表态和作者借人物之口总结。
- 章末按章纲的钩子收，不把本章讲完讲散。
- 字数 2000-2500，用户约束优先。不够时扩有效场景与反应，不靠风景和回忆注水。

### 章日志（五行，不写剧透式长文）

```md
# chNNN 日志

- 本章事件：3 条以内，写发生了什么
- 人物变化：谁的状态/关系/认知变了
- 伏笔：新埋什么、回收了什么、仍未回收什么
- 道具：关键道具现在在哪、谁持有
- 下一章起点：下一章开始时的时间、地点、人物状态
```

### 剧情快照

`剧情快照.md` 只写当前时点，不按章累积。≤1500 字，包含：世界状态、主要人物状态、未回收伏笔、道具位置、关系变化、最近 3 章发生的事（各一句）。每次 T5 收尾整体重写，不追加旧章。

## T6 单章审稿

T6 只交审稿结论，写进 `剧情日志/chNNN.md` 末尾的「审稿」段，不改正文。发现硬伤时给出「问题句 + 改法 + 重写范围」。

### 八维检查

1. **连续性**：人数、物品、时间、人物状态四项与快照/上一章一致。
2. **人设**：每个重要行动都能找到性格、利益或关系上的理由。
3. **逻辑**：发现与反转有前文依据；人物不知道自己不可能知道的事。
4. **节奏**：本章有目标受阻、局面变化、情绪缓冲，不是全程同一强度。
5. **文笔**：视角不飘、句子闭合、细节有功能、对话可区分。
6. **AI 味**：高频套话与同质句式密度低，按 `ai-flavor.md` 判定。
7. **钩子**：章末有新问题、升级、关系变化或新目标。
8. **卖点兑现**：本章承诺的爽点在正文里能被看见，不靠旁白解释。

### 判定

- 任何一维出现「读者会回读才能理解」的硬伤 → FAIL，列重写范围。
- 只有措辞偏好、不影响理解 → PASS，列可选建议。
- FAIL 时不提供整章重写稿；重写由用户确认后的新一轮 T5 执行。

## T7 批末报告

T7 只交 `批次报告/第NNN批.md`，基于五章日志与卖点卡复盘，不重读五章正文。

### 必填

1. 本批五章的章号与一句话事件。
2. 卖点兑现情况：承诺了什么、实际兑现到第几章、读者是否能看见。
3. 连续性风险：未回收伏笔、道具悬空、人物状态矛盾。
4. 下一批改什么：最多 3 条可执行动作（如「第 16 章前回收铜钥匙」「减少旁白解释」）。
5. 数据缺口：没有读者数据时写「无数据」，不编造追读率。

### 判断锚点

- 每条改进动作都能落到具体章号或具体写法 → 合格；写「提升文笔」→ 重写。
- 报告里的章号与日志一致 → 合格；对不上 → 先修日志。
