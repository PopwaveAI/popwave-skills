# 去AI味改写

> 对中文正文做一次改写：先按三条规则做少量语感改写，再跑脚本收尾标点与字形。创作管线里唯一的改写执行方。

## 这个 Skill 做什么

**做**：按三条规则做少量语感改写；跑脚本统一标点与字形；改完做质量校验并回报。

**不做**：不做强度分级、不给前后对照、不讲脚本改了什么、不对外承诺任何降幅。不写初稿，不排章纲，不判档。

**产出**：改写后的正文（管线内写回项目文件；独立调用时给文本，用户自己取）。

## 三条语感规则

只改这三样，不动别的：

| # | 规则 | 动作 |
| :-: | :-- | :-- |
| 1 | 长句串动作 | 一句里三个以上动作的，按动作拆开；最重的那句单独收尾 |
| 2 | 同义短语重复 | 一段里近义短语出现两次以上的，只留一处 |
| 3 | 情绪直说 | 「心里一紧」「身上发凉」这类报情绪的，换成身体反应、动作或细节 |

**硬约束**：不新增原文没有的设定、道具、回忆、人物关系；不改事实、人价判断与情感极性。原文的口语、具体动作、个性语气词一个都不能丢。

语感改写**只服务于阅读质量**。实测这三条对朱雀分数没有贡献，甚至会让分数小回升，这是已知且接受的代价。

## 走法

1. 读输入：定位正文（项目章节文件或用户贴的文本），确认字数与分段，先留一份改前稿。
2. 改写：按三条规则过一遍，只动表达。
3. 跑脚本收尾：`python skills/pop-ai-reduce-lite/scripts/deai_gate.py <文件> --fix`。标点与字形归位由脚本做，不手工改。
4. 质量校验：见下一节。不过就回退语感改动。
5. 写回与留档（仅管线内）：写回新正文，旧正文留一份历史档。
6. 回报：回执一行，附本次命中条目。

**顺序不能反**：脚本必须放在改写之后。模型改写时会重新打出弯引号、冒号、破折号，脚本若在前面跑，这一步的红利会被覆盖掉。

## 质量校验

语感改写**允许分数回升，上限 0.05**（实测单次回升约 0.029）。但**质量提升必须被验证过，不能只是声称**。三道校验，任一条不过就回退语感改动、只交脚本结果：

1. **命中数必须降**：改写前后各跑一次脚本，长句串动作、同义短语重复、情绪直说三项的命中数必须都不高于改前。有任一项没降，说明那条规则没生效。
2. **内容守恒**：字数波动在 ±10% 以内；原文的人名、地名、道具名、数字一个不丢；不新增设定与回忆。
3. **盲评**：把改前稿与改后稿交独立评审（另起会话或换一个模型），不给顺序提示、不说哪份是改后稿，让它选阅读体验更好的一份并说明理由。选改后稿才算过；选改前稿就整段回退。

**分数回升超过 0.05**：只保留脚本的标点结果，语感改动整段回退。

## 标点与字形

**执行方是脚本，不是模型；动哪些项由脚本定，本文件不逐条列，也不在别处解释。** 这一轮的口径不写进回执，也不讲给作者听——作者要的是改后的正文。

## 写回与留档

管线内改项目正文时：新正文写回原文件；**旧正文必须留一份历史档**（同目录下，不改名、不显示、不打扰），作者说回退时用它。

对话流里只给改后的正文，不给前后对照、不给 diff。

## 回执

```
去AI味:正文|PASS
```

## 红线

1. 工程标签不动（锚点、刻度、单元边界这类精确技术名不属于叙事主体）。
2. 只改表达，不改事实、人设、剧情。
3. 旧正文必须留档，不许直接覆盖丢了。
4. 不给任何效果承诺，不说「能改到什么程度」。
5. 只交改后的正文，不讲这一轮改了什么、按什么标准改的。
6. 标点这一轮只由脚本做，不手工替改，也不借这一步改字词。
7. 只查不改的场景下，一个字都不许改。
8. 质量校验没过就回退语感改动，不许把没验过的稿子交出去。
