# 去AI味改写

> 对中文正文做一次改写：先按八条规则改语感，再跑一轮标点规范化。创作管线里唯一的改写执行方。
> 主干重写于 2026-09-20，旧版的「李白」流程（8 步脚本流水线、破式五层法、规则 JSON）已废。

## 这个 Skill 做什么

**做**：按八条规则改写正文；跑标点规范化与零风险机械项；改完自查并回报。
**不做**：不写初稿（那是 write）、不排章纲（outline）、不判档、不动工程标签、不做前后对照的界面。

**产出**：改写后的正文（管线内写回项目文件；独立调用时给文本，用户自己取）。

## 三种调用场景

| 场景 | 输入 | 产出 |
| :-- | :-- | :-- |
| 管线内（写在 write 之后） | 项目里的一章正文 | 改后正文写回 ＋ 旧版留档 ＋ 回执 |
| 独立调用（功能区 / 外部工具） | 用户贴的一段文本 | 改后正文，用户自己复制 |
| 只查不改 | 一章正文 | 走查清单（命中位置），一个字不改 |

作者只要说了「去 AI 味 / 润色 / 降 AI」就走本 skill。没说清场景时按「管线内」走，若发现没有项目文件，退成独立调用。

## 三条铁律（不得违反）

**立场守恒**：不改事实陈述（时间、地点、事件、数据）、价值判断（褒贬倾向）、情感极性。违反任一条即视为执行失败。

**血肉不丢**：原文的口语表达、具体动作描写、有温度的场景细节、个性语气词，一个都不能丢。只砍「虚」的，不碰「实」的。

**篇幅容差**：允许一成上下的浮动。删虚词必然减字，加白描必然增字，追求零波动不现实。

## 八条规则

| # | 规则 | 可判特征 | 动作 |
| :-: | :-- | :-- | :-- |
| 1 | 长句串动作 | 单句主要动作 ≥3，或超字数线 | 按动作拆成短句；最重的那句单独成句收尾 |
| 2 | 同义短语重复 | 同段近义短语命中 ≥2 处；「一X一X」≥2 处 | 只留一次 |
| 3 | 虚词冗余 | 「的、了、是、着、却、已经」超密度；「进行、加以、使得」 | 删到意思不变 |
| 4 | 句首单调 | 连续三段以同一主语或同一时间词开头 | 换指代或换语序 |
| 5 | 解释性交代句 | 「X 是 Y」介绍式判断句 | 改掉，让信息从动作或细节里自己漏出来 |
| 6 | 情绪直说 | 「心里一紧」「身上发凉」这类直接报情绪 | 换成身体反应、动作或细节 |
| 7 | 语域混用 | 一段之内口语与书面两种调子并存 | 一段只留一种调子；口语只留给人物自己的话 |
| 8 | 对话承载句雷同 | 连续三轮都是「人物＋动作＋冒号＋引语」 | 改成引语在前，或省掉承载句 |

前四条脚本能判，改写时逐条对；后四条要读懂段落再动。

**一条附则（保留自旧版，唯一经实采验证的比喻判据）**：抽象对偶比喻——抽象名词（命运／世界／时代／历史／人生／人性／压迫／真相／意义）接联结词（是／像／如同／宛如／化作／成了）接另一个抽象词（账本／契约／迷宫／深渊／棋局／天平／洪流／注脚）。命中则删或换成具体物。**贴合影象豁免**：喻体若与本作叙事真实贴合（主角真在下棋，则可写「棋手」），不判违规。

**硬约束**：不新增原文没有的设定、道具、回忆、人物关系。

## 标点规范化

改完语感后跑一次脚本，做一轮标点规范化与零风险机械项。**执行方是脚本，不是模型；这一轮动哪些项由脚本定，本文件不逐条列，也不在别处解释。**

脚本：`python skills/pop-ai-reduce-lite/scripts/deai_gate.py <正文文件> --fix`。改完把修复计数一并回报。

这一轮的判定口径不写进回执，也不讲给作者听。作者要的是改后的正文。

## 一次交付做完两件事

语感改写与标点规范化在同一次交付里做完，不许只做其中一件：

- 只跑脚本不碰语感：文字本身没变好，算半成品，退回重做。
- 只改语感不跑脚本：标点这一轮没做，同样不算完成。
- 两者一起做完再回报。

标点这一轮全部交给脚本，不手工替改；也不许借这一步动字词。

## 走法

1. 读输入：定位正文（项目章节文件或用户贴的文本），确认字数与分段。
2. 脚本预扫：`python skills/pop-ai-reduce-lite/scripts/deai_gate.py <文件> --profile body --json`，拿清单定位问题段。`body` 就是正文档，FAIL 项即必改项。
3. 按八条改写正文（含附则）。改写只动表达。
4. 标点规范化：`python skills/pop-ai-reduce-lite/scripts/deai_gate.py <文件> --fix`。这一步交给脚本，不手工改标点。
5. 自查：八条逐条过一遍，命中处给出原文与改后对照；确认三条铁律没破。
6. 写回与留档（仅管线内）：写回新正文，旧正文留一份历史档。
7. 回报：回执一行，加本次命中条目与修复计数。

## 写回与留档

管线内改项目正文时：新正文写回原文件；**旧正文必须留一份历史档**（同目录下的历史档，不改名、不显示、不打扰），作者说回退时用它。

对话流里只给改后的正文，**不给前后对照、不给 diff**。作者要对比就自己取。

## 回执

```
去AI味:正文|PASS
```
或命中有 WARN 时 `去AI味:正文|WARN×N`，并附上 WARN 条目与位置。

## 红线

1. 工程标签不动（锚点、刻度、单元边界这类精确技术名不属于叙事主体）。
2. 不改事实、人设、剧情，只改表达。
3. 旧正文必须留档，不许直接覆盖丢了。
4. 不承诺任何降幅数字，不给「能降到多少」的说法。
5. 输出、日志、文案里都不提检测口径的实现细节。
6. 标点这一轮只由脚本做，不手工替改，也不借这一步改字词。
7. 只查不改的场景下，一个字都不许改。
