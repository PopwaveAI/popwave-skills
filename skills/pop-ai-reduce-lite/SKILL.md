# pop-ai-reduce-lite · 快速去AI味

> v3.0.0 | 单轮4步管线 · 能改不删 · 零迭代 · 不改内容 · 表面降噪 + 内置 Node 验证脚本
>
> ⚠️ **路由规则**：用户说"降AI/去AI味/降朱雀/润色"→ **默认先走本 skill 做表层降噪**。跑完输出后询问用户是否深度去AI（见「表层后询问」节），确认后才路由到 `pop-ai-reduce` 执行深度叠层改写；用户明确指定深度时才跳过本步直达。

> 定位：**表层降噪器，不是润色器。** 不改角色感受、情节推进、场景描写。能改不删——保留信息，换掉套话外壳。深层AI味（情感扁平、Telling）走 `pop-ai-reduce`。

**执行模式**：主agent直执——单章改写+脚本验证+询问用户是同一交互闭环，无自然子agent适配点。

## 四步执行管线（SOP全内联）

**执行总则**：获取完整原文后开工。每步对全文执行，步间不回头修改，禁止中途验证或微调，4步全部完成后一次性输出文件。字数保留率规则见红线❌5。

### Step 1：结构骨架改写

把模板化开头结尾改成场景化表达，打破三段式僵化结构。**能改不删**——只有纯套话且与正文零关联时才删。

- **改写头**（不直接删，改为1-2字场景化起句，保留原句时间/氛围信息）：命中"在当今社会/随着…的发展（进步/降临）/近年来，随着/当下/众所周知/人们常说/在这个…的时代"类模板化开头。示例："随着夜幕的降临，黑衣人的身形骤然暴起"→"天擦黑，黑衣人的身形骤然暴起"
- **改写尾**（压缩改写为简短收尾，去掉展望套话但保留收束）：命中"综上所述/总而言之/总的来说/让我们拭目以待/相信在不久的将来…/随着…的不断发展，…将会…"及强行展望未来的段落。示例："总而言之，这个女人绝对不是等闲之辈，她的到来必将掀起波澜"→"这个女人，不简单"
- **打破三段式**：原文呈"首先→其次→最后"或"第一→第二→第三"三段并列时，把内容最弱的一段压缩为1-2句融入其他段落，删掉序号词（由Step 4统一处理）。改写后结尾突兀时允许简短收尾句结束，但不生成新展望。

### Step 2：句长随机化

打破句子长度均匀分布，制造长短交错的视觉纹理。

1. 扫描全文，标记连续3句以上长度都在15-25字的均匀区
2. 在均匀区插入1-2个 ≤5字极短句打断节奏；不做句内拆分和扩展，不碰原文句子结构

**不拆叙述连续性**：插入后前后句需读者主动脑补因果关系或时间顺序→不插入。正确插入位=自然段落转折处、动作切换处；错误插入位=因果链中间、时间顺序流中间。只处理叙述句不改对话；无明显均匀区（句长已自然波动）则跳过此步；全文插入不超过3处。

### Step 3：破折号+英文引号+对仗清理

兜底清除表层AI味字符。

- **破折号**：保留≤1个/500字（只留列举式"包括A——B、C"或必要转折），其余替换为逗号/句号或删除后合并前后文
- **英文引号**：半角 `"..."` 和 `'...'` **全部替换**为中文全角引号；引号内文本不动
- **对仗排比**（只处理以下明确的模板式对仗，不动正常文学表达）：

| 命中模式 | 处理 |
|---------|------|
| "不仅……而且……" | 删除"不仅"，"而且"改逗号或"还" |
| "既……又……" | 拆为两句，或删除"既…又" |
| "既需要…又需要…还需要…" | 拆散排比，保留核心意思 |
| "一方面……另一方面……" | 合并为一句 |
| 连续3句以上结构高度一致的排比 | 保留第一句，其余拆散 |

（"无比怀念又无比心痛"这类不是模板对仗，不处理。）

### Step 4：过渡词改写

**能改就改，改不动才删**——优先替换保留衔接，避免删词造成句间断裂；替换后仍需连接时用一个口语词补位不留空。只处理明确模板连接词，不动"然而""但是"等自然转折词。

| 原文 | 改写为 |
|------|--------|
| 首先 / 第一 | "头一件事""上来就"；或直接删（句意已清晰时） |
| 其次 / 第二 | "还有就是""接着" |
| 最后 / 第三 | "末了""到最后" |
| 值得注意的是 | "说白了""关键是"；或直接删 |
| 由此可见 | "看得出来" |
| 与此同时 | "同一时间""这边还没完，那边又" |
| 进一步来说 | "往深了说" |
| 不禁让人 | 删掉，直接写感受 |

### 输出与验证

4步执行完毕后，读 `templates/rewrite-output.md` 按其格式生成双文件输出。输出位置：原文目录下新建 `正文-降AI味版本/`（与主skill一致），同名文件自动追加 `_v2`、`_v3`。

验证（内置脚本，禁止自写）：`node scripts/analyze_metrics.mjs`（字数保留率/破折号/引号/句长指标统计）+ `node scripts/validate_l2.mjs`（L2校验：文件存在+字节数+首末行）。若 `node` 不在PATH，用Popwave自带运行时：`C:\Users\HAN\AppData\Roaming\popwave\openclaw-runtime\current\node\node.exe`。

**加载保障**：本SKILL.md每次run强制注入；`templates/rewrite-output.md` 弱保障，生成输出前主动读取。

## 表层后询问

表层4步管线跑完、双文件输出后，**必须询问用户是否继续深度去AI**，判断权交给用户：

```
表层降噪已完成：
- 字数保留率：XX%（≥85% 达标）
- 残余AI味预估：X.XX（仅参考，非实测）

需要进一步深度去AI吗？先提醒两点：
1. 深度处理（pop-ai-reduce 18技法叠层改写）耗算力、耗时长
2. 深度改写会改变原文表达方式和文风（加入感官过滤、内心独白等），非表面清理
是否继续？1. 要 → 路由到 pop-ai-reduce；2. 不用 → 本次降AI到此为止
```

**残余AI味预估算法**（轻量，纯文本规则匹配，不调模型）。预估 = 0.40 基准 + 命中加分：

| 残余信号 | 命中 → 加分 |
|---|---|
| 破折号仍 >1个/100字 | +0.05 |
| "不是...而是..."仍 >1次/500字 | +0.10 |
| 句长仍集中 15-25 字（连击≥3） | +0.10 |
| 英文引号残留 | +0.05 |
| 对仗排比残留 | +0.10 |
| "忽然/突然"类概括式内心活动（"他忽然觉得/她忽然明白"）全文 >3 处 | +0.10 |
| 金句升华腔（"一切都很好""从不停歇""这就是生活的答案"类收尾） | +0.05 |

**仅作参考信息，不参与任何自动分流判断。** lite 不处理深层AI味（概括式内心、金句升华），但残余预估**必须如实反映**这些信号——让用户知道表层处理后还有多少深层AI味未动（实测出现过lite自评与深度实测口径不可比的问题）。

**分级建议**（询问用户时参考）：≤0.45 可不深度（表层已够）；0.45-0.65 建议深度；>0.65 强烈建议深度。

## ❌ 质量红线

| # | 红线 |
|:-:|:-----|
| ❌1 | **读取文件用宿主原生文件读取工具（Read）** — 不绑定特定命令 |
| ❌2 | **一轮完成禁止迭代** — 4步执行完即交付，不回改不微调 |
| ❌3 | **不修改内容** — 只做表层改写和替换，不改情节、感受、描写 |
| ❌4 | **一次任务仅一章** — 严禁单次任务改写多章 |
| ❌5 | **字数保留率 ≥ 85%** — 低于时**回查最多1轮**（重点查Step 1/Step 4过度删除，只补回误删信息不回改内容），仍不达标→报告标注"字数保留率偏低（已回查1轮）"直接交付，禁止第2轮回查 |
| ❌6 | **验证用内置脚本，禁止自写** — 指标统计用 `scripts/analyze_metrics.mjs`，L2 校验用 `scripts/validate_l2.mjs`。**所有指标数据必须来自脚本输出**，禁止自写脚本或自行估算（运行时自写=试错循环浪费算力） |
| ❌7 | **执行效率红线** — ①表层字符处理（引号/破折号）**一次性批量完成**，写文件前验证，禁止返工；②台词跨段的15-25字连击是**切分伪影**，直接跳过不分析；③指标一次跑全量，禁止多次小查询 |
