# 去AI味改写

> 由 agent 给主角与重要角色加直角引号，再由脚本把其余标点与字形规范化，最后按破式五层法过一遍语感。创作管线里唯一的去AI味执行方。

## 做什么

1. **agent 加引号**：读正文，给主角与重要角色的若干处加直角引号（见「加引号」一节）。
2. **脚本收尾**：跑脚本，把其余标点与字形规范化。
3. **自检语感**：按破式五层法过一遍，命中处给出原文与改后对照。
4. **写回与留档**，回报一行。

**不做**：不做强度分级、不做前后对照、不承诺任何降幅数字。

## 加引号

**这件事由 agent 做，脚本做不了。** 脚本认不出谁是主角，也判断不了哪一处人名值得加引号（照《十日终焉》的做法，加在人物被当作话题、称谓、对象的位置，不是每个主语都加）。

做法：

- 名单从**章纲或角色卡**取，不凭记忆。名单只装主角与重要角色，不装本章只出现一次的龙套。
- 只加不改：插「」两个字符，不改字、不删字、不调语序。
- 篇数按实测给：一章 2 处完全无效，8 处起效。**一个人名最多加 4 处、全章最多 12 处**，位置在全文里均匀铺开（不管送检方怎么切块，每块里都能落到几处）。出现次数最多的那一个人名优先。
- 名字已经落在直角引号里的不再重复加。落在对话引号内部会读成「……「某某」……」，这是这套写法的已知观感代价，先接受。

**省事档**：不想逐处挑位置时，可以把名单交给脚本由它均匀加——`--names "主角、重要角色"`，见参数表。效果是一样的（脚本按出现位置均匀取），差别只在位置是机器挑的还是人挑的。

## 语感五条：破式五层法

出处：`@user_741dc82b/libai`（李白.Skill:润色专家 v2.0）的「破式五层法」，v4.0.0 整包替换时进入本 skill，v7.0.0 随语感层一起撤掉，2026-09-21 写回。

| 层 | 操作 | 手段 |
| :-- | :-- | :-- |
| L1 破句式 | 打破排比、对仗、工整句式 | 拆长句为短句；删「不仅…而且…」「不是…而是…」对仗框架 |
| L2 破词汇 | 替换 AI 污染词 | 禁用词替换；书面词换口语词 |
| L3 破结构 | 打碎总分总、三段式 | 删小标题；合并三段为一段；中段插入跑题但微妙的细节 |
| L4 破思维 | 用「我的片面」替「AI 的全面」 | 删掉八成观点只留最痛一个；加私人记忆；允许逻辑跳跃 |
| L5 破语气 | 让「我」的立场与情绪站出来 | 「可能是」改成「我赌五毛钱是」；加小吐槽、怀疑、自嘲 |

**默认只自检，不自动改写。** 理由是本包实测过的代价，写清再动手：

- 这五条服务阅读质量，**对朱雀分数无贡献甚至负贡献**：字词层实测 ±0.0000，整段语感改写 +0.029。
- 把语感改动叠在标点红利上，同一段从 0.3559 回升到 0.7504（另一个记载：只跑脚本 0.6405，脚本加语感改写 0.7671）。
- 执行一次要十分钟，是纯脚本那一秒的数百倍。

所以默认流程是：第 3 步只**指出**命中处（给出原文与改后对照），不落笔；用户在回执后明确要求「按五条重写」时，才从 L1 往 L5 推进，每层留改前改后对照，读起来没变好就回退。

## 走法

1. 定位正文文件。
2. 复制一份改前稿留底。
3. 从章纲或角色卡取出本章的主角与重要角色名单。
4. 读正文，按「加引号」一节的篇数与位置规则，给名单里的人名加直角引号。
5. 跑脚本：`python "<包根>\scripts\deai_gate.py" <文件> --fix`。脚本原地改写其余标点与字形。
6. 按破式五层法自检，命中处列原文与改后对照。
7. 写回与留档（仅管线内）：新正文写回原文件，旧正文留一份历史档。
8. 回报：回执一行，附本次加引号处数与脚本修复条目。

第 4 步是唯一允许动正文的一步，且只许插引号。其余步骤不许改字词、句式、语感。

## 脚本位置与参数

**脚本位置**：`scripts/deai_gate.py`，路径相对**本包根目录**展开。本包根目录 = 本 skill 的 SKILL.md 所在目录，即你读取本 SKILL.md 时那个绝对路径的父目录（系统提示 `<available_skills>` 里该 skill 的 `<location>` 也是它），命令行等价于 `--skill` 的取值，逐台机器不同。不要写死绝对路径，不要用 `<pop-ai-reduce-lite 包根>/...` 这类写法，也不要到磁盘上搜脚本。

**参数表**，以 `python <包根>\scripts\deai_gate.py --help` 为准：

| 参数 | 作用 |
| :-- | :-- |
| `<文件>` | 位置参数，必填。本脚本只处理单个正文文件 |
| `--fix` | 原地机械修复，标点与字形归位，改后文本写回原文件 |
| `--names` | 省事档：把主角与重要角色名单交给脚本，由它均匀加引号。顿号或逗号分隔；不给则不做加引号 |
| `--name-marks` | 省事档下每个人名最多加几处，默认 4 |
| `--name-max` | 省事档下全章最多加几处，默认 12 |
| `--json` | 输出 JSON，供 agent 消费 |
| `-h` / `--help` | 打印用法 |

脚本只有以上参数。**不存在 `--profile`、`--prof`、`-r`**，这三项已于 2026-09-20 移除，不要试。报「找不到文件」时，脚本会打印它实际找的完整绝对路径与用法，照那条路径改一次即可，不要搜索磁盘。

## 标点与字形

动哪些项由脚本定，本文件不逐条列，也不在别处解释。这一轮的口径不写进回执，也不讲给作者听——作者要的是改后的正文。

一处要说清：**对话引号保持原样，脚本不再把弯引号全量转成直角引号**；直角引号只加在主角与重要角色身上。

## 红线

1. 只有第 4 步（加引号）允许动正文，且只许插「」两个字符；不许顺手改字词、句式、语感。
2. 旧正文必须留档，不许直接覆盖丢了。
3. 只交改后的正文，不讲这一轮改了什么、按什么标准改的。
4. 不承诺任何降幅数字，不说「能改到什么程度」。
5. 只查不改的场景下，一个字都不许改。
6. 工程标签不动（锚点、刻度、单元边界这类精确技术名不属于叙事主体）。
7. 名单从章纲或角色卡取，不凭记忆；不把正文读进上下文以外的用途。
8. 按五条重写只在用户明确要求时做；做了必须给改前改后对照，读起来没变好就回退。
