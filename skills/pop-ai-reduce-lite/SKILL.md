# pop-ai-reduce-lite · 快速去AI味

> v2.2.0 | 单轮4步管线 · 能改不删 · 零迭代 · 不改内容 · 表面降噪
>
> ⚠️ **路由规则**：用户说"降AI/去AI味/降朱雀/润色"→ **默认先走本 skill 做表层降噪**。跑完输出后询问用户"是否需要进一步深度去AI"——用户确认后才路由到 `pop-ai-reduce` 执行深度叠层改写。用户明确指定深度（如"直接深度去AI"）时才跳过本步直达 `pop-ai-reduce`。

## 管线顺序

```
Step 1: 结构骨架改写   —— 模板头尾改成场景化表达 + 打散三段式
Step 2: 句长随机化      —— 插极短句打破15-25字均匀区 [不拆叙述连续性]
Step 3: 破折号+英文引号+对仗 —— 兜底清理表层字符
Step 4: 过渡词改写      —— 词表改写为口语连接词
```

> 定位：**表层降噪器，不是润色器。** 不改角色感受、情节推进、场景描写。能改不删——保留信息，换掉套话外壳。深层AI味（情感扁平、Telling）走 `pop-ai-reduce`。

## 表层后询问（v2.2.0 新增）

表层 4 步管线跑完、双文件输出后，**必须询问用户是否继续深度去AI**，判断权交给用户：

```
表层降噪已完成：
- 字数保留率：XX%（≥85% 达标）
- 残余AI味预估：X.XX（仅参考，非实测）

需要进一步深度去AI吗（18技法叠层改写，效果更强但耗时更长）？
1. 要 → 主Agent 路由到 pop-ai-reduce 执行深度处理
2. 不用 → 本次降AI到此为止
```

**残余AI味预估算法**（轻量，纯文本规则匹配，不调模型）：

| 残余信号 | 命中 → 加分 |
|---|---|
| 破折号仍 >1个/100字 | +0.05 |
| "不是...而是..."仍 >1次/500字 | +0.10 |
| 句长仍集中 15-25 字 | +0.10 |
| 英文引号残留 | +0.05 |
| 对仗排比残留 | +0.10 |

预估 = 0.40 基准 + 命中加分。**仅作参考信息，不参与任何自动分流判断。**

**分级建议**（供询问用户时参考）：

| 预估区间 | 建议 |
|---|---|
| ≤0.45 | 可不深度（表层已够） |
| 0.45-0.65 | 建议深度 |
| >0.65 | 强烈建议深度 |

## ❌ 质量红线

| # | 红线 |
|:-:|:-----|
| ❌1 | **读取文件用宿主原生文件读取工具（Read）** — 不绑定特定命令 |
| ❌2 | **一轮完成禁止迭代** — 4步执行完即交付，不回改不微调 |
| ❌3 | **不修改内容** — 只做表层改写和替换，不改情节、感受、描写 |
| ❌4 | **一次任务仅一章** — 严禁单次任务改写多章 |
| ❌5 | **字数保留率 ≥ 85%** — 改后字数不得低于原文85%。若低于，**回查最多 1 轮**，补回被误删信息后仍不达标 → 报告标注"字数保留率偏低（已回查1轮）"，直接交付，不回查第 2 轮 |
