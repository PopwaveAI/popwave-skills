## v4.6.0 | 2026-08-14

### 防复制陷阱 + 防犹豫 + 朱雀预估限次（基于 run c79615fd / 527960cd 实测）

- **新增红线 #11（原文 AI 味分级）** — 改写前分级：>0.6 全改 / 0.4-0.6 轻改+深度区定点 / <0.4 保原文+定向改 1-2 处；模糊区间不硬切；改后字数差 <5% 时防复制自查

- **pipeline Step 4+5 新增朱雀预估规则** — 只做改前基线 + 改后终稿 2 次，迭代中禁止重复预估

### 背景

run c79615fd（第三章深度）：agent 面对低 AI 味原文连续 5 轮输出复制稿（膨胀比 1.0-1.08），浪费 10+ 轮后才转定向改方案——根因是 skill 没有"原文 AI 味分级"路径。run 527960cd（第二章深度）：主 agent 声明进入 L3 却零产出抛回用户决策，被子 agent 当场抓出 3 项违规。

## v4.5.0 | 2026-08-14

### 脚本迁移 Node.js（Popwave 标准运行时）+ 执行效率优化

- **analyze_metrics.py → `analyze_metrics.mjs`（Node 版）** — Popwave 环境无 Python 解释器（实测 run e4ba6de3 的 agent 花了 14 轮找 Python、被迫 Node 移植脚本）。改用 Node 后直接用 openclaw-runtime 自带 node 执行，零适配
- **validate_l2.py → `validate_l2.mjs`（Node 版）** — 同上
- **新增红线 #10（执行效率红线）** — ①表层字符一次性批量完成防返工；②台词跨段连击 = 切分伪影直接跳过；③指标一次跑全量；④node 不在 PATH 时用 Popwave 自带运行时
- **删除 .py 脚本**（保留 .mjs 为唯一实现，避免双份维护）

### 背景

run e4ba6de3（第一章 lite 表层）实测 63 次模型调用：约 14 次浪费在找 Python 运行时、3 次在引号替换返工、3 次在连击伪影分析、2 次在 PowerShell 转义。本轮目标：40 次必要调用 → 10 次以内。

## v4.3.0 | 2026-08-13

### 深度专用化：路由反转 + Step 3.5 表层收尾

- **路由反转** — 用户说"降AI/去AI味/降朱雀/润色"→ **先走 `pop-ai-reduce-lite` 表层降噪**（快速低成本），跑完询问用户是否需深度。用户确认要深度（或直接指定"深度去AI"）→ 本 skill 执行深度叠层改写。**删除自动分流判断，表层/深度由用户决策**
- **新增 Step 3.5 表层收尾（必做）** — 深度改写完成后必做表面清理：英文引号/标点归零、机械破折号删净、连接破折号改标点、表意破折号限频 ≤1/100字、"不是...而是..."含变体 ≤1/500字
- **新增红线 #8** — Step 3.5 表层收尾必做，不因深度通道豁免
- **skill.json** — displayName 改"（深度版）"；slashCommands 改为"深度去AI/深度降AI"（表层词让给 lite）
- **fallback 快速模式** — Step 4' 加简化表层收尾（英文引号归零 + 对话开头破折号清零）
- **循环上限管理（防算力浪费）** — ①Step 3.5 单遍处理即停，未达标项报告标注不回头再清；②句长检查最多微调 1 轮，1 轮后未达标报告标注直接交付

### 背景

v4.2.3 时代路由冲突：用户说"降AI"时本 skill 直接深度处理，表层问题（破折号/英文引号）常被跳过。且主 Agent 面对低 AI 味章节反复写复制稿（Run c79615fd，20 轮）。改为两段式（lite 表层 → 用户确认 → 本 skill 深度），判断权交给用户。

## v4.2.3 (2026-08-13)

子Agent 直接落盘 + 主Agent 轻量校验元数据（不回传全文）。

### 修改

- **`subagent-execution.md`**：子Agent 职责从"返回全文给主Agent写"改为"直接写入双文件 + 返回元数据（路径+字节数+首末行片段）"；主Agent 工作改为"轻量校验元数据（Test-Path + Length + 首末片段），失败则进 L3"；新增确认清单项"调用子Agent用执行类 purpose（implementation），勿用 implementation-check/background（只读）"
- **`SKILL.md`**：执行模式 L1/L2/L3 更新为"直接落盘→返回元数据→轻量校验"
- **`steps/pipeline-execute.md`**：Step 4+5 子Agent 模式说明改回"直接写文件，返回元数据"

### 背景

v4.2.1 曾将子Agent 改为"返回全文给主Agent写"，但长正文（数千字）全文回传到主Agent 上下文是保真度和算力的双重倒退。且根因是主Agent 调用子Agent 时误用只读 purpose（implementation-check），非子Agent 天生无写权限。改为方案 A：子Agent 直接落盘（内容只过一遍），返回元数据供主Agent 轻量校验（可检测失败、不搬全文）。

## v4.2.0 (2026-08-12)

基于 Run 637b36fc / dbbae295 的实际数据：每次 run 消耗 6 轮模型往返，其中 Step 1 朱雀预估 + Step 2a 节奏规划 是同一"扫描判断"思维链，Step 4 句长检查 + Step 5 双文件输出 是同一"检查+输出"链。分开执行增加 2 轮冗余往返。

### 修改

- **`steps/pipeline-execute.md`**：Step 1+2a 合并（朱雀预估+节奏规划）、Step 4+5 合并（句长检查+双文件输出）、Step 2 段落分层独立保留（依赖深度区选定结果，保持质量）、Step 3 叠层改写独立保留（核心创作，全注意力）。快速模式同步压缩为 3 步。
- **`SKILL.md`**：版本 4.1.1→4.2.0、速查表更新步骤描述
- **`references/subagent-execution.md`**：执行指令更新为 4 步流程

### 预期效果

- 每 run 模型轮次：6 → 4（-33%）
- 工具调用：~8 → ~6
- Step 2 和 Step 3 保持独立，分层质量和改写质量不回退
