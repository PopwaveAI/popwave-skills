# 子Agent执行模式：上下文组装规范

## 为什么用子Agent

主Agent 执行降AI改写的效果通常不如子Agent，原因：

| 问题 | 主Agent | 子Agent |
|:---|:---|:---|
| 上下文污染 | 历史对话、其他项目文件引用混杂 | 干净上下文，只有任务相关文件 |
| 注意力稀释 | 前N轮对话的细节争夺注意力 | 全注意力聚焦当前文本 |
| 文件加载意愿 | 倾向于略读或不读 reference | 独立任务，会系统读完所有文件 |
| 质量检查深度 | 容易跳过 Step 4/5 | 完整执行流水线 |

## 主Agent职责（确认 + 组装）

主Agent 收到降AI请求后，**不亲自改写**，而是做两件事：

### 1. 确认任务参数

快速向用户确认：
- **拆章（任务前置）**：先确认本次任务只处理几章。**一次任务仅一章**，用户给多章先按章拆分，逐章发起独立子Agent任务，禁止单章塞多章
- 原文是哪个文本（如果用户给了原文则跳过）——确认该文本仅为单章范围
- 角色的认知体系是什么（陈远=勇哥连麦/现代商业，张平凡=公文比喻，叶小棠=农家感官记忆）——如果用户没给，主动问
- 如果没有指定角色认知体系，从原文中提取关键词提示子Agent自行判断

### 2. 组装子Agent上下文

**一次任务仅组装一章原文。** 以下内容作为子Agent的任务参数传入：

```
【原文】
{粘贴用户提供的当前章节完整文本（仅一章，禁止跨章）}

【角色认知体系】
{主Agent确认或从原文提取的角色类比系统}
如果未确认：从原文分析主角的职业/背景/语言习惯，自动构建认知体系。

【输出位置】
{原文目录下新建的「正文-降AI味版本」文件夹完整路径}
产出双文件（纯正文 + 分析报告）都写入此文件夹，绝不覆盖原文。

【执行指令】
1. 读取所有 skill 文件（techniques.md → pipeline-execute.md → rewrite-output.md）
2. 按 pipeline-execute.md 的 Step 1-5 完整执行（本次任务仅处理此一章）
3. 输出双文件到【输出位置】指定文件夹：纯正文 + 分析报告
4. 返回结果摘要给主Agent（含输出文件完整路径）
```

## 子Agent职责（执行 + 输出）

子Agent 拿到干净上下文后：

1. 强制加载所有 reference 文件（techniques.md 为改写前必读）
2. 按 pipeline-execute.md 的 5 步流水线完整执行
3. 输出两个文件并返回执行摘要

## 上下文隔离规则

| 传入子Agent | 不传入子Agent |
|:---|:---|
| 用户原文全文 | 历史对话记录 |
| 角色认知体系说明 | 其他项目的文件 |
| 所有 skill 文件（techniques, pipeline, output-template） | 之前的改写版本 |
| 输出文件夹路径（`正文-降AI味版本/`） | 降朱雀的讨论过程 |
| | 主Agent自己的分析 |

> 核心原则：子Agent 看到的是一个"全新任务"，不知道前面发生过什么，只知道当前这段文本需要改写。

## 主Agent确认清单（给子Agent前必须检查）

- [ ] 单次任务 = 单章（已按章拆分，未跨章）
- [ ] 原文完整（未截断，且仅为当前章节范围）
- [ ] 角色认知体系已标注（或已指示子Agent自判）
- [ ] 输出文件夹路径已指定（原文目录下 `正文-降AI味版本/`，已建或可建）
- [ ] 已告知子Agent"读所有skill文件后执行"

## 返回后主Agent工作

子Agent 返回执行摘要后，主Agent：
1. 展示两个文件的路径给用户
2. 简述核心数据（朱雀预估降幅、膨胀比）
3. 提醒用户实测验证
