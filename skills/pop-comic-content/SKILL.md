# pop-comic-content

> 本技能负责把漫画转为内容物料。以模型读图的方式理解漫画页，以图片为主，`页面配置.json` 文字兜底，随后一键产出三件套：**口播脚本**（视频配音用）+ **种草/安利笔记**（小红书/公众号）+ **短视频推广文案**（标题/封面/话题/简介话术）。**（可选）出片**：把确认后的口播脚本与漫画页图组装成竖版短视频（**整页顺序播放 + 章节封面信息页 + xfade 淡入淡出**，配整段火山灿灿配音，**不烧字幕**，因成品图已内嵌文字，**切页点严格对齐口播段边界**）。**图片优先用 `分享/` 成品图**（有字、有水印），无则回退 `output/` 生图。**先读图后产出**，产出一套后停下来等老板确认。v1.1.0

**核心定位**：把已成稿的漫画页（page1~N.png、页面配置.json、OC/封面）转化为**可投放市场的内容物料**，服务"让更多人看到这部漫画"的推广目标。文本三件套是主产出；出片为可选项（确定性渲染：FFmpeg 整页拼接，TTS/混音脚本与 pop-video-brand 同源）。

**读图为主、配置兜底（铁律）**：所有内容产出的依据是模型**读图**得到的剧情理解，`页面配置.json` 与 `导演卡.md` 的文字只做锚点与保真兜底。不得跳过读图，凭记忆编造漫画内容。

**执行模式**：Step 0/1（素材收集 + 读图理解）是只读扫描与读图分析，可派子 agent 执行并回报素材清单、逐页白描表与卖点识别，由主 agent 写入；Step 2 起进入老板确认闸门（需多轮交互确认），Step 2-6（创作/配音/出片/混音/归档）由主 agent 直接执行。

## 做什么

输入：漫画页图片（page1~N.png）、`页面配置.json`（文字锚点）、可选 `导演卡.md`（剧情因果链）与 OC/封面图。
输出：一套内容物料（三份可投放文本），以及可选的竖版短视频。

| 产出 | 文件名 | 用途 | 主投平台 |
|:--|:--|:--|:--|
| 口播脚本 | `口播脚本.md` | 视频配音/解说稿 | 抖音/视频号/B站 |
| 种草笔记 | `种草安利笔记.md` | 图文安利笔记 | 小红书/公众号 |
| 推广文案 | `短视频推广文案.md` | 标题+封面+话题+简介话术 | 抖音/视频号 |
| 出片视频（可选） | `第{N}章-配音-v{版本}-final.mp4` | 图片+配音 | 抖音/视频号 |

核心管线：**Step 0 收集 → Step 1 读图理解 → Step 2 内容创作【确认闸门】→ Step 3 配音（可选）→ Step 4 出片（可选）→ Step 5 混音（可选）→ Step 6 导出归档**。

## 模型说明

| 工序 | 工具/方式 | 说明 |
|:-----|:---------|:-----|
| 读图理解（画面与剧情） | 模型多模态读图 | 主 agent（或子 agent）逐页 Read 漫画页，产出逐页画面白描与剧情因果锚点 |
| 内容创作 | DeepSeek/主 agent | 复用漫画剧情与卖点，按平台语法产出口碑内容 |
| TTS 配音（可选） | 火山灿灿 2.0（`scripts/tts_generate.py`） | key 固化在 `scripts/.env`（`VOLC_ARK_API_KEY`），脚本自动读取 |
| 出片渲染（可选） | FFmpeg 图片序列加 xfade（`scripts/build_comic_video.py`） | 整页顺序播放，加入封面信息页，切页点对齐口播段，不烧字幕；确定性渲染，不生成上千张 PNG 中间帧 |
| 混音（可选） | `scripts/mix_audio.py` | 以 ffmpeg adelay 与 amix 按时间轴定位混入，BGM 音量 0.15，不压人声 |
| 导出归档 | 主 agent 写文件 | 三件套与视频写入 `{项目}/内容/` 与 `{项目}/视频/` |

> 出片是**确定性渲染**（脚本与 FFmpeg），不采用 AI 视频（Seedance/GenerateVideo）。若老板只要文本三件套，Step 3/4/5 可跳过。

## 操作步骤（规程全文内联）

### Step 0: 收集素材

1. **扫描章目录**，确认素材来源：
   - **图片两套来源（重点）**：`分享/page01~N.png` 成品图（含对白、旁白与水印，**优先**，因为这是投放市场的真实样子，读图与出片首选）；`output/page1~N.png` 生图（无字、无水印，**回退替补**，在分享缺页时以对应页补齐，并标注「成品图缺失，用生图回退」）
   - `页面配置.json`（每页文字锚点）
   - `导演卡.md`（可选：剧情因果链、高光名场面、旁白文案，卖点识别的保真锚点）
   - OC/封面图（可选，种草与推广的视觉素材，通常在 `成品/` 或 `漫画/assets/characters/`）
2. 读 `页面配置.json`，提取每页文字锚点清单（page / 文字锚点 / 类型 os|dialogue|narration）。
3. 读 `导演卡.md`（若存在），提取因果链摘要。
4. 用 PIL 记录每页图片数量与尺寸（供视觉描述与画布规划），**记录每页来源（分享或 output）**。
5. 产出 `素材清单.md`：每页图片路径、来源、尺寸、文字锚点、导演卡摘要与 OC/封面路径。

**缺件兜底**：缺 `页面配置.json` 时，跳过文字锚点而只做读图，仍可执行，但锚点会偏弱；缺 `导演卡.md` 时，卖点识别只依靠读图与页面配置；`分享/` 与 `output/` 都缺页时，如实报告缺图，不得编造。

**完成判定**：成品图优先已检查；缺页回退已标注；文字锚点已提取；素材清单已写入，且含来源标注。

### Step 1: 读图理解

1. **逐页 Read 漫画图**（一次一页），每页产出五要素：

| page | 画面白描 | 氛围标签 | 剧情因果锚点 | 镜头感 | 展示模板 |
|:--|:--|:--|:--|:--|:--|
| page1 | 非对称三格，痛苦主体+青蓝裂纹 | 身体恐怖/心理惊悚 | 周明瑞头痛惊醒，穿越前奏 | 特写压迫 | T1@面部 |

   **展示模板**列：按画面特征映射 `T1` 推近（特写）、`T2` 拉远（全景）、`T3` 横移（长横格）、`T4` 纵移（竖分格）、`T5` 驻留（情绪落幅）与聚焦点，供 Step 2 口播脚本引用，参数见 `references/scene-template.md`。

2. **审查兜底（铁律❌2）**：单页被安全审查拦截时，用该页 `页面配置.json` 文字锚点与 `导演卡.md` 因果链补全画面理解，并标注 `[读图被拦截，配置文字兜底]`。**不得因读图失败中断管线**，继续处理下一页。
3. **氛围标签统一词汇表**：恐怖系（身体恐怖/心理惊悚/哥特恐怖/密恐/压迫）｜情绪系（脆弱/崩解/窒息/悬置/绝望）｜奇观系（史诗/壮观/神秘/崇高）。
4. **全章卖点识别**（口碑内容的唯一素材来源，铁律❌3 的保真基础）：剧情主线，一句话概括；高光与名场面，写明哪几页最抓眼球，例如视觉奇观、情绪爆发、剧情转折；观众爽点与悬念，即观众为什么想看下去；可安利卖点，包括人设、画风、世界观、剧情冲突。
5. 产出 `画面理解.md`（逐页五要素表与全章卖点识别）。

**完成判定**：所有页已处理，含拦截页兜底；每页五要素齐全；卖点识别完成；已写入。

### Step 2: 内容创作【🚪 老板确认闸门】

**素材驱动的六步创作法**（先想清楚再写，沿用 brand 骨架，把"价值点"换成漫画的"剧情卖点"）：

1. **提炼剧情真相**：找出这部漫画或这一章最打动人之处，从画面理解中的卖点识别提炼。
2. **立定立意**：确定这套内容想让观众带走的一句话，即北极星。
3. **选择角度**：从剧情卖点中选择切入角度，如强钩子、悬念、情感、视觉奇观。
4. **铺设结构**：明确三件套的功能位，口播负责推进与情绪线，种草负责感受与安利，推广负责钩子与互动。
5. **逐镜写作**：三件套逐条写作，卖点全部来自画面理解。
6. **闸门自检**：删掉画面描述，只看文字，验证能否讲清、是否有钩子、是否无虚构、是否像真人说话。

**① 口播脚本.md**（视频配音用，直接进 Step 3/4）：

```
[钩子 0-5s]   开场 1-2 句抓注意力（设问/悬念/反差）
[展开 5-50s]  按页推进，每页 1-2 句口播，情绪线递进
[收尾 50-60s] 钩子留白/悬念，引导追读
```

每句口播字段（绑定 page，保证画面与口播同步）：`seq / page / text / emotion / est_sec / template / focus`

- **template**：该页展示模板（`T1` 推近、`T2` 拉远、`T3` 横移、`T4` 纵移、`T5` 驻留），按情绪线选择，参数见 `references/scene-template.md`
- **focus**（仅 T1/T3/T4 需要）：聚焦点或扫过方向，如 `T1@镜中白狗`、`T3@左→右`；T2/T5 填 `—`。

**② 种草安利笔记.md**（小红书/公众号）：

```
标题（吸睛，含情绪或悬念，≤20字）
正文（3-5 段）：开场钩子（"这部漫画第一页就让我头皮发麻..."）→ 剧情亮点（全章主线+高光名场面）
  → 视觉卖点（画风/人设/OC/封面）→ 安利理由（人设/世界观/悬念/爽点）→ 结尾钩子（埋追读悬念）
话题标签：#漫画推荐 #悬疑漫画 ...（5-8 个）
```

**③ 短视频推广文案.md**（抖音/视频号）：

```
标题 ×3（不同角度，各 ≤25 字，含钩子/反差/悬念）
封面文案（大字，≤8 字，一眼抓人）
热门话题标签（5-8 个，贴合平台热门池）
视频简介话术（完整简介：钩子+内容预告+引导关注）
评论区引导（3-5 条预埋互动话术，引导讨论）
```

**写作总原则**：一、卖点全部来自画面理解（铁律❌3，不得虚构）；二、平台语法差异化，口播用口语化叙述，种草用感性安利，推广用短平快钩子，三件套角度互补，不重复同一句话；三、钩子优先，开头不平铺直叙；四、情绪线贯穿，例如按"痛醒、陌生、穿越、恐惧、惊悚"递进；五、每页至少一句且绑定 `page{N}`，总时长约 60 秒（约 240 至 300 字），**每句必须指定 template**（镜头感标注，出片不得自由发挥动效）；六、平台写法细节参照 `references/content-method.md`。

**🚪 确认闸门**：产出三件套后**须停下来等老板确认**（铁律❌4）。确认后方可进入 Step 3/4/5（如需视频）与 Step 6 归档；只要文本、不出片时，跳过 Step 3/4/5，直接归档。

**完成判定**：口播有钩子，每页至少一句并绑定 page，情绪线递进，时长约 60 秒，每句都有 template 与 focus；种草五要素齐全；推广五要素齐全；三件套卖点无虚构；**已等老板确认**（未确认不得进入出片或归档）。

### Step 3: TTS 配音（可选，火山灿灿）

**前置**：口播脚本已确认；火山控制台已开通「豆包语音合成大模型」；X-Api-Key 固化在 `scripts/.env`（`VOLC_ARK_API_KEY=<X-Api-Key>`，脚本自动读取；无 .env 时复制 `scripts/.env.example` 并填入。key 获取方式：访问 `https://console.volcengine.com/voice`，开通豆包语音合成大模型，然后在 API Key 管理页复制 X-Api-Key）。

**操作**：

1. **文案嵌入情绪指令**：每段前用全角括号 `（低沉，恐惧地）` `（松了口气，温暖）` `（神秘，压低）` 等引导语气，封面钩子句配 `（低沉，神秘地）`。seed-audio-1.0 是自然语言驱动的音频大模型，括号指令用于调节念法，且**不会被念出**，此点经 ASR 验证。
2. **整段一次合成**（含封面钩子句与正文全部内容，避免逐句拼接造成割裂或语速不均）：
   ```bash
   python scripts/tts_generate.py \
     --text "$(cat 口播全文含情绪指令.txt)" \
     --out "{项目}/视频/audio/v{版本}/full_voice.mp3" \
     --speech-rate 5
   ```
   - key 读取优先级依次为 `--api-key`、环境变量 `VOLC_ARK_API_KEY`、`scripts/.env`；三者皆缺时脚本报错并提示配置
   - 默认音色灿灿；`--speaker` 可换其他音色（如 `zh_female_zhixingnv_uranus_bigtts` 知性女声）
   - **统一使用 `--speech-rate +5`**（v0.11 终稿：+8 偏快且抹平情绪，+5 更从容，让情绪指令有发挥空间）；必要时用 `--loudness-rate`、`--pitch-rate` 微调
3. **ASR 对齐**：用 faster-whisper（small, word_timestamps）对整段音频做词级时间戳，按**纯文本（去掉情绪指令）**的汉字序列映射到每句，产出 `audio/v{版本}/对齐.json`（seq / start / end / duration / text；封面句为 seq0，正文各段依次）。对齐必须用纯文本，因情绪指令不进语音、不占时长。

**失败处理**：整段合成失败时重试整段；反复失败时更换 `--speaker` 备用音色，或对情绪指令做口语化微调。

**完成判定**：整段一次合成，无割裂；对齐.json 含全部句（封面 seq0 与正文）的 seq/start/end/duration；语速 +5，情绪指令生效，有起伏且无指令被念出；总时长与画面的偏差可接受。

### Step 4: 出片渲染（可选）

**核心决策（v0.10 起定稿）**：

| 决策 | 定稿方案 |
|:--|:--|
| 页面形态 | **整页顺序播放**（漫画是分格叙事，不得使用 Ken Burns 缩放） |
| 封面信息页 | **开头加章节封面与信息页**（长图顶部标题区，含书名与章节号） |
| 字幕 | **不烧字幕**（成品图已内嵌文字，避免重复或重叠） |
| 切页点 | **对齐口播段边界**（每页末句 end，xfade 过渡中心即切页点） |
| 配音 | **整段 TTS**（一次合成，语速统一无割裂） |

**输入**：老板确认的口播脚本；漫画页，按素材清单的来源记录取图，优先分享成品图；封面或信息页，取 `分享/长图-*.png` 顶部标题区或 `成品/封面/*-final.jpg`，无则跳过封面；`对齐.json`（每句 start 与 end）；`分镜标注.json`（可选，整页方案下主要用于页与 seq 的映射）。

**操作**：

1. **准备封面信息页**：优先取 `分享/长图-*.png` 顶部标题区，按竖版宽高比裁顶部 `h = w/0.5625`，用 LANCZOS 缩放到 1080×1920，存为 `cover.png`；无长图时用 `成品/封面/*-final.jpg`（已竖版，直接缩放）。封面配口播首句（书名钩子，如"苟在诸天，从黑暗佛门开始。"）。
2. **切页点计算**（脚本内已实现）：每页口播窗口为该页首句 start 至末句 end；经平滑处理消除句间间隙与重叠（`start = max(start, 前句end)`），保证切页点连续。
3. **FFmpeg 整页拼接**（`scripts/build_comic_video.py`）：
   ```bash
   python scripts/build_comic_video.py \
     --base <项目根目录> --share <分享成品图目录> \
     --align <对齐.json> --voice <整段配音.mp3> \
     --outdir {项目}/视频 --chapter N --v v{版本} \
     [--cover <封面.png> --cover-seq 0] \
     [--page-seq '{"cover":[0],"page01.png":[1,2],"page02.png":[3]}'] \
     [--trans 0.4] [--fg-h 1515]
   ```
   - `--page-seq`：页文件名到口播段 seq 列表的映射（0-based）；缺省为一页一段
   - 每个输入以 `-loop 1 -t dur -i img` 处理；每个输入的 filter 为：背景 scale 1080:1920，加模糊与压暗，前景等比缩放居中 overlay（分享页 820×1150，缩放为宽 1080、高 `FG_H=1515`，垂直居中）
   - 以 `xfade` 串联：`transition=fade duration=TRANS`，`offset = 上一页末句end - TRANS/2`；`TRANS=0.4`（比 0.5 利落）
   - 产出 `第{N}章-v{版本}.mp4`（无音轨中间候选），并自动混入整段配音，得到 `第{N}章-配音-v{版本}-final.mp4`（命名遵循落盘规范 §3.1b）
4. **逐帧校验（铁律）**：
   ```bash
   ffmpeg -ss <切页点> -i 第{N}章-配音-v{版本}-final.mp4 -frames:v 1 -q:v 2 check.png
   ```
   抽取封面、各切页点与各页中段帧，**逐张 Read 审查**：封面标题完整；无黑边变形；每页取景完整；切页点前后已切到对应页；无水印残留侵占；无字幕与画面文字重叠。发现问题后回改重出，直到通过。

**完成判定**：开头封面信息页（书名与章节号清晰、无黑边）；整页顺序播放，无 Ken Burns；切页点对齐口播段边界；无字幕与画面文字重叠；1080×1920、30fps、时长与配音一致（probe 校验）。

> 出片是确定性渲染（FFmpeg 图片序列加 xfade），不采用 AI 视频。若老板只要文本三件套，本步可跳过。

### Step 5: 混音（可选）

1. **BGM 选曲**：按漫画的**赛道与主要情绪段**，从 `references/bgm-guide.md` 的「赛道 × 情绪 → 参考曲目」表选定（示例：悬疑赛道钩子段配 `青衣` 国风戏腔悬疑感；紧张与高潮段配 `fever pitch` 电子狂热感），BGM 放 `{项目}/视频/bgm/bgm-*.mp3`。老板已指定 BGM 时直接使用，不重新选。
2. **配音/BGM 混入**（`scripts/mix_audio.py`，本质 ffmpeg adelay+amix+volume）：
   ```bash
   python scripts/mix_audio.py \
     --video 第{N}章-v1.mp4 \
     --audio-dir audio \
     --offsets "seg01.mp3=3.0,seg02.mp3=8.9,seg03.mp3=16.2,..." \
     --out 第{N}章-配音-v1-final.mp4 \
     [--bgm {项目}/视频/bgm/bgm-悬疑-青衣.mp3 --bgm-vol 0.15 --voice-vol 1.1]
   ```
   - `--offsets` 每项 `文件名=起始秒`，逗号分隔，与配音段一一对应；每段 `adelay` 延迟到对应时间点，`amix` 混合，`volume` 控制响度
   - 有 BGM 时传 `--bgm`（音量 0.15，循环铺满全程，不盖人声）；无 BGM 时省略，脚本自动只混配音
   - 注：整段配音流程（v0.11 起）的 final 已由 Step 4 的 `build_comic_video.py` 直接混入，本步主要用于 BGM 植入与逐段时间轴定位重混
3. **probe 校验**：分辨率 1080×1920；时长正确；含 AAC 音轨。

**完成判定**：BGM（若有）匹配赛道与情绪，且音量 0.15 不压人声；口播清晰，落在对应画面时间点；probe 三项通过；最终视频已交付。只要文本三件套时，本步可跳过。

### Step 6: 导出归档

1. **确认产出完整**：三件套、素材清单与画面理解均已存在且内容完整。
2. **写入目标目录**：文本三件套写入 `{项目}/内容/`（确认后即内容成品）；视频（若出片）写入 `{项目}/视频/`（`第{N}章-配音-v{版本}-final.mp4`）。命名遵循落盘规范 §3.1b。
3. **产出 `内容索引.md`** 汇总：
   ```markdown
   # 内容索引 · {章节名}

   章节：{章节名} | 产出日期：{date}
   来源：{漫画项目路径}

   ## 内容清单
   | 文件 | 用途 | 主投平台 |
   |:--|:--|:--|
   | 口播脚本.md | 视频配音/解说稿 | 抖音/视频号/B站 |
   | 种草安利笔记.md | 图文安利笔记 | 小红书/公众号 |
   | 短视频推广文案.md | 标题+封面+话题+简介 | 抖音/视频号 |
   | 第{N}章-配音-v{版本}-final.mp4 | 出片视频（若出片） | 抖音/视频号 |

   ## 核心卖点速览
   （一行列出本套内容的主打卖点，供后续投放时快速回顾）
   ```
4. 向老板汇报产出位置与内容索引。

**完成判定**：三件套、素材清单与画面理解全部在目标目录；若出片，final 视频已归档；内容索引.md 已写入；已向老板汇报。

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **先读图后产出** — Step 1 必须先 Read 漫画页完成画面理解，不得跳过读图直接凭项目记忆编造内容 | 内容与画面脱节，卖点虚构，口碑失真 |
| ❌2 | **读图为主、配置文字兜底** — 剧情理解以模型读图为主，`页面配置.json` 与 `导演卡.md` 的文字做锚点；图片被安全审查拦截时用配置文字补全，不得因读图失败中断 | 审查拦截页导致管线断裂，产出残缺 |
| ❌3 | **内容必须绑定真实剧情** — 种草/推广文案的卖点、亮点、悬念必须来自实际读图到的剧情，不得虚构书中不存在的剧情或卖点 | 安利内容与漫画不符，读者落差，口碑反噬 |
| ❌4 | **产出三件套后停下等确认** — Step 2 产出完成必须停下来等老板确认，确认后才进配音、出片与归档；不得一次性直接跑完全流程 | 方向跑偏，三件套作废，需返工三份 |
| ❌5 | **出片采用确定性渲染，不采用 AI 视频** — 用脚本与 FFmpeg 合成（整页顺序播放），不得使用 Seedance/GenerateVideo 按秒生成的 AI 视频 | 成本失控、画面不可控、与漫画版式相悖 |
| ❌6 | **产出写入版本化并加 final** — 文本三件套确认后放在 `内容/`（内容成品）；出片视频命名 `第{N}章-配音-v{版本}-final.mp4`，不得使用裸名 `成品.mp4` 或 `成品-配音.mp4`；`preview/frames/audio/` 是过程（见落盘规范 §3.1b §六） | 多版本无法区分、过程误当成品、与视觉管线脱节 |
