# pop-content-card

> 网文素材图文卡生产器。素材主题 → 5页手机可读HTML长图。v3.2.0

## 这个 Skill 做什么

输入：素材主题（如"恨海情天""100个古言氛围细节"）+ 可选账号配置 + 可选风格选择。
输出：一张 1080×1920 竖版 5 页 HTML 长图，手机可读，可导出 PDF。

素材类型：桥段 / 字句 / 人设 / 写法拆解。生产流程自包含，不依赖外部内容 skill。

## 三层×三维度对齐

三层各自回答三个问题，且"好"的标准从上游传导到下游，不衰减：

| 层 | 定位（解决什么） | 什么是好的 | 如何写出好的 |
|:--|:--|:--|:--|
| **内容方法论** | 定义内容价值——素材卡对读者有什么用 | 三可：可截图×可套用×可回看 | 素材句三层结构 + 生产公式 + 自检门禁 |
| **信息架构** | 把内容价值传导为可渲染数据 | 68字段全齐 + 8项校验（每项对应一个可） | JSON输出 + 字段映射 + 校验门禁 |
| **视觉模板** | 把数据传导为读者0.5秒可感知的视觉 | 占比≥75% + 无残留 + 三可可视化 | 母版填充 + body class切换 + 密度检查 |

**质量传导链**：三可 → 68字段×8校验 → 版式呈现。每层的"好"都从三可推导。脱离三可的工程检查（如"字段数对"但不"可截图"）= 不通过。

## 怎么运作

- **Step 1** 素材生产 → `steps/step1-content.md`（主题分析 → 素材类型判定 → 内容生产 → 5页文案组织）
- **Step 2** HTML视觉化 → `steps/step2-visual.md`（选风格 → 复制母版 → 切body class → 填账号占位符 → 按5页节奏填内容 → 密度检查 → 落盘）

默认 5 页结构（桥段型）：封面 → 公式+素材句 → 正误对照 → 名场面 → 收束地图。

## 素材类型与5页结构

| 类型 | P1 | P2 | P3 | P4 | P5 |
|:--|:--|:--|:--|:--|:--|
| **桥段** | 封面 | 公式+素材句 | 正误对照 | 名场面 | 收束地图 |
| **字句** | 封面 | 分类清单A | 分类清单B | 分类清单C | 使用指南 |
| **人设** | 封面 | 人设公式 | 素材句 | 正误对照 | 弧光+收束 |
| **写法** | 封面 | 原理拆解 | 正误对照 | 实战示范 | 检查清单 |

详见 `references/content-method.md`。

## 风格池（6套锁死色板）

| 风格 | body class | 气质 | 适配题材 |
|:-----|:-----------|:-----|:---------|
| 暖纸调（默认） | `theme-warm` | 温暖手作 | 情感/古言/治愈 |
| 墨韵调 | `theme-ink` | 冷静克制 | 现代/悬疑/都市 |
| 青碧调 | `theme-jade` | 清新自然 | 种田/治愈/日常 |
| 赤金调 | `theme-gold` | 华贵厚重 | 权谋/大女主/宫斗 |
| 暮紫调 | `theme-dusk` | 神秘梦幻 | 奇幻/修仙/幻想 |
| 极夜调 | `theme-night` | 深邃暗黑 | 暗黑/无限流/恐怖 |

用户未指定时用 `theme-warm`。切换方式：改 `<body>` 的 class 即可，禁止手改 CSS 变量。

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **不从空白写HTML** — 必须复制 `templates/html/master-template.html` 母版改槽位 | 版式崩坏 |
| ❌2 | **不改5页结构和模块类型** — 只填 `{{...}}` 占位符，不增删页面、不改CSS、不加新模块 | 设计失控 |
| ❌3 | **只用风格池配色** — 切 body class 选风格，禁止手改 `:root` 变量或内联写死颜色 | 色彩混乱 |
| ❌4 | **单页占比 ≥75% + 页脚安全区** — 满页不等于贴底，主内容不得碰到页脚 | 手机不可读 |

## 强弱加载保障

- **强保障**：本 SKILL.md 由 host 层每次 run 强制注入，100% 到达 agent 上下文
- **弱保障**：`steps/` `references/` `templates/` 需 agent 按 SKILL.md 指引主动 readFile，天然弱保障
- **设计原则**：设计 SKILL.md 时假设 step/reference 文件可能没读到，核心 SOP 骨架和铁律必须在 SKILL.md 自包含
