# pop-critic-panel

> 本技能负责多子 agent 盲评：以相互隔离的不同视野评审同一靶子，各视野在单轮内互不可见，最终由主 agent 回收裁决。v1.1.0：初始版。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 职责范围

**输入**：靶子，即一个或多个待审文件的路径；可选视角点名，默认为四团，用户可增加自定义视角。

**过程**：主 agent 组团，并行派出 N 个子 agent，每个子 agent 各自独立上下文、各自初始提示词、各自材料清单，随后进行单轮盲评，最后由主 agent 回收裁决。

**产出**：盲评报告，在对话中呈现并写入 `审查/盲评-{靶子名}-{YYYYMMDD}.md`。刺点分四类：**采纳、误报、冲突、存疑**。

**边界**：
- 只挑刺，不改文：产出止于报告；改与不改、如何改，均由用户决定。
- 只做单轮，不做多轮互辩：盲评的价值在于隔离。子 agent 一旦互相看到对方结论，立场便会趋同，多视野随之失效。冲突意见原样保留给用户，不安排"对辩和解"。
- 子 agent 只读不写入：挑刺结论回传主 agent，写入统一由主 agent 执行。

## 操作步骤（规程全文内联）

### Step 1 接收靶子并组团

1. 确认靶子：靶子为用户给出的文件路径列表，章纲、幕白描、卷纲、设定档、融合立项稿、正文均可。靶子含多个文件时，视为一个整体评审，例如"卷1全部幕白描"。
2. 确认视角团：默认为下表四团；用户可点名增删，或自带视角，提供一句视野描述即可入团。无特殊要求时不追问，直接开始执行。

**内置视角团（默认四团）**：

| 视角 | 身份一句话 | 视野边界（只读） | 评审尺 |
|:--|:--|:--|:--|
| 读者代表 | 12 岁手机滑动读者，每 30 秒要新东西 | 只读靶子本身，禁读一切背景/设定/日志 | 哪里会划走、哪里看不懂、哪里无聊；连续 3 次纯氛围就退出；第一屏没吸引力就退出 |
| 逻辑审查 | 连续性校对员 | 靶子＋`全书日志.md`（当前态） | 事实漂移、前后矛盾、人物行为没动机、时间地点对不上、设定和正文打架 |
| 赛道编辑 | 网文编辑部编辑 | 靶子＋大纲卷向（本卷到哪） | 爽点密度够不够、章末钩子断没断、蓄力是否超支、事件密度是否塌陷 |
| 设定考据 | 世界观守门员 | 靶子＋设定库/人物卡（按需点查） | 设定违背、术语不一致、力量越权、名词前后不统一 |

> 视野边界是刻意设置的信息不对称，不是疏漏：读者代表看不到设定，其挑出的问题才是真实的读者反应；考据不看剧情节奏，其挑出的问题才是纯设定问题。组装子 agent 提示词时须写明这一点，防止子 agent"好心"补读。

### Step 2 组装子 agent 提示词（模板骨架）

每个子 agent 一份提示词，按下列骨架填充。骨架全文内联，可直接复制使用：

```markdown
【身份】你是一名{视角名}。{身份一句话}。按本视角的评审尺评审下列材料。

【视野边界】只读：{材料清单（靶子＋该视角对照材料）}。不得读取任何其它文件。这是刻意设置的视野边界，不是疏漏；越界评审会让结论失真。

【评审尺】
{该视角的评审尺，逐条列出}

【纪律】
- 只挑刺，不改文：给出问题的定位与修改方向，不替作者写文字。
- 每条刺必须给出定位，即文件与章节或段落；给不出定位的整体感想不予采纳。
- 材料中查不到或看不懂的，直接写明"看不到"，不得猜测，不得编造。
- 挑出最痛的至多 10 条，按严重度从高到低排列，不得凑数。

【回传格式】（严格遵守）
视野名：{视角名}
总评：一句话，写明本视野看这个靶子的整体印象。
刺点：
1. 定位：{文件＋位置}｜类型：{理解障碍/事实矛盾/节奏塌陷/设定违背/吸引力缺失}｜严重度：🔴致命｜问题：{一句话}｜建议：{修改方向一句话}
2. ……
```

### Step 3 派发（隔离纪律）

- 各子 agent 并行派发，互不依赖。通道适配如下：popwave 使用 `paopao_subagent_run`（purpose=critique，只读通道天然合规）；TRAE 使用 Agent 工具（子代理只读类）。
- **盲评铁律**：每份提示词中只有该视角自己的材料，不得携带其它 agent 的任何结论、口径或提示，包括主 agent 自己的预判。主 agent 在回收前不得"预点评"。
- 靶子文本直接附入提示词，或给出路径由子 agent 自行读取，两种方式均可；对照材料给出路径与查阅指引。

### Step 4 回收校验

- 收齐全部回传后先校格式：缺定位的刺直接丢弃；超过 10 条的砍到 10 条，保留高严重度者；总评缺失的补一句"未给出"。
- 格式合规的刺点全部进入裁决，不做内容预筛选。筛选属于 Step 5 的裁决动作，不得提前。

### Step 5 四分裁决与出报告

对全部刺点做合并与分类：

1. **合并去重**：同一定位被多个视野命中时，合并为一条，标注命中视野数。多视野同点命中，大概率是真问题，排在前列。
2. **四分裁决**：
   - **采纳**：具体、可执行、不违背管线既有决策的修改方向。
   - **误报**：视野局限导致的假问题，例如读者代表挑出"背景没交代"，而该背景本就应由后文揭晓。须给出一句误报理由。
   - **冲突**：不同视野意见相反，例如编辑要快、考据要全。原样保留双方，标注"由用户决定"，主 agent 不替用户裁决。
   - **存疑**：信息不足无法判断的，列出需要补哪些材料才能裁定。
3. **写入** `审查/盲评-{靶子名}-{YYYYMMDD}.md`，报告模板：

```markdown
# 盲评报告·{靶子名}·{YYYYMMDD}
> 视角团：{实际参团列表}｜单轮盲评，子 agent 互不可见

## 总裁决
🔴致命 N 条｜🟡警告 N 条｜🔵建议 N 条｜多视野同点命中 N 处｜冲突 N 处

## 采纳（按严重度与命中视野数排列）
（合并后的刺点，每条标注命中视野）

## 冲突（视野冲突，由用户决定）
（A 视角说 X；B 视角说 Y）

## 误报（视野局限导致，弃）
（一句话理由）

## 存疑
（需要补什么材料才能裁）
```

4. **写入后的第二步是去 AI 味**：`python skills/pop-snow-pipeline/scripts/deai_gate.py 审查/盲评-{靶子名}-{YYYYMMDD}.md --profile doc --json`。WARN 项按报告定位自查，评审措辞须贴合事实，装腔之词改为大白话；机械项由 `--fix` 修正；并输出一行确认：`去AI味:盲评报告|PASS` 或 `WARN×N`。
5. 对话呈现总裁决、采纳清单与冲突项，其余细节指向写入的文件。至此结束，不追问用户"要不要改"；修改靶子的指令由用户另行发出。

## 红线

1. **盲评隔离**：子 agent 提示词不得携带其它 agent 的任何结论或主 agent 的预判。单轮盲评，谁都不能被谁带节奏。
2. **子 agent 只读不写入**：结论回传主 agent，写入归主 agent。
3. **每条刺必有定位**：无定位的刺直接丢弃，不进裁决。
4. **冲突由用户决定**：主 agent 不替用户裁决视野冲突，只呈现双方。
5. **查不到须明说**：材料缺失或读不到即声明，不得编造刺点凑数。
6. **产出止于报告**：不改正文、不改章纲；修改靶子是用户决定后另起管线环节的事。

## 执行模式

子 agent 并行派发，互不依赖，可同时执行；主 agent 直接执行组团、组装、回收裁决与写入。
