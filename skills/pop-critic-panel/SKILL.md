# pop-critic-panel

> 多子agent盲评：不同视野隔离评审同一靶子，单轮互不可见，主agent回收裁决。v1.0.0：初始版。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 这个 Skill 做什么

**输入**：靶子（1 个或多个待审文件路径）＋可选视角点名（默认四团，用户可加自定义视角）。

**过程**：主 agent 组团 → 并行派 N 个子 agent（各自独立上下文、各自初始提示词、各自材料清单）→ 单轮盲评 → 主 agent 回收裁决。

**产出**：盲评报告（对话呈现＋落盘 `审查/盲评-{靶子名}-{YYYYMMDD}.md`）——刺点四分：**采纳 / 误报 / 冲突 / 存疑**。

**边界**：
- 只挑刺不改文：产出止于报告，改不改、怎么改，用户拍板。
- 只做单轮，不做多轮互辩：盲评的价值就在隔离——子 agent 一旦互相看到对方结论会立场趋同，多视野就废了。冲突意见原样保留给用户，不安排"对辩和解"。
- 子 agent 只读不落盘：挑刺结论回传主 agent，落盘统一归主 agent。

## 怎么操作（SOP 全内联）

### Step 1 接靶子·组团

1. 确认靶子：用户给的文件路径列表（章纲/幕白描/卷纲/设定档/融合立项稿/正文均可）。靶子含多个文件时视为一个整体评（如"卷1全部幕白描"）。
2. 确认视角团：默认下表四团；用户点名增删或自带视角（一句视野描述即可入团）。无特殊要求不追问，直接开跑。

**内置视角团（默认四团）**：

| 视角 | 身份一句话 | 视野边界（只读） | 评审尺 |
|:--|:--|:--|:--|
| 读者代表 | 12 岁手机滑动读者，每 30 秒要新东西 | 只读靶子本身，禁读一切背景/设定/日志 | 哪里会划走、哪里看不懂、哪里无聊；连续 3 次纯氛围就退出；第一屏没抓手就点走 |
| 逻辑审查 | 连续性校对员 | 靶子＋`全书日志.md`（当前态） | 事实漂移、前后矛盾、人物行为没动机、时间地点对不上、设定和正文打架 |
| 赛道编辑 | 网文编辑部编辑 | 靶子＋大纲卷向（本卷到哪） | 爽点密度够不够、章末钩子断没断、蓄力是否超支、事件密度是否塌陷 |
| 设定考据 | 世界观守门员 | 靶子＋设定库/人物卡（按需点查） | 设定违背、术语不一致、力量越权、名词前后不统一 |

> 视野边界是刻意的信息不对称，不是疏漏：读者代表看不到设定，挑出来的才是真读者反应；考据不看剧情节奏，挑出来的才是纯设定问题。给子 agent 的 prompt 里要写明这一点，防止它"好心"去补读。

### Step 2 组装子 agent 提示词（模板骨架）

每个子 agent 一份 prompt，按下面骨架填充（骨架全内联，直接复制用）：

```markdown
【身份】你是一名{视角名}。{身份一句话}。用你这把专属的尺子评审下面的材料。

【视野边界】只读：{材料清单（靶子＋该视角对照材料）}。禁止读其它任何文件——这是刻意设计的视野边界，不是疏漏；越界评审反而让结论失真。

【评审尺】
{该视角的评审尺，逐条列出}

【纪律】
- 只挑刺不改文：给问题定位和修改方向，不替作者写文字。
- 每条刺必须给定位（文件＋章节/段落），给不出定位的整体感想不要。
- 材料里查不到、看不懂的，直接说"看不到"，不猜不编。
- 挑最痛的 ≤10 条，按严重度从高到低排，不凑数。

【回传格式】（严格遵守）
视野名：{视角名}
总评：一句话——这个视野看这个靶子的整体印象。
刺点：
1. 定位：{文件＋位置}｜类型：{理解障碍/事实矛盾/节奏塌陷/设定违背/吸引力缺失}｜严重度：🔴致命｜问题：{一句话}｜建议：{修改方向一句话}
2. ……
```

### Step 3 派单（隔离纪律）

- 各子 agent 并行派发，互不依赖。通道适配：popwave 走 `paopao_subagent_run`（purpose=critique，只读通道天然合规）；TRAE 走 Agent 工具（子代理只读类）。
- **盲评铁律**：每份 prompt 里只有该视角自己的材料，禁止携带其它 agent 的任何结论、口径或提示——包括主 agent 自己的预判。主 agent 在回收前不许"预点评"。
- 靶子文本直接附进 prompt 或给路径让子 agent 自读均可；对照材料给路径＋点读指引。

### Step 4 回收校验

- 收齐全部回传后先校格式：缺定位的刺丢弃；超 10 条的砍到 10 条（保高严重度）；总评缺失的补一句"未给出"。
- 格式合规的刺点全部进入裁决，不做内容预筛选——筛选是 Step 5 的裁决动作，不能提前。

### Step 5 四分裁决·出报告

对全部刺点做合并与分类：

1. **合并去重**：同一定位被多个视野命中 → 合并为一条，标注命中视野数（多视野同点命中=大概率真问题，排前面）。
2. **四分裁决**：
   - **采纳**：具体、可执行、不违背管线既有决策的修改方向。
   - **误报**：视野局限导致的假问题（如读者代表挑"背景没交代"——本来就该后文揭晓的悬念）。给一句误报理由。
   - **冲突**：不同视野意见相反（如编辑要快、考据要全）→ 原样保留双方，标"留用户拍板"，主 agent 不替用户裁决。
   - **存疑**：信息不足无法判断的，列出需要补什么材料才能裁。
3. **落盘** `审查/盲评-{靶子名}-{YYYYMMDD}.md`，报告模板：

```markdown
# 盲评报告·{靶子名}·{YYYYMMDD}
> 视角团：{实际参团列表}｜单轮盲评·子agent互不可见

## 总裁决
🔴致命 N 条｜🟡警告 N 条｜🔵建议 N 条｜多视野同点命中 N 处｜冲突 N 处

## 采纳（按严重度＋命中视野数排）
（合并后的刺点，每条标注命中视野）

## 冲突（视野打架，留用户拍板）
（A 视角说 X；B 视角说 Y）

## 误报（视野局限导致，弃）
（一句话理由）

## 存疑
（需要补什么材料才能裁）
```

4. **落盘后半步=消毒**：`python skills/pop-snow-pipeline/scripts/deai_gate.py 审查/盲评-{靶子名}-{YYYYMMDD}.md --profile doc --json`——WARN 定位自查（评审措辞贴事实，装腔换大白话）、机械项 `--fix`，回执一行 `消毒:盲评报告|PASS` 或 `WARN×N`。
5. 对话呈现总裁决＋采纳清单＋冲突项，其余细节指向落盘文件。结束——不追着用户问"要不要改"，改靶子的指令由用户另发。

## 红线

1. **盲评隔离**：子 agent prompt 禁止携带其它 agent 的任何结论或主 agent 的预判——单轮盲评，谁都不能被谁带节奏。
2. **子 agent 只读不落盘**：结论回传主 agent，落盘归主 agent。
3. **每条刺必有定位**：无定位的刺直接丢弃，不进裁决。
4. **冲突留用户拍板**：主 agent 不替用户裁决视野冲突，只呈现双方。
5. **查不到明说**：材料缺失或读不到就声明，不编刺点凑数。
6. **产出止于报告**：不改正文、不改章纲，改靶子是用户拍板后另起管线环节的事。

## 执行模式

子 agent 并行派发（互不依赖，可同时跑）；主 agent 直执组团、组装、回收裁决与落盘。
