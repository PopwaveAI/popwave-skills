# pop-decon-dimension · 单书深度wiki引擎

> v3.0.0 推倒重做：旧版（维度证据聚合）产出 `设计/{维度}拆解.md` 证据稿——"像证据聚合、没讲清故事、伏笔断裂"。现升级为对齐《深渊主宰》重建标准的**六模块深度wiki成品**。L1 批次拆解是 L2 的地基，**质量硬门禁不过关禁止进 L2**。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 为什么这样设计（旧 vs 新）

| | 旧（v2.x 证据聚合） | 新（v3.0 深度wiki） |
|:--|:--|:--|
| 产出单元 | 7 张 `{维度}拆解.md` 维度稿 | 六模块深度wiki：剧情库/角色与势力库/力量与战斗/世界观/赛道特色/文风DNA |
| 剧情稿 | 事件证据罗列 | 每卷叙事流回答「讲了什么故事/主线链条/支线串联/伏笔埋回收/卷末钩子」 |
| 力量稿 | 机制条款 | 力量体系 + **动力引擎合一**（长什么样 + 凭什么爬/代价多少） |
| 角色稿 | 字段清单 | 深度卡（性格挂行为/金手指/口头禅/语言指纹/成长对齐质变点） |
| 写作观感 | 素材夹 | **当百科读、当模板抄、当资产取** |

> 一句话：拆书 = **建这本书的单书深度wiki**。L1 证据只做内部依托，不再直接对外交付。

## 做什么

| 输入 | 来源 | 输出 | 下游 |
|:-----|:-----|:-----|:-----|
| 原文 + 范围（全书/卷/N章）+ 书信息 | 原文（必）+ pop-decon 征询 | `{书名}/` 六模块深度wiki成品 | pop-snow* 统一管线创作复用、人工wiki |

**执行模式**：L1 分批精读（只读拆解）可派子 agent 回报笔记、主 agent 汇总落盘批次档案；L2 成品整合（叙事流写作+落盘）主 agent 串行直执，卷级文档可派子起草、主统稿。子 agent 永不落盘。

## 两层结构

| 层 | 载体 | 性质 | 门禁 |
|:--|:--|:--|:--|
| **L1 事实层** | `_temp/batches/` 批次档案（内部依托） | 事件链+七维提取+🔒量化+ch锚点 | **硬门禁：不过关不进 L2** |
| **L2 成品层** | `{书名}/` 六模块深度wiki（对外交付） | 叙事流具名讲透 + ch归表尾 | 成品门禁：不证据聚合 |

|:--|:--|:--|:--|

| **角色与势力库** | `角色与势力库/` | `主角卡.md`/`盟友卡.md`/`敌人卡.md`/`配角卡.md`/`势力卡.md`/`总表与版图.md`/`各卷出场角色对账表.md` | 性格挂行为证据/双核金手指/口头禅语体/语言指纹/成长数据对齐力量质变点；各卷出场角色对账表=按卷点名查漏（以L1参与角色列聚合） |
| **力量与战斗** | `力量与战斗/` | `力量体系.md`+`战斗系统.md`+`金手指.md` | 力量怎么长+通过什么战斗长（三层结构/主养成线/子养成线/交叉规则/刻度） |
| **世界观** | `世界观/` | `总纲.md`/`地理版图.md`/`文明与社会.md`/`危机与敌人.md`/`规则总账.md` | 世界长什么样+大背景/地理/文明/危机/规则分层立清楚 |
| **赛道特色** | `赛道特色/` | `名词表.md`/`命名规则.md`/`类型风味基线.md` | 本书独有名词/命名机制/赛道风味基线（供复刻跨书复用） |
| **文风DNA** | `文风DNA/` | `通用笔触基底.md` | 笔触DNA（句式/叙事距离/对白风格/感官描写）沉淀为可复刻文风 |

收尾：`爽点.md`（名场面+爽感公式+压力机制）+ `立项.md`（逆向破解+商业+连载+风险，消费六模块综合）+ `索引.md`（六模块导航+主线/支线/伏笔检索协议）+ `CHANGELOG.md`。
> **标题命名约定（去行政标签，全模块适用）**：六模块+收尾所有成品文件的 **H1 标题**遵循「只留内容词、力压精简」——只写模块/内容本身，**不得**附加书名前缀、`· 深度拆解wiki`/`库索引`/`立项设计`/`文风DNA（含某种·规范词）`等行政格式后缀，或用括号塞 `（vX/占位/L2模块/L1拆书/wiki内X/索引/档案/整理/入口…）` 之类格式标签。具体到固定文件：`立项.md`→标题 `立项`，`爽点.md`→标题 `爽点`，`{模块}/readme.md`→标题 `{模块}`（如 `世界观`、`角色与势力库`）。**正文零改动**，只缩 H1。跨书共享的文风DNA 文件（`写作技法库/文风DNA/{赛道}/{书名}-{作者}·文风DNA.md`）允许保留 `书名 · 作者` 用于跨库辨识，但同样去掉格式后缀。内容性括号（如角色卡里的 `（解题引擎）`、金手指里的 `（存读档经济学）`）属内容，**保留**。详见 `references/output-quality-standards.md`「标题命名约定」节。

## 怎么操作（SOP）

> 强制流程：**L1 批次拆解（硬门禁）→ 验收 → L2 成品整合**。禁止跳过 L1 直接写成品。

### L1 批次拆解（地基 · 硬门禁）

**Step 1 预扫描（一次，全程共享）**：读 scope 前 3-5 章，提 5 张术语表记为临时笔记——人名表/地名表/等级名表/势力名表/物品名表（作为补充检索词，通用词命中率有限）。

**Step 2 联合 Grep → 锚点池**：读 `references/维度路由清单.md` 取六模块检索词 + 术语表匹配补充词 → **一次 Grep（`|` 连接）**对 scope 全部章节执行 → 命中章去重成锚点池。文风不走 Grep，按场景采样（日常/战斗/情感爆发/环境/严肃/高潮，每种2-3章）。

**Step 3 切批**：scope 切批，默认 **~30章/批**（质量优先每批≤20章，全书骨架每批≤40章）。落在 `_temp/batches/V{n}_B{m}_chXXX-YYY.md`。

**Step 4 分批精读多维提取**：每批 1 个子 agent（或主 agent）读该批连续章节 → 产出维度提取笔记回报 → 主 agent 汇总落盘批次档案。提取 8 维：**剧情/人物/力量/世界观/爽点/情感/文风/功能位（原子候选）**。每条笔记带 `(chXXX)`、量化数值标 🔒、原文未展开标「原文未展开」、「本章无XX」是合法标注。批次档案格式见 `references/batch-format.md`。

> **第 8 维「功能位（原子候选）」默认顺带提**（零额外读原文，随 L1 精读同步识别）：读到「可提炼为跨书剧情节点的功能位」时记一条——功能义名（≤6字，人名地名不出现）+ 干什么活 + 服务爽点 + `(chXXX)`。**不判断、不抽骨架、不定族**，只做事件级候选标注，落 `剧情周期表/_原子候选/`。识别标准与入库 SOP 见 [剧情周期表建设计划](../../../library/写作技法库/剧情周期表/00-建设计划.md)「增长与裂变规则」。

**L1 硬门禁（任一不过 → 退回补拆，禁止进 L2）**：

| # | 检查项 | 标准 |
|:-:|:--|:--|
| 1 | 术语表完整 | 人名/地名/等级/势力/物品 5 表均提取 |
| 2 | 锚点池覆盖 | 命中章 ≥20；覆盖开头/中段/结尾；每模块命中章≥该模块下限的60% |
| 3 | schema 完整 | 每批含 7 维提取子节；每事件带 ch 锚点 |
| 4 | 证据密度 | 每批证据条目 ≥ 章数×2 |
| 5 | 量化无丢失 | 关键数值 🔒 必标，不省略 |
| 6 | 不编造 | 无证据且未标「原文未展开」= 编造，禁止 |
| 7 | 章节号可回溯 | 所有结论可回到原文对应章 |

> **空中楼阁禁令**：L1 任一门禁不过，直接退回补拆该批，绝不携残地基进 L2。这是对 _《深渊主宰》重建时"拆解简略证据不足"报错的根治。

### L2 成品整合（目标 · 先样板验收再铺）

**Step 5 验收节奏征询**：产出前征询「先产 1-2 个模块样板验收，通过后铺全，还是一步到位全线铺」。样板优先选**剧情库第一卷**（最能检验叙事流是否达标）。

**Step 6 依序产出六模块成品**：读对应模板 + L1 批次档案 + 必要精读直读 → 叙事流整合落盘。产出顺序：**剧情库（分卷+动力引擎）→ 角色与势力库 → 力量与战斗 → 世界观 → 赛道特色 → 文风DNA**。

**L2 成品门禁（每模块自检）**：

| # | 检查项 | 标准 |
|:-:|:--|:--|
| 1 | 叙事流具名讲透 | 可当百科读，非证据清单平铺 |
| 2 | 证据归表尾 | ch 锚点归表格列/段落尾证据行，**正文不内联 chXX** |
| 3 | 量化标 🔒 | 关键数值不省略、不发明 |
| 4 | 与 L1 一致 | 成品证据与批次档案对齐，不自行推翻 |
| 5 | 结构符合骨架 | 命中速查表该模块骨架字段 |

**Step 7 收尾**：`索引.md` 导航各卷名与实际功能位对齐；`爽点.md` + `立项.md` 消费六模块综合；`CHANGELOG.md` 落盘。

**Step 8 原子候选归集与自动入库**（默认顺带，不阻断主线六模块交付）：

1. 把 L1 第 8 维「功能位（原子候选）」产生的候选，按**功能义**归集到 `剧情周期表/_原子候选/`（一功能义一份 `{功能义}.md`，每条带源书名 + `(chXXX)` + 干什么活 + 服务爽点）。
2. 归集后逐功能义复查：**同一功能义是否已攒 ≥2 本不同书的异构血肉**——达标则自动走入库 SOP（抽功能位 → 定族打 tag → 入库族目录 + 登记索引与溯源），并遵守「增长与裂变规则」（功能义变没变分流、分支 ≤8 条）。
3. 不达标（仍只 1 本）→ 留在候选池待下本书收敛，不上架。
4. 完成后向老板汇报：**本轮新增入库原子 X 张、候选池还差待收敛 Y 个**。

> 入库 SOP 与增长/裂变/8 条上限规则见 [剧情周期表建设计划](../../../library/写作技法库/剧情周期表/00-建设计划.md)。

## 红线（断裂级）

1. **L1 批次质量不过关进 L2** — 任一硬门禁 fail → 退回补拆，禁止携空中楼阁写成品
2. **成品证据聚合并列** — 成品必须叙事流/具名讲透/可当百科读；证据清单只做内部依托，不直接交付
3. **正文内联 chXX** — ch 锚点归表格列/段尾证据行，正文不内联
4. **凭空发明内容** — 无 chXX 且未标「原文未展开」= 编造；禁止凭记忆/书评补充
5. **量化数值丢失** — 关键数值 🔒 必标
6. **未征询范围/验收节奏就全跑** — 范围（全书/卷/N章）+ 样板验收顺序必须先征询
7. **单批精读超限** — 每批≤40章，超限拆批，避免子 agent 超时+保证批次质量
