# pop-decon-dimension · 单书深度wiki拆解

> 本技能负责单书正本拆解：消费原文与范围，进入 L1 批次拆解（硬性检查），再产出 L2 六模块深度wiki成品，供 pop-snow* 统一管线复用。当前版本 v3.6.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 为什么这样设计（旧与新）

| | 旧（v2.x 证据聚合） | 新（v3.0 深度wiki） |
|:--|:--|:--|
| 产出单元 | 7 张 `{维度}拆解.md` 维度稿 | 六模块深度wiki：剧情库、角色与势力库、力量与战斗、世界观、赛道特色、文风DNA |
| 剧情稿 | 事件证据罗列 | 每卷叙事流回答「讲了什么故事、主线链条、支线串联、伏笔埋回收、卷末钩子」 |
| 力量稿 | 机制条款 | 力量体系与**动力引擎合一**（长什么样，凭什么攀升，代价多少） |
| 角色稿 | 字段清单 | 深度卡（性格挂行为、金手指、口头禅、语言指纹、成长对齐质变点） |
| 写作观感 | 素材夹 | **当百科读、当模板抄、当资产取** |

> 一句话：拆书就是**建这本书的单书深度wiki**。L1 证据只做内部依托，不再直接对外交付。

## 做什么

| 输入 | 来源 | 输出 | 下游 |
|:-----|:-----|:-----|:-----|
| 原文与范围（全书/卷/N章）与书信息 | 原文（必填）与 pop-decon 征询 | `{书名}/` 六模块深度wiki成品 | pop-snow* 统一管线创作复用、人工wiki |

**执行模式**：L1 分批精读（只读拆解）可派子 agent 回报笔记，由主 agent 汇总并写入批次档案；L2 成品整合（叙事流写作与写入）由主 agent 串行直接执行，卷级文档可派子 agent 起草、由主 agent 统稿。子 agent 永不写入文件。

## 两层结构

| 层 | 载体 | 性质 | 检查 |
|:--|:--|:--|:--|
| **L1 事实层** | `_temp/batches/` 批次档案（内部依托） | 事件链、八维提取、🔒量化、ch锚点 | **硬性检查：不过关不得进 L2** |
| **L2 成品层** | `{书名}/` 六模块深度wiki（对外交付） | 叙事流具名讲透、ch归表尾 | 成品检查：不做证据聚合 |

> **标题命名约定（去行政标签，全模块适用）**：六模块与收尾所有成品文件的 **H1 标题**遵循「只留内容词、力压精简」——只写模块或内容本身，**不得**附加书名前缀、`· 深度拆解wiki`/`库索引`/`立项设计`/`文风DNA（含某种·规范词）`等行政格式后缀，或用括号塞 `（vX/占位/L2模块/L1拆书/wiki内X/索引/档案/整理/入口…）` 之类格式标签。具体到固定文件：`立项.md` 的标题为 `立项`，`爽点.md` 的标题为 `爽点`，`{模块}/readme.md` 的标题为 `{模块}`（如 `世界观`、`角色与势力库`）。**正文零改动**，只缩 H1。跨书共享的文风DNA 文件（`写作技法库/文风DNA/{赛道}/{书名}-{作者}·文风DNA.md`）允许保留 `书名 · 作者` 用于跨库辨识，但同样去掉格式后缀。内容性括号（如角色卡里的 `（解题引擎）`、金手指里的 `（存读档经济学）`）属内容，**保留**。详见 `references/output-quality-standards.md`「标题命名约定」节。

## 怎么操作（规程）

> 强制流程：**先做 L1 批次拆解（硬性检查），再做验收，最后做 L2 成品整合**。禁止跳过 L1 直接写成品。

### L1 批次拆解（地基 · 硬性检查）

**Step 1 预扫描（一次，全程共享）**：读取 scope 前 3-5 章，提取 5 张术语表并记为临时笔记——人名表、地名表、等级名表、势力名表、物品名表（作为补充检索词，通用词命中率有限）。

**Step 2 联合 Grep 生成锚点池**：读取 `references/维度路由清单.md`，取六模块检索词与术语表匹配补充词，以**一次 Grep（`|` 连接）**对 scope 全部章节执行，命中章去重成锚点池。文风不走 Grep，按场景采样（日常、战斗、情感爆发、环境、严肃、高潮，每种 2-3 章）。

**Step 3 切批**：对 scope 切批，默认 **~30章/批**（质量优先时每批不超过 20 章，全书骨架时每批不超过 40 章）。批次档案写入 `_temp/batches/V{n}_B{m}_chXXX-YYY.md`。

**Step 4 分批精读多维提取**：每批由 1 个子 agent（或主 agent）读取该批连续章节，产出维度提取笔记并回报，再由主 agent 汇总并写入批次档案。提取 8 维：**剧情、人物、力量、世界观、爽点、情感、文风、功能位（原子候选）**。每条笔记带 `(chXXX)`，量化数值标 🔒，原文未展开标「原文未展开」，「本章无XX」为合法标注。批次档案格式见 `references/batch-format.md`。

> **第 8 维「功能位（原子候选）」默认顺带提取**（不额外读取原文，随 L1 精读同步识别）：读到「可提炼为跨书剧情节点的功能位」时记一条——功能义名（不超过 6 字，人名地名不出现）与它干什么活、服务哪个爽点、`(chXXX)`。**不判断、不抽骨架、不定族**，只做事件级候选标注，写入 `剧情周期表/_原子候选/`。识别标准与入库规程见 `https://wiki.popwave.cn/写作技法库/剧情周期表/00-建设计划`（即 wiki.popwave.cn）「增长与裂变规则」。

**L1 硬性检查（任一项不过即退回补拆，禁止进 L2）**：

| # | 检查项 | 标准 |
|:-:|:--|:--|
| 1 | 术语表完整 | 人名、地名、等级、势力、物品 5 表均提取 |
| 2 | 锚点池覆盖 | 命中章不少于 20 章；覆盖开头、中段、结尾；每模块命中章不少于该模块下限的 60% |
| 3 | schema 完整 | 每批含 8 维提取子节；每事件带 ch 锚点 |
| 4 | 证据密度 | 每批证据条目不少于章数的 2 倍 |
| 5 | 量化无丢失 | 关键数值 🔒 必须标注，不得省略 |
| 6 | 不编造 | 无证据且未标「原文未展开」即为编造，禁止 |
| 7 | 章节号可回溯 | 所有结论可回到原文对应章 |

> **半成品禁令**：L1 任一项检查不通过时，直接退回补拆该批，不得把残缺结果带进 L2。这是对《深渊主宰》重建时"拆解简略、证据不足"报错的根治。

### L2 成品整合（目标 · 先样板验收再铺）

**Step 5 验收节奏征询**：产出前征询「先产 1-2 个模块样板验收，通过后再铺开，还是一步到位全线铺开」。样板优先选择**剧情库第一卷**（最能检验叙事流是否达标）。

**Step 6 依序产出六模块成品**：读取对应模板、L1 批次档案，必要时精读原文，完成叙事流整合并写入。产出顺序：**剧情库（分卷与动力引擎）→ 角色与势力库 → 力量与战斗 → 世界观 → 赛道特色 → 文风DNA**。

**L2 成品检查（每模块自检）**：

| # | 检查项 | 标准 |
|:-:|:--|:--|
| 1 | 叙事流具名讲透 | 可当百科读，非证据清单平铺 |
| 2 | 证据归表尾 | ch 锚点归入表格列或段落尾证据行，**正文不内联 chXX** |
| 3 | 量化标 🔒 | 关键数值不省略、不发明 |
| 4 | 与 L1 一致 | 成品证据与批次档案对齐，不自行推翻 |
| 5 | 结构符合骨架 | 命中速查表中该模块的骨架字段 |

**Step 7 收尾**：`索引.md` 导航各卷名，并与实际功能位对齐；`爽点.md` 消费六模块综合；`立项/` 文件夹（**00-L0核心卖点 → 01-L1命运图 → 02-L2命运图plus → 03-L3全书大纲 → 04-逆向破解**，消费六模块与爽点综合，**拆书必要产出，缺一不可**）；`CHANGELOG.md` 写入。

**Step 7.5 L0 母题卡回填**（默认顺带，产出书级 L0 时一并进行，去专名进卖点方向库）：
> 纪律：**skill 不在文档内固定本地路径、不固定到文件级**——wiki 是唯一读写目标，统一走站点 `https://wiki.popwave.cn/卖点方向库`（目录级），具体卡片与索引由 agent 在库内自行查找；skill 内不出现任何 `D:\` 本地 wiki 路径。
1. **判定母题类型**：从 `立项/00-L0核心卖点.md` 反推本母题落在五类中的哪一轨——①剧情结构模板、②世界观神话体系、③题材机制杂交、④金手指×生态、⑤情绪与市场。
2. **查重（读取走站点，目录级自行查找）**：从 `https://wiki.popwave.cn/卖点方向库` 进入，在库内按母题名或可识别性自主检索是否已有该卡，不预设具体索引或卡片文件。
3. **分流**：
   - 无已有卡 → **产出 L0 母题卡**（一句话母题定义、四判据、不少于 3 种「可改编融合方式」各配真实案例、可杂交方向、反例与边界、案例锚定🔒），作为拆书交付物返回；收录进 wiki 由发布流程处理，**skill 不在文档内固定收录路径**。
   - 已有卡 → 产出**增量**（补交流换方式、案例、章节锚点，写清明确定位与变更点），交由 wiki 侧更新，不覆盖预设本地文件。归一原则：同一母题一张卡，不因本书拆解拆同名分轨。
4. **汇报**：本轮拆书**新增或更新 L0 母题卡 X 张（卖点方向库）**。

> 卡片格式：在 `https://wiki.popwave.cn/卖点方向库` 目录内读取现有卡片并对齐 schema（不钉具体文件）。必含一句话母题定义、四判据（命根子、可识别、可撑全书、源书锚定）、不少于 3 种融合方式与案例、可杂交方向、反例与边界、案例锚定🔒，不堆砌"母题名"。

**Step 8 原子候选归集与自动入库**（默认顺带，不阻断主线六模块交付）：

1. 把 L1 第 8 维「功能位（原子候选）」产生的候选，按**功能义**归集到 `剧情周期表/_原子候选/`（一功能义一份 `{功能义}.md`，每条带源书名、`(chXXX)`、干什么活、服务爽点）。
2. 归集后逐功能义复查：**同一功能义是否已积累不少于 2 本不同书的异构血肉**——达标则自动走入库规程（抽功能位 → 定族打 tag → 入库族目录，并登记索引与溯源），并遵守「增长与裂变规则」（按功能义是否变化分流、分支不超过 8 条）。
3. 不达标（仍只有 1 本）时，留在候选池等待下本书收敛，暂不上架。
4. 完成后向老板汇报：**本轮新增入库原子 X 张、候选池还差待收敛 Y 个**。

> 入库规程与增长、裂变、8 条上限规则见 `https://wiki.popwave.cn/写作技法库/剧情周期表/00-建设计划`（即 wiki.popwave.cn）。

## 红线（断裂级）

1. **L1 批次质量不过关就进 L2** — 任一硬性检查失败即退回补拆，禁止携带半成品写成品
2. **成品证据聚合并列** — 成品必须做到叙事流、具名讲透、可当百科读；证据清单只做内部依托，不直接交付
3. **正文内联 chXX** — ch 锚点归入表格列或段尾证据行，正文不内联
4. **凭空发明内容** — 无 chXX 且未标「原文未展开」即为编造；禁止凭记忆与书评补充
5. **量化数值丢失** — 关键数值 🔒 必须标注
6. **未征询范围或验收节奏就全量执行** — 范围（全书/卷/N章）与样板验收顺序必须先征询
7. **单批精读超限** — 每批不超过 40 章，超限则拆批，避免子 agent 超时，并保证批次质量
8. **拆书缺立项文件夹或 L0 母题卡回填** — 收尾必须产出 `立项/` 文件夹（00-L0核心卖点、01-L1命运图、02-L2命运图plus、03-L3全书大纲、04-逆向破解）并回填 L0 母题卡到卖点方向库（新建或补案例，去专名），缺一件即视为拆书未完成
9. **成品写入后去 AI 味（doc 报告检查）** — 六模块成品与 `立项/` 文件夹写入后，须自行执行 `python skills/pop-snow-pipeline/scripts/deai_gate.py <文件> --profile doc --json`——只报不打回：黑话与套路句式、空腔段按 WARN 定位自查（拆书措辞贴原文事实，装腔换大白话，行话正常用可放行）；工程标签（chXX 锚点、🔒量化值、表格列名）不在去 AI 味范围。零风险机械项可加 `--fix` 原地修。wiki 资料包的源头干净，下游管线才不被污染。
