# PRD · pop-decon-dimension（单书深度wiki拆解）

## 解决什么问题（带凭据）

旧拆书产出「按维度证据聚合稿」，被判定「像证据聚合、没讲清故事、支线伏笔断裂」（CHANGELOG v3.0.0 根因记录），以《深渊主宰》重建成功的「六模块深度wiki」为新标准推翻重做。核心问题：证据稿能当素材夹，不能当百科读、不能当模板抄、不能当资产取。

## 解决思路（每步为什么必须这样）

1. **两层结构：L1 事实层 + L2 成品层**。L1 批次档案（`_temp/batches/`）只做内部依托，保真不保读；L2 六模块成品对外交付，保读不保证。中间用 7 项硬性门禁隔开——任一不过退回补拆，禁止带半成品进 L2（根治「拆解简略、证据不足」）。
2. **L1 八维提取 + 联合 Grep 锚点池**。一次 Grep 生成命中章池，分批精读同时提取八维，每章只读一次，控制 token 与超时。八维是门禁第 3 项（schema）的前提，一条不减。
3. **L2 六模块依序产出**。剧情库→角色与势力库→力量与战斗→世界观→赛道特色→文风DNA，叙事流具名讲透、ch 归表尾、量化标 🔒。支持「先样板验收再铺」。
4. **收尾必产立项与 L0 母题卡**。立项文件夹（00-L0→04-逆向破解）消费六模块综合，是拆书的必要产出；L0 母题卡回填卖点方向库（去专名），让拆书沉淀为跨书资产。

## 关键取舍

| 选了什么 | 放弃了什么 | 为什么 |
|:--|:--|:--|
| L1 八维全提 | 不让用户裁剪维度 | 八维是门禁前提，裁剪会连带拖垮锚点池（第2项）与证据密度（第4项）；重点方向只作用 L2 |
| 批次档案为内部依托 | 不把证据稿当交付物 | 证据聚合稿正是被否掉的旧形态 |
| ~30章/批 | 不逐章人工整理 | 逐章白描卡冗余（CHANGELOG 记录），30章/批在保真与效率间平衡 |
| 拆书即建单书wiki | 不做独立立项/设计包 skill | 旧 pop-decon-prd / design-pack 方法论已内吸，少两个 skill 少两份维护 |

## 不做什么

- 不下载、不分章（`tool-download-webnovel` / `tool-split-chapters` 的活）。
- 不做范围征询与路由编排（`pop-decon` 的活）。
- 不写正文（`pop-write` 的活），只产出供创作复用的 wiki 与立项。
