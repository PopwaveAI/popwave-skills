# Step 2：精读联合锚点池 + 多维提取 + 分维度产出

> pop-decon-dimension 执行流程的 Step 2-4。
> 核心改变：每章只读一次，同时提取所有选中维度的设定，不再逐维度重复读。
> 前置：Step 1 已完成，联合锚点池已确认。

---

## 2a：分批策略

> ⛔ **硬限制**：每批精读≤8章。超8章强制拆批。

### 分批规则

| 联合锚点池大小 | 分批数 | 每批 | 执行方式 |
|:-------------|:------:|:----:|:---------|
| ≤8 章 | 1 | 全量 | 主 agent 直接精读 |
| 9-16 章 | 2 | ~5-8 | 主 agent 分批精读 或 委派 2 个子 agent |
| 17-32 章 | 3-4 | ~6-8 | 委派子 agent（参考 `pop-decon/references/delegation-orchestration.md`） |
| 33+ 章 | 5-7 | ~6-8 | 委派子 agent，上限 7 批 |

### 分批方法

1. 将联合锚点池按章节序号排序
2. 按≤8章/批切分
3. 每批记录章节范围

---

## 2b：精读 + 多维提取

> 核心步骤：每章读一次，按多维提取清单同时提取所有选中维度的设定。

### 多维提取清单

对每章精读时，按以下清单逐维度提取（选中哪些维度就提取哪些，未选的跳过）：

| 维度 | 提取什么 | 无相关内容时 |
|:-----|:---------|:-----------|
| plot | 事件推进/转折点/伏笔/时间跳跃/主线进展 | 标注「本章无剧情线相关内容」 |
| romance | CP 互动/情感变化/信任/背叛/关系进展 | 标注「本章无情感线相关内容」 |
| character | 人物出场/性格表现/能力展示/关系建立/成长变化 | 标注「本章无人物相关内容」 |
| power | 等级变化/新能力/战斗过程/修炼突破/力量规则 | 标注「本章无力量相关内容」 |
| world | 地理信息/势力信息/物品信息/历史背景/社会规则 | 标注「本章无世界观相关内容」 |
| beat | 名场面/爽点触发/情绪高潮/反转/打脸/追读钩子 | 标注「本章无爽点相关内容」 |
| style | 笔触特征/句式/对白风格/叙事距离/感官描写方式 | 标注「本章无文风相关内容」 |

### 提取笔记格式

```
[ch003]
- plot: 萧炎测试斗气结果为斗之气三段，被族人嘲笑 (ch003)
- character: 萧战（父亲）对萧炎态度从骄傲到失望；萧炎性格倔强不服输 (ch003)
- power: 斗之气三段 🔒，处于最低等级 (ch003)
- beat: 被嘲笑→隐忍→暗自决心变强，爽点铺垫 (ch003)
- world: 乌坦城，萧家宅院 (ch003)
- romance: 本章无情感线相关内容
- style: 第三人称限知视角，短句为主，对话简洁有力 (ch003)

[ch005]
- plot: 药老在戒指中苏醒，要求萧炎拜师 (ch005)
- character: 药老性格狡猾但护短；萧炎从警惕到接受 (ch005)
- power: 药老自称曾为斗尊 🔒，提出可以帮萧炎恢复天赋 (ch005)
...
```

### 提取红线

- 每条必须带 `(chXXX)` 章节号
- 量化数值（等级/数量/距离/时间）原文有的必须摘录并标 🔒
- 原文未展开的设定标注「原文未展开」
- 只提取选中维度的内容，未选维度不提取
- 禁止凭记忆/书评补充原文没有的内容
- "本章无XX相关内容"是合法标注，不强制每章每个维度都有内容

## 2c：分维度笔记汇总

> 多批精读时，每批完成后将笔记按维度拆分汇总。

### 操作

1. 收集所有批次的多维提取笔记
2. 按维度拆分：将每条笔记归入对应维度
3. 每个维度内按章节序号排序
4. 设定演变的保留时间线：`ch003: 前期状态 → ch045: 中期变化 → ch120: 后期定型`

### 委派模式下的汇总

如果使用了子 agent 委派：
1. 每个子 agent 返回多维提取笔记（含所有选中维度）
2. 主 agent 按维度拆分合并
3. 检查批次间设定冲突（同一设定不同章节的演变保留时间线）
4. 主 agent 负责产出文档（子 agent 不产出）

---

## 2d：按维度分别产出

> 每个选中维度各自按模板产出一份文档。

### 操作

1. 对每个选中维度：
   a. 读取该维度的产出模板（`templates/{维度}.tpl.md`）
   b. 将 2c 中该维度的汇总笔记按模板结构填充
   c. 每条设定标注 chXX 证据
   d. 量化数值标 🔒
2. 产出文件路径：`项目本地/设计/{维度}拆解-{范围}.md`

### 文件命名

| 场景 | 文件名 |
|:-----|:-------|
| 全书拆解 | `{维度}拆解-ch001-ch{末章}.md` |
| 前N章拆解 | `{维度}拆解-ch001-ch{N}.md` |
| 指定卷拆解 | `{维度}拆解-卷N.md` |

> ⛔ 文件名不得含"全书"。必须有 scope 声明。

### SCOPE 声明模板

```markdown
> 维度：{维度}（方案B · 共享锚点池）| 范围：ch001-ch{N}（共{N}章）| 依据：原文 `_temp/chapters/`
> 方法：联合 Grep 共享锚点池，单次精读多维提取
```

## 2e：自检（各维度分别）

> 读取 `references/output-quality-standards.md` 执行自检。每个维度独立自检。

### 自检清单（每个维度）

| 检查项 | 标准 |
|:------|:-----|
| 锚点章覆盖 | 该维度在联合锚点池中的命中章数≥该维度下限 |
| 证据条目数 | 每条设定带 chXX 证据，证据条目数≥锚点章数×2 |
| 量化数值 | 关键数值标 🔒，不省略 |
| 可回溯性 | 所有结论可回到原文对应章节 |
| 不编造 | 原文未明确处标注「原文未展开」 |
| scope 声明 | 文件名不含"全书"，有范围声明 |

### 不通过时的处理

- 某维度锚点不足 → 补充该维度的专属 Grep 检索，追加精读
- 证据条目不足 → 补充精读遗漏章节
- 编造内容 → 删除无 chXX 证据的条目
