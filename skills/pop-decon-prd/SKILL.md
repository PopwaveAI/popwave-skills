# pop-decon-prd
> 全书立项设计 v3.0.0。拆书管线最后环节，消费 pop-decon-dimension 各维度产出。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 做什么
| 输入 | 来源 | 输出 | 下游 |
|------|------|------|------|
| 各维度拆解产出（剧情/情感/人物/力量/世界观/爽点/文风） | pop-decon-dimension | 全书立项设计.md | 无（拆书终点） |

核心哲学：拆书=逆向破解——PRD 只综合已有数据不产生新数据。

**执行模式**：Step 1 数据收集（只读扫描）可并行派 2-3 个子 agent 回报数据摘要、主 agent 落盘；Step 2 综合必须主 agent 串行直执。

## 怎么操作（SOP全内联）

### Step 1：收集各维度产出 → `_temp/prd-collected-data.md`

扫描各维度产出（`设计/{维度}拆解-{范围}.md`），**只收集不分析**，数据原样记录（分析判断留给 Step 2）：

| 收集项 | 收集/统计什么 |
|:-----|:-----|
| 拆解窗口 | scope 范围（前N章/全书M章/百分比）、章节数、总字数 |
| 剧情线拆解 | 主线/支线、核心矛盾链、主角成长曲线、卷纲/分幕结构、伏笔 |
| 情感线拆解 | CP 互动、信任/背叛、关系演变 |
| 人物拆解 | 角色卡、角色弧线、对白风格 |
| 力量拆解 | 力量体系结构、金手指 |
| 世界观拆解 | 地理/势力/物种/物品设定、世界基调 |
| 爽点拆解 | 名场面总数、可复刻/变奏方向、爽点分布与密度规律、悬念链、压力机制 |
| 文风拆解 | 核心文风特征、笔触层维度 |

产出 `_temp/prd-collected-data.md`：以上各项统计的结构化摘要。

### Step 2：综合产出立项设计 → `全书立项设计.md`

按 `templates/book-prd.tpl.md` 填写，8 个综合项（数据来源/提炼方法/门禁）：

| 综合项 | 数据来源 | 提炼方法 | 门禁 |
|:-----|:-----|:-----|:-----|
| 核心假说 | 剧情线拆解（主线梗概+核心矛盾链）+力量拆解 | 从核心矛盾链提炼「这本书为什么成立」的一句话假说 | 必须有 chXX 证据（来自剧情线有效事件），不得凭书名/直觉编造 |
| 赛道判定 | 力量+世界观拆解（力量体系类型/世界基调）+爽点拆解的爽感公式 | 交叉判定赛道、子类型 | 基于实际拆解数据，不凭书名猜测 |
| 卖点与读者承诺 | 爽点拆解的爽点分布+名场面可复刻方向 | 从高频爽点公式提炼核心卖点，从名场面清单提炼读者承诺 | 卖点必须有爽点数据支撑 |
| 目标读者 | 文风拆解+爽点拆解 | 从文风难度/爽点类型/压力机制推断读者画像和阅读场景 | 文风拆解缺失时标注「基于设定推断」 |
| 全书结构 | 剧情线拆解的卷纲/分幕 | 从幕数和篇幅预算推断卷数和章数 | 前N章拆解时标注「基于前N章推断」 |
| 主角驱动 | 人物拆解的角色弧线+剧情线的成长曲线 | 从成长曲线关键跃迁节点提炼核心驱动事件和成长弧线 | 成长曲线缺失时标注「数据不足」 |
| 读者体验分析 | 爽点拆解（爽点密度+情绪曲线+压力机制） | 分析读者追读驱动力 | 爽点拆解缺失时标注「数据不足」 |
| 可复用资产清单 | 各维度产出 | 统计可复刻名场面数、可迁移结构模式数、设定设计模式数、文风特征数 | 必须引用已产出的具体文件，不得列出虚拟条目 |

> PRD 不产生新数据，只综合已有数据。每个结论必须可追溯到各维度拆解的具体产出文件。

## 红线
1. **读取协议**：强加载=红线+速查表（每轮必读）；弱加载=templates/references按步骤按需加载
2. **维度产出缺失就执行** — 剧情/力量/世界观等维度产出缺失 → 退回 pop-decon-dimension
3. **核心假说无证据支撑** — 核心假说必须有维度产出的 chXX 证据，不得凭书名/直觉编造
4. **赛道判定凭书名猜测** — 赛道必须基于实际拆解数据（设定+名场面爽感公式）
5. **PRD与各维度数据矛盾** — 结论必须与各维度产出一致，不得自行推翻已有结论
