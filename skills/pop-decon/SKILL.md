# pop-decon · 拆书专家入口

> 拆书专家入口：下载 txt → 征询范围+维度 → 路由（方案B 联合Grep共享锚点池）。不常驻调度。v25.0.0：step 内容全合入单文件精炼。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 做什么

| 输入 | 输出 | 下游 |
|:-----|:-----|:-----|
| 用户拆书需求 + 源文件 | 征询拆解范围+维度 + 路由到 dimension（传 dims+scope） | pop-decon-dimension / pop-decon-prd |

**执行模式**：主 agent 直执——下载/征询/路由/沉淀均为交互编排环节，无自然子 agent 适配点；拆解整体路由给 pop-decon-dimension skill。

**路由地图**：下载txt → ★征询范围+维度★ → 路由 dimension（dims+scope）→ 联合Grep→多维提取→分维度产出 → 沉淀+提醒少测

## 怎么操作（SOP全内联）

> execution.mode: 按需路由 | 强保障：本 SKILL.md 每次 run 强制注入 | 弱保障：references/ 需主动 readFile

### Step 0：源文件检查 + 下载

| 情况 | 动作 |
|:-----|:-----|
| 用户已提供路径（TXT/EPUB/PDF） | 确认文件存在 → 进 Step 1 |
| 未提供文件 | 路由 `tool-download-webnovel` 下载 → 完成后进 Step 1 |
| 说"网上有"但无 URL | 搜索 `{书名} txt 下载` 找到 URL 后交 tool-download-webnovel |

**门禁**：无源文件且未完成下载不得进 Step 1（换源失败处理同红线5）。

### Step 1：征询范围 + 维度（强制，禁止默认全量跑）

**1a 拆什么范围？**

| 范围选项 | 说明 | Grep 搜索范围 | 精读数量下限调整 |
|:--------|:-----|:-------------|:---------------|
| 全书 | 全量拆解 | `_temp/chapters/` 全部 | 标准下限 |
| 某一卷 | 指定卷范围（如 ch001-ch080） | 该卷章节 | 按章数比例缩小 |
| 前N章 | 指定章数（如前100章） | ch001-ch{N} | 按章数比例缩小 |

> 精读数量按范围比例缩小：如全书500章标准精读35章（7%），则100章范围精读约15-20章。

**1b 拆哪些维度？**（多选；由 pop-decon-dimension 统一承载——联合 Grep 共享锚点池，每章只读一次多维提取）

| # | 维度 | 拆什么 | 触发词 |
|:-:|:-----|:-----|:-----|
| 1 | 剧情线 | 主线/支线/暗线/卷纲/转折 | 剧情/主线/支线/卷纲/转折 |
| 2 | 情感线 | CP/暧昧/信任/背叛/羁绊演变 | 感情/情感/CP/恋爱/羁绊 |
| 3 | 人物角色 | 角色卡+弧线+动机+成长 | 人物/角色/人设/弧线 |
| 4 | 力量体系 | 力量/升级/战斗 | 力量/境界/战斗/升级/体系 |
| 5 | 世界观 | 地理/历史/物种/势力/物品 | 世界观/设定/地理/势力 |
| 6 | 爽点体验 | 名场面/读者体验/爽点分布 | 爽点/名场面/读者/节奏 |
| 7 | 文风 | 对白/笔触/文风 | 文风/对白/笔触/风格 |
| 8 | 立项设计 | 全书立项设计 | 立项/PRD/商业 |

征询话术：「老板，这本《{书名}》要拆多大范围？（全书 / 某一卷给章节范围 / 前N章给N）要拆哪些维度？可多选 1-8（也可说"全部"）——多维度共享精读，不重复读取。」

**门禁**：用户未明确选择范围+维度 → 退回征询，不得擅自开始拆解。

### Step 2：路由到下游（方案B）

范围+所有维度**一次性**传入：

| 用户选择 | 路由到 | 传入参数 | 说明 |
|:-----|:-----|:-----|:-----|
| 1-7 个维度 | pop-decon-dimension | `dims=[选中维度]` + `scope=[章节范围]` | 联合Grep→多维提取→分维度产出 |
| 立项设计 | pop-decon-prd | — | 各维度产出完成后路由（可独立于上述维度） |

- **文风维度特殊处理**：style 不参与联合 Grep（走场景定向采样），但可与其它维度共享精读章——被锚点池命中的章节同时提取 style 笔触特征。
- **可选加速器**：用户明确要逐章白描卡/设计包时，可先调 `pop-decon-design-pack`（非必选）。

### Step 3：沉淀 + 提醒少测

全部分解完成后，逐模块确认产出已沉淀到项目本地并更新索引，**不入库 pop-trope-library**：各维度 → `项目本地/设计/{维度}拆解-{范围}.md`；立项 → `项目本地/`。未指定项目时询问沉淀到哪个项目；完成后告知用户产出已沉淀。

### 边界条件

| 场景 | 处理 |
|:-----|:-----|
| 前N章跑完要求升级全书 | 重新联合 Grep（扩到全书）→ 重新精读 |
| 只选了1个维度 | 退化为单维度模式（联合锚点池=该维度锚点章） |
| 选了文风+其它维度 | 其它维度走联合 Grep，文风走场景采样，共享精读章 |
| 子 skill SKILL.md 不可读 | 终止，输出具体哪个子 skill 缺失 |
| 用户中途改变维度 | 保存当前阶段产出，用户确认后再切 |
| 源文件编码不确定 | 中文 TXT 优先 GBK → GB18030 → UTF-8 |
| 多卷同目录拆解 | 每卷置于独立子目录 `vol1/` `vol2/` |

## 🚪 首次对话引导（onboarding）

首次触发（无拆书项目、非续写）时，先直接粘贴 `references/onboarding-guide.md` 全文（声明为功能介绍+引导、未执行任务），补一句"报书名+想学那块就开始"；用户已明确要拆则跳过。

## 红线

1. **读取协议**：读取 skill 文件用 `Get-Content -Encoding UTF8 -Raw`，禁用 Read 工具
2. **未征询就全量跑** — 必须先征询用户要拆哪些维度，只跑被选中的，禁止默认全量跑
3. **跳过原文直读** — 方案B 默认直读原文，不得要求先产白描卡（白描卡仅可选加速器）
4. 产出物不经质量门禁直接进下一级
5. 无源文件先路由 tool-download-webnovel 下载，不得跳过；换源全失败 → 终止告知，不得空文件硬跑
6. 产出沉淀到项目本地文件夹，不入库 pop-trope-library
7. **未提醒少测即切入全书** — 拆书启动或完成时必须提醒用户"本拆解服务较耗算力，建议先用第一卷少量测试，确认效果后再拓展到全书"
