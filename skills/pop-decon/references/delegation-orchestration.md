# 大规模拆书 · 联合锚点池并行精读编排（方案B · 共享锚点池）

> **用途**：当联合锚点池 > 8 章时，使用并行委派模式分批精读。
> **设计原则**：联合 Grep 定位 → 分批精读（每批≤8章，每章多维提取）→ 分维度笔记汇总 → 分维度产出。
> v3.0.0：方案B 重构，从单维度并行精读改为多维提取并行精读。

---

## 一、分批策略

| 锚点池命中量 | 分批数 | 每批大小 | 推荐方式 |
|:------------|:------:|:---------|:---------|
| ≤8 章 | 1 | 全量 | 主 agent 直接精读，无需委派 |
| 9-16 章 | 2 | ~5-8 | 按章节序等分 |
| 17-32 章 | 3-4 | ~6-8 | 按章节序等分 |
| 33+ 章 | 5-7 | ~6-8 | 按章节序等分，上限7批 |

> ⛔ **硬限制**：每批≤8章。超8章强制拆批，避免子 agent 超时导致主 agent 兜底手动读取。

## 二、编排流程

### 2.1 Grep 检索结果分批（主 agent 执行）

主 agent 拿到 Grep 命中的锚点章列表后：
1. 按章节序号排序
2. 按≤8章/批切分
3. 为每批准备子 agent 上下文

### 2.2 并行精读（子 agent 执行）

每个子 agent 的任务：
1. 读取本批锚点章原文（`_temp/chapters/chXXX.txt`）
2. 按多维提取清单同时提取所有选中维度的设定（每章读一次，不重复读）
3. 每条抽取记录格式：`- {维度}: {设定内容} (chXXX)` —— 必须带维度标签和章节号
4. 某维度本章无相关内容时标注「本章无{维度}相关内容」
5. 输出多维提取笔记（纯文本，不落盘，返回给主 agent）

> ⚠️ 子 agent 只负责"读+多维提取+返回笔记"，不负责产出文档。产出文档由主 agent 统一按维度模板填充。
> 多维提取清单详见 `pop-decon-dimension/steps/step-2-precision-read.md` 的「多维提取清单」表格。

### 2.3 笔记汇总 + 产出（主 agent 执行）

主 agent 收到所有批次的多维提取笔记后：
1. 按维度拆分合并（去重/归并/排序）
2. 每个维度按对应模板（`templates/{维度}.tpl.md`）填充产出文档
3. 各维度独立自检（锚点覆盖/量化数值/可回溯性）

### 2.4 产出验证

```bash
# 验证产出文件存在
设计/{维度}拆解-{范围}.md → 存在
# 验证锚点覆盖（grep chXX 标记数量）
```

## 三、子 agent 上下文模板

每个子 agent 接收以下信息：

```
任务：精读原文锚点章，按多维提取清单同时提取所有选中维度设定
项目路径：{项目根目录}
章节范围：chXXX-chYYY（N章）
选中维度：{dims列表，如 plot/character/power}
原文路径（绝对路径）：
  {项目根目录}/_temp/chapters/chXXX.txt
  ...
多维提取要求：
  - 每条记录格式：- {维度}: {设定内容} (chXXX)
  - 按维度逐条提取，每章每个选中维度都要检查
  - 量化数值（等级/数量/距离等）原文有的必须摘录并标 🔒
  - 原文未展开的标注「原文未展开」
  - 某维度本章无内容标注「本章无{维度}相关内容」
  - 返回纯文本笔记，不产出文件
```

## 四、常见陷阱

### ❌ 子 agent 读取了非锚点章
**现象**：子 agent 读取了未被 Grep 命中的章节，浪费时间。
**原因**：上下文中章节路径不明确。
**解决方案**：在上下文中给出精确的章节文件列表（绝对路径），不给出整个 `_temp/chapters/` 目录。

### ❌ 子 agent 返回全文而非笔记
**现象**：子 agent 把原文内容复制返回，导致主 agent 上下文爆炸。
**原因**：子 agent 未理解"抽取笔记"的要求。
**解决方案**：在上下文中明确写"返回抽取笔记（每条1-3句话+chXXX），禁止返回原文全文"。

### ❌ 产出被写入错误路径
**现象**：产出文件不在项目目录下。
**原因**：子 agent 使用相对路径。但在方案B中，子 agent 不负责产出文件，此问题应不存在。
**解决方案**：确认产出由主 agent 执行，子 agent 只返回笔记。

### ❌ 批次间设定冲突
**现象**：不同批次的笔记对同一设定有矛盾描述。
**原因**：原文设定在不同章节有演变（如角色前期和后期性格变化）。
**解决方案**：主 agent 汇总时按章节序排列，设定演变保留时间线（标注"chXXX: 前期→chYYY: 后期"）。

### ❌ scope 声明缺失
**现象**：只读到全书一部分时，产出使用"全书"等绝对化表述。
**解决方案**：主 agent 产出时在文件头部添加 scope 声明（覆盖范围+总章数）。
