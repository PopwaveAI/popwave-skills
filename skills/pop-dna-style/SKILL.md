# pop-dna-style

> 本技能只规定流程、文件契约与检查项，不规定题材、结构、风格或审美偏好。
> 本技能从用户提供的参考文本提取可复用特征，写成文风锚定文件，供 pop-write 使用。不指定参考书目，不预设风格方向。
> 当前版本 3.0.0，版本历史见 CHANGELOG.md。

## 职责范围

| 阶段 | 输入 | 输出 | 下游 |
|:--|:--|:--|:--|
| **Stage 1** | 用户提供的参考书 txt | `素材/文风锚定.md` v1（特征条目＋来源标注） | write、Stage 2 |
| **Stage 2** | v1、本书设定文件、用户意图 | `素材/文风锚定.md` v2（特征层＋本书约束层＋用户要求层） | write |

**与 decon 的边界**：decon 重拆全书八维度并产出 Beat Sheet；本技能只提取可复用的文本特征，粒度更轻，两者互不冲突。

**执行方式**：Stage 1 的读章与提取属只读分析，可派子 agent 执行并回报，主 agent 负责检查与写入。Stage 2 由主 agent 直接执行。

## Stage 1：特征提取

### Step 1：原文验证

1. 检查 `素材/downloads/{书名}.txt` 是否存在；不存在时再查用户指定路径。
2. 两处都不存在，报错中止：`参考书txt未找到，无法执行文风DNA提取。请先通过tool-download-webnovel下载，或手动提供txt文件路径。`
3. 验证 txt 非空且为正文：读前一百行，确认是小说内容而非错误页面。
4. 验证通过后，在 `素材/文风锚定.md` 的元数据中记录 `采样源文件: {txt路径}`、文件大小、验证时间。

不得基于记忆、书评、评论或公开数据替代原文；不得跳过验证直接采样。

### Step 2：采样

**采样范围由用户指定。** 用户未指定时，按下述默认执行，并在产出中标明实际采样范围：

- 覆盖前、中、后期，每段取若干章，避免只看开书阶段。
- 覆盖多种场景（对话、动作、环境、情绪、过渡等），按参考书实际分布选取，不预设场景清单，不设固定章数。
- 参考书不足三十章时全书采样；超过五百章时只采前三百章；章名无关键词时隔章采样，并读前五十行判断场景。
- 采样章清单写成 `章号｜章名｜选取理由`，随产出留档。

### Step 3：提取可复用特征

每个特征写成一条，含五项：

| 字段 | 内容 |
|:--|:--|
| **特征名** | 一句话命名，如「对话引导用动作带出」 |
| **观察** | 可执行描述：作者在什么位置用哪种写法，出现频率或条件 |
| **原文例证** | 从源文本逐字复制的完整段落，可回源 txt 逐字搜到 |
| **来源** | 文件名与章号 |
| **适用条件** | 该写法在什么场景成立，什么场景不适用 |

**观察维度按需选取，不强制齐备**：叙事距离、情绪外化方式、对话引导、外貌描写、数值或面板呈现、环境展开、段落长度与分段、物品描写、时间推进方式。用户指定维度优先。

**硬性要求：**

- 原文例证必须逐字真实原文，不得二创、不得美化、不得把操作特征或剧情概述伪装成原文。
- 每条特征必须能回源，来源字段不可空。
- 只提取文本怎么写，不提取剧情内容、人物设定或世界观。

### Step 4：部署

| 产出 | 部署路径 | 消费方 |
|:--|:--|:--|
| 特征文件 v1 | `{项目空间}/素材/文风锚定.md` | write（第一优先级加载）、Stage 2 |

1. **确认项目空间**：用户在创作项目中调用时，当前工作目录即项目空间；未指定时询问「部署到哪个项目？」。`素材/` 不存在时创建。
2. **写入文风锚定.md（v1）**：文件头含参考书名、`提取: pop-dna-style · {timestamp}`、参考书路径、采样范围（章数与场景类型）、消费方声明、`v1-Stage1产出，待Stage2重构` 标注。正文按特征逐条排列，格式见 `references/style-dna-profile.md`。
3. **更新索引**：在 `素材/索引.md` 追加条目（文件不存在时创建）：产出、来源（pop-dna-style 与参考书名）、时间。
4. **向用户确认消费协议**：write 从文风锚定.md 取特征与原文例证；可学节奏、组合与结构，不照抄内容与情节。

**部署检查**：文件已创建｜文件头完整（参考书名、采样范围、时间戳、源文件路径）｜索引已更新｜消费协议已告知用户。

## Stage 2：综合重构

> 定位：本书设定与用户要求确定后，用它们校验 Stage 1 的特征：成立则保留，部分不成立则修改，完全不成立则删除；再补本书约束与用户要求，产出 v2。Stage 2 对 Stage 1 的特征层有写权限。

**前置输入（有则读，无则跳过并标注）：**

| 输入 | 来源 | 用途 |
|:--|:--|:--|
| `素材/文风锚定.md`（v1） | Stage 1 | 重构对象 |
| 全书设定文件（战斗系统、物理规则、民风民俗、世界设计原则等） | world Phase 3 | 本书对文风的约束 |
| `素材/用户意图.md` | pipeline Phase 0 | 用户显性要求 |
| `设计/世界决策表.md` | world Phase 0 | 用户对世界的选择 |
| `立项/01-立项PRD.md` | seed Phase 1 | 故事调性 |

### 5.1 提取本书约束

从设定文件提取与文风相关的约束：战斗呈现方式、环境气质、日常调性、力量呈现方式。每条约束回溯到具体设定文件与段落；设定文件缺失时写「未提供」，不编造。

### 5.2 校验 v1 特征

对每条特征问三句：

1. 这条特征放到本书设定下是否成立？
2. 部分不成立，还是完全不成立？
3. 若修改，改成什么？写明修改前后。

成立则保留；部分不成立则修改；完全不成立则删除。每次修改或删除必须写明依据（对应哪条设定），不得以「我觉得不好」为由删除。结果汇总为重构决策表：`特征名｜校验结果｜处理方式｜依据`。

### 5.3 用户要求

从用户意图与决策表提取用户对文风的显性要求，逐条引用原话。用户未提出的维度写「用户未指定」。

**优先级**：用户要求高于本书设定约束，本书设定约束高于参考书特征。三者冲突时按此顺序取舍。

### 5.4 产出 v2

覆盖 `素材/文风锚定.md`，仍是单一文件，三层用 H2 分隔：

- **文件头**：Stage 2 声明与时间戳、参考书与源文件路径、采样范围、设定文件来源、用户要求来源、消费方、产出格式声明。
- **第一层 特征层**：v1 全部特征保留原文，每条标注校验结果（保留／修改／删除）与依据；被修改的显示修改前后对比；被删除的保留原文并注删除原因。
- **第二层 本书约束层**：战斗、环境、日常、力量呈现四类约束，各附设定出处。
- **第三层 用户要求层**：逐条列用户原话；未指定的维度写「用户未指定」。
- **末尾 重构决策表**：供 write 查哪些特征被改过、为什么。

**无参考书模式**：用户在 Phase 0 跳过拆书时，v1 不存在，跳过 5.2，只做 5.1、5.3、5.4 的后两层，文件头标注「Stage 1: 跳过（用户选择无参考书）」。

**Stage 2 检查**：每条 v1 特征都有校验结果｜每次修改或删除都有设定依据｜用户要求逐条引用或标「用户未指定」｜单一文件｜引用原文可回源。

产出后向 pipeline 报告：保留 N 条、修改 N 条、删除 N 条；本书约束条数；用户要求覆盖情况。

## 红线

1. **原文来源必须逐字可回源**：每个原文例证都是源书 txt 里原样存在的完整段落，不得二创、不得美化、不得以剧情概述冒充原文。
2. **不得以记忆、书评或公开数据替代原文**：Step 1 验证不通过即中止。
3. **来源字段必填**：每条特征标明文件名与章号；文件头标明 `采样源文件: {txt路径}`。
4. **单一文件**：`素材/文风锚定.md` 是唯一产出。Stage 1 写 v1，Stage 2 覆盖为 v2。
5. **用户要求优先**：用户明确提出的文风要求覆盖本书约束与参考书特征。
6. **不预设偏好**：不指定参考书目、不规定题材、不规定结构与风格方向；用户未指定的项标「待定」，不阻塞产出。
