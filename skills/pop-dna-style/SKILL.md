# pop-dna-style
> 文风DNA提取与综合重构 v2.0.0。write skill笔触DNA标准插槽的供给方。双阶段：Stage 1笔触提取（Phase 0）+ Stage 2综合重构（Phase 3完成后）。完整版本历史见 CHANGELOG.md。

> ⚠️ 产出格式为「**操作特征+完整段落+反面教材**」三段式（v1.7.0 起，淘汰旧"操作特征+精选原文金句碎片"）。AB测试实证：完整段落（不切碎）让模型学到段落内技法组合，反面教材（AI味护栏）压住默认AI写作先验，二者缺一不可——碎片化是被证明垫底的旧设计。本格式与文风库、write消费协议同构。

## 做什么
| 输入 | 来源 | 输出 | 下游 |
|------|------|------|------|
| **Stage 1**: 参考书txt | 用户提供 | 素材/文风锚定.md v1（笔触层） | seed ch001 + Stage 2 |
| **Stage 2**: v1 + 全书设定文件（战斗系统.md/物理规则.md/民风民俗.md等）+ 用户意图 + 世界决策表 | pipeline Phase 3完成后调度 | 素材/文风锚定.md v2（笔触层+世界画风层+用户需求层） | write（Phase 5正文写作） |

和decon的边界：decon=重拆(8维度+Beat Sheet)，pop-dna-style=轻采(笔触DNA+剧情brief)+综合重构。同书不同粒度，不冲突。

**执行模式**：Stage 1采样与笔触DNA提取（读25-30采样章归纳特征）是只读分析类工作，可派子agent执行并回报（子agent读采样章提取，主agent做门禁校验+落盘部署）；Step 4部署确认与Stage 2综合重构（pipeline调度+对笔触层的写权限决策）主agent直执。

## 怎么操作（SOP全内联）
> 双阶段设计：Stage 1在Phase 0执行，Stage 2在Phase 3完成后执行。两阶段间隔可能跨越数轮对话。

### Stage 1：笔触提取（Phase 0）

#### Step 1: 原文验证+场景定向采样

**1.0 原文存在性验证（前置门禁）**：
1. 检查 `素材/downloads/{书名}.txt` 是否存在（LS或Read）；不存在再查用户指定路径
2. 都不存在=**报错中止**：`参考书txt未找到，无法执行文风DNA提取。请先通过tool-download-webnovel下载，或手动提供txt文件路径。`
3. 验证txt非空且为正文（读前100行确认是小说内容非错误页面）
4. 验证通过后在文风锚定.md元数据记录：`采样源文件: {txt路径}` + 文件大小 + 验证时间

禁止基于记忆/书评/评论/公开数据替代原文；禁止跳过验证直接采样。

**采样目标**：总采样量25-30章；场景类型覆盖≥8种（9种中至少8种）；核心场景多采（3-4章）、边缘场景少采（1-2章）；禁止"前10+中5+后5"固定时间分段。

**类型→采样偏重**：采样前先判断参考书类型（优先用户关键词如"参考《诡舍》的恐怖笔触"→无关键词读前5章推断→无法判断则均匀采样每类2-3章）。不同类型的核心笔触集中在不同场景，均匀采样=稀释核心笔触样本权重：

| 参考书类型 | 核心场景（采3-4章） | 边缘场景（采1-2章） |
|:--|:--|:--|
| 恐怖悬疑（诡舍类） | 揭秘/心理戏、情感高潮（含死亡/牺牲）、暗杀/背刺 | 日常对话、群战/军队战、早期遭遇战 |
| 战斗爽文（深渊主宰类） | 中坚boss战、群战/军队战、早期遭遇战 | 日常对话、暗杀/背刺 |
| 都市异能·情报交易（烧烤摊类） | 日常对话、揭秘/心理戏、暗杀/背刺 | 群战/军队战、早期遭遇战、中坚boss战 |
| 仙侠养成（玄鉴仙族类） | 环境引入、过渡缓冲、揭秘/心理戏 | 暗杀/背刺、群战/军队战 |

（两表未列出的场景为常规场景，采2-3章。）采样清单头部追加：`> 采样偏重：{类型}。核心场景（{列表}）采3-4章，边缘场景（{列表}）采1-2章。`

**采样流程**：
1. 解析章节列表（匹配 `第\d+章` / `第[一二三四五六七八九十百千]+章` 等格式），产出 `章号|章名` 列表
2. 按章名关键词初分类到9种场景类型：

| 场景类型 | 章名关键词线索 |
|:--|:--|
| 日常对话 | 叙旧/来访/闲谈/夜话/茶/酒 |
| 环境引入 | 初到/抵达/新地/入城/进入 |
| 早期遭遇战 | （前30章内的战斗章） |
| 中坚boss战 | 单挑/对决/招式名对抗 |
| 群战/军队战 | 围杀/战场/军阵/万军/千军 |
| 暗杀/背刺 | 刺杀/潜行/暗影/偷袭/暗算 |
| 揭秘/心理戏 | 真相/发现/回忆/秘密/心魔 |
| 过渡缓冲 | 战后/清晨/赶路/休整/疗伤 |
| 情感高潮 | 告别/重逢/告白/泪/死/牺牲 |

3. 分类不确定的章读前50行确认场景标志（战斗描写/对话密度/环境铺陈/内心独白），先标"待定"最后统一归位
4. 每种场景类型选2-3个代表章（优先典型章避免边缘章），生成采样清单（`章号|章名|场景类型|采样理由` 表）

**Step 1门禁**：场景类型覆盖≥8种｜总采样25-30章｜每种场景类型至少2章。不达标→补采样到达标。

**边界条件**：

| 场景 | 处理 |
|:--|:--|
| 参考书<30章 | 全书采样，场景类型按实际分布选 |
| 参考书>500章 | 只采样前300章（覆盖前期成长线） |
| 章名无关键词（如纯数字章名） | 间隔采样（每20章抽1章）+读前50行分类 |
| 某场景类型全书都没有 | 跳过并在采样清单标注"本书无此场景"，总覆盖数仍需≥8 |

#### Step 2: 笔触DNA提取（档位A·必做）

**提取目标**：通用维度≥4个（从8个必选维度中选，优先该参考书最有特色的）+ 场景卡矩阵≥8个（覆盖采样清单主要场景类型）+ 全书稳定特征2条。产出格式与文风库、Stage 2终版、write消费协议同构。

**三段式模板**（通用维度卡与场景卡同构）：

```markdown
### 维度：{维度名} / ### 场景卡：{场景类型}

**操作特征**：（条件式指令——【何时启用】→【写什么】→【写多长】→【边界】。用可执行动词，禁"营造/巧妙/让读者"等评价词；场景卡含该场景类型的时间演变要点）
**完整段落**：（1-3段该维度/场景最典型原文，blockquote引用，整段保留不切碎——让模型学段落内技法组合，宁精勿滥）
**反面教材**：（AI味禁则清单——功能级禁则+病句族+「原书会怎么写」的反例替代；场景卡为对话/动作/氛围各一条最易翻车的病句族）
```

**8个必选维度**（每个维度读3-5个采样章归纳特征）：

| 维度 | 观察什么 |
|:--|:--|
| 叙事者距离 | 近距跟随主角/中距旁观/全知视角？视角切换频率？是否偷看配角度 |
| 情绪传递 | 直述情绪/动作外化/物象外化/环境烘托？ |
| 对话引导词 | "道"/"说"/省略引导词/动作带出？ |
| 外貌描写 | 什么时候写外貌？写多少？静态铺陈还是动态带出？ |
| 数据嵌入 | 系统面板/数值/属性怎么呈现？内联【】还是独立段？ |
| 环境展开 | 环境描写长度？感官覆盖？功能化还是氛围化？ |
| 段落呼吸 | 段落长度分布？长短交替规律？节奏感？独句段功能？ |
| 物品描写 | 物品命名风格？描写详略？是否功能化？ |

**场景卡候选**（每张场景卡读该类型的2-3个采样章）：战斗·早期遭遇战 / 战斗·中坚boss战 / 战斗·群战/军队战 / 战斗·暗杀/背刺 / 对话·日常 / 对话·情感高潮 / 对话·信息交换 / 描写·环境引入 / 描写·角色外貌 / 叙述·孤独紧张 / 叙述·过渡缓冲 / 叙述·揭秘/心理戏

**反面教材三要素**（每维度/场景卡必做，从采样章反推该特征最易翻成AI味的写法）：

| 要素 | 定义 | 示例 |
|:--|:--|:--|
| 病句族 | 该维度下模型最容易默认产出的AI病句形态 | 情绪直述病（"他的眼睛里闪过一丝复杂"）/定格病（"时间仿佛凝固了"） |
| 功能级禁则 | 该维度下必须禁止的功能行为 | 禁"点破后文"（"这是他此生最后一个安全时刻"）/禁"能力科普旁白" |
| 原书替代 | 原书怎么避开上面病句——给一句原书处理示范 | 原书用"动作外化"替代"情绪直述" |

> 反面教材是功能性护栏，不是关键词黑名单：禁的是"该维度里模型最易翻车的功能行为"，不是某个词；原书替代说明"该禁的东西，原书作者用了什么更高明的写法顶上"。

**全书稳定特征（2条）**：归纳全书贯穿始终、不随场景变化的稳定笔触（如"全书对话段独立成段，不与动作段混合""全书无内心独白大段，情绪用动作或物象外化"）。

**Step 2自检**：三段式完整性（每维度/场景卡三部分齐全）｜操作特征条件式（何时→写什么→多长→边界可执行，禁评价词）｜完整段落不切碎（整段blockquote）｜反面教材功能性（非关键词黑名单）｜场景卡矩阵≥8｜只学笔触不学内容（操作特征禁出现"主角用XX技能打败敌人"类剧情描述，只描述"短句密集+动作动词连续+无心理描写"类笔触特征）｜原文真实性（完整段落必须来自采样章真实原文，不杜撰）。

#### Step 3: 剧情DNA brief（档位B·可选）

启用判断：用户明确要求"提取剧情DNA"或"档位B"→执行本步；只要笔触DNA→跳过直接进Step 4。

3维度brief，每维度=1段话观察+1-2条迁移指引。**不写Beat Sheet，不做压力源6字段转化**：

| 维度 | 观察点（1段话） | 迁移指引示例（1-2条） |
|:--|:--|:--|
| 爽点节奏 | 单元剧循环模式（如"每3-5章一个完整闭环：建压→升级→爆发"）、爆发间隔（大爽点间隔章数）、章末钩子类型（悬念/威胁/揭示/反转） | "3章闭环模式可迁移到番茄连载，保持每3章一个完整爽感闭环"；"章末钩子以威胁逼近为主，避免纯悬念型（番茄读者要即时压力）" |
| Boss梯度 | 4层递进结构（如"街头混混→地方帮主→执法系统→幕后金主"）、出场铺垫方式（如"每个boss出场前2章埋伏笔，通过配角对话暗示"） | "4层梯度结构可直接迁移，但第一卷boss须在ch020前出场"；"铺垫迁移为'前1章配角对话暗示+出场章直接冲突'" |
| 主角成长曲线 | 破局手段演变（如"前期金手指碾压→中期信息差智斗→后期势力博弈"）、压力源切换（如"生存→身份→责任"） | "破局演变可迁移，但番茄前期更偏直接碾压（前20章信息差智斗太慢）"；"压力源切换节奏可迁移，每50章切换一次" |

**产出格式**：`# {参考书名} · 剧情DNA brief`（标注档位B、供seed/plot消费）+ 3个H2节（爽点节奏/Boss梯度/主角成长曲线），每节 `**观察**` 1段 + `**迁移指引**` 编号列表。

和decon的边界：同三维度在decon是全书Beat Sheet+boss卡+成长曲线图的重拆，在本skill是1段观察+1-2条迁移的轻采——拿参考书当灵感源，不做立项圣经。

#### Step 4: 部署到项目本地

| 产出 | 部署路径 | 消费方 |
|:--|:--|:--|
| 笔触DNA（档位A） | `{项目空间}/素材/文风锚定.md` | write（第一优先级加载） |
| 剧情DNA-brief（档位B） | `{项目空间}/素材/剧情DNA-brief.md` | seed/plot |

**部署流程**：
1. **确认项目空间**：用户在创作项目中调用→当前工作目录即项目空间；未指定→询问"部署到哪个项目？"；`素材/` 不存在→创建
2. **写入文风锚定.md**（v1·笔触层），文件头含：参考书名 + `提取: pop-dna-style · {timestamp}` + 参考书文件路径 + 采样章数与场景类型数 + 产出格式声明（三段式与文风库同构，write全量加载无压力）+ 消费方声明（write skill 笔触DNA标准插槽·启用态）+ `v1-Stage1产出，待Stage2重构` 标注；正文=通用维度 / 场景卡矩阵 / 全书稳定特征三节
3. **写入剧情DNA-brief.md**（如启用档位B），文件头含参考书路径 + 档位B声明
4. **索引更新**：`素材/索引.md` 追加条目（不存在则创建）：产出 | 来源（pop-dna-style+参考书名）| 时间
5. **消费协议确认**（向用户输出）：启用态——write从文风锚定.md取笔触层，禁止凭空发挥；加载优先级第一（10万字裁剪时不裁剪）；消费规则——操作特征=可执行笔触约束、完整段落=句式/感官/叙事距离的段落内技法组合示范（可学节奏与组合，禁止照抄内容）、反面教材=功能级禁则（禁点破后文/能力科普/情绪直述）压AI味；只学笔触不学内容

**部署门禁**：文件已创建｜文件头完整（参考书名+采样章数+场景类型数+时间戳）｜索引已更新｜消费协议已向用户输出确认。

### Stage 2：综合重构（Phase 3完成后）

#### Step 5: 文风DNA综合重构

> 定位：世界设定产出后，拿世界画风当镜子照Stage 1笔触层——问"这个笔触维度放到本书世界里还成立吗？"成立→保留，部分不成立→修改，完全不成立→删除；再追加世界画风层+用户需求层，产出终版文风锚定.md。由pipeline Phase 3完成后调度执行。核心权限：对Stage 1笔触层拥有写权限（可修改/删除/保留任何维度），不是只读追加。

**前置输入**：

| 输入 | 来源 | 用途 |
|:--|:--|:--|
| 素材/文风锚定.md（v1） | Stage 1 | **重构对象**——笔触层每个维度都要被世界画风校验 |
| 设计/全书设定/战斗系统.md | world Phase 3 | 战斗画风源（产出E战斗画风表） |
| 设计/全书设定/物理规则.md | world Phase 3 | 环境画风源（物理规则+源力量特性） |
| 设计/全书设定/民风民俗.md | world Phase 3 | 日常画风源（民风民俗+政治经济调性） |
| 设计/全书设定/世界设计原则.md | world Phase 3 | 世界整体调性（所有设定的"宪法"） |
| 素材/用户意图.md | pipeline Phase 0 | 用户需求（面板偏好/节奏偏好/主角姿态偏好） |
| 设计/世界决策表.md | world Phase 0 | 世界方向约束（用户对世界的偏好选择） |
| 设计/力量体系.md | world Phase 3 | 源力量特性（战斗画风的因果源头） |
| 立项/01-立项PRD.md | seed Phase 1 | 故事调性（六要素/起因经过结果/命运终点） |

**5.1 世界画风提取**：从全书设定文件提取本书世界的综合画风。画风从世界因果链涌现（源力量→物理规则→战斗方式→画风），不是凭空设计，每个画风描述必须回溯到全书设定文件的具体设定：

| 画风维度 | 来源 | 提取方法 |
|:--|:--|:--|
| 战斗画风 | 战斗系统.md产出E（战斗画风表） | 直接消费每个阶位段的画风描述 |
| 环境画风 | 物理规则.md + 力量体系源力量 | 问"这个世界的物理环境什么气质？"（阴冷压抑/飘逸华丽/硬朗写实/荒诞诡谲） |
| 日常画风 | 民风民俗.md + 政治经济 | 问"这个世界的人日常生活什么调性？"（苦涩沉重/轻松市井/森严等级） |
| 源力量画风 | 物理规则.md力量法则 + 源力量 | 问"这个世界的超凡力量什么视觉气质？"（金色神圣/暗红血腥/幽蓝神秘/灰色朴素） |

**5.2 笔触层校验重构**（核心环节）：对v1每个通用维度+每张场景卡执行校验三问：

| # | 问题 | 判断标准 | 处理 |
|:--|:--|:--|:--|
| 1 | 这个笔触维度放到本书世界里成立吗？ | 笔触描述的写作手法在世界画风的气质下是否自然 | 成立→✅保留 |
| 2 | 部分不成立还是完全不成立？ | 部分=核心手法对但某些细节和世界矛盾；完全=整个手法和世界气质冲突 | 部分→🔧修改；完全→❌删除 |
| 3 | 如果修改，改成什么？ | 用世界画风当校准基准，把矛盾部分替换成本书世界的等效手法 | 写明修改前后对比 |

校验重点举例：叙事者距离（参考书贴身跟随但本书世界宏大史诗感→拉远）；情绪传递（参考书身体反应传情但本书高魔华丽→加灵能/法术层面表达）；对话引导词（参考书朴素直接但本书贵族政治→加身份感引导词）；数据嵌入（**关键校验项**——参考书弹窗式面板但本书写实生存感→改编织式或混合式）；环境展开（参考书嗅觉先行但本书冰雪纯净→触觉先行）；段落呼吸（参考书短句密集但本书史诗感→加长段叙事）；外貌/物品描写同法校验；每张场景卡按对应期画风校验（如boss战笔触放到本书中武期画风下是否自然）。

校验结果汇总为**重构决策表**（维度/场景卡｜校验结果｜处理方式｜修改说明），示例："数据嵌入｜部分不成立｜🔧修改｜弹窗式→混合式（战斗中编织+战后结算弹窗），因本书世界是生存记录感，弹窗打断叙事流"。**重构硬约束**：修改/删除必须有世界画风的因果依据（源力量+物理规则+战斗方式矛盾才能改/删），不能"我觉得这个不好"就删。

**5.3 用户需求层提取**：从用户意图+世界决策表提取用户对文风的显性偏好。优先级最高——用户需求 > 世界画风 > 笔触层，冲突时用户需求覆盖世界画风、世界画风覆盖笔触层：

| 需求维度 | 提取方法 |
|:--|:--|
| 面板嵌入方式 | 用户是否明确要求保留/删除面板？保留的话偏好弹窗式/编织式/混合式？ |
| 主角姿态偏好 | 猎手式（掌控全局）/幸存者式（挣扎求生）/混合式？ |
| 节奏偏好 | 快节奏游戏化/慢节奏生存感/混合节奏？ |
| 特殊文风要求 | 明确的文风要求（如"像XX书的笔触""要有古风感"） |

**5.4 三层综合产出**：素材/文风锚定.md v2（覆盖v1，单一文件，三层用H2分隔）：

- **文件头**：提取声明（Stage 2·时间戳）+ Stage 1参考书（书名+txt路径）+ 世界画风源（四个全书设定文件）+ 用户需求源（用户意图.md+世界决策表.md）+ 消费方（write Phase 5正文写作）+ 产出格式声明（三段式与文风库同构）
- **第一层 笔触层**：通用维度+场景卡矩阵+全书稳定特征，每个维度/场景卡保留三段式结构并标注校验结果（✅保留/🔧修改/❌删除+依据）；场景卡含 `scene:` 字段（对齐prose-render消费协议）
- **第二层 世界画风层**：战斗画风（按低武/中武/高武阶位段表+回溯依据）/环境画风/日常画风/源力量画风——画风是整体气质不是参数清单，write拿到画风后结合笔触层和六要素自行落地
- **第三层 用户需求层**：面板嵌入方式/主角姿态偏好/节奏偏好/特殊文风要求，每个声明必须引用用户原话（用户意图.md或世界决策表.md中的原文）
- **末尾 重构决策表**：write可据此理解哪些维度被修改过及原因

**产出硬约束**：①单一文件不拆分；②Stage 1内容不删除——即使某维度标记❌删除也保留原文+标注删除原因（write可据此理解参考书原貌）；③修改标注可见——🔧修改的维度修改前后对比必须可见（修改说明字段）；④画风回溯——每个画风描述回溯到全书设定文件的具体设定（源力量/物理规则/战斗方式）；⑤用户需求原话引用。

**无参考书模式**：用户Phase 0跳过拆书时v1不存在，Stage 2从零构建——跳过5.2（无笔触层可校验），5.1/5.3照常执行，5.4调整为二层产出（仅世界画风层+用户需求层），文件头标注"Stage 1: 跳过（用户选择无参考书）"。write拿到无笔触层的文风锚定.md时从世界画风层+用户需求层推导笔触（画风决定"战斗什么气质"、用户需求决定"面板怎么嵌"），质量会降级但不会无法工作。

**Stage 2质量门**：4个画风维度（战斗/环境/日常/源力量）全部提取｜每个通用维度+每张场景卡都有校验结果｜每个修改/删除都有世界画风的因果依据｜用户需求4维度全提取（无则标注"用户未指定"）｜三层H2分隔+重构决策表在末尾｜画风回溯链完整｜单一文件｜三段式完整（每维度/场景卡含三段，与文风库同构）｜操作特征条件式（非观察描述，禁评价词）｜完整段落不切碎（每维1-3段整段原文blockquote）｜反面教材功能性（功能级禁则+病句族+原书替代）。

产出后向pipeline报告：校验结果汇总（保留N项/修改N项/删除N项）+ 画风层数量 + 用户需求覆盖情况。

## 红线
1. **档位与调度**：档位B（剧情DNA brief）由用户开关控制是否执行。Stage 2由pipeline调度触发，不由用户直接调用。
2. **笔触DNA必须按三段式模板** — 每个维度/场景卡=操作特征(条件式指令)+完整段落(整段保留不切碎)+反面教材(AI味清单+功能诊断)，三者不可缺一，时间演变并入操作特征。禁止"金句碎片化"——碎片破坏段落内技法组合，已被AB测试证明垫底。
3. **采样必须场景定向覆盖≥8种** — 禁止只用"前10+中5+后5"时间分段
4. **只学笔触不学内容** — 观察字段只描述句式/感官/叙事距离等风格特征，禁止描述剧情/战斗/角色思维
5. **原文存在性前置门禁** — Step 1采样前必须验证参考书txt存在于`素材/downloads/`或用户指定路径。文件不存在=报错中止，禁止基于记忆/书评/评论/公开数据替代原文。文风锚定.md元数据必须包含`采样源文件: {txt路径}`字段，无此字段=产出无效。
6. **Stage 2重构权限** — Stage 2对Stage 1笔触层拥有写权限（可修改/删除/保留），但每个修改/删除必须有世界画风的因果依据（源力量+物理规则+战斗方式矛盾才能改/删）。用户需求层优先级最高：用户需求 > 世界画风 > 笔触层。
7. **单一文件** — 文风锚定.md是唯一产出文件。Stage 1产出v1，Stage 2覆盖为v2。不拆分多文件。
