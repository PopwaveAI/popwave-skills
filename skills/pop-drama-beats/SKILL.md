# pop-drama-beats

> 短剧分集模块。当前版本 v4.0.0（2026-10-19：按“分集”创作对象重排，输出 `05-分集/` 四份）。
> 本模块排每集写什么：核心事件、转折、卡点、镜头预算；不写台词、不写场次。

---

## 本模块负责什么

| 产出 | 内容 |
|:--|:--|
| `05-分集/分集卡点表.md` | 全剧网格、逐集冲突/转折/卡点/预算 |
| `05-分集/前10集节拍.md` | 前 10 集秒级节拍 |
| `05-分集/钩子台账.md` | 钩子埋设、回收、健康度 |
| `05-分集/预算表.md` | 每集镜头/台词/场景/角色/风险预算 |

**边界**：

- 不改故事核与人物关系。发现故事核撑不住，回 setting。
- 不写台词、动作行、场次头。剧本归 script。

**它可以单独调用**：用户已有设定和人物，只想排分集；或只想补前 10 集节拍，都可以只做对应文件。

## AI 可生成性约束（先读）

| 项 | 标准 |
|:--|:--|
| 单集时长 | 75-80 秒 |
| 单集镜头 | 12-13 镜 |
| 单集主场景 | 1 个（最多 2 个） |
| 单集主要角色 | 3 个（最多 4 个） |
| 单集台词总量 | 70-80 字 |
| 单句台词 | ≤12 字 |
| 单镜动作 | 1 个 |

排分集时就要算镜头账：一集超过 13 镜，拆集或砍线；少于 10 镜，加一次交锋。

详见 `<pop-drama-workbench 包根>/references/AI短剧生产约束.md`。

## 操作步骤

### Step 0 读输入

- `03-设定/故事核.md`：一句话、信息差、结局、20 个冲突源。
- `03-设定/世界与规则.md`：规则、权力、禁忌。
- `03-设定/场景库.md`：主场景清单、单集场景分配。
- `04-人物/人物总表.md` 与 `04-人物/主要人物.md`：谁要什么、谁挡谁、谁瞒什么。
- `01-市场定位.md`：总集数、单集时长、生产模式、付费墙位置。

缺故事核或人物时，先补，不硬排。

### Step 1 排全剧网格

按总集数缩放五段：

| 段 | 30 集 | 60-70 集 | 任务 | 结束在 |
|:--|:--|:--|:--|:--|
| 开局 | 1-3 | 1-3 | 前提讲清，主角做出选择 | 主角不再被动 |
| 蓄势到付费墙 | 4-10 | 4-10 | 每集抬高代价 | 付费墙揭露 |
| 升级 | 11-20 | 11-35 | 秘密难藏，对手逼近 | 中点反转 |
| 崩塌 | 21-25 | 36-56 | 主角搭起来的东西全塌 | 最低点 |
| 收束 | 26-30 | 57-70 | 对决、真相、情感落地 | 结局画面 |

**每 3 集一弧**：铺垫 → 反转 → 翻面。

**四个关键集**：

| 关键集 | 位置 |
|:--|:--|
| 付费墙 | 第 8-12 集或 15% 处，默认第 10 集 |
| 中点 | 50% 处，必须是一次权力或关系翻面 |
| 最低点 | 85% 处，用倒计时 |
| 结局 | 末集，回答核心信息差 |

### Step 2 填逐集表

每集一行，十三列：

| 列 | 写法 |
|:--|:--|
| 集 | EP001 |
| 弧 | 第几弧·第几拍 |
| 核心冲突 | 谁要什么，谁挡着，一句话 |
| 转折 | 主角做了什么选择 |
| 卡点 | 最后 5 秒发生什么 |
| 卡点类型 | 揭露/反转/倒计时/闯入 |
| 下集开头 | 卡点的反应怎么接 |
| 情绪 | 本集主情绪，一个词 |
| 场景 | 场景 ID，1 个（最多 2 个） |
| 角色 | 3 个主要角色 ID |
| 镜头预算 | 预计 12-13 镜 |
| 台词预算 | 预计 70-80 字 |
| 风险 | 打斗/crowd/儿童/动物/水/火 |

**五条纪律**：

1. 一集一冲突。
2. 每集有转折，主角主动。
3. 每集有卡点，四型轮换。
4. 成对：本集只给事件，反应放下集开头。
5. 不许过渡集。

### Step 3 写前 10 集节拍

90 秒标准四拍：

| 时间 | 任务 |
|:--|:--|
| 0-15 秒 | 钩子 |
| 15-60 秒 | 升级，2-3 次交锋 |
| 60-80 秒 | 转折 |
| 80-90 秒 | 卡点 |

60 秒集：0-10 / 10-40 / 40-53 / 53-60。
120 秒集：0-15 / 15-75 / 75-108 / 108-120。

**前 10 集额外检查**：

- 第 1 集前 3 秒有画面钩子。
- 第 1 集 15 秒内讲清谁、要什么、谁挡着。
- 第 3 集主角主动做出选择。
- 第 10 集是前段最强揭露。
- 每集镜头 12-13、台词 70-80 字。

### Step 4 记钩子台账

每集一条：集、卡点类型、卡点内容、埋设、预计回收、实际回收、状态。

**每 10 集查健康度**：

- 连续两集同型：改后一集。
- 悬置超过 10 集未推进：本弧内回收或标“搁置”。
- 预计回收集已过：下一集必须表态。
- 回收方式重复：换一种。

### Step 5 写预算表

把每集的镜头、台词、场景、角色、风险集中到 `预算表.md`：

| 集 | 镜头数 | 总时长 | 台词字数 | 主场景 | 主要角色 | 风险 |
|:--|--:|--:|--:|:--|:--|:--|
| EP001 | 12 | 78s | 75 | S1 | A1/A2/A3 |  |

**预算规则**：

- 镜头 12-13；10-14 可接受；>15 拆集；<10 加交锋。
- 台词 70-80 字；单句 ≤12 字。
- 单集 1 主场景；需要第二个场景，先用同一场景不同机位解决。
- 单集 3 主要角色；第 4 个只作为无台词背景或声音。

### Step 6 交付检查

- [ ] 每集只有一个核心冲突。
- [ ] 每集都有主角主动做出的转折。
- [ ] 每集都有卡点，相邻两集不同型。
- [ ] 每集都写了“下集开头”。
- [ ] 付费墙是前段最强揭露。
- [ ] 中点有权力或关系翻面。
- [ ] 85% 处有最低点。
- [ ] 没有过渡集。
- [ ] 每集镜头 12-13（10-14 可接受）。
- [ ] 每集 1 主场景（最多 2 个）。
- [ ] 每集 3 主要角色（最多 4 个）。
- [ ] 每集台词 70-80 字，单句 ≤12 字。
- [ ] 钩子台账字段齐全，无超期未表态。
- [ ] 预算表与逐集表一致。

通过后写四份文件，更新 `00-创作总表.md` 的模块就绪。
