# pop-drama-character

> 短剧人物库模块。当前版本 v1.0.0（2026-10-19：从 story 拆出，人物库独立）。
> 产出：人物库五份。人物库同时服务编剧、选角、美术、B 组锁角色。

---

## 本模块负责什么

| 产出 | 内容 |
|:--|:--|
| `04-人物/人物总表.md` | 角色 ID、姓名、功能位、身份、核心标签、出场阶段 |
| `04-人物/主要人物.md` | 5-8 个主要人物的完整人物卡 |
| `04-人物/配角与功能位.md` | 配角、一次性角色、功能位清单 |
| `04-人物/关系图.md` | 人物关系、表面/真实关系、既需要又对抗的点 |
| `04-人物/选角与视觉锚点.md` | 选角信息、视觉锚点七项、禁用项、服装三套、固定道具 |

**边界**：

- 世界规则归 `pop-drama-setting`。
- 分集归 `pop-drama-beats`。
- 台词归 `pop-drama-script`。
- 本模块不写台词、不排分集、不写场景。

**它可以单独调用**：用户只想补人物、只想做关系图、只想定选角，都可以只做对应文件。

---

## AI 可生成性约束（先读）

| 项 | 标准 |
|:--|:--|
| 全剧主要人物 | 5-8 个 |
| 单集主要角色 | 3 个（最多 4 个） |
| 单集有台词人物 | ≤5 个 |
| 视觉锚点 | 七项写死，B 组能生成同一个人两张图 |
| 禁用项 | 每个主要人物必须有 |

**人物一多，AI 生成必崩。** 功能重复的合并；单集超过 3 个主要角色，回故事核砍线。

详见 `<pop-drama-workbench 包根>/references/AI短剧生产约束.md`。

## 操作步骤

### Step 0 读输入

- `03-设定/故事核.md`：一句话、主题、情感契约、20 个冲突源。
- `03-设定/世界与规则.md`：社会结构、权力、题材机制。
- `03-设定/视觉风格.md`：色彩、光线、镜头语言。
- `03-设定/语言风格.md`：台词总则、语言指纹四型。

缺故事核时，先补 setting，不硬写。

### Step 1 建人物总表

| 列 | 写法 |
|:--|:--|
| 角色 ID | A1 / A2 / A3…，全剧固定 |
| 姓名（中/英） | 海外剧英文名要能一次读对 |
| 功能位 | 推动者/阻挡者/见证者/引爆者 |
| 身份 | 职业、阶层、与主角关系 |
| 核心标签 | ≤2 个，观众 3 秒能记住 |
| 出场阶段 | 开局/中段/结局 |
| 主要/配角 | 主要人物 5-8 个 |

**功能位四条**：

- 推动者：主角，做选择，承担代价。
- 阻挡者：对手，利益与主角冲突。
- 见证者：让观众看到主角的变化。
- 引爆者：在关键节点把秘密或危机捅破。

**判据**：每个功能位至少一个具体的人；功能重复的合并。

### Step 2 写主要人物

每人十二项：

| 项 | 写法 |
|:--|:--|
| 角色 ID | A1 |
| 姓名（中/英） |  |
| 功能位 |  |
| 身份 |  |
| 核心标签（≤2） |  |
| 欲望 | 本剧里具体要什么，能用动作演 |
| 阻碍 | 谁或什么不让他得到 |
| 秘密 | 他知道什么、瞒着什么，与信息差挂钩 |
| 关系张力 | 与主角既合作又对抗的点 |
| 弧光 | 第 1 集与最后一集各一个具体画面 |
| 语言指纹 | 短刀型/绕弯型/书面型/沉默型，加口头禅与禁用词 |
| 行为习惯 | 一个反复出现的小动作或固定道具 |

**关系设计**：

- 主角与对手是镜像：同一欲望的不同解法，或同一伤口的不同反应。
- 每对重要关系写一句“既需要又对抗”的理由。
- 对手的行为必须能从利益推出来，不能靠“天生坏”。

**两个测试**：

1. 遮住名字读三句台词，能否认出是谁。
2. 只看视觉锚点，B 组能否生成同一个人的两张图。

### Step 3 写配角与功能位

| 类 | 写法 |
|:--|:--|
| 常驻配角 | 有名字、有功能、有固定出场场景 |
| 一次性角色 | 只服务某一集，写“功能 + 一句话外形” |
| 背景角色 | 不给名字，用“两个具体的人”代替 crowd |

**判据**：配角不能抢主线；一次性角色不能重复功能；背景角色不写成 crowd。

### Step 4 画关系图

| A | B | 表面关系 | 真实关系 | 既需要又对抗的点 | 变化节点 |
|:--|:--|:--|:--|:--|:--|
|  |  |  |  |  |  |

**关系类型**：血缘、契约、利益、情感、权力、秘密。

**判据**：每对重要关系至少有一次变化；没有变化的关系，合并或删。

### Step 5 写选角与视觉锚点

每个主要人物一份：

| 项 | 内容 |
|:--|:--|
| 角色 ID | A1 |
| 年龄感（实际/视觉） |  |
| 外形记忆点 |  |
| 主色 / 禁用色 |  |
| 服装三套 | 日常：；正式：；关键场次： |
| 固定道具 |  |
| 参考形象 |  |

**视觉锚点七项（写死）**：

| 项 | 内容 |
|:--|:--|
| 年龄 |  |
| 性别 |  |
| 脸型 |  |
| 发型发色 |  |
| 服装（颜色材质） |  |
| 标志特征（疤/痣/饰品） |  |
| 气质 |  |

**禁用项**：

- 不要胡须 / 不要眼镜 / 不要浓妆 / 不要换发型 / 其他：

**写法要求**：

- 中文写，给 B 组翻译成英文 prompt。
- 写“稳定可见”的特征，不写“倾国倾城”。
- 每个角色必须有禁用项。
- 服装三套与 `03-设定/道具与服装.md` 一致。

### Step 6 交付检查

- [ ] 主要人物 5-8 个，每人十二项齐全。
- [ ] 单集主要角色 ≤3，有台词人物 ≤5。
- [ ] 每个主要人物有视觉锚点七项与禁用项。
- [ ] 每个主要人物有语言指纹与固定道具。
- [ ] 关系图每对重要关系有“既需要又对抗”的点。
- [ ] 每对重要关系至少有一次变化。
- [ ] 配角不抢主线，一次性角色不重复功能。
- [ ] 遮名字能认出说话人。
- [ ] B 组能生成同一个人两张图。
- [ ] 与设定库、故事核不矛盾。

通过后写五份文件，更新 `00-创作总表.md` 的模块就绪。
