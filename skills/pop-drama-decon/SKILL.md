# pop-drama-decon

> 短剧对标拆解模块。当前版本 v2.0.0（2026-10-19：整体重构——增加 AI 可生成性判断与 AI 招式）。
> 本模块只提炼结构与招式，不抄剧情、不抄人名、不抄台词。

---

## 本模块负责什么

| 产出 | 内容 |
|:--|:--|
| `02-对标拆解.md` | 3-5 部对标剧的九项结构、横向对比、可复用招式、AI 可生成性判断、避坑清单 |

**它可以单独调用**：用户只拿来一部剧，就只拆一部；用户要写剧本但没把握节奏，也可以只拆"卡点"这一项。

**边界**：

- 不写本项目的故事、人物、分集。
- 不复制参考剧的事件链、台词、人名、场景细节。
- 不把"某部剧火了"当成"这个结构一定成立"。

---

## 操作步骤

### Step 0 选对标剧

选 3-5 部，覆盖三类：

| 类型 | 作用 |
|:--|:--|
| 爆款 | 看验证过的结构与卡点 |
| 同预算 | 看这个预算能拍成什么样 |
| 邻近题材 | 看哪些招式可以迁移 |

筛选条件：同平台、同受众、同题材或邻近题材；优先最近 6 个月在播的。AI 生成项目优先选单场景、12-13 镜、3 角色的样本。

用户没给具体剧名时，去平台在播榜找，把候选与选择理由列给用户确认。不擅自开拆。

### Step 1 每部记九项

只记结构，不写剧情梗概：

| 项 | 记什么 |
|:--|:--|
| 1 基本信息 | 平台、集数、单集时长、题材标签 |
| 2 一句话故事 | 谁、要什么、谁挡着、代价 |
| 3 核心信息差 | 观众知道什么、角色不知道什么 |
| 4 前 3 集卡点 | 每集最后 5 秒的画面 + 卡点类型 |
| 5 付费墙 | 第几集、揭什么、类型 |
| 6 中点 | 第几集、什么反转 |
| 7 人物功能 | 主角、对手、见证者、引爆者各是谁（只写功能） |
| 8 制作约束 | 主场景数、主要人物数、有无特效、最贵的戏 |
| 9 AI 可生成性 | 单集场景数、角色数、镜头数、有无复杂动作、整体可行性 |

**AI 可生成性判断**：

| 项 | 记什么 |
|:--|:--|
| 单集场景 | 1 个 / 2 个 / 3 个以上 |
| 单集角色 | 3 个 / 4 个 / 5 个以上 |
| 单集镜头 | 约 12-13 / 10 以下 / 15 以上 |
| 复杂动作 | 有打斗/奔跑/crowd/儿童/动物/水火吗 |
| 可行性 | 可直接 AI / 改造后可 AI / 不适合 AI |

**记录纪律**：

- 卡点必须写成"最后 5 秒的画面"，不写"这集很燃"。
- 类型必须归入揭露/反转/倒计时/闯入。
- 看不清的标"未看清"，不猜。

### Step 2 横向对比

三项对比：

| 对比项 | 看什么 |
|:--|:--|
| 共性 | 3 部以上都用的结构、卡点、人物关系 |
| 差异 | 爆款与同预算剧的差别在哪 |
| 变化 | 近半年与前两年的写法有什么不同 |
| AI 适配 | 哪些样本本来就是单场景/12 镜/3 角色 |

**判据**：共性要能解释"为什么有效"，不能只列"都用了反转"。

### Step 3 提炼可复用招式

按七类整理，每类 2-4 条：

| 类 | 招式 | 适用条件 | 不适用条件 |
|:--|:--|:--|:--|
| 开场钩 |  |  |  |
| 升级 |  |  |  |
| 转折 |  |  |  |
| 卡点 |  |  |  |
| 付费墙 |  |  |  |
| 人物关系 |  |  |  |
| AI 可生成 | 单场景调度、12 镜节奏、局部特写替代动作 |  |  |

**写法要求**：

- 招式写成可执行的动作，不写抽象评价。
- 每条标"适用条件"与"不适用条件"，防止生搬。
- AI 可生成招式要写清"用什么替代复杂动作"。

### Step 4 映射到本项目

| 招式 | 本项目能不能用 | 怎么改 | 风险 |
|:--|:--|:--|:--|
|  | 能/不能/改造后用 |  |  |

**三条映射规则**：

1. 与核心信息差不匹配的招式，不用。
2. 与预算/生产模式不匹配的招式，改造或放弃。
3. 已经在本题材用烂的招式，只保留结构，换执行细节。

### Step 5 避坑清单

列出本题材/本平台"已经失效"的写法，每条写为什么失效：

| 写法 | 为什么失效 | 替代 |
|:--|:--|:--|
|  |  |  |

### Step 6 交付检查

- [ ] 3-5 部，每部九项齐全。
- [ ] 每部至少 3 集卡点记到"最后 5 秒画面"。
- [ ] 卡点类型可归类。
- [ ] 每部有 AI 可生成性判断：场景/角色/镜头/复杂动作/可行性。
- [ ] 横向对比有共性、差异、变化、AI 适配。
- [ ] 招式库每条有适用与不适用条件。
- [ ] 映射到本项目，标了能用/不能用。
- [ ] 没有出现参考剧的人名、台词、事件链原文。
- [ ] 每条来源带链接与日期。

通过后写 `02-对标拆解.md`，用 `templates/对标拆解.tpl.md`，更新 `00-创作总表.md` 文件索引。

## 检索纪律

- 先内部 wiki `https://wiki.popwave.cn`，不足再联网。
- 单模块最多 1 轮，最多 5 个检索项，回传不超过 30KB。
- 平台规则查官方，榜单与题材数据查第三方报道，标"报道"。
- 查不到就写"没查到"，不猜。
