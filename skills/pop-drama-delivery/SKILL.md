# pop-drama-delivery

> 短剧剧本包交付模块。当前版本 v1.0.0（2026-10-19：新增）。
> 本模块只做两件事：把 A 组文件收齐、写成 B 组能直接开工的交付包；缺什么报什么。

---

## 本模块负责什么

| 项 | 内容 |
|:--|:--|
| 输入 | `00` 至 `07` 全部文件 |
| 输出 | `08-交付/` 五份文件 |
| 下游 | B 组（AI 制作）、甲方、平台 |

**边界**：

- 不写故事、不改剧本、不改镜头意图。
- 缺文件只列缺口并退回对应模块，不替它补内容。
- 不写首帧 prompt、不做抽帧、不做剪辑。

---

## 交付前检查

逐项查文件，缺一项不进入打包：

| # | 检查 | 判据 |
|:--|:--|:--|
| 1 | 创作总表 | `00-创作总表.md` 存在，关键决定齐全 |
| 2 | 市场定位 | `01-市场定位.md` 存在，平台/受众/题材/生产模式/集数/时长/卖点/标题齐全 |
| 3 | 对标拆解 | `02-对标拆解.md` 存在（可标"未做"，但需用户确认） |
| 4 | 故事核 | `03-故事核.md` 存在，一句话/情感契约/信息差/结局/20 冲突源齐全 |
| 5 | 人物卡 | `03-人物关系与人物卡.md` 存在，主要人物有视觉锚点 |
| 6 | 场景与视觉 | `03-场景与视觉.md` 存在，主场景有空景锚点 |
| 7 | 分集卡点 | `04-分集卡点表.md` 存在，逐集冲突/转折/卡点/镜头预算齐全 |
| 8 | 剧本 | `05-剧本/EP001…` 与 `全剧剧本.md` 齐全 |
| 9 | 镜头意图 | `06-镜头意图表/EP001…` 与 `全剧镜头意图表.md` 齐全 |
| 10 | 审稿 | `07-审稿/EP001…` 与 `全剧审稿报告.md` 齐全，结论为可交付 |

**红线**：

- 任何一集缺剧本或缺镜头意图，不交付。
- 全剧审稿结论不是"可交付"，不交付。
- 镜头意图超过 15 镜或少于 10 镜，不交付。
- 缺平台合规自查，不交付。

## 五份交付文件

### 1. 剧本包说明.md

给 B 组和甲方的使用说明。内容：

- 项目基本信息。
- 包含哪些文件、每个文件干什么。
- 推荐使用顺序。
- A→B 交接契约：A 给什么、B 补什么。
- 版本号与变更记录。
- 联系方式与交接人（可选）。

### 2. 一句话故事与卖点.md

给发行、运营、封面设计。内容：

- 一句话故事（≤60 字）。
- 15 秒口述版。
- 情感契约。
- 核心信息差。
- 3 个标题候选（中/英）。
- 封面方向。
- 人物一句话。
- 平台标签建议。

### 3. 人物小传合集.md

给选角、美术、B 组锁角色。内容：

- 每个主要人物的压缩卡：姓名、年龄、身份、核心标签、欲望、阻碍、语言指纹、视觉锚点、禁用项。
- 人物关系图。
- 角色 ID 对照（A1/A2/A3）。
- 服装与色彩变化。

### 4. 全剧台词统计.md

给配音、B 组排期、制作预算。内容：

- 每集台词字数。
- 每集预估语音秒数（按每秒 4-5 字）。
- 每集最长单句。
- 全剧总字数、总语音时长。
- 需要旁白/字幕的段落清单。

### 5. 平台合规自查.md

给发行与审稿。内容：

- 暴力、血腥、性暗示、未成年人、敏感身份、真实人物、迷信导向、平台规则八项。
- 每项判据与结论。
- 需要修改的集数与位置。
- 最终结论：可交付 / 需修改。

## 操作步骤

### Step 0 收文件

用 LS 扫 `00` 至 `07`，列文件清单与缺项。

### Step 1 过检查表

按「交付前检查」逐项打勾。缺项列成清单，退回对应模块。

### Step 2 写五份文件

按 `templates/` 五份模板写。每份只写该文件该有的内容，不复制整本剧本。

### Step 3 交付验收

逐项问：

- [ ] B 组拿到包，能不能不看 A 组聊天记录就开工？
- [ ] 每一集都有剧本、镜头意图、审稿结论？
- [ ] 每一个角色都有 ID、视觉锚点、禁用项？
- [ ] 每一个场景都有 ID、空景锚点？
- [ ] 每一集镜头数 12-13、总时长 75-80 秒？
- [ ] 台词统计与镜头意图对得上？
- [ ] 合规自查有结论？
- [ ] 剧本包说明写清了怎么用？

任何一项"不能"，补完再交。

### Step 4 更新总表

在 `00-创作总表.md`：

- `08-交付/` 标已建。
- 最近改动写"交付包完成"。
- 如有降级项，写清欠什么。
