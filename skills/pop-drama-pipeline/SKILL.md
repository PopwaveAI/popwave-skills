# pop-drama-pipeline

> 短剧剧本线总控。当前版本 v1.0.0（2026-10-19：首版，范围到剧本交付与审核为止，不含分镜、拍摄、成片）。

---

## 职责范围

| 职责 | 说明 |
|:--|:--|
| 一次性初始化（fresh） | 建项目目录，写 `状态.md` |
| 导入与续写（import/resume） | 扫资产、归位、查缺口、定落地环节、重建状态 |
| 状态维护 | `状态.md` 是唯一状态总账，agent 只读写其中的状态片段 |
| 阶段路由 | 按用户说法直接选 skill，不让用户记流程 |
| 交付检查 | 每个环节交付前按本文件的检查项过一遍 |

**边界**：本线只做到剧本与剧本审核。分镜、拍摄、配音、成片不在本期范围。pipeline 不写内容，不做格式转换，不常驻。

**执行方式**：主 agent 直接执行，不派子 agent 代跑创作环节。纯只读的资料检索可派子 agent，由主 agent 汇总。

---

## 开工前须完成的检查

每个环节动笔前与定稿前各执行一次：

- **一、找缺口**：列出"要更好还须见过哪些面"，再列已覆盖项，两者之差即缺口。缺一个维度就补一轮资料。
- **二、再取材**：优先内部 wiki `https://wiki.popwave.cn`，不足再联网。单环节最多一轮，一轮最多 5 个检索项，回传不超过 30KB，超出只留结论。
- **三、给依据**：候选与现项并列打分，不只说"这个更好"。最终选哪个由用户定。
- **四、交付后复检**：问"这是不是上限"，有更优才重议，最多两轮。

取材内容只进上下文，用户采纳后才写进产出。

## 项目目录规范

初始化建 7 个一级目录：

```
{项目名}/
  状态.md
  调研采风/
    市场与平台.md
    参考剧拆解.md
    采风/
  立项/
    00-立项稿.md
  人物库/
    人物小传.md
    选角卡.md
  舞台库/
    场景库.md
    视觉规则.md
  剧情库/
    00-主线结构表.md
    分集大纲.md
    前10集节拍表.md
    钩子台账.md
  剧本/
    EP001.md … EP{总集数}.md
    全剧剧本.md
  审核/
    EP001-审核.md … EP{总集数}-审核.md
    全剧审核报告.md
```

**文件口径**：

- 一集一个剧本文件，命名 `EP001.md`，三位数。
- 人物只建两份：`人物小传.md` 写完整卡，`选角卡.md` 写外形、配色、参考形象，供选角与美术用。
- 阶段之间的传递只认文件，不认聊天记录。

## 操作步骤

### Step 0：导入与续写

触发：用户说"导入/续写/已有剧本/接着写"，或 Step 1 检测到目录里已有文件。

**0a 资产扫描**：用 LS 扫目录，列出每个文件的文件名、位置、一句话内容。

**0b 资产归位**：

| 用户文件（模糊匹配） | 归到 | 标准文件名 |
|:--|:--|:--|
| *想法*/*方向*/*题材* | `调研采风/` | 用户意图.md |
| *市场*/*平台*/*排行*/*数据* | `调研采风/` | 市场与平台.md |
| *拆解*/*拉片*/*参考剧* | `调研采风/` | 参考剧拆解.md |
| *资料*/*考据*/*职业*/*场景* | `调研采风/采风/` | {主题}.md |
| *立项*/*梗概*/*策划* | `立项/` | 00-立项稿.md |
| *人物*/*人设*/*角色* | `人物库/` | 人物小传.md |
| *选角*/*参考形象*/*配色* | `人物库/` | 选角卡.md |
| *场景*/*场地*/*美术* | `舞台库/` | 场景库.md / 视觉规则.md |
| *大纲*/*分集*/*集纲* | `剧情库/` | 分集大纲.md |
| *节拍*/*卡点表*/*付费点* | `剧情库/` | 前10集节拍表.md |
| *剧本*/*第N集*/*EP* | `剧本/` | EP{NNN}.md |
| *审核*/*意见*/*打分* | `审核/` | EP{NNN}-审核.md |

匹配不上的归入"未分类资产"，向用户问映射。`.docx` 先读内容再写成 md。归位前问用户是否保留原文件。

**0c 缺口检查**（按文件是否存在判定）：

| 环节 | 就绪条件 |
|:--|:--|
| 1 立项 | `立项/00-立项稿.md` |
| 2 人物舞台 | `人物库/人物小传.md` + `舞台库/场景库.md` |
| 3 分集 | `剧情库/分集大纲.md`（30 集以上剧须含全剧集数） |
| 3+ 前10集 | `剧情库/前10集节拍表.md` |
| 4 剧本 | `剧本/EP*.md`（下一集 = 最大编号 + 1） |
| 5 审核 | `审核/EP*-审核.md` 与剧本逐集对应 |

**0d 落地环节判定**：

| 已有文件 | 落到 |
|:--|:--|
| 有剧本、有审核 | 4，继续写下一集 |
| 有剧本、缺审核 | 5，先补审 |
| 有分集大纲、无剧本 | 4 |
| 有立项、无分集 | 3 |
| 有立项、无人物舞台 | 2 |
| 全无 | 1 |

向用户展示资产清单、缺口、落地建议，确认后再写 `状态.md`。

**0e 状态重建**：`状态.md` 不存在则按模板新建；已存在则只改涉及字段。

### Step 1：初始化

1. 建 7 个一级目录和标准空档。
2. 写 `状态.md`，`mode: fresh`，`phase: init`，全部就绪态标 `[ ]`。
3. 输出首次引导：说明本线做短剧剧本，不做分镜与成片；问用户"平台、市场、集数、单集时长、题材"五项。已说清的不重问。

**Step 1 检查**：目录齐全、`状态.md` 已写、五项输入有答案或明确标"待定"。

## 阶段路由状态机

```
init → 1 立项 → 2 人物与舞台 → 3 分集大纲 → 4 写剧本 → 5 审核 → 回 4 写下一集
```

| phase | skill | 产出 | 完成后 |
|:--|:--|:--|:--|
| 1 | `pop-drama-seed` | `立项/00-立项稿.md` | 2 |
| 2 | `pop-drama-stage` | 人物小传、选角卡、场景库、视觉规则 | 3 |
| 3 | `pop-drama-plot` | 主线结构表、分集大纲、前10集节拍表、钩子台账 | 4 |
| 4 | `pop-drama-script` | `剧本/EP{NNN}.md` | 5 |
| 5 | `pop-drama-review` | `审核/EP{NNN}-审核.md` | PASS 回 4；REJECT 留 4 重写 |
| 任意 | `pop-drama-research` | `调研采风/` 下的条目 | 回原环节 |

**日常路由不经过本 skill**：用户说"写第 5 集"，主 agent 读 `状态.md`，直接加载 `pop-drama-script`。用户说"审一下"，直接加载 `pop-drama-review`。

**批量写法**：3 集为一组写，写一组审一组。审核 PASS 后 `current_episode` 加 3。用户要求一次性跑全剧时，按组分批，不许一次生成 30 集不审。

**状态更新**：每个 skill 完成后，更新 `phase`、`current_episode`、对应就绪态、`updated_at`、最近产出。只改涉及字段。

## 全剧事实优先级

冲突时按此取证，不得反向覆盖：

| 权重 | 事实源 | 说明 |
|:--:|:--|:--|
| 1 | 用户本轮要求 | 可覆盖，但须指出冲突并记录改法 |
| 2 | 已定稿剧本 | 已写出的台词与事件最硬 |
| 3 | 立项稿 | 一句话故事、情感契约、结局 |
| 4 | 人物小传与选角卡 | 性格、关系、外形、语言习惯 |
| 5 | 场景库与视觉规则 | 地点、道具、服装、色彩 |
| 6 | 分集大纲与钩子台账 | 计划层，优先级最低 |

## 交付标准（本期范围）

一部短剧交付齐以下五件，才算完成：

1. `立项/00-立项稿.md`：一句话故事、情感契约、核心信息差、结局、付费墙位置齐全。
2. `人物库/` 与 `舞台库/`：主要人物有功能位与语言指纹；主场景不超过 8 个且可拍。
3. `剧情库/分集大纲.md`：每集一行，含核心事件、转折、卡点类型。
4. `剧本/EP001.md` 至末集：格式统一，每集有钩子、有转折、有卡点。
5. `审核/全剧审核报告.md`：逐集 PASS/REJECT 记录与最终结论。

**红线**：单集没有卡点、单集出现小说式心理描写、场景数超出预算、人物功能重复，四项任一命中即不合格。
