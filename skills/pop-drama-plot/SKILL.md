# pop-drama-plot

> 短剧剧本线分集环节。当前版本 v1.0.0（2026-10-19：首版）。
> 本环节把立项骨架拆成每一集可写的冲突、转折与卡点。

---

## 本环节负责什么

| 任务 | 触发 | 消费 | 产出 |
|:--|:--|:--|:--|
| P 主线结构表 | 全剧只做一次 | 立项稿的七节点、五段式 | `剧情库/00-主线结构表.md` |
| A 分集大纲 | 每部一次，可分批 | 主线结构表、人物小传、场景库 | `剧情库/分集大纲.md` |
| B 前 10 集节拍表 | 分集大纲后 | 分集大纲第 1-10 集 | `剧情库/前10集节拍表.md` |
| C 钩子台账 | 与分集大纲同步 | 分集大纲每集卡点 | `剧情库/钩子台账.md` |

**边界**：本环节不写台词、不写动作行、不写场次头。剧本归 script。

**执行方式**：主 agent 直接执行。分集是整部剧最贵的一层，关键集（第 1、3、10、中点、最低点、结局）必须让用户确认。

---

## 操作步骤

### Step 0 读输入

- `立项/00-立项稿.md`：五段式、七节点、前 3 集、付费墙、结局。
- `人物库/人物小传.md`：谁能做什么、谁瞒着什么。
- `舞台库/场景库.md`：哪些场景可用、每集能排几场。
- `状态.md`：总集数、单集时长。

缺一项，回上一环节补，不在本环节猜。

### 任务 P：主线结构表

纵轴集数，横轴五项：

| 列 | 写什么 |
|:--|:--|
| 集数段 | 每 3 集为一格；关键节点单独标 |
| 弧线位置 | 铺垫 / 反转 / 翻面（每 3 集一轮） |
| 核心事件 | 这一格发生什么，一句话 |
| 局势变化 | 谁的力量、关系或信息位置变了 |
| 卡点类型 | 揭露 / 反转 / 倒计时 / 闯入 |
| 距结局 | 这一格让观众离结局近哪一步 |

**三条硬规则**：

1. 每 3 集必须完成一次"铺垫 → 反转 → 翻面"。三集走不完，说明冲突不够，回 seed。
2. 不得原地踏步：每格至少一项（力量、关系、信息）发生变化。
3. 关键节点固定：第 3 集主角做出选择；第 10 集付费墙；50% 处中点反转；85% 处最低点；末集结局。

### 任务 A：分集大纲

**每集一行，九列**：

| 列 | 写法 | 判据 |
|:--|:--|:--|
| 集 | EP001 | 三位数 |
| 弧线 | 第几弧·第几拍 | 每 3 集一弧 |
| 核心冲突 | 谁要什么，谁挡着 | 一句话，只有一个冲突 |
| 转折 | 主角做了什么选择 | 必须是主角主动做的 |
| 卡点 | 最后 5 秒发生什么 | 一个画面或一句台词 |
| 卡点类型 | 揭露/反转/倒计时/闯入 | 相邻两集不重复 |
| 下集开头 | 卡点的反应怎么接 | 与上集成对 |
| 情绪 | 本集主情绪，一个词 | 不许写"复杂" |
| 场景/人物 | 本集用哪些场景、哪些人 | 场景 ≤3，有台词人物 ≤5 |

**分集五条纪律**：

1. **一集一冲突**：写出两个冲突，拆成两集或砍一个。
2. **每集有转折**：主角从头被动到尾的集，重写。
3. **每集有卡点**：卡点类型按四型轮换，不允许连续两集同型。
4. **成对**：本集卡点只给事件，反应放下集开头。
5. **不许过渡集**：没有冲突、只交代信息的集，合并进相邻集。

**批量节奏**：

- 第 1-3 集：反常开局 + 连续反转，主角在第 3 集做出选择。
- 第 4-9 集：每次交锋抬高代价，秘密越来越难藏。
- 第 10 集（或 15% 处）：付费墙，用"揭露"，必须是前段最强。
- 中点（50%）：秘密曝光或权力翻面，用"反转"。
- 中点后：后果全面展开，盟友反水，代价落到主角身上。
- 85% 处：最低点，用"倒计时"。
- 末 2-3 集：最终对决、真相揭晓、结局画面。

**长剧分配**（60 集以上）：

- 每 3 集一小弧，每 9-12 集一个中弧，每 30 集一个大段。
- 每个中弧结束要有一次局势翻面，不能只换对手。
- 每 10 集检查一次：主角的目标有没有变、代价有没有加、关系有没有动。

### 任务 B：前 10 集节拍表

前 10 集是平台审核与观众留存的重点，必须逐集拆到秒。

每集四拍（90 秒标准）：

| 时间 | 任务 | 写什么 |
|:--|:--|:--|
| 0-15 秒 | 钩子 | 一个画面或一句台词，直接抛冲突 |
| 15-60 秒 | 升级 | 2-3 次交锋，每次抬高代价 |
| 60-80 秒 | 转折 | 主角做出改变局势的选择 |
| 80-90 秒 | 卡点 | 一个观众答不出的问题 |

60 秒集按比例压：0-10 / 10-40 / 40-53 / 53-60。

**前 10 集额外检查**：

- 第 1 集前 3 秒是否有画面钩子。
- 第 1 集是否在 15 秒内讲清"谁、要什么、谁挡着"。
- 第 3 集主角是否已经主动做出选择。
- 第 10 集卡点是否是全剧前段最强的一次揭露。
- 第 10 集结束时，观众是否有一个非知道不可的答案。

### 任务 C：钩子台账

每集一条，七个字段：

| 字段 | 内容 |
|:--|:--|
| 集 | EP001 |
| 卡点类型 | 揭露/反转/倒计时/闯入 |
| 卡点内容 | 一句话 |
| 埋设 | 这一集埋了什么 |
| 预计回收 | 第几集回答 |
| 实际回收 | 写完再填 |
| 状态 | 开启/推进/回收/搁置 |

**健康度检查**（每 10 集一次）：

- 连续两集同型：改后一集。
- 悬置超过 10 集未推进：本弧内回收，或显式标"搁置"并写理由。
- 预计回收集已过仍未回收：下一集必须表态。
- 回收方式重复：换一种（不能每次都是"某人突然出现"）。

### Step 6 交付检查

- [ ] 每集只有一个核心冲突。
- [ ] 每集都有主角主动做出的转折。
- [ ] 每集都有卡点，且相邻两集不同型。
- [ ] 第 10 集付费墙是前段最强揭露。
- [ ] 中点有一次权力或关系翻面。
- [ ] 85% 处有最低点。
- [ ] 没有过渡集。
- [ ] 每集场景 ≤3，有台词人物 ≤5。
- [ ] 钩子台账字段齐全，无超期未表态。

通过后写 `剧情库/` 四份文件，更新 `状态.md`，交 script。
