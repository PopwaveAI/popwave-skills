# pop-drama-research

> 短剧剧本线资料检索环节。当前版本 v1.0.0（2026-10-19：首版）。
> 本环节只提供材料与结论，不替用户做决定，不写剧本。

---

## 本环节负责什么

| 场景 | 触发 | 查什么 | 产出 |
|:--|:--|:--|:--|
| ① 市场与选题 | 立项前、选题卡住 | 平台在播题材、榜单、集数时长、付费墙惯例 | `调研采风/市场与平台.md` |
| ② 参考剧拆解 | 需要样本、找结构 | 前 3 集卡点、付费墙、中点、场景数、人物数 | `调研采风/参考剧拆解.md` |
| ③ 场景与职业考据 | 写具体行业、地点、文化 | 真实流程、行话、器物、空间、法律与宗教常识 | `调研采风/采风/{主题}.md` |
| ④ 用户点名 | 用户指定查某件事 | 按指定范围 | 对应文件 |

**边界**：不复制参考剧的台词、人名、事件链。只提炼结构与手法。

**执行方式**：主 agent 可派只读子 agent 并行采集，回报原始材料，由主 agent 汇总写文件。

---

## 检索纪律

1. **先内部后外部**：先查 `https://wiki.popwave.cn`，不足再联网。
2. **一轮五个**：单环节最多 1 轮，一轮最多 5 个检索项。
3. **三十 KB**：回传不超过 30KB，超出只留结论。
4. **可回源**：每条结论带来源链接与日期。
5. **分清事实与观点**：平台官方规则标"官方"，报道标"报道"，个人经验标"经验"。
6. **查不到就写没查到**：不猜、不编、不用旧数据顶替。

## 操作步骤

### Step 1 定检索问题

先把"要回答什么"写成 3-5 个具体问题。问题不具体，查回来的是泛泛而谈。

**差**：查一下海外短剧市场。
**好**：2026 年下半年 ReelShort 在播前 20 部里，狼人题材占几部？它们的第 1 集卡点分别是什么类型？

### Step 2 选来源

| 问题类型 | 优先来源 |
|:--|:--|
| 平台规则、分账、审核 | 平台官方帮助中心、官方公告 |
| 题材趋势、榜单 | 平台在播榜、DataEye 等第三方数据报道 |
| 创作方法 | 编剧教程、平台官方教程、行业访谈 |
| 职业与场景 | 从业者访谈、行业手册、纪录片、实地资料 |
| 文化习俗 | 当地公开资料、权威百科、宗教/法律常识 |

来源优先级：官方 > 权威媒体 > 垂直媒体 > 社区讨论（标"非官方"）。

### Step 3 采集与记录

每条材料记六项：

| 项 | 内容 |
|:--|:--|
| 结论 | 一句话，能直接用于判断 |
| 依据 | 原文摘录或数据 |
| 来源 | 链接或文件 |
| 日期 | 发布或访问日期 |
| 性质 | 官方 / 报道 / 经验 / 推测 |
| 可用处 | 立项 / 人物 / 场景 / 卡点 |

### Step 4 交叉验证

- 同一结论至少两个来源，或一个官方来源。
- 只有一个来源的，标"单一来源，待验证"。
- 两个来源冲突时，并列写出，不擅自选一个。

### Step 5 入库

- 市场类写 `调研采风/市场与平台.md`。
- 参考剧写 `调研采风/参考剧拆解.md`。
- 具体考据写 `调研采风/采风/{主题}.md`，用 `templates/采风条目.tpl.md`。
- 不把大段原文粘进项目文件，只留结论与出处。

## 参考剧拆解方法

每部只记八项，不写剧情梗概：

| 项 | 记什么 |
|:--|:--|
| 题材与标签 | 主标签、副标签 |
| 一句话故事 | 谁、要什么、谁挡着 |
| 核心信息差 | 观众知道什么、角色不知道什么 |
| 第 1 集卡点 | 最后 5 秒画面 + 类型 |
| 第 2-3 集卡点 | 类型是否轮换 |
| 付费墙 | 第几集、揭什么、类型 |
| 中点 | 第几集、什么反转 |
| 制作约束 | 主场景数、主要人物数、有无特效 |

**禁止**：抄台词、抄人名、抄事件顺序。需要举例时，用自己的话重写。
