# pop-drama-review

> 短剧剧本包审稿动作。当前版本 v4.0.0（2026-10-19：审稿扩到设定、人物、分集、剧本、分镜、交付）。
> 本模块只判能不能交，不改写。改写回对应模块。

---

## 本模块负责什么

| 任务 | 输入 | 产出 |
|:--|:--|:--|
| 设定审稿 | `03-设定/` 八份 | `06-剧本/审稿/全剧审稿报告.md` 追加设定结论 |
| 人物审稿 | `04-人物/` 五份 | 同上，追加人物结论 |
| 分集审稿 | `05-分集/` 四份 | 同上，追加分集结论 |
| 剧本审稿 | `06-剧本/EP{NNN}.md`、`05-分集/`、`04-人物/`、`03-设定/`、上集剧本 | `06-剧本/审稿/EP{NNN}-审稿.md` |
| 分镜审稿 | `06-剧本/分镜/EP{NNN}.md`、本集剧本 | 同上，追加分镜结论 |
| 交付包审稿 | `00` 至 `07` 全部文件 | `06-剧本/审稿/全剧审稿报告.md` 追加交付结论 |

**边界**：审稿只出结论与改法，不替 script 重写、不替 shotintent 拆镜。发现方向性错误，报 setting、character 或 beats。

**执行方式**：主 agent 直接执行。审稿必须逐集读原文，不能只看自检表。

---

## 审稿顺序（不可跳步）

```
设定 → 人物 → 分集 → 剧本 → 分镜 → 连续性 → 合规 → 交付包
```

设定/人物不过，后面不用审；剧本不过，不拆分镜；最后审交付包完整性。

## 一、设定库检查

| 项 | 判据 |
|:--|:--|
| 故事核 | 一句话 ≤60 字、情感契约、信息差、结局、20 冲突源 |
| 世界与规则 | 时代、地域、社会结构、题材机制、禁忌、时间线 |
| 视觉风格 | 色彩脚本、光线、镜头语言、重复符号、特效边界 |
| 场景库 | 主场景 ≤8、单集 1 主场景、每个场景有空景锚点 |
| 道具与服装 | 关键道具、服装三套、连续性 |
| 声音基调 | 配乐、音效、静默、主题旋律 |
| 合规红线 | 八项边界与处理 |
| 语言风格 | 台词总则、旁白、禁用词、字幕规则 |

**红线**：缺故事核、世界规则、场景库、合规红线任一项，REJECT。

---

## 二、人物库检查

| 项 | 判据 |
|:--|:--|
| 人物总表 | 5-8 个主要人物，功能位齐全 |
| 主要人物 | 每人十二项齐全 |
| 配角与功能位 | 配角不抢主线，一次性角色不重复功能 |
| 关系图 | 每对重要关系有“既需要又对抗”的点，至少一次变化 |
| 选角与视觉锚点 | 每人七项视觉锚点 + 禁用项 |
| 单集角色 | 主要角色 ≤3，有台词人物 ≤5 |
| 语言辨识 | 遮名字能认出说话人 |
| 视觉一致性 | B 组能生成同一个人两张图 |

**红线**：缺人物库、主要人物无视觉锚点、单集主要角色超过 3 个，REJECT。

---

## 三、分集检查

| 项 | 判据 |
|:--|:--|
| 分集卡点表 | 每集一冲突一转折一卡点，卡点类型轮换 |
| 前 10 集节拍 | 逐集四拍齐全 |
| 钩子台账 | 无超期未回收，无连续同型 |
| 预算表 | 每集 12-13 镜、台词 70-80 字、1 场景、3 角色 |
| 关键节点 | 付费墙、中点、最低点、结局位置正确 |

**红线**：连续两集卡点同型、没有付费墙、预算超限未处理，REJECT。

---

## 四、剧本检查

### 格式

| 项 | 判据 |
|:--|:--|
| 剧本文件名 | `06-剧本/EP{NNN}.md` |
| 场次头 | 集号-场号 地点 时间 内/外 |
| 动作行 | 全部以 △ 开头 |
| 台词 | 角色（状态）：台词 |
| 首次出场 | 有字幕介绍 |
| 卡点 | 有 `【卡点】` 标记 |

格式不合格超过 3 处，直接 REJECT。

### 卡点

| 项 | 判据 |
|:--|:--|
| 是一个问题 | 观众无法从本集内容回答 |
| 类型明确 | 揭露/反转/倒计时/闯入 |
| 不与上集同型 | 对照钩子台账 |
| 与下集开头成对 | 下集开头接反应 |
| 不是情绪收尾 | 最后不是“她哭了” |
| 不是结论 | 最后不是“她终于安全了” |

**红线**：连续两集同型，或本集没有卡点，REJECT。

### 开头与转折

| 项 | 判据 |
|:--|:--|
| 前 3 秒 | 有画面钩子 |
| 前 15 秒 | 讲清谁、要什么、谁挡着 |
| 无前情提要 | 不靠旁白补前集 |
| 有转折 | 局势发生一次变化 |
| 主角主动 | 转折由主角选择造成 |
| 位置 | 55%-80% 区间 |
| 有代价 | 主角付出代价 |

**红线**：主角全程被动，或转折由配角替主角完成，REJECT。

### 台词与可拍性

| 项 | 判据 |
|:--|:--|
| 单句长度 | ≤12 字 |
| 本集总量 | 70-80 字 |
| 口语 | 念一遍顺口 |
| 无解释 | 不出现“其实我是因为……” |
| 有辨识度 | 遮住名字能认出人 |
| 无 AI 腔 | 无“值得注意的是/总之/由此可见” |
| 场景数 | 1 个（最多 2 个） |
| 主要角色 | 3 个（最多 4 个） |
| 无心理/抽象 | 无“她心里一沉”“气氛尴尬” |
| 禁止动作 | 无奔跑/打斗/快速转身/多人互动/crowd/儿童/动物/大范围水火 |

**红线**：出现心理描写、抽象判断、无法拍摄的概述，REJECT。

---

## 五、分镜检查

逐集看 `06-剧本/分镜/`：

| 项 | 判据 |
|:--|:--|
| 镜头数 | 12-13（10-14 可接受） |
| 总时长 | 75-80 秒 |
| 单镜时长 | 3-8 秒 |
| 一镜一动作 | 每镜只有一个动作 |
| 每镜有变化 | 新信息/权力/情绪/威胁 |
| 首镜钩子 | 有 |
| 末镜卡点 | 有 |
| 台词 | 单句 ≤12 字，总量 70-80 字 |
| 场景/角色 | 1 场景 / 3 主要角色 |
| 风险 fallback | A/B 级都有 |
| 交接摘要 | 六项齐全 |

**红线**：

- 没有分镜，或镜头数超过 15/少于 10。
- 一镜两个动作。
- A 级风险无 fallback。
- 分镜与剧本事件对不上。

---

## 六、连续性检查

| 项 | 判据 |
|:--|:--|
| 人物称呼 | 与人物库一致 |
| 性格 | 与人物卡一致 |
| 语言 | 与语言指纹一致 |
| 时间线 | 与上集接得上 |
| 伤势/道具 | 与上集结尾一致 |
| 信息边界 | 人物只知道他该知道的事 |
| 钩子 | 台账已更新，无超期未表态 |
| 角色/场景 ID | 全剧一致 |

**红线**：人物知道了他不该知道的信息，或关键道具凭空出现，REJECT。

---

## 七、合规检查

| 项 | 判据 |
|:--|:--|
| 暴力 | 不过度展示血腥细节 |
| 血腥 | 无 gore、断肢、内脏、喷血特写 |
| 性暗示 | 不写露骨内容 |
| 未成年人 | 不涉及性化、虐待细节 |
| 敏感身份 | 不歧视地域、职业、疾病、族群 |
| 真实人物 | 不影射可识别的真实个人 |
| 迷信导向 | 灵异/民俗最终落到人为或现实解释 |
| 平台规则 | 与目标平台公开规则不冲突 |

合规问题不评分，命中即改。

---

## 八、交付包检查

| 项 | 判据 |
|:--|:--|
| 00 创作总表 | 项目信息、当前焦点、模块就绪、关键决定 |
| 01 市场定位 | 平台、受众、题材、生产模式、集数、时长、卖点、标题 |
| 02 对标拆解 | 3-5 部九项（可标未做） |
| 03 设定 | 八份齐全 |
| 04 人物 | 五份齐全 |
| 05 分集 | 四份齐全 |
| 06 剧本 | 每集 + 合订本 + 台词统计 |
| 06 分镜 | 每集 + 全剧分镜表 |
| 06 审稿 | 每集 + 全剧报告 |
| 07 交付 | 五份齐全 |
| 交接 | B 组不看聊天记录即可开工 |

**红线**：缺任何一类文件，或全剧审稿结论不是“可交付”，REJECT。

## 九、评分与结论

满分 100：

| 维度 | 分值 |
|:--|--:|
| 设定 | 10 |
| 人物 | 10 |
| 分集 | 10 |
| 卡点 | 15 |
| 开头与转折 | 10 |
| 台词与可拍性 | 10 |
| 分镜 | 20 |
| 连续性与合规 | 10 |
| 格式 | 5 |

**结论规则**：

- 80 分以上且无红线：PASS。
- 60-79 分：CONDITIONAL，列必改项，改完复审。
- 60 分以下或命中任一红线：REJECT。

**红线十条**：

1. 缺设定库、人物库、分集、剧本、分镜任一类。
2. 没有卡点，或连续两集同型。
3. 出现小说式心理描写或无法拍摄的概述。
4. 人物知道了他不该知道的信息，或关键道具凭空出现。
5. 没有分镜，或镜头数超过 15/少于 10。
6. 一镜两个动作，或 A 级风险无 fallback。
7. 一集超过 1 个主场景（AI 模式）或超过 3 个主要角色。
8. 主要人物无视觉锚点，B 组无法锁角色。
9. 交付包缺文件。
10. 全剧审稿结论不是“可交付”。

## 报告写法

每集一份 `06-剧本/审稿/EP{NNN}-审稿.md`，用 `templates/审稿报告.tpl.md`。问题逐条写四样：

- 位置：第几场、哪一句、哪一镜。
- 问题：原文摘录。
- 判据：违反哪条。
- 改法：具体怎么改，给一句示例。

不只写“节奏不好”“台词生硬”。

---

## 整剧审稿

全剧写完后做一次，追加检查：

- [ ] 设定库八份齐全，无矛盾。
- [ ] 人物库五份齐全，视觉锚点一致。
- [ ] 分集四份齐全，关键节点兑现。
- [ ] 每 3 集一个完整弧线，弧末有翻面。
- [ ] 付费墙集是全剧前段最强揭露。
- [ ] 中点有一次权力或关系翻面。
- [ ] 85% 处有最低点。
- [ ] 卡点四型都有出现，无连续同型。
- [ ] 钩子台账无超期未回收。
- [ ] 人物弧光从起点走到终点。
- [ ] 主场景未超出场景库。
- [ ] 结局回答了核心信息差。
- [ ] 每集分镜齐全、镜头数合规。
- [ ] 交付包五份文件齐全。
