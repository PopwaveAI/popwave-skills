# pop-drama-review

> 短剧剧本包审稿模块。当前版本 v3.0.0（2026-10-19：整体重构——审剧本、审镜头意图、审交付包）。
> 本模块只判能不能交，不改写。改写回对应模块。

---

## 本模块负责什么

| 任务 | 输入 | 产出 |
|:--|:--|:--|
| 剧本审稿 | `05-剧本/EP{NNN}.md`、`04-分集卡点表.md`、人物卡、场景与视觉、上集剧本 | `07-审稿/EP{NNN}-审稿.md` |
| 镜头意图审稿 | `06-镜头意图表/EP{NNN}.md`、本集剧本 | 同上，追加镜头意图结论 |
| 交付包审稿 | `00` 至 `08` 全部文件 | `07-审稿/全剧审稿报告.md` 追加交付结论 |

**边界**：审稿只出结论与改法，不替 script 重写、不替 shotintent 拆镜。发现方向性错误，报 beats 或 story。

**执行方式**：主 agent 直接执行。审稿必须逐集读原文，不能只看自检表。

---

## 审稿顺序（不可跳步）

```
格式 → 剧本 → 镜头意图 → 连续性 → 合规 → 交付包
```

先看格式与剧本，剧本过了才审镜头意图；最后审交付包完整性。

## 一、格式检查

| 项 | 判据 | 不合格处理 |
|:--|:--|:--|
| 剧本文件名 | `EP{NNN}.md` | 改名 |
| 镜头意图文件名 | `EP{NNN}.md` | 改名 |
| 场次头 | `集号-场号 地点 时间 内/外` | 补全 |
| 人物行 | 本场相关人物，不用"众人" | 补全 |
| 动作行 | 全部以 △ 开头 | 改格式 |
| 台词 | `角色（状态）：台词` | 改格式 |
| 首次出场 | 有字幕介绍 | 补字幕 |
| 卡点 | 有 `【卡点】` 标记 | 补标记 |
| 镜头表 | 12 字段齐全 | 补全 |

格式不合格超过 3 处，直接 REJECT。

---

## 二、剧本检查

### 卡点（最重）

逐集看最后 5 秒：

| 项 | 判据 |
|:--|:--|
| 是一个问题 | 观众无法从本集内容回答 |
| 类型明确 | 揭露/反转/倒计时/闯入 |
| 不与上集同型 | 对照钩子台账 |
| 与下集开头成对 | 下集开头接反应，不换场景 |
| 不是情绪收尾 | 最后不是"她哭了""他笑了" |
| 不是结论 | 最后不是"她终于安全了" |

**红线**：连续两集同型，或本集没有卡点，REJECT。

### 开头

| 项 | 判据 |
|:--|:--|
| 前 3 秒 | 有画面钩子，不靠台词开场 |
| 前 15 秒 | 讲清谁、要什么、谁挡着 |
| 无前情提要 | 不靠字幕或旁白补上一集 |
| 第 1 集 | 反常开局，不是日常起床 |

### 转折

| 项 | 判据 |
|:--|:--|
| 有转折 | 本集局势发生一次变化 |
| 主角主动 | 转折由主角的选择造成 |
| 位置 | 55%-80% 区间 |
| 有代价 | 主角付出代价，不是白赚 |

**红线**：主角全程被动，或转折由配角替主角完成，REJECT。

### 台词

| 项 | 判据 |
|:--|:--|
| 单句长度 | ≤12 字 |
| 本集总量 | 70-80 字 |
| 口语 | 念一遍顺口，无书面腔 |
| 无解释 | 不出现"其实我是因为……" |
| 有辨识度 | 遮住名字能认出说话人 |
| 无 AI 腔 | 不出现"值得注意的是/总之/由此可见" |

### 可拍性

| 项 | 判据 |
|:--|:--|
| 场景数 | 1 个（最多 2 个） |
| 主要角色 | 3 个（最多 4 个） |
| 动作可拍 | 无心理、无抽象判断、无"众人震惊" |
| 构图 | 不同时并排站 3 人以上 |
| 道具 | 关键道具在本集前后一致 |
| 禁止动作 | 无奔跑/打斗/快速转身/多人互动/crowd/儿童正脸/动物特写/大范围水火 |

**红线**：出现心理描写、抽象判断、无法拍摄的概述，REJECT。

---

## 三、镜头意图检查

逐集看 `06-镜头意图表`：

| 项 | 判据 |
|:--|:--|
| 镜头数 | 12-13（10-14 可接受） |
| 总时长 | 75-80 秒 |
| 单镜时长 | 3-8 秒 |
| 一镜一动作 | 每镜只有一个动作 |
| 每镜有变化 | 新信息/权力/情绪/威胁至少一个 |
| 首镜 | 是钩子 |
| 末镜 | 是卡点 |
| 台词 | 单句 ≤12 字，总量 70-80 字 |
| 场景 | 1 个（最多 2 个） |
| 主要角色 | 3 个（最多 4 个） |
| 风险 | A/B 级风险有 fallback |
| 交接摘要 | 镜头数、时长、角色/场景 ID、风险镜、最稳三镜、删了会断的一镜 |

**红线**：

- 没有镜头意图表。
- 镜头数超过 15 或少于 10。
- 一镜两个动作。
- 有 A 级风险但没有 fallback。
- 镜头意图与剧本事件对不上。

---

## 四、连续性检查

| 项 | 判据 |
|:--|:--|
| 人物称呼 | 与人物卡一致，无改名 |
| 性格 | 行为与人物卡一致 |
| 语言 | 与本集之前一致 |
| 时间线 | 与上集接得上 |
| 伤势/道具 | 与上集结尾一致 |
| 信息边界 | 人物只知道他该知道的事 |
| 钩子 | 钩子台账已更新，无超期未表态 |
| 角色/场景 ID | 全剧一致，没有一号多人 |

**红线**：人物知道了他不该知道的信息，或关键道具凭空出现，REJECT。

---

## 五、合规检查

| 项 | 判据 |
|:--|:--|
| 暴力 | 不过度展示血腥细节 |
| 血腥 | 无 gore、断肢、内脏、喷血特写 |
| 性暗示 | 不写露骨内容 |
| 未成年人 | 不涉及性化、虐待细节 |
| 敏感身份 | 不歧视地域、职业、疾病、族群 |
| 真实人物 | 不影射可识别的真实个人 |
| 迷信导向 | 灵异/民俗最终落到人为或现实解释 |
| 平台规则 | 与目标平台公开规则不冲突 |

合规问题不评分，命中即改。

---

## 六、交付包检查

| 项 | 判据 |
|:--|:--|
| 00 创作总表 | 项目信息、关键决定、文件索引齐全 |
| 01 市场定位 | 平台、受众、题材、生产模式、集数、时长、卖点、标题 |
| 02 对标拆解 | 3-5 部、八项、可生成性判断（可标未做） |
| 03 三份 | 故事核、人物卡、场景与视觉齐全 |
| 04 分集卡点 | 逐集冲突/转折/卡点/镜头预算齐全 |
| 05 剧本 | 每集 + 全剧合订本 |
| 06 镜头意图 | 每集 + 全剧总表 |
| 07 审稿 | 每集 + 全剧报告 |
| 08 交付 | 五份文件齐全 |
| 交接 | B 组不看聊天记录即可开工 |

**红线**：缺任何一类文件，或全剧审稿结论不是"可交付"，REJECT。

## 评分与结论

满分 100：

| 维度 | 分值 |
|:--|--:|
| 卡点 | 20 |
| 开头 | 10 |
| 转折 | 10 |
| 台词 | 10 |
| 可拍性 | 10 |
| 镜头意图 | 25 |
| 连续性 | 10 |
| 格式 | 5 |

**结论规则**：

- 80 分以上且无红线：PASS。
- 60-79 分：CONDITIONAL，列必改项，改完复审。
- 60 分以下或命中任一红线：REJECT。

**红线八条**：

1. 没有卡点，或连续两集同型。
2. 出现小说式心理描写或无法拍摄的概述。
3. 人物知道了他不该知道的信息，或关键道具凭空出现。
4. 没有镜头意图表，或镜头数超过 15/少于 10。
5. 一镜两个动作，或 A 级风险无 fallback。
6. 一集超过 1 个主场景（AI 模式）或超过 3 个主要角色。
7. 交付包缺文件。
8. 全剧审稿结论不是"可交付"。

## 报告写法

每集一份 `07-审稿/EP{NNN}-审稿.md`，用 `templates/审稿报告.tpl.md`。问题逐条写四样：

- 位置：第几场、哪一句、哪一镜。
- 问题：原文摘录。
- 判据：违反哪条。
- 改法：具体怎么改，给一句示例。

不只写"节奏不好""台词生硬"。

---

## 整剧审稿

全剧写完后做一次，追加检查：

- [ ] 每 3 集一个完整弧线，弧末有翻面。
- [ ] 付费墙集是全剧前段最强揭露。
- [ ] 中点有一次权力或关系翻面。
- [ ] 85% 处有最低点。
- [ ] 卡点四型都有出现，无连续同型。
- [ ] 钩子台账无超期未回收。
- [ ] 人物弧光从起点走到终点。
- [ ] 主场景未超出场景卡。
- [ ] 结局回答了核心信息差。
- [ ] 全剧没有重复的冲突解法。
- [ ] 每集镜头意图齐全、镜头数合规。
- [ ] 交付包五份文件齐全。
