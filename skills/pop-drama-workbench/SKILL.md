# pop-drama-workbench

> 短剧创作工作台。当前版本 v2.0.0（2026-10-19：按短剧工作流重排，去掉小说管线的阶段状态机）。
> 本技能不是流程机器，只做三件事：建项目、维护创作总表、把用户的话路由到对应模块。

---

## 这套 skill 怎么组织

短剧的实际做法不是"立项→舞台→卷纲→章纲"那条长跑，而是围绕**卖点、对标、人物关系、分集卡点、剧本**来回改。

所以这套 skill 是模块化的，不强制顺序：

| 模块 | skill | 什么时候用 | 产出 |
|:--|:--|:--|:--|
| 市场定位 | `pop-drama-market` | 只有想法，要定平台、题材、集数、卖点 | `01-市场定位.md` |
| 对标拆解 | `pop-drama-decon` | 有参考剧，要拆结构、找可复用招式 | `02-对标拆解.md` |
| 故事核与人物 | `pop-drama-story` | 卖点有了，要做成能撑几十集的故事与人物 | `03-故事核.md`、`03-人物关系与人物卡.md`、`03-场景与视觉.md` |
| 分集卡点 | `pop-drama-beats` | 故事定了，要排每集冲突、反转、卡点 | `04-分集卡点表.md` |
| 剧本 | `pop-drama-script` | 有分集表，要写单集剧本 | `05-剧本/EP{NNN}.md` |
| 审稿 | `pop-drama-review` | 剧本写完，要独立审 | `06-审稿/EP{NNN}-审稿.md` |
| 资料检索 | `pop-drama-research` | 任何模块缺资料 | `资料/` |

**模块可以单独用**：用户只拿来一部对标剧，就只跑 decon；用户已有剧本，就直接跑 review。不要求从 market 开始，也不要求把六份文件都做完。

**唯一的顺序约束来自依赖，不来自流程**：

- 写分集卡点前，至少要有故事核和主要人物。
- 写剧本前，至少要有本集的分集卡点。
- 审稿前，至少要有剧本。

其余顺序由用户决定。

## 本技能负责什么

| 职责 | 说明 |
|:--|:--|
| 建项目 | 建目录，写 `00-创作总表.md` |
| 导入已有项目 | 扫文件、归位、登记到创作总表 |
| 维护创作总表 | 记录关键决定、文件索引、当前进度；不记录阶段编号 |
| 路由 | 按用户说法直接选 skill |
| 交付检查 | 每个模块交付前，按本文件检查项过一遍 |

**边界**：本技能不写内容、不做格式转换、不常驻。范围到剧本与审稿，不含分镜、拍摄、配音、成片。

**执行方式**：主 agent 直接执行。纯只读的资料检索可派子 agent，由主 agent 汇总。

- 一集一个剧本文件，三位数编号。
- 审稿与剧本一一对应。
- 文件名固定，不按项目另起名字；换项目只换目录。

## 操作步骤

### Step 0 判断入口

先看用户这句话属于哪一类，直接路由：

| 用户说 | 加载 |
|:--|:--|
| "选题/平台/题材/卖点/多少集" | `pop-drama-market` |
| "拆对标/拉片/参考剧/看看别人怎么拍" | `pop-drama-decon` |
| "故事核/一句话/人物/关系/结局" | `pop-drama-story` |
| "分集/卡点/付费墙/前10集/每集写什么" | `pop-drama-beats` |
| "写剧本/写第N集/下一集" | `pop-drama-script` |
| "审/改/打分/看看哪里不行" | `pop-drama-review` |
| "查资料/市场数据/职业细节" | `pop-drama-research` |
| "新建短剧项目" | 走 Step 1 |
| "导入/续写/已有剧本" | 走 Step 2 |

用户一句话里混了两件事，先做依赖更靠前的那件，或问用户先做哪件。不擅自替用户排整条流程。

### Step 1 新建项目

1. 建目录：`05-剧本/`、`06-审稿/`、`资料/`。
2. 写 `00-创作总表.md`，项目信息按用户已说的填，未说的留空。
3. 问三项就够，不一次问十项：
   - 海外还是国内，哪个平台。
   - 总集数与单集时长。
   - 现在手上有什么：只有想法、有对标剧、有故事、还是有剧本。
4. 按第 3 项直接路由到对应模块。

**不输出"完整流程说明"**。用户没问流程，就不要讲六个阶段。

### Step 2 导入已有项目

**2a 扫文件**：列出每个文件的文件名、位置、一句话内容。

**2b 归位**：

| 文件内容 | 归到 |
|:--|:--|
| 市场、平台、题材、集数 | `01-市场定位.md` |
| 对标、拉片、参考剧 | `02-对标拆解.md` |
| 一句话、情感契约、信息差、结局 | `03-故事核.md` |
| 人物、人设、关系 | `03-人物关系与人物卡.md` |
| 场景、美术、视觉 | `03-场景与视觉.md` |
| 分集、卡点、付费墙 | `04-分集卡点表.md` |
| 单集剧本 | `05-剧本/EP{NNN}.md` |
| 审稿意见 | `06-审稿/EP{NNN}-审稿.md` |
| 资料、考据 | `资料/{主题}.md` |

匹配不上的列"未分类"，问用户。`.docx` 先读内容再写 md。归位前问是否保留原文件。

**2c 重建总表**：按 Step 1 模板写 `00-创作总表.md`，文件索引按实际状态填。

**2d 缺口提示**：只提示与用户当前目标相关的缺口。用户要写第 5 集，就只查第 5 集的分集卡点、人物、场景；不要求补齐市场定位。

### Step 3 维护创作总表

每个模块完成后，只改涉及的行：

- 文件索引的状态与更新时间。
- 关键决定（一句话、情感契约、信息差、结局、付费墙）。
- 当前进度与最近改动。

**不做全量重写**，不把模块内容抄进总表。

## 交付检查

每个模块交付前，按对应检查项过一遍。检查项在各 skill 的 SKILL.md 里，本文件只列总口径：

| 模块 | 最低交付标准 |
|:--|:--|
| 市场定位 | 平台、受众、题材、集数、时长、卖点、标题候选三项齐全 |
| 对标拆解 | 3-5 部，每部八项，横向对比与可复用招式齐全 |
| 故事核 | 一句话 ≤60 字、情感契约一句、信息差一句、结局一个画面、20 个冲突源 |
| 人物 | 5-8 个主要人物，每人有功能位、欲望、阻碍、语言指纹 |
| 场景与视觉 | 主场景 ≤8，每个有不可替代用途；视觉规则五条 |
| 分集卡点 | 每集一冲突一转折一卡点，相邻不同型，付费墙与前10集节拍齐全 |
| 剧本 | 格式统一，每集有钩子、转折、卡点，无小说式心理描写 |
| 审稿 | 逐集 PASS/REJECT，问题带位置、原文、判据、改法 |

**红线四条**（任一命中即不合格）：

1. 一集没有卡点，或连续两集同型。
2. 剧本出现小说式心理描写或无法拍摄的概述。
3. 一集场景 >3 或有台词人物 >5。
4. 人物知道了他不该知道的信息，或关键道具凭空出现。

## 创作总表与模块的边界

- 总表只记"决定"和"文件在哪"，不存人物卡、场景卡、分集表的正文。
- 模块文件才是内容源。总表与模块冲突时，以模块文件为准，回头改总表。
- 用户口头改了决定，先改对应模块，再改总表；不许只改总表。
