# pop-drama-workbench

> 短剧剧本包工作台。当前版本 v4.0.0（2026-10-19：按“创作对象”重排，不再按生产工序排）。
> 本技能只做四件事：建项目、维护创作总表、按创作对象路由、检查交付完整性。

---

## 一级导航（只放创作对象）

| Tab | 对应目录 | 定位 |
|:--|:--|:--|
| 概览 | `00-创作总表.md` | 项目状态、当前焦点、下一步、风险 |
| 设定 | `03-设定/` | 故事核、世界规则、视觉风格、场景库、道具服装、声音、合规、语言 |
| 人物 | `04-人物/` | 人物库：主配角、关系图、选角、视觉锚点、语言指纹 |
| 分集 | `05-分集/` | 全剧网格、前 10 集节拍、钩子台账、预算 |
| 剧本 | `06-剧本/` | 分集正文、分镜、台词统计、审稿 |
| 交付 | `07-交付/` | 交付检查、剧本包、卖点、人物小传、合规、导出 |

**市场定位与对标拆解不占一级**：它们是项目背景，放在 `01`、`02`，从「概览 > 项目背景」进入。

**审稿不是一级**：它是剧本与交付里的动作，记录在 `06-剧本/审稿/`。

**分镜不是一级**：它是剧本的子页，放在 `06-剧本/分镜/`。

---

## A 组交付什么

A 组交付的不是一份剧本，是**一个能让 B 组直接开工的剧本包**。

三层：

| 层 | 回答什么 | 主要文件 |
|:--|:--|:--|
| 创作底子 | 为什么做、世界是什么、人物是谁 | 01、02、03 设定库、04 人物库 |
| 剧集蓝图 | 每集发生什么 | 05 分集 |
| 最终成品 | 台词说什么、每镜看到什么 | 06 剧本（含分镜） |
| 交付验收 | 能不能交、交给谁、怎么用 | 07 交付 |

**边界**：A 组不写首帧 prompt、不写运动指令、不做抽卡、不做剪辑。那些归 B 组。

## 路由表

| 用户说 | 直接进 | 开工前检查 |
|:--|:--|:--|
| 选题 / 平台 / 题材 / 卖点 / 多少集 | market | 无 |
| 拆对标 / 拉片 / 参考剧 | decon | 无 |
| 故事核 / 世界 / 规则 / 视觉 / 场景 / 道具 / 声音 / 合规 / 语言风格 | setting | 市场定位（至少三项） |
| 人物 / 人设 / 关系 / 选角 / 视觉锚点 | character | 故事核 |
| 分集 / 卡点 / 付费墙 / 前 10 集 | beats | 设定库、人物库 |
| 写剧本 / 写第 N 集 / 全剧合订 | script | 本集分集卡点、人物、场景 |
| 拆镜头 / 分镜 / 镜头意图 / 交给 AI 做 | shotintent（从剧本进） | 本集剧本已 PASS |
| 审剧本 / 审分镜 / 打分 | review | 剧本或分镜 |
| 打包 / 交付 / 给甲方或制作 | delivery | 00-06 全部就绪 |
| 查资料 | research | 无 |
| 新建 / 导入 / 续写 | 本工作台 | 见 Step 1 / Step 2 |

**日常路由不经过本技能**：用户说“写第 5 集”，主 agent 读 `00-创作总表.md`，直接加载 `pop-drama-script`。只有建项目、导入、状态重建、交付检查时才进工作台。

## 依赖检查

| 目标 | 最低前置 | 缺了怎么办 |
|:--|:--|:--|
| 建设定库 | 市场定位、故事核 | 补 market；或按用户口述建临时档，标待回填 |
| 建人物库 | 故事核 | 补 setting；或先立 3 个主要人物，标待补 |
| 排分集 | 设定库、人物库 | 补 setting/character；或降级排，记录欠账 |
| 写剧本 | 本集分集卡点、人物卡、场景库 | 补 beats/setting/character；或降级写，记录欠账 |
| 拆分镜 | 本集剧本已 PASS | 先审剧本；或降级拆，记录风险 |
| 审稿 | 剧本或分镜 | 先写 |
| 打包交付 | 00-06 全部、全剧审稿通过 | 补缺；缺一项不交付 |

**依赖检查不是阶段闸**：只回答“现在做这件事，手上够不够”。

## 降级模式

用户坚持跳步时，允许，但必须记录：

- 在 `00-创作总表.md` 的「降级记录」写：跳了什么、欠什么、预计什么时候补。
- 在对应文件里标 `降级:无人物库` / `降级:无分镜` / `降级:无合规`。
- 下一次进入相关模块时优先补欠账。

**禁止静默降级**。

## 操作步骤

### Step 0 判断入口

先看用户这句话属于哪个创作对象，直接路由。一句话里混了两件事，先做依赖更靠前的那件，或问先做哪件。

### Step 1 新建项目

1. 建目录：`03-设定/`、`04-人物/`、`05-分集/`、`06-剧本/分镜/`、`06-剧本/审稿/`、`07-交付/`、`资料/`。
2. 写 `00-创作总表.md`，项目信息按用户已说的填，未说的留空。
3. 问四项就够：
   - 海外还是国内，哪个平台。
   - AI 生成还是真人拍摄。
   - 总集数与单集时长。
   - 现在手上有什么：想法 / 对标 / 设定 / 人物 / 分集 / 剧本。
4. 按第 4 项直接路由到对应模块。

**不输出完整流程说明**。用户没问流程，就不要讲十个模块。

### Step 2 导入已有项目

**2a 扫文件**：列出文件名、位置、一句话内容。

**2b 归位**：

| 文件内容 | 归到 |
|:--|:--|
| 市场、平台、题材、集数、生产模式 | `01-市场定位.md` |
| 对标、拉片、参考剧 | `02-对标拆解.md` |
| 故事核、一句话、情感契约、信息差、结局 | `03-设定/故事核.md` |
| 世界、规则、题材机制、禁忌 | `03-设定/世界与规则.md` |
| 视觉、色彩、光线、镜头语言 | `03-设定/视觉风格.md` |
| 场景、美术、空间、空景 | `03-设定/场景库.md` |
| 道具、服装、造型 | `03-设定/道具与服装.md` |
| 音乐、音效、声音基调 | `03-设定/声音基调.md` |
| 合规、平台禁忌 | `03-设定/合规红线.md` |
| 台词规则、旁白规则、语言风格 | `03-设定/语言风格.md` |
| 人物、人设、关系、选角、视觉锚点 | `04-人物/` 对应文件 |
| 分集、卡点、付费墙、镜头预算 | `05-分集/` 对应文件 |
| 单集剧本 | `06-剧本/EP{NNN}.md` |
| 全剧剧本 | `06-剧本/全剧剧本.md` |
| 镜头、分镜、镜头意图 | `06-剧本/分镜/EP{NNN}.md` |
| 审稿、意见、打分 | `06-剧本/审稿/EP{NNN}-审稿.md` |
| 交付说明、卖点、人物合集、合规 | `07-交付/` 对应文件 |
| 资料、考据 | `资料/{主题}.md` |

旧项目迁移：

- `03-故事核.md`、`03-人物关系与人物卡.md`、`03-场景与视觉.md` → 拆进 `03-设定/` 与 `04-人物/`。
- `04-分集卡点表.md` → `05-分集/分集卡点表.md`。
- `05-剧本/` → `06-剧本/`。
- `06-镜头意图表/` → `06-剧本/分镜/`。
- `07-审稿/` → `06-剧本/审稿/`。
- `08-交付/` → `07-交付/`。

匹配不上的列“未分类”，问用户。`.docx` 先读再写 md。

**2c 重建总表**：按模板写 `00-创作总表.md`，模块就绪按实际状态填。

**2d 缺口提示**：只提示与用户当前目标相关的缺口。用户要写第 5 集，就只查第 5 集的分集卡点、人物、场景。

### Step 3 维护创作总表

每个模块完成后，只改涉及的行：模块就绪、当前焦点、风险、降级记录、最近改动。不做全量重写。

## 交付标准

A 组交付前逐项检查，缺一项不交付：

| Tab | 完成标准 |
|:--|:--|
| 概览 | 项目信息、当前焦点、模块就绪、关键决定、风险齐全 |
| 项目背景 | 市场定位八项；对标拆解 3-5 部九项（可标未做） |
| 设定 | 八份齐全：故事核、世界与规则、视觉风格、场景库、道具与服装、声音基调、合规红线、语言风格 |
| 人物 | 五份齐全：总表、主要人物、配角、关系图、选角与视觉锚点 |
| 分集 | 四份齐全：分集卡点表、前 10 集节拍、钩子台账、预算表 |
| 剧本 | 每集正文 + 全剧合订本 + 台词统计 |
| 分镜 | 每集 12-13 镜、一镜一动作、风险 fallback、全剧分镜表 |
| 审稿 | 逐集 PASS/CONDITIONAL、全剧审稿报告结论可交付 |
| 交付 | 五份齐全、B 组不用追问即可开工 |

**红线六条**：

1. 没有分镜，或镜头数超过 15/少于 10。
2. 一集超过 1 个主场景（AI 模式）或超过 3 个主要角色。
3. 剧本出现小说式心理描写或无法拍摄的概述。
4. 人物知道了他不该知道的信息，或关键道具凭空出现。
5. 设定库缺故事核、世界规则、场景库、合规红线任一项。
6. 交付包缺文件，或缺全剧审稿结论。

## A→B 交接契约

A 组交 `06-剧本/分镜/`，B 组据此写 prompt。A 组只写“观众看到什么”，不写“模型怎么生成”。

| 字段 | A 组填 | B 组补 |
|:--|:--|:--|
| 镜号/时长 | 节拍与秒数 | 实际生成时长 |
| 画面 | 一个动作 | 首帧 prompt、构图 |
| 台词 | ≤12 字 | 音色、语速、配音 |
| 情绪 | 本镜情绪 | 光线、表演、音效 |
| 参考 | 角色/场景 ID | 参考图、模型参数 |
| 风险 | 生成难点与 fallback | 抽卡方案 |
