# pop-drama-workbench

> 短剧剧本包生产线工作台。当前版本 v3.0.0（2026-10-19：整体重构——从"写剧本"升级为"交付可开工的剧本包"）。
> 本技能不是流程机器，只做四件事：建项目、维护创作总表、按当前任务路由、检查交付完整性。

---

## A 组交付什么

A 组交付的不是一份剧本，是**一个能让 B 组直接开工的剧本包**。

三层结构：

| 层 | 回答什么 | 主要文件 |
|:--|:--|:--|
| 决策层 | 为什么做、故事是什么、人物是谁 | 01 市场定位、02 对标拆解、03 故事核、03 人物卡、03 场景与视觉 |
| 剧本层 | 每集发生什么、台词说什么、每镜让观众看到什么 | 04 分集卡点表、05 剧本、06 镜头意图表 |
| 交付层 | 能不能交、交给谁、怎么用 | 07 审稿、08 交付包 |

**边界**：A 组不写首帧 prompt、不写运动指令、不做抽卡、不做剪辑。那些归 B 组（AI 短剧工业线）。

## 路由表

| 用户说 | 直接进 | 开工前检查 |
|:--|:--|:--|
| 选题 / 平台 / 题材 / 卖点 / 多少集 | `pop-drama-market` | 无 |
| 拆对标 / 拉片 / 参考剧 | `pop-drama-decon` | 无 |
| 故事核 / 一句话 / 人物 / 关系 / 结局 / 场景 | `pop-drama-story` | 市场定位（至少三项） |
| 分集 / 卡点 / 付费墙 / 前 10 集 | `pop-drama-beats` | 故事核、人物卡 |
| 写剧本 / 写第 N 集 | `pop-drama-script` | 本集分集卡点、人物卡、场景 |
| 拆镜头 / 镜头意图 / 交给 AI 做 | `pop-drama-shotintent` | 本集剧本已 PASS |
| 审剧本 / 审镜头 / 打分 | `pop-drama-review` | 剧本或镜头意图 |
| 打包 / 交付 / 给甲方或制作 | `pop-drama-delivery` | 00-07 全部就绪 |
| 查资料 | `pop-drama-research` | 无 |
| 新建 / 导入 / 续写 | 本工作台 | 见 Step 0 / Step 1 |

**日常路由不经过本技能**：用户说"写第 5 集"，主 agent 读 `00-创作总表.md`，直接加载 `pop-drama-script`。只有建项目、导入、状态重建、交付检查时才进工作台。

## 依赖检查

| 目标 | 最低前置 | 缺了怎么办 |
|:--|:--|:--|
| 写剧本 | 本集分集卡点、人物卡、场景 | 补 beats 或 story；或降级写，记录欠账 |
| 拆镜头意图 | 本集剧本已通过审稿 | 先审剧本；或降级拆，记录风险 |
| 审剧本 | 剧本 | 先写剧本 |
| 审镜头意图 | 镜头意图表、剧本 | 先拆镜头 |
| 打包交付 | 00-07 全部、全剧审稿通过 | 补缺；缺一项不交付 |
| 改设定 | 故事核 | 补 story；或按用户口述建临时档，标待回填 |

**依赖检查不是阶段闸**：只回答"现在做这件事，手上够不够"。

## 降级模式

用户坚持跳步时，允许，但必须记录：

- 在 `00-创作总表.md` 的「降级记录」写：跳了什么、欠什么、预计什么时候补。
- 在对应剧本或审稿里标 `降级:无镜头意图` / `降级:无场景锚点`。
- 下一次进入相关模块时优先补欠账。

**禁止静默降级**。

## 操作步骤

### Step 0 判断入口

先看用户这句话属于哪一类，直接路由。用户一句话里混了两件事，先做依赖更靠前的那件，或问先做哪件。

### Step 1 新建项目

1. 建目录：`05-剧本/`、`06-镜头意图表/`、`07-审稿/`、`08-交付/`、`资料/`。
2. 写 `00-创作总表.md`，项目信息按用户已说的填，未说的留空。
3. 问四项就够：
   - 海外还是国内，哪个平台。
   - AI 生成还是真人拍摄。
   - 总集数与单集时长。
   - 现在手上有什么：想法 / 对标 / 故事 / 剧本。
4. 按第 4 项直接路由到对应模块。

**不输出完整流程说明**。用户没问流程，就不要讲十个模块。

### Step 2 导入已有项目

**2a 扫文件**：列出文件名、位置、一句话内容。

**2b 归位**：

| 文件内容 | 归到 |
|:--|:--|
| 市场、平台、题材、集数、生产模式 | `01-市场定位.md` |
| 对标、拉片、参考剧 | `02-对标拆解.md` |
| 一句话、情感契约、信息差、结局 | `03-故事核.md` |
| 人物、人设、关系、视觉锚点 | `03-人物关系与人物卡.md` |
| 场景、美术、视觉、空景锚点 | `03-场景与视觉.md` |
| 分集、卡点、付费墙、镜头预算 | `04-分集卡点表.md` |
| 单集剧本 | `05-剧本/EP{NNN}.md` |
| 全剧剧本 | `05-剧本/全剧剧本.md` |
| 镜头、分镜、镜头意图 | `06-镜头意图表/EP{NNN}.md` |
| 审稿、意见、打分 | `07-审稿/EP{NNN}-审稿.md` |
| 交付说明、卖点、人物合集、合规 | `08-交付/` 对应文件 |
| 资料、考据 | `资料/{主题}.md` |

旧项目把 `06-审稿/` 整体改名为 `07-审稿/`。匹配不上的列"未分类"，问用户。`.docx` 先读再写 md。

**2c 重建总表**：按模板写 `00-创作总表.md`，文件索引按实际状态填。

**2d 缺口提示**：只提示与用户当前目标相关的缺口。用户要写第 5 集，就只查第 5 集的分集卡点、人物、场景。

### Step 3 维护创作总表

每个模块完成后，只改涉及的行：文件索引、关键决定、当前进度、降级记录、最近改动。不做全量重写。

## 交付标准

A 组交付前逐项检查，缺一项不交付：

| # | 交付物 | 完成标准 |
|:--|:--|:--|
| 00 | 创作总表 | 项目信息、关键决定、文件索引、进度齐全 |
| 01 | 市场定位 | 平台、受众、题材、生产模式、集数、时长、卖点、标题三项 |
| 02 | 对标拆解 | 3-5 部、八项、可生成性判断、招式库 |
| 03a | 故事核 | 一句话 ≤60 字、情感契约、信息差、结局、20 冲突源 |
| 03b | 人物卡 | 5-8 人、功能位、欲望/阻碍/秘密、语言指纹、视觉锚点 |
| 03c | 场景与视觉 | 主场景 ≤8、每集 1 主场景、空景锚点、视觉规则 |
| 04 | 分集卡点表 | 每集一冲突一转折一卡点、镜头预算 12-13、台词预算 |
| 05 | 剧本 | 全剧剧本写完、无小说腔、每集有钩子 |
| 06 | 镜头意图表 | 每集 12-13 镜、一镜一动作、风险标注、可交 B |
| 07 | 审稿 | 逐集 PASS/CONDITIONAL、全剧审稿报告结论可交付 |
| 08 | 交付包 | 五份文件齐全、B 组不用追问即可开工 |

**红线五条**：

1. 没有镜头意图表，或镜头数超过 15。
2. 一集超过 3 个有台词人物，或超过 1 个主场景（AI 生成模式）。
3. 剧本出现小说式心理描写或无法拍摄的概述。
4. 人物知道了他不该知道的信息，或关键道具凭空出现。
5. 交付包缺文件，或缺全剧审稿结论。

## A→B 交接契约

A 组交 `06-镜头意图表`，B 组据此写 prompt。A 组只写"观众看到什么"，不写"模型怎么生成"。

| 字段 | A 组填 | B 组补 |
|:--|:--|:--|
| 镜号/时长 | 节拍与秒数 | 实际生成时长 |
| 画面 | 一个动作 | 首帧 prompt、构图 |
| 台词 | ≤12 字 | 音色、语速、配音 |
| 情绪 | 本镜情绪 | 光线、表演、音效 |
| 参考 | 角色/场景 ID | 参考图、模型参数 |
| 风险 | 生成难点 | 抽卡方案、fallback |
