# 短剧 SOP 阶段契约（0166）

> 本文件是 **Web 项目总控** 与各专家 skill 共用的一份阶段定义。
> 页面显示的阶段、状态、闸门和「下一步」，与 Agent 写文件时的判据必须来自这里。
> 阶段只是**派生视图**：真正的源仍是项目文件，不新增第二真源。

## 1. 阶段表

| id | 阶段 | 主产物 | 完成判据 | 阻塞判据（gate） | 点「执行」送进对话 |
|:--|:--|:--|:--|:--|:--|
| `prep` | 准备 | `01-市场定位.md`，可选 `02-对标拆解.md` | 平台、受众、题材、集数、单集时长、生产模式六项齐全 | 缺平台或集数 | 「先定平台、受众、题材、总集数与单集时长」 |
| `brief` | 故事梗概 | `03-设定/故事核.md` | 8 字段齐全；核心梗概 800-1200 字；事件 3-5 个 | 缺任一字段 | 「先补故事梗概 8 字段」 |
| `characters` | 人物小传 | `04-人物/人物小传.md` | 6-8 人；每人 5 字段；功能位含主角/对手/锚点/助攻；姓名唯一 | 少于 6 人或姓名重复 | 「生成 6-8 人人物小传」 |
| `outline` | 粗纲 | `05-分集/粗纲.md` | 起承转合四段；集数合计 = 总集数；每段写「结束时局面变成什么」 | 四段合计 ≠ 总集数 | 「重排粗纲到起承转合四段」 |
| `episodes` | 集纲 | `05-分集/集纲.md` | 已排集数 / 总集数；每集含事件、主动方、阻挡方、转折、集末落点 | 少于总集数 | 「生成下一批集纲」 |
| `script` | 正文 | `06-剧本/EP{NNN}.md` | 已有集数；单集 2-4 场、约 1000 字；集末落在决定/新问题/画面卡点 | 集末纯情绪收尾、人名越界 | 「写下一集正文」 |
| `delivery` | 审稿交付 | `06-剧本/审稿/`、`07-交付/` | 审稿结论 + 交付清单齐全 | 交付五份未齐 | 「做交付检查」 |

`prep` 是可选前置，不阻塞主链；用户没有平台和集数时先做 prep。

## 2. 阶段状态

| 状态 | 含义 | 页面表现 |
|:--|:--|:--|
| `empty` | 主产物不存在，或 0 项判据满足 | 未开始 |
| `partial` | 产物存在但判据未全满足；`statusText` 写缺什么（如「3/6 人物」「2/10 集」） | 进行中 |
| `ready` | 判据全满足，可进入下一阶段 | 已完成 |
| `blocked` | 闸门失败，停在本阶段 | 阻塞 + 原因 |
| `stale` | 上游产物在本阶段产物之后被修改 | 需重核，不静默覆盖 |

**上游改动**：下游产物 mtime 早于上游时标 `stale`，并在总控写「需重新核对」。Agent 不得静默覆盖，先读上游差异再重写。

## 3. 闸门

1. **人名白名单**：本阶段出现未登记人名 → `blocked`。
2. **关系白名单**：称呼/关系与账本冲突 → `blocked`。
3. **道具/伏笔**：已开未收超过 10 集 → 警告；凭空出现 → `blocked`。
4. **集末落点**：每集末必须是决定 / 新问题 / 画面卡点三型之一；纯情绪收尾 → `blocked`。
5. **桥段重复**：同一招式在冷却期内重复 → 警告，不阻塞。

闸门只提示与拦截，**不自动改稿**。

## 4. 账本

路径：`00-创作总表.md` 的「连续性账本」段（JSON 块，由文件派生，可整份重算）。
不写 `.popwave/`：Web 版本发布拒绝隐藏目录与文件，账本必须随总表一起发布。

```json
{
  "characters": [{ "name": "陆言", "aliases": ["小陆"], "role": "主角", "firstSeen": "EP001" }],
  "relations": [{ "from": "陆言", "to": "苏晚", "type": "搭档", "since": "EP002" }],
  "props": [{ "name": "捉诡册", "opened": "EP001", "closed": null, "status": "open" }],
  "beats": [{ "name": "镜中倒影慢半拍", "episodes": ["EP001"], "cooldown": 3 }],
  "episodes": [{ "no": "EP001", "status": "scripted", "ending": "决定" }]
}
```

- 页面和 Agent 都读它；它**不反向写正文**。
- 人名、关系、道具只在账本登记后才能在新一集出现；新增先登记再写。

## 5. Agent 执行规则

1. **每轮只做当前阶段**；用户明确跳步时，在 `00-创作总表.md` 写「降级记录」，下游标 `stale`。
2. 写文件前先读上一阶段产物 + 账本；找不到就补，不猜。
3. 生成正文前先过本集 schema；失败只重试本集，不重跑全剧。
4. **一次最多 5 集**；超过 5 集先审。
5. 不在页面里直接改文件；页面只发 prompt。
6. 完成后回三件事：做了哪个阶段、落在哪些文件、下一步是什么。不复述全文。

## 6. 与旧「创作对象」的关系

`00-创作总表.md` 与设定/人物/分集/剧本/交付的对象目录仍然有效；SOP 阶段机只是在它们之上加了一层**顺序与判据**。

- 旧文件：`04-分集卡点表.md`、`05-剧本/`、`06-镜头意图表/`、`07-审稿/`、`08-交付/` 继续按 workbench 的导入规则归位。
- 新写项目按本契约的路径产出，不再新增旧路径。
