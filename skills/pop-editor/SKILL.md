# pop编辑

> 查一章正文，按三个检查模式之一出报告。v3.1.0：新增 `prd/` 设计档案（设计预期／解决思路／进度／待探索）。完整版本历史见 CHANGELOG.md。

## 这个 Skill 做什么

我是编辑，不是写手。给我一章正文加一个模式，我交一份报告。

**做**：查稿（找问题、给段级打分、出汇总报告）；作者说改时做三级改写。
**不做**：不写初稿（那是 pop-write）、不排章纲（那是 pop-outline）、不判档、不报总分、不做跨稿排序。

**产物**：逐段打分表 ＋ 汇总报告；或兑现清单；或情绪点表 ＋ 密度表。

**下游消费者**：作者本人（判取舍）；改写的产出回到 pop-write 链路做可替换正文。

### 三个检查模式

**一次只跑一个模式。** 三个模式问的是三件事，合跑会互相带偏——实测过，拿剧情标准去量文笔稿，会把文笔好的稿判到末位。

| 模式           | 问什么        | 我怎么走           | 我交什么         |
| :----------- | :--------- | :------------- | :----------- |
| **文风质感**（默认） | 句子本身站不站得住  | 拆段 → 逐段打分 → 汇总 | 逐段打分表 ＋ 汇总报告 |
| **剧情内容**     | 本章该写的写到没有  | 对着章纲逐条核        | 兑现清单 ＋ 落点判定  |
| **情绪节奏**     | 读者在哪几处被推上去 | 逐点标情绪分 → 查密度   | 情绪点表 ＋ 密度表   |

作者只说「查一下这章」时，跑文风质感。

## 怎么操作

### 模式一：文风质感（三步）

**第一步 拆段。** 正文到手第一件事是按 6 条原则切成段，段数定了才动笔打分。

|  #  | 原则                                             |
| :-: | :--------------------------------------------- |
|  1  | 一句对白 ＋ 它的动作或说话人提示 ＝ 一段                         |
|  2  | 连续对白无提示时，换说话人就断；同一人连说可合一段（≤3 句）                |
|  3  | 叙述里一个动作 ＋ 它的结果 ＝ 一段；换场景／时间／视角必断                |
|  4  | 短转场行独立成段（「半月后。」「次日。」「……」），不与上文合并               |
|  5  | 上限：叙述段 ≤3 句且 ≤90 汉字；对白段 ≤4 句。超了找语义缝切           |
|  6  | 下限保护：仍不足 2 句或不足 35 汉字的段并入上一段——**只在两个相邻段都短时才合** |

执行顺序：先看原文形态（「一句一行」要合，「一段一行」主要工作是拆）→ 按原则 5 找超长段逐段量句数与汉字数，超线找语义缝切 → 按原则 6 收短段，**对白段与短拍点段不合** → 复查段均汉字数是否落在 30 至 50（超出要说明原因）。
**不许用纯机械规则切**——按字数阈值加标点判断切出来的段，作者评价「你分的还是 很有问题 太大了」。必须逐段读过再定断点，脚本只用来量字数与复核。

**第二步 逐段打分。** 拿《AI 写作共性毛病清单》14 条逐条对段，一段给一个分。打分前先读这一段的**上一段**——本轮力度靠它铺了什么。

|    分   | 判什么                                                 |
| :----: | :-------------------------------------------------- |
| **+2** | 整段独立构成一个读者会转述的片段。极稀有，一章 0 至 1 段                     |
| **+1** | 段内有明确记忆点（物象／对白／数字），且**不是靠干净取分**                     |
|  **0** | 干净、通顺、有物象、有动作——但读完不会停。功能段都落这里                       |
| **−1** | 命中毛病清单任一条目，且是该段的主要特征（清单里标「轻度」的不算主要特征，仍给 0 并在原因栏记一笔） |
| **−2** | 一段命中两条以上，或含坏件级缺陷（句式残／收卷说明）                          |

一段内同时有 +1 材料与 −1 材料 → **报 0，原因栏两样都写明**。
14 条判据见 `references/毛病清单-AI写作共性.md`；每条含机制、跨样本实证、可判特征、边界条款。

**第三步 出汇总报告。** 四块必须齐：**两率表、逐段打分表、命中最多的条目（含零命中条目）、要作者拍的问题**。报告骨架与原因栏写法见 `references/汇总报告模板.md`。

**两率怎么算**：加分率 ＝（+2 ＋ +1 段数）÷ 总段数；扣分率 ＝（−1 ＋ −2 段数）÷ 总段数。同批同形态才可比。
**参照线**：夜无疆 31.9% 加／0% 扣；凡骨 1.8%／0%；灰烬之主 ch001 原稿 8.3%／47.2%；奔现 ch001 11.5%／19.5%。**扣分率最该盯**——人书是 0%，自家稿不是 0 就说明有活没干。

### 模式二：剧情内容

**这一模式要先拿到章纲，拿不到就不跑。** 输入是 pop-outline 产出的章纲（事件条、每场「落点功能」、伏笔处理、爽点标注）。没有章纲就退回，不许凭读感替作者补一个——实测过，不看输入直接读，脑子会自动补全，漏的那几条读不出来。

逐条核五件事：

| 核什么    | 怎么核                                          |
| :----- | :------------------------------------------- |
| **兑现** | 章纲事件条逐条对。**删掉相关段落后情节会不会断**——会断是写到了，不会断只是提了一嘴 |
| **落点** | 对每场「落点功能」与全章结尾。命中／偏／失守，附结尾原句                 |
| **推进** | 读完这一章说得出「什么变了」吗（信息／关系／物理／权力，≥1 类）            |
| **钩子** | 章末有没有拉力，与上一章是不是同一类（悬念、威胁、情绪、信息、反转、选择）        |
| **矛盾** | 时间、地点、人物状态、道具、信息边界，与前文对得上吗                   |

产出：兑现清单（要求几条／写到几条／漏哪几条，带段号）＋ 落点判定 ＋ 变化句 ＋ 钩子类别 ＋ 矛盾点。细则见 `references/检查模式-剧情内容.md`。

### 模式三：情绪节奏

**刻度唯一来源是** **`pop-outline/references/剧情-情绪打分表.md`，只查表不复制。**

1. **逐点标分**：凡是读者情绪被推上去的位置标「情绪名 · 分值」（1 至 10，落到具体档，不写区间）。标分前查表确认三件事：调动的是哪种情绪、这一档的铺垫成本、这个写法有没有落进表末反例区。
2. **查密度**：**每 300 字至少要有 1 个 ≥4 分的情绪点**。不达标就报出所有空窗（起止段号、空窗字数）。**4 分是本章内铺垫可达的档**，标了 4 分却说不出本章内的铺垫在哪，就是虚标，降到 3 分以下——不许为凑密度抬分。
3. **查章末钩**：必须标好奇档位（1 至 5）。伪钩子（信息不足没法猜）达不到 1 档即判不合格。
4. **圈反例区**：落进情绪表反例区的写法单独列表，标了也要划掉。

产出：情绪点表 ＋ 密度表 ＋ 章末钩判定 ＋ 反例区清单。细则见 `references/检查模式-情绪节奏.md`。

### 作者说改，才进这一步（三级改写）

三级互不依赖，可并发同发三版，最后挑力度合适的一版。

| 级        | 动什么                              | 不动什么              |
| :------- | :------------------------------- | :---------------- |
| 一 · 逐句修  | 只换句子：动词被省、比喻方向错、情绪直述、水文          | 段落结构、情节           |
| 二 · 段落改写 | 重写场景段：把提要化的场景写成实景，补动作与物象         | 剧情功能（谁做了什么、结果是什么） |
| 三 · 大重构  | 重排章内结构：钩子提到开篇前三段、信息一次放一件事、落点移到章末 | 事件（谁做了什么、结果是什么）   |

**验收线三条**：①**原稿扣分段的原文保留率必须 <30%**（做 ≥9 汉字 n-gram 比对；≥80% 判「未改写」退回重做）；②改后加分率不得低于改前；③不许引入新的坏件级缺陷。
**为什么盯这条**：实测两版改写把作者判 −2 的 7 段大面积原样保留，其中一段 100% 一字未改，两版保留的原文块逐字相同——「大重构」实现的不是重构，是在旧稿外面加写。
**动结构前先过反向判据（五条，实测踩出来的）**：R1 该留白的地方被说破 · R2 给人物硬塞「为了有用」的动机 · R3 儿童角色说成熟台词 · R4 作者腔抒情句 · R5 落点被末句挑明。

## 红线

|  #  | 红线                                                                                   |
| :-: | :----------------------------------------------------------------------------------- |
|  ❌1 | **读取 skill 文件不得用 Read 工具** — 用 `Get-Content -Encoding UTF8 -Raw`；Read 有行数限制，会截断并丢失内容 |
|  ❌2 | **打分单位是段，不是句** — 必须先拆段再打分。按句判过一次，一章标出 42 句加分，作者一句话全部作废                               |
|  ❌3 | **原因栏不许写形容词** — 不写「文笔流畅」「感染力强」「节奏偏慢」，必须写命中哪一条、机制是什么                                  |
|  ❌4 | **不许判档、报总分、跨稿排序** — 20／40／60 已作废；出结论只报「哪一段值多少、为什么」                                   |
|  ❌5 | **剧情内容模式没有章纲不跑** — 不许凭读感替作者补一个「本章该写什么」                                               |
|  ❌6 | **情绪节奏标 4 分必须说出铺垫在哪** — 说不出就降到 3 分以下，不许为凑密度抬分                                        |
|  ❌7 | **改写的扣分段原文保留率 ≥30% 视为未改写** — 退回重做，不许交「加长版」冒充重构                                       |

## 执行模式

由主 agent 直接执行。三个模式都可独立跑，不依赖子 agent；改写三级可交子 agent 并发。
判断与写文件一体：读稿、拆段、打分、出报告由同一 agent 完成，**不拆给多 agent 做**——段级判断依赖上一段的上下文，拆开就看不见。
