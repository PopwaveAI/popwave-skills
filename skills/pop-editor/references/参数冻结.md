# 参数冻结

> 每次开跑前先比对本文件与 `.env`，不一致即停。这是防"跑完才发现参数错了"的第一道闸。
> **改判据即重校**：换模型、换档样、改红线、加赛道，四件事任一发生，校准作废重跑。

## 一、冻结的参数

| 项 | 值 | 为什么是这个值 |
|:--|:--|:--|
| 模型 | `deepseek-flash` | 项目规则：所有走 API 的任务默认 flash，无当次特别指示不换 |
| temperature | 0 | 评委要可复现：同一稿同一问法，两次跑结果应一致 |
| top_p | 1 | 不做额外截断 |
| max_tokens | 32000 | 实测：要求模型"先权衡再落笔"的输入会吃满输出额度（出现过 2 万字思考、正文 0 字）。低于此值容易出半截稿 |
| system message | **不发** | 评委要盲，不带身份与口吻倾向 |
| 一次批内稿量 | ≤6 | 超过六稿，排序会发虚 |
| 并发 | ≤4 | 控制失败率与限流 |
| 重试 | 同参数最多 2 次 | 之后必须分析原因改参数，不盲目重试 |

## 二、开跑前的四项比对

1. `.env` 的 `MODELS` 必须是 `deepseek-flash`；`MAX_TOKENS` 必须 ≥32000。
2. `素材/manifest.jsonl` 与磁盘实际文件是否对得上（缺一即停）。
3. 本批是否只含**同赛道**稿（本轮赛道：东方幻想＝玄幻／仙侠／武侠）。跨赛道稿不入同批。
4. 本批各稿的**故事位置是否对齐**（同为首章／同为中段／同为独立单章）。位置不齐会污染"内容剧情／情绪节奏"两维——中段章的情节天然比首章多，混排时首章必输。对了才开跑；不齐就换稿。

## 二·补、素材开跑前必做的一道归一

跑 `scripts/normalize_material.py`，剥掉各稿开篇的章节标题行（如「第一章 旧宅」「仙门杂役的逆袭」），并砍掉尾巴上的模型思考块（flash 直出稿尾巴带过 5 份 `<details>思考过程</details>`）。

为什么必须做：G18（正文夹带工作标记）是文笔质感的硬门槛。若有的稿带标题、有的不带，代称与章序会不对称地触发 G18，把本属合格边缘的稿压进红线组，制造成假倒挂。**已实测踩到过：13 份素材里有标题行。**

同时检查正文里有没有站点导航与广告行（「零点小说」「返回目录」「为您推荐」「亲,双击屏幕」等）。**已实测踩到过：不死帝师整章曾被带进 7 行站点导航，编辑评委据此打出 G18，把 70 档稿压到文笔末位。**

## 三、每稿必记的检查项

| 字段 | 判失败的线 |
|:--|:--|
| `finish_reason` | 出现 `length` 即为截断，本稿作废重跑 |
| `reasoning_tokens` | 记下来；显著偏高（超过 3000）说明这次调用在"权衡"，结论要打问号 |
| 正文汉字数 | 为 0 即失败 |

## 四、命名与落盘

- 输入：`scripts/输入/稿XX.md`（纯正文，无来源、无档位、无标题）
- 输出：`scripts/输出/第N轮/稿XX__{角色}.json`、`稿XX__内容剧情二轮.json`、`manifest.jsonl`
- 幂等：同名输出存在即跳过，`--no-skip` 强制重跑；失败可断点续跑
