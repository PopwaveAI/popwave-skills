# 测试 SOP（跑批与验收）

> 这是**测试流程**，不是 pop编辑 的行为逻辑。pop编辑 自己的读法与判法见 `SKILL.md`。
> 本文件管的是：素材怎么归一、跑批怎么跑、验收线在哪、什么时候必须重校、怎么迁仓。

## 一、跑批前必过（漏一条就别跑）

1. **素材归一**：跑 `scripts/normalize_material.py`。它剥开篇标题行、砍站点导航与广告、砍模型思考块、砍作者 PS 与求票。
   - 为什么必做：G18 是硬门槛。带不带标题、夹不夹 PS，会**不对称**触发 G18，把好稿压下去，制造成假倒挂。
   - 已实测踩到四次：不死帝师整章带 7 行站点导航；13 份稿带开篇标题行；5 份 flash 稿尾巴带 `<details>思考过程</details>`；三本 60 档书正文里夹作者 PS（超维度玩家、剑烛大荒、黜龙）。
2. **重建 manifest**：跑 `scripts/rebuild_manifest.py`，**核对打印出来的每档份数**。
   - 已实测踩到两次：一版按废弃目录重建，目录不存在就被静默清空；一版把目录名写成「不合格20-30」而实际叫「不合格」，6 份稿被静默丢掉。
3. **行号重校**：素材一归一，`对照表-*.md` 与 `打分表-*.md` 里的案例行号全部错位，必须重校。已实测：归一整体挪了 2 行，案例全指向错句。
4. **同批同赛道、同单元形态**：一批里不混连载首章与独立单章（混批会让内容剧情／情绪节奏两维整体颠倒）。

## 二·补、分段打分器（作者自己打分用）

**位置**：`新流程探索/网文编辑/打分器/`（本地工具，**不入 git**——它内嵌了素材正文，含已出版小说选段）。

| 文件 | 作用 |
|:--|:--|
| `打分器.html` | 产物。双击即用，无需服务器。13 章 / **人工定稿 649 段** |
| `breaks.json` | **人工断点**（主 agent 逐章读后定的"新段首行序号"）。段的口径就是它 |
| `模板.html` | UI（含 `/*__CHAPTERS__*/ []` 标记） |
| `build.py` | 读 breaks.json 切段（再过一道下限保护）+ 注入模板 + 产出 `打分器.html` |

**切段为什么要重建**：源文 txt 的空行只在章与章之间，章内一律"一句一行"（一整章 = 一个 40 至 130 行的连续块）。照行切出来每段只有一句，读不出上下文，没法打分。
**为什么不用机械规则**：作者 2026-09-13 连续纠偏两次——先要求按段合并，再指出「你分的还是很有问题 太大了 你是用脚本写的匹配规则吗？」。字数阈值只能定"大小"，定不了"在哪断"；"在哪断"靠说话人切换、动作与结果、场景转场这些语义信息，正则读不出来。**结论：逐章人工定断点，机械口径只给新加的书做兜底试切。**
**段的口径**：13 章 649 段，每段 9 至 133 汉字、平均约 45 字。六条断段原则写在 `references/打分表-文笔质感-分段加减分.md`。
**素材文件不动**：`素材/*.md` 保持"一句一行"的原始格式（`对照表`／`打分表` 的行号都对着它），段在构建打分器时现场切。

**用法**：选章节 → 每段右边点 +2／+1／0／−1／−2 → 打分自动存本机（localStorage）。
快捷键：点段落选中 → **5**=+2 **4**=+1 **3**=0 **2**=−1 **1**=−2 ・**↓** 下一段 ・**Del** 清除。
顶栏实时滚出**段数／已打分／加分段／扣分段／加分率／扣分率／参考判定**。可导出 Markdown（贴进仓库）或 JSON（给 pop编辑 读回来算）。
另有「载入本地文件…」按钮，把任意 `.md`／`.txt` 拖进来按空行切段打分，不占内嵌位。

**为什么内嵌而不是读文件**：本地 `file://` 打开时浏览器禁止读本地文件，内嵌才能双击就跑。
**加新章**：在 `build.py` 的 JOBS 里加一行（分组／显示名／相对路径），重跑 `python build.py`。人家的书与我们的稿都往这里放。

**判定的阈值来自 `references/打分表-文笔质感-分段加减分.md`，标着"待校准"**，别拿它当结论。

## 三、参数冻结

| 项 | 值 | 为什么 |
|:--|:--|:--|
| 模型 | `deepseek-flash` | 项目规则：所有走 API 的任务默认 flash，无当次特别指示不换 |
| temperature | 0 | 要可复现 |
| top_p | 1 | 不做额外截断 |
| max_tokens | 32000 | 低于此值容易出半截稿或正文 0 字 |
| system message | **不发** | 评委要盲 |
| 一批稿量 | ≤6 | 超过六稿排序会发虚 |
| 并发 | 4 至 6 | 先小批压测，出现限流即退回 4 |

每稿必记 `finish_reason`（出现 `length` 即作废重跑）与 `reasoning_tokens`。

## 三、跑法

```powershell
cd 'd:\popwave-skills\新流程探索\pop编辑\scripts'

# 选稿（--ids 指定，或用 --plan 分层抽样）
python anon.py --round 9 --ids "A-全民大航海时代-第1章,A-超维度玩家-第1章,A-明末从西北再造天下-第1章,A-莫欺老年穷-第1章"

# 三位评委 + 排序官（排序官同时给判档）
python run_judge.py --mode judge --round 9
python run_judge.py --mode rank  --round 9

# 三级改写（只对自家产出）
python run_judge.py --mode fix     --round 改写 --id "X-灰烬之主ch001,X-灰烬之主ch002,X-旧海图ch001"
python run_judge.py --mode para    --round 改写 --id "X-灰烬之主ch001,..."
python run_judge.py --mode rebuild --round 改写 --spec "输入\灰烬之主ch001-该写什么.md" --id "X-灰烬之主ch001,..."
python extract_rewrites.py        # 把改写结果抽成可读正文，落到 scripts/改写/
```

- 幂等：同名输出存在即跳过；`--no-skip` 强制重跑。
- 三级改写**互不依赖**，一次并发同发三次，不逐级串跑。

## 四、验收通过线

| 步 | 通过线 | 实测 |
|:--|:--|:--|
| 判档 | 给定一稿判到 80／60／40 之一；相邻档算半对，**≥5/6 命中**才算过 | 第 9 轮 **6/6、0 错杀** |
| 找问题 | ≥3 处带行号的硬伤；**对作者已知判定召回 ≥80%** | 模型首测 2/4＝50%（未达标）；主 agent 逐句读 4/4 |
| 改到 60 | 三级产出为可替换正文；改后稿在盲测里判到 **60 档及以上** | 三级重构稿判到 80 档（原文为 20 至 30） |
| 错杀 | **必须是 0**。把好稿判成差稿，一次即整批不可用 | 第 9 轮 0 |

**召回的算法**：拿作者圈过的每一处当一条答案，逐条看模型有没有点到同一行、且机制对得上。只点行号不对机制，算半条。

## 五、什么时候必须重校

1. 模型换版本
2. 对照表改动（换样本、补样本、改档线）
3. 判据包改动（`references/判据摘要.md`、红线增删、维度定义改动）
4. 新增赛道
5. **素材归一**（行号会错位）

改任何判据 = 校准作废，必须重跑受影响批次。

## 六、迁仓纪律

**改 D 盘 → 提交 git → 同步 C 盘 → UTF-8 校验 C 盘。** 顺序不可倒，缺同步 = 应用还在跑旧版。

```powershell
# 1. 提交前先过仓库校验（pre-commit 钩子也会跑）
cd 'd:\popwave-skills'; npm run --silent skills:validate
git add skills/pop-editor; git commit -m "..."; git push

# 2. 同步 C 盘（版本目录 = skill.json 的 version 字段）
$dst='C:\Users\AWMPRO\AppData\Roaming\popwave\remote-skills\pop-editor\1.1.0'
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item 'd:\popwave-skills\skills\pop-editor\*' $dst -Recurse -Force

# 3. UTF-8 回读校验（必须用 -Encoding UTF8，默认编码会骗人）
$c = Get-Content "$dst\SKILL.md" -Raw -Encoding UTF8
$c.Contains('本次改动独有的关键字符串')
```

- **`.env` 绝不入仓**（含 API key），只带 `.env.example`。
- 素材与迭代记录不入仓（含已出版小说选段）。
- C 盘只读参照，不在 C 盘改内容。

## 七、目录约定

| 目录 | 放什么 |
|:--|:--|
| `素材/八十80`、`六十60`、`四十40` | 按成绩切好的三档整章稿 |
| `素材/合格边缘`、`不合格` | 旧名保留（改了会弄坏历轮 `映射表-封存.json` 的历史路径）；新方案里是"改写对象池"，不是档位 |
| `scripts/输入` | 匿名稿（纯正文，无来源、无档位、无标题） |
| `scripts/输出/第N轮` | 每轮三评委输出 + 排序官输出 |
| `scripts/改写` | 三级改写产出 |
| `迭代记录/` | 每轮结论（每阶段只落一份，不逐步汇报） |

## 八、算命中率的一条硬规矩

**真身必须现查，不许把稿号映射写死。** 已实测踩到：`anon.py` 每轮按 `SEED+轮次` 重排稿号，我把上一轮的映射写死在验收脚本里，算出"4/6"，实际是 6/6。凡算命中率，从 `scripts/映射表-封存.json` 现读。
