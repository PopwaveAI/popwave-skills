## v1.2.1 | 2026-09-13

**write 环节按老板的流程图补齐三条边。** 老板原话：「skill 上面没写的 以我为准 1 2 3 都改了」。

### 背景：图与本文有三处不一致

| # | 图上画了 | 本文原来 |
|:--|:--|:--|
| 1 | **第 N-1 章正文 → write**（前馈边） | 只写了「write 永远跟在章纲之后」，没写它还要读上一章正文 |
| 2 | **第 N 章正文 → write**（自环） | 没画进循环。实际 pop-write 的 Step 3 就在做这件事，只是本文没体现 |
| 3 | write 的输入 = 文风dna ＋ 第 N 章章纲 ＋ 第 N-1 章正文 | 本文列的是「轻量章纲、涌现账本、世界装配单、文风承诺」——漏了上一章正文与文风dna，把两条底线约束当成了写作输入 |

**裁决：以图为准。**

### 改法

**写作输入收成三条**：`章纲/ch{NNN}-章纲.md`、`正文/ch{NNN-1}.txt`（前馈，必读）、`文风dna/文风锚定.md`（项目内存在时读，由 pop-dna-style 产出）。
**底线约束另列两条**：`剧情日志/涌现账本.md`（不得与已发生事实冲突）、`立项/世界装配单.md`（力量体系、世界观、金手指、身份只能取自其中）。**这两项是约束，不是写作输入。**
**自环写进循环**：`outline → write 正文 → write 自环复查（结构层五项＋语义七项＋字数脚本＋去 AI 味脚本，全过才交）→ review 三件事 → 回 outline`。并写明「review 不替 write 补足字数，也不替它过自环」。
**前馈边为什么不能省**：章日志记上一章讲了何事，上一章正文记其如何讲述、停在何处、气韵为何。缺这条边会重复上一章的动作与比喻，语气也接不上。

### 同步位置

状态机 2b 行、每章收束段、可调度 Skill 清单 pop-write 行、速查表（新增 `文风dna/文风锚定.md` 与 `正文/ch{NNN-1}.txt` 两行）。
