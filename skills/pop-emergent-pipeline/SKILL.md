# pop-emergent-pipeline

> 涌现流总控。当前版本 v1.0.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

### 心智前置·意识层（贯穿本 skill 与全流程）

动笔/定稿前自问：本产出要更好，还需要看过哪些候选？当前信息够不够？有更优选项没探索？

- **Know-Gap**：先显式列出"要更好需见过哪些候选面"，再列已覆盖，缺口=差值；缺口≥1 个未覆盖维度才触发取材，缺了取、别硬写。
- **Pack**：缺口足够才取材，query 自生成；来源 **wiki 站 https://wiki.popwave.cn** 居先、网络补齐；单环节 ≤1 轮 / ≤5 query / 回传 ≤30KB，超限截断仅留结论区。
- **Worth**：拿本 skill 决策尺对"现有 vs 候选"必给打分表，禁止一句"更优"带过；只端候选/升级版，不越权定终局。
- **Deepen**：产出/候选后自问"这是天花板吗？有更优候选吗？"显著更优才升级再问，上限 2 轮。

取材仅进上下文，升级被采纳才落产出。

## 做什么

| 职责 | 说明 |
|:--|:--|
| 一次性安装（fresh） | 建目录 + 存档 `状态.md`（薄机器状态）+（可选）导出展示面板 + README |
| 一次性导入/续写（import/resume） | 资产扫描→归位→缺口分析→落地Phase→状态重建→补跑调度 |
| 状态文件维护 | `状态.md` = 唯一状态总账，agent 只读写它的状态片段；展示面板仅供老板查看，agent 不读 html |
| 写章循环路由 | 涌现流滚动写章循环：轻量章纲 → 直接写 → 审查回填 → 阶段性回看 |

**日常路由不经此 skill**：用户说"继续写/下一步/写正文/审核"时，主 agent 按涌现流状态机直接选 skill，先读 `状态.md` 取状态片段（mode/phase/current_chapter），路由参照=下方「涌现流状态机」。pipeline 不写正文、不做内容转换、不常驻。

**涌现流三原则（贯穿路由）**：

1. **只锁两样＋模糊灯塔**：立项只锁——主角立身一句话＋文风承诺（没有这两样没法下笔）＋模糊灯塔（结局方向一句话）。不设路线、不排卷、不产设定。
2. **先写后补**：黄金三章直接写试味；设定不从事前设计来，**从账本里长出来**——每章 review 把新事实回填涌现账本，后文只从账本取。
3. **轻量章纲＋阶段性回看**：章纲只定接下来 1-3 章；写 N 章/一个故事弧后回看账本校准方向；味道验证后可**转灯塔流**（用已涌现的正文＋账本反推方向总表与滚动卷纲）。

**执行模式**：主 agent 直执。初始化/导入交互（资产清点、缺口确认、落地决策）由主 agent 完成；生成任务由主 agent 加载对应子 skill 执行。禁止派发子 agent 执行 skill 生成任务。

## 怎么操作（SOP 全内联）

### Step 0：导入/续写模式

> 触发（任一满足）：①用户说"导入/续写/已有/接续/迁移" ②Step 1 初始化时检测到 `正文/` 或 `立项/` 已有文件 ③项目目录已有内容但无 `状态.md`。
> 理念：pipeline 是调度员不是制造者。只做资产清点、文件归位、缺口分析、补跑调度；深度内容转换由主 agent 加载对应 skill 完成。

**0a 资产扫描**：LS 扫描项目目录（或用户指定源目录）→ 输出原始资产清单（文件名+位置+内容摘要1句话）。

**0b 资产归位**（只归位，不做内容结构标准化）：

| 用户文件（模糊匹配） | → 标准位置 | 标准文件名 | 对应位 |
|:--|:--|:--|:--|
| *意图*/*方向*/*想法*/用户口述 | `素材/` | 用户意图.md | 1 |
| *文风*/*DNA*/*笔触*/*风格* | `素材/` | 文风锚定.md | 1 |
| *调研*/*市场*/*赛道*/*排行* | `素材/` | 市场校准.md / 赛道调研.md | 1 |
| *采风*/*资料收集*/*质感*/*原型* | `素材/采风/` | {定向}-{主题}.md | 按需 |
| *立项*/*主角*/*一句话*/*立意* | `立项/` | 涌现立项卡.md | 1 |
| *开篇*/*黄金三章*/*前三章*/*试味* | `开篇/` | 试味评估.md | 2 |
| *章纲*/*轻量*/*叙事* | `章纲/` | ch{NNN}-章纲.md | 3a |
| *正文*/*章节*/ch*/第*章 | `正文/` | ch{NNN}.txt | 3b |
| *章日志*/*本章记录* | `章节日志/` | ch{NNN}.md | 3c |
| *账本*/*快照*/*进度*/*涌现设定* | `章节日志/` | 涌现账本.md | 3c |
| *回看*/*校准*/*阶段* | `章节日志/` | 阶段性回看.md | 4 |

操作：匹配不上的归"未分类资产"询问用户映射；.docx 等异构格式 Read 内容→Write 标准位置标准文件名；正文统一编号（`第一章.txt`/`chapter1.md`→`正文/ch001.txt`）；拿不准问用户；询问用户是否保留原文件。

**文件来源标记**（每个归位文件记入资产清单）：

| 来源标记 | 含义 | 后续处理 |
|:--|:--|:--|
| `user-original` | 用户已有文件，直接归位 | ⚠️需校验 |
| `pipeline-relocated` | pipeline 做了格式转换（.docx→.md 等） | ⚠️需校验 |
| `skill-generated` | 对应 skill 正向产出 | 正常消费 |

**0c 缺口分析**：归位完成后对照依赖链逐位检查（就绪判定=文件存在，查文件系统）：

| 位 | 就绪判定 |
|:--|:--|
| 1 | `立项/涌现立项卡.md`（主角立身一句话＋文风承诺＋模糊灯塔） |
| 2 | `正文/ch001-003.txt`（黄金三章已写）＋ `开篇/试味评估.md` |
| 3a | `章纲/` 接下来 1-3 章的轻量章纲 |
| 3b | `正文/ch*.txt`（current_chapter=最大编号+1） |
| 3c | `章节日志/ch{NNN}.md` ＋ `章节日志/涌现账本.md` |
| 4 | 每 N 章/一个故事弧后的 `章节日志/阶段性回看.md` |

进度检测：`正文/` 有文件→提取最大章节号，current_chapter=下一章待写。输出缺口报告。

**0d 落地Phase决策**（缺口报告+正文进度）：

| 条件 | mode | 落地位 | 说明 |
|:--|:--|:--|:--|
| 正文有+章日志有+账本有 | resume | 3a 或 3b | 状态完整：轻量章纲已产→3b，未产→3a |
| 正文有+账本缺 | resume | 先 0f 调度 review 补账本→3a/3b | 需补涌现账本 |
| 正文无+章纲有 | import | 3b（write） | 缺正文 |
| 正文无+试味评估有 | import | 3a（outline） | 缺轻量章纲 |
| 正文无+立项卡有 | import | 2（opening 试味） | 缺黄金三章 |
| 全无 | fresh | 1（seed） | 走 Step 1 初始化 |

→ 向用户展示：资产清单（含来源标记）+缺口报告+落地Phase建议+补跑建议清单（0f），**用户确认后**进 0e。

**0e 状态文件重建**：`状态.md` 不存在→按「状态.md 模板」创建；已存在→更新。字段：mode/phase/current_chapter/就绪态按 0c 标 [x]。展示面板可选：老板要求时按 `templates/项目总控.html` 套值导出。

**0f 调度skill补跑**（pipeline 只识别缺口+调度+汇报，不自行做内容转换）：

| 缺口类型 | 调度 skill | 做什么 |
|:--|:--|:--|
| 有正文+缺章日志/涌现账本 | pop-emergent-review 回溯 | 批量回溯：逐章章日志+涌现账本重建（含设定回填） |
| 缺立项卡/试味/章纲文档 | 对应 skill（seed/opening/outline） | 读已有文件→按 skill 方法论校验+补全→标准格式 |
| 已有文档但来源=user-original | 对应 skill（用户确认后按需） | 校验→标注缺口或确认达标 |

- review 回溯采样：≤10章全审 / 11-30章最近5章+每5章取1章 / >30章最近5章+第一章+每10章取1章。产出 `章节日志/ch{NNN}.md`+`章节日志/涌现账本.md`。
- 补跑建议清单：逐文件一行——文件名：来源=…，状态=…，建议=正常消费/补跑XX skill。用户三选：正常接续/按需补跑/全量补跑。

**Step 0 质量门**：原始资产清单已生成｜归位完成（含来源标记）｜缺口报告已生成｜落地Phase经用户确认｜状态.md 已创建/更新｜补跑建议清单已展示。

### Step 1：初始化（fresh 模式）

**前置检测**：执行任何创建前先 LS 扫描——`正文/` 有章节文件或 `立项/` 有 .md 文件→跳转「Step 0 导入/续写」；目录为空或仅有 `状态.md`→继续本步。

1. **创建目录（一次性）**：`素材/`（含 `采风/`）+ `立项/` + `开篇/` + `章纲/` + `正文/` + `章节日志/`。创建后 LS 自检全部存在，缺一=初始化失败，补创后才继续。（`素材/采风/`=定向采风库，存 research 世界观/人物/剧情/场景四类定向采风，文件名规范 `{定向}-{主题}.md`）
2. **创建 状态.md**：按「状态.md 模板」写入项目根（mode: fresh / phase: init / current_chapter: ch000 / 就绪态标 [ ]）；再简建 README.md（项目信息+目录说明+指向 状态.md）。
3. **展示面板（可选）**：老板要求时按 `templates/项目总控.html` 套 状态.md 值导出；agent 只写 状态.md，不读 html。
4. **路由 Phase 1**：加载 pop-emergent-seed 按其 SKILL.md 执行（问需求→只锁主角立身一句话＋文风承诺＋模糊灯塔）。

**Step 1 质量门**：目录齐全+状态.md 存档｜README 存档。

### 状态.md 模板（薄，机器读）

```markdown
mode: fresh            # fresh/import/resume
phase: init            # init/1/2/3a/3b/3c/4
current_chapter: ch000 # 下一章待写（本章 review PASS 后+1）
就绪态:
- [ ] 1  立项（涌现立项卡：主角立身一句话/文风承诺/模糊灯塔）
- [ ] 2  黄金三章试味（正文 ch001-003 + 试味评估）
- [ ] 3a 轻量章纲（接下来 1-3 章）
- [ ] 3b chNNN-正文
- [ ] 3c 章日志+涌现账本
- [ ] 4  阶段性回看（每 N 章/一个故事弧后）
```

### 涌现流状态机（日常路由参照）

```
Phase 1  立项（pop-emergent-seed）：主角立身一句话＋文风承诺＋模糊灯塔 —— 只锁两样＋方向感
  │
  ▼
Phase 2  黄金三章试味（pop-emergent-opening）：直接写三章 → 试味评估
  │        —— 味道不对：调向/重写；味道对：进写章循环
  ▼
Phase 3  滚动写章循环：
  3a  pop-emergent-outline：轻量章纲（接下来 1-3 章，从账本＋模糊灯塔临场生成）
  3b  pop-emergent-write：按轻量章纲/上一章＋账本直接写正文
  3c  pop-emergent-review：三源审查＋回填账本（新事实→设定从账本长出来）
  │
  ▼
Phase 4  阶段性回看（每 N 章/一个故事弧后）：pop-emergent-review 产回看报告
        （味道保持？连续性健康？模糊灯塔要不要清晰化？要不要转灯塔流？）
        → 校准后回 3a
```

路由判定：读 状态.md 的 phase/current_chapter → 对照状态机 → 选 skill。用户口头指令优先（"写正文"→3b；"审核"→3c；"回看"→4；"转灯塔流"→见下）。

### 转灯塔流衔接（涌现流试味成功、确定写长时）

涌现流与灯塔流是两段式，不是并列竞争：涌现流负责"最快试出味道"，灯塔流负责"味道验证后稳定长跑"。用户选择转灯塔流时，按此走：

1. **反推方向总表**：用已涌现的正文＋涌现账本，由 pop-lantern-plot 反推方向总表（每卷一句话：质变点＋卷末对手＋爽点标签）——已写内容作卷1方向行，未写部分保持开放。
2. **回填卷1卷纲**：已写章节作卷1首个剧情单元的起手，回填进卷1卷纲；后续走 pop-lantern-* 滚动卷循环。
3. **设定交接**：涌现账本里已长出的设定，由 pop-lantern-world/character 校验后并入 `设计/`（冲突以已发布正文为准）。
4. **状态迁移**：状态.md 改 mode=lantern，走灯塔流状态机（根→开篇→滚动卷循环）。

> 转不转、什么时候转，由老板拍板。涌现流本身适合：单卷试味、中短篇、人工操作、试错期。

## 红线

1. **只锁两样＋模糊灯塔**：立项不产设定、不排卷、不写大纲；模糊灯塔只到"结局方向一句话"。
2. **先写后补**：设定从账本长出来，禁止事前铺设定；本章新事实必须当场回填涌现账本。
3. **轻量章纲**：只定接下来 1-3 章，禁止提前排章、禁止回头写全书卷纲。
4. **账本唯一**：涌现账本是已发生事实的唯一承载，后文只从账本取，不翻前期规划（没有前期规划）。
5. **试味把关**：黄金三章未过试味评估不进写章循环；阶段性回看不做=连续写是裸奔。
6. **调度不制造**：pipeline 只识别缺口+调度+汇报，不自行做内容转换。
