# pop-emergent-pipeline

> 本技能负责涌现流总控：**在 snow 雪花流基础上做减法**，不做复杂长线设计，只保留 `seed(甲方文档) → state(设定装配) → outline(情绪章纲) → write(正文) → review(章日志+账本) → 再 outline` 这一轻量循环。设定不创造，只做装配（从内容模板库选取）；剧情以情绪标准先行（先查剧情-情绪打分表定本章情绪坐标，再反向设计剧情）。当前版本 v1.2.0（剧情-情绪打分表结构重构承接——峰值规则：每章≥2个峰值点、普通章5-6为主、8分稀缺须铺垫支撑），完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

### 动笔前须完成的检查（贯穿本技能与全流程）

动笔前与定稿前各执行一次，自查三问：本产出若要更好，尚缺哪些未见过的候选面？当前信息是否充足？是否存在未探索的更优选项？

- **一、先找出缺口。** 将"若要更好还须见过哪些面"明确列出，再列出已覆盖项，二者之差即为缺口。缺口内只要尚有一个维度未覆盖，即须取材。取材成功即采用；取材失败，不得勉强成文。
- **二、缺口足够时方可取材。** 检索项自拟。来源优先使用内部 wiki 站 https://wiki.popwave.cn，不足时再补充网络检索。单个环节最多取材一轮，一轮最多提出五个检索项，回传不超过 30KB，超出上限即截断，仅保留结论区。
- **三、交付候选须附依据。** 以本技能的判断尺，将现有项与候选项并列制成打分表，不得以一句"更优"一笔带过。只能交付候选或升级版，最终选定不由本环节决定。
- **四、交付后复检。** 产出或候选交付后，自查"这是否已是上限、是否有更优候选"。确有更优者方可升级重议，上限两轮。

取材内容仅进入上下文，仅当升级被采纳后方可写入产出。

## 职责范围

| 职责 | 说明 |
|:--|:--|
| 一次性安装（fresh） | 建目录；存档 `状态.md`（薄状态总账）；（可选）导出展示面板与 README |
| 一次性导入/续写（import/resume） | 资产扫描、归位、缺口分析、落地 Phase 决策、状态重建、补跑调度 |
| 状态文件维护 | `状态.md` 为唯一状态总账，agent 只读写其中的状态片段；`项目总控.html` 是仅供老板查看的展示面板，按需导出，**agent 不读 html** |

**日常路由不经由本技能**：用户说"继续写/下一步/写正文/审核"时，主 agent 按「涌现循环状态机」直接选 skill，先读 `状态.md` 取状态片段（mode、phase、current_chapter 与就绪态），路由依据见下方「涌现循环状态机」。本技能不写正文，不做内容转换，也不常驻留。

**涌现流四原则（贯穿路由）**：

1. **seed 是甲方文档**：立项只确定"要写什么、读者图什么、卖点、主角立身一句话、文风承诺、模糊灯塔"六项，它是后续所有环节的需求源头，不锁定复杂设定。
2. **state 是装配，不是创造**：设定从内容模板库选配（力量体系、世界观结构、金手指、身份结构），不让 agent 凭空发明；写章过程中长出的新设定继续从库中选取。
3. **plot 环节已砍掉**：不设计长线剧情，没有卷级排期。
4. **情绪标准先行**：outline 先查剧情-情绪打分表，定本章情绪坐标（每章不少于 2 个峰值点，普通章以 5 至 6 为主，8 分稀缺，须有铺垫支撑），再反向设计剧情事件；轻量章纲一次排 1 至 3 章。

**执行模式**：由主 agent 直接执行。初始化与导入的交互（资产清点、缺口确认、落地决策）由主 agent 完成；生成任务由主 agent 加载对应子 skill 执行。不得派发子 agent 执行 skill 生成任务。

## 操作步骤（规程全文内联）

### Step 0：导入/续写模式

> 触发条件（满足任一即可）：一、用户说"导入/续写/已有/接续/迁移"；二、执行 Step 1 初始化时检测到 `正文/` 已有文件；三、项目目录已有内容但没有 `状态.md`。
> 原则：本技能只负责调度，不负责内容生成，具体做资产清点、文件归位、缺口分析、补跑调度四项；深度内容转换由主 agent 加载对应 skill 完成。

**0a 资产扫描**：用 LS 扫描项目目录（或用户指定的源目录），输出原始资产清单，每项注明文件名、位置与一句话内容摘要。

**0b 资产归位**（只做归位，不做内容结构标准化）：

| 用户文件（模糊匹配） | → 标准位置 | 标准文件名 | 对应位 |
|:--|:--|:--|:--|
| *意图*/*方向*/*想法*/用户口述 | `调研采风/` | 用户意图.md / 灵感收集.md | 1 |
| *调研*/*市场*/*赛道*/*排行* | `调研采风/` | 市场校准.md / 赛道调研.md | 1 |
| *采风*/*资料收集*/*质感*/*原型*/*世界观素材* | `调研采风/采风/` | {定向}-{主题}.md | 1 |
| *文风*/*DNA*/*笔触*/*风格* | `文风dna/` | 文风锚定.md | 1 |
| *decon*/*拆书*/*力量分析* | `调研采风/` | decon-lite-{书名}.md | 1 |
| *立意*/*种子*/*创意*/*立项* | `立项/` | 涌现立项卡.md | 1 |
| *设定*/*装配*/*力量体系*/*世界观*/*境界* | `立项/` | 世界装配单.md | 1.5 |
| *设定包*/*下载物*/*源书*/*参考答案* | `原始资料/` | 保留原名 | 1 |
| *章纲*/*叙事原子* | `章纲/` | ch{NNN}-章纲.md | 2a |
| *正文*/*章节*/ch*/第*章 | `正文/` | ch{NNN}.txt | 2b |
| *章日志*/*本章记录* | `剧情日志/` | ch{NNN}.md | 2c |
| *账本*/*全书日志*/*快照*/*进度* | `剧情日志/` | 涌现账本.md | 2c |
| *草稿*/*试写*/*废稿* | `草稿/` | 保留原名 | — |

> 涌现流不建 `设计库/人物库/剧情库`。遇到 snow/灯塔 项目的复杂设定资产（世界全书、力量体系、角色库、卷纲等）时，**不拆解归位，整体存入 `原始资料/` 存档备查**，涌现循环不消费这些资产；需要用时再从内容模板库重新选取装配。

操作方式：匹配不上的归入"未分类资产"并询问用户映射关系；.docx 等异构格式先用 Read 读取内容，再用 Write 写入标准位置与标准文件名；正文统一编号（`第一章.txt`、`chapter1.md` 统一编号为 `正文/ch001.txt`）；询问用户是否保留原文件。

**文件来源标记**（每个归位文件均须记入资产清单）：

| 来源标记 | 含义 | 后续处理 |
|:--|:--|:--|
| `user-original` | 用户已有文件，直接归位 | ⚠️需校验 |
| `pipeline-relocated` | pipeline 做了格式转换（.docx 转为 .md 等） | ⚠️需校验 |
| `skill-generated` | 对应 skill 正向产出 | 正常消费 |

**0c 缺口分析**：归位完成后，对照涌现依赖链逐位检查（就绪判定标准为文件存在，以文件系统为准）：

| 位 | 就绪判定 |
|:--|:--|
| 1 | `立项/涌现立项卡.md`（甲方文档：要写什么、读者图什么、卖点、主角立身一句话、文风承诺、模糊灯塔） |
| 1.5 | `立项/世界装配单.md`（从内容模板库选配的世界底子：力量体系、世界观、金手指、身份） |
| 2a | `章纲/ch{NNN}-章纲.md`（NNN 为下一章待写章节号；前三章章纲含开篇三要素、情绪坐标与峰值标注） |
| 2b | `正文/ch*.txt`（current_chapter 取最大编号加一） |
| 2c | `剧情日志/涌现账本.md`（当前态、悬着的线与已长出的设定） |

进度检测：`正文/` 内有文件时，提取最大章节号，current_chapter 取下一章待写编号。质量来源检测：user-original 与 pipeline-relocated 标为 ⚠️需校验；skill-generated 标为 ✅。最终输出缺口报告。

**0d 落地 Phase 决策**（依据缺口报告与正文进度）：

| 条件 | mode | 落地位 | 说明 |
|:--|:--|:--|:--|
| 正文有，账本有 | resume | 2a 或 2b | 状态完整：下一章章纲已排则进入 2b，未排则进入 2a |
| 正文有，账本缺 | resume | 先由 0f 调度 review reconstruct，再进入 2a 或 2b | 需补账本 |
| 正文无，章纲有 | import | 2a（outline） | 缺账本，可先执行 review 重建，再续写 |
| 正文无，立项卡有，装配单有 | import | 2a（outline） | 缺章纲 |
| 正文无，立项卡有，装配单缺 | import | 1.5（state） | 缺装配单 |
| 全无 | fresh | 1（seed） | 执行 Step 1 初始化 |

→ 向用户展示资产清单（含来源标记）、缺口报告、落地 Phase 建议与补跑建议清单（0f）；**用户确认后**进入 0e。

**0e 状态文件重建**：`状态.md` 不存在时，按「状态.md 模板」创建；已存在时，用 SearchReplace 更新。字段包括 mode、phase、current_chapter 与就绪态，其中就绪态按 0c 的结论标注 [x]。展示面板为可选项：老板要求时，按 `templates/项目总控.html` 套值导出。

**0f 调度 skill 补跑**（本技能只识别缺口、调度与汇报，不自行做内容转换）：

| 缺口类型 | 调度 skill | 做什么 |
|:--|:--|:--|
| 有正文，缺章日志或账本 | pop-review reconstruct | 批量回溯审核：采样逐章生成章日志，并重建账本 |
| 缺立项卡 | pop-emergent-seed | 读取已有文件，校验并补全，产出标准格式 |
| 缺装配单 | pop-emergent-state | 读取立项卡，从内容模板库选配，产出世界装配单 |
| 缺章纲 | pop-outline | 从账本、装配单与立项卡排 1 至 3 章章纲 |

- review reconstruct 采样规则：不超过 10 章时全部审核；11 至 30 章时审核最近 5 章，并每 5 章取 1 章；超过 30 章时审核最近 5 章与第一章，并每 10 章取 1 章。产出 `剧情日志/ch{NNN}.md` 与 `剧情日志/涌现账本.md`。
- 补跑建议清单：每个文件一行，写明文件名、来源、状态与建议，建议内容为"正常消费"或"补跑某 skill"。用户有三种选择：正常接续、按需补跑、全量补跑。

**Step 0 质量检查**：原始资产清单已生成；归位完成（含来源标记）；缺口报告已生成；落地 Phase 已经用户确认；`状态.md` 已创建或更新；补跑建议清单已展示。

### Step 1：初始化（fresh 模式）

**前置检测**：执行任何创建操作前，先用 LS 扫描。`正文/` 有章节文件时，跳转「Step 0 导入/续写」；目录为空或仅有 `状态.md` 时，继续本步。

1. **创建目录（一次性）**：`调研采风/`（含 `采风/`）、`原始资料/`、`立项/`、`章纲/`、`正文/`、`剧情日志/`、`文风dna/` 与 `草稿/`。创建后用 LS 自检全部存在；缺一即判定初始化失败，补建后方可继续。（不建 `设计库/人物库/剧情库`，因为涌现流不产复杂设定文档；世界底子为 `立项/世界装配单.md`，长出的设定归入账本。）
2. **创建 `状态.md`**：按「状态.md 模板」写入项目根（mode: fresh、phase: init、current_chapter: ch000，全部就绪态标 [ ]）；再简单创建 README.md（项目信息、目录说明与指向 `状态.md` 的说明）。
3. **展示面板（可选）**：老板要求时，按 `templates/项目总控.html` 套用 `状态.md` 的值导出；agent 只写 `状态.md`，不读 html。
4. **首次对话引导**：用户第一次触发且没有项目时，先输出 `references/onboarding-guide.md` 的引导语（声明本次为功能介绍，未执行任务）；用户已明确要开始写作时可跳过。
5. **路由至 Phase 1**：加载 pop-emergent-seed，按其 SKILL.md 执行（甲方文档：要写什么、读者图什么、卖点、主角立身一句话、文风承诺、模糊灯塔）。立项需要市场底子时，触发 pop-snow-research 查底子（跨系列只读调用），结果写入 `调研采风/采风/`。seed 完成后加载 pop-emergent-state 装配世界底子（从内容模板库选配，写入 `立项/世界装配单.md`），随后进入写章循环。

**Step 1 质量检查**：目录齐全，`状态.md` 已存档；README 已存档。

## 事实优先级裁决链（全线统一）

正文、章纲、账本与审查遇到**事实冲突**时，全线（seed、state、outline、write、review）按以下序列取证，**不得反向覆盖更高权位的事实**：

| 权重 | 事实源 | 说明 |
|:--:|:--|:--|
| 最高 | **用户本轮临时要求** | 可覆盖既有事实，但必须**显式指出其与既有事实的冲突并记录改法**，不得静默覆盖 |
| 2 | **已发布正文** | 明确写出的，最高文字权威 |
| 3 | **账本当前态**（涌现账本） | 已发生事实的唯一承载，包括当前态、悬着的线与已长出的设定 |
| 4 | **章日志**（最新章节事实提取） | 正文驱动的最近事实 |
| 5 | **世界装配单** | 装配的世界底子（力量体系、世界观、金手指）。装配件如与正文冲突，以正文为准，冲突记入账本 |
| 6 | **轻量章纲** | 叙事计划，优先级最低 |

> 裁决原则：叙事计划（轻量章纲）低于已落地事实（正文、账本与章日志）；用户临时要求权重最高，但**指出冲突是义务**，即使照办也要让老板与后续环节知道改了什么、为什么改。涌现流没有世界书、角色卡与卷级大纲；世界底子即装配单，事实以正文和账本为准。

## 涌现循环状态机（路由参照）

### 每章收束（写一章的完整循环，防止路由走错）

每一章严格循环，**outline 写章纲永远在 write 之前，不得跳过**：

```
outline 章纲（查剧情-情绪打分表定本章情绪坐标→反向设计剧情）→ write 正文(ch{NNN}.txt) → write 自环复查（结构层五项＋语义七项＋字数与去 AI 味脚本，全过才交）→ review 三件事 → 回到 outline 写 ch{NNN+1} 章纲 → …
```

- **review 三件事**：一、确认本章正文满意（定稿，未定稿不入库）；二、生成 `剧情日志/ch{NNN}.md`（事件源，只增不改）；三、回填 `剧情日志/涌现账本.md`（当前态，只记活跃项；新事实即设定从账本中长出，长出的设定须标注"从内容模板库选了哪个"）。
- **write 的输入与自环（按老板的流程图定，本文原缺）**：
  - **写作输入三条**：`章纲/ch{NNN}-章纲.md`、**`正文/ch{NNN-1}.txt`（前馈，必读）**、**`文风dna/文风锚定.md`（外挂，项目内存在时读；由 pop-dna-style 产出）**。
  - **前馈边的作用**：与章日志分工互补——章日志记上一章讲了何事，上一章正文记其如何讲述、停在何处、气韵为何；本章须在文气上无缝衔接。**少了这条边，会重复上一章的动作与比喻，且语气接不上。**
  - **底线约束两条**：`剧情日志/涌现账本.md`（不得与已发生事实冲突）与 `立项/世界装配单.md`（力量体系、世界观、金手指、身份四项只能取自其中）。这两项是约束，不是写作输入。
  - **自环**：正文存档后，对**本章正文**自己再过一遍——结构层五项＋语义七项＋字数脚本＋去 AI 味脚本，全过才交 review。**review 不替 write 补足字数，也不替它过自环。**
  - 文风锚定文件缺失时，按 `pop-write` §0 表兜底（涌现线固定用其 `references/夜无疆.md`，另加立项卡内的文风承诺）。
- **产物归谁消费**：review 产出的章日志与账本，喂给**下一轮的 outline** 当章纲依据，**不直接喂给 write**；write 永远跟在章纲之后，不得跳过 outline 从日志直接开写。
- **对应状态机位**：`2a(outline) → 2b(write) → 2c(review) → 回 2a(下一批章纲)`。

新书流程：`init → 1(seed) → 1.5(state) → 写章循环`。其中**前三章章纲（2a）按开篇三要素排**：outline 写 ch001-ch003 章纲时，按「落差→特权→小账+新标」设计并标注情绪坐标（峰值）；前三章不是空着硬排，也不脱离滚动循环单独执行。前三章已写完的项目（导入或续写）跳过该设计，只做开篇复盘诊断。

| 位 | 做什么 | skill | 产出 | 完成后进入下一位 |
|:--|:--|:--|:--|:--|
| 1 | 甲方文档（要写什么、读者图什么、卖点、主角立身一句话、文风承诺、模糊灯塔） | pop-emergent-seed | `立项/涌现立项卡.md` | 1.5 |
| 1.5 | 设定装配（从内容模板库选配力量体系、世界观、金手指与身份） | pop-emergent-state | `立项/世界装配单.md` | 2a |
| 2a | 情绪章纲（接下来 1 至 3 章；查剧情-情绪打分表定本章情绪坐标（峰值），再反向设计剧情；前三章含开篇三要素） | pop-outline | `章纲/ch{NNN}-章纲.md` | 2b |
| 2b | 正文写作（每章 2000 至 2500 字）。**写作输入三条**：`章纲/ch{NNN}-章纲.md`、`正文/ch{NNN-1}.txt`（前馈，必读）、`文风dna/文风锚定.md`（缺则用 pop-write 的 `references/夜无疆.md` ＋立项卡文风承诺）。**底线约束两条**：`剧情日志/涌现账本.md`、`立项/世界装配单.md`。写完**自环复查**（结构层五项＋语义七项＋字数与去 AI 味脚本）全过才交 | pop-write | `正文/ch{NNN}.txt` | 2c |
| 2c | 审核与存档（PASS 或 REJECT；含情绪达标核验） | pop-review | `剧情日志/ch{NNN}.md` 与 `剧情日志/涌现账本.md` | PASS 则进入 2a 下一批章纲；REJECT 则退回 2b 重写本章 |
| 3 | 阶段性回看（每 N 章或一个故事弧后） | pop-review | 回看报告（账本、情绪点兑现与方向校准） | 回 2a |

**阶段性回看**：每写完一个故事弧（约 5 至 10 章）或老板要求时，由 pop-review 产出回看报告：对照模糊灯塔检查方向是否偏离、情绪点兑现情况（峰值达成率），以及账本里长出哪些设定成了新的稳定依据。回看不是大改，只是校准方向，继续滚动。

**状态.md 更新协议**（谁执行谁更新，只更新涉及字段，不全量替换）：

| 时机 | 更新 |
|:--|:--|
| 各 skill 完成 | phase 推进到状态机的下一位，更新 updated_at，将就绪态对应项标 [x]，并在最近产出中追加一行 |
| seed 完成 | 另更新书目（book_name、one_line） |
| state 完成 | 另更新就绪态中的"装配单[x]" |
| outline/write/review 每章 | current_chapter 加一（review PASS 后），phase 在 2a、2b、2c 之间流转 |
| 阶段性回看 | phase 置为 3，回看后回到 2a |

本技能只在初始化与导入时写 phase；日常推进由各 skill 完成后按本表更新。

## 存档质量检查（deai_gate.py，本包 scripts 统一管理）

去 AI 味检查脚本归本包 `scripts/deai_gate.py` 管理（配置外置为 `scripts/deai_profiles.json`，纯标准库实现），两套 profile 服务全管线的存档质量。**各 skill 存档后自行执行，不进入 LLM，也不派子 agent。**

| profile | 服务对象 | 性质 | 检测面 | 调用 |
|:--|:--|:--|:--|:--|
| `body`（默认） | write 正文（`正文/ch{NNN}.txt`） | **打回检查**：FAIL 必须清零才算存档完成 | 套话硬模板约 120 条、软密度约 28 组、结构统计与工具痕迹四层，阈值按人书基线校准 | `python skills/pop-emergent-pipeline/scripts/deai_gate.py 正文/ch{NNN}.txt --fix --json` |
| `doc` | 非正文文档（seed 立项卡、state 装配单、research 调研、outline 章纲、review 章日志与账本，以及拆书、卖点、大纲类） | **报告检查**：只给出 WARN 与定位，不打回 | 黑话（hard 实锤与 soft 风格分层）、套路句式、空腔段与生成器残留；分号、破折号、括号、列举行、工程 emoji 标记与 0% 对话一律放行 | `python skills/pop-emergent-pipeline/scripts/deai_gate.py <文件或目录> --profile doc --json`（目录加 `-r` 递归，含聚合热点统计） |

**边界三条**：
1. 工程标签（【锚】、养成刻度、卷末边界等精确技术名）不做去 AI 化改写；去 AI 味只作用于叙事主体。
2. 自动修仅限零风险机械项，共 36 类，包括英文标点、HTML 残留与零宽字符等；滥用类只上报，不自动修改。
3. `doc` 的 WARN 清单由存档 agent 按上下文判断：装腔之词改为大白话，行话正常使用可放行（回复中注明放行理由）；**词库类文档的自指命中项豁免**。

**阈值与词库调校**：只改 `scripts/deai_profiles.json` 即可，不改代码；改后须执行回归（负面样例高召回、人书零误杀、wiki 与 skills 误伤增量可控），通过后才生效。
