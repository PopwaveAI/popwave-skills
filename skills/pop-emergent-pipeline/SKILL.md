# pop-emergent-pipeline

> 涌现流工作台。当前版本 v2.0.0（2026-10-19：调度层改造——去掉 phase 状态机，改为模块路由 + 依赖检查 + 状态总表）。
> 技能 id 与文件名保留 `pipeline`，避免全库跨包引用大改。

---

## 这套工作台怎么运转

涌现流是"先写后补、写中长设定"：立项只定甲方文档，设定从模板库装配，剧情靠章纲滚动，写完再收束进账本。

工作台只做四件事：

1. 建项目或导入旧稿。
2. 维护 `状态.md`（项目总表）。
3. 按用户当前要做的事路由到模块。
4. 开工前做依赖检查，缺什么报什么。

**没有 phase。** 唯一约束来自依赖：写正文要有章纲，写章纲要有立项卡与装配单，审稿要有正文。

---

## 涌现流四原则

1. **seed 是甲方文档**：只定要写什么、读者图什么、卖点、主角立身一句话、文风承诺、模糊灯塔六项。
2. **state 是装配，不是创造**：设定从内容模板库选配，不凭空发明。
3. **plot 环节砍掉**：不设计长线剧情，没有卷级排期。
4. **情绪标准先行**：章纲先查剧情-情绪打分表定情绪坐标，再反向设计剧情。

## 职责范围

| 职责 | 说明 |
|:--|:--|
| 一次性初始化（fresh） | 建目录，写 `状态.md` |
| 一次性导入/续写（import/resume） | 扫资产、归位、查缺口、定当前模块、重建状态、调度补跑 |

| 路由 | 按用户说法直接选 skill |
| 依赖检查 | 开工前查前置文件，缺则补或显式降级 |

**边界**：工作台不写正文、不做内容转换、不常驻。

## 路由表

| 用户说 | 直接进 | 开工前检查 |
|:--|:--|:--|
| 写第 N 章 / 继续写 | `pop-write` | `章纲/ch{NNN}-章纲.md` |
| 写章纲 / 排接下来几章 | `pop-outline` | 立项卡、装配单、账本 |
| 装配设定 / 换个力量体系 | `pop-emergent-state` | 立项卡、内容模板库 |
| 审这一章 / 找问题 | `pop-review` | `正文/ch{NNN}.txt` |
| 查资料 | `pop-snow-research` | 无 |
| 新建项目 / 导入 / 续写 | 本工作台 | 见 Step 0 / Step 1 |

**日常路由不经过本技能**：用户说"写第 5 章"，主 agent 读 `状态.md`，直接加载 `pop-write`。

## 依赖检查

| 目标 | 最低前置 | 缺了怎么办 |
|:--|:--|:--|
| 写正文 | 本章章纲 | 补章纲；或降级直写，记录"无章纲" |
| 写章纲 | 立项卡、装配单、账本 | 补 seed/state/review reconstruct；或降级排章纲 |
| 装配设定 | 立项卡 | 补 seed；或按用户口述装配，标"待回填" |
| 审稿 | 正文 | 先写正文 |
| 阶段性回看 | 账本与最近正文 | 补账本；或缩小回看范围 |

**依赖检查不是阶段闸**：只回答"现在做这件事，手上够不够"。

## 降级模式

用户坚持跳步时，允许，但必须记录：

- `状态.md` 的「降级记录」写：跳了哪一步、欠什么、预计什么时候补。
- 本章章日志或账本标 `降级:无章纲` / `降级:无装配单`。
- 下一次进入相关模块时，优先补欠账。

**禁止静默降级**。

---

## 推荐节奏（不是硬性状态机）

```
立项 → 设定装配 → 章纲（1-3 章）→ 正文 → 审稿 → 回填账本
→ 下一批章纲 → … → 阶段性回看 → 继续滚动
```

允许：

- 从任意一环进入，只要依赖检查通过。
- 先写一章试味，再回头补装配单。
- 只改设定、只审一章、只补账本。
- 阶段性回看按故事弧或老板要求触发，不按固定章数强制。

## 操作步骤

### Step 0：导入与续写

**0a 资产扫描**：LS 扫目录，列文件名、位置、一句话内容。

**0b 资产归位**：

| 用户文件 | 归到 |
|:--|:--|
| 意图、方向、市场调研 | `调研采风/` |
| 采风、资料、原型 | `调研采风/采风/{定向}-{主题}.md` |
| 文风、DNA | `文风dna/文风锚定.md` |
| 立项、种子、创意 | `立项/涌现立项卡.md` |
| 设定、装配、力量、世界观 | `立项/世界装配单.md` |
| 设定包、源书、参考答案 | `原始资料/` |
| 章纲 | `章纲/ch{NNN}-章纲.md` |
| 正文 | `正文/ch{NNN}.txt` |
| 章日志 | `剧情日志/ch{NNN}.md` |
| 账本、全书日志、快照 | `剧情日志/涌现账本.md` |
| 草稿、试写、废稿 | `草稿/` |

**Snow/灯塔项目的复杂设定资产**（世界画像、世界法则、角色库、卷纲等）：不拆解，整体存入 `原始资料/` 备查；涌现循环不消费。

**0c 缺口分析**：按文件存在标就绪态，输出缺口报告与来源标记。

**0d 定当前模块**：

| 已有 | 落到 |
|:--|:--|
| 正文、账本齐 | `pop-write` 或 `pop-outline` |
| 正文有、账本缺 | 先 `pop-review reconstruct` |
| 章纲有、账本缺 | `pop-outline` 或先 reconstruct |
| 立项卡有、装配单缺 | `pop-emergent-state` |
| 全无 | `pop-emergent-seed` |

**0e 状态重建**：按模板写 `状态.md`；旧 phase 映射为 `focus`。

**0f 补跑调度**：

| 缺口 | 调度 |
|:--|:--|
| 有正文、缺章日志/账本 | `pop-review reconstruct` |
| 缺立项卡 | `pop-emergent-seed` |
| 缺装配单 | `pop-emergent-state` |
| 缺章纲 | `pop-outline` |
| 缺采风 | `pop-snow-research` |

补跑建议逐文件一行，用户三选：正常接续、按需补跑、全量补跑。

### Step 1：初始化

1. 建 11 个一级目录：`调研采风/`（含 `采风/`）、`原始资料/`、`立项/`、`设计库/`、`人物库/`、`剧情库/`、`章纲/`、`正文/`、`剧情日志/`、`文风dna/`、`草稿/`。`设计库/`、`人物库/`、`剧情库/` 建空待长。
2. LS 自检，缺一补建。
3. 写 `状态.md`，`mode: fresh`，`focus: 未定`，模块就绪全 `[ ]`。
4. 问三项：现在手上有什么、目标是什么、想写多长。
5. 按第 4 项直接路由，不输出完整流程说明。

## 每章写作的输入与自环

**写作输入三条**：

- `章纲/ch{NNN}-章纲.md`
- `正文/ch{NNN-1}.txt`（前馈，必读）
- `文风dna/文风锚定.md`（存在时读；缺失按 `pop-write` §0 兜底）

**底线约束两条**：

- `剧情日志/涌现账本.md`：不得与已发生事实冲突。
- `立项/世界装配单.md`：力量、世界观、金手指、身份只能取自其中。

**自环复查**：正文存档后，write 自己对本章再过一遍结构层五项＋语义七项＋字数脚本，全过才交 review。review 不替 write 补字数，也不替它过自环。

## 存量项目兼容

- 旧 `状态.md` 的 `phase` 字段映射为 `focus`。
- 旧目录与文件名按 0b 归位；不覆盖同名不同源文件。
- 迁移只动路径与文件名，不动正文与章日志内容。
- 认线：读 `line` 或 phase 写法；读不出按上游文件判，仍判不出问用户。
