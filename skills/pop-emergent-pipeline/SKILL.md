# pop-emergent-pipeline

> 涌现流总控：**在 snow 雪花流基础上做减法**——不做复杂长线设计，只留 `seed(甲方文档) → state(设定装配) → outline(情绪章纲) → write(正文) → review(章日志+账本) → 再 outline` 轻循环。设定不创造只装配（从内容模板库选），剧情情绪标准先行（查剧情-情绪打分表定本章情绪坐标再反向设计）。当前版本 v1.2.0（剧情-情绪打分表结构重构承接——峰值规则：每章≥2个峰值点、普通章5-6为主、8分稀缺须铺垫支撑），完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

### 心智前置·意识层（贯穿本 skill 与全流程）

动笔/定稿前自问：本产出要更好，还需要看过哪些候选？当前信息够不够？有更优选项没探索？

- **Know-Gap**：先显式列出"要更好需见过哪些候选面"，再列已覆盖，缺口=差值；缺口≥1 个未覆盖维度才触发取材，缺了取、别硬写。
- **Pack**：缺口足够才取材，query 自生成；来源 **wiki 站 https://wiki.popwave.cn** 居先、网络补齐；单环节 ≤1 轮 / ≤5 query / 回传 ≤30KB，超限截断仅留结论区。
- **Worth**：拿本 skill 决策尺对"现有 vs 候选"必给打分表，禁止一句"更优"带过；只端候选/升级版，不越权定终局。
- **Deepen**：产出/候选后自问"这是天花板吗？有更优候选吗？"显著更优才升级再问，上限 2 轮。

取材仅进上下文，升级被采纳才落产出。

## 做什么

| 职责 | 说明 |
|:--|:--|
| 一次性安装（fresh） | 建目录 + 存档 `状态.md`（薄机器状态）+（可选）导出展示面板 + README |
| 一次性导入/续写（import/resume） | 资产扫描→归位→缺口分析→落地Phase→状态重建→补跑调度 |
| 状态文件维护 | `状态.md` = 唯一状态总账，agent 只读写它的状态片段；`项目总控.html` 是仅供老板查看的展示面板，按需导出，**agent 不读 html** |

**日常路由不经此 skill**：用户说"继续写/下一步/写正文/审核"时，主 agent 按「涌现循环状态机」直接选 skill，先读 `状态.md` 取状态片段（mode/phase/current_chapter/就绪态），路由参照=下方「涌现循环状态机」。pipeline 不写正文、不做内容转换、不常驻。

**涌现流四原则（贯穿路由）**：

1. **seed=甲方文档**：立项只锁"要写什么/读者图什么/卖点/主角立身一句话＋文风承诺＋模糊灯塔"——后面所有环节的需求源头，不锁复杂设定。
2. **state=装配不创造**：设定从内容模板库选配（力量体系/世界观结构/金手指/身份结构），不让 agent 凭空发明；写章中长出的新设定继续从库选。
3. **plot 砍掉**：不设计长线剧情，没有卷级排期。
4. **情绪标准先行**：outline 查剧情-情绪打分表定本章情绪坐标（每章 ≥2 个峰值点，普通章 5-6 为主，8 分稀缺须铺垫支撑）→ 反向设计剧情事件；轻量章纲一次排 1-3 章。

**执行模式**：主 agent 直执。初始化/导入交互（资产清点、缺口确认、落地决策）由主 agent 完成；生成任务由主 agent 加载对应子 skill 执行。禁止派发子 agent 执行 skill 生成任务。

## 怎么操作（SOP 全内联）

### Step 0：导入/续写模式

> 触发（任一满足）：①用户说"导入/续写/已有/接续/迁移" ②Step 1 初始化时检测到 `正文/` 已有文件 ③项目目录已有内容但无 `状态.md`。
> 理念：pipeline 是调度员不是制造者。只做资产清点、文件归位、缺口分析、补跑调度；深度内容转换由主 agent 加载对应 skill 完成。

**0a 资产扫描**：LS 扫描项目目录（或用户指定源目录）→ 输出原始资产清单（文件名+位置+内容摘要1句话）。

**0b 资产归位**（只归位，不做内容结构标准化）：

| 用户文件（模糊匹配） | → 标准位置 | 标准文件名 | 对应位 |
|:--|:--|:--|:--|
| *意图*/*方向*/*想法*/用户口述 | `调研采风/` | 用户意图.md / 灵感收集.md | 1 |
| *调研*/*市场*/*赛道*/*排行* | `调研采风/` | 市场校准.md / 赛道调研.md | 1 |
| *采风*/*资料收集*/*质感*/*原型*/*世界观素材* | `调研采风/采风/` | {定向}-{主题}.md | 1 |
| *文风*/*DNA*/*笔触*/*风格* | `文风dna/` | 文风锚定.md | 1 |
| *decon*/*拆书*/*力量分析* | `调研采风/` | decon-lite-{书名}.md | 1 |
| *立意*/*种子*/*创意*/*立项* | `立项/` | 涌现立项卡.md | 1 |
| *设定*/*装配*/*力量体系*/*世界观*/*境界* | `立项/` | 世界装配单.md | 1.5 |
| *设定包*/*下载物*/*源书*/*参考答案* | `原始资料/` | 保留原名 | 1 |
| *章纲*/*叙事原子* | `章纲/` | ch{NNN}-章纲.md | 2a |
| *正文*/*章节*/ch*/第*章 | `正文/` | ch{NNN}.txt | 2b |
| *章日志*/*本章记录* | `剧情日志/` | ch{NNN}.md | 2c |
| *账本*/*全书日志*/*快照*/*进度* | `剧情日志/` | 涌现账本.md | 2c |
| *草稿*/*试写*/*废稿* | `草稿/` | 保留原名 | — |

> 涌现流不建 `设计库/人物库/剧情库`——导入 snow/灯塔 项目的复杂设定资产（世界全书/力量体系/角色库/卷纲等）时，**不拆解归位，整体入 `原始资料/` 存档备查**，涌现循环不消费它们；需要用时从内容模板库重选装配。

操作：匹配不上的归"未分类资产"询问用户映射；.docx 等异构格式 Read 内容→Write 标准位置标准文件名；正文统一编号（`第一章.txt`/`chapter1.md`→`正文/ch001.txt`）；询问用户是否保留原文件。

**文件来源标记**（每个归位文件记入资产清单）：

| 来源标记 | 含义 | 后续处理 |
|:--|:--|:--|
| `user-original` | 用户已有文件，直接归位 | ⚠️需校验 |
| `pipeline-relocated` | pipeline 做了格式转换（.docx→.md 等） | ⚠️需校验 |
| `skill-generated` | 对应 skill 正向产出 | 正常消费 |

**0c 缺口分析**：归位完成后对照涌现依赖链逐位检查（就绪判定=文件存在，查文件系统）：

| 位 | 就绪判定 |
|:--|:--|
| 1 | `立项/涌现立项卡.md`（甲方文档：要写什么/读者图什么/卖点/主角立身一句话＋文风承诺＋模糊灯塔） |
| 1.5 | `立项/世界装配单.md`（从内容模板库选配的世界底子：力量体系/世界观/金手指/身份） |
| 2a | `章纲/ch{NNN}-章纲.md`（NNN=下一章待写；前3章章纲含开篇三要素＋情绪坐标＋峰值标注） |
| 2b | `正文/ch*.txt`（current_chapter=最大编号+1） |
| 2c | `剧情日志/涌现账本.md`（当前态+悬着的线+已长出设定） |

进度检测：`正文/` 有文件→提取最大章节号，current_chapter=下一章待写。质量来源检测：user-original/pipeline-relocated→⚠️需校验；skill-generated→✅。输出缺口报告。

**0d 落地Phase决策**（缺口报告+正文进度）：

| 条件 | mode | 落地位 | 说明 |
|:--|:--|:--|:--|
| 正文有+账本有 | resume | 2a 或 2b | 状态完整：下一章章纲已拼→2b，未拼→2a |
| 正文有+账本缺 | resume | 先 0f 调度 review reconstruct→2a/2b | 需补账本 |
| 正文无+章纲有 | import | 2a（outline） | 缺账本可先跑 review 重建再续 |
| 正文无+立项卡有+装配单有 | import | 2a（outline） | 缺章纲 |
| 正文无+立项卡有+装配单缺 | import | 1.5（state） | 缺装配单 |
| 全无 | fresh | 1（seed） | 走 Step 1 初始化 |

→ 向用户展示：资产清单（含来源标记）+缺口报告+落地Phase建议+补跑建议清单（0f），**用户确认后**进 0e。

**0e 状态文件重建**：`状态.md` 不存在→按「状态.md 模板」创建；已存在→SearchReplace 更新。字段：mode/phase/current_chapter/就绪态按 0c 标 [x]。展示面板可选：老板要求时按 `templates/项目总控.html` 套值导出。

**0f 调度skill补跑**（pipeline 只识别缺口+调度+汇报，不自行做内容转换）：

| 缺口类型 | 调度skill | 做什么 |
|:--|:--|:--|
| 有正文+缺章日志/账本 | pop-emergent-review reconstruct | 批量回溯审核：采样逐章章日志+账本重建 |
| 缺立项卡 | pop-emergent-seed | 读已有文件→校验+补全→标准格式 |
| 缺装配单 | pop-emergent-state | 读立项卡→从内容模板库选配→世界装配单 |
| 缺章纲 | pop-emergent-outline | 从账本/装配单/立项卡排 1-3 章章纲 |

- review reconstruct 采样：≤10章全审 / 11-30章最近5章+每5章取1章 / >30章最近5章+第一章+每10章取1章。产出 `剧情日志/ch{NNN}.md`+`剧情日志/涌现账本.md`。
- 补跑建议清单：逐文件一行——文件名：来源=…，状态=…，建议=正常消费/补跑XX skill。用户三选：正常接续/按需补跑/全量补跑。

**Step 0 质量门**：原始资产清单已生成｜归位完成（含来源标记）｜缺口报告已生成｜落地Phase经用户确认｜状态.md 已创建/更新｜补跑建议清单已展示。

### Step 1：初始化（fresh模式）

**前置检测**：执行任何创建前先 LS 扫描——`正文/` 有章节文件→跳转「Step 0 导入/续写」；目录为空或仅有 `状态.md`→继续本步。

1. **创建目录（一次性）**：`调研采风/`（含 `采风/`）+ `原始资料/` + `立项/` + `章纲/` + `正文/` + `剧情日志/` + `文风dna/` + `草稿/`。创建后 LS 自检全部存在，缺一=初始化失败，补创后才继续。（不建 `设计库/人物库/剧情库`——涌现不产复杂设定文档；世界底子=立项/世界装配单.md，长出的设定=账本。）
2. **创建 状态.md**：按「状态.md 模板」写入项目根（mode: fresh / phase: init / current_chapter: ch000 / 全部就绪态标 [ ]）；再简建 README.md（项目信息+目录说明+指向 状态.md）。
3. **展示面板（可选）**：老板要求时按 `templates/项目总控.html` 套 状态.md 值导出；agent 只写 状态.md，不读 html。
4. **首次对话引导**：用户第一次触发且无项目时，先输出 `references/onboarding-guide.md` 引导语（声明本次为功能介绍未执行任务）；用户已明确要开做可跳过。
5. **路由 Phase 1**：加载 pop-emergent-seed 按其 SKILL.md 执行（甲方文档：要写什么/读者图什么/卖点/主角立身一句话＋文风承诺＋模糊灯塔）。立项需要市场底子时，触发 pop-snow-research 查底子（跨系列只读调用），落 `调研采风/采风/`。seed 完成后加载 pop-emergent-state 装配世界底子（从内容模板库选配，落 `立项/世界装配单.md`），再进写章循环。

**Step 1 质量门**：目录齐全+状态.md 存档｜README 存档。

## 贯穿级·事实优先级裁决链（全线统一）

正文/章纲/账本/审查遇到**事实冲突**时，全线（seed/state/outline/write/review）按以下序列取证，**禁止倒着覆盖更高权位**：

| 权重 | 事实源 | 说明 |
|:--:|:--|:--|
| 最高 | **用户本轮临时要求** | 可覆盖既有事实，但必须**显式指出其与既有事实的冲突、记录改法**，不静默覆盖 |
| 2 | **已发布正文** | 明确写出的，最高文字权威 |
| 3 | **账本当前态**（涌现账本） | 已发生事实的唯一承载：当前态/悬着的线/已长出设定 |
| 4 | **章日志**（最新章节事实提取） | 正文驱动的最近事实 |
| 5 | **世界装配单** | 装配的世界底子（力量体系/世界观/金手指）——装配件如与正文冲突，正文为准，冲突记入账本 |
| 6 | **轻量章纲** | 叙事计划，优先级最低 |

> 裁决原则：叙事计划（轻量章纲）低于已落地事实（正文/账本/章日志）；用户临时要求权重最高，但**指出冲突是义务**——即使照办也让老板与后续环节知道改了什么、为什么改。涌现流没有世界书/角色卡/卷级大纲——世界底子=装配单，事实以正文和账本为准。

## 涌现循环状态机（路由参照）

### 每章收束（写一章的完整一圈 · 防止路由绕错）

每一章严格循环，**outline 写章纲永远在 write 之前，不许跳**：

```
outline 章纲（查剧情-情绪打分表定本章情绪坐标→反向设计剧情）→ write 正文(ch{NNN}.txt) → review 三件事 → 回到 outline 写 ch{NNN+1} 章纲 → …
```

- **review 三件事**：①确认本章正文满意（=定稿，未定稿不入库）②生成 `剧情日志/ch{NNN}.md`（事件源·只增不改）③回填 `剧情日志/涌现账本.md`（当前态·只记活跃·新事实=设定从账本长出来，长出的设定标"从内容模板库选了哪个"）。
- **产物归谁消费**：review 产出的章日志/账本，喂给**下一轮的 outline** 当章纲依据，**不是直接喂 write**——write 永远跟在章纲之后，不得跳过 outline 从日志直接开写。
- **对应状态机位**：`2a(outline) → 2b(write) → 2c(review) → 回 2a(下一批章纲)`。

新书流程：`init → 1(seed) → 1.5(state) → 写章循环`。其中**前3章章纲（2a）按开篇三要素排**：outline 写 ch001-ch003 章纲时，按「落差→特权→小账+新标」设计并标注情绪坐标（峰值）——前3章不是空着硬排，也不脱离滚动循环单独跑。前3章已写的项目（导入/续写）跳过该设计，只做开篇复盘诊断。

| 位 | 干什么 | skill | 产出 | 完成→下一位 |
|:--|:--|:--|:--|:--|
| 1 | 甲方文档（要写什么/读者图什么/卖点/主角立身一句话＋文风承诺＋模糊灯塔） | pop-emergent-seed | `立项/涌现立项卡.md` | 1.5 |
| 1.5 | 设定装配（从内容模板库选配力量体系/世界观/金手指/身份） | pop-emergent-state | `立项/世界装配单.md` | 2a |
| 2a | 情绪章纲（接下来 1-3 章；查剧情-情绪打分表定本章情绪坐标（峰值）→反向设计剧情；前3章含开篇三要素） | pop-emergent-outline | `章纲/ch{NNN}-章纲.md` | 2b |
| 2b | 正文渲染（2000-2500字/章，固定文风辰东） | pop-emergent-write | `正文/ch{NNN}.txt` | 2c |
| 2c | 审核+存档（PASS/REJECT；含情绪达标核验） | pop-emergent-review | `剧情日志/ch{NNN}.md`+`剧情日志/涌现账本.md` | PASS→2a下一批章纲；REJECT→2b重写本章 |
| 3 | 阶段性回看（每 N 章/一个故事弧后） | pop-emergent-review | 回看报告（账本+情绪点兑现+方向校准） | 回 2a |

**阶段性回看**：每写完一个故事弧（约 5-10 章）或老板要求时，pop-emergent-review 产回看报告：对照模糊灯塔看方向偏没偏、情绪点兑现怎么样（峰值达成率）、账本里长出哪些设定成了新锚。回看不是大改——只是校准方向，继续滚动。

**状态.md 更新协议**（谁干活谁更新，只更新涉及字段，不全量替换）：

| 时机 | 更新 |
|:--|:--|
| 各 skill 完成 | phase 推进到状态机下一位 + updated_at + 就绪态对应项 [x] + 最近产出追加一行 |
| seed 完成 | 另更新书目（book_name/one_line） |
| state 完成 | 另更新就绪态"装配单[x]" |
| outline/write/review 每章 | current_chapter+1（review PASS 后），phase 在 2a/2b/2c 间流转 |
| 阶段性回看 | phase=3，回看后回 2a |

pipeline 只在初始化/导入时写 phase；日常推进由各 skill 完成后按本表更新。

## 存档质量检查（deai_gate.py，本包 scripts 统一管理）

去AI味检查脚本归本包 `scripts/deai_gate.py`（配置外置 `scripts/deai_profiles.json`，纯 stdlib），双 profile 服务全管线存档质量。**各 skill 存档后自跑，不进 LLM、不派子 agent。**

| profile | 服务对象 | 性质 | 检测面 | 调用 |
|:--|:--|:--|:--|:--|
| `body`（默认） | write 正文（`正文/ch{NNN}.txt`） | **打回检查**：FAIL 必须清零才算存档完成 | 套话硬模板~120条/软密度~28组/结构统计/工具痕迹四层，阈值按人书基线校准 | `python skills/pop-emergent-pipeline/scripts/deai_gate.py 正文/ch{NNN}.txt --fix --json` |
| `doc` | 非正文文档（seed 立项卡 / state 装配单 / research 调研 / outline 章纲 / review 章日志账本，及拆书/卖点/大纲类） | **报告检查**：只 WARN+定位，不打回 | 黑话（hard 实锤/soft 风格分层）+套路句式+空腔段+生成器残留；分号/破折号/括号/列举行/工程emoji标记/0%对话一律放行 | `python skills/pop-emergent-pipeline/scripts/deai_gate.py <文件或目录> --profile doc --json`（目录加 `-r` 递归，含聚合热点统计） |

**边界三条**：
1. 工程标签（【锚】/养成刻度/卷末边界等精确技术名）不做去AI化改写——去AI味只作用于叙事主体。
2. 自动修仅限零风险机械项（英文标点/HTML残留/零宽字符等36类）；滥用类只报不自动改。
3. `doc` 的 WARN 清单由存档 agent 按上下文判断：装腔换大白话，行话正常用可放行（回复注明放行理由）；**词库类文档自指命中豁免**。

**阈值/词库调校**：改 `scripts/deai_profiles.json` 即可，不改代码；改后跑回归（负面样例高召回+人书零误杀+wiki/skills 误伤增量可控）再生效。
