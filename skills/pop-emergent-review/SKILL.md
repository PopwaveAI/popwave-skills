# pop-emergent-review

> 涌现流章节验收 + 存档。就三件事：确认本章正文满意（定稿）→ 生成本章日志 → 回填涌现账本。满意判别标准含爽点密度（每章 ≥1 重大爽点、密度目标 ≥2、爽点含发生+反应+影响）。当前版本 v1.0.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

***

## 这是什么

review 是"写完这一章、准备写下一章"之间那道存档关口。它**不审质量**——质量是 write 的事；它只负责把"这一章发生了啥"记下来、把"账本现在该是啥样"更新到最新，让下一章开写之前有可依据的准。

**正文没让用户满意前，不进账本**（还在改的，别记）。

涌现流特有：**review 是"设定从账本长出来"的执行者**——write 临场长出的新设定/新角色/偏离章纲的内容，由 review 核验后落进账本"已长出设定"，成为后续章节不可违背的事实。

## 三件事

| # | 活 | 产出 |
|:--|:--|:--|
| 1 | 确认本章正文满意 | 满意=定稿（不满意→打回，不入库） |
| 2 | 按定稿正文，生成本章日志 | `剧情日志/ch{NNN}.md`（本章档案，只增不改） |
| 3 | 按本章日志，回填涌现账本 | `剧情日志/涌现账本.md`（当前态·只记活跃·replace） |

## 两个产物 + 一个账本

- **本章日志**（=单章档案）：每章一张，只增不改，存"这一章怎么了"（事件源，历史）。
- **涌现账本**：单份 replace，已发生事实的唯一承载——**当前态**（现在在哪／主角此刻）＋**此刻悬着的线**（未收的线，含不可提前吞并的钩子）＋**已长出设定**（写章过程中临场长出的世界碎片/金手指形态/配角——设定从账本长出来）＋**退出区**（已回收钩子／已退场角色／已完结线挪进来，留痕防失联）。不拆分多文件。

> 三条心法：
> 1. 账本**只记活跃**——人物退场/钩子已回收/线已完结，就从"当前态/悬着的线"挪进"退出区"，别再留在当前态；这样它"进得来出得去"，100 章也不臃肿。
> 2. **已长出设定按"够写章用"记**——涌现不做复杂设定，只记写章过程中真正长出来的、后续会再用的；一次性细节（某条街叫啥）不用记，用到了 write 当场再造。
> 3. 账本**不拆分**——当前态就是这一份，靠"只记活跃"压体积，不搞一堆文件。

## 步骤

**第 1 步 确认满意＋去AI味核验**

读本章正文。判断：用户/完成度上，这章算定稿了吗？
- 满意 → 定稿，进第 2 步。
- 不满意 / 还要改 → 打回 write（或告诉用户），**不入库**，结束。

**去AI味核验（收尾检查）**：查上游去AI味结果——①write 交接的正文去AI味结果（正文检查 FAIL 清零）；②outline 章纲的 `去AI味:ch{NNN}-章纲|PASS` / `WARN×N` 结果。章纲缺结果 → review 补跑 `python skills/pop-emergent-pipeline/scripts/deai_gate.py 章纲/ch{NNN}-章纲.md --profile doc --json` 一次（doc 报告检查：WARN 定位自查、机械项 `--fix`），并在对话注明补去AI味；正文去AI味结果缺失 → 在本章日志备注"上游去AI味结果缺失"，提示 write 下章前补跑。报告检查只报不打回，核验不阻塞存档，但必留痕。

**满意判别标准（第 1 步"确认满意"时逐条核，供"定稿/打回"判据，不审文风只审一致性/连续性/设定/爽点）**：

| # | 判别维度 | 判定 |
|:--|:--|:--|
| 1 | **硬状态承接** | 位置/伤势/能力/持有物/信息边界与上章结尾、账本无错位；"突然想到/突然做到"糊过去=不一致 |
| 2 | **行为可信（动机6问）** | 异常行为能由 经历→利益→恐惧→渴望→压力→误判 推出；**只能用"剧情需要"解释=OOC**；**信息越界（角色知道他不该知道的）最严重，优先于性格偏差** |
| 3 | **对白遮名辨人** | 关掉角色名仍能分辨谁在说话（称呼/句长/语气/禁忌）——抽 1-2 段验 |
| 4 | **钩子承接** | 上一章钩子在本章有反馈（回应/推进/误导/压住），章末留新缺口，未提前吞并未到期钩子 |
| 5 | **章末落地改变** | 信息/关系/物理/权力 至少一类落地；**四类皆无=空转章** |
| 6 | **高潮后效** | 本章处大高潮后 1-2 章时，是否写出改变（主线推进/人设成长/关系变化），不能直接跳下一个蓄压 |
| 7 | **爽点密度** | 对照章纲爽点标注逐条核：每章 ≥1 个重大爽点（无爽点章不连续），密度目标 ≥2；爽点须含**发生（事件本身）＋反应（读者情绪落点）＋影响（对状态/剧情的实际改变）**，只写事件不写反应与影响=假爽点；章纲标注的爽点正文没兑现=打回 |

**爽点类型（9类，章纲选1-2）**：战斗胜利/夺宝获资/成长升级/打脸装逼/剧情推进/关系推进/身份跃迁/危机拯救/震撼场面。

**打回意见（四要素格式）**：位置（章节/段落/句子）→ 问题（违反哪条既有事实/信息边界/爽点）→ 严重性（严重/警告/提示）→ 改法（不改变核心剧情的最小修复）。按此给 write，**不替 write 写文、只给方向和最小修法**——通过才入库，最多 2 轮。

**第 2 步 生成本章日志**

按定稿正文写 `剧情日志/ch{NNN}.md`（模板：`templates/chapter-card.tpl.md`）：
1. 时间 · 地点 · 人物
2. 本章剧情（顺一遍，回看用）
3. 这一章定了哪些事（改了后文对不上的重事实）
4. 这一章动了哪些线（`线｜这章干了啥｜线现在走到哪`）
5. 爽点 · 钩子（模板已有字段：爽点类型一句话＋本章留下的钩）

> **write 交接并入**：write 对话回复给【冲突标注/新增事实待核】——review 核验有效性后并入"这一章定了哪些事"，write 只声明不落库，落库以 review 为准。**新长出的设定（世界碎片/金手指形态/新角色）→ 一并进"已长出设定"交接，第 3 步落账本。**

> **字数=消费 write 交接数据**：字数检查已在 write 内收束（word-count.ps1 由 write 存档后自跑，不足自扩写，不交 review 补救）。review 不跑字数脚本，直接把 write 交接的 stdout 原文（`chNNN.txt|汉字N|判定:PASS`）填进本章日志"字数"栏；交接缺失时追问 write，不自己补跑。

> **存档后半步=去AI味**：章日志存档后自跑 `python skills/pop-emergent-pipeline/scripts/deai_gate.py 剧情日志/ch{NNN}.md --profile doc --json`——WARN 定位自查（档案措辞贴事实，装腔换大白话）、机械项 `--fix`，结果一行 `去AI味:ch{NNN}-章日志|PASS` 或 `WARN×N`。

**第 3 步 回填涌现账本**

打开 `剧情日志/涌现账本.md`，按本章日志 replace：
- **当前态**：更新"现在在哪/主角此刻"，给出下一章开写前的准；
- **此刻悬着的线**：新钩子进"活跃"；已解/已弃/退场/已揭 → 移出活跃，落账本"退出区"；
- **已长出设定**：write 临场长出的设定/新角色，核验后落这里（只记够写章用的、后续会再用的）——**这是涌现流"设定从账本长出来"的唯一落点**；
- 这章若有意改翻了某条旧现状 → 当场在账本标"改了哪条、为什么"，留痕。

**群像卫生（撤角色即检查）**：把人物撤进退出区时，对照当前"活跃"人物顺一遍——**同时活跃 ≤5-7 人**（超出读者记不住）；功能重叠的合并一个；每个活跃人物都要有"本章在场理由"，没理由的不进画面；退场必须交代（死亡/离开/转背景板），不许人间蒸发。**每 ~20 章顺手清一次活跃表**：谁还起作用、谁该退。

> **存档后半步=去AI味**：账本 replace 后同第 2 步步步法自跑，结果一行 `去AI味:涌现账本|PASS` 或 `WARN×N`。

- 结束。

## 阶段性回看（Phase 3，每 N 章/一个故事弧后）

每写完一个故事弧（约 5-10 章）或老板要求时，产一份**回看报告**（对话交付，不强制存档文件）：

1. **方向校准**：对照模糊灯塔（立项卡第三样）——主角行动还朝那个方向吗？第一个标到了吗？偏了就说偏了，怎么掰回来（不改设定，改下一批章纲的排法）。
2. **爽点兑现**：这 N 章爽点密度怎么样（对照章日志爽点字段）——有没有无爽点连章？假爽点（只有发生没有反应/影响）有几处？
3. **账本长出盘点**：这 N 章从账本长出了哪些设定——哪些成了新锚（后续要一直用），哪些一次性细节已过时（从"已长出设定"清掉）。

回看不是大改——只是校准方向，继续滚动。回看后回 outline 排下一批章纲。

## 速查

| 模板 | 用在哪 | 说明 |
|:--|:--|:--|
| `templates/chapter-card.tpl.md` | 第 2 步 | 本章日志模板（含爽点·钩子字段） |

> 涌现账本为单份一体文件（当前态＋悬着的线＋已长出设定＋退出区），不需要独立的状态快照/退出档案模板——靠"只记活跃"压体积。

## 批量回溯（可选）

对已有正文批量重建时，用同一个流程逐章跑：每章做第 1 步（存量正文视为已定稿）→ 第 2 步建本章日志 → 第 3 步合进涌现账本。批量不宜一次硬吞，按采样/分批逐章推进。
