# pop-emergent-review

> 涌现流审查回填：**三源审查**（账本一致性/文风承诺/写作硬尺）→ 定稿或打回 → 生成本章日志 → **回填涌现账本**（新事实落账，设定从账本长出来）→ **阶段性回看**（每 N 章/一个故事弧后：味道保持？连续性健康？模糊灯塔要不要清晰化？要不要转灯塔流？）。产出 `章节日志/ch{NNN}.md`＋`章节日志/涌现账本.md`（更新）＋`章节日志/阶段性回看.md`（触发时）。当前版本 v1.1.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

***

## 这个 Skill 做什么

**职责：把"写完这一章"变成"下一章可依据的准"。** 与灯塔流的区别：涌现流没有全书日志/设计库，**涌现账本是已发生事实的唯一承载**——审查、回填、下一章 outline/write 都只从账本取。review 是"设定从账本长出来"的唯一入口：write 临场长出的新设定，只有 review 核验落账后才成为后文可依据的事实。

| 段 | 对谁 | 干什么 | 产出 |
| :-- | :-- | :-- | :-- |
| 三源审查（Step 0-1） | 对文档 | 账本一致性＋文风承诺＋写作硬尺三把尺过本章 | 定稿 / 打回意见（四要素） |
| 生成本章日志（Step 2） | 对文档 | 按定稿正文记本章档案（事件/定事/动线/字数） | `章节日志/ch{NNN}.md` |
| 回填账本（Step 3） | 对文档 | write 新增事实清单核验落账；悬线/当前态/退出区更新 | `章节日志/涌现账本.md` |
| 阶段性回看（Step 4） | 对双方 | 每 N 章/故事弧后：味道/连续性/灯塔/转流四问 | `章节日志/阶段性回看.md` |

三条根原则：

1. **账本唯一**：涌现账本是已发生事实的唯一承载（当前态＋悬着的线＋已长出设定＋退出区）。后文只从账本取，不翻前期规划（没有前期规划）。review 是账本唯一的写入者。
2. **正文没定稿不进账本**：还在改的章不入账——审查不满意打回 write，最多 2 轮，通过才落账。
3. **阶段性回看不做=裸奔**：涌现流没有卷纲兜方向，回看是唯一的方向校准点——该回看不回看，连续写就是蒙眼跑。

**边界**：review 审一致性/连续性/设定/文风，不重写正文（打回意见只给位置+问题+严重性+改法，不替 write 写文）；不跑字数脚本（write 已收束，review 消费交接数据）；不产创作记录（章日志是档案不是创作谈）。

**产出**：`章节日志/ch{NNN}.md`（只增不改）＋`章节日志/涌现账本.md`（replace 只记活跃＋已长出设定＋退出区）＋触发时 `章节日志/阶段性回看.md`。

**称谓约定（不混叫）**：「涌现账本」=已发生事实唯一承载；「章日志」=单章档案（事件源，历史）；「回看报告」=阶段性方向校准（四问）；「打回」=不满意退回 write 重写（最多 2 轮）。

## 执行模式

**主 agent 直执审查与落账。** 审查判据、账本写入必须主 agent 亲自做。唯一例外：批量回溯（存量正文重建账本）采样多时可按采样分批推进；`pop-snow-research` **主动补采**（跨系列只读调用，不写其文件）——**不设"考据不足才派"门槛**：审查发现事实类存疑（现实设定/专业细节/历史器物对不上）、或阶段性回看要校准市场/赛道行情时，**主动派 research 补采**再判定；查不到的写"没查到"，不自行脑补判定。

**共创三态**：

1. **共创态**（默认）：定稿确认问用户；回看四问（尤其"要不要转灯塔流"）端给用户拍板。
2. **代理自定态**（无真人／自动化环境）：agent 自审自判，拍板标注 `[](agent自定·{原因})`。
3. **降级态**：共创中用户离开——保持已确认，未确认降为 agent 自定。

## 怎么操作（SOP 全内联）

### Step 0 消费输入（审查包）

读三样＋write 交接清单：

| 读什么 | 取什么 |
| :-- | :-- |
| 本章 `正文/ch{NNN}.txt` | 审查对象（全文） |
| 上一版 `章节日志/涌现账本.md` | 当前态/悬着的线/已长出设定/退出区——一致性比对基准 |
| write 对话交接 | 摘要/钩子/字数 stdout/**新增事实待 review 清单**/冲突标注 |
| 上一章 `章节日志/ch{NNN-1}.md`＋`正文/ch{NNN-1}.txt` | 衔接基准（上章停在哪/钩子是什么） |
| `立项/涌现立项卡.md` | 文风承诺（审查尺）＋模糊灯塔（回看参照） |

### Step 1 三源审查（三把尺）

**尺①账本一致性**：

| # | 判别维度 | 判定 |
|:--|:--|:--|
| 1 | **硬状态承接** | 位置/伤势/能力/持有物/信息边界与账本当前态、上章结尾无错位；"突然想到/突然做到"糊过去=不一致 |
| 2 | **新事实核验** | write 清单里的新增事实逐条核：与账本冲突=打回；成立=待落账（Step 3 落） |
| 3 | **信息边界** | 角色知道了他不该知道的=最严重错误，优先于性格偏差 |

**尺②文风承诺**：

| # | 判别维度 | 判定 |
|:--|:--|:--|
| 4 | **腔调遵守** | 叙事腔调对得上文风承诺（抽 2-3 段验） |
| 5 | **防漂移禁区** | 正文进没进承诺的防漂移禁区（进=本章不合格） |
| 6 | **大纲腔** | 出现章纲/账本的结构语言（抽象名/标签句/压缩句式）进正文=语感污染 |

**尺③写作硬尺**：

| # | 判别维度 | 判定 |
|:--|:--|:--|
| 7 | **行为可信** | 异常行为能由 经历→利益→恐惧→渴望→压力→误判 推出；只能用"剧情需要"解释=OOC（write 临场补的动机须在此验证合理性） |
| 8 | **对白遮名辨人** | 关掉角色名仍能分辨谁在说话（称呼/句长/语气/禁忌）——抽 1-2 段验 |
| 9 | **钩子承接** | 账本悬着的线/上章钩子在本章有反馈（回应/推进/误导/压住），章末留新缺口，未提前吞并未到期钩子 |
| 10 | **章末落地改变** | 信息/关系/物理/权力 至少一类落地；**四类皆无=空转章** |

**定稿/打回**：三把尺全过=定稿，进 Step 2；任一不过=打回 write，**不入库**。

**打回意见（四要素格式）**：位置（章节/段落/句子）→ 问题（违反哪条账本事实/信息边界/文风承诺）→ 严重性（严重/警告/提示）→ 改法（不改变核心剧情的最小修复）。按此给 write，**不替 write 写文、只给方向和最小修法**——最多 2 轮。

### Step 2 生成本章日志

按定稿正文写 `章节日志/ch{NNN}.md`（模板 `templates/章日志.tpl.md`）：

1. 时间 · 地点 · 人物
2. 本章剧情（顺一遍，回看用）
3. 这一章定了哪些事（改了后文对不上的重事实——write 新增事实清单核验后并入）
4. 这一章动了哪些线（`线｜这章干了啥｜线现在走到哪`）

> **write 交接并入**：write 对话回复给【新增事实待 review/冲突标注】——review 核验有效性后并入"这一章定了哪些事"，write 只声明不落库，落库以 review 为准。
>
> **字数=消费 write 交接数据**：review 不跑字数脚本，直接把 write 交接的 stdout 原文（`chNNN.txt|汉字N|判定:PASS`）填进"字数"栏；交接缺失时追问 write，不自己补跑。

### Step 3 回填涌现账本

打开 `章节日志/涌现账本.md`，按章日志 replace（模板 `templates/涌现账本.tpl.md`）：

| 区块 | 操作 |
| :-- | :-- |
| 当前态 | 更新：现在在哪（时间线/地点/故事到哪）＋主角此刻（当刻在场·正交互的人） |
| 悬着的线 | 新钩子/新线进；已收/已弃移出→落退出区 |
| 已长出的设定 | 核验通过的新事实落账（世界碎片/金手指形态/配角/新地点/新规则）——**这是"设定从账本长出来"的落点** |
| 退出区 | 已收线/已退场角色留痕（防失联，只留一行） |

**群像卫生**：收线/退场时对照活跃人物顺一遍——同时活跃 ≤5-7 人（超出读者记不住）；功能重叠的合并；退场必须交代（死亡/离开/转背景板），不许人间蒸发。每 ~20 章顺手清一次。

### Step 4 阶段性回看（触发判定＋四问）

**触发条件**（任一）：距上次回看 ≥10 章｜本故事弧收线（一条悬线走完）｜用户要求。

**回看四问**（产出 `章节日志/阶段性回看.md`，模板 `templates/阶段性回看.tpl.md`）：

| # | 问 | 判据 |
|:--|:--|:--|
| 1 | **味道保持？** | 对照文风承诺＋主角立身：最近 N 章的味道还像这本书吗？跑偏=回 seed 对齐文风承诺 |
| 2 | **连续性健康？** | 账本悬着的线有无长期不动（≥10 章）的？活跃人物 ≤5-7 人？空转章占比？ |
| 3 | **模糊灯塔要不要清晰化？** | 写到现在，结局方向有更具体的预感了吗？有=把灯塔从"一句话方向"细化到"质变点"（仍不锁路线） |
| 4 | **要不要转灯塔流？** | 试味成功＋确定写长 → 走 pipeline「转灯塔流衔接」（反推方向总表→回填卷1卷纲→设定交接→状态迁移）；还想继续涌现 → 回 3a |

**回看后**：校准结果回喂——方向校准进账本（灯塔更新），状态.md 的 phase 相应更新。**转不转、什么时候转由老板拍板。**

**Step 4 质量门**：回看报告落盘｜四问各有明确结论｜校准结果已回喂账本/状态.md。

## 红线

1. **正文没定稿不进账本**：打回最多 2 轮，通过才落账；未定稿内容绝不写入账本。
2. **账本唯一**：review 是账本唯一写入者；write/outline 只声明不落库，落库以 review 为准。
3. **新事实必须核验**：write 新增事实清单逐条核（冲突=打回），核验通过才落"已长出的设定"。
4. **回看不做=裸奔**：触发条件到了必须做阶段性回看，禁止"先写着再说"。
5. **不替 write 写文**：打回只给位置/问题/严重性/改法，不重写正文。
6. **research 主动触发**：审查事实存疑（现实设定/专业细节/历史器物对不上）或回看要校准市场/赛道行情时，主动派 pop-snow-research 补采再判定（跨系列只读调用，不写其文件），不设"考据不足才派"门槛；查不到写"没查到"，不自行脑补判定。

## 速查表

| 环节 | 校验点 |
|:--|:--|
| Step 0 输入 | 本章正文/账本/交接清单/上章衔接/文风承诺 |
| Step 1 三源审查 | 尺①账本一致性（硬状态/新事实/信息边界）＋尺②文风承诺（腔调/禁区/大纲腔）＋尺③写作硬尺（行为/对白/钩子/落地改变） |
| Step 2 章日志 | 时间地点人物/剧情/定事/动线/字数；write 交接核验并入 |
| Step 3 回填账本 | 当前态/悬着的线/已长出设定/退出区四区块；群像卫生 |
| Step 4 回看 | 触发（≥10章/弧收线/用户要求）→四问→校准回喂；转灯塔流老板拍板 |
| research 主动触发 | 审查事实存疑/回看市场校准即主动派 pop-snow-research 补采再判定；查不到写"没查到" |
| 批量回溯 | 存量正文重建账本：采样逐章跑（≤10章全审/11-30章最近5章+每5章取1/30章以上最近5章+首章+每10章取1） |
