# pop-emergent-seed

> 本技能只规定流程、文件契约与检查项，不规定题材、结构、风格或审美偏好。
> 本技能负责涌现流的立项，产出甲方文档：收清要写什么、给谁看、卖点是什么，并记录用户拍板的主角立身一句话。未拍板项标「待定」，不阻塞下游。当前版本 v2.0.1（2026-10-23：瘦身为流程层，删除固定创作配方与固定文风样例）。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 这个 Skill 做什么

**职责：把用户的模糊想法与参考材料，收成一张甲方文档，即涌现立项卡。** 甲方文档是后续环节的需求来源，不是故事正文，也不是写作规则。执行顺序固定：先问需求，再查资料，最后逐项拍板。产出为 `立项/涌现立项卡.md`，下游 state 据此收世界底子。

| 段 | 对谁 | 干什么 | 产出 |
| :-- | :-- | :-- | :-- |
| 立项引导（Step 0-2） | 对人 | 收集命题并问清需求，按需求查资料，逐项拍板 | 需求清单、底子卡组、涌现立项卡 |

**甲方文档要素**：

| # | 要素 | 谁定 | 缺省处理 |
| :- | :-- | :-- | :-- |
| 1 | 要写什么：题材与方向 | 用户定；模型给候选 | 标「待定」 |
| 2 | 给谁看：读者群与分类方向 | 用户定；模型给候选 | 标「待定」 |
| 3 | 卖点是什么：读者打开这本书图什么，方向级一句话 | 用户定；模型给候选 | 标「待定」 |
| 4 | 主角立身一句话：主角是谁、要什么、谁挡着 | 用户定；模型给候选 | 标「待定」 |
| 5 | 文风承诺：腔调一句话与禁区（可选） | 用户提出时记录 | 标「待定」 |
| 6 | 模糊灯塔：方向一句话与近期可验证目标（可选） | 用户提出时记录 | 标「待定」 |

第 3 项是 state 判断世界底子方向的依据；第 4 项是写章时主角行动的来源。第 5、6 项是可选记录，不做默认要求。

**不做**：不排卷，不锁长线决策（欲望线、压力源、世界结局、最终敌人、伏笔线），不设计世界观、力量体系、角色卡。世界底子由 state 收成装配单，细节在写章时从账本中生长。

**边界**：只记录故事方向，不做实名（人物以「主角、反派、配角」占位），不拆卷，不排章。

## 执行模式

**由主 agent 直接执行，禁止派子 agent 代为执行共创。** 立项是交互最密集的环节——出候选、听意见、改稿必须由主 agent 亲自完成。唯一例外：纯只读的资料检索可派子 agent 回报原始材料，由主 agent 读取。

**共创三态**：

1. **共创态**（默认）：用户在场，每步提交候选给用户圈定，由用户拍板。
2. **代理自定态**（无真人或自动化环境）：agent 逐层起草、审核、拍板，依次推进。拍板栏显式标注 `[](agent自定·{原因})`，禁止伪造「用户说过」。
3. **降级态**：共创过程中用户离开——已拍板的层保持用户意见，未拍板的层降为 agent 自定，降级发生的时间点写入共创记录。

所有产出物头部「共创状态」按三态如实标注。

## 怎么操作（规程全文内联）

### Step 0 收命题、问需求

**产品形态先说明**：本产品直接进入 AI 对话，没有前置表单——用户开口说的那句话就是全部输入。所以立项的第一步是提问，不是读取字段。

执行顺序为先收后问：

1. **收命题**：用户进入对话所说的话逐字收下，拆出要素清单。
2. **清点已有材料**：项目内资产（调研采风、拆书报告、旧大纲、原始资料）与用户历次裁决记录。已确认的不重复提问，已有的不重复查找。
3. **问缺口**：命题没有说清的部分，分轮提问，一轮问两三个问题，每问给出 2-4 个候选并写明各自依据：

   - 想写什么方向或题材
   - 给谁看（读者群、主分类方向）
   - 卖点是什么（读者打开这本书图什么，方向级一句话即可）
   - 篇幅量级（目标章数，用户定；未定标「待定」）

产出**需求清单**，包含四项：写什么、给谁看、图什么、多长。**需求清单未经用户确认，不得开始查资料**——查什么由需求决定。

**文风**：用户提出文风要求时，记录腔调与禁区；没提就标「待定」，由 write 在写作时按项目资料处理。不预设参考样文。

### Step 1 查底子

按需求清单逐个要素各出一张底子卡（模板为 `templates/底子卡.tpl.md`），共七栏：

| 栏 | 内容 |
| :----- | :---------------- |
| 定义与定位 | 这个方向是什么，用平台标签定位 |
| 代表作 | 三到五本，注明出处 |
| 读者需求 | 可查证的读者期待与反馈，标来源 |
| 常见配置 | 这个方向常见的机制、机构、阶层、循环 |
| 常见主线 | 有先例的主线走法，标作品 |
| 已知问题 | 被反复使用后读者反馈变差的点，标来源 |
| 组合先例 | 要素组合有没有人写过，写成了什么 |

规则：

- **调研清单须先经用户确认增删，再执行**——查什么由用户拍板。
- 检索顺序：先查 wiki 站 `https://wiki.popwave.cn`（卖点方向库、`写作灵感/{赛道}/{书名}/seed-*` 卡），再查 web。wiki 命中与 web 新查须分区标注。
- 信息源优先级依次为：自有 wiki、官方资料、权威百科、垂直百科、社区讨论（社区讨论降权，标注「非官方」）。
- 取材预算：单个环节最多一轮，一轮最多提出五个检索项，回传不超过 30KB；超限即截断，仅保留结论区。
- 方向定位用 `references/番茄标签库.md` 按需查，不向用户穷举整表。
- 查不到如实写「未查到」，不得用脑补顶替；对应要素标「待定」，不阻塞 Step 2。
- 批量查资料走 `pop-snow-research`（跨系列只读调用，不写其文件）。

### Step 2 逐项拍板

分轮与用户确认，一轮问一两个问题，每问给 2-4 个候选并写明依据。**只定上表六项**——用户想多定细节时，提醒「涌现流不提前锁定，世界底子由 state 收，细节在写作时生长」，除非用户坚持。

- **轮一·要写什么与给谁看**：题材与方向、读者群，基于 Step 0 提交 2-3 个候选。
- **轮二·卖点是什么**：读者打开这本书图什么，方向级一句话。此为 state 定世界底子方向的依据。
- **轮三·主角立身一句话**：主角是谁、要什么、谁挡着。基于卖点与底子卡组装 2-3 个候选句。判定标准：一句话能说清；听的人能复述这三个问题。未定标「待定」。
- **轮四·文风承诺（可选）**：用户提出时记录腔调与禁区；没提标「待定」。
- **轮五·模糊灯塔（可选）**：方向一句话，加上用户认可的近期可验证目标。章数与范围由用户定；未定标「待定」。

**冲突交由用户选择（不得静默覆盖）**：新需求、新查证或用户的新说法，与**已确认的要素、底子卡、历次裁决**冲突时，不得断言、不得平均处理、不得直接覆盖。须摆出冲突双方与各自后果，让用户选择保留哪一条；用户确认之前不得写入。（来源：Mirror 01 立项沟通纪律）

**只记录已确认内容，留白不构成阻塞**：用户只回答一部分时，只记录已确认的部分，其余标「待定」并登记，不得把「用户没有回答的」当作「用户默认同意」。

### Step 3 定稿交接

**一道检查**：

- **一句话测试**：合上材料，只凭记忆把这本书讲给没读过材料的人听（100 字左右），对方能复述「主角是谁、要什么、谁挡着、往哪里走」才算通过。卡住，或只有设定没有事件，即为没有成型，退回 Step 2 重新拍板。用户坚持保留时标「待定」放行，并记录欠账。

存档流程：用户逐项确认，拍板，存档 `立项/涌现立项卡.md`（模板见 `templates/涌现立项卡.tpl.md`）。

**载体分流标签**（存档时每项标注，避免载体错位。来源：Mirror 01 三载体分流）：

- 作品元数据（书名、分类、标签、简介）写入头部独立块。**分类与标签是元数据，不是写作规则**，不得写入约束块。
- 写作行为约束（POV、每章字数、禁忌、节奏）写入约束块。**一条只管一个维度，须可执行**。
- 故事事实（要写什么、卖点、主角立身、文风承诺、模糊灯塔）写入对应块。**不得进入写作规则**。
- 流程（skill、工作流）不承载故事事实——本稿只归档决定，不把任何可执行流程当作小说资料写入。

向用户报告交接：「涌现立项卡（甲方文档）已经确定，接下来 state 把立项卡与已有资料收成世界底子（力量体系、世界观、金手指、身份），outline 排章纲，write 写正文，review 审查回填账本。」随后加载 pop-emergent-state 接力。
