# pop-emergent-seed

> 本技能负责涌现流的立项，产出甲方文档。它在 snow seed 基础上做减法——不产出 14 维融合立项稿，只收集三项内容：要写什么小说、需求是什么、卖点是什么；并锁定三样：主角立身一句话、文风承诺、模糊灯塔。seed 产出的立项卡是后续所有环节（state、outline、write、review）的甲方文档，故事方向由用户拍板，细节不提前设计。当前版本 v1.2.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

***

## 这个 Skill 做什么

**职责：把用户的模糊想法与参考材料，收成一张甲方文档，即涌现立项卡。** 执行顺序不可颠倒：先问需求，再查底子，最后锁三样。产出为 `立项/涌现立项卡.md`，下游 state 据此装配世界底子。

| 段 | 对谁 | 干什么 | 产出 |
| :-- | :-- | :-- | :-- |
| 立项引导（Step 0-2） | 对人 | 收集命题并问清需求，按需求查底子，拍板锁定三样 | 需求清单、底子卡组、涌现立项卡 |

**甲方文档五要素**（后续所有环节的需求源头）：

1. **要写什么**：题材与赛道（流派的明确指向，如"修仙+凡人流"）
2. **给谁看**：读者群（男频或女频，主分类方向）
3. **卖点是什么**：读者打开这本书图的是什么（方向级的一句话，可执行）。此为 state 装配金手指与身份结构的依据
4. **主角立身一句话**：主角是谁、要什么、谁挡着。写章循环里主角的所有行动都从这句话来
5. **文风承诺**：腔调一句话，加上防漂移禁区。此为唯一稳定依据。渲染参照固定为 `pop-write/references/夜无疆.md`（辰东《夜无疆》玄幻史诗纯样文），seed 只定承诺，不选档

另附**模糊灯塔**，即方向感一句话，加上 3-10 章内可达的第一个标。它给写章循环一个方向，不锁细节，不锁卷级剧情。

**不做**：不排卷，不锁根决策（欲望线、压力源、世界结局、最终敌人、伏笔线都不锁），不产出 14 维转录，不设计世界观、力量体系、角色卡。世界底子由 state 从内容模板库装配，细节在写章时从账本中生长。

**边界**：只锁定故事的功能方向，不做实名（人物以「主角、反派、配角」占位，命名与细节临场生成），不拆卷，不排章（本线没有卷）。

## 执行模式

**由主 agent 直接执行，禁止派子 agent 代为执行共创。** 立项是交互最密集的环节——出草案、听意见、改稿必须由主 agent 亲自完成。唯一例外：纯只读的调研支撑（扫榜、查底子）可派子 agent 回报原始材料，由主 agent 读取。

**共创三态**：

1. **共创态**（默认）：用户在场，每一步都提交候选给用户圈定，由用户拍板定稿。
2. **代理自定态**（无真人或自动化环境）：agent 逐层自行起草、自行审核、自行拍板，依次推进。拍板栏显式标注 `[](agent自定·{原因})`，禁止伪造"用户说过"。
3. **降级态**：共创过程中用户离开——已拍板的层保持用户意见，未拍板的层降为 agent 自定，降级发生的时间点写入共创记录。

所有产出物头部「共创状态」按三态如实标注。

## 怎么操作（规程全文内联）

### Step 0 收命题、问需求

**产品形态先说明**：本产品直接进入 AI 对话，没有前置表单——用户开口说的那句话就是全部输入。所以立项的第一步是提问，不是读取字段。

执行顺序为先收后问：

1. **收命题**：用户进入对话所说的话逐字收下，拆出元素清单。
2. **清点已有材料**：项目内资产（调研采风、拆书报告、旧大纲、`pop-write/references/夜无疆.md` 固定文风档）与用户历次裁决记录。已确认的不重复提问，已有的不重复查找。
3. **问缺口**：命题没有说清的部分，分轮提问，一轮问两三个问题，每问给出 2-4 个选项，其中至少一个标注推荐：

   - 想写什么流或什么题材（命题只给出模糊方向时，凭常识给出流派候选让用户挑选；这一步只定方向，不做深度调研）
   - 给谁看（男频或女频，主分类方向）
   - **卖点是什么**（读者打开这本书图的是什么。方向级一句话即可，精确内容留给 outline 与 review 落实）
   - 篇幅量级（目标章数，给出几卷的量级即可。涌现流不排卷，此数只用于估算节奏）

产出**需求清单**，包含四项：什么流、给谁看、图什么、多长。**需求清单未经用户确认，不得开始查底子**——调研方向由需求决定。

**文风参照档在此确定**：涌现流的渲染参照固定为 `夜无疆.md`（辰东《夜无疆》玄幻史诗纯样文），不按题材另选。文风承诺（腔调一句话）须按本书题材与用户口味确定——问用户想要什么腔调（热血、压抑、诙谐、冷峻……），并给出候选句。

### Step 1 查底子

按需求清单逐个元素各出一张底子卡（模板为 `templates/底子卡.tpl.md`），共七栏：

| 栏 | 内容 | 例（神豪流） |
| :----- | :---------------- | :------------------- |
| 定义与定位 | 这个流派是什么，用番茄标签库定流派 | 系统发钱、狂拽平推 |
| 开山与代表作 | 三到五本 | 《重生之神级败家子》… |
| 读者图什么 | 爽点清单，逐项可执行 | 压抑后打脸／扮猪吃虎／消费奇观／平推碾压 |
| 标配零件 | 这个流的世界配置 | 花钱系统、返利公式、打脸递进 |
| 王道走法 | 主流验证过的主线 | 触发→执行→到账，高频短循环 |
| 写烂清单 | 被用滥的点 | 纯炫耀无代价 |
| 组合先例 | 元素组合有没有人写过 | 灵气复苏×财富＝《全球高武》 |

规则：

- **调研清单须先经用户确认增删，再执行**——调研不是可选项，查什么由用户拍板。
- 检索顺序：先查 wiki 站 `https://wiki.popwave.cn`（卖点方向库、`写作灵感/{赛道}/{书名}/seed-*` 卡），再查 web。wiki 命中与 web 新查须分区标注。
- 信息源优先级依次为：自有 wiki、官方资料、权威百科、垂直百科、社区讨论（社区讨论降权，标注"非官方"）。
- 取材预算：单个环节最多一轮，一轮最多提出五个检索项，回传不超过 30KB；超限即截断，仅保留结论区。
- 流派定位用 `references/番茄标签库.md` 按需查，不向用户穷举整表。
- 查不到的元素如实说明"没查到"，不得用脑补顶替。**底子卡没有齐备，不得进入 Step 2。**
- 批量查底子走 `pop-snow-research`（跨系列只读调用，不写其文件）。

### Step 2 锁定甲方文档五要素与模糊灯塔（分轮拍板）

分轮与用户确认，一轮问一两个问题，每问给出 2-4 个选项，其中至少一个标注推荐。**五要素之外一概不锁定**——用户想多定细节时，提醒"涌现流不提前锁定，世界底子由 state 从内容模板库装配，细节在写作时生长"，除非用户坚持。

- **轮一·要写什么与给谁看**：题材与赛道、读者群，基于 Step 0 的方向提交 2-3 个候选给用户选择。
- **轮二·卖点是什么**：读者打开这本书图的是什么（如"被废之后一步步打脸、重回巅峰的痛快"）。此为 state 装配金手指与身份结构的依据，方向级一句话即可。
- **轮三·主角立身一句话**：主角是谁、要什么、谁挡着。基于卖点与底子卡的"读者图什么"组装，提交 2-3 个候选句给用户选择。判定标准：一句话能说清；听的人能说出"这是本 XX 流的书"。定金手指倾向时，须验证三个毒点：任意改根规则型金手指（一出手就是终局）、以神转世或天选当理由（机械降神）、丢记忆或丢人性或反噬伤己式副作用（代价由外部世界承担）。
- **轮四·文风承诺**：腔调一句话，加上防漂移禁区。腔调按本书题材与用户口味确定（固定渲染参照夜无疆.md，此处只定承诺、不选档）；防漂移禁区即明确"禁止漂移到何处"（如"禁止飘成轻快沙雕腔""禁止使用现代网络梗"）。
- **轮五·模糊灯塔**：方向感一句话，加上 3-10 章内可达的第一个标。方向感即这本书往哪里走（一句话，如"从弃儿一步步揭开身世，卷进王都的旧案"）；第一个标即 3-10 章内可达成的小目标（如"第一次力量觉醒""在城里立住脚"）。**不锁具体情节，不排卷。**

**冲突交由用户选择（不得静默覆盖）**：新需求、新查证或用户的新说法，与**已确认的五要素、底子卡、历次裁决**冲突时，不得断言、不得平均处理、不得直接覆盖。须摆出冲突双方与各自后果，让用户选择保留哪一条；用户确认之前不得写入。（来源：Mirror 01 立项沟通纪律）

**只记录已确认内容，留白不构成阻塞**：用户只回答一部分时，只记录已确认的部分，剩余缺口继续保留、登记待补强，不得把"用户没有回答的"当作"用户默认同意"。留白不阻塞立项完成。

### Step 3 定稿交接

**一道检查**：

- **一句话测试**：合上材料，只凭记忆把这本书讲给没读过任何材料的朋友听（100 字左右），对方能复述"主角是谁、要什么、谁挡着、往哪里走"才算通过。卡住，或只有设定没有事件，即为没有成型，退回 Step 2 重新拍板。

存档流程：用户逐项确认，拍板，存档 `立项/涌现立项卡.md`（模板见 `templates/涌现立项卡.tpl.md`），随后执行**去 AI 味最后一步**：`python skills/pop-emergent-pipeline/scripts/deai_gate.py 立项/涌现立项卡.md --profile doc --json`（WARN 项按定位自查，机械项使用 `--fix`），回复中报告一行 `去AI味:涌现立项卡|PASS` 或 `WARN×N`。

**载体分流标签**（存档时每项标注，避免载体错位。来源：Mirror 01 三载体分流）：

- 作品元数据（书名、分类、标签、简介）写入头部独立块。**分类与标签是元数据，不是写作规则**，不得写入约束块。
- 写作行为约束（POV、每章字数、禁忌、节奏）写入约束块。**一条只管一个维度，须可执行，不含空话**。
- 故事事实（要写什么、卖点、主角立身、文风承诺、模糊灯塔）写入对应块。**不得进入写作规则，不得作为长期约束传入**。
- 流程（skill、工作流）不承载故事事实——本稿只归档决定，不把任何可执行流程当作小说资料写入。

向用户报告交接："涌现立项卡（甲方文档）已经确定，接下来 state 从内容模板库装配世界底子（力量体系、世界观、金手指、身份），outline 按情绪标准排章纲，write 写正文，review 审查回填账本。"随后加载 pop-emergent-state 接力。
