# Step 0: 导入/续写模式

> 当用户已有历史资料/设定/正文时，将已有资料标准化转换为 pipeline 标准格式，重建项目状态并路由到正确Phase。
> 核心理念：这不是"检测+跳Phase"，而是"检测→标准化转换→补缺→路由"的完整初始化过程。

## 触发条件（任一满足即进入本Step）

1. 用户明确说"导入/续写/已有/接续/迁移"
2. Step 1初始化时检测到 `正文/` 或 `设计/` 已有文件
3. 项目目录已有内容但无project-state.md

---

## 执行

### 0a. 资产扫描

用LS扫描项目目录（或用户指定的源目录），列出所有已有文件。

→ 输出：**原始资产清单**（文件名 + 位置 + 内容摘要1句话）

### 0b. 资产标准化转换

> 这是核心步骤。将用户的非标准文件逐个转换为 pipeline 标准格式：标准文件名 + 标准目录位置 + 标准内容结构。

#### 0b-1. 文件名+目录归位

将用户文件映射到标准位置并重命名：

| 用户文件（模糊匹配） | → 标准位置 | 标准文件名 | 对应Phase |
|:--|:--|:--|:--|
| *意图* / *方向* / *想法* / 用户口述 | `素材/` | `用户意图.md` | Phase 0 |
| *调研* / *市场* / *赛道* / *排行* | `素材/` | `赛道调研.md` | Phase 0 |
| *文风* / *DNA* / *笔触* / *风格* | `素材/` | `文风锚定.md` | Phase 0 |
| *decon* / *拆书* / *力量分析* | `素材/` | `decon-lite-{书名}.md` | Phase 0 |
| *市场校准* / *对标* | `素材/` | `市场校准.md` | Phase 1 |
| *创意* / *故事* / *纲领* / *简介* | `设计/` | `创意.md` | Phase 1 |
| *力量体系* / *力量* / *体系* | `设计/全书设定/` | `力量体系.md` | Phase 2 |
| *地图* / *地理* / *城市* | `设计/全书设定/` | `地图.md` | Phase 2 |
| *势力* / *组织* / *帮派* | `设计/全书设定/` | `势力.md` | Phase 2 |
| *危机* / *威胁* / *危险* | `设计/全书设定/` | `危机.md` | Phase 2 |
| *配角* / *全书角色* | `设计/全书设定/` | `全书配角.md` | Phase 2 |
| *各卷切片* / *卷设定* | `设计/全书设定/` | `各卷切片.md` | Phase 2 |
| *剧情白描* / *大纲* / *分幕* | `设计/第一卷剧情/` | `剧情白描.md` | Phase 3 |
| *角色库* / *NPC* / *角色* | `设计/角色库/` | `角色库.md` | Phase 3.5 |
| *正文* / *章节* / ch* / 第*章 | `正文/` | `ch{NNN}.txt` | Phase 4 |
| *快照* / *状态* / *进度* | `审核/` | `小说快照.md` | Phase 5 |
| *current-state* / *入口包* | 项目根 | `current-state.md` | Phase 5 |

**操作**：
1. 匹配不上的文件归入"未分类资产"，询问用户映射到哪个标准位置
2. 格式转换：.docx/.txt → .md（用Read读取内容→Write写入标准位置标准文件名）
3. 正文文件统一编号：`第一章.txt` / `chapter1.md` → `正文/ch001.txt`
4. 询问用户是否保留原文件

#### 0b-2. 内容结构标准化

> 用户文件内容往往是自由格式，需要转换为 pipeline 模板定义的标准结构。

逐个文件检查内容结构，对照标准模板补全缺失部分。**转换规则**：保留用户原始内容，用标准结构重新组织（加标准标题/分节），不删除用户已有信息。

| 标准文件 | 标准内容结构（必须有的分节） | 转换方式 |
|:--|:--|:--|
| `素材/用户意图.md` | ①赛道方向 ②标签/元素 ③参考书群 ④现有设定 | 将用户口述/笔记按四层分节整理 |
| `素材/赛道调研.md` | 赛道定位调研内容 | 将用户调研笔记整理落盘 |
| `素材/文风锚定.md` | 文件头(参考书名+采样章数+场景类型数+时间戳)+场景卡矩阵+通用维度+场景卡+全书稳定特征 | 保留用户DNA提取内容，补全文件头和分节标记 |
| `素材/decon-lite-{书名}.md` | 8表(力量体系规则级/剧情节奏/情绪弧线/人称视角/开篇解剖/势力格局/金手指深度/世界危机引擎) | 将用户拆书笔记按8表分节，缺的表标注"待补" |
| `素材/市场校准.md` | 借鉴点清单/避雷点清单/爽点类型清单/赛道格局 | 将用户市场分析按四部分重组 |
| `设计/创意.md` | 创意名/一句话简介/创意/创意来源/金手指(创意×机制×限制×合成)/行为引擎/轻量主角轮廓/番茄简介(150-300字第一人称)+故事纲领(三核心+营销层) | 将用户故事构想按标准分节整理，缺的标注"待补" |
| `设计/全书设定/力量体系.md` | 世界源力量(第一层)/主养成线位阶(第二层,5-7阶含社会地位参照)/子养成线(第三层)/交叉规则(第四层)/力量体系全书展开表 | 将用户力量设定按四层结构重组 |
| `设计/全书设定/地图.md` | 城市舞台表+地图全书展开表(所有区域标注预计进入卷) | 将用户地图设定按表格重组 |
| `设计/全书设定/势力.md` | 势力结构表(4层tier+弱点裂缝+和上层关系)+势力全书展开表(4层全具名，标注碰撞卷) | 将用户势力设定按4层表格重组 |
| `设计/全书设定/危机.md` | 全书危机体系(终极+阶段性+倒计时，四源)+危机全书展开表(标注爆发卷) | 将用户危机设定按四源分层重组 |
| `设计/全书设定/全书配角.md` | 每个配角含核心欲望/设定角色/势力归属/关系张力/预计出场卷 | 将用户配角设定按标准字段重组 |
| `设计/全书设定/各卷切片.md` | 每卷设定切片(力量/地理/势力/危机范围+卷末设定边界) | 将用户卷级设定按切片格式重组 |
| `设计/第一卷剧情/剧情白描.md` | 头部(ch001锚点+本卷规模)→一、本卷设定快照→二、分支剧情线≥6条→三、分幕设计(4-5幕,起承转合)→四、按幕白描(五段式叙事梗概+场景表+幕末钩子+主角力量成长线)→卷末钩子 | 将用户大纲按四层结构+分幕设计重组 |
| `设计/角色库/角色库.md` | 头部→角色总表(角色名/定位/阵营/引入章/当前力量层级/最后出场章)→角色详细卡(基本信息/性格描述/背景≥200字/口头禅/与主角关系/成长数据/出场记录)→增量更新日志 | 将用户角色资料按总表+详细卡格式重组 |
| `审核/小说快照.md` | 全书进度+涌现设定累计+角色状态总表+剧情线进度+读者已知信息池+待回收伏笔总表 | 见0f正文反推 |
| `current-state.md` | 元数据+当前章位+不可改事实+人物状态+设定状态+可用燃料队列+伏笔债务+下一章硬推进+DNA执行包+禁止漂移 | 见0f正文反推 |

**转换原则**：
- 保留用户原始内容，不删除不篡改
- 用标准结构重新组织（加标准标题/分节标记）
- 缺失的分节标注"⏳待补"，不编造
- 非md文件（.docx/.txt/.json）先读取内容再按标准格式写入.md

→ 输出：**标准化资产清单**（每个文件标记：✅已标准化 / ⚠️部分标准化(缺分节已标注待补) / ❌无法转换(需人工处理)）

### 0c. 缺口分析

标准化完成后，对照依赖链逐Phase检查：

| Phase | 产出 | 就绪判定 |
|:--|:--|:--|
| Phase 0 | 用户意图.md + 赛道调研.md | 两者都有=✅ |
| Phase 1 | 设计/创意.md + 正文/ch001.txt | 两者都有=✅ |
| Phase 2 | 设计/全书设定/ 有文件 | 目录有文件=✅ |
| Phase 3 | 设计/第一卷剧情/剧情白描.md | 存在=✅ |
| Phase 3.5 | 设计/角色库/角色库.md | 存在=✅ |
| Phase 4 | 正文/ch*.txt | 有正文=✅ |
| Phase 5 | 审核/小说快照.md | 存在=✅ |

**正文进度检测**：如果 `正文/` 有文件，提取最大章节号。例如有 ch001.txt~ch015.txt → current_chapter = ch016（下一章待写）。

→ 输出：**缺口报告**（哪些Phase已就绪/哪些缺失）

### 0d. 落地Phase决策

根据缺口报告 + 正文进度，按下表决定落地Phase：

| 条件 | mode | 落地Phase | 说明 |
|:--|:--|:--|:--|
| 正文有 + 小说快照有 | resume | Phase 4（续写下一章） | 状态完整，直接接续 |
| 正文有 + 小说快照无 | resume | 先执行0f正文反推 → Phase 4 | 需补建快照 |
| 正文无 + Phase 3.5就绪 | import | Phase 4（write） | 设定+剧情+角色完整 |
| 正文无 + Phase 3就绪 | import | Phase 3.5（character） | 缺角色库 |
| 正文无 + Phase 2就绪 | import | Phase 3（plot） | 缺剧情白描 |
| 正文无 + Phase 1就绪 | import | Phase 2（world） | 缺世界设定 |
| 正文无 + Phase 0就绪 | import | Phase 1（seed） | 缺创意+首章 |
| 全无 | fresh | Phase 0 | 从零开始（走正常step1流程） |

→ **向用户展示标准化资产清单 + 缺口报告 + 落地Phase建议，用户确认后进入0e**

### 0e. 状态文件重建

#### 创建/更新project-state.md

如果 `project-state.md` 不存在，创建标准格式。如果已存在，直接SearchReplace更新。

用SearchReplace更新以下字段：

```markdown
# 项目：{项目名}

> 管线：番茄skill群 | 创建：{时间} | 更新：{时间}

## 当前阶段
mode: {import/resume/fresh}
phase: {落地Phase}
current_chapter: {current_chapter}

## 阶段完成情况
- [x] Phase 0: 用户意图 + 并发前置准备（如就绪）
- [x] Phase 1: Seed → 设计/创意.md + 正文/ch001.txt（如就绪）
- [x] Phase 2: World → 设计/全书设定/（如就绪）
- [x] Phase 3: Plot → 设计/第一卷剧情/剧情白描.md（如就绪）
- [x] Phase 3.5: Character → 设计/角色库/角色库.md（如就绪）
- [x] Phase 4: Write → 正文/chXXX.txt（如就绪）
- [x] Phase 5: Review → 审核/review-chXXX.md（如就绪）
```

**规则**：已就绪的Phase标记 `[x]`，未就绪的标记 `[ ]`，落地Phase为当前进行中。

#### 更新底牌就绪区块

将已有素材对应的底牌从❌改为✅或done/skipped。

#### 生成project-state.html

运行脚本生成可视化HTML：

```bash
python skills/pop-fanqie-pipeline/scripts/generate-state-html.py {projectDir}/project-state.md
```

### 0f. 补缺生成（按需执行）

> 根据缺口报告，对落地Phase前置依赖中缺失的关键文件进行补建。分两种策略：有正文→从正文反推；无正文→标注待补由下游skill生成。

#### 0f-1. 正文反推（有正文但缺状态文件时执行）

> 触发条件：`正文/` 有文件 且 `审核/小说快照.md` 不存在

读取已有正文（全部章节，或量大时取最近5章+第一章），提取信息生成：

**a) 生成 `审核/小说快照.md`**：

```markdown
# 小说快照（导入反推生成）

> ⚠️ 本快照由正文反推生成，未经逐章review校验，需人工审核确认。

## 全书进度
- 已完成：chXXX（最大章节号）
- 当前卷：第X卷（从正文推断）
- 当前幕：第X幕（从正文推断）

## 涌现设定累计
- （从正文中提取已建立的设定/规则/力量体系信息）

## 角色状态总表
| 角色 | 当前位置 | 能力等级 | 关系 | 当前目标 |
|:--|:--|:--|:--|:--|
| （从正文最后几章提取各角色最新状态） |

## 剧情线进度
| 剧情线 | 状态 | 进度 |
|:--|:--|:--|

## 读者已知信息池
- （截至最后一章读者已知的信息）

## 待回收伏笔总表
| 伏笔 | 埋设章号 | 待回收 | 状态 |
|:--|:--|:--|:--|
```

**b) 生成 `current-state.md`**（下一章写作入口包）：
- 当前章位 = 最大章节号 + 1
- 人物状态 = 快照中的角色状态总表
- 不可改事实 = 从正文提取的已发生关键事件
- 下一章硬推进 = 从最后一章的章末钩子推断
- 伏笔债务 = 快照中的待回收伏笔

#### 0f-2. 缺失设计文档补建（有正文但缺设计文档时执行）

> 触发条件：`正文/` 有文件 但 `设计/` 下关键文档缺失

| 缺失文档 | 补建方式 | 标注 |
|:--|:--|:--|
| 创意.md | 从正文提取故事核心 → 按创意模板分节生成 | "⏳反推，需校验" |
| 全书设定/力量体系.md | 从正文提取力量规则 → 按四层结构生成 | "⏳反推，需校验" |
| 全书设定/势力.md | 从正文提取势力信息 → 按4层表格生成 | "⏳反推，需校验" |
| 角色库.md | 从正文提取出场角色 → 按角色库模板总表+详细卡生成 | "⏳反推，需校验" |

#### 0f-3. 无法反推的文档处理

以下文档无法从正文反推，必须询问用户：

| 缺失文档 | 处理方式 |
|:--|:--|
| 剧情白描.md | **必须询问用户**：①提供大纲（我们标准化转换）②跳过plot直接续写（降级模式） |
| 全书设定/各卷切片.md | 标注"⏳导入模式跳过，由后续world补跑" |
| 全书设定/危机.md | 部分可从正文反推，部分需用户补充 |
| 全书设定/世界矛盾轴.md | 需用户补充 |

**降级模式说明**：如果用户选择跳过plot直接续写，write将无剧情白描约束。需在 `current-state.md` 中手动指定下一章核心事件和爽感节点，write按current-state指导续写。后续可补跑plot生成正式剧情白描。
