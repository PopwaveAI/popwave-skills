# pop-fanqie-review

> 番茄审核引擎。四步审核：正向符合性→正文质量→反向充足性→沉淀。v4.9.0：剧情记录双文件收束——流水账=白描卡（存发生），新增剧情累计卡（存状态），废除current-state/review-沉淀/压缩归档。

## 做什么

输入：正文/chXXX.md + write交付面板 + 剧情白描本章段 + 骨架/设定 + 角色库 + 笔触DNA(三态协议) + 上一章白描卡 + 剧情累计卡

| 产出文件 | 核心内容 |
|:--|:--|
| `审核/review-chXXX.md` | 四步审核结论+gap清单+好看度4问+反向补强建议+主角变化+钩子追踪 |
| `审核/review-verdict-chXXX.md` | PASS/REJECT+一句话理由+打回条目 |
| `审核/剧情白描流水账.md`（append，白描卡） | 每章剧情白描入口累计：白描+信息差+涌现/角色状态+埋设/回收钩子（存"发生"，只增不改） |
| `审核/剧情累计卡.md`（replace，剧情累计卡） | 全书累计视图（存"状态"）：未回收钩子台账+角色当前状态表+读者已知信息池+禁止漂移+DNA执行包 |

> 双文件职责：剧情白描流水账存"发生"（append，历史），剧情累计卡存"状态"（replace，当下）。已废弃 current-state/review-沉淀/压缩归档。

审核结论：全部通过→PASS→ch+1。任一不通过→REJECT→重写（附打回条目+修改建议）。

## 怎么操作（SOP骨架）

> execution.mode: formal（落盘）/ draft（补全继续）/ trial（不落盘）。
> 强弱加载：SKILL.md=完整骨架（必读），steps/下step文件=详细操作（按Step强加载全文）。

### Step 1：正向符合性检查 → `steps/step1.md`
核心事件逐beat对照→设定一致性（金手指规则+力量体系+世界观）→角色一致性→爽感闭环（三段式）+番茄底线（章末钩子/节奏密度8-12/字数2000-2500/前后章衔接/**6章型7节拍对齐**/**战斗可写性**/**主角主动性**/**多视角覆盖**）。不通过=废章。

### Step 2：正文质量检查 → `steps/step1.md`
AI味检测（15项patterns+高疲劳词3级+结构性4项+自检）+ 笔触DNA一致性（启用态8维度/trial模式3项）+ 好看度4问（有没有劲/记忆点/哪里无聊/代入感）。

### Step 3：反向充足性检查 → `steps/step1.md`
审完正文后反向评估：剧情白描、设定库、角色卡、燃料库是否足以指导下一章创作。产出补强建议清单。

### Step 4：剧情沉淀 → `steps/step2.md`
输出审核报告+verdict+追加剧情白描流水账（append，白描卡）+更新剧情累计卡（replace，剧情累计卡）。

## 红线

1. **读取协议**：读取skill文件用`Get-Content -Encoding UTF8 -Raw`，禁用Read工具。
2. **正向符合性不通过=废章**：核心事件主线丢失/金手指违规/爽感闭环三段缺一=REJECT。
3. **AI味检测每项检出必须给原文引用+修正方向**：不能泛泛说"有AI味"，必须标注哪句话/哪个段落+pattern编号+修正方向。
4. **好看度4问必须给具体证据**：必须引用原文或标注段落位置，不能泛泛说"还行"。
5. **反向检查必须产出补强建议清单**：即使全部充足也要逐项确认"充足"，缺项必须给出具体补强建议。
6. **审核结论必须PASS/REJECT**：不能模棱两可，REJECT必须列出具体打回条目+修改建议。
7. **双文件每章必更新**：review完成后必须向`审核/剧情白描流水账.md`追加本章入口（append-only，白描卡）+ 更新`审核/剧情累计卡.md`（replace，剧情累计卡）。
8. **新增质量卡口必须审核**：6章型7节拍对齐/战斗可写性/主角主动性/多视角覆盖——四项是上游升级的下游卡口，缺一项不得通过。
