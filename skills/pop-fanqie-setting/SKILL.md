# pop-fanqie-setting

> 设定环节（番茄）：金手指决策、世界观、世界底线、世界地图、世界历史、写作规则。只写正文要用的，不写百科。
> 当前版本 2.3.0。

## 负责什么

输入：`立项/故事.md` 的故事核心与分卷设计、题材弹药、可选已有设定。

输出：

- `设定/世界.md`：世界底线 3 条、权力阶梯 4 级、经济锚点 3–5 条、文风关键词 3 个。
- `设定/世界地图.md`：世界格局、势力、分区与分区关系；都市／甜宠也至少写世界格局与主舞台。
- `设定/世界历史.md`：时代背景、关键前史时间线与当前冲突的历史根源。
- `设定/写作规则.md`：人称与视角、字数区间、对话/环境比例、人名引号策略、亲密尺度、禁用元素；300–600 字。
- 金手指决策（写进 `设定/世界.md` 开头）：名称、机制、限制、日常用法、与主线咬合。

不负责：人物卡（归 `pop-fanqie-character`）、卷纲章纲（归 `pop-fanqie-plot`）、正文。

## 流程

### Step 0 读取

- `立项/故事.md` 全文，重点取故事核、金手指设计、分卷设计。
- 已有 `设定/世界.md`、`设定/世界地图.md`、`设定/世界历史.md`、`设定/写作规则.md`：保留用户手改内容，只补缺口。
- 题材弹药：优先读项目里已选定的弹药；没有就从 `pop-fanqie-idea` 产出的偏好卡「选定弹药」读。
- 若用户点名了已解锁的赛道知识，先读 `/library/<id>/index.md`，再只取与设定相关的 `t_rules`、`t_power`、`t_cast`；不要读全库目录，也不要整包读 14 篇。
- 先看提示词里的「创作循环」段：当前节点是「设定」时由本环节继续；用户点名别的环节时按用户要求执行。

### Step 1 生成设定

调 `popwave-write-setting`，协议 v2：

- `protocolVersion`：2；`mode`：`setting`；`brief`：一句"写设定"。
- `context` 按段标题装：必填 `【故事核心】【题材弹药】`；可选 `【总控设定】`（用 `popwave_project_site_read` 读 `/pages/settings/rules`）、`【已有地图与历史】`（读 `/pages/settings/map` 与 `/pages/settings/history`）、`【人物与势力】`、`【本书规则】`（读 `/rules`）、`【赛道知识】`（用户点名的赛道 `t_rules`／`t_power`／`t_cast` 原文）。
- `constraints`：世界底线条数、权力阶梯级数、经济锚点条数、地图分区与地标数量上限、历史时间线数量上限；必须避免的设定（用户雷点）。

要求：

- 金手指至少一条限制把主角逼向主线动作；不许万能许愿机。
- 世界观 4 级权力阶梯；经济数值每条带来源，没有来源标「待核」。
- 文风关键词 3 个，来自对标或用户原话。
- 只写决策级，不写数值表、百科、历史长档。
- 每本书都要给世界地图与世界历史，但按题材控制体量：玄幻／历史／末世／无限流写 3–6 个分区、5–10 个地标、5–8 条时间线；都市／甜宠／校园只写世界格局、主舞台与 2–4 条关键前史。

### Step 2 写世界.md

把工具产出原样落到 `设定/世界.md`，结构固定：

1. 金手指（名称/机制/限制/日常用法/与主线咬合）
2. 世界底线 3 条
3. 权力阶梯 4 级
4. 经济锚点 3–5 条
5. 文风关键词 3 个
6. 待核清单

### Step 2.1 写世界地图.md 与 世界历史.md

按 `templates/世界地图.tpl.md` 与 `templates/世界历史.tpl.md` 落盘，文件名必须含「世界地图」「世界历史」，否则总控识别不到：

- `设定/世界地图.md`：世界格局一句、势力（key/label/说明）、分区（所属势力、说明、地标）、分区关系（from/to/类型）。
- `设定/世界历史.md`：时代背景、关键前史时间线（时间点＋事件＋对现在的影响）、当前冲突的历史根源。
- 不要写坐标、色值和百科长档；地图与历史都只服务于正文会写到的场面与人物选择。
- 工具没有单独产出这两份时，主 agent 按同一份世界设定整理成上述结构，不编造故事.md 没有的势力与事件。

### Step 3 写写作规则.md

按 PRD 的单文件规则生成，只写项目级长期有效的要求：

- 人称与视角；单章字数区间；对话与环境比例；人名引号策略；亲密尺度；禁用元素；平台硬规则。
- 用户说「以后」「每章」「都」「不要出现」的才写进来；只对本章有效的留给正文环节的 constraints。
- 冲突时直接改这一句，旧的删掉，不并存。全文 300–600 字。

### Step 4 门禁与交接

1. 世界底线每条都能在正文里被执行，不是口号。
2. 金手指限制与分卷设计不打架：每一卷至少用到一次限制。
3. 写作规则能被正文直接照做，不含「尽量」「适当」这类空话。
4. `世界地图.md` 的每个分区都能对上势力；`世界历史.md` 的每条时间线都写清对现在的影响，不写无效编年。

用 `popwave_project_site_update` 把本轮设定写进总控 `pages.settings`：

- `rules` 至少一条 canon；写作规则同步到 `rules.text`。
- `map`：`state: "has"`，`summary` 一句话格局；`factions` 每项 `key`／`label`／`note`；`regions` 每项 `key`／`name`／`note`／`faction`／`landmarks`（地标 `kind` 取 city／shrine／ruin／site／pin）；`links` 每项 `from`／`to`／`type`／`status`。不写坐标与色值。
- `history`：`state: "has"`，`timeline` 每项 `at`／`text`。
- 每本书都写 `map` 与 `history`；确实没有可写内容时写 `state: "none"`，其余键不写。
- 没变化不调用；不再手写流程待办：下一步由宿主按创作循环生成；只有用户明确要求的事项才写进 `todos`。

交接给 `pop-fanqie-character`；`设定/世界地图.md`、`设定/世界历史.md` 与写作规则路径写进故事.md 交接段。

## 红线

1. 不新增故事.md 没有的方向与势力。
2. 不把「待核」当已核。
3. 不写人物卡与卷纲章纲。
4. 写作规则不超过 600 字，超了合并同类项。
5. 地图与历史只写正文会用到的东西，不写百科长档、不写坐标与色值。
