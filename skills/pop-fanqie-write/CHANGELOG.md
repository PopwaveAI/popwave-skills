# pop-fanqie-write

> 番茄平台正文技能 v1.0.0（2026-10-29）。

- 从 `pop-snow-write` 复制内容并改名，首版与 snow 正文技能一致。
- 只读 `pop-fanqie-outline` 给的章纲、设定、人物卡，不自己发明剧情。

## v1.0.1 | 2026-10-30

- 支持用户指定章号范围（如 ch001-ch003）与每章字数区间；未指定时默认连写 3-5 章、每章 2000-2500 字。
- 成稿统一为 `成稿/第N批.md`。
- 仍一次只写一章、逐章落盘，不合并多章。

## v1.0.2 | 2026-11-03

- 证据：heavy 471 run 中 101 个在重复说字数、对话/环境比、引号、名字；churn 13/34 项目零文件；用户贴原文求改与「人名不要框」冲突；正文工具上游不可用时静默自写。
- Step 1 必读 `设定/写作规则.md`、`人物/人物索引.md`、`剧情日志/全书日志.md`，并写进 body 的 context/constraints。
- Step 0 新增「直接写」快线；新增模式四「导入用户已写章节」，原文一字不改。
- Step 3 新增实体核对；人名引号改为可被用户原话覆盖，去掉前先说明这是为降低朱雀 AI 检测分；章日志同时追加 `剧情日志/全书日志.md` 承接台账。
- 工具失败最多重试一次，仍失败自写时在章日志标「工具降级：<错误码>」。

## v1.0.3 | 2026-11-03

- 人名引号自检补密度口径：名单内每次出现都包；整章少于 8 处先查名单是否漏取；参考 26–166 处/万字（常用约 82 处）；超过 166 处/万字或代词、普通名词被包判误标并删。
- body 工具生成时已要求全角标点与人名 `「」`，本检查只做交付前验收。

## v1.0.4 | 2026-11-03

- 对应需求 0160：body 工具返回首行 `【截断】` 时，删掉系统提示，把已返回正文追加落盘；主 agent 判断是否续写一次，再次截断可按剩余章纲自己补写，但必须在章日志和回执声明「工具降级：OUTPUT_TRUNCATED」。
- 工具失败由主 agent 判断是否重试一次；仍失败可按章纲自己补写，但必须在章日志和回执声明「工具降级：<错误码>」，不得静默。
- 红线新增第 8 条：正文工具失败或截断时不静默，未写完的章不拼进 `成稿/`。
