# pop-fanqie-write

> 番茄正文渲染。从ch002开始，章型骨架驱动结构，笔触DNA驱动笔触。v9.0.0：steps三件合入单文件精炼（修复harness层step文件永不加载的断点），steps目录删除，速查表+知识地图合一。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 做什么

输入：项目上下文（剧情白描+剧情白描流水账+状态快照+全书设定+前章正文+设定库精选含类型风味基线）+本章锚点+笔触DNA（三态协议）
输出：2000-2500字章节正文（不准超过2500字），附交付面板

write从ch002开始（ch001由seed产出）。消费plot产出的剧情白描.md + review维护的双文件——**剧情白描=向前锚（定位本章场景表），剧情白描流水账=长线锚（全书历史+上一章白描，review按章追加），状态快照=状态锚（当前跨章状态：未回收钩子/角色状态/禁止漂移）**，逐章渲染。续写项目必须先由plot补建剧情白描.md再写，禁止用章锚点表替代。

**执行模式**：主agent直执写作——正文创作+落盘+字数自检一体化（子agent通道为审查型只读，不承担写作）；质检由review承担。

## 怎么操作（SOP全内联）

> execution.mode: 串联式 | 强保障：本SKILL.md由host层强制注入 | 弱保障：references/scripts需agent主动读取，设计时假设可能没读到

- **Step 1** 加载燃料（内化）→ 1a全文加载(剧情白描=向前锚>剧情白描流水账=长线锚>状态快照=状态锚>全书设定>创意>前章)→1b设定库精选注入(≤3维度≤1500字,角色库+类型风味基线必选)→1c笔触DNA三态协议(启用态=项目空间/涌现/文风锚定.md存在/禁用态=必须从references/文风兜底/选内置兜底文风DNA/trial态=用户声明,战斗升级场景必须面板格式)→1d回收前章钩子
- **Step 2** 选章型+章意图思考+爽感引擎+技法选择（见下）
- **Step 3** 写正文（内化·三层指导）→ 结构层(6种章型7节拍骨架,字数分配)→节奏层(事件间隔≤20行,密度8-12个/章,微钩子每3-5行)→爽感层(主推爽感必触发,爆发后三段式:爆发≤3行→反馈≤2段→余韵≥1段)→技法层(从微观技法索引选2-3类落地)
- **Step 4** 篇幅硬限制检查+落盘（见下）
- **Step 5** 交付面板+人机共创（见下）

### Step 2: 选章型+章意图思考+爽感引擎+技法选择

**2a 选章型**——选章型前**必须加载** `references/章型定义.md`（🔴写崩级）：7节拍骨架+密度约束是正文结构的真源，禁止凭速查表硬套。依据=白描本章核心事件类型+章意图；选定即锁定该章型战斗/系统交互/冲突密度；核心事件是什么选什么，不硬塞。

**2b 章意图思考**——回答4问（想清楚再写，不写进正文）：①本章核心事件是什么（1句话）？②爽感爆发点在哪（对应7节拍哪个节拍）？③章末钩子是什么（主动钩子或威胁逼近）？④类型声明是什么（从 `设计/全书设定/类型风味基线.md` 注入——类型+保持什么味+禁止漂移到哪，本章命名/器物/社会符号必须符合类型基线，杜绝类型味漂移）？

**2c 爽感引擎**——设计爽感爆发段前**必须加载** `references/爽点引擎.md`（🔴写崩级）：爆发后三段式是爽感闭环的真源，禁止凭表大意写平淡爆发。从5种引擎选1-2个：**主推必触发**，次推可选；**爽感必须闭环：触发→爆发→后果，缺一不可**。

**2d 微观技法**——从 `references/微观技法索引.md` 选2-3类（≤3类/章），优先章型推荐组合。**加载对应技法文件（不是索引文件）**：索引定位后读 `references/通用技法/{技法名}.md` 拿详细指导，挑1-2个子技法落地本章具体场景，交付面板"微观技法"字段填所选+落地位置。硬约束：≤3类禁堆砌（技法是调料不是主菜）/每类1-2个子技法不全铺/技法服务于爽感爆发或角色塑造，不为炫技而用。

**章型速查表**（6种选1）：

| 章型 | 使用条件 | 读者期待 | 主推爽感 | 次推爽感 | 推荐技法组合 |
|:--|:--|:--|:--|:--|:--|
| opening_shift | 第一章/规则松动/金手指激活 | 先信现实→被打开更大世界 | 压力突破 | 未知揭示 | 信息差博弈+感官锚点+预期违背 |
| exploration_gain | 进入新地点/发现资源/秘境探索 | 跟着主角挖宝 | 即时奖励 | 未知揭示 | 世界观渐进揭示+感官锚点+后果链设计 |
| confrontation_pressure | 对峙/打脸/信息差博弈 | 看打脸反转 | 打脸循环 | 即时奖励 | 信息差博弈+人设微操+节奏微操 |
| combat_reversal | 战斗/绝境翻盘/首杀 | 看绝境翻盘 | 压力突破 | 小爽沿途 | 节奏微操+感官锚点+后果链设计 |
| high_tier_display | 高位者出场/格局展示 | 看碾压+立志 | 未知揭示 | 压力突破（转化为动力） | 高位视角插入+恐怖奇观美学化+感官锚点 |
| reveal_hook | 揭秘/新敌人/升级/章末钩子 | 看真相炸裂 | 未知揭示 | 小爽沿途 | 预期违背+后果链设计+信息差博弈 |

### Step 4: 篇幅硬限制检查+落盘

**4a 字数检查**（纯汉字计数，不含标点/空格/英文/数字/markdown标记）：

| 汉字数 | 判断 | 处理 |
|---------|------|------|
| 2000-2500 汉字 | ✅ 合格 | 进入4b |
| <2000 汉字 | ❌ 少写 | 补爽感反馈或微观技法落地，重跑脚本 |
| >2500 汉字 | ❌ 超写 | **必须裁剪**：删描述性文字、压缩铺垫段、保留剧情推进和对话，重跑脚本 |

裁剪优先级（先删→后删）：环境描写→人物外貌→内心独白→铺垫段→对话（最后删，番茄读者最爱看对话）。**禁止裁剪**：剧情推进点/爽感爆发段/章末钩子。

**字数自检脚本（红线）**：模型自报字数不可信（R29测试10章全部虚报，平均虚报1637字），**落盘前必须跑脚本，禁止用自报字数落盘**：

```powershell
powershell -ExecutionPolicy Bypass -File skills/pop-fanqie-write/scripts/word-count.ps1 -Path 正文/chXXX.txt
```

脚本统计**纯汉字**（[\u4e00-\u9fff]，不含标点/空格/英文/数字/markdown标记），判定区间 2000-2500 汉字。**脚本 stdout 原文一行必须完整贴进交付面板/验收记录**，判定以脚本输出为准——禁转述、禁心算、禁引用生成侧统计。FAIL → 修补后重跑，重跑输出覆盖前次记录。

**4b 章型节拍检查**：节拍1-7是否都有？节拍5（爽感爆发点）是否到位？节拍7是否主动钩子？缺则补齐。

**4c 落盘**：正文写入 `正文/chXXX.txt`——纯正文不含思考过程/检查表；章标题第一行；系统面板格式由DNA决定（trial模式不内置面板）；不含markdown标记。

### Step 5: 交付面板+人机共创

写完正文后，在正文末尾附交付面板（供用户/review检查）：

```
---

## 交付面板

| 字段 | 值 |
|------|-----|
| 章号 | chXXX |
| 章名 | （10字以上的设计章名） |
| 章型 | （6种之一，见章型速查表） |
| 字数 | XXXX字 |
| 核心事件 | （1句话） |
| 爽感引擎 | （主推+次推） |
| 微观技法 | （选了哪3-4类，含动作链/多感官标注） |
| 动作链数量 | X处（战斗章≥5，日常章≥3） |
| 多感官场景数量 | X处（每章≥2，战斗章≥3） |
| 章末钩子 | （1句话） |
| 推进L2线 | （推进了哪条剧情线） |
| 笔触DNA | 启用/未启用 |
| 前章钩子回收 | 是/否（第一章为N/A） |
```

**人机共创**：用户在场可问——爽感爆发点是否到位/章末钩子是否够吸引/是否需调整章型/动作链是否够细（有无概括式动作）/多感官是否到位（有无场景只覆盖1种感官）；不在场（自动模式）跳过。本章交付完成→下一章或等用户指示；下游skill为pop-fanqie-review。

## 红线

1. **读取协议**——读取skill参考文件（references/scripts）用`Get-Content -Encoding UTF8 -Raw`，Read工具有行数限制会截断丢内容
2. **每章必须全文加载剧情白描+剧情白描流水账+状态快照+全书设定+角色库**——禁止用状态快照替代立项包；设定库禁止全文注入（≤3维度≤1500字，角色库必选）
3. **篇幅硬限制 2000-2500 汉字**（纯汉字计数，不含标点/空格/英文/数字）——超 2500 汉字=废章必须裁剪；章型必选（6种选1按7节拍骨架）；爽感≥1/章
4. **ch001由seed产出write从ch002开始**——ch002必须回收ch001章末钩子；每章以主动钩子或威胁逼近收尾
5. **笔触DNA三态协议**——三态判定见Step 1 1c；战斗/升级场景必须DNA面板格式（即时反馈/成长反馈面板），禁止无面板
6. **不写思考过程/检查表**——直接写正文，每章正文开头必须有正常章节名
7. **微观技法每章选2-3类**——按章型推荐组合选，≤3类/章，禁止堆砌（技法是调料不是主菜）
8. **类型风味注入**——每章从 `设计/全书设定/类型风味基线.md` 注入类型声明（类型+保持什么味+禁止漂移到哪）并全程锚定；命名/器物/社会符号必须符合类型基线——声明西幻却写出"铜板/米斗/驿站/柴刀/江湖/门派"=类型味漂移，打回
9. **落盘前必须执行字数自检脚本**——跑 `scripts/word-count.ps1` 统计纯汉字，stdout 原文贴进验收记录，禁用模型自报字数落盘
