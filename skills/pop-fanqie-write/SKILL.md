# pop-fanqie-write

> 番茄正文渲染。从ch002开始，章型骨架驱动结构，笔触DNA驱动笔触。**v10.1.0：文风兜底扩至 20 份全赛道纯样文** + 每章必注入≥1份文风DNA门禁。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 做什么

输入：项目上下文（剧情白描+剧情白描流水账+状态快照+全书设定+前章正文+设定库精选含类型风味基线）+本章锚点+笔触DNA（三态协议）
输出：2000-2500字章节正文（不准超过2500字），附交付面板

write从ch002开始（ch001由seed产出）。消费plot产出的剧情白描.md + review维护的双文件——**剧情白描=向前锚（定位本章场景表），剧情白描流水账=长线锚（全书历史+上一章白描，review按章追加），状态快照=状态锚（当前跨章状态：未回收钩子/角色状态/禁止漂移）**，逐章渲染。续写项目必须先由plot补建剧情白描.md再写，禁止用章锚点表替代。

**执行模式**：主agent直执写作——正文创作+落盘+字数自检一体化（子agent通道为审查型只读，不承担写作）；质检由review承担。

## 怎么操作（SOP全内联）

> execution.mode: 串联式 | 强保障：本SKILL.md由host层强制注入 | 弱保障：references/scripts需agent主动读取，设计时假设可能没读到

- **Step 1** 加载燃料（内化）→ 1a全文加载(剧情白描=向前锚>剧情白描流水账=长线锚>状态快照=状态锚>全书设定>创意>前章)→1b设定库精选注入(≤3维度≤1500字,角色库+类型风味基线必选)→1c笔触DNA三态协议(启用态=素材/文风锚定.md存在/禁用态=必须从references/文风兜底/选内置兜底文风DNA/trial态=用户声明,战斗升级场景必须面板格式; **三态都必须注入≥1份文风DNA,不允许为空**)→1d回收前章钩子
- **Step 2** 选章型+章意图思考+爽感设计（见下；笔触由文风DNA驱动，不再外部技法库）
- **Step 3** 写正文（内化·三层指导）→ 结构层(6种章型7节拍骨架,字数分配)→节奏层(事件间隔≤20行,密度8-12个/章,微钩子每3-5行)→爽感层(主推爽感必触发,爆发后三段式:爆发≤3行→反馈≤2段→余韵≥1段)→笔触层(由已注入文风DNA驱动,兑现翻页颗粒+肉痛代入)
- **Step 4** 篇幅硬限制检查+落盘（见下）
- **Step 5** 交付面板+人机共创（见下）

### Step 2: 选章型+章意图思考+爽感设计（笔触由文风DNA驱动）

**2a 选章型**——用`下方内联章型速查表`（6种选1，v10.0.0：references/章型定义.md 已移除，本表为唯一真源）：7节拍骨架+密度约束是正文结构的真源。依据=白描本章核心事件类型+章意图；选定即锁定该章型战斗/系统交互/冲突密度；核心事件是什么选什么，不硬塞。

**2b 章意图思考**——回答4问（想清楚再写，不写进正文）：①本章核心事件是什么（1句话）？②爽感爆发点在哪（对应7节拍哪个节拍）？③章末钩子是什么（主动钩子或威胁逼近）？④类型声明是什么（从 `设计/全书设定/类型风味基线.md` 注入——类型+保持什么味+禁止漂移到哪，本章命名/器物/社会符号必须符合类型基线，杜绝类型味漂移）？

**2c 爽感闭环**——用`内联爽感规则`（v10.0.0：references/爽点引擎.md 已移除）：爆发后三段式是爽感闭环真源——**触发→爆发→后果，缺一不可**；爆发≤3行→读者反馈≤2段→余韵≥1段。主推爽感必触发，次推可选。

**2d 文风DNA落地（强制，不允许为空）**——本章文字由**已注入的文风DNA**驱动（见 Step1 1c），兑现 DNA 的翻页颗粒（短句分镜/独句段/每屏有推进）与肉痛代入（主角痛苦/屈辱写成具体身体事件）导向；不再加载外部技法库。

### Step 4: 篇幅硬限制检查+落盘

**4a 字数检查**（纯汉字计数，不含标点/空格/英文/数字/markdown标记）：

| 汉字数 | 判断 | 处理 |
|---------|------|------|
| 2000-2500 汉字 | ✅ 合格 | 进入4b |
| <2000 汉字 | ❌ 少写 | 补爽感反馈或微观技法落地，重跑脚本 |
| >2500 汉字 | ❌ 超写 | **必须裁剪**：删描述性文字、压缩铺垫段、保留剧情推进和对话，重跑脚本 |

裁剪优先级（先删→后删）：环境描写→人物外貌→内心独白→铺垫段→对话（最后删，番茄读者最爱看对话）。**禁止裁剪**：剧情推进点/爽感爆发段/章末钩子。

**字数自检脚本（红线）**：模型自报字数不可信（R29测试10章全部虚报，平均虚报1637字），**落盘前必须跑脚本，禁止用自报字数落盘**：

```powershell
powershell -ExecutionPolicy Bypass -File skills/pop-fanqie-write/scripts/word-count.ps1 -Path 正文/chXXX.txt
```

脚本统计**纯汉字**（[\u4e00-\u9fff]，不含标点/空格/英文/数字/markdown标记），判定区间 2000-2500 汉字。**脚本 stdout 原文一行必须完整贴进交付面板/验收记录**，判定以脚本输出为准——禁转述、禁心算、禁引用生成侧统计。FAIL → 修补后重跑，重跑输出覆盖前次记录。

**4b 章型节拍检查**：节拍1-7是否都有？节拍5（爽感爆发点）是否到位？节拍7是否主动钩子？缺则补齐。

**4c 落盘**：正文写入 `正文/chXXX.txt`——纯正文不含思考过程/检查表；章标题第一行；系统面板格式由DNA决定（trial模式不内置面板）；不含markdown标记。

### Step 5: 交付面板+人机共创

写完正文后，在正文末尾附交付面板（供用户/review检查）：

```
---

## 交付面板

| 字段 | 值 |
|------|-----|
| 章号 | chXXX |
| 章名 | （10字以上的设计章名） |
| 章型 | （6种之一，见章型速查表） |
| 字数 | XXXX字 |
| 核心事件 | （1句话） |
| 爽感引擎 | （主推+次推） |
| 动作链数量 | X处（战斗章≥5，日常章≥3） |
| 多感官场景数量 | X处（每章≥2，战斗章≥3） |
| 章末钩子 | （1句话） |
| 推进L2线 | （推进了哪条剧情线） |
| 笔触DNA | 启用/未启用 |
| 前章钩子回收 | 是/否（第一章为N/A） |
```

**人机共创**：用户在场可问——爽感爆发点是否到位/章末钩子是否够吸引/是否需调整章型/动作链是否够细（有无概括式动作）/多感官是否到位（有无场景只覆盖1种感官）；不在场（自动模式）跳过。本章交付完成→下一章或等用户指示；下游skill为pop-review。

## 红线

1. **读取协议**——读取skill参考文件（references/scripts）用`Get-Content -Encoding UTF8 -Raw`，Read工具有行数限制会截断丢内容
2. **每章必须全文加载剧情白描+剧情白描流水账+状态快照+全书设定+角色库**——禁止用状态快照替代立项包；设定库禁止全文注入（≤3维度≤1500字，角色库必选）
3. **篇幅硬限制 2000-2500 汉字**（纯汉字计数，不含标点/空格/英文/数字）——超 2500 汉字=废章必须裁剪；章型必选（6种选1按7节拍骨架）；爽感≥1/章
4. **ch001由seed产出write从ch002开始**——ch002必须回收ch001章末钩子；每章以主动钩子或威胁逼近收尾
5. **文风DNA兜底注入门禁（不允许为空）**——每章写前必须确定并注入≥1份文风DNA：`素材/文风锚定.md` 最优先；不存在必须从 `references/文风兜底/` 按赛道选一，执行报告标注兜底赛道名；禁跳过、禁无风格凭空写。战斗/升级场景必须DNA面板格式（即时反馈/成长反馈面板）
6. **不写思考过程/检查表**——直接写正文，每章正文开头必须有正常章节名
7. **类型风味注入**——每章从 `设计/全书设定/类型风味基线.md` 注入类型声明（类型+保持什么味+禁止漂移到哪）并全程锚定；命名/器物/社会符号必须符合类型基线——声明西幻却写出"铜板/米斗/驿站/柴刀/江湖/门派"=类型味漂移，打回
8. **落盘前必须执行字数自检脚本**——跑 `scripts/word-count.ps1` 统计纯汉字，stdout 原文贴进验收记录，禁用模型自报字数落盘
