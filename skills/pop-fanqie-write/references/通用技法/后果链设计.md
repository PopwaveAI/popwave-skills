# 后果链设计

> 章内事件不闭环，每一个动作都产生可见的后果涟漪，让读者觉得"世界是活的"，同时自然引出下一章钩子。
> 适用章型：exploration_gain / combat_reversal / reveal_hook

---

## 子技法清单

| 子技法 | 一句话说明 | 用在哪 |
|:--|:--|:--|
| 显性后果 | 主角做了A，立刻出现B结果，肉眼可见 | 战斗/探索章收尾，打完架留下痕迹 |
| 隐性伏笔 | 一个小动作在本章没影响，后面会炸 | 日常章埋雷，比如打碎一个花瓶 |
| 连锁反应 | 后果1触发后果2，像多米诺骨牌 | 危机升级场景，越搞越糟 |
| 第三方波及 | 事件波及到无关角色，引出新线 | 都市/修仙，打斗误伤路人引出势力 |
| 时间延迟后果 | 本章做的事，几天后才出结果 | 布局/经营类章节，种因待果 |
| 反向后果 | 本意是好的，结果反而坏事 | 主角好心办坏事，制造困境 |

---

## 怎么用

### 使用步骤
1. 确定本章核心事件（主角干了什么）
2. 设计1个显性后果（本章内可见，收束本章）
3. 设计1个隐性/延迟后果（作为下一章钩子或中期伏笔）
4. 后果必须和动作有因果逻辑，不能硬加

### 注意事项
- 每章至少1个显性后果，不能事件说完就完了
- 隐性伏笔不要超过3条并行，读者追踪不过来
- 后果要具体：不是"有麻烦了"，是"王家三公子明天要来砸店"

### 反例（别这么写）
- 主角大闹一场，第二天什么事都没有，世界像失忆了
- 一章埋8个伏笔，后面大部分忘了回收
- 后果全靠角色嘴上说"这下麻烦了"，没有画面支撑
