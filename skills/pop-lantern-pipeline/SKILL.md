# pop-lantern-pipeline

> 灯塔流总控。当前版本 v1.1.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

### 心智前置·意识层（贯穿本 skill 与全流程）

动笔/定稿前自问：本产出要更好，还需要看过哪些候选？当前信息够不够？有更优选项没探索？

- **Know-Gap**：先显式列出"要更好需见过哪些候选面"，再列已覆盖，缺口=差值；缺口≥1 个未覆盖维度才触发取材，缺了取、别硬写。
- **Pack**：缺口足够才取材，query 自生成；来源 **wiki 站 https://wiki.popwave.cn** 居先、网络补齐；单环节 ≤1 轮 / ≤5 query / 回传 ≤30KB，超限截断仅留结论区。
- **Worth**：拿本 skill 决策尺对"现有 vs 候选"必给打分表，禁止一句"更优"带过；只端候选/升级版，不越权定终局。
- **Deepen**：产出/候选后自问"这是天花板吗？有更优候选吗？"显著更优才升级再问，上限 2 轮。

取材仅进上下文，升级被采纳才落产出。

## 做什么

| 职责 | 说明 |
|:--|:--|
| 一次性安装（fresh） | 建目录 + 存档 `状态.md`（薄机器状态）+（可选）导出展示面板 + README |
| 一次性导入/续写（import/resume） | 资产扫描→归位→缺口分析→落地Phase→状态重建→补跑调度 |
| 状态文件维护 | `状态.md` = 唯一状态总账，agent 只读写它的状态片段；展示面板仅供老板查看，agent 不读 html |
| 卷循环路由 | 灯塔流滚动卷循环：plot 滚动两卷 → outline → write → review → 卷末回看 → 滚下一卷 |

**日常路由不经此 skill**：用户说"继续写/下一步/写正文/审核"时，主 agent 按卷循环状态机直接选 skill，先读 `状态.md` 取状态片段（mode/phase/current_volume/current_chapter），路由参照=下方「卷循环状态机」。pipeline 不写正文、不做内容转换、不常驻。

**research 依赖（三方共用基建·各环节大量拉取）**：灯塔流是 research 的重度消费方——seed 立项查底子/赛道行情、world/character 建设定遇现实 IP/参考作品/专业考据、opening 开篇现实场景、plot 卷规划剧情素材与单元剧库增量、review 审查事实存疑，各环节落盘前答"资料够不够"，不够必派 `pop-snow-research` 补采（跨系列只读调用，不写其文件）再落盘；查不到的写"没查到"，不凭空编造。采风统一落 `素材/采风/`（文件名 `{定向}-{主题}.md`）。

**灯塔流三原则（贯穿路由）**：

1. **根→开篇→滚动卷循环**：立项只锁灯塔四样（主角立身/世界内核/结局方向/篇幅量级）→ 核心设定（锁根）→ 开篇（读者验证前置，先于卷方向）→ 主线剧情（方向总表）→ 滚动卷循环（只细化当前卷＋下一卷）。
2. **延迟锁定**：卷级硬约束只在滚动细化某卷卷纲时执行，不提前排全书单元表；决策时机=信息足够时才锁。
3. **账本是连续性兜底**：全书日志承载方向总表进度＋跨卷钩子，写完一卷卷末回看，再滚下一卷。

**执行模式**：主 agent 直执。初始化/导入交互（资产清点、缺口确认、落地决策）由主 agent 完成；生成任务由主 agent 加载对应子 skill 执行。禁止派发子 agent 执行 skill 生成任务。

## 怎么操作（SOP 全内联）

### Step 0：导入/续写模式

> 触发（任一满足）：①用户说"导入/续写/已有/接续/迁移" ②Step 1 初始化时检测到 `正文/` 或 `设计/` 已有文件 ③项目目录已有内容但无 `状态.md`。
> 理念：pipeline 是调度员不是制造者。只做资产清点、文件归位、缺口分析、补跑调度；深度内容转换由主 agent 加载对应 skill 完成。

**0a 资产扫描**：LS 扫描项目目录（或用户指定源目录）→ 输出原始资产清单（文件名+位置+内容摘要1句话）。

**0b 资产归位**（只归位，不做内容结构标准化）：

| 用户文件（模糊匹配） | → 标准位置 | 标准文件名 | 对应位 |
|:--|:--|:--|:--|
| *意图*/*方向*/*想法*/用户口述 | `素材/` | 用户意图.md | 1 |
| *调研*/*市场*/*赛道*/*排行* | `素材/` | 市场校准.md / 赛道调研.md | 1 |
| *采风*/*资料收集*/*质感*/*原型*/*世界观素材* | `素材/采风/` | {定向}-{主题}.md | 1 |
| *文风*/*DNA*/*笔触*/*风格* | `素材/` | 文风锚定.md | 2e（DNA带进） |
| *decon*/*拆书*/*力量分析* | `素材/` | decon-lite-{书名}.md | 1（底牌） |
| *需求*/*故事脉络*/*立意*/*篇幅* | `立项/` | 需求卡.md + 故事脉络.md + 篇幅量级.md | 1 |
| *力量*/*体系*/*位阶*/*法则* | `设计/` | 世界法则.md | 2 |
| *世界设定*/*地理*/*画像*/*内核* | `设计/` | 世界画像.md | 2 |
| *势力*/*格局*/*矛盾* | `设计/` | 世界格局.md | 2 |
| *金手指*/*外挂*/*主角* | `设计/` | 主角设计.md | 2 |
| *角色库*/*NPC*/*配角* | `设计/` | 角色库.md | 2 |
| *开篇*/*黄金三章*/*前三章* | `开篇/` | 开篇设计.md | 3 |
| *主线*/*方向总表*/*卷方向*/*卷进度* | `方向总表/` | 方向总表.md | 4 |
| *卷舞台*/*卷设定*/*各卷切片* | `设计/卷舞台/` | 卷N-舞台.md | 5a |
| *卷纲*/*大纲*/*分幕* | `卷纲/` | 卷N-卷纲.md | 5a |
| *章纲*/*叙事原子* | `卷纲/章纲/` | ch{NNN}-章纲.md | 5b |
| *正文*/*章节*/ch*/第*章 | `正文/` | ch{NNN}.txt | 5c |
| *章日志*/*本章记录* | `章节日志/` | ch{NNN}.md | 5d |
| *全书日志*/*快照*/*进度*/*账本* | `章节日志/` | 全书日志.md | 5d |

操作：匹配不上的归"未分类资产"询问用户映射；.docx 等异构格式 Read 内容→Write 标准位置标准文件名；正文统一编号（`第一章.txt`/`chapter1.md`→`正文/ch001.txt`）；卷纲与章日志易混——含单元表/旅程弧/兑现清单的归 `卷纲/`，含关键数据/爽点钩子/跨卷钩子的归 `章节日志/`，拿不准问用户；询问用户是否保留原文件。

**文件来源标记**（每个归位文件记入资产清单）：

| 来源标记 | 含义 | 后续处理 |
|:--|:--|:--|
| `user-original` | 用户已有文件，直接归位 | ⚠️需校验 |
| `pipeline-relocated` | pipeline 做了格式转换（.docx→.md 等） | ⚠️需校验 |
| `skill-generated` | 对应 skill 正向产出 | 正常消费 |

**0c 缺口分析**：归位完成后对照依赖链逐位检查（就绪判定=文件存在，查文件系统）：

| 位 | 就绪判定 |
|:--|:--|
| 1 | `立项/需求卡.md` + `立项/故事脉络.md` + `立项/篇幅量级.md` |
| 2 | `设计/` 锁根四档：世界画像+世界法则+世界格局+主角设计（含金手指三件套） |
| 3 | `开篇/开篇设计.md`（黄金三章，读者验证前置） |
| 4 | `方向总表/方向总表.md`（每卷一行：质变点+卷末对手+爽点标签） |
| 5a | `卷纲/卷N-卷纲.md`（当前卷+下一卷；写完一卷才滚下一卷） |
| 5b | `卷纲/章纲/ch{NNN}-章纲.md`（NNN=下一章待写） |
| 5c | `正文/ch*.txt`（current_chapter=最大编号+1） |
| 5d | `章节日志/ch{NNN}.md` + `章节日志/全书日志.md`（账本：方向总表进度+跨卷钩子） |

进度检测：`正文/` 有文件→提取最大章节号，current_chapter=下一章待写；卷号=取 `卷纲/` 与 `设计/卷舞台/` 中最大卷号，无则=1；方向总表行数=已排卷方向数，当前卷=最大已写卷+1。输出缺口报告。

**0d 落地Phase决策**（缺口报告+正文进度）：

| 条件 | mode | 落地位 | 说明 |
|:--|:--|:--|:--|
| 正文有+章日志有+全书日志有 | resume | 5b 或 5c | 状态完整：下一章章纲已拼→5c，未拼→5b |
| 正文有+账本缺（章日志/全书日志） | resume | 先 0f 调度 review reconstruct→5b/5c | 需补账本 |
| 正文无+章纲有 | import | 5c（write） | 缺正文 |
| 正文无+卷纲有 | import | 5b（outline） | 缺章纲 |
| 正文无+方向总表有 | import | 5a（plot 滚动卷纲） | 缺当前卷卷纲 |
| 正文无+开篇有 | import | 4（plot 方向总表） | 缺方向总表 |
| 正文无+设计有 | import | 3（opening 开篇） | 缺开篇（读者验证前置） |
| 正文无+立项有 | import | 2（world/character） | 缺核心设定 |
| 全无 | fresh | 1（seed） | 走 Step 1 初始化 |

→ 向用户展示：资产清单（含来源标记）+缺口报告+落地Phase建议+补跑建议清单（0f），**用户确认后**进 0e。

**0e 状态文件重建**：`状态.md` 不存在→按「状态.md 模板」创建；已存在→更新。字段：mode/phase/current_volume/current_chapter/current_direction_row（方向总表当前行）/就绪态按 0c 标 [x]。展示面板可选：老板要求时按 `templates/项目总控.html` 套值导出。

**0f 调度skill补跑**（pipeline 只识别缺口+调度+汇报，不自行做内容转换）：

| 缺口类型 | 调度 skill | 做什么 |
|:--|:--|:--|
| 有正文+缺章日志/全书日志 | pop-lantern-review reconstruct | 批量回溯审核：采样逐章章日志+全书日志（含方向总表进度+跨卷钩子重建） |
| 缺立项/设定/开篇/剧情/章纲文档 | 对应 skill（seed/world/character/opening/plot/outline） | 读已有文件→按 skill 方法论校验+补全→标准格式 |
| 已有文档但来源=user-original | 对应 skill（用户确认后按需） | 校验→标注缺口或确认达标 |

- review reconstruct 采样：≤10章全审 / 11-30章最近5章+每5章取1章 / >30章最近5章+第一章+每10章取1章。产出 `章节日志/ch{NNN}.md`+`章节日志/全书日志.md`（账本）。
- 设计文档补跑按依赖链顺序：world（画像→法则→格局）→ character（主角设计）→ opening（开篇）→ plot（主线脉络→方向总表→滚动卷纲）→ outline（章纲）。用户已有正文但缺剧情文档→plot 从正文反推；用户选跳过 plot 直接续写（降级模式）→在全书日志手动指定下一章核心事件。
- 补跑建议清单：逐文件一行——文件名：来源=…，状态=…，建议=正常消费/补跑XX skill。用户三选：正常接续/按需补跑/全量补跑。

**Step 0 质量门**：原始资产清单已生成｜归位完成（含来源标记）｜缺口报告已生成｜落地Phase经用户确认｜状态.md 已创建/更新｜补跑建议清单已展示。

### Step 1：初始化（fresh 模式）

**前置检测**：执行任何创建前先 LS 扫描——`正文/` 有章节文件或 `设计/` 有 .md 文件→跳转「Step 0 导入/续写」；目录为空或仅有 `状态.md`→继续本步。

1. **创建目录（一次性）**：`素材/`（含 `采风/`）+ `立项/` + `设计/`（含 `卷舞台/`）+ `开篇/` + `方向总表/` + `卷纲/`（含 `章纲/`）+ `正文/` + `章节日志/`。创建后 LS 自检全部存在，缺一=初始化失败，补创后才继续。（`素材/采风/`=定向采风库，存 research 世界观/人物/剧情/场景四类定向采风，文件名规范 `{定向}-{主题}.md`）
2. **创建 状态.md**：按「状态.md 模板」写入项目根（mode: fresh / phase: init / current_volume: 1 / current_chapter: ch000 / 就绪态标 [ ]）；再简建 README.md（项目信息+目录说明+指向 状态.md）。
3. **展示面板（可选）**：老板要求时按 `templates/项目总控.html` 套 状态.md 值导出；agent 只写 状态.md，不读 html。
4. **路由 Phase 1**：加载 pop-lantern-seed 按其 SKILL.md 执行（问需求→查底子→故事脉络五元素→篇幅量级：只锁灯塔四样）。

**Step 1 质量门**：目录齐全+状态.md 存档｜README 存档。

### 状态.md 模板（薄，机器读）

```markdown
mode: fresh            # fresh/import/resume
phase: init            # init/1/2/3/4/5a/5b/5c/5d/5e
current_volume: 1      # 当前卷号
current_chapter: ch000 # 下一章待写（本章 review PASS 后+1）
current_direction_row: 1  # 方向总表当前行（当前卷）
就绪态:
- [ ] 1  立项（需求卡/故事脉络/篇幅量级）
- [ ] 2  核心设定（世界画像/法则/格局/主角设计）
- [ ] 3  开篇（开篇设计）
- [ ] 4  方向总表
- [ ] 5a 卷N-卷纲（当前卷+下一卷）
- [ ] 5b chNNN-章纲
- [ ] 5c chNNN-正文
- [ ] 5d 章日志+全书日志
```

### 卷循环状态机（日常路由参照）

```
Phase 1  立项（pop-lantern-seed）：需求卡+故事脉络+篇幅量级 —— 只锁灯塔四样
  │
  ▼
Phase 2  核心设定（pop-lantern-world → pop-lantern-character）：画像→法则→格局→主角金手指三件套 —— 锁根：近乎不可逆
  │
  ▼
Phase 3  开篇（pop-lantern-opening）：黄金三章 —— 读者验证前置：开篇定调后再排卷方向
  │
  ▼
Phase 4  主线剧情（pop-lantern-plot）：主线脉络→方向总表（每卷一句话）—— 骨架+方向
  │
  ▼
Phase 5  滚动卷循环（写完一卷才滚下一卷）：
  5a  plot 滚动细化：当前卷+下一卷卷纲（硬约束此时才执行）→ 卷末回看账本+方向总表再滚
  5b  pop-snow-outline：按当前卷卷纲拆章纲
  5c  pop-snow-write：按章纲写正文
  5d  pop-lantern-review：三源审查+存档三件事（确认→章日志→全书日志账本）
  5e  卷末回看（该卷最后一章 PASS 后）：pop-lantern-review 产卷末回看报告 → plot 滚下一卷（回 5a）
```

路由判定：读 状态.md 的 phase/current_volume/current_chapter → 对照状态机 → 选 skill。用户口头指令优先（"写正文"→5c；"审核"→5d；"下一卷"→5e→5a）。

## 红线

1. **只锁灯塔四样**：立项不产全书卷纲；方向总表到"每卷一句话"为止（半固定，后段行可调）。
2. **开篇前置**：读者验证先于卷方向排期；开篇定调后才产方向总表。
3. **滚动两卷**：只细化当前卷+下一卷，禁止一次排完全书单元表；写完一卷回看账本+方向总表再滚。
4. **账本唯一**：全书日志是方向总表进度+跨卷钩子的唯一承载，agent 只读写状态片段。
5. **调度不制造**：pipeline 只识别缺口+调度+汇报，不自行做内容转换。
