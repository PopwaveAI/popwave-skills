# pop-lantern-pipeline

> 灯塔流工作台。当前版本 v4.0.0（2026-10-19：调度层改造——去掉 phase 状态机，改为模块路由 + 依赖检查 + 状态总表）。
> 技能 id 与文件名保留 `pipeline`，避免全库跨包引用大改。

---

## 这套工作台怎么运转

灯塔流是"只锁方向、滚动细化"：方向总表定终局与单元走向，世界与人物按需长，剧情以单元剧滚动推进。

工作台只做四件事：

1. 建项目或导入旧稿。
2. 维护 `状态.md`（项目总表）。
3. 按用户当前要做的事路由到模块。
4. 开工前做依赖检查，缺什么报什么。

**没有 phase。** 唯一约束来自依赖：写正文要有章纲，排单元要有主线结构与舞台，审稿要有正文。

## 职责范围

| 职责 | 说明 |
|:--|:--|
| 一次性初始化（fresh） | 建目录，写 `状态.md` |
| 一次性导入/续写（import/resume） | 扫资产、归位、查缺口、定当前模块、重建状态、调度补跑 |
| 状态维护 | `状态.md` 是唯一总表，agent 只读写其中的状态片段 |
| 路由 | 按用户说法直接选 skill |
| 依赖检查 | 开工前查前置文件，缺则补或显式降级 |
| 内容库索引 | 库文件归各环节包持有，工作台只维护索引与消费纪律 |

**边界**：工作台不写正文、不做内容转换、不常驻。

**执行方式**：主 agent 直接执行。初始化与导入交互由主 agent 完成；生成任务由主 agent 加载对应模块。

## 路由表

| 用户说 | 直接进 | 开工前检查 |
|:--|:--|:--|
| 写第 N 章 / 继续写 | `pop-write` | `章纲/ch{NNN}-章纲.md` |
| 写章纲 / 排下一批章 | `pop-outline` | 本单元编排 |
| 排下一单元 / 单元剧 | `pop-lantern-plot` | 主线结构表、舞台 |
| 改世界 / 改人物 / 补设定 | `pop-lantern-stage` | 立项稿 |
| 审这一章 / 打分 / 找问题 | `pop-review` | `正文/ch{NNN}.txt` |
| 查资料 / 采风 | `pop-snow-research` | 无 |
| 新建项目 / 导入 / 续写 | 本工作台 | 见 Step 0 / Step 1 |

**日常路由不经过本技能**：用户说"写第 5 章"，主 agent 读 `状态.md`，直接加载 `pop-write`。

## 依赖检查

| 目标 | 最低前置 | 缺了怎么办 |
|:--|:--|:--|
| 写正文 | 本章章纲 | 补章纲；或降级直写，记录"无章纲" |
| 写章纲 | 本单元编排 | 补单元编排；或降级排章纲，记录风险 |
| 排单元 | 主线结构表、舞台骨架 | 补 plot 或 stage；或降级排单元 |
| 改世界/人物 | 立项稿 | 补 seed；或按用户口述建临时档，标"待回填" |
| 审稿 | 正文 | 先写正文 |
| 单元回看 | 本章日志与全书日志 | review reconstruct 补账本 |

**依赖检查不是阶段闸**：只回答"现在做这件事，手上够不够"。

## 降级模式

用户坚持跳步时，允许，但必须记录：

- `状态.md` 的「降级记录」写：跳了哪一步、欠什么、预计什么时候补。
- 本章章日志或全书日志标 `降级:无章纲` / `降级:无单元编排`。
- 下一次进入相关模块时，优先补欠账。

**禁止静默降级**。

---

## 推荐节奏（不是硬性状态机）

```
立项 → 舞台首喷 → 主线结构表 → 单元采风 → 单元编排
→ 章纲 → 正文 → 审稿 → 下一章 → … → 单元回看 → 下一单元
```

允许：

- 从任意一环进入，只要依赖检查通过。
- 先写几章试味，再回头补单元编排。
- 只改设定、只审一章、只补人物卡。
- 单元回看可按单元或按老板要求触发，不强制每单元都做全套。

**单元回看**建议做三件：review 单元级检查、stage 重跑（沉淀/扩展/防漂移/人物分流）、plot 推进上升线并回填配方。

## 内容库体系

**做法**：不凭空创造，从库中择取配方，换皮适配。库文件由持有环节包管理，工作台只索引。

| 库 | 位置 | 消费环节 |
|:--|:--|:--|
| 剧情-情绪打分表（唯一权威） | `<pop-lantern-plot 包根>/references/内容库/剧情-情绪打分表.md` | plot 标情绪目标；outline 定情绪坐标；review 达标检查 |
| 力量体系模板库 | `<pop-lantern-stage 包根>/references/内容库/力量体系模板库.md` | stage 建力量体系 |
| 世界观模板库 | `<pop-lantern-stage 包根>/references/内容库/世界观模板库.md` | stage 建世界骨架 |
| 单元剧模板库 | `<pop-lantern-plot 包根>/references/内容库/单元剧模板库.md` | plot 单元剧编排 |
| 套路库 | `<pop-outline 包根>/references/内容库/套路库.md` | outline 择取剧情套路 |
| 文风DNA库 | `<pop-write 包根>/references/` | write 带入文风 |

**消费纪律**：

1. 先查库，再创造；库中无匹配时，research 现场提取并 48 小时内回填，标"待验证"。
2. 一个主配方加微调，不多配方硬拼。
3. 适配不改内核，只换名称、场景、题材外壳。
4. review 记录"哪套配方生效、效果如何"，回填验证状态。
5. 库文件归持有环节包管理，任何灯塔流项目可跨包消费。

**情绪打分表引用纪律**：不复制表内容，需要时打开打分表查级；标注格式 `{情绪}·{分值}`。

## 操作步骤

### Step 0：导入与续写

**0a 资产扫描**：LS 扫目录，列文件名、位置、一句话内容。

**0b 资产归位**：

| 用户文件 | 归到 |
|:--|:--|
| 意图、方向、市场调研 | `调研采风/` |
| 采风、资料、原型 | `调研采风/采风/{定向}-{主题}.md` |
| 文风、DNA | `文风dna/文风锚定.md` |
| 立项、种子、融合稿 | `立项/00-融合立项稿14维.md` |
| 世界、力量、位阶、势力、基调 | `设计库/` |
| 主角、角色、配角 | `人物库/` |
| 主线、上升线、单元目录 | `剧情库/00-主线结构表.md` |
| 单元剧、单元编排 | `剧情库/单元N-编排.md` |
| 章纲 | `章纲/ch{NNN}-章纲.md` |
| 正文 | `正文/ch{NNN}.txt` |
| 章日志、全书日志 | `剧情日志/` |

匹配不上的列"未分类"，问用户。`.docx` 先读再写 md。

**0c 缺口分析**：按文件存在标就绪态，输出缺口报告与来源标记。

**0d 定当前模块**：

| 已有 | 落到 |
|:--|:--|
| 正文、章日志、全书日志齐 | `pop-write` 或 `pop-outline` |
| 正文有、账本缺 | 先 `pop-review reconstruct` |
| 单元编排有、无章纲 | `pop-outline` |
| 主线结构表有、无单元编排 | `pop-lantern-plot` |
| 立项有、无舞台 | `pop-lantern-stage` |
| 全无 | `pop-lantern-seed` |

**0e 状态重建**：按模板写 `状态.md`；旧 phase 映射为 `focus`。

**0f 补跑调度**：

| 缺口 | 调度 |
|:--|:--|
| 有正文、缺章日志/全书日志 | `pop-review reconstruct` |
| 缺立项/舞台/剧情/章纲 | 对应模块补全 |
| 缺前置采风、单元采风 | `pop-snow-research` |
| 文风锚定缺失 | `pop-dna-style` |

补跑建议逐文件一行，用户三选：正常接续、按需补跑、全量补跑。

### Step 1：初始化

1. 建 11 个一级目录：`调研采风/`（含 `采风/`）、`原始资料/`、`立项/`、`设计库/`（含 `舞台/` 与 5 件主档空档）、`人物库/`、`剧情库/`、`章纲/`、`正文/`、`剧情日志/`、`文风dna/`、`草稿/`。
2. LS 自检，缺一补建。
3. 写 `状态.md`，`mode: fresh`，`focus: 未定`，模块就绪全 `[ ]`。
4. 问三项：现在手上有什么、目标是什么、篇幅量级。
5. 按第 4 项直接路由，不输出完整流程说明。

**立项前置采风（硬性）**：seed 定完调研清单后，必须执行 `pop-snow-research` 的世界观与人物基础轮采风，写入 `调研采风/采风/`，再进 stage 首喷。
