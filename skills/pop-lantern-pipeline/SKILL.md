### 心智前置·意识层（贯穿本 skill 与全流程）

动笔/定稿前自问：本产出要更好，还需要看过哪些候选？当前信息够不够？有更优选项没探索？

- **Know-Gap**：先显式列出"要更好需见过哪些候选面"，再列已覆盖，缺口=差值；缺口≥1 个未覆盖维度才触发取材，缺了取、别硬写。
- **Pack**：缺口足够才取材，query 自生成；来源 **wiki 站 https://wiki.popwave.cn** 居先、网络补齐；单环节 ≤1 轮 / ≤5 query / 回传 ≤30KB，超限截断仅留结论区。
- **Worth**：拿本 skill 决策尺对"现有 vs 候选"必给打分表，禁止一句"更优"带过；只端候选/升级版，不越权定终局。
- **Deepen**：产出/候选后自问"这是天花板吗？有更优候选吗？"显著更优才升级再问，上限 2 轮。

取材仅进上下文，升级被采纳才落产出。

## 做什么

| 职责 | 说明 |
|:--|:--|
| 一次性安装（fresh） | 建目录 + 存档 `状态.md`（薄机器状态）+（可选）导出展示面板 + README |
| 一次性导入/续写（import/resume） | 资产扫描→归位→缺口分析→落地Phase→状态重建→补跑调度 |
| 状态文件维护 | `状态.md` = 唯一状态总账，agent 只读写它的状态片段；`项目总控.html` 是仅供老板查看的展示面板，按需导出，**agent 不读 html** |
| **内容库体系索引** | 内容库分散归各环节包持有（plot 剧情-情绪映射表＋单元剧模板库、outline 套路库、stage 力量体系＋世界观模板库）；pipeline 只维护统一索引表＋消费纪律，不持有库文件 |

**日常路由不经此skill**：用户说"继续写/下一步/写正文/审核"时，主agent按专家提示词阶段地图直接选 skill，先读 `状态.md` 取状态片段（mode/phase/current_unit/current_chapter/就绪态），路由参照=下方「单元剧循环状态机」。pipeline 不写正文、不做内容转换、不常驻。

**执行模式**：主agent直执。初始化/导入交互（资产清点、缺口确认、落地决策）由主agent完成；生成任务由主agent加载对应子skill执行。禁止派发子agent执行skill生成任务。

## 内容库体系（灯塔流 v3 核心）

**思想：agent 不凭空创造内容，从库里选配方、换皮适配。** LLM 凭空生成=平均质量网文；有被验证配方（从真小说抽离）+适配，质量下限被拉高。这是 AI 写小说跑通的底层方法。

### 库清单与消费环节（索引表：库文件归持有环节包管理，pipeline 只索引不持有）

| 库 | 位置（持有包） | 消费环节 | 性质 |
|:--|:--|:--|:--|
| 剧情-情绪映射表（多维情绪强度表） | `{pop-lantern-plot}/references/内容库/剧情-情绪映射表.md` | plot 四拍/章序列标情绪目标；outline 章纲情绪坐标；review 情绪达标检查 | **实装**（审美固定位，唯一权威参照） |
| 力量体系模板库 | `{pop-lantern-stage}/references/内容库/力量体系模板库.md` | stage 模式A 建力量体系 | 占位+示范，持续回填 |
| 世界观模板库 | `{pop-lantern-stage}/references/内容库/世界观模板库.md` | stage 模式A 建世界骨架 | 占位+示范，持续回填 |

### 统一库规（每库头部一致，新增条目照此写）

```
- 名称：{配方名}
- 内核：{可复用的核心结构/机制，3-5句}
- 来源：{哪本书/哪类作品抽离}
- 验证状态：{头部作品/普通验证/待验证}
- 适配规则：{什么题材能用/怎么换皮}
- 不可动硬核：{哪些部分禁止改}
```

### 消费纪律（全管线统一）

1. **先查库，再创造**：对应环节开工前必须查对应库；库有配方→选配方换皮适配；库没有→现场提取并**48 小时内回填**（标"待验证"）。
2. **一个主配方＋微调，禁多配方硬拼**：选一个主配方，其余只能作配料（拼两个主配方必串味）。
3. **适配不改内核**：换皮动的是名称/场景/题材外壳；"不可动硬核"字段禁止改。
4. **回填验证**：review 记录"哪套配方生效了/效果如何"，对应库同步更新验证状态。
5. **跨项目资产**：内容库按库归持有环节包管理（谁持有谁回填验证），任何灯塔流项目可跨包消费；回填注明提取自哪个项目（书名/项目名）。

### 剧情-情绪映射表特殊地位（审美固定位）

情绪刻度以 `{pop-lantern-plot}/references/内容库/剧情-情绪映射表.md`（plot 包）为**唯一权威参照**，禁止另立刻度。结构：**情绪向（正/负）× 8 条情绪线 × 1-10 级**（负3线：威胁生死/失去/背叛不公；正5线：斩杀胜利/收获机缘/成长升级/打脸装逼/关系甜蜜），每条线带事件示例。标注格式 `线{1-8}{线名}·{刻度}`（可并列，如"线1威胁生死·8分"）。核心规则：**双8**（每章 ≥2 个 8 分级峰值，可一正一负）＋**示例致命度**（8 分及以上必须见血/见死/见不可逆，假致命不算 8 分）。**同源声明**：本表与 `pop-emergent-outline/references/读者心跳库.md` 同源（结构/示例/规则一致），**改动必须两边同步**。情绪布局纪律见库内（四拍峰值各异/相邻章不连续同刻/峰值有起伏不滥用 10 级顶点）。

## 怎么操作（SOP全内联）

### Step 0：导入/续写模式

> 触发（任一满足）：①用户说"导入/续写/已有/接续/迁移" ②Step 1 初始化时检测到 `正文/` 或 `设计库/` 已有文件 ③项目目录已有内容但无 `状态.md`。
> 理念：pipeline 是调度员不是制造者。只做资产清点、文件归位、缺口分析、补跑调度；深度内容转换（正文反推/设计补建）由主agent加载对应skill完成。

**0d 落地Phase决策**（缺口报告+正文进度）：

| 条件 | mode | 落地位 | 说明 |
|:--|:--|:--|:--|
| 正文有+章日志有+全书日志有 | resume | 4b 或 4c | 状态完整：下一章章纲已拼→4c，未拼→4b |
| 正文有+账本缺（章日志/全书日志） | resume | 先 0f 调度 review reconstruct→4b/4c | 需补账本 |
| 正文无+单元编排有 | import | 4b（outline） | 缺章纲 |
| 正文无+上升线表有（首喷完） | import | 4a（plot 单元编排） | 进单元循环 |
| 正文无+融合立项稿有 | import | 2（stage首喷） | 缺舞台 |
| 全无 | fresh | 1（seed） | 走 Step 1 初始化 |

→ 向用户展示：资产清单（含来源标记）+缺口报告+落地Phase建议+补跑建议清单（0f），**用户确认后**进 0e。

**0e 状态文件重建**：`状态.md` 不存在→按「状态.md 模板」创建；已存在→SearchReplace 更新。字段：mode/phase/current_unit/current_chapter/seed_path（仅路径C项目填）/就绪态按 0c 标 [x]。展示面板可选：老板要求时按 `templates/项目总控.html` 套值导出。

**0f 调度skill补跑**（pipeline 只识别缺口+调度+汇报，不自行做内容转换）：

| 缺口类型 | 调度skill | 做什么 |
|:--|:--|:--|
| 有正文+缺章日志/全书日志 | pop-lantern-review reconstruct | 批量回溯审核：采样逐章章日志+全书日志 |
| 缺立项/舞台/剧情/章纲文档 | 对应skill（seed/stage/plot/outline） | 读已有文件→按skill方法论校验+补全→标准格式 |
| 已有文档但来源=user-original | 对应skill（用户确认后按需） | 校验→标注缺口或确认达标 |

- review reconstruct 采样：≤10章全审 / 11-30章最近5章+每5章取1章 / >30章最近5章+第一章+每10章取1章。产出 `剧情日志/ch{NNN}.md`+`剧情日志/全书日志.md`。
- 设计文档补跑按依赖链顺序：stage（设计库五长档：世界全书/力量体系+位阶-社会坐标谱/势力格局/基调母题，人物库两档：主角/角色库）→ plot（上升线表→单元编排）→ outline（章纲）。用户已有正文但缺剧情文档→plot 从正文反推；用户选跳过 plot 直接续写（降级模式）→在全书日志手动指定下一章核心事件。
- 不调度的情况：素材层文件 pipeline 自行按标准分节重组；文风锚定.md 缺失→提示用户跑 pop-dna-style（非 reconstruct 场景）。
- 补跑建议清单：逐文件一行——文件名：来源=…，状态=…，建议=正常消费/补跑XX skill。用户三选：正常接续/按需补跑/全量补跑。

**Step 0 质量门**：原始资产清单已生成｜归位完成（含来源标记）｜缺口报告已生成｜落地Phase经用户确认｜状态.md 已创建/更新｜补跑建议清单已展示。

### Step 1：初始化（fresh模式）

**前置检测**：执行任何创建前先 LS 扫描——`正文/` 有章节文件或 `设计库/` 有 .md 文件→跳转「Step 0 导入/续写」；目录为空或仅有 `状态.md`→继续本步。

1. **创建目录（一次性）**：`调研采风/`（含 `采风/`）+ `原始资料/`（含 `downloads/`、`知识沉淀/`）+ `立项/` + `设计库/`（含 `舞台/`）+ `人物库/` + `剧情库/` + `章纲/` + `正文/` + `剧情日志/` + `文风dna/` + `草稿/`。创建后 LS 自检全部存在，缺一=初始化失败，补创后才继续。（`调研采风/采风/`=定向采风库，存 research 世界观/人物/剧情/场景四类定向采风，文件名规范 `{定向}-{主题}.md`；`原始资料/`=源书/下载物/设定包/参考答案，`文风dna/`=文风锚定.md，`草稿/`=临时未定稿）
2. **创建 状态.md**：按「状态.md 模板」写入项目根（mode: fresh / phase: init / current_unit: 1 / current_chapter: ch000 / 全部就绪态标 [ ]）；再简建 README.md（项目信息+目录说明+指向 状态.md）。
3. **展示面板（可选）**：老板要求时按 `templates/项目总控.html` 套 状态.md 值导出；agent 只写 状态.md，不读 html。
4. **首次对话引导**：用户第一次触发且无项目时，先输出 `references/onboarding-guide.md` 引导语（声明本次为功能介绍未执行任务）；用户已明确要开做可跳过。
5. **路由 Phase 1**：加载 pop-lantern-seed 按其 SKILL.md 执行（六步流水线共创《融合立项稿14维》：问诉求→定调研清单→调研→归集取材·卖点源→融合→定稿交接；**北极星六要素=遥远目标，锁根时同步定稿**）。**调研环节内嵌"立项前置采风"**：seed 定完调研清单后，触发 pop-snow-research 做**世界观定向 + 人物定向**基础轮批量采风（可派并行只读子 agent 分主题采集，回报主 agent 存档 `调研采风/采风/`），供 Phase 2 stage 建世界/人物直接取材——资料前置够用，不写到卡壳才补。**seed 定稿交接时产出"内容库配方指向块"（融合立项稿附录A.5）**——stage/plot/outline 开工按指向查对应库选配方换皮（见「内容库体系」）。

## 贯穿级·事实优先级裁决链（全线统一）

正文/章纲/设定/审查遇到**事实冲突**时，全线（seed/stage/plot/outline/write/review）按以下序列取证，**禁止倒着覆盖更高权位**——这是"约束由正文驱动"的落点：

| 权重 | 事实源 | 说明 |
|:--:|:--|:--|
| 最高 | **用户本轮临时要求** | 可覆盖既有事实，但必须**显式指出其与既有事实的冲突、记录改法**，不静默覆盖 |
| 2 | **已发布正文** | 明确写出的，最高文字权威 |
| 3 | **最新章节事实提取**（章日志） | 正文驱动的最近事实 |
| 4 | **角色卡当前状态** | 关系/能力/伤势/持有物/信息边界 |
| 5 | **世界书/设定规则** | 力量上限/地图/资源/制度 |
| 6 | **活跃伏笔与未解冲突** | 悬着未回收的线 |
| 7 | **大纲** | 剧情库/单元编排/章纲（优先级最低的叙事计划） |

> 裁决原则：叙事计划（大纲）低于已落地事实（正文/章日志/角色卡/世界书/伏笔）；用户临时要求权重最高，但**指出冲突是义务**——即使照办也让老板与后续环节知道改了什么、为什么改。遇"冲突该以哪条为准"拿不准时，按此表自上而下取证，不做临时拍板。说明：本裁决链吸收自 Mirror 09-审查专家的事实优先级 7 级，与全线统一。

## 单元剧循环状态机（4a-4e，路由参照）

**灯塔流 v3 骨架：遥远目标（北极星·形状级模糊）＋舞台（逐步扩展·配方驱动）＋单元剧循环（12-20章/单元，趋向终点）。卷已删除——单元剧是唯一剧情单元与推进节奏，阶段只是上升线表上的分组标记，不做卷纲。每一环开工前先查对应内容库（见「内容库体系」索引表）。**

### 每章收束（写一章的完整一圈 · 防止路由绕错）

每一章严格五步循环，**outline 写章纲永远在 write 之前，不许跳**：

```
outline 章纲 → write 正文(ch{NNN}.txt) → review 三件事 → 回到 outline 写 ch{NNN+1} 章纲 → …
```

- **review 三件事**：①确认本章正文满意（=定稿，未定稿不入库）②生成 `剧情日志/ch{NNN}.md`（事件源·只增不改）③更新 `剧情日志/全书日志.md`（当前态·只记活跃·replace，回收项落 `剧情日志/退出档案.md`）。
- **产物归谁消费**：review 产出的章日志/全书日志，喂给**下一章的 outline** 当章纲依据，**不是直接喂 write**——write 永远跟在章纲之后，不得跳过 outline 从日志直接开写。
- **对应状态机位**：`4b(outline) → 4c(write) → 4d(review) → 回 4b(下一章 outline)`；本单元末章 review PASS → 4e 剧末回看。

新书流程：`init → 1(seed) → 2(stage首喷骨架) → 3(plot 上升线表+单元1编排) → 单元循环`。其中**单元1前3章章纲（4b）按开篇三要素排**：outline 写 ch001-ch003 章纲时，按「落差→特权→小账+新标」设计并标注爽点，开篇承诺基线随前3章章纲写入全书日志——前3章不是空着硬排，也不脱离滚动循环单独跑。前3章已写的项目（导入/续写）跳过该设计，只做开篇复盘诊断。单元循环每单元一圈：

| 位 | 干什么 | skill | 配方库 | 产出 | 完成→下一位 |
|:--|:--|:--|:--|:--|:--|
| 3 | 上升线表（每单元一行：阶段/本集问题/上升维度/剧末钩子） | pop-lantern-plot 任务U | —（对照剧情-情绪映射表（plot 包）定情绪走向） | `剧情库/00-上升线表.md` | 4a（单元1编排） |
| 4a | 单元剧编排（选单元剧类型配方→套北极星方法武装→四拍标情绪目标） | pop-lantern-plot 任务E | **单元剧模板库**（plot 包）＋剧情-情绪映射表（plot 包） | `剧情库/单元N-编排.md` | 4b |
| 4a+ | 单元级调研+剧情素材实时搜索（轻量，编排有增量需求时跑） | pop-snow-research 场景② | — | `调研采风/采风/剧情-*.md` | 4a |
| 4b | 章纲拼接（剧情-情绪映射表定本章情绪坐标→套路库选剧情套路→反向设计剧情；每章一文件） | pop-lantern-outline | **剧情-情绪映射表**（plot 包）＋套路库（outline 包） | `章纲/ch{NNN}-章纲.md` | 4c |
| 4c | 正文渲染（2000-2500字/章） | pop-lantern-write | 文风样文库（P0 纯样文原文） | `正文/ch{NNN}.txt` | 4d |
| 4d | 审核+存档（PASS/REJECT；含爽点密度+情绪达标检查+配方生效记录） | pop-lantern-review | 剧情-情绪映射表（plot 包·达标参照） | `剧情日志/ch{NNN}.md`+`剧情日志/全书日志.md` | PASS→4b/4c下一章；REJECT→4c重写本章；本单元末章PASS→4e |
| 4e | 剧末回看（单元末章PASS后）：①review 单元级检查（起承转合/情绪目标兑现）②stage 模式C 重跑（沉淀/扩展/防漂移/人物分流）③plot 上升线推进（本行画勾+预告下一行）④配方生效回填内容库 | 主agent调度 review→stage→plot | 各环节包内容库（回填验证状态） | `剧情日志/单元N-回看.md`+舞台台账增量+上升线表本行更新 | 回 4a（下一单元） |

> **单元1 前3章的开篇承诺基线（1+1>2）**：pop-lantern-outline 写 ch001-ch003 章纲时，把开篇承诺（第3章新标/特权信息备忘/对比触发器锚点）随章纲写入全书日志，后续 outline 写章纲时可引用"主角正往那个新标推进"；plot 上升线表评审"距终点贡献"时校验开篇立的标是否在预期章节兑现——开篇从"只把关一次"升维成"全书承诺基线"。

**单元内滚动**：推荐「4a产单元N → 4b拼单元N章纲 → 4c/4d逐章 → 4e剧末回看 → 4a产单元N+1」，让后续单元吸收正文成果。

**4e 剧末判定**：单元编排预算章数耗尽+单元三件套（本集问题解决+上升一格兑现+下集钩子立住）完成→本单元完，进 4e 回看后开下一单元。

**状态.md 更新协议**（谁干活谁更新，只更新涉及字段，不全量替换）：

| 时机 | 更新 |
|:--|:--|
| 各 skill 完成 | phase 推进到状态机下一位 + updated_at + 就绪态对应项 [x] + 最近产出追加一行 |
| seed 完成 | 另更新 seed_path + 书目（book_name/one_line） |
| 单元1前3章章纲完成 | 若 phase 在 4+，project 就绪态补标 前3章章纲[x]，最近产出追加一行 |
| write/review 每章 | current_chapter+1（review PASS 后），phase 在 4b/4c/4d 间流转 |
| 4e 剧末回看 | current_unit+1 + 单元编排/章纲/正文/章日志就绪态清零 + phase=4a |

pipeline 只在初始化/导入时写 phase；日常推进由各 skill 完成后按本表更新。

## 存档质量检查（deai_gate.py，本包 scripts 统一管理）

去AI味检查脚本归本包 `scripts/deai_gate.py`（配置外置 `scripts/deai_profiles.json`，纯 stdlib），双 profile 服务全管线存档质量。**各 skill 存档后自跑，不进 LLM、不派子agent。**

| profile | 服务对象 | 性质 | 检测面 | 调用 |
|:--|:--|:--|:--|:--|
| `body`（默认） | write 正文（`正文/ch{NNN}.txt`） | **打回检查**：FAIL 必须清零才算存档完成 | 套话硬模板~120条/软密度~28组/结构统计/工具痕迹四层，阈值按人书基线校准 | `python skills/pop-lantern-pipeline/scripts/deai_gate.py 正文/ch{NNN}.txt --fix --json` |
| `doc` | 非正文文档（seed 融合立项稿 / research 调研拆书包 / stage 长档·舞台 / plot 上升线表·单元编排 / outline 章纲 / review 章日志全书日志 / decon 拆书wiki成品 / dna-style 文风锚定说明文字，及拆书/卖点/大纲/世界观类） | **报告检查**：只 WARN+定位，不打回 | 黑话（hard 实锤/soft 风格分层）+套路句式+空腔段+生成器残留；分号/破折号/括号/列举行/工程emoji标记/0%对话一律放行 | `python skills/pop-lantern-pipeline/scripts/deai_gate.py <文件或目录> --profile doc --json`（目录加 `-r` 递归，含聚合热点统计） |

**边界三条**：
1. 工程标签（【锚】/养成刻度/单元末边界等精确技术名）不做去AI化改写——去AI味只作用于叙事主体。
2. 自动修仅限零风险机械项（英文标点/HTML残留/零宽字符等36类）；滥用类只报不自动改。
3. `doc` 的 WARN 清单由存档 agent 按上下文判断：装腔换大白话，行话正常用可放行（回复注明放行理由）；**词库类文档自指命中豁免**——`pop-ai-reduce-lite` 词表 / write 检测面说明等文档本身讨论这些特征词，命中属合法引用非残留。

**词库蓝本与维护**：doc 黑话/套话词库吸收自 `pop-ai-reduce-lite/resources/banned-words.md`（v3.2 全量类别）+ 老板点名 seed/设定场景词；v3.3/v3.4 广泛搜索轮补齐（维基 Signs of AI writing / Humanizer 35条军规 / cn-humanizer / 连享会 / OpenAI slop words / 番茄拒签七破绽实测——企业黑话/宣传腔/万能收尾/模糊来源/假坦率/虚假替代/公式化谚语/浅层象征词）。管线自身行话（赛道/卖点/爽点/钩子等）与语料专有名词/世界观字面义（封神/版图/天花板/破局等）不入库——v3.4.1 按 wiki 语境抽样校准。`deai_profiles.json` 与代码内 `DEFAULT_DOC_CFG` 兜底须同步维护。

**阈值/词库调校**：改 `scripts/deai_profiles.json` 即可，不改代码；改后跑回归（负面样例高召回+人书零误杀+wiki/skills 误伤增量可控）再生效。
