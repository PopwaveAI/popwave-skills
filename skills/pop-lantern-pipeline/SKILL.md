### 开工前须完成的检查（贯穿本技能与全流程）

开工前与定稿前各执行一次，自查三问：本产出若要更好，尚缺哪些未见过的候选面？当前信息是否充足？是否存在未探索的更优选项？

- **一、先找出缺口。** 将"若要更好还须见过哪些面"明确列出，再列出已覆盖项，二者之差即为缺口。缺口内只要尚有一个维度未覆盖，即须取材。取材成功即采用；取材失败，不得勉强成文。
- **二、缺口足够时方可取材。** 检索项自拟。来源优先使用内部 wiki 站 **https://wiki.popwave.cn**，不足时再补充网络检索。单个环节最多取材一轮，一轮最多提出五个检索项，单次回传不超过 30KB；超出上限即截断，仅保留结论。
- **三、交付候选须附依据。** 以本技能的判断尺，将现有项与候选项并列制成打分表，不得以一句"这样更好"带过。只能交付候选或升级版，最终选定不由本环节决定。
- **四、交付后复检。** 产出或候选交付后，自查"此为上限否，是否有更优候选"。确有更优者方可升级重议，上限两轮。

取材内容仅进入上下文，仅当升级被采纳后方可写入产出。

## 职责范围

| 职责 | 说明 |
|:--|:--|
| 一次性安装（fresh） | 创建目录，写入 `状态.md`（精简状态文件），按需导出展示面板与 README |
| 一次性导入/续写（import/resume） | 依次执行资产扫描、文件归位、缺口分析、落地 Phase 判定、状态重建、补跑调度 |
| 状态文件维护 | `状态.md` 为唯一状态总账，agent 只读写其中的状态片段；`项目总控.html` 是仅供老板查看的展示面板，按需导出，**agent 不读取 html** |
| **内容库体系索引** | 内容库分散归各环节包持有：plot 持有剧情-情绪打分表与单元剧模板库，outline 持有套路库，stage 持有力量体系模板库与世界观模板库。pipeline 只维护统一索引表与消费纪律，不持有库文件 |

**日常路由不经本技能**：用户说"继续写""下一步""写正文""审核"时，主 agent 按专家提示词的阶段地图直接选定 skill，先读取 `状态.md` 取得状态片段（mode/phase/current_unit/current_chapter/就绪态），路由参照下方「单元剧循环状态机」。pipeline 不写正文，不做内容转换，不常驻。

**执行方式**：由主 agent 直接执行。初始化与导入交互（资产清点、缺口确认、落地决策）由主 agent 完成；生成任务由主 agent 加载对应子 skill 执行。不得派发子 agent 执行 skill 生成任务。

## 内容库体系（灯塔流 v3 核心）

**本管线的做法**：agent 不凭空创造内容，而是从库中择取配方，换皮适配。LLM 凭空生成只能得到平均质量的网文；采用经真小说抽离并验证过的配方再适配，质量下限被拉高。这是 AI 写小说跑通的底层方法。

> **内容库模板不足时的硬性规定（2026-09-11 老板拍板）**：当前内容库各库多为占位与示范，回填不足，**各环节不得假设"库里有配方"**。对应库没有匹配配方时，必须走 research 现场提取或定向补采（各环节 SKILL.md 的取材检查均为硬性，见下），不得跳过取材凭感觉硬写。

### 统一库规（每库头部一致，新增条目照此写）

```
- 名称：{配方名}
- 内核：{可复用的核心结构/机制，3-5句}
- 来源：{哪本书/哪类作品抽离}
- 验证状态：{头部作品/普通验证/待验证}
- 适配规则：{什么题材能用/怎么换皮}
- 不可动硬核：{哪些部分禁止改}
```

### 消费纪律（全管线统一）

1. **先查库，再创造**：对应环节开工前必须查对应库。库中有配方时，择取配方换皮适配；库中没有时，现场提取（由 research 聚焦调研查实），并在 **48 小时内回填**，标注"待验证"。
2. **一个主配方加微调，不得多配方硬拼**：只择取一个主配方，其余只能作配料。拼接两个主配方必定串味。
3. **适配不改内核**：换皮只改动名称、场景、题材外壳；"不可动硬核"字段不得改动。
4. **回填验证**：review 记录"哪套配方生效、效果如何"，对应库同步更新验证状态。
5. **跨项目资产**：内容库按库归持有环节包管理，谁持有谁负责回填验证；任何灯塔流项目均可跨包消费。回填时注明提取自哪个项目（书名或项目名）。

### 剧情-情绪打分表特殊地位（审美固定位）

情绪刻度以 `{pop-lantern-plot}/references/内容库/剧情-情绪打分表.md`（plot 包）为**唯一权威参照**，不得另立刻度。**引用纪律（2026-09-11 老板拍板）：本文件不复制打分表内容**（情绪清单、8 分示例、铺垫规则），需要时打开打分表查级：第二节情绪模块（基础四情主推、高阶慎赌）、第三节分数档位（铺垫成本为硬性约束）、第四节情绪细则（"铺垫至引爆"的剧情落点）、第五节峰值规则、第六节反例区。标注格式为 `{情绪}·{分值}`（可并列）。**同源声明**：打分表与 `pop-outline/references/剧情-情绪打分表.md` 同源，结构、示例与规则一致；**同源同步是打分表本身的事**，本文件只索引不持有。

## 怎么操作（规程全内联）

### Step 0：导入/续写模式

> 触发条件（满足任一）：一、用户说"导入""续写""已有""接续""迁移"；二、执行 Step 1 初始化时检测到 `正文/` 或 `设计库/` 已有文件；三、项目目录已有内容但无 `状态.md`。
> 理念：pipeline 只做调度，不做内容生产。本环节只负责资产清点、文件归位、缺口分析、补跑调度；深度内容转换（正文反推、设计补建）由主 agent 加载对应 skill 完成。

| `pipeline-relocated` | pipeline 做了格式转换（.docx→.md 等） | ⚠️需校验 |
| `skill-generated` | 对应skill正向产出 | 正常消费 |

**0c 缺口分析**：归位完成后对照依赖链逐位检查。就绪判定为文件存在，查文件系统：

| 位 | 就绪判定 |
|:--|:--|
| 1 | `立项/00-融合立项稿14维.md`（旧版三件 01/02/03 齐也可，调度 seed 转写） |
| 1a | `调研采风/采风/` 世界观-*.md 与 人物-*.md（立项前置采风，seed 后必跑） |
| 2 | `设计库/` 五长档：世界全书、力量体系、位阶-社会坐标谱、势力格局、基调母题（类型风味基线随首喷），以及 `人物库/` 两档：主角、角色库 |
| 3 | `剧情库/00-上升线表.md` |
| 4a | `剧情库/单元N-编排.md`（N=当前单元号） |
| 4b | `章纲/ch{NNN}-章纲.md`（NNN=下一章待写；单元1前3章章纲含开篇三要素与爽点标注） |
| 4c | `正文/ch*.txt`（current_chapter=最大编号+1） |
| 4d | `剧情日志/` + `剧情日志/全书日志.md` |

进度检测：`正文/` 有文件时，提取最大章节号，current_chapter 取下一章待写章号；单元号取 `剧情库/` 与 `设计库/舞台/` 中的最大单元号，无则为 1。质量来源检测：user-original 与 pipeline-relocated 标 ⚠️需校验；skill-generated 标 ✅。最终输出缺口报告。

**0d 落地 Phase 决策**（依据缺口报告与正文进度）：

| 条件 | mode | 落地位 | 说明 |
|:--|:--|:--|:--|
| 正文有、章日志有、全书日志有 | resume | 4b 或 4c | 状态完整：下一章章纲已拼接时取 4c，未拼接时取 4b |
| 正文有、账本缺（章日志或全书日志） | resume | 先由 0f 调度 review reconstruct，再取 4b/4c | 需补账本 |
| 正文无、单元编排有 | import | 4b（outline） | 缺章纲 |
| 正文无、上升线表有（首喷完成） | import | 4a（plot 单元编排） | 进单元循环 |
| 正文无、融合立项稿有 | import | 2（stage 首喷） | 缺舞台 |
| 全无 | fresh | 1（seed） | 走 Step 1 初始化 |

向用户展示资产清单（含来源标记）、缺口报告、落地 Phase 建议与补跑建议清单（0f），**经用户确认后**进入 0e。

**0e 状态文件重建**：`状态.md` 不存在时，按「状态.md 模板」创建；已存在时用 SearchReplace 更新。字段：mode、phase、current_unit、current_chapter、seed_path（仅路径 C 项目填写）、就绪态按 0c 标 [x]。展示面板为可选项：老板要求时按 `templates/项目总控.html` 填入数值导出。

**0f 调度 skill 补跑**（pipeline 只识别缺口、调度与汇报，不自行做内容转换）：

| 缺口类型 | 调度 skill | 处理内容 |
|:--|:--|:--|
| 有正文、缺章日志或全书日志 | pop-review reconstruct | 批量回溯审核：采样生成逐章章日志与全书日志 |
| 缺立项、舞台、剧情或章纲文档 | 对应 skill（seed/stage/plot/outline） | 读取已有文件，按该 skill 的方法论校验并补全，产出标准格式 |
| 缺前置采风、单元采风或章纲场景料 | pop-snow-research | 按缺口类型定向补采（世界观、人物、剧情、场景），写入 `调研采风/采风/` |
| 已有文档但来源为 user-original | 对应 skill（用户确认后按需） | 校验后标注缺口或确认达标 |

- review reconstruct 采样规则：10 章以内全审；11 至 30 章取最近 5 章，另每 5 章取 1 章；超过 30 章取最近 5 章与第一章，另每 10 章取 1 章。产出 `剧情日志/ch{NNN}.md` 与 `剧情日志/全书日志.md`。
- 设计文档补跑按依赖链顺序执行：stage（设计库五长档：世界全书、力量体系、位阶-社会坐标谱、势力格局、基调母题；人物库两档：主角、角色库），随后 plot（上升线表、单元编排），最后 outline（章纲）。用户已有正文但缺剧情文档时，由 plot 从正文反推；用户选择跳过 plot 直接续写（降级模式）时，在全书日志手动指定下一章核心事件。
- 不调度的情况：素材层文件由 pipeline 自行按标准分节重组；文风锚定.md 缺失时提示用户执行 pop-dna-style（非 reconstruct 场景）。
- 补跑建议清单：逐文件一行，格式为文件名、来源、状态、建议（正常消费或补跑某 skill）。用户三选：正常接续、按需补跑、全量补跑。

**Step 0 质量检查**：原始资产清单已生成；归位完成（含来源标记）；缺口报告已生成；落地 Phase 经用户确认；`状态.md` 已创建或更新；补跑建议清单已展示。

### Step 1：初始化（fresh 模式）

**前置检测**：执行任何创建动作前先用 LS 扫描。`正文/` 有章节文件，或 `设计库/` 有 .md 文件时，跳转「Step 0 导入/续写」；目录为空或仅有 `状态.md` 时，继续本步。

1. **创建目录（一次性）**：依次创建 `调研采风/`（含 `采风/`）、`原始资料/`（含 `downloads/`、`知识沉淀/`）、`立项/`、`设计库/`（含 `舞台/`）、`人物库/`、`剧情库/`、`章纲/`、`正文/`、`剧情日志/`、`文风dna/`、`草稿/`。创建后用 LS 自检是否全部存在，缺一即为初始化失败，补建后方可继续。（`调研采风/采风/` 为定向采风库，存放 research 的世界观、人物、剧情、场景四类定向采风，文件名规范 `{定向}-{主题}.md`；`原始资料/` 存放源书、下载物、设定包与参考答案；`文风dna/` 存放 文风锚定.md；`草稿/` 存放临时未定稿）
2. **创建 `状态.md`**：按「状态.md 模板」写入项目根（mode: fresh、phase: init、current_unit: 1、current_chapter: ch000，全部就绪态标 [ ]）；再简建 README.md，含项目信息、目录说明与指向 `状态.md` 的说明。
3. **展示面板（可选）**：老板要求时按 `templates/项目总控.html` 套用 `状态.md` 的数值导出；agent 只写 `状态.md`，不读取 html。
4. **首次对话引导**：用户第一次触发且无项目时，先输出 `references/onboarding-guide.md` 的引导语，并声明本次为功能介绍、未执行任务；用户已明确要开做时可跳过。
5. **路由 Phase 1**：加载 pop-lantern-seed，按其 SKILL.md 执行（六步流水线共创《融合立项稿14维》，即问诉求、定调研清单、调研、归集取材与卖点源、融合、定稿交接；**北极星六要素为遥远目标，锁根时同步定稿**）。**立项前置采风（硬性 Step）**：seed 定完调研清单后，**必须执行** pop-snow-research，完成**世界观定向与人物定向**基础轮的批量采风（可派并行只读子 agent 分主题采集，回报主 agent 后写入 `调研采风/采风/`），产出计入就绪态 `前置采风[x]`，stage 首喷前必查，未完成不进首喷。当前内容库模板不足，各环节不得假设"库里有配方"，资料须靠 research 前置补足，不得写到卡壳才补。**seed 定稿交接时产出"内容库配方指向块"（融合立项稿附录 A.5）**，stage、plot、outline 开工时按指向查对应库，择取配方换皮（见「内容库体系」）。

**Step 1 质量检查**：目录齐全，`状态.md` 已存档；README 已存档。

## 贯穿级·事实优先级裁决顺序（全线统一）

正文、章纲、设定或审查遇到**事实冲突**时，全线（seed、stage、plot、outline、write、review）按以下序列取证，**不得倒序覆盖更高权位的事实**。这是"约束由正文驱动"的落实点：

| 权重 | 事实源 | 说明 |
|:--:|:--|:--|
| 最高 | **用户本轮临时要求** | 可覆盖既有事实，但必须**显式指出其与既有事实的冲突、记录改法**，不静默覆盖 |
| 2 | **已发布正文** | 正文中明确写出的内容，为最高文字权威 |
| 3 | **最新章节事实提取**（章日志） | 正文驱动的最近事实 |
| 4 | **角色卡当前状态** | 关系、能力、伤势、持有物、信息边界 |
| 5 | **世界书/设定规则** | 力量上限、地图、资源、制度 |
| 6 | **活跃伏笔与未解冲突** | 悬着未回收的线 |
| 7 | **大纲** | 剧情库、单元编排、章纲（优先级最低的叙事计划） |

> 裁决原则：叙事计划（大纲）低于已落地事实（正文、章日志、角色卡、世界书、伏笔）；用户临时要求权重最高，但**指出冲突是义务**，即使照办也须让老板与后续环节知道改了什么、为什么改。遇"冲突该以哪条为准"无法确定时，按此表自上而下取证，不做临时拍板。说明：本裁决顺序吸收自 Mirror 09-审查专家的事实优先级 7 级，与全线统一。

## 单元剧循环状态机（4a-4e，路由参照）

**灯塔流 v3 骨架由三部分组成：遥远目标（北极星，形状级模糊）、舞台（逐步扩展，配方驱动）、单元剧循环（每单元 12 至 20 章，趋向终点）。卷已删除，单元剧是唯一剧情单元与推进节奏，阶段只是上升线表上的分组标记，不做卷纲。每一环开工前先查对应内容库（见「内容库体系」索引表）与采风库（`调研采风/采风/`）；库或采风库无料时，必须先补跑 research 定向采风再开工（取材检查为硬性，不得凭感觉硬写）。**

### 每章收束（写一章的完整循环，防止路由绕错）

每一章严格按五步循环执行，**outline 写章纲永远在 write 之前，不得跳过**：

```
outline 章纲 → write 正文(ch{NNN}.txt) → review 三件事 → 回到 outline 写 ch{NNN+1} 章纲 → …
```

- **review 三件事**：一、确认本章正文满意，即定稿，未定稿不入库；二、生成 `剧情日志/ch{NNN}.md`（事件源，只增不改）；三、更新 `剧情日志/全书日志.md`（当前态，只记活跃项，replace，回收项写入 `剧情日志/退出档案.md`）。
- **产物的消费方**：review 产出的章日志与全书日志，传给**下一章的 outline** 作为章纲依据，**不直接传给 write**。write 永远跟在章纲之后，不得跳过 outline 直接从日志开写。
- **对应状态机位**：`4b(outline) → 4c(write) → 4d(review) → 回 4b(下一章 outline)`；本单元末章 review PASS 后进入 4e 剧末回看。

新书流程为 `init → 1(seed) → 2(stage首喷骨架) → 3(plot 上升线表+单元1编排) → 单元循环`。其中**单元1 前 3 章章纲（4b）按开篇三要素排布**：outline 写 ch001 至 ch003 章纲时，按「落差→特权→小账+新标」设计并标注爽点，开篇承诺基线随前 3 章章纲写入全书日志。前 3 章不是空着硬排，也不脱离滚动循环单独执行。前 3 章已写的项目（导入或续写）跳过该设计，只做开篇复盘诊断。单元循环每单元为一轮：

| 位 | 做什么 | skill | 配方库 | 产出 | 完成后进入 |
|:--|:--|:--|:--|:--|:--|
| 3 | 上升线表（每单元一行：阶段、本集问题、上升维度、剧末钩子） | pop-lantern-plot 任务U | —（对照剧情-情绪打分表（plot 包）定情绪走向） | `剧情库/00-上升线表.md` | 4a（单元1编排） |
| 4a+ | 单元级调研与剧情素材实时搜索（**每单元编排前必须执行一轮**：由剧情定向 research 采集冲突升级、转折、解开模型；编排前查 `调研采风/采风/剧情-*`，无对应种子时必补采） | pop-snow-research 场景② | — | `调研采风/采风/剧情-*.md` | 4a |
| 4a | 单元剧编排（择取单元剧类型配方，套用北极星方法武装，四拍标注情绪目标） | pop-lantern-plot 任务E | **单元剧模板库**（plot 包）与剧情-情绪打分表（plot 包） | `剧情库/单元N-编排.md` | 4b |
| 4b | 章纲拼接（剧情-情绪打分表定本章情绪坐标，套路库择取剧情套路，反向设计剧情；每章一文件） | pop-outline | **剧情-情绪打分表**（plot 包）与套路库（outline 包） | `章纲/ch{NNN}-章纲.md` | 4c |
| 4c | 正文写作（每章 2000 至 2500 字） | pop-write | 文风样文库（P0 纯样文原文） | `正文/ch{NNN}.txt` | 4d |
| 4d | 审核与存档（PASS 或 REJECT；含爽点密度、情绪达标检查、配方生效记录） | pop-review | 剧情-情绪打分表（plot 包，达标参照） | `剧情日志/ch{NNN}.md` 与 `剧情日志/全书日志.md` | PASS 后进入 4b 或 4c 写下一章；REJECT 后回 4c 重写本章；本单元末章 PASS 后进入 4e |
| 4e | 剧末回看（单元末章 PASS 后）：一、review 做单元级检查（起承转合、情绪目标兑现）；二、stage 模式C 重跑（沉淀、扩展、防漂移、人物分流）；三、plot 推进上升线（本行画勾，预告下一行）；四、配方生效回填内容库 | 主 agent 调度 review → stage → plot | 各环节包内容库（回填验证状态） | `剧情日志/单元N-回看.md` 与舞台台账增量、上升线表本行更新 | 回 4a（下一单元） |

> **单元1 前 3 章的开篇承诺基线（1+1>2）**：pop-outline 写 ch001 至 ch003 章纲时，把开篇承诺（第 3 章新标、特权信息备忘、对比触发器锚点）随章纲写入全书日志，后续 outline 写章纲时可引用"主角正往那个新标推进"；plot 上升线表评审"距终点贡献"时，校验开篇立的标是否在预期章节兑现。开篇由此从"只把关一次"升维为"全书承诺基线"。

**单元内滚动**：推荐「4a+ 采风 → 4a 产出单元 N → 4b 拼接单元 N 章纲 → 4c 与 4d 逐章执行 → 4e 剧末回看 → 4a+ 采风 → 4a 产出单元 N+1」，让后续单元吸收正文成果。

**4e 剧末判定**：单元编排预算章数耗尽，且单元三件套（本集问题解决、上升一格兑现、下集钩子立住）完成时，本单元完成，进入 4e 回看后开下一单元。

**状态.md 更新协议**（谁执行谁更新，只更新涉及字段，不做全量替换）：

| 时机 | 更新 |
|:--|:--|
| 各 skill 完成 | phase 推进到状态机下一位，更新 updated_at，就绪态对应项标 [x]，最近产出追加一行 |
| seed 完成 | 另更新 seed_path 与书目（book_name、one_line） |
| 立项前置采风完成 | 就绪态 前置采风 世界观采风[x] 人物采风[x] |
| 单元1 前 3 章章纲完成 | 若 phase 在 4 及以后，就绪态补标 前3章章纲[x]，最近产出追加一行 |
| 4a 单元编排完成 | 就绪态 单元采风[x] 单元编排[x]（4a+ 采风先于编排） |
| write 与 review 每章 | review PASS 后 current_chapter 加 1，phase 在 4b、4c、4d 间流转 |
| 4e 剧末回看 | current_unit 加 1，单元采风、单元编排、章纲、正文、章日志就绪态清零，phase 置为 4a |

pipeline 只在初始化或导入时写 phase；日常推进由各 skill 完成后按本表更新。

## 存档质量检查（deai_gate.py，本包 scripts 统一管理）

去AI味检查脚本归本包 `scripts/deai_gate.py` 管理与维护（配置外置为 `scripts/deai_profiles.json`，纯 stdlib），双 profile 服务全管线存档质量。**各 skill 存档后自行执行，不进入 LLM，不派子 agent。**

**去AI味确认行入交接协议（硬性，2026-09-11 老板拍板）**：seed、stage、plot、outline、write 存档后自行执行去AI味，随后**必须回报一行 `去AI味:{档名}|PASS` 或 `WARN×N`**；**缺此确认行即交接不完整**。review 第 1 步核验上游确认行（write 正文 FAIL 清零，outline 章纲），其余环节的确认行由**下游收档时首查**（stage 收 seed、plot 收 stage、outline 收 plot 的 `去AI味:...|PASS 或 WARN×N`）。确认行进入对话交接，不写入档案。

| profile | 服务对象 | 性质 | 检测面 | 调用 |
|:--|:--|:--|:--|:--|
| `body`（默认） | write 正文（`正文/ch{NNN}.txt`） | **打回检查**：FAIL 必须清零才算存档完成 | 套话硬模板约 120 条、软密度约 28 组、结构统计、工具痕迹四层，阈值按人书基线校准 | `python skills/pop-lantern-pipeline/scripts/deai_gate.py 正文/ch{NNN}.txt --fix --json` |
| `doc` | 非正文文档（seed 融合立项稿、research 调研拆书包、stage 长档与舞台、plot 上升线表与单元编排、outline 章纲、review 章日志与全书日志、decon 拆书 wiki 成品、dna-style 文风锚定说明文字，以及拆书、卖点、大纲、世界观类） | **报告检查**：只报 WARN 并定位，不打回 | 黑话（hard 实锤、soft 风格分层）、套路句式、空腔段、生成器残留；分号、破折号、括号、列举行、工程 emoji 标记、0% 对话一律放行 | `python skills/pop-lantern-pipeline/scripts/deai_gate.py <文件或目录> --profile doc --json`（目录加 `-r` 递归，含聚合热点统计） |

**边界三条**：
1. 工程标签（【锚】、养成刻度、单元末边界等精确技术名）不做去AI化改写；去AI味只作用于叙事主体。
2. 自动修仅限零风险机械项（英文标点、HTML 残留、零宽字符等 36 类）；滥用类只报不自动改。
3. `doc` 的 WARN 清单由存档 agent 按上下文判断：装腔处换成大白话，行话正常使用可放行（回复时注明放行理由）；**词库类文档自指命中豁免**——`pop-ai-reduce-lite` 词表、write 检测面说明等文档本身讨论这些特征词，命中属合法引用，非残留。

**词库蓝本与维护**：doc 黑话与套话词库吸收自 `pop-ai-reduce-lite/resources/banned-words.md`（v3.2 全量类别）及老板点名的 seed、设定场景词；v3.3、v3.4 通过广泛搜索轮补齐（维基 Signs of AI writing、Humanizer 35 条军规、cn-humanizer、连享会、OpenAI slop words、番茄拒签七破绽实测，涵盖企业黑话、宣传腔、万能收尾、模糊来源、假坦率、虚假替代、公式化谚语、浅层象征词）。管线自身行话（赛道、卖点、爽点、钩子等）与语料专有名词、世界观字面义（封神、版图、天花板、破局等）不入库，v3.4.1 已按 wiki 语境抽样校准。`deai_profiles.json` 与代码内 `DEFAULT_DOC_CFG` 的补足配置须同步维护。

**阈值与词库调校**：改 `scripts/deai_profiles.json` 即可，不改代码；改后执行回归（负面样例高召回、人书零误杀、wiki 与 skills 误伤增量可控）再生效。
