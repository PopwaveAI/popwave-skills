# pop-lantern-stage

> 舞台设定——世界与角色的唯一产出方（长档方）。当前版本 v4.0.0（灯塔流 v3：配方驱动——建力量体系/世界骨架前先查内容库选配方换皮），完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

### 心智前置·意识层（贯穿本 skill 与全流程）

动笔/定稿前自问：本产出要更好，还需要看过哪些候选？当前信息够不够？有更优选项没探索？

- **Know-Gap**：先显式列出"要更好需见过哪些候选面"，再列已覆盖，缺口=差值；缺口≥1 个未覆盖维度才触发取材，缺了取、别硬写。
- **Pack**：缺口足够才取材，query 自生成；来源 **wiki 站 https://wiki.popwave.cn** 居先、网络补齐；单环节 ≤1 轮 / ≤5 query / 回传 ≤30KB，超限截断仅留结论区。
- **Worth**：拿本 skill 决策尺对"现有 vs 候选"必给打分表，禁止一句"更优"带过；只端候选/升级版，不越权定终局。
- **Deepen**：产出/候选后自问"这是天花板吗？有更优候选吗？"显著更优才升级再问，上限 2 轮。

取材仅进上下文，升级被采纳才落产出。

## 做什么

stage 把 seed 融合立项稿的**世界观组（1-4）＋人物组（5-7）＋北极星块**长成可落笔的**长档**。**长=扩展补充丰富，不是换张表格抄主干**——每层只做"上一层没做、但下一层真需要的增量"。剧情归 plot、表达归 write。

**灯塔流 v3 舞台哲学：逐步扩展＋配方驱动，不做全集预设。** 首喷只立"骨架"（主角+核心配角+世界骨架+力量体系方向），单元循环中按需扩展，单元末重跑沉淀——写多少记多少，不一次性把两百万字的设定全部造完。**建力量体系/世界骨架前先查内容库选配方换皮（力量体系模板库/世界观模板库），agent 不凭空创造内容。**

**14维 → 长档地图**：

| seed 维 | 长档（设计库/人物库/文风dna 分档存档） |
|:--|:--|
| 1 世界形态 | `世界全书.md` |
| 2 力量体系 | `力量体系.md` ＋ 配套档 `位阶-社会坐标谱.md` |
| 3 势力格局 | `势力格局.md` |
| 4 基调/母题 | `基调母题.md` |
| 5 主角（含金手指） | `人物库/主角.md` |
| 6 主角团/配角 | `人物库/角色库.md`（长期角色档） |
| 7 反派/敌人 | `人物库/角色库.md`（反派敌梯） |
| —（write 方向参照） | `文风dna/类型风味基线.md`（命名参考系＋复用名词库） |
| —（涌现归档） | `人物库/剧档案/`（单元剧涌现角色，一次性/待升格） |

**三种模式**：

| 模式 | 触发 | 干什么 |
|:--|:--|:--|
| A 首喷骨架 | 无 `人物库/主角.md` | 新书一次：消费 `立项/00-融合立项稿14维.md`（含北极星块）＋**力量/世界观模板库**，只立**骨架**——主角＋核心配角＋世界骨架＋力量体系方向，不追文件全家桶 |
| B 按需扩展 | plot 单元剧编排的舞台增量需求 | 单元循环中：编排点哪块长哪块（新地图/新势力/新规则），回填对应长档 |
| C 剧末重跑 | 每单元末（4e） | 四动作：沉淀（本单元新事实入台账）→扩展（下一单元预告所需设定）→防漂移（校验违反已设定）→人物分流（涌现角色 Triage 归档） |

**占位符实名（首喷第一动作，seed 对接）**：seed 的立项稿是占位符版——人物用「主角/主角团A/卷敌A/终敌」＋功能描述，世界/力量体系只有功能级描述，命名留给 stage。首喷时先消费立项稿头部的**占位符实名表**：逐占位符定实名（人物名/地名/体系名，走命名参考系造词），填回实名表并同步各长档——实名后全管线以实名称呼。**实名是创作不是翻译**：好的实名自带味道（人名有身世感、体系名有世界观），不许敷衍音译；功能描述锁定的角色功能不许改名漂移。

**长档四原则（长档尺，逐档过）**：

1. **参考源真落地（否决条款）**：任一关键复用点未吃透/未查实（没走聚焦调研、没法回源），该档不达交付标准。禁止"为凑满而挂复用源"——没吃透就张冠李戴标"复用自X"，是本轮最重的教训。
2. **一档只服务 seed 特指主干**：长的是 seed 点名的那根主干；不发明 seed 没定的故事方向，方向不足或矛盾→报错回上游（seed/plot），不在 stage 层自己补。
3. **有温度画面**：关键条目带"正文长什么样"的可落笔描述（战斗气质/一句画面）。只有规则没有画面，write 不知道怎么落笔。
4. **待补强项补掉**：seed 待补强清单点名的问题必须消化；消化不掉的显式登记回待补强清单，不许装看不见。

**复用域纪律（力量体系尤其如此）**：

- **先查内容库**：`references/内容库/力量体系模板库.md`（pipeline 包）有配方→选一个主配方换皮适配（适配规则/不可动硬核见库内）；库没有→主动搜相似赛道最有名那套复用（派 research 聚焦调研查实）→**48 小时内回填库**（六字段齐全，标"待验证"）。
- 能复用就复用，不原创：有参考→消化其**分级方式**；没参考→主动搜相似赛道最有名那套复用。
- 自定义的是**成长斜率**（多少内容爬多少阶、前期陡中段换节奏后期重质量），不是阶位本身。
- 数值刻度从参考来：钉"板式＋跨度"，具体数值留给正文按板式现算（防拍脑袋返工）。

**位阶-社会坐标谱（力量体系配套档）**：纵轴=全书完整位阶，每档横摆战力表现/社会地位/大众感知三坐标——让"主角爬到第几阶=多高"可感知；同时钉死世界金字塔约束（满街不见高阶）。plot 排上升线表、write 写量级都拿它当参照系。

**执行模式**：主agent直执。用户在场时关键决策走交互轮（给选项不给空白，每轮2-3方案+自定义入口）；不在场 agent 自定并在档头标注"agent 自定"。

## 怎么操作（SOP全内联）

### 模式A：首喷骨架（新书一次）

```
Step 0  输入加载：立项/00-融合立项稿14维.md 全文（含北极星块）＋待补强清单
Step 1  查内容库：力量体系模板库＋世界观模板库——选主配方（换皮适配）
Step 2  北极星关键人物先行：主角档＋终局关键人物骨架（长期角色档）
Step 3  世界骨架＋力量体系方向＋位阶-社会坐标谱配套档
Step 4  类型风味基线（命名参考系＋复用名词库）
Step 5  逐档过长档尺 → 去AI味 → 交接 plot
```

**Step 0 输入加载**：读融合稿全文，重点取世界观组、人物组、北极星块（关键人物/主角终态）、附录A机制溯源、附录B待补强清单。输入路径判定：改编=另读拆书成果当质量参照（有则必用，不抄事件不抄人名）；半成书=另读已有正文反推既有设定。

**Step 1 查内容库（配方驱动第一步）**：打开 `references/内容库/力量体系模板库.md`＋`世界观模板库.md`（pipeline 包）——有匹配配方→选一个主配方，按库内"适配规则/不可动硬核"换皮；库没有→现场提取（搜相似赛道最有名那套，派 research 聚焦调研查实）并准备回填。**一个主配方＋微调，禁多配方硬拼；换皮动外壳，不动硬核。**

**Step 2 主角档＋终局关键人物（北极星关键人物先行，只立骨架）**：

- **主角档**：攀登方式/起点阶位/性格（写行为倾向——"嘴硬心软，总在暗地里帮忙"，不写"善良勇敢"）/小传≥200字/成长线/语言指纹；**标签上限**：核心标签 ≤2-3 个（力量/智慧/个性/情感/信念 5 型里选），再定 **1 个核心情绪主轴**（逆袭/重生/穿越/系统/无限/日常，可混合但情绪单主轴）作一致性基准——**越多越写散**；金手指三约束（是钥匙不是资源机器/强化不越级/限制写明白）
- **终局关键人物（北极星块"关键人物"指名者）**：只立骨架卡——功能位/与主角的关系/欲望一句/终局站位——**名字实名，细节等其在单元剧中登场时再长**。北极星埋种第一条：终局关键人物必须早期登场，错过登场窗口=回写。
- **角色原型联动（写前必刮 wiki，人物复用域）**：建每个角色前，先查 wiki 取原型——**`素材原型库/人设原型/`** 按定位作**搭主干选型**；再翻**`赛道设定集/{本书赛道}/角色库`**取该赛道已验证角色做**同级参考**。**人物是复用域，同力量体系纪律：有原型→消化其人格内核换壳填本书，不硬原创**。没刮过就建卡=人物复用域失责，review 可打回。

**Step 3 世界骨架＋力量体系方向**（从 Step 1 选的配方长，只立方向，细部按需扩展）：

- **世界骨架**：从第1维长主干——地理大格局（几层/几域，每域一句）/时代质感/运作逻辑；**只长当前要开写那批区域（首单元）**，其余留待单元滚动按需扩展。**每个地点过"地图剧情绑定4问"**：①地点=利益（控制什么资源/信息，谁想要）②冲突（不同势力态度是否不同）③门槛（进入付什么代价）④记忆（主角在此经历过什么，重访读者想起什么）——**被另一地点完全可替代→不单独入档或标记精简**。
- **力量体系**（质量参照：`references/长档样例-力量体系.md`）：按 Step 1 选定的配方换皮长——先边界后名字＋设计四问（获得什么/失去什么/误判什么/争夺什么）——答不出=纯摆设定，回炉；过**自洽6查**（向下兼容/向上封顶/横向克制/环境约束/时间成本/一句话测试）；两股源（主角那股＋敌人对位邪路）；主角职业线表（阶位/升级触发/正文长什么样——每阶一段可落笔画面）；数值板式钉板式＋跨度，具体数值正文现算；神力刻度中间不许吞格；非主角变强路径≥5。
- **势力格局**：从第3维长多方棋局（抵抗/入侵/摇摆）——**首喷只长当前单元涉及的势力**，其余按需。
- **基调母题**：从第4维长——底色（暗到哪）＋减压阀（暖在哪）＋一句话母题。一次立完（全书稳定项）。
- **位阶-社会坐标谱**（质量参照：`references/长档样例-位阶社会坐标谱.md`）：全书位阶×三坐标表＋金字塔约束——**全书完整立**（它是上升线表的参照系，不按需）。

**Step 4 类型风味基线**（质量参照：`references/长档样例-类型风味基线.md`）：类型声明（write 每章带进）/命名、器物、社会符号参考系（本书自建）/复用名词库（库里有直接用，库外按参考系造词并回填登记）。一次立完。

**Step 5 交付检查（先过资料门）**：交档前自问"配方库选了吗（力量/世界观）、复用域有没有找到可复用源、要新设的现实主干查实没、角色原型落位没？"——有缺口→**先派 research 定向补采（落 `调研采风/采风/`、来源可回源）再来长**。资料门过了才逐档过长档尺四原则 → **存档后半步=去AI味**：本次产出的档逐份 `python skills/pop-lantern-pipeline/scripts/deai_gate.py <文件> --profile doc --json`（doc 报告检查：WARN 定位自查、机械项 `--fix`；多档可目录递归 `-r` 聚合），结果一行 `去AI味:设计长档|PASS` 或 `WARN×N` → 向用户报告 → 交接 plot（排上升线表与单元1编排）。

### 模式B：按需扩展（单元循环中）

```
Step R0  输入加载：单元N-编排的舞台增量需求＋全书日志＋舞台台账
Step R1  按单生长：新地图/新势力/新规则/新角色参照长进对应长档；新复用点先查内容库（库没有→现场提取+48h回填）
Step R2  贯穿层 append：新阶位/新势力进总纲、演化记录——只追加不重写，写错走纠错注记
Step R3  交接 plot
```

**现编回填**：write/plot 现编的设定（地名/组织/规则）回填对应长档；取词优先查类型风味基线复用名词库，库外按命名参考系造词并回填登记。现编是权利，登记是义务。

**R2 存档后半步=去AI味**：本单元动过的档逐份 `python skills/pop-lantern-pipeline/scripts/deai_gate.py <文件> --profile doc --json`，结果一行 `去AI味:设计长档|PASS` 或 `WARN×N`。

### 模式C：剧末重跑（每单元末，4e）

**触发**：本单元末章 review PASS 后，pipeline 调度 stage 模式C。**这是"舞台逐步扩展"的机制化——四动作，全做完才算重跑完成。**

```
Step C0  输入加载：本单元编排＋单元末章日志＋全书日志＋舞台台账（设计库/人物库）
Step C1  沉淀：本单元产生的新事实写入台账（世界被改变/力量边界被验证或扩展/新规则/新关系）
Step C2  扩展：下一单元预告要用到什么新设定，按需展开（对照 plot 上升线表下一行预告；新配方先查库）
Step C3  防漂移：校验本单元有没有违反已设定——重点查"已设定的做不到"（世界规则防漂移）
Step C4  人物分流：本单元涌现角色 Triage 归档
Step C5  存档去AI味 → 交接 plot（上升线推进）
```

**C1 沉淀细则**：只追加不重写——世界/规则/关系变化记入对应长档"演化记录"区；写错走纠错注记，不改历史。

**C2 扩展细则**：从上升线表下一行预告取增量需求——只长下一单元要用的，不顺手把后面全造了。新复用点先查内容库，库没有→现场提取+48h 回填。

**C3 防漂移细则（重点）**：逐条核本单元正文有没有突破已设定边界（力量上限/地图约束/角色能力）——突破=纠错注记＋回写该事实；无突破=过。**舞台台账必须记录"已设定的做不到"**，防单元剧之间打架。

**C4 人物分流细则（Triage 三问）**：

| Triage 问 | 答案 | 去向 |
|:--|:--|:--|
| 这个角色还会再出场吗？ | 否 | 留在 `人物库/剧档案/单元N/`（一次性） |
| 会再出场/影响全书问题？ | 是 | **升格补录** `人物库/角色库.md`（长期档：功能位＋独立欲望＋语言指纹） |
| 是终局关键人物吗？（对照北极星块） | 是 | 升格长期档＋**查埋种**——早期登场了吗？没埋=回写 plot 补种 |

**人物两档约定**：长期角色（`人物库/角色库.md`，stage 预设骨架或升格补录）供 outline/write 跨单元引用；剧档案（`人物库/剧档案/单元N/`）只服务本单元，单元末 Triage 后归档或升格。

**C5 存档后半步=去AI味**：本单元动过的档逐份跑 doc profile，结果一行 `去AI味:剧末重跑|PASS` 或 `WARN×N`。
