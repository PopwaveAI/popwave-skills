# pop-lantern-write

> 正文写作：消费**本章章纲＋全书日志（当前态）＋前一章正文＋文风DNA**，渲染 2000-2500 字/章。write 只干三件事：**①读章纲读日志 → ②注入文风DNA → ③去AI味**（文档篇幅大部分留给去AI味：sepia 结构层 + 字词层唤起）。当前版本 v1.17.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

### 心智前置·意识层（贯穿本 skill 与全流程）

动笔/定稿前自问：本产出要更好，还需要看过哪些候选？当前信息够不够？有更优选项没探索？

- **Know-Gap**：先显式列出"要更好需见过哪些候选面"，再列已覆盖，缺口=差值；缺口≥1 个未覆盖维度才触发取材，缺了取、别硬写。
- **Pack**：缺口足够才取材，query 自生成；来源 **wiki 站** **<https://wiki.popwave.cn>** 居先、网络补齐；单环节 ≤1 轮 / ≤5 query（超限截断仅留结论区）。
- **Worth**：拿本 skill 决策尺对"现有 vs 候选"必给打分表，禁止一句"更优"带过；只端候选/升级版，不越权定终局。
- **Deepen**：产出/候选后自问"这是天花板吗？有更优候选吗？"显著更优才升级再问，上限 2 轮。

取材仅进上下文，升级被采纳才落产出。

## 做什么

**输入（只吃四样核心，其余按需）**：本章章纲 + 全书日志（当前态）+ 前一章正文 + 文风DNA。

**输出**：`正文/ch{NNN}.txt`（2000-2500字/章）。不产任何账本/记录文件——write 只在对话回复给一句摘要+章末钩子。字数检查与去AI味检查均由 write 存档后自跑脚本收束。

**硬约束链**：本章章纲🔒（时空与主体/事件节点/交接信息三块）→ 全书日志🔒（当前态：现在在哪/此刻悬着的线/禁止漂移）→ DNA约束（3-5条笔触）→ 结局收到读者怀里。

**执行模式**：主 agent 直执写作+存档。输入缺口审计/章纲事实 vs 全书日志冲突比对可派子 agent（verification）只读审计回报。

## Step 1：读输入（三件事的第一件——把料吃进来）

> 🔒 **语感隔离阀（先读这道总开关）**：章纲/幕白描/全书日志的措辞是**剧情结构语言**，不是正文语感——天然带压缩性 AI 腔（"过量收敛""打脸"这类标签句），只用于描述"这章发生什么、读起来该怎样"。write 只从它们取**意**（事件顺序+落点功能+情绪基调+钩子），用文风DNA的语言**重铸**成正文。**禁止照抄章纲/幕白描的抽象名、标签句、句式进正文**；正文出现与文风DNA语感不符的"大纲腔"=语感污染，review 打回。

按"必读核心 vs 按需点读"分层消费，不把档案全搬进上下文。缺必读核心项记入缺口。

**①用户本轮要求（最优先）**：覆盖默认取值。用户要求与全书日志冲突时以用户要求为准。

**②必读·本章章纲（向前依据）**：`章纲/ch{NNN}-章纲.md`（pop-lantern-outline 产出，每章一文件）。向左用上一章章日志衔接（不必读前1章章纲）。三块各司其职：
- **时空与主体**=场景与登场：时间×地点×在场人物 → 本章画面基准
- **事件节点**=推进主干：每节点「事件/转折/落点功能」按序兑现，一个不丢；落点功能是本节点目标，write 负责落到正文
- **交接信息**=写前约定：对白意图→现编台词；世界观功能→现编意象；角色语感→查角色卡

章纲缺失（outline 未产出到本章）=缺口，走缺口处理（回 outline 补章纲），不自行补剧情、不降级硬写。

**③必读·全书日志（当前态·跨章连续参照）**：`剧情日志/全书日志.md`（当前态·只记活跃·全量读）。抽取：现在在哪 / 人物此刻 / 此刻悬着的线（含不可提前吞并的钩子）/ 还没揭的悬念 / 不许碰。章纲事实与全书日志冲突时**以全书日志为准**+对话回复给 review"冲突标注"。

**④按需·上一章章日志（衔接摘要）**：`剧情日志/ch{NNN-1}.md`。要回顾上一章讲了哪些事/定了什么才读。

**⑤必读·前一章正文（叙事流+文气基准）**：`正文/ch{NNN-1}.txt`（full-if-targeted）。不只是"读过"，而是把它作为衔接基准带进——上一章结尾停在哪（余味/钩子落点）、人物蹦到哪、叙事口吻/语感到哪。保证本章从上一章文气上无缝接续。与章日志互补：章日志管事件讲了啥，前一章正文管怎么讲的、停在哪、那股气。

**⑥注入文风DNA（第二步的核心）**：读本包 `references/` 里的**文风文档**（当前唯一权威源＝`夜无疆.md`，frontmatter 标注源书与txt路径，可回源逐字核查）。取该文档的**笔触/句式/段落呼吸/叙事距离**等解剖维度，作为本章生成的**语感主师**——正文从头到尾用它说话，禁止用别的语感替代。

- 缺失兜底：`references/` 无匹配文档时，从本包其他文风文档挑一个对着写；仍空=直接用上一章正文的文气续写，不跳去项目外搜索/蒸馏现造新锚定。
- 禁止行为：①不用本地自造锚定替代文档原文；②不跳过 DNA 直接写作；③不允许"其实文档里有我却说没有"去外搜。违者=文风源断言不实，review 打回。

## Step 2：渲染正文（按章纲写，不自己发挥）

按本章章纲事件节点渲染 2000-2500 字，一个节点一个节点兑现。正文写入 `正文/ch{NNN}.txt`。

**正文规则（质量护栏，write 照做不越界）**：

- 开场 120 字内出现目标、异常、压力、反馈或主动动作之一
- **章纲必兑现**：事件节点按序推进一个不丢；每节点「事件/转折/落点功能」落到正文；落点功能（本节结尾读者感受到什么/为后文铺什么）必须兑现；交接信息按写前约定走。不能只铺氛围
- **事实冲突以全书日志为准**（见 Step 1③）
- 关键爽点必须**外显**（旁人反应/资源变化/局势翻转/敌人误判），不能只由作者总结"他赢了"
- 不提前吞并全书日志"此刻悬着的线"里未到期的钩子
- 结尾必须留下主动钩子或威胁逼近，不用自然停顿收尾
- 判定链/系统数值一律自然段内联呈现（【】格式），禁弹窗式/代码块

**对白**：按章纲交接信息（谁对谁、要达成什么）现编台词；有台词角色的语言指纹（句式偏好/用词偏好）按需查 `人物库/角色库.md`，不凭记忆写。write 负责"对话内容对+角色语言指纹对"，review 负责"对话质量好不好看"。

**存档**：正文写入 `正文/ch{NNN}.txt`，文件名固定。对话只回交接信息（摘要/钩子/字数/新增事实待核/冲突），不把正文全文放进对话，不存档创作记录文件。

## Step 3：去AI味（第三步的核心·write 把多数功夫花在这）

> 顺序：先在写时规避表层 AI 味（生成即达标），写完过【结构层复查】→【字词层唤起】→【脚本兜底】三道。结构层优先于字词层——结构有问题时改词句是治标。

### 3.0 写时规避（生成即达标，非事后降噪）

写作时主动规避表层 AI 味信号，正文天然去魅，禁止写完再整章跑"降AI味"重写流程：

| 信号 | 写时规避 |
| :------- | :------------------------------------ |
| 模板化开头 | 不写"随着…/在当今社会/近年来/众所周知"，直接场景起句（"天擦黑…"） |
| 展望套话收尾 | 不写"综上所述/让我们拭目以待/相信在不久的将来"，点到即收束 |
| 三段式/对仗排比 | 不排"首先→其次→最后""不仅…而且""既…又""一方面…另一方面" |
| 过渡连接词 | 换口语：值得注意的是→说白了；由此可见→看得出来；与此同时→同一时间 |
| 破折号 | ≤1个/500字，只留列举式/必要转折 |
| 半角引号 | 一律中文全角引号，禁止半角 `"` `'` |
| 句长均匀 | 避免连续3句都是15-25字，穿插≤5字短句控节奏 |
| 概括式内心 | 少写"他忽然觉得/她突然明白"，落到具体动作/细节外显 |

### 3.1 结构层复查（sepia 核心·先过这层，5 项全过落地）

机器抓表面模式、字词层抓句子语义；**结构层问题（上下逻辑/氛围兑现/重复/矛盾/造作句）在话语与语用层**，两句单看都对、连起来就不对，只有通读全章才现形。终稿通读一遍，5 项全过才算落盘（源：用户点评+sepia 结构去AI味）：

| # | 把关项 | 反例（AI常见病） | 合格判据 |
|:--|:--|:--|:--|
| 1 | 上下逻辑接得住 | "桅是旧伤，断口在里头，昨天就裂了。他说完，闭了嘴。"——前因不接后果 | 每处事件/对白的**前因→后果**两条都能对上；读者不用回读找逻辑。查法：把每个"于是他/所以/从此"往回问一句"凭什么是这后果" |
| 2 | 氛围铺垫有兑现 | 写了凉意和祷词断裂，后面直接跳去"他站住了，对面船有记号"，凉意没接任何后续 | 每个显眼的氛围描写（发凉/静默/异响/异象）后**必须兑现**——要么引出下一个事件，要么被后文解释/反讽；写氛围不兑现=空转，删或补承接 |
| 3 | 细节不重复描 | 刚写过"刻得很深，像是拿刀凿出来的"后文又说一遍刻痕深 | 同一细节（深度/新旧/颜色/声音）**只描述一次**，后文需要时用"它""那处"指代或换事件视角，不换词重描 |
| 4 | 细节不自相矛盾 | "声音不大，甲板上每个人都听见了"——声音不大+众人全听见互斥 | 同一逻辑事实不互相打架（音量/数量/距离/时间/空间）。查法：夸张修辞（"每个人都/全都/一动不动"）与精确限定（"声音不大/只有…/险些"）不同框出现 |
| 5 | 无造作句法 | "一眼——他把一次辩解"——破折号硬塞解释句，语义勉强 | 每句都用正常中文语序能通读；破折号不给硬补解释；不靠顿号/破折号/分行强行制造"文学感" |

> **结构层优先于词句层（sepia 核心）**：先过结构层（主题别讲白、因果别收太工整、氛围因与魂都在、情绪用动作不靠身体空转），再过字词层——结构有问题时改词句是治标。任一项不过=回该节点按冲突/落点功能重写该段，不靠降AI味词句打补丁。

### 3.2 语义复审清单（字词层·只查机器抓不出的语义味）

机器脚本抓表面模式（标点/套话/句式/句长），判不了语义味。终稿人工过一遍，7 项全过（源：Mirror 08 去AI味专家叙事恶习）：

| # | 把关项 | 合格判据 |
|:--|:--|:--|
| 1 | 无分析腔入正文 | 「核心动机/信息边界/信息落差/利益最大化」等分析术语禁止进句子；推导链、信息差设计只在脑中跑 |
| 2 | 不替读者下结论 | 读者能从行为推断的意图，叙述者不说破（"他明白她是生气了"✗，让行为外显✓） |
| 3 | 情感不后置解释 | 情绪动作后不紧跟"他感到/他忽然觉得"（"他攥紧拳头走开"✓，尾追"他感到委屈"✗） |
| 4 | 无金句体质 | 听起来像名人名言的句子重写为场景白话 |
| 5 | 无元叙事旁白 | "到这里算是钉死了"这类编剧脚注不进正文 |
| 6 | 同体感不连续渲染 | 同一意象域（如火在体内流动）连续渲染≤两轮 |
| 7 | 惊讶标记词≤1/3000字 | 「仿佛/忽然/竟/竟然/猛地/猛然/不禁/宛如」终稿数一遍，超了删到只剩最有力一处 |

### 3.3 脚本兜底（两项，写完必跑）

**① 字数检查（先跑——字数收束会增删文本，AI味检测须在终稿上跑）**：

```
powershell -File skills/pop-lantern-write/scripts/word-count.ps1 -Path 正文/ch{NNN}.txt
```

- 纯汉字 2000-2500 合格。不足→回章纲既有节点内扩写（补场景细节/对话往来/动作链，不灌水不复读）；超限→删最弱场景；改完复跑至 PASS
- **字数不足不外交**：review 不补救字数，write 自己收束达标后才交 review
- stdout 原文进对话回复交接信息，review 直接消费（review 不跑脚本）
- **段落节奏扫描（同脚本·自动化）**：**60% 以上叙事段<40字 = `判定:FAIL(段落过碎)`，阻断交稿**，write 调段（并短句、扩长句）复跑至 PASS；连续 3 短段处数、短段总数输出给 agent 人工判断是否留（允许场景：开场前300字反转金句/章末钩子最后一句/单章≤3个爆点短段，三个场景合计一章最多5个短段，超即"堆砌电报体"）。叙事段 40-120 字，对话段天然短不计入叙事段。

**② 去AI味检查（终稿上跑）**：

```
python skills/pop-lantern-pipeline/scripts/deai_gate.py 正文/ch{NNN}.txt --fix --json
```

- **零风险项脚本原地自动修** 36 类（标点全角化/引号配对/省略号归一/零宽字符/HTML与markdown残留/emoji/思考残留行/tab/行首标点归位等），无需人工
- **WARN/FAIL 项=自查自修清单**：按报告 hits 行号定位，只局部改写命中处（禁止全文重写），修后复跑至 FAIL 清零；WARN 酌情。注意"中文间空格""引号未配对""括号注释"三项有合法豁免，确认合法可放行
- 阈值经人书基线校准（八本同口径抽样实测，人书全过、AI稿多挂）：破折号 0/500字，AI稿超 1.0 即警；句号密度人书 21-38/千字，超 45 即警；的着了气口人书 38-79.5/千字，低于 36 即警（AI缺气口）

## 存档后检查 + 收束

三道（字数→去AI味→人工复审）都在 write 存档后自跑，不达标自己收束后才交 review。语义复审与结构层复审需人工通读，不放脚本。**验收检查**：正文存在 ✓｜字数 PASS 且段落节奏 PASS ✓｜去AI味 FAIL 清零 ✓｜结构层 5 项全过 ✓｜语义 7 项全过 ✓。

**新增事实处理**：write 不维护任何库文件。新增事实只在对话回复列"新增事实待review"清单，由 review 落库。write 只声明不落库。

**下一步（硬后继）**：正文存档后必须执行 pop-lantern-review。review 是 write 的硬后继，未执行 review 不得写下一章。
