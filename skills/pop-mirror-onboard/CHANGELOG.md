## v2.2.0 | 2026-09-10

### 补产出三检查总述（事前沟通/事后确认/research 评估显式成节）

老板统一要求：每个 skill 产出关键文档前要和用户预选沟通、产出后要确认、要评估是否 research。本 skill 的聊天式流程天然覆盖三检查，但未显式成节，本轮把已有实现点明归位：

- **新增「第 0 节 · 产出三检查」**：事前沟通 = 第 1/2/3/6 步聊天式提问（根决策先行、一轮 1-2 问 + 选项 + 推荐项）；事后确认 = 第 5 步落盘纪律（元数据/规则/需求卡/调研/故事脉络/篇幅推导，每份确认才写入，你来定也汇总为建议请求确认）；research 评估 = 第 3 步资料门（存档前先答"资料够不够"，不够必派 pop-snow-research 补采，查不到的写"没查到"）。
- **红线新增第 8 条、速查表加"产出三检查"行**。
- SOP 精华（需求卡/故事脉络/篇幅推导/资料门）不动。

同步三件套：SKILL.md / skill.json（version 2.2.0）/ CHANGELOG。

## v2.1.0 | 2026-09-10

### 全新立项重构：去掉运行时遗产，提问改聊天式

老板反馈 9-10 项目a 实测：onboarding 提问僵硬、劝退用户。根因是「先读再问 / 创作路线分流 / AgentRules / AgentSkill / 大纲轨道」等镜界 `11-创作向导` 运行时设计被带入全新立项，agent 读盘发现空项目后反而搬出旧契约门禁。本轮重构：

- **每次 onboarding 都是全新立项**：删「前置准备：先读，再问」「确认创作路线（fanfic/sequel/original）」两节；前置输入改为"无，不读旧内容"。
- **删运行时遗产**：删「区分元数据、规则与故事事实」（novel 资源/AgentRules/大纲轨道/加入书架）与「AgentSkill 能力配置与设定加深」两节；落盘统一为项目空间五档 `00-作品元数据 / 00-写作规则 / 01-需求卡 / 02-调研文档 / 03-故事脉络`。
- **提问改聊天式**：新增「第 1 步 先聊想法」开场（一句"想写本什么书"，顺着聊，不问卷）；「提问原则」改为「提问怎么聊」——一轮 1-2 问、大白话选项、不掺行话。
- **黑话清零红线**：显式禁止源料/改编强度/创意X/设定包/5表/Phase 等旧体系术语进入提问与产出（防旧专家提示词污染）。
- SOP 精华保留不动：需求卡五字段、故事脉络五元素公式、越界边界、欲望串、篇幅推导链、research 资料门、默认建议。

同步三件套：SKILL.md / skill.json（version 2.1.0）/ CHANGELOG。
