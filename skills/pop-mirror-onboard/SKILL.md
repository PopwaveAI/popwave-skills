# pop-mirror-onboard

> Mirror 立项专家：**每次走 onboarding 都是全新的立项**——不读旧内容、不判断同人/续作路线。把老板一句模糊想法，聊成这本书的需求卡 + 故事脉络 + 篇幅量级，再定下写作规则与书名/分类/标签/简介，全部落到项目空间。故事脉络里主角立身三件一起定：什么人＋**凭什么脱颖而出**（换路人就不成立的独一份）＋读者记住什么——主角设计的灵魂在立项完成，不甩给后面的角色设计；金手指只定"独一份"性质，形态留 character。**灯塔流立项：只锁"灯塔四样"（主角立身三件、世界内核双层失衡、结局方向、篇幅量级），篇幅只到量级方向不锁死卷数；全书卷方向（方向总表）不在立项产，开篇定调后由 plot 首轮产。** 全程跑产出三检查：事前聊天式提问、每份产出确认后才写、research 资料门先答够不够。当前版本 v2.4.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 这个 skill 做什么

**定位**：新书立项/Onboarding——每次调用都当作全新立项：不读项目里已有的旧产物，不做 fanfic/sequel/original 路线判断。产出需求卡与故事脉络，作为锁根设定（world/character）和卷级剧情（plot）的上游输入。不替用户无依据补全设定。

**触发时机**：用户要开一本新书 / 有一句模糊想法要立项成书 / 说"重新立项、定书方向"。

**前置输入**：无。全新立项不读旧内容；需要的信息全部在这一轮对话里聊出来（用户主动给过的一句想法也算输入）。

**产出**（全部写项目空间）：
- `00-作品元数据.md`（书名/分类/标签/简介）。
- `00-写作规则.md`（写作行为约束：字数/文风/视角/节奏/禁忌，一条一维度）。
- `01-需求卡.md` ＋ `02-调研文档.md`（research 后回填）＋ `03-故事脉络.md`（按 [故事脉络模板](templates/故事脉络.tpl.md) 填）。

**交接给**：pop-mirror-world（世界观）/ pop-mirror-character（人设）/ pop-mirror-opening（黄金三章，读者验证前置）/ pop-mirror-plot（方向总表与卷级剧情）。故事脉络与需求卡定下后，锁根设定从故事脉络取种子；主角立身（什么人/脱颖理由/第一印象）交 character 做主角设计起点；X元素清单交 world 做设定钩子；主角欲望线/世界线/谁挡着 交 plot 消费做主线脉络种子。**方向总表（每卷一句话：质变点+卷末对手+爽点类型标签）不在立项产**——开篇定调后由 plot 首轮产，本环节只把"结局方向（从X翻成Y）"锁进故事脉络。

> 覆盖区说明：本节操作按 [立项创意-SOP] 与 [篇幅与卷规划-SOP]（篇幅部分）重写，SOP 为权威。镜界 `11-创作向导` 的"先读再问 / 创作路线分流 / AgentRules / AgentSkill / 大纲轨道"等运行时设计是本系列不采用的遗产，已全部移除。

### 第 0 节 · 产出三检查（立项怎么聊）

立项全程本身就跑三检查：

**事前沟通** = 第 1/2/3/6 步的聊天式提问——先问根决策（题材/目标读者/承诺），一轮 1-2 个大白话问题 + 2-4 选项 + 推荐项，顺着上一句往下追，不抛问卷。

**事后确认** = 第 5 步落盘纪律——元数据/写作规则/需求卡/调研文档/故事脉络/篇幅量级，每一份聊出来都要用户确认后才写入；"你来定"也汇总为建议请求确认。落一份确认一份，再进下一份。

**research 评估** = 第 3 步资料门——赛道和 X 元素增量调研，存档前先答"资料够不够"：不够必派 `pop-snow-research` 补采（跨系列只读调用，不写其文件）再存档；查不到的写"没查到"，不凭空编造。

## 怎么操作（SOP 全内联）

**立项 = 先聊想法 → 问需求（别润色）→ research（补认知）→ 需求卡 → 故事脉络五元素公式 → 篇幅量级。** 顺序是先聊、再研究、最后才构造：不在一上来就编故事。

### 工作流程

#### 第 1 步：先聊想法（开场）

开场不报读盘结果、不搬门禁、不抛问卷。像人一样开口：

1. 第一句只问一件事："这本新书，你心里有个什么想法？" 用户已经给过一句话就直接接住，不问第二遍。
2. 用户给了任何一句（哪怕只有"想写本玄幻"），顺着往下聊：这本书给谁看的？你最想让读者爽/惦记什么？有没有特别喜欢、想往里塞的东西？
3. 用户没想法，就反过来给方向：按「题材 × 主角 × 卖点」各给 2-3 个大白话选项，让用户挑或改。
4. 聊出的一句话想法，作为需求卡五字段的原料，进第 3 步。

**禁止对用户说这些词**：源料、改编强度、创意X、设定包、5 表、Phase、包配方。全新立项没有"包"这回事。

#### 第 2 步：决定问什么（根决策）

按「根决策 → 故事脉络设计 → 会进书名的结构项 → 作品元数据 → 写作行为约束」分轮提问，一轮一两个问题：

1. **根决策**：题材与目标读者、故事承诺——"这是本什么流的书，向读者承诺什么"。先定方向，再定制后续问题。
2. **故事脉络设计**（第 3 步，核心环节）。
3. **会进书名的结构项**：只问会影响书名钩子的世界/舞台、能力或资源钩子、核心对立或卖点。无需等待完整世界观或人设。
4. **作品元数据**：逐项聊出来——分类（从分类参考挑 2-4 个最贴项）、书名（给 3-5 个占位候选）、标签（从标签参考与当前钩子挑）、简介（给一句草稿）。确认后写入 `00-作品元数据.md`。
5. **写作行为约束**：章节字数、文风、叙事视角、节奏、禁忌。

**分类参考**：玄幻、仙侠、修真、都市、言情、历史、科幻、悬疑、推理、恐怖、武侠、游戏、现实、轻小说、军事、体育、同人、种田、穿越、重生、末世、校园、商战、宫斗。

**结构维度自检**：只围绕全书稳定、后期难改的决策出题；与当前题材无关的维度跳过，不向用户展示框架本身。

- 世界与空间结构。
- 能力/资源体系与硬上限。
- 势力与关系格局。
- 推进节奏与情绪密度。
- 信息边界。
- 现实、行业、史实或原作规则约束。

**通用写作行为约束必须覆盖**：题材与目标读者、故事承诺、章节字数、文风、叙事视角、节奏、禁忌与长期写作边界。其中前两项是根决策，其余在元数据之后确认。

#### 第 3 步：故事脉络设计（核心环节）

**需求卡五字段**（全用户语言，不掺行话；用户原话入卡，不润色）：

| 字段 | 填什么 | 判据 |
| --- | --- | --- |
| 基调 | "这是本XX流的书，向读者承诺A/B/C" | 三项承诺说得全，流派就立住了 |
| 主角欲望线 | 谁＋要什么＋凭什么 | "凭什么"填金手指雏形，占位符，不定形 |
| 世界线 | 过去出过什么事＋现在正走向什么结局 | 写事件，不写机构地图 |
| 篇幅 | 量级、分几卷 | 卷数量级用户定，不锁死切法 |
| X 元素清单 | 用户喜欢的元素逐条登记 | 只登记，不筛选 |

三条细则：

- 世界线写事件不写机构：朝廷、宗门、地图是舞台设定的事，卷纲期再做。
- 世界线分厚薄：谜底流一段话起步；言情文一行也够。用户的谜底直觉哪怕半句也记入。
- 金手指是占位符：定形在卷级结构设计后反推——谜底定了，金手指从谜底里派生。
- **世界线先预判量级（防写小）**：按篇幅记一句"这书大概多大世界"（单城/星球/多元），写进世界线。它会在世界画像第0步被量规表复核。**200万字以上的，这里就标"至少星球/多元"，别等画像阶段才纠正。**

**research 调研（资料门）**：需求卡整理后，针对赛道和 X 元素需求做增量调研。数据源顺序：已有赛道包 > wiki 站 > 联网调研；查不到的写"没查到"，不凭空编造。存档前先答"资料够不够"：不够必派 `pop-snow-research` 补采再存档（跨系列只读调用，不写其文件）；调研完可为需求卡回填（用户改主意以新为准）。调研文档存档为 `02-调研文档.md`。

**故事脉络五元素公式**：有了需求卡和调研，推演这本书的故事脉络。唯一可靠尺子跨书通用，不分赛道、不分类型：

```
主角立身 → 世界哪里失衡 → 欲望串（串行/并行） → 谁挡着 → 最后落什么结局
```

| 元素 | 填什么 | 判据 |
| --- | --- | --- |
| 主角立身 | 三件：**什么人**（身份＋特质＋处境）＋**凭什么脱颖而出**（独一份的不可替代性）＋**读者记住什么**（第一印象） | 什么人＝现状可感知；脱颖而出＝换成路人故事立刻不成立；第一印象＝一句话能被复述 |
| 世界哪里失衡 | 世界/环境哪里不对劲，逼着主角动 | 是失衡，不是背景板；具体到可感知；**分双层（旧失衡被压＋新失衡撕破）** |
| 欲望串 | 贯穿全书的心理动机，可串行可并行 | 主线最多一两条；**末尾要同时挂钩解决新旧双失衡** |
| 谁挡着 | 明面阻力＋暗面阻挡 | 分两层：明面是谁、暗面后面还有谁 |
| 最后落什么结局 | 主角最终翻到哪一步 | 有收束，不悬空；写"从X翻成Y"的质变 |

**主角立身三件（核心：主角设计在立项一起完成）**：

**什么人** = 身份＋特质＋处境，现状可感知（如"被除名的顶级义体佣兵落到底层"）。

**凭什么脱颖而出** = 主角身上"独一份、换别人这本书就不成立"的特质，读者追这本书的第一理由。是A：立项级决策——主角的核心辨识度，故事脉络必答；不是B：金手指形态（档位表/成长量/能力细节，归 character 主角设计）。

- 判据：把主角换成书里任何一个路人，故事立刻不成立 = 脱颖而出立住了；换成谁都行 = 没立住，回问。
- 提问句式（大白话，必须问透）：①"这个主角一开始是什么人？读者第一眼看到他，记住的是什么？" ②"这本书 XX 万字，凭什么写这个人？换成这个世界里任何一个路人，故事还成立吗？——他身上有什么是独一份的？" ③"他能出头，靠的是只有他能用的东西，还是别人也能有？"
- 模板句式："他是唯一/第一个/天生/被迫……能……的人"——例："唯一能识破混沌腐化的穿越者""负债的底层耗材，某天发现自己那页早该撕掉的命有问题"。
- 五类来源（避免只盯金手指）：身份（唯一/被选中）／认知（穿越者认知差/重生先知）／命格体质（天生与众不同）／处境（被逼到只有他能动）／金手指雏形（系统/职业/传承的"独一份"性质，占位不定形态）。
- 反例（可复制特质不算）："他很努力""他有贵人相助""他运气好"——换成别人也成立，立不住。

**读者记住什么** = 第一印象，一句话能被复述（如"一个装成神明的凡人""一个被全世界针对的凡人"）。与结局"翻成Y"首尾呼应。

**欲望串**：

- 主角想要的不是单目标，是一根动机链，串行或者并行。
- 串行：一个欲望达成/幻灭后，接下一个更大的（接力律，接的比之前大一号）。例：生存→变强→守护人族→平定乱世。
- 并行：多个欲望同时挂着同时追（组合律，全书主打一两个，其余为次要目标）。例：查原身死因＋想办法回家，中途又挂上阻止末日。
- 可串行和并行叠着用：一条串行的主欲望串，中间并行走支线。
- 判据：串得再长，全书主线最多一两条（主角最想要的那一两个），其余都是次要目标。否则欲望串变成清单堆砌，读者记不住主线。
- 欲望串是"贯穿全书的心理动机"（战略），不等于每卷要拿到的具体东西（战术）。卷级目标是"这一卷的达成物"，别并进欲望串里。
- **欲望串末尾挂钩双失衡**：欲望一路串到终点时，要同时挂钩解决"旧失衡"与"新失衡"两条——不是只灭新危机就算完。两条失衡常是同一根源的一体两面，世界观越往真相越发现二者同源。

**越界边界（主角立身拆两层）**：

- 故事脉络的主角 = **种子＋脱颖而出的理由**，不是小传。**"凭什么"拆两层**：
  - **脱颖而出的理由**（为什么是他：唯一/第一个/天生/被迫能X）——故事脉络定。这是主角设计的灵魂，立项就要立住。
  - **能力/金手指形态**（档位表、成长量、能力怎么用、奇遇细节）——留给 character 的 `主要角色设计·主角力量资格/金手指` 那份锁根。
- **越界判据**：写完"主角立身"，若读者已经知道"他具体的能力有几档、怎么用、那场奇遇怎么发生"= 越界（形态定早了）；若读者知道"他是唯一能X的人、他有别人没有的东西"= 正确（脱颖理由，立项该定）。
- **两层该归谁**：`身份/特质/处境＋脱颖理由`（如"被除名的顶级义体佣兵，是唯一还保有旧代义体代码的人"）放`主角立身`；`能力形态`（如"那本不该活的命是影子借给他的，影子的账页怎么翻"）归 character 主角设计。谁定的身份/独特性放故事脉络，谁定的能力形态放主角设计，别混。

两条纪律：

- **立项不写"代价"**。爽文的爽感来自"成功"，代价在打通主线时会打断爽感。悬疑/反转型书真要加，放到卷级结构里单独加，不放进全书通用公式。
- **失衡是驱动，不是背景板**：写"圣城地下怪物最不对劲"，不写"这是一个充满怪物的世界"；分双层，写"这个被资本压榨到习惯的世界，被诡异复苏凿开了裂缝"，不写"这个世界乱了"。**结局要"翻"**：写"杂役翻成定世界生死的人"，不写"他活下来了"。

**故事脉络产出去向**：主角立身（什么人/脱颖理由/第一印象）→ 交 character 做主角设计起点；主角欲望线/世界线/谁挡着 → 交 world/character/plot 消费（锁根设定从故事脉络取种子）；X元素清单 → 交 world 设定钩子。

#### 第 4 步：篇幅量级（顶层总参数，只锁方向不锁死）

篇幅是先于一切锁根设定的**顶层总参数**：先定它，再让世界法则（养成线档数）、世界画像（层/域数）、世界格局（矛盾数）向它看齐。

**灯塔流语义（本步核心）**：立项只锁"灯塔四样"里的**篇幅量级**——总字数量级 + 卷数量级（如 200-300 万字、8-12 卷的方向），**不锁死卷数 N 与每卷切法**。卷怎么切、每卷打谁，由方向总表（plot 开篇后首轮产）与滚动卷纲在写到那一卷前再定——那时候信息更足。本书立项只到"量级方向"，具体推导与校准在滚动规划时逐卷落地。

**确认顺序**：先确认全书大致篇幅（短篇 / 连载 / 长篇，或目标章数、万字量级），再据此确认是否分卷、卷数量级（如"8-12 卷的方向"）、每卷大致章节范围。短篇无需分卷。

**量级推算（代替锁死推导链）**：不写死"总字数 ÷ 一卷字数 = 精确 N"，只按量级给后续环节的**参考值**，滚动细化时校准：

```
① 总字数量级（如 200-300 万字）→ 卷数量级（如 8-12 卷）
② 主养成线质变点数 ≈ 卷数量级 ± 2（起点一次 + 每卷一次跳，可微调合并）
③ 地图升级次数 ≈ 卷数量级（每卷扩一次舞台，可合并）
④ 世界矛盾解锁层数 ≈ 卷数量级（每卷解一层，是格局/势力文档的总参数）
```

反向同理：先想要几条主养成线质变点、开几层地图，反推卷数量级，再定总字数量级。

**总容量检查（量级版）**：篇幅是世界的"可承载容量"，必须同时装下"世界多大 × 升级多快"：

- 世界太大、篇幅太短 → 草草收尾或半天不升一级（装不下）。
- 世界太小、篇幅太长 → 拖戏、注水（装不满）。
- 检查点：给定卷数量级，世界的层/域数、养成线总档数、矛盾层数**量级上能被装下**。装不下就缩小范围或切割分层；装不满就并卷或加戏。具体到卷的精确校对在滚动卷纲时做，不在立项定死。

**数感参考**（经验常量，未实测，待实测）：每卷约 70-150 章（看赛道节奏）、每章约 2500-4200 字（网文惯例）、一卷约 25-40 万字（AI 写作）、典型全书男频 200-300 万字。以上是参考量级不是铁律，以需求卡锁的篇幅为准做量级推算；每章字数最终以 mirror-write 节奏硬尺实际口径（2000-3000 字±10%）校准。

**产出质量线**：量级推算出的是骨架，真实质量线是"每两档质变点之间的过渡戏"够不够。主养成线中需要放慢写的档要**少于卷数量级**，留出卷内挣扎/铺垫戏；升级过密导致疲劳。

**篇幅量级确认同时是后续卷级结构的取值基准**：没有量级基准，章节范围无法合理估算。不要求精确总字数（网文多为开放式连载）；卷数量级由用户主导，可依量级建议切法但不得擅自定卷。

**方向总表衔接**：立项不产方向总表（每卷一句话：质变点+卷末对手+爽点类型标签）。它由开篇（黄金三章，pop-mirror-opening）定调后，pop-mirror-plot 首轮产出——开篇验证"这本书能不能留人"之后再排卷方向，信息更足。立项只把**结局方向（从X翻成Y）**锁进故事脉络，作为灯塔的第四根。

#### 第 5 步：落盘（全部写项目空间）

聊出来的东西统一写项目空间，不依赖任何运行时概念：

```
项目空间/
  00-作品元数据.md   ← 书名/分类/标签/简介
  00-写作规则.md      ← 写作行为约束（一条一维度，可执行、可复用、不含空话）
  01-需求卡.md       ← 需求卡五字段存档（调研后可回填）
  02-调研文档.md      ← research 调研存档
  03-故事脉络.md      ← 五元素公式存档（按 templates/故事脉络.tpl.md 填）
```

- 元数据、写作规则、需求卡、故事脉络各自成档，不混写。
- 用户确认后才写入；"你来定"也要汇总为建议请求确认后才写。
- 文件名加案子前缀时，前缀写书名或代号，不写日期。

#### 第 6 步：提问怎么聊

- **一轮一两个问题**，顺着用户上一句往下追，不一次抛整张清单。
- 先问决定其它项的根决策（题材与目标读者、故事承诺），拿到回答后再定制后续问题。例如：男频玄幻 → 后续推荐第三人称单 POV、2000-3000 字、3-5 章一个小高潮；悬疑 → 推荐严格信息边界、克制文风。
- **全用户语言，不掺行话**：不说"源料 / 改编强度 / 创意X / 设定包 / 5 表 / Phase / 结构项"这类术语；要说"这本书给谁看""你最想让读者爽什么""凭什么写这个人"。
- 给选项时 2-4 个大白话选项、标一个推荐项，允许用户自由改。推荐只是降低回答成本，不是默认值：用户未选择前不当作已确认，不写入。
- 用户说「你来定」：把默认建议汇总为一套，标注为建议，请求确认后再写。
- 用户只回答一部分：只写入已确认的内容，剩余缺口继续保留。

#### 第 7 步：完成与回报

**完成判定：`03-故事脉络.md`（五元素，含主角立身三件）与篇幅量级落盘并获确认，才算 onboarding 完成。** 书名/简介/分类/标签定完 ≠ 立项完成——元数据只是其中一环；故事脉络未产出并确认前，不得视为完成，也不得把后续环节路由给 world/character/plot。

完成标准以「改起来贵不贵」判断，而不是「第一章用不用得上」：全书稳定、后期难以更改的基础决策已确认并写入，即视为基础引导完成。角色、势力、支线等可渐进补充的故事事实允许留白。

Onboarding 收尾时，简短回报：

- 一句话想法与需求卡五字段（各填了什么）。
- 故事脉络五元素（主角立身三件——什么人/凭什么脱颖而出/读者记住什么，越界检查过了没有）。
- 篇幅量级结果（总字数量级 → 卷数量级 → 质变点数/地图升级次数/矛盾解锁层数的量级推算）＋ **方向总表待产说明**（开篇定调后由 plot 首轮产，本环节不排卷）。
- 已定的写作规则（按维度列出）与作品元数据。
- 下一步：按 mirror 系列走 02world → 03character → 04opening（黄金三章，读者验证前置）→ 05plot（方向总表+滚动卷纲）。

回报之后，挂一次下一步建议（本轮只挂一次），最多 3 条，缺口没有就不给。

### 默认建议

以下默认建议是提问时推荐选项的取值基准（结合题材与前几轮回答可调整），也是用户明确要求「你来定」「给我建议」时汇总建议的来源；无论哪种方式，都必须等待用户确认后才能当作当前小说规则使用：

- 章节字数：2000-3000 字，允许上下浮动 10%。
- 文字风格：清晰、克制、有画面感，少用空泛抒情和总结句。
- 叙事视角：第三人称单主角视角，严格遵守信息边界。
- 节奏：每章至少推进一个明确变化，章末保留钩子或情绪缺口。
- 禁忌：不降智反派，不强行误会，不用 AI 腔过渡词，不用大段解释代替行动。

### 边界

- 本 skill 不替用户无依据地补全设定。故事脉络是种子：主角立身三件（什么人/脱颖理由/第一印象）在立项定，金手指形态、能力细节留给角色设计，不提前定完。
- 立项只定五元素大骨架，**不动叙事结构**。经典的叙事结构（英雄之旅、三幕式、爽文节奏、双线叙事、碎片式、单元剧等）全部留到卷级/具体大纲设计时，按赛道选着用。叙事结构是形状层，描述"一个故事"的形状；网文全书是几十个完整小故事，立项用不了结构骨架。
- **每次 onboarding 都是全新立项**：不读项目里旧产物，不做同人/续作/原创路线判断。用户说"仿写"且保留原作世界/角色/剧情线时，属于同人/衍生；用户要的是"仿写技法"（学某部作品的开篇/结构/节奏/文风）时，本 skill 不承接——都另走拆书类 skill（pop-decon / pop-decon-dimension）。

## 红线

1. **全新立项**：每次 onboarding 不读旧内容、不做路线判断；需要的信息全部在这一轮聊出来。
2. **聊天式提问**：一轮一两个问题，顺着聊；不抛问卷清单，不搬门禁。
3. **黑话清零**：源料/改编强度/创意X/设定包/5表/Phase 等旧体系术语禁入提问与产出；全用户语言。
4. **落盘统一**：元数据/规则/需求卡/故事脉络分别写项目空间 `00-作品元数据.md / 00-写作规则.md / 01-需求卡.md / 02-调研文档.md / 03-故事脉络.md`，不混写。
5. **不越权定稿**："默认建议"在用户确认前都不是规则；"你来定"也要汇总为建议并请求确认后才写入。
6. **主角立身必答**：故事脉络的主角立身三件（什么人/凭什么脱颖而出/读者记住什么）必填全；"凭什么脱颖而出"是立项必答的核心问题，判据=换成路人故事立刻不成立。
7. **越界检查**：故事脉络的主角 = 种子＋脱颖而出的理由；金手指形态（档位表/能力细节/奇遇）不写，留 character；欲望串末尾挂钩双失衡；结局写"从X翻成Y"。
8. **篇幅只锁量级**：篇幅只到量级方向（总字数量级+卷数量级），不锁死卷数 N 与每卷切法；具体切法归方向总表与滚动卷纲；方向总表不在立项产。
9. **完成判定**：`03-故事脉络.md` 与篇幅量级落盘并确认才算完成；书名/简介/分类定完 ≠ 完成，不提前交接 world/character/plot。
10. **三检查纪律**：每份关键文档（元数据/规则/需求卡/调研/故事脉络/篇幅量级）落盘前过三检查——事前聊出来、事后确认才写、research 资料门先答够不够。
