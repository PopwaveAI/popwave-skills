# pop-mirror-onboard

> Mirror 立项专家：新书 Onboarding——确认并保存基础写作规则、作品元数据与稳定故事边界；再把用户一句模糊想法变成这本书的故事脉络（需求卡 + 五元素公式 + 篇幅推导）。**不一次性穷举问题，不经确认不覆盖已有内容**。当前版本 v2.0.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 这个 skill 做什么

**定位**：新书立项/Onboarding——确认并保存基础写作规则、作品元数据与稳定故事边界；向下推一步，产出需求卡与故事脉络，作为锁根设定（world/character）和卷级剧情（plot）的上游输入。不替用户无依据补全设定。

**触发时机**：新建书 / 已有书名简介分类需重新整理规则与元数据 / 用户有一句模糊想法要立项成书。

**前置输入**：先读当前已完成内容（元数据/已有规则/工作区资料），再问；按"先读再问"。

**产出**：
- 已确认的作品元数据（书名/分类/标签/简介）。
- 写作行为约束（规则）。
- 故事事实入对应载体。
- 需求卡（01-需求卡.md）＋ 调研文档（02-调研文档.md，research 后回填）＋ 故事脉络（03-故事脉络.md）。
- 能力配置清单（若适用）。

**交接给**：pop-mirror-world（世界观）/ pop-mirror-character（人设）/ pop-mirror-plot（卷级剧情）——故事脉络与需求卡定下后，锁根设定从故事脉络取种子；X元素清单交 world 做设定钩子；主角欲望线/世界线/谁挡着 交 plot 消费做主线脉络种子。

> 覆盖区说明：本节操作按 [立项创意-SOP] 与 [篇幅与卷规划-SOP]（篇幅部分）重写，SOP 为权威；镜界 `11-创作向导` 原精华降为参考，冲突处以 SOP 为准。

## 怎么操作（SOP 全内联）

**立项 = 一句话想法 → 问需求（别润色）→ research（补认知）→ 需求卡 → 故事脉络五元素公式 → 篇幅推导。** 顺序是先问、再研究、最后才构造：不在一上来就编故事。

### 工作流程

#### 1. 前置准备：先读，再问

提问前必须先收集已有信息：

1. 读取当前小说元数据（`title`、`description`、`category`、`tags` 等），记下哪些已有、哪些为空或占位，作为后续确认/补全的起点，以读到的实际状态为准。
2. 查看已有 AgentRules，识别哪些写作行为约束已经存在。
3. 查看应用内全局已安装的 AgentSkill，识别哪些创作能力已经可用、哪些缺口。
4. 浏览当前小说工作区资料：世界观、角色、势力、大纲、已有章节等，识别哪些故事事实已经存在。
5. 把待办记下来：哪些写作行为约束缺失、哪些已有资料可提炼为规则但尚未写入、哪些结构性故事基础缺失、哪些元数据需确认或补全、哪些资料应补充而非新建、哪些能力需要配置。

已有规则与当前方向一致时不要重复问同样规则；但已有资料可提炼为写作行为约束、且尚未写入规则时，必须单独通过 AskUser 确认是否写入。

#### 2. 确认创作路线

- 当前作品上下文中的 `type` 为 fanfic：走同人流程（保留原作世界/角色/关系/剧情线）。
- 当前作品上下文中的 `type` 为 sequel：走续作流程。
- 当前作品上下文中的 `type` 为 original：直接走本 skill 的原创流程，从零创作。
- 用户说"仿写"但保留原作世界、角色、关系、剧情线或关键设定时，属于同人/衍生，走同人流程。
- 用户要的是"仿写技法"（学习某部作品的开篇、结构、节奏、文风或技巧）时，本 skill 不承接——仿写/拆书另走拆书类 skill（pop-decon / pop-decon-dimension）。

#### 3. 决定问什么（根决策）

**题材识别**：题材优先看已有 `/novel/category`、`/novel/tags` 与简介；皆空时再靠用户在根决策中的回答。`type` 是作品性质，不是题材，不要用它推断题材方向。

按「根决策 → 故事脉络设计 → 会进书名的结构项 → 作品元数据 → 其余写作约束」分轮提问：

1. **根决策**：题材与目标读者、故事承诺。先定方向，再定制后续问题。
2. **故事脉络设计**（第 4 步，核心环节）。
3. **会进书名的结构项**：只问会影响书名钩子的世界/舞台、能力或资源钩子、核心对立或卖点。无需等待完整世界观或人设。
4. **作品元数据**：展示现值，让用户确认保留或修改；空缺则补齐。未经 AskUser 确认不得覆盖已有值。
   - 分类：从下方分类参考对应目标读者的主分类中挑 2–4 个最贴项；确认后写入 `/novel/category`。
   - 书名：占位名必须给 3–5 个候选；已有正式名只问是否调整；确认后写入 `/novel/title`。
   - 标签：从标签参考与当前钩子中挑候选；确认后以逗号分隔写入 `/novel/tags`。
   - 简介：空时可给一句草稿；已有时展示并询问是否修改；确认后写入 `/novel/description`。
5. **其余写作行为约束**：章节字数、文风、叙事视角、节奏、禁忌。

**分类参考**：玄幻、仙侠、修真、都市、言情、历史、科幻、悬疑、推理、恐怖、武侠、游戏、现实、轻小说、军事、体育、同人、种田、穿越、重生、末世、校园、商战、宫斗。

**结构维度自检**：只围绕全书稳定、后期难改的决策出题；与当前题材无关的维度跳过，不向用户展示框架本身。

- 世界与空间结构。
- 能力/资源体系与硬上限。
- 势力与关系格局。
- 推进节奏与情绪密度。
- 信息边界。
- 现实、行业、史实或原作规则约束。

**通用写作行为约束必须覆盖**：题材与目标读者、故事承诺、章节字数、文风、叙事视角、节奏、禁忌与长期写作边界。其中前两项是根决策，其余在元数据之后确认。

#### 4. 故事脉络设计（核心环节）

**需求卡五字段**（全用户语言，不掺行话；用户原话入卡，不润色）：

| 字段 | 填什么 | 判据 |
| --- | --- | --- |
| 基调 | "这是本XX流的书，向读者承诺A/B/C" | 三项承诺说得全，流派就立住了 |
| 主角欲望线 | 谁＋要什么＋凭什么 | "凭什么"填金手指雏形，占位符，不定形 |
| 世界线 | 过去出过什么事＋现在正走向什么结局 | 写事件，不写机构地图 |
| 篇幅 | 量级、分几卷 | 卷数用户定 |
| X 元素清单 | 用户喜欢的元素逐条登记 | 只登记，不筛选 |

三条细则：

- 世界线写事件不写机构：朝廷、宗门、地图是舞台设定的事，卷纲期再做。
- 世界线分厚薄：谜底流一段话起步；言情文一行也够。用户的谜底直觉哪怕半句也记入。
- 金手指是占位符：定形在卷级结构设计后反推——谜底定了，金手指从谜底里派生。
- **世界线先预判量级（防写小）**：按篇幅记一句"这书大概多大世界"（单城/星球/多元），写进世界线。它会在世界画像第0步被量规表复核。**200万字以上的，这里就标"至少星球/多元"，别等画像阶段才纠正。**

**research 调研（资料门）**：需求卡整理后，针对赛道和 X 元素需求做增量调研。数据源顺序：已有赛道包 > wiki 站 > 联网调研；查不到的写"没查到"，不凭空编造。存档前先答"资料够不够"：不够必派 `pop-snow-research` 补采再存档（跨系列只读调用，不写其文件）；调研完可为需求卡回填（用户改主意以新为准）。调研文档存档为 `02-调研文档.md`。

**故事脉络五元素公式**：有了需求卡和调研，推演这本书的故事脉络。唯一可靠尺子跨书通用，不分赛道、不分类型：

```
主角是谁 → 世界哪里失衡 → 欲望串（串行/并行） → 谁挡着 → 最后落什么结局
```

| 元素 | 填什么 | 判据 |
| --- | --- | --- |
| 主角是谁 | 一句话立人：身份＋特质＋处境 | **只写"什么人"，不写"凭什么"**——读者能记住这是个什么人，但不知道他具体凭什么、经历了什么（那些留给主角设计） |
| 世界哪里失衡 | 世界/环境哪里不对劲，逼着主角动 | 是失衡，不是背景板；具体到可感知；**分双层（旧失衡被压＋新失衡撕破）** |
| 欲望串 | 贯穿全书的心理动机，可串行可并行 | 主线最多一两条；**末尾要同时挂钩解决新旧双失衡** |
| 谁挡着 | 明面阻力＋暗面阻挡 | 分两层：明面是谁、暗面后面还有谁 |
| 最后落什么结局 | 主角最终翻到哪一步 | 有收束，不悬空；写"从X翻成Y"的质变 |

**欲望串**：

- 主角想要的不是单目标，是一根动机链，串行或者并行。
- 串行：一个欲望达成/幻灭后，接下一个更大的（接力律，接的比之前大一号）。例：生存→变强→守护人族→平定乱世。
- 并行：多个欲望同时挂着同时追（组合律，全书主打一两个，其余为次要目标）。例：查原身死因＋想办法回家，中途又挂上阻止末日。
- 可串行和并行叠着用：一条串行的主欲望串，中间并行走支线。
- 判据：串得再长，全书主线最多一两条（主角最想要的那一两个），其余都是次要目标。否则欲望串变成清单堆砌，读者记不住主线。
- 欲望串是"贯穿全书的心理动机"（战略），不等于每卷要拿到的具体东西（战术）。卷级目标是"这一卷的达成物"，别并进欲望串里。
- **欲望串末尾挂钩双失衡**：欲望一路串到终点时，要同时挂钩解决"旧失衡"与"新失衡"两条——不是只灭新危机就算完。两条失衡常是同一根源的一体两面，世界观越往真相越发现二者同源。

**越界边界**：

- 故事脉络的主角 = 一颗种子（身份/特质/处境），不是小传。金手指、能力、凭什么入局、心理转折，**全部留给后面的 `主要角色设计·主角力量资格/金手指` 那份锁根**。
- **越界判据**：写完"主角是谁"，若读者已经知道"他到底凭什么、具体经历了什么某段奇遇"，= 越界。故事脉络只该让人记住"他是个什么人"，不该把"他凭什么"定完——否则主角设计那份没料可产。
- **两层该归谁**：`身份/特质/处境`（如"被除名的顶级义体佣兵落到底层"）放`主角是谁`；`凭什么/能力/奇遇`（如"那本不该活的命是影子借给他的"）归 `主要角色设计`。谁定的身份放故事脉络，谁定的能力放主角设计，别混。

两条纪律：

- **立项不写"代价"**。爽文的爽感来自"成功"，代价在打通主线时会打断爽感。悬疑/反转型书真要加，放到卷级结构里单独加，不放进全书通用公式。
- **失衡是驱动，不是背景板**：写"圣城地下怪物最不对劲"，不写"这是一个充满怪物的世界"；分双层，写"这个被资本压榨到习惯的世界，被诡异复苏凿开了裂缝"，不写"这个世界乱了"。**结局要"翻"**：写"杂役翻成定世界生死的人"，不写"他活下来了"。

**故事脉络产出去向**：主角欲望线/世界线/谁挡着 → 交 world/character/plot 消费（锁根设定从故事脉络取种子）；X元素清单 → 交 world 设定钩子。

#### 5. 篇幅推导（顶层总参数）

篇幅是先于一切锁根设定的**顶层总参数**：先定它，再让世界法则（养成线档数）、世界画像（层/域数）、世界格局（矛盾数）向它看齐。用 AskUser 确认全书大致篇幅（短篇 / 连载 / 长篇，或目标章数、万字量级），再据此确认是否分卷、分几卷、每卷大致章节范围。

推导链：

```
① 定总字数（需求卡里锁的篇幅）
② 定每卷的章节数 & 每章字数 → 得"一卷约多少字"
③ 总字数 ÷ 一卷字数 → 全书总卷数 N
④ 主养成线质变点数 ≈ N + 1（起点一次 + 每卷一次跳，可微调合并）
⑤ 地图升级次数 ≈ N（每卷扩一次舞台，可合并）
⑥ 世界矛盾解锁层数 ≈ N（每卷解一层，是格局/势力文档的总参数）
```

反向同理：先想要几条主养成线质变点、开几层地图，反推需要多少卷，再定总字数。

**总容量检查**：篇幅是世界的"可承载容量"，必须同时装下"世界多大 × 升级多快"：

- 世界太大、篇幅太短 → 草草收尾或半天不升一级（装不下）。
- 世界太小、篇幅太长 → 拖戏、注水（装不满）。
- 检查点：给定 N 卷，世界的层/域数、养成线总档数、矛盾层数**必须恰好被 N 装下**。装不下就缩小范围或切割分层；装不满就并卷或加戏。

**数感参考**（经验常量，未实测，待实测）：每卷约 70-150 章（看赛道节奏）、每章约 2500-4200 字（网文惯例）、一卷约 25-40 万字（AI 写作）、典型全书男频 200-300 万字。以上是参考量级不是铁律，以需求卡锁的篇幅为准套推导链；每章字数最终以 mirror-write 节奏硬尺实际口径（2000-3000 字±10%）校准。

**产出质量线**：推导出的质变点数是骨架，真实质量线是"每两档质变点之间的过渡戏"够不够。主养成线中需要放慢写的档要**少于 N**，留出卷内挣扎/铺垫戏；升级过密导致疲劳。

**篇幅量级确认同时是大纲轨道的取值基准**：这是轨道 `start_chapter_num` 与 beat `chapter_count` 的取值基准——没有量级基准，章节范围无法合理估算。不要求精确总字数（网文多为开放式连载）；卷数与范围由用户主导，AI 可依量级建议切法但不得擅自定卷。短篇无需分卷，单轨即可。

#### 6. 区分元数据、规则与故事事实

收集到的内容必须分流到正确载体，不能混写为 AgentRule：

**作品元数据 → novel 资源本身**

- 载体是 novel 资源本身，既不是 AgentRule，也不是世界观 / 角色等工作区资源。
- 用户确认后分别写入 `/novel/title`、`/novel/category`、`/novel/tags`、`/novel/description`。
- 不要把分类或标签写成 AgentRule。

**加入书架**：若无书库草稿，书名与方向确认后用 AskUser 问一次是否加入；同意则加入书库；拒绝则不调用。

**写作行为约束 → AgentRules**

- 稳定的、AI 后续写作时需要遵守的判断规则。
- 例如：「不写露骨内容」「保持第三人称单主角视角」「每章 4000-5000 字」「反派不得降智」「章末必须留钩子」。
- 对已有资料提炼出的候选规则，AskUser 必须说明候选内容、来源资料，以及写入后后续智能体写作都会参考该规则；只有用户明确确认后才能创建或更新。
- 一条规则只管一个维度，可执行、可复用、不含空话。

**故事事实 → 对应工作区资源**

- 人设、世界观、力量体系、境界划分、势力格局、核心谜题、真相层级、时代制度、关系主线等。
- 不要写成 AgentRule。引导用户（或在用户确认后由 AI）写入对应工作区资料：世界观条目、角色档案、势力档案、大纲等。
- 如果某条故事事实同时需要 AI 后续创作严格遵循，可以在写入工作区之后再提炼一条 AgentRule（例如「主角火焰不能点燃金属」），但故事事实本身的载体仍是工作区资源，不是 AgentRule。

**大纲轨道**

- `/outlines` 里的每条大纲都是独立轨道，不设 kind，也没有父子关系；用标题表达用途，例如"全书总纲""主线：第一卷""感情线：A↔B""暗线：幕后身份"。
- 新建或修改前先 Read `/outlines`，根据实际标题和内容确认要操作的轨道；不要把"感情线""暗线"等当作系统枚举，也不要为了模板完整而新建空轨道。
- "全书总纲"可以只写全书结构；分卷主线、感情线、暗线等只在需要独立长期维护时另建。具体标题、是否拆分及每条线的内容必须由用户或已确认的创作需求决定。

#### 7. AgentSkill 能力配置与设定加深

在根决策、结构项、元数据和写作行为约束确认后，补齐近期高频创作能力；不预装所有技能，也不把 AgentSkill 当作故事资料或 AgentRule。

**基础创作能力**：用于后续高频的章节工作。先看第 1 步已读取的全局 AgentSkill：已安装且启用、职责匹配时，后续直接用其 `call_name` 调用，不再查询目录或安装。若缺失，先读取一次官方技能目录，按"章节规划""正文写作""跨章节连续性"等能力方向挑选（能力方向，非固定技能名），再 AskUser 展示每项名称、用途与全局可用影响。只有确认的候选才逐项安装。用户暂不安装不阻塞引导完成，收尾列为尚未配置能力。

**设定加深**：检查工作区资料是否仍有需工程化梳理的故事事实缺口。只有某项事实同时满足「全书稳定、后期难改、需要多轮结构化确认」，且现有资料不足时，才推荐匹配的设定 AgentSkill。按缺口判断匹配度，不按题材硬编码映射。已全局安装直接调用；未安装时先确认来源再 AskUser 安装并立即调用。

**其他专项能力与来源规则**：开篇、节奏、润色、审查等能力按当前创作阶段或用户明确提出的任务推荐，不进入基础包。优先选 `official` 的通用能力；official 无匹配或用户想浏览社区再考虑 `marketplace`。已全局安装且职责匹配优先直接使用。安装流程：按候选名称/描述筛选；用 `get` 按需看完整 prompt；AskUser 说明来源/用途/全局可用影响，未确认不安装；确认后按来源安装并用返回的 `call_name` 立即调用；`call_name_conflict` 用 AskUser 让用户选覆盖/改名/取消，不自行覆盖；marketplace `login_required` 时先 login 再重试失败那步。一个缺口只装一个最匹配技能；多个缺口分轮处理，每轮重新 AskUser。

#### 8. 提问原则

- **必须使用 AskUser 工具**进行交互式提问，不要直接输出问题列表等待用户回复。
- **按依赖顺序分轮提问**，一轮 AskUser 放 2-3 个相关问题，不要一次抛出整张清单。先问决定其它项的根决策（题材与目标读者、故事承诺），拿到回答后再用它定制后续轮次的问题与推荐项。例如：男频玄幻 → 后续推荐第三人称单 POV、4000-5000 字、3-5 章一个小高潮；悬疑 → 后续推荐严格信息边界、克制文风。
- **每个问题提供 2-4 个 options，并将其中一个标注 `recommended: true`**。推荐依据是已读取的小说元数据、已有资料和前几轮回答，保持 `allow_free_text` 允许用户自行输入。推荐只是降低回答成本，不是默认值：用户未选择前不当作已确认，不写入。
- 如果用户说「你来定」，把「默认建议」结合前几轮回答汇总为一套建议，但必须标注为建议，并请求确认；确认前不写入。
- 如果用户只回答一部分，只写入已确认的内容，剩余缺口继续保留。
- 发现新回答与旧 AgentRules 冲突时，不要平均处理；直接指出冲突，让用户选择保留哪条，确认前不覆盖。

#### 9. 完成与回报

完成标准以「改起来贵不贵」判断，而不是「第一章用不用得上」：全书稳定、后期难以更改的基础决策已确认并写入，即视为基础引导完成。角色、势力、支线等可渐进补充的故事事实允许留白。基础创作能力已安装，或本轮已明确暂不安装、无匹配候选或暂不可用，不影响基础引导完成；已启动的设定加深或其他专项 AgentSkill 则按其最小存档要求继续，直到完成或用户中止。

Onboarding 收尾时，简短回报：

- 需求卡五字段与故事脉络五元素（各填了什么，越界检查过了没有）。
- 篇幅推导结果（总字数 → 卷数 N → 质变点数/地图升级次数/矛盾解锁层数）。
- 已创建/更新了哪些 AgentRules（按维度列出）。
- 已写入哪些作品元数据（书名/分类/标签/简介）。
- 已安装的全局基础创作 AgentSkill（名称、来源、用途）；已安装并接力的设定加深或其他专项 AgentSkill，以及据此写入了哪些工作区资源。
- 仍有哪些缺口未解决（含尚未配置基础能力、用户拒绝安装、需登录未完成或目录无匹配），建议下一步如何补齐；如有推荐但未安装的技能，列出候选说明用户可随时手动安装。

回报之后，挂一次下一步建议（本轮只挂一次）。从候选中按本轮实际写入的内容挑最多 3 条，缺口没有就不给。

### 存档

问需求三步的产出（需求卡、调研文档）＋故事脉络，都写在项目空间：

```
项目空间/
  01-需求卡.md       ← 需求卡五字段存档（调研后可回填）
  02-调研文档.md      ← research 调研存档
  03-故事脉络.md      ← 五元素公式存档
```

文件名加案子前缀时，前缀写书名或代号，不写日期。

### 默认建议

以下默认建议是提问时 `recommended` 选项的取值基准（结合小说元数据与前几轮回答可调整），也是用户明确要求「你来定」「给我建议」时汇总建议的来源；无论哪种方式，都必须等待用户确认后才能当作当前小说规则使用：

- 章节字数：2000-3000 字，允许上下浮动 10%。
- 文字风格：清晰、克制、有画面感，少用空泛抒情和总结句。
- 叙事视角：第三人称单主角视角，严格遵守信息边界。
- 节奏：每章至少推进一个明确变化，章末保留钩子或情绪缺口。
- 禁忌：不降智反派，不强行误会，不用 AI 腔过渡词，不用大段解释代替行动。

### 边界

- 本 skill 不替用户无依据地补全设定。故事脉络是种子：只写"什么人/哪里失衡/欲望串/谁挡着/什么结局"，金手指、能力、凭什么入局留给角色设计，不提前定完。
- 立项只定五元素大骨架，**不动叙事结构**。经典的叙事结构（英雄之旅、三幕式、爽文节奏、双线叙事、碎片式、单元剧等）全部留到卷级/具体大纲设计时，按赛道选着用。叙事结构是形状层，描述"一个故事"的形状；网文全书是几十个完整小故事，立项用不了结构骨架。
- AgentSkill 不保存故事事实，也不替代 AgentRules；技能执行后的规则与设定必须写回正确载体。
- AgentSkill 虽然全局可用，但不得硬编码当前小说的故事事实；涉及作品上下文时，prompt 必须先读取或询问当前小说资料。
- 初始化无法预测用户未来的全部任务。后续用户突然要求审稿、润色或其他未安装能力时，应由聊天路由或「创作工具管理」的技能管理附件一次读取目录、确认并安装，不要求本 skill 预装全部技能。
- 日常 AgentRules / AgentSkills 的增删改查使用「创作工具管理」对应附件；本 skill 负责 Onboarding 阶段的初次写入与设定加深编排。
- "仿写技法"（学习某部作品的开篇/结构/节奏/文风）不在本 skill 承接范围，另走拆书类 skill。

## 红线

1. **先读再问**：提问前必须收集已有信息，不得空手问；已有内容未经确认不得覆盖。
2. **分轮提问**：按依赖顺序一轮 2-3 问，不一次性扔出整张清单；顺序是根决策 → 故事脉络 → 结构项 → 元数据 → 写作约束。
3. **载体分流**：元数据→novel 资源、行为约束→规则、故事事实→工作区资源，三者不得混写。
4. **不越权定稿**：记得"默认建议"在用户确认前都不是规则；"你来定"也要汇总为建议并请求确认后才写入。
5. **越界检查**：故事脉络的主角只写什么人、不写凭什么；金手指占位不定形；欲望串末尾挂钩双失衡；结局写"从X翻成Y"。
