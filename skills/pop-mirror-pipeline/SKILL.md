# pop-mirror-pipeline

> 将镜界（Mirroric 小说创作应用）系列 AgentSkill 的提示词精华，改造成一个可直接跑通全创作流程的专家 skill 系列。本 skill 是系列**总控**——维护专家清单+源映射+创作链路+四阶段心智模型，按链路路由到八个写作子专家，并路由 research 调用、检查各子专家产出三检查（事前沟通/事后确认/research 评估）。项目空间约定：research 存档统一 `素材/采风/`，剧情进度记录统一存 `小说日志/`（不叫"产出"）。当前版本 v2.2.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 这个 skill 做什么

**定位**：Mirror 创作专家系列总控，负责编排与路由，**不产具体创作产出**。八个写作子专家各司其职，配合本总控构成完整专家系列。

**触发时机**：新书想用 Mirror 专家体系走完整创作流程时；或进入某创作环节想确认该调哪个专家时；或需要核对"这份产出该在哪一步产"时。

**前置输入**：用户当前创作意图（立项/世界观/人设/卷级剧情/开篇/规划/写作/去AI味/审查/research）+ 已有项目资料（若存在）。

**产出**：路由指示（该调哪个子专家 + 优先喂什么）+ 阶段定位（这份产出落在管线哪一步）；不产出正文/大纲等创作物。

**交接给**：按链路路由到八个子专家之一或 research；子专家产物回流本总控继续下一环。

**子专家清单（id → 源 → 链路作用）**：

**通用约定**：

- **一次一专家**：同一时刻只有一个执行者，避免方法论混用。
- **保真红线分区**：正文循环区（04 opening / 06 write / 07 deai / 08 review）的「怎么操作·精华」节 = 镜界对应源文件原文逐字直贴，未增删改写；覆盖区（01 onboard / 02 world / 03 character / 05 plot 卷级部分）操作方法论按我方 SOP 重写，SOP 为权威，镜界原文降为参考。凡新增编排内容只出现在专属「做什么/红线/速查表」节，与精华分隔。若编排节与精华冲突，以各节声明的权威源为准。
- **运行时落地**：镜界原文含 `Run {command:...}` / `AgentSkill` / 工作区资源（`/novel`、`/relations` 等）等镜界运行时能力；纯本地/其他项目落地时视为需轻量化的人为输入，不改变方法精化。
- **剧情进度记录存 `小说日志/`**：每章审查报告/进度记录与状态快照统一存项目空间 `小说日志/`（记录剧情进度），不叫"产出"。

## 怎么操作（编排 SOP 全内联）

### 第 0 节 · 四阶段心智模型（管线全貌-SOP 权威）

整条管线从一句故事脉络走到正文，四个阶段。越往上的阶段，产出越不可逆。

```
创意（故事脉络：主角是谁→世界失衡→欲望串→谁挡着→结局）
  │
  ▼
核心设定设计阶段（写主线剧情之前）────────
  │  产出 tag=锁根 的那些：力量的根、主角力量的根、世界基调的根、主角本命
  │  特征：主路径必踩、牵一发动全身、几乎不可逆
  ▼
主线剧情设计阶段（骨架：先立主线，再拆卷）──
  │  产出 tag=骨架 的那些：宏观地理格局、顶层势力、世界历史段落、主要反派、卷级结构
  │  卷级结构 = 主线脉络（世界终点×主角欲望线耦合：同芯拧双脊柱／并行两线独立）＋按质变点切卷＋每卷三同进＋卷内单元循环层
  │  特征：决定全书形状，比"根"轻，骨架级即够；先立主线脉络再拆卷，拆卷是排期不是编戏
  ▼
逐卷展开期（排卷→写卷纲→写章）────────
  │  产出 tag=展开 的那些：这一卷遇到的势力分支、体系方向、当卷角色
  │  卷纲 = 把卷级结构的单元循环落地到章节弧段与章纲（每章标题+核心剧情点+参数递增标注）
  │  特征：剧情走到哪卷，就产出这份设定的那一卷版；卷纲做法见 pop-mirror-plot
  ▼
写章期（临场）────────────────
  │  产出 tag=写章 的那些：地名细节、路人、风土人情、低层规则
  │  特征：写到那一章才需要，临场造即可
```

**四条要点**：

1. **越靠上越不可逆**：核心设定设计阶段定的东西，后期改动＝重写一堆；写章期造的，随时可改。
2. **每份产出只有一个合适的时机**：不该在写章期才定"成长体系"，也不该在核心设定设计阶段就造"某条街叫什么"。
3. **判断一份产出落在哪，只问一个问题**：它是主路径必踩、牵一发动全身，还是用到才够？
4. **剧情产出的顺序是硬约束**：先立主线脉络（世界终点×主角欲望线耦合：同芯拧双脊柱，并行两线独立），再按主养成线质变点拆卷，每卷填三同进（质变/地图/矛盾），卷内拆单元循环（5-7 个剧情单元，日常/推进/结算三类，参数递增），最后才写卷纲。反着来＝编戏代替排期，卷会漏。

### Step 1：判断当前创作环节

先问用户此刻要做什么，映射到子专家之一：

```
立项(01：故事脉络+需求卡+篇幅推导)
  │
  ▼
核心设定设计（02 世界观 · 03 人设）── 锁根：近乎不可逆
  │
  ▼
主线剧情设计（05 卷级部分：立主线脉络→拆卷→单元循环→卷纲）── 骨架：决定全书形状
  │
  ▼
开篇(04 黄金三章)
  │
  ┌──── 每章循环（05 章节级四段式 先行）─────┐
  ▼                                         │
06 写作专家（渲染正文 + 节奏硬尺）             │
  │                                          │
07 去AI味专家（清洗）                        │
  │                                          │
08 审查专家（一致性/设定/连续性）── 打回/通过 ──┤
  └──────────────────────────────────────► 下一章
```

- **一次一专家**：同一时刻只路由一个子专家，避免方法论混用。
- **开篇专家(04)** 只在前三章启用；**审查专家(08)** 是创作后的质量检查口，不做创作入口。
- **写法合一**：单章节奏硬尺（字数±10%、密度、断章、钩子轮换）已并入 **06 write**，规划(05)只需交给 write 大纲与伏笔台账，不再另调节奏专家。
- **research 是横向能力**：立项调研/设定考据/剧情素材三类需求随时可路由 `pop-snow-research`（跨系列只读调用，不写其文件；存档统一 `素材/采风/`）。

### Step 2：按环节通向对应子专家

| 用户想要 | 路由到 | 优先喂给它的输入 |
|:--|:--|:--|
| 开新书/重新立项（完整 onboarding） | pop-mirror-onboard | 一句话想法（无则空，全新立项）；产出顺序：需求卡→故事脉络→篇幅推导→元数据/规则；**完成判定：03-故事脉络.md + 篇幅推导落盘并确认（书名/简介/分类定完 ≠ 立项完成）** |
| 建世界观/力量体系 | pop-mirror-world | 前提：onboard 已完成（故事脉络 + 篇幅推导已落盘）；喂 故事脉络 + 篇幅推导 + 已有设定摘要 |
| 建人设 | pop-mirror-character | 世界观 + 故事脉络的主角种子 |
| 定卷级结构/拆卷/写卷纲 | pop-mirror-plot（卷级部分） | 故事脉络 + 锁根/骨架设定 + 篇幅推导 |
| 设计开篇/黄金三章 | pop-mirror-opening | 根决策 + 世界观 + 主角人设 + 第一卷卷纲 |
| 定本章大纲 | pop-mirror-plot（章节级部分） | 上章钩子 + 主线 + 伏笔台账 |
| 写正文（含节奏） | pop-mirror-write | 本章规划大纲 + 人设/设定（节奏硬尺内嵌） |
| 去AI味清洗 | pop-mirror-deai | 待清洗正文 |
| 审查一致性 | pop-mirror-review | 正文 + 既有事实（角色卡/世界书/伏笔） |
| 立项调研/设定考据/剧情素材 | pop-snow-research | 需求卡 + 待查清单（四场景 SOP/检索协议/搜索纪律） |

### Step 3：收尾衔接

- 每个子专家产出后，若创作未完成，路由到其「交接给」所指的下一专家，形成循环。
- **onboard 未产出并确认 `03-故事脉络.md` 与篇幅推导前，不得路由 world/character/plot**：故事脉络是 world/character/plot 的上游种子，元数据（书名/简介/分类/标签）只是 onboard 的一环，不是立项完成的标志。
- 审查未通过 → 打回写作专家重写；通过 → 进入下一章/下一环。
- 不跨专家预判内容：trigger 具体写作、审查等任务时不擅自越权由本总控直接执行对应专家的工作。
- 覆盖区子专家存档前先答"资料够不够"（资料门）：不够必派 research 补采再存档。
- **三检查纪律（总控检查项）**：每个子专家产关键文档前先与用户沟通（事前沟通）；产出后回查自检并请用户确认，确认后才继续下一环（事后确认）；涉及现实考据/专业设定的，落盘前评估资料够不够，不够路由 `pop-snow-research` 补采（research 评估）。总控路由时按此检查子专家是否已过三检查，未过先补。

## 红线

1. **总控不越权**：本 skill 只路由编排，不替代任何子专家执行具体创作/审查；落到具体环节时必须加载对应子 skill。
2. **保真红线分区**：正文循环区（04/06/07/08）精华逐字直贴不改写，路由与编排不得用"升华/改写/去AI味"加工原文；覆盖区（01/02/03/05 卷级）以 SOP 为权威，冲突以 SOP 为准。
3. **一次一专家**：同一时刻一个执行者，禁止在同一产出内混用多个专家方法论。
4. **阶段纪律**：越靠上越不可逆；一份产出只在该产出的阶段产；判断标准只问"主路径必踩、牵一发动全身，还是用到才够"。
5. **剧情产出顺序硬约束**：先立主线脉络 → 按质变切卷 → 填三同进 → 拆单元循环 → 写卷纲；反着来＝编戏代替排期，卷会漏。
6. **research 只读调用**：pop-snow-research 跨系列调用，只读不写其文件；存档统一 `素材/采风/`。
7. **立项完成判定**：03-故事脉络.md + 篇幅推导落盘并确认才等于 onboarding 完成；标题/简介/分类定完不算完成，不得提前路由 world/character/plot。
8. **三检查纪律**：各子专家产关键文档前与用户沟通、产出后确认、落盘前评估 research；总控路由时检查未过先补。
9. **落盘约定**：剧情进度记录（每章审查报告/进度记录 + 状态快照）统一存项目空间 `小说日志/`，不叫"产出"。

## 执行模式

主 agent 直执路由：判断环节 → 路由子专家 → 接子专家产物继续编排；路由时检查子专家产出三检查是否走完。不派子 agent 执行创作。
