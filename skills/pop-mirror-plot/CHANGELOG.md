## v2.2.0 | 2026-09-10

### 补卷纲硬约束：单元表内容要素 / 重大爽点清单 / 每章爽点密度 / 卷级旅程弧

9-10 项目a 卷1 卷纲暴露三个缺陷：幕剧情太笼统（谁登场/谁是boss/成长点/冲突点/线推进节点全缺）、整卷看不出打掉谁、单元幕乏味且节奏慢。老板拍板补四条硬约束（SOP 同步，剧情产出-SOP 二修）：

- **单元表内容要素（阶段3）**：单元表除排期字段外，每单元必填 5 个内容要素——登场角色/幕内敌档链（小敌→中敌→幕末敌人）/成长点/冲突点/线推进节点；没有内容要素＝单元空壳、拆章临场硬编。
- **重大爽点类型清单（阶段3）**：9 类写死枚举——战斗胜利/夺宝获资/成长升级/打脸装逼/剧情推进/关系推进/身份跃迁/危机拯救/震撼场面。
- **每章爽点密度（阶段3）**：每章 ≥1 个重大爽点（卷纲必标类型标签）；密度目标 ≥2；无爽点章最多 1 章不连续；爽点闭环三件（发生+反应+影响），假爽点验收不过。
- **卷级旅程弧（阶段4）**：卷首先写旅程弧（起点处境→第一波遭遇→中间经历→卷末对手→击杀/达成→卷末新处境）；一卷 = 一个大的英雄之旅；每卷必须有可命名的卷末对手并正面结算（不是"爪牙头目"一笔带过）。
- **卷纲章格式**：加"爽点（类型标签）"字段；兑现清单加旅程弧闭环 + 每章爽点标注；产出SOP 步骤6/7 验收基准与收尾验收一句话同步更新。
- **红线**：新增 3 条（单元表必有内容要素 / 卷纲必有卷级旅程弧 / 每章必有爽点），重排至 12 条；速查表加"重大爽点""卷级旅程弧"两行。

同步三件套：SKILL.md / skill.json（version 2.2.0）/ CHANGELOG（＋ references/单元剧剧情库.md v1.2）。
