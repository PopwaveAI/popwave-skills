# pop-mirror-review

> Mirror 审查专家：三源合一（角色一致性/设定一致性/长篇连续性），对正文做一致性、设定冲突与长篇连续性的审查闭环——给位置/问题/严重性/最小改法/状态更新。镜界 `04-角色一致性` + `09-设定一致性` + `08-长篇连续性` 精华逐字直贴。当前版本 v1.0.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 这个 skill 做什么

**定位**：创作后的质量闸——审查正文在**角色一致性**、**设定一致性**、**长篇连续性**三个维度上是否站得住。不做创作入口，只做审查与打回/通过判定。

**触发时机**：pop-mirror-write 出稿 + pop-mirror-deai 去味后，进入每章审查闭环时。

**前置输入**：待审正文 + 既有事实来源（已发布正文/角色卡/世界书/伏笔台账/章纲）。

**产出**：结构化审查报告，按问题输出【位置 / 问题 / 严重性 / 改法 / 状态更新】（详见精华·A/B 的输出建议节）。

**交接给**：审查未通过 → 打回 pop-mirror-write 重写；通过 → 进入下一章/下一环。与 pop-mirror-world/character/plot 共用同一事实源（角色卡/世界书/伏笔台账）。

***

## 怎么操作（SOP 全内联）

> **精华保真声明**：本节为镜界 `04-角色一致性` / `09-设定一致性` / `08-长篇连续性` 三个源文件正文**逐字直贴，未增删改写**。三个源按各自原文顺序排列，仅作「来源标注」分节，不改动原文任何表述。

### 精华·A｜源文件 04-角色一致性

# 角色一致性

## 核心目标

角色行为必须能从既有事实推出。不能为了剧情方便临时改变性格、知识边界、能力水平或关系状态。

## 事实优先级

判断角色一致性时，按以下顺序取证：

1. 已发布正文中的明确事实
2. 最新章节事实提取和章节摘要
3. 角色卡的当前状态、关系、能力、伤势、持有物
4. 世界书中与角色能力、身份、阵营有关的规则
5. 活跃伏笔和未解决冲突
6. 大纲和本轮临时要求

用户临时要求如果和已发布正文冲突，必须指出冲突，不能直接覆盖角色既有事实。

## 状态检查

审查角色行为前，先核对硬状态：

- 位置：角色此刻在哪里，是否有合理路径到达现场？
- 伤势与消耗：上一章的伤、疲惫、能力消耗是否被承接？
- 能力：使用的能力是否已获得、已恢复、已满足触发条件？
- 持有物：关键物品、武器、证据、资源是否仍在他手里？
- 信息边界：他知道什么、不知道什么、误以为什么？
- 当前目标：他此刻最想得到什么，最怕失去什么？

硬状态错位时，优先判为一致性问题，不要用"角色突然想到/突然做到"糊过去。

## 动机闭环

每个关键选择必须能回答：

- 经历：过去发生了什么，让他形成这种反应？
- 利益：这个选择让他得到什么、避免什么损失？
- 恐惧：他最怕哪件事重演？
- 渴望：他真正想证明、拥有或守住什么？
- 压力：现场是否有足够压力逼他越过原本边界？
- 误判：他基于哪些信息做错了判断？

如果只能用"剧情需要"解释，就是 OOC。

## 信息边界

- POV 角色不能知道他没看见、没听见、没被告知、不能合理推断的信息。
- 角色不能突然忘记前文明确经历、承诺、伤害、秘密或线索。
- 误会、试探、隐瞒必须有信息来源和心理理由。
- 群像场景中，每个角色只能基于自己掌握的信息行动，不能共享作者视角。

信息越界比性格偏差更严重，因为它会直接破坏读者对叙事公平性的信任。

## 关系变化

关系升温、背叛、和解、称呼升级、敌意缓和，都必须有触发事件和后效。

审查时追问：

- 触发事件是什么？
- 双方各自付出了什么代价？
- 关系变化后，称呼、站位、资源共享或保密边界有没有改变？
- 旁人是否会注意到这种变化？
- 下一章这段关系会带来什么新状态？

没有事件支撑的关系变化，判为突兀。

## 对白一致性

对白不是只传信息，还要暴露角色。

- 称呼：是否符合身份、亲疏、场合和关系阶段？
- 句长：急性子、谨慎者、学者、权力者的句长和信息量应不同。
- 语气：恭敬、讽刺、冷淡、试探不能混成同一种声音。
- 禁忌：角色不会说的话比会说的话更重要。
- 潜台词：重要关系场景里，角色不应把真实目的全说破。

关掉角色名仍能分辨谁在说话，才算通过。

## OOC 判定

发现可疑行为时，逐项判断：

- 硬状态是否正确？
- 这个选择是否符合经历、利益、恐惧、渴望和现场压力？
- 信息边界是否被突破？
- 关系变化前是否有触发事件？
- 对白是否符合称呼、句长、语气和禁忌话题？
- 如果只读过前文，读者会不会觉得这个人换了芯？

三个以上问题无法回答，判为严重 OOC；一到两个问题缺证据，标记为证据不足或警告。

## 输出建议

用于审查报告时，按问题输出：

- 位置：指出章节、段落或具体句子。
- 问题：说明违反了哪个角色事实或信息边界。
- 严重性：严重 / 警告 / 提示。
- 改法：给出不改变核心剧情的最小修复方案。
- 状态更新：如正文产生了新事实，说明是否需要写入角色卡或关系记录。

### 精华·B｜源文件 09-设定一致性

# 设定一致性

这是给内容核验、世界观分析和改稿任务使用的规则包，不是最终审查入口。最终是否通过由内容核验 agent 判定。

## 核心目标

世界观规则必须稳定、可追踪、有代价。新设定不能只服务本章，也不能绕开前文难题，让旧冲突显得多余。

## 事实优先级

判断设定冲突时，按以下顺序取证：

1. 已发布正文中的明确事实
2. 最新章节事实提取和章节摘要
3. 世界书 / 设定圣经
4. 角色卡中的能力、身份、阵营和持有物
5. 伏笔记录和未解冲突
6. 大纲和本轮临时要求

如果大纲或用户临时要求需要突破既有规则，必须给出限制、代价或读者可接受的解释。

## 力量体系

审查能力、功法、科技、系统、神器时，逐项检查：

- 等级：当前角色是否达到使用门槛？
- 消耗：使用是否需要体力、灵力、寿命、金钱、权限、媒介或冷却？
- 上限：本章表现是否超过当前卷允许的能力天花板？
- 克制：是否存在反制、失败条件或环境限制？
- 后效：使用后是否留下伤害、痕迹、债务或暴露风险？
- 向下兼容：新能力是否让旧能力、旧困境或旧胜利失去意义？

如果主角能用新能力解决所有问题，体系有问题。

## 地图与距离

移动、传讯、调兵、运输都必须受距离、时间、资源和权限约束。

审查时追问：

- 角色从哪里来，怎么到达，花了多久？
- 是否跨越了前文设定的交通、地理、门禁或通讯限制？
- 场景切换是否有过渡？
- 同一地点的空间关系是否稳定？
- 天气、季节、昼夜、政局等宏观状态是否连贯？

没有解释的远距离瞬移、即时传讯、资源调动，默认判为设定风险。

## 势力与制度

势力不是名字列表，而是利益和规则系统。

- 权限：角色是否有资格进入地点、调动资源或使用信息？
- 奖惩：违反制度后是否有代价？
- 利益：势力为什么支持、阻挠或沉默？
- 内部矛盾：组织内部不同人是否有一致立场，还是需要派系解释？
- 弱点：强势力是否有成本，弱势力是否有生存理由？

势力行为不能只为了给主角让路。

## 资源经济

资源必须有来源、消耗和稀缺理由。

- 货币或资源如何兑换？
- 谁控制供给？
- 为什么不能无限获取？
- 本章消耗是否影响后续行动？
- 交易、治疗、装备、情报是否有价格或风险？

资源突然出现、免费解决问题、用完不影响后续，都会削弱世界可信度。

## 信息释放

设定揭示要服务当前行动。

- 单章新设定通常不超过 2 个。
- 重要规则最好通过角色遭遇、行动失败或代价显露。
- 例外规则出现前，常规必须已经稳定存在。
- 新名词过多时，优先保留影响本章选择和冲突的设定。

科普段不算违规，但必须发生在进入新领域、学习新体系或规则改变的节点。

## 冲突判定

新设定有以下情况时，至少标记警告：

- 与已发布正文、世界书、角色能力或时间线冲突。
- 绕开既有难题，让前文困境显得多余。
- 没有明确代价、限制和后续影响。
- 只在本章生效，后续无需承担结果。
- 引入过多新名词，挤压当前章节的情绪和行动。

严重冲突必须要求修订；轻微冲突可给出补丁解释，但补丁也要能写进正文或世界书。

## 输出建议

用于审查报告时，按问题输出：

- 位置：指出章节、段落或具体设定。
- 冲突来源：引用既有正文、世界书、角色卡或事实提取。
- 严重性：严重 / 警告 / 提示。
- 改法：给出最小修复方案，如降低能力表现、补充代价、增加过渡、调整信息释放。
- 世界书更新：如新设定成立，说明名称、首次出现章节、适用范围、例外条件和后续影响。

### 精华·C｜源文件 08-长篇连续性

# 长篇连续性

用于超长小说写作的记忆、逻辑和角色一致性规则。目标不是让模型一次记住全书，而是把每章写作纳入可追踪的状态闭环。

## 核心原则

1. **事实优先于灵感**：已发布正文、章节摘要、角色卡、世界书、伏笔记录的事实优先级高于本轮创作冲动。
2. **写前做状态核对**：每章动笔前先确认时间、地点、角色状态、道具归属、未解伏笔和上一章钩子。
3. **写中不静默修补**：发现前后矛盾时，不要用新设定硬盖旧设定；正文中必须给出可被读者接受的因果解释，或在审查报告中标出待修。
4. **写后更新记忆**：章节完成后提取真实发生的事实，更新角色、地点、关系、章节摘要和伏笔状态。
5. **近因强，远因准**：最近1-3章负责语气、情绪和动作衔接；全书摘要和世界书负责硬设定、因果链和长期目标。

## 上下文优先级

当上下文互相冲突时，按以下顺序裁决：

1. 已发布正文中的明确事实
2. 最新章节摘要与事实提取结果
3. 角色卡的当前状态、关系、能力、伤势、持有物
4. 世界书/设定圣经中的规则、地理、势力、能力上限
5. 活跃伏笔与未解决冲突
6. 全书大纲、卷纲、章纲
7. 用户本轮临时要求

用户临时要求若与上层事实冲突，必须指出冲突并给出改法，不能直接覆盖。

## 写前状态包

规划或扩写前，至少核对以下项目：

- **时间线**：上一章结束时间、本章开始时间、场景之间经过多久。
- **空间线**：角色从哪里来、如何到达本场景、离开后去哪里。
- **角色状态**：位置、情绪、伤势、能力、公开身份、秘密、当前目标。
- **关系状态**：称呼、信任度、敌意、利益绑定是否有事件支撑。
- **道具状态**：关键物品由谁持有、是否损坏、是否已被别人看见。
- **信息边界**：每个角色知道什么、不知道什么、误以为什么。
- **伏笔状态**：本章要回应、推进、回收、暂压的钩子。
- **世界规则**：能力、科技、制度、地理限制是否允许本章事件发生。

缺失关键信息时，用中性承接或在计划中标注待补；不要编造会影响后续的硬事实。

## 角色防乱规则

每个关键行为必须能回答：

- 角色此刻最想得到什么，最怕失去什么？
- 这个选择是否符合ta已知的经历、利益、性格底色？
- ta掌握的信息是否足以做出这个判断？
- 如果行为看似反常，本章是否给出了压力、误判、伪装或成长事件？

关系变化必须由事件驱动。称呼升级、信任加深、敌意缓和、背叛与原谅，都需要可定位的触发事件。

## 伏笔和长线管理

- 每章至少处理一个旧钩子：回应、推进、误导、压住但给理由，四选一。
- 新伏笔上限通常为2个，且要和本章事件有因果关系。
- 伏笔记录必须包含：埋设章节、当前状态、下一次推进窗口、预计回收范围。
- 超过10章未被提及的伏笔，在规划或审查时标为沉睡伏笔。
- 回收伏笔时写清后果：谁知道了、谁受损、关系或局势如何改变。

## 长篇审查清单

输出前做以下检查：

- 角色没有突破信息边界。
- 伤势、消耗、距离、时间没有被忽略。
- 能力和世界规则没有临时加码。
- 道具、金钱、身份、证据等硬状态前后一致。
- 上一章钩子得到承接，章末留下新的未完成动作或情绪缺口。
- 本章新增事实可以被写后提取进记忆库。

## 写后事实提取标准

只提取正文明确发生的事实，不把大纲计划当成既成事实。优先记录：

- 角色当前状态变化：位置、伤势、能力、目标、情绪、秘密暴露情况。
- 关系变化：触发事件、双方态度、称呼或利益绑定变化。
- 时间与地点：本章开始/结束时间、重要场景地点。
- 道具与资源：获得、失去、损坏、转交、被发现。
- 伏笔：新埋、推进、误导、回收、沉睡。
- 世界规则：新揭示的规则、例外、限制和代价。

事实提取结果应服务下一章写作，而不是写成读后感。

***

## 红线

1. **三源并审不偏科**：角色一致性 / 设定一致性 / 长篇连续性三源都须过审，缺一不可；以「严重」级问题是否清零为是否通过判据。
2. **取证顺序恒定**：审查按各源「事实优先级」自上而下取证，不得跳过「已发布正文的明确事实」直接拍板。
3. **最小修复**：改法给出不改变核心剧情的最小方案，不擅自改剧情走向。
4. **冲突不得静默覆盖**：用户临时要求若与既有事实冲突，必须指出冲突并给改法，不能直接覆盖。
5. **状态回流**：正文产生新事实（角色/设定/伏笔变动）必须在报告中给出状态更新建议，回流 pop-mirror-world/character/plot 的事实档案。

## 执行模式

主 agent 直执审查：读取正文 + 既有事实 → 三源逐维审查 → 出结构化报告 → 判定打回/通过。审查可进入 archive/审阅模式只读核验既有文档，不产创作物。
