## v2.9.1 | 2026-07-31

### 话数规划机制

解决信息超载导致的剧情看不懂问题——不是叙事结构问题，而是篇幅不够。

**根因分析**：玄鉴仙族第1话将2章原文（ch1122+ch1395）塞进12格漫画，信息负载超载2-3倍：

| 维度 | 第1话实际值 | 12格合理承载量 | 超载倍数 |
|:-----|:----------|:------------|:--------|
| 原文章节 | 2章 | 1章 | 2x |
| 关键信息 | 9条 | 4-6条 | 1.5-2x |
| 场景数 | 7个 | 2-3个 | 2.3-3.5x |
| 定妆角色 | 7个 | 3-5个 | 1.4-2.3x |
| 故事线 | 2条 | 1主+0-1副 | 2x |

v2.9.0 解决的是"给定篇幅内怎么讲好故事"，v2.9.1 解决"篇幅本身够不够"——这是更上游的决策。

**一、话数规划**（`step1-director.md` 新增 §2.5）：

改编分析前先评估信息负载，四项指标：

| 指标 | 统计方式 |
|:-----|:---------|
| 关键信息数 | 初步提取"丢了看不懂后续"的信息点 |
| 场景数 | 统计不同地点/时间的场景切换 |
| 出场角色数 | 统计有名字且说话/行动的角色 |
| 故事线数 | 统计独立并行的主要情节线 |

负载分级与话数决策：

| 总负载 | 判定条件 | 话数决策 |
|:------|:--------|:--------|
| 轻 | ≤5信息+≤3场景+≤4角色+1故事线 | 1话（6-8格） |
| 中 | 6-8信息+4-5场景+5-6角色+1-2故事线 | 1话精选（8-12格） |
| 重 | ≥9信息+≥6场景+≥7角色+≥2故事线 | **拆分为2+话** |

**拆分触发线**：四项指标中任意两项达到"重"级别 → 拆分。

**二、拆分原则**：

1. **按故事线切**：不同 POV/地点的并行线各自独立成话
2. **按因果断裂点切**：找到"起因→发展"或"发展→决策"之间的自然停顿
3. **每话有完整弧线**：起因→发展→决策→后果，不能只有"上半场"
4. **保留钩子衔接**：前一话的结尾钩子指向后一话的开头

拆分后每话独立走完整 Step 1 → Step 2 → Step 3 流程。

**三、同步更新**：
- 导演卡模板新增「话数规划」段落
- 门禁从5项升级为6项（新增"话数规划合不合理"为第1项）
- 改编自检新增2项（信息负载已评估 / 话数决策合理）
- SKILL.md Phase 1 Step 1 描述同步更新

## v2.9.0 | 2026-07-31

### 叙事主线设计 + 名场面设计方法论

解决两个叙事质量问题：漫画剧情看不懂（信息碎片化、无因果链），以及名场面张力不足（关键帧全是 talking head，缺乏视觉冲击力）。

**根因分析**：玄鉴仙族第1话测试中，导演卡的9条关键信息平铺直叙塞进12格——信息覆盖了但读者看到的是碎片不是故事；关键帧（金瞳定策/剑意冲霄/伐蜀只是顺便）全是角色站着说话的 talking head，去掉对白后画面没有任何视觉信息。

**一、叙事主线设计**（`step1-director.md` 新增 §1.5）：

信息审计是"零件清单"，叙事主线是"装配图"。先设计装配图，再清点零件：

1. **一句话故事**：读者看完本章后应该能用一句话总结什么？`{谁}在{什么情境}下做了{什么决策/行动}，导致了{什么后果}`
2. **因果链设计**：起因（1-2帧）→ 发展（2-3帧）→ 决策（1-2帧）→ 后果（1帧）。每帧必须推进故事，不是呈现信息
3. **主副线结构**：A-story 占 60-70% 享最佳帧位，B-story 占 20-30% 必须服务 A-story（铺垫/对比/悬念），无关系的副线砍掉
4. **读者理解路径**：模拟没读过原文的读者，逐帧列出"理解了什么"和"期待什么"——空白帧=废帧

**二、信息分级**（`step1-director.md` §3 关键信息审计升级）：

不是所有关键信息都同等重要，按优先级分三级：

| 级别 | 定义 | 处理 | 帧位 |
|:-----|:-----|:-----|:-----|
| S 级 | 丢了完全看不懂主线 | 必须呈现，分配最佳帧位 | 独占格/名场面 |
| A 级 | 丢了影响理解但不致命 | 应该呈现，可旁白浓缩 | 正常帧 |
| B 级 | 世界观增色但不影响主线 | 可砍，帧位紧张时第一个砍 | 合并或旁白 |

S 级不超过 3 条——一章的核心决策/转折最多 2-3 个。审计表新增"优先级"列。

**三、名场面设计**（`references/storyboard-guide.md` 新增 §8）：

高光独占格解决"信息不稀释"，名场面设计解决"画面有没有冲击力"：

1. **名场面识别三标准**：视觉奇观（画出来好不好看）/ 情绪爆发（能不能让读者感到什么）/ 剧情转折（是否改变故事走向）。三条满足两条 = 名场面，必须用最大布局 + 高精度提示词。每章至少 1 个
2. **张力构建五技法**：尺度对比（角色渺小vs环境宏大）/ 静默铺垫（爆发前留一格安静的）/ 反应镜头（不画事件画反应）/ 视觉隐喻（用象征物承载情绪）/ 留白截断（关键时刻画面截断）
3. **冲击帧提示词升级**：普通帧写"发生了什么"，冲击帧写"后果和感受"。不写"剑意冲霄"，写"百丈山峰被剑气切出裂痕，碎石纷飞如暴雨"
4. **talking head 反模式**：角色站着说话、去掉对白后画面什么都没有 = 最差漫画画面。名场面的画面应该不需要对白也能传达信息

**四、同步更新**：
- 导演卡模板新增「叙事主线」段落
- 门禁从 4 项确认升级为 5 项（新增"叙事主线清不清楚"）
- 改编自检新增 5 项检查（一句话故事/因果链/主副线/读者理解路径/S 级不超过 3 条）
- storyboard-guide 改编自检新增 4 项检查（S 级帧位/名场面存在/talking head 检查/冲击帧提示词写法）
- SKILL.md Phase 1 Step 1/Step 2 描述同步更新

**二、知名角色二创搜索**（`step0-init.md` 新增 §2.5）：

知名网文角色在读者心中有共同视觉记忆（官方插画、二创同人、社区共识）。新增搜索步骤：

1. **判断 IP 知名度**：万订/有官方改编/有大量二创 → 执行搜索；冷门/原创 → 跳过
2. **逐角色 WebSearch**：搜索"{小说名} {角色名} 漫画 插画 二创"
3. **提取视觉共识**：多个来源一致的特征 = 读者共同记忆
4. **融合到规格表**：二创共识回填规格表，标注验证结果
5. **下载参考图**（可选）：存到 `assets/characters/refs/`，用于图生图生成定妆图

门禁0 新增"二创参考对照"确认项：每个角色的二创共识特征 vs 定妆图实际效果。
定妆图生成新增图生图模式说明：有参考图时用模式 A/B，无参考图时用模式 C。

**根因分析**：玄鉴仙族漫画测试中，画风为 agent 自由拼串的"国风水墨漫画风格"（泛化不可识别），角色定妆图纯文字生成（不匹配读者对李周巍、程郇之等角色的视觉印象）。两个问题导致漫画"不像"且"不讨喜"。

## v2.7.1 | 2026-07-31

### 新增截长图功能

HTML 漫画产出后自动截取长图，用户无需手动截图即可分享。

**新增脚本** `scripts/screenshot_html.py`：

- **原理**：浏览器 headless 模式渲染 HTML → 全页截图 → Pillow 自动裁剪底部空白
- **零依赖**：自动检测系统自带的 Edge/Chrome（Windows 自带 Edge），无需安装 Playwright/Puppeteer
- **智能裁剪**：扫描 comic-page 背景色（#f5f0e8）定位内容底边界，hook panel 暗角不会被误判为空白
- **双格式**：PNG（无损）或 JPEG（小体积，分享推荐），默认 JPEG quality=90
- **截断检测**：内容超出 max-height 时自动警告

**管线集成**：
- `step2-storyboard.md` 新增 §8 截长图步骤（内联化后必须执行）
- `step3-review.md` 产出检查表新增"长图已生成"检查项
- `SKILL.md` 速查表新增截图脚本入口，产出文件结构新增长图文件

**测试验证**（深渊主宰 ch15，962KB HTML）：
- 原始截图 940×12000 → 裁剪后 940×4491
- JPEG output 991KB，9 帧全部完整，footer 文字可见

## v2.7.0 | 2026-07-31

### 借鉴 book-to-comic 五大机制

分析小红书 RedSkill 商店的 book-to-comic v5.13.6 后，吸收五项最具工程价值的设计，系统性提升跨格场景一致性、改编可审计性和漫画感染力。

**一、场景主镜机制**（`references/storyboard-guide.md` 新增 §场景主镜机制）：

- 同一场景的**首格**生成确认后成为"主镜"（scene master），该场景后续每格生成时必须将主镜图作为参考图输入
- 锁定维度：空间布局 + 光源方向 + 环境材质（角色一致性仍由定妆图负责）
- 分镜表新增**场景组**列，标识每帧所属场景；场景切换时旧主镜废弃，新场景首格成为新主镜
- `generate_storyboard.py` 的 `FRAME_REFS` 升级为双参考图：`[角色定妆图, 场景主镜图]`
- 何时不用主镜：首格自身、抽象隐喻帧、闪回帧

同步更新：`step2-storyboard.md` 分镜表新增场景组+场景主镜列，FRAME_REFS 配置示例升级为双参考图；`step3-review.md` 新增 §2.4 场景主镜记录表

**二、高光独占格**（`references/storyboard-guide.md` 新增 §选帧六原则 §7 高光独占格）：

- 原文高光时刻必须独占至少一格，禁止和多件事挤在同格
- 三种高光类型：反应型（情绪骤变→特写独占）/ 转折型（剧情逆转→大格独占）/ 震撼型（认知骤变→两格一抑一扬）
- 反例对比：三信息塞一格 → 三格递进各一焦点
- 独占格 ≠ 大格，关键是**信息独占**

**三、证据链**（`step1-director.md` §4 步骤3 关键信息审计表升级）：

- 审计表新增**来源段落**和**原文摘录（≤30字）**两列
- 每条关键信息必须追溯到具体原文段落，确保改编决策可审计
- 无法追溯到原文的信息标记为"原创改编"
- 导演卡门禁新增确认项：每条关键信息是否有原文来源

**四、改编灵魂**（`step1-director.md` §4 步骤1 新增改编灵魂环节）：

- 选帧前先用三问定调改编方向：
  - **灵魂冲突**：本章最核心的矛盾是什么（不是"发生了什么"而是"什么较量"）
  - **避开俗套**：最容易被画成什么烂俗画面，至少列 2 个要避开的套路
  - **求新钩子**：什么元素"只有漫画能表现，小说文字做不到"
- 后续所有改编策略必须服务灵魂冲突、避开俗套、发挥求新钩子
- 导演卡模板新增「改编灵魂」段落

**五、感染力评审**（`step3-review.md` §3 新增感染力评审）：

- 产出完整性检查通过后，进行五维结构性评审（DeepSeek 无视觉能力，通过提示词记录和分镜表做判断）：
  - **3秒焦点**：每帧缩到缩略图大小能否3秒看出主角/主动作/关键道具
  - **情绪钉子**：本章是否至少一格"读者滑过后会记住"的画面
  - **角色记忆点**：每个常驻角色是否有可区分的视觉记忆特征
  - **记忆句**：是否有一句准确、短、可复述、贴画面动作的句子
  - **扫描测试**：只看对白/旁白主句能否读出故事弧
- ⚠️ 记录不阻断，❌ 记录问题并在下章导演卡中针对性改进
- 评审结果写入视觉沉淀.md

将 Phase 1 从单 step 拆为双 step，实现改编决策与分镜生成的认知模式隔离。

**拆分动机**：v2.4.0 将改编分析作为 step1 内部的 §3.5 子环节，但改编分析（"读"的活）和选帧（"画"的活）挤在同一个 step 中，agent 容易跳过前者直奔后者。拆分后导演卡 step 唯一任务是"想清楚怎么改"，分镜 step 唯一任务是"怎么画"。

**Step 1: 漫画导演卡**（`steps/step1-director.md`，新建）：
- 读状态+角色库 → 读取原文 → 角色变化识别 → 漫画化改编分析 → 产出导演卡.md
- 导演卡含：章节概要 + 角色变化记录 + 关键信息审计表 + 改编策略表 + 转化帧设计 + 旁白文案 + 改编自检
- 🚪 门禁：导演卡确认（关键信息有没有漏 / 改编策略对不对 / 转化方案行不行）

**Step 2: 分镜生成**（`steps/step2-storyboard.md`，新建）：
- 读导演卡 → 增量定妆图（如有）→ 基于策略表拆分镜 → 🚪 门禁：分镜确认 → 逐格生成 → HTML组装+内联化
- 导演卡是选帧的唯一输入源，不重新做改编分析
- 直接选帧和视觉转化帧混合排列

**Step 3: 视觉审核**（`steps/step3-review.md`，原 step2-review 重命名）：
- 内容不变，更新文件引用和产出检查项（新增导演卡存在性检查）
- 审核完成后回到 Step 1（读 step1-director.md）

**门禁从1个变2个**：
- 旧：门禁A 同时审 改编分析+分镜+角色变化（三合一）
- 新：门禁1 审改编策略（导演卡），门禁2 审具体帧（分镜表）—— 先确认"怎么改"再确认"怎么画"

**导演卡作为独立产出物**：保存到 `第{N}章/导演卡.md`，可沉淀复用。后续如需重新生成画面，不用重做改编分析，直接读导演卡进入 Step 2。

**删除文件**：`steps/step1-chapter.md`（内容拆分到 step1-director + step2-storyboard）、`steps/step2-review.md`（重命名为 step3-review.md）

## v2.4.0 | 2026-07-31

### 漫画化改编SOP

解决"选帧 ≠ 改编"的核心问题：网文章节中大量内心独白、系统数值、世界观设定无法直接选帧，旧流程默认跳过导致漫画信息断崖。

**step1-chapter.md 新增 §3.5 漫画化改编分析**（选帧前必须完成）：

1. **内容分段标注** — 逐段标记为七种内容类型之一（动作/情感/对话/内心独白/系统数值/世界观设定/记忆闪回）
2. **关键信息审计** — 提取"丢失后后续剧情无法理解"的关键信息点，标注丢失后果
3. **逐条定改编策略** — 四种策略：直接选帧 / 视觉转化 / 旁白浓缩 / 砍掉
4. **转化方案设计** — 为视觉转化帧设计具体视觉手段（抽象隐喻/角色反应替代/旁白浓缩+象征画面/原创视觉插入）
5. **信息覆盖率自检** — 逐条核对每条关键信息是否都有对应呈现

**门禁A升级**：从"分镜+角色变化"二合一升级为"改编分析+分镜+角色变化"三合一确认，用户在选帧前可审查"这一章传达什么信息、每条怎么处理"。

**storyboard-guide.md 新增「改编策略：从文字到画面」章节**：

- 改编决策树（关键性判断 → 可画性判断 → 四种转化方案选择）
- 四种转化方案详解（方案A抽象视觉隐喻 / 方案B角色反应替代 / 方案C旁白浓缩+象征画面 / 方案D原创视觉插入），每种含适用条件、原文示例、转化画面、提示词要点
- 闪回与记忆的视觉区分手段（边框纹理/色调偏移/画中画/抽象背景）
- 改编自检清单（5项 checklist）

**根因分析**：R15 测试中第二章（原文为内心独白+系统数值密集章）漫画化后信息量断崖式下跌，读者不看原文无法理解"索伦为什么能醒过来"。旧 storyboard-guide 的"选帧六原则"全部是提取逻辑，缺少转化逻辑。

## v1.2.0 | 2026-07-29

### 修复（HTML 图片内联化）
- **根因**：popwave webview 安全策略禁止加载外部资源（相对路径、绝对路径、file:// 协议均被阻止），HTML 中 `<img src="output/frame1.png">` 在 popwave 中显示为图片损坏
- **验证过程**：相对路径 ❌ → 绝对路径 file:// ❌ → base64 内联 472KB ✅ → base64 内联 6.5MB ❌（文件过大无法打开）→ 压缩 base64 内联 ✅
- **修复**：新增 `scripts/inline_html.py` 脚本，将 HTML 中所有本地图片引用压缩为 base64 data URI（默认 800px 宽 + JPEG quality 65），使 HTML 完全自包含
- **新增铁律6**：HTML 必须内联图片，禁止交付含外部图片路径的 HTML
- **step2-generate.md** 新增 §4 HTML 图片内联化步骤（必须执行）和质量检查项

## v1.1.0 | 2026-07-29

### 修复（格式保真）
- **根因**：Seedream API 返回的 URL 资源实际为 JPEG（magic bytes `FF D8 FF`），但 `generate_storyboard.py` 以 `.png` 命名保存，导致扩展名与实际格式不符
- **现象**：浏览器做 MIME sniffing 能兼容显示，但 popwave webview（nosniff 模式）按扩展名校验 MIME，判定为图片损坏
- **修复**：新增 `ensure_png_format()` 函数，在图片下载后自动检测 magic bytes，若为 JPEG 内容则用 Pillow 转码为真 PNG
- **同步修复**：`pop-novel-visual/scripts/generate.py` 的 `download_file` 和 `save_base64_image` 两条路径（新增 `ensure_format_integrity()` 函数）
- **新增铁律5**：下载后格式保真
