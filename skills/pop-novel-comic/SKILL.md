# pop-novel-comic

> 网文漫画连载管线。DeepSeek 做编剧和项目管理（导演卡、拆分镜、管角色库、记状态），Seedream 做画师（高并发生成画面），HTML 做排版（Pillow 备选），Playwright 截长图。v3.1.0

## 这个 Skill 做什么

把长篇小说逐章变成漫画连载。通过**冻结提示词 + 定妆图持久化 + 分层记忆机制**，解决 DeepSeek 无视觉能力下的跨章人设/画风一致性问题。

输入：小说项目（含角色库.md / 正文 / 力量体系.md 等）
输出：每章一个 HTML 漫画页面（主要）+ 长图截图（分享用）+ 持久化的角色定妆库 + 连载状态管理文件

核心管线：**Phase 0 初始化**（一次性建角色库+定妆图）→ **Phase 1 导演卡+分镜生成**（循环，导演卡→分镜→生成→组装）→ **Phase 2 视觉审核**（记忆沉淀+状态更新）

## 怎么运作

### Phase 0: 项目初始化 → `steps/step0-init.md`（一次性）

- **优先读取 `素材/视觉资产/` 下的资产文件**（pop-novel-asset 产出）：角色档案→规格表、视觉符号库→画风推导、IP视觉DNA→IP背景、场景资产表→Phase 1分镜参考
- 资产缺失时回退到原流程（读取角色库.md/力量体系.md等设定文件）
- **§2.5 知名角色二创搜索**：知名网文角色搜索现有二创/官方插画，提取视觉共识特征回填规格表，下载参考图用于图生图
- **§3 画风选择**：从八大画风锚定池选取（Agent推荐→用户选→赛道微调），不再自由拼串
- 生成主角定妆图验证画风 → 继续生成全部角色定妆图（有参考图时用图生图模式）
- **🚪 门禁0：角色 + 画风双确认**（画风不对→调整风格串→重新生成；角色不对→调整规格→重新生成）
- 门禁0通过后才冻结：风格锚定串→漫画快照.md / 角色提示词→漫画角色库.md
- 创建四个记忆文件

### Phase 1 Step 1: 漫画导演卡 → `steps/step1-director.md`（循环）

- 读 漫画状态.md + 漫画角色库.md → 获取角色定妆图路径和冻结提示词
- 读小说正文 ch{NNN}.txt → **话数规划**（信息负载评估 → 轻/中/重分级 → 1话/拆分多话决策）
- **角色外观变化识别**（换装/受伤/变身等→计划增量定妆图）
- **漫画化改编分析（三层推导）**：
  - 故事层：改编灵魂三问 → 叙事主线设计（一句话故事+因果链+主副线+读者理解路径+**情感曲线**）→ 内容分段 → 关键信息审计（S/A/B分级）→ 改编策略 → 转化方案
  - 页层：**页面布局设计**（情感转折点→页面分割→每页功能位/视觉重心/情绪基调/格数预算/页间衔接）
  - 格层：**分格设计**（信息级别→格子大小，页面节奏→格子排列，布局选择决策树→分格设计表）
- 产出 **导演卡.md**（话数规划+章节概要+叙事主线+情感曲线+改编灵魂+角色变化+关键信息审计表+改编策略表+转化帧设计+旁白文案+**页面设计表+分格设计表**）
- **🚪 门禁：导演卡确认**（话数规划 / 叙事主线+情感曲线 / 改编灵魂 / 关键信息+分级 / 改编策略 / 转化方案 / **页面布局** / **分格设计**）

### Phase 1 Step 2: 分镜生成 → `steps/step2-storyboard.md`（循环）

- 读导演卡 → **继承分格设计表**的布局类/节奏/效果类，补充画面提示词/定妆图版本/场景主镜/对白文字 → 形成分镜脚本表
- 增量定妆图生成（如有变化）→ **高并发生成**（ThreadPoolExecutor 8线程，16帧~20秒）按帧映射角色定妆图+场景主镜生成画面（同场景首格成为主镜，后续帧引用锁定空间/光源/材质）
- **🚪 门禁：分镜+角色变化确认**（帧选得对不对）
- **漫画 HTML 排版**（按页面设计表分割+按分格设计表布局类排版，嵌入原文旁白，输出 HTML 漫画页面；Pillow 拼图为备选方案）
- **截长图**（Playwright 逐元素截图+Pillow 拼接，输出分享用长图 PNG/JPEG）
- 完成后自动进入 Phase 2

### Phase 2: 视觉审核+记忆沉淀 → `steps/step3-review.md`（每章生成后）

- 检查产出完整性（帧数、格式、HTML 漫画页面/JPEG 长图）
- **感染力评审**（五维：3秒焦点/情绪钉子/角色记忆点/记忆句/扫描测试）
- 记录本章视觉决策（定妆图版本+场景主镜记录+有无增量）
- append 视觉沉淀.md（问题+规则，永不删改历史）
- 更新 漫画快照.md（章节清单+角色出场记录）
- 更新 漫画状态.md（下一章角色状态+注意事项）

## 记忆机制

| 文件 | 层级 | 更新方式 | 作用 |
|:-----|:-----|:---------|:-----|
| `漫画角色库.md` | 长期 | 增量更新 | 角色规格表+冻结提示词+定妆图资产+决策日志 |
| `漫画快照.md` | 中期 | replace | 章节清单+风格锚定串+角色出场记录 |
| `漫画状态.md` | 短期 | replace | 当前章位+角色状态+上章问题+注意事项 |
| `视觉沉淀.md` | 审稿 | append-only | 每章一致性判断+问题记录+改进规则 |

> 漫画角色库.md 的每个角色含四层结构：规格表（人读）→ 冻结提示词（API读，真相源）→ 定妆图资产（版本管理）→ 决策日志（append-only）。

## 产出文件结构

```
{小说项目}/漫画/
├── assets/characters/           # 定妆图持久化（跨章复用）
│   ├── char-{名}-v1.png
│   └── char-{名}-v2.png         # 角色变化后的增量版
├── 漫画角色库.md                  # 长期记忆
├── 漫画快照.md                    # 中期记忆
├── 漫画状态.md                    # 短期记忆
├── 视觉沉淀.md                    # 审稿记忆
├── 第1章/
│   ├── 导演卡.md                # Step 1 产出（改编决策记录）
│   ├── storyboard.md
│   ├── 拼图配置.json             # Step 2 排版配置（帧布局+旁白+样式）
│   ├── output/frame1~N.png      # 帧数不固定，按章节内容决定
│   ├── index.html               # HTML 漫画页面（主要产出，外部图片引用+原文旁白嵌入）
│   ├── 漫画-{章节名}.jpg         # 漫画长图（Pillow 备选方案产出）
│   └── 长图-{章节名}.png         # 截长图（Playwright 逐元素截图+拼接，分享用）
└── 第2章/...
```

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **冻结提示词是角色一致性唯一真相源** — 角色定妆图生成后，提示词立即冻结到漫画角色库.md。后续章节直接引用冻结版，禁止重新从规格表组装提示词。角色外观变化时基于冻结版+变化描述生成新版本，新提示词同样冻结 | 跨章角色漂移，同一角色画出不同的人 |
| ❌2 | **HTML 排版必须覆盖所有帧 + 排版避让铁律** — `index.html` 必须包含分镜脚本表的全部帧，不得遗漏。每帧的布局类必须与分格设计表一一对应。clip-path 斜切线只能穿过画面空白区，旁白文字不能放在被裁切区域内，斜切无叙事必要性时用垂直分格替代（详见 `references/layout-pool.md` 排版避让铁律） | 帧遗漏导致剧情断裂，布局类不匹配导致排版错乱，斜切穿过人物/文字导致画面残缺 |
| ❌3 | **每章生成后必须走 Phase 2 审核** — 更新记忆文件（角色库/快照/状态/沉淀），不得连续生成两章不审核 | 记忆断裂，下章不知道上章角色外观变化和视觉问题 |
| ❌4 | **定妆图持久化在 assets/characters/** — 定妆图存放在项目级 `assets/characters/` 目录，不放章节 `output/` 下。跨章复用，版本递增 | 定妆图随章节散落，无法跨章复用，每章重新生成导致角色不一致 |

## 前置条件

1. Python 3.8+ + Pillow（图片转码/压缩/拼图）
2. 浏览器 + Python http.server（HTML 漫画页面预览，主要产出格式）
3. Playwright（截长图，可选：`pip install playwright && playwright install chromium`）
4. `ARK_API_KEY` 环境变量（火山引擎方舟 API Key）
5. 小说项目已存在（含角色库.md 或 主角设计.md）
6. 输出目录可写
