# pop-novel-comic

> 网文漫画连载管线。DeepSeek 做编剧和项目管理（导演卡、页面设计、管角色库、记状态），Seedream 做画师（直出多格漫画页），HTML 做翻页阅读器+文字叠加层。v4.3.0

## 这个 Skill 做什么

把长篇小说逐章变成漫画连载。通过 **Seedream 直出多格漫画页 + 冻结提示词 + 定妆图持久化 + 分层记忆机制**，解决 DeepSeek 无视觉能力下的跨章人设/画风一致性问题。

**v4.0 核心变化**：生成单位从"格"升级为"页"。Seedream 在单张图内直出完整漫画页（含分格线、多格内容、镜头语言），HTML 做翻页阅读器+文字叠加层（旁白条/对白气泡）。画面是 AI 画的，文字是 HTML 叠的——各司其职。**v4.3 翻页阅读器**：一次只显示一页，点击/滑动/方向键切换。

输入：小说项目（含角色库.md / 正文 / 力量体系.md 等）
输出：每章多页漫画（Seedream 直出 page1~N.png）+ HTML 文字叠加页面 + 长图截图 + 持久化的角色定妆库 + 连载状态管理文件

核心管线：**Phase 0 初始化**（一次性建角色库+定妆图）→ **Phase 1 导演卡+页面生成**（循环，导演卡→页面提示词→直出生成→文字叠加）→ **Phase 2 视觉审核**（记忆沉淀+状态更新）

## 怎么运作

### Phase 0: 项目初始化 → `steps/step0-init.md`（一次性）

- **优先读取 `素材/视觉资产/` 下的资产文件**（pop-novel-asset 产出）
- 资产缺失时回退到原流程（读取角色库.md/力量体系.md等设定文件）
- **§2.5 知名角色二创搜索**：搜索现有二创/官方插画，提取视觉共识特征
- **§3 画风选择**：从八大画风锚定池选取
- 生成主角定妆图验证画风 → 继续生成全部角色定妆图
- **🚪 门禁0：角色 + 画风双确认**
- 门禁0通过后冻结：风格锚定串→漫画快照.md / 角色提示词→漫画角色库.md
- 创建四个记忆文件

### Phase 1 Step 1: 漫画导演卡 → `steps/step1-director.md`（循环）

- 读 漫画状态.md + 漫画角色库.md → 获取角色定妆图路径和冻结提示词
- 读小说正文 ch{NNN}.txt → **话数规划**（信息负载评估 → 轻/中/重分级 → 1话/拆分多话决策）
- **角色外观变化识别**（换装/受伤/变身等→计划增量定妆图）
- **漫画化改编分析（两层推导）**：
  - 故事层：改编灵魂三问 → 叙事主线设计（一句话故事+因果链+主副线+读者理解路径+情感曲线）→ 内容分段 → 关键信息审计（S/A/B分级）→ 改编策略 → 转化方案
  - 页层：**页面设计**（情感转折点→页面分割→每页功能位/格数/格布局/每格内容概述/视觉重心/旁白文字/页间衔接）
- **高光设计**（高光独占页 + 名场面识别 + 张力构建 + 冲击帧提示词方向）
- **文化元素设计**（可选，古风赛道：定场诗/印章/版式线/小篆题字规划）
- 产出 **导演卡.md**（话数规划+章节概要+叙事主线+情感曲线+改编灵魂+角色变化+关键信息审计表+改编策略表+转化帧设计+旁白文案+**页面设计表**+高光设计+文化元素设计）
- **🚪 门禁：导演卡确认**

### Phase 1 Step 2a: 页面提示词设计 → `steps/step2a-storyboard.md`（循环）

- 读导演卡 → **继承页面设计表**的格数/格布局/每格内容/视觉重心，组装页面级提示词 → 形成分镜脚本表
- **页面级提示词**：一个提示词描述一整页（含所有格子），Seedream 一次直出完整漫画页
- **提示词持久化到 storyboard.md**（作为真相源）
- **🚪 门禁：页面提示词确认**

### Phase 1 Step 2b: 页面生成+文字叠加 → `steps/step2b-production.md`（循环）

- 增量定妆图生成（如有变化）→ **逐页生成**（调用 `generate_comic_page.py`，每页带角色定妆图参考）
- **翻页阅读器 HTML**（在漫画页图片上叠加旁白条/对白气泡，生成翻页阅读器 index.html）
- **截图分享**（Playwright 逐页截图+Pillow 拼接，输出分享用长图，可选）
- 完成后自动进入 Phase 2

### Phase 2: 视觉审核+记忆沉淀 → `steps/step3-review.md`（每章生成后）

- 检查产出完整性（页数、格式、HTML 漫画页面/长图）
- **感染力评审**（五维：3秒焦点/情绪钉子/角色记忆点/记忆句/扫描测试）
- 记录本章视觉决策（定妆图版本+角色出场记录+有无增量）
- append 视觉沉淀.md（问题+规则，永不删改历史）
- 更新 漫画快照.md + 漫画状态.md

## 记忆机制

| 文件 | 层级 | 更新方式 | 作用 |
|:-----|:-----|:---------|:-----|
| `漫画角色库.md` | 长期 | 增量更新 | 角色规格表+冻结提示词+定妆图资产+决策日志 |
| `漫画快照.md` | 中期 | replace | 章节清单+风格锚定串+角色出场记录 |
| `漫画状态.md` | 短期 | replace | 当前章位+角色状态+上章问题+注意事项 |
| `视觉沉淀.md` | 审稿 | append-only | 每章一致性判断+问题记录+改进规则 |

> 漫画角色库.md 的每个角色含四层结构：规格表（人读）→ 冻结提示词（API读，真相源）→ 定妆图资产（版本管理）→ 决策日志（append-only）。

## 产出文件结构

```
{小说项目}/漫画/
├── assets/characters/           # 定妆图持久化（跨章复用）
│   ├── char-{名}-v1.png
│   └── char-{名}-v2.png         # 角色变化后的增量版
├── 漫画角色库.md                  # 长期记忆
├── 漫画快照.md                    # 中期记忆
├── 漫画状态.md                    # 短期记忆
├── 视觉沉淀.md                    # 审稿记忆
├── 第1章/
│   ├── 导演卡.md                # Step 1 产出（改编决策+页面设计）
│   ├── storyboard.md            # Step 2a 产出（页面级提示词）
│   ├── 页面配置.json             # Step 2b 文字叠加配置
│   ├── output/page1~N.png      # 漫画页（Seedream 直出，每页含多格）
│   ├── index.html               # HTML 漫画页面（漫画页图+文字叠加）
│   └── 长图-{章节名}.png         # 截长图（Playwright 截图，分享用）
└── 第2章/...
```

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **冻结提示词是角色一致性唯一真相源** — 角色定妆图生成后，提示词立即冻结到漫画角色库.md。后续章节直接引用冻结版，禁止重新从规格表组装提示词。角色外观变化时基于冻结版+变化描述生成新版本，新提示词同样冻结 | 跨章角色漂移，同一角色画出不同的人 |
| ❌2 | **每页必须生成且有文字叠加** — `generate_comic_page.py` 必须为导演卡页面设计表的每一页生成漫画图。`index.html` 必须包含全部页面图片，且每页的文字叠加（旁白/对白）不得遗漏。文字叠加位置不得遮挡画面关键信息（人物面部/动作焦点） | 页面遗漏导致剧情断裂，文字缺失导致信息丢失 |
| ❌3 | **每章生成后必须走 Phase 2 审核** — 更新记忆文件（角色库/快照/状态/沉淀），不得连续生成两章不审核 | 记忆断裂，下章不知道上章角色外观变化和视觉问题 |
| ❌4 | **定妆图持久化在 assets/characters/** — 定妆图存放在项目级 `assets/characters/` 目录，不放章节 `output/` 下。跨章复用，版本递增 | 定妆图随章节散落，无法跨章复用，每章重新生成导致角色不一致 |

## 前置条件

1. Python 3.8+ + Pillow（图片转码/压缩/拼接）
2. 浏览器 + Python http.server（HTML 漫画页面预览）
3. Playwright（截长图，可选：`pip install playwright && playwright install chromium`）
4. `ARK_API_KEY` 环境变量（火山引擎方舟 API Key）
5. 小说项目已存在（含角色库.md 或 主角设计.md）
6. 输出目录可写
