# Step 0: 项目初始化

> 读取设定 → 推导画风 → 生成定妆图 → 门禁0(角色+画风双确认) → 冻结 → 创建记忆文件

## 设计哲学

Phase 0 是漫画连载的**一次性地基**。所有跨章一致性的根基在这里奠定：角色长什么样（定妆图）、怎么描述（冻结提示词）、全系列什么风格（风格锚定串）。

冻结提示词是核心——角色定妆图生成后，发给 API 的原始提示词立即冻结到角色库。后续所有章节直接引用这个冻结版，不再重新组装。这样 DeepSeek 即使没有视觉能力，也能通过"引用同一份文本指令"保证角色一致。

**画风不是从表里选一行字符串就定的**——风格锚定串必须通过定妆图的视觉效果验证后才能冻结。门禁0同时确认角色外观和画风，不通过则调整后重新生成。

## 0. 视觉资产检查（优先路径）

> 如果 `pop-novel-asset` 已提取过视觉资产，直接读取，跳过手动设定提取。

### 0.1 扫描资产目录

用 LS 扫描 `素材/视觉资产/` 目录：

| 资产文件 | 消费方式 | 替代的原流程 |
|:---------|:---------|:-------------|
| `[角色名]角色档案.md` | 读取10维度档案 → 直接提取维度二（外貌演变）和维度九（视觉设计参考）作为角色规格表依据 | §1 读取角色库.md + §2 手动提取规格表 |
| `视觉符号库.md` | 读取标志色+器物+意象 → 辅助 §3 画风推导的世界观特征维度 | §1 读取力量体系.md |
| `IP视觉DNA.md`（同人时） | 读取4维度DNA → 跳过 §1.1 IP背景检查的WebSearch | §1.1 IP背景检查 |
| `场景资产表.md` | 读取可定格帧清单 → Phase 1 拆分镜时参考已有帧评估 | Phase 1 从正文手动拆帧 |

### 0.2 资产完整性校验

- 角色档案：确认维度二（外貌演变）和维度九（视觉设计参考）有内容
- 视觉符号库：确认标志色和器物部分有内容
- 场景资产表：确认帧清单覆盖主要角色和关键场景
- 采样范围：检查文件头部"采样范围"标记，如过旧建议用户先运行 asset 增量更新

### 0.3 资产缺失时的回退

| 缺失资产 | 回退行为 |
|:---------|:---------|
| 角色档案不存在 | 走 §1 原流程（读取角色库.md + 正文提取规格表），提示用户可先运行 `pop-novel-asset` |
| 视觉符号库不存在 | 走 §1 原流程（读取力量体系.md），不影响核心流程 |
| IP视觉DNA不存在 | 走 §1.1 原流程（WebSearch搜索源IP） |
| 场景资产表不存在 | Phase 1 从正文手动拆帧（原流程） |

> **关键**：asset 产出的角色档案含10维度+行号索引，比从角色库.md提取更立体。有资产时优先用资产，无资产时回退到原流程。

## 1. 读取小说项目设定（无资产时回退路径）

> ⚠️ 如果 §0 已读取到资产文件，本节仅补充读取角色库.md的角色清单（确认哪些角色需要定妆图），规格表数据来自资产。

从小说项目读取以下文件（按优先级）：

| 文件 | 路径 | 用途 |
|:-----|:-----|:-----|
| 角色库.md | `设计/角色库.md` 或 `角色库.md` | 提取角色清单和视觉特征 |
| 主角设计.md | `设计/主角设计.md` | 主角详细设定 |
| 力量体系.md | `设计/力量体系.md` | 世界观风格参考 |
| 卷纲.md | `设计/第一卷剧情/卷纲.md` | 了解故事走向，预判角色变化 |
| ch001.txt | `正文/ch001.txt` | 无设定文件时，从正文提取 |

### 1.1 IP 背景检查（画风推导前必执行）

> ⚠️ 如果 §0 已读取 `IP视觉DNA.md`，跳过本节，直接使用资产中的IP视觉DNA。

**在推导画风之前，必须先判断小说是否基于已有 IP。** 同人/改编小说的画风推导需要参考源 IP 的视觉 DNA。

| IP 类型 | 识别信号 | 处理方式 |
|:---------|:---------|:---------|
| **同人** | 出现原著角色名、世界观术语、能力体系 | WebSearch 搜索源 IP 官方画风 → 提取视觉 DNA → 决定锚定或偏离 |
| **改编** | 书名或设定与已知 IP 高度重合 | 同上 |
| **原创** | 无原著角色名、无已知世界观 | 跳过，正常推导画风 |

> 详见 `../pop-novel-visual/references/novel-visual-design.md` §IP 背景理解。漏判 IP 背景会导致画风方向完全跑偏。

## 2. 提取角色视觉规格表

为每个重要角色建立视觉规格表。**必读 `references/char-consistency-guide.md`** 了解角色一致性管理方法论。

### 角色筛选标准

- 主角：必出定妆图
- 出场≥2章的配角：强制出定妆图
- 只出场1章的配角：不需要，在分镜提示词中描述即可

### 规格表格式

| 字段 | 说明 | 示例 |
|:-----|:-----|:-----|
| 角色名 | 原文中的称呼 | 索伦 |
| 年龄/性别 | 推断 | 18岁男性 |
| 体型 | 瘦弱/健壮/高大/矮小 | 瘦削，病后初愈 |
| 发色/发型 | 原文描述或推断 | 亚麻色短发，微乱 |
| 瞳色 | 原文描述或推断 | 黑色 |
| 服装 | 原文描述或推断 | 破旧亚麻衬衫，赤脚 |
| 标志性特征 | 疤痕/异色瞳/特殊道具 | 苍白面色，锁骨突出 |
| **视觉锚点串** | **面部+身体+服饰的具体识别标签** | **`short messy sandy hair, black eyes, pale skin, prominent collarbone, thin build, worn linen shirt, barefoot`** |

> **视觉锚点**是规格表的关键增量。锚点必须具体到位置、形状、颜色（见 storyboard-guide §角色一致性工艺包 §视觉锚点）。锚点串将在每帧提示词中强制继承，是角色一致性的第二道保险（第一道是冻结提示词+定妆图参考）。

## 2.5 知名角色二创搜索（关键步骤）

> 知名网文的角色在读者心中有共同的视觉记忆——官方插画、二创同人、读者社区共识。如果定妆图和这些记忆对不上，读者会觉得"不像"。

### 为什么需要这一步

Agent 只从文字描述生成定妆图，等于"闭门造车"。对于知名网文（如玄鉴仙族、诡秘之主、大奉打更人等），角色早有大量二创和官方视觉资产。**先搜索现有视觉参考，再基于参考图生成定妆图**，能大幅提升角色辨识度和读者认同感。

### 执行流程

#### 步骤 1：判断 IP 知名度

| 判断条件 | 处理 |
|:---------|:-----|
| 小说在起点/番茄等平台有 **万订/均订过万** 记录 | 执行二创搜索 |
| 小说有 **官方漫画/动画改编** | 执行二创搜索（优先取官方视觉） |
| 小说有 **大量读者二创**（搜得到角色名+同人/二创/插画） | 执行二创搜索 |
| 小说是 **冷门/新作/原创** | 跳过，走 §2 纯文字规格表生成 |

#### 步骤 2：逐角色搜索

对每个需要定妆图的角色，执行 WebSearch：

```
搜索关键词："{小说名} {角色名} 漫画 插画 二创"
搜索关键词："{角色名} 同人 绘画"（如角色名足够独特）
```

从搜索结果中筛选：
- **优先级 1**：官方插画/官方漫画截图（最权威）
- **优先级 2**：高赞二创同人图（读者共识）
- **优先级 3**：角色 cosplay（面部特征参考）

#### 步骤 3：提取视觉 DNA

从搜索到的参考图中提取**视觉共识特征**（多个来源都一致的特征 = 读者共同记忆）：

| 提取维度 | 示例（玄鉴仙族 李周巍） |
|:---------|:-----|
| 面部共识 | 金色重瞳、剑眉、冷峻面容 |
| 发型共识 | 黑色长发束起 |
| 服饰共识 | 乌金战甲、麒麟纹、白袍内衬 |
| 标志物共识 | 三尖两刃戟、天眼神光 |
| 读者印象关键词 | 霸王之姿、不怒自威 |

> 如果搜索结果中同一角色的视觉差异很大（没有共识），说明角色视觉记忆分散，此时以原文规格表为主，二创参考为辅。

#### 步骤 4：融合到规格表

将二创搜索提取的视觉共识特征**回填到 §2 的规格表**中：

- 二创共识与原文描述一致 → 确认规格表，标注"二创验证一致"
- 二创共识与原文描述有差异 → 以原文为准，但标注差异点供用户在门禁0决策
- 二创有原文未提及的视觉特征 → 补充到规格表（如"二创普遍画成左脸有疤"）

#### 步骤 5：下载参考图（可选）

如果搜索到高质量参考图，下载到 `assets/characters/refs/` 目录：

```
assets/characters/
├── refs/                    # 二创参考图（不用于直接生成，仅作图生图参考）
│   ├── ref-李周巍-official.jpg
│   └── ref-李周巍-fanart.jpg
├── char-李周巍-v1.png       # 基于参考图生成的定妆图
```

> 参考图用于**图生图模式**生成定妆图（pop-novel-visual 的模式 A/B），比纯文字描述更可靠。参考图不作为最终定妆图使用——最终定妆图仍需按画风锚定串重新生成，确保画风统一。

### 与 pop-novel-asset 的关系

如果 `素材/视觉资产/` 下已有 `[角色名]角色档案.md`（pop-novel-asset 产出），其中维度九（视觉设计参考）可能已包含二创信息。此时：
- 资产文件有视觉参考 → 直接使用，跳过 WebSearch
- 资产文件无视觉参考 → 执行本步骤的 WebSearch 补充

> 二创搜索不是必须的——冷门/原创小说跳过此步骤，走纯文字规格表生成流程。但对知名 IP 小说，这一步能显著提升读者认同感。

## 3. 画风选择（从锚定池选取）

> **画风不是 agent 拼出来的，是用户选出来的。** **必读 `references/art-style-pool.md`** 了解八大主流画风。

画风选择分三步：推荐 → 用户选 → 赛道微调。

### 3.1 Agent 推荐画风

根据小说赛道，从 `references/art-style-pool.md` 的「赛道→画风快速映射」表中取首选和备选各 1 种，向用户呈现：

```
基于小说赛道【{赛道名}】，推荐以下画风：

1. {首选画风名} — 代表作：{代表作} — 推荐理由：{一句话}
2. {备选画风名} — 代表作：{代表作} — 推荐理由：{一句话}

您也可以选池中其他画风，或描述自定义风格。
```

### 3.2 用户选择

| 用户反馈 | 处理 |
|:---------|:-----|
| 选某画风 | 取该画风的锚定串 → 进入 §3.3 赛道微调 |
| 选某画风 + 修改意见 | 在锚定串基础上调整 → 进入 §3.3 赛道微调 |
| 描述自定义画风 | 按 art-style-pool §自定义画风 结构组装锚定串 → 进入 §3.3 赛道微调 |

### 3.3 赛道微调

在选定画风的锚定串末尾，根据小说具体内容追加**赛道微调修饰**（最多 2 个短句）：

- 色调修正：如暗黑奇幻有灶火场景 → `暖色火光点缀`
- 氛围修饰：如贫民窟设定 → `破败泥泞质感`
- 特效倾向：如修仙战斗多 → `剑光灵气特效密集`

> 微调是"在画风基础上加调料"，不是改画风。**微调修饰同时追加到锚定串和 Seedream 执行串末尾**。详见 `references/art-style-pool.md` §赛道微调。

### 3.4 推导示例

《玄鉴仙族》——修仙玄幻赛道 + 权谋战争基调：

```
推荐画风：国漫玄幻修仙厚涂风（代表作：《凡人修仙传》《沧元图》）

三字段（待赛道微调）：
锚定串：国漫玄幻修仙厚涂风格，毛笔感粗细变化线稿，华丽服饰金属玉石质感，高饱和法术发光特效，东方纹样，史诗仙侠氛围
Seedream 执行串：Chinese xianxia painterly manga style, brush-like variable-width lineart, ornate costumes with metal and jade material textures, high-saturation glowing magic effects with particle layers, dense Eastern ornamental patterns, epic xianxia atmosphere. Art style similar to Battle Through the Heavens manga
风格保真约束：Maintain brush-like variable-width lineart. Include Eastern ornamental patterns. Use high-saturation magic effects. No Western fantasy style. No flat cel-shading. No modern clothing elements.

赛道微调：+ 鎏金与墨色交织的权谋战争色调（追加到锚定串和 Seedream 执行串末尾）
```

> 此时的三字段是**待验证版**，尚未冻结。定妆图验证通过后才冻结。

## 4. 生成角色定妆图（兼画风验证）

定妆图同时承载两个验证目标：**角色外观对不对** + **画风效果好不好**。

### 定妆图提示词写法

定妆图是跨章一致性的基准，建议使用高精度模板（见 `../pop-novel-visual/references/seedream-prompt-guide.md` §1.10）。

**基础写法**（简单角色/速度优先）：
```
[Seedream 执行串(含赛道微调)]。一个[年龄]的[体型特征]角色，[发色/发型]，[瞳色]，穿[服装描述]，[标志性特征]。[表情]。全身立绘，纯色背景。[风格保真约束]。
```

**高精度写法**（主角定妆图/商业级质量）：
```
[Seedream 执行串(含赛道微调)]。

LOCKED COMPOSITION:
[镜头规格]：35mm镜头，平视，角色居中占画面75%
[角色外观]：年龄+种族+发型发色+眼瞳色+面部特征+皮肤质感+表情+服装逐层（外套→衬衫→腰带→裤子→靴子）+配饰
[角色动作]：每只手的具体动作 + 身体姿态
[背景]：纯色或简约背景

ENVIRONMENT AND LIGHTING:
[光源]：正面柔光为主 + 轮廓光
[渲染]：photorealistic materials, detailed fabric texture, individual hair strands, skin pores

HARD CONSTRAINTS:
[风格保真约束]
Exactly one character. No duplicated limbs. Exactly five fingers per hand. No chibi proportions.
```

> **定妆图是全系列基准，值得用高精度模板。** 主角定妆图强烈建议使用高精度写法，配角可用基础写法加速。

### 调用方式

```powershell
$env:ARK_API_KEY="{API_KEY}"
python "{pop-novel-visual路径}/scripts/generate.py" image `
  --prompt '{定妆提示词}' `
  --model doubao-seedream-5-0-lite-260128 `
  --size 1728x2304 `
  --output "{漫画项目}/assets/characters/char-{角色名}-v1.png"
```

### 生成顺序

1. 先生成**主角**定妆图（1张）——用最关键的角色验证画风
2. 看效果，如果画风明显不对 → 回 §3 调整风格串 → 重新生成
3. 画风OK → 继续生成其他角色定妆图

### 图生图模式（有二创参考图时）

如果 §2.5 下载了二创参考图，定妆图生成应使用**图生图模式**（pop-novel-visual 模式 A/B）：

```powershell
python "{pop-novel-visual路径}/scripts/generate.py" image `
  --prompt '{定妆提示词}' `
  --model doubao-seedream-5-0-lite-260128 `
  --size 1728x2304 `
  --image "data:image/png;base64,{二创参考图base64}" `
  --output "{漫画项目}/assets/characters/char-{角色名}-v1.png"
```

> 有参考图时用模式 A（全面参考，≤200字只改差异）或模式 B（画风参考，分离公式+4块结构）。详见 `../pop-novel-visual/references/seedream-prompt-guide.md` §参考图三模式。无参考图时走纯文生图（模式 C）。

## 5. 🚪 门禁0：角色 + 画风双确认

向用户呈现：

1. **画风选择**：选定的画风名 + 代表作 + 风格锚定串（含赛道微调）+ 推荐理由
2. **角色定妆图**（全部已生成的角色）
3. **角色视觉规格表**（全部角色的规格表，含二创验证标注）
4. **二创参考对照**（如执行了 §2.5）：每个角色的二创共识特征 vs 定妆图实际效果

### 用户决策分支

| 反馈 | 处理 |
|:-----|:-----|
| 角色OK，画风OK | → 进入 §6 冻结 |
| 画风不对 | → 回 §3 调整风格串 → 重新生成全部定妆图 → 再次门禁0 |
| 某个角色不对 | → 调整该角色的规格表/提示词 → 重新生成该角色定妆图 → 再次门禁0 |
| 增删角色 | → 补生成新角色定妆图 / 删除不需要的 → 再次门禁0 |

> **画风调整时必须重新生成全部已出的定妆图**——因为风格串变了，旧定妆图的画风就不统一了。

## 6. 冻结（门禁0通过后执行）

门禁0通过后，**一次性冻结所有基线资产**：

### 6.1 冻结风格三字段

将门禁0确认的三个字段写入 `漫画快照.md` 和 `漫画角色库.md` 顶部：
- **锚定串**（人读·画风概览）
- **Seedream 执行串**（API 读·分镜帧提示词开头用）
- **风格保真约束**（API 读·分镜帧提示词末尾用）

> 此后全系列冻结，不每章重推导。分镜帧组装时从角色库复制 Seedream 执行串和风格保真约束。

### 6.2 冻结角色提示词

将每个角色定妆图的完整提示词原文冻结到 `漫画角色库.md`。

> 冻结提示词 = 曾经发给 API 的原始文本（含 Seedream 执行串 + 角色描述 + 风格保真约束）。后续章节引用此文本，不重新组装。

### 6.3 创建记忆文件

使用模板创建四个记忆文件：

### 6.4 表情变体库（可选增强）

定妆图只有一张正面中性表情。如果主角在故事中有大量强情绪戏（战斗、哭泣、愤怒），可在 Phase 0 额外生成**表情变体**作为图生图参考，比纯文字微表情描述更可靠。

**详见 `references/storyboard-guide.md` §角色一致性工艺包 §表情变体库**，包含标准表情变体集（angry/sad/surprised/determined/fearful）、调用方式和存储规范。

执行策略：
- **主角**：建议生成 3 个核心变体（determined + angry + sad），覆盖大部分强情绪帧
- **配角**：不需要变体，Phase 1 用微表情描述即可
- 变体定妆图保存到 `assets/characters/char-{名}-{表情}-v1.png`，提示词冻结到角色库

> 表情变体不是必须的。微表情技法能解决 80% 的问题，变体库用于解决剩下 20% 的"图生图参考图不够准"的情况。是否生成由用户在门禁0时决定。

> Phase 0 完成后，进入 Phase 1 Step 1（读取 `steps/step1-director.md`）。
