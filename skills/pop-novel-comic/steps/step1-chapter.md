# Step 1: 单章生成

> 读状态+角色库 → 读取原文 → 角色变化识别 → **漫画化改编分析** → 拆分镜(弹性格数) → 门禁A → 增量定妆图(如有) → 逐格生成 → HTML组装+内联化

## 设计哲学

Phase 1 是循环执行的核心环节。每章生成都从读取记忆文件开始——漫画状态.md 告诉 Agent"上一章画到哪、角色有什么变化"，漫画角色库.md 提供"定妆图路径+冻结提示词"。

**角色一致性靠引用冻结提示词保证**，不靠重新组装。每帧的角色描述部分直接从角色库复制冻结提示词，加上场景动作描述和风格锚定串即可。

**角色是活的，定妆图也要跟着活。** 角色从贫民窟到穿上好衣服、从受伤到痊愈、从觉醒到变身——每个外观变化节点都要生成增量定妆图。变化识别在拆分镜之前完成，这样分镜表才能标注正确的定妆图版本。

**格数不锁死。** 一章内容有多少值得画的场面，就拆多少格。Agent 根据章节内容密度自主判断，不被固定数字束缚。

**漫画是再创作，不是翻译。** 网文原文中大量内容是内心独白、系统数值、世界观设定——这些无法直接"选帧"画出来。选帧前必须先做改编分析：识别内容类型、审计关键信息、为每条信息确定改编策略（直接选帧/视觉转化/旁白浓缩/砍掉），确保读者只看漫画也能理解核心剧情。

## 1. 读取记忆文件

### 必读文件

| 文件 | 读什么 |
|:-----|:-------|
| 漫画状态.md | 当前章位、角色外观变化、上一章视觉问题、本章注意事项 |
| 漫画角色库.md | 所有角色的定妆图路径（`assets/characters/char-{名}-v{N}.png`）和冻结提示词 |
| 漫画快照.md | 风格锚定串（全系列冻结）、已生成章节清单 |

### 角色定妆图版本选择

读角色库的定妆图资产表，选择每个角色的**最新版本**。如果状态文件标注了角色在本章有外观变化，在步骤 3 处理增量定妆图。

## 2. 读取章节原文

读取用户指定的章节文件：
- `正文/ch{NNN}.txt` 或 `正文/ch{NNN}.md`

## 3. 角色外观变化识别（拆分镜前执行）

**先识别变化，再拆分镜**——因为分镜表需要标注每帧用的是哪个版本的定妆图。

### 识别流程

1. 通读本章原文，对比角色库中每个角色的当前版本规格表
2. 找出本章中角色外观发生变化的所有节点

### 变化类型清单

| 变化类型 | 示例 | 是否需要增量定妆图 |
|:---------|:-----|:-----------------|
| 换装 | 贫民窟破衣 → 贵族华服 | ✅ 必须增量 |
| 受伤/疤痕 | 战斗后脸上留疤 | ✅ 必须增量 |
| 变身/形态变化 | 觉醒后瞳色变金 | ✅ 必须增量 |
| 年龄跳变 | 时间线跳跃数年 | ✅ 必须增量 |
| 装备变化 | 获得武器/防具 | ✅ 必须增量 |
| 临时状态（脏污/淋湿） | 雨中行走后湿透 | ❌ 不增量，分镜提示词中描述 |
| 表情/姿态变化 | 从恐惧到愤怒 | ❌ 不增量，分镜提示词中描述 |

### 变化记录表

将识别到的变化整理成表（供门禁A确认）：

| 角色 | 变化节点 | 变化描述 | 当前版本 | 新版本 | 变化类型 |
|:-----|:---------|:---------|:---------|:-------|:---------|
| 薇薇安 | 本章中段换装 | 从破旧麻布衣换成白色连衣裙 | v1 | v2 | 换装 |
| 索伦 | 本章末尾觉醒 | 瞳色从黑变金，背部出现纹路 | v1 | v2 | 变身 |

> 无变化的章节跳过角色变化识别，但 **§3.5 改编分析不可跳过**。

## 3.5 漫画化改编分析

> 选帧前必须完成的改编决策环节。**参考 `references/storyboard-guide.md` 的「改编策略」章节**了解方法论。

网文章节天然混合多种内容类型：动作场面可以直接画，但内心独白、系统数值、世界观设定无法直接选帧。如果只"选帧"不"改编"，这些内容会被无声跳过，导致漫画信息断崖。

本环节的目标：**确保读者只看漫画也能理解本章核心剧情。**

### 步骤 1：内容分段标注

通读原文，将章节内容按段落标记为以下七种类型之一：

| 内容类型 | 定义 | 典型特征 |
|:---------|:-----|:---------|
| 动作场面 | 角色有物理位移/对抗 | 打斗、追逐、逃亡 |
| 情感场景 | 角色情绪外化、有互动 | 哭泣、拥抱、对视 |
| 对话场景 | 角色间语言交流 | 威胁、争吵、告白 |
| 内心独白 | 角色心理活动、无外部动作 | "我要醒过来"、挣扎、决心 |
| 系统/数值 | 游戏面板、属性、技能描述 | 属性表、经验值、技能说明 |
| 世界观设定 | 背景/历史/规则描述 | 诸神之战、脑域开发、势力格局 |
| 记忆/闪回 | 非当前时间线的画面 | 前世记忆、巫师攻击、童年回溯 |

### 步骤 2：关键信息审计

从标注的内容中提取**读者必须理解的关键信息点**——不是所有内容都关键，只提取"如果丢失，后续剧情无法理解"的信息。

逐条列出，形成审计表：

| # | 关键信息 | 来源段落 | 内容类型 | 丢失后果 |
|:-:|:---------|:---------|:---------|:---------|
| 1 | 索伦是穿越者，前世在虚拟游戏中出意外 | ch002 §2 | 内心独白 | 读者不知道他为何有游戏系统 |
| 2 | 数据流融入大脑，这是他能醒来的原因 | ch002 §2-3 | 系统/数值 | 读者不知道他怎么醒的 |
| 3 | 原身主动放弃意识让穿越者接管 | ch002 §3 | 内心独白 | 读者不理解人格融合 |
| 4 | 希斯老死后安详离世 | ch002 §5 | 情感场景 | 读者错过核心情感点 |

> **判断标准**：遮掉这条信息后，读者还能理解后续剧情吗？能 → 非关键，可砍；不能 → 关键，必须呈现。

### 步骤 3：逐条定改编策略

对每条关键信息，确定处理方式：

| 策略 | 适用条件 | 执行方式 |
|:-----|:---------|:---------|
| **直接选帧** | 信息本身有视觉化场面（动作/情感/对话） | 进入分镜表，标注为正常帧 |
| **视觉转化** | 信息关键但无直接画面（独白/系统/设定） | 设计视觉隐喻或替代画面（见下方转化方案库） |
| **旁白浓缩** | 信息量大但视觉化成本过高 | 用 1-2 句旁白框概括，搭配象征性/反应画面 |
| **砍掉** | 非关键信息，不影响剧情理解 | 直接跳过 |

形成策略表：

| # | 关键信息 | 改编策略 | 转化方案（如需） |
|:-:|:---------|:---------|:---------------|
| 1 | 索伦是穿越者 | 视觉转化 | 画面：意识空间中两个半透明身影重叠融合，一个消散一个留存 |
| 2 | 数据流融入大脑 | 视觉转化 | 画面：数字雨0/1从头顶倾泻注入身体，体内电路纹路亮起 |
| 3 | 原身放弃意识 | 旁白浓缩 | 旁白框："他放弃了自己，把身体留给了另一个人。" 画面：一只手伸向另一只手后消散 |
| 4 | 希斯之死 | 直接选帧 | 正常分镜帧 |

### 步骤 4：转化方案设计

对策略为"视觉转化"的信息，设计具体视觉手段。**详见 `references/storyboard-guide.md` 的「转化方案库」**。

核心原则：
- **抽象内容具象化**：内心独白 → 角色在象征性空间中的动作（意识空间行走、灵魂对峙）
- **系统内容视觉化**：属性面板 → 半透明 UI 叠层浮现于角色眼前（不画完整数值，画"界面出现"这个瞬间）
- **设定内容场景化**：世界观 dump → 用一个宏大的视觉奇观承载（末日异象、历史壁画、地图标注）
- **闪回内容区分化**：非当前时间线 → 用边框纹理/色调偏移/画中画等手段与主线区分

> 转化帧同样进入分镜表，在"画面提示词"列中写明转化设计。

### 步骤 5：信息覆盖率自检

将策略表与审计表逐条核对：

- 每条关键信息是否都有对应的改编策略？
- 策略为"视觉转化"的信息，转化方案是否具体到可以写提示词？
- 策略为"旁白浓缩"的信息，旁白文字是否已拟好？

**自检通过后**，将直接选帧 + 视觉转化 + 旁白浓缩的条目整合为分镜序列，进入 §4。

> **改编分析表和策略表纳入门禁A呈现**，让用户确认"这一章传达什么信息、每条怎么处理"，而不只是"选了这几帧"。

## 4. 拆分镜脚本

基于 §3.5 的改编分析结果拆出分镜序列。**参考 `references/storyboard-guide.md`** 了解选帧方法论和转化方案库。

### 格数由内容决定，不锁死

Agent 根据章节内容自主判断格数：

- **内容密集章**（多场战斗/多线交织/大量信息揭示）：10-15格
- **标准章节**（有起承转合，3-5个情绪转折）：6-8格
- **过渡章**（日常/铺垫为主，情绪平稳）：4-6格
- **高潮章**（大事件密集爆发）：可到15-20格，分多页呈现

判断标准：**每个值得"看到"的瞬间都该有独立分镜。** 如果一章有8个该画的场面就画8格，有15个就画15格。宁可多画不可漏画——漏掉关键场面比多画几格更影响阅读体验。

### 分镜脚本表格式

每帧必须标注出场角色和对应的定妆图版本（含本章增量版本）：

| 帧号 | 场景 | 角色动作 | 机位 | 情绪 | 出场角色 | 定妆图版本 | 对白/文字 | 画面提示词 |
|:-----|:-----|:---------|:-----|:-----|:---------|:-----------|:---------|:-----------|
| 1 | 破屋，雨夜 | 薇薇安从米袋抓米 | 全景 | 压抑 | 薇薇安 | char-vivian-v1 | 旁白:没有食物了 | [提示词] |
| 2 | 破屋灶台 | 薇薇安抱老狗 | 中近景 | 温暖 | 薇薇安 | char-vivian-v1 | 对白:又不会偷东西 | [提示词] |
| 5 | 集市 | 薇薇安穿新衣出行 | 中景 | 明亮 | 薇薇安 | char-vivian-v2 | 旁白:第一次穿上干净的衣裳 | [提示词] |

> 注意帧5标注的是 v2——因为本章中段薇薇安换装，v2 是 §3 识别的增量版本。

### 提示词组装规则

每格提示词结构：

```
[冻结提示词中的角色描述部分] + [角色动作描述] + [场景环境描述] + [风格锚定串] + 画面底部中央融入 "popwave" 品牌签名，半透明无衬线小字。
```

**关键**：角色描述部分**从角色库的冻结提示词直接复制**，不重新组装。只追加场景和动作描述。

如果本章有增量定妆图（§3 识别的变化），变化后的帧使用新版本的冻结提示词。

### 关键帧高精度模板（可选）

**高潮帧、变身帧、名场面**等需要最高质量的帧，可使用高精度模板（见 `../pop-novel-visual/references/seedream-prompt-guide.md` §1.10）。将基础提示词结构升级为 4 块结构（LOCKED COMPOSITION / ENVIRONMENT AND LIGHTING / HARD CONSTRAINTS），加入镜头规格和硬约束。

判断标准：
- 这帧是否值得读者停留 3 秒以上看细节？→ 是 → 用高精度模板
- 这帧是否有复杂动作/特效/多角色交互？→ 是 → 用高精度模板
- 普通对话帧/过渡帧 → 用基础提示词，速度优先

示例（索伦觉醒后帧）：
```
# 从角色库复制的 v2 冻结提示词角色描述（觉醒后）：
一个18岁的瘦削男性角色，亚麻色短发微乱，金色眼眸（觉醒后），穿破旧亚麻衬衫，苍白面色，背部隐约可见金色纹路。
# 追加的场景和动作：
年轻男子站在废墟中，金色眼眸首次绽放光芒，周围碎石悬浮。
# 追加的风格锚定串：
暗黑奇幻半写实日式漫画风格，水彩质感笔触，灰暗色调被金光撕裂，觉醒的震撼氛围。
```

> 无角色帧（纯环境/特写）不需要参考图和角色描述，直接写场景提示词 + 风格锚定串。

## 5. 🚪 门禁A：改编分析+分镜+角色变化确认

向用户呈现：

1. **改编分析表**（§3.5 产出）—— 本章关键信息清单 + 每条信息的改编策略 + 转化方案
2. **角色变化记录表**（如有变化）—— 列出本章识别到的所有角色外观变化和增量定妆图计划
3. **分镜脚本表**（含每帧的出场角色+定妆图版本+格数）—— 直接选帧和视觉转化帧混合排列

用户确认后继续。如用户认为格数过多/过少或变化识别有误，调整后再次门禁A。

## 6. 增量定妆图生成（如有变化）

执行 §3 识别、§5 确认的增量定妆图生成：

1. 基于角色的当前版本冻结提示词 + 变化描述，组装新提示词
2. 调用 `scripts/update_char_asset.py` 生成新版本定妆图
3. 新定妆图保存到 `assets/characters/char-{名}-v{N+1}.png`
4. **新提示词冻结到角色库**（作为 v{N+1} 的冻结提示词）
5. 记录到角色库的增量定妆表和决策日志

```powershell
python "{本skill路径}/scripts/update_char_asset.py" `
  --char-name "{角色名}" `
  --version {N+1} `
  --base-prompt "{当前版本冻结提示词}" `
  --change-desc "{变化描述}" `
  --output "{漫画项目}/assets/characters/char-{名}-v{N+1}.png"
```

> 无变化的章节跳过此步骤。

## 7. 逐格分镜生成

### 批量生成（推荐）

配置 `generate_storyboard.py` 的 `FRAMES` 列表和 `FRAME_REFS`（按帧映射角色参考图）：

```python
# 按帧映射角色定妆图（支持同一角色不同版本）
FRAME_REFS = {
    "frame1": "char-vivian-v1.png",    # 换装前
    "frame2": "char-vivian-v1.png",    # 换装前
    "frame3": "char-vivian-v1.png",    # 换装前
    "frame4": "char-vivian-v2.png",    # 换装后，用新版本定妆图
    "frame5": "char-vivian-v2.png",    # 换装后
    "frame6": None,                     # 无角色帧
    "frame7": "char-soren-v1.png",     # 索伦觉醒前
    "frame8": "char-soren-v2.png",     # 索伦觉醒后
    # ... 格数不限于8，按实际分镜数量配置
}
```

```powershell
$env:ARK_API_KEY="{API_KEY}"
python "{本skill路径}/scripts/generate_storyboard.py"
```

### 单格生成

```powershell
python "{pop-novel-visual路径}/scripts/generate.py" image `
  --prompt '{分镜提示词}' `
  --model doubao-seedream-5-0-lite-260128 `
  --size 1728x2304 `
  --image "data:image/png;base64,{角色定妆图base64}" `
  --output "第{N}章/output/frame{N}.png"
```

## 8. HTML 漫画页组装

读取 `templates/comic-page.tpl.html`，替换占位符，组装漫画页面。

详见模板文件中的占位符说明。布局原则：Grid 2列，全宽格和半宽格交替。对白气泡用 CSS 定位叠加。

**格数超过8格时**：在模板基础上追加 `<div class="panel">` 节点即可。模板中的8帧结构是示例，不是上限。超过12格时考虑分页（生成两个HTML文件）。

输出到 `{漫画项目}/第{N}章/漫画-{章节名}.html`

## 9. HTML 图片内联化（必须执行）

```powershell
python "{本skill路径}/scripts/inline_html.py" "{漫画项目}/第{N}章/漫画-{章节名}.html"
```

> 内联化后 HTML 在浏览器和 popwave 中均能正常显示。
