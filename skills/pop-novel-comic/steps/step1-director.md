# Step 1: 漫画导演卡

> 读状态+角色库 → 读取原文 → **话数规划** → 角色变化识别 → 漫画化改编分析（故事层→页层→格层）→ 产出导演卡 → 🚪门禁确认

## 设计哲学

导演卡是选帧前的**改编决策环节**。它的唯一任务是回答："这一话要讲什么故事、分几页、每页怎么布局、每格画什么？"

**漫画是再创作，不是翻译。** 网文原文中大量内容是内心独白、系统数值、世界观设定——这些无法直接"选帧"画出来。选帧前必须先做改编分析：识别内容类型、审计关键信息、为每条信息确定改编策略（直接选帧/视觉转化/旁白浓缩/砍掉），确保读者只看漫画也能理解核心剧情。

**三层推导：故事→页面→格子。** 漫画不是帧的堆砌，是页的组织。先想清楚"这一话讲什么故事"（故事层），再推导"分几页、每页做什么"（页层），最后设计"每格画什么、多大、怎么排"（格层）。**布局服务于叙事，不为动态而动态**——每个布局选择必须有叙事理由。

**改编和选帧是两种认知模式。** 改编分析是"读"的活——深度阅读原文、分类、审计信息、做策略决策。选帧是"画"的活——视觉化想象、写提示词、排机位节奏。分开两个 step，让导演卡专注"想清楚怎么改+怎么布局"，选帧 step 专注"怎么画"。

**导演卡可沉淀。** 产出物是一份独立文件，记录本章的改编决策和布局设计全貌。后续如需重新生成画面，不用重做改编分析，直接读导演卡进入选帧。

## 2.5 话数规划

> **一话漫画的容量是有限的。** 网文一章 3000-5000 字，信息密度差异极大——日常铺垫章可能 4 格就够，多线战争章可能 20 格都塞不下。如果不评估信息负载就直接开做，要么信息超载（读者看不懂），要么格数爆炸（节奏稀烂）。

### 信息负载评估

通读原文后，统计以下四项指标：

| 指标 | 统计方式 | 示例（玄鉴仙族 ch1122+1395） |
|:-----|:---------|:--------------------------|
| 关键信息数 | 初步提取"丢了看不懂后续"的信息点 | 9 条 |
| 场景数 | 统计不同地点/时间的场景切换 | 7 个（望月湖/大西塬/云海/寻阳池/阁楼/剑门山/金一山） |
| 出场角色数 | 统计有名字且说话/行动的角色 | 7 个（李周巍/李曦明/蜀帝/天霍/程郇之/庆济方/上官游） |
| 故事线数 | 统计独立并行的主要情节线 | 2 条（魏王密议线 + 剑仙出关线） |

### 负载分级与话数决策

| 总负载 | 判定条件 | 话数决策 | 每话格数预算 |
|:------|:--------|:--------|:----------|
| **轻** | ≤5 信息 + ≤3 场景 + ≤4 角色 + 1 故事线 | 1 话 | 6-8 格 |
| **中** | 6-8 信息 + 4-5 场景 + 5-6 角色 + 1-2 故事线 | 1 话（需精选） | 8-12 格 |
| **重** | ≥9 信息 + ≥6 场景 + ≥7 角色 + ≥2 故事线 | **拆分为 2+ 话** | 每话 8-12 格 |

> **拆分触发线**：四项指标中**任意两项**达到"重"级别 → 拆分。不要求全部达标——7 个场景 + 2 条故事线就已经该拆了，即使信息数只有 7 条。

### 拆分原则

当判定需要拆分时，按以下原则切分：

| 原则 | 说明 | 示例 |
|:-----|:-----|:-----|
| **按故事线切** | 不同 POV/地点的并行线各自独立成话 | 魏王线(ch1122)→第1话 / 剑仙线(ch1395)→第2话 |
| **按因果断裂点切** | 找到"起因→发展"或"发展→决策"之间的自然停顿 | 密议结束=第1话结尾 / 剑仙出关=第2话开头 |
| **每话有完整弧线** | 拆出的话必须有起因→发展→决策→后果，不能只有"上半场" | 第1话：定策（有决策有后果=金卷）；第2话：应伐（有决策=应下+后果=密令送达） |
| **保留钩子衔接** | 前一话的结尾钩子指向后一话的开头 | 第1话结尾：金卷展开"擒主焚庙"→第2话开头：剑仙出关 |

### 拆分后的执行流程

拆分为多话时，**每话独立走完整的 Step 1 → Step 2 → Step 3 流程**：

```
第1话：§2.5 判定拆分 → 定义第1话范围 → §3 角色变化 → §4 改编分析 → 导演卡1 → Step 2 分镜 → Step 3 审核
第2话：§2.5 判定拆分 → 定义第2话范围 → §3 角色变化 → §4 改编分析 → 导演卡2 → Step 2 分镜 → Step 3 审核
```

> 拆分后每话的导演卡中，章节概要需标注"本话覆盖原文 ch{NNN} 的 §{段落范围}"，明确本话的原文边界。

### 不拆分时

负载为"轻"或"中"时，1 话处理。但在 §4 改编分析中，B 级信息的砍除要更积极——"中"负载时宁可砍掉 2-3 条 B 级信息，也不要超过 12 格。

### 话数规划表（写入导演卡）

| 字段 | 值 |
|:-----|:---|
| 原文范围 | ch{NNN}（或 ch{NNN}+ch{MMM}） |
| 信息负载 | {轻/中/重}（{信息数}信息+{场景数}场景+{角色数}角色+{故事线数}故事线） |

## 3. 角色外观变化识别

**先识别变化，再做改编分析**——因为导演卡需要记录角色变化计划，供选帧 step 标注定妆图版本。

### 识别流程

1. 通读本章原文，对比角色库中每个角色的当前版本规格表
2. 找出本章中角色外观发生变化的所有节点

### 变化类型清单

| 变化类型 | 示例 | 是否需要增量定妆图 |
|:---------|:-----|:-----------------|
| 换装 | 贫民窟破衣 → 贵族华服 | ✅ 必须增量 |
| 受伤/疤痕 | 战斗后脸上留疤 | ✅ 必须增量 |
| 变身/形态变化 | 觉醒后瞳色变金 | ✅ 必须增量 |
| 年龄跳变 | 时间线跳跃数年 | ✅ 必须增量 |
| 装备变化 | 获得武器/防具 | ✅ 必须增量 |
| 临时状态（脏污/淋湿） | 雨中行走后湿透 | ❌ 不增量，分镜提示词中描述 |
| 表情/姿态变化 | 从恐惧到愤怒 | ❌ 不增量，分镜提示词中描述 |

### 变化记录表

将识别到的变化整理成表：

| 角色 | 变化节点 | 变化描述 | 当前版本 | 新版本 | 变化类型 |
|:-----|:---------|:---------|:---------|:-------|:---------|
| 薇薇安 | 本章中段换装 | 从破旧麻布衣换成白色连衣裙 | v1 | v2 | 换装 |
| 索伦 | 本章末尾觉醒 | 瞳色从黑变金，背部出现纹路 | v1 | v2 | 变身 |

> 无变化的章节跳过角色变化识别，但 **§4 改编分析不可跳过**。

## 4. 漫画化改编分析

> **参考 `references/storyboard-guide.md`** 了解改编策略、布局系统和提示词方法论。
>
> 本环节采用**三层推导**：故事层（讲什么故事）→ 页层（分几页、每页做什么）→ 格层（每格画什么、多大、怎么排）。自上而下推导，不能反过来。

网文章节天然混合多种内容类型：动作场面可以直接画，但内心独白、系统数值、世界观设定无法直接选帧。如果只"选帧"不"改编"，这些内容会被无声跳过，导致漫画信息断崖。

本环节的目标：**确保读者只看漫画也能理解本章核心剧情，且阅读体验是"翻页讲故事"而非"幻灯片堆帧"。**

### 步骤 1：改编灵魂（本章核心冲突定调）

在做内容分段之前，先用 3 个问题定调本章的改编方向：

| 问题 | 说明 | 产出 |
|:-----|:-----|:-----|
| **灵魂冲突** | 本章最核心的矛盾是什么？不是"发生了什么"，而是"这一章在讲什么较量" | 一句话：`{角色} vs {对立面}的{冲突本质}` |
| **避开俗套** | 这一章最容易被画成什么样的烂俗画面？至少列 2 个要避开的套路 | 列表：`避免：{俗套1}` / `避免：{俗套2}` |
| **求新钩子** | 这一章有什么是"只有漫画能表现出来，小说文字反而做不到"的？ | 一句话：`{视觉化独有点}` |

示例（深渊主宰 ch002）：
```
灵魂冲突：索伦的意识 vs 消亡的命运——一个灵魂在数据流中拒绝消散的较量
避开俗套：避免：标准穿越光环开场 / 避免：游戏面板直接弹出
求新钩子：两个灵魂的意识空间对峙——文字只能描述心理，漫画能画出两个半透明身影重叠融合的视觉奇观
```

> 这 3 条写入导演卡的「改编灵魂」段落，后续所有改编策略和布局设计必须服务灵魂冲突、避开俗套、发挥求新钩子。

### 步骤 2：叙事主线设计（故事层）

> **信息审计是"零件清单"，叙事主线是"装配图"。** 先设计装配图，再清点零件——否则 9 条信息平铺直叙塞进 12 格，读者看到的是碎片不是故事。

#### 2.1 一句话故事

读者看完本话后应该能用一句话总结什么？

```
{谁}在{什么情境}下做了{什么决策/行动}，导致了{什么后果}。
```

示例（玄鉴仙族 第1话）：
```
魏王李周巍定下灭蜀大策，同时剑门剑仙程郇之应下伐蜀——两条线汇聚成灭蜀战争的开端。
```

> 一句话故事是叙事主线的锚点。如果总结不出来，说明原文内容太散，需要砍副线聚焦主线。

#### 2.2 因果链设计

将本章内容组织成一条因果链，每环节对应 1-3 帧：

| 环节 | 功能 | 帧数预算 | 示例 |
|:-----|:-----|:---------|:-----|
| 起因 | 为什么要做这件事 | 1-2 帧 | 西蜀在大西塬吃亏、真人陨落 |
| 发展 | 形势如何推动决策 | 2-3 帧 | 魏王密议、剑仙出关 |
| 决策 | 核心决定是什么 | 1-2 帧 | "迟早要攻蜀" + "伐蜀只是顺便" |
| 后果 | 这个决定会导致什么 | 1 帧 | 金卷密令"擒主焚庙可矣" |

> 因果链不是信息清单的重新排列——它要求每帧都**推进**故事，而不是**呈现**信息。一帧如果既不是起因也不是发展也不是决策也不是后果，它就是在浪费格数。

#### 2.3 主副线结构

一章通常有 1 条主线（A-story）和 0-1 条副线（B-story）：

| 结构 | 定义 | 帧数占比 | 处理 |
|:-----|:-----|:---------|:-----|
| A-story | 本章的核心因果链 | 60-70% | 享有最佳帧位（名场面/冲击帧） |
| B-story | 平行发生的另一条线 | 20-30% | 服务于 A-story（铺垫/对比/悬念） |
| 无副线 | 只有一条线 | 100% | 不要硬凑副线 |

> **B-story 必须服务于 A-story**——要么铺垫（B 的因果推动了 A），要么对比（B 和 A 形成反差），要么悬念（B 留下钩子让读者期待与 A 的交汇）。如果 B-story 和 A-story 没有关系，砍掉 B-story。

#### 2.4 读者理解路径

模拟一个**没读过原文的读者**，逐帧列出他在每一帧时"应该理解什么"和"应该期待什么"：

| 帧序 | 读者此时理解了什么 | 读者此时期待什么 |
|:-----|:-----------------|:---------------|
| 1-2 | 有人在密谋重大军事行动 | 什么行动？为什么？ |
| 3-5 | 西蜀刚吃了大亏，格局有变 | 要报复？要趁火打劫？ |
| 6 | 决策是"亲自攻蜀" | 怎么攻？谁去？ |
| 8-11 | 另一拨人也准备伐蜀 | 两边会合作还是冲突？ |
| 12 | 灭蜀令已下 | 开战！ |

> 如果某一帧的"读者理解了什么"是空的或和前一帧重复，说明这帧没有推进故事——考虑砍掉或合并到相邻帧。

#### 2.5 情感曲线

> **情感曲线是页面分割的驱动力。** 读者情绪发生翻转的地方，就是一页结束、新一页开始的信号。

在因果链的每个环节标注**读者情绪标签**和**情感强度**，连接成曲线，标注**情感转折点**：

| 因果链环节 | 读者情绪 | 情感强度 | 转折点 |
|:-----------|:---------|:---------|:-------|
| 起因 | 压抑/紧张 | ★★ | — |
| 发展 | 焦虑升级 | ★★★ | 转折点1：信息揭示（情绪从压抑转向焦虑） |
| 决策 | 震撼/爆发 | ★★★★★ | 转折点2：核心决策（情绪从焦虑跳到爆发） |
| 后果 | 沉寂/悬念 | ★★ | 转折点3：钩子（情绪从爆发跌入沉寂） |

示例（深渊主宰 ch002）：
```
起因：绝望/恐惧 ★★ → 发展：挣扎/焦灼 ★★★ [转折点1：数据流注入] → 
决策：融合/震撼 ★★★★ [转折点2：原身放弃意识] → 后果：孤独/微光 ★★ [转折点3：希斯之死]
```

> **情感转折点 ≠ 帧边界。** 转折点可能发生在两帧之间，也可能在一帧内部。转折点的作用是**标识页面分割线**——步骤7会用它来决定分几页。

### 步骤 3：内容分段标注

通读原文，将章节内容按段落标记为以下七种类型之一：

| 内容类型 | 定义 | 典型特征 |
|:---------|:-----|:---------|
| 动作场面 | 角色有物理位移/对抗 | 打斗、追逐、逃亡 |
| 情感场景 | 角色情绪外化、有互动 | 哭泣、拥抱、对视 |
| 对话场景 | 角色间语言交流 | 威胁、争吵、告白 |
| 内心独白 | 角色心理活动、无外部动作 | "我要醒过来"、挣扎、决心 |
| 系统/数值 | 游戏面板、属性、技能描述 | 属性表、经验值、技能说明 |
| 世界观设定 | 背景/历史/规则描述 | 诸神之战、脑域开发、势力格局 |
| 记忆/闪回 | 非当前时间线的画面 | 前世记忆、巫师攻击、童年回溯 |

### 步骤 4：关键信息审计（含证据链 + 信息分级）

从标注的内容中提取**读者必须理解的关键信息点**——不是所有内容都关键，只提取"如果丢失，后续剧情无法理解"的信息。

#### 信息分级

**不是所有关键信息都同等重要。** 按优先级分三级，决定帧位分配和呈现力度：

| 级别 | 定义 | 处理 | 帧位 |
|:-----|:-----|:-----|:-----|
| **S 级** | 丢了完全看不懂主线 | 必须呈现，分配**最佳帧位**（名场面/冲击帧） | 独占格 |
| **A 级** | 丢了影响理解但不致命 | 应该呈现，可用旁白浓缩或视觉转化 | 正常帧 |
| **B 级** | 世界观增色但不影响主线 | 可砍，帧位紧张时第一个砍 | 合并或旁白 |

> **分级原则**：S 级信息不超过 3 条——一章的核心决策/转折最多 2-3 个。如果 S 级超过 3 条，说明对"主线"的理解太宽泛，回步骤 2 重新聚焦因果链。

每条信息必须标注**原文来源**（证据链）和**优先级**：

| # | 优先级 | 关键信息 | 来源段落 | 原文摘录（≤30字） | 内容类型 | 丢失后果 |
|:-:|:------:|:---------|:---------|:-----------------|:---------|:---------|
| 1 | S | 索伦是穿越者，前世在虚拟游戏中出意外 | ch002 §2 | "他记得自己曾经是玩家" | 内心独白 | 读者不知道他为何有游戏系统 |
| 2 | A | 数据流融入大脑，这是他能醒来的原因 | ch002 §2-3 | "数据流冲刷着他的意识" | 系统/数值 | 读者不知道他怎么醒的 |
| 3 | A | 原身主动放弃意识让穿越者接管 | ch002 §3 | "他把身体留给了另一个人" | 内心独白 | 读者不理解人格融合 |
| 4 | B | 希斯老死后安详离世 | ch002 §5 | "老狗闭上了眼睛" | 情感场景 | 读者错过核心情感点 |

> **判断标准**：遮掉这条信息后，读者还能理解后续剧情吗？完全不能 → S 级；有影响但能猜 → A 级；无所谓 → B 级或砍。
>
> **证据链要求**：每条信息必须有 `来源段落` + `原文摘录`，确保改编可审计——选帧时能追溯到"这条信息来自原文哪里"。无法追溯到原文的关键信息标记为"原创改编"。

### 步骤 5：逐条定改编策略

对每条关键信息，确定处理方式：

| 策略 | 适用条件 | 执行方式 |
|:-----|:---------|:---------|
| **直接选帧** | 信息本身有视觉化场面（动作/情感/对话） | 进入分镜表，标注为正常帧 |
| **视觉转化** | 信息关键但无直接画面（独白/系统/设定） | 设计视觉隐喻或替代画面（见下方转化方案库） |
| **旁白浓缩** | 信息量大但视觉化成本过高 | 用 1-2 句旁白框概括，搭配象征性/反应画面 |
| **砍掉** | 非关键信息，不影响剧情理解 | 直接跳过 |

形成策略表：

| # | 关键信息 | 改编策略 | 转化方案（如需） |
|:-:|:---------|:---------|:---------------|
| 1 | 索伦是穿越者 | 视觉转化 | 画面：意识空间中两个半透明身影重叠融合，一个消散一个留存 |
| 2 | 数据流融入大脑 | 视觉转化 | 画面：数字雨0/1从头顶倾泻注入身体，体内电路纹路亮起 |
| 3 | 原身放弃意识 | 旁白浓缩 | 旁白框："他放弃了自己，把身体留给了另一个人。" 画面：一只手伸向另一只手后消散 |
| 4 | 希斯之死 | 直接选帧 | 正常分镜帧 |

### 步骤 6：转化方案设计

对策略为"视觉转化"的信息，设计具体视觉手段。**详见 `references/storyboard-guide.md` 的「转化方案库」**。

核心原则：
- **抽象内容具象化**：内心独白 → 角色在象征性空间中的动作（意识空间行走、灵魂对峙）
- **系统内容视觉化**：属性面板 → 半透明 UI 叠层浮现于角色眼前（不画完整数值，画"界面出现"这个瞬间）
- **设定内容场景化**：世界观 dump → 用一个宏大的视觉奇观承载（末日异象、历史壁画、地图标注）
- **闪回内容区分化**：非当前时间线 → 用边框纹理/色调偏移/画中画等手段与主线区分

### 步骤 7：页面布局设计（页层）

> **从"帧"到"页"——一帧帧堆砌不是漫画，一页页组织才是。** 漫画阅读是翻页体验，不是幻灯片。读者一次滑动看到的是一"页"的内容，每页必须有独立的叙事功能和情绪体验。
>
> **这一步回答老板的问题："这几页漫画要呈现什么？"**

**核心原则：布局服务于叙事，不为动态而动态。** 每个布局选择必须有叙事理由——这格为什么大？因为这帧是名场面。这格为什么小？因为这是快节奏推进。如果回答不出"为什么这么布局"，就是为动态而动态。

#### 7.1 页面分割

根据步骤2.5的情感转折点，将一话分为 2-5 个"叙事页"。**每个情感转折点 = 一个页面分割候选位。**

一话通常分为 2-4 页：

| 页码 | 功能位 | 对应因果链环节 | 典型格数 |
|:-----|:-------|:-------------|:---------|
| P1 | 建立页 | 起因 | 2-3 格 |
| P2 | 发展页 | 发展 | 3-4 格 |
| P3 | 高潮页 | 决策 | 2-3 格 |
| P4 | 钩子页 | 后果 | 1-2 格 |

> 格数较少的话（6-8格）可以只有 2 页（建立+发展 / 高潮+钩子）。不要为了凑页数而强行分割——一页内也可以有节奏变化。

#### 7.2 四种页面功能位

| 功能位 | 叙事任务 | 布局策略 | 视觉重心 |
|:-------|:---------|:---------|:---------|
| **建立页** | 场景建立+角色登场+情境交代 | 大格开场建立空间 → 中格交代角色和关系 | 场景全景或角色登场 |
| **发展页** | 推进因果链+信息揭示+冲突升级 | 快慢交替推进 → 大格停在关键信息点 | 角色互动或信息揭示 |
| **高潮页** | 名场面+核心决策+情绪爆发 | 独占格定格名场面 → 小格反应镜头 → 大格定格后果 | 名场面/冲击帧 |
| **钩子页** | 后果呈现+情绪回落+章末钩子 | 大格余韵 → 小格过渡 → hook 格留悬念 | 余韵画面或悬念暗示 |

> **每页必须有且只有一个视觉重心**——读者扫过这一页时第一眼应该看到什么。没有视觉重心的页面是散的，读者不知道该看哪里。

#### 7.3 页间衔接

每页结尾需要**页内钩子**——让读者想继续往下滑：

| 衔接类型 | 说明 | 示例 |
|:---------|:-----|:-----|
| 悬念衔接 | 上一页最后抛出问题，下一页回答 | P1结尾：脚步声逼近 → P2开头：门外是谁 |
| 情绪衔接 | 上一页情绪推到高点，下一页释放或升级 | P2结尾：决策做出 → P3开头：后果爆发 |
| 转场衔接 | 场景/时间/POV切换 | scene-break + 旁白条 |
| 对比衔接 | 上一页A线，下一页切B线 | P1魏王线 → P2剑仙线 |

> 页间衔接不是可选的——没有衔接的页面是断裂的，读者会感到"跳了"。

#### 7.4 页面设计表（写入导演卡）

| 页码 | 功能位 | 因果链环节 | 情感标签 | 视觉重心 | 格数预算 | 布局策略 | 页内钩子 |
|:-----|:-------|:-----------|:---------|:---------|:---------|:---------|:---------|
| P1 | 建立页 | 起因 | 压抑 | 荒凉战场远景 | 3格 | panel-full开场→panel-half×2角色登场 | 密议即将开始 |
| P2 | 发展页 | 发展 | 焦虑升级 | 魏王金瞳特写 | 4格 | 快慢交替→panel-half停在决策瞬间 | 金卷展开 |
| P3 | 高潮页 | 决策 | 震撼爆发 | 剑仙出关名场面 | 3格 | panel-splash独占→panel-half反应 | 密令送达 |
| P4 | 钩子页 | 后果 | 沉寂/悬念 | 金卷文字特写 | 2格 | panel-full余韵→panel-hook悬念 | 战争倒计时 |

### 步骤 8：分格设计（格层）

> **先设计格子，再画格子里的图。** 页面设计确定"每页做什么"，分格设计确定"每格画什么、多大、怎么排"。
>
> **这一步回答老板的问题："格子→格子的图→然后再设计格子"——先定格子布局，再交给 step2 画具体画面。**

**核心原则：格子大小由信息重要性决定，格子排列由节奏决定。** 不是随机选布局类，而是从叙事需求推导——S级信息要大格/独占格，快节奏要紧密小格，高潮要独占大格。**每个布局选择必须能回答"为什么这么布局"。**

#### 8.1 格子大小推导

从步骤4的信息分级推导每格的布局规模：

| 信息级别 | 布局规模 | 理由 |
|:---------|:---------|:-----|
| S级 | 独占格（panel-splash/bleed/full） | 核心决策/转折必须给最大视觉空间 |
| A级 | 正常格（panel-half） | 重要信息正常呈现 |
| B级 | 小格（panel-third）或合并 | 辅助信息不抢视觉空间 |
| 转化帧 | 视觉奇观格（panel-splash/bleed） | 抽象内容的视觉化需要足够空间 |
| 旁白帧 | 半格+旁白（panel-half） | 画面是配角，旁白是主角 |
| 无角色环境帧 | 全宽格（panel-full/cinema） | 环境建立需要宽度 |

#### 8.2 格子排列推导

从步骤7的页面节奏推导格子排列方式：

| 页面节奏 | 排列策略 | 布局组合 |
|:---------|:---------|:---------|
| 慢节奏（建立/余韵） | 大格+少格，给读者时间消化 | panel-full → panel-half |
| 快节奏（推进/冲突） | 小格+多格，快速切换制造紧迫感 | panel-half × N 或 grid-3 |
| 爆发节奏（高潮/名场面） | 独占格定格 → 小格反应 → 大格定格后果 | panel-splash → panel-half → panel-full |
| 悬念节奏（钩子） | 渐收 → hook格留白 | panel-half → panel-hook |

> **节奏交替是铁律**：连续 3 格以上相同节奏 = 节奏单调。连续 3 个以上相同布局类 = 读者疲劳。

#### 8.3 布局选择决策树

为每个格子选布局时，按以下顺序决策：

```
这格承载什么级别的信息？
├─ S级 → 独占格（panel-splash/bleed/full）+ 高精度提示词
├─ A级 → 这格在什么节奏段？
│   ├─ 慢节奏段 → panel-full 或 panel-half（宽松）
│   └─ 快节奏段 → panel-half（紧凑）
├─ B级 → panel-third 或合并到相邻格
└─ 转化帧/旁白帧 → panel-half 或 panel-splash（视觉奇观型转化）

这格是名场面吗？（步骤6/storyboard-guide §8 三标准满足两条）
├─ 是 → panel-splash 或 panel-bleed + 效果类 + 高精度提示词
└─ 否 → 按上面的信息级别选

这格是章末最后一格吗？
├─ 是 → panel-hook（必须）
└─ 否 → 按上面的逻辑选
```

#### 8.4 分格设计表（写入导演卡）

为每页的每个格子填写设计意图。**此表是 step2 拆分镜的直接输入——step2 继承布局类/节奏/效果类，只补充画面提示词、定妆图版本、场景主镜等执行细节。**

#### 8.5 布局自检

逐页检查布局是否服务于叙事：

- [ ] 每页是否有且只有一个视觉重心？
- [ ] S级信息是否分配到了独占格/大格？
- [ ] 快慢节奏是否交替（连续3格以上同节奏=单调）？

### 步骤 9：信息覆盖率自检

将策略表、分格设计表与审计表逐条核对：

- 每条关键信息是否都有对应的改编策略？
- 每条关键信息是否都出现在分格设计表的"信息来源"列中？
- 策略为"视觉转化"的信息，转化方案是否具体到可以写提示词？
- 策略为"旁白浓缩"的信息，旁白文字是否已拟好？
- 分格设计表的格数总和是否与页面设计表的格数预算一致？

## 6. 🚪 门禁：导演卡确认

向用户呈现导演卡全文（`第{N}章/导演卡.md`），核心确认八件事：

1. **话数规划合不合理** — 信息负载评估是否准确，1 话/拆分决策是否合理，拆分时每话范围和弧线是否完整
2. **叙事主线清不清楚** — 一句话故事能否总结，因果链是否连贯，读者理解路径有无空白，情感曲线转折点是否合理
3. **改编灵魂对不对** — 灵魂冲突是否抓住了本章核心，俗套避开了没有，求新钩子是否成立
4. **关键信息有没有漏+分级对不对** — 审计表中的关键信息是否覆盖了本章必须传达的内容，S/A/B 分级是否合理，每条是否有原文来源
5. **改编策略对不对** — 每条信息的处理方式（直接选帧/视觉转化/旁白浓缩/砍掉）是否合理，S 级信息是否分到了最佳帧位
6. **转化方案行不行** — 视觉转化帧的设计是否具体、可执行
7. **页面布局对不对** — 分页是否合理（2-5页），每页功能位是否正确，视觉重心是否明确，页间衔接是否自然
8. **分格设计对不对** — 每格布局类是否从叙事需求推导（非模板驱动），S级信息是否独占大格，节奏是否交替，名场面是否最大布局，章末是否 hook

用户确认后，携带导演卡进入 Step 2（读取 `steps/step2-storyboard.md`）执行分镜生成。

> 导演卡是选帧的唯一输入源——选帧 step 基于导演卡的分格设计表拆分镜，继承布局类/节奏/效果类，补充画面提示词和定妆图版本，不重新做改编分析和布局设计。
