# Step 3: 视觉审核 + 记忆沉淀

> 检查产出完整性 → 感染力评审 → 记录视觉决策 → 沉淀问题规则 → 更新记忆文件

## 设计哲学

Phase 2 是漫画连载的**记忆刷新点**。每章生成后必须执行，确保下章生成时有完整的上下文。

对齐起点 pipeline 的"write 完成后必须进入 review——不得连续写两章不 review"原则。漫画管线同样：不得连续生成两章不审核。

DeepSeek 无视觉能力，所以这里的"审核"不是看图判断角色像不像，而是**检查工程完整性 + 结构性感染力评审 + 沉淀决策记录**：
- 产出文件是否齐全（页数、格式、HTML 漫画页面/长图）
- 本章用了哪些定妆图版本（为下章提供角色状态参考）
- 本章有无增量定妆图（角色外观变化记录）
- 页面级感染力评审（叙事流/页面节奏/情绪钉子/角色一致性/扫描测试）
- 本章遇到的问题和改进规则（append 到沉淀文件）

## 1. 产出完整性检查

| 检查项 | 方法 | 达标标准 |
|:-------|:-----|:---------|
| 页数完整 | LS output/ 目录 | 导演卡页面设计表的每页 page{N}.png 全部存在 |
| 图片格式 | 检查文件头 | magic bytes 为 `89 50 4E 47`（真PNG），脚本已内置自动转码 |
| 页面配置完整 | 检查 页面配置.json | pages 数组覆盖全部页面，captions 与导演卡旁白文字对应 |
| HTML 漫画页面已生成 | LS 检查 | index.html 已落盘，图片引用路径正确（非 base64 内联） |
| 长图截图已生成 | LS 检查 | 长图-{章节名}.png 已落盘（Playwright 截图，分享用） |
| storyboard.md 存在 | LS 检查 | 分镜脚本（页面级提示词）已落盘 |
| 导演卡存在 | LS 检查 | 第{N}章/导演卡.md 已落盘 |
| 生成元数据 | 检查 generation_meta.json | 页数/成功/失败/耗时记录完整 |

## 2. 感染力评审

> 产出完整性检查通过后，对本章漫画进行页面级感染力评审。DeepSeek 无视觉能力，但可通过导演卡页面设计表和分镜脚本表做结构性判断。

### 五维评审表

| 维度 | 检查问题 | 通过标准 | 判定 |
|:-----|:---------|:---------|:-----|
| **叙事流** | 从 P1 滑到最后一页，不看原文能理解"谁做了什么、为什么、导致了什么"吗？ | 页面设计表的因果链完整，每页推进故事，无信息断崖 | ✅/⚠️/❌ |
| **页面节奏** | 相邻页的格数/格布局/页面类型有变化吗？还是全是 2x2 网格？ | 页面类型有交替（多格页/大单页/双格页），格布局有变化 | ✅/⚠️/❌ |
| **情绪钉子** | 本章是否至少有一页"读者滑过去后会记住"的画面？ | 大单页或名场面页承载了核心情绪爆发，提示词写的是"后果和感受" | ✅/⚠️/❌ |
| **角色一致性** | 每页的角色定妆图参考是否正确配置？同一角色跨页外观一致？ | storyboard.md 每页的 ref_images 与角色库版本对应，增量定妆图（如有）已更新到角色库 | ✅/⚠️/❌ |
| **扫描测试** | 只看每页的旁白/对白主句，能否读出完整故事弧？ | 旁白文字串起来能讲清"起因→发展→决策→后果" | ✅/⚠️/❌ |

### 评审规则

- **叙事流** ❌ → 标记信息断裂处，在沉淀中记录"第X页到第Y页之间信息跳跃，导演卡因果链需补充过渡"
- **页面节奏** ❌ → 在沉淀中记录"本章页面类型单一，全是多格页/全是2x2，下章导演卡需增加大单页或双格页变化"
- **情绪钉子** ❌ → 在沉淀中记录"本章缺少名场面页，下章导演卡高光设计需确保至少1个大单页"
- **角色一致性** ⚠️/❌ → 在沉淀中记录"第X页角色参考图版本配置错误/缺失，下章需检查 ref_images 映射"
- **扫描测试** ❌ → 标记旁白断裂处，在沉淀中记录"第X页旁白缺失，读者无法理解该页发生了什么"

> 感染力评审结果写入视觉沉淀.md 的本章审核段落。⚠️ 记录即可，不阻断流程；❌ 需记录问题并在下章导演卡中针对性改进。

## 3. 记录本章视觉决策

整理本章的视觉决策信息：

### 3.1 定妆图使用记录

| 角色 | 使用版本 | 定妆图路径 | 出场页码 | 备注 |
|:-----|:---------|:-----------|:---------|:-----|

### 3.2 增量定妆图记录（如有）

本章是否有新生成的增量定妆图？如果有：

- 确认已更新到 漫画角色库.md

### 3.3 角色出场记录

| 角色 | 出场页码 | 本章状态变化 |
|:-----|:---------|:-------------|
| {角色名} | P1,P2,P4 | 无变化 / {状态变化描述} |

### 3.4 页面设计记录

| 页码 | 页面类型 | 格数 | 格布局 | 参考图 | 生成状态 | 备注 |
|:-----|:---------|:-----|:-------|:-------|:---------|:-----|

## 4. Append 视觉沉淀.md

将本章的审核结果追加到 `视觉沉淀.md`（**append-only，永不删改历史**）：

```markdown
## 第{N}章审核 | {日期}

### 产出状态
- 页数: {N}/{N} ✅
- 格式: 全部真PNG ✅
- HTML 漫画页面: ✅ (index.html)
- 长图截图: ✅ (长图-{章节名}.png)
- storyboard.md: ✅
- 导演卡: ✅
- 生成元数据: ✅ (generation_meta.json)

### 感染力评审
- 叙事流: ✅/⚠️/❌ — {说明}
- 页面节奏: ✅/⚠️/❌ — {说明}
- 情绪钉子: ✅/⚠️/❌ — {说明}
- 角色一致性: ✅/⚠️/❌ — {说明}
- 扫描测试: ✅/⚠️/❌ — {说明}

### 定妆图使用
- {角色名}: v{N}（{出场页码}，{状态描述}）

### 角色状态变化
- {角色名}: {变化描述}，下章需{注意事项}

### 页面设计记录
- P1: {页面类型} {格数}格 {格布局} — {备注}
- P2: ...
- P3(大单页): {名场面描述} — {冲击帧提示词是否正确}

### 问题记录
- [问题描述，如：P3大单页的角色面部与定妆图有偏差]

### 改进规则
- [基于问题提炼的规则，如：大单页的参考图权重需提高，提示词中增加面部锚点描述]
```

## 5. 更新漫画快照.md

更新中期记忆文件（replace 模式，覆盖为最新状态）：

- **章节清单**：追加本章记录（章号 + 章节名 + 生成日期 + 页数 + 定妆图版本快照）
- **角色出场记录**：更新每个角色的出场章节列表
- **风格锚定串**：不变（全系列冻结）
- **已知视觉问题池**：从沉淀中提取未解决的问题

## 6. 更新漫画状态.md

更新短期记忆文件（replace 模式），为下一章生成准备入口包：

- **当前章位**：下一章的章号
- **角色状态**：每个角色的当前外观版本 + 状态描述
- **上一章问题**：从沉淀中提取最近一章的问题
- **注意事项**：下章生成需要注意的事项（如"角色已换装，需使用v2定妆图"）
- **待处理增量定妆图**：如果本章标注了角色变化但未生成增量定妆图，记录在此

## 7. 审核完成

Phase 2 完成后：
- 如果还有下一章 → 回到 Phase 1 Step 1（读取 `steps/step1-director.md`）
- 如果本卷结束 → 通知用户，可考虑更新风格锚定串或批量重生成角色定妆图
