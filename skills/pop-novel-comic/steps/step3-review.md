# Step 3: 视觉审核 + 记忆沉淀

> 检查产出完整性 → 记录视觉决策 → 沉淀问题规则 → 更新记忆文件

## 设计哲学

Phase 2 是漫画连载的**记忆刷新点**。每章生成后必须执行，确保下章生成时有完整的上下文。

对齐起点 pipeline 的"write 完成后必须进入 review——不得连续写两章不 review"原则。漫画管线同样：不得连续生成两章不审核。

DeepSeek 无视觉能力，所以这里的"审核"不是看图判断角色像不像，而是**检查工程完整性 + 沉淀决策记录**：
- 产出文件是否齐全（帧数、格式、HTML 漫画页面/JPEG 长图）
- 本章用了哪些定妆图版本（为下章提供角色状态参考）
- 本章有无增量定妆图（角色外观变化记录）
- 本章遇到的问题和改进规则（append 到沉淀文件）

## 1. 产出完整性检查

| 检查项 | 方法 | 达标标准 |
|:-------|:-----|:---------|
| 帧数完整 | LS output/ 目录 | 6-8 帧 frame{N}.png 全部存在 |
| 图片格式 | 检查文件头 | magic bytes 为 `89 50 4E 47`（真PNG），脚本已内置自动转码 |
| 排版配置完整 | 检查 拼图配置.json | frames 数组覆盖全部分镜帧，layout 值与分格设计表对应 |
| HTML 漫画页面已生成 | LS 检查 | index.html 已落盘，图片引用路径正确（非 base64 内联） |
| 长图截图已生成 | LS 检查 | 长图-{章节名}.png 已落盘（Playwright 截图，分享用） |
| 漫画长图已生成（备选） | LS 检查 | 漫画-{章节名}.jpg 已落盘（Pillow 备选方案），文件大小 >100KB |
| storyboard.md 存在 | LS 检查 | 分镜脚本已落盘 |
| 导演卡存在 | LS 检查 | 第{N}章/导演卡.md 已落盘 |

## 3. 感染力评审

> 产出完整性检查通过后，对本章漫画进行感染力维度评审。DeepSeek 无视觉能力，但可通过提示词记录和分镜表做结构性判断。

### 五维评审表

| 维度 | 检查问题 | 通过标准 | 判定 |
|:-----|:---------|:---------|:-----|
| **3秒焦点** | 每帧缩小到手机缩略图大小后，能否在3秒内看出主角、主动作、关键道具？ | 每帧只有一个视觉焦点，主角和主动作可辨识 | ✅/⚠️/❌ |
| **情绪钉子** | 本章是否至少有一格"读者滑过去后会记住"的画面？ | 至少一格组合了具体动作+身体反应+关键道具/环境细节 | ✅/⚠️/❌ |
| **角色记忆点** | 每个常驻角色是否有至少一个可区分的视觉记忆特征？ | 主角有1个主吸引轴+2个记忆特征（如发型/疤痕/姿态） | ✅/⚠️/❌ |
| **记忆句** | 本章是否有一句准确、短、可复述、贴画面动作的句子？ | 换一本书这句话不成立，不是通用鸡汤 | ✅/⚠️/❌ |
| **扫描测试** | 只看每帧的对白/旁白主句，能否读出"谁/发生什么/变化是什么"？ | 标题+主句能讲清故事弧 | ✅/⚠️/❌ |

### 评审规则

- **3秒焦点** ❌ → 标记问题帧，在沉淀中记录"该帧构图焦点不清，下章类似场景需简化背景"
- **情绪钉子** ❌ → 在沉淀中记录"本章缺少记忆画面，下章需设计至少一个情绪锚点帧"
- **角色记忆点** ❌ → 在沉淀中记录"角色辨识度不足，Phase 0 需补充视觉锚点"
- **记忆句** ❌ → 在沉淀中记录"本章文案缺少记忆句，下章导演卡旁白需增加记忆句设计"
- **扫描测试** ❌ → 标记信息断裂处，在沉淀中记录"第X帧到第Y帧之间信息跳跃"

> 感染力评审结果写入视觉沉淀.md 的本章审核段落。⚠️ 记录即可，不阻断流程；❌ 需记录问题并在下章导演卡中针对性改进。

## 4. Append 视觉沉淀.md

将本章的审核结果追加到 `视觉沉淀.md`（**append-only，永不删改历史**）：

```markdown
## 第{N}章审核 | {日期}

### 产出状态
- 帧数: 8/8 ✅
- 格式: 全部真PNG ✅
- HTML 漫画页面: ✅ (index.html)
- 长图截图: ✅ (长图-{章节名}.png)
- 漫画长图（备选）: ✅ (814KB)
- storyboard.md: ✅
- 导演卡: ✅

### 定妆图使用
- 索伦: v1（本章末醒来，下章可能需要新表情版）
- 薇薇安: v1（稳定）

### 角色状态变化
- 索伦: 昏迷→醒来，下章开始正常活动

### 问题记录
- [问题描述，如：frame3的老狗毛色与定妆图不一致]

### 改进规则
- [基于问题提炼的规则，如：配角动物也应有参考图]
```

## 4. 更新漫画快照.md

更新中期记忆文件（replace 模式，覆盖为最新状态）：

- **章节清单**：追加本章记录（章号 + 章节名 + 生成日期 + 定妆图版本快照）
- **角色出场记录**：更新每个角色的出场章节列表
- **风格锚定串**：不变（全系列冻结）
- **已知视觉问题池**：从沉淀中提取未解决的问题

## 5. 更新漫画状态.md

更新短期记忆文件（replace 模式），为下一章生成准备入口包：

- **当前章位**：下一章的章号
- **角色状态**：每个角色的当前外观版本 + 状态描述
- **上一章问题**：从沉淀中提取最近一章的问题
- **注意事项**：下章生成需要注意的事项（如"索伦已醒来，需要更多表情版定妆图"）
- **待处理增量定妆图**：如果本章标注了角色变化但未生成增量定妆图，记录在此

## 6. 审核完成

Phase 2 完成后：
- 如果还有下一章 → 回到 Phase 1 Step 1（读取 `steps/step1-director.md`）
- 如果本卷结束 → 通知用户，可考虑更新风格锚定串或批量重生成角色定妆图
