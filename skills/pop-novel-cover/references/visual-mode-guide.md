# 封面 skill 视觉模式路由总览

> 本文件是三种视觉产出模式的**判定入口和路由总览**。各模式的详细设计方法论已拆分到独立文件，按路由表读取对应文件即可。

## 三种模式对照表

| 维度 | 封面图 | 普通素材 | 场景图 |
|:-----|:-------|:---------|:-------|
| **目的** | 书架展示，0.3秒识别赛道 | 场景/氛围/参考图 | 从原文还原画面 |
| **起点** | 用户意图 | 用户意图 | 小说原文 |
| **设计驱动** | 视觉钩子（营销优先） | 纯视觉美学 | 原文理解→视觉转化 |
| **文字** | 书名+作者+标语（必须） | 无要求 | 无强制要求 |
| **文字角色** | 书名是主角之一（20%权重） | 无 | 无 |
| **画幅** | 3:4（1125x1500） | 任意 | 按场景决定 |
| **Step 0** | Pinterest搜图+选图 | Pinterest搜图+选图 | 原文理解管线 |
| **门禁A** | 选图+对齐参考点 | 选图+对齐参考点 | 理解确认 |
| **详细文件** | `mode-cover.md` | `mode-scene-art.md` | `mode-scene.md` |

## 模式判定流程

Step 0 提取视觉意图时，按以下流程判定模式：

```
用户需求
  ├─ 提到"封面/上架/书架" → 封面图模式 → 读 mode-cover.md
  ├─ 提到"场景/氛围/概念图/参考图" → 普通素材模式 → 读 mode-scene-art.md
  ├─ 提供小说原文 / 说"场景图/场景画面/原文场景" → 场景图模式 → 读 mode-scene.md（走 step0-scene-understand.md）
  └─ 未明确 → 询问用户
```

> **场景图模式判定关键**：用户直接贴了一段小说原文，或者说"把这段文字画出来"、"这段场景生成图"——这就是场景图模式。场景图走独立的理解管线，不走Pinterest搜图流程。

判定后，在门禁A呈现时**明确标注视觉模式**，让用户确认。
