# pop-novel-visual

> 网文视觉资产生成器。支持两种起点：①用户意图→Pinterest搜参考→选图+对齐参考点→设计方案→提示词→API生成；②小说原文→原文解构→上下文补全→叙事瞬间选取→理解确认→设计方案→提示词→API生成。v2.4.0

## 这个 Skill 做什么

输入：小说项目文件（全书设定文件、角色库、卷纲等）+ 视觉需求（封面/人设图/场景图）+ 可选参考图或小说原文。
输出：生成图片或视频 + 设计方案文档（人可读）+ 提示词记录。

核心价值：帮用户把脑子里的模糊画面变成可执行的参考图和参考点，再翻译为模型能理解的提示词。**两种起点，同一个终点**：封面/立绘从"用户想要什么感觉"出发（Pinterest搜图驱动），场景图从"这段文字在讲什么"出发（原文理解驱动）。**两个用户对齐门禁**确保方向不跑偏。

**三段流程**：
1. 用户意图 →（意图分析+Pinterest 3维度搜索）→ **选图+对齐参考点**（门禁A：用户选最喜欢的参考图，明确"参考这张的什么"）
   - **场景图模式分支**：用户提供小说原文时 → 原文解构→上下文补全→叙事瞬间选取→门禁A（理解确认）
2. 参考图+参考点 →（设计画面差异）→ **方案对齐**（门禁B：用户确认设计方案）
   - **场景图模式**：理解层产出 →（整体性视觉设计：构图→光影→色彩→焦点）→ 门禁B
3. 确认方案 →（参考点驱动的提示词策略）→ API 生成
   - **场景图模式**：确认方案 →（理解层转化的提示词）→ API 生成

> **v2.2.0 核心重构**：从"固定路线（图生图/文生图二选一）"升级为"参考点驱动的灵活提示词策略"。用户在门禁A选定参考点（全面参考/色系/构图/画风/光影/字体/组合），Step 2 据此决定提示词在哪些维度放手、哪些维度控制。核心铁律：用户选了什么参考点，提示词就在那个维度**放弃控制权**交给参考图，不自相矛盾。
>
> **v2.1.2 搜索策略**：Pinterest 搜索采用3维度×多表达并行策略，拆分IP/角色/风格三个维度，每个维度用2-3个不同英文表达并行搜索，合计返回6张差异化结果。

**参考点系统**：用户在门禁A选定参考图后，明确参考点（全面参考/色系/构图/画风/光影/字体/组合）。参考点决定后续设计方案的范围和提示词策略——参考图决定设计方向，不是方案决定后再找参考图配。

## 模型说明

| 模型 | 版本 | 用途 | API 端点 | 默认 |
|:-----|:-----|:-----|:---------|:----:|
| Seedream | 5.0 Pro | 静态图片（封面、人设图） | `POST /api/v3/images/generations` | ✅ |
| Seedream | 5.0 lite | 静态图片（速度优先，可选） | `POST /api/v3/images/generations` | ❌ |
| Seedance | 1.0 Pro | 动态视频封面（可选） | `POST /api/v3/contents/generations/tasks` | ❌ |

默认使用 Seedream 5.0 Pro（`doubao-seedream-5-0-pro-260628`）生成静态图片。A/B 实测 5.0 Pro 在色彩层次、文字渲染、视觉焦点管理上显著优于 5.0 lite 和 4.5，纯文生图质量达到商业优秀级。

> **关键特性**：Seedream 5.0 Pro/5.0 lite **画面不再泛白**，简洁精确的提示优于堆砌华丽词汇。支持文生图、图生图（增删替换改）、参考图生图、多图输入、组图生成。**支持文字渲染**：将要生成的文字内容用双引号包裹。

## 怎么运作

### Step 0: 用户意图分析 + 搜图 + 选图对齐参考点 → `steps/step0-research.md`
### Step 0-Scene: 原文理解管线（场景图模式）→ `steps/step0-scene-understand.md`

- **提取视觉意图** → 赛道+气质关键词+目标读者画像+视觉类型+书名
- **目标读者画像** → 年龄层决定画风方向（18-35岁女性=韩系唯美，非卡通）
- **Pinterest 3维度搜索** → 拆分风格/角色/IP维度，每维度2-3个英文表达并行搜6张
- **图片分析** → 逐张提取画风/构图/配色特征，标注所属维度和子方向
- **🚪 门禁A：选图+对齐参考点** → 用户选最喜欢的参考图，明确参考点（全面参考/色系/构图/画风/光影/字体/组合）。参考点决定后续设计方案和提示词策略

### Step 1: 设计方案（基于参考图+参考点） → `steps/step1-design.md`

- 基于参考图和参考点，设计需要改动/差异化的部分
- 参考点决定设计方案需要描述的维度（全面参考=只描述差异；色系参考=描述画面+构图+画风等，不描述配色）
- 目标读者画像校验（确保画风与读者年龄层一致）
- 形成人可读设计方案（全部用人话，非技术prompt）
- **🚪 门禁B：方案对齐** → 向用户呈现完整设计方案。用户确认/调整

### Step 2: 生成资产（参考点驱动提示词策略） → `steps/step2-generate.md`

- 读取门禁B确认的设计方案 + 用户选定的参考点
- **参考点→提示词策略**：用户选了什么参考点，提示词就在那个维度**放弃控制权**交给参考图
  - 全面参考 → 提示词只写差异（书名+必要改动）
  - 色系 → 提示词不写配色，交给参考图
  - 构图 → 提示词不写布局，交给参考图
  - 画风 → 精确分离公式，只吸收笔触技法
  - 组合 → 多维度放权，剩余维度详写
- 翻译为 Seedream/Seedance 提示词 → 执行 API 脚本 → 保存图片 → 回写提示词记录
- 降级机制：太像→收窄参考点；放权维度失控→该维度降级为控制

## 参考点系统

用户在门禁A选定参考图后，明确**参考点**——参考这张图的什么。参考点决定后续设计方案的范围和提示词策略：

| 参考点 | 提示词策略 | 核心原则 |
|:-------|:---------|:---------|
| 全面参考 | 保留参考图画面主体，提示词只描述差异 | 不抢画面控制权 |
| 色系 | 提示词不写配色，交给参考图 | 不抢配色权 |
| 构图 | 提示词不写布局，交给参考图 | 不抢构图权 |
| 画风 | 精确分离公式，只吸收笔触技法 | 不抢画风权 |
| 光影氛围 | 提示词不写光源设计，交给参考图 | 不抢光影权 |
| 字体风格 | 提示词不写字体材质，交给参考图 | 不抢字体权 |
| 组合 | 多维度放权，剩余维度详写 | 按选定维度放权 |

> **核心铁律**：用户选了什么参考点，提示词就在那个维度**放弃控制权**，交给参考图。不能既说"参考色系"又写"暖粉七成"——自相矛盾时模型听提示词不听参考图。

## 实测验证的控制公式

| 公式 | 用途 | 写法 |
|:-----|:-----|:-----|
| **结构化提示词V3** | 纯文生图达到商业级质量 | `整体氛围框架（画面是绝对主体）+ 画面内容（远景→前景按层次）+ 文字（最后描述，融入画面）+ 风格` |
| 风格控制 | 精确指定画风 | `[风格名称] + [技法描述] + [质感描述] + [参考标杆]` |
| 字体控制 | 精确指定书名质感 | `[书名] + [字体类型] + [材质/质感] + [色彩层次]` |
| 定场诗创作 | 浓缩小说意境为古体诗 | `[核心意象A] + [核心意象B] + [因果/转折] + [情感升华]` |
| 参考图精确分离 | 控制画风/构图吸收 | `仅参考此图的[具体要素]，不参考[具体要素]。以下画面内容由描述决定` |

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **先搜图选图再出方案** — 必须先 Pinterest 搜索参考图、用户选图+对齐参考点，再设计方案。禁止先出方案再找参考图配 | 参考图沦为装饰，设计方向跑偏 |
| ❌2 | **两个门禁不可跳过** — 门禁A（选图+对齐参考点）和门禁B（方案对齐）必须等用户确认后才能继续 | 方向跑偏，浪费生成次数 |
| ❌3 | **参考点放权一致性** — 用户选了什么参考点，提示词就在那个维度放弃控制权。不能"参考色系"又写"暖粉七成" | 提示词与参考图自相矛盾，模型听提示词不听参考图 |
| ❌4 | **设计方案必须落盘** — 选图记录、参考点、设计方案和提示词记录写入 `素材/视觉设计方案.md` | 无法迭代优化 |
| ❌5 | **场景图必须经过理解管线** — 用户提供原文时，必须经过原文解构→上下文补全→叙事瞬间选取→门禁A（理解确认），才能进入设计。禁止直接把原文翻译成提示词 | 理解偏差，精确地画错画面 |

## 前置条件

1. Python 3.8+ 环境
2. `requests` 库（pinterest_search.py 依赖，`pip install requests`）
3. API Key 已内置在脚本中（环境变量可覆盖）：
   - `ARK_API_KEY`（火山引擎方舟）→ `scripts/generate.py`
   - `BRIGHTDATA_API_KEY`（Pinterest 搜索）→ `scripts/pinterest_search.py`
4. **Pinterest 图片下载三层 fallback**（Pinterest CDN `i.pinimg.com` 在国内被墙）：
   - Layer 1：本地代理自动检测（环境变量→Windows注册表→端口探测7890/1080等），有VPN/Clash时自动生效
   - Layer 2：Bright Data Web Unlocker API（不需本地VPN，需在Bright Data后台创建Web Unlocker zone，环境变量 `BRIGHTDATA_UNLOCKER_ZONE` 可覆盖默认名 `web_unlocker1`）
   - Layer 3：优雅降级（保留图片URL到JSON，不崩溃，agent可呈现URL供用户浏览器打开）

## 强弱加载保障

- **强保障**：本 SKILL.md 由 host 层每次 run 强制注入，100% 到达 agent 上下文
- **弱保障**：`steps/` `references/` `templates/` `scripts/` 需 agent 按 SKILL.md 指引主动 readFile
- **设计原则**：核心 SOP 骨架和铁律在 SKILL.md 自包含，step/reference 文件提供详细指导
