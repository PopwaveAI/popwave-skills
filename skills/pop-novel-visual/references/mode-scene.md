# 场景图模式

> 场景图从**小说原文**出发，不是从"用户想要什么感觉"出发。核心是**理解**——把文学叙事翻译成视觉叙事，再生成画面。

## 核心原则

场景图的核心不是"生成"是"理解"——理解不到位，提示词再精确也是"精确地画错了"。

与封面/立绘/素材的根本区别：**起点不同**。

| 模式 | 起点 | 核心能力 |
|:-----|:-----|:---------|
| 封面图 | 用户意图（书名+赛道+感觉） | 视觉钩子设计 |
| 人物立绘 | 用户意图（角色+气质） | 角色名片设计 |
| 普通素材 | 用户意图（场景描述） | 纯视觉生成 |
| **场景图** | **小说原文** | **原文理解→视觉转化** |

场景图必须走独立的理解管线（`steps/step0-scene-understand.md`），不能直接把原文丢进提示词。

## 理解管线五层

1. **原文解构**：拆动作序列→角色规格→环境元素→材质细节→安全转换
2. **上下文补全**：角色身份/前因后果/读者印象/文字体验/小说基调（分级策略：热门IP自动搜索→冷门IP搜索+用户补充→原创小说从项目文件读取）
3. **叙事瞬间选取**：从连续动作中选最该画的那一帧（情感峰值+叙事关键+读者共鸣+视觉张力）
4. **🚪门禁A**：理解确认（不是选图，是确认理解正确）
5. **[可选]风格参考搜索**：Pinterest搜画风参考（画面内容由理解层决定，不由参考图决定）

## 设计要素

| 要素 | 要求 |
|:-----|:-----|
| 画面 | 基于理解层产出（选定瞬间+视觉元素+情感基调） |
| 文字 | 无强制要求（场景图通常无文字，除非用户要求加标题） |
| 画幅 | 按场景决定，常用3:4或16:9 |
| 理解层 | **必须经过五层理解管线才能进入设计** |

## 设计方法论

设计输入是理解层产出（选定瞬间+视觉元素+上下文+情感基调），不是参考图+参考点。

设计流程：
1. **构图方案**：角色站位、视线方向、空间纵深
2. **光影方案**：光源方向、色温、明暗分配
3. **色彩方案**：主色/辅色/点缀
4. **焦点设计**：第一眼看哪、视线如何流动

> 如果§5可选风格参考搜索中用户选了Pinterest画风参考图，则参考点=画风，提示词在画风维度放权。

## 与其他模式的关键区别

| 区别点 | 封面/立绘/素材 | 场景图 |
|:-------|:-------------|:-------|
| 输入 | 用户意图描述 | 小说原文 |
| Step 0 | Pinterest搜图+选图+对齐参考点 | 原文解构+上下文补全+瞬间选取 |
| 门禁A | 选图+对齐参考点 | 理解确认 |
| 设计驱动 | 参考图+参考点 | 理解层产出 |
| 画面内容来源 | 参考图+提示词 | 理解层转化 |

## 提示词结构

```
整体氛围框架（基于情感基调）+ 画面内容（选定瞬间的角色+环境+材质，按空间层次）+ 风格
```

> 画面内容来源不是用户描述，是理解层产出（选定瞬间+视觉元素清单+安全转换后的描述）。提示词必须忠实于理解层，不能自行添加理解层没有的元素。
