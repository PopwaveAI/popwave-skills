# pop-pipeline

> 统一管线总控。v1.1.0：对齐 pop-seed v2.0.0 全书大纲架构，立项产物从"六要素PRD"改为共创三层（01-命运图/02-命运图plus/03-全书大纲），归位表/就绪判定/状态模板/可调度清单同步改指。v1.0.0 由 test-pipeline 改造，吸收三族 pipeline。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 做什么

| 职责 | 说明 |
|:--|:--|
| 一次性安装（fresh） | 建目录 + 落盘 `状态.md`（薄机器状态）+（可选）导出展示面板 + README |
| 一次性导入/续写（import/resume） | 资产扫描→归位→缺口分析→落地Phase→状态重建→补跑调度 |
| 状态文件维护 | `状态.md` = 唯一机器状态源，agent 只读写它的状态片段；`项目总控.html` 是仅供老板查看的展示面板，按需导出，**agent 不读 html** |

**日常路由不经此skill**：用户说"继续写/下一步/写正文/审核"时，主agent按专家提示词阶段地图直接选 skill，先读 `状态.md` 取状态片段（mode/phase/current_volume/current_chapter/就绪态），路由参照=下方「卷循环状态机」。pipeline 不写正文、不做内容转换、不常驻。

**执行模式**：主agent直执。初始化/导入交互（资产清点、缺口确认、落地决策）由主agent完成；生成任务由主agent加载对应子skill执行。禁止派发子agent执行skill生成任务。

## 怎么操作（SOP全内联）

### Step 0：导入/续写模式

> 触发（任一满足）：①用户说"导入/续写/已有/接续/迁移" ②Step 1 初始化时检测到 `正文/` 或 `设计/` 已有文件 ③项目目录已有内容但无 `状态.md`。
> 理念：pipeline 是调度员不是制造者。只做资产清点、文件归位、缺口分析、补跑调度；深度内容转换（正文反推/设计补建）由主agent加载对应skill完成。

**0a 资产扫描**：LS 扫描项目目录（或用户指定源目录）→ 输出原始资产清单（文件名+位置+内容摘要1句话）。

**0b 资产归位**（只归位，不做内容结构标准化）：

| 用户文件（模糊匹配） | → 标准位置 | 标准文件名 | 对应位 |
|:--|:--|:--|:--|
| *意图*/*方向*/*想法*/用户口述 | `素材/` | 用户意图.md / 灵感收集.md | 1 |
| *调研*/*市场*/*赛道*/*排行* | `素材/` | 市场校准.md / 赛道调研.md | 1 |
| *文风*/*DNA*/*笔触*/*风格* | `素材/` | 文风锚定.md | 2e（DNA注入） |
| *decon*/*拆书*/*力量分析* | `素材/` | decon-lite-{书名}.md | 1（底牌） |
| *设定包*/*包配方*/*参考答案* | `素材/` | 参考答案-{书名}/（含包配方.md） | 1（路径C） |
| *改编计划*/*DNA替换* | `素材/` | 改编计划.md | 1（路径C） |
| *命运图*/*立意*/*种子*/*创意* | `立项/` | 01-命运图.md+02-命运图plus.md+03-全书大纲.md | 1 |
| *力量*/*体系*/*骨架* | `设计/` | 力量体系.md+动力引擎.md | 2 |
| *金手指*/*外挂* | `设计/` | 金手指.md | 2 |
| *世界设定*/*地理*/*势力*/*危机*/*民风* | `设计/全书设定/` | 对应维度文件 | 2 |
| *角色库*/*NPC*/*配角* | `设计/角色库/` | 角色库.md | 2 |
| *主线*/*全书卷目录* | `设计/` | 主线.md | 2 |
| *卷舞台*/*卷设定*/*各卷切片* | `设计/卷舞台/` | 卷N-舞台.md | 2b |
| *卷需求*/*brief* | `卷纲/` | 卷N-需求brief.md | 2a |
| *卷纲*/*大纲*/*分幕* | `卷纲/` | 卷N-卷纲.md | 2c |
| *幕白描*/*剧情白描*/*章白描* | `卷纲/` | 卷N-幕M-白描.md | 2c |
| *章纲*/*叙事原子* | `卷纲/章纲/` | ch{NNN}-章纲.md | 2d |
| *正文*/*章节*/ch*/第*章 | `正文/` | ch{NNN}.txt | 2e |
| *白描卡*/*本章记录*（审核沉淀） | `产出/白描卡/` | ch{NNN}.md | 2f |
| *状态快照*/*快照*/*进度* | `产出/` | 状态快照.md | 2f |

操作：匹配不上的归"未分类资产"询问用户映射；.docx 等异构格式 Read 内容→Write 标准位置标准文件名；正文统一编号（`第一章.txt`/`chapter1.md`→`正文/ch001.txt`）；幕白描与审核白描卡易混——含锚点段/叙事流的归 `卷纲/`，含关键数据🔒/爽点钩子的归 `产出/白描卡/`，拿不准问用户；询问用户是否保留原文件。

**文件来源标记**（每个归位文件记入资产清单）：

| 来源标记 | 含义 | 后续处理 |
|:--|:--|:--|
| `user-original` | 用户已有文件，直接归位 | ⚠️需校验 |
| `pipeline-relocated` | pipeline 做了格式转换（.docx→.md 等） | ⚠️需校验 |
| `skill-generated` | 对应skill正向产出 | 正常消费 |

**0c 缺口分析**：归位完成后对照依赖链逐位检查（就绪判定=文件存在，查文件系统）：

| 位 | 就绪判定 |
|:--|:--|
| 1 | `立项/01-命运图.md`+`02-命运图plus.md`+`03-全书大纲.md` 三件齐 |
| 2 | `设计/力量体系.md`+`动力引擎.md`+`全书设定/`（有文件）+`金手指.md`+`角色库/角色库.md`+`主线.md`+`卷舞台/卷一-舞台.md` |
| 2a | `卷纲/卷N-需求brief.md` |
| 2b | `设计/卷舞台/卷N-舞台.md` |
| 2c | `卷纲/卷N-卷纲.md` + `卷纲/卷N-幕M-白描.md`（至少一幕） |
| 2d | `卷纲/章纲/ch{NNN}-章纲.md`（NNN=下一章待写） |
| 2e | `正文/ch*.txt`（current_chapter=最大编号+1） |
| 2f | `产出/白描卡/` + `产出/状态快照.md` |

进度检测：`正文/` 有文件→提取最大章节号，current_chapter=下一章待写；卷号=取 `卷纲/` 与 `设计/卷舞台/` 中最大卷号，无则=1。质量来源检测：user-original/pipeline-relocated→⚠️需校验；skill-generated→✅。输出缺口报告。

**0d 落地Phase决策**（缺口报告+正文进度）：

| 条件 | mode | 落地位 | 说明 |
|:--|:--|:--|:--|
| 正文有+白描卡有+状态快照有 | resume | 2d 或 2e | 状态完整：下一章章纲已拼→2e，未拼→2d |
| 正文有+双文件缺 | resume | 先 0f 调度 review reconstruct→2d/2e | 需补状态文件 |
| 正文无+幕白描有 | import | 2d（outline） | 缺章纲 |
| 正文无+卷纲有 | import | 2c（幕白描） | 缺幕白描 |
| 正文无+卷N舞台有 | import | 2c（卷纲） | 缺卷纲 |
| 正文无+主线有（首喷完） | import | 2a（卷需求brief） | 进卷循环 |
| 正文无+PRD有 | import | 2（stage首喷） | 缺舞台 |
| 全无 | fresh | 1（seed） | 走 Step 1 初始化 |

→ 向用户展示：资产清单（含来源标记）+缺口报告+落地Phase建议+补跑建议清单（0f），**用户确认后**进 0e。

**0e 状态文件重建**：`状态.md` 不存在→按「状态.md 模板」创建；已存在→SearchReplace 更新。字段：mode/phase/current_volume/current_chapter/seed_path（仅路径C项目填）/就绪态按 0c 标 [x]。展示面板可选：老板要求时按 `templates/项目总控.html` 套值导出。

**0f 调度skill补跑**（pipeline 只识别缺口+调度+汇报，不自行做内容转换）：

| 缺口类型 | 调度skill | 做什么 |
|:--|:--|:--|
| 有正文+缺白描卡/状态快照 | pop-review reconstruct | 批量回溯审核：采样逐章白描卡+状态快照 |
| 缺立项/舞台/剧情/章纲文档 | 对应skill（seed/stage/plot/outline） | 读已有文件→按skill方法论校验+补全→标准格式 |
| 已有文档但来源=user-original | 对应skill（用户确认后按需） | 校验→标注缺口或确认达标 |

- review reconstruct 采样：≤10章全审 / 11-30章最近5章+每5章取1章 / >30章最近5章+第一章+每10章取1章。产出 `产出/白描卡/ch{NNN}.md`+`产出/状态快照.md`。
- 设计文档补跑按依赖链顺序：stage（力量体系+动力引擎+全书设定+金手指+角色库+主线+卷一舞台）→ plot（brief→卷纲→幕白描）→ outline（章纲）。用户已有正文但缺剧情文档→plot 从正文反推；用户选跳过 plot 直接续写（降级模式）→在状态快照手动指定下一章核心事件。
- 不调度的情况：素材层文件 pipeline 自行按标准分节重组；文风锚定.md 缺失→提示用户跑 pop-dna-style（非 reconstruct 场景）。
- 补跑建议清单：逐文件一行——文件名：来源=…，状态=…，建议=正常消费/补跑XX skill。用户三选：正常接续/按需补跑/全量补跑。

**Step 0 质量门**：原始资产清单已生成｜归位完成（含来源标记）｜缺口报告已生成｜落地Phase经用户确认｜状态.md 已创建/更新｜补跑建议清单已展示。

### Step 1：初始化（fresh模式）

**前置检测**：执行任何创建前先 LS 扫描——`正文/` 有章节文件或 `设计/` 有 .md 文件→跳转「Step 0 导入/续写」；目录为空或仅有 `状态.md`→继续本步。

1. **创建目录（一次性）**：`素材/`（含 `downloads/`、`知识沉淀/`）+ `立项/` + `设计/`（含 `全书设定/`、`角色库/`、`卷舞台/`）+ `卷纲/`（含 `章纲/`）+ `正文/` + `产出/`（含 `白描卡/`）。创建后 LS 自检全部存在，缺一=初始化失败，补创后才继续。
2. **创建 状态.md**：按「状态.md 模板」写入项目根（mode: fresh / phase: init / current_volume: 1 / current_chapter: ch000 / 全部就绪态标 [ ]）；再简建 README.md（项目信息+目录说明+指向 状态.md）。
3. **展示面板（可选）**：老板要求时按 `templates/项目总控.html` 套 状态.md 值导出；agent 只写 状态.md，不读 html。
4. **首次对话引导**：用户第一次触发且无项目时，先输出 `references/onboarding-guide.md` 引导语（声明本次为功能介绍未执行任务）；用户已明确要开做可跳过。
5. **路由 Phase 1**：加载 pop-seed 按其 SKILL.md 执行（三输入路径 A/B/C → 与用户共创三层：L1命运图→L2命运图plus→L3全书大纲）。

**Step 1 质量门**：目录齐全+状态.md 落盘｜README 落盘。

## 卷循环状态机（2a-2g，路由参照）

新书流程：`init → 1(seed) → 2(stage首喷，含卷一舞台) → 卷循环`。卷循环每卷一圈：

| 位 | 干什么 | skill | 产出 | 完成→下一位 |
|:--|:--|:--|:--|:--|
| 2a | 卷需求brief（订货单+方向盘） | pop-plot 任务A | `卷纲/卷N-需求brief.md` | 2b（卷一→2c，舞台首喷已含） |
| 2a+ | 卷级调研（轻量，brief有增量需求时跑） | pop-research 模式2 | `素材/卷级调研-卷N.md` | 2b |
| 2b | 卷舞台刷新（卷二起每卷一次） | pop-stage 模式B | `设计/卷舞台/卷N-舞台.md`+角色库增量+贯穿层append | 2c |
| 2c | 卷纲→幕白描（七查绿灯才交付） | pop-plot 任务B→C | `卷纲/卷N-卷纲.md`→`卷纲/卷N-幕M-白描.md` | 2d |
| 2d | 章纲拼接（每章一文件） | pop-outline | `卷纲/章纲/ch{NNN}-章纲.md` | 2e |
| 2e | 正文渲染（2000-2500字/章） | pop-write | `正文/ch{NNN}.txt` | 2f |
| 2f | 审核+沉淀（PASS/REJECT） | pop-review | `产出/白描卡/ch{NNN}.md`+`产出/状态快照.md` | PASS→2d/2e下一章；REJECT→2e重写本章；本卷末章PASS→2g |
| 2g | 卷末盘点 | 主agent | 状态.md：current_volume+1、卷循环四项就绪态清零 | 回 2a |

**幕内滚动**：推荐「2c产幕N → 2d拼幕N章纲 → 2e/2f逐章 → 2c产幕N+1」，让后续幕吸收正文沉淀。

**2g 卷末判定**：卷纲预算章数耗尽+卷末三件套（面板大爆+新地图解锁+下卷钩子）兑现→本卷完。

**状态.md 更新协议**（谁干活谁更新，只更新涉及字段，不全量替换）：

| 时机 | 更新 |
|:--|:--|
| 各 skill 完成 | phase 推进到状态机下一位 + updated_at + 就绪态对应项 [x] + 最近产出追加一行 |
| seed 完成 | 另更新 seed_path + 书目（book_name/one_line） |
| write/review 每章 | current_chapter+1（review PASS 后），phase 在 2d/2e/2f 间流转 |
| 2g 卷末 | current_volume+1 + 需求brief/卷舞台/卷纲/幕白描四项清零 + phase=2a |

pipeline 只在初始化/导入时写 phase；日常推进由各 skill 完成后按本表更新。

## 红线

1. **只安装不生产**：pipeline 不写正文/不设计/不审核；深度内容转换（正文反推/设计补建）调度对应 skill 完成。
2. **就绪判定查文件系统**：Phase 推进条件=产出文件存在（不信口头声明）；依赖链（立项→舞台→brief→卷纲→幕白描→章纲→正文→双文件）不可跳。
3. **user-original/pipeline-relocated 资产必须标⚠️需校验**：未经对应 skill 校验的设计层用户文件不得直接消费。
4. **状态源**：`状态.md`=唯一机器状态源，agent 每轮只读写它；`项目总控.html` 为展示面板，按需导出，agent 不读 html、不承担渲染成本。
5. **状态.md 更新走协议**：谁干活谁更新，只改涉及字段；pipeline 只在初始化/导入时碰 phase。
6. **读文件用宿主原生读取工具**。
