# character

> 起点角色库引擎。Phase 3.5——world完成后、plot之前的必经加工站。v1.4.0：新增关系网络结构化设计+骨骼比喻+主角-对手轴+功能性人物派生。

---

## 做什么

输入：力量体系.md + 动力引擎.md + 主角设计.md + 设计/全书设定/（势力.md+全书配角.md）+ 创意.md + ch001.txt
输出：`设计/角色库/角色库.md`（角色总表+角色详细卡+增量更新日志）

**定位**：character不前置建库——world完成后根据全书设定规划分幕，按分幕设计出场角色清单按需批量塑造。角色库是write的角色唯一源。

**上下游**：上游seed（骨架+主角+创意+首章）+world（全书设定）→ character → 下游plot（消费角色库写剧情）+write（角色唯一源）+review（一致性检查）。

---

## 怎么操作（SOP骨架）

> execution.mode: 加载底牌→按分幕设计角色清单→逐个塑造角色卡→落盘。
> 强弱加载：SKILL.md=完整骨架（必读），steps/step2.md=建角色库详细操作（强加载全文），力量体系.md/动力引擎.md/主角设计.md/全书设定=项目空间底牌（Step 1强加载），创意.md/ch001.txt=辅助参考（弱加载）。

### Step 0：交互式角色库决策 → `steps/step-0-interactive.md`
**v1.2.0新增，v1.4.0重构C2轮**。在角色库生成前，通过2轮交互式决策（C1 NPC roster+反派设计 / C2 关系网络结构化设计）采集用户偏好，产出`设计/角色库/角色库决策表.md`。两轮均核心必答。C2轮使用骨骼比喻+主角-对手轴+功能性人物派生方法论。后续角色库生成必须遵守决策表。

### Step 1：加载底牌（内化）
读动力引擎.md（攀登方式分层）+力量体系.md（力量体系坐标系）+主角设计.md+全书设定/势力.md+全书设定/全书配角.md+创意.md+ch001.txt。力量体系.md+动力引擎.md缺失则报错不执行。

### Step 2：按分幕设计建角色库 → `steps/step2.md`
规划第一卷分幕（4-5幕）→提取角色清单→塑造主角深度卡+配角池+反派卡→落盘角色库.md。

## 红线

1. **读取协议**：执行前先读SKILL.md获取骨架+底牌清单，再强加载steps/step2.md获取详细操作。力量体系.md+动力引擎.md缺失则报错不执行——骨架是标注攀登方式类型和等级坐标的必要依据。禁止跳过SKILL.md直接读step文件。
2. **每个具名角色必须标注攀登方式类型**——与动力引擎.md动力引擎组成3（众生攀登方式分层）对齐：有资源型/没资源型/爬到顶层型/掉下来型。行为逻辑由攀登方式决定。不标注=废卡。
3. **每个具名角色必须填写行为逻辑三源+人物真相**——原生家庭/教育创伤/亲密关系三源解释行为逻辑，表象vs真相通过矛盾揭示。缺任一项=角色是空壳=废卡。
4. **角色等级坐标必须与力量体系对齐**——引用力量体系.md主养成线阶位，不自行发明等级。不对齐=废卡。
5. **角色库是write的唯一角色源**——write所有角色信息以角色库为准，不得创造矛盾角色。write引入新角色或更新状态时必须同步回写角色库。
