# character

> 起点角色库引擎。Phase 3.5——world完成后、plot之前的必经加工站。character 是全部"人"的唯一产出方：消费 PRD 人物方向句，自己展开完整主角（深度卡）+金手指+全书角色版图+按分幕批量塑造配角/反派池。角色库是 write 的角色唯一源。v3.0.0：steps 两件全合入单文件精炼（-30%）；塑造要求三处重复归一为一份通用清单。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 做什么

**输入**：立项/01-立项PRD.md（「人物」方向句：主角定位/身份/核心动机/金手指方向/爽感矛盾）+ 设计/力量体系.md（等级坐标）+ 设计/动力引擎.md（攀登方式分层）+ 设计/全书设定/（势力人物.md+各卷切片.md）。PRD人物方向句+力量体系.md+动力引擎.md缺失则报错不执行。

**输出**：`设计/角色库/角色库.md`（角色总表+详细卡+增量更新日志）+ `设计/金手指.md`（主角金手指展开）+ `设计/角色库/角色库决策表.md`（Step 0 产出）。

**上下游**：上游 seed（PRD人物方向句）+world（力量体系+动力引擎+全书设定）→ character → 下游 plot（消费角色库写剧情）+write（角色唯一源）+review（一致性检查）。

---

## 执行模式：主agent直执

Step 0 是用户交互决策（C1/C2），Step 1-2 是生成+落盘——全程主agent直执。无可派子agent的只读环节（生成本身需要写权限，交互需要用户在场）。

> execution.mode: 交互决策（Step 0）→ 加载底牌（Step 1）→ 展开主角+金手指+全书角色版图+按分幕建库（Step 2）。

## 怎么操作（SOP全内联）

### Step 0：交互式角色库决策 → `设计/角色库/角色库决策表.md`

角色库生成前 2 轮交互决策采集用户偏好，给选项不给空白（每轮 2-3 个结构化选项+自定义入口）。**NPC roster 定下后，plot 的 Boss 设计和 NPC 登场顺序都基于此。**

**C1 NPC roster+反派设计（核心轮·必答）**：读势力人物.md（活跃层NPC+势力结构）+动力引擎.md（众生攀登4类分层），生成 3 个方案——A丰富型（8-10人，多层反派梯队）/B精简型（5-7人，集中反派深度刻画）/C反转型（6-8人，含盟友/中立方反转）。每个方案标注核心NPC清单/反派梯队（底层→中层→关底）/关系网/引入节奏/参考书角色结构。

**C2 NPC关系网细节（可选轮·可跳过）**：基于选定 roster 提 2-3 个关系网方案（核心关系/暗线关系/冲突关系）。用户说"跳过"→按角色库模板自动生成。

**决策表落盘**：C1选定方案+核心NPC+反派梯队+人数；C2三关系（或跳过）；后续约束声明（角色库生成必须遵守本决策表，调整需重走对应轮次）。**决策表是角色库生成的硬输入。**

### Step 1：加载底牌（内化）

读立项/01-立项PRD.md「人物」方向句+动力引擎.md（攀登方式分层）+力量体系.md（坐标系）+全书设定/势力人物.md+各卷切片.md。

### Step 2：展开主角+金手指+全书角色版图+按分幕建角色库

**2a 主角深度卡**（从PRD人物方向句展开）：攀登方式类型（主角通常"没资源型"或"掉下来型"——从底层爬起，金手指加速）+起点阶位（力量体系主养成线对齐）+性格（具体行为倾向，✅"嘴硬心软，从不承认关心别人但总在暗地帮忙" ❌"善良勇敢聪明"）+小传≥200字+成长数据（起点→终点阶位+关键转折）+口头禅+语言指纹。

**语言指纹**（供write写对话直接消费，不靠agent猜；核心判据=去掉说话人标签仍能认出谁是谁）：句式偏好（长短句/反问/命令式）+用词偏好（粗俗/文雅/方言/术语/标志用词）+语气节奏（急促/缓慢/情绪外露/压抑）+对话标志2个（辨识度最高的特征，如"①每句话带数字 ②紧张时反而笑"）。

**2b 金手指 → `设计/金手指.md`**（从PRD金手指方向展开，world不落盘金手指）。三约束：key非生成器（是钥匙/赋能不是资源机器）/赋能不越级（当前阶位内更强，不跳阶）/限制显性声明（代价/冷却/副作用，限制提供张力）。格式：一句话定义/机制展开（触发/使用/获取）/赋能范围/限制与代价/成长路线（与主养成线对齐）。

**2c 全书角色版图（广度先行·圈定全书格局，深度后置）**：从PRD+各卷切片（扩张阶梯）+力量体系（阶位顶点）圈定——①主角弧线终点（起点→终点阶位+终卷主角形态+全书级关键转折）②核心配角表（全书级跨卷：角色/定位[情感锚点/引路人/...]/势力/登场卷/关系基调，只立骨架分幕时深做）③跨卷反派表（敌人阶梯：角色/层级[街头/地方/执法/幕后金主]/登场卷/冲突必然性[攀登方式差异导致]/弱点；含全书终极对手，第一卷只暗线伏笔）④势力关系网（势力/角色归属/主角立场/冲突合作点）。**world势力人物.md只提供势力组织+代表人物一句话锚定，character消费它填人。**

**2d 规划分幕+提取角色清单**：从各卷切片提取第一卷设定范围（力量阶位范围/碰撞势力层级[通常前2层]/主要危机）→规划4-5幕（每幕8-12章，标注场景区域/势力层级/出场角色需求）。角色清单来源：动力引擎组成3（每种攀登方式代表角色候选）+势力人物.md（敌人4层梯度+势力代表人物）+金手指.md（限制=主角弱点来源=反派可利用点），去重合并按分幕组织。每角色初始信息：角色名/定位（主角/配角/反派·层级）/攀登方式类型/等级坐标/势力归属/首次出场幕。

**2e-2f 配角卡+反派卡**（按分幕实际出场角色数逐个塑造）：

**通用塑造要求**（每张卡必备）：攀登方式类型标注（配角决定行为逻辑——有资源型靠资源行动/没资源型靠命换投机；反派通常"爬到顶层型"垄断者或"有资源型"压制者）+等级坐标对齐（反派阶位通常高于主角当前阶位）+势力归属锚定+独立动机（配角非工具人，欲望与主角部分重合部分冲突；反派有"为什么变成这样"的过去）+性格细节超出预期（如冷面杀手怕猫/反派大佬按时给母亲打电话）+小传≥200字+口头禅+语言指纹。

**反派额外必备**：性格弱点（主角可利用）+与主角冲突必然性（攀登方式差异导致，非碰巧挡路）+敌人层级标注（街头层=一卷前半主力对手实力接近/地方势力层=一卷后半需越级对抗/执法系统层=暗示存在二卷碰撞/幕后金主层=终极对手一卷暗线）。

**配角类型参考**（分幕设计决定，非固定模板）：情感锚点/幽默担当/引路人/战斗伙伴/信息源/对手型（非反派竞争关系）。

## 红线

1. **底牌缺失即报错**：力量体系.md+动力引擎.md缺失则报错不执行——骨架是标注攀登方式类型和等级坐标的必要依据。
2. **每个具名角色必须标注攀登方式类型**（与动力引擎.md组成3对齐：有资源/没资源/爬到顶层/掉下来型）。行为逻辑由攀登方式决定。不标注=废卡。
3. **角色等级坐标必须与力量体系对齐**——引用力量体系.md主养成线阶位，不自行发明等级。不对齐=废卡。
4. **角色库是write的唯一角色源**——write所有角色信息以角色库为准；write引入新角色或更新状态时必须同步回写角色库（增量更新日志）。
5. **金手指从PRD人物方向句展开，不喧宾夺主**——服从PRD金手指方向（key非生成器/赋能不越级/限制显性声明），是主角的加速器而非主角本身。
6. **广度先行·深度递归**——先圈定全书角色版图再深做第一卷分幕；后卷角色届时递归塑造。禁止只做第一卷——否则后期角色和全书关系网对不上。
7. **Step 0 选项红线**：每轮必须给2-3个结构化选项+自定义入口；选项必须在世界设定约束内（攀登方式和等级匹配力量体系+动力引擎）；C1必答C2可跳；决策表是硬输入。
