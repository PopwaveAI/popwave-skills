# Step 0 - 交互式角色库决策

> **v1.2.0新增**：在角色库生成之前，通过2轮交互式决策采集用户偏好，产出`角色库决策表.md`。
> **核心原则**：给选项不给空白——每轮提供2-3个结构化选项+1个自定义入口。
> **杠杆位置**：NPC roster定下后，plot的Boss设计和NPC登场顺序都基于此。

## 前置条件

- Phase 3 world完成
- 全书设定/ + 世界圣经.md 齐全
- 力量体系.md + 动力引擎.md（众生攀登分层）+ 主角设计.md 齐全

## 产出

`设计/角色库/角色库决策表.md`——后续角色库生成的硬输入

## 2轮交互决策

### C1 NPC roster+反派设计（核心轮·必答）

**底牌消费**：全书设定/ + 世界圣经.md + 动力引擎.md众生攀登分层 + decon-plot NPC登场效果（如有）

**Agent动作**：
1. 读取世界圣经，提取活跃层NPC+势力结构
2. 读取动力引擎.md，提取众生攀登方式分层（4类）
3. 生成3个NPC roster方案，每个标注：核心NPC清单/反派设计/关系网/引入节奏

**选项生成规则**：
- 方案A：丰富型（8-10人，多层反派梯队，参考主流网文角色结构）
- 方案B：精简型（5-7人，集中反派，聚焦少数角色深度刻画）
- 方案C：反转型（6-8人，含盟友反转/中立方反转，增加意外性）

**输出格式**：
```
## C1 NPC roster+反派设计

基于{世界结构}，提供3个NPC roster方案：

A) {方案A名}（{人数}人）
   → 核心：{NPC1(定位)} / {NPC2(定位)} / {NPC3(定位)}
   → 反派：{反派1(底层)} → {反派2(中层)} → {反派3(关底)}
   → 关系网：{核心关系}
   → 参考：{参考书角色结构}

B) {方案B名}（{人数}人）
   → ...

C) {方案C名}（{人数}人）
   → ...

请选择，或调整NPC清单。
```

**影响标注**：NPC roster定下后，plot的Boss设计和NPC登场顺序都基于此。

### C2 关系网络结构化设计（核心轮·必答）

> **v1.4.0重构**：从"简单关系网方案"升级为"关系网络结构化设计"。
> 方法论详见 `references/关系网络与功能性人物.md`（强加载）。

**底牌消费**：C1选择的roster + 世界圣经.md势力结构 + 主角设计.md（主角缺什么）

**Agent动作**：
1. 基于选定的roster，确定**主角-对手轴**（敌对/竞争/镜像型）
2. 从主角需求派生**功能性人物**（盟友/导师/同伴/恋人/信息源/变数）
3. 检查角色划分（生旦净末丑或坦克/辅助/DPS）——功能是否缺失或重叠
4. 提出2-3个关系网络方案，每个标注：主角-对手轴+功能派生表+随机关联+动态变化

**选项生成规则**：
- 方案A：稳定型（关系网络变化少，适合快节奏爽文——敌我分明）
- 方案B：动态型（≥2个关系变化，适合中后期——盟友变敌人/信息源变恋人）
- 方案C：镜像型（对手轴为镜像型，适合深度向——主角和对手一体两面）

## 决策表产出格式

```markdown
# 角色库决策表
> 交互完成时间：{YYYY-MM-DD HH:mm}

## C1 NPC roster+反派设计
- 方案：{用户选定的方案}
- 核心NPC：{清单}
- 反派梯队：{清单}
- 人数：{N人}
- 选择：{A/B/C/自定义}

## C2 关系网络结构化设计
- 主角-对手轴：{对手名} / {敌对/竞争/镜像}型 / {对立点}
- 功能派生表：{盟友/导师/同伴/恋人/信息源/变数 的角色清单}
- 随机关联：{≥3条配角间关系}
- 关系动态变化：{≥1条变化轨迹}
- 选择：{A/B/C/自定义}

## 后续约束
- 角色库生成必须遵守本决策表（含关系网络结构）
- 如需调整，需重新走对应轮次的交互
```

## 红线

1. **每轮必须给选项**——必须给2-3个结构化选项
2. **每轮必须有自定义入口**——选项末尾必须有"或调整XXX"
3. **选项必须在世界设定约束内**——NPC的攀登方式和等级必须匹配力量体系.md+动力引擎.md
4. **核心轮不可跳过**——C1和C2均必答（C2从v1.4.0起升级为核心轮）
5. **决策表是角色库生成的硬输入**
