# pop-qidian-outline

> 开书前立项：先访谈需求，再读题材弹药，产出五节立项融合稿、快线设定摘要与人物卡、卷 1 卷纲和前 10 章章纲，最后可选写第 0 章样张。
> 本技能只规定流程、文件契约与检查项，不规定题材、结构、风格或审美偏好。故事内容由用户决定；用户没决定的，由 agent 出候选，交用户选。
> 当前版本 v1.0.2。版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 本技能负责什么

输入：用户的一句话、一个角色、一个场面、一段设定、一份外部大纲，或者什么都没有。

输出六件，另加可选的第 0 章样张：

- `立项/故事.md`：五节立项融合稿——故事核心、金手指、世界观、核心人设、分卷设计，外加用户偏好卡、自检与待定。
- `设定/世界.md`：快线版设定摘要——世界底线、权力阶梯、经济锚点、文风关键词；只写写正文要用的，不写四份长档。
- `人物/人物卡.md`：快线版人物卡——主角、核心配角、对手阶梯；只写写正文要用的。
- `剧情/卷1-卷纲.md`：第一卷卷纲，含卷剧情、卷目标、卷级敌人、卷末变化、分章推进。
- `章纲/ch001.md`…`ch010.md`：前 10 章章纲，每章五栏。
- `立项/brief候选.md`：2-3 个定位候选全文，供用户挑选或合成。
- `立项/第0章试写.md`（可选）：用户选定后写的一章样张。

**边界**：

- 快线版设定摘要与人物卡由本技能写；用户要精修时，在本技能里补长档细节，不另开技能。
- 前 10 章章纲与卷 1 卷纲由本技能写；第 11 章起的章纲与后续卷纲也由本技能续补，一次只补 10 章。
- 不写正式正文——归 `pop-qidian-write`。第 0 章只用 `popwave-write-body` 写样张，样张不进 `正文/`。
- 不做拆书——归 `pop-decon`。
- 不新增 `立项/00-立项融合稿.md`；五节稿就写进 `立项/故事.md`。

**与下游的契约**：

- 精修时，本技能读 `故事.md` 的「金手指设计」「世界观」「核心人设」，补长档设定与人物细节，不重新发明方向。
- 本技能读 `故事.md` 的「分卷设计」，续补第 11 章起的章纲与后续卷纲，不改卷目标、卷级敌人、卷末变化。
- 本技能把「立项」定义为五节齐全 + 自检完成。
- **默认路径**：`pop-qidian-outline` → `pop-qidian-write`。本技能已给设定摘要、人物卡、卷 1 卷纲与前 10 章章纲，正文技能可直接开写。

## 五节立项稿是什么

不是参数表，是一份能让编辑、作者和下游都读懂的书说明。五个部分固定：

| 节 | 写什么 | 判断锚点 |
|:--|:--|:--|
| 故事核心 | 一句话、一段话、主线、支线、剧情循环 | 合上材料，150 字能讲清「谁、要什么、谁挡着、怎么推进、结局往哪去」 |
| 金手指 | 名称、机制、限制、日常用法、与主线咬合 | 至少一条限制把主角逼向主线动作；不是许愿机 |
| 世界观 | 时代逻辑、差异层、权力阶梯、社会规则、边界、经济 | 读者能说出「这个世界逼人做什么」；数值有来源 |
| 核心人设 | 主角 7 项、配角 4-6、对手阶梯 | 每个对手有凭仗/弱点/击败后收益；量级逐卷升级 |
| 分卷设计 | 每卷七栏 + 卷内循环 + 时代节点 | 能复述每卷；卷数对得上；不写分章 |

完整骨架见 `templates/立项融合稿.tpl.md`。

**合格判据（五条，缺一条即未完成）**：

1. 五节齐全，配额达标，未确认项标「待定」。
2. 偏好卡 12 项逐项有落点，未满足的写明原因。
3. 金手指限制能被每一卷用到；没有一卷使用被禁止的能力。
4. 每卷七栏齐全；每条支线四栏齐全；每个对手三栏齐全。
5. 数值/政策有来源或标「待核」；「待核」不当定论。

## 流程

### Step 0 接住用户手上已有的

1. 逐字收下用户本轮原话，不摘要、不改写。
2. 拆出已有元素：赛道、标签、主角、场面、终点、感觉、对标书、外部大纲。
3. 读项目已有资产：旧立项稿、旧大纲、拆书成果、文风档、历史正文、`状态.md`。已确认的不重问。
4. **旧版兼容**：`立项/故事.md` 已存在且只有四段时，先读、先报缺口，再问用户「是否升级为五节」；用户不确认就只补缺失节，不覆盖已有内容。

收完直接进访谈，不播报流程，不说「你手上已有 X 缺 Y」这类话。

### Step 1 需求访谈（最多 3 轮）

读 `references/访谈问题库.md`，按三轮执行：

- **轮一·定位**：平台与篇幅、主分类与标签、对标与「读者图什么」。
- **轮二·偏好**：爽点类型、雷点/禁区、主角底线与感情线。
- **轮三·方向**：差异化方向、终点期待、金手指偏好。

每题 2-4 个候选 + 「其他」；用户已回答的不重问；跳过的标「待定」，不阻塞。访谈结束把 12 项写入 `故事.md` 头部「用户偏好卡」。

**用户一上来就给完整外部大纲**：跳过访谈，先按五节拆读，只问缺口（缺哪节、哪个数值要核、哪个偏好没写）。

### Step 2 读题材弹药

1. 读 `references/题材弹药/00-索引.md`，按用户主分类找到对应文件。
2. 有文件：读九栏，挑 5-8 条「可打的弹药」摆给用户——开局 2-3 条、破局 2-3 条、循环 2 条、金手指/替代驱动 2 条。
3. 没文件：由主 agent 做一轮最小检索（先 wiki `https://wiki.popwave.cn`，再 web；最多 5 个检索项，回传 ≤30KB），补 `references/题材弹药/{赛道}.md`，至少填「定义/读者期待/常见套路/反套路/雷点」五栏；其余标「待补」。当前环境若挂载了 `pop-snow-research`，可优先派它；没挂载就主 agent 自己查，不因缺 skill 卡住。
4. 用户选 3-5 条，写进偏好卡「选定弹药」；用户自带桥段/设定/对标，原样记入，不改写。

不一次倒整张卡，不替用户选。

### Step 3 定位候选

调 `popwave-write-idea` 出 2-3 个定位候选，每个 ≤200 字，必须含：

- 一句话定位（这本书在货架上长什么样）
- 差异化（与同类最大的不同）
- 终点（最后站到哪）
- 金手指一句话（含一条硬限制）
- 主角立身一句话（他是谁、要什么、谁挡着）

`brief`：给 2-3 个定位候选，每个写清上述五项。
`context`：用户原话（逐字）、偏好卡、选定弹药、对标摘录。
`constraints`：候选之间必须换世界、换主角位置或换终点；只换措辞不算；不写第一章细节；每份 ≤200 字。

候选全文先写入 `立项/brief候选.md`，一个候选一节；Ask 选项给三个候选，每项带 `detail`：用 150-300 字写清「主角是谁、开局冲突、主线爽点、终点」，并传 `critical: true`。用户可单选、可合成第三版；合成版先写入文档再确认。brief 选择超时不要自动选推荐：停下告诉用户未选，等用户回复后再继续。

### Step 4 五节立项稿（分段生成，禁止一次调完）

按顺序调工具，每节单独一次；每节最多重试 2 次，仍不达标标「待补」并记录，不只嘴上说完成。

**4a 故事核心** `[工具:idea]`

- `brief`：写故事核心五小节——一句话梗概、一段话梗概、主线设计、支线设计、剧情循环；配额照模板。
- `context`：用户原话、偏好卡、选定弹药、选定的定位候选全文、对标摘录。
- `constraints`：一句话 ≤60 字；一段话 300-500 字、六要素齐全；主线四阶冲突；支线 2-4 条、每条四栏；循环 4-6 拍；不写正文句、不写对白。

**4b 金手指 + 世界观 + 人设** `[工具:setting]`

- `brief`：写立项稿的「金手指设计」「世界观」「核心人设」三节，只写决策级，不写长档；配额照模板。
- `context`：4a 全文、偏好卡、选定弹药、题材弹药文件全文。
- `constraints`：金手指至少一条限制逼出主线动作；世界观 4 级权力阶梯；经济数值每条带来源或「待核」；人设用占位符（主角/女主/对手A/终敌），不取实名；不新增 4a 没有的方向。

**4c 分卷设计** `[工具:outline]`

- `brief`：按 4a/4b 排 N 卷卷级设计，每卷七栏 + 卷内循环 + 时代节点；不写分章。
- `context`：4a/4b 全文、偏好卡、目标卷数、题材弹药中的分卷阶梯样例。
- `constraints`：卷数 = 用户确认值（未确认默认 10）；每卷 400-600 字；对手量级逐卷升级；不发明 4a/4b 没有的势力与能力。

**4d 合稿**

主 agent 把工具产出原样填入 `templates/立项融合稿.tpl.md`，只做四件事：格式、配额、去重、一致性检查。不自己重写故事；工具产出缺哪节就回哪一步补。

**4e 快线设定摘要 + 人物卡** `[工具:setting]`

- `brief`：按 `故事.md` 的世界观、金手指、人设，写快线版 `设定/世界.md` 与 `人物/人物卡.md`，只写正文要用的，不写四份长档。
- `context`：`故事.md` 全文、偏好卡、题材弹药文件全文。
- `constraints`：`设定/世界.md` 含世界底线 3 条、权力阶梯 4 级、经济锚点 3-5 条、文风关键词 3 个；`人物/人物卡.md` 含主角 5 项（身份/目标/能力与限制/说话风格/底线）、配角 3-5 人、对手 3 档；不新增 本技能 未确认的设定。
- 产出原样落盘，主 agent 只做格式与一致性检查。

**4f 首批章纲** `[工具:outline]`

- `brief`：按 `故事.md` 的卷 1 与 `设定/`、`人物/`，写 `剧情/卷1-卷纲.md`（卷剧情/卷目标/卷级敌人/卷末变化 + 分章推进）和 `章纲/ch001` 到 `ch010`（每章五栏）。
- `context`：`故事.md` 全文、`设定/世界.md`、`人物/人物卡.md`、题材弹药中的分卷阶梯样例。
- `constraints`：只写前 10 章，不排后续卷；每章五栏——本章目标/冲突/事件 3-5 条/转折/章末钩子；不改卷目标、卷级敌人、卷末变化；不写对白、心理与结尾意象。
- 产出落 `剧情/卷1-卷纲.md` 与 `章纲/ch001.md`…`ch010.md`。

### Step 5 门禁

任一不过，回对应步骤补，不进入第 0 章或正文。

1. **需求匹配**：偏好卡 12 项逐项写「落在哪一节」或「未满足·原因」。
2. **一致性**：金手指限制 vs 每卷解法；时代红线 vs 产业形态；对手量级逐卷升级；卷数对账。
3. **事实回源**：每个数值/政策/物价有来源或标「待核」；「待核」不得写成正文定论。
4. **可复述**：合上材料，150 字讲清「谁、要什么、谁挡着、怎么推进、结局往哪去」。
5. **可写性**：每卷七栏齐全；每条支线四栏齐全；每个对手三栏齐全。
6. **快线可开写**：`设定/世界.md`、`人物/人物卡.md` 存在且对上 本技能；`章纲/ch001` 到 `ch010` 齐全，每章五栏；`剧情/卷1-卷纲.md` 的分章推进正好 10 章。缺一不进 `pop-qidian-write`。

### Step 6 第 0 章试写 `[工具:body]`

五节稿定稿后再写第 0 章。第 0 章不在正文章序里，不是本书真实剧情。

- `brief`：按 `立项/故事.md` 的定稿稿，写第 0 章样张。开篇三句内交代具体的人、具体的处境、一个不对劲的信号；本章有一个完整的小冲突并收束；章末留下必须翻页的钩子；不解释设定、不写背景综述。
- `context`：`立项/故事.md` 全文、用户原话（逐字）、对标书开局原文（整段）、赛道/标签/篇幅。
- `constraints`：1500-2000 汉字；视角与文风照对标；人物名与专名可临时起，统一标「试写临时名」；不写章标题以外的说明文字。

**抓人判据（三条，缺一条重写）**：

1. 前三句里出现具体的人、具体的麻烦、一个不对劲的信号。
2. 本章有一个明确的压力，并在章末兑现或升级。
3. 读完想翻下一章。

调子不对时只改开头：先重写开头 600 字让用户确认，调子对了再续完全章，不整章重跑。落盘 `立项/第0章试写.md`，文件头三行固定：

```
> 试写稿：不作为本书真实剧情，不进正文。
> 人物名与设定为临时，正式以本技能的 `设定/世界.md` 与 `人物/人物卡.md` 为准。
> 写作日期：
```

用户明确说不看试写，可跳过本步，并在 `故事.md` 交接段记「第 0 章试写：跳过」。

### Step 7 交接

在 `故事.md` 末尾写交接段：

- **已锁定项**：用户拍过板、后面不许改的。
- **待定项**：明确留白，交给下游或用户后续决定。
- **用户原话**：不可改写的句子，原样保留。
- **下一步（快线）**：直接 `pop-qidian-write`，按 `章纲/ch001`…`ch010` 写第一批 3-5 章，写完自动拼成 `成稿/第N批.md`。
- **下一步（精修）**：要加深设定或补第 11 章以后的章纲时，回到本技能的大纲精修模式。

下游只读 `故事.md`，不读本技能。

## 红线

1. **不一次调完五节**：必须 4a→4b→4c→4d 分段；一次生成容易卷数丢失、金手指与分卷打架。
2. **只排前 10 章**：卷 1 卷纲与前 10 章章纲由本技能写；第 11 章起与后续卷纲由本技能续补，不一次排全书。
3. **不写长档**：世界观、人设、金手指只到决策级；细节在本技能内补。
4. **不做万能金手指**：没有限制的金手指不许通过门禁。
5. **不把「待核」当已核**：没有来源的数值不写成定论。
6. **不覆盖旧稿**：旧版四段 `故事.md` 只升级、不覆盖；用户不确认就只补缺口。
7. **不替用户拍板**：推荐项只是降低回答成本；用户不选，推荐不算数。
8. **不发明用户没选的弹药**：题材卡里的条目只有被用户选中才进入立项稿。
