# 状态.md 更新协议（单源）

> 本文件是 `状态.md` 所有更新操作的唯一规范。初始化创建（pipeline Step 1）、导入重建（pipeline Step 2）、Phase 推进更新（seed/world/character/plot 完成后 / write 主agent验收通过后 / review 落盘后）都读本文件，禁止在其他文件复述字段表（防多源漂移）。
> 加载时机：任何 状态.md 更新时。
> 源文件 = 项目根 `状态.md`（唯一机器状态源）。`项目总控.html` 是仅供老板查看的展示面板，agent **不读它、不直接改它**；老板要看时由 agent 套 状态.md 值按 `templates/项目总控.html` 导出。

**只更新本次操作涉及的字段，不全量替换。**

---

## 1. 初始化创建字段（fresh 首次落盘时）

读模板 `templates/状态.md` 写入项目根后，更新：

| 字段 | 替换值 |
|:--|:--|
| project_name | `{用户给的项目名}`（保留 "未命名项目" 若用户未给） |
| genre | `{用户赛道方向}`（未指定则保留"待指定"） |
| created_at / updated_at | `{YYYY-MM-DD HH:mm}` |

## 2. 导入重建字段（import/resume 落地Phase后）

| 字段 | 替换值 |
|:--|:--|
| mode | `{import/resume}` |
| phase | `{落地Phase}` |
| current_chapter | `{正文最大编号+1}`（无正文则 ch000） |
| project_name / updated_at | 同 §1 |

同时把已就绪 Phase 对应的就绪态字段改 `[x]`。

## 3. 推进更新字段（每次 Phase 完成后，由对应 skill 更新）

### 3a. 通用（每次必更）

| 操作 | SearchReplace 示例 |
|:--|:--|
| 更新 phase | `phase: phase0` → `phase: phase1` |
| 更新时间戳 | `updated_at: 旧时间` → `updated_at: {当前时间}` |
| 更新 next_step | `next_step: 旧值` → `next_step: {下一步}` |

### 3b. 就绪态标记（按 phase 产出更新）

| Phase 完成 | 就绪态字段改 [x] |
|:--|:--|
| Phase 0 | 用户意图、赛道调研、参考书、笔触DNA、decon-lite（按实际产出） |
| Phase 1 | 立项PRD |
| Phase 3 | 力量体系、动力引擎、全书设定 |
| Phase 3→3.5 | DNA综合 |
| Phase 3.5 | 金手指、角色库 |
| Phase 4 | 主线、卷纲 |

写法：`用户意图[ ]` → `用户意图[x]`

> **Phase 5→6 写审循环**：只更新 current_chapter（上一章写完后 +1）和 next_step，**不改 phase 值**（Phase 5/6 已在循环中交替）。

### 3c. 书目（Phase 1 seed 产出后）

- `book_name` / `one_line`：`待seed产出` → `{实际值}`

### 3d. 流派（Phase 5 开始时）

- `write_skill`：`待Phase 5指定` → `pop-qidian-write（流派: {流派名}）`

### 3e. 最近产出追加（每次 Phase 完成都追加）

- 在 `## 最近产出` 下追加一行 `- {Phase名}: {产出文件路径} | {时间}`
