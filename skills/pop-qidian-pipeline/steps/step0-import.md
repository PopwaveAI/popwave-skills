# Step 0: 导入/续写模式

> 当用户已有历史资料/设定/正文时，将已有资料标准化转换为 pipeline 标准格式，重建项目状态并路由到正确Phase。
> 核心理念：这不是"检测+跳Phase"，而是"检测→标准化转换→补缺→路由"的完整初始化过程。

## 触发条件（任一满足即进入本Step）

1. 用户明确说"导入/续写/已有/接续/迁移"
2. Step 1初始化时检测到 `正文/` 或 `设计/` 已有文件
3. 项目目录已有内容但无项目总控.html

---

## 执行

### 0a. 资产扫描

用LS扫描项目目录（或用户指定的源目录），列出所有已有文件。

→ 输出：**原始资产清单**（文件名 + 位置 + 内容摘要1句话）

### 0b. 资产标准化转换

> 这是核心步骤。将用户的非标准文件逐个转换为 pipeline 标准格式：标准文件名 + 标准目录位置 + 标准内容结构。

#### 0b-1. 文件名+目录归位

将用户文件映射到标准位置并重命名：

| 用户文件（模糊匹配） | → 标准位置 | 标准文件名 | 对应Phase |
|:--|:--|:--|:--|

| *decon* / *拆书* / *力量分析* | `素材/` | `decon-lite-{书名}.md` | Phase 0 |
| *骨架* / *体系* / *力量* / *设定大纲* | `设计/` | `骨架.md` | Phase 1 |
| *创意* / *故事* / *纲领* / *简介* | `设计/` | `创意.md` | Phase 1 |
| *立项* / *决策* / *选择* | `设计/` | `立项决策表.md` | Phase 1 |

**操作**：
1. 匹配不上的文件归入"未分类资产"，询问用户映射到哪个标准位置
2. 格式转换：.docx/.txt → .md（用Read读取内容→Write写入标准位置标准文件名）
3. 正文文件统一编号：`第一章.txt` / `chapter1.md` → `正文/ch001.txt`
4. 询问用户是否保留原文件

#### 0b-2. 内容结构标准化

> 用户文件内容往往是自由格式，需要转换为 pipeline 模板定义的标准结构。

**转换原则**：

- 非md文件（.docx/.txt/.json）先读取内容再按标准格式写入.md

→ 输出：**标准化资产清单**（每个文件标记：✅已标准化 / ⚠️部分标准化(缺分节已标注待补) / ❌无法转换(需人工处理)）

### 0c. 缺口分析

标准化完成后，对照依赖链逐Phase检查：

| Phase | 产出 | 就绪判定 |
|:--|:--|:--|
| Phase 0 | 用户意图.md + 赛道调研.md | 两者都有=✅ |
| Phase 1 | 骨架.md + 创意.md | 两者都有=✅ |
| Phase 2 | 主角设计.md | 存在=✅ |
| Phase 3 | 全书设定/ 有文件 | 目录有文件=✅ |
| Phase 3.5 | 角色库/角色库.md | 存在=✅ |
| Phase 4 | 第一卷剧情/卷纲.md + 章锚点表.md | 两者都有=✅ |
| Phase 5 | 正文/ch*.txt | 有正文=✅ |
| Phase 6 | 审核/小说快照.md | 存在=✅ |

**正文进度检测**：如果 `正文/` 有文件，提取最大章节号。例如有 ch001.txt~ch015.txt → current_chapter = ch016（下一章待写）。

→ 输出：**缺口报告**（哪些Phase已就绪/哪些缺失）

### 0d. 落地Phase决策

根据缺口报告 + 正文进度，按下表决定落地Phase：

| 条件 | mode | 落地Phase | 说明 |
|:--|:--|:--|:--|
| 正文有 + 小说快照有 | resume | Phase 5（续写下一章） | 状态完整，直接接续 |
| 正文有 + 小说快照无 | resume | 先执行0f正文反推 → Phase 5 | 需补建快照 |
| 正文无 + Phase 4就绪 | import | Phase 5（开始写） | 设定+剧情完整 |
| 正文无 + Phase 3.5就绪 | import | Phase 4（plot） | 缺剧情 |
| 正文无 + Phase 3就绪 | import | Phase 3.5（character） | 缺角色库 |
| 正文无 + Phase 2就绪 | import | Phase 3（world） | 缺世界设定 |
| 正文无 + Phase 1就绪 | import | Phase 2（主角） | 缺主角设计 |
| 正文无 + Phase 0就绪 | import | Phase 1（seed） | 缺骨架 |
| 全无 | fresh | Phase 0 | 从零开始（走正常step1流程） |

→ **向用户展示标准化资产清单 + 缺口报告 + 落地Phase建议，用户确认后进入0e**

### 0f. 补缺生成（按需执行）

> 根据缺口报告，对落地Phase前置依赖中缺失的关键文件进行补建。分两种策略：有正文→从正文反推；无正文→标注待补由下游skill生成。

#### 0f-1. 正文反推（有正文但缺状态文件时执行）

> 触发条件：`正文/` 有文件 且 `审核/小说快照.md` 不存在

读取已有正文（全部章节，或量大时取最近5章+第一章），提取信息生成：

**a) 生成 `审核/小说快照.md`**：

```markdown
# 小说快照（导入反推生成）

> ⚠️ 本快照由正文反推生成，未经逐章review校验，需人工审核确认。

## 全书进度
- 已完成：chXXX（最大章节号）
- 当前卷：第X卷（从正文推断）
- 当前幕：第X幕（从正文推断）

## 涌现设定累计
- （从正文中提取已建立的设定/规则/力量体系信息）

## 角色状态总表
| 角色 | 当前位置 | 能力等级 | 关系 | 当前目标 |
|:--|:--|:--|:--|:--|
| （从正文最后几章提取各角色最新状态） |

## 剧情线进度
| 剧情线 | 状态 | 进度 |
|:--|:--|:--|

## 读者已知信息池
- （截至最后一章读者已知的信息）

## 待回收伏笔总表
| 伏笔 | 埋设章号 | 待回收 | 状态 |
|:--|:--|:--|:--|
```

**b) 生成 `current-state.md`**（下一章写作入口包）：
- 当前章位 = 最大章节号 + 1
- 人物状态 = 快照中的角色状态总表
- 不可改事实 = 从正文提取的已发生关键事件
- 下一章硬推进 = 从最后一章的章末钩子推断
- 伏笔债务 = 快照中的待回收伏笔

#### 0f-2. 缺失设计文档补建（有正文但缺设计文档时执行）

> 触发条件：`正文/` 有文件 但 `设计/` 下关键文档缺失

| 缺失文档 | 补建方式 | 标注 |
|:--|:--|:--|
| 骨架.md | 从正文提取力量体系/金手指规则 → 按骨架模板四层结构生成 | "⏳反推，需校验" |
| 主角设计.md | 从正文提取主角信息 → 按主角设计模板2a/2b/2c生成 | "⏳反推，需校验" |
| 角色库.md | 从正文提取出场角色 → 按角色库模板总表+详细卡生成 | "⏳反推，需校验" |
| 创意.md | 从正文提取故事核心 → 按创意模板分节生成 | "⏳反推，需校验" |

#### 0f-3. 无法反推的文档处理

以下文档无法从正文反推，必须询问用户：

| 缺失文档 | 处理方式 |
|:--|:--|
| 卷纲.md + 章锚点表.md | **必须询问用户**：①提供大纲（我们标准化转换）②跳过plot直接续写（降级模式） |
| 立项决策表.md | 标注"⏳导入模式跳过，由后续seed补跑" |
| 世界决策表.md | 标注"⏳导入模式跳过，由后续world补跑" |
| 全书设定/各文件 | 部分可从正文反推（力量体系/势力/危机），部分需用户补充（各卷切片/世界矛盾轴） |

**降级模式说明**：如果用户选择跳过plot直接续写，write将无章锚点表约束。需在 `current-state.md` 中手动指定下一章核心事件和爽感节点，write按current-state指导续写。后续可补跑plot生成正式卷纲。
