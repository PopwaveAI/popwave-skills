# Step 4：剧情沉淀执行

> 触发：step-1 审计通过门禁后进入。
> 目标：按双文件方案落盘——产出本章白描卡 + 更新剧情累计卡 + 按需更新库文件。落盘必须达 formal 或 draft，trial 不落盘。

## 核心约束：双文件职责分离

- **白描卡存"发生"**（`产出/白描卡/ch{NNN}.md`）——单章历史，只增不改。review 为本章新建一张卡，不覆盖任何旧卡。
- **剧情累计卡存"状态"**（`产出/剧情累计卡.md`）——跨章聚合，每章 replace 更新。只记跨章累计（钩子台账/角色状态/读者已知/禁止漂移），单章细节留在白描卡。
- **已删除的旧文档**：current-state.md、审核/小说快照.md、审核/review-沉淀.md、审核/压缩归档/ 全部废弃，不再产出。前者的"上一章白描"由上一章白描卡承担，"信息差/钩子/禁止漂移"由剧情累计卡承担。

---

## 执行步骤

### 1. 更新库文件（按需）

按 step-1 分流清单更新：

| 信息 | 文件 |
|:--|:--|
| 已确认设定 | `设计/全书设定/（10个最小闭环文件）` |
| 人物最新状态 | `设计/角色库/角色库.md` |
| 伏笔和长线 | `设计/第一卷剧情/卷纲.md` |
| 可入场燃料池 | `素材/写作燃料.md` |

### 2. 产出本章白描卡（新增文件，只增不改）

参照 `templates/chapter-card.tpl.md` 新建 `产出/白描卡/ch{NNN}.md`：
- **`## 事件白描`**：3-5 句叙事流，像给朋友讲本章发生了什么（主角做了什么→冲突转折→结果留下什么），是 write 回溯"过去"的唯一锚点。
- **`## 关键数据`**：🔒 不可改事实一行式（人名/数值/新设定），供剧情累计卡禁止漂移提取。
- **`## 爽点·钩子`**：本章爽感类型一句话 + 章末钩子（预期回收章 + 信息差类型：读者/主角哪方已知）。
- **`## 人物关系变化`**（可选）。
- **`## 本章DNA执行包`**（启用文风DNA时写下一章要执行的DNA，不复制整份）。

### 3. 更新剧情累计卡（replace 模式）

参照 `templates/accumulate-card.tpl.md` 覆盖 `产出/剧情累计卡.md`（不是追加）：
- **`## 全书进度`**：已完成章序列 + 当前卷幕。
- **`## 未回收钩子台账`**：跨章累计。把本章白描卡埋的新钩子入账；回收了旧钩子→状态标 `✅已回收·chXXX`；超 3 章未回收的标红🔴。信息差类型标注哪方已知。
- **`## 角色当前状态表`**：按本章白描卡+review 主角变化五项更新活跃角色；龙套/已退场角色移除。
- **`## 读者已知信息池`**：逐章追加去重。
- **`## 禁止漂移`**：从白描卡关键数据+卷纲提炼的不可改事实硬清单（人名/地名/阶位数值/已死角色/已废设定）。

> 职责边界：剧情累计卡只写跨章聚合，不重复白描卡内容（例如"某章发生了某事"的细节只留在白描卡）。

### 4. 落盘审核报告

`审核/chNNN-审核报告.md`（模板见下），含四步结论 + 主角变化五项 + 钩子追踪 + 反向充足性结论 + 下章建议。
