# Step 4：沉淀核对执行

> 触发：step-1 审计通过门禁后进入。
> 目标：核对 write v4.1.0 沉淀的白描卡+状态快照的事实准确性并修正；write 未沉淀（旧版本/直写正文）时按本 step 补产。审核结论只在对话内输出，不落盘。落盘必须达 formal 或 draft，trial 不落盘。

## 核心约束：双文件职责分离

- **白描卡存"发生"**（`产出/白描卡/ch{NNN}.md`）——单章历史，只增不改。review 为本章新建一张卡，不覆盖任何旧卡。write 读近 5 张做场景连续性。
- **状态快照存"状态"**（`产出/状态快照.md`）——跨章聚合，每章 replace 更新。只记跨章状态（钩子台账/角色状态/禁止漂移），单章细节留在白描卡。
- **已删除的旧文档**：审核报告（`审核/chNNN-审核报告.md`）、剧情累计卡、current-state.md、小说快照.md、review-沉淀.md、压缩归档/ 全部废弃，不再产出。审核结论只在对话内输出。

## 执行步骤

### 1. 更新库文件（按需）

按 step-1 分流清单更新：

| 信息 | 文件 |
|:--|:--|
| 已确认设定 | `设计/全书设定/（10个最小闭环文件）` |
| 人物最新状态 | `设计/角色库/角色库.md` |
| 伏笔和长线 | `设计/第一卷剧情/卷纲.md` |
| 可入场燃料池 | `素材/写作燃料.md` |

### 2. 产出本章白描卡（新增文件，只增不改，~300-500字）

参照 `templates/chapter-card.tpl.md` 新建 `产出/白描卡/ch{NNN}.md`：
- **`## 事件白描`**：3-5 句叙事流，像给朋友讲本章发生了什么（主角做了什么→冲突转折→结果留下什么）。
- **`## 关键数据`**：🔒 不可改事实一行式（人名/数值/新设定），供状态快照禁止漂移提取。
- **`## 爽点·钩子`**：本章爽感类型一句话 + 章末钩子（预期回收章 + 信息差类型：读者/主角哪方已知）。
- **`## 人物关系变化`**（可选）：关系一行式。

> 体量红线：整卡 ~300-500 字，禁止展开成 1500+ 字长文档。细节写不下的留在库文件，不进白描卡。

### 3. 更新状态快照（replace 模式）

参照 `templates/state-snapshot.tpl.md` 覆盖 `产出/状态快照.md`（不是追加）：
- **`## 未回收钩子台账`**：跨章累计。把本章白描卡埋的新钩子入账；回收了旧钩子→状态标 `✅已回收·chXXX`；超 3 章未回收的标红🔴。信息差类型标注哪方已知。
- **`## 角色当前状态表`**：按本章白描卡+review 主角变化五项更新活跃角色；龙套/已退场角色移除。
- **`## 禁止漂移`**：从白描卡关键数据+卷纲提炼的不可改事实硬清单（人名/地名/阶位数值/已死角色/已废设定）。

> 职责边界：状态快照只写跨章聚合，不重复白描卡内容（例如"某章发生了某事"的细节只留在白描卡）。

### 4. 审核结论（对话内输出，不落盘）

审核结论在对话内输出，含：四步审核判定 + 主角变化五项 + 反向充足性结论 + 下章建议。不生成 `审核/chNNN-审核报告.md` 文件。
