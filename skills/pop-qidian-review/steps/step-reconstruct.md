# Step Reconstruct：批量回溯审核

> 触发：pipeline 导入模式 0f 调度，或用户说"回溯审核""批量审稿"。
> 目标：对已有正文逐章回溯审核，生成 current-state + 小说快照 + review-沉淀，为续写提供状态基础。

## 与正常review的区别

| 维度 | 正常review（单章） | reconstruct review（批量回溯） |
|:--|:--|:--|
| 触发 | write写完一章后 | 导入模式/续写模式，已有未审核正文 |
| 输入 | 单章正文 + current-state + 施工卡 | 多章正文（采样）+ 已有设定文件 |
| 审核 | 四步完整审核 | 简化版（跳过"要求用户修改"，只做信息提取+沉淀） |
| 产出 | 单章审核报告 + current-state更新 | 多章简版审核报告 + current-state生成 + 小说快照生成 |
| 落盘 | formal/draft | formal（必须落盘，为续写提供基础） |

---

## 采样策略

根据已有正文章数选择审核范围：

| 章数 | 采样策略 | 说明 |
|:--|:--|:--|
| ≤10章 | 全部逐章审核 | 章数少，全审保证质量 |
| 11-30章 | 最近5章全审 + 其余每5章取1章采样 | 兼顾效率与覆盖 |
| >30章 | 最近5章全审 + 第一章 + 每10章取1章采样 | 大量章节采样审核 |

> 采样章节做完整审核（信息提取+正向符合性简化+正文质量简化），非采样章节只快速提取关键信息（角色状态/设定/伏笔/章末钩子）。

---

## 执行步骤

### 1. 读取已有正文

用LS扫描 `正文/` 目录，获取所有章节文件列表，确定最大章节号。

按采样策略确定审核范围：
- 全审章节：完整审核
- 采样章节：完整审核
- 非采样章节：快速提取（角色出场/设定揭示/伏笔埋设/章末钩子）

### 2. 读取已有设定文件（按需）

- `设计/力量体系.md`（如存在）：审核力量体系一致性
- `设计/主角设计.md`（如存在）：审核主角行为一致性
- `设计/角色库/角色库.md`（如存在）：审核角色一致性
- `设计/全书设定/世界圣经.md`（如存在）：审核世界观一致性
- `素材/文风锚定.md`（如存在）：审核笔触DNA一致性
- `设计/第一卷剧情/章锚点表.md`（如存在）：审核剧情符合性

> 设定文件不存在时跳过对应检查，不阻塞流程。

### 3. 逐章审核（采样章节）

对每个采样章节执行简化版四步审核：

#### 3a. 信息提取（每章必做）

从正文中提取：
- 核心事件（2-3句概括）
- 角色状态变化（位置/能力/资产/心态/关系）
- 新揭示的设定/规则
- 新登场角色（如有）
- 章末钩子
- 伏笔埋设/回收

#### 3b. 正向符合性（简化版）

仅检查：
- 主角是否有动作闭环（压力→判断→动作→反馈）
- 是否有越级不付代价
- 是否有金手指规则违反

> 不检查与施工卡的对照（导入模式可能无施工卡）。

#### 3c. 正文质量（简化版）

仅检查：
- AI味检测（15项patterns+高疲劳词3级+结构性4项，每项检出给具体位置）
- 字数检查

> 不做好看度4问（回溯审核不要求主观评价，只提取信息）。

#### 3d. 产出简版审核报告

每章一份 `审核/chNNN-审核报告.md`：

```markdown
# 审核-chNNN（reconstruct）

## 一、信息提取
- 核心事件：（2-3句）
- 角色状态变化：（位置/能力/资产/心态/关系）
- 新揭示设定：（如有）
- 新登场角色：（如有）
- 章末钩子：
- 伏笔：埋设/回收

## 二、正向符合性（简化）
- 主角动作闭环：✓/✗
- 越级不付代价：✓/✗
- 金手指规则：✓/✗

## 三、正文质量（简化）
- AI味：标注问题项+位置
- 字数：XXXX字

## 四、来源标记
- 审核模式：reconstruct
- 采样类型：全审/采样/快速提取
```

### 4. 汇总生成状态文件

#### 4a. 生成 `审核/小说快照.md`

基于所有章节的信息提取汇总（replace模式，覆盖旧版）：

```markdown
# 小说快照（reconstruct生成）

> ⚠️ 本快照由批量回溯审核生成，采样章节已完整审核，非采样章节仅提取关键信息。

## 全书进度
- 已完成：chXXX（最大章节号）
- 当前卷：第X卷（从正文推断）
- 当前幕：第X幕（从正文推断）

## 涌现设定累计
- （从所有章节提取的已建立设定/规则/力量体系信息）

## 角色状态总表
| 角色 | 当前位置 | 能力等级 | 关系 | 当前目标 |
|:--|:--|:--|:--|:--|

## 剧情线进度
| 剧情线 | 状态 | 进度 |
|:--|:--|:--|

## 读者已知信息池
- （截至最后一章读者已知的信息）

## 待回收伏笔总表
| 伏笔 | 埋设章号 | 待回收 | 状态 |
|:--|:--|:--|:--|
```

#### 4b. 生成 `current-state.md`

基于最后一章的状态 + 小说快照，参照 `templates/current-state.tpl.md` 模板写入：

- 当前章位 = 最大章节号 + 1
- 人物状态 = 快照中的角色状态总表
- 不可改事实 = 从所有章节提取的已发生关键事件
- 下一章硬推进 = 从最后一章的章末钩子推断
- 伏笔债务 = 快照中的待回收伏笔
- DNA执行包 = 若 `素材/文风锚定.md` 存在，按模板填充本章DNA执行包（DNA源/模式/章型/笔触目标/章内套路/可见反馈/禁止误用）；不存在则填"未启用"
- 元数据 source 标记 = `skill-reconstruct`

#### 4c. 追加 `审核/review-沉淀.md`

append一段汇总判断（不删改历史）：

```markdown
## reconstruct汇总 - {YYYY-MM-DD}

- 回溯章数范围：ch001~ch{N}
- 采样策略：{全审/最近5章+每5章取1章/最近5章+第一章+每10章取1章}
- 采样章数：{X}章完整审核 + {Y}章快速提取
- 总体质量判断：{可用/需修改/问题较多}
- 主要问题（1-3条）：
  1. {问题描述+涉及章号}
  2. ...
- 修正规则（本次回溯沉淀出的可复用规则）
- current-state已生成（source: skill-reconstruct）
- 小说快照已生成（replace模式）
```

### 5. 落盘后检查

- [ ] 所有采样章节的简版审核报告已落盘
- [ ] `审核/小说快照.md` 已生成（含全部章节信息汇总）
- [ ] `current-state.md` 已生成（含DNA执行包+来源标记skill-reconstruct）
- [ ] `审核/review-沉淀.md` 已追加reconstruct汇总段
- [ ] current-state.md 元数据 source 标记为 `skill-reconstruct`
