# seed

> 起点立项引擎。极轻立项：只产出用户满意的**六要素立项 PRD**（世界[含时间地点类型]/力量体系/人物/起因/经过/结果），选出一个读者想看、你能写的故事。seed 只做立项，不产 `设计/` 子文档——后续 world/character/plot 各自消费 PRD 里属于它的要素，直接交付工程级。v13.0.0：7步→3步极简，产出收敛为单份 立项PRD。

---

## 做什么

输入：用户创意想法/题材方向 + pipeline Phase 0 底牌（意图/赛道调研/decon-lite/文风锚定）

输出：

| 产出文件 | 来源 | consumer | 核心内容 |
|:--|:--|:--|:--|
| `立项/01-立项PRD.md` | Step 3 | world/character/plot/write | **六要素定型**（世界/力量体系/人物/起因/经过/结果）——讲清楚的故事 idea |

> seed 只产这一份 PRD。它是整条管线立项的依据，后续所有 skill 从 PRD 六要素出发各自完善成工程级方案。

**下游对接**：
- world 消费「世界 + 力量体系」→ 直接工程级（7维度全书设定 + 力量体系四层 + 动力引擎六组成）
- character 消费「人物」→ 直接工程级（主角完整卡 + 金手指机制 + 角色库）
- plot 消费「起因/经过/结果」→ 直接工程级（主线 + 卷纲 + 幕白描）
- write 消费三者的工程级产出 → 正式正文

---

## 怎么操作（SOP骨架）

> execution.mode: formal（落盘）/ draft（补全继续）/ trial（不落盘）。用户给任何方向→立即执行，不先问问题。
> 强弱加载：SKILL.md=完整骨架（必读），steps/下step文件=详细操作（按步强加载全文）。
> **六要素是立项主线**：Step1 收集 → Step2 碰撞骨架 → Step3 定型故事。每个 step 都是在充实同一个六要素故事。

### 真实执行链路

```
Step1 灵感收集（问答+调研+种子候选池）→ 素材/灵感收集.md
Step2 种子碰撞（候选展开六要素骨架 + PK 选 2-3）→ 素材/种子碰撞.md
Step3 立项PRD定型（选中种子打磨成六要素故事）→ 立项/01-立项PRD.md
```

### Step 1：灵感收集 → `steps/step1-brief.md`

用户问答（4问）+ 赛道调研（3类燃料）+ 10个种子候选发散（三眼法筛保留3-5）。产出 `素材/灵感收集.md`。

### Step 2：种子碰撞 → `steps/step2-seed.md`

对候选种子逐个展开**六要素骨架**（世界/力量体系/人物/起因/经过/结果），用六要素完整性判断"能不能讲成故事"，PK 选 2-3。产出 `素材/种子碰撞.md`。

### Step 3：立项PRD定型 → `steps/step3-lixiang.md`

把用户最满意的种子打磨成**一份完整的六要素立项 PRD**——一个能讲清楚、有爽点、有追读欲的故事。产出 `立项/01-立项PRD.md`（seed 唯一产出）。

> **seed 止于立项 PRD**：六要素故事定稿后立项完成。力量体系/主角/主线等工程级展开由下游（world/character/plot）接力，不再回 seed。

## 红线

1. **读取协议**：执行任何步前先读 SKILL.md 获取骨架，再按步加载对应 step 文件（强加载全文）。
2. **seed 只立项，不产设计**：seed 只产出 `立项/01-立项PRD.md`（六要素），禁止产出 `设计/` 力量体系/主角/主线等工程级文档——那些是 world/character/plot 的职责。
3. **六要素必讲成故事**：立项 PRD 必须能用六要素讲成一个读者想看的故事。设定堆叠/要素缺失/讲不成故事 = 立项失败，回炉。
4. **起点爽文标准**：经过必须有递进阶梯（变强/变懂），结果必须有爽点落点。平铺线索无升级 = 不合格。
5. **世界是舞台非角色载具**：世界要有增量钩子（≥3 元素+主钩子）能立厚，换主角也能长出精彩故事。
6. **用户验收是唯一关卡**：立项 PRD 必须经用户确认（六要素齐全+有爽感+有画面+有追读）。用户不满意 = 回 Step 2 换种子。
