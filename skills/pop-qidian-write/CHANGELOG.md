## v4.2.2 | 2026-08-24

### 验收门禁脚本化 + 执行模式实测校准

**背景**：首章实测（8-24项目日志）暴露两个问题——①agent 报"正文 2476 字达标"，文件实测仅 1620 字（去空白），虚报 800+ 字被门禁放行；②harness 的 `paopao_subagent_run` purpose 枚举只有 verification/research/critique/implementation-check 四个审查型值，且对隐藏支线自动注入只读约束——子 agent 无法落盘，v4.2.0 设计的"子 agent 执行写作"在当前 harness 下不可实现。

**改动**：
- **新增 `scripts/word-count.ps1`**：文件实测字数（总字符/去空白/汉字）+ PASS/FAIL 判定，机器可读单行输出；UTF-8 BOM 编码兼容 PowerShell 5.1
- **验收门禁改造**（表格化）：字数项改为 exec 跑脚本，**脚本 stdout 原文一行必须完整贴进验收记录**——判定以脚本输出为准，禁转述/禁心算/禁引用生成侧统计；FAIL→修补后重跑、输出覆盖前次；脚本缺失时回退 PowerShell 内联统计仍须贴实测输出
- **执行模式如实修订**：从"默认子 agent 执行"改为"主 agent 直执写作 + 子 agent 审查（可选）"——子 agent 派发 implementation-check 做授权核验+输入缺口审查+mode判定合规（首章实测该组合跑通：子 agent 真实读取总控 STATE 并核验授权）；派发清单同步改为审查指令版；harness 层待解问题显式标注（需增设 execution purpose）
- **红线 4 升级**：字数判定以脚本实测为准 + stdout 原文贴进验收记录
- **Step 5 回复**增加验收记录项；知识地图登记 scripts/word-count.ps1
- **skill.json**：4.2.1→4.2.2

**实测验证**：脚本对 ch001.txt 跑出 `ch001.txt|总字符1680|去空白1620|汉字1392|判定:FAIL(去空白1620小于阈值1800少写)`——精确复现虚报并被当场拦截。

## v4.2.0 | 2026-08-24

### 默认子 agent 执行模式

**背景**：主 agent 直写 write 的恶果=两两成宝事故链（会话膨胀7.8MB→compaction 崩溃→expert 配置丢失回退 unrestricted）。且子 agent 链路实测已通（SKILL.md 全文注入+主动 Read），v4.1.0 SOP 全内联后天然适配子 agent 执行。

**改动**：
- **新增「执行模式」节**：主 agent=调度方（核对路径→组装硬清单派发→验收门禁），子 agent=执行方（按已注入 SKILL.md SOP 全流程）
- **派发指令硬清单**：章节号+输入文件逐项路径（近5白描卡/快照/锚点表条目/角色库/类型基线/文风锚定/最近正文/用户要求原文）+落盘三件+回报格式；缺一路径=指令不合格，子 agent 有权报错不开工
- **验收门禁**：查文件系统不信口头——正文存在且≥1800字+白描卡新建+快照 mtime 更新，缺任一幂等重派（先查半成品防覆盖）
- **skill.json**：4.1.0→4.2.0

**核心原则**：子 agent 没有项目上下文，输入路径必须由调度方硬清单给出，不能指望子 agent 自己找。

## v4.1.0 | 2026-08-24

### 正确性基线重构：沉淀挪入 write + 写好层降级

**背景**：两项目 70 run 实证失败模式 100% 在事实层（伏笔多版本/设定冲突/时间线倒挂），零条是"文笔不好"。而沉淀挂在 review Step 4 后=依赖"review 必跑"，实测用户 11-15 章连写时 review 全跳（57 章仅 2 份叙事记录）——沉淀挂在可能被跳过的环节上=没挂。

**改动**：
- **沉淀职责挪入 write**：新增 Step 4 沉淀双文件——写完即产出本章白描卡（只增不改~300-500字，模板内联）+ replace 更新状态快照（钩子台账/角色状态/禁止漂移）。新增沉淀红线：每章写完必沉淀，跳过=不合格。新增事实仍只声明不落库（设定落库权留 review）
- **review 职责联动调整**（由 write 侧声明）：review Step 4 从"唯一产出方"降为"核对修正方"——review 跑了就校正沉淀，没跑记录也在
- **写好层降级**：DNA三态协议/五层指导/17微观技法/爽感方法论全部从 SOP 正文降为知识地图触发行（references 文件一个不删，改存储位置不删能力）；正确性主流程（Step 1-4）零依赖知识地图
- **SOP 7步→5步**：消费输入→抽写作包→写正文→沉淀双文件→回复移交
- **新增入口**：用户自带细纲（写对场景高频）——有则覆盖章锚点表默认取值
- **体量**：7127→6072 字符；红线维持4条（更新沉淀红线，删除注入红线中的部分细则并入Step 1/3）
- **skill.json**：4.0.0→4.1.0

**核心洞察**：write 是唯一必然执行的环节（用户会跳 review，不会跳 write）。防失控机制必须挂在必然执行的环节上。白描卡记事实层非质量自评，自证偏差可控；review 交叉核对兜底。
