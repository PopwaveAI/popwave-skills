# write

> 起点唯一写作引擎。v4.2.0：默认子 agent 执行模式（派发指令硬清单+验收门禁查文件系统不信口头）。v4.1.0：正确性基线重构——沉淀职责从 review 挪入 write（写完即沉淀双文件，不再依赖 review 必跑）；"写好"层（DNA三态/17技法/爽感方法论/五层指导）降为知识地图触发行，必达层只保正确性。

---

## 做什么

| 项 | 内容 |
|:--|:--|
| 产出 | `正文/ch{NNN}.txt`（2000-2500字，不准超3000）+ `产出/白描卡/ch{NNN}.md`（新增）+ `产出/状态快照.md`（replace）+ 执行报告（对话内，用 `templates/chapter-record.tpl.md`） |
| 下游 | 移交 pop-qidian-review 审核（review 改为核对修正沉淀；未 review 不得写下一章，但沉淀已由 write 保证） |

> execution.mode：formal（落盘）/ draft（有缺口继续写）/ trial（试做不落盘、不沉淀）。
> 第一性原理：**先写对，再写好**。事实错误不可自愈（全卷级返工），平庸可自愈（review+用户反馈可改）。写好的方法论全在 references，知识地图有触发索引，按需加载。

### 执行模式：默认子 agent 执行

写作是重任务（读5类输入+写2500字+沉淀双文件），主 agent 直写会背着全项目历史干重活（实测：会话膨胀→compaction 崩溃→expert 配置丢失回退）。本 skill SOP 已全内联，SKILL.md 注入即得完整流程，天然适配子 agent 执行。

| 角色 | 职责 |
|:--|:--|
| 主 agent（调度方） | 按 Step 1 输入表核对路径存在 → 组装派发指令（硬清单） → 派发子 agent → **验收门禁** |
| 子 agent（执行方） | 收指令后按本 SKILL.md SOP 全流程执行 → 落盘三件 → 回报执行报告 |

**派发指令硬清单**（主 agent 必须逐项给出，缺一路径=指令不合格，子 agent 有权报错不开工）：

```
任务：写作 ch{NNN}
1. SKILL执行：按 pop-qidian-write SKILL.md（已注入）SOP 全流程执行
2. 输入文件（逐项核对存在）：
   - 近5张白描卡：产出/白描卡/ch{NNN-5}~ch{NNN-1}.md（列出实际存在的路径）
   - 状态快照：产出/状态快照.md
   - 章锚点表本章条目：设计/第一卷剧情/章锚点表.md（ch{NNN}行）
   - 角色库：设计/角色库/角色库.md
   - 类型基线：设计/全书设定/类型风味基线.md
   - 文风锚定：素材/文风锚定.md（不存在时按赛道从 references/文风兜底/ 选一）
   - 最近正文：正文/ch{NNN-1}.txt
   - 用户本轮要求（原文附上，含自带细纲如有）
3. 落盘三件（写完缺任一=任务失败）：
   - 正文/ch{NNN}.txt（2000-2500字）
   - 产出/白描卡/ch{NNN}.md（新建）
   - 产出/状态快照.md（replace更新）
4. 回报：执行报告（mode/摘要/硬锚点兑现/新增事实清单/沉淀状态）
```

**验收门禁**（主 agent 收到回报后**查文件系统，不信口头**）：`正文/ch{NNN}.txt` 存在且字数≥1800 ✓ 白描卡 `ch{NNN}.md` 新建存在 ✓ 状态快照 mtime 晚于派发时刻 ✓——缺任一按幂等键重派（先查文件是否半成品，避免覆盖已写内容）。

## 怎么操作（SOP 全内联·正确性基线）

### Step 1：消费输入（写对的前提）

按优先级消费，缺一项记入缺口：

| 输入 | 路径 | 读法 | 抽取 |
|:--|:--|:--|:--|
| 用户本轮要求（最优先） | 对话 | — | 覆盖以下默认取值；与状态快照冲突时以用户为准，创作记录标注冲突 |
| 近5张白描卡 | `产出/白描卡/ch{NNN-5}~ch{NNN-1}.md` | **全量读，禁摘要替代** | 事件白描（叙事流回溯锚，不得矛盾）/ 关键数据🔒（写错=bug）/ 爽点·钩子（已兑现+已埋，续写接应）/ 人物关系变化 |
| 状态快照 | `产出/状态快照.md` | **全量读** | 未回收钩子台账（不提前吞并未到期钩子）/ 角色当前状态表（对话互动不漂移）/ 禁止漂移（硬清单） |
| 章锚点表本章条目 | `设计/第一卷剧情/章锚点表.md` | 按需读本章条目 | 4硬锚点+3软指导——**向前推进的唯一来源**；白描卡/快照只提供"过去"，锚点表提供"方向" |
| 最近正文 | `正文/ch{NNN-1}.txt` | 按需 | 需对话原文/具体描写细节时才读，不得凭对话历史替代 |
| 用户细纲（如自带） | 用户消息/项目文件 | 有则最优先 | 自带细纲覆盖章锚点表默认取值，冲突以用户细纲为准 |

**设定注入（每章≤3维度≤1500字，禁全文注入）**：每章必选 `设计/角色库/角色库.md`（本章有对话角色的语言指纹+关系张力）+ `设计/全书设定/类型风味基线.md`（类型声明：类型+保持什么味+禁止漂移到哪）；再按章型选≤1个：战斗→`力量体系.md`+`战斗系统.md` / 日常→`势力人物.md`+`地理建筑.md` / 探索→`物理规则.md`+`地理建筑.md` / 危机→`危机敌人矛盾.md` / 社交→`政治经济.md`+`民风民俗.md` / 成长→`主角设计.md`（阶位突破+`物理规则.md`）。每文件只提取本章相关段落（≤500字）。

**禁止默认读取**：`立项/01-04-*PRD.md`、`设计/全书设定/`表外文件、`卷纲.md`、未指定的其他文风DNA文件。仅用户明确指定或处理缺口时读，创作记录标注。

**缺口处理**：白描卡/状态快照缺关键事实→不自行翻库补写，mode 降 draft 并在创作记录声明缺口；用户要求继续→照降。**formal 判定：白描卡+快照+锚点条目+正文齐全达标（缺上一章白描卡/状态快照不得标 formal）。**

### Step 2：抽写作包（写对的施工单）

从 Step 1 输入抽取，不扩展成章纲表：

```markdown
## 本章写作包
execution.mode:
- 把 X 写成 Y： / 当前章位：
- 上一章白描：（上一章白描卡叙事流，续写不得矛盾）
- 钩子台账：（状态快照——本章可回收/不可提前吞并）
- 角色当前状态：（主角/配角当前立场）
- 读者已知信息池：（快照钩子台账信息差类型，写信息不穿帮）
- 关键数据🔒：（上一章白描卡，写错=bug）
- 章锚点表（本章条目）：（4硬锚点+3软指导，向前唯一来源；用户自带细纲时以此为准）
- 可用燃料： / 用户本轮新增要求：
- 类型声明：（类型风味基线，写作全程锚定）
- 对话锚点：（本章有对话角色的语言指纹——句式/用词/对话标志×2；无对话填"本章无对话"）
- 设定状态：（设定注入的精选内容，≤1500字）
```

**写前门禁**（全过才动笔）：写作包完整 ✓ mode已判定 ✓ 硬锚点已锁定 ✓ 上一章白描/钩子台账/角色状态/关键数据已引用 ✓ 类型声明已注入 ✓ 对话锚点已提取 ✓ 缺口已声明 ✓

### Step 3：写正文（写对的核心规则）

- 开场120字内出现目标、异常、压力、反馈或主动动作之一。
- **兑现章锚点表本章硬锚点（按序踩中，不可触发项不得触发）**，不能只铺氛围。
- **关键数据🔒写错=bug；状态快照禁止漂移不得违反**（人名/数值/已死角色/已废设定）。
- **不提前吞并状态快照未回收钩子台账里未到期的钩子**；埋新钩子要标预期回收章+信息差类型（读者知主角不知=爽点储备；主角知读者不知=悬念储备）。
- 主角至少完成一次动作闭环：压力/诱因→判断→主动动作→阻碍升级→可见反馈→收益/损失→新压力。
- 关键爽点外显（旁人反应/资源变化/局势翻转/敌人误判），不作者总结式"他赢了"。
- 角色库是角色唯一源，不发明角色；对话从对话锚点取语言参数（句式/用词一致，对话标志至少体现1个），不凭记忆写对话；角色库无语言指纹→标注缺口不编造。
- 结尾留主动钩子或威胁逼近，不用自然停顿收尾。

**写好层**（质量提升，非正确性必需）：章型选择→知识地图 `章型定义.md`；爽感设计→`爽点引擎.md`+`爽点链条矩阵.md`+`爽文剧情设计SOP.md`（三章型场景触发）；笔触DNA→`素材/文风锚定.md`（不存在时按赛道从 `references/文风兜底/` 选一：深渊主宰=西幻/夜无疆=玄幻修仙/诡秘之主=西幻诡秘流/捞尸人=民俗恐怖/东京医途=都市，执行报告标注兜底书名，禁跳过）；微观技法→`微观技法工具箱.md` 3类17种选2-3类加载落地。**这些不达标时先回查知识地图，不阻塞正确性主流程。**

### Step 4：沉淀双文件（写完即做，不等review）

**为什么在 write**：用户可能连写不 review（实测如此），沉淀挂在 review 后=大概率不发生。write 是唯一必然执行的环节，必须自带闭环。白描卡记的是事实层（发生什么/数据/钩子状态），不是质量自评，自证偏差可控；review 若跑，交叉核对修正。

**4a. 产出本章白描卡**（新建 `产出/白描卡/ch{NNN}.md`，只增不改，~300-500字）：

```markdown
---
doc_type: 白描卡
role: 单章剧情白描（历史，只增不改）｜write 读近5张做场景连续性
read_policy: full-required（近5张）
compression: forbid
primary_consumer: write
source_of_truth: true
chapter: chNNN
last_updated: YYYY-MM-DD
---

# chNNN「{标题}」

POV: {主角/配角} | 章型: {章型} | 原文: {字数}字

## 事件白描（3-5句，覆盖本章核心）
（像给朋友讲本章发生了什么：主角做了什么 → 冲突/转折是什么 → 结果留下了什么。画面、情绪、内心融入叙事，不拆标签、不自评。）

## 关键数据
🔒 {不可改事实一行式，来源：chNNN-xxx段}

## 爽点·钩子
爽点: {爽感类型一句话}
钩子: {钩子} → 预期回收 chXXX（信息差类型: 读者/主角哪方已知）

## 人物关系变化（可选）
{角色A}→{角色B}: {变化一句话}
```

**4b. 更新状态快照**（replace 覆盖 `产出/状态快照.md`，不是追加）：

- `## 未回收钩子台账`：跨章累计表（钩子/埋设章/信息差类型/预期回收/状态）。本章埋的新钩子入账；回收旧钩子→标 `✅已回收·chXXX`；超3章未回收标🔴。
- `## 角色当前状态表`：一行一活跃角色（位置/等级/当前目标/关键关系变化）；龙套/退场角色移除。
- `## 禁止漂移`：从白描卡关键数据提炼的不可改事实硬清单（人名/地名/阶位数值/已死角色/已废设定）。

**双文件职责**：白描卡存"发生"（逐章历史），状态快照存"状态"（跨章聚合，不重复白描卡内容）。体量红线：白描卡~300-500字禁膨胀；快照只记跨章聚合。

**新增事实只声明不落库**：设定级新增（角色库/全书设定/卷纲变更）只在创作记录列"新增事实待review"清单，不落库文件——沉淀双文件只记剧情事实，设定落库权在 review。

### Step 5：回复 + 移交review

**落盘**：正文写 `正文/ch{NNN}.txt`（路径文件名固定，NNN为3位章节号）；trial 不落盘不沉淀。

**回复**（模板 `templates/chapter-record.tpl.md`，对话只回摘要不贴正文）：本次采用skill / execution.mode / 第N章标题已写入文件名 / 摘要 / 章末钩子 / 创作记录（已读输入 / 兑现硬锚点 / 新增事实待review清单 / 沉淀状态：白描卡已建+快照已更 / 下一步建议review）。

**review后继**：review采纳→下一章；review需修改→重写；review裁决→暂停。review 现职责=四步审核+**核对修正**沉淀（write已保证记录必发生）。

## 红线（4条）

1. **读取红线**：近5张白描卡+状态快照**全量读禁摘要替代**，章锚点表本章条目必读，类型风味基线每章必注入；缺口不得静默绕过——降mode并在创作记录声明。
2. **事实红线**：硬锚点按序踩中、不可触发项不得触发；禁止漂移不得违反、关键数据🔒写错=bug；角色库唯一源不发明角色；不提前吞并未到期钩子；设定未覆盖的细节先落盘（通知plot补建）再写。违反=不合格。
3. **沉淀红线**：**每章写完必沉淀**——白描卡新建（只增不改~300-500字）+状态快照replace更新，trial外不得跳过。跳过=下一章无回溯锚=剧情失控之源。违反=不合格。
4. **流程红线**：落盘路径/文件名固定；未review不得写下一章；正文2000-2500字不准超3000。违反=不合格。

> 质量约束（非断裂下游）：隔离（不搬运原作专有元素）/ 节奏（事件密度≥8/章+爽感≥1/章+微钩子每3-5行）/ DNA落地（章内套路至少改变一处展开方式，每章一条可见反馈）。
