# Step 1：消费输入

本步骤消费 write 的 5 类基础输入，并在项目启用文风DNA时消费本章DNA执行包，抽取本章写作包。引用 PRD §4.1（骨架）、§4.2（owner/read_policy）、§4.5（execution.mode）。

## 1. 必读输入（5 类基础输入 + DNA 条件输入）

按优先级消费，缺一项记入缺口：

### 1.1 用户本轮要求（优先）

用户本轮口头/文字要求是最优先输入，覆盖以下三类的默认取值。例如"把第 3 章重写得更狠"、"续写下一章"、"开篇样章"。

- 明确：把 X 写成 Y / 当前章位 / 续写或重写 / 特殊约束。
- 若用户要求与 current-state 冲突，以用户要求为准，但必须在创作记录里标注冲突。

### 1.2 current-state.md（全量读，回溯锚）

路径：`current-state.md`（项目根）。read_policy = full-required。

必须全量读取，不得用摘要替代。抽取"过去发生了什么"：
- 主体 `## 上一章白描`：叙事流回溯锚，写正文时不得与其中已确立事实矛盾。
- `## 信息差锚`：读者以为/角色以为/实际——写对话和内心戏时保持错位，不穿帮。
- `## 钩子回收表`：写本章时遵守预期回收，不提前吞并未到期钩子。
- `## 禁止漂移`：硬清单，写错=bug，不得违反。

### 1.3 章锚点表（按需读，向前锚）

路径：`设计/第一卷剧情/章锚点表.md`（plot产出）。read_policy = 按需读本章条目。

**向前推进（下一章写什么）由章锚点表决定，不依赖 current-state**。读本章 4 硬锚点（核心事件/章末钩子等）+ 3 软指导，作为本章剧情轨道的硬约束。current-state 只提供"过去"，章锚点表提供"方向"。

### 1.4 最近正文（全量读）

路径：`正文/ch{NNN-1}.txt`（上一章）或用户指定锚定正文。read_policy = full-if-targeted。

必须全量读目标文件，不得凭对话历史替代。

### 1.5 文风DNA输入（存在时必读）

**DNA源文件**：`素材/文风锚定.md`

触发条件（任一满足即启用DNA）：

- `素材/文风锚定.md` 存在（最简路径，续写模式适用）。
- `审核/current-state.md` 存在 `## 本章DNA执行包`（正向模式review产出）。
- 用户本轮明确要求使用某个文风DNA。

读取规则：

- **优先级**：若 `current-state.md` 存在 `## 本章DNA执行包`，优先按执行包加载（执行包指定了本章章型卡、笔触目标、章内套路）。
- **无执行包时**（续写模式或review未产出执行包）：直接从 `素材/文风锚定.md` 按本章章型加载对应场景卡 + 通用维度。按需读取与本章章型相关的场景卡、笔触约束、章内套路、角色/口癖隔离；不要把整份 DNA 当剧情事实库。
- 如果 DNA 源过大，只读取目录、对应章型卡、章内笔触、单章套路、角色/口癖隔离。
- DNA文件不存在时，提示用户部署（缺失态），不内置默认风格。trial模式由用户声明风格，执行报告标注。

## 2. 禁止默认读取

以下文件 read_policy 为 index-only 或 full-if-targeted，write 不得默认读取：

- `设计/创意.md`
- `设计/全书设定/`（10个最小闭环文件，按设定库精选注入规则按需读取——见下方注入表）
- `设计/第一卷剧情/卷纲.md`（按需读取本章所属幕的设定快照）
- `审核/review-沉淀.md`
- `审核/压缩归档/`
- 未被 `本章DNA执行包` 或 `素材/文风锚定.md` 指向的其他文风DNA文件

仅当用户明确指定或处理缺口时才可读取，且必须在创作记录"已读输入"里如实标注。

### 3.3 注入规则

- 角色库必选（每章），再从按章型表选≤2个文件
- 每个文件只提取本章相关段落（≤500字），不全文注入
- 提取内容写入本章写作包的"设定状态"字段
- 如本章需读取设定库精选注入表外的文件，必须在创作记录"已读输入"里如实标注原因

## 4. 缺口处理

如果 current-state 明显缺关键事实：

- 不自行翻库补写。
- 停止并要求先执行 pop-qidian-review 更新 current-state。
- 若用户要求继续试写，execution.mode 降为 draft 或 trial。

## 5. 抽取本章写作包

从 4 类输入抽取，不扩展成章纲表：

```markdown
## 本章写作包
execution.mode:
- 把 X 写成 Y：
- 当前章位：
- 上一章白描：（从 current-state 引用叙事流，续写不得与之矛盾）
- 信息差锚：（读者以为/角色以为/实际，写对话内心时保持错位）
- 钩子回收表：（本章可回收/不可提前吞并）
- 禁止漂移：（硬清单，写错=bug）
- 章锚点表（本章条目）：（4硬锚点+3软指导，向前推进的唯一来源）
- 可用燃料：
- 用户本轮新增要求：
- DNA约束：（列 3-5 条本章实际执行的笔触约束，来自素材/文风锚定.md的通用维度+场景卡）
- 文风DNA执行：（未启用填"未启用"；启用时列 DNA源、模式、章型、笔触目标、章内套路、可见反馈、禁止误用）
- 对话锚点：（从角色库或current-state提取本章有对话角色的语言指纹——句式偏好/用词偏好/对话标志2个。本章无对话填"本章无对话"）
```

- `章锚点表（本章条目）` 是向前推进的硬约束，本章核心事件必须兑现其硬锚点。
- `禁止漂移` 不得违反。
- `钩子回收表` 里未到期的钩子不得提前吞并。
- `DNA约束` 必须列 3-5 条，且正文里能看出来。来源为 `素材/文风锚定.md` 的通用维度和对应场景卡。
- `文风DNA执行` 必须来自 current-state 的本章DNA执行包（若有）或直接从 `素材/文风锚定.md` 提取（无执行包时）；不得临场把整本参考小说的特殊桥段当通用规则。

## 6. execution.mode 判定

- formal：current-state + 章锚点表本章条目 + 最近正文 + 用户要求 齐全且达标；若 `素材/文风锚定.md` 存在，DNA源也齐全。
- draft：必读输入有缺口但用户要求继续。
- trial：快速试做，不落盘。

缺 current-state 不得标 formal。

## 7. 门禁

进入 step-2 前必须满足：

- [ ] 本章写作包已抽取完整。
- [ ] execution.mode 已判定。
- [ ] 章锚点表本章硬锚点已锁定（向前唯一来源）。
- [ ] 上一章白描/信息差锚/禁止漂移已从 current-state 引用。
- [ ] DNA约束 3-5 条已选定（来源：`素材/文风锚定.md`）。
- [ ] 如启用文风DNA，已锁定章型、笔触目标、章内套路、可见反馈和禁止误用项。
- [ ] 对话锚点已提取（本章有对话的角色及其语言指纹参数）或已确认"本章无对话"。
- [ ] 缺口已记录或已要求 review 修复。

## 8. 下一步

门禁通过后，读取 `steps/step-2-write.md` 开始写正文。
