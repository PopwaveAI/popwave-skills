# Step 1：消费输入

本步骤消费 write 的 4 类基础输入，并在项目启用文风DNA时消费本章DNA执行包，抽取本章写作包。引用 PRD §4.1（骨架）、§4.2（owner/read_policy）、§4.5（execution.mode）。

## 1. 必读输入（4 类基础输入 + DNA 条件输入）

按优先级消费，缺一项记入缺口：

### 1.1 用户本轮要求（优先）

用户本轮口头/文字要求是最优先输入，覆盖以下三类的默认取值。例如"把第 3 章重写得更狠"、"续写下一章"、"开篇样章"。

- 明确：把 X 写成 Y / 当前章位 / 续写或重写 / 特殊约束。
- 若用户要求与 current-state 冲突，以用户要求为准，但必须在创作记录里标注冲突。

### 1.2 current-state.md（全量读）

路径：`current-state.md`（项目根）。read_policy = full-required。

必须全量读取，不得用摘要替代。抽取本章写作包所需字段。

### 1.3 最近正文（全量读）

路径：`正文/ch{NNN-1}.txt`（上一章）或用户指定锚定正文。read_policy = full-if-targeted。

必须全量读目标文件，不得凭对话历史替代。

### 1.4 文风DNA输入（存在时必读）

**DNA源文件**：`素材/文风锚定.md`

触发条件（任一满足即启用DNA）：

- `素材/文风锚定.md` 存在（最简路径，续写模式适用）。
- `审核/current-state.md` 存在 `## 本章DNA执行包`（正向模式review产出）。
- 用户本轮明确要求使用某个文风DNA。

读取规则：

- **优先级**：若 `current-state.md` 存在 `## 本章DNA执行包`，优先按执行包加载（执行包指定了本章章型卡、笔触目标、章内套路）。
- **无执行包时**（续写模式或review未产出执行包）：直接从 `素材/文风锚定.md` 按本章章型加载对应场景卡 + 通用维度。按需读取与本章章型相关的场景卡、笔触约束、章内套路、角色/口癖隔离；不要把整份 DNA 当剧情事实库。
- 如果 DNA 源过大，只读取目录、对应章型卡、章内笔触、单章套路、角色/口癖隔离。
- DNA文件不存在时，提示用户部署（缺失态），不内置默认风格。trial模式由用户声明风格，执行报告标注。

## 2. 禁止默认读取

以下文件 read_policy 为 index-only 或 full-if-targeted，write 不得默认读取：

- `设计/创意.md`
- `设计/全书设定/`（世界圣经等，按设定库精选注入规则按需读取）
- `设计/第一卷剧情/卷纲.md`（按需读取本章所属幕的设定快照）
- `审核/review-沉淀.md`
- `审核/压缩归档/`
- 未被 `本章DNA执行包` 或 `素材/文风锚定.md` 指向的其他文风DNA文件

仅当用户明确指定或处理缺口时才可读取，且必须在创作记录"已读输入"里如实标注。

## 3. 缺口处理

如果 current-state 明显缺关键事实：

- 不自行翻库补写。
- 停止并要求先执行 pop-qidian-review 更新 current-state。
- 若用户要求继续试写，execution.mode 降为 draft 或 trial。

## 4. 抽取本章写作包

从 4 类输入抽取，不扩展成章纲表：

```markdown
## 本章写作包
execution.mode:
- 把 X 写成 Y：
- 当前章位：
- 不可改事实：
- 人物状态：
- 设定状态：
- 可用燃料：
- 伏笔债务：
- 下一章硬推进：
- 禁止漂移：
- 用户本轮新增要求：
- DNA约束：（列 3-5 条本章实际执行的笔触约束，来自素材/文风锚定.md的通用维度+场景卡）
- 文风DNA执行：（未启用填"未启用"；启用时列 DNA源、模式、章型、笔触目标、章内套路、可见反馈、禁止误用）
- 视角决策：（见下方 §5 章意图7问 + 本章视角决策）
```

- `下一章硬推进` 是硬约束，必须至少兑现 1 条。
- `禁止漂移` 不得违反。
- `DNA约束` 必须列 3-5 条，且正文里能看出来。来源为 `素材/文风锚定.md` 的通用维度和对应场景卡。
- `文风DNA执行` 必须来自 current-state 的本章DNA执行包（若有）或直接从 `素材/文风锚定.md` 提取（无执行包时）；不得临场把整本参考小说的特殊桥段当通用规则。
- `视角决策` 必须在 §5 完成后回填，不可留空。

## 5. 章意图7问 + 本章视角决策

> 选完章型后、加载技法前，先想清楚本章给读者什么体验。前6问定方向，第7问定视角——视角是每章必决策项，不可默认跳过。
> 视角方法论详见 `references/视角设计框架.md`（强加载）。

### 5.1 章意图7问

| # | 问题 | 回答要求 |
|:--|:--|:--|
| 1 | 定位：本章在全卷位置？ | 开篇/发展/转折/高潮/收束 |
| 2 | 体验：读者读完获得什么感受？ | 具体感受词 |
| 3 | 信息：本章必须传递什么信息？ | 1-3条硬信息 |
| 4 | 角色：哪些角色出场？谁的主视角？ | 角色清单+主视角人物 |
| 5 | 爽感：爽点类型？在哪个节拍爆发？ | 爽感类型+节拍位置 |
| 6 | 主动行为：主角做什么决策+行动？ | ≥1决策+≥1行动 |
| 7 | **视角：选择谁的视角？信息藏还是露？视角远近？** | 必答——见 `references/视角设计框架.md` |

### 5.2 本章视角决策（必填）

> 每章必须显式声明。违反=不合格（SKILL.md 红线第8条）。

```markdown
#### 本章视角决策
- 视角类型：全知 / 有限（主角）/ 有限（配角）/ 摄影机 / 说书人 / 多机位
- 观察机位：远观 / 近观 / 多机位 / 采访当事人
- 内外视角配比：外为主（默认）/ 内为主 / 交织
- 信息策略：对主角藏 / 对读者藏 / 对双方都藏 / 全露
- 目标效果：期待感 / 悬念感 / 代入感
- 视角切换计划：不切换 / 切换N次（标注切换点+标志+目的）
```

### 5.3 视角决策快速指引

| 章型 | 默认视角 | 默认效果 | 备注 |
|:--|:--|:--|:--|
| 开篇章 | 有限（主角） | 代入感 | 建立主轨道，不切换 |
| 战斗章 | 有限（主角）+敌人插入 | 期待感 | 敌人视角≤3-5行放大爽感 |
| 升级章 | 有限（主角） | 期待感 | 外为主，内视角点睛突破瞬间 |
| 反转章 | 多机位/摄影机 | 悬念感 | 多视角拼凑全貌 |
| 日常章 | 有限（主角） | 代入感 | 外为主，轻松节奏 |
| 高潮章 | 多机位交叉 | 期待感+悬念感 | 视角切换最密集，但仍≥60%主角 |

## 6. execution.mode 判定

- formal：current-state + 最近正文 + 用户要求 齐全且达标；若 `素材/文风锚定.md` 存在，DNA源也齐全。
- draft：必读输入有缺口但用户要求继续。
- trial：快速试做，不落盘。

缺 current-state 不得标 formal。

## 7. 门禁

进入 step-2 前必须满足：

- [ ] 本章写作包已抽取完整。
- [ ] execution.mode 已判定。
- [ ] 下一章硬推进至少 1 条已锁定。
- [ ] DNA约束 3-5 条已选定（来源：`素材/文风锚定.md`）。
- [ ] 如启用文风DNA，已锁定章型、笔触目标、章内套路、可见反馈和禁止误用项。
- [ ] **章意图7问已回答（含第7问视角）。**
- [ ] **本章视角决策已填写（视角类型/内外配比/信息策略/目标效果/切换计划）。**
- [ ] 缺口已记录或已要求 review 修复。

## 8. 下一步

门禁通过后，读取 `steps/step-2-write.md` 开始写正文。
