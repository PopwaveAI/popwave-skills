# pop-review

> 章节验收 + 存档 + 回看（三线共用）。就三件事：**确认本章正文满意（定稿）→ 生成本章日志 → 更新状态档**。满意判别含硬状态承接/行为可信/对白辨人/钩子承接/章末落地/高潮后效/**爽点密度**/**情绪达标**八项。
> **本 skill 由三线 review 合并**（灯塔 pop-lantern-review v3.6.0 / 雪花 pop-snow-review v1.8.0 / 涌现 pop-emergent-review v1.3.0），蓝本＝灯塔系列（判别最全）。**线间差异收在 §0 系列适配表**。当前版本 v1.0.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 这是什么

review 是"写完这一章、准备写下一章"之间那道存档关口。它**不审质量**——质量是 write 的事；它只负责把"这一章发生了啥"记下来、把"整个世界现在该是啥样"更新到最新，让下一章开写之前有可依据的准。

**正文没让用户满意前，不进账本**（还在改的，别记）。

**涌现线特有**：review 是"设定从账本长出来"的执行者——write 从内容模板库新选/临场长出的新设定/新角色/偏离章纲的内容，由 review 核验后落进账本"已长出设定"，成为后续章节不可违背的事实。

## 三件事

| # | 活 | 产出 |
|:--|:--|:--|
| 1 | 确认本章正文满意 | 满意=定稿（不满意→打回，不入库） |
| 2 | 按定稿正文，生成本章日志 | 本章日志（路径照 §0，只增不改） |
| 3 | 按本章日志，更新状态档 | 状态档（路径照 §0，当前态 replace 只记活跃）＋回收项入退出区/退出档案 |

**回看（照 §0）**：灯塔＝单元末章 PASS 后「剧末回看」；涌现＝每 5-10 章/故事弧「阶段性回看」；雪花＝无。

## 两个产物 + 一个状态档

- **本章日志**＝每章一张，只增不改，存"这一章怎么了"（事件源，历史）。
- **状态档**＝单份 replace，只记"当下仍活跃的"（现在在哪／人物此刻／此刻悬着的线／还没揭的悬念／不许碰）——当前态投影。（涌现线：状态档＝涌现账本，另有"已长出设定"区。）
- **退出区/退出档案**：从状态档移除的（已回收钩子／已退场角色／已完结线）落这里，留痕防失联。（涌现线：退出区就在账本内。）

> 三条心法：
> 1. 状态档**只记活跃**——人物退场/钩子已回收/线已完结，就挪进退出区，别再留在当前态；这样它"进得来出得去"，100 章也不臃肿。
> 2. **世界规则/静态设定不进状态档**——力量体系/货币/地理这些在设定库·编排/大纲里已有，再记就是重复、就是双源打架。（涌现线例外：写章过程中真长出来的设定进"已长出设定"区。）
> 3. 状态档**不拆分**——当前态就是这一份，靠"只记活跃"压体积，不搞一堆文件。

## 步骤

**第 1 步 确认满意＋去AI味核验**

读本章正文。判断：用户/完成度上，这章算定稿了吗？
- 满意 → 定稿，进第 2 步。
- 不满意 / 还要改 → 打回 write（或告诉用户），**不入库**，结束。

**去AI味核验（收尾检查）**：查上游去AI味结果——①write 交接的正文去AI味结果（正文 `deai_gate.py` FAIL 清零）；②outline 章纲的 `去AI味:ch{NNN}-章纲|PASS` / `WARN×N` 结果。章纲缺结果 → review 补跑 `python skills/pop-snow-pipeline/scripts/deai_gate.py {章纲路径} --profile doc --json` 一次（WARN 定位自查、机械项 `--fix`），并在对话注明补去AI味；正文去AI味结果缺失 → 在本章日志备注"上游去AI味结果缺失"，提示 write 下章前补跑。报告检查只报不打回，核验不阻塞存档，但必留痕。

**满意判别标准（第 1 步"确认满意"时逐条核，供"定稿/打回"判据，不审文风只审一致性/连续性/设定/爽点/情绪）**：

| # | 判别维度 | 判定 |
|:--|:--|:--|
| 1 | **硬状态承接** | 位置/伤势/能力/持有物/信息边界与上章结尾、状态档无错位；"突然想到/突然做到"糊过去=不一致 |
| 2 | **行为可信（动机6问）** | 异常行为能由 经历→利益→恐惧→渴望→压力→误判 推出；**只能用"剧情需要"解释=OOC**；**信息越界（角色知道他不该知道的）最严重，优先于性格偏差** |
| 3 | **对白遮名辨人** | 关掉角色名仍能分辨谁在说话（称呼/句长/语气/禁忌）——抽 1-2 段验 |
| 4 | **钩子承接** | 上一章钩子在本章有反馈（回应/推进/误导/压住），章末留新缺口（对照打分表好奇模块标 `好奇·X档`，伪钩子=打回），未提前吞并未到期钩子 |
| 5 | **章末落地改变** | 信息/关系/物理/权力 至少一类落地；**四类皆无=空转章** |
| 6 | **高潮后效** | 本章处大高潮后 1-2 章时，是否写出改变（主线推进/人设成长/关系变化），不能直接跳下一个蓄压 |
| 7 | **爽点密度** | 对照章纲爽点标注逐条核：每章 ≥1 个重大爽点（无爽点章不连续），密度目标 ≥2；爽点须含**发生（事件本身）＋反应（读者情绪落点，对照打分表情绪名）＋影响（对状态/剧情的实际改变）**，只写事件不写反应与影响=假爽点；章纲标注的爽点正文没兑现=打回 |
| 8 | **情绪达标** | **先反核章纲标注**：章纲 8 分事件是否符合打分表情绪定义+铺垫成本？（打开 `{pop-lantern-plot}/references/内容库/剧情-情绪打分表.md` 情绪细则+反例区核——8分定义/临界规则/虚标判据一律以打分表为准，不另立判据）→ **虚标直接打回 outline 重排，不核正文**；**再核正文兑现**：本章实际情绪强度 vs 目标值——**差 2 级以上=打回**（目标 `愤怒·8分` 实际只到 `愤怒·5分`，说明这场戏没推到设计高度）；**峰值兑现**：章纲标注的 8 分事件正文没兑现/没写透=打回；**情绪布局纪律**：与上章不连续同刻、10 级顶点不滥用（对照打分表峰值规则+反例区） |

**爽点类型（9类，章纲选1-2）**：战斗胜利/夺宝获资/成长升级/打脸装逼/剧情推进/关系推进/身份跃迁/危机拯救/震撼场面。

**打回意见（四要素格式）**：位置（章节/段落/句子）→ 问题（违反哪条既有事实/信息边界/爽点/情绪坐标）→ 严重性（严重/警告/提示）→ 改法（不改变核心剧情的最小修复）。按此给 write，**不替 write 写文、只给方向和最小修法**——通过才入库，最多 2 轮。

**第 2 步 生成本章日志**

按定稿正文写本章日志（路径照 §0；模板 `templates/chapter-card.tpl.md`）：
1. 时间 · 地点 · 人物
2. 本章剧情（顺一遍，回看用）
3. 这一章定了哪些事（改了后文对不上的重事实）
4. 这一章动了哪些线（`线｜这章干了啥｜线现在走到哪`）
5. 爽点 · 钩子 · 情绪（字段：爽点类型一句话＋本章留下的钩＋本章情绪峰值对照剧情-情绪打分表）

> **write 交接并入**：write 对话回复给【冲突标注/新增事实待核】——review 核验有效性后并入"这一章定了哪些事"，write 只声明不落库，落库以 review 为准。**涌现线**：新长出的设定（从内容模板库新选/世界碎片/金手指形态/新角色）一并接（标装配来源），第 3 步落账本"已长出设定"。

> **字数=消费 write 交接数据**：字数检查已在 write 内收束（`word-count.ps1` 由 write 存档后自跑，不足自扩写，不交 review 补救）。review 不跑字数脚本，直接把 write 交接的 stdout 原文（`chNNN.txt|汉字N|判定:PASS`）填进本章日志"字数"栏；交接缺失时追问 write，不自己补跑。

> **存档后半步=去AI味**：章日志存档后自跑 `python skills/pop-snow-pipeline/scripts/deai_gate.py {章日志路径} --profile doc --json`——WARN 定位自查（档案措辞贴事实，装腔换大白话）、机械项 `--fix`，结果一行 `去AI味:ch{NNN}-章日志|PASS` 或 `WARN×N`。

**第 3 步 更新状态档**

打开状态档（路径照 §0），按本章日志 replace：
- 新人物 / 新线 / 新悬念 → 进"活跃"；
- 已解 / 已弃 / 退场 / 已揭 → 移出"活跃"，落退出区/退出档案（模板：`templates/state-snapshot.tpl.md`、`templates/exit-archive.tpl.md`）；
- 更新"现在在哪"，给出下一章开写前的准。
- 这章若有意改翻了某条旧现状 → 当场标"改了哪条、为什么"，留痕。
- **涌现线**：新增「已长出设定」落点——write 从内容模板库新选/临场长出的设定/新角色，核验后落这里（只记够写章用的、后续会再用的），**标装配来源**（选了哪个模板/无模板临场造）。
- **存档后半步=去AI味**：状态档 replace 后同第 2 步步法自跑（退出档案本轮有追加也一并跑），结果一行 `去AI味:{档名}|PASS` 或 `WARN×N`。

**群像卫生（撤角色即检查）**：把人物撤进退出区时，对照当前"活跃"角色表顺一遍——**同时活跃 ≤5-7 人**（超出读者记不住）；功能重叠的合并一个（两个智囊不如一个智囊+一个执行者）；每个活跃人物都要有"本章在场理由"，没理由的不进画面；退场必须交代（死亡/离开/转背景板），不许人间蒸发。**每 ~20 章顺手清一次活跃表**：谁还起作用、谁该退。（涌现线升格归属以 stage 模式C 人物分流为准。）

- 结束（灯塔线本单元末章 → 接「剧末回看」；涌现线到故事弧 → 接「阶段性回看」）。

## 剧末回看（灯塔线·单元末章 PASS 后）

**触发**：本单元末章 review PASS。**产出** `剧情日志/单元N-回看.md`。**对照物**：`剧情库/单元N-编排.md`＋`剧情库/00-上升线表.md` 本行＋北极星块＋`{pop-lantern-plot}/references/内容库/剧情-情绪打分表.md`。

**单元级六查**（逐条核，全过才进 stage 模式C 重跑）：

| # | 检查 | 判据 |
|:--|:--|:--|
| 1 | **起承转合完整** | 四拍都在正文兑现？起（承接上单元末钩）→承（手段与第一次变强）→转（最深谷）→合（本集问题解决）——缺拍=回写 |
| 2 | **本集问题解决** | 单元末读者不憋屈——本集问题有答案（哪怕答案引向更大的问题） |
| 3 | **上升一格兑现** | 对照上升线表本行"从X到Y"：读者能说出主角/世界比单元初强了一层？只堆事件没跃迁=假上升 |
| 4 | **剧末钩子立住** | 指向下一格（下一单元上升维度预告）——钩子类型 6 类之一，与单元末章章末钩一致；对照打分表好奇模块查出 `好奇·X档`（伪钩子=打回 plot） |
| 5 | **埋种清单兑现** | 单元编排"伏笔账·本集种"该种的机会种了吗？终局关键人物登场窗口错过没？（对照北极星块） |
| 6 | **伏笔 Triage 判级** | 本单元涉及的每条伏笔判过级：必须/尽量/可留——必须的已排上回收路径，可留的显式搁置 |

**情绪达标回看**：本单元四拍情绪峰值是否达到编排目标（对照打分表）？哪拍没推到位=标出，下单元同类拍补强或回写本章。回看时先反核单元编排的情绪目标标注（虚标=编排层问题，标给 plot 下单元修正）。

**配方生效回填（本步必做）**：记录本单元消费的配方——单元剧模板（选了什么类型）/套路（哪几章用了什么套路）/力量世界观模板（stage 用了什么）——逐一记"生效情况/效果如何"，**回填对应内容库验证状态**（`{pop-lantern-plot}/references/内容库/单元剧模板库.md`、`pop-outline/references/内容库/套路库.md`、`{pop-lantern-stage}/references/内容库/力量体系模板库.md`、`{pop-lantern-stage}/references/内容库/世界观模板库.md`），有效=升级验证状态，无效=标弱并写原因。现场提取的新配方若本单元用过，确认 48h 内已回填。

**回看记录格式**：六查逐条 `PASS/REJECT＋一句证据`；情绪回看一行；配方回填清单（库名/配方名/验证状态变更）。REJECT 项 → 回写（由 plot 处理）；全 PASS → 汇报"单元N回看 PASS"，调度 stage 模式C 重跑 → plot 上升线推进。

**存档后半步=去AI味**：`python skills/pop-snow-pipeline/scripts/deai_gate.py 剧情日志/单元N-回看.md --profile doc --json`，结果一行 `去AI味:单元N-回看|PASS` 或 `WARN×N`。

## 阶段性回看（涌现线·每 N 章/一个故事弧后）

每写完一个故事弧（约 5-10 章）或老板要求时，产一份**回看报告**（对话交付，不强制存档文件）：

1. **方向校准**：对照模糊灯塔（立项卡）——主角行动还朝那个方向吗？第一个标到了吗？偏了就说偏了，怎么掰回来（不改设定，改下一批章纲的排法）。
2. **情绪点兑现**：这 N 章峰值达成率怎么样（对照章日志情绪坐标字段）——有几章没到峰值点？假致命峰值有几处？峰值类型是不是总在同一情绪上（老用害怕=单调，要换情）？高阶情绪（感动/甜蜜/悲伤）没把握的章有没有硬赌？
3. **账本长出盘点**：这 N 章从账本长出了哪些设定（标了哪个模板）——哪些成了新锚（后续要一直用），哪些一次性细节已过时（从"已长出设定"清掉）。

回看不是大改——只是校准方向，继续滚动。回看后回 outline 排下一批章纲。

## 批量回溯（可选）

对已有正文批量重建时，用同一个流程逐章跑：每章做第 1 步（存量正文视为已定稿）→ 第 2 步建本章日志 → 第 3 步合进状态档。批量不宜一次硬吞，按采样/分批逐章推进。回溯到单元末（灯塔线）时补跑剧末回看。
