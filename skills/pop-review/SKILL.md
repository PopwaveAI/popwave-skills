# pop-review

> 本技能只规定流程、文件契约与检查项，不规定题材、结构、风格或审美偏好。
> 本技能负责章节验收、存档与回看，三条流程线共用。只做三件事：确认本章定稿、生成本章日志、更新状态档。
> 本技能由灯塔线 pop-lantern-review、雪花线 pop-snow-review、涌现线 pop-emergent-review 合并而成。三线共用主干流程，差异见 §0。
> 当前版本 2.0.0，版本历史见 CHANGELOG.md。

## §0 流程线判定（验收前先读本表）

| 线 | 判定依据（项目内存在的上游文件） | 本章日志 | 状态档 | 回看 |
|:--|:--|:--|:--|:--|
| **灯塔流** | 项目内存在 `剧情库/单元N-编排.md` | `剧情日志/ch{NNN}.md` | `剧情日志/全书日志.md` 与 `剧情日志/退出档案.md` | 单元末章 PASS 后执行剧末回看 |
| **雪花流** | 项目内存在 `剧情库/卷N-幕M-白描.md` | `剧情日志/ch{NNN}.md` | `剧情日志/全书日志.md` 与 `剧情日志/退出档案.md` | 无独立回看（卷循环由 plot 承载） |
| **涌现流** | 项目内存在 `剧情日志/涌现账本.md` | `剧情日志/ch{NNN}.md` | `剧情日志/涌现账本.md`（一体档：当前态、悬着的线、已长出设定、退出区四项合一） | 每 5-10 章或一个故事弧执行阶段性回看 |

**无法判定所属流程线时**：先读项目内 `状态.md` 的线声明。仍无法判定时向用户确认，不猜。

## 这是什么

本技能是「写完这一章、准备写下一章」之间的存档关口。本技能**不评文风、不打分、不审审美**。只把「这一章发生了什么」记录下来，把「世界当前是什么样」更新到最新，让下一章开写前有可依据的状态。

**正文未获用户满意之前，不得进状态档**（仍在修改的稿，不予记录）。

**涌现线特有**：write 从内容模板库新选的设定、临场生成的新设定、新角色、偏离章纲的内容，由本技能核验后写入账本「已长出设定」区，成为后续章节不可违背的事实。

## 三件事

| # | 事项 | 产出 |
|:--|:--|:--|
| 1 | 确认本章正文定稿 | 定稿，或打回 write 改稿，不入库 |
| 2 | 按定稿正文生成本章日志 | 本章日志（路径照 §0 表查，只增不改） |
| 3 | 按本章日志更新状态档 | 状态档（路径照 §0 表查，当前态 replace，只记活跃）；移出项写入退出区或退出档案 |

## 两个产物与一个状态档

- **本章日志**：每章一张，只增不改，记录这一章发生了什么（事件源，属历史）。
- **状态档**：单份 replace，只记当下仍活跃的内容：现在在哪、人物此刻状态、此刻悬着的线、尚未揭开的悬念、不得触碰的事项。（涌现线：状态档即涌现账本，另有「已长出设定」区。）
- **退出区或退出档案**：从状态档移除的内容，即已回收线索、已退场角色、已完结线，落入此处留痕。（涌现线：退出区在账本内。）

**三条规则：**

1. 状态档只记活跃。人物退场、线索已回收、线已完结，挪入退出区，不留在当前态。
2. 世界规则与静态设定不进状态档。力量体系、货币、地理这些内容在设定库、编排或大纲里已有，重复记录会形成双源冲突。（涌现线例外：写章过程中真实生成的设定，进「已长出设定」区。）
3. 状态档不拆分。当前态就是这一份，靠「只记活跃」控制体积。

## 步骤

### 第 1 步 确认定稿

读取本章正文，按下列清单逐条核对。全部通过后交用户确认；用户确认即定稿，进入第 2 步。任一未过或用户不满意，打回 write 改稿，不入库，本流程结束。

| # | 检查项 | 判定 |
|:--|:--|:--|
| 1 | **硬状态承接** | 位置、伤势、能力、持有物、信息边界，与上一章结尾及状态档均无错位。以「突然想到」「突然做到」糊过去，判为不一致 |
| 2 | **时间线** | 本章时间与上一章结束时间衔接；章内时序不倒退、不跳空 |
| 3 | **人名与称谓** | 人名、称谓、身份、关系与状态档及前文一致；改名、改称呼须有正文事件支撑 |
| 4 | **前后章衔接** | 上一章结尾的处境、人物位置、未结线索在本章有交代；不出现与上一章互斥的事实 |
| 5 | **行为可信** | 人物行为能由既有经历、利益、恐惧、渴望、压力、误判推出。只能用「剧情需要」解释，判为 OOC |
| 6 | **信息边界** | 角色不掌握他此刻不该知道的信息 |
| 7 | **未结线索** | 状态档登记的每条线，本章已推进、已回收、或写明继续悬置。不静默丢线，不提前吞并未到期的线 |
| 8 | **用户要求** | 用户当次提出的要求已落实。用户未表态的项标「待定」，不替用户判定 |

**打回意见（四要素）**：位置（章节、段落或句子）、问题（违反哪条既有事实、信息边界或用户要求）、严重性（严重、警告、提示）、改法（不改变核心剧情的最小修复）。只给方向与最小修法，不替 write 写文。通过方可入库，最多两轮。

### 第 2 步 生成本章日志

按定稿正文生成本章日志，路径照 §0 表查，模板为 `templates/chapter-card.tpl.md`：

1. 时间 · 地点 · 人物
2. 本章剧情（按顺序梳理一遍，供回看使用）
3. 这一章定了哪些事（记录改了之后与后文对不上的重事实）
4. 这一章动了哪些线（`线｜这章做了什么｜线现在走到哪`）
5. 未结线索与章末落点（本章留下哪些未结线索、预期回收位置；章末停在哪）
6. 字数（取自 write 交接的 `word-count.ps1` 标准输出原文）

> **write 交接并入**：write 在对话中回复【冲突标注／新增事实待核／待定项】，本技能核验后并入「这一章定了哪些事」。write 只声明不写入库文件，入库以本技能为准。涌现线：新生成的设定，含从内容模板库新选的设定、金手指新形态、新角色，一并接收并标注装配来源，第 3 步写入账本「已长出设定」区。

> **字数一项消费 write 的交接数据**：字数检查已在 write 环节收束，`word-count.ps1` 由 write 在存档后自行执行。本技能不执行字数脚本，直接把 write 交接的标准输出原文（`chNNN.txt|汉字N|判定:PASS`）填入本章日志「字数」栏。交接缺失时追问 write，不自行补跑。

> **章日志措辞贴合事实**，把装腔的表述换成白话。

### 第 3 步 更新状态档

打开状态档，路径照 §0 表查，按本章日志执行 replace：

- 新人物、新线、新悬念，进入「活跃」区。
- 已解、已弃、退场、已揭的内容，移出「活跃」区，落入退出区或退出档案（模板为 `templates/state-snapshot.tpl.md` 与 `templates/exit-archive.tpl.md`）。
- 更新「现在在哪」一项，给出下一章开写前的基准。
- 本章若有意推翻某条旧现状，当场标注「改了哪一条、原因是什么」。
- **涌现线**：新增「已长出设定」落点。write 从内容模板库新选的设定、临场生成的设定、新角色，核验后写入此处（只记后续会再使用的），并标注装配来源（用了哪个模板，或无模板时临场生成）。

**退场处理**：把人物撤进退出区时，写明退场方式（死亡、离开、转为背景板），不留「人间蒸发」。已退场角色从活跃表移除。

- 结束。灯塔线在本单元末章之后接剧末回看；涌现线到达故事弧之后接阶段性回看。

## 剧末回看（灯塔线·单元末章 PASS 后）

**触发条件**：本单元末章 review 通过。**产出**：`剧情日志/单元N-回看.md`。**对照物**：`剧情库/单元N-编排.md`、`剧情库/00-主线结构表.md` 本行、`剧情日志/全书日志.md`。

逐条核对，只记事实与偏差，不评好坏：

| # | 检查项 | 判据 |
|:--|:--|:--|
| 1 | 排定事件兑现 | 单元编排排定的事件是否都发生。未发生的写明原因与去向（移入下一单元、废弃、改由自补位替代） |
| 2 | 主线进度 | 对照主线结构表本行，写明本单元结束时主线从哪推进到哪；与计划不一致处写明原因 |
| 3 | 未结线索 | 列出本单元新开、已回收、仍悬置的线。到期的线是否处理；未处理的写明留给哪一章 |
| 4 | 设定变动 | 本单元新生成并写入状态档的设定，是否与既有设定冲突 |
| 5 | 状态档一致性 | 状态档当前态与本章日志、退出档案是否一致 |
| 6 | 偏离记录 | 列出 write 偏离章纲、outline 自举或自补的位置，写明是否保留，交用户确认 |

**记录格式**：逐条写 `PASS／REJECT＋一句证据`。REJECT 项回写，由 plot 处理；全部 PASS 时汇报「单元N回看 PASS」，再推进 plot 上升线。

## 阶段性回看（涌现线·每 N 章或一个故事弧后）

每写完一个故事弧（约 5-10 章）或用户要求时，产出一份回看报告，在对话中交付，不强制存档为文件：

1. **方向校准**：对照立项卡的模糊灯塔，核查主角行动是否仍朝该方向、第一个标是否达到。偏离则如实说明，并给出修正方式：不改设定，改下一批章纲的排法。
2. **未结线索盘点**：列出这 N 章新开、已回收、仍悬置的线；到期的线是否处理。
3. **账本长出盘点**：盘点这 N 章从账本生成了哪些设定、分别标注了哪个模板。分辨哪些成为新锚、后续继续使用，哪些一次性细节已过时、应从「已长出设定」中清掉。
4. **偏离记录**：列出 write 偏离章纲的位置与处理结果，交用户确认。

回看不做大改，只做事实核对与方向校准。回看完成后回到 outline，排下一批章纲。

## 批量回溯（可选）

对已有正文批量重建时，用同一流程逐章执行：每章先做第 1 步，存量正文视为已定稿；再做第 2 步生成本章日志；最后做第 3 步合进状态档。批量处理分批逐章推进。回溯至单元末时，灯塔线补跑剧末回看。

## 交付提醒

本次任务只要产出了文档（brief、故事核、试写章、设定、人物卡、章纲、正文、审核报告等），交付回复必须写清产出了哪几份、各自路径，并提醒用户可点开右侧文件夹按钮预览详细内容；没有文档产出就不写这段。
