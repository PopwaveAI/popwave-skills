# pop-review

> 本技能负责章节验收、存档与回看，三条流程线共用。只做三件事：**确认本章正文满意并定稿、生成本章日志、更新状态档**。满意判别含八项：硬状态承接、行为可信、对白辨人、钩子承接、章末落地、高潮后效、**爽点密度**、**情绪达标**。
> 本技能由三条流程线的 review 能力合并而成：灯塔线 pop-lantern-review v3.6.0、雪花线 pop-snow-review v1.8.0、涌现线 pop-emergent-review v1.3.0。合并底稿取自灯塔线，因其判别最全。三条线之间的差异全部收录于 §0 系列适配表。本版为 1.0.0，完整版本历史见 CHANGELOG.md。

| 线 | 判定依据（项目内存在的上游文件） | 本章日志 | 状态档 | 回看 | 本线专有动作 |
|:--|:--|:--|:--|:--|:--|
| **灯塔流** | 项目内存在 `剧情库/单元N-编排.md` | `剧情日志/ch{NNN}.md` | `剧情日志/全书日志.md` 与 `剧情日志/退出档案.md` | **单元末章 PASS 后执行剧末回看**（含单元六查、情绪回看、配方生效回填） | **配方生效回填**（回填 plot 单元剧模板库、outline 套路库、stage 力量体系模板库与世界观模板库的验证状态） |
| **雪花流** | 项目内存在 `卷纲/卷N-幕M-白描.md` | `章节日志/ch{NNN}.md` | `全书日志.md` 与 `退出档案.md` | 本线回看：无（卷循环由 plot 承载） | 无附加动作 |
| **涌现流** | 项目内存在 `剧情日志/涌现账本.md` | `剧情日志/ch{NNN}.md` | `剧情日志/涌现账本.md`（**一体档**：当前态、悬着的线、已长出设定、退出区四项合一，不拆分） | **阶段性回看**（每 5-10 章或一个故事弧执行一次，在对话中交付，不强制存档） | **已长出设定写入账本**（write 从内容模板库新选的设定、临场生成的设定、新角色，经核验后写入账本并标注装配来源）。此为涌现流"设定从账本长出来"的唯一落点 |

**共用底子**：情绪达标一律打开 `{pop-lantern-plot}/references/内容库/剧情-情绪打分表.md`（正本，唯一权威）查级核对。**判据以打分表为准，本文件不另立判据**。

## 这是什么

本技能是"写完这一章、准备写下一章"之间的存档关口。本技能**不审质量**，质量由 write 负责；只负责把"这一章发生了什么"记录下来，把"整个世界当前是什么样"更新到最新，使下一章开写之前有可依据的状态。

**正文未获用户满意之前，不得进账本**（仍在修改的稿，不予记录）。

**涌现线特有**：本技能是"设定从账本长出来"的执行者。write 从内容模板库新选的设定、临场生成的新设定、新角色、偏离章纲的内容，由本技能核验后写入账本"已长出设定"区，成为后续章节不可违背的事实。

## 三件事

| # | 事项 | 产出 |
|:--|:--|:--|
| 1 | 确认本章正文满意 | 满意即定稿；不满意则打回，不入库 |
| 2 | 按定稿正文生成本章日志 | 本章日志（路径照 §0 表查，只增不改） |
| 3 | 按本章日志更新状态档 | 状态档（路径照 §0 表查，当前态 replace，只记活跃）；回收项入退出区或退出档案 |

**回看（照 §0 表查）**：灯塔线在单元末章 PASS 后执行剧末回看；涌现线每 5-10 章或一个故事弧执行阶段性回看；雪花线无。

## 两个产物与一个状态档

- **本章日志**：每章一张，只增不改，记录"这一章发生了什么"（事件源，属于历史）。
- **状态档**：单份 replace，只记"当下仍活跃的"内容，即现在在哪、人物此刻状态、此刻悬着的线、尚未揭开的悬念、不得触碰的事项，是当前态的投影。（涌现线：状态档即涌现账本，另有"已长出设定"区。）
- **退出区或退出档案**：从状态档移除的内容，即已回收钩子、已退场角色、已完结线，落入此处留痕，防止失联。（涌现线：退出区就在账本内。）

> 三条心法：
> 1. 状态档**只记活跃**。人物退场、钩子已回收、线已完结，即挪入退出区，不得继续留在当前态。如此状态档"进得来出得去"，写到一百章也不臃肿。
> 2. **世界规则与静态设定不进状态档**。力量体系、货币、地理这些内容在设定库、编排或大纲里已有，重复记录即形成双源冲突。（涌现线例外：写章过程中真实生成的设定，进"已长出设定"区。）
> 3. 状态档**不拆分**。当前态就是这一份，靠"只记活跃"控制体积，不另建一堆文件。

## 步骤

**第 1 步 确认满意与去 AI 味核验**

读取本章正文，判断本章在用户要求与完成度两项上是否达到定稿。
- 满意：定为定稿，进入第 2 步。
- 不满意或仍需修改：打回 write，或告知用户，**不入库**，本流程结束。

**去 AI 味核验（收尾检查）**：查看上游去 AI 味结果，含两项：第一，write 交接的正文去 AI 味结果，即正文经 `deai_gate.py` 检查后 FAIL 清零；第二，outline 章纲的 `去AI味:ch{NNN}-章纲|PASS` 或 `WARN×N` 结果。章纲缺少结果时，由本技能补跑一次 `python skills/pop-snow-pipeline/scripts/deai_gate.py {章纲路径} --profile doc --json`，WARN 项按定位自查，机械项交由 `--fix` 处理，并在对话中注明已补跑去 AI 味。正文去 AI 味结果缺失时，在本章日志中备注"上游去 AI 味结果缺失"，提示 write 在下一章前补跑。此项检查只报告不打回，核验不阻塞存档，但必须留痕。

**满意判别标准（第 1 步"确认满意"时逐条核对，作为"定稿或打回"的判据。只审一致性、连续性、设定、爽点、情绪五项，不审文风）**：

| # | 判别维度 | 判定 |
|:--|:--|:--|
| 1 | **硬状态承接** | 位置、伤势、能力、持有物、信息边界，与上一章结尾及状态档均无错位；以"突然想到""突然做到"糊过去，即判为不一致 |
| 2 | **行为可信（动机六问）** | 异常行为能由经历、利益、恐惧、渴望、压力、误判六项推出；**只能用"剧情需要"解释，即判为 OOC**；**信息越界，即角色知道了他不该知道的事，为最严重问题，优先于性格偏差** |
| 3 | **对白遮名辨人** | 隐去角色名后仍能分辨谁在说话，依据为称呼、句长、语气、禁忌。抽取一至两段查验 |
| 4 | **钩子承接** | 上一章钩子在本章有反馈，方式为回应、推进、误导或压住；章末留下新缺口，对照打分表好奇模块标注 `好奇·X档`，伪钩子即打回；未提前吞并未到期的钩子 |
| 5 | **章末落地改变** | 信息、关系、物理、权力四类中至少一类落地；**四类皆无，即判为空转章** |
| 6 | **高潮后效** | 本章处于大高潮之后一至两章时，须写出改变，包括主线推进、人设成长、关系变化，不得直接跳入下一个蓄压 |
| 7 | **爽点密度** | 对照章纲爽点标注逐条核对：每章 ≥1 个重大爽点（无爽点章不得连续），密度目标 ≥2；爽点须含三项，即**发生**（事件本身）、**反应**（读者情绪落点，对照打分表情绪名）、**影响**（对状态或剧情的实际改变）。只写事件而不写反应与影响，即判为假爽点；章纲标注的爽点正文未兑现，即打回 |
| 8 | **情绪达标** | **第一，反核章纲标注**：打开 `{pop-lantern-plot}/references/内容库/剧情-情绪打分表.md`，对照其情绪细则与反例区，核查章纲中的八分事件是否符合打分表情绪定义与铺垫成本。八分定义、临界规则、虚标判据一律以打分表为准，不另立判据。**虚标直接打回 outline 重排，不核正文**。**第二，核正文兑现**：比对本章实际情绪强度与目标值，**差两级以上即打回**（目标为 `愤怒·8分`，实际只到 `愤怒·5分`，说明这场戏未推至设计高度）。**第三，核峰值兑现**：章纲标注的八分事件在正文中未兑现或未写透，即打回。**第四，情绪布局纪律**：与上一章不得连续同一时刻，十级顶点不得滥用，对照打分表峰值规则与反例区 |

**爽点类型（九类，章纲中选择一至两类）**：战斗胜利、夺宝获资、成长升级、打脸装逼、剧情推进、关系推进、身份跃迁、危机拯救、震撼场面。

**打回意见（四要素格式）**：位置，指章节、段落或句子；问题，指违反哪一条既有事实、信息边界、爽点或情绪坐标；严重性，分严重、警告、提示三级；改法，指不改变核心剧情的最小修复。按此四项给 write，**不替 write 写文，只给方向与最小修法**。通过方可入库，最多两轮。

**第 2 步 生成本章日志**

按定稿正文生成本章日志，路径照 §0 表查，模板为 `templates/chapter-card.tpl.md`：
1. 时间 · 地点 · 人物
2. 本章剧情（按顺序梳理一遍，供回看使用）
3. 这一章定了哪些事（记录改了之后与后文对不上的重事实）
4. 这一章动了哪些线（`线｜这章做了什么｜线现在走到哪`）
5. 爽点 · 钩子 · 情绪（字段为：爽点类型一句话、本章留下的钩、本章情绪峰值对照剧情-情绪打分表）

> **write 交接并入**：write 在对话中回复【冲突标注/新增事实待核】，本技能核验有效性后并入"这一章定了哪些事"。write 只声明不写入库文件，入库以本技能为准。**涌现线**：新生成的设定，含从内容模板库新选的设定、世界碎片、金手指形态、新角色，一并接收并标注装配来源，第 3 步写入账本"已长出设定"区。

> **字数一项消费 write 的交接数据**：字数检查已在 write 环节收束，`word-count.ps1` 由 write 在存档后自行执行，字数不足时自行扩写，不交由 review 补救。本技能不执行字数脚本，直接把 write 交接的标准输出原文（`chNNN.txt|汉字N|判定:PASS`）填入本章日志"字数"栏。交接缺失时追问 write，不自行补跑。

> **存档后的收尾步骤为去 AI 味**：章日志存档后自行执行 `python skills/pop-snow-pipeline/scripts/deai_gate.py {章日志路径} --profile doc --json`。WARN 项按定位自查，要求档案措辞贴合事实，把装腔的表述换成白话；机械项交由 `--fix` 处理。结果记一行 `去AI味:ch{NNN}-章日志|PASS` 或 `WARN×N`。

**第 3 步 更新状态档**

打开状态档，路径照 §0 表查，按本章日志执行 replace：
- 新人物、新线、新悬念，进入"活跃"区；
- 已解、已弃、退场、已揭的内容，移出"活跃"区，落入退出区或退出档案（模板为 `templates/state-snapshot.tpl.md` 与 `templates/exit-archive.tpl.md`）；
- 更新"现在在哪"一项，给出下一章开写前的基准。
- 本章若有意推翻某条旧现状，当场标注"改了哪一条、原因是什么"，留下记录。
- **涌现线**：新增「已长出设定」落点。write 从内容模板库新选的设定、临场生成的设定、新角色，经核验后写入此处（只记足够写章使用、后续会再使用的），并**标注装配来源**（选用了哪个模板，或无模板时临场生成）。
- **存档后的收尾步骤为去 AI 味**：状态档 replace 后，按第 2 步的方法自行执行（退出档案本轮若有追加，一并执行），结果记一行 `去AI味:{档名}|PASS` 或 `WARN×N`。

**群像卫生（撤角色时即检查）**：把人物撤进退出区时，对照当前"活跃"角色表顺查一遍。**同时活跃 ≤5-7 人**，超出读者记不住；功能重叠者合并为一个，两个智囊不如一个智囊加一个执行者；每个活跃人物都要有"本章在场理由"，无理由者不进画面；退场必须交代，方式为死亡、离开或转为背景板，不得人间蒸发。**每约 20 章顺带清理一次活跃表**，确认谁仍起作用、谁应当退出。（涌现线升格归属以 stage 模式C 人物分流为准。）

- 结束。灯塔线在本单元末章之后接「剧末回看」；涌现线到达故事弧之后接「阶段性回看」。

## 剧末回看（灯塔线·单元末章 PASS 后）

**触发条件**：本单元末章 review 通过。**产出** `剧情日志/单元N-回看.md`。**对照物**：`剧情库/单元N-编排.md`、`剧情库/00-上升线表.md` 本行、北极星块、`{pop-lantern-plot}/references/内容库/剧情-情绪打分表.md`。

**单元级六查**（逐条核对，六项全部通过方可进入 stage 模式C 重跑）：

| # | 检查 | 判据 |
|:--|:--|:--|
| 1 | **起承转合完整** | 四拍是否均在正文兑现：起，承接上一单元末钩；承，手段与第一次变强；转，最深谷；合，本集问题解决。缺拍即回写 |
| 2 | **本集问题解决** | 单元末读者不憋屈，即本集问题有答案，哪怕答案引向更大的问题 |
| 3 | **上升一格兑现** | 对照上升线表本行"从X到Y"，读者能说出主角或世界比单元初强了一层。只堆事件而无跃迁，即判为假上升 |
| 4 | **剧末钩子立住** | 指向下一格，即下一单元上升维度的预告；为钩子六类之一，与单元末章章末钩一致；对照打分表好奇模块查出 `好奇·X档`。伪钩子即打回 plot |
| 5 | **埋种清单兑现** | 单元编排"伏笔账·本集种"中应埋的种子是否埋下；终局关键人物的登场窗口是否错过。对照北极星块 |
| 6 | **伏笔 Triage 判级** | 本单元涉及的每条伏笔均已判级，级别为必须、尽量、可留三级。必须级已排上回收路径，可留级显式搁置 |

**情绪达标回看**：核对本单元四拍情绪峰值是否达到编排目标，对照打分表。未推到位的拍标出，下一单元同类拍补强，或回写本章。回看时先反核单元编排的情绪目标标注；虚标属于编排层问题，标注给 plot，由下一单元修正。

**配方生效回填（本步必做）**：记录本单元消费的配方，含三类：单元剧模板，记选用了什么类型；套路，记哪几章用了什么套路；力量与世界观的模板，记 stage 用了什么。逐一记下"生效情况与效果如何"，**并回填对应内容库的验证状态**，涉及 `{pop-lantern-plot}/references/内容库/单元剧模板库.md`、`pop-outline/references/内容库/套路库.md`、`{pop-lantern-stage}/references/内容库/力量体系模板库.md`、`{pop-lantern-stage}/references/内容库/世界观模板库.md`。有效则升级验证状态，无效则标记为弱并写明原因。现场提取的新配方若本单元用过，确认已在 48h 内回填。

**回看记录格式**：六查逐条记 `PASS/REJECT＋一句证据`；情绪回看记一行；配方回填列一份清单，含库名、配方名、验证状态变更。REJECT 项回写，由 plot 处理；全部 PASS 时，汇报"单元N回看 PASS"，调度 stage 模式C 重跑，再推进 plot 上升线。

**存档后的收尾步骤为去 AI 味**：执行 `python skills/pop-snow-pipeline/scripts/deai_gate.py 剧情日志/单元N-回看.md --profile doc --json`，结果记一行 `去AI味:单元N-回看|PASS` 或 `WARN×N`。

## 阶段性回看（涌现线·每 N 章或一个故事弧后）

每写完一个故事弧（约 5-10 章）或老板要求时，产出一份**回看报告**，在对话中交付，不强制存档为文件：

1. **方向校准**：对照模糊灯塔（立项卡），核查主角行动是否仍朝该方向、第一个标是否达到。偏离则如实说明偏离，并给出修正方式：不改设定，改下一批章纲的排法。
2. **情绪点兑现**：核对这 N 章的峰值达成率，对照章日志情绪坐标字段。统计有几章未到峰值点、假致命峰值有几处、峰值类型是否总落在同一情绪上（老用害怕即单调，须换情绪）。高阶情绪，即感动、甜蜜、悲伤，无把握的章是否有硬赌。
3. **账本长出盘点**：盘点这 N 章从账本生成了哪些设定、分别标注了哪个模板。分辨哪些成为新锚、后续要一直使用，哪些一次性细节已过时、应从"已长出设定"中清掉。

回看不是大改，只做方向校准，之后继续滚动。回看完成后回到 outline，排下一批章纲。
