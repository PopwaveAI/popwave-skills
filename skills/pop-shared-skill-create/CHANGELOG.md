## v9.0.0 — 2026-09-13

### 新增 `prd/`（设计档案）为 skill 标配

> **根因**：老板 2026-09-13 指示——「在 pop editor 里面应该新建一个子文件夹 叫 prd。这个用来记录 这个skill 设计预期（为了解决什么问题）解决思路 当前进度 后续可迭代方向/未完成的探索。这个 prd 文件夹 应该成为所谓 skill 的标配 方便有效迭代和维护 skill 持续进化。」

**为什么是 major**：给全部 skill 加了一类必建的资源目录，skill 作者与改造流程的行为都变。

**改动**：
- **`prd/` 升为标配**（原只有 references/templates/scripts 三类资源）。两个文件分工固定：
  - `prd/PRD.md` — 设计预期（解决什么问题，带凭据）、解决思路（每步为什么必须这样）、关键取舍（选了什么／放弃了什么／为什么）、不做什么（**指名邻接 skill**）。**改一次要慎重**。
  - `prd/进度与待探索.md` — 当前进度（已完成带凭据／进行中／已知缺口）、后续方向（近期／中期／长期，每项带"怎么算做完"）、悬而未决（等谁拍）、踩过的坑。**每轮都动**。
- **三条纪律写进规范**：①"已完成"必须带凭据（写"已完成""已验证"不算完成）；②"怎么算做完"不许写"改好为止"；③取舍表里"放弃了什么"不能空。
- **新增两个模板**：`templates/prd-PRD.tpl.md`、`templates/prd-进度与待探索.tpl.md`。模板里带填写纪律（不许写形容词验收、不许预写没踩过的坑）。
- **二、内容定位**：结构图加 `prd/`；资源目录表加一行；新增一节讲 prd 的定位、两文件分工与三条纪律。
- **七、创建流程**：新增第 6 步「创建 `prd/`（标配，必建）」，并强调**创建时就要把"解决什么问题"与"第一条验收"写实**（那时资料最全）；完成报告要含 prd 两份。
- **八、改造流程**：原 5 步扩成 6 步，新增第 3 步「补 `prd/`（缺则必补）」，内容从 SKILL.md／CHANGELOG／git 历史反推，**推不出来的写"待补（日期）"，不许编**。
- **九、检查清单**：结构项加「`prd/` 存在且两文件齐全，已完成各条带凭据、怎么算做完可判、取舍表的放弃了什么不空」；另补一条「**包内没有任何指向已不存在文件的指针**」（起因：pop编辑 曾因手动删文件留下 9 处指空）。
- **十、写入检查点**：加一行 `prd/`（标配，必建）。

**范本**：`skills/pop-editor/prd/` 是本规范的第一份实例（v3.1.0 建）。

## v8.0.0 — 2026-09-09

### 全文用词升级为 Mirror 创作专家标准，新增「五、用词与表达」

> **根因**：老板 2026-09-09 指示——镜界专家系列（D:\popwave-skills\Mirror创作专家）的文档用词最稳：不写生僻黑话，也不写大白话口语。把它的写法定成本规范的书写标准，从源头教后续每个 skill 怎么用词、怎么表达需求。

**改动**：
- **新增「五、用词与表达（照 Mirror 创作专家系列）」节**：六条书写标准，每条是行为指令+正反例对照——
  1. 规则写成行为指令（做什么/不做什么，一条一个动作，不写感受评价）
  2. 新概念出现即定义，用"是A，不是B"锁边界
  3. 判断给锚点，不给形容词（写"以什么判断"）
  4. 行业词直接用，不自造（引擎/耦合/闭环）也不降格（管饭/撒盘边）
  5. 一段一义，短句为主
  6. 禁 AI 腔（值得注意的是/总而言之等）
  - 附判据：写完拿给没读过文档的人看，任何一句都能照做、不用追问
  - 「装饰性比喻黑名单」保留，改写为行为指令格式
- **全文用词 Mirror 化**：黑话换人话——注入链/harness/host 层→运行环境/平台，机读→机器读，加载门禁→检查条件，落盘→写入，骨架→主干；「单文件自包含」「强弱加载保障」保留术语但补"是A不是B"定义
- **检查清单「文档质量」组**：去AI味六条自检 → 五、用词与表达六条对照
- skill.json description 补"用词照 Mirror 创作专家系列"，version 7.3.0→8.0.0

## v7.0.0 — 2026-08-24

### 规范口径升级为单文件自包含：steps/ 目录废除，step-1-design.md 规范正文全合入 SKILL.md

> **根因**：实测 step 文件在当前 harness 从未被加载/Read（子agent注入链断在骨架层）——skill 注入链只把 SKILL.md 全文注入 prompt，SKILL.md 里对 steps/xxx.md 的引用形同虚设。全仓 41 个 skill 的 steps/ 已于 2026-08-24 全部合入单文件，本规范（教别人怎么建 skill 的规范本身）必须同步改口径。

**改动**：
- **steps/ 目录删除**：step-1-design.md（规范完整正文）全部合入 SKILL.md 一~十节
- **规范口径修改**（规范级，覆盖正文所有 steps/ 目录设计位置）：
  - 「SOP骨架 + steps 展开层」教法 → 「单文件自包含」教法：SKILL.md 骨架节直接内联执行要点，不再建 steps/ 目录
  - 目录结构/层级职责表去掉 steps/ 展开层；「steps vs references vs templates vs scripts 区别表」缩为三类资源表
  - 删除「steps/ 文件拆分原则（按独立阶段拆）」与「step 文件自传导（加载门禁+下一步指引）」两节，新增「执行要点内联写法」（合入精炼原则：50-65% 体量控制/门禁与脚本调用方式不丢）
  - 红线❌3 改口径：自带 SOP 骨架 → 单文件自包含 + 禁止 steps/ 目录与引用
  - 检查清单/落盘检查点/创建流程/改造流程同步：新增"无 steps/ 目录、无 steps/ 引用残留"检查项，改造流程新增"发现 steps/ 合入并删目录清引用"步骤
- **保留**：资源分层原则（references/templates/scripts 外部文件合法）、scripts 代码目录规范、精简原则（红线≤7/注意力预算/信息不重复）、强弱加载保障（弱保障集合从 steps/references/templates/scripts 缩为 references/templates/scripts）
- **执行模式明确**：主agent直执（规范理解与落盘一体）
