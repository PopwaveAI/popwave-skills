# pop-snow-outline

> 章纲＝事前预演的写前参数单（描述约束版）。当前版本 v1.3.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

***

### 心智前置·意识层（贯穿本 skill 与全流程）

动笔/定稿前自问：本产出要更好，还需要看过哪些候选？当前信息够不够？有更优选项没探索？

- **Know-Gap**：先显式列出"要更好需见过哪些候选面"，再列已覆盖，缺口=差值；缺口≥1 个未覆盖维度才触发取材，缺了取、别硬写。

- **Pack**：缺口足够才取材，query 自生成；来源 **wiki 站** **<https://wiki.popwave.cn>** 居先、网络补齐；单环节 ≤1 轮 / ≤5 query / 回传 ≤30KB，超限截断仅留结论区。

- **Worth**：拿本 skill 决策尺对"现有 vs 候选"必给打分表，禁止一句"更优"带过；只端候选/升级版，不越权定终局。

- **Deepen**：产出/候选后自问"这是天花板吗？有更优候选吗？"显著更优才升级再问，上限 2 轮。

取材仅进上下文，升级被采纳才落产出。

***

## 做什么

章纲＝「没文风渲染的正文」该有的剧情含金量，但**只定事件/转折/落点功能，把动作细节、心理、对白台词、结尾意象全部划给 write 现场创作**。write 的唯一向前锚＝章纲，读 3 章渲染正文。

白描卡管"这章发生哪些事件＋锚点"，outline 管"这些事件排成什么推进/张力曲线＋把 write 动笔前要定的东西提前答掉"。

| 项  | 内容                                                                                                     |
| :- | :----------------------------------------------------------------------------------------------------- |
| 输入 | **态**＝`全书日志.md`（当前态·只记活跃）｜**向**＝本幕`卷N-幕M-白描.md`（钦定事件）＋大纲卷向（本卷到哪）＋上一章`章节日志/ch{NNN-1}.md`（衔接） |
| 输出 | `卷纲/章纲/ch{NNN}-章纲.md`（每章一文件）                                                                           |
| 下游 | pop-snow-write（读章纲3章渲染正文）                                                                              |

**执行模式**：章纲求"事前预演+自举"是创作，主agent直执。若缺上游/被改烂，outline 自举推演并将新事件**回流登记全书日志**（B路，见 Step 0）。

## 怎么操作（SOP全内联）

### Step 0：接收自检·A/B双路径

判断本章剧情料是否够推到、能否构成一个让 write 直接起稿的章纲：

- **A路【消费】**：上游健全（白描有钦定事件+锚点，全书日志当前态可用）→ 直接把钦定事件排成节点序列。
- **B路【自举】**：上游缺失/被改烂（用户自带、白描单薄、锚线断裂），或"极可能跟真实后续冲突"的设定风险 → outline **自己推演本章事件**：读全书日志当前态＋悬着的线＋用户最新意图＋大纲卷向，自主定出本章该发生什么＋张力节奏；自举定下的**新事件/新钩子必须回流登记回全书日志**，再据此写章纲。

一句话：**上游好的当导演排张力，上游烂的自己当编剧+导演，且永远踩在最新全书日志上重建。**

### Step 1：输入加载（只看三样，按需零分叉）

- **态**：`全书日志.md`（当前态·只记活跃——现在在哪/人物此刻/此刻悬着的线/没揭悬念/不许碰）
- **向**：本幕`卷N-幕M-白描.md`（本章事件+锚点，白描卡管"写什么"）＋ 大纲卷向（本卷到哪，方向锚）＋ 上一章`章节日志/ch{NNN-1}.md`（衔接"上一章停在哪"）
- **事实抽查**：锚点中的年龄/等级/人名已对照全书日志（plot 已做，此处抽查）

**设定、人物卡、元素卡库、剧情周期表＝一律不进必读。** 它们只是字典，只在"某个节点你实在想不出怎么排张力"时按需点开查一眼；任何"要不要读"的掂量都会分叉注意力，章纲默认零分叉。

### Step 2：写章纲（描述约束版三块）

**块①时空与主体**：时间×地点×在场人物＋每个在场人物今天要干嘛。把该用的角色画进画面，write 不必为"要不要查人物卡"纠结。

**块②事件节点**（每节点≤3行，按推进顺序）：
- **事件**＝谁做什么/发生什么（只定事，不定动作细节）
- **转折**＝这一节点的关键变化
- **落点功能**＝一个动作/一句话写清"这节结尾要读者感受到什么/为后文铺什么"

**块③交接信息**：
- **对白**＝只写"要达成什么"（哪几处、谁对谁、功能），**不预写一句台词**
- **世界观**＝只写"要铺什么功能"（铺哪几处、服务什么），不代劳意象
- **角色语感**＝哪个角色要语气（查那张卡）、哪个免查

### Step 3：描述约束自检（任一越界＝删）

章纲里出现以下任何一项＝"成品句/越界"，必删：

- **动作细节**（"她把干饼掰一半塞给它"→ 只写"她分饼"）
- **心理陈述**（"她心里升起凉意"→ 不写，不代劳）
- **对白台词**（预写具体话 → 只写意图）
- **结尾意象/文学落点**（"天际露出一线血色""决定比夜还硬"→ 只写功能）。

**铁律判据**：章纲里出现任何"像正文句子"的表述＝越界。write 的活（动作/心理/对白/意象）outline 不得代劳，只能圈功能区——用"—write发挥：…你现编—"占位划界。

### Step 4：落盘

每章一文件 `卷纲/章纲/ch{NNN}-章纲.md`（模板 `templates/章纲.tpl.md`）。write 读章纲 3 章渲染正文。write/review 反馈章纲质量问题时回本步重写该章，禁止 write 层私自补剧情——事件锚的修改权在 plot 层，outline 自举的演化登记在全书日志。

## 章纲格式 v4（描述约束版）

```

一、时空与主体

二、事件节点（按推进顺序，每节点≤3行：事件/转折/落点功能）
N1 {名}：事件{谁做什么}｜转折{关键变化}｜落点功能{这节结尾要读者感受到什么/为后文铺什么}
  （write发挥：{动作/心理/对白/意象，你现编}）
N2 …
N{…}

三、交接信息
对白：{哪几处、谁对谁、达成什么——不预写台词}
世界观要铺：{铺哪几处、服务什么——不代劳意象}
角色语感：{哪个角色要语气（查那张卡）｜哪个免查}
```

章型起"方向引导"作用，列在章头作注释，不强制全章按序列组装（章纲 v4 不按章型拼积木，章型只为 write 提示本章基调）。

| 英文枚举          | 中文别名  | 提示基调            |

| opening_shift | 开局转折章 | 世界/身份剧变开局       |

## 红线

1. **描述约束**：章纲只定事件/转折/落点功能，不给动作细节、心理陈述、对白台词、结尾意象。出现"像正文句子"的表述＝越界，删。write 的活不得代劳，只能圈功能区。
2. **自举回流**：B路 outline 自举推演出的新事件/新钩子必须回流登记回全书日志，否则下次写前状态跟史对不平。
3. **事实校验链**：章纲锚点事实字段产前必读全书日志。章纲→正文冲突时以全书日志/前文为准。
4. **零必读分叉**：设定/人物卡/元素卡库/剧情周期表一律不进必读，只当卡壳字典。任何"要不要读"的掂量都是注意力税，默认不掂。
5. **不代plot职责**：上游健全时 outline 只排张力、不发明剧情；自举只在缺上游时兜底，不抢 plot 主导。
