# pop-snow-pipeline

> 本技能只做三件事：建项目目录、记一行状态、按用户说法路由。不写内容、不评审美。
> 当前版本 v9.0.0。

## 何时用

新建项目、导入旧稿、续写、用户说不清这轮做什么、跨环节大改。日常「写第 N 章」不进这里，直接读 `pop-snow-write`。

## 初始化（只在新建或导入时做）

1. 建七个目录：`立项/`、`设定/`、`人物/`、`剧情/`、`章纲/`、`正文/`、`日志/`。
2. 写 `状态.md`，只记七行：书名、当前卷章、立项状态（五节齐全/缺哪节）、章纲状态（已到第 N 章）、成稿批次（已出 N 批）、下一件事、文风/禁区。不写模块清单，不写阶段表。
3. 问三个问题：手上有什么（只有想法／有设定／有卷纲／有正文）、目标（开新书／续写／补设定／只写一章）、篇幅。
4. 按回答路由，不解释整套流程。

## 路由表

| 用户说 | 进 | 只查这一件 |
|:--|:--|:--|
| 有个想法／要方向／新书 | `pop-snow-seed` | 无 |
| 试写／先写个开头看看 | `pop-snow-seed`（第0章试写） | 立项五节（没有就先出三个定位候选让用户选） |
| 写正文／继续写／写下一批 | `pop-snow-write` | 章纲 chNNN + `设定/世界.md` + 人物卡 |
| 改稿／审稿 | `pop-snow-write`（改稿或审稿模式） | 正文 |
| 立项稿体检／补卷／五节缺项 | `pop-snow-seed` | `立项/故事.md` |
| 精修设定／补人物长档 | `pop-snow-stage` | 立项五节（金手指/世界观/人设） |
| 补第 11 章以后章纲／后续卷纲 | `pop-snow-outline` | 分卷设计 + 人物卡 |

**快线默认只走两步**：`pop-snow-seed` 出全书大纲、设定摘要、人物卡、卷 1 卷纲与前 10 章章纲；`pop-snow-write` 按章纲批量写 3-5 章并拼成稿。`pop-snow-stage` / `pop-snow-outline` 只在用户明确说「精修设定」「补后续章纲」时进入，不塞进默认流程。

seed 收尾固定给一章第0章试写（1500–2000 字，存 `立项/第0章试写.md`）：五节立项稿定稿后才写，只验证味道，不占正式章号；用户认可后可直接进 `pop-snow-write`，要精修再进 stage/outline。

## 依赖检查

只回答「现在做这件事，手上够不够」，不要求把前置一次做完：

- 写正文：要有 `章纲/ch{NNN}.md`、`设定/世界.md`、`人物/人物卡.md`；缺章纲或设定先回 seed 补，不自己编。
- 精修设定：要有 seed「金手指设计」「世界观」「核心人设」三节；缺哪节先回 seed 补。
- 补第 11 章以后章纲／后续卷纲：要有 seed「分卷设计」与人物卡；缺分卷设计先回 seed。
- 缺前置时给两个选项：补前置，或按降级继续并记录。

## 老项目兼容

项目里已有 `设计库/`、`人物库/`、`剧情库/`、`剧情日志/` 时，直接读旧路径，不搬文件、不改名；写入时也写回旧路径。只有用户明确要求整理目录时，才迁移到新的七个目录，并在 `状态.md` 记一行「已迁移」。新旧两套同时存在时，以旧路径为准，避免同一设定出现两份。

## 谁干活

- `[主]` 判断路由、建目录、写七行状态、向用户确认。
- `[工具]` 本技能不调用任何写作工具。

## 红线

1. 不建多余目录（不建调研、草稿、文风、拆书目录）。
2. 不写长状态表，不维护模块就绪清单。
3. 不主动读图书馆。
4. 不在一次回复里输出整套流程说明。
5. 默认只走 `pop-snow-seed` → `pop-snow-write` 两步；stage/outline 只在精修或补章纲时进，不塞进默认流程。

## 交付提醒

本次任务只要产出了文档（brief、故事核、试写章、设定、人物卡、章纲、正文、审核报告等），交付回复必须写清产出了哪几份、各自路径，并提醒用户可点开右侧文件夹按钮预览详细内容；没有文档产出就不写这段。
