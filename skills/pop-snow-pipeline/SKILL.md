# pop-snow-pipeline

> 雪花流工作台。当前版本 v2.0.2（2026-10-23：路由表去掉“打分”措辞）。
> 本技能只规定流程、文件契约与检查项，不规定题材、结构、风格或审美偏好。
> 技能 id 与文件名保留 `pipeline`，避免全库跨包引用大改；内部已按工作台理念重写。

---

## 这套工作台怎么运转

雪花流适合"先设计后写作"：立项、世界、人物、卷纲先备足，再稳定跑量。但创作不是流水线，作者会改设定、跳卷、回头补人物、只审一章。

所以工作台只做四件事：

1. 建项目或导入旧稿。
2. 维护 `状态.md`（项目总表）。
3. 按用户当前要做的事路由到模块。
4. 在开工前做依赖检查，缺什么报什么。

**没有 phase，没有"必须先做完 A 才能做 B"的硬顺序。** 唯一的约束来自依赖：写正文要有章纲，排卷要有世界与人物，审稿要有正文。

---

## 职责范围

| 职责 | 说明 |
|:--|:--|
| 一次性初始化（fresh） | 建目录，写 `状态.md` |
| 一次性导入/续写（import/resume） | 扫资产、归位、查缺口、定当前模块、重建状态、调度补跑 |
| 状态维护 | `状态.md` 是唯一总表，agent 只读写其中的状态片段 |
| 路由 | 按用户说法直接选 skill，不让用户记流程 |
| 依赖检查 | 开工前查前置文件，缺则补或显式降级 |

**边界**：工作台不写正文、不做内容转换、不常驻。生成任务由主 agent 加载对应模块执行。

**执行方式**：主 agent 直接执行。初始化与导入交互由主 agent 完成；纯只读检索可派子 agent。

## 路由表

| 用户说 | 直接进 | 开工前检查 |
|:--|:--|:--|
| 写第 N 章 / 继续写 | `pop-write` | `章纲/ch{NNN}-章纲.md` |
| 写章纲 / 排下一章 | `pop-outline` | 本卷卷纲或卷需求 brief |
| 排下一卷 / 卷纲 | `pop-snow-plot` | 世界与人物长档 |
| 改世界 / 改人物 / 补设定 | `pop-snow-stage` | 立项稿 |
| 审这一章 / 找问题 | `pop-review` | `正文/ch{NNN}.txt` |
| 查资料 / 采风 | `pop-snow-research` | 无 |
| 新建项目 / 导入 / 续写 | 本工作台 | 见 Step 0 / Step 1 |

**日常路由不经过本技能**：用户说"写第 5 章"，主 agent 读 `状态.md`，直接加载 `pop-write`。只有新建、导入、状态重建、跨模块大改时才进本工作台。

## 依赖检查

开工前按表查文件，缺前置时给两个选项：补前置，或走降级模式。

| 目标 | 最低前置 | 缺了怎么办 |
|:--|:--|:--|
| 写正文 | 本章章纲 | 补章纲；或降级直写，记录"无章纲" |
| 写章纲 | 本卷卷纲（至少卷需求 brief） | 补卷纲；或降级排章纲，记录风险 |
| 排卷 | 世界与人物长档、上一卷日志 | 补 stage 或 review reconstruct；或降级排卷 |
| 改世界/人物 | 立项稿 | 补 seed；或按用户口述建临时档，标"待回填" |
| 审稿 | 正文 | 先写正文 |
| 卷循环收束 | 本卷章日志与全书日志 | review reconstruct 补账本 |

**依赖检查不是阶段闸**：它只回答"现在做这件事，手上够不够"，不要求把所有前置一次做完。

## 降级模式

用户坚持跳步时，允许，但必须记录：

- 在 `状态.md` 的「降级记录」写：跳了哪一步、欠什么、预计什么时候补。
- 在本章章日志或全书日志标 `降级:无章纲` / `降级:无卷纲`。
- 下一次进入相关模块时，优先补欠账。

**禁止静默降级**：不记录就开写，视为流程违规。

## 推荐节奏（不是硬性状态机）

雪花流的常规跑法：

```
卷需求 brief → 舞台刷新 → 卷纲 → 幕白描（按需）
→ 章纲 → 正文 → 审稿 → 下一章 → … → 卷末盘点 → 下一卷
```

这只是推荐。允许：

- 从任意一环进入，只要依赖检查通过。
- 跳过幕白描（默认就不逐幕执行）。
- 先写几章试味，再回头补卷纲。
- 只改设定、只审一章、只补人物卡。

**卷末盘点**仍建议做：面板与势位、新局解锁、下卷钩子三件套兑现，再进下一卷。

## 状态.md 模板（项目总表）

```markdown
line: snow                # snow / lantern / emergent，用于导入认线
mode: fresh               # fresh / import / resume
focus: 未定               # 当前焦点，写人话：卷2第14章 / 补人物卡 / 修卷1结尾
current_volume: 1
current_chapter: ch000    # 下一章待写
project_name: 未命名项目
genre: 待指定
created_at: --
updated_at: --

## 书目
book_name: 待seed产出
one_line: 待seed产出

## 关键决定
主角: 待定
终点: 待定
文风: 待定

## 模块就绪（[x]=文件已存在且可用）
立项[ ] 世界[ ] 人物[ ] 主线[ ] 卷需求[ ] 卷纲[ ] 幕白描[ ] 章纲[ ] 正文[ ] 日志[ ]

## 当前焦点
- 在做：
- 下一步建议（不强制）：
- 悬而未决：

## 降级记录
| 时间 | 跳了什么 | 欠什么 | 预计补 |
|:--|:--|:--|:--|

## 最近产出
- {日期} {模块} {文件路径}
```

**总表不是阶段机**：只记文件有没有、当前在做什么、欠什么。`focus` 可以是任何一句人话，不要求编号。

## 操作步骤

### Step 0：导入与续写

触发：用户说"导入/续写/已有/接续/迁移"，或 Step 1 检测到 `正文/`、`设计库/` 已有文件。

**0a 资产扫描**：用 LS 扫项目目录，列出文件名、位置、一句话内容。

**0b 资产归位**（只移动与改名，不做内容重构）：

| 用户文件 | 归到 |
|:--|:--|
| 意图、方向、想法、市场调研 | `调研采风/` |
| 采风、资料、原型、场景素材 | `调研采风/采风/` |
| 文风、DNA、笔触 | `文风dna/文风锚定.md` |
| 拆书、力量分析 | `调研采风/decon-lite-{书名}.md` |
| 立项、种子、创意、融合稿 | `立项/00-融合立项稿14维.md` |
| 世界、力量、位阶、势力、基调 | `设计库/` |
| 主角、角色、配角、NPC | `人物库/` |
| 主线、卷进度、卷纲、幕白描 | `剧情库/` |
| 章纲、叙事原子 | `章纲/ch{NNN}-章纲.md` |
| 正文、章节 | `正文/ch{NNN}.txt` |
| 章日志、全书日志、快照 | `剧情日志/` |

匹配不上的列"未分类"，问用户。`.docx` 先读再写 md。归位前问是否保留原文件。

**0c 缺口分析**：按文件是否存在标就绪态，输出缺口报告。质量来源标 `user-original`（⚠️需校验）或 `skill-generated`（✅）。

**0d 定当前模块**（不是定 phase）：

| 已有 | 落到 |
|:--|:--|
| 正文、章日志、全书日志齐 | `pop-write` 或 `pop-outline`，看下一章章纲是否已排 |
| 正文有、账本缺 | 先 `pop-review reconstruct`，再续写 |
| 幕白描有、无章纲 | `pop-outline` |
| 卷纲有、无幕白描 | `pop-outline`（幕白描按需） |
| 卷需求有、无卷纲 | `pop-snow-plot` |
| 立项有、无舞台 | `pop-snow-stage` |
| 全无 | `pop-snow-seed` |

向用户展示资产清单、缺口、建议模块、补跑清单，确认后写状态。

**0e 状态重建**：按模板写 `状态.md`；旧版 `状态.md` 的 phase 字段读到后映射为 `focus`，不丢信息。

**0f 补跑调度**：

| 缺口 | 调度 |
|:--|:--|
| 有正文、缺章日志或全书日志 | `pop-review reconstruct` |
| 缺立项/舞台/剧情/章纲 | 对应模块，读已有文件补全 |
| 缺采风 | `pop-snow-research` |
| 文风锚定缺失 | `pop-dna-style` |

补跑建议逐文件一行，用户三选：正常接续、按需补跑、全量补跑。

### Step 1：初始化

1. 建 11 个一级目录：`调研采风/`（含 `采风/`）、`原始资料/`、`立项/`、`设计库/`（含 `卷舞台/` 与 5 件主档空档）、`人物库/`、`剧情库/`、`章纲/`、`正文/`、`剧情日志/`、`文风dna/`、`草稿/`。
2. 用 LS 自检，缺一补建。
3. 写 `状态.md`，`mode: fresh`，`focus: 未定`，模块就绪全 `[ ]`。
4. 问三项就够：
   - 现在手上有什么：只有想法 / 有设定 / 有卷纲 / 有正文。
   - 目标是什么：开新书 / 续写 / 补设定 / 只审。
   - 篇幅量级：多少卷、多少章。
5. 按第 4 项直接路由到对应模块，不输出完整流程说明。

## 存量项目兼容

- 旧 `状态.md` 的 `phase` 字段：读到后映射为 `focus`（如 phase 6 → "写正文"，phase 5 → "写章纲"），其余字段保留。
- 旧目录名与文件名：按 0b 映射表归位；不自动覆盖同名不同源文件。
- 迁移只动路径与文件名，不动正文与章日志内容；搬空后的空目录才删除。
- 认线：读 `状态.md` 的 `line` 或 phase 写法；读不出按上游文件判，仍判不出问用户。
