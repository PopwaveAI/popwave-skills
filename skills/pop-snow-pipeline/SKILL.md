### 动笔前须完成的检查

动笔前与定稿前各执行一次，自查三问：本产出若要更好，尚缺哪些未见过的候选面？当前信息是否充足？是否存在未探索的更优选项？

- **一、先找出缺口。** 将"若要更好还须见过哪些面"明确列出，再列出已覆盖项，二者之差即为缺口。缺口内只要尚有一个维度未覆盖，即须取材。取材成功即采用；取材失败，不得勉强成文。
- **二、缺口足够时方可取材。** 检索项自拟。来源优先使用内部 wiki 站 https://wiki.popwave.cn，不足时再补充网络检索。单个环节最多取材一轮，一轮最多提出五个检索项，回传不超过 30KB，超出上限即截断，仅保留结论。
- **三、交付候选须附依据。** 以本技能的判断尺，将现有项与候选项并列制成打分表，不得以一句"这样更好"一笔带过。只能交付候选或升级版，最终选定不由本环节决定。
- **四、交付后复检。** 产出或候选交付后，自查"这是否已是上限、是否有更优候选"。确有更优者方可升级重议，上限两轮。

取材内容仅进入上下文，仅当升级被采纳后方可写入产出。

## 职责范围

| 职责 | 说明 |
|:--|:--|
| 一次性安装（fresh） | 创建目录，写入 `状态.md`（精简状态文件），可选导出展示面板与 README |
| 一次性导入/续写（import/resume） | 依次执行资产扫描、文件归位、缺口分析、落地 Phase 决策、状态重建与补跑调度 |
| 状态文件维护 | `状态.md` 是唯一状态总账，agent 只读写其中的状态片段；`项目总控.html` 是仅供老板查看的展示面板，按需导出，**agent 不读 html** |

**日常路由不经过本技能**：用户说出"继续写""下一步""写正文"或"审核"时，主 agent 按专家提示词阶段地图直接选定 skill，先读取 `状态.md` 获取状态片段（mode/phase/current_volume/current_chapter/就绪态），路由参照下方「卷循环状态机」。pipeline 不写正文，不做内容转换，不常驻。

**执行方式**：由主 agent 直接执行。初始化与导入的交互，包括资产清点、缺口确认、落地决策，由主 agent 完成；生成任务由主 agent 加载对应子 skill 执行。不得派发子 agent 执行 skill 生成任务。

## 操作步骤（规程全内联）

### Step 0：导入与续写模式

> 触发条件（满足任一项即可）：一、用户说出"导入""续写""已有""接续"或"迁移"；二、执行 Step 1 初始化时检测到 `正文/` 或 `设计/` 已有文件；三、项目目录已有内容但没有 `状态.md`。
> 定位：pipeline 是调度者，不是内容制造者。它只做资产清点、文件归位、缺口分析与补跑调度；深度内容转换，包括正文反推与设计补建，由主 agent 加载对应 skill 完成。

| 位 | 就绪判定 |
|:--|:--|

| 2b | `设计/卷舞台/卷N-舞台.md` |
| 2c | `卷纲/卷N-卷纲.md` 与 `卷纲/卷N-幕M-白描.md`（至少一幕） |
| 2d | `卷纲/章纲/ch{NNN}-章纲.md`（NNN 指下一章待写） |
| 2e | `正文/ch*.txt`（current_chapter=最大编号+1） |
| 2f | `章节日志/` 与 `全书日志.md` |

**0d 落地Phase决策**（缺口报告+正文进度）：

| 条件 | mode | 落地位 | 说明 |
|:--|:--|:--|:--|
| 正文有、章日志有、全书日志有 | resume | 2d 或 2e | 状态完整：下一章章纲已拼接则进 2e，未拼接则进 2d |
| 正文有、账本缺（章日志或全书日志） | resume | 先由 0f 调度 review reconstruct，再进 2d 或 2e | 需补账本 |
| 正文无、幕白描有 | import | 2d（outline） | 缺章纲 |
| 正文无、卷纲有 | import | 2c（幕白描） | 缺幕白描 |
| 正文无、卷N舞台有 | import | 2c（卷纲） | 缺卷纲 |
| 正文无、卷进度表有（首喷完） | import | 2a（卷需求brief） | 进卷循环 |
| 正文无、融合立项稿有 | import | 2（stage首喷） | 缺舞台 |
| 各项全无 | fresh | 1（seed） | 走 Step 1 初始化 |

→ 向用户展示资产清单（含来源标记）、缺口报告、落地 Phase 建议与补跑建议清单（0f）。**用户确认后**再进 0e。

**0e 状态文件重建**：若 `状态.md` 不存在，则按「状态.md 模板」创建；若已存在，则用 SearchReplace 更新。字段包括 mode、phase、current_volume、current_chapter、seed_path（仅路径C项目填写）与就绪态，就绪态按 0c 标 [x]。展示面板为可选项：老板要求时按 `templates/项目总控.html` 套值导出。

**0f 调度 skill 补跑**（pipeline 只识别缺口、调度与汇报，不自行做内容转换）：

| 缺口类型 | 调度skill | 做什么 |
|:--|:--|:--|
| 有正文、缺章日志或全书日志 | pop-review reconstruct | 批量回溯审核：采样逐章章日志与全书日志 |
| 缺立项、舞台、剧情或章纲文档 | 对应 skill（seed/stage/plot/outline） | 读取已有文件，按 skill 方法论校验并补全，输出标准格式 |
| 已有文档但来源为 user-original | 对应 skill（用户确认后按需） | 校验后标注缺口或确认达标 |

- review reconstruct 的采样规则：不超过 10 章全审；11 至 30 章取最近 5 章，并每 5 章抽 1 章；超过 30 章取最近 5 章、第一章，并每 10 章抽 1 章。产出 `章节日志/ch{NNN}.md` 与 `全书日志.md`。
- 设计文档补跑按依赖链顺序执行：先 stage（七长档：世界全书、力量体系与位阶-社会坐标谱、势力格局、基调母题、主角、角色库），再 plot（卷进度表、brief、卷纲、幕白描），最后 outline（章纲）。用户已有正文但缺剧情文档时，由 plot 从正文反推；用户选择跳过 plot 直接续写（降级模式）时，在全书日志手动指定下一章核心事件。
- 不调度的情况：素材层文件由 pipeline 自行按标准分节重组；文风锚定.md 缺失时，提示用户执行 pop-dna-style（非 reconstruct 场景）。
- 补跑建议清单：逐文件一行，列出文件名、来源、状态与建议（正常消费或补跑对应 skill）。用户三选一：正常接续、按需补跑、全量补跑。

**Step 0 质量门**：原始资产清单已生成；文件归位完成（含来源标记）；缺口报告已生成；落地 Phase 经用户确认；状态.md 已创建或更新；补跑建议清单已展示。

### Step 1：初始化（fresh 模式）

**前置检测**：执行任何创建前，先用 LS 扫描。若 `正文/` 有章节文件或 `设计/` 有 .md 文件，则跳转「Step 0 导入与续写」；若目录为空或仅有 `状态.md`，则继续本步。

1. **创建目录（一次性）**：创建 `素材/`（含 `downloads/`、`知识沉淀/`、`采风/`）、`立项/`、`设计/`（含 `卷舞台/`）、`卷纲/`（含 `章纲/`）、`正文/` 与 `章节日志/`。创建后用 LS 自检，确认全部存在；缺一即初始化失败，补创后才可继续。（`素材/采风/` 是定向采风库，存放 research 的世界观、人物、剧情、场景四类定向采风，文件名规范为 `{定向}-{主题}.md`）
2. **创建 状态.md**：按「状态.md 模板」写入项目根，取值 mode: fresh、phase: init、current_volume: 1、current_chapter: ch000，全部就绪态标 [ ]；再简建 README.md，写入项目信息、目录说明与指向状态.md 的指引。
3. **展示面板（可选）**：老板要求时，按 `templates/项目总控.html` 套用状态.md 的值导出；agent 只写状态.md，不读 html。
4. **首次对话引导**：用户第一次触发且无项目时，先输出 `references/onboarding-guide.md` 的引导语，声明本次仅为功能介绍、未执行任务；用户已明确要开做时可跳过。
5. **路由 Phase 1**：加载 pop-snow-seed，按其 SKILL.md 执行，即六步流水线共创《融合立项稿14维》：问诉求、定调研清单、调研、归集取材与卖点源、融合、定稿交接。**调研环节内嵌"立项前置采风"**：seed 定完调研清单后，触发 pop-snow-research 执行**世界观定向与人物定向**的基础轮批量采风（可派并行只读子 agent 分主题采集，回报主 agent 后存档至 `素材/采风/`），供 Phase 2 stage 建世界与人物时直接取材——资料须前置备足，不得写到卡住才补。

**Step 1 质量门**：目录齐全，状态.md 已写入，README 已写入。

## 全线事实优先级裁决链

正文、章纲、设定与审查遇到**事实冲突**时，全线（seed/stage/plot/outline/write/review）按以下序列取证，**不得反向覆盖更高权位**——这是"约束由正文驱动"的落点：

| 权重 | 事实源 | 说明 |
|:--:|:--|:--|
| 最高 | **用户本轮临时要求** | 可覆盖既有事实，但必须**显式指出其与既有事实的冲突并记录改法**，不得静默覆盖 |
| 2 | **已发布正文** | 正文中明确写出的事实，文字权威最高 |
| 3 | **最新章节事实提取**（章日志） | 由正文驱动得出的最近事实 |
| 4 | **角色卡当前状态** | 关系、能力、伤势、持有物、信息边界 |
| 5 | **世界书与设定规则** | 力量上限、地图、资源、制度 |
| 6 | **活跃伏笔与未解冲突** | 悬而未收的线 |
| 7 | **大纲** | 卷纲、幕白描、章纲，为优先级最低的叙事计划 |

> 裁决原则：叙事计划（大纲）低于已落地事实（正文、章日志、角色卡、世界书、伏笔）；用户临时要求权重最高，但**指出冲突是义务**——即使照办，也要让老板与后续环节知道改了什么、为什么改。遇到"冲突该以哪条为准"拿不准时，按此表自上而下取证，不得临时拍板。说明：本裁决链吸收自 Mirror 09-审查专家的事实优先级 7 级，与全线统一。

## 卷循环状态机（2a-2g，路由参照）

### 每章收束（写一章的完整循环，防止路由绕错）

每一章严格按五步循环推进，**outline 写章纲永远在 write 之前，不得跳过**：

```
outline 章纲 → write 正文(ch{NNN}.txt) → review 三件事 → 回到 outline 写 ch{NNN+1} 章纲 → …
```

- **review 三件事**：一、确认本章正文满意（即定稿，未定稿不入库）；二、生成 `章日志 ch{NNN}.md`（事件源，只增不改）；三、更新 `全书日志.md`（当前态，只记活跃项，replace，回收项落 `退出档案.md`）。
- **产物归谁消费**：review 产出的章日志与全书日志，喂给**下一章的 outline** 作为章纲依据，**不直接喂给 write**——write 永远跟在章纲之后，不得跳过 outline 从日志直接开写。
- **对应状态机位**：`2d(outline) → 2e(write) → 2f(review) → 回 2d(下一章 outline)`；本卷末章 review PASS → 2g 卷末盘点。

新书流程：`init → 1(seed) → 2(stage首喷，含卷一舞台) → 卷循环`。卷1 前3章章纲（2d）按开篇三要素排列——落差三要素（锚点、现状、对比触发点）、特权信息（择一）与还小账立新标（3-10章内可达成），开篇承诺基线随前3章章纲写入全书日志。已写前3章的项目（导入与续写）跳过该设计，只做开篇复盘诊断。卷循环每卷一圈：

| 位 | 执行内容 | skill | 产出 | 完成后进入 |
|:--|:--|:--|:--|:--|
| 2a | 卷需求brief（订货单与方向盘） | pop-snow-plot 任务A | `卷纲/卷N-需求brief.md` | 2b（卷一则进 2c，舞台首喷已包含） |
| 2a+ | 卷级调研与剧情素材实时搜索（轻量，brief 有增量需求时执行） | pop-snow-research 场景② | `素材/采风/剧情-*.md` | 2b |
| 2b | 卷舞台刷新（卷二起每卷一次） | pop-snow-stage 模式B | `设计/卷舞台/卷N-舞台.md`、角色库增量与贯穿层 append | 2c |
| 2c | 由卷纲产出幕白描（七查全绿才交付） | pop-snow-plot 任务B→C | `卷纲/卷N-卷纲.md`→`卷纲/卷N-幕M-白描.md` | 2d |
| 2d | 章纲拼接（每章一个文件） | pop-outline | `卷纲/章纲/ch{NNN}-章纲.md` | 2e |
| 2e | 正文写作（2000-2500字/章） | pop-write | `正文/ch{NNN}.txt` | 2f |
| 2f | 审核与存档（PASS/REJECT） | pop-review | `章节日志/ch{NNN}.md`+`全书日志.md` | PASS 进 2d 或 2e 下一章；REJECT 回 2e 重写本章；本卷末章 PASS 进 2g |
| 2g | 卷末盘点 | 主 agent | 状态.md：current_volume+1，卷循环四项就绪态清零 | 回 2a |

> **卷1 前3章的开篇承诺基线（1+1>2）**：outline 写 ch001-ch003 章纲时，把开篇承诺（第3章新标、特权信息备忘、对比触发点锚点）随章纲写入全书日志，后续 outline 写章纲时可引用"主角正往那个新标推进"；plot 卷进度表评审"距终点贡献"时，校验开篇立的标是否在预期章节兑现——开篇从"只检查一次"升级为"全书承诺基线"。

**幕内滚动**：推荐「2c 产出幕 N → 2d 拼幕 N 章纲 → 2e/2f 逐章 → 2c 产出幕 N+1」，让后续幕吸收正文成果。

**2g 卷末判定**：卷纲预算章数耗尽，且卷末三件套（面板大爆、新地图解锁、下卷钩子）兑现，即本卷结束。

**状态.md 更新协议**（由执行者自行更新，只更新涉及的字段，不做全量替换）：

| 时机 | 更新 |
|:--|:--|
| 各 skill 完成 | phase 推进到状态机的下一位、更新 updated_at、对应就绪态项标 [x]、最近产出追加一行 |
| seed 完成 | 另更新 seed_path 与书目（book_name、one_line） |
| 卷1 前3章章纲完成 | 若 phase 在 2d，project 就绪态补标开篇承诺基线 [x]，并在最近产出追加一行 |
| write/review 每章 | review PASS 后 current_chapter+1，phase 在 2d、2e、2f 之间流转 |
| 2g 卷末 | current_volume+1，需求brief、卷舞台、卷纲、幕白描四项清零，phase 置为 2a |

pipeline 只在初始化与导入时写 phase；日常推进由各 skill 完成后按本表更新。

## 存档质量检查（deai_gate.py，本包 scripts 统一管理）

去 AI 味检查脚本由本包 `scripts/deai_gate.py` 统一管理（配置外置 `scripts/deai_profiles.json`，仅用 stdlib），两个 profile 共同服务整条管线的存档质量。**各 skill 存档后自行执行该脚本，不进入 LLM，不派子 agent。**

| profile | 服务对象 | 性质 | 检测面 | 调用 |
|:--|:--|:--|:--|:--|
| `body`（默认） | write 正文（`正文/ch{NNN}.txt`） | **打回检查**：FAIL 必须清零才算存档完成 | 套话硬模板 ~120 条、软密度 ~28 组、结构统计与工具痕迹四层，阈值按人书基线校准 | `python skills/pop-snow-pipeline/scripts/deai_gate.py 正文/ch{NNN}.txt --fix --json` |
| `doc` | 非正文文档（seed 融合立项稿、research 调研拆书包、stage 长档与卷舞台、plot 卷进度表、brief、卷纲、幕白描、outline 章纲、review 章日志与全书日志、decon 拆书 wiki 成品、dna-style 文风锚定说明文字，以及拆书、卖点、大纲、世界观类文档） | **报告检查**：只 WARN+定位，不打回 | 黑话（hard 实锤与 soft 风格分层）、套路句式、空腔段与生成器残留；分号、破折号、括号、列举行、工程 emoji 标记与 0% 对话一律放行 | `python skills/pop-snow-pipeline/scripts/deai_gate.py <文件或目录> --profile doc --json`（目录加 `-r` 递归，含聚合热点统计） |

**边界三条**：
1. 工程标签（【锚】、养成刻度、卷末边界等精确技术名）不做去 AI 化改写——去 AI 味只作用于叙事主体。
2. 自动修正仅限零风险机械项（英文标点、HTML 残留、零宽字符等 36 类）；滥用类只报告，不自动修改。
3. `doc` 的 WARN 清单由存档 agent 按上下文判断：装腔处改用大白话，行话正常使用可放行（回复时注明放行理由）；**词库类文档自指命中豁免**——`pop-ai-reduce-lite` 词表、write 检测面说明等文档本身讨论这些特征词，命中属合法引用，不是残留。

**词库蓝本与维护**：doc 的黑话与套话词库吸收自 `pop-ai-reduce-lite/resources/banned-words.md`（v3.2 全量类别）与老板点名的 seed、设定场景词；v3.3、v3.4 经广泛搜索轮补齐（维基 Signs of AI writing、Humanizer 35条军规、cn-humanizer、连享会、OpenAI slop words、番茄拒签七破绽实测——企业黑话、宣传腔、万能收尾、模糊来源、假坦率、虚假替代、公式化谚语、浅层象征词）。管线自身行话（赛道、卖点、爽点、钩子等）与语料专有名词、世界观字面义（封神、版图、天花板、破局等）不入库——v3.4.1 按 wiki 语境抽样校准。`deai_profiles.json` 与代码内 `DEFAULT_DOC_CFG` 兜底须同步维护。

**阈值与词库调校**：修改 `scripts/deai_profiles.json` 即可，无需改代码；修改后须跑回归（负面样例高召回、人书零误杀、wiki 与 skills 误伤增量可控），通过后才生效。
