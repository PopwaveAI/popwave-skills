# pop-snow-research

> 实时联网搜索站。当前版本 v5.6.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

***

## 做什么（本 skill 的定位）

**research 的核心 = 强化 agent 联网搜索能力，把"真实信息/可写素材/质感细节"实时搜出来，直接喂给写作任务的下一步。** 它是**实时搜索站**，不是异步资料整理 master：

- **实时**：写手写到哪卡在哪，当下点单就去搜当下搜到、存档，供 outline 章纲 / write 正文 / stage 设定 / plot 排戏 直接取用。

- **服务写作**：每个场景回答"这次搜来喂谁、干什么用"——不是为搜而搜，是写完下一步只缺这块料。

- **搜能搜到的**：优先真实一手信息（史实/行业/民俗/物理规则/真实组织运作），让虚构踩在真实主干上，质感才扎实。

- **去能搜的地方搜对的东西**：不漫游，每个场景有"去哪搜·搜什么·整理成什么·存档到哪"的固定路由（见下）。

**不做什么**（范围边界，收束）：不做**拆书类**（decon-lite 9表/剧情拆解/对标开篇/建包/燃料——已有独立 skill pop-decon/pop-decon-dimension 承接）；不做二次清洗/知识整理 master；不排章纲、不写正文、不产工程级设定（那是 stage 的活）。

***

## 搜前构思（开搜前先想一轮）

一句话：**先知道当前任务情况，构思一轮"要搜哪些信息"，列成清单，再开搜。**

### 三步

1. **盘任务**：当前在哪个环节（seed 立项 / stage 建世界·角色·力量 / plot 排戏 / outline·write 质感）、这本书是什么（题材/组合/卖点）、这个环节要产出什么。任务不同，要搜的清单完全不同。

2. **列搜索清单**：由任务反推要搜的信息，通常三类、按这个顺序：

   - **基本盘**——题材/体系各自的设定：是什么、核心机制、经典设定、代表作。**要搜深（档案级，用** **`templates/地基档案模板.md`），浅搜一两条等于没搜**——之前"各自设定搜了却没用"的教训不是搜错对象，是搜得太浅。基本盘搜透了，缺口自然浮出来，缺什么再补搜什么。

   - **组合先例**——有没有人把这些东西组合过（知名小说/游戏/官方联动），怎么焊的、成什么样，搜来当参考。

   - **市场盘**——赛道盘子、竞品与成绩、读者口味与流失原因。

   按任务增减：write 前只要一景质感就不用市场盘，seed 立项则三类都要。

3. **开搜存档**：逐条搜、逐条落 `素材/采风/`；搜完对清单查漏——哪条没搜到？查不到明说，不编造。

### 例子（DND×克苏鲁西幻网文 · seed 环节）

| 顺序    | 搜什么                                                               | 落成什么    |
| :---- | :---------------------------------------------------------------- | :------ |
| ①基本盘  | DND 是什么（规则确定性/职业/神系/法术环）＋ 克苏鲁是什么（宇宙冷漠主义/神明层级/San机制/经典作品）          | 两份档案级地基 |
| ②组合先例 | 有没有 DND×克苏鲁 的知名尝试：诡秘之主（克苏鲁×序列）、DND 官方克苏鲁造物（灵吸怪/Far Realm）、已出的同类网文 | 融合参考卡   |
| ③市场盘  | 西幻网文盘子、克苏鲁流/DND流竞品、读者流失原因                                         | 立项决策依据  |

> 顺序不能倒：基本盘没搜深就看组合先例，读到先例也吃不透——先知道两边各自是什么，才看得出先例焊在哪、焊得好不好。

## 四场景 SOP（核心——四写作刚需）

每个场景=一张「去哪搜→搜什么→整理成什么→存档到哪」四联路由。触发看「触发时机」节；深度格式看 `templates/采风条目模板.md`；**seed/stage 立项级取材用** **`templates/地基档案模板.md`（档案级多维），写前单点质感用采风条目模板**。

> 四场景共同底子：**先答"喂谁/干什么用"（用途不清不开工）→ 拆成可独立回答的主题（每主题一个文件）→ 每主题落地** **`素材/采风/{场景}-{主题}.md`** **→ 存档后半步跑** **`deai_gate.py --profile doc`** **去AI味**。批量可并行子agent（research 适配只读通道，子agent搜索+回报条目，主agent合并存档）。

## 按写作环节定搜索深度（目标细化·每个环节搜到什么程度）

**搜索深度不由 research 自己拍，由"喂给哪个消费环节、那个环节开口要什么"决定。** 读 snow 整条流程后总结——每个消费端对 research 的"搜到什么程度"有明确开口：

| 消费环节                  | research 触发点                                  | 搜到什么程度（够用即止）                                                                       | 实跑实证                                      |
| :-------------------- | :-------------------------------------------- | :--------------------------------------------------------------------------------- | :---------------------------------------- |
| **seed（卖点源）**         | Step2 定调研清单→Step3 调研；给参考书/IP时（BG3/战锤/深渊主宰）    | 每源一卡**消化五件套**：终点形态/核心危机/敌人谱系/主角特殊性/结构节奏 + **可嫁接点→锚定立项哪一维**。不是背书                    | ✅ 子agent五件套法跑战锤/BG3/深渊主宰，各源产出可嫁接点+锚维      |
| **stage（世界观）**        | Step1 盘复用源：已吃透不搜，没吃透才派 research 查实；要建新体系/新设定时 | 补 stage 答不出的**具体规则运作**（"神=信仰具象怎么运转""深渊理性崩解怎么设 San"），复用源优先、增量补缺                     | ✅ stage 长档尺"复用源真落地"前置，research 只补缺口       |
| **stage（角色）**         | Step4 建角色库：主要角色都要**有原型、不原创**                  | 搜到够落角色卡：**人格核心/欲望动力/行事+语言指纹/结构性弱点/可嫁接设计点/一个可直接排幕的冲突场景模板**，不搜完整传记；两原型可混处要点出**嫁接雷区** | ✅ 子agent搜出小指头/随春生+曹操+沈万三，五件套齐全+雷区提示       |
| **stage（力量体系）**       | Step1/2 力量体系是复用域，不为凑满挂复用源                     | 消化参考的**分级方式**（搜"最有名那套"复用，不照抄专名序列），自定义只有成长斜率；数值钉板式跨度                                | ✅ 西幻→DND SRD；仙侠→修真境界词条                    |
| **plot（剧情）**          | 任务B卷纲找冲突/事件模型；任务A brief 舞台点播                  | 搜够排一幕的**冲突/转折/新悬念模型**（一个"单元剧收束"），供模型不供稿剧情                                          | ✅ 子agent搜出格列高利/亨利·都铎/伊维洛/乌尔班二世四模型，每个=一幕收束 |
| **outline/write（质感）** | 章纲/正文前，新场景/职业/地域且槽位未采                         | 搜够本章那笔的**五感细节/职业黑话/场景布局**，够写即止                                                     | ✅ 信息源库场景①②（中世纪职业/莱茵河收费城堡带）                |

**目标细化的五把尺（什么时候停）**：

1. **对write 不需要的细节不搜**——搜到"够消费端落地"即止，不求百科全书。
2. **已经采过的不重搜**——先进 `素材/采风/` 查是否已覆盖，再决定增量搜哪些（stage 的"盘复用源"即此）。
3. **复用优先于原创**——有参考源消化其结构，不搞"从零发明"（stage 长档尺硬约束）。
4. **供模型不供成品**——剧情给"冲突模型/事件形状"，不给现成剧情；力量给"分级方式"，不给抄好的命名字列。
5. **原型优先于编造**——角色尽量有真实/文学原型，让角色脱胎于"有人活过/写过的活人"，不用捏造脸谱。

## 触发时机（实时·按需·不靠等）

> **触发不是自觉、是"定稿门"强制**：*seed / stage / plot / outline* 四消费端在各自存档 Step 内嵌「资料门」——存档前先答"资料够不够"，不够**必派本 research 补采再存档**；write 缺料不直接打 research，**打回 outline 采完重写**。本 skill 是被它们强制拉动的执行通道，不是等用户点名的可选项。下面四检查口即四个固定触发位：

| 检查口             | 触发位（消费端存档 Step 内嵌资料门强制）                       | 四场景                              | 存档                                             | 服务                            |
| :------------- | :---------------------------------------------- | :------------------------------- | :--------------------------------------------- | :---------------------------- |
| **① 立项考据·卖点源** | seed 定调研清单后（给参考书/IP 时，如 BG3/战锤/深渊主宰；Agent自定态也跑） | 世界观 + 剧情 + 人物·势力 基础轮（批量并行子agent） | `素材/采风/世界观-*.md`+`剧情-*.md`+`人物-*.md`+`势力-*.md` | seed 消化五件套·卖点源 / stage 建世界·角色 |
| **② 卷循环剧情素材**  | plot 卷需求brief 产出后（2a+）                          | 剧情（本卷新地图/势力/人物原型/机制/民俗事件）        | `素材/采风/剧情-*.md`                                | plot 排卷纲·幕白描 / stage 卷舞台刷新    |
| **③ 写前按需质感**   | outline 章纲存档前，要写新场景/新职业/新地域/新体系且槽位未采过（write 缺料不入本检查口，打回 outline 采） | 四场景任选（世界观/剧情/人物·势力/力量）           | `素材/采风/{场景}-{主题}.md`                           | outline 本章质感            |
| **④ 用户点名**     | 老板说"查/搜/采风/补资料/考据/找X"任意时刻                       | 四场景任选                            | `素材/采风/{场景}-{主题}.md`                           | 当前环节                          |

> **实时原则**：写到哪卡到哪当下点单，写前问"这段要用什么资料，采到了吗？"缺面即补采。采风不是一次性的——每次进新地图/新卷/新职业/新题材区，先查 `素材/采风/` 是否已采。

## 检索协议（全局）

任何搜索前，顺序固定：

1. **先查 wiki 站** `https://wiki.popwave.cn`（世界知识库/写作技法库/素材原型库/赛道设定集）。命中→直接引用并标注 `来源: wiki/{路径}`，不重复造轮子。
2. **未命中或深度不够→ 查** **`references/信息源库.md`**（三层结构：**通用层**全赛道起手站 → **信息类型层**按要搜的信息类型选专用站 → **赛道包**已实跑验证的赛道专用站），优先命中站。
3. **仍未命中→ 泛 web 搜索**（WebSearch/WebFetch），标注来源URL/书名/词条；新命中可用站回写信息源库。
4. 产出中 wiki 命中部分与 web 新搜部分**分区标注**，下游知道哪些已验证。

**高质量信息源优先级**：wiki站 <https://wiki.popwave.cn> → **信息源库具体站**（references/信息源库.md）→ 官方资料/SRD → 百度百科·维基百科 → 垂直百科（灰机wiki/书站百科等） → 文旅/史地/行业垂直站 → 社区讨论（降权，标非官方）。

## 搜索纪律（实时搜索的七条）

1. **先定用途**：这次搜来喂谁、干什么用；用途不清不开工。
2. **拆成明确模块清单**：把"要查什么"拆成一条条可独立回答的模块，逐条交付。
3. **每条必标可回源**：结论必带来源链接/出处，可回源核验。
4. **三级可信度标注**：官方/权威百科/社区讨论分级标注；社区结论标"非官方、自取"。
5. **查不到就明说**：查不到的条目显式写"查不到"，绝不编造——宁缺毋假。
6. **限结论区字数**：回传只留结论区（≤30KB），过程材料不进产出。
7. **数据纪律**：任何赛道/市场结论必须标注**平台、榜型、分类、日期、样本数**；区分"数据事实"与"创作建议"；不从名次/热度变化直接断言原因。

聚焦搜索属只读，可派子 agent 执行回报，主 agent 存档与元数据。

## 怎么操作（SOP 全内联）

### 通用流程（四场景共用主干）

**S1 定用途**：这次采来喂谁（stage/plot/outline/write）、干什么用。用途不清不开工。

**S2 拆主题 + 定场景**：按四场景 SOP 把需求拆成若干主题，每主题一个文件（文件名= `{场景}-{主题}.md`）。批量采集拆多主题并行子 agent 采，主 agent 合并存档。

**S3 检索采集**：按「检索协议」先 wiki 站后 web；按该场景「去哪搜→搜什么」取一手细节；每面按 `templates/采风条目模板.md` 采 3-8 条，禁空泛面。

**S4 存档 + 去AI味**：落 `素材/采风/{场景}-{主题}.md`（元数据：场景+服务环节+采样来源+时间+并行子agent）→ `python skills/pop-snow-pipeline/scripts/deai_gate.py <file> --profile doc --json`，WARN 自查、机械项 `--fix`，结果一行 `去AI味:采风-{场景}-{主题}|PASS` 或 `WARN×N`。

**S5 质量门**：场景明确｜必采面逐面有料（无空泛面）｜每条有来源或一手细节｜存档 `素材/采风/`｜去AI味结果一行。

> 聚焦搜索（跨 skill 服务口）：stage/plot 点名要"查实一件事"（如把参考体系查实做底座、立卷敌身份再查），同样按七条纪律走，直接回报结论区+来源，不必存档采风文件。
