# pop-snow-research

> 本技能是实时联网搜索站，含两个模式：模式 A 查找素材，模式 B 查找模版。本技能是 snow、灯塔、涌现三条流程线共用的基础技能，所有消费端均可调用本技能取料，消费端包括 snow 的 seed、stage、plot、outline、write，灯塔流的 seed、stage、plot、outline、write、review，涌现流的 seed、outline、write、review。当前版本为 v5.9.1，本版完成情绪引用拆分：正文示例不再写出分值，改为指向打分表的指针，情绪刻度一律打开打分表查级。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

***

## 做什么（本技能的定位）

**本技能的核心是强化 agent 的联网搜索能力，把真实信息、可写调研采风、质感细节实时搜出来，直接提供给写作任务的下一步。** 本技能是**实时搜索站**，不是异步资料整理的汇总工具：

- **三条流程线共用的基础技能**：本技能不专属 snow，灯塔流与涌现流同样大量依赖本技能。**涌现流的任何环节都可主动触发本技能**，触发场景包括写前缺质感、排章纲遇专业场景、审查时事实存疑、回看市场校准，不设"必须考据不足方可调用"的门槛。

- **实时**：写作时在何处卡住，即在当下提交检索需求，当次搜到即存档，供 outline 章纲、write 正文、stage 设定、plot 排剧情直接取用。

- **服务写作**：每个场景均须回答"本次所搜材料供谁使用、用于何处"，不为搜索而搜索，只补写作下一步所缺的那块材料。

- **搜索可搜到的真实信息**：优先使用真实一手信息，含史实、行业、民俗、物理规则、真实组织运作，令虚构建立在真实主干之上，质感方可扎实。

- **在可搜之处搜所需内容**：不做漫游式搜索，每个模式与场景均设"去哪搜、搜什么、整理成什么、存档到哪"的固定路由，详见下文。

**两个模式（v5.8.0 核心）**：

- **模式 A 查找素材**：含现有四个场景，搜索真实信息、质感、一手细节，存档于 `调研采风/采风/`，供**当前这本书**的下一步使用。
- **模式 B 查找模版**：从真实内容中提取**内容配方**，真实内容含真小说、头部作品、已拆成果；方向含力量体系方向的分级方式（如修仙线性升级）、剧情方向的套路结构（如打脸、退婚流）。提取后整合成一条条可复用的**模版条目**，回填各环节包的内容库：力量体系与世界观→`{pop-lantern-stage}` 包，单元剧→`{pop-lantern-plot}` 包，套路→`{pop-outline}` 包。模式 B 的产出供**所有后续项目**使用，属跨项目资产。

**判定模式的依据**：所搜材料供当前这本书的下一步使用，走模式 A；所建内容资产须跨项目复用，走模式 B。

**不做的部分**（范围边界）：本技能不做**拆书类**工作，拆书类含 decon-lite 9表、剧情拆解、对标开篇、建包、燃料，此类工作已由独立技能 pop-decon 与 pop-decon-dimension 承接。本技能不做二次清洗，不做知识整理汇总。本技能不排章纲，不写正文，不产工程级设定，此类工作属 stage 的职责。**模式 B 查找模版与拆书不同**：拆书是深度全拆，含 9表、对标开篇、建包；模式 B 只做定向提取某一方向的配方，方向含力量体系、世界观、单元剧、套路，产出为内容库条目，不是拆书报告。已拆成果含 wiki seed-* 卡与拆书包，是模式 B 的最高优先来源，直接提取即可。

## 双模式总览

| 模式 | 做什么 | 产出形态 | 存放位置 | 供谁使用 |
|:--|:--|:--|:--|:--|
| **A 查找素材** | 四个场景采风：世界观考据、剧情素材、人物·势力、力量·养成 | 采风条目，每面 3-8 条，一手信息优先且可回源 | `调研采风/采风/{场景}-{主题}.md` | 当前这本书的下一步 |
| **B 查找模版** | 从真实内容中提取内容配方，整合成模版条目 | 模版条目，采用内容库六字段：名称、内核、来源、验证状态、适配规则、不可动硬核 | 回填对应环节包的内容库：力量体系与世界观→`{pop-lantern-stage}`，单元剧→`{pop-lantern-plot}`，套路→`{pop-outline}` | 所有后续项目，属跨项目资产 |

**两个模式互不混用**：模式 A 的产出进入项目自己的 `调研采风/`，随这本书走；模式 B 的产出进入跨项目内容库，任何书都可取用。模式 B 提取配方时一并采到的一手细节，按模式 A 的规则存档于 `调研采风/采风/`，两者并不冲突。

## 搜前构思（开搜前须构思一轮）

本环节的要求：**先掌握当前任务的情况，构思一轮要搜哪些信息，列成清单，然后开始搜索。**

### 三个步骤

1. **盘清任务**：须先确定当前所处环节（snow：seed 立项、stage 建世界与角色与力量、plot 排剧情、outline 与 write 质感；灯塔：seed 立项、stage 建设定与力量、plot 排单元、outline 章纲、review 审查；涌现：seed 立项、outline 轻量章纲、write 正文、review 审查与回看）、这本书的情况（题材、组合、卖点）、本环节要产出什么。任务不同，搜索清单完全不同。

2. **列出搜索清单**：由任务反推要搜的信息，通常分三类，按以下顺序排列：

   - **基本盘**：题材或体系各自的设定，含是什么、核心机制、经典设定、代表作。**须深搜至档案级，使用 `templates/地基档案模板.md`；只搜一两条等于未搜**。此前"各自设定搜了却没用"的教训，原因不在搜错对象，而在搜得太浅。基本盘搜透之后，缺口自然显现，缺什么再补搜什么。

   - **组合先例**：是否有人将这些东西组合过，组合形式含知名小说、游戏、官方联动；须查明其组合方式与产出形态，搜来作为参考。

   - **市场盘**：赛道规模、竞品与成绩、读者口味与流失原因。

3. **确定搜索深度**：每个消费环节均设"够用即止"的口径，见下表；须按口径收手，不无限深挖。

**目标细化的五项尺子（何时停止）**：

1. **write 不需要的细节不搜**：搜到足以让消费端落地即止，不求百科全书式的完备。
2. **已采过的不重复搜**：先查 `调研采风/采风/` 是否已覆盖，再决定增量搜哪些（stage 的"盘复用源"即此意）。
3. **复用优先于原创**：有参考源时消化其结构，不采取从零发明的方式（stage 长档尺硬约束）。
4. **提供模型，不提供成品**：剧情给"冲突模型与事件形状"，不给现成剧情；力量给"分级方式"，不给抄好的名称序列。
5. **原型优先于编造**：角色尽量采用真实原型或文学原型，令角色脱胎于有人活过或写过的真人，不捏造脸谱化角色。

## 触发时机（实时触发、按需触发）

> **触发分两种：定稿检查强制触发（被动）与各环节主动提交检索需求（主动）。** 定稿检查指消费端存档 Step 内嵌的资料检查，考据不足时必须派单补采；主动提交检索需求指任何环节认为"缺真实材料"即可触发，涌现流六个环节尤其**不设门槛**，写前缺质感、排章纲遇专业场景、审查时事实存疑、回看市场校准，均可当场提交检索需求。本技能是被拉动的执行通道，不是等待用户点名的可选项。下列检查口即固定触发位：

| 检查口             | 触发位（消费端存档 Step 内嵌资料检查，强制触发）                       | 模式与场景                          | 存档位置                                             | 服务对象                            |
| :------------- | :---------------------------------------------- | :------------------------------- | :--------------------------------------------- | :---------------------------- |
| **① 立项考据·卖点源** | seed 定调研清单后（给出参考书或 IP 时，如 BG3、战锤、深渊主宰；Agent 自行确定时同样执行） | 模式 A：世界观 + 剧情 + 人物·势力 基础轮（批量并行子agent） | `调研采风/采风/世界观-*.md`+`剧情-*.md`+`人物-*.md`+`势力-*.md` | seed 消化五件套·卖点源 / stage 建世界·角色 |
| **② 单元循环剧情素材**  | plot 单元编排需求 brief 产出后                                | 模式 A：剧情（本单元新地图、势力、人物原型、机制、民俗事件）        | `调研采风/采风/剧情-*.md`                                | plot 排单元·白描 / stage 舞台刷新    |

| **④ 用户点名**     | 老板提出"查""搜""采风""补资料""考据""找某物"中任意一项的任意时刻                       | 模式 A：四个场景任选；模式 B：老板提出"找模版""提取配方""回填库""做模板"时 | 模式 A 存档于 `调研采风/采风/`；模式 B 回填对应环节包内容库（力量与世界观→stage、单元剧→plot、套路→outline）             | 当前环节                          |
| **⑤ 涌现流主动提交检索需求**  | 涌现流六个环节中任一步骤缺真实材料即触发：seed 查底子与文风参照、outline 遇专业场景（含前 3 章开篇考据）、write 写作前缺材料、review 事实核验与回看市场校准 | 模式 A：四个场景任选；write 缺材料时走聚焦搜索，回报结论区即可     | `调研采风/采风/{场景}-{主题}.md` 或聚焦回报（不强制存档）              | 当前环节                          |

## 四个场景的作业流程（模式 A 核心，四种写作刚需）

每个场景对应一张四联路由表，四联为「去哪搜、搜什么、整理成什么、存档到哪」。触发条件见「触发时机」节；深度与格式见 `templates/采风条目模板.md`。**seed 与 stage 的立项级取材使用 `templates/地基档案模板.md`，该模板按档案级多维度铺开；写作前的单点质感取材使用采风条目模板。**

> 四个场景的共同底子：**先回答"供谁使用、用于何处"，用途不清不开工；再拆成可独立回答的主题，每个主题一个文件；每个主题存档于 `调研采风/采风/{场景}-{主题}.md`；存档后另执行 `deai_gate.py --profile doc` 去 AI 味。** 批量采集可并行子 agent，本技能适配只读通道，由子 agent 搜索并回报条目，由主 agent 合并存档。

## 模式 B：查找模版（从真实内容提取配方，回填内容库）

**定位：本模式不找素材，而是从真实作品中抽出"已被验证的内容配方"，整合成一条条可复用的模版条目，回填内容库。** 素材（模式 A）供当前这本书使用；模版（模式 B）供所有后续项目使用，属跨项目资产。模版处于**内容层面**，力量体系方向即力量体系方向，剧情方向即剧情方向，不是结构层面的空壳。

### 四联路由

| 作业项       | 内容 |
| :-------- | :-------------------------------------------------------------------------------------------------------- |
| **去哪找**   | ① wiki 站的拆书成果 `https://wiki.popwave.cn/写作灵感/{赛道}/{书名}/`（seed-* 卡与拆书卡，已结构化抽离，优先级最高）；② 书站百科与完本头部作品（番茄、起点分类榜头部，以及同赛道最有名的那一套）；③ 项目内已拆书包（decon 成果）。**真实内容优先，模版必须从真实作品抽离，不得凭空编造配方** |
| **找什么**   | 按方向抽"内核结构"，不抄专名序列：<br>**力量体系方向**（回填力量体系模板库）：分级方式（几阶、每阶能力表现）、升级触发与代价、每阶社会坐标、上限约束。例：修仙线性升级的内核为境界、突破、寿元压力；觉醒分层的内核为先天与后天、精神阈限<br>**世界观方向**（回填世界观模板库）：世界结构（地图层数与换层触发）、势力格局（几方势力、谁控制核心资源、主角位处何处）<br>**单元剧方向**（回填单元剧模板库）：单元剧类型（副本流、案件流、委托流）的流程结构（触发、推进、对抗、收束）与每个单元的收束点<br>**套路方向**（回填套路库）：套路（打脸、退婚流、宝物自投）的事件链（铺垫、触发、反杀、余波）与情绪落点（对照剧情-情绪打分表：{情绪}·{分值}，查表定级） |
| **怎么整合** | 按内容库统一的六字段撰写模版条目：名称；内核（3-5句可复用结构）；来源（抽自哪本书或哪类作品，可回源）；验证状态（取值为头部作品、普通验证、待验证）；适配规则（什么题材能用、如何换皮）；不可动硬核（哪些部分禁止改动）。情绪相关条目的情绪刻度对照 `剧情-情绪打分表`，该表为审美固定位 |
| **存哪**    | 回填对应环节包的 `references/内容库/`：力量体系与世界观→`{pop-lantern-stage}/references/内容库/`（`力量体系模板库.md`、`世界观模板库.md`），单元剧→`{pop-lantern-plot}/references/内容库/`（`单元剧模板库.md`），套路→`{pop-outline}/references/内容库/`（`套路库.md`）。**不存档于** `调研采风/采风/`，因该库跨项目共享；条目须标注提取自哪个项目或哪本书 |

### 模版条目格式（与内容库库规一致）

```markdown
- 名称：{配方名}
- 内核：{可复用的核心结构/机制，3-5句}
- 来源：{哪本书/哪类作品抽离，可回源}
- 验证状态：{头部作品/普通验证/待验证}
- 适配规则：{什么题材能用/怎么换皮}
- 不可动硬核：{哪些部分禁止改}
```

### 质量检查（模式 B 五查）

1. **内核可复用**：所抽的是结构（分级方式、事件链、流程），而非照抄专名序列？
2. **来源真实且可回源**：来源为真实作品或 wiki 拆书成果，是否已标注书名与路径？
3. **六字段齐全**：名称、内核、来源、验证状态、适配规则、不可动硬核是否全部具备？
4. **情绪刻度对照打分表**：套路与单元剧条目的情绪落点是否标注 `{情绪}·{分值}`？
5. **验证状态如实**：头部作品指头部书已验证；新提取尚未实跑者，是否标注"待验证"？

### 触发时机（模式 B）

- **pipeline 消费纪律规定"库中没有则现场提取并在 48h 内回填"**：stage、plot、outline 查库无匹配时，现场走模式 B 提取该方向配方并回填。
- **用户点名**：老板提出"找模版""提取配方""回填库""做模板""找套路""找体系模板"时。
- **顺带回填**：拆书或复盘时发现可复用结构，按六字段一并回填对应库。

## 检索协议（全局）

任何搜索开始前，顺序固定如下：

1. **先查 wiki 站** `https://wiki.popwave.cn`（世界知识库、写作技法库、素材原型库、赛道设定集）。命中则直接引用并标注 `来源: wiki/{路径}`，不重复造轮子。
2. **未命中或深度不够时，查 `references/信息源库.md`**，该库分三层结构：**通用层**为全赛道起手站；**信息类型层**按所搜信息的类型选专用站；**赛道包**为已实跑验证的赛道专用站。优先使用命中站。
3. **仍未命中时，做泛 web 搜索**（WebSearch、WebFetch），标注来源 URL、书名或词条；新命中的可用站回写信息源库。
4. 产出中 wiki 命中部分与 web 新搜部分须**分区标注**，供下游识别哪些已经验证。

**高质量信息源的优先级**：wiki 站 <https://wiki.popwave.cn>，其次为**信息源库中的具体站**（`references/信息源库.md`），再次为官方资料与 SRD，再次为百度百科与维基百科，再次为垂直百科（灰机 wiki、书站百科等），再次为文旅、史地、行业垂直站，最后为社区讨论（降权，标注非官方）。

## 搜索纪律（实时搜索七条）

1. **先定用途**：本次所搜材料供谁使用、用于何处；用途不清不开工。
2. **拆成明确的模块清单**：把"要查什么"拆成一条条可独立回答的模块，逐条交付。
3. **每条必标可回源**：结论须附来源链接或出处，可回源核验。
4. **三级可信度标注**：按官方、权威百科、社区讨论三级标注；社区结论须标"非官方、自取"。
5. **查不到即明说**：查不到的条目显式写明"查不到"，不得编造，宁缺毋假。
6. **限定结论区字数**：回传只保留结论区（≤30KB），过程材料不进产出。
7. **数据纪律**：任何赛道或市场结论均须标注**平台、榜型、分类、日期、样本数**；区分"数据事实"与"创作建议"；不得由名次或热度变化直接断言原因。

聚焦搜索属只读操作，可派子 agent 执行并回报，由主 agent 完成存档与元数据填写。

## 操作方式（作业流程全部内联）

### 通用流程（模式 A 四个场景共用主干）

**S1 定用途**：本次所采材料供谁使用（stage/plot/outline/write/涌现任意环节）、用于何处；**先判定模式**：供当前这本书使用走 A，建跨项目资产走 B。用途不清不开工。

**S2 拆主题与定场景**：按四个场景的作业流程把需求拆成若干主题，每个主题一个文件（文件名取 `{场景}-{主题}.md`）。批量采集时拆成多主题并行子 agent 采集，由主 agent 合并存档。

**S3 检索采集**：按「检索协议」先查 wiki 站，后查 web；按该场景的「去哪搜」与「搜什么」取一手细节；每面按 `templates/采风条目模板.md` 采 3-8 条，不得采空泛面。

**S4 存档与去 AI 味**：存档于 `调研采风/采风/{场景}-{主题}.md`（元数据含场景、服务环节、采样来源、时间、并行子agent），随后执行 `python skills/pop-snow-pipeline/scripts/deai_gate.py <file> --profile doc --json`，WARN 项自查，机械项用 `--fix`；结果记一行，为 `去AI味:采风-{场景}-{主题}|PASS` 或 `WARN×N`。

**S5 质量检查**：场景明确｜必采面逐面有料（无空泛面）｜每条有来源或一手细节｜存档于 `调研采风/采风/`｜去 AI 味结果记一行。

> 聚焦搜索（跨技能服务口）：stage、plot、涌现流任一环节提出"查实一件事"（如把参考体系查实做基础、立卷敌身份后再查、涌现 write 写作前缺材料），同样按七条纪律执行，直接回报结论区与来源，不必存档采风文件。

### 模式 B 流程（查找模版）

**B1 定向**：先确定缺哪类配方（力量体系/世界观/单元剧/套路），再确定对应的环节包内容库：力量与世界观→`{pop-lantern-stage}`，单元剧→`{pop-lantern-plot}`，套路→`{pop-outline}`。

**B2 查库去重**：先读目标库的现有条目。已有匹配配方则直接引用，不回填第二条；没有才提取。

**B3 查找真实内容**：按模式 B 四联路由的「去哪找」取真实作品或 wiki 拆书成果，抽该方向的**内核结构**（分级方式、事件链、流程），不抄专名。

**B4 整合成条目**：按六字段撰写模版条目；情绪相关条目对照剧情-情绪打分表，标注情绪与分值。

**B5 回填与标注**：追加进对应环节包 `references/内容库/{对应库}.md` 的对应方向小节（力量与世界观→stage、单元剧→plot、套路→outline），须标注提取自哪个项目或哪本书，并标注验证状态。

**B6 质量检查**：通过「模式 B 五查」后，回填完成，向消费环节报告"配方已就位"。
