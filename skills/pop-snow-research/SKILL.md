# pop-snow-research

> 统一管线调研。当前版本 v3.0.2，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 做什么

**三模式**，按触发切换：

| 模式 | 触发 | 产出 | 消费方 |
|:--|:--|:--|:--|
| **模式1·立项调研** | 新书立项期：seed 摸底给了参考书 / pipeline 触发 / 用户说"调研/找燃料/采风" | `素材/赛道调研.md`、`素材/decon-lite-{书名}.md`、`素材/decon-plot-{书名}.md`、`素材/research-写作燃料.md`+`素材/content-mechanics.md`、`素材/知识沉淀/{主题}-采风.md` | pop-snow-seed / pop-snow-stage / pop-snow-plot / pop-snow-review |
| **模式2·卷级调研** | 卷循环固定位：pop-snow-plot 卷需求brief 产出后 | `素材/卷级调研-卷N.md`（增量盘点） | pop-snow-stage 卷级刷新 |
| **模式3·wiki盘点+建包** | 用户说"建包/拆书建包"或提供成功书要仿写 | `KB/设定包/{书名}/` 七文件夹全套 + `包配方.md`（5张参数表） | 全管线硬对齐层（pop-snow-seed 路径C主消费） |

**模式1六档位**：赛道定位调研（pipeline触发或手动）/ decon-lite 9表拆书（给了力量体系参考书）/ decon-plot 剧情拆解（给了剧情参考书）/ 燃料+题材机制（"找燃料/补燃料"）/ 采风（write写作质感缺口）/ 三界框架（seed/stage深层需求，可选）。

---

## 执行模式

搜索/拆解分析类工作（WebSearch/燃料采集/原文采样拆表）可派子agent（research purpose 天然适配只读通道——子agent执行搜索+分析并回报，主agent落盘与元数据）；轻量任务主agent直执。execution.mode：formal（落盘）/ draft（补全继续）/ trial（不落盘）——仅燃料档适用三档切换，其余档必须完整执行并落盘。

## wiki 主源检索协议（全局，三模式共用）

任何调研动作开始前，检索顺序固定：

1. **先查本地 wiki 镜像** `D:\popwave-wiki\docs`（=用户侧 wiki.popwave.cn 的本地副本）——赛道设定集（配方层）/写作技法库/素材原型库/世界知识库（含IP百科）/网文动态/知名小说wiki 六库。命中→直接引用并在产出标注 `来源: wiki/{路径}`，不重复造轮子。
2. **未命中或深度不够→走 web 调研**（WebSearch），产出标注来源URL/书名。
3. 产出中 wiki 命中部分与 web 新调研部分**分区标注**，下游知道哪些是库内已验证资产。

## 怎么操作（SOP全内联）

### 模式1·立项调研

#### 1a 赛道定位调研

**S1 接收**：赛道方向（`素材/用户意图.md`）+用户参考书（标注避免撞车）+指定对标书（如有）。边界：不做深层世界观调研、不拆书。

**S2 四轮搜索**（每轮先过 wiki 协议，再走 web 且至少看前5条结果摘要）：

| 轮 | 目标 | 搜索词示例 | 产出要求 |
|:--|:--|:--|:--|
| 1 赛道格局 | 什么在火什么在衰落 | `{赛道} 番茄小说 排行榜 热销 2026`+`{赛道} 起点 精品 万订 2026` | top作品≥5本，每本1句核心卖点+可迁移方向 |
| 2 读者偏好 | 读者在找什么骂什么 | `{赛道} 小说 推荐 出圈 2026`+`{赛道} 小说 不爽 雷点 审美疲劳 2026`+`{赛道} 爽点 名场面 好评 2026` | 借鉴点≥3条+避雷点≥3条，每条有来源 |
| 3 赛道演变 | 往哪个方向变 | `{赛道} 新题材 新趋势 2026`+`{赛道} 细分 垂直 蓝海 2026` | 细分格局≥3方向（代表作品+热度+饱和度+机会判断具体） |
| 4 对标分析 | 指定对标书的位置 | `{书名} 作者 风格 读者评价` | 细分位置+读者核心认可点+撞车确认（设定/金手指/开局三层）；无对标书跳过但注明 |

**S3 落盘** → `素材/赛道调研.md`：元数据（消费方+用户意图引用）+五节——赛道格局（top卖点表+赛道盘子+衰落老模式）/借鉴点与避雷点/细分赛道格局/对标分析/落地建议（力量体系方向+剧情节奏+风险提示）。

**S4 质量门禁**：top≥5本有书名列卖点｜借鉴/避雷各≥3条有来源｜细分≥3方向含热度饱和度｜落地建议有具体内容。

#### 1b decon-lite 9表拆书

**DL0 原文存在性验证（前置门禁）**：检查`素材/downloads/{书名}.txt`存在（或用户指定路径），读前100行确认是正文非错误页面。不存在=**报错中止**（提示先 tool-download-webnovel 下载或手动提供路径）。验证通过在产出元数据记录：采样源文件路径+文件大小+验证时间。**禁止基于记忆/书评/评论/公开数据重构内容。**

**DL1 接收需求**：书名+txt路径+采样范围（默认前300章）+本项目赛道方向（判断可迁移方向）。采样策略：开篇前10章（服务表5）+中段间隔章（服务表2/3）+关键高潮点（从目录章节标题判断）。采样声明落到产出元数据。

**DL2 九表拆解**（9张表必须全拆，表1/表9是硬约束）：

| 表 | 执行要点 |
|:--|:--|
| 表1 力量体系结构（**规则级深度**） | 先识别类型（等级制/修炼境/规则系/百分比/职业树…）→主养成线≥4阶（每阶标注章节范围+质变标志）→先识别子养成线**数量**再逐条拆规则（数量不固定勿预设"4条"）→每条标注原文chXX出处→交叉规则（兼职惩罚/制约/增益）→升级触发/强度膨胀/破局手段演变/设计亮点。陷阱：只列阶位骨架=描述级不合格 |
| 表2 剧情节奏 | 爽点间隔必须有具体章数（不是"快/慢"） |
| 表3 情绪弧线 | 每10章标注情绪高点位置 |
| 表4 人称与视角 | 视角策略+切换规律 |
| 表5 开篇解剖 | 第1章第1句必须有**原句摘录**（不仅分析） |
| 表6 势力格局 | 先识别分层结构（层数由书决定）→每层具名势力+主角关系 |
| 表7 金手指深度 | 机制/限制/代价/成长路径四项齐全+与主养成线耦合（加速哪条线） |
| 表8 世界危机机制 | 分层结构+终极危机1-2句概括+驱动机制 |
| 表9 动力引擎提取（**三组成齐全**） | 驱动逻辑（世界级驱动力非个人动机，标注覆盖范围+chXX）/运转机制（输入→转化→输出→反馈闭环+加速器+减速器+自洽性）/代价结构（代价清单+是否真实可感）+范式归类+引擎与力量体系关系（骨架本身/外挂/平行）+三组成合一性+辨识度评估 |

范式判据（24本男频验证）：飞轮型29.2%｜探索型29.2%｜混合型25%｜压迫型12.5%｜对抗型4.2%。

**DL3 质量门禁**（不合格补拆）：9表全完整｜表1规则级（主养成线≥4阶+子养成线≥2条有规则+chXX出处+交叉规则）｜表6≥2层具名+层间矛盾｜表7四项齐全+耦合明确｜表8≥2层+终极危机明确｜表9三组成+范式+合一性｜爽点间隔有章数｜开篇第1句有原句｜采样范围已声明。

**DL4 落盘+返回**：写入`素材/decon-lite-{书名}.md`（元数据+9表各一节）。返回：书名+采样范围+落盘路径+9表完整性摘要+下一步消费指引（seed消费表1/6/7/8/9，故事纲领消费表2/3/5）。

#### 1c decon-plot 剧情拆解

- **DP1 接收+采样**：同 DL0 原文存在性门禁。
- **DP2 6维度拆解**（必须全拆，每维度标注消费方）：力量体系对比（→seed）/金手指设计对比（→seed：加速比/限制设计/代价平衡）/Boss战设计（→plot：铺垫时长/战斗阶段数/破局方式/临终反扑/爽感爆发点）/爽感场景拆解（→plot：信息差铺设/面板爆发节奏/越级杀节奏）/分幕转折手法（→plot：转折事件/节奏变化/读者冲击）/NPC登场效果（→stage：出场方式/关系建立节奏/伏笔埋设手法）。
- **DP3-DP4 质检+存盘**：6维度完整性门禁（缺维度=不合格）→落盘`素材/decon-plot-{书名}.md`（含采样源文件元数据）→返回路径指针。

#### 1d 燃料+题材机制

**Step 1 采集+分流（对话内草稿）**：

1. **燃料采集**：从用户资料/参考书/外部事件/行业机制中找可入场面的燃料，每条必须落到三要素（缺一不可）：**事件形状**（什么事件/什么场面/怎么触发）+**主角操作点**（主角能做什么怎么主动介入，非被动遭遇）+**可外显爽点**（读者能直接看到的爽感外显，非内心活动）。
2. **题材机制分流**：参考书里的武学招式/系统面板/诡异规则/职业数值/战斗升级路径/组织运营模型，先当"内容机制"处理——能进入本书→转成三要素进燃料表；不能直接迁移→记入content-mechanics（来源/能否迁移/正确路由/禁止误用）；疑似文风特征→在content-mechanics标注"禁止误用"，不得交给 write 当文风。
3. **燃料分级**：近期可用（可筛入状态快照）/中期保留/禁用（与本书冲突或风险过高）。

**质量门**：≥3条可写燃料（formal）｜每条主燃料有三要素｜机制已分流。草稿过门+用户确认后进Step 2。

**Step 2 落盘**（读两模板后写入）：
- `素材/research-写作燃料.md`（模板 `templates/fuel-doc.tpl.md`）：元数据块+资料覆盖声明+本书涌现燃料表+外部燃料表+分级表+分流建议表。
- `素材/content-mechanics.md`（模板 `templates/mechanics-doc.tpl.md`）：元数据块+机制分流表+机制明细。**不能迁移的机制必须正式落盘**，不再只停留在"分流建议"里。

**回复格式**：skill名+execution.mode+燃料条数/主燃料摘要/content-mechanics落盘条数+下一步建议（review更新状态快照筛入近期燃料）。

#### 1e 采风

- **C1-C2** 接收主题+质感需求→2-4轮搜索（一手资料/感官细节/职业黑话/场景布局）
- **C3-C4** 片段整理（3-8个/50-200字）+质感标注→落盘`素材/知识沉淀/{主题}-采风.md`

#### 1f 三界框架（可选）

三界定界（社会界6维/自然界6维/超自然界5维）→分界调研→压力源转化+交叉困境→落盘`素材/知识沉淀/{主题}.md`。执行细则见 `references/三界框架SOP.md`；调研深度标尺见 `references/调研深度标准.md`。

### 模式2·卷级调研（卷循环固定位）

> 位置：卷末盘点→pop-snow-plot 出卷需求brief 之后、pop-snow-stage 卷级刷新之前。输入=`卷纲/卷N-需求brief.md`，输出=`素材/卷级调研-卷N.md` 喂 stage。

**V1 提取缺口**：读卷需求brief，列出本卷需要的增量设定清单——新地图/新势力/新角色原型/新机制（力量子线/金手指演化）/新素材（职业黑话/场景质感/民俗规则）。每条标注：为什么需要（brief 哪一句）+需要什么颗粒度。

**V2 wiki 盘点**：按 wiki 主源检索协议逐条查本地镜像——命中（已有设定件可复用/改编）→标注 `来源: wiki/{路径}`+复用方式（直接引用/风味微调/机制平移）；未命中→记入 web 调研清单。

**V3 web 补调**：对未命中条目执行 WebSearch（每条1-2轮，目标=一手资料/机制案例/感官细节），标注来源URL。

**V4 落盘** → `素材/卷级调研-卷N.md`：

```markdown
# 卷级调研·卷N
> 输入: 卷纲/卷N-需求brief.md | {timestamp}
> 消费方: pop-snow-stage 卷级刷新（卷N-舞台.md）

## 增量盘点表
| 缺口条目 | 为什么需要 | 来源 | 复用方式 | 内容摘要（够stage直接用） |
|:--|:--|:--|:--|:--|

## 未解决项（wiki+web均未命中，需stage自创）
| 条目 | 建议推导方向 |
|:--|:--|
```

**质量门**：brief 提取的缺口逐条有落点（wiki命中/web命中/未解决标推导方向三态之一），禁止只列缺口不给料。

### 模式3·wiki盘点+建包

**W1 wiki 盘点（防重复建包）**：查本地 wiki 镜像——`知名小说wiki/{书名}` 是否已拆、`赛道设定集/` 是否已有同赛道包。已存在→向用户报告已有资产+询问继续（重建/跳过/增量补拆）；不存在→进建包流程。

1. **原文存在性门禁**（decon-lite/decon-plot/建包共用）：采样前必须验证 txt 存在且为正文，不存在=报错中止，禁止凭记忆/书评/公开数据重构；产出元数据必带 `采样源文件` 字段，无此字段=产出无效。
