# pop-snow-review

> 章节审核引擎（起点/番茄/设定包 三范式通用）。四步审核：正向符合性→正文质量→反向充足性→沉淀。v1.1.1 更名 pop-review → pop-snow-review（雪花流家族徽记）；test 范式改称设定包范式（test 族已删，设定包改编由 pop-snow-seed 路径C 承载）。**v1.0.0 三族合并首版**：由 pop-qidian-review(v4.1.0) + pop-fanqie-review(v5.0.0) + test-review(v7.0.0) 合并——公共四步骨架单点维护，范式差异收进门禁分支（番茄追加五项卡口；设定包前置配方+X 双门禁）。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 做什么

**输入**：状态.md（确认 phase + current_chapter 授权）→ 本章对照物（按范式）→ 本章正文 → write 沉淀的白描卡+状态快照（待核对）→ 素材/文风锚定.md（如启用DNA）→ 设定库/角色库（按需）→ 上一章白描卡。

| 范式 | 对照物（Step 1 正向符合性基准） | 双文件路径 |
|:--|:--|:--|
| 统一管线 | 本章章纲（pop-snow-outline 产出：`卷纲/章纲/ch{NNN}-章纲.md`） | `产出/白描卡/ch{NNN}.md`（每章一卡，只增不改）+ `产出/状态快照.md`（replace） |
| 起点（旧管线） | 本章施工卡（plot 产出） | 同上 |
| 番茄（旧管线） | 剧情白描本章段 | `审核/剧情白描流水账.md`（append 入口）+ `审核/状态快照.md`（replace） |
| 设定包（路径C） | 本章白描卡（plot 章白描）+ 包`包配方.md` + `素材/改编计划.md` | 同统一管线 |

> 双文件职责：白描卡/流水账存"发生"（历史，只增不改/append），状态快照存"状态"（跨章聚合，replace）。write 写完即沉淀（正式产出方），review 核对其事实准确性并修正；write 未沉淀时（旧版本/直写正文）补产。**审核结论只在对话内输出，不落盘**——必须 PASS / REJECT 明确判定，REJECT 列具体打回条目+修改建议。已废弃：审核报告/verdict/剧情累计卡/current-state/小说快照/review-沉淀/压缩归档。

## 执行模式：子agent审计 + 主agent落盘

**review 是全家族唯一与子 agent 审查通道天然适配的 skill**：Step 1-3 是纯只读审计（读正文+读设定+对照+判断），不落盘；只有 Step 4 需要写文件。分工：

| 角色 | 职责 |
|:--|:--|
| 子agent（审计官，派发 verification/implementation-check） | Step 1-3 全量执行：读输入文件→三步审计→输出完整审计报告（判定+原文引用+修正方向+沉淀修正建议） |
| 主agent | 派发（附输入文件路径清单+本章章号+execution.mode）→ 收审计报告 → Step 4 落盘 → 验收门禁 |

主agent直执模式（子agent不可用/用户在场快速审）同样合法：按 SOP 顺序全流程自做。

**派发审计指令硬清单**（缺一路径=指令不合格）：任务=审核 ch{NNN}；0. 授权：状态.md phase+current_chapter=ch{NNN}；1. 输入文件逐项路径（正文/对照物/write白描卡/状态快照/上一章白描卡/文风锚定/设定库按需；设定包加包配方+改编计划）；2. 执行 Step 1-3（按已注入 SKILL.md SOP）；3. 回报：审计报告全文（判定表+检出问题原文引用+沉淀修正建议清单）。

## 怎么操作（SOP全内联）

> execution.mode：formal（材料齐全，落盘）/ draft（缺部分材料，产出标记draft）/ trial（快速体感，不落盘）。

### Step 0：范式判定+输入加载

按输入源判定范式，加载对应底牌，缺一记缺口：

- **设定包**：包`包配方.md` + `素材/改编计划.md` 存在 → 设定包范式（Step 1 前置第 0/0.5 审）
- **番茄**：`设计/创意.md` + `剧情白描.md` 存在 → 番茄范式（Step 1 追加 1e-1i 五项卡口）
- **起点**：`立项/01-立项PRD.md` + 施工卡存在 → 起点范式
- 授权核对：状态.md 确认 phase=审核阶段 + current_chapter=本章章号；不符→报用户裁决

### Step 1：正向符合性检查（正文 vs 参考资料匹配）

> 第一道闸门：正文是否兑现了对照物承诺的故事。**主线丢失=废章**。

**【设定包前置门禁，先于 1a 执行】**

**第0审·配方符合性**（不达标直接打回，后续审不做）——对照本章白描卡+包配方逐项打钩：

| 检查项 | 达标线 |
|:--|:--|
| 白描卡兑现 | 白描段（场景/事件/对话锚/动作锚/情绪转折/钩子落点）+锚点（爽点/POV/X耦合/关键数据🔒）全兑现，缺任一=打回 |
| 爽点密度 | ≥0.9/章（本章锚点标注的爽感公式必须落地且有爆发感） |
| 章末钩子 | 100%有钩+分级标注正确（L1-L5） |
| 节奏物理量 | 蓄力≤2段、大爽点前有压力铺垫、事件密度达标 |
| 偏离项 | PRD配方继承表标⚠️的参数按X取值放行，其余按包 |

达标率<90% → 打回清单（缺什么+怎么改）交write，流程结束。

**第0.5审·X符合性**（改编引擎专属，不达标打回）——对照`素材/改编计划.md`X体验层逐项检查本章X是否深耦合：

| 检查项 | 达标线 |
|:--|:--|
| X战斗耦合（战斗章） | 本章战斗是否用X独特方式，禁止写成包式打斗 |
| X日常耦合（日常/过渡章） | X在日常的表现与代价是否落地 |
| X剧情耦合（剧情推进章） | X与主线耦合点是否推进 |
| X参与度 | X必须参与动作/对话/决策，不能只是背景设定提及 |
| 事件原创性 | 本章核心事件是否从X核心张力重推，禁止复用包事件（换名复用=打回） |

X浮于表面或复用包事件 → 打回清单交write，流程结束。

**1a 核心事件逐beat对照**：从对照物本章段提取核心事件beat（2-4个），逐条对照正文，标注兑现✓/✗与偏离类型（缺失/替换/增加/顺序变/强度变）。全部兑现或偏离但主线未丢→进1b；主线丢失→**废章**。

**1b 设定一致性**：

| 检查项 | 判定标准 | 不合格处理 |
|:--|:--|:--|
| 力量体系 | 主角能力越级？等级与骨架一致？ | 标注越级点 |
| 金手指规则 | 符合"梗×机制×限制"？加代价了吗？ | 标注违反点 |
| 骨架一致性 | 越级不付代价/攀登逻辑断裂/驱动脱钩 | **废章** |
| 天赋约束 | 金手指喧宾夺主让坐标系失去意义？ | **废章** |
| 世界观规则 | 违反世界自洽（能力来源/触发条件/作用边界）？ | 标注违反点 |
| 势力格局 | 势力关系/实力数值与设定一致？ | 标注不一致 |

**1c 角色一致性**：配角/反派行为符合角色卡？标注OOC点。
**1d 爽感闭环**：本章主推爽感类型+触发段/爆发段/后果段三段位置——**三段缺一=废章**。
**1e 连续性**：人物状态/设定/资源/时间线/伏笔与上一章白描卡、状态快照冲突？冲突项进 Step 4 沉淀。

**【番茄追加五项卡口，缺一项不得通过】**

**1e' 番茄底线检查**：

| 检查项 | 标准 | 不合格处理 |
|:--|:--|:--|
| 字数 | 2000-2500字，不准超过2500 | 超出→REJECT |
| 章末钩子 | 主动决策型，禁止被动接收型 | 违规→REJECT |
| 节奏密度 | 8-12个事件/章 | 不足→标注 |
| 章型7节拍 | 开场炸弹→冲突→金手指→应用→爽感→危机→钩子 | 缺节拍→标注 |
| 前后章衔接 | 是否回收前章钩子？ | 未回收→标注 |
| 章名格式 | 10字以上，有噱头/反差/创意点 | 违规→标注 |
| 合规底线 | 政治敏感/红线词/未成年保护/价值观 | 命中任一→直接REJECT |

**1f 6章型7节拍对齐**（对齐 fanqie-write 章型体系）：章型归属明确（opening_shift/exploration_gain/confrontation_pressure/combat_reversal/high_tier_display/reveal_hook之一，无归属→标注）/7节拍完整（缺→标注缺哪个）/章型-内容匹配（错位→标注+建议调整）。

**1g 战斗可写性审核**（只在战斗章触发，非战斗章标N/A）：4拍节奏（压迫→反转→碾压→余波，缺拍→标注）/代价可见（无损碾压→标注）/画风一致（符合力量体系.md战斗画风标签）/能力边界（越界→REJECT）。

**1h 主角主动性审核**：本章决策（≥1个主动决策）/行动驱动（主动出击触发还是被动卷入）/目标推进（推进自己的目标）/主动性等级（A主动出击/B主动应对/C被动推着走）。**连续2章C级=REJECT级警示，必须重写。**

**1i 多视角覆盖审核**：当前幕多视角（每幕≥1段非主角视角段落）/视角切换合理性（服务于信息差/悬念/格局展示）/视角返回（单章非主角视角≤30%篇幅）。

### Step 2：正文质量检查

**2a AI味检测**：识别具体 pattern 而非泛泛判断。**每项检出必须给原文引用+pattern编号+修正方向**；疑似作者风格标注"⚠️请确认"。

15项 patterns：①二分对比（"不是X而是Y"→直接说Y）②开场清嗓子（"要知道"→砍掉直接进入）③伪洞察铺垫（"真正的高手都懂"→让观点自己站住）④浅层分析尾缀（"凸显了/彰显了"→删或改具体因果）⑤重要性吹嘘（"划时代意义"→说事实）⑥模糊归因（"专家认为"→说来源或砍）⑦假强动词（"发挥着作用"→用"是/有"）⑧同义词循环（同一实体换着叫→该重复就重复）⑨否定列举（"不是X不是Y而是Z"→直接说Z）⑩戏剧性碎片化（连续3+短句碎片→完整句）⑪机械节奏（连续同句式→变换）⑫修辞铺垫（"试想一下"→砍掉直接说）⑬假深刻结尾（章末金句升华→停在具体动作/画面）⑭总结重述结尾（"总之"→停在最后具体点）⑮情绪直给（"他感到XX"→动作展示）。

高疲劳词3级——S级（出现即标）：蝼蚁/蚍蜉/井底之蛙/倒吸凉气/瞳孔骤缩/满场死寂/鸦雀无声/轰然炸裂/全场哗然/不寒而栗/毛骨悚然；A级（≥2次标）：冷笑/嗤笑/不屑/嘴角上扬/眉头微皱/眼中闪过/淡然/漠然/凌厉/深邃/恐怖如斯；B级（≥3次标）：不禁/不由得/忍不住/似乎/仿佛/犹如/霎时间/刹那间/顿时/骤然。

结构性4项：描写堆叠（连续3行+纯感官无动作→插动作）/信息重复（同信息2次+→删）/对话死板（连续6行+纯对话→穿插动作）/破折号滥用（单章≥5处→改标点）。

对话质量6项（给方向不替写）：①信息密度（连续2句+同维度→删减合并）②潜台词（传声筒讲设定→补话外之音）③节奏（连续3句+句长相近→长短交替）④动作插入（"笑了笑"标签式重复→改有信息的动作）⑤功能复合（只传递信息→补塑造/伏笔/氛围层）⑥个性区分（去标签认不出谁→按状态快照语言指纹调）。判定：全过=合格；1-2不过=标注方向下章注意；3+不过=建议修改本章对话。

**2b 笔触DNA一致性**（启用态=素材/文风锚定.md存在）：句式节奏/叙事距离/对话引导词/感官顺序/情绪外化/系统面板格式（DNA含面板须遵从、无面板禁擅加）/章名（贴合内容无噱头）/章末钩子（主动决策型，禁被动接收型）8项逐查。输出本章DNA生效等级（强/中/弱/未生效）+下一章执行包建议。trial模式：查全章风格自洽+未套错风格。

**2c 好看度4问**（最主观也最重要，**每问必须给具体证据**）：①有没有让人想往下翻的劲？（有→引用最抓人的1-2句；无→问题在哪）②最抓人的画面/台词？（引用原文；找不到→标"无记忆点"=本章最大问题）③哪里无聊了？（标具体段落位置+删/压缩/插动作/换场景建议）④代入感够不够？（画面感强弱段/主角选择与读者重叠度/配角像不像活人）。

**2d 字数检查**：**以脚本实测为准**（exec 跑 `pop-snow-write/scripts/word-count.ps1 -Path 正文/ch{NNN}.txt`；脚本不可达回退 PowerShell 内联统计纯汉字）——**实测输出原文必须贴进审核结论**，禁转述/引用生成侧数字。超/不足标注。

**进 Step 3 前自检**（任一项未过→补全后再进）：15项patterns每项已查（命中或未命中都确认）｜疲劳词3级已扫｜结构性4项已查｜每个检出有原文引用+pattern编号+修正方向｜已区分AI slop与疑似作者风格｜修正建议给方向不给成品。

### Step 3：反向充足性检查（参考资料是否足以指导后续创作）

| 维度 | 检查项（缺→建议） |
|:--|:--|
| 大纲/对照物 | 下一章核心事件beat有吗（缺→plot补）/爽感三段式设计了吗（→plot补）/章末钩子规划了吗（→plot补）/剩余幕序列方向明确吗（→plot补幕纲） |
| 设定库 | 正文用了但无定义的设定（→world补）/下一章场景所需设定（→world补）/力量体系后续阶位（→seed补骨架） |
| 角色卡 | 新登场角色有卡吗（→character补）/已有角色行为模式够指导写作吗（→character补）/角色关系网络明确吗（→character补） |
| 燃料库 | 可用燃料队列够后续章节吗（→research补）/需要新一轮调研吗（→research执行） |

**产出补强建议清单**（四维度 ✅充足/⚠️需补强+具体建议）。**红线：即使全充足也要逐项确认，不能跳过。**

### Step 4：沉淀核对与落盘（主agent执行）

**核对**：对照正文核对 write 沉淀的双文件事实准确性——关键数据🔒/钩子状态（含超3章未回收标红🔴）/角色状态/禁止漂移。有误即修正；write 未沉淀时补产。

**落盘清单（路径按 Step 0 范式）**：

| 动作 | 对象 | 规则 |
|:--|:--|:--|
| 白描卡（起点/设定包） | `产出/白描卡/ch{NNN}.md` | 只增不改（新建本章卡，不覆盖旧卡），~300-500字：事件白描（3-5句叙事流）+关键数据🔒一行式+爽点·钩子（含信息差类型）+人物关系变化（可选）。【设定包追加】本章DNA执行包节（章型卡/笔触目标/章内套路——write下一章消费）。模板 templates/chapter-card.tpl.md |
| 流水账入口（番茄） | `审核/剧情白描流水账.md` | append-only 追加本章入口：`## chXXX「章名」` + 白描（3-5句叙事流）+信息差+涌现/角色状态+埋设钩子+回收钩子（标注埋设章）。首章初始化文件头：`# 剧情白描流水账` + `> skill：pop-snow-review \| 每章剧情白描 append-only \| 起点：chXXX` |
| replace状态快照 | `产出/状态快照.md` 或 `审核/状态快照.md` | 只写跨章聚合：未回收钩子台账（本章新钩子入账，回收标✅已回收·chXXX）+角色当前状态表（按主角变化五项更新，龙套移除）+禁止漂移（人名/地名/阶位数值/已死角色/已废设定硬清单）。模板 templates/state-snapshot.tpl.md |
| 按需更新库文件（起点） | 设定库10文件/角色库/卷纲/写作燃料 | 已确认设定→全书设定；人物状态→角色库；伏笔长线→卷纲；可入场燃料→写作燃料.md |

**验收门禁**（查文件系统不信口头）：白描卡 ch{NNN}.md 存在且含四节（番茄=流水账已追加本章入口且历史未删改）✓ 快照 mtime 晚于审核开始时刻 ✓ 未产出任何废弃文档 ✓。

### Reconstruct模式：批量回溯审核

**触发**：pipeline 导入流程调度，或用户说"回溯审核""批量审稿"。对已有正文逐章回溯，生成逐章白描卡+状态快照，为续写提供状态基础。落盘必须 formal。与正常review差异：多章正文采样输入/简化审核（只做信息提取+正向简化+AI味+字数，跳过好看度4问与对照物对照）/审核结论对话内输出。

**采样策略**：≤10章全审；11-30章最近5章全审+其余每5章取1章；>30章最近5章全审+第一章+每10章取1章。采样章节完整审核并建卡；非采样章节快速提取（角色状态/设定揭示/伏笔/章末钩子）汇聚进快照。批量审核>8章强制拆批。

**执行**：①LS扫描 `正文/` 确定章节范围与采样集 ②设定文件按需读（力量体系/金手指/角色库/全书设定/文风锚定/对照物，不存在则跳过该项检查）③采样章逐章：信息提取（核心事件2-3句/角色状态变化五项/新设定/新角色/钩子/伏笔埋设回收）+正向简化（主角动作闭环✓✗/越级不付代价✓✗/金手指规则✓✗）+质量简化（AI味标注位置+字数实测）→ 每章建白描卡 ④汇总生成状态快照（标注"由批量回溯审核生成"）。完成后更新 状态.md（phase 归位到续写 Phase/就绪态）。

**回复**：审核范围/采样策略/产出N张卡+快照/总体质量判断/主要问题1-3条/下一步建议。

## 红线

1. **正向符合性不通过=废章**：核心事件主线丢失/越级不付代价/金手指取消坐标系意义/爽感三段缺一 → REJECT 打回重写，不得带病放行。设定包前置门禁：配方达标率<90% 或 X 浮于表面/换名复用包事件=打回，其他审不用做。
2. **检出必须给证据**：AI味每项检出给原文引用+pattern编号+修正方向；好看度4问每问给具体证据（原文引用或段落位置）；禁泛泛说"有AI味/还行"。
3. **反向检查必须产出补强建议清单**：四维度逐项确认（全充足也要确认"充足"），缺项给具体补强建议。不能跳过。
4. **双文件每章必核对**：review 完成必须核对/修正白描卡+状态快照（write未沉淀则补产；番茄=流水账append+快照replace）；主角变化五项（位置/能力/资产/心态/关系）每章沉淀。只审不核双文件=沉淀未完成=write断粮。
5. **字数以脚本实测为准**：实测输出原文贴进审核结论，禁转述/引用生成侧数字。
6. **审核结论必须 PASS/REJECT 明确，review 不重写正文**：不能模棱两可；REJECT 列具体打回条目+修改建议；review 只诊断+打回清单，修改由 write 执行。
