# pop-snow-seed

> 统一管线立项引擎。v3.0.0 新增正式 L0 核心卖点步骤（立项五律+创意撞击+三关筛选），四层串行 L0→L1→L2→L3。v2.1.1 更名 pop-seed → pop-snow-seed（雪花流家族徽记，功能零变化）。v2.1.0 模板进化（L1 加世界舞台 / L2 改分卷走向+每卷张力结构 / L3 卷表加里程碑强敌+新困境列）。v2.0.0 架构重写：**产出从"六要素PRD"改为"三层共创全书大纲"**——seed 不止于立项，而是把全书大纲写完再开工。老板 2026-08-31 拍板：写 200 万字小说是大型软件工程，seed 必须把命运图→plus白描→结构化大纲三层定死，world 完善设定、plot 完善分卷卷纲、outline/write 接力。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 做什么

**seed 的核心职责 = 与用户共创四层产物，定下全书大纲。** 四层严格串行（L0→L1→L2→L3），每层不定稿不进下一层：

| 层 | 产物 | 干什么 | 落盘 |
|:--|:--|:--|:--|
| **L0 核心卖点** | 0.3秒卖点——读者一眼识别赛道并产生点击欲望 | 从卖点引擎库选 2 个已验证引擎杂交 + 差异化钩子，过可写性/差异化/容量三关 | `立项/00-L0核心卖点.md` |
| **L1 命运图** | 世界舞台+一句话说清整本书讲了个什么命 | 交代世界/时代/变局，钉四颗钉子：起点/终点/最大反转/最大落差 | `立项/01-命运图.md` |
| **L2 命运图plus** | 每卷一段走向（概括层，细节留给 plot） | 每卷立张力结构：实力/势力质变+里程碑强敌+新困境，让故事持续发生 | `立项/02-命运图plus.md` |
| **L3 全书大纲** | 结构化剧情大纲 | 分卷剧情安排，可从中提炼世界观/人物/养成节点/力量体系 | `立项/03-全书大纲.md` |

**共创原则（立身之本）**：每一层都是"agent 出草案 → 用户拍板 → 改 → 再拍"的来回拉锯。**用户拍板是每层的唯一关卡**，不是 agent 自检。审美判断（动不动人/好不好看/逻辑密不密）全部发生在用户与 agent 面对面共创的这几步，在源头被人的判断接住，不在下游被规则拦截。

**下游对接**：L3 全书大纲=全书宪法。pop-snow-stage 消费大纲补世界血肉（力量体系数值化/势力/地理/角色库）；pop-snow-plot 在大纲的一卷切片内展开卷纲→幕白描，不许突破大纲刻度；pop-snow-outline/write 接力正文。

## 执行模式

**主 agent 直执，禁用子agent代跑共创。** seed 是全链路交互最密集的环节——三层每层都要和用户对话、拍板、修改，这些共创对话必须由主 agent 亲自进行，不得派发给子agent。

**唯一例外**：纯只读的调研支撑（扫榜/拆书包内容检索/市场数据搜集）可派子agent回报原始材料，主agent消费。但凡涉及"出草案给用户看、听用户意见、改稿"的环节，一律主agent。

execution.mode：formal（落盘定稿）/ draft（共创中，未拍板）。

## 怎么操作（SOP全内联）

### Step 0：路径判定 + 拆书包匹配

一次问清两件事，禁止反复打断：

**0a 输入路径**（决定创意从哪来）：

| 用户状态 | 判定 | 去向 |
|:--|:--|:--|
| 给了设定包/要仿写某本书+有自己的创意X | 路径C 设定包改编 | 直接以该包为最近标杆 |
| 给了明确创意（一句话说清主角+在做什么） | 路径A 创意直通 | 0b |
| 只给方向/偏好，或"没想好想推荐" | 路径B 方向发散 | 0b 发散后再匹配 |

**0b 拆书包匹配（找最近标杆）**：扫描 wiki 赛道设定集（本地镜像 `D:\popwave-wiki\docs\赛道设定集`，= wiki.popwave.cn）现有拆书包，找与用户想写的书**赛道/机制最接近**的一本作为参考标杆。匹配到参考书后，**读它的 `D:\popwave-wiki\docs\知名小说wiki\{书名}\立项\` 文件夹**（00-L0核心卖点 / 01-L1命运图 / 02-L2命运图plus / 03-L3全书大纲，拆书必要产出），拿它的 L0-L3 骨架作对标。匹配结果向用户确认："我找到最接近的标杆是《XXX》拆书包，L0-L3 共创时我会参考它的骨架（卖点引擎/结构/节奏/养成刻度），内容全部原创，可以吗？"**原创 vs 参考的比重由用户拍**：用户可选"多参考骨架"或"基本全原创"。无接近的拆书包→声明裸原创，L0 从卖点引擎库杂交、L3 骨架由 agent 从 L2 白描现推。

**0c 底牌处理**（路径B/C有参考书时）：笔触参考书→pop-dna-style 提取文风锚定；力量/体系参考书→pop-snow-research 拆书。只读工作可派子agent，回报主agent消费。

### L0：核心卖点（立项五律）

**干什么**：定 0.3 秒卖点——读者一眼识别赛道并产生点击欲望。这是全书的第一颗种子，L1 命运图从这里长出来。**L0 不定稿，不进 L1。**

**立项五律（从 9 本成品好小说反推，L0/L1 的生成标准）**：

| # | 规律 | 干什么 |
|:--|:--|:--|
| 1 | **L0 卖点 = 两个已验证爽点引擎的杂交 + 一个差异化钩子** | 卖点必须落在"读者已验证会爽"的引擎上，差异化钩子只是让这个爽点有记忆点。**禁止抽象概念堆砌**——"记忆银行""心灵窃贼"这类概念读者不知道它能带来什么爽 |
| 2 | **金手指 = 叙事装置，不是战力工具** | 金手指同时承担成长引擎+结构骨架+主线伏笔三重功能（如诡秘灰雾=身份错位+信息平台+登神伏笔）。禁止只当一次性能力设定 |
| 3 | **结构 = 一个可复制的"单元" + 一条贯穿的"主线"** | 单元保证日常产出（每 3-5 章一个爽点闭环），主线保证长线悬念（读者追读的理由）。能写长的书都是"单元可无限复制+主线可无限回收" |
| 4 | **立项五件事一起想清楚** | 卖点/金手指/结构/节奏/读者预期五件事在 L0 一起定，不只想卖点。好的立项不是"想一个创意"，是"想清楚一个能自运转的系统" |
| 5 | **可写性 = 机制化的"剧情发生器"** | 有机制保证每章都有事发生、有爽点（如冒险屋"下一单是什么"、诡秘"每卷一个谜团"），不靠每次现想"下一章写什么" |

**创意撞击（规律1 的落地方法）**：

1. **读引擎库**：读 `D:\popwave-wiki\docs\卖点引擎库\00-索引.md`（= wiki.popwave.cn 顶层库），按用户方向/创意选 2 个已验证引擎——一个管日常爽感，一个管长线结构；
2. **杂交**：把两个引擎的机制叠在一起，问"这个组合会产生什么新玩法"；
3. **加差异化钩子**：给杂交产物加一个只属于这个组合的记忆点（让读者 0.3 秒记住）；
4. **过三关**：可写性（规律5）/ 差异化 / 容量（规律3）；
5. **反例自查**：翻两个引擎卡的"反例/边界"，确认没踩坑。

**三关筛选（每个 L0 候选必过）**：

| 关 | 问什么 | 不过怎么办 |
|:--|:--|:--|
| 可写性 | 能不能机制化产生剧情？有"自动产生剧情的引擎"吗 | 换引擎/补机制 |
| 差异化 | 和现有书有什么不同？有记忆点吗 | 补差异化钩子 |
| 容量 | 能不能撑 200 万字？单元可复制+主线可回收吗 | 补结构/换结构 |

**输入路径与 L0 的关系**：路径A（用户有创意）→ agent 用引擎库把创意拆解成引擎组合，检查是否落在已验证引擎上，补差异化钩子，出 L0 候选；路径B（只有方向）→ agent 从引擎库选 2 引擎杂交，出 3 个 L0 候选；路径C（设定包改编）→ 读设定包/参考书的 `立项/00-L0核心卖点.md`，继承或改编。

**共创流程**：agent 出 2-3 个 L0 候选（各带引擎拆解+差异化钩子）→ 用户选/改/拍板 → 定稿落盘 `立项/00-L0核心卖点.md`。**用户没拍板，不进 L1。**

### L1：一句话命运图

**干什么**：用一句话说清整本书讲了主角的一个什么命。这不是故事简介，是浓缩的命运图。

**先交代世界舞台（一句话命运图之外，单独立一段）**：故事发生在哪个世界、什么时代背景、当下正处什么大变局。世界决定格局——是缩在一座城，还是牵动整个位面。如：DND 费伦大陆 / 近未来赛博朋克都市 / 高武大唐；当下变局如：圣者浩劫、灵气复苏、智械叛乱。**舞台不交代清楚，故事容易写小。**

**四颗钉子（缺一不可）**：

| 钉子 | 干什么 | 深渊主宰示例 |
|:--|:--|:--|
| 起点 | 主角开局是个什么处境 | 平民窟孤儿，护着八岁妹妹 |
| 终点 | 主角最后成了什么 | 统一死亡三神、执掌冥界的死亡之主 |
| 最大反转 | 全书最深的钩子/真相 | 妹妹是恐惧神子，自己是杀戮之子 |
| 最大落差 | 起点到终点的距离=全书养成总账 | 凡人5级平民→伟大神力 |

**判断标准**：这句话读完，读者脑子里要浮现"我要看这个人怎么从那走到那"的欲望。世界舞台+四颗钉子钉死，全书的方向和格局就锁了。

**共创流程**：agent 出 1-3 个候选命运图（各带世界舞台）→ 用户选/改/拍板 → 定稿落盘 `立项/01-命运图.md`。**用户没拍板，不进 L2。**

---

### L2：命运图 plus（分卷走向）

**干什么**：对 L1 的丰富扩写。**每卷写一段走向**，把 L1 略过的血肉填回来——主角从什么状态到什么状态、世界往哪走。只到**概括层"发生了什么"**，具体打法/战斗/对话全部留给 plot。合起来是全书脉络，不是某一卷的详写。

**每卷必立张力结构（网文持续发生的命门，缺一卷都不是合格的卷）**：

| 件 | 要求 |
|:--|:--|
| 质变 | 本卷主角的**实力或势力**发生一次不可逆跃迁（不是平推，是上一个台阶） |
| 里程碑强敌 | 本卷解决一个**此前压了主角一段**的标志性对手，兑现积压的张力 |
| 新困境/新敌 | 旧敌解决的同时**立刻引来更大一层的麻烦或敌人**——读者翻下一卷的理由 |

三段合起来：主角每卷都在"爬一级台阶—踩碎一个拦路的—发现头顶还有更大的"。**任何一卷没有新困境，故事就在这里断了气。**

**容量红线**：L2 是全书的**脉络**，不是某一卷的详写。每卷一段概括走向，**不写成一整段抒情白描，更不写具体事件细节**——那是 plot 的活。上次犯的"把一卷的料铺成全书""只抒情没写事实"都从这管住。

**判断标准**：故事本身要好看——有起承转合、有情感峰值、有让人想追的钩子。这一层最吃审美，全靠用户读起来的反应判断。

**共创流程**：agent 基于已定 L1 逐卷扩写走向（此时可参考 0b 匹配的拆书包节奏，比重按用户拍板）→ 用户读、提意见 → agent 改 → 再拍 → 定稿落盘 `立项/02-命运图plus.md`。**用户没拍板，不进 L3。**

---

### L3：结构化全书大纲

**干什么**：把 L2 的白描，结构化拆成可执行的全书大纲。这一层是全书宪法，后续 world/plot 全在它的约束下做功。

**必须可提炼出五样东西**：

| 提炼物 | 内容 |
|:--|:--|
| 分卷剧情安排 | 全书几卷，每卷一句话卷命运（从什么状态到什么状态+最大不可逆改变） |
| 世界观 | 世界格局/力量层级/核心规则 |
| 人物 | 主要人物清单+各自定位（长期线/本卷线/伏笔线） |
| 养成系节点 | 主养成线全书刻度（哪卷到哪一阶/天花板何时碰）+副养成线卷间分配 |
| 逻辑缜密 | 卷间因果链咬合，无前后矛盾，无数值崩坏（养成刻度不超天花板） |

**骨架来源**：按 0b 用户拍板的比重——多参考→从匹配拆书包继承骨架（四段式大结构/养成刻度/角色配置基线），血肉从 L2 填；裸原创→agent 从 L2 白描现推骨架。**无论哪条，数值刻度必须显式列出（每卷养成到哪一档），不许含糊。**

**共创流程**：agent 搭骨架+填血肉出草案 → 用户逐卷审、提意见 → 改 → 用户拍板 → 定稿落盘 `立项/03-全书大纲.md`。

---

### 定稿后：交接下游

L3 全书大纲用户拍板定稿后，seed 职责完成。向用户报告："全书大纲已定，接下来交 world 完善设定（力量体系数值化/势力/地理/角色），再由 plot 逐卷展开卷纲。"加载 pop-snow-stage 接力。

> **seed 止于全书大纲**：力量体系数值化/角色库/分卷卷纲等工程级展开由 pop-snow-stage/pop-snow-plot 接力，不回 seed。

## 红线

1. **四层串行，层层用户拍板**：L0 不定稿不进 L1，L1 不定稿不进 L2，L2 不定稿不进 L3。用户拍板是每层唯一关卡，agent 自检不能替代用户确认。禁止一口气四层全出完丢给用户。
2. **共创对话主 agent 直执**：出草案/听意见/改稿一律主agent，禁派子agent代跑与用户的共创对话；仅纯只读调研支撑可派子agent。
3. **L3 数值刻度必须显式**：养成线每卷到哪一档、天花板何时碰，必须写成可查的刻度，禁止"逐步变强"这类含糊表述。这是防 28 章半神类崩坏的唯一闸门。
4. **参考不抄内容**：参考拆书包只取结构/节奏/刻度骨架，专有名/具体事件/人物 100% 原创，禁止换名复用。
5. **seed 止于全书大纲**：禁产 `设计/` 力量体系数值化/角色库/卷纲等工程级文档——那是 stage/plot 的职责。
6. **L0 卖点必须落在已验证引擎上**：禁止抽象概念堆砌（"记忆银行""心灵窃贼"类读者不知道能带来什么爽的概念），卖点必须从卖点引擎库选已验证引擎杂交 + 差异化钩子。
7. **金手指必须是叙事装置**：金手指要承担成长引擎+结构骨架+主线伏笔三重功能，禁止只当一次性能力设定。
