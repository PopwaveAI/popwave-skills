# pop-snow-seed

> 统一管线立项。v6.2.0：融入结构理论阶段积累——Step 4 先定线（主日常线＋副线＋每轮固定走法＋咬合方式），排卷补每卷日常线交代与伏笔够用检查，轮三补拍压力源。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

***

## 这个 Skill 做什么

**职责：把用户的模糊想法＋参考＋调研，先做成一个精彩的、用户拍板的故事，再把故事转录成 14 维主干文档。** 顺序不可倒：故事是源，文档是故事的结构化表达。

| 段               | 对谁  | 干什么                         | 产出                  |
| :-------------- | :-- | :-------------------------- | :------------------ |
| 立项引导（Step 0-3）  | 对人  | 收命题问需求，按需求查底子出卡，分轮拍板根决策     | 需求清单＋底子卡组＋已确认的根决策   |
| 故事工坊（Step 4-8）  | 对文档 | 照确认结果组装：王道主干→出奇项→伏笔线→排卷→讲一遍 | 定稿故事（叙事白描）          |
| 定稿交接（Step 9-10） | 对双方 | 六问自检、脱稿讲述测试、存档去AI味          | `立项/00-融合立项稿14维.md` |

三条根原则：

1. **先问需求，再查底子，后组装**。家里产品直接进 AI 对话，没有前置表单——用户开口那句话就是全部输入。先把方向问清（什么流、给谁看、图什么、多长），再按方向查底子（是什么流、读者图什么、标配是什么、王道怎么走、什么写烂了），出奇项最后加。方向没定就查，查回来一堆用户不要的；没查底子就组装，产出结构再对也会跑题——都是实测教训。
2. **主线是双元的**：主角的欲望（起点）＋世界的结局（终点线），两线的张力关系四选一。全书反转只放世界线；欲望线线性推进不反转。
3. **结构分三层各管一段**：英雄之旅、三幕管一卷之内；日常线与伏笔线管全书几十个小故事从哪来；立项这页纸管这本书最初的样子。英雄之旅当不了全书主干。

**边界**：只锁故事功能位（终点、冲突结构、反转、浪、主干），不实名——人物用「主角／反派A／终敌」占位，命名、刻度、建制归 stage；不拆卷、不排章，归 plot。

**产出**：`立项/00-融合立项稿14维.md`，双层——定稿故事（每卷一段叙事白描）置顶，14 维主干为转录解剖图，附伏笔清单。下游：stage 消费世界观组 1-4＋人物组 5-7 做实名与细化；plot 消费剧情组 8-11 排卷进度表与卷纲。

**称谓约定（不混叫）**：「底子卡」=查底子的输入料卡（一源一卡）；「定稿故事」=故事工坊拍板的叙事白描；「融合立项稿」=输出文档（定稿故事＋14 维转录）。

## 执行模式

**主 agent 直执，禁用子 agent 代跑共创。** 立项是整条流程交互最密集的环节——出草案、听意见、改稿必须主 agent 亲自做。唯一例外：纯只读的调研支撑（扫榜、拆书包检索、参考材料消化）可派子 agent 回报原始材料，主 agent 消费。

**共创三态**：

1. **共创态**（默认）：用户在场，每步端候选给用户圈定，拍板定稿。
2. **代理自定态**（无真人／自动化环境）：agent 逐层自出草案、自审自拍，串行推进。拍板栏显式标注 `[](agent自定·{原因})`，禁止伪造"用户说过"。
3. **降级态**：共创中用户离开——已拍层保持用户意见，未拍层降为 agent 自定，降级时刻写进共创记录。

所有产出物头部「共创状态」按三态如实标注。

## 怎么操作（SOP 全内联）

### 第一段·立项引导（对人：分轮确认，没拍板不往下走）

#### Step 0 收命题、问需求

**产品形态先说清**：家里产品直接进 AI 对话，没有前置表单——用户不先填书名、分类、标签，开口那句话就是全部输入。所以立项第一步是问，不是读字段。别家产品让用户先填表再进对话，开场"读字段"那套不照抄。

先收再问：

1. **收命题**：用户进对话说的话逐字收下，拆出元素清单。
2. **盘已有**：项目内资产（赛道包、拆书报告、旧大纲、`pop-snow-write/references/文风兜底/` 的现成文风档）、用户历次裁决记录（同类问题他怎么判过）。已确认的不重问，已有的不重查。
3. **问缺口**：命题说不清的，分轮问，一轮两三问，每问给 2-4 个选项、至少一个标推荐：

   - 想写什么流／什么题材（命题只给模糊方向时，凭常识给流派候选让用户挑；这一步只定方向，不做深度调研）

   - 给谁看（男频／女频，主分类方向）

   - 读者点开这本书图什么（方向级一句即可，不必精确）

   - 篇幅量级（目标章数、大概几卷）

产出**需求清单**：什么流、给谁看、图什么、多长。**需求清单没经用户确认，不开查底子**——调研方向由需求定，方向没定就查，查回来一堆用户不要的。

**文风味主档在此收**：按用户赛道从文风兜底库筛 2-4 个同赛道候选端给用户勾选。用户点中本地档名，绝不再外搜蒸馏，直接作一手输入；未点中再走调研。

#### Step 1 查底子

按需求清单逐个元素出一张底子卡（模板 `templates/底子卡.tpl.md`）。七栏：

| 栏      | 内容                | 例（神豪流）               |
| :----- | :---------------- | :------------------- |
| 定义与定位  | 这个流派是什么，用番茄标签库定流派 | 系统发钱、狂拽平推            |
| 开山与代表作 | 三到五本              | 《重生之神级败家子》…          |
| 读者图什么  | 爽点清单，逐项可执行        | 压抑后打脸／扮猪吃虎／消费奇观／平推碾压 |
| 标配零件   | 这个流的世界配置          | 花钱系统、返利公式、打脸递进       |
| 王道走法   | 主流验证过的主线          | 触发→执行→到账，高频短循环       |
| 写烂清单   | 被用滥的点             | 纯炫耀无代价               |
| 组合先例   | 元素组合有没有人写过        | 灵气复苏×财富＝《全球高武》       |

规则：

- **调研清单先经用户确认增删再执行**——调研不是可选项，查什么由用户拍板。

- 检索顺序：本地文风兜底档 → wiki 站 `https://wiki.popwave.cn`（卖点方向库、`写作灵感/{赛道}/{书名}/seed-*` 卡）→ web。wiki 命中与 web 新查分区标注。

- 信息源优先级：自有 wiki → 官方资料 → 权威百科 → 垂直百科 → 社区讨论（降权，标"非官方"）。

- 取材预算：单环节 ≤1 轮 / ≤5 query / 回传 ≤30KB，超限截断留结论区。

- 流派定位用 `references/番茄标签库.md` 按需查，不向用户穷举整表；非番茄平台也只作候选参考。

- 查不到的元素如实说"没查到"，不用脑补顶替。**底子卡没齐，不进 Step 2。**

> wiki 踩坑两条（实测）：① 赛道目录名全小写无分隔符（`写作灵感/西幻dnd/`），大写直接 404；② `写作灵感/{赛道}/` 裸目录不可枚举，发现参考书走「卖点方向库」页脚链接或种子卡直连。

#### Step 2 根决策分轮拍板

分轮与用户确认，一轮两三问，每问给 2-4 个选项、至少一个标推荐。**先拍决定其它项的根决策，拿到答案再定制后续轮的问题与推荐项**——男频神豪，轮三就往"挣钱兴家欲望线＋身份差伏笔线"上推荐；女频宅斗，往"身份恢复＋复仇对象升级"上推荐。推荐只是降低回答成本，用户没选不算数。

- **轮一·流派承诺**：拿底子卡回验 Step 0 定的方向——这个流的读者图什么、什么写烂了；命题方向跟底子卡对不上（说要神豪的爽点、查出来是经营文配置），摆出来让用户重选。拍板产出一句承诺："这是本XX流的书，向读者承诺XX、XX、XX。"爽点承诺从底子卡的"读者图什么"栏来。

- **轮二·篇幅与分卷**：量级已在 Step 0 问过，此处定切法——分几卷、每卷大致范围。**卷数由用户定**，agent 只建议切法。

- **轮三·结构根**（改起来最贵的一轮，逐项拍；问题与推荐按轮一流派定制）：

  - **欲望线**：主角要什么。类型库：求生、变强、长生、回家、复仇、复活某人、找真相、挣钱兴家、守护、身份恢复；可组合（复仇＋变强）、可接力（满足后接大一号的）。

  - **压力源**：什么逼主角不能停。备选：欠债、倒计时、仇家追杀、家道中落、组织任务、找不到就死。与欲望线配套拍（复仇配仇家追杀）；没有压力源，主角随时能躺平。

  - **世界结局**：主线揭开后世界落什么局面。

  - **最终敌人**：具体可恨、能列出一排爪牙的对象——不是抽象制度。

  - **两线关系**：四选一——同路（要到＝世界得救）／相撞（要的与世界需要的不兼得）／变了样（要A最后发现是B）／主角是钥匙（欲望达成即世界结局开关）。

  - **伏笔线类型**：四选一——身份差（神豪、马甲）／世界谜底（灵气复苏、玄幻）／系统来源（系统文）／复仇对象升级（都市复仇）。选了世界谜底才定谜底类型（六型见 `references/底层认识.md`）。

  - **多候选纪律**：欲望线×关系×谜底的组合出 2-3 个候选端给用户选——故事核是全书改起来最贵的决策，没见过候选不许拍板。可故意放一个错位组合测张力。

  - **轮换查重**：列出同一出题人近三个案子的关系、谜底、排期节奏，撞了必须换。

#### Step 3 锁边界

只锁全书稳定、后期改起来贵的决策，与题材无关的跳过：

- 世界与空间结构（多大、几层、地图外有没有东西）

- 能力／资源体系的方向与硬上限、代价

- 势力与关系格局（谁掌握核心资源、谁对抗谁、主角在哪）

- 信息边界（谁知道什么、真相怎么逐步揭示）

- 现实、行业、史实约束

**占位符纪律**：本步只锁功能级描述（"一座没有金银的墓"），不取名字、不定刻度数值、不建建制——那些是 stage 的创作空间，为填格子编细节＝越权。

**完成标准以"改起来贵不贵"判断**：根决策全部确认即算立项引导完成；角色支线、具体数值、细部设定留白，登记待补强清单。

### 第二段·故事工坊（对文档：照确认结果组装，先主干后出奇）

#### Step 4 立王道骨架

先定线，后出三表。**定线是全书换血级的决策**——中途换日常线等于重开一本书。

**定线**：

- **主日常线一条**，定书身份。从赛道验证过的王道走法里选：打怪升级换地图（升级流）、单元剧（外壳流程固定、每单元换内容——案件、副本、委托；无限流、神医流、灵异侦探皆是）、经营扩张（种田、商战）。

- **副线一两条**，管卷级高潮或爽感：马甲流（装→藏→险被揭→将揭未揭→揭→换）、层层揭开的世界谜底；换图本身也能当副线。

- **每轮固定走法定型**：触发→冲突→小胜→代价→新钩。按赛道改措辞（神豪＝花钱→返利→升级消费清单；灵气复苏＝觉醒→修炼→势力博弈）。走法定了，几十轮内容换、骨架不换，读者追读的是"还是这个故事"。

- **日常线与伏笔线怎么咬合**，四选一：接力（前期一条、后期换一条）；一明一暗（并行）；挂钩（伏笔进度挂进日常单元，每单元推一点）；喂料（揭一层谜底，解锁一块新地图）。

**三表**：

- **爽点兑现表**：故事承诺里的每个爽点，首次兑现排在哪卷、之后什么频率（打脸每卷必有；消费奇观每两三卷一场）。**前三卷必须排上承诺的爽点**——排不上说明跑题，回 Step 2 重谈承诺。

- **换图阶梯**：从赛道自有的阶梯来（老街→城→国→天下；新手村→宗门→大陆）。换地图当主线的书，境界表是结构设定不是力量设定——阶梯不预先设计，两百万字后无图可换。

- **敌人阶梯**：由弱到强排到最终敌人，每级具体可恨、招致真实利益反扑。判死线：一根急转弯（半卷就打到最后）、结尾空降大反派，判死回炉。终点三判据在此验：终点是母题的自然终点；落差排得出梯子爬得完；终点身份回扣起点。

#### Step 5 加出奇项

出奇项（X）最后加，只加一个大的。两道测试：

- **去掉测试**：把 X 拿掉，王道主干还站得住吗？站不住＝它已经换了菜，打回。

- **驱动测试**：X 直接给王道循环供油吗（《大王饶命》负面情绪值直接驱动升级循环）？只好看不驱动的，砍。

**三毒点必验**（定金手指与主角时）：

- ✗ 任意改根规则型金手指——一出手就是终局，没得爬坡。特殊性落在偷步、加速、抗性、覆盖这一档。

- ✗ 神转世／天选当理由——双倍机械降神。特殊性必须可解释（血脉、体质、知识、经历、选择）。

- ✗ 丢记忆／丢人性／反噬伤己式主角副作用——代价由外部世界承担（被追杀、利益反扑），不从主角身上割。

#### Step 6 挂伏笔线

按轮三定的类型挂，四种挂法：

| 类型     | 挂什么                       | 长在哪         |
| :----- | :------------------------ | :---------- |
| 身份差    | 揭穿排期：几次险揭、哪卷真揭、揭后换什么身份    | 神豪、马甲、战神回归  |
| 世界谜底   | 说法清单：每条"表面说法＋真相"两行，标揭开卷次  | 灵气复苏、玄幻、克苏鲁 |
| 系统来源   | 金手指来源链：谁给的、要什么代价、升级指向什么真相 | 一切系统文       |
| 复仇对象升级 | 对手抬升链：仇人背后还有谁，逐层抬到哪       | 都市、复仇文      |

选世界谜底的说法清单规则：条数四到八条；揭的顺序从具体到根本，"我是谁""世界是什么"压最后两卷；每条材料从赛道自有的东西里长。**用词三级**：赛道现成词（末法、道统、祠堂）＞ 赛道语素造新词（承泽、除籍）＞ 禁止跨行借词（结果、信托、存档）。判据：大纲里的名词逐个问"赛道头部作品里出现过吗？"有一个不是就重造。

金手指与谜底的关系记一笔：金手指常常是谜底露在外面的一角（听得懂怪物＝母语）——定 X 时想一层"它凭什么是这个样子"，答案可以埋进伏笔线。

#### Step 7 排卷

- 全书分三到四段，段与段之间换挡（日常线换皮、伏笔线抬层）。

- 每卷一个完整小故事：卷内自带危机与解决。

- **每卷交代日常线的量与方向**：本卷日常线写什么、跑几轮、每轮比上轮大在哪（对手量级、舞台、代价各抬一级）、伏笔推进到哪条。分卷大纲只排主线事件＝卷级事件两三章跑完后正文断粮——主线给方向和终点，章节的血肉由日常线供。此项是交接 plot 的输入，plot 卷纲在此基础上展开每轮的具体事件。

- 揭说法的卷次排定：两次大揭间隔不超过三卷；场面越揭越大，事情越揭越与主角相关。

- **伏笔够用检查**：大约两卷揭一层大说法。埋的层数对照总卷数——缺额回 Step 6 补埋，不补的显式转系列钩；最后一条揭开后书还剩什么，在此验一次。

- **伏笔清单**：每条伏笔记四态——开启（埋设方式＋目标卷）、推进（新线索）、回收（回收方式与影响）、搁置（理由＋下次窗口）。健康度每卷查：悬置超三卷、超期、沉睡过久的，要么推进要么显式搁置。

#### Step 8 讲一遍

把整本书讲给朋友听：主角本来是什么人，出了什么事，遇上谁，干了什么，得到什么。**每卷一段，叙事白描**；揭说法的卷写成大转折，不是流水账。判据：拿掉标签，听的人能说出"这是本XX流的书"。

**开局情绪工程三件套落位检查**（缺了就补，补不上回 Step 4 调主干）：

- **落差三要素**：锚点（主角坠落前最高光·具体画面）→现状（坠落低谷·具体画面）→对比触发器（同场景让两者碰撞）。读者不关心陌生人被刀架脖子，只关心"从高处跌落且不该如此"的人。

- **特权信息**：至少一层"读者知道、剧中人不知道"的信息差（身份／未来／能力／视角四型选一）。

- **还小账立新标**：每卷开头先还上一卷的情绪账（反击、验证、选择），再钉一个新标（时间标、距离标、状态标）。

### 收尾

#### Step 9 六问自检

1. **防套路**：大线是欲望／建造驱动，不是危机串？
2. **防撞梗**：谜底没撞赛道写烂清单？没撞自己近三个案子？
3. **防串味**：全文名词都是赛道的话？
4. **防断粮**：日常线到四百章还有产出？
5. **防烂尾**：最后一条说法揭开之后，这本书还剩什么？
6. **防跑题**：承诺的每个爽点，前三卷排上了吗？频率对吗？

外加一问：第一卷埋的三个不对劲——金手指的怪、主角的怪癖、第一场事件——到后边都收回来了吗？

#### Step 10 定稿交接

**两道门，都过了才存档**：

- **脱稿讲述测试**：合上材料，只凭脑子把这本书讲给没读过任何材料的朋友听（200 字左右）——他能复述"主角是谁、要什么、谁挡着、怎么打、怎么赢"才算过。卡壳、只有设定没有事件、因果链断裂＝故事没成型，回故事工坊重熔。本测试在对话中实际执行，不是自查声明。

- **资料门**：逐维审"这 14 维哪几维是缺料凑的"——主参考分歧、某维主干单薄、读者雷点没查实→先派 research 补齐再定稿。

存档流程：用户逐维审→拍板→存档 `立项/00-融合立项稿14维.md`→**去AI味后半步**：`python skills/pop-snow-pipeline/scripts/deai_gate.py 立项/00-融合立项稿14维.md --profile doc --json`（WARN 定位自查，机械项 `--fix`），回复报一行 `去AI味:融合立项稿|PASS` 或 `WARN×N`。

**载体分流标签**（存档时每项标注，杜绝载体错位）：作品元数据（书名/分类/标签/简介）→头部独立块；写作行为约束（POV/每章字数/禁忌）→约束块；故事事实（人设/世界观/谜底）→对应维，不进写作规则。

向用户报告交接："融合立项稿已定，接下来交 stage 实名与长档，再由 plot 排卷。"加载 pop-snow-stage 接力。
