# pop-snow-seed

> 统一管线立项——按六步流水线共创《融合立项稿 14 维》：**问诉求 → 定调研清单（用户确认）→ 调研 → 归集取材·卖点源 → 融合 → 定稿交接**。融合稿是全书宪法骨架层：每维锁骨架不画死，stage 补世界血肉、plot 排每卷剧情，各自长成大档。每步用户拍板、串行定稿（无真人时走 agent 自定态）。当前版本 v4.5.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

### 心智前置·意识层（贯穿本 skill 与全流程）

动笔/定稿前自问：本产出要更好，还需要看过哪些候选？当前信息够不够？有更优选项没探索？

- **Know-Gap**：先显式列出"要更好需见过哪些候选面"，再列已覆盖，缺口=差值；缺口≥1 个未覆盖维度才触发取材，缺了取、别硬写。
- **Pack**：缺口足够才取材，query 自生成；来源 **wiki 站 https://wiki.popwave.cn** 居先、网络补齐；单环节 ≤1 轮 / ≤5 query / 回传 ≤30KB，超限截断仅留结论区。
- **Worth**：拿本 skill 决策尺对"现有 vs 候选"必给打分表，禁止一句"更优"带过；只端候选/升级版，不越权定终局。
- **Deepen**：产出/候选后自问"这是天花板吗？有更优候选吗？"显著更优才升级再问，上限 2 轮。

取材仅进上下文，升级被采纳才落产出。

## 做什么

**seed 的核心职责 = 把用户的诉求＋参考＋调研，融合成一份 14 维骨架层立项稿。** 核心思想（终点优先，思考纪律）：**先设想终点（终点给读者什么补偿、主角图什么），终点把故事锁一大半；其余全部为终点服务。** 终点锁定后，世界、人物、剧情在 14 维骨架里融合成型——不是"逐层创造"，是"一次想透、分层归位"。

| 步骤 | 干什么 | 产出 |
|:--|:--|:--|
| **1 问诉求** | 收拢用户方向，锁硬要素（终点三件套＋主参考＋大灾变＋主角力量） | 硬要素清单（进上下文） |
| **2 定调研清单** | 从诉求推出"要更好需看过哪些候选面"，列清单给用户确认增删 | 调研清单（确认后生效） |
| **3 调研** | Wiki＋外部并重执行清单；信息源分级；聚焦调研纪律 | 调研结论（进上下文） |
| **4 归集取材·卖点源** | 每个参考/调研源一张料卡：消化五件套＋按14维归集 | 取材·卖点源卡组 |
| **5 融合** | 14 维逐维融合：要什么／取材比对／融合后三件套 | 融合立项稿草案 |
| **6 定稿交接** | 用户逐维审→拍板→落盘，交接 stage/plot | `立项/00-融合立项稿14维.md` |

**称谓约定（不混叫）**：「取材·卖点源」=输入侧料卡（一源一卡）；「融合立项稿」=输出侧定稿卖点（14 维融合产物）。

**共创原则（立身之本）**：每步都是"agent 出草案 → 用户拍板 → 改 → 再拍"的来回拉锯。**用户拍板是每步的唯一关卡**——审美判断（动不动人/好不好看/逻辑密不密）在源头被人的判断接住，不在下游被规则拦截。

**下游对接**：融合稿 14 维=全书宪法骨架。stage 消费世界观组 1-4＋人物组 5-7 长成长档；plot 消费剧情组 8-11 排卷进度表与卷纲；outline/write 接力正文。

## 执行模式

**主 agent 直执，禁用子agent代跑共创。** seed 是全链路交互最密集的环节——每步都要和用户对话、拍板、修改，这些共创对话必须由主 agent 亲自进行，不得派发给子agent。

**唯一例外**：纯只读的调研支撑（扫榜/拆书包内容检索/参考材料消化）可派子agent回报原始材料，主agent消费。但凡涉及"出草案给用户看、听用户意见、改稿"的环节，一律主agent。

**共创三态（决定每步走哪套拍板）**：

1. **共创态**（默认）：用户在场，每步端候选给用户圈定 → 拍板定稿。这是 skill 的主设计。
2. **代理自定态**（无真人/自动化/评估环境）：用户不在场或明确"你全权定"。agent 以 `agent 自定` 模式逐层自拍板：每层自出最优草案、自审自拍，全程串行推进。拍板结果在「用户拍板」栏显式标注 `[](agent自定·{原因})`，共创记录用户意见栏同样标注，禁止伪造"用户说过"。
3. **共创→自定降级**：共创进行中用户中途离开——已拍层保持用户意见，未拍层降为 agent 自定继续，降级时刻写进共创记录。
   所有产出物头部「共创状态」按三态如实标注：已定稿（用户拍板于·共创态）/ 已定稿（agent 自定·{原因}）。

execution.mode：formal（落盘定稿）/ draft（共创中，未拍板）。

## 怎么操作（SOP全内联）

### Step 1：问诉求（终点优先，锁硬要素）

收拢三样：①用户的赛道方向/情绪诉求；②用户给的参考（书/IP/游戏）；③已知硬约束。然后锁**硬要素**——一旦拍板，融合阶段不许漂移：

- **终点三件套**（终点优先的心脏）：
  - **最终敌人**：具体可恨的对象，能列出一排爪牙（不是抽象制度）
  - **终点状态**：主角最终把世界变成什么样，终点给读者什么补偿
  - **主角图什么**：驱动欲望。套别参考：改变型（危机→变强整顿世界）/经营扩张型（一亩三分地立成王）/情感执念型（守人/弥补/讨口气），套2/套3 可叠进套1
- **主参考**（用户点名=优先级最高）

**收「主参考」时先把本地现成文风档端给用户点选**（不是先问"给本王牌/书"）：主 agent 先读 `pop-snow-write/references/文风兜底/` 目录列出**23 个现成档**（西幻·玄幻史诗/西幻·dnd战斗/西幻·诡秘克苏鲁/都市·商战/都市·异能/都市·直播/仙侠·正统修仙/仙侠·争霸史诗/仙侠·家族群像/仙侠·系统流/仙侠·诸天/悬疑·诡异/灵异·民俗怪谈/灵异·规则怪谈/灵异·恐怖经营/女频·古言虐恋/女频·宫斗宅斗/女频·甜宠/女频·网游竞技/女频·网游萌宠/都市·凡尘修仙/都市·日常/城市·商战…），按用户赛道先筛出 2-4 个**同赛道候选**，让用户直接勾一个当「文风味」主档。用户点中 → 该档进 `03 文风味` 维＋Step 3 本地命中跳过蒸馏。**用户若点的是本地已存在档名，绝不再外搜/蒸馏，直接用原位档**。
- **大灾变/核心冲突**（全书底色与主线引信）
- **主角力量方向**（走哪条力量线）

**终点三判据**（锁"终点定多高"的尺）：

1. **与母题/赛道的匹配烈度**：终点是母题内在逻辑的自然终点（登神文→神位；克苏鲁→看清深渊并超脱），不是随手安"世界最强"。
2. **落差可兑现（波浪式上升）**：起点到终点能排出一条**由弱到强的敌人阶梯**一格一格爬完。一根急转弯（半卷就打到最后）→ 判死回炉。
3. **头尾呼应**：终点的"身份/位置"回扣起点与最大反转。

**依赖分层提问（镜界11-A2 吸收）**：收诉求时不抛整张清单，按依赖顺序**分层问、一轮 2-3 题**——①**根决策先行**（题材/目标读者/故事承诺），它决定后续问题定制（男频玄幻→第三人称单 POV＋4-5 千字；悬疑→严格信息边界），先定方向再问细节，不"先铺零碎后定方向"；②**会进书名的结构项**（书名雏形/主参考/篇幅量级）——全书门面与骨架；③**元数据＋写作行为约束**（分类/标签/章节字数/禁忌）——落地前收尾约束。每轮给 2-4 个 options 且至少一个标推荐，"你来定"时先给建议请求确认，**新旧冲突直接指出让用户选，不平均处理**。

**三毒点排除（定终点/主角时必验）**：

- ✗ **禁"任意改根规则"型金手指**：一出手就是终局，没得爬坡。特殊性必须落在系统内偷步/加速成长/抗性/覆盖这一档。
- ✗ **禁"神转世/天选"当理由**：双倍机械降神。特殊性来源必须可解释、符合世界内在逻辑（血脉/体质/知识/经历/选择）。
- ✗ **禁丢记忆/丢人性/反噬伤己式主角副作用**：代价应由外部世界承担（被追杀/利益反扑），不从主角身上割。

**共创流程**：agent 出 1-3 个终点候选（各带三件套＋三判据判定＋三毒点排除）→ 用户选/改/拍板。**终点没拍板，不进 Step 2。**

### Step 2：定调研清单（用户确认，不确认不调研）

从诉求＋参考反推（Know-Gap）：要更好，需要见过哪些候选面？列**调研清单**——每条=一个待查证的问题面（例："战锤灰骑士的真实建制与隶属""DND 神力分级的原始刻度""该赛道近两年头部作品与读者雷点"）。

**清单必须先经用户确认增删再执行**——调研从来不是可选项，但查什么由用户拍板。

### Step 3：调研执行（Wiki＋外部并重）

按确认后的清单执行。检索顺序固定：

0. **先查本地资产后端（最新增）**：主参考若命中 **write 的文风兜底库 23 档之一**（路径 `pop-snow-write/references/文风兜底/{赛道}·{风味}.md`，即用户默认会点的那批：西幻·玄幻史诗/西幻·诡秘克苏鲁/都市·商战/仙侠·正统修仙…）→**该参考已是成品纯样文 DNA，跳过 Web/wiki 文风蒸馏调研**，直接作为 14 维「文风味」维的一手输入，回源标 `references/文风兜底/{档名}`＋源书。**绝不把本地已有档名误当"需外搜蒸馏的书名"**——本地有现成的就别再造一份。
1. **再查 wiki 站** `https://wiki.popwave.cn`——卖点方向库（母题卡：五类谱系＋融合方式＋判据）、`写作灵感/{赛道}/{书名}/seed-*` 卡（参考书反推的骨架）。命中→直接引用并标注来源。
2. **未命中或深度不够→web 调研**（WebSearch/WebFetch）。
3. 产出中 wiki 命中部分与 web 新调研部分**分区标注**，下游知道哪些是库内已验证资产。

**信息源优先级**：自有 wiki → 官方资料/SRD → 百度百科·维基百科 → 垂直百科 → 社区讨论（降权，标"非官方、立项自取"）。

**聚焦调研纪律**（每个查实项）：先定用途→拆成模块清单→每条标可回源＋三级可信度→查不到就明说绝不编造→限结论区字数。纯只读调研可派子agent回报，主agent消费。

> ⚠️ wiki 踩坑两条（实测补录）：
> ① wiki 赛道目录名**全小写无分隔符折叠**（实测 `写作灵感/西幻dnd/`，大写直接 404）——拿不准先试小写；
> ② `写作灵感/{赛道}/` 裸目录不可枚举，发现参考书的可靠入口=「卖点方向库」页脚链接 / 知名书种子卡直连；某赛道无 seed-* 卡=拆书数据未迁移，走"裸原创＋方向库做实"并在共创记录注明。

### Step 4：归集取材·卖点源（一源一卡）

每个参考/调研源产出一张料卡（模板 `templates/取材-卖点源-14维.tpl.md`）：

- **消化五件套**：终点形态／危机／敌人谱系／主角特殊性／结构节奏——参考不是"看过"，是"拆出能用的骨架"，说不出来=没消化。
- **按 14 维归集**：该源在哪些维给了可用骨架，有则填、无则空——不许编。
- **可回源标注**：关键复用点出处（URL/书名＋锚点）；查不到的明说。

### Step 5：融合（14 维三件套）

按 `templates/融合立项稿-14维.tpl.md` 逐维融合，每维三件套：

- **要什么**：这一维给读者什么（终点的容器/代入感/爽点来源）。
- **取材比对**：各源分别给什么骨架（一眼看出谁贡献了什么）。
- **融合后（简略骨架）**：锁骨架不画死——力量体系到"梯度怎么爬"为止不写死数值与命名；剧情到"前中后期"不拆卷；给 stage/plot 留发挥余地。

结构性纪律：

- **头部**：一句话卖点（0.3 秒）＋硬要素锁定（Step 1 拍板项置顶，融合不许漂移）＋语感隔离声明（write 消费必读：本稿是剧情结构语言不是正文语感）。
- **世界观组回扣终点**：A1-A4 每维回扣终点三件套——世界形态是终点需要的容器，不是随便设背景；敌梯（第 7 维）从起点到终点的落差反排。
- **四钉**：剧情组头部先钉起点/终点/最大反转（标落卷）/最大落差四钉，剧情组围绕四钉长。
- **剧情组强纪律**：先 8 故事大概 → 9 剧情线＋10 成长曲线 → 最后 11 前中后期（含篇幅规模）。每卷具体剧情归 plot。
- **附录A·机制溯源（零自创）**：每条机制/设定标"出自哪张取材·卖点源"，可回源。
- **附录B·待补强清单**：具体缺口点名（主角出身命名/组织建制/具体克制关系…），交给 stage/plot 前必须补齐或显式移交。

### Step 6：定稿交接

**Step 6 定稿前先过资料门**：逐维审前自问"这 14 维的骨架，哪几维是缺料凑的？"——主参考/卖点的分歧、某维骨架单薄、读者雷点/赛道头名书没查实→**先派 research 补齐（落 `素材/采风/`、来源可回源）再定稿**。资料门过了才走下方落盘：

用户逐维审 → 拍板 → 落盘 `立项/00-融合立项稿14维.md`。**落盘后半步=消毒**：`python skills/pop-snow-pipeline/scripts/deai_gate.py 立项/00-融合立项稿14维.md --profile doc --json`——WARN 定位自查（装腔换大白话，行话放行；工程标签如刻度/锚点名不查）、机械项 `--fix` 原地修，回复报一行 `消毒:融合立项稿|PASS` 或 `WARN×N`。向用户报告："融合立项稿已定，接下来交 stage 长长档（世界/人物），再由 plot 排卷进度表与卷纲。"加载 pop-snow-stage 接力。

**载体分流三分类（镜界11-A1 吸收，定稿落盘时给每项标载体标签）**：融合稿每处产出在落盘时标注它属哪一类，杜绝"把故事事实写成写作规则"这类载体错位——

| 载体 | 装什么 | 落到 |
|:--|:--|:--|
| **作品元数据** | 书名/分类/标签/简介/篇幅量级 | 立项稿头部独立块（这是"这本是什么书"） |
| **写作行为约束** | 第三人称单POV/每章字数/反降智/章末钩/禁忌 | 立项稿"写作行为约束"块（可执行可复用，一条管一维） |
| **故事事实** | 人设/世界观/力量体系/势力格局/谜题真相 | 各对应维（14维骨架），**不进写作规则** |

**完成标准 ＝ 改起来贵不贵（镜界11-A3 吸收）**：立项**止于"全书稳定、后期难改的基础决策已确认并沉淀"即算完成**——终点三件套/主参考/大灾变/主角力量/篇幅分卷这些"改起来贵"的定了✅，**角色势力支线、具体数值、细部设定属"可渐进"直接留白**（留白项显式登记待补强清单），不为追求"一次成稿/完整"拖长立项——防立项通胀。

> **seed 止于骨架**：分卷走向／卷进度表／数值刻度／角色库等工程级展开归 plot/stage，不回 seed。

## 红线

1. **调研强制**：清单先经用户确认增删再执行；Wiki 与外部并重，不许只翻内部或只搜外网。
2. **终点优先**：硬要素（尤其终点三件套）没拍板，不进调研不进融合；先想冲突/卖点再回头贴终点=两张皮。
3. **称谓不混**：取材·卖点源=输入料卡，融合立项稿=输出定稿，不许混叫。
4. **锁骨架不画死**：每维给 stage/plot 留发挥余地；不写数值细节、不排卷、不建角色库。
5. **机制溯源零自创**：附录逐条标源；查不到就明说，绝不编造（勘误："深渊主宰=小数化数值"是错误记载，实际是整数大数字面板）。
6. **三毒点红线**：定终点/主角必验（见 Step 1）；代价由外部世界承担，不从主角身上割。
7. **波浪式上升**：敌人阶梯（第 7 维）必须由弱到强、每级具体可恨、招致真实利益反扑；一根急转弯/半卷打最终BOSS/结尾空降大反派=判死回炉。
8. **每步串行，用户拍板**：不定稿不进下一步；禁止一口气全出完丢给用户。
9. **共创对话主 agent 直执**：出草案/听意见/改稿一律主agent；仅纯只读调研支撑可派子agent。
