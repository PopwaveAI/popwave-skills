# pop-snow-seed

> 本技能只做一件事：开书前，用少量确认加工具产出，定下一本什么样的书，产出一份讲得清的故事 brief，并给一章试写样张。
> 不规定题材、结构、风格、桥段或审美偏好。故事由用户决定；用户没决定的，由 agent 出候选，交用户选。
> 当前版本 v8.3.0。

---

## 本技能负责什么

输入：用户的一句话、一个角色、一个场面、一段设定，或者什么都没有。

输出三件：

- `立项/故事.md`：四段——世界背景、主角特性、主线、终点。
- `立项/第0章试写.md`：一章样张，让用户看到"这本书写出来是什么感觉"。
- `立项/brief候选.md`：候选全文，供用户挑选。

**边界**：

- 不出 14 维、不取名、不定数值、不建组织制度——世界与人物长档归 `pop-snow-stage`。
- 不拆卷、不排章、不写卷纲——归 `pop-snow-outline`。
- 不写正式正文——归 `pop-snow-write`。本技能只用 `popwave-write-body` 写一章样张，样张不进 `正文/`。
- 不做拆书——归 `pop-decon`。

## 故事 brief 是什么

brief 是一本书的四段复述，不是参数表。

- 是「这本书讲了个什么故事」，不是「这本书有哪些设定」。
- 是给人看的故事，不是给机器读的字段。
- 一段一义，每段 2-6 句，读完能记住。

**四段固定**：

| 段 | 写什么 | 判断锚点 |
|:--|:--|:--|
| 世界背景 | 什么时候、什么地方、正在发生什么变局 | 读者能说出这个世界逼人做什么 |
| 主角特性 | 他是谁，凭什么是主角 | 答的是「为什么非他不可」，不是「他有什么能力」 |
| 主线 | 他要做什么，一路做什么 | 至少三步，每步有前因 |
| 终点 | 故事停在哪，他成了什么，世界成了什么 | 能从终点反推出前三段为什么长这样 |

**合格判据（四条，缺一条即未完成）**：

1. 四段齐全。
2. 四段能连成一条因果链，从上往下读得通：因为世界这样，所以非他不可；因为他要这个，所以做这些事；因为一路做这些，所以落到这个终点。
3. 「主角特性」回答的是「为什么非他不可」，不是「他手里有什么」。
4. 合上材料，用 150 字讲给没听过的人，对方能复述这本书是讲什么的。

**正例（四段齐全，一条链读得通）**：

> 末法之世，厉诡复苏，人间已是绝路。（世界背景）
> 主角苏午激活「完美人生模拟器」，可以模拟尚未发生的未来，并抽卡各种神奇天赋，从一次次必死的结局里找到活下来的生路。（主角特性）
> 他在现实与历史、神话的缝隙间游走——密藏域的经咒与供物、灶神教炼油称米油炸诡的手艺，还有更多已断的传承——寻找变强与根治厉诡复苏的办法。（主线）
> 最终证得太上，使天下无诡。（终点）

它成立在四点上：世界把人逼到绝路；主角的装置让「必死」变成可重来的循环，所以他非动不可；主线每一步都在给他「活下去」添一分；终点落在开局那句「人间已是绝路」的反面。

**反例（四段缺三段）**：

> 夜班调度员周叙用通话诱杀诡异，代价是五感逐种剥夺。

这句只有主角特性加代价。没有世界逼他动、没有他一路做什么、没有终点落在哪。这一类不是 brief，是一句设定梗。

**主角变强、使用异能，不挂代价**：

- 不写反噬伤身、用一次少一次、丢记忆、丢人性、五感逐种剥夺。读者有损失厌恶，主角每损失一样，爽感就被抵掉一分。
- 压迫感从世界背景给：世界本身在收缩、敌人量级压着、时间与资源有限、退路被堵。压力来自外面，不从主角身上割。
- 「代价」不是不能用，是不许当爽点的配套。用户明确要求写代价时按用户要求写，并在 brief 的交接段标「用户指定」。

**思考顺序与呈现顺序相反**：

- 呈现顺序：世界 → 主角 → 主线 → 终点。读的人从处境读到结果。
- 思考顺序：终点 → 主角 → 主线 → 世界。写的人先定落在哪，再反推谁走到那、怎么走、从什么样的处境出发。
- 终点定不下来，先给两个不同终点让用户选。终点没定就铺世界，容易写出一堆漂亮但没处落的设定。

## 流程

> **只在前三步问人**：赛道、标签组合、篇幅，用 Ask 组件确认；一题最多 4 个选项，用户可选「其他」自己写。确认完不再盘问剧情，直接出试写样张与 brief 候选。

### Step 0 接住用户手上已有的

1. 逐字收下用户本轮原话，不摘要、不改写。
2. 拆出已有元素：赛道、标签、主角、场面、终点、感觉、对标书。
3. 读项目已有资产：旧立项稿、旧大纲、拆书成果、文风档、历史正文。已确认的不重问。

收完直接问第一步，不播报流程，不说「你手上已有 X 缺 Y」这类话。

### Step 1 确认大赛道

读 `references/番茄标签库.md`，从男频与女频主分类里挑 4 个大方向，用 Ask 问他。例：

- 男频 · 玄幻仙侠
- 男频 · 都市异能
- 女频 · 古言宅斗
- 女频 · 现言都市

他要的不在这四个里，用「其他」直接写。他自己报了赛道，直接采用，不再确认。

### Step 2 确认标签与元素组合

按赛道从标签库里挑 2-3 个「主分类 ＋ 主题 ＋ 情节」组合，用 Ask 问他。例：

- 悬疑灵异 ＋ 民俗 ＋ 都市高武
- 都市异能 ＋ 系统 ＋ 诡异
- 悬疑灵异 ＋ 灵气复苏 ＋ 升级流

每个组合附一本 library 里真实存在的同标签书；查不到就不附，不编书名。

**同一次 Ask 里加问一句：有没有对标书**

> - 有，我 @library/书名
> - 没有，按上面的组合帮我挑
> - 不看对标，直接往下走

**用户点了书**：读那本，只取与本次立项相关的原文——开局处境、主角怎么被逼动、主线怎么推进、停在哪。不只读摘要。

**用户没点**：按组合从 library 找 2-3 本有真实成绩的，列出来让他挑 1-2 本；他不挑，取最贴的 1-2 本直接对照。library 没覆盖，退到 `参考小说txt/`；再没有，联网查公开梗概。

**每本出一张对照卡**：

- 像在哪：世界、主角处境、主线形态、终点，逐项对。
- 差在哪：同一元素上这本书怎么做，用户想做的不一样在哪。
- 可借什么：结构、开局处境、敌人量级。只借结构，不借专名。
- 别学什么：这本书被读者骂的地方。

有 1 本就够对照。一本都没有，写「无对标」，照常往下走。

### Step 3 确认篇幅

用 Ask 问，三档：

- 30 万字上下：单主线，收得快。
- 80-150 万字：常规连载。
- 200 万字以上：长线，中途要换图。

篇幅决定主线能走几步、终点能落多高。他说不清，按赛道常见量级给建议，仍由他定。确认后不再改。

**context 传正文，不传文件名**：调用工具前先把要传的文档整份读入，原文放进 `context`。不得只写路径，不得把段落压成要点。`context` 上限约 13 万字节，超出时按优先级取舍：用户原话 ＞ 试写样张 ＞ 对标原文。

### Step 4 第 0 章试写（工具：`popwave-write-body`）

目的：让用户直接读到这本书写出来是什么感觉，兼作 onboarding。第 0 章不在正文章序里，不是本书真实剧情。

- `brief`：按已确认的赛道、标签、篇幅，写第 0 章样张。开篇三句内交代具体的人、具体的处境、一个不对劲的信号；本章有一个完整的小冲突并收束；章末留下必须翻页的钩子；不解释设定、不写背景综述。
- `context`：用户原话（逐字）、对标书开局原文（整段）、赛道／标签／篇幅。
- `constraints`：2000-2500 汉字；视角与文风照对标；人物名与专名可临时起，统一标「试写临时名」；不写章标题以外的说明文字。

**惊艳与抓人的判据（三条，缺一条重写）**：

1. 前三句里出现具体的人、具体的麻烦、一个不对劲的信号。
2. 本章有一个明确的压力，并在章末兑现或升级。
3. 读完想翻下一章。

**调子不对时只改开头**：先重写开头 600 字让用户确认调子，调子对了再续完全章，不整章重跑。仍不对，问他要什么感觉，照他说的写进 `constraints`。

落盘 `立项/第0章试写.md`，文件头三行固定：

```
> 试写稿：不作为本书真实剧情，不进正文。
> 人物名与设定为临时，正式以 pop-snow-stage 的设定为准。
> 写作日期：
```

**不写**：章纲、后续剧情；不把试写稿当剧情事实引用。用户明确说不看试写，可跳过本步，并在故事核交接段记「第 0 章试写：跳过」。

### Step 5 出 brief 候选（工具：`popwave-write-idea`）

调 `popwave-write-idea` 出 2-3 个 brief 候选，每个四段齐全。

- `brief`：给 2-3 个故事 brief 候选，每个写清世界背景、主角特性（为什么非他不可）、主线（至少三步）、终点。候选之间换世界、换主角位置或换终点。
- `context`：用户原话（逐字）、赛道／标签／篇幅、第 0 章试写全文、对标对照结论原文。
- `constraints`：四段齐全；四段能连成一条因果链；主角变强与用异能不挂代价，压迫感由世界给；不写第一章细节与设定机制；每份不超过 300 字。

拿到稿子后 agent 只做三件事：删配方词（金手指、爽点名、敌人阶梯等专名）、补齐四段标题、给每份补一句「读者会是谁」。不另写一份替代工具产出。

**候选必须先落文档**：把每个候选的四段全文写入 `立项/brief候选.md`，一个候选一节。不要只贴在对话里。

**再用 Ask 让用户选**：Ask 的选项只写「候选一／二／三 ＋ 一句核心（15 字内）」，提问前告知「三个候选的全文已写入 `立项/brief候选.md`，可先读再选」。选项文本放不下完整故事，不要试图塞进去。

**候选之间必须真的不同**：换了世界、换了主角位置、或换了终点，才算另一个。只换措辞不算。讲不出差异时减到两个，不凑数。

### Step 6 用户选与定稿

1. 用 Ask 把候选摆给他挑；他说「A 的世界加 B 的终点」，合成第三版，先写进 `立项/brief候选.md` 再确认。
2. 跑四条合格判据。任一不过，回 Step 5 重出一份，不在文字上糊过去。
3. 脱稿复述：合上材料，150 字讲清这本书。讲不清回 Step 5。
4. 写入 `立项/故事.md`，骨架固定为：

```markdown
# 故事brief
书名（暂定）：
赛道 / 标签：
篇幅：
共创状态：（用户拍板 / agent 代拟，写原因）

## 世界背景

## 主角特性

## 主线

## 终点

## 第0章试写
见 `立项/第0章试写.md`（样张，非正式剧情）

## 对标与参照
（每本一行：书名 / 像在哪 / 差在哪 / 可借什么 / 别学什么）

## 待定

## 用户原话
```

5. 告知用户下一步：建立世界与人物，进入 `pop-snow-stage`；进行分卷规划，进入 `pop-snow-outline`。下游需要更细的字段时，各自从故事核展开，seed 不再补 14 维。

### Step 7 交接

在 brief 末尾写交接段：

- 已锁定项：用户拍过板、后面不许改的。
- 待定项：明确留白，交给下游或用户后续决定。
- 用户原话：不可改写的句子，原样保留。

下游只读 brief，不读本技能。

**两条边界**：

- 不向用户追问第一章细节：他为什么在这一夜出现、第一场怎么打、第一句说什么，由第 0 章样张来回答，成稿归 `pop-snow-outline` 与 `pop-snow-write`。
- 不往设定里追：井里镇着什么、力量体系怎么分级、敌人分几层、专名与数值，归 `pop-snow-stage`。用户主动讲就记下，不追问。
