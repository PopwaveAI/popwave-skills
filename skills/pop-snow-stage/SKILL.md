# pop-snow-stage

> 本技能只规定舞台环节的流程、文件契约与检查项，不规定题材、力量体系形态、人物原型、命名风格或审美偏好。
> 世界与角色内容由用户决定；用户没决定的，由模型按立项稿和调研结果提出候选，交用户确认。
> 当前版本 v3.0.0。

---

## 职责范围

stage 把 seed 立项稿的**世界观组（1-4）与人物组（5-7）**长成可落笔的长档。剧情归 plot，表达归 write。

**14 维与长档的对应**：

| seed 维 | 长档 |
|:--|:--|
| 1 世界形态 | `设计库/世界画像.md` |
| 2 力量体系 | `设计库/世界法则.md`、`设计库/位阶-社会坐标谱.md` |
| 3 势力格局 | `设计库/世界格局.md` |
| 4 基调/母题 | `设计库/基调母题.md` |
| 5 主角（含金手指） | `人物库/主角.md` |
| 6 主角团/配角 | `人物库/角色库.md` |
| 7 反派/敌人 | `人物库/角色库.md` |
| 用户指定文风时 | `文风dna/类型风味基线.md` |

**两种模式**：

| 模式 | 触发 | 工作内容 |
|:--|:--|:--|
| 首喷 | 无 `设计库/世界法则.md` | 读取立项稿，长当前要开写的那批 |
| 卷级点播 | plot 提交卷需求 brief 与舞台点播清单 | 点哪块长哪块，回填对应长档 |

**执行**：主 agent 直接执行。用户在场时给候选让用户选；用户不在场时由 agent 决定，并在档头标"agent 代拟"。

## 流程

### Step 0 输入加载

1. 读 `立项/00-融合立项稿14维.md` 全文。
2. 盘点已有长档、旧正文、拆书成果。
3. 读附录里的资料来源与待补清单。

### Step 1 列缺口

按本次要长的档，列出缺什么：

- 立项稿没写清的世界规则
- 需要真实资料支撑的组织、职业、地理、行业
- 用户点名要补的设定

缺料先派 `pop-snow-research` 查，查不到就写"待补"，不编。

### Step 2 世界类长档

按顺序写：

1. `设计库/世界画像.md`：地理格局、时代质感、运作逻辑、各区域有什么可写的东西。
2. `设计库/世界法则.md`：能力或规则的运作方式、上限、限制、使用条件。
3. `设计库/位阶-社会坐标谱.md`：有明确等级体系时写；没有就跳过。
4. `设计库/世界格局.md`：有哪些势力、谁掌握什么资源、谁和谁对抗、主角在哪。
5. `设计库/基调母题.md`：用户要的整体气质与一句话母题。

只写立项稿已有的方向；需要新增方向时，回 seed 或问用户。

### Step 3 人物长档

1. `人物库/主角.md`：出身、能力、性格、目标、恐惧、成长线、说话方式。
2. `人物库/角色库.md`：主角团、关键配角、反派。每人写清：要什么、怎么做事、和主角什么关系、什么时候出场。

人物名由用户定；用户不定时，模型给候选，用户确认后写入。

### Step 4 文风基线（仅用户要求时）

用户指定文风或要求统一命名时，写 `文风dna/类型风味基线.md`：

- 用户指定的腔调、视角、命名习惯
- 本书自建的专名表
- 需要回避的词或写法（用户指定才写）

用户没要求，不建此档。

### Step 5 完整性与一致性检查

1. 每个长档是否都能在立项稿里找到对应方向。
2. 力量、势力、人物之间有没有互相矛盾。
3. 数值、等级、时间线是否前后一致。
4. 查不到的、未确认的，是否都标了"待补"。
5. 用户确认的内容与 agent 代拟的内容，是否分开标注。

不做审美评分，不要求"必须有代价""必须有弱点""必须有原型"。

### Step 6 交接

向用户报告本次长了哪些档，然后交接 `pop-snow-plot`。
