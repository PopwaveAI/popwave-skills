# pop-snow-write

> 正文写作 + 收尾检查（字数、结构、去 AI 味）+ 一行章日志。三种模式：写正文／改稿／审稿。
> 当前版本 v8.1.1。

## 何时用

用户要写这一章、续写、改稿、或让审一章。

## 模式一：写正文

### Step 1 读输入 `[主]`

- 本章章纲（有就读，没有读上一章末 800 字与卷纲全文）
- 出场人物卡（整份读入）
- 世界底线三条（`设定/世界观.md` 规则底座的原文）
- 文风：用户当次指定 > `设定/世界画风.md` > 沿用上一章口吻

### Step 2 写 `[工具:body]`

一次调用写完一章，按下方注入清单传参。工具产出原样落盘到 `正文/ch{NNN}.md`，不压缩、不重写、不换稿。

### Step 3 收尾 `[主]`，不调模型

按顺序做四件事：

1. **字数**：纯汉字 2000–2500。在项目根执行下面这行统计，不足在既有事件内补细节，超了删最弱场景，不灌水。

   ```bash
   node -e "const s=require('fs').readFileSync(process.argv[1],'utf8');console.log((s.match(/[\u4e00-\u9fff]/g)||[]).length)" 正文/ch001.md
   ```

2. **结构三查**：前后因果接得上；同一细节不重复描写；细节之间不矛盾（时间、数量、距离）。
3. **去 AI 味**（只改标点、分段与人名引号，不改情节、不重写句子）：
   - 半角与全角标点混用、成对标点不闭合、连续两个以上同类标点
   - 相邻两段用同一个开头或同一句式
   - 连续三个叙事段都不足 20 字（段落过碎）
   - 单段超过 400 字（没有换气）
   - **人名加直角引号**：主角、主要反派、关键配角的名字，以及正文里使用的绰号与称呼，每一处出现都包上 `「」`；只许插入 `「」` 两个字符，其余文字一个字不动。名单先从 `人物/人物卡.md` 取全（正式名＋绰号），再逐处加。已经包着的、引号里重复的不再加；人称代词不加。
   - **书名号只给书名、篇章名、典籍名用**，不拿来包人名。

   本项完成后自检一次：把正文里主角与重要角色的名字出现次数，和 `「」` 包裹次数对齐；对不上就是漏加，返工补齐。
4. **章日志**：写 `日志/ch{NNN}.md`，五行：谁、在哪、发生了什么、留下什么钩子、字数。无章纲时加一行「无章纲」。老项目已有 `剧情日志/` 时写到那里，不另建 `日志/`。

## 模式二：改稿

用户说「改」「重写这段」「不满意」时：

- 只改用户点名的部分，其余不动。
- 改前把原稿另存 `正文/ch{NNN}-v1.md`，不覆盖。
- 改完仍跑 Step 3 的四项检查。

## 模式三：审稿

用户只让审、不让改时：

- 读正文，按「结构三查 + 去 AI 味五项」逐条检查（含人名 `「」` 是否加齐）。
- 再对照人物卡与 `设定/世界观.md` 的规则底座，找行为不符与规则冲突。
- 输出「位置 + 问题 + 最小改法」，不改剧情、不重写正文。

## 给 body 的注入清单（缺一不调）

**context 传正文，不传文件名**：调用前先用 Read 把下列材料整份读入，原文放进 `context`。不得只写文件路径，不得把人物卡或设定压成要点。`context` 上限约 13 万字节，超出时按优先级取舍：本章章纲 ＞ 上一章末原文 ＞ 出场人物卡 ＞ 世界底线与文风。

- `brief`：写第 N 章，目标字数区间。
- `context`：
  - 本章章纲全文（无则写「无章纲，按上一章末与卷纲续写」，并附卷纲全文）
  - 出场人物卡全文（只传出场的那几张，不传全书人物库）；另附全书主角、主要反派、关键配角的姓名与绰号清单（去 AI 味加 `「」` 用）
  - 上一章末 800 字原文（逐字，不改写）
  - `设定/世界观.md` 规则底座的原文（三条）
  - `设定/世界画风.md` 中世界质感、调子与关键词、禁用词表三节的原文
  - 文风要求（用户原话优先）
- `constraints`：字数区间、视角、必须发生／必须避免、禁区。

## 红线

1. 不覆盖已有正文；要改先确认并另存版本。
2. 不改章纲、不改人物设定；写作中发现冲突，记一行「冲突」交用户。
3. 不新增设定；新出现的事实写进章日志「新事实」一行。
4. 字数不达标不交付；去 AI 味只动标点、分段与 `「」`，不改字词与句子内容。

## 交付提醒

本次任务只要产出了文档（brief、故事核、试写章、设定、人物卡、章纲、正文、审核报告等），交付回复必须写清产出了哪几份、各自路径，并提醒用户可点开右侧文件夹按钮预览详细内容；没有文档产出就不写这段。
