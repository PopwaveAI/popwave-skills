# pop-visual-art-bible

> Art Bible · 美术设定集。L1 基建层「产出美术设定集」的引擎。v2.2.0

## 做什么

输入：`pop-visual-asset`（查原文：角色档案/场景资产表/视觉符号库/IP视觉DNA/势力档案/地理档案/规则档案）+ `pop-visual-style`（定画风：画风DNA/画风决策/定标图）。
输出：**美术设定集** `素材/美术设定集.md`（八篇合一）——全 IP 宇宙视觉的唯一真源，**文+图**。

**核心价值**：把原 `character` skill 从"只设计人物身份"升级为"产出整部美术设定集"。原体系下画风归 style、人物归 character、场景和符号散在 asset，**没有统一 owner 裁决"这个 IP 宇宙看起来整体是什么样"**，三处各画各的必然漂移。本 skill 是那个权威 owner——它消费三个引擎的产出，翻译成统一的美术设定集，做跨实体一致性仲裁，冻结为派生层唯一消费的真源。

**一句话定位**：`asset` 负责"**原文里有什么**"（查），`style` 负责"**用什么画**"（画风），`art-bible` 负责"**这个宇宙看起来怎样**"（设定集，唯一真源）。

> **世界观推广素材同样归此**：势力卡/地理卡/规则卡等推广素材的视觉真源，由势力篇/地理篇/规则篇统一裁定，oc 只消费不再重建。

## 与 L1 引擎的关系

| L1 引擎 | 提供什么 | 本 skill 消费方式 |
|:-----|:--------|:-------|
| `pop-visual-asset` | 角色档案（10维度）、场景资产表、视觉符号库、IP视觉DNA、势力档案（8维度）、地理档案（7维度）、规则档案（6维度） | 作为人物/场景/符号/势力/地理/规则篇的**原文证据来源**，翻译成画面 |
| `pop-visual-style` | 画风DNA（37种）、画风决策、定标图、seed | 作为画风篇的**引用来源**，不发明新画风 |

## 与下游的关系

| 消费方 | 消费什么 | 怎么用 |
|:-----|:--------|:-------|
| `pop-visual-oc` | 美术设定集全篇（人物/势力/地理/规则/场景） | 取角色/势力/地理/规则视觉身份 + 定妆图，渲染对应的 OC 卡/势力卡/地理卡/规则卡/场景卡 |
| `pop-visual-comic` | 美术设定集全篇 | 取画风/人物/场景/符号，做导演卡与分格 |
| `pop-visual-cover` | 画风篇 + 场景篇 + 人物篇 | 取画风/场景/角色钩子，做封面/场景图 |
| `pop-comic-content` | 间接继承（不直接读设定集） | 读漫画成品图+页面配置产内容物料，画风/人设等卖点来自漫画成品（已继承设定集视觉）；不直接消费美术设定集 |

> **铁律**：美术设定集是派生层唯一消费的视觉真源。下游渲染时**只改渲染格式，不改视觉事实**（人物/场景/符号/画风）。任何视觉事实改动必须回到本 skill 升级设定集版本。美术设定集经认可后冻结为基线资产（标 `✅ 已认可`），下游只消费冻结版。

## 怎么运作

### Step 0: 读输入 → `steps/step0-read-input.md`

- 读 asset 资产（角色档案/场景资产表/视觉符号库/IP视觉DNA，缺失则提示先跑 asset）
- 读 style 画风（画风DNA库 + 画风决策，按赛道选基准）
- 读已有美术设定集（存在则升级，反类型化+撕裂感保持）
- **按 intent 档位规划**：封面/OC 轻量（人物+画风篇），漫画/全套完整（五篇）

### Step 1: 设计美术设定集 → `steps/step1-design-bible.md`

- **画风篇**：引用 style 画风DNA + 画风决策 + 定标图，定全宇宙色彩基调
- **人物篇**：三把锁差异化纪律 + 五问提取法 + 角色设计金字塔 + 记忆锚点分级 + 反类型化 + 撕裂感（保留原 character 全套方法论）
- **场景篇**：从 asset 场景资产表翻译成画面（场景意象/氛围/光/构图/可定格帧）
- **符号篇**：从 asset 视觉符号库整理（标志符/器物/阵营符号）
- **势力篇**：从 asset 势力档案翻译成"阵营视觉身份"（阵营美学/象征体系/等级秩序）
- **地理篇**：从 asset 地理档案翻译成"空间视觉设计"（空间质感/氛围基调/标志性地标）
- **规则篇**：从 asset 规则档案设计"抽象规则可视化"（从原文视觉外显提取具象载体）
- **一致性仲裁**：三把锁全局互查 + 跨实体冲突裁决（见 `references/bible-arbitration-guide.md`）
- 产出**美术设定集** `素材/美术设定集.md`（八篇合一 + 复现资产索引 + 版本）

### Step 2: 确认+落盘+冻结 → `steps/step2-confirm-freeze.md`

- **🚪 门禁：美术设定集确认**（用户确认设定集设计无误）
- 落盘 `素材/美术设定集.md`
- **冻结为基线资产**（标 `✅ 已认可`），通知下游可直接消费

### Step 3: 复现资产生成（按 intent 档位分支）→ `steps/step3-reproduce-assets.md`

- 用**冻结画风 + 设定集冻结提示词**渲染复现资产（人物定妆图/场景定妆图/符号示例图/势力示例图/地理示例图/规则示例图），让设定集第一次被眼睛看到
- **档位分支（按 intent）**：
  - `comic`/`full` → **完整复现（必做）**：人物**正/侧双角度**定妆图 + 关键场景定妆图，🚪 **复现验收门禁**，用户认可 → **冻结设定集为基线资产**（标 `✅ 已认可`）
  - `cover`/`oc` → **轻量复现（可选）**：基建到美术设定集（Step 0→1→2）即可派生，**不强制双角度**；如需参考图渲染单张，agent 自查达标标 `✅ 已认可`
  - `world` → **世界观复现（可选）**：基建到美术设定集（Step 0→1→2）即可派生；如需势力/地理/规则示例图渲染单张，agent 自查达标标 `✅ 已认可`
  - 只做设定集（不渲染）时 → **跳过本步**（Step 0→1→2 出设定集即完成）
- 未认可 → 回设定集升级版本，**禁止在渲染层硬凑**

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **视觉事实必须来自 asset 原文提取（五问提取法）** — 人物/场景/符号形象必须能从角色档案/场景资产表/视觉符号库或原文找到证据，禁止凭记忆/想象虚构 | 视觉事实扁平化，偏离原著，下游全部跑偏 |
| ❌2 | **每个视觉元素必须有"为什么"** — 提示词里每个元素都要能回答"为什么必须是这个样子的"，写不出原因的元素删掉 | 落入平均值陷阱，视觉平庸不出彩 |
| ❌3 | **必须显式写"偏科"** — 禁止默认输出"黑发+白T+标准网感脸/标准场景"；要写 `lean build`、`tired bloodshot eyes`、`muted gray palette` 这类偏离均值的词 | 视觉无辨识度，0.3秒认不出 |
| ❌4 | **美术设定集是唯一真源，下游不重建** — 设定集落盘后，oc/cover/comic/comic-content 只消费它，禁止各自重新设计人物/场景/符号/画风 | 各处各画各的，视觉漂移 |
| ❌5 | **视觉事实改动必须升级版本** — 人物/场景/符号/画风变化必须回本 skill 升级设定集版本，禁止下游擅自改 | 设定集与渲染脱节，跨形态不一致 |
| ❌6 | **复现图不达标回设定集，不硬凑渲染** — 复现图不达标时回设定集升级版本（改视觉事实），禁止在渲染层硬凑 | 视觉漂移，下游全跑偏 |
| ❌7 | **三把锁差异化先行** — 设计人物前先定全局唯一位置（剪影签名/签名色/记忆锚点），同书互比不撞；记忆锚点按重要度分级（主角2-3个组合/配角1个），过不了置换测试即回炉 | 角色"属性堆砌"，同书角色撞脸 |
| ❌8 | **定妆照是纯生产材料** — 定妆图必须纯净（无文字/无装饰/无文化元素），只做全下游（oc/cover/comic）的生产参考，禁止混合展示功能 | 定妆图混杂展示元素，下游无法直接复用 |
| ❌9 | **画风必须引用 style 冻结** — 画风篇只引用 style 的冻结画风（DNA+决策+seed+定标图），禁止发明新画风 | 画风漂移，脱离已认可的定标 |
| ❌10 | **势力/地理/规则形象必须来自 asset 对应档案** — 势力篇/地理篇/规则篇只消费 asset 的势力档案/地理档案/规则档案，规则可视化必须从原文视觉外显提取具象载体，禁止凭空虚构势力/地理/规则或发明规则符号 | 势力/地理/规则脱离原著，设定集失真 |
| ❌11 | **人物篇范围 = asset 档案范围，禁止虚构配角** — 人物篇与一致性互查表只覆盖 asset 角色档案清单内的角色；无档案角色（金翅鸟/配角）不进入人物篇，cover/oc 档在主角符号里锚定，comic/full 档先回 asset 补档案；角色数 <2 时互查表仅单行+标注待补 | 为填互查表虚构配角视觉，违反 ❌1 且设定集失真 |
| ❌12 | **势力/地理/规则篇范围 = asset 对应档案范围，禁止虚构实体** — 势力/地理/规则篇与跨实体互查只覆盖 asset 对应档案清单内的实体；无档案的势力/地理/规则不进入对应篇，先回 asset 补档案 | 为填设定集虚构势力/地理/规则视觉，违反 ❌1 且设定集失真 |
| ❌13 | **规则可视化必须有原文视觉外显依据** — 抽象规则的可视化载体（光效/纹路/器物/天象）必须来自 asset 规则档案的原文行号，禁止凭空发明与原文无关的规则符号 | 规则可视化架空原著，下游规则卡失真 |
