# pop-visual-asset

> 小说视觉资产提取器。从原文提取结构化素材，供视觉 skill 群消费。v2.0.0：steps 两件全合入 SKILL.md 单文件精炼，SOP 全内联。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 做什么

输入：小说原文（txt 文件或多章 txt 目录）+ 可选的角色名/章节范围/提取需求。
输出：`素材/视觉资产/` 目录下的标准化资产文件。

核心价值：**只提取不生成，只理解不画图**。把非结构化的小说原文，转化为结构化的视觉资产库，让下游 skill（OC/漫画/封面/世界观推广素材）不用各自从原文提取、重复劳动。

与拆书 skill 的本质区别：拆书拆的是**怎么写的**（技法），asset 提的是**有什么**（素材）。消费者不同，提取层不同。

**资产类型**：除角色档案/场景资产表/视觉符号库/IP视觉DNA外，新增**势力档案/地理档案/规则档案**三类（世界观推广素材的视觉真源），供 art-bible 势力篇/地理篇/规则篇消费。

## 两种项目空间

用 LS 扫描项目根目录，按优先级依次检测信号判定项目类型：

| 探测信号 | 项目类型 | 原文路径 | 已有设定 |
|:---------|:---------|:---------|:---------|
| `项目总控.html` | 写作专家·起点 | `正文/ch*.txt` | `设计/角色库/` + `设计/全书设定/` |
| `project-state.md` | 写作专家·番茄 | `正文/ch*.txt` | `设计/角色库/` + `设计/` |
| `原料/小说原文/` | 独立小说项目 | 单个完整 txt | 无 |
| 用户指定路径 | 临时模式 | 指定文件 | 无 |

写作专家项目已有设定可辅助提取（独立项目无此层）：

| 已有文件 | 辅助方式 |
|:---------|:---------|
| `设计/角色库/角色库.md` | 提供角色名单/定位/关系概览——仍需从正文采样原文佐证和行号 |
| `设计/主角设计.md` | 主角核心设定，辅助理解不替代原文采样 |
| `设计/力量体系.md` | 力量体系视觉外显线索，辅助视觉符号库提取 |
| `设计/全书设定/` | 世界观背景，辅助场景资产表的环境理解 |

> **关键**：已有设定提供"这个角色大概是什么样"，原文采样提供"原文怎么写的、在哪一行"。asset 的产出必须包含行号索引，已有设定只做辅助参考。

## 执行模式

**原文采样提取可派子 agent，门禁归主 agent**：角色/场景/符号/IP DNA 的 Grep+Read 原文采样是只读类工作，可派子 agent 执行并回报采样结果（行号+原文佐证），主 agent 负责档案整理与落盘；角色名单确认与「资产确认」门禁需用户多轮交互，主 agent 直执。

## 怎么运作（SOP全内联）

### Step 0: 项目空间探测 + 原文定位 + 产出规划

**1. 项目空间探测**：按「两种项目空间」表判定类型，向用户呈现探测结果（项目类型 / 原文位置+章节数 / 已有设定清单 / `素材/视觉资产/` 下已有资产清单）。

**2. 原文定位**：
- 写作专家项目（多章 txt）：扫描 `正文/` 获取全部 `ch*.txt`，按章节号排序确认连续性，记录最新章节号（供增量判断）。采样时 Grep 搜索整个 `正文/` 目录，Read 读取具体章节
- 独立小说项目（单文件）：定位 `原料/小说原文/` 下 txt，多本时向用户确认要提取哪本；单文件可能数十万字，Grep 搜索时记录行号
- 临时模式：向用户询问原文文件路径，确认存在后继续

**3. IP 背景判定**：书名+角色名+世界观术语包含已知 IP 要素（如"海贼/恶魔果实/One Piece"）→同人；书名含"同人/改编/之[某IP]"→同人；不确定→问用户"这本小说是否基于某个已有IP？"；确认原创→原创。判定为同人后在产出规划中增加 IP视觉DNA 产出：识别源IP名称→WebSearch 搜索源IP视觉资料→提取4维度视觉DNA（画风/经典形象/世界观符号/标志色）。

**4. 产出规划（按 intent 档位定深，不默认全量）**：Pipeline 语境下读 `视觉项目总控.html` 的 `<!--STATE:intent -->` 按档位定深；独立模式按用户当次需求映射到同一档位。

| intent 档位 | 基建定位 | 产出偏重 | 角色档案深度 |
|:------------|:---------|:---------|:-------------|
| `cover` | 轻量 | 场景资产表+视觉符号库为主 | 只提封面涉及角色，可精简（3-5 关键场景） |
| `oc` | 轻量~中 | 角色档案为主 | 目标角色深度 10 维度，场景可精简 |
| `comic` | 完整 | 全量（角色档案+场景资产表，符号库/IP DNA 可选） | 深度 10 维度 |
| `full` | 完整 | 全部产出 | 深度 10 维度 |
| `asset-only` | 最轻 | 用户指定资产 | 按指定 |

扩展产出组合（用户点名才提）：做势力卡/势力素材→势力档案（+关联角色档案/视觉符号库）；做地理卡/世界观卡→地理档案（+场景资产表/视觉符号库）；做规则卡/体系卡→规则档案（+视觉符号库/关联角色档案）；做世界观推广素材→势力+地理+规则档案（+角色档案/场景表/符号库）。未明确→询问用户。

**角色名单确认**（产出含角色档案时）：写作专家项目读 `设计/角色库/角色库.md` 列角色供用户选择；独立项目问用户。默认按 intent 划定——`oc`/`comic`/`full`→主角+用户指定角色；`cover`→只提封面涉及的出场角色（精简版）；`asset-only`→用户指定角色。**章节范围**：写作专家项目默认全部已写章节（用户可指定如"只看最新5章"）；独立项目默认全文。

**5. 增量更新检查**：扫描 `素材/视觉资产/` 已有资产文件，读取文件头部"采样范围"标记（如"截至 ch015"），对比当前原文范围计算增量（如 ch016-ch020）→ 只对新增章节执行提取 → 结果追加到已有文件。无任何资产文件→全量提取。向用户呈现增量计划（已有资产+采样范围 / 新增章节 / 增量产出方向：角色档案追加新外貌/新场景/新评价，场景表追加新关键帧，符号库扫描新意象）。

**6. 落盘资产索引**：创建或更新 `素材/视觉资产/资产索引.md`——项目信息（项目类型/原文路径/原文范围/IP背景）+ 资产清单表（资产文件/采样范围/状态/最后更新）+ 消费记录表（日期/消费方/读取资产/产出）。

### Step 1: 资产提取

按 Step 0 规划执行提取，每种产出独立操作。详细方法论见 `references/asset-extract-guide.md` 对应节。

**1. 角色档案**（§一）：对每个目标角色执行——
- **5轮关键词搜索**（Grep，output_mode=content、-n=true 记录命中行号；写作专家项目搜 `正文/` 全部 ch*.txt，独立项目搜单 txt）：

| 轮次 | 关键词类型 | 示例（李周巍） | 目的 |
|:-----|:---------|:-------------|:-----|
| 1 | 角色名 | `李周巍` | 定位所有出场段落 |
| 2 | 外貌词 | `李周巍.*(眸\|眼\|甲\|氅\|袍\|发)` | 采集外貌描写 |
| 3 | 性格词 | `李周巍.*(霸道\|虎豹\|冷\|笑\|怒)` | 采集性格特征 |
| 4 | 评价词 | `白麟\|魏王\|李氏天骄` | 采集他人评价 |
| 5 | 关系词 | `李周巍.*(父亲\|母亲\|叔公\|部下)` | 采集人际关系 |

- **上下文采样**：每个关键词命中后 Read 前后 20-50 行上下文，重点外貌描写/对话/动作/他人评价/心理活动；每个维度至少 3-5 条原文佐证。
- **10维度档案整理**：

| 维度 | 内容 |
|:-----|:-----|
| 一、角色概览 | 姓名/道号/称号/兵器/功法/命格/核心气质 |
| 二、外貌演变 | 按年龄阶段记录外貌变化（含行号） |
| 三、性格特征 | 5-7个性格侧面+原文佐证 |
| 四、人际关系 | 与3-5个关键人物的互动模式 |
| 五、成长弧线 | 6-8个成长阶段（事件+变化） |
| 六、金句语录 | 5-10句标志性台词（按主题分类） |
| 七、他人评价 | 旁人/长辈/敌人/龙属的评价（分类） |
| 八、矛盾与暗面 | 角色的复杂性、阴暗面、非人感 |
| 九、视觉设计参考 | 3-8个最适合做OC的关键场景与形象 |
| 十、核心意象与符号 | 贯穿全文的视觉符号（3-7个） |

- 写作专家项目有角色库.md 时：作维度一/三辅助参考，档案中"已有设定参考"与"原文采样"分开标注。
- 增量模式：只搜增量章节；新外貌→追加维度二、新成长事件→维度五、新评价金句→维度六/七；更新采样范围标记。

**2. 场景资产表**（§二）：对指定章节范围（或全文）——
- 场景扫描：Grep 搜场景转换标志词（`到了|进入|来到|站在|眼前|远处|天空|大地`）+ 视觉密集段落（颜色词+器物词+动作词共现），每个命中段落 Read 上下文确认是否关键场景
- 场景拆解为"可定格帧"：帧编号/章节位置/场景名/参与角色/视觉元素清单/氛围基调/叙事含义/行号
- 帧评估三指标（各1-5）：视觉张力（构图潜力）/叙事含量（故事信息量）/情感共鸣（读者想看到的程度）。**优先保留视觉张力≥3 且叙事含量≥3 的帧**，消费方可按需选取

**3. 视觉符号库**（§三）：全文意象扫描——

| 搜索维度 | Grep 关键词模板 | 提取内容 |
|:---------|:---------------|:---------|
| 核心意象 | `[角色名].*(眸\|眼\|甲\|袍\|戟\|钺)` | 角色标志性视觉特征 |
| 标志色 | `(金色\|暗金\|黑金\|白金\|浅紫\|朱砂)` | 反复出现的色彩 |
| 标志器物 | `(长戟\|王钺\|法器\|灵器)` | 标志性道具 |
| 阵营符号 | `(旗帜\|纹章\|族徽\|标记)` | 势力视觉标识 |

整理为表（意象/含义/首次出现/出现频率/视觉描述）。有 `设计/力量体系.md` 时读其中视觉外显描述（如"明阳之道→金色光芒"）辅助推导。

**4. IP视觉DNA**（同人时，§四）：识别源IP→WebSearch 搜索4维度——`[源IP] official art style`（源IP画风：笔触/比例/色彩倾向）/ `[源IP] character design`（角色经典形象）/ `[源IP] visual symbols`（世界观视觉符号）/ `[源IP] color palette`（标志色）→落盘 `IP视觉DNA.md`。

**5. 势力/地理/规则档案**（§五/§六/§七，做世界观推广素材时；只在用户点名或 intent 明确要做推广素材时提取，不默认全量）：
- **势力档案**：定位目标势力（用户点名或从全文识别主线势力）→按 §五 搜索势力名/归属/人群/地标，整理 8 维度档案→落盘 `[势力名]势力档案.md`。**只提取原文有明确描述的势力，禁止凭刻板印象虚构势力美学**
- **地理档案**：定位目标地理（用户点名或识别关键小世界/城市/秘境）→按 §六 搜索地名/空间特征/氛围/建筑，整理 7 维度档案→落盘 `[地名]地理档案.md`。**只在原文有明确空间描述时提取，禁止拼凑"仙侠标配"通用场景**
- **规则档案**：定位目标规则/体系（用户点名或识别力量体系/境界/禁忌）→按 §七 搜索规则名/视觉外显/境界异象/器物载体，整理 6 维度档案→落盘 `[规则名]规则档案.md`。**必须在原文有视觉外显描述时提取，禁止凭空发明规则符号**

### 🚪 门禁：资产确认（强制暂停点，禁止跳过）

提取完成后向用户呈现资产摘要，确认准确性和完整性后落盘：

- **角色档案**（每个角色）：核心气质（1-2句）/外貌关键特征（3个+行号）/最适合做OC的场景（3个+行号）/核心意象（3-5个）/核心金句（1句+行号）
- **场景资产表**：共提取 N 个可定格帧 / 高视觉张力帧（≥4）M 个 / 覆盖章节范围
- **视觉符号库**：核心意象 N 个 / 标志色 N 个 / 标志器物 N 个
- **IP视觉DNA**（如有）：源IP/画风特征一句话/标志色列表
- **势力档案**（如有）：核心气质一句话/美学基调（标志色/纹饰）/象征体系（旗帜/纹章）
- **地理档案**（如有）：空间质感一句话/氛围基调（光/色/情绪）/标志性节点 N 个
- **规则档案**（如有）：视觉外显（光效/纹路）/层级可视化（N 个境界异象）/器物载体

用户回复处理："确认，落盘"→执行落盘｜"[角色]的评价不对"→修正后重新呈现｜"漏了一个场景"→补充提取｜"再提取一个角色"→返回角色档案环节执行新角色。

### 落盘

确保 `素材/视觉资产/` 目录存在，每个产出写入独立文件：`[角色名]角色档案.md` / `场景资产表.md` / `视觉符号库.md` / `IP视觉DNA.md`（同人时）/ `[势力名]势力档案.md` / `[地名]地理档案.md` / `[规则名]规则档案.md`。每个资产文件头部必须包含：

```markdown
> 采样范围：ch001-ch020（共20章）
> 提取日期：2026-07-30
> 项目类型：[类型]
> 源文件：[原文路径]
```

落盘后更新 `资产索引.md` 的资产清单和状态。

### 消费路由（按 intent 档位）

资产就绪后，**Pipeline 语境下优先路由到 `pop-visual-art-bible`（L1 基建第三引擎）**，由 art-bible 汇总成美术设定集（唯一真源）后再下发给派生层 oc/cover/comic。不进派生层时停在 asset：

| intent | 路由到 | 读取哪些资产 | 基建档位 |
|:---------|:-------|:------------|:---------|
| `asset-only` | 停止 | 资产已就绪供 art-bible 使用 | 最轻 |
| `cover` | `pop-visual-art-bible`（轻量）→ cover | 场景资产表 + 视觉符号库（+ 封面涉及角色档案） | 轻量 |
| `oc` | `pop-visual-art-bible`（轻量~中）→ oc | 角色档案（深度） | 轻量~中 |
| `comic` | `pop-visual-art-bible`（完整）→ comic | 角色档案（深度）+ 场景资产表 | 完整 |
| `full` | `pop-visual-art-bible`（完整）→ 按需 loop cover/oc/comic | 全部产出 | 完整 |

> **L1 汇总铁律**：asset 的产出是给 **art-bible** 消费的（L1 内），不是直接给派生层。派生层（oc/cover/comic）只消费 art-bible 产出的美术设定集，禁止各自直接从 asset 重建人物/场景/符号。独立模式（无 pipeline/无 art-bible 语境）时，才允许 oc/cover 直接读 asset 资产。
>
> **定深原则**：intent 决定"提什么、提多深"。`comic`/`full` 走全量深度提取；`cover` 以场景+符号为主、角色档案只提封面涉及角色；`oc` 以角色档案为主、场景可精简；`asset-only` 只提用户指定资产不进派生层。
>
> **独立模式**：不在 pipeline 语境时，按用户当次需求（见 Step 0 产出规划表）判定，规则一致。
>
> asset skill 本身不调用消费 skill，只告知用户资产已就绪，由用户或主 agent 按 intent 档位触发消费 skill。

## 增量更新机制

当写作专家项目写到新章节后，用户可要求增量更新已有资产：

1. 读取已有资产文件的"采样范围"标记（如"截至 ch015"）
2. 检测原文新增章节（ch016-ch020）
3. 只对新增章节执行提取
4. 合并到已有资产文件（追加新维度内容 + 更新采样范围标记）

> 增量更新不覆盖已有内容，只追加新发现的信息。已有角色档案的维度二（外貌演变）追加新阶段，维度五（成长弧线）追加新阶段。
