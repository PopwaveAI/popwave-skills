# pop-visual-asset

> 小说视觉资产提取器。从原文提取结构化素材，供视觉 skill 群消费。v1.2.0

## 做什么

输入：小说原文（txt 文件或多章 txt 目录）+ 可选的角色名/章节范围/提取需求。
输出：`素材/视觉资产/` 目录下的标准化资产文件。

核心价值：**只提取不生成，只理解不画图**。把非结构化的小说原文，转化为结构化的视觉资产库，让下游 skill（OC/漫画/封面/世界观推广素材）不用各自从原文提取、重复劳动。

与拆书 skill 的本质区别：拆书拆的是**怎么写的**（技法），asset 提的是**有什么**（素材）。消费者不同，提取层不同。

**资产类型**：除角色档案/场景资产表/视觉符号库/IP视觉DNA外，新增**势力档案/地理档案/规则档案**三类（世界观推广素材的视觉真源），供 art-bible 势力篇/地理篇/规则篇消费。

## 两种项目空间

| 探测信号 | 项目类型 | 原文路径 | 已有设定 |
|:---------|:---------|:---------|:---------|
| `项目总控.html` | 写作专家·起点 | `正文/ch*.txt` | `设计/角色库/` + `设计/全书设定/` |
| `project-state.md` | 写作专家·番茄 | `正文/ch*.txt` | `设计/角色库/` + `设计/` |
| `原料/小说原文/` | 独立小说项目 | 单个完整 txt | 无 |
| 用户指定路径 | 临时模式 | 指定文件 | 无 |

> 写作专家项目已有角色库.md 时，asset 读取作为辅助参考，但仍需从正文采样原文佐证和行号索引。

## 怎么运作

### Step 0: 项目空间探测 + 原文定位 + 产出规划 → `steps/step0-detect.md`

- 探测项目类型（四种信号）
- 定位小说原文（多章合并 or 单文件）
- IP 背景判定（同人/改编/原创）
- **按 intent 档位规划产出组合与深度**（谁要什么就提什么，不默认全量）：Pipeline 语境下读 `视觉项目总控.html` 的 `intent`（cover/oc/comic/full/asset-only），独立使用时按用户需求判定
- 增量更新检查：已有资产文件 → 检测原文新增章节 → 规划增量范围

### Step 1: 资产提取 → `steps/step1-extract.md`

按 Step 0 规划执行提取，每种产出独立操作：

**角色档案**：5轮关键词搜索 → 上下文采样 → 10维度档案 → 落盘
**场景资产表**：原文通读/章节扫描 → 关键场景拆解 → 可定格帧清单 → 落盘
**视觉符号库**：全文意象扫描 → 标志色/器物/符号提取 → 落盘
**IP视觉DNA**（同人时）：源IP搜索 → 画风/经典形象/世界观符号提取 → 落盘

### 🚪 门禁：资产确认

向用户呈现提取结果摘要，确认准确性和完整性后落盘。

### 消费路由（按 intent 档位）

资产就绪后，**Pipeline 语境下优先路由到 `pop-visual-art-bible`（L1 基建第三引擎）**，由 art-bible 汇总成美术设定集（唯一真源）后再下发给派生层 oc/cover/comic。不进派生层时停在 asset：

| intent | 路由到 | 读取哪些资产 | 基建档位 |
|:---------|:-------|:------------|:---------|
| `asset-only` | 停止 | 资产已就绪供 art-bible 使用 | 最轻 |
| `cover` | `pop-visual-art-bible`（轻量）→ cover | 场景资产表 + 视觉符号库（+ 封面涉及角色档案） | 轻量 |
| `oc` | `pop-visual-art-bible`（轻量~中）→ oc | 角色档案（深度） | 轻量~中 |
| `comic` | `pop-visual-art-bible`（完整）→ comic | 角色档案（深度）+ 场景资产表 | 完整 |
| `full` | `pop-visual-art-bible`（完整）→ 按需 loop cover/oc/comic | 全部产出 | 完整 |

> **L1 汇总铁律**：asset 的产出是给 **art-bible** 消费的（L1 内），不是直接给派生层。派生层（oc/cover/comic）只消费 art-bible 产出的美术设定集，禁止各自直接从 asset 重建人物/场景/符号。独立模式（无 pipeline/无 art-bible 语境）时，才允许 oc/cover 直接读 asset 资产。
>
> **定深原则**：intent 决定"提什么、提多深"。`comic`/`full` 走全量深度提取；`cover` 以场景+符号为主、角色档案只提封面涉及角色；`oc` 以角色档案为主、场景可精简；`asset-only` 只提用户指定资产不进派生层。
>
> **独立模式**：不在 pipeline 语境时，按用户当次需求（见 step0-detect §4 表格）判定，规则一致。

## 增量更新机制

当写作专家项目写到新章节后，用户可要求增量更新已有资产：

1. 读取已有资产文件的"采样范围"标记（如"截至 ch015"）
2. 检测原文新增章节（ch016-ch020）
3. 只对新增章节执行提取
4. 合并到已有资产文件（追加新维度内容 + 更新采样范围标记）

> 增量更新不覆盖已有内容，只追加新发现的信息。已有角色档案的维度二（外貌演变）追加新阶段，维度五（成长弧线）追加新阶段。

## 产出文件结构

```
{项目}/素材/视觉资产/
├── [角色名]角色档案.md          # 10维度 · 原文采样+行号索引
├── 场景资产表.md                # 可定格帧清单
├── 视觉符号库.md                # 核心意象/标志色/器物/阵营符号
├── IP视觉DNA.md                 # 同人时才有
├── [势力名]势力档案.md          # 8维度 · 阵营美学/象征体系（做势力卡时）
├── [地名]地理档案.md            # 7维度 · 空间质感/氛围基调（做地理卡时）
├── [规则名]规则档案.md          # 6维度 · 视觉外显/层级可视化（做规则卡时）
└── 资产索引.md                  # 所有资产的目录和状态
```

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **只提取不生成** — asset skill 禁止调用任何图片/视频生成 API，禁止做视觉设计方案。只从原文提取素材，生成交给消费 skill | 职责越界，和消费 skill 重复 |
| ❌2 | **原文采样必须有行号索引** — 每条提取的信息必须标注原文行号，便于用户查验和消费 skill 定位场景 | 无法溯源，消费 skill 无法定位原文 |
| ❌3 | **增量更新不覆盖** — 增量更新只追加新内容，不删除或覆盖已有内容。已有内容如有错误，在门禁环节由用户确认后修改 | 丢失已有采样数据 |
| ❌4 | **资产必须落盘到 素材/视觉资产/** — 所有产出文件写入 `素材/视觉资产/` 目录，不散落到项目根目录或其他目录 | 消费 skill 找不到资产文件 |
