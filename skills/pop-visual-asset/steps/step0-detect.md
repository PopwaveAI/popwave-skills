# Step 0: 项目空间探测 + 原文定位 + 产出规划

> 探测项目类型 → 定位原文 → IP判定 → 规划产出 → 增量检查

## 1. 项目空间探测

### 1.1 探测信号

按优先级依次检测以下信号，判定项目类型：

| 探测顺序 | 检测信号 | 判定项目类型 | 原文路径 | 已有设定 |
|:---------|:---------|:------------|:---------|:---------|
| 1 | 项目根目录有 `项目总控.html` | 写作专家·起点 | `正文/ch*.txt` | `设计/角色库/角色库.md` + `设计/全书设定/` |
| 2 | 项目根目录有 `project-state.md` | 写作专家·番茄 | `正文/ch*.txt` | `设计/角色库/角色库.md` + `设计/` |
| 3 | 有 `原料/小说原文/` 目录 | 独立小说项目 | `原料/小说原文/[书名].txt` | 无 |
| 4 | 以上都不匹配 | 临时模式 | 向用户询问原文路径 | 无 |

> 用 LS 工具扫描项目根目录，根据文件特征判定。

### 1.2 写作专家项目的特殊处理

写作专家项目（起点/番茄）有以下已有设定可辅助提取：

| 已有文件 | 辅助方式 | 注意事项 |
|:---------|:---------|:---------|
| `设计/角色库/角色库.md` | 提供角色名单、定位、关系概览 | 仍需从正文采样原文佐证和行号 |
| `设计/主角设计.md` | 提供主角核心设定 | 辅助理解，不替代原文采样 |
| `设计/力量体系.md` | 提供力量体系视觉外显线索 | 辅助视觉符号库提取 |
| `设计/全书设定/` | 提供世界观背景 | 辅助场景资产表的环境理解 |

> **关键**：已有设定提供"这个角色大概是什么样"，原文采样提供"原文怎么写的、在哪一行"。asset 的产出必须包含行号索引，已有设定只做辅助参考。

### 1.3 呈现探测结果

```
## 项目空间探测

### 项目类型
[写作专家·起点 / 写作专家·番茄 / 独立小说项目 / 临时模式]

### 原文位置
[路径 + 章节数量]

### 已有设定（如有）
- [文件路径]：[一句话说明]
- ...

### 已有视觉资产（如有）
- [素材/视觉资产/ 下的文件清单]
```

## 2. 原文定位

### 2.1 写作专家项目（多章 txt）

扫描 `正文/` 目录，获取所有 `ch*.txt` 文件：

```
正文/
├── ch001.txt
├── ch002.txt
├── ...
└── ch015.txt
```

- 按章节号排序，确认连续性
- 记录最新章节号（用于增量更新判断）
- 原文采样时：Grep 搜索整个 `正文/` 目录，Read 读取具体章节

### 2.2 独立小说项目（单文件）

定位 `原料/小说原文/` 下的 txt 文件：

```
原料/小说原文/
├── 玄鉴仙族.txt
├── 诡秘之主.txt
└── ...
```

- 向用户确认要提取哪本书
- 单文件可能很大（数十万字），Grep 搜索时记录行号

### 2.3 临时模式

向用户询问原文文件路径，确认文件存在后继续。

## 3. IP 背景判定

### 3.1 判定流程

```
书名 + 角色名 + 世界观术语
  ├─ 包含已知IP要素（如"海贼""恶魔果实""One Piece"）→ 同人
  ├─ 书名含"同人""改编""之[某IP]" → 同人
  ├─ 不确定 → 问用户："这本小说是否基于某个已有IP？"
  └─ 确认原创 → 原创
```

### 3.2 同人/改编的处理

判定为同人后，在产出规划中增加 IP视觉DNA 产出：

1. 识别源IP名称
2. WebSearch 搜索源IP视觉资料
3. 提取4维度视觉DNA（画风/经典形象/世界观符号/标志色）

> 详见 `references/asset-extract-guide.md` §四

## 4. 产出规划

### 4.0 读取 intent 档位（定深依据）

Pipeline 语境下，先读 `视觉项目总控.html` 的 `<!--STATE:intent -->` 字段，按档位定深；独立模式按用户当次需求映射到同一档位。**不默认全量提取。**

| intent 档位 | 基建定位 | 产出偏重 | 角色档案深度 |
|:------------|:---------|:---------|:-------------|
| `cover` | 轻量 | 场景资产表 + 视觉符号库为主 | 只提封面涉及角色，可精简（3-5 关键场景） |
| `oc` | 轻量~中 | 角色档案为主 | 目标角色深度 10 维度，场景可精简 |
| `comic` | 完整 | 全量 | 深度 10 维度 |
| `full` | 完整 | 全量 | 深度 10 维度 |
| `asset-only` | 最轻 | 用户指定资产 | 按指定 |

### 4.1 根据 intent / 用户需求规划产出组合

| 用户需求（intent） | 必需产出 | 可选产出 |
|:---------|:---------|:---------|
| "做封面/场景图" (`cover`) | 场景资产表 + 视觉符号库 | 封面涉及角色档案（精简）、IP视觉DNA（同人时） |
| "给[角色]做OC" (`oc`) | 目标角色档案（深度） | IP视觉DNA（同人时） |
| "做漫画" (`comic`) | 角色档案（深度）+ 场景资产表 | 视觉符号库、IP视觉DNA |
| "做全套视觉" (`full`) | 全部产出 | — |
| "做势力卡/势力素材" | 势力档案（目标势力） | 关联角色档案、视觉符号库 |
| "做地理卡/世界观卡" | 地理档案（目标地区） | 场景资产表、视觉符号库 |
| "做规则卡/体系卡" | 规则档案（目标体系） | 视觉符号库、关联角色档案 |
| "做世界观推广素材" | 势力档案 + 地理档案 + 规则档案 | 角色档案、场景资产表、视觉符号库 |
| "只提取角色档案" (`asset-only`) | 指定角色档案 | — |
| 未明确 | 询问用户 | — |

### 4.2 角色名单确认（按 intent 划定范围）

如果产出包含角色档案，确认要提取哪些角色：

- 写作专家项目：读取 `设计/角色库/角色库.md`，列出角色供用户选择
- 独立项目：向用户询问要提取哪些角色
- **默认按 intent 划定**：`oc`/`comic`/`full` → 主角 + 用户指定角色；`cover` → 只提封面涉及的出场角色（精简版）；`asset-only` → 用户指定角色

### 4.3 章节范围确认

- 写作专家项目：默认提取所有已写章节（如 ch001-ch015）
- 用户可指定范围（如"只看最新5章"）
- 独立项目：默认全文

## 5. 增量更新检查

### 5.1 检测已有资产

扫描 `素材/视觉资产/` 目录：

| 已有文件 | 增量策略 |
|:---------|:---------|
| `[角色名]角色档案.md` 存在 | 读取文件头部的"采样范围"标记，对比当前原文范围，确定增量章节 |
| `场景资产表.md` 存在 | 同上 |
| `视觉符号库.md` 存在 | 同上 |
| 无任何资产文件 | 全量提取 |

### 5.2 增量范围计算

```
已有资产采样范围：截至 ch015
当前原文范围：ch001-ch020
→ 增量范围：ch016-ch020
→ 只对 ch016-ch020 执行提取
→ 提取结果追加到已有资产文件
```

### 5.3 呈现增量计划

```
## 增量更新计划

### 已有资产
- 李周巍角色档案.md（采样范围：ch001-ch015）
- 场景资产表.md（采样范围：ch001-ch015）

### 新增章节
ch016-ch020（5章）

### 增量产出
- 角色档案：追加 ch016-ch020 的新外貌描写、新场景、新评价
- 场景资产表：追加 ch016-ch020 的关键场景帧
- 视觉符号库：扫描新章节是否有新意象
```
