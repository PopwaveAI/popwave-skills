# pop-visual-character

> 人物形象设计 · 营销专家基建层。角色档案→角色视觉身份卡。v1.5.0

## 做什么

输入：角色档案（`pop-visual-asset` 产出，10维度）+ 画风（`pop-visual-style` 画风DNA库）。
输出：**角色视觉身份卡**（`素材/视觉资产/[角色名]视觉身份卡.md`）——全书角色视觉的唯一真源。

**核心价值**：营销专家管线里"人物形象设计"是基建，目前是空的。OC/封面/场景/漫画各自画角色，导致三处各画各的、平庸不出彩。本 skill 把"这个角色长什么样"这个**身份设计**一次性做对，然后全下游消费它渲染。

**一句话定位**：其他 skill 负责"**怎么把这个角色画出来**"（渲染），本 skill 负责"**这个角色到底是谁**"（身份）。

## 与下游的关系

| 消费方 | 消费什么 | 怎么用 |
|:-----|:--------|:-------|
| `pop-visual-oc` | 角色视觉身份卡 | 作为杂志版立绘的"角色本体"，只加六层排版+氛围 |
| `pop-visual-comic` | 角色视觉身份卡 | 作为定妆照的"角色本体"，只做正/侧双角度+高精度4块 |
| `pop-visual-cover` | 角色视觉身份卡 | 作为封面角色钩子的视觉依据 |
| `pop-visual-cover`(场景) | 角色视觉身份卡 | 作为场景中角色出现的视觉依据 |

> **铁律**：角色视觉身份卡是全下游共用的真源。下游渲染时**只改渲染格式，不改角色身份**。身份改动必须回到本 skill 升级身份卡版本。Pipeline 语境下，身份卡经定妆认可后冻结为基线资产（标 `✅ 已认可`），下游只消费冻结的身份卡 + 定妆图。

> **定妆照 vs 立绘OC**：本 skill Step 3 产出的**定妆照**是纯生产参考图（无文字/无装饰/无文化元素），供 oc/cover/comic 做图生图参考；`pop-visual-oc` 产出的**立绘OC**是带文字+文化元素的展示作品（角色名片）。二者职责不同，不可混用——定妆照被 OC 消费时，作为角色本体参考，OC 的文字/装饰由 OC 层叠加。

## 怎么运作

### Step 0: 读输入 → `steps/step0-read-input.md`

- 读角色档案（`pop-visual-asset` 产出 `素材/视觉资产/[角色名]角色档案.md`，缺失则提示先跑 asset）
- 读画风（`pop-visual-style` 画风DNA库，按赛道选基准）
- 读已有身份卡（存在则升级，反类型化+撕裂感保持）

### Step 1: 身份设计 → `steps/step1-design-identity.md`

- **三把锁差异化纪律**（全局先行：剪影签名/签名色/记忆锚点，一人一个"唯一"视觉位置）
- **五问提取法**（从原著处境提取视觉锚点，非外貌形容词）
- **角色设计金字塔**（剪影层→色彩层→细节层，逐层递进）
- **记忆锚点**（7类，按重要度分级：主角2-3个组合/配角1个）
- **反类型化**（打破网感脸：表情/职业/完美/密度）
- **撕裂感**（命运符号 vs 日常行为冲突）
- 产出**角色视觉身份卡**（含三把锁 + 七维度规格表 + 视觉锚点串 + 冻结提示词）

### Step 2: 确认+落盘 → `steps/step2-confirm-save.md`

- **🚪 门禁：身份卡确认**（用户确认角色身份设计无误）
- 落盘 `素材/视觉资产/[角色名]视觉身份卡.md`
- 通知下游可直接消费

### Step 3: 角色定妆（按 intent 档位分支）→ `steps/step3-character-tuning.md`

- 用**选定画风 + 身份卡冻结提示词**渲染角色定妆图（身份不变，只验证渲染）
- 让身份设计第一次被眼睛看到，验证角色在大图上是否成立
- **档位分支（按 intent）**：
  - `comic`/`full` → **完整定妆（必做）**：渲染**正/侧双角度**定妆图（跨章一致性），🚪 **角色定妆验收门禁**（剪影层/色彩签名/记忆锚点/反类型化/画风一致），用户认可 → **冻结身份卡为基线资产**（身份卡标 `✅ 已认可`）
  - `cover`/`oc` → **轻量定妆（可选）**：基建到身份卡（Step 0→1→2）即可派生，**不强制双角度定妆**；如需封面/OC 角色参考图，渲染**单张**定妆图即可，agent 自查达标标 `✅ 已认可`
  - 只做身份设计（不渲染）时 → **跳过本步**（Step 0→1→2 出身份卡即完成）
- 未认可 → 回身份卡升级版本，**禁止在渲染层硬凑**

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **身份卡必须来自原著处境（五问提取法）** — 禁止凭记忆/想象虚构角色身份，每个视觉锚点都要能从角色档案或原文找到处境证据 | 角色扁平化，偏离原著，下游全部跑偏 |
| ❌2 | **每个锚点必须有"为什么"** — 提示词里每个视觉元素都要能回答"为什么必须是这个样子的"，写不出原因的元素删掉 | 落入平均值陷阱，角色平庸不出彩 |
| ❌3 | **必须显式写"偏科"** — 禁止默认输出"黑发+白T+卫衣+牛仔裤+标准网感脸"；要写 `lean build`、`subtle asymmetry`、`tired bloodshot eyes` 这类偏离均值的词 | 角色无辨识度，0.3秒认不出 |
| ❌4 | **身份卡是唯一真源，下游不重建** — 身份卡落盘后，oc/cover/comic 只消费它，禁止各自重新设计角色身份 | 三处各画各的，角色漂移 |
| ❌5 | **身份改动必须升级版本** — 角色身份变化（换装/受伤/觉醒/年龄）必须回本 skill 升级身份卡，禁止下游擅自改 | 身份与渲染脱节，跨章不一致 |
| ❌6 | **定妆图不达标回身份卡，不硬凑渲染** — 角色定妆图不达标时，回身份卡升级版本（改身份），禁止在渲染层硬凑 | 三处各画各的，身份漂移，下游全跑偏 |
| ❌7 | **三把锁差异化先行** — 设计角色前先定全局唯一位置（剪影签名/签名色/记忆锚点），同书互比不撞；记忆锚点按重要度分级（主角2-3个组合/配角1个），过不了置换测试即回炉 | 角色"属性堆砌"，跨书辨识度低，同书角色撞脸 |
| ❌8 | **定妆照是纯生产材料** — 角色定妆必须产出纯净定妆图，**无文字、无装饰元素、无文化元素**，只做全下游（oc/cover/comic）的生产参考，禁止混合OC展示功能 | 定妆图混杂展示元素，下游使用时无法直接复用为参考图 |
