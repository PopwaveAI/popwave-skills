# pop-visual-comic

> 网文漫画连载管线。DeepSeek 做编剧和项目管理（场景拆分、导演卡、提示词产出、管角色库、记状态），Seedream 做画师（8并发出多格漫画页），HTML 做长条滚动展示+文字叠加层。v7.5.3

## 这个 Skill 做什么

把长篇小说逐章变成漫画连载。通过 **Seedream 直出多格漫画页 + 冻结提示词 + 双角度定妆图 + 分层记忆机制**，解决 DeepSeek 无视觉能力下的跨章人设/画风一致性问题。

**v7.4.0 核心变化（高级角色设计层）**：解决"立绘廉价没特色、千篇一律"根因。现有"美型"只解决画得好看、不解决画得独特。新增 `pop-visual-character/references/advanced-character-design.md`——角色设计金字塔（剪影/色彩/细节三层）+ 反类型化 + 符号与行为撕裂感 + 从原著提取视觉锚点（五问提取法）。**所有主角/重要配角立绘，组装规格表前必须先读该文件，用"偏科"思维写规格表，禁止落入"黑发+白T+卫衣+牛仔裤+标准网感脸"的平均值陷阱。**

**v7.3.0 核心变化（文字控制铁律）**：2026-08-03 实测确认 Seedream 生成的文字（伪汉字/数字）基本不可用。全库新增"文字控制"铁律——**对话类文字（气泡/对话框/拟声字）由 HTML 承载，Seedream 只画"开口说话"的画面；环境文字（日记/书本/招牌/符咒）允许乱字作装饰**。负面词升级为逐字列举锁定版（NEG_DIALOGUE / NEG_STRONG），见 `references/content-layer.md` §六。

**v7.2.0 核心变化（画风随赛道动态选 + 立绘质量升级）**：画风库从"唯一基准元尊V1"升级为"**多画风基准池**"——画风不再定死，跟随小说风格类型选（仙侠/玄幻/史诗→厚涂玄幻史诗，国漫玄幻/古风→元尊V1，赛博朋克→韩漫暗黑厚涂待入库）。同时老板定调"**立绘 OC 图基本决定成品漫画质量**"，立绘升级为高精度模板（4块结构：锁构图+锁光源+锁材质+锁硬约束）作为全书质量上限，立绘画风与页面画风同源（跟随所选基准）。

**v7.1.0 核心变化（画风硬边界定型）**：R4-R10 实测确认 **Seedream 多格直出时画风纯度与排版结构互斥**——单格可达 65-70% 赛璐璐纯度，直出多格必掉到 20-40%。定型生产路线：**常规叙事页直出多格、接受半赛璐璐**（保住排版结构/色彩分区/叙事流），**S级名场面/章末钩子页用 YZ-8 全幅单格独立生图**（纯度最高）。画风改进点仅在单格独立生图时有效。

**v7.0.0 核心变化（工程化复现重构）**：清空美术层，从"数学符自由发挥"改为"**成熟漫画工程化复现**"。美术层收敛为三大支柱，全部来自元尊真实页面+Seedream实测已验证：
- **画风基准库**（`references/art-style-baseline.md`）：**多画风基准池**（入库 `元尊V1` 赛璐璐+书法墨线 / `厚涂玄幻史诗` 无线稿厚涂 两个基准），**按小说赛道选基准**，换题材只换配色，不换画风底盘
- **排版基准库**（`references/layout-baseline.md`）：只留元尊 YZ-1~8 八个已验证分页结构，丢掉从零发明的12种花样
- **内容层**（`references/content-layer.md`）：合并镜语/构图/整页语法，管"每格内容怎么填"（L/C/F三码+情绪映射+三重锁定+台词气泡）

**核心铁律**：画风、排版这两根"底盘"是固定的，换题材只换配色和内容，不换画风底盘和排版结构。保证任何题材都交付同等级画风+排版质量。

输入：小说项目（含角色库.md / 正文 / 力量体系.md 等）
输出：每章多页漫画（Seedream 直出 page1~N.png）+ HTML 文字叠加页面 + 长图截图 + 持久化的角色定妆库 + 连载状态管理文件

核心管线：**Step 0 初始化**（一次性定画风+定OC）→ **Step 1 场景拆分**（读章节→拆场景表+台词）→ **Step 2 导演卡定稿**（改编分析+镜语分配+台词气泡+提示词产出）→ **Step 3 生成+审核**（8并发生成+HTML+审核+记忆沉淀）

## 怎么运作

### Step 0: 项目初始化 → `steps/step0-init.md`（一次性）

- 读取项目设定（优先 `素材/视觉资产/`，回退角色库.md）
- **定画风**：从 `references/art-style-baseline.md` **按小说赛道选基准**（仙侠/玄幻/史诗→厚涂玄幻，国漫玄幻/古风→元尊V1），换题材只换配色
- **定OC**：七维度规格表 → **高精度双角度立绘**（正面+侧面，4块硬约束）→ 知名IP二创融合
- **🚪 门禁0：画风+OC双确认**
- 冻结：风格三字段→漫画快照.md / 双角度提示词→漫画角色库.md
- 创建四个记忆文件

### Step 1: 场景拆分 → `steps/step1-scene-breakdown.md`（循环）

- 读 漫画状态.md + 漫画角色库.md + 漫画快照.md
- 读小说正文 ch{NNN}.txt → **页数规划**（信息负载评估→轻/中/重→页数预算+叙事引擎修正）
- **以页思路拆场景表**：时间/地点/出场人物/剧情概述/记忆锚定·高光表现/台词
- 标注不可画内容（`[独白]`/`[系统]`/`[设定]`/`[闪回]`）供 Step 2 改编
- 标注角色外观变化供 Step 3 增量定妆图
- 产出 **场景表.md**

### Step 2: 导演卡定稿 → `steps/step2-director-card.md`（循环）

- 读场景表 + 角色库 + 快照
- **改编分析（故事层）**：改编灵魂 → 叙事引擎 → 叙事主线 → 关键信息审计 → 改编策略
- **页面设计（页层）**：**整页系统（先定）**（content-layer §二：色彩分区/权力姿态/垂直轴线/破框/蒙太奇/完成度）→ 页面设计表（功能位/格数/排版模板/格布局/镜语/台词气泡/每格内容/视觉重心/页间衔接）+ 张力布局强制规则 + **镜语分配**（每格 L/C/F 三码，情绪→镜语强制映射）+ **台词气泡分配** + 拟声字规划
- **提示词产出（提示词层）**：6段式PE范式（每格 L/C 码必带）+ 排版基准库（layout-baseline 元尊YZ-1~8）+ 画风基准库（art-style-baseline 元尊V1）+ 多角色三重锁定 → 持久化到 storyboard.md
- **高光设计**：高光独占页 + 名场面识别 + 张力构建 + 冲击帧提示词方向
- 产出 **导演卡.md** + **storyboard.md**
- **🚪 门禁：导演卡+提示词确认**

### Step 3: 生成+审核 → `steps/step3-production-review.md`（每章）

- 增量定妆图（如有变化）→ **8并发生成**（generate_comic_page.py，ThreadPoolExecutor 8线程）
- **长条滚动 HTML**（漫画页图片+文字叠加，纯 HTML+CSS 零 JS）
- **截图分享**（可选）
- **产出检查** + **感染力评审**（五维：叙事流/页面节奏/情绪钉子/角色一致性/扫描测试）
- 记忆沉淀：append 视觉沉淀.md + 更新 漫画快照.md + 漫画状态.md

## 记忆机制

| 文件 | 层级 | 更新方式 | 作用 |
|:-----|:-----|:---------|:-----|
| `漫画角色库.md` | 长期 | 增量更新 | 角色规格表+冻结提示词+双角度定妆图资产+决策日志 |
| `漫画快照.md` | 中期 | replace | 章节清单+风格锚定串+角色出场记录 |
| `漫画状态.md` | 短期 | replace | 当前章位+角色状态+上章问题+注意事项 |
| `视觉沉淀.md` | 审稿 | append-only | 每章一致性判断+问题记录+改进规则 |

> 漫画角色库.md 的每个角色含四层结构：规格表（人读）→ 冻结提示词（API读，真相源）→ 双角度定妆图资产（版本管理）→ 决策日志（append-only）。

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **冻结提示词是角色一致性唯一真相源** — 角色定妆图生成后，提示词立即冻结到漫画角色库.md。后续章节直接引用冻结版，禁止重新从规格表组装提示词。角色外观变化时基于冻结版+变化描述生成新版本，新提示词同样冻结 | 跨章角色漂移，同一角色画出不同的人 |
| ❌2 | **每页必须生成且有文字叠加** — `generate_comic_page.py` 必须为导演卡页面设计表的每一页生成漫画图。`index.html` 必须包含全部页面图片，且每页的文字叠加（旁白/对白）不得遗漏。文字叠加位置不得遮挡画面关键信息 | 页面遗漏导致剧情断裂，文字缺失导致信息丢失 |
| ❌3 | **每章生成后必须走 Step 3 审核** — 更新记忆文件（角色库/快照/状态/沉淀），不得连续生成两章不审核 | 记忆断裂，下章不知道上章角色外观变化和视觉问题 |
| ❌4 | **定妆图持久化在 assets/characters/ 且使用双角度格式** — 定妆图存放在项目级 `assets/characters/` 目录，跨章复用，版本递增。每个角色每个版本必须生成正面立绘（`-front.png`）和侧面立绘（`-side.png`） | 定妆图随章节散落无法复用；单角度导致侧面/半侧面机位角色漂移 |
| ❌5 | **每格提示词必带镜语 L/C 码** — Step 2 镜语分配必须为页面设计表每一格选择 `L{镜头}+C{构图}+F{特效}` 三码，提示词组装时 L/C 码必带、F 码如非必要省略。禁止无构图的中庸平铺描述 | 画面平庸、张力弱（用户明确反馈"画风平庸张力很弱"） |
| ❌6 | **对话类文字由 HTML 承载，Seedream 只画开口画面** — 画面内禁止出现对话气泡/对话框/拟声字（负面词用 NEG_DIALOGUE 锁定版，含 `speech bubbles/dialogue balloons/dialogue text`）。环境文字（日记/书本/招牌/符咒）允许乱字作装饰，但 Panel 描述禁止 `handwriting/label/banner/sign/writing/text/数字` 等主动触发文字渲染的词。对话内容由 HTML 气泡叠加 | 伪对话场景出现乱字气泡，完全不可用且无法修复（用户明确痛点） |

## 前置条件

1. Python 3.8+ + Pillow（图片转码/压缩/拼接）
2. 浏览器 + Python http.server（HTML 漫画页面预览）
3. Playwright（截长图，可选：`pip install playwright && playwright install chromium`）
4. `ARK_API_KEY` 环境变量（火山引擎方舟 API Key）
5. 小说项目已存在（含角色库.md 或 主角设计.md）
6. 输出目录可写
