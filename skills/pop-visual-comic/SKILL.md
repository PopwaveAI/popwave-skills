# pop-visual-comic

> 网文漫画连载管线。DeepSeek 做编剧和项目管理（场景采摘+导演卡、提示词产出、管角色库、记状态），Seedream 做画师（连续出多格漫画页），HTML 做长条滚动展示+文字叠加层。**页漫模式**。**L2 派生层：只消费 `pop-visual-art-bible` 美术设定集，不重建画风/人物。** 当前版本 v8.1.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 这个 Skill 做什么

把长篇小说逐章变成漫画连载。通过 **Seedream 直出多格漫画页 + 冻结提示词 + 双角度定妆图 + 分层记忆机制**，解决 DeepSeek 无视觉能力下的跨章人设/画风一致性问题。

**美术层三大支柱（画风来自美术设定集，排版/内容来自本库）**：
- **画风**（消费 `pop-visual-art-bible` 美术设定集·画风篇）：画风DNA/约束/定标图/seed/色彩基调均来自美术设定集，**禁止自建画风基准**；本库 `references/art-style-baseline.md` 仅保留 §2.5 分镜画风硬边界铁律（Step 1 用）
- **排版基准库**（`references/layout-baseline.md` 页漫 YZ-1~8）：已验证分页结构，禁止自创布局
- **内容层**（`references/content-layer.md`）：管"每格内容怎么填"（L/C/F三码+情绪映射+三重锁定+台词气泡+文字控制）

**核心铁律**：画风（来自美术设定集）、排版这两根"底盘"是固定的，换题材只换配色和内容，不换画风底盘和排版结构。

> 历史版本"核心变化"记录见 `CHANGELOG.md`，SKILL.md 只保留当前版本关键项。

输入：小说项目（含角色库.md / 正文 / 力量体系.md 等）
输出：每章多页漫画（Seedream 直出 page1~N.png）+ HTML 文字叠加页面 + 长图截图 + 持久化的角色定妆库 + 连载状态管理文件

核心管线：**Step 0 初始化**（一次性）→ **Step 1 导演卡定稿**（剧情白描→分镜头处理→改编分析→页面设计→提示词产出）→ **Step 2 生成+审核**（连续出图+HTML+审核+记忆沉淀）

## 页漫模式（唯一模式）

> 全书统一走页漫：**一页多格**（YZ-1~8 分页）。排版基准 `references/layout-baseline.md`，分格用页面设计表（页级），节奏靠翻页+格内布置，HTML 长条滚动（每页一张图）。条漫模式已剥离归档（见 `CHANGELOG.md` v7.13.0）。

## 模型说明

| 生成内容 | 工具/方式 | 说明 |
|:-----|:---------|:-----|
| 定妆+漫画页（默认 Pro） | `image_generate` 工具 | 文生图/图生图/多图输入，无 API Key |

## 怎么运作（SOP全内联）

**执行模式**：Step 1 导演卡定稿与 🚪 门禁确认（用户多轮交互确认创作决策）、Step 0 初始化落盘、Step 2 生成+HTML+脚本+记忆沉淀（调工具与落盘）**主agent直执**；Step 1 剧情白描与原文采摘提取、三级门禁①原文保真核验、Step 2 感染力评审+0基础可读性检查（只读类：读原文/文本层核验）可派子agent执行并回报结果，**落盘一律归主agent**。

> 三层推导：**故事→页面→提示词**，自上而下不能反过来。Step 1 是创意核心（所有创作决策在此完成），Step 2 只执行不决策。**生成后立即审核**——不连续生成两章不审核（记忆断裂导致下章角色状态和视觉问题丢失）。

### Step 0: 项目初始化（一次性）

> comic 是 L2 派生层，只消费美术设定集，不重建画风/角色身份；只做两件事：**把美术设定集冻结资产转成 comic 渲染格式（双角度定妆图）**、**冻结到记忆文件**。不做门禁0的画风/OC重确认（art-bible ❌4：美术设定集是唯一视觉真源，comic 只改渲染格式不改视觉事实）。

**🚪 美术设定集唯一入口门禁**：读取 `素材/美术设定集.md`——

| 检测结果 | 处理 |
|:---------|:-----|
| 存在且 `✅ 已认可` | 进入消费流程 |
| 存在但 `待认可` | 中止，提示先跑 `pop-visual-art-bible` 确认冻结 |
| 缺失 | 中止，提示先跑 `pop-visual-pipeline` 基建（asset→style→art-bible） |

> 禁止自建画风基准（art-style-baseline 自选）、自建OC规格表、做门禁0重确认——这些是基建层职责。

**消费画风**（画风篇 → 漫画快照/角色库顶部）：

| 画风篇字段 | 用途 |
|:-----|:-----|
| 画风DNA | Seedream 执行串（画风串开头） |
| 画风约束 | 风格保真约束（提示词末尾） |
| 定标图 | 双角度定妆图参考图（图生图 image 参数） |
| 复现 seed | 沿用，保证画风一致 |
| 色彩基调 | 全漫画用色上限（主色≤3+辅助≤2），撞色即废 |

**消费角色 + 双角度渲染**（人物篇 → 定妆图）：
1. **角色筛选**：主角/出场≥2章配角必出双角度定妆图；只出场1章配角不需要（分镜提示词中描述）
2. **取角色本体**：每角色取本体描述（三层：剪影/色彩/细节 + 反类型化 + 撕裂感 + 冻结提示词）
3. **双角度渲染**：按 `references/oc-design-guide.md` §高精度立绘（4块结构：锁构图+锁光源+锁材质+锁硬约束）组装提示词 → 正面 `char-{名}-v1-front.png`（定面部+服装）+ 侧面 `char-{名}-v1-side.png`（传正面作参考，锁轮廓+发型）→ 存 `assets/characters/`，版本递增
4. **技术动作，不设确认闸口**（身份已认可；生成偏离美术设定集人物篇描述 → 回 art-bible 升级设定集版本，不在此处重新确认）

**冻结 + 创建记忆文件**：画风字段（DNA/约束/seed/定标图/色彩基调）写入 `漫画快照.md`+`漫画角色库.md` 顶部（此后全系列冻结）；每角色正面+侧面完整提示词原文冻结到 `漫画角色库.md`（后续章节直接引用不重新组装）。按「记忆机制」表创建四个记忆文件（角色库/快照用 `templates/*.tpl`，视觉沉淀空文件）。确认 `assets/characters/` 已有全部角色双角度定妆图。

### Step 1: 导演卡定稿（循环）

> 读记忆+原文 → **①剧情白描** → **②分镜头处理** → **③改编分析** → **④页面设计** → **⑤提示词产出** → 三级对齐门禁 → 产出导演卡+storyboard → 🚪门禁确认

| 阶段 | 回答的问题 | 动作 |
|:-----|:-----------|:-----|
| ① 剧情白描 | 这章**讲了一个什么故事** | 白描式完整故事弧线（讲清因果/动机/转折） |
| ② 分镜头处理 | 故事**怎么拆成页和镜** | 因果单元→页数反推→以页拆采摘表→镜语预分 |
| ③ 改编创作 | 漫画**怎么表达** | 改编灵魂/叙事引擎/关键信息审计/改编策略 |
| ④ 页面设计 | 每页**怎么呈现** | 整页系统/页面设计表/镜语/台词/信息页 |
| ⑤ 提示词产出 | 每格**怎么画** | 6段式PE/三重锁定/持久化 storyboard |

> **为什么先白描再分镜**：漫画"画得漂亮但没讲清剧情"的病根是信息被压缩成点状概述——导演卡"剧情概述"列是概述式而非白描式，因果/动机/转折在"讲清"层面断裂。必须先把整章写成白描式完整故事弧线，分镜和导演卡的一切从白描派生。**白描是"讲什么"，分镜是"怎么讲"，导演卡是"怎么画"。先讲清，再拍，再画。** 落盘仍为一张导演卡（白描段内嵌顶部 §「剧情白描」，采摘表内嵌 §「原文采摘」，不再单独产场景表）。

**输入**：读 `漫画状态.md`（当前章位/角色外观变化/上章视觉问题/注意事项）+ `漫画角色库.md`（定妆图路径+冻结提示词）+ `漫画快照.md`（风格锚定串/已生成章节）+ `正文/ch{NNN}.txt`（用户可指定多章合并，读取全部指定章节）。

#### ① 剧情白描（硬性前置）

> 本阶段只回答"这章讲了一个什么故事"，不做任何分镜/改编决策。白描是分镜和整张导演卡的唯一故事源头。

通读原文，用白描式叙述（画面/情绪/内心融入叙事，像给朋友讲故事的自然流畅方式）写出整章完整故事弧线，**800-2000字**，必须讲清六要素：**谁**（主角+关键出场角色及动机）/ **做了什么**（关键事件，按时间/因果顺序）/ **为什么**（每个关键决策/转折的动机与因果，不跳步）/ **导致什么**（每个行动的直接后果，形成闭环）/ **转折点**（情绪/局势转向处，明确标注）/ **章末悬念**（留给下一章的钩子）。

**写法要求**：①完整弧线不是分点罗列——读完能像给朋友讲故事一样流畅复述；②因果白描——"失忆所以家人不惊讶"这类硬逻辑写透，禁止读者自己脑补；③关键处带画面感和情绪（供分镜直接取用）；④0基础读者只读白描能讲清"谁→为什么→导致什么"；⑤严禁表格式概述/关键词堆砌/只剩结论金句。白描忠实原文因果（不虚构不丢关键信息），用"讲故事"口吻组织。

**白描自检两问**：复述测试（0基础只读白描能否完整复述含因果和动机？不能→补因果白描）+ 信息完整测试（原文关键信息单元——跨场景/转折/设定/钩子——是否都进了白描？漏了→补）。

#### ② 分镜头处理（白描→页/分镜）

> 以白描为唯一输入源拆页，不再直接从原文拆。一章=一话不拆分。**铁律：页数宁多勿少**——少页=压缩旁白=丢因果=读者看不懂（第1章6页实测：章节预算给少是讲不清故事的核心根因）。

**页数规划（0基础可读性反推）**：先算承载量再定页数，**禁止先定页数再压缩文字**。从白描拆因果单元（起因/发展/转折/决策/后果/悬念），统计：**N_cause**（讲清主线因果链至少需要的旁白条数，每条≤80字）、**S**（场景数，时间/地点切换次数，每个新场景至少1页建立认知）、**H**（名场面/高光数，三标准满足两条的每个独占1页）、**I**（信息页数）。

```
核心页数 = max( ceil(N_cause / 每页因果旁白数) , S )    每页因果旁白数 = 1~2（每页2-4条文字中至少1条讲因果）
总页数   = 核心页数 + H + I
```

页数保底表（下限只增不减，因果单元多就加页不受封顶）：过渡/概述章4-6页；标准起承转合章6-10页；内容密集章（多线/战斗/设定重）9-14页；高潮/大事件章10-16页。

**文字量反检门禁（页数规划后立即做）**：某页需塞>4条文字或关键旁白>80字→页数不够**加页**，禁止压缩文字；整章因果旁白总数>页数×1.5→加页；0基础读者只读实际要渲染的文字层能否重建因果链，不能→加页。反检不通过=页数预算不足，**禁止拿信息页/精简旁白凑数掩盖**。

**叙事引擎修正**（叠加在总页数上）：渐进揭示引擎（日记/信件/多视角拼图）+1-2页；感官逼近引擎（≥3级感官递进）+1页；同时≥2个引擎+1页。

**以页思路拆采摘表**（内嵌导演卡「原文采摘」段）。拆分原则：情绪转折点=页面分割线；场景切换=页面分割线；高光独占（反应型/转折型/震撼型独占一页或一格大格）；每页视觉信息量大致均衡；避免纯对话页（两人站着说话是最差的漫画画面，合并到有动作的页）。

| 采摘表字段 | 提取要求 |
|:-----|:---------|
| 页码/时间/地点 | 原文明确的值，无则推断 |
| 出场人物 | 本页有台词或动作的角色 |
| 剧情概述（白描切片） | **从白描切出本页对应叙事片段**（2-3句，保持白描式），非重新从原文概述 |
| 白描因果链 | 本页要讲清的因果（为什么这么做→导致什么），防概述式丢因果 |
| 记忆锚定/高光表现 | 本页最值得"看到"的瞬间 |
| 台词 | 说话者+对白（原文关键句≤30字）+情绪标签（哀求/冷笑/决绝/崩溃，供推导镜语和气泡样式），每页≤3条 |

**不可画内容标注**：`[独白]`（内心独白）/`[系统]`（系统数值）/`[设定]`（世界观设定）/`[闪回]`（记忆闪回），供③改编分析转化为视觉方案。

**角色外观变化识别**（对比角色库当前版本）：换装/受伤/变身/年龄跳变→采摘表对应页码标注 `【变化:角色名-变化描述】`→Step 2 增量定妆图；临时状态（脏污/淋湿）→提示词中描述，不出增量。

#### ③ 改编分析（故事层）

> 参考 `references/guides/adaptation-guide.md` — 选帧原则/改编策略/四种转化方案/名场面设计/张力构建。

- **改编灵魂**（3问定调）：灵魂冲突 `{角色} vs {对立面}的{冲突本质}` + 避开俗套 + 求新钩子 `{视觉化独有点}`（只有漫画能表现的）
- **叙事引擎识别**：引擎类型（渐进揭示/感官逼近/时间线断裂/因果链驱动/反转颠覆，可多选）+ 不可压缩节奏（标注靠逐条/逐层递进产生效果的段落+最少展开格数）+ 叙事体验保护声明 `本章叙事体验核心：{读者跟着角色{做什么}，逐{层/条/级}{发现/感受}到{什么}}`
- **叙事主线**：一句话故事 `{谁}在{什么情境}下做了{什么决策/行动}，导致了{什么后果}`；因果链（起因1页→发展1-2页→决策1页大单页→后果1页）；主副线（A-story 60-70%享最佳页位 / B-story 20-30%服务A-story）；情感曲线（因果链每环节标情绪标签+强度+转折点，**情感转折点=页面分割线**）
- **关键信息审计**：S级（丢了完全看不懂主线，独占页或大格，**S级≤3条**）/ A级（丢了影响理解但不致命，正常格）/ B级（世界观增色不影响主线，合并或旁白）。恐怖前提/情感前提/角色动机即使非S级也必须保留
- **改编策略**（对不可画内容逐条定）：直接选帧（信息有视觉化场面）/ 视觉转化（关键但无直接画面，走 adaptation-guide 四种转化方案）/ 旁白浓缩（旁白条每条上限80字；关键旁白——因果链/关键剧情/恐怖前提/章末钩子——可直接放宽至80字，禁止为压缩而压缩丢剧情；信息量超单条80字或需集中交代世界观/角色背景时**升级为信息页**）/ 砍掉（非关键信息）

#### ④ 页面设计（页层）

> 必读：`references/content-layer.md` §二（整页系统）+ `references/guides/adaptation-guide.md`（页面分割/格布局/张力布局）+ `references/layout-baseline.md`（元尊YZ-1~8模板）。

**整页系统设计（必修前置，按 content-layer §2.1 整页设计顺序自上而下）**：①定整页情绪单元（从情感曲线提取本页核心情绪）→②定页级色彩分区（主色系+冷暖/线索色叙事，写进页面设计表备注）→③定跨格编排（是否结构性破框？几个格的情绪蒙太奇累加？）→④定权力姿态（高位/神秘角色背影/侧影不露正脸？）→⑤定垂直象征轴线（纵向页权威格在上/受难格在下？）。**核心顺序：先定整页系统，再排格子，最后进格内镜语。**

**页面设计表**（每页一行）：页码 / 功能位（起承转合）/ 页面类型（多格页·大单页·信息页）/ 格数 / 排版花样 / 格布局 / 镜语 / 台词气泡 / 每格内容概述 / 视觉重心 / 页间衔接。

**镜语分配（强制，必读 `references/content-layer.md` §三）**：为每一格执行——①定情绪（这格要传达什么）②查「情绪→镜语强制映射表」推荐L/C/F组合③在表"镜语"列写 `Lx Cy Fz`（F克制格写`-`）④相邻格镜语必须变化（镜头/构图至少一变）⑤限密度（S级页/名场面从C2/C4/C6/C9/C10选、禁C1三分法；特效每页≤2格带、特效格≤2种）。

**台词气泡分配（强制，解决"丢失的对话文案"痛点）**：①从采摘表台词列取关键对白，去重提纯②逐句分配到具体页+格③控音量：每页2-4条文字（旁白+台词+OS）且**至少1条讲因果的旁白**（旁白讲因果/台词给事件/OS给动机，三层文字法见 adaptation-guide §0基础读者可读性），超4条砍次要④anti站桩：两人对谈连续同页最多3句，之后必须切画面/动作⑤台词带情绪标签，供HTML后处理区分气泡样式。

**信息页设计（半文半图，YZ-INFO）**：**上半50%=Seedream单格大图**（画风统一/漫画沉浸）+ **下半50%=HTML文字块**（文字层物理上只能由HTML承载，Seedream不画可读文字），每页仅1次生成。**禁止纯HTML搭整页**（信息页变"网页"硬插漫画滚动流）、**禁止纯文字无图的信息卡**（必须有图，否则放弃信息页退回旁白浓缩）。**触发条件**：采摘表出现≥2条不可画内容（`[设定]`/`[系统]`/`[背景]`）且单条信息量超80字旁白上限，或需集中交代世界观/角色背景。**结构**：上半与设定相关的场景/象征画面（走提示词层生成，非纯色块）；下半2-4条分条信息每条≤80字，直接摘原文/浓缩，禁止二次创作丢因果。**穿插节奏铁律**：信息页前后必须各有至少1页漫画页，禁止连续2个信息页；一章信息页占页数≤30%，推荐「漫画页×2~3→信息页×1」；触点放"需要消化/建立认知"的节点（开场引子后/新场景前/揭示真相后/转折处），首次出现的世界观/角色背景优先用信息页承载。页面设计表中独占一行：页面类型=信息页、格数=`图文1:1`、格布局=`上漫画+下文字`、镜语只填上半漫画格。信息页文字块仍参与门禁③因果链通读。

**排版花样选择**：从元尊YZ-1~8已验证模板为每页选布局，**禁止自创布局**。

**张力布局强制规则**：恐怖/灵异/悬疑→必须张力布局，禁等分布局；高潮/名场面→必须大单页或张力布局，禁等分多格页；精神动摇/混乱→必须倾斜分割或破框出血，禁对称/等分。恐怖/悬疑赛道张力布局≥50%页面。

**高光设计**：高光独占页表（原文高光时刻独占至少一页或一格大格）；名场面识别三标准（视觉奇观/情绪爆发/剧情转折，满足两条=名场面，每章至少1个）；张力构建技法（尺度对比/静默铺垫/反应镜头/视觉隐喻/留白截断）；冲击帧提示词方向写"后果和感受"，不写"发生了什么"。

#### 导演卡硬性核查（产出前必检）

**三级对齐门禁**（核心不可省；**先对原文再对自洽，否则会"自洽地错"**）：

| 级 | 检查对象 | 锁什么 |
|:--:|:---------|:-------|
| ① | 导演卡 vs **原文** | 保真（不丢、不虚）：提取 `正文/ch{NNN}.txt` 全部关键信息单元逐条核验承载，**S级保真率≥80%**；同时反查导演卡每个新增因果有原文出处，找不到出处=虚构补写=打回（除非标注"改编补写"且经认可） |
| ② | 画面白描 vs **旁白/OS/台词** | 自洽（同一件事）：每格画面白描与该格文字逐格比对，画面讲密谋旁白讲灯火=❌对不齐，回页面设计表改画面概述或补承载 |
| ③ | **实际渲染文字层** vs **0基础读者** | 可读：把实际要渲染到 页面配置.json 的旁白+OS+台词按阅读顺序串读，只读这些文字能否讲清"起因→发展→决策→后果→章末悬念"。**禁止用导演卡自写完整叙事段替代**（否则"自洽地通读"却交付碎片）。断点（动机缺失/关键事件无解释/规则未渲染/时空不清/因果断裂）→补**讲因果的旁白**，非只补OS反应句 |

**11 项硬性核查表**（全部通过才可产出；只留"错了会返工/会断裂"的项，其余细分——拟声字/完成度/文化元素/负面约束/三重锁定适用性等——降为产出时默认满足的实现要求，**红线太多约等于没有红线**）：

| # | 硬性核查项 | 不通过则 |
|:-:|:-----------|:---------|
| 1 | S级保真率≥80%，无虚构补写（对原文） | 回②补承载/删虚构 |
| 2 | 画面×旁白逐格对齐，无错位 | 改画面概述或旁白 |
| 3 | 因果链通读可讲清（对实际渲染文字层串读，0基础只读文字可重建因果） | 补讲因果的旁白 |
| 4 | 恐怖/情感前提 + 角色动机未丢 | 回③补策略 |
| 5 | 每格镜语三段式齐全+相邻变化（S级页禁C1） | 回④镜语分配重选 |
| 6 | 特效密度达标（每页≤2格带、≤2种） | 回④削减 |
| 7 | 排版从YZ-1~8库选取+张力页用张力布局 | 回④重选 |
| 8 | 每页唯一视觉重心 | 回④页面设计表调整 |
| 9 | 台词气泡≤4句/页，站桩≤3句 | 回④削减 |
| 10 | 章末有悬念 | 回③/④补钩子 |
| 11 | 信息页不孤立不堆叠（有图半文半图+前后各有漫画页+占页数≤30%） | 回④重排节奏或补图 |

> 门禁不通过→按#打回对应小节，**禁止带保真缺失/虚构补写/画面×文字错位进入 Step 2 生成**（生成后返工成本极高）。

**产出**：`第{N}章/导演卡.md`（模板 `references/guides/director-card-template.md` 直接复制替换占位符；结构：剧情白描/原文采摘/章节概要/叙事引擎/叙事主线/改编灵魂/角色变化记录/改编分析/页面设计/页面提示词/高光设计/文化元素设计（仅古风赛道）/硬性核查填写结果）+ `第{N}章/storyboard.md`。

**🚪 门禁：导演卡+提示词确认**（主agent直执）。向用户呈现导演卡全文和 storyboard.md，核心确认7项：①改编灵魂（灵魂冲突+俗套避开+求新钩子）②叙事主线（一句话故事+因果链+情感曲线）③场景采摘（页数规划合理+关键信息无遗漏+高光独占）④页面设计（分页合理+排版花样匹配+格布局有变化+视觉重心明确+已走整页系统）⑤高光设计（名场面大单页+冲击帧提示词方向正确）⑥镜语分配（每格三码齐全+相邻变化+S级页禁C1+特效密度+台词气泡分配）⑦页面提示词（6段式完整+每格L/C齐全+排版从元尊YZ-1~8选取+多角色三重锁定+负面约束含禁止文字渲染）。用户确认后携带 storyboard.md 进入 Step 2。

### Step 2: 生成+审核（每章）

> 执行+收尾：按导演卡图纸施工，不做创作决策（所有决策已在 Step 1 完成）。

**1. 增量定妆图（如有变化）**：基于当前版本冻结提示词+变化描述组装新提示词 → 生成双角度新版本（front+side）存 `assets/characters/`（版本递增）→ 新提示词冻结到角色库 → 更新增量定妆表和决策日志。无变化的章节跳过。

**2. 生图（任务清单导出 + image_generate 工具）**：`generate_comic_page.py` 不直连生图API、不内置Key，只负责解析提示词/校验尺寸/导出任务清单。

- **配置脚本**：从 storyboard.md 读取每页提示词和参考图（**复制不重新组装**），写入 `PAGES` 列表，每项 `{"id": "page1", "prompt": "{storyboard P1完整6段式提示词}", "ref_images": ["char-{角色名}-v{N}-front.png", "char-{角色名}-v{N}-side.png"], "size": "1125x1500"}`；`OUTPUT_DIR = r"第{N}章/output"`，`CHAR_ASSETS_DIR = r"assets/characters"`
- **导出任务清单**：`python "{本skill路径}/scripts/generate_comic_page.py"` → 输出 `output/generation_tasks.json`（每页 id/prompt/size/ref_images/output_path）
- **批量生成（单 turn 一次发完，禁止逐张等完成）**：读取任务清单，**在一个回复里连续调用全部页（含增量定妆图）的 `image_generate`**（prompt/size/output 按任务；有 ref_images 传参考图路径，图生图保角色一致）。⚠️ `image_generate` 是**异步工具**，逐张调用（发一张→结束turn→重复守卫警告→醒来只收第一张）会导致**后续页全部漏掉**——这就是"只出第一张/跑一半中断"的根因。系统支持同 session 多任务排队，每页 prompt 不同不触发重复守卫。全部发出后结束 turn 让任务后台排队逐个投递；收齐全部页后统一进入产出检查+评审；中途单页失败/failed 只记录不中断，收齐后补发该页单次 `image_generate`
- **格式校验**：全部页收齐后统一做（扩展名与实际字节一致，JPEG 转码真 PNG），不逐页校验；超时/失败未收到的页补发单次调用

**3. 长条滚动 HTML**（必读 `references/guides/page-layout-guide.md` — 完整 HTML 模板+文字叠加 CSS）：
- 创建 `第{N}章/页面配置.json`：`title`/`subtitle`（第{N}章·章节名）/`pages_dir`(output)/`output_html`(index.html)/`pages`（每页 `file`+`captions`：`{"type": "narration"|"dialogue", "text": "...", "position": "bottom"|"top-right"}`）。文字叠加两类：旁白条 `.caption-narration`（旁白/独白/环境描写）+ 对白气泡 `.caption-dialogue`（角色台词）。大单页通常不加文字——名场面画面自说
- 按 page-layout-guide 的 HTML 模板结构生成 `index.html`（纯 HTML+CSS 零 JS），**禁止手写简化版绕过模板**（实测导致品牌水印 slogan/footer 全丢）
- **品牌水印强制注入（必做工程兜底）**：`python "{本skill路径}/scripts/inject_watermark.py" "{漫画项目}/第{N}章/index.html"` — 脚本幂等注入标题区 slogan `popwave.cn 让创意一键落地` + 页脚 footer `未完待续 · popwave.cn 让创意一键落地` 并校验三要素齐全，校验不过 ERROR exit 1，**禁止跳过/发布无品牌水印的漫画**
- 本地预览：`cd "{漫画项目}/第{N}章"; python -m http.server 8000`

**4. 按页导出分享图 + 整条长图（必做）**：分享是"一张一张图去分享"，不只看整条长图——
- `python "{本skill路径}/scripts/export_pages.py" "{漫画项目}/第{N}章/index.html"`：Playwright 逐页截图 **`.page` + `.info-page` 容器**（含文字叠加层，信息页文字不丢）→ Pillow 底部追加品牌水印条（暗红分隔线+`popwave.cn 让创意一键落地`）→ `分享/page01~N.png`。**产出校验**：分享/页数=导演卡页数、每张底部必有品牌水印条，缺失即打回——禁止发无品牌水印的分页分享图
- **整条长图**：逐元素拼接（title-banner+漫画页+信息页+footer-banner）→ `分享/长图-{章节名}.png`（非 full_page 全页截图，免底部质量退化）。分页与长图统一放 `分享/`
- 整条截图备选：`python "{本skill路径}/scripts/screenshot_comic.py" "{index.html}" "{长图输出}"`

**5. 产出检查**：页数完整（导演卡每页 page{N}.png 全存在）/ 图片格式全真 PNG（magic bytes `89 50 4E 47`）/ index.html 落盘且图片引用路径正确 / 品牌水印三要素齐全（slogan+footer，缺失即打回）/ 分享图页数+水印齐全 / storyboard.md + 导演卡.md 已落盘。

**6. 感染力评审**（**模型无视觉能力，不读图不看画面**，全部基于导演卡+storyboard+页面配置.json 文本层核验；画面效果交用户目检）：

| 维度 | 检查对象（文本） | 通过标准 |
|:-----|:---------|:---------|
| 叙事流 | 页面配置.json 全部旁白/对白/OS串起来 | 不看原文能理解"谁做了什么、为什么、导致了什么"，因果链完整 |
| 页面节奏 | 页面设计表页面类型/格数 | 相邻页类型有变化，无连续3页相同节奏 |
| 情绪钉子 | 高光设计表 | 至少一页"名场面/大单页"承载核心情绪爆发 |
| 角色一致性 | storyboard ref_images 字段 | 每页参考图与角色库版本对应，无遗漏/错配 |
| 扫描测试 | 页面配置.json 文字层 | 只看旁白/对白能读出完整故事弧（起因→后果） |

**0基础可读性检查（审稿门禁，不通过不得进入记忆沉淀）**：无纯画面无文字页（每页至少1条旁白/台词/OS）/ 因果链完整（旁白+OS串起来讲清谁→做了什么→为什么→导致了什么）/ 关键异变·规则·时空有旁白交代 / 主角决策有 OS 或旁白说明动机 / 开场引子（第1章标题下交代人物+处境+悬念）/ 文字不遮关键画面（每页≤4条，不压表情/道具/表盘）。方法论见 adaptation-guide §0基础读者可读性（三层文字法）。⚠️记录即可不阻断；❌记录问题并在下章导演卡改进。

**7. 记忆沉淀**：
- **append `视觉沉淀.md`**：`## 第{N}章审核 | {日期}` — 产出状态（页数 N/N、HTML/长图/storyboard/导演卡 ✅）+ 五维评审逐项 ✅/⚠️/❌+说明 + 定妆图使用（角色名: v{N}（出场页码））+ 问题记录&改进规则（{问题}→{规则}）
- **replace `漫画快照.md`**：章节清单追加本章 + 角色出场记录更新 + 风格锚定串不变 + 已知视觉问题池从沉淀提取
- **replace `漫画状态.md`**：当前章位→下一章 + 角色状态（当前外观版本+描述）+ 上一章问题从沉淀提取 + 注意事项（如"角色已换装，需使用v2定妆图"）

**完成路由**：还有下一章 → 回 Step 1；本卷结束 → 通知用户。

## 🚪 首次对话引导（onboarding）

> 视觉专家的首次对话引导**由 `pop-visual-pipeline` 统一负责**（`../pop-visual-pipeline/references/onboarding-guide.md`，介绍整套视觉工程 + 意图闸口）。本派生层不单独引导——用户第一次触发视觉专家时从总入口进入，由 pipeline 引导后按其 intent 路由到本漫画环节。
>
> 若用户直接触发本专家且确认为首次对话（无漫画项目、非续写），也可复用 pipeline 的 `../pop-visual-pipeline/references/onboarding-guide.md` 引导语作总入口介绍，再进入 Step 0。
>
> `templates/onboarding.html` 为可选的视觉版展示（单文件 base64 内嵌约 0.5MB，发给任何用户不裂图），仅在需"哇效果"视觉演示时使用。

## 记忆机制

| 文件 | 层级 | 更新方式 | 模板/内容 | 作用 |
|:-----|:-----|:---------|:-----|:-----|
| `漫画角色库.md` | 长期 | 增量更新 | `templates/漫画角色库.md.tpl`（全角色四层结构） | 角色规格表+冻结提示词+双角度定妆图资产+决策日志 |
| `漫画快照.md` | 中期 | replace | `templates/漫画快照.md.tpl`（风格锚定串+角色清单+空章节清单） | 章节清单+风格锚定串+角色出场记录 |
| `漫画状态.md` | 短期 | replace | `templates/漫画状态.md.tpl`（初始：当前章=第1章） | 当前章位+角色状态+上章问题+注意事项 |
| `视觉沉淀.md` | 审稿 | append-only | 无模板（空文件起） | 每章一致性判断+问题记录+改进规则 |

> 漫画角色库.md 的每个角色含四层结构：规格表（人读）→ 冻结提示词（API读，真相源）→ 双角度定妆图资产（版本管理）→ 决策日志（append-only）。

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **冻结提示词是角色一致性唯一真相源** — 角色定妆图生成后，提示词立即冻结到漫画角色库.md。后续章节直接引用冻结版，禁止重新从规格表组装提示词。角色外观变化时基于冻结版+变化描述生成新版本，新提示词同样冻结 | 跨章角色漂移，同一角色画出不同的人 |
| ❌2 | **每页必须生成且有文字叠加，禁止纯画面无文字页** — `generate_comic_page.py` 必须为导演卡页面设计表的每一页生成漫画图。`index.html` 必须包含全部页面图片，且每页文字叠加（旁白/台词/内心OS）不得遗漏——**0基础读者可读性：禁止"纯画面无文字页"**，每页至少 1 条文字，旁白讲因果/台词给事件/OS给动机（三层文字法见 adaptation-guide §0基础读者可读性）。文字叠加位置不得遮挡画面关键信息 | 页面遗漏导致剧情断裂；文字缺失导致 0基础读者不知道讲了什么（2026-08-04 实测踩坑） |
| ❌3 | **每章生成后必须走 Step 2 审核** — 更新记忆文件（角色库/快照/状态/沉淀），不得连续生成两章不审核 | 记忆断裂，下章不知道上章角色外观变化和视觉问题 |
| ❌4 | **定妆图持久化在 assets/characters/ 且使用双角度格式** — 定妆图存放在项目级 `assets/characters/` 目录，跨章复用，版本递增。每个角色每个版本必须生成正面立绘（`-front.png`）和侧面立绘（`-side.png`） | 定妆图随章节散落无法复用；单角度导致侧面/半侧面机位角色漂移 |
| ❌5 | **每格提示词必带镜语 L/C 码** — Step 1 镜语分配必须为页面设计表每一格选择 `L{镜头}+C{构图}+F{特效}` 三码，提示词组装时 L/C 码必带、F 码如非必要省略。禁止无构图的中庸平铺描述 | 画面平庸、张力弱（用户明确反馈"画风平庸张力很弱"） |
| ❌6 | **对话类文字由 HTML 承载，Seedream 只画开口画面** — 画面内禁止出现对话气泡/对话框/拟声字（负面词用 NEG_DIALOGUE 锁定版，含 `speech bubbles/dialogue balloons/dialogue text`）。环境文字（日记/书本/招牌/符咒）允许乱字作装饰，但 Panel 描述禁止 `handwriting/label/banner/sign/writing/text/数字` 等主动触发文字渲染的词。对话内容由 HTML 气泡叠加 | 伪对话场景出现乱字气泡，完全不可用且无法修复（用户明确痛点） |
| ❌7 | **导演卡产出前必过剧情完整性三级对齐门禁** — Step 1 产出导演卡前必须按顺序执行：①**原文保真**（打开原文 ch{NNN} 提取关键信息单元逐条核验承载，S级保真率≥80%；反查导演卡每个新增因果有原文出处，找不到出处=虚构补写=打回，除非标注"改编补写"且经认可）→ ②**画面×旁白自洽**（每格画面白描 vs 旁白/OS/台词，逐格判定是否讲同一件事，锁"画面讲密谋、旁白讲灯火"的错位）→ ③**因果链通读**（**对着实际渲染文字层——页面配置.json 的旁白+OS+台词——串读**，禁止用导演卡自写完整叙事段替代；0基础读者只读实际文字能否讲清"谁→做了什么→为什么→导致什么"）。**先对原文再对自洽否则会"自洽地错"；不通过必须按级打回，禁止带保真缺失/虚构补写/画面×文字错位进入 Step 2 生成** | 漫画画得漂亮但读者不知道讲了什么，且旧门禁（只看文字自洽）查不出画面×文字错位和虚构补写，返工成本极高（老板校准：第4章实测S级保真仅43%含虚构补写；第1章实测门禁③自评全过但实际渲染仅OS碎片读者看不懂） |
| ❌8 | **index.html 必含品牌水印，禁止手写简化版 HTML 绕过模板** — `index.html` 必须按 `references/guides/page-layout-guide.md` 的品牌水印结构生成：**标题区第三行 slogan `popwave.cn 让创意一键落地` + 页脚 footer `未完待续 · popwave.cn 让创意一键落地`**。禁止手写 `comic-header`/`comic-footer` 简化版模板绕过。Step 2 产出检查必检此项，缺失即打回 | 品牌水印丢失，发出去的漫画无 popwave 署名（2026-08-06 实测：agent 手写简化版 HTML，slogan/footer 全部丢失） |
| ❌9 | **按页导出分享图必须含信息页 + 保留水印 + 长图同放分享/** — `export_pages.py` 必须同时选中 `.page` 和 `.info-page` 容器（否则信息页文字整页丢失），每张截图都走 Pillow 底部品牌水印条；**同时逐元素拼接整条 HTML 长图**（`分享/长图-{章节名}.png`，title+漫画页+信息页+footer 拼接，非 full_page 全页截图以免底部质量退化），分页与长图**统一放 `分享/`**。HTML 旁白条类名只用 `top`/`bottom`/`side-top`/`side-bottom`，**禁用 `top-left`/`top-right` 作旁白类**（无定位规则会错位落页面底部之外）；角色脸放画面中部，旁白条只放顶/底 6% 安全带，避免文字压脸 | 信息页文字+水印丢失（2026-08-07 第4章实测：2个信息页漏切）；旁白类名无规则错位（P1/P6 实测落页面外）；文字压脸；长图未与分页同目录不便管理 |
| ❌10 | **美术设定集是唯一入口，禁止自建画风/OC** — Step 0 必须消费 `素材/美术设定集.md`（存在且 ✅ 已认可）；缺失/未签核 → 中止引导先跑 `pop-visual-art-bible`。禁止用 `art-style-baseline.md` 自选画风基准、自建七维度规格表、做门禁0的画风/OC重确认。画风字段来自美术设定集画风篇，角色本体来自美术设定集人物篇，本步只做双角度渲染格式转换 | 下游重建画风/人物，与美术设定集漂移，跨形态不一致（art-bible ❌4） |

## 前置条件

1. Python 3.8+ + Pillow（图片转码/压缩/拼接）
2. 浏览器 + Python http.server（HTML 漫画页面预览）
3. Playwright（截长图，可选：`pip install playwright && playwright install chromium`）
4. 生图走 `image_generate` 工具（无需任何 API Key。脚本只导出任务清单，不直连生图 API）
5. 小说项目已存在（含角色库.md 或 主角设计.md）
6. 输出目录可写
