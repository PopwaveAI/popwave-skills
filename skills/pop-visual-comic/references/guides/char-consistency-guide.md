# 角色一致性管理指南

> DeepSeek 无视觉能力，如何通过结构化文本管理跨章角色一致性

## 核心问题

DeepSeek 作为主控 agent 没有视觉能力——它看不到定妆图画了什么，也无法判断生成画面中的角色是否一致。传统方案的"看图对比"路径走不通。

## 解决方案：冻结提示词

角色一致性的关键不是"看图"，而是"用同一份指令"。

### 冻结提示词的工作原理

```
第一次生成定妆图:
  Agent 组装提示词 → 发给 API → 得到定妆图
  → 提示词立即冻结到角色库（原文保存，不修改）

后续所有章节:
  Agent 读角色库 → 拿到冻结提示词 → 直接引用（不重新组装）
  → 追加场景/动作描述 → 发给 API
```

**为什么有效**：Seedream 的图生图能力会从参考图（定妆图）中提取角色特征。只要参考图不变、提示词中的角色描述不变，生成的角色就会保持一致。DeepSeek 不需要"看"图，只需要确保"引用的文本不变"。

### 规格表 vs 冻结提示词

| 层 | 给谁看 | 作用 | 修改规则 |
|:---|:-------|:-----|:---------|
| 规格表 | 人/Agent 检索 | 快速了解角色长什么样 | 可修改，不影响生成 |
| 冻结提示词 | API 直接消费 | 角色一致性的真正锚点 | 首次冻结后不改，仅角色变化时追加新版本 |

**Gap 风险**：规格表是语义描述（"亚麻色短发"），冻结提示词是执行指令（完整的 API 原文）。如果每章从规格表重新组装提示词，用词可能不同（"亚麻色"→"浅金色"），导致角色漂移。冻结提示词消除了这层翻译 gap。

## 四层角色结构

### 层1: 规格表（人读）

7 字段：年龄/性别、体型、发色/发型、瞳色、服装、标志性特征。用于快速检索和理解角色外观。

### 层2: 冻结提示词（API 读 — 真相源）

首次生成定妆图时发给 API 的完整提示词原文。后续章节直接引用此文本。

### 层3: 定妆图资产

版本管理表，记录每个版本的路径、冻结提示词、变化说明。版本递增，旧版保留。

### 层4: 决策日志（append-only）

记录"为什么这么画"的决策。append-only，永不删改。

## 增量定妆图机制

角色外观变化（换装/受伤/变身）时，不修改原版本，而是生成新版本：

1. 基于上一版本的冻结提示词 + 变化描述，组装新提示词
2. 传入上一版本定妆图作为参考（图生图）
3. 新提示词中的角色描述部分 = 原冻结提示词 + 变化描述
4. 生成后新提示词冻结为新版本
5. 后续章节使用新版本

```
v1: 初始定妆 → 冻结提示词 v1
v2: 觉醒变化 → 冻结提示词 v1 + "觉醒后瞳色变金" → 冻结提示词 v2
v3: 换装 → 冻结提示词 v2 + "穿着黑色铠甲" → 冻结提示词 v3
```

## 分镜提示词组装规则

每帧提示词 = **冻结提示词的角色描述部分**（直接复制）+ 场景动作描述 + 风格锚定串

**禁止**：从规格表重新组装角色描述。**必须**：从角色库复制冻结提示词原文。

### 多角色同帧处理

Seedream API 的 `image` 参数接收单个 data URI。多角色同框帧的处理策略：

1. **选择主要角色**：以画面中占比最大/最重要的角色作为参考图
2. **次要角色用文字描述**：在提示词中描述次要角色的外观
3. **无角色帧**：不传参考图，直接文生图

## 配角一致性策略

| 配角类型 | 定妆图 | 一致性保障 |
|:---------|:-------|:-----------|
| 出场≥2章 | 强制出定妆图 | 冻结提示词 + 图生图 |
| 只出场1章 | 不需要 | 在分镜提示词中详细描述 |
| 动物配角（如宠物） | 建议出定妆图 | 动物外观一致性同样重要 |

## 质量检查清单

Phase 2 审核时检查（DeepSeek 可执行的检查项）：

- [ ] 所有出场角色在角色库中有对应版本定妆图
- [ ] 每帧提示词的角色描述部分来自冻结提示词（非重新组装）
- [ ] 角色外观变化已生成增量定妆图并更新角色库
- [ ] 定妆图文件存在于 `assets/characters/` 目录
- [ ] 风格锚定串与漫画快照.md 中的冻结版一致
