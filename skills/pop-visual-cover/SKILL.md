# pop-visual-cover

> **脚本调用约定**：本包脚本都在**本包根目录**下的 `scripts/`。本包根目录 = 本 skill 的 SKILL.md 所在目录，即你读取本 SKILL.md 时那个绝对路径的父目录（系统提示 `<available_skills>` 里该 skill 的 `<location>` 也是它），命令行等价于 `--skill` 的取值，逐台机器不同。所以调用一律写成 `python "<包根>\scripts\<脚本>" ...`。
>
> **跨包路径**：要用别的包的脚本或资源，用**那个包自己的包根**，写成 `<包名 包根>`，对端包根 = 该 skill 的 SKILL.md 所在目录，从其 `<location>` 或你读取它的绝对路径取父目录。不要写 `../其它包/...`，也不要写 `skills/<包名>/...`。
>
> **参数**：以脚本自身 `--help` 为准。脚本报错时会打印实际用法。

> 网文封面与场景视觉资产生成器。v2.2.0：默认走「一次确认」快路径，纯文生图封面改用高精度 4 块结构，修正生图工具参数，Pinterest 降为可选。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 做什么

输入：小说项目文件、视觉需求（封面、场景图或素材）与可选的参考图或原文。
输出：生成的图片、设计方案文档与提示词记录。

核心价值：把模糊的画面变成可执行的画面结构，再翻译成模型提示词。**默认只做一次确认**，不把用户拖进多轮流程。

## 工具事实（写死，避免踩坑）

静态图片统一走 `image_generate` 工具（桌面端为 OpenClaw 内置）。下表按桌面端契约写；Web 端若暴露的是其它生图工具，以宿主实际列出的参数为准，不要照搬本表。

| 事项 | 事实 | 你必须怎么做 |
|:-----|:-----|:-------------|
| 模型 | 由后台配置决定（当前可能是 doubao-seedream-4-5 或 5.0），调用方无法指定 | **不要传 `model`**，也不要在提示词里承诺"5.0 Pro" |
| 参考图 | 字段是 `image` / `images` | **禁止写 `ref_image`**，写工具不认，参考图会被静默丢弃 |
| 输出路径 | 工具没有 `output`，只有 `filename` 提示；成品落到 `generated-images/<runId>/` | **禁止写 `output=`**；生成后记录工具返回的图片路径 |
| 尺寸 | `aspectRatio` 有效；`resolution` 是否生效取决于后台模型与链路，不保证精确像素 | 竖版封面用 `aspectRatio='3:4'`；不要写死像素值 |
| 提示词兜底 | 工具层**没有任何质量词、负面词或模板兜底**，prompt 原样上送 | 质量与结构必须写进 prompt，不能指望工具 |

> 工具层只会追加一句宽高比指令。**画面结构、字体排版、负面约束全部由本 skill 负责**，这是封面质量的分水岭。

## 两条路径

**默认走快路径（2 次交互）**：需求简报 → 一张方案卡（一次确认）→ 直接出 3 版 → 迭代。
**精修路径（可选）**：用户明确要求"照着某张图做"或要做系列视觉时，才走 Pinterest 搜图 + 参考点对齐。

> Pinterest 搜索依赖 `BRIGHTDATA_API_KEY` 与本机 python 环境，Web 容器里通常不可用。**搜不到图不得阻塞流程**，直接退回快路径。

## 快路径（默认）

### Step A：需求简报（一次问清）

从用户输入与项目文件里提取，缺的**一次性**问完，不要一问一答挤牙膏：

- 赛道与书名
- 目标读者年龄段（决定画风：12-18 少女→日系动漫；18-25 女性→韩系唯美；25-35 女性→写实电影感；男性→概念艺术）
- 核心卖点一句话（视觉钩子从这句来）
- 画幅（默认 3:4 竖版）
- 是否已有参考图（有则收下路径，走图生图）

无法判断读者年龄时**必须问**，不得默认"甜宠=可爱卡通"。

### Step B：方案卡（唯一一次确认）

用通俗语言给一张卡，**不出现技术 prompt**：

- 视觉钩子：一句话说清读者第一眼看到什么（从 [novel-visual-design.md](references/novel-visual-design.md) §二选 1 种钩子类型）
- 构图：给 3 个方向选 1（从 §四构图骨架库选，例如"中心放射 / 对角线对峙 / L 型竖排"），每个方向一句话说明
- 字体：给 2-3 个方向选 1（毛笔书法 / 宋体衬线 / 黑体无衬线），说明适合的赛道气质
- 主色：给 2 个方向选 1（用色名，不用色值）
- 书名排版：分行方式与位置（上 1/4 或一侧竖排）

用户选完即进入生成。**不得在用户确认前直接出图**；用户说"你定"就按你的推荐直接生成。

### Step C：生成（一次出 3 版）

按下面的「封面 4 块结构」写提示词，同一方案连出 3 版（用 `count=3`，或在同一提示词里换构图细节重跑 3 次），挑最像样的给用户。

### Step D：迭代

用户不满意时按其反馈改对应块，文件名或说明里递增 v2、v3：

| 反馈 | 改哪一块 |
|:-----|:---------|
| 太素、像 AI 图 | 块 1 加镜头焦段与主体占比；块 2 加材质清单；块 4 加"不泛白、不发灰" |
| 构图平 | 块 1 换构图骨架，明确前中后景各占几成、谁虚谁实 |
| 字丑、看不清 | 块 3 调字号占高、字形类别、描边与材质 |
| 颜色脏 | 块 2 改回三色成数，写死唯一主光源 |
| 人物变形 | 块 4 加"五官清晰、人体结构正常、不重复肢体" |

## 封面 4 块结构（纯文生图必用）

> 纯文生图没有参考图提供构图骨架、配色比例与字体版式，**必须把这三层写进提示词**。只写一段自然语言是最容易出"廉价 AI 图"的写法。

```
块1 锁定构图
  镜头规格（焦段+景别）+ 主体位置与占比 + 前中后景各层内容/占比/虚实 + 人物姿态朝向

块2 环境与光影
  唯一主光源 + 方向 + 色温 + 主色/辅色/强调色/点缀色的成数 + 材质清单 + 渲染方式

块3 精确文字排版
  每个文字元素用双引号 + 字号占画面高度 + 分行 + 字形类别 + 材质/描边/投影 + 位置

块4 硬约束
  单一主体、五官清晰、人体结构正常、不重复肢体、不泛白、不发灰、无乱码、无水印
```

### 块 1 写法

- 焦段写具体值：`35mm` 中景人像、`24mm` 广角环境、`85mm` 特写；不写"广角"
- 主体占比写死：主视觉占画面六到七成，文字区留白约两成
- 分层写：远景（环境，占比/虚化）、中景（叙事元素，半剪影）、主体（最高细节密度）、前景（压边道具，纯剪影）
- 群像用"倒三角站位 + 背光剪影"或"只画上半身"，避免手脚崩坏

### 块 2 写法

- 光源只写一个，并声明"为画面唯一主光源"；写方向与色温（如"左后方逆光，暖金 3200K"）
- 配色用成数不用百分比：主色七成、辅色两成、强调色半成、点缀色半成
- 材质清单按画面实际写：布料织纹、金属划痕、雾气粒子、尘埃悬浮、纸张纤维
- 渲染方式落到具体：厚涂可见笔触 / 赛璐璐平涂 / 胶片颗粒 / 水彩湿画法

### 块 3 写法（决定封面像不像商品）

- 书名用双引号包裹，写清字形类别：毛笔书法 / 宋体衬线 / 黑体无衬线（只选一种，不混排）
- 字号：书名占画面高度 **15%-25%**，最多不超过三成；作者名约为书名的四分之一；定场诗不超过书名的五分之一
- 分行：按语义断成 2-3 行，主标题字重最重；禁止一行塞满
- 材质与效果：鎏金、朱砂、墨色、碑刻龟裂；必要时加 1-2px 描边或外发光以脱离背景
- 位置：上 1/4 居中，或一侧竖排；文字与画面有物理交互（被前景雾气、粒子、山体轻微遮挡）
- 必须有这句硬要求：**字形准确可读，禁止错字、乱码、自造字、整段英文**

### 块 4 写法（负面清单是核心增量）

固定写上这几条，按需增补：

```
画面只有一个主体，不重复肢体；人物五官清晰、人体结构正常；
画面不泛白、不发灰、不脏不糊，色彩干净、明暗对比明确；
不出现水印、角标、二维码、签名和与书名无关的额外文字。
```

### 组装示例（中文，全文不超过 400 字）

```
竖版网文封面。35mm 中景，主角立于画面中央偏右，占画面六成；远景为雾中古城，虚化压暗，占两成；前景左下角压一枚断裂剑柄剪影，占一成；左侧留出竖排文字区，占两成。
唯一主光源来自左后方，暖金逆光，勾出人物轮廓；玄黑占七成、暗金两成、赤红半成；材质写清：粗麻衣料织纹、剑身金属划痕、空气里悬浮尘埃。
书名"深渊主宰"用鎏金毛笔书法体，四字竖排于左侧，字高合计约占画面高度两成，带金石碑刻龟裂纹理与轻微外发光；作者名"某某"置于右下角，字号约为书名的四分之一。
画面只有一个主体，不重复肢体；五官清晰、人体结构正常；不泛白、不发灰、不脏不糊；字形准确可读，无乱码；无水印、角标与多余文字。暗黑国风厚涂插画风格。
```

> 有参考图时不要用整块 4 块结构，改走下面的「参考点策略」，把参考图已提供的维度放权。

## 精修路径（可选）

用户明确要"参考这张图"或做系列视觉时执行：

1. **搜图**（可选，最多 6 张）：按风格、角色、IP 三个维度各搜 2-3 个英文表达；用 `<pop-visual-shared 包根>\scripts\pinterest_search.py`，需 `BRIGHTDATA_API_KEY`。
2. **确认点 A**：呈现候选图 + 用户选一张 + 明确"参考它的什么"（全面/色系/构图/画风/光影/字体，可多选）。
3. **方案卡**：同快路径 Step B，但只描述参考图没覆盖的维度。
4. **确认点 B**：方案确认后生成。
5. **生成策略**：用户选了什么参考点，提示词就在那个维度**不写**（详见下表）。

| 参考点 | 提示词要写 | 提示词不写（交给参考图） | 传入方式 |
|:-------|:-----------|:-------------------------|:---------|
| 全面参考 | 仅书名与必要差异 | 画面、色系、构图、画风、光影、字体 | `image=参考图路径`，提示词写"在此基础上仅改…，其余保持" |
| 色系 | 画面、构图、画风、光影、字体 | 配色 | `image=参考图路径`，不写任何颜色词 |
| 构图 | 画面、配色、画风、光影、字体 | 布局与人物位置 | `image=参考图路径`，不写构图词 |
| 画风 | 画面内容、构图、字体 | 画风质感 | `image=参考图路径`，用放开吸收公式（见下） |
| 字体 | 画面、配色、构图、画风、光影 | 字体与排版 | `image=参考图路径`，书名只写内容 |
| 多图组合 | 其余维度 | 各自放权维度 | `images=[图A, 图B]`，逐图说明参考范围 |

**画风参考的放开吸收公式**（不要堆"不参考"清单）：

```
参考这张图的画风质感、色彩系统和光影氛围：[具体吸收要素，如柔和数字插画笔触、通透光效、暖色过渡]。
仅排除图中具体场景内容和人物长相，其余允许自然传导。
以下画面内容完全由本段描述决定：[目标画面详细描述]
```

> 参考图必须是可读路径或 data URI（`data:image/png;base64,...`）。多图时逐张说明参考范围。

## 场景图模式（用户给的是原文时）

场景图从"这段文字在讲什么"出发，不走搜图。核心是理解，不是生成。

1. **视觉资产优先**：`素材/视觉资产/` 下有 `场景资产表.md`、`[角色名]角色档案.md`、`视觉符号库.md` 时直接引用。角色身份以 `pop-visual-art-bible` 产出的「美术设定集·人物篇」为唯一真源，封面只负责把角色放进构图，不得重建角色身份。
2. **原文解构**：拆成可定格帧（帧号、动作、角色、视觉要素），提取角色外观、环境元素、材质细节。
3. **安全转换**：可能触发审核的描述换成视觉等效表达（无头→面部隐入兜帽阴影；鲜血→金色光尘；尸体→消散轮廓）。保留诡异/神圣/危险的氛围，只替换具体描述。
4. **上下文补全**：热门书用 WebSearch 查角色定位与读者印象；原创书查项目文件或直接问用户。
5. **选帧**：按情感峰值、叙事关键、读者共鸣、视觉张力各 1-5 分，选最强的那个瞬间（通常是动作交接点）。
6. **确认点 A（理解确认）**：呈现原文引用、角色身份、场景上下文、文字体验、选定瞬间与理由、安全转换、视觉元素清单，请用户确认或修正。
7. **生成**：设计构图→光影→色彩→焦点，提示词按"整体氛围 + 画面内容（按空间层次）+ 风格"写；可选搜 Pinterest 只作画风参考。

## 生成与落盘

```text
# 纯文生图（无参考图，默认）
image_generate(prompt='<4 块结构提示词>', aspectRatio='3:4', count=3)

# 图生图（精修路径）
image_generate(prompt='<参考点策略提示词>', aspectRatio='3:4', image='<参考图绝对路径>')
```

- 尺寸：竖版封面 `3:4`；横版 banner `16:9`；方图 `1:1`。实际像素由后台配置决定，不要写死；需要更高精度时先在后台确认档位。
- 记录：把模型返回的图片路径、完整提示词、方案卡、用户反馈写入 `_过程/提示词记录.md`。
- 归档：候选图留在工具返回目录；用户确认后把那张标为成品（文件名加 `-final`），记录其路径。
- 品牌水印：**仅在可执行 python 的环境**（桌面端/本地）运行 `<pop-visual-shared 包根>\scripts\watermark.py <图>`。Web 容器只读且无脚本环境时跳过，并在记录里注明"未加水印"。

## 丑图自检（生成前逐条过）

| 检查 | 不合格表现 | 修法 |
|:-----|:-----------|:-----|
| 构图有骨架吗 | 主体居中站桩、没有前后景 | 块 1 补焦段、主体占比、前中后景虚实 |
| 光源唯一吗 | 多处乱光、脸上双影 | 块 2 写"唯一主光源 + 方向 + 色温" |
| 配色干净吗 | 五颜六色、发灰发土 | 块 2 改回七成/两成/半成成数 |
| 书名能读吗 | 字太小、字形糊、乱码 | 块 3 调字号占高（15%-25%）、字形类别、描边 |
| 有材质细节吗 | 塑料感、纯色块 | 块 2 加材质清单（织纹、划痕、粒子、纤维） |
| 有负面约束吗 | 多指、多手、泛白 | 块 4 补齐负面清单 |

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **默认快路径** — 不强制搜图；Pinterest 搜图失败或环境不可用直接退回快路径，不得阻塞 | 流程卡死，用户拿不到图 |
| ❌2 | **只确认一次** — 方案卡确认后才能生成；用户说"你定"按推荐直接出 | 多轮空转，浪费生成次数 |
| ❌3 | **纯文生图封面必须用 4 块结构** — 构图/光影/文字/硬约束四块齐全 | 构图平、画风廉价、字丑 |
| ❌4 | **参数必须真实** — 不传 `model`、不传 `ref_image`、不传 `output`；参考图用 `image`/`images`，尺寸用 `aspectRatio` | 参考图丢失，退化成纯文生图 |
| ❌5 | **文字必须可读** — 字号占高、字形准确、禁止乱码与整段英文 | 封面像半成品 |
| ❌6 | **场景图须经理解管线** — 原文→解构→补全→选帧→确认点 A | 精确地画错画面 |
| ❌7 | **过程与产物可追溯** — 方案卡、提示词、图片路径写入 `_过程/提示词记录.md` | 无法迭代优化 |
