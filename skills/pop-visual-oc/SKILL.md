# pop-visual-oc

> 网文视觉推广素材生成器。OC 即原创设定（Original Creation），不限于人物。当前版本 v7.2.0，完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 做什么

**OC 即原创设定**——不限于人物，涵盖一切可视觉化的设定实体；从原文系统采样，立体化理解后设计视觉展示。

**输入**：小说项目文件、目标实体与可选参考图。**输出**：设定档案与视觉卡（纯立绘零文字底图、HTML 顶部聚字、整图截图）。

**五类内容类型**（信息架构见 `references/content.md`）：

| 类型 | 视觉主体 | 一句话定位 |
|:-----|:---------|:-----------|
| **人物卡** | 角色本人 | 让读者记住这个人 |
| **势力卡** | 阵营/宗门/家族/王朝 | 让读者记住这群人什么气质 |
| **地理卡** | 城市/秘境/位面 | 让读者记住这个地方什么感觉 |
| **规则卡** | 力量体系/境界/功法 | 让抽象规则被"看到" |
| **场景卡** | 关键场景/名场面 | 让读者记住这个高光时刻 |

**唯一范式：立绘优先 · 顶部聚字（V6，全 OC 质量基准）**

> **AI 底图只出纯立绘、不出现文字**（主体占画面不低于 60%，居中下部，顶部留出不低于 40% 的纯净背景），**HTML 只在顶部纯背景区叠加少量核心文字**（类型、名字、称号、一句金句）并**在底部放一个印章**，整图截图即为成品。**质量重心从"文字排版"转向"立绘本身"。**

**范式依据（2026-08 老板定稿）**：字槽混合式（v5）实测 **AI 写字不可控**，因此**不让 AI 承担任何"落实文字"的工作**；质量聚焦于构图、画风、原文理解与二创注入（好看是第一生产力，原文描述不一定好看），放弃复杂的 HTML 排版。

**核心原则**：四条基础律 G1-G4，加二创律 G5（完整约束见铁律表）。

**二创是 OC 的灵魂**：原文理解与好看注入的方法见 `references/二创-method.md`（Step 1 必读）——从原文提取气质要点与核心意象，构图、姿态、光影、动作张力与记忆点由设计者注入，不被原文的朴素描述束缚。

**视觉真源**：视觉本体来自 `pop-visual-art-bible` 美术设定集对应篇（唯一真源，须使用最新版，避免与基线版本产生差异），OC 只负责"怎么画好看"与顶部叠加少量文字，**不得重建设定身份**；构图、姿态、光影由二创注入。

## 怎么运作（规程全内联）

**执行模式**：确认点A（档案确认）与确认点B（方案对齐）需要用户交互确认，设计、生图、组装与截图由**主 agent 直接执行**；Step 0 的原文采样调研（Grep 与 Read 只读工作）可派发子 agent 执行并回报采样结果，再由主 agent 整理写入。

### Step 0: 需求确认与设定调研

**需求确认**（生成前必问，一次性问清）：内容类型（五类卡中属哪一类，不明确时按实体推荐）｜用途与传播场景（社交单图、封面、设定集，影响画幅与信息密度）｜画风偏好（可按参考图标定）｜是否参考生图（全面参考、画风参考、纯文生图）｜画幅（默认 2:3 竖版，可改 4:3 或 16:9）。结果记入 `_过程/提示词记录.md`；无明确偏好时用默认值直接进入调研，不为影响较小的偏好反复打扰。

**资产检查（优先路径）**：用 LS 扫描 `素材/视觉资产/` 寻找对应档案——人物为 `[角色名]角色档案.md`（10 个维度），势力为 `[势力名]势力档案.md`（8 个维度），地理为 `[地名]地理档案.md`（7 个维度），规则为 `[规则名]规则档案.md`（6 个维度），场景为 `场景资产表.md`（记录可定格帧）。存在时校验维度是否完整，再直接进入确认点A；不存在时提示可先行执行 `pop-visual-asset`，或走原文采样（**找不到原文文件时须问用户，不得凭记忆设计**）。

**原文采样（回退路径）**：Grep 按类型轮次搜索（关键词模板，示例实体名）：

| 类型 | 轮次 | 关键词模板 |
|:--|:--|:--|
| 人物 | 5轮 | 角色名 / `名.*(眸\|眼\|甲\|氅\|袍\|发)` / `名.*(霸道\|冷\|笑\|怒)` / 他人评价 / `名.*(父亲\|部下)` |
| 势力 | 4轮 | 势力名 / `名.*(宗门\|家族\|王朝\|教派)` / `名.*(弟子\|族人\|信众)` / `名.*(峰\|城\|宫\|殿\|谷)` |
| 地理 | 4轮 | 地名 / `名.*(山\|海\|渊\|宫\|界\|域)` / `名.*(雾\|光\|暗\|冷\|热)` / `名.*(楼\|殿\|塔\|桥\|街)` |
| 规则 | 4轮 | 规则名 / `名.*(光\|纹\|阵\|雷\|焰\|雾\|印记)` / `名.*(突破\|天象\|雷劫\|金光)` / `名.*(印\|镜\|书\|卷\|符\|剑)` |
| 场景 | 帧定位 | `到了\|进入\|来到\|眼前` / 颜色+器物+动作共现 / `怒\|笑\|吼\|惊` |

对每个命中项读取前后 20 至 50 行，采样分**三层**：表层（外貌、美学、空间描述，即画皮）、中层（气质、秩序、氛围，即画骨）、深层（评价、隐喻、意象，即画魂），每个维度记录 3 至 5 条佐证并标注行号。**二创专用采样**：另记气质要点（性格、身份、处境中最核心的一点）、核心意象与视觉母题（贯穿性符号，如蝉、碑、麒麟）、他人评价与标志台词（可提炼为金句）——这些是 Step 1 二创注入的原料，**魂与符号须取自原文**。

**设定档案**：整理为 `素材/[类型][实体名]档案.md`；方法论：人物部分查 character-research-guide，势力、地理、规则部分查 asset-extract-guide §五、§六、§七（完整路径见速查表·调研方法论）。

**🚪 确认点A：设定档案确认**（强制暂停，不得跳过）——向用户呈现：核心气质｜关键视觉特征（附原文佐证）｜最适合制卡的内容｜核心意象（3 至 5 个符号）｜代表词与口号。**等用户确认后才可进入 Step 1**；档案存入 `素材/`，确认结果追记到 `_过程/提示词记录.md`。

### Step 1: 设计（二创设计、顶部聚字与成图预估）

> 内容见 `references/content.md`（五类信息架构、文案公式与字体系统）；排版见 `references/layout.md`；二创见 `references/二创-method.md`（**设计立绘前必读**）。

**读取输入**：Step 0 的需求、设定档案（气质、视觉、意象、金句）与美术设定集对应篇（`素材/美术设定集.md`，使用最新版）。画幅默认 2:3 竖版，可改 4:3 或 16:9。

**二创设计立绘（核心环节，质量的第一来源）**：好看是第一生产力，立绘是绝对主角。先回答**二创五问**，再按**好看注入六式**选择招式：

| 五问 | 答案（写入方案） |
|:--|:--|
| ① 他的魂是什么？ | 性格、身份、处境中最核心的一点（取自原文） |
| ② 他的符号是什么？ | 贯穿的视觉母题或意象（取自原文，如蝉、碑、麒麟） |
| ③ 他该是什么姿态？ | 用姿态外显①——骄傲就昂首，阴冷就垂眸，癫狂就咧嘴 |
| ④ 他该是什么光？ | 用光影营造②的情绪——神性就金光，压抑就暗部，凄美就冷月 |
| ⑤ 让他多难忘？ | 一个记忆点动作、特效或氛围物，让读者 0.3 秒记住 |

再写**立绘构图段**（Step 2 直接拼入生图 prompt）：主体（全身或半身、姿态、视角，占画面约 60-65%）｜位置（居画面中下部，脚部约 10%，头顶约在垂直 55% 处）｜顶部留白（顶部 40% 为纯净背景，**须显式声明"无任何元素、无第二分身、无杂物"**，防止 AI 将气流、分身或光效画入并污染文字安全区；人物本体不得侵入）｜记忆点（由二创注入）。

**顶部聚字文案**（钩子优先，按 content.md §文案公式填写，**不得使用介绍句**；五个字段对应 `ocr-1flow.tpl.html` 占位符）：

| 字段（占位符） | 公式 | 约束 |
|:--|:--|:--|
| 类型标签（`{{kicker}}`） | 系列名加类型（如"玄鉴仙族·人物卡"） | 不超过 10 字 |
| 名字/标题（`{{name}}`） | 实体名（鎏金大字） | 第一权重，楷体 |
| 称号/定位（`{{subtitle}}`） | 最有记忆点的反差/强力特征 | ≤8字，仿宋/隶书 |
| 金句/箴言（`{{creed}}`，可选） | 「[动作/交易]，换/成/得[结果]」，有代价/反转 | ≤16字，钩子，仿宋 |
| 印章（`{{seal}}`/`{{seal_cap}}`） | 专属印章（人名朱文/族徽/地标/规则符印/场景图腾） | 印文≤4字，底部，避开人物下摆 |

**文案稳定性检查**（组装前须通过）：① 有钩子吗？② 圈外人 3 秒能看懂吗？③ 字数够少吗（总模块不超过 5 个）？任一项不通过即回退修改。**文字分工（v6）**：全部文字由 HTML 在顶部聚字，AI 底图不出现文字（G1），印章由 HTML 在底部叠加（G2）。

**成图效果预估（组装前必填）**：生图前先用 HTML 骨架占位（`ocr-1flow.tpl.html`）预估加字后的成品——文字大小、间距、是否在留白区内、与头顶是否保持不低于 7% 的间距、颜色是否融入底图。确认点B 呈现的是"成图预期"，而非文字描述。

**系列化规划（如需）**：由一份档案生成 N 张图，填写 `templates/design-plan-oc.tpl.md` 系列表；冻结特征见铁律 ❌3，变量为服饰、场景、姿态与文字层。

**选择画风并回填生图 DNA**：从 `skills/pop-visual-style/references/文风DNA-library.json` 中按赛道与气质选择最匹配的条目（玄幻→国漫玄幻厚涂、暗黑→暗黑奇幻油画），再回填 `dna`/`constraint`/`recommended_lighting` 供生图使用，并**据画风确定字色**（浅色留白用深色字，深色留白用浅色字）；产出记入方案（画风条目、DNA 来源、底色倾向）。**画风不匹配时，再好的构图也无效**（质量第二来源）。

**可选 Pinterest 参考**：气质参考图（档案够用时即跳过）；画风参考使用放开吸收公式（只排除具体场景与人物长相）。

**🚪 确认点B：方案对齐**（强制暂停，不得跳过）——向用户呈现：类型与画幅｜设定理解（核心气质与冻结特征）｜**二创设计方案**（五问与构图段）｜**聚字文案**（须通过稳定性检查）｜**画风条目与字色**｜**成图效果预估**（HTML 骨架预览）。**等用户确认后才可进入 Step 2**；方案追记到 `_过程/提示词记录.md`，并填写 `design-plan-oc.tpl.md`。

### Step 2: 生成纯立绘零文字底图、顶部聚字与截图

**读取输入**：读取 `_过程/提示词记录.md` 中上一版的确认方案（二创设计、聚字文案、画风 DNA、冻结特征、参考图、画幅）。

**生成纯立绘零文字底图**（🔴 主视觉由 pop 直接调用 `image_generate` 生成，无该工具时暂停等待——❌5）。提示词按 layout.md §立绘构图组装，画风用 Step 1 条目的 DNA 回填：

```
[画风 DNA（Step 1 条目回填，无匹配时按赛道写质感）]
[主体：<实体>全身/半身立绘，姿态<N>，视角<正面/侧身/仰角>，占画面约60-65%]
[位置：人物居画面中下部，脚部在画面底部约10%，头顶在画面垂直约55%]
[顶部留白：画面顶部40%为纯净背景色，无任何元素、无第二分身、无杂物，用于后续叠加标题]
[记忆点：二创注入的动作张力/特效/氛围物]
[环境/光源/氛围]
[硬约束：负面清单（含 No text overlay, no text, no letters, no watermark, no seal）+ 冻结特征清单]
```

有参考图时按意图选择模式（详见 prompt-guide §三）：模式A 全面参考（提示词不超过 200 字，只描述差异）；模式B 画风参考（放开吸收，只排除具体场景与人物长相）；模式C 纯文生图。

```
image_generate(prompt='[提示词]', size='1125x1500', ref_image='[参考图，如有]', output='测试/{类型}/{类型}-{实体名}-v1.png')
```

出图后须**检查顶部留白是否纯净**：若被气流、分身或光效污染，或出现文字、水印，则回退重出（v2、v3……）；顶部不净者直接打回。

**HTML 顶部聚字**：复制底图到 `测试/{类型}/`，用 `templates/ocr-1flow.tpl.html` 组装（唯一模板，由 CSS 变量驱动五类与画风；占位符见 Step 1 文案表，底图填 `{{visual_path}}`；字色 `--ink/--em/--gold` 从顶部留白取色；画幅 `--cv-w/--cv-h` 与底图一致，改横版时同步修改截图 width）。组装约束：文字只落在顶部纯背景（G2），与人物头顶保持不低于 7% 的间距（G3），间距不足时调小字号或上移，**不得压住人物**；印章避开人物下摆，必要时并入顶部；同一张卡最多使用 2 种字体。

**截取整图**（默认 2:3 竖版）：

```
SCREENSHOT_WIDTH=1125 SCREENSHOT_SCALE=2 python scripts/screenshot_album.py '<html>' '<out.png>'
```

**失败中断**：文字溢出顶部留白、文字压到人物、顶部留白不净或底图出现文字，任一项即判定截图失败，修正后重新截图，**不得带残缺交付**。

**三态写入**：候选存入 `测试/{类型}/`，用户确认后复制到 `成品/{类型}/`（加 `-final`）；HTML 与成品图为 `成品/{类型}/{类型}-{实体名}-{形态}.html` 与 `-成品.png`；设计记录追加到 `_过程/提示词记录.md`（模型、类型、实体、形态、参考模式、提示词、二创设计、冻结特征、输出、状态）。

**系列化循环（如需）**：对系列表中的每张图，先复制冻结特征（HARD CONSTRAINTS 块），再更新变量、重组提示词、生成（v2、v3……），最后做一致性检查（冻结特征不变，且顶部留白仍纯净）。

**自检**：G1-G4 全过｜冻结特征嵌入 HARD CONSTRAINTS｜文案通过稳定性检查｜字体不超过 2 种｜截图无溢出｜三态写入完成且记录已追加。

**迭代快速路径**：修改已生成的图时跳过 Step 0 与 Step 1，直接读取 `_过程/提示词记录.md` 中上一版方案，修改对应维度后重新生成（v2、v3……）；仅当"重新设计"或"更换方向"时才回到完整流程。

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:--------|
| **G1** | **AI 底图零文字** — 提示词负面清单须包含 no text 类硬约束（见 Step 2 prompt 结构），不得让 AI 直接生成任何文字 | 文字乱码或压住人物，卡面作废 |
| **G2** | **文字集中于顶部** — 全部文字收敛到顶部纯背景区（顶部留出不低于 40% 的纯净留白），底部只放一个印章 | 文字无处安放，压住人物 |
| **G3** | **字不压人物** — 文字只落在纯背景上，与人物头顶保持不低于 7% 的画布间距 | 主体被遮挡，失去焦点 |
| **G4** | **字少而精** — 总文字模块不超过 5 个，称号不超过 8 字、金句不超过 16 字，不写大段正文 | 信息过载，立绘沦为背景 |
| **G5** | **二创不可跳过** — 设计立绘前必读 `references/二创-method.md`，答二创五问并选择好看注入招式；魂与符号取自原文，构图、姿态、光影由设计者注入 | 立绘平庸，好看第一位落空 |
| ❌1 | **角色调研不可跳过** — 须从原文系统性采样设定并形成档案（含气质要点与视觉母题），不得凭记忆或想象设计 | 形象扁平，偏离原著 |
| ❌2 | **两个检查不可跳过** — 确认点A（档案确认）与确认点B（方案对齐，含二创设计与成图预估）须等用户确认 | 理解偏差，浪费生成次数 |
| ❌3 | **系列一致性** — 系列图冻结核心特征（人物取眼瞳、轮廓、气质；势力取阵营美学；地理取空间氛围；规则取视觉外显；场景取场景基调），只变更服饰、场景与姿态 | 同一设定不同图认不出来 |
| ❌4 | **三态写入** — 档案进 `素材/视觉资产/`；方案与提示词进 `_过程/提示词记录.md`；候选进 `测试/`，确认后复制到 `成品/` | 无法迭代和系列扩展 |
| ❌5 | **主视觉须由 pop 直接生成** — 使用 `image_generate` 工具，不使用本地或替代的生图工具；无 `image_generate` 时暂停等待 | 画面质量远不及 pop 直接生成 |
| ❌6 | **文案按公式填写** — 文案按 `references/content.md` 的公式填写，组装前须通过稳定性检查（有钩子、圈外人 3 秒能看懂、字数够少），不得使用无钩子的介绍句 | 文案时好时坏，卡退化成说明书 |
| ❌7 | **字体使用本机书法系统** — HTML 补字使用本机已安装的书法字体（楷体、仿宋、隶书、宋体），同一张卡最多使用 2 种字体；字体系统见 `references/content.md` §字体系统 | 字体不可控或乱码 |
| ❌8 | **AI 画风做减法** — 写意留白优于铺满细节，克制而精致、追求真实质感，不得"过度精致"（毛发过度渲染、算法对称脸、塑料质感） | 失去差异化辨识度，被竞品淹没 |
| ❌9 | **画风决定一切** — 须从 `文风DNA-library.json` 选择画风条目并回填 DNA，画风决定立绘质感与顶部留白字色；无匹配时按赛道撰写质感 | 画风漂移，再好的构图也无效 |
