# pop-visual-oc

> 网文视觉推广素材生成器。OC = 原创设定（Original Creation），不止人物。v6.1.0

## 做什么

**OC = 原创设定**，天然涵盖一切可视觉化的设定实体——人物只是其中一类。从小说原文系统采样设定，立体化理解后设计视觉展示。

**输入**：小说项目文件 + 目标实体 + 可选参考图。**输出**：设定档案 + 视觉卡（AI 纯立绘零文字底图 + HTML 顶部聚字 + 整图截图）。

**五类内容类型**（信息架构见 `references/content.md`）：

| 类型 | 视觉主体 | 一句话定位 |
|:-----|:---------|:-----------|
| **人物卡** | 角色本人 | 让读者记住这个人 |
| **势力卡** | 阵营/宗门/家族/王朝 | 让读者记住这群人什么气质 |
| **地理卡** | 城市/秘境/位面 | 让读者记住这个地方什么感觉 |
| **规则卡** | 力量体系/境界/功法 | 让抽象规则被"看到" |
| **场景卡** | 关键场景/名场面 | 让读者记住这个高光时刻 |

**唯一大范式：立绘优先 · 顶部聚字（V6，全 OC 质量基准）**

> **AI 底图只出纯立绘零文字**（人物/视觉主体，占画面≥60%，人物居中下部，顶部留≥40%纯净背景）→ **HTML 只在顶部纯背景区叠少量核心文字**（类型/名字/称号/一句金句）+ **底部一个印章** → 整图截图即成品。**质量重心从"文字排版"转向"立绘本身"**——构图、画风、原文理解、二创注入。

**范式为什么是它（2026-08 老板定稿）**：字槽混合式（v5）要求 AI 直出"短书法字+预留字槽"，实测 **AI 写字不可控**（广蝉"蝉"字压肩颈、正文贴衣袍）。**模型写字不稳 → 不让 AI 承担任何"落实文字"的活**，改为「立绘 + 顶部聚字」。同时老板定调简化方案：**质量聚焦构图、画风、原文理解、二创注入**（好看是第一生产力，小说原文描述不一定好看），放弃复杂 HTML 排版。

**核心原则（四律）**：

| 律 | 含义 |
|:--|:--|
| **G1 AI 零文字** | AI 底图全画面零文字，禁止出现任何字/字母/数字/水印/印章 |
| **G2 文字顶部聚** | 所有文字收敛到顶部纯背景留白区，底部只留一个印章 |
| **G3 字不压人物** | 文字只落纯背景，与人物头顶保持 ≥7% 画布间距 |
| **G4 字少而精** | 只叠极少量核心文字（类型/名字/称号/一句金句/印章），不做大段正文 |

**二创是 OC 的灵魂**：原文理解→好看注入方法论见 `references/二创-method.md`（Step 1 设计立绘前必读）。**从原文提取气质锚点/核心意象，但构图、姿态、光影、动作张力、记忆点由设计者注入**——让角色"看起来够帅/够美/够有记忆点"，不被原文朴素描述捆住。

## 怎么运作（SOP）

1. **Step 0 需求确认 + 设定调研** → `steps/step0-setting-research.md`：确认用途/传播场景/画风偏好/是否参考图 → 优先读 `素材/视觉资产/` 已有档案，无则原文采样（Grep 关键词→上下文采样→按类型维度整理档案，含二创专用采样：气质锚点/核心意象/他人评价）→ **🚪门禁A：档案确认**
2. **Step 1 设计（含二创设计 + 成图预估）** → `steps/step1-design.md`：选类型 → **必读 `references/二创-method.md`，答二创五问 + 好看注入六式定立绘**（构图段直接拼进生图 prompt）→ 顶部聚字文案（`references/content.md` 公式 + 稳定性门禁）→ **选画风 + 回填生图 DNA**（`style-dna-library.json`，画风定立绘质感与字色）→ **成图效果预估**（HTML 骨架占位，预估最终效果）→ **🚪门禁B：方案对齐**
3. **Step 2 生成 + 顶部聚字** → `steps/step2-generate.md`：`image_generate` 直出纯立绘零文字底图（prompt 明确顶部留白 + 负面清单含 no text）→ HTML 顶部聚字（`ocr-1flow.tpl.html`，本机书法字体）→ `screenshot_album.py` 整图截图 → 落盘三态 → 系列化循环

**视觉真源**：所有类型视觉本体来自 `pop-visual-art-bible` 美术设定集对应篇（唯一真源），OC 只负责"怎么画好看 + 顶部叠少量文字"，**禁止重建设定身份**。用最新版（防跨版本 gap）。但**构图/姿态/光影/动作张力由二创注入**（原文描述不一定好看）。

**迭代快速路径**：用户要求改已生成图时跳过 Step 0/1，直接读 `_过程/提示词记录.md` 上一版方案改对应维度重生成（v2, v3...）。

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:--------|
| **G1** | **AI 底图零文字** — 提示词负面清单必须含 `No text overlay, no text, no letters, no watermark, no seal`，禁止让 AI 直出任何字 | 字乱码/压人物，卡毁掉 |
| **G2** | **文字顶部聚** — 所有文字收敛到顶部纯背景区，底部只留一个印章；构图必须保证顶部 ≥40% 纯净留白 | 字没地方放，压人物 |
| **G3** | **字不压人物** — 文字只落纯背景，与人物头顶保持 ≥7% 画布间距 | 主体被遮挡，失去焦点 |
| **G4** | **字少而精** — 总文字模块 ≤5，称号≤8字、金句≤16字，不做大段正文 | 信息过载，立绘沦为背景 |
| **G5** | **二创不可跳过** — 设计立绘前必读 `references/二创-method.md`，答二创五问 + 选好看注入招式；魂和符号从原文锚定，构图姿态光影由设计者注入 | 立绘平庸，好看第一位落空 |
| ❌1 | **角色调研不可跳过** — 必须从原文系统性采样设定，形成档案（含气质锚点/视觉母题），禁止凭记忆/想象设计 | 形象扁平，偏离原著 |
| ❌2 | **两个门禁不可跳过** — 门禁A（档案确认）和门禁B（方案对齐，含二创设计+成图预估）必须等用户确认 | 理解偏差，浪费生成次数 |
| ❌3 | **系列一致性** — 系列图冻结核心特征（人物=眼瞳/轮廓/气质；势力=阵营美学；地理=空间氛围；规则=视觉外显；场景=场景基调），只变服饰/场景/姿态 | 同一设定不同图认不出来 |
| ❌4 | **落盘三态** — 档案进 `素材/视觉资产/`；方案+提示词进 `_过程/提示词记录.md`；候选 `测试/{类型}/`，确认后 `成品/{类型}/` | 无法迭代和系列扩展 |
| ❌5 | **主视觉必须 pop 直出** — 用 `image_generate` 工具，不用本地/替代生图工具；无 `image_generate` 时暂停等待 | 画面质量远不及 pop 直出 |
| ❌6 | **文案按公式填** — 文案按 `references/content.md` 公式填写，组装前必过稳定性门禁（有钩子/圈外人3秒懂/字少），禁止介绍句无钩子文案 | 文案时好时坏，卡退化成说明书 |
| ❌7 | **字体用本机书法系统** — HTML 补字用本机已装书法字体（楷体/仿宋/隶书/宋体），同一张卡最多 2 种字体；字体系统见 `references/content.md` §字体系统 | 字体不可控或乱码 |
| ❌8 | **AI 画风做减法** — 写意留白 > 满铺细节，克制精致、真实质感，禁止"过度精致"（毛发过度渲染/算法对称脸/塑料质感） | 失去差异化辨识度，被竞品淹没 |
| ❌9 | **画风决定一切** — 必须从 `style-dna-library.json` 选画风条目并回填 DNA，画风定立绘质感与顶部留白字色；无匹配时按赛道写质感 | 画风漂移，再好的构图也白搭 |
