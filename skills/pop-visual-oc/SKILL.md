# pop-visual-oc

> 网文角色立绘生成器。角色调研→设计方案→生成。v1.8.0

## 做什么

输入：小说项目文件 + 角色名 + 可选参考图。
输出：角色档案 + OC立绘图（基础版/加强版）+ 设计方案文档 + 提示词记录。

核心价值：**不是从零画一个角色，是先从原文中系统性地调研角色形象，立体化理解后再设计视觉**。一份角色档案驱动N张系列图。

与封面图的本质区别：封面是视觉钩子（让读者点进书），OC是角色名片（让读者记住这个人）。

**三段流程**：
1. 角色调研 →（原文关键词搜索→上下文采样→角色档案.md）→ **门禁A：角色档案确认**
2. 角色档案 →（选形态+设计六层信息+可选Pinterest参考）→ **门禁B：方案对齐**
3. 确认方案 →（高精度提示词→API生成）→ 系列化循环（如需）

## 定妆照 vs 立绘OC（核心区分）

| 维度 | `pop-visual-character` 定妆照 | `pop-visual-oc` 立绘OC |
|:-----|:------------------------------|:-----------------------|
| 本质 | 纯生产参考图 | 展示作品/角色名片 |
| 用途 | 给 oc/cover/comic 做图生图参考 | 给读者看的角色展示 |
| 内容 | 无文字、无装饰、无文化元素 | 必须含文字（角色名+定场诗/小传）+文化元素（题诗/书法/钤印/装饰） |
| 产出位置 | `assets/characters/` 项目级资产跨章复用 | `素材/` 项目级展示资产 |

> OC 必须基于**最新版本定妆图**生成：定妆图是角色本体参考，OC 只负责在此之上叠加六层文字排版和氛围渲染——身份改动时，定妆图会升级版本，OC 必须使用最新版，避免跨版本 gap。

## 模型说明

| 生成内容 | 工具/方式 | 说明 |
|:-----|:---------|:-----|
| 静态图片（Seedream 5.0 Pro） | `image_generate` 工具 | 文生图/图生图/多图输入，无 API Key |

Seedream 5.0 Pro 画面不再泛白，简洁精确优于堆砌。支持文生图、图生图、多图输入。文字用双引号包裹。

## 怎么运作

### Step 0: 角色调研管线 → `steps/step0-character-research.md`

**核心增量**——OC不是直接搜图画图，是先从原文中系统性地采样角色信息，形成立体化的角色档案。

**两条路径**：
- **优先路径**：检查 `素材/视觉资产/[角色名]角色档案.md`（pop-visual-asset 产出）→ 存在则直接读取，跳过原文采样
- **回退路径**：资产文件不存在时，OC 内部完成原文采样

1. **资产文件检查**：扫描 `素材/视觉资产/` 是否有角色档案
2. **关键词搜索**（回退路径）：角色名+外貌词+性格词+评价词，多轮搜索原文
3. **上下文采样**（回退路径）：每个命中段落扩展前后文，提取关键信息
4. **角色档案**：10维度系统整理（外貌演变/性格特征/金句/他人评价/成长弧线/矛盾暗面/视觉设计参考等）
5. **可选Pinterest参考**：搜角色气质参考图（非必须，角色档案已提供足够信息时跳过）。画风参考模式默认用放开吸收公式（只排除场景内容+人物长相，人物长相排除正好保护角色一致性）
6. **🚪 门禁A**：角色档案确认（用户确认角色理解是否准确）

> 详见 `../pop-visual-shared/references/character-research-guide.md` 调研方法论（唯一权威源）。

### Step 0.5: 消费角色视觉身份卡（基建层）

**角色本体身份以 `pop-visual-character` 产出的「角色视觉身份卡」为唯一真源**。检查 `素材/视觉资产/[角色名]视觉身份卡.md`：

- **存在** → 直接读取，作为角色本体（剪影/色彩/细节/记忆锚点/冻结提示词），本 skill 只负责在此之上做六层排版+杂志版氛围渲染，**禁止重建角色身份**。
- **不存在** → 提示先跑 `pop-visual-character` 产出身份卡，再回来做 OC 渲染。OC 渲染本身不产出身份。

> **版本一致性校验（防 gap）**：身份卡经定妆认可后冻结并记录**定妆图版本**（如 `char-苏午-v2.png`）。OC 渲染前必须读取该版本，**禁止使用旧版本定妆图**。若身份卡/定妆图版本已升级（v2→v3），OC 必须用最新版重新生成，不得沿用旧版参考图——否则会造成角色本体与展示作品跨版本 gap。

> 身份与渲染分离：身份卡定了"长什么样"（唯一真源），OC 只定"怎么摆进杂志版式"（渲染）。

> **档位说明（oc 意图 = 轻量~中基建）**：Pipeline 语境下 oc 只需基建到身份卡即可派生，**不强制双角度定妆**；如需角色参考图，用 character 产出的**单张**定妆图作图生图参考（版本一致性校验❌6 仍生效）。

### Step 1: 设计方案 → `steps/step1-design.md`

- 读取角色档案，选取最适合做OC的关键场景/形态
- **系列化规划**：一份档案可驱动N张系列图
  - 形态演变系列（外貌演变表→婴幼/少年/封王/战斗）
  - 核心场景系列（视觉设计参考→多个标志性瞬间）
  - 群像关系系列（人际关系→对峙/臣服/父子）
- 设计六层信息架构（角色名+身份→称号→角色小传→题诗→书法大字→钤印）
- 选择布局模板（底部面板/侧边条/叠加层/四角分布/右侧古籍版式）
- **🚪 门禁B**：用户确认设计方案

### Step 2: 生成资产 → `steps/step2-generate.md`

- 读取确认方案 + 角色档案
- 翻译为高精度提示词（4块结构：LOCKED COMPOSITION→ENVIRONMENT AND LIGHTING→EXACT TYPOGRAPHY→HARD CONSTRAINTS）
- 执行 API → 保存图片 → 回写记录
- **系列化循环**：冻结核心特征（眼瞳/轮廓/气质），变化服饰/场景/姿态/年龄，循环生成

### 迭代模式（快速路径）

**当用户要求修改已生成的图片时**（如"更霸气一些""换姿态""文字错了"），**跳过 Step 0 和 Step 1**，直接执行：

1. 读取 `素材/视觉设计方案.md` 获取上一版设计方案+提示词记录
2. 识别用户要求的变更点
3. 直接进入 `steps/step2-generate.md`，在上一版提示词基础上修改对应维度
4. 执行 API 生成（文件名递增 v2, v3...）
5. 回写提示词记录

> 仅当用户明确要求"重新设计/换方向/换角色"时，才回到完整三段流程。

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **角色调研不可跳过** — 必须从原文系统性采样角色信息，形成角色档案，禁止凭记忆/想象设计角色 | 角色形象扁平化，偏离原著 |
| ❌2 | **两个门禁不可跳过** — 门禁A（角色档案确认）和门禁B（方案对齐）必须等用户确认 | 角色理解偏差，浪费生成次数 |
| ❌3 | **系列一致性** — 系列图中角色的核心特征必须冻结（眼瞳色/轮廓/气质），只变化服饰/场景/姿态/年龄 | 同一角色不同图认不出来 |
| ❌4 | **设计方案必须落盘** — 角色档案、设计方案和提示词写入 `素材/` | 无法迭代优化和系列扩展 |
| ❌5 | **立绘必须含文字+文化元素** — 纯图不算立绘，必须包含角色名+定场诗/人设简介等文字层，并叠加题诗/书法/钤印/装饰等文化元素；这是立绘OC与定妆照的本质区别 | 退化为普通素材/定妆照，丢失展示属性 |
| ❌6 | **必须使用最新版本定妆图** — OC 渲染前校验定妆图版本，禁止沿用旧版本参考图；身份卡升级后必须用最新版重新生成 | 角色本体与展示作品跨版本 gap，两张图对不上 |
