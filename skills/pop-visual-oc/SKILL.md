# pop-visual-oc

> 网文视觉推广素材生成器。OC = 原创设定（Original Creation），不止人物。v3.3.0

## 做什么

**OC = 原创设定（Original Creation），天然涵盖一切可视觉化的设定实体**——人物只是其中一类。本 skill 从不改名，只把 OC 的完整边界做出来。

输入：小说项目文件 + 目标实体（角色/势力/地理/规则/场景名）+ 可选参考图。
输出：设定档案 + 视觉卡（基础版/加强版·OC/**设定卡传播版**/**HTML组装版·画册页**）+ 设计方案文档 + 提示词记录。

**五类内容类型**（OC 的完整边界）：

| 类型 | 视觉主体 | 一句话定位 | 消费的美术设定集篇 |
|:-----|:---------|:-----------|:------------------|
| **人物卡** | 角色本人 | 让读者记住这个人 | 人物篇 |
| **势力卡** | 阵营/宗门/家族/王朝 | 让读者记住这群人是什么气质 | 势力篇 |
| **地理卡** | 城市/小世界/秘境/位面 | 让读者记住这个地方什么感觉 | 地理篇 |
| **规则卡** | 力量体系/境界/功法/禁忌 | 让抽象规则被"看到" | 规则篇 |
| **场景卡** | 关键场景/名场面瞬间 | 让读者记住这个高光时刻 | 场景篇（+符号篇） |

核心价值：**不是从零画一个设定，是先从原文中系统性地调研设定实体，立体化理解后再设计视觉**。一份设定档案驱动 N 张系列卡。

与封面图的本质区别：封面是视觉钩子（让读者点进书），OC 是设定名片（让读者记住这个设定/这个人）。

**四档位**：基础版（3层文字）/ 加强版·OC（6层文字）/ **设定卡传播版（模块化信息卡，对标竞品主流传播形态）** / **HTML组装版·画册页（无文字主视觉+HTML装裱排版，推广素材终极形态）**。

**五段流程**：
1. 设定调研 →（原文关键词搜索→上下文采样→设定档案.md）→ **门禁A：设定档案确认**
2. 设定档案 →（选类型+选档位+设计信息架构+可选Pinterest参考）→ **门禁B：方案对齐**
3. 确认方案 →（高精度提示词→API生成）→ 系列化循环（如需）

## 定妆照 vs 立绘OC（核心区分）

| 维度 | `pop-visual-art-bible` 定妆照/复现图 | `pop-visual-oc` 立绘OC/设定卡 |
|:-----|:------------------------------|:-----------------------|
| 本质 | 纯生产参考图 | 展示作品/设定名片 |
| 用途 | 给 oc/cover/comic 做图生图参考 | 给读者看的设定展示 |
| 内容 | 无文字、无装饰、无文化元素 | 必须含文字（实体名+定场诗/简介）+文化元素（题诗/书法/钤印/装饰） |
| 产出位置 | 美术设定集复现资产（`素材/视觉/`） | `素材/` 项目级展示资产 |

> OC 必须基于**美术设定集最新版本**生成：复现图是实体本体参考，OC 只负责在此之上叠加文字排版和氛围渲染——实体视觉改动时，设定集会升级版本，OC 必须使用最新版，避免跨版本 gap。

## 怎么运作

### Step 0: 设定调研管线 → `steps/step0-setting-research.md`

**核心增量**——OC不是直接搜图画图，是先从原文中系统性地采样设定信息，形成立体化的设定档案。

> 人物走角色档案（10维度）；势力/地理/规则优先消费 `pop-visual-asset` 提取的对应档案（势力档案8维度/地理档案7维度/规则档案6维度）；场景消费场景资产表。

**两条路径**：
- **优先路径**：检查 `素材/视觉资产/` 是否有对应设定档案 → 存在则直接读取，跳过原文采样
- **回退路径**：资产文件不存在时，OC 内部完成原文采样

1. **资产文件检查**：扫描 `素材/视觉资产/` 是否有对应档案（角色/势力/地理/规则档案、场景资产表）
2. **关键词搜索**（回退路径）：实体名+外貌/美学/空间/外显词，多轮搜索原文
3. **上下文采样**（回退路径）：每个命中段落扩展前后文，提取关键信息
4. **设定档案**：按实体类型维度系统整理（人物=10维度；势力=8维度；地理=7维度；规则=6维度）
5. **可选Pinterest参考**：搜实体气质参考图（非必须，档案已提供足够信息时跳过）。画风参考模式默认用放开吸收公式（只排除场景内容+实体长相，实体长相排除正好保护实体一致性）
6. **🚪 门禁A**：设定档案确认（用户确认设定理解是否准确）

> 详见 `../pop-visual-shared/references/character-research-guide.md` 调研方法论（人物唯一权威源）+ `skills/pop-visual-asset/references/asset-extract-guide.md` §五/§六/§七（势力/地理/规则方法论）。

### Step 0.5: 消费美术设定集对应篇（基建层）

**设定本体身份以 `pop-visual-art-bible` 产出的「美术设定集」为唯一真源**。检查 `素材/美术设定集.md`：

- **存在** → 直接读取对应篇（人物篇/势力篇/地理篇/规则篇/场景篇），作为设定本体（剪影/美学/氛围/外显/冻结提示词），本 skill 只负责在此之上做排版+版式氛围渲染，**禁止重建设定身份**。
- **不存在** → 提示先跑 `pop-visual-art-bible` 产出美术设定集，再回来做 OC 渲染。OC 渲染本身不产出身份。

> **版本一致性校验（防 gap）**：美术设定集经认可后冻结并记录**复现图版本**。OC 渲染前必须读取该版本，**禁止使用旧版本复现图**。若美术设定集/复现图版本已升级，OC 必须用最新版重新生成，不得沿用旧版参考图——否则会造成设定本体与展示作品跨版本 gap。

> 身份与渲染分离：美术设定集定了"这个设定长什么样"（唯一真源），OC 只定"怎么摆进版式"（渲染）。

> **档位说明（oc 意图 = 轻量~中基建）**：Pipeline 语境下 oc 只需基建到美术设定集即可派生，**不强制双角度定妆**；如需参考图，用 art-bible 产出的**单张**复现图作图生图参考（版本一致性校验❌6 仍生效）。

### Step 1: 设计方案 → `steps/step1-design.md`

- 读取设定档案，选取最适合做OC的关键场景/形态
- **类型选择**：人物卡 / 势力卡 / 地理卡 / 规则卡 / 场景卡
- **档位选择**：基础版 / 加强版（OC）/ 设定卡传播版 / HTML组装版·画册页
- **系列化规划**：一份档案可驱动N张系列图
  - 人物：形态演变系列 / 核心场景系列 / 群像关系系列
  - 势力：阵营美学沿革 / 代表场景 / 势力群像
  - 地理：地标节点系列 / 四季昼夜 / 小世界全景
  - 规则：层级可视化系列 / 突破异象系列
- 设计信息架构：加强版=六层信息；**设定卡传播版=模块化信息（人物=属性/配色/表情/花语/徽章/语录；势力/地理/规则/场景见 `mode-setting-cards.md`）**；**HTML组装版=画册页信息架构（顶部标题区+无文字主视觉+图外信息区，见 `mode-album-html.md`）**
- 选择布局模板（底部面板/侧边条/叠加层/四角分布/右侧古籍版式/**设定卡模块化版式**/**设定实体卡模块化版式**/**画册页版式**）
- **🚪 门禁B**：用户确认设计方案

### Step 2: 生成资产 → `steps/step2-generate.md`

- 读取确认方案 + 设定档案 + 美术设定集对应篇
- 翻译为高精度提示词（4块结构：LOCKED COMPOSITION→ENVIRONMENT AND LIGHTING→EXACT TYPOGRAPHY→HARD CONSTRAINTS）；**消费美术设定集对应篇冻结提示词时必须剥离其中 no text/no letters/no characters 等文字禁止词（复现图专用），补回 EXACT TYPOGRAPHY 块写入信息架构（仅前三档位）**
- 执行 API → 保存图片 → 回写记录
- **系列化循环**：冻结核心特征（人物=眼瞳/轮廓/气质；势力=阵营美学；地理=空间质感；规则=视觉外显），变化服饰/场景/姿态/层级，循环生成
- **品牌水印（必做，前三档位）**：OC 卡是**对外展示产出**，落地后用共享脚本叠加半透明 `popwave.cn`：`python skills/pop-visual-shared/scripts/watermark.py '<图路径>'`（幂等，二次运行输出"已含水印，跳过"）

### HTML 组装版·画册页（第四档位，推广素材终极形态）

> **必读 `references/mode-album-html.md`**（画册页范式 + 三条铁律 + 排版语言）+ `templates/album-card.tpl.html`（样板）。

**核心范式**：一张图放在页面中央，四周 HTML 排版（标题、说明、装饰）。**图是主角，HTML 是装裱和排版**——这是 OC 所有内容类型的核心设定。

**三步分工**（不走 AI 渲染文字）：
1. **① 无文字主视觉**：**必须由 pop 直出（`image_generate` 工具）**——老板验收定调，本地直出（GenerateImage）画面质量远不及 pop 直出 Seedream（构图/质感/文字意境/信息层级皆逊色）。从美术设定集对应篇冻结提示词取设定本体，提示词**保留 no text**（铁律 A2）。无 `image_generate` 时暂停等待 pop 直出，或请用户提供 pop 直出图，**禁止擅自用本地工具出图**
2. **② HTML 画册页**：用 `album-card.tpl.html` 组装——顶部标题区（系列名/类型标签/实体名鎏金大字/定位）+ 中央独立图框主视觉 + 图外信息区（箴言/核心气质/等级色板/象征词条）+ footer 品牌水印
3. **③ 截成长图**：用 `scripts/screenshot_album.py` 把画册页截成高清长图（`-长图.png`，Playwright 整页 + deviceScaleFactor=2，与漫画 `screenshot_comic.py` 同构），交付可传播长图

**人物卡专项（v3.3.0 铁律 P1-P3）**：人物卡是信息量最大的类型，**HTML 组装版必须承载角色名/称号/属性栏/配色板/花语/台词/题诗/小传/表情差分全部模块**，主视觉只画角色本人（零文字零标签零色板）。三铁律：P1 主视觉零文字零标签零色板；P2 信息区全部在图框外；P3 角色是绝对主角（≥60% 画面）。详见 `mode-character.md` §人物卡 HTML 组装版。

**品牌水印**：HTML 档位**不走 `watermark.py`**，水印已作为 HTML footer 内嵌（`popwave.cn 让创意一键落地`），比图片水印更清晰可控。

### 迭代模式（快速路径）

**当用户要求修改已生成的图片时**（如"更霸气一些""换姿态""文字错了"），**跳过 Step 0 和 Step 1**，直接执行：

1. 读取 `素材/视觉设计方案.md` 获取上一版设计方案+提示词记录
2. 识别用户要求的变更点
3. 直接进入 `steps/step2-generate.md`，在上一版提示词基础上修改对应维度
4. 执行 API 生成（文件名递增 v2, v3...）
5. 回写提示词记录

> 仅当用户明确要求"重新设计/换方向/换角色"时，才回到完整三段流程。

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **角色调研不可跳过** — 必须从原文系统性采样角色信息，形成角色档案，禁止凭记忆/想象设计角色 | 角色形象扁平化，偏离原著 |
| ❌2 | **两个门禁不可跳过** — 门禁A（角色档案确认）和门禁B（方案对齐）必须等用户确认 | 角色理解偏差，浪费生成次数 |
| ❌3 | **系列一致性** — 系列图中角色的核心特征必须冻结（眼瞳色/轮廓/气质），只变化服饰/场景/姿态/年龄 | 同一角色不同图认不出来 |
| ❌4 | **设计方案必须落盘** — 角色档案、设计方案和提示词写入 `素材/` | 无法迭代优化和系列扩展 |
| ❌5 | **立绘必须含文字+文化元素** — 纯图不算立绘，必须包含角色名+定场诗/人设简介等文字层，并叠加题诗/书法/钤印/装饰等文化元素；这是立绘OC与定妆照的本质区别 | 退化为普通素材/定妆照，丢失展示属性 |
| ❌6 | **必须使用最新版本定妆图** — OC 渲染前校验定妆图版本，禁止沿用旧版本参考图；美术设定集升级后必须用最新版重新生成 | 角色本体与展示作品跨版本 gap，两张图对不上 |
| ❌7 | **OC 提示词禁止携带 no text** — 美术设定集·人物篇冻结提示词是定妆图专用（含 `no text/no letters/no characters` 等文字禁止词），组装 OC 提示词时必须剥离这些文字禁止词，并补回 EXACT TYPOGRAPHY 块 | 文字被压制，立绘退化成定妆照，丢失展示属性 |
| ❌8 | **设定卡传播版文字密度铁律** — 传播版模块化信息总模块≤7，属性栏每项≤4字、花语≤8字、语录≤15字；信息量过大时宁可减少模块数，禁止塞满导致乱码 | 文字乱码直接毁掉传播卡的收藏价值 |
| ❌9 | **AI画风做减法（差异化）** — 传播版/立绘画风须写意克制（留白/笔触感/真实质感），禁止落入竞品"过度精致"陷阱（毛发过度渲染/算法对称脸/塑料质感） | 失去差异化辨识度，被竞品审美疲劳淹没 |
| ❌10 | **对外产出必加品牌水印** — OC 立绘/设定卡落地后必须运行 `watermark.py` 叠加 `popwave.cn`（幂等，二次运行输出"已含水印，跳过"）；禁止跳过此步 | 发布图无溯源，品牌曝光丢失 |
| ❌11 | **规则卡必须有原文视觉外显依据** — 规则卡主视觉载体（器物/天象/纹路）必须来自美术设定集规则篇的原文视觉外显，禁止凭空发明与原文无关的符号 | 抽象规则被画歪，误导读者认知 |
| ❌12 | **HTML组装版·画册页三铁律** — ①A1 图是主角，HTML 是装裱（图作为独立 `<figure>` 图框主体放中央，禁止铺满当 background）；②A2 主视觉零文字（AI 不画字，提示词保留 no text，文案全由 HTML 承载）；③A3 信息区在图框之外（标题/说明/装饰不压图主体）。**本档位是 ❌7「禁止 no text」的唯一例外** | 退化成"网页海报"，图失去主角地位；或图上乱字，推广物料不可用 |
| ❌13 | **人物卡 HTML 组装版三铁律（P1-P3）** — ①P1 主视觉零文字零标签零色板（角色名/称号/属性/色板/tag/台词**一律由 HTML 承载**，禁止 AI 渲染在人物图上）；②P2 信息区全部在图框之外；③P3 角色是绝对主角（占画面≥60%）。人物卡做正式推广**默认走 HTML 组装版**，不做 AI 渲染文字的前三档位 | 退化成旧版"字多色杂tag密"海报，角色被文字稀释、乱码风险高 |
