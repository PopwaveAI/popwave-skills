# HTML 组装档位（画册页范式）

> OC 的第四个档位，也是**推广素材的终极形态**。核心范式一句话：
>
> **「画册页」——一张图放在页面中央，四周 HTML 排版（标题、说明、装饰）。图是主角，HTML 是装裱和排版。**
>
> 这是 OC 所有内容类型的核心设定（人物/势力/地理/规则/场景五类通用）。

## 为什么需要这个档位

前三个档位（基础版/加强版/设定卡传播版）都是**让 Seedream 直接把文字渲染进画面**。但：

| 局限 | 说明 |
|:-----|:-----|
| AI 文字渲染能力有限 | Seedream 5.0 Pro 稳定处理 4-6 个短文本区块；宣传图需要大量文案时必然乱码 |
| 文字压画面 | 文字堆进图里会稀释主视觉，构图被文字区块绑架而平庸 |
| 无法承载长文案 | 势力小传、人物生平、规则说明这类长文案，AI 画不了也排不美观 |

**HTML 组装档位的答案是：分工。** AI 只画一张**无文字的高完成度主视觉**（图是主角），HTML 负责四周的**全部排版**（标题/说明/装饰/信息区）。图不被文字污染，文字不被 AI 限制，各得其所。

> 与漫画管线同构：漫画用「Seedream 直出无文字画面 + HTML 文字叠加导出」，本档位用「Seedream 直出无文字主视觉 + HTML 画册页排版」。

## 核心范式：画册页

```
┌──────────────────────────────────────┐
│  ┌────────────────────────────────┐  │
│  │  [系列名]         [类型标签]      │  │  ← 顶部标题条
│  │      实体名（鎏金渐变大字）        │  │
│  │      定位（如"伪善佛门·香火吞噬众生"）│  │
│  └────────────────────────────────┘  │
│  ┌────────────────────────────────┐  │
│  │                                │  │
│  │        【主视觉 · 图】           │  │  ← 图是绝对主角，独立画框
│  │        （无文字，完整边界）        │  │     有边框+投影+金色托线
│  │                                │  │
│  └────────────────────────────────┘  │
│  ┌────────────────────────────────┐  │
│  │  箴言/口号（压在图下缘，金光）      │  │
│  │  ── 金色分割线 ────────────────  │  │  ← 信息区，全部在图框之外
│  │  核心气质：[一句短句，可加粗高亮]   │  │
│  │  等级/色板：[横向色块阵列]          │  │
│  │  象征：[两栏词条]                  │  │
│  │  popwave.cn 让创意一键落地        │  │  ← 品牌水印
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘
```

### 三条铁律（画册页 DNA）

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| **A1** | **图是主角，HTML 是装裱** — 图必须作为独立 `<figure>`/`<img>` 主体放在中央，有完整边界；HTML 是更大的外围一层（`.frame`）包裹住它。**禁止把图铺满整卡当 background**，禁止文字压在图主体上遮挡画面 | 退化成"网页海报"，图失去主角地位，违背画册页本质 |
| **A2** | **主视觉零文字** — AI 生成的主视觉必须无文字（提示词含 `no text, no letters`），所有文案由 HTML 承载。不得让 AI 在图上画任何字 | 图上乱字/文字被 AI 限制，推广物料不可用 |
| **A3** | **信息区在图外** — 标题区、信息区、预算、象征等排版全部放在图框之外（上/下/四周），不压图主体。图保留完整画面呼吸 | 主视觉被遮挡，图失去传播力 |

## 五类内容类型的信息架构（HTML 组装版）

与设定卡传播版同源（读 `mode-setting-cards.md` 的模块化信息），但**文字量可放开**——HTML 不受 AI 渲染限制，可承载完整介绍。

| 类型 | 顶部标题区 | 图（主视觉） | 信息区推荐模块 |
|:-----|:---------|:-----------|:-------------|
| **人物卡** | 角色名（鎏金大字）+ 身份定位 | 纯净人物主视觉（零文字零标签零色板，铁律P1） | 称号 · 属性栏 · 配色板 · 花语 · 台词 · 题诗 · 小传 · 表情差分（全由 HTML 承载，见下） |
| **势力卡** | 势力名 + 阵营定位 | 势力代表场景/阵列 | 核心气质 · 等级秩序 · 象征体系 · 宣言口号 |
| **地理卡** | 地名 + 地理定位 | 地标/空间全景 | 氛围基调 · 标志性地标 · 当地生灵 · 象征隐喻 |
| **规则卡** | 规则名 + 体系定位 | 规则载体（器物/天象/纹路） | 规则内涵 · 层级可视化 · 外显色板 · 器物符号 |
| **场景卡** | 场景名 + 高光定位 | 场景高光瞬间 | 氛围基调 · 关键元素 · 情境一句话 |

> **视觉真源不变**：图的主视觉一律来自美术设定集对应篇的冻结提示词（剥离 no text），HTML 只做装裱排版，禁止重建设定身份。

### 人物卡专项：HTML 承载全部字/色板/tag（v3.3.0 铁律升级）

人物卡是信息量最大的类型（角色名+称号+小传+题诗+属性+色板+台词+表情差分），**禁止让 AI 渲染这些文字**——AI 渲染 4-6 个短文本区块是极限，超限必乱码且稀释角色主体。人物卡 HTML 组装版信息架构（承接 `mode-character.md` §人物卡 HTML 组装版）：

| 模块 | 内容 | 位置 | 说明 |
|:-----|:-----|:-----|:-----|
| **主视觉（无文字）** | 角色立绘 | 中央独立 `<figure>` 图框 | 角色占画面主体≥60%，四周留呼吸空间 |
| **顶部标题区** | 系列名 / 「人物设定卡」标签 / 角色名（鎏金）/ 身份定位 | 图框上方 | 角色名信息第一权重 |
| **称号** | 四字格（方框衬底） | 标题区下 | 一句话点出角色厉害在哪 |
| **属性栏** | 境界/阵营/煞兽/秘法/命格（≤4字/项，5-6项） | 图框外 | 硬核设定，可收藏 |
| **配色板** | 代表色系 swatch（无字，仅色块） | 图框外 | 视觉记忆点，可二创取色 |
| **花语象征** | 代表花 + 花语（≤8字） | 图框外 | 文化隐喻 |
| **台词** | 代表性台词（≤15字） | 图框外 | 情感共鸣 |
| **题诗** | 七言对仗 | 图框外 | 升华意境 |
| **小传** | 60-100字微型人物志 | 图框外 | 核心信息层，HTML 精确排版 |
| **表情差分** | 2-4 个表情小图（可选） | 图框外 | 角色鲜活度 |

> **人物卡三铁律（P1-P3，承接 ❌12）**：P1 主视觉零文字零标签零色板（角色名/称号/属性/色板/tag/台词一律 HTML 承载）；P2 信息区全部在图框外；P3 角色是绝对主角（≥60% 画面）。详见 `mode-character.md`。

## 排版语言（对齐 onboarding 的精致度）

学习 `../pop-visual-comic/templates/onboarding.html` 的视觉语言，但**保持画册页的克制**（不做过度的网页化组件）：

| 技术 | 用法 | 效果 |
|:-----|:-----|:-----|
| **渐变文字** | `background:linear-gradient(...)` + `-webkit-background-clip:text` + `-webkit-text-fill-color:transparent` | 实体名鎏金渐变，高级感 |
| **分层背景** | `--bg/--bg2/--bg3` 三级暗色 + 角落 radial-gradient 光晕 | 深度，不死黑 |
| **双线边框装饰** | `.frame::before` 内层细线框 + 四角金印（TL/TR/BL/BR） | 装裱感，画册页识别度 |
| **图框装裱** | 图容器 `border + box-shadow + 底部金色托线` | 图是"被装裱的画" |
| **信息模块** | 编号徽标（01/02/03）+ 模块标题 + hover 上浮 | 信息层级清晰 |
| **色板/等级** | 横排色块 swatch（带光泽高光描边 + 内阴影） | 直观呈现等级/配色 |
| **品牌水印** | 底部 `popwave.cn 让创意一键落地`，渐变字 | 品牌曝光 |

## 工作流（HTML 组装档位）

```
Step 1 设计（选档位=HTML组装版）
  ├─ 从档案+美术设定集对应篇选主视觉形态（无文字）
  ├─ 设计画册页信息架构（顶部标题区 + 图 + 信息区模块）
  ├─ 门禁B：方案对齐（图长什么样 + 排版分几块）
  └─ 落盘到 design-plan-oc.tpl.md

Step 2 生成（两步）
  ├─ ① AI 生成无文字主视觉（image_generate，剥离 no text）
  ├─ ② 用 album-card.tpl.html 模板组装画册页（填主视觉路径 + 文案）
  ├─ 本地预览（python -m http.server）→ 用户确认
  ├─ ③ 截成长图（screenshot_album.py）→ 交付可传播长图
  └─ 落地：复制到 `素材/`，品牌水印 已内嵌在 HTML footer
```

> **关键差异**：前三个档位是"一张图"（AI 出成品图）；本档位是"一张图 + 一个 HTML 文件"（AI 出主视觉，HTML 组装成品）。**HTML 组装档位不需要 `watermark.py` 叠加**——品牌水印已作为 HTML footer 内嵌，比图片水印更清晰更可控。

### ③ 画册页截成长图（交付形态）

画册页是长图文案载体，**交付时必须截成一张高清长图**（与漫画同构，`screenshot_comic.py` 的 OC 版）。使用 `scripts/screenshot_album.py`：

```
python skills/pop-visual-oc/scripts/screenshot_album.py \
  '素材/[类型][实体名]-画册页.html' \
  '素材/[类型][实体名]-画册页-长图.png'
```

- **高清**：Playwright 整页 `full_page` 截图 + `deviceScaleFactor=2`（默认 680px 视口 ×2 倍 → 1360px 宽长图），底部质量不退化
- **自动等图**：自动移除 lazy loading + 等待所有 `<img>` 完全加载后再截图，避免主视觉没渲染出来就截
- **输出**：PNG 无损长图（`-长图.png`），与 HTML 同目录落地
- **可选**：`SCREENSHOT_WIDTH` 调视口宽、`SCREENSHOT_SCALE` 调倍率（一般用默认即可）
- **校验**：长图应完整含顶部标题区 + 主视觉 + 信息区 + 品牌水印 footer，四段都不缺才算成功

## 与三档位的关系

| 档位 | 产出 | 文字承载 | 适用 |
|:-----|:-----|:---------|:-----|
| 基础版 | 单张图 | AI 渲染少量文字 | 快速出图 |
| 加强版（OC） | 单张立绘 | AI 渲染六层文字 | 角色名片 |
| 设定卡传播版 | 单张卡 | AI 渲染模块化短文字（≤7模块） | 可传播短文案卡 |
| **HTML 组装版** | **图 + HTML** | **HTML 承载无限文案** | **推广物料/设定集/长文案** |

> 当文案多到 AI 渲染会乱码、或需要正式推广排版时，直接用 HTML 组装版，不要用设定卡传播版硬塞。
