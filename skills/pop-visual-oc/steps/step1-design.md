# Step 1: 设计方案（含字槽规划 + 成图预估）

> 读档案 → 选类型 → 设计信息架构 → **字槽规划** → **成图效果预估** → 系列化 → 🚪门禁B：方案对齐。
> **放什么内容**见 `references/content.md`（五类信息架构+文案SOP+视觉系统+字体系统）；**怎么排版**见 `references/layout.md`（字槽混合式大范式）。

## 1. 读取输入

1. **需求确认**：Step 0 产出的需求（类型/画幅/画风/参考图偏好）。
2. **设定档案**：读 Step 0 产出的 `素材/[类型][实体名]档案.md`，聚焦气质/视觉/意象/金句。
3. **美术设定集对应篇**（唯一真源）：`素材/美术设定集.md` → 人物篇/势力篇/地理篇/规则篇/场景篇。**版本校验**：用最新版，禁止旧版（防跨版本 gap）。

## 2. 选类型

**类型**：人物卡/势力卡/地理卡/规则卡/场景卡（五类定义见 `references/content.md` §五类）。

**画幅**：2:3 竖版（默认）→ 按需求/参考图可改 4:3 横版 / 16:9 横幅。

## 3. 设计信息架构

按 `references/content.md` 填文案 SOP 四模块（**组装 HTML 前必按公式填写，禁止介绍句**）：

| 字段 | 公式 | 字数 |
|:-----|:-----|:-----|
| 定位线 | `[核心]即[本质]·[命运]` | ≤14字 |
| 箴言（钩子） | `「[动作/交易]，换/成/得[结果]」`，有代价/反转 | ≤16字 |
| 机制 | `[体系]：谁做什么→换来什么→代价` | 人话可复述 |
| 体系 ranks/symbols | 层级递进链 + 象征键值对 | ≤5字/层，≤12字 |

人物卡另填：称号/属性栏/配色板/花语/台词/小传。**过文案稳定性四问**（有钩子？讲清机制？无黑话？圈外人3秒懂？）任一不通过回写修正。

**文字分工标注**：明确每个文案模块是"短书法字（AI 直出）"还是"长效文字（HTML 字槽补）"：
- 短书法字（AI 直出）：标题/副题/印章/器物标签，每处≤4字
- 长效文字（HTML 补）：金句/小传/词条说明/落款，放预留字槽

## 4. 字槽规划（核心新增 · 必答）

按 `references/layout.md` §字槽规划维度，明确：

| 维度 | 产出 |
|:-----|:-----|
| **留白预留** | 图哪些区域要专门留白给长效文字？预留多大？→ 字槽清单（位置/尺寸/用途） |
| **画面元素** | 图要哪些元素？主体什么姿态/场景？短书法字放哪几处？ |
| **是否参考生图** | 参考模式（全面/画风/纯文生图） |
| **画幅比例** | 比例 + 尺寸 |

> **关键**：这一步决定"图怎么出"。字槽位置想清楚，生成时提示词才能明确预留空白块，文字才有地方放（铁律 A2）。

## 5. 成图效果预估（核心新增 · 组装前必填）

**在真正生图前，先用 HTML 骨架占位，预估加了字之后的最终成品效果**——这是与旧路径最大的区别：方案阶段就要"看到"打完字的完整画面，而不是生成后才调整。

做法：用一个临时 HTML（或直接改 `design-plan-oc.tpl.md` 的布局占位），把文案四模块按字槽位置摆进去，用本机书法字体渲染，**预估**最终效果长什么样（文字大小/间距/是否溢出字槽/与图主体位置关系）。这一步是"纸上谈兵的预览"，让门禁B 时老板看到的是"成图预期"而非"图+文字的文字描述"。

## 6. 系列化规划（如需）

一份档案驱动 N 张图。填 `templates/design-plan-oc.tpl.md` 系列表。**冻结特征**（不变）：人物=眼瞳/轮廓/气质；势力=阵营美学；地理=空间氛围；规则=视觉外显；场景=场景基调。**变量**：服饰/场景/姿态/文字层。

## 7. 选赛道 + 画风库联动（核心新增）

template 的 `body[data-track="{{track}}"]` 决定整套文字风格（字体/配色/装饰/排版，见 `references/layout.md` §跨赛道）。**必须联动画风库**：

1. **选画风库条目**：读 `skills/pop-visual-style/references/style-dna-library.json`，按实体所在小说赛道 + 气质选最匹配的画风条目（如赛博朋克玄幻→「赛博边缘行者」）。
2. **回填生图 DNA**：把该条目的 `dna`/`constraint`/`recommended_lighting` 供 Step 2 生图用（现有机制）。
3. **映射赛道 token**：按画风库 `category` → 模板 `data-track` 赛道（映射表见 `references/layout.md` §画风库联动），决定 `--track-*` 字体与配色。

| 产出 | 值 |
|:-----|:---|
| 画风库条目 | {{style_entry}} |
| 生图 DNA 来源 | {{dna_source}} |
| 模板赛道 `{{track}}` | {{track}} |

> **赛道只决定字体与配色**；短书法字（≤4字）仍由 AI 直出、颜色由底图决定。HTML 补字的 `--ink/--em/--gold` 组装时以底图实际拿色为准微调，保证融入不割裂。

## 8. 可选：Pinterest 参考

设定气质参考图（非必须，档案够用即跳过）。画风参考默认用放开吸收公式（只排除场景内容+实体长相）。

## 9. 🚪 门禁B：方案对齐（强制暂停，禁止跳过）

向用户呈现（人话）：类型+画幅 / 设定理解（核心气质+冻结特征）/ **字槽规划表**（哪些区域留白给文字）/ **赛道 token 包**（画风库条目 + 字体配色装饰）/ **成图效果预估**（HTML 骨架预览，打完字的样子）/ 文案四模块（按公式）+ 稳定性四问 / 画面描述（2-3句）。**等用户确认后才能进 Step 2**。方案追记 `_过程/提示词记录.md`，填 `design-plan-oc.tpl.md`。

## 10. 进入 Step 2

方案确认后，读 `steps/step2-generate.md` 生成含字槽底图并按字槽补字。
