# Step 2: 生成资产

> 读取确认方案 → 选择参考配合模式 → 组装提示词 → 执行 API → 保存产出 → 系列化循环（如需）

## 设计哲学

Step 2 的核心是**根据参考图使用方式选择正确的提示词策略**——提示词细节量与参考图影响力成反比，选错模式是翻车的首要原因。

三种配合模式：
- **模式A（全面参考）**：参考图主导，提示词≤200字只改差异
- **模式B（画风参考）**：放开吸收画风+4块结构控制画面
- **模式C（纯文生图）**：完整4块高精度模板，控制全部维度

对于系列化产出，通过冻结核心特征+变化变量特征，确保同一角色在不同图中保持一致。

## 1. 读取确认方案

读取 `素材/视觉设计方案.md` 中的记录，提取：
- 角色档案路径
- 选定的形态/场景
- 六层信息架构内容
- 布局模板
- 冻结特征列表
- 系列化规划（如需）
- 参考图路径（如有）

## 2. 组装提示词

读取 `../pop-visual-shared/references/seedream-prompt-guide.md` §三 获取高精度模板详细说明（4块结构）。

> **画风DNA来源**：从 `skills/pop-visual-style/references/style-dna-library.json` 取画风的 `dna` + `constraint` 字段。按赛道用 `suggested_genres` 筛选，取 `recommended_lighting` 检查光照兼容性（柔美风格禁用LT1减法照明）。`constraint` 字段加入4块结构的HARD CONSTRAINTS块。详见 `skills/pop-visual-style/references/lighting-composition-templates.md`。

> **注意**：4块结构是模式C（纯文生图）和模式B（画风参考）的控制维度写法。模式A（全面参考）不使用4块结构，只写差异描述。

### 2.1 四块结构

```
[LOCKED COMPOSITION]
锁定构图：角色站位、姿态、视角、画面分割比例。这一块定义画面的骨架，后续块不得矛盾。

[ENVIRONMENT AND LIGHTING]
环境与光影：背景场景、光源方向、色温、明暗分配、氛围粒子。

[EXACT TYPOGRAPHY]
精确文字：每一层文字的精确内容、字体类型、字号比例、位置、材质质感。文字用双引号包裹。

[HARD CONSTRAINTS]
硬约束：负面约束（禁止多指、残肢、文字乱码、面部扭曲等）+ 一致性约束（冻结特征清单）。
```

### 2.2 冻结特征嵌入

在 HARD CONSTRAINTS 块中嵌入冻结特征清单：
```
Character consistency locks:
- Eye color: [冻结的眼瞳色]
- Facial structure: [冻结的面部轮廓]
- Core temperament: [冻结的核心气质表达]
以上特征在系列图中必须保持一致。
```

### 2.2.1 消费美术设定集·人物篇冻结提示词：去 no text，加 EXACT TYPOGRAPHY

OC 以美术设定集·人物篇为角色本体（Step 0.5），会读取人物篇的「冻结提示词」。但**该冻结提示词是定妆图专用**，内含 `no text, no letters, no characters, no watermark, no decorative elements, no border, no seal`——定妆图要纯参考图，OC 立绘必须含文字。

> **矛盾**：若把人物篇冻结提示词原样拼进 OC 提示词，「no text」会压制 EXACT TYPOGRAPHY，导致立绘渲染不出文字，退化成定妆照。

**组装 OC 提示词时的处理规则**：
1. **剥离**：删掉冻结提示词中的文字禁止约束 `no text, no letters, no characters, no watermark, no decorative elements, no border, no seal`（这些属于定妆图，不属于 OC）
2. **保留**：冻结提示词中的人物本体描述（外貌/服饰/特征/姿态/气质/锚点）原样保留，作为 LOCKED COMPOSITION 的角色外观来源
3. **补回**：EXACT TYPOGRAPHY 块必须完整写入六层信息架构（角色名+身份→称号→小传→题诗→书法大字→钤印），见 §2.3
4. **校验**：最终 OC 提示词中**不得残留任何 no text / no letters / no characters 类文字禁止词**，否则文字渲染被压制

> 一句话：人物篇冻结提示词提供"这个人长什么样"，EXACT TYPOGRAPHY 提供"图上要出现哪些字"。两者必须并存，且文字禁止词绝不进入 OC。

### 2.3 文字层翻译

将六层信息架构翻译为 EXACT TYPOGRAPHY 块：
- 每层文字用双引号包裹
- 明确字体类型（书法体/宋体/篆刻体）
- 明确字号比例（相对画面高度）
- 明确位置（底部面板/右侧竖排/四角分布）
- 明确材质质感（鎏金/银白/朱砂/墨色）

### 2.3.1 设定卡传播版模块化文字层（新增）

设定卡传播版不是六层文字，而是模块化信息架构。EXACT TYPOGRAPHY 块按模块逐个声明：

```
EXACT TYPOGRAPHY:
- 顶部标题区："[系列名] [角色名·称号·身份]"（书法体，鎏金质感）
- 属性栏：横条，每项"境界·金丹" "武器·青锋" "天赋·噬魂"（宋体，≤4字/项，最多5-6项）
- 配色板：3-5个色块 swatch（无文字，仅色块）
- 花语："[花名]" + 花语短句（≤8字，楷体）
- 境界徽章："[徽章名]"（篆刻/灵纹式）
- 语录："[台词]"（1句≤15字，楷体，底部）
```

> **文字密度铁律**：Seedream 5.0 Pro 稳定处理 4-6 个短文本区块。传播版模块多，文字必须精简，总模块≤7。信息量过大时**宁可减少模块数**保文字清晰，也不要塞满导致乱码。

### 2.4 参考图与提示词配合策略

> **核心原理**：Seedream 的参考图机制中，**提示词细节量与参考图影响力成反比**。提示词越详细→参考图影响越弱；提示词越简洁→参考图影响越强。选错模式是参考图生图翻车的首要原因。

如果用户提供了参考图或在 Step 1 搜到了 Pinterest 参考图，根据用户意图选择以下三种配合模式之一：

#### 模式A：全面参考（参考图主导，提示词只改差异）

**适用场景**：用户喜欢参考图的整体效果（画风+构图+光影+氛围），只需把图中角色换成自建角色。

**提示词原则**：≤200字，只写差异，不抢控制权。参考图已是一张完整图，提示词的任务是"微调"而非"重画"。

```
参考图中的画风、色调、光影和构图保持不变。
将图中角色替换为：[角色档案核心特征，仅关键外貌差异]
文字层：[文字内容、位置、字体类型、材质质感]
```

**禁止**：不使用4块结构，不写镜头/光源/配色/渲染要求——这些全部交给参考图。
**冻结特征**：角色核心识别特征（眼瞳色/面部轮廓/核心气质）必须在替换描述中明确指定。
**风险**：可能过于类似参考图（洗稿感）。如用户反馈太像，切换为模式B。

#### 模式B：画风参考（放开吸收，提示词控制画面）

**适用场景**：用户只想吸收参考图的画风/笔触/色彩系统/光影氛围，人物形象和构图由提示词控制。

**提示词原则**：放开吸收公式声明吸收范围 + 4块结构控制画面（画风维度放权，其余维度全写）。

```
参考这张图的画风质感、色彩系统和光影氛围：柔和数字插画笔触，painterly soft-focus质感，人物精致细腻的画风，[色彩倾向描述]，[光影氛围描述]。
仅排除图中具体场景内容和人物长相——场景里的物品、环境元素、人物五官长相不参考。

LOCKED COMPOSITION:
[完整锁定构图——镜头/角色定位/外观/动作/背景层次]

ENVIRONMENT AND LIGHTING:
[光源设计+渲染要求——但不写色彩方案，配色交给参考图]

EXACT TYPOGRAPHY AND PLACEMENT:
[文字层]

HARD CONSTRAINTS:
[负面约束+冻结特征清单]
```

**关键**：
1. **正向吸收**：明确列出要吸收的要素——画风质感（笔触/渲染）+ 色彩系统（色调倾向/饱和度/明暗）+ 光影氛围（光源/氛围/空气感）+ 人物精致度，落到具体词，不写"参考风格"这种模糊词
2. **最小排除**：只排除两样——具体场景内容（场景物品/环境元素）和人物长相（五官/脸型）。**"人物长相"排除正好保护角色一致性**——冻结特征不受参考图影响，系列图仍保持同一人
3. **构图不被参考图传导**：LOCKED COMPOSITION 块锁定构图，角色站位/姿态由提示词控制
4. **反向强化**（参考图影响过强时）：将目标描述提到最前面+用量化词+用禁止词+用具体色名。

> **实测结论**（R14 封面同款经验）：放开吸收后画风传递显著增强（柔和 painterly 笔触、通透光效、暖色调过渡、光斑粒子均明显从参考图传导），同时画面主体仍由提示词精确控制。早期"精确分离公式"（排除人物/姿态/服饰/场景/构图/配色，堆"不参考"清单）画风吸收被抑制，用户反馈"等于没参考"。

#### 模式C：纯文生图（提示词主导，无参考图）

**适用场景**：无参考图，或用户要求完全控制画面。使用完整4块高精度模板。

```
[完整的 LOCKED COMPOSITION → ENVIRONMENT AND LIGHTING → EXACT TYPOGRAPHY → HARD CONSTRAINTS]
```

按 §2.1-2.3 的标准4块结构执行，控制全部维度。

#### 模式选择决策树

```
用户提供了参考图？
├─ 是 → 用户想保留参考图的什么？
│   ├─ 整体效果（画风+构图+光影+氛围）→ 模式A：全面参考
│   ├─ 仅画风/笔触/色调 → 模式B：画风参考
│   └─ 仅角色形象（换装/换场景）→ 模式A变体：参考人物形象
│       （提示词写"参考图中的人物形象，保持面部发型不变，[替换内容]"）
└─ 否 → 模式C：纯文生图
```

> **技术注意**：`image` 参数必须使用 data URI 格式 `data:image/png;base64,<base64数据>`。多图参考时每张图分别标注参考范围。

## 3. 确定参数

| 参数 | 默认值 | 说明 |
|:-----|:-------|:-----|
| model | `doubao-seedream-5-0-pro-260628` | Seedream 5.0 Pro |
| size | 按画幅决定（常用1125x1500=3:4，总像素须≤236万） | 详见 seedream-prompt-guide §八 |
| watermark | `false` | 不需要水印 |
| response_format | `b64_json` | 直接返回base64，避免URL下载问题 |
| image | 无 | 参考图 data URI（有参考图时传入） |

## 4. 执行生图（image_generate 工具）

> 生图不再调用 `generate.py` 直连 API（已移除内置 API Key），统一改用 `image_generate` 工具。图生图时传参考图路径。

### 4.1 文生图（无参考图）

```text
image_generate(prompt='[高精度提示词]', size='1125x1500', output='素材/[角色名]OC-v1.png')
```

### 4.2 图生图（有参考图）

```text
image_generate(prompt='[高精度提示词]', size='1125x1500', ref_image='素材/[参考图].png', output='素材/[角色名]OC-v1.png')
```

### 4.3 输出目录

确保输出目录存在，如不存在则创建。

## 5. 系列化循环

如果 Step 1 规划了系列图，在第一张生成完成后进入循环：

### 5.1 循环流程

对系列规划表中的每一张图：
1. **复制冻结特征**：从上一版提示词的 HARD CONSTRAINTS 块中复制冻结特征
2. **更新变量特征**：按系列规划表更新服饰、场景、姿态、文字层
3. **重新组装提示词**：LOCKED COMPOSITION（新姿态）+ ENVIRONMENT（新场景）+ EXACT TYPOGRAPHY（新文字层）+ HARD CONSTRAINTS（冻结特征不变）
4. **执行生成**：文件名递增（v2, v3...）
5. **一致性检查**：对比上一张图，确认冻结特征一致

### 5.2 一致性检查

每张系列图生成后检查：
- [ ] 眼瞳色一致
- [ ] 面部轮廓一致
- [ ] 核心气质一致
- [ ] 文字渲染正确（无乱码）
- [ ] 角色可辨识（同一人）

> 如果一致性不达标，在提示词的 HARD CONSTRAINTS 块中强化冻结特征描述，重新生成。

## 6. 降级机制

| 问题 | 降级策略 |
|:-----|:---------|
| 文字乱码 | 精简文字内容，每层≤15字；或减少文字层数 |
| 角色不一致 | 强化 HARD CONSTRAINTS 中的冻结特征描述 |
| 面部扭曲 | 添加"五官清晰、面部对称、人体结构正常"约束 |
| **模式A太像参考图（洗稿感）** | 切换为模式B：用放开吸收公式只吸收画风，提示词补回构图和角色描述 |
| **模式B画风吸收不足** | 放开吸收范围：删掉"仅排除"限制，允许更自由传导；或切换为模式A让参考图主导 |
| **模式B参考图影响过强** | 将目标描述提到提示词最前面+用量化词+用禁止词"完全不使用[参考图色彩]" |
| **提示词与参考图矛盾** | 检查放权维度：模式A不写画风/构图/光影；模式B不写配色。消除矛盾描述 |
| 整体翻车 | 降级为模式C纯文生图，放弃参考图 |

## 9. 迭代

如果用户对生成结果不满意：

1. 诊断问题维度——是文字渲染问题、角色一致性问题、还是画面整体问题
2. 调整对应提示词块
3. 重新生成（文件名递增 v2, v3...）
4. 更新提示词记录

常见调整方向：

| 用户反馈 | 诊断 | 调整方向 |
|:---------|:-----|:---------|
| 文字乱码 | 文字层过多或过长 | 精简文字，每层≤15字 |
| 角色不像 | 冻结特征描述不够 | 强化 HARD CONSTRAINTS |
| 气质不对 | LOCKED COMPOSITION 姿态描述不准 | 调整姿态和视角描述 |
| 背景太抢 | ENVIRONMENT 块过重 | 简化背景，增加角色占比 |
| 整体偏暗 | 光影描述不够 | 调整 ENVIRONMENT AND LIGHTING 块 |
| 太像参考图 | 模式A放权过度 | 切换为模式B，补回构图和角色控制 |
| 不像参考图风格 | 模式B吸收不足 | 放开吸收范围，删掉"仅排除"限制；或切换为模式A |
| 参考图风格没体现 | 提示词太详细压过参考图 | 精简提示词，在放权维度删除描述词 |
