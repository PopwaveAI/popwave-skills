# Step 2: 生成资产

> 读取确认方案 → 选择参考配合模式 → 组装提示词 → 执行 image_generate → 保存产出 → 系列化循环（如需）

## 设计哲学

Step 2 的核心是**根据参考图使用方式选择正确的提示词策略**——提示词细节量与参考图影响力成反比，选错模式是翻车的首要原因。

三种配合模式：
- **模式A（全面参考）**：参考图主导，提示词≤200字只改差异
- **模式B（画风参考）**：放开吸收画风+4块结构控制画面
- **模式C（纯文生图）**：完整4块高精度模板，控制全部维度

对于系列化产出，通过冻结核心特征+变化变量特征，确保同一设定在不同图中保持一致。

> **HTML 组装档位**（第四档位，画册页）：不走"AI 渲染文字"，而是**两步分工**——①AI 生成一张**无文字主视觉**（图是主角）；②用 `templates/album-card.tpl.html` 组装 HTML 画册页（HTML 是装裱和排版）。详见 `references/mode-album-html.md`。本档位适用文案多/正式推广物料。**主视觉提示词必须保留 no text / no letters（铁律 A2），与 ❌7 剥离逻辑相反，见 §2.5。**

## 1. 读取确认方案

读取 `素材/视觉设计方案.md` 中的记录，提取：
- 设定档案路径（按类型）
- 选定的形态/场景
- 信息架构内容（六层 or 模块化，按类型）
- 布局模板
- 冻结特征列表
- 系列化规划（如需）
- 参考图路径（如有）

## 2. 组装提示词

读取 `../pop-visual-shared/references/seedream-prompt-guide.md` §三 获取高精度模板详细说明（4块结构）。

> **画风DNA来源**：从 `skills/pop-visual-style/references/style-dna-library.json` 取画风的 `dna` + `constraint` 字段。按赛道用 `suggested_genres` 筛选，取 `recommended_lighting` 检查光照兼容性（柔美风格禁用LT1减法照明）。`constraint` 字段加入4块结构的HARD CONSTRAINTS块。详见 `skills/pop-visual-style/references/lighting-composition-templates.md`。

> **注意**：4块结构是模式C（纯文生图）和模式B（画风参考）的控制维度写法。模式A（全面参考）不使用4块结构，只写差异描述。

### 2.1 四块结构

```
[LOCKED COMPOSITION]
锁定构图：主视觉主体、站位/层次、视角、画面分割比例。这一块定义画面的骨架，后续块不得矛盾。

[ENVIRONMENT AND LIGHTING]
环境与光影：背景场景、光源方向、色温、明暗分配、氛围粒子。

[EXACT TYPOGRAPHY]
精确文字：每一层文字的精确内容、字体类型、字号比例、位置、材质质感。文字用双引号包裹。

[HARD CONSTRAINTS]
硬约束：负面约束（禁止多指、残肢、文字乱码、面部扭曲等）+ 一致性约束（冻结特征清单）。
```

### 2.2 冻结特征嵌入

在 HARD CONSTRAINTS 块中嵌入冻结特征清单（按类型）：

```
[Entity] consistency locks:
- [人物] Eye color / Facial structure / Core temperament
- [势力] Camp aesthetic (signature color + ornament)
- [地理] Spatial texture / Atmosphere tone
- [规则] Visual manifestation (light/rune/artifact)
- [场景] Scene keynote / Key elements
以上特征在系列图中必须保持一致。
```

### 2.2.1 消费美术设定集对应篇冻结提示词：去 no text，加 EXACT TYPOGRAPHY

OC 以美术设定集对应篇为设定本体（Step 1.2），会读取对应篇的「冻结提示词」。但**该冻结提示词是复现图专用**，内含 `no text, no letters, no characters, no watermark, no decorative elements, no border, no seal`——复现图要纯参考图，OC 卡必须含文字。

> **矛盾**：若把对应篇冻结提示词原样拼进 OC 提示词，「no text」会压制 EXACT TYPOGRAPHY，导致卡渲染不出文字。

> **⚠️ 档位分流**：如下规则只适用于**前三个档位**（基础版/加强版/设定卡传播版，AI 渲染文字）。**HTML 组装档位恰恰相反**——主视觉必须保留 `no text, no letters`（铁律 A2），跳到 §2.5，不补 EXACT TYPOGRAPHY。

**组装 OC 提示词时的处理规则（前三个档位）**：
1. **剥离**：删掉冻结提示词中的文字禁止约束 `no text, no letters, no characters, no watermark, no decorative elements, no border, no seal`（这些属于复现图，不属于 OC）
2. **保留**：冻结提示词中的设定本体描述（人物外貌/势力美学/地理空间/规则外显/场景基调）原样保留，作为 LOCKED COMPOSITION 的主视觉来源
3. **补回**：EXACT TYPOGRAPHY 块必须完整写入信息架构，见 §2.3
4. **校验**：最终 OC 提示词中**不得残留任何 no text / no letters / no characters 类文字禁止词**，否则文字渲染被压制

> 一句话：美术设定集对应篇冻结提示词提供"这个设定长什么样"，EXACT TYPOGRAPHY 提供"图上要出现哪些字"。两者必须并存，且文字禁止词绝不进入 OC。

### 2.3 文字层翻译

将信息架构翻译为 EXACT TYPOGRAPHY 块：
- 每层文字用双引号包裹
- 明确字体类型（书法体/宋体/篆刻体）
- 明确字号比例（相对画面高度）
- 明确位置（底部面板/右侧竖排/四角分布/模块化布局）
- 明确材质质感（鎏金/银白/朱砂/墨色）

**人物卡六层**：角色名+身份→称号→小传→题诗→书法大字→钤印。

### 2.3.1 设定卡传播版模块化文字层（所有类型通用）

设定卡传播版不是六层文字，而是模块化信息架构。EXACT TYPOGRAPHY 块按模块逐个声明（按类型调整模块）：

```
EXACT TYPOGRAPHY:
- 顶部标题区："[系列名] [实体名·定位]"（书法体，鎏金质感）
- 属性/标签栏：横条，每项"境界·金丹"/"阵营·铁血"/"地标·望月台"/"层级·筑基"（宋体，≤4字/项，最多5-6项）
- 配色板：3-5个色块 swatch（无文字，仅色块）
- 象征/地标/层级："[族徽名]/[地标名]/[境界名]"（楷体，≤4字/项）
- 口号/隐喻/台词："[宣言之句]"（1句≤15字，楷体，底部）
```

> **文字密度铁律（❌8）**：Seedream 5.0 Pro 稳定处理 4-6 个短文本区块。传播版模块多，文字必须精简，总模块≤7。信息量过大时**宁可减少模块数**保文字清晰，也不要塞满导致乱码。

### 2.4 参考图与提示词配合策略

> **核心原理**：Seedream 的参考图机制中，**提示词细节量与参考图影响力成反比**。提示词越详细→参考图影响越弱；提示词越简洁→参考图影响越强。选错模式是参考图生图翻车的首要原因。

如果用户提供了参考图或在 Step 1 搜到了 Pinterest 参考图，根据用户意图选择以下三种配合模式之一：

#### 模式A：全面参考（参考图主导，提示词只改差异）

**适用场景**：用户喜欢参考图的整体效果（画风+构图+光影+氛围），只需把图中主体换成自建设定。

**提示词原则**：≤200字，只写差异，不抢控制权。参考图已是一张完整图，提示词的任务是"微调"而非"重画"。

```
参考图中的画风、色调、光影和构图保持不变。
将图中主体替换为：[设定档案核心特征，仅关键差异]
文字层：[文字内容、位置、字体类型、材质质感]
```

**禁止**：不使用4块结构，不写镜头/光源/配色/渲染要求——这些全部交给参考图。
**冻结特征**：设定核心识别特征必须在替换描述中明确指定。
**风险**：可能过于类似参考图（洗稿感）。如用户反馈太像，切换为模式B。

#### 模式B：画风参考（放开吸收，提示词控制画面）

**适用场景**：用户只想吸收参考图的画风/笔触/色彩系统/光影氛围，设定主体和构图由提示词控制。

**提示词原则**：放开吸收公式声明吸收范围 + 4块结构控制画面（画风维度放权，其余维度全写）。

```
参考这张图的画风质感、色彩系统和光影氛围：柔和数字插画笔触，painterly soft-focus质感，主体精致细腻的画风，[色彩倾向描述]，[光影氛围描述]。
仅排除图中具体场景内容和主体长相——场景里的物品、环境元素、主体五官长相不参考。

LOCKED COMPOSITION:
[完整锁定构图——镜头/主体定位/外观/动作/背景层次]

ENVIRONMENT AND LIGHTING:
[光源设计+渲染要求——但不写色彩方案，配色交给参考图]

EXACT TYPOGRAPHY AND PLACEMENT:
[文字层]

HARD CONSTRAINTS:
[负面约束+冻结特征清单]
```

**关键**：
1. **正向吸收**：明确列出要吸收的要素——画风质感（笔触/渲染）+ 色彩系统（色调倾向/饱和度/明暗）+ 光影氛围（光源/氛围/空气感）+ 主体精致度，落到具体词，不写"参考风格"这种模糊词
2. **最小排除**：只排除两样——具体场景内容（场景物品/环境元素）和主体长相（五官/脸型）。**"主体长相"排除正好保护设定一致性**——冻结特征不受参考图影响，系列图仍保持同一设定
3. **构图不被参考图传导**：LOCKED COMPOSITION 块锁定构图，主体站位/姿态由提示词控制
4. **反向强化**（参考图影响过强时）：将目标描述提到最前面+用量化词+用禁止词+用具体色名

#### 模式C：纯文生图（提示词主导，无参考图）

**适用场景**：无参考图，或用户要求完全控制画面。使用完整4块高精度模板。

```
[完整的 LOCKED COMPOSITION → ENVIRONMENT AND LIGHTING → EXACT TYPOGRAPHY → HARD CONSTRAINTS]
```

按 §2.1-2.3 的标准4块结构执行，控制全部维度。

#### 模式选择决策树

```
用户提供了参考图？
├─ 是 → 用户想保留参考图的什么？
│   ├─ 整体效果（画风+构图+光影+氛围）→ 模式A：全面参考
│   ├─ 仅画风/笔触/色调 → 模式B：画风参考
│   └─ 仅主体形象（换装/换场景）→ 模式A变体：参考主体形象
│       （提示词写"参考图中的主体形象，保持核心特征不变，[替换内容]"）
└─ 否 → 模式C：纯文生图
```

> **技术注意**：`image` 参数必须使用 data URI 格式 `data:image/png;base64,<base64数据>`。多图参考时每张图分别标注参考范围。

### 2.5 HTML 组装档位：无文字主视觉生成（画册页）

> **必读 `references/mode-album-html.md`**（画册页范式 + 三条铁律 + 排版语言）。

HTML 组装档位**不生成带文字的成品图，只生成一张无文字主视觉**。文字全部由 HTML 承载。主视觉提示词与前三档位**相反**——必须保留 no text。

> **🔴 铁律：主视觉必须由 pop 直出（`image_generate` 工具）**。老板验收定调——**本地直出（如 GenerateImage）画面质量远不及 pop 直出的 Seedream**（构图、质感、文字意境、信息层级皆逊色）。HTML 组装档位的主视觉图一律走 `image_generate`（pop 直出），禁止用本地/替代生图工具直接出主视觉。若当前环境无 `image_generate`，**暂停等待 pop 直出，或请用户提供 pop 直出图作为主视觉，不要擅自用本地工具出图**。产出典范见《苟在诸天》「借香他化」规则卡（pop 直出：垂直对称金字塔构、香炉为轴烟雾树状分叉、深海蓝+暖金贵气质感、技能条+Slogan 一体）。

> **🔴 人物卡专项（v3.3.0 铁律 P1）**：人物卡主视觉**必须先剥离美术设定集人物篇冻结提示词中的 `no text` 之外，再确认不含任何"标签/属性/色板"描述**——人物主视觉只画角色本人。若从人物篇冻结提示词继承到 `no text, no letters, no characters` 已满足 P1；**禁止以任何形式在人物提示词里补 EXACT TYPOGRAPHY 或属性/色板/标签**（角色名/称号/属性/色板/tag/台词全由 HTML 承载，见 §4.5 人物卡专项）。

**主视觉提示词组装**（沿用 §2.1 4块结构，但 EXACT TYPOGRAPHY 块替换为文字禁止约束）：

```
[LOCKED COMPOSITION]
锁定构图：主视觉主体（从美术设定集对应篇冻结提示词取设定本体描述）、站位/层次、视角、画面分割。这张图是画册页的主角，构图完整、边界清晰，四周留出呼吸空间。

[ENVIRONMENT AND LIGHTING]
环境与光影：背景场景、光源方向、色温、明暗分配、氛围粒子。

[文字禁止（替代 EXACT TYPOGRAPHY）]
no text, no letters, no words, no characters, no captions, no labels, no watermark, no logo. 画面纯净无任何文字元素。

[HARD CONSTRAINTS]
硬约束：负面约束（禁止多指/残肢/面部扭曲等）+ 一致性约束（冻结特征清单，见 §2.2）。
```

**三条铁律约束（mode-album-html.md）**：
- **A1 图是主角**：主视觉构图要"够格当主角"——主体饱满、层次清晰、有独立画框的完整边界，供 HTML 装裱
- **A2 主视觉零文字**：提示词必须含 `no text, no letters, no words, no characters, no captions, no labels`，禁止 AI 在图上画任何字
- **A3 信息区在图外**：主视觉四周留出呼吸空间，供 HTML 放置标题区/信息区，不压图主体

> **与 ❌7 的关系**：❌7 规定「OC 提示词禁止携带 no text」是针对**前三档位**（AI 渲染文字）。HTML 组装档位是**唯一例外**——它的文字由 HTML 渲染，主视觉反而必须 no text。两条规则各自成立，互不冲突。

## 3. 确定参数

| 参数 | 默认值 | 说明 |
|:-----|:-------|:-----|
| model | `doubao-seedream-5-0-pro-260628` | Seedream 5.0 Pro |
| size | 按画幅决定（常用1125x1500=3:4，总像素须≤236万） | 详见 seedream-prompt-guide §八 |
| watermark | `false` | 不需要水印（后续工程化叠加） |
| response_format | `b64_json` | 直接返回base64，避免URL下载问题 |
| image | 无 | 参考图 data URI（有参考图时传入） |

## 4. 执行生图（image_generate 工具）

> 生图统一改用 `image_generate` 工具。图生图时传参考图路径。

### 4.1 文生图（无参考图）

```text
image_generate(prompt='[高精度提示词]', size='1125x1500', output='素材/[类型][实体名]卡-v1.png')
```

### 4.2 图生图（有参考图）

```text
image_generate(prompt='[高精度提示词]', size='1125x1500', ref_image='素材/[参考图].png', output='素材/[类型][实体名]卡-v1.png')
```

### 4.3 输出目录

确保输出目录存在，如不存在则创建。设定实体卡建议放 `素材/` 项目级展示资产。

### 4.4 叠加品牌水印（必做）

OC 卡是**对外展示产出**，图片落地后用共享水印脚本叠加半透明 `popwave.cn` 小字水印（工程化后处理，**不进提示词**，避免污染 Seedream 文生图）：

```
python skills/pop-visual-shared/scripts/watermark.py '素材/[类型][实体名]卡-v1.png'
```

- 默认：右下角，alpha=80（约31%不透明，低调可见）
- **幂等**：脚本通过元数据标记自动跳过已含水印的图，重复运行不叠加
- 若需调整位置/透明度：`--pos 左下 --alpha 60`（一般用默认即可）
- 校验：跑完后二次运行 `watermark.py <图>` 应输出"已含水印，跳过"，确认水印已加

> ⚠️ **HTML 组装档位不走 `watermark.py`**：品牌水印已作为 HTML footer 内嵌（`popwave.cn 让创意一键落地`），比图片水印更清晰更可控。**跳过 §4.4，直接走 §4.5 HTML 组装。**

### 4.5 HTML 组装档位：组装画册页成品（两步之第二步）

生成无文字主视觉后，用 `templates/album-card.tpl.html`（规则/势力/地理/场景卡）或 `templates/album-character.tpl.html`（**人物卡多表达**）组装 HTML 成成品：

1. **读取模板**：`skills/pop-visual-oc/templates/album-card.tpl.html`（画册页样板）或 `album-character.tpl.html`（人物卡多表达样板，含 CSS 装裱 + `{{变量}}` 占位）
2. **填主视觉**：将生成的无文字主视觉复制到 `素材/`，替换模板中的图片路径占位符；主视觉作为独立 `<figure>` 图框主体（铁律 A1）
3. **填文案**：按 Step 1 门禁B 确认的信息架构，替换标题区/信息区占位符（实体名、定位、箴言、核心气质、等级色板、象征词条、类型标签、系列名）。**文案必须按 `references/mode-album-html.md` §文案设计规范 公式填写**——定位线≤14字、箴言有代价/反转、机制人话可复述、象征键=具象物；**组装前必过文案稳定性四问（有钩子/讲清机制/无黑话/圈外人3秒懂），任一不通过回写修正后再组装，禁止带介绍句风格的无钩子文案**
4. **调排版**：按 `mode-album-html.md` §排版语言对齐精致度——渐变文字、双线边框、四角金印、图框金色托线、色块 swatch；信息区全部在图框之外（铁律 A3）
5. **本地预览**：主视觉与 HTML 同目录，`python -m http.server` 本地预览确认排版
6. **截成长图**：用 `scripts/screenshot_album.py` 把画册页截成高清长图（交付形态，与漫画同构）
7. **落地**：HTML 复制到 `素材/[类型][实体名]-画册页.html`，footer 品牌水印已内嵌；长图落地到 `素材/[类型][实体名]-画册页-长图.png`

> **画册页三铁律（mode-album-html.md）**：①A1 图是主角，HTML 是装裱（禁止图铺满当 background）；②A2 主视觉零文字（AI 不画字，文案全由 HTML 承载）；③A3 信息区在图框之外，不压图主体。

#### 4.5.0 人物卡 HTML 组装专项（v3.3.0 铁律 P1-P3 + v3.5.0 多表达图格）

人物卡是信息量最大的类型，**HTML 组装版必须承载角色名/称号/属性栏/配色板/花语/台词/题诗/小传/表情差分全部模块**，主视觉只画角色本人（铁律 P1）。**v3.5.0 起默认启用多表达图格**（主视觉 + 表达图格区，打破单图单调）。按 `references/mode-character-multi.md` + `references/mode-character.md` §人物卡 HTML 组装版 + `mode-album-html.md` §人物卡专项组装，用 `templates/album-character.tpl.html`：

1. **主视觉**：纯净人物立绘（零文字零标签零色板，角色占画面≥60%）
2. **顶部标题区**：系列名 / 「人物设定卡」标签 / 角色名（鎏金大字）/ 身份定位
3. **称号区**：四字格称号（方框衬底，标题区下方）
4. **属性栏**：境界/阵营/煞兽/秘法/命格（≤4字/项，5-6项，图框外横条）
5. **配色板**：角色代表色系 swatch（无字仅色块）
6. **花语象征**：代表花 + 花语短句（≤8字）
7. **台词**：代表性台词（≤15字）
8. **题诗**：七言对仗（意象驱动法）
9. **小传**：60-100字微型人物志（HTML 精确排版，可竖排或分栏）
10. **表情差分**：2-4 个表情小图（可选，图框旁）
11. **品牌水印**：footer 内嵌

**多表达图格区（v3.5.0，人物卡增强）**：
1. 读 `templates/album-character.tpl.html`，按 Step 1 确认的图格类型设 `variant_type=state/view/daily`（state 2列竖图 / view 4列方图 / daily 3列横图）
2. 每格替换为 `<div class="variant"><span class="idx">n</span><span class="stat">状态类型</span><img src="图格路径"><span class="lbl">标签</span></div>`
3. **图格零文字**：图格与主视觉一样是无文字纯图（提示词保留 no text），状态名/视角名/场景标注全由 HTML 承载
4. **一致性锚点**：所有图格同一张脸（眼瞳/轮廓/气质/关键配饰），是同一角色的不同切面，不是两个角色
5. 图格不单独叠水印，整体卡 footer 水印即可

> **人物卡三铁律**：P1 主视觉零文字零标签零色板；P2 信息区全部在图框外；P3 角色是绝对主角（≥60% 画面）。违反任一即打回重做。

#### 4.5.1 画册页截成长图（必做，交付形态）

画册页是长图文案载体，**HTML 组装完成后必须截成一张高清长图**（与漫画 `screenshot_comic.py` 同构）：

```
python skills/pop-visual-oc/scripts/screenshot_album.py \
  '素材/[类型][实体名]-画册页.html' \
  '素材/[类型][实体名]-画册页-长图.png'
```

- 高清：Playwright 整页 `full_page` + `deviceScaleFactor=2`（默认 680px 视口 ×2 → 1360px 宽长图），底部质量不退化
- 自动等图：自动移除 lazy loading + 等待所有 `<img>` 完全加载后再截图
- 输出：PNG 无损长图（`-长图.png`），与 HTML 同目录落地
- 可选：`SCREENSHOT_WIDTH` 调视口宽、`SCREENSHOT_SCALE` 调倍率

> **失败中断**：若长图缺顶部标题区/主视觉/信息区/品牌水印任一区段，视为截图失败，修正 HTML 后重截，禁止带残缺长图交付。

## 5. 系列化循环

如果 Step 1 规划了系列图，在第一张生成完成后进入循环：

### 5.1 循环流程

对系列规划表中的每一张图：
1. **复制冻结特征**：从上一版提示词的 HARD CONSTRAINTS 块中复制冻结特征
2. **更新变量特征**：按系列规划表更新服饰/场景/姿态/层级/文字层
3. **重新组装提示词**：LOCKED COMPOSITION（新姿态）+ ENVIRONMENT（新场景）+ EXACT TYPOGRAPHY（新文字层）+ HARD CONSTRAINTS（冻结特征不变）
4. **执行生成**：文件名递增（v2, v3...）
5. **一致性检查**：对比上一张图，确认冻结特征一致

### 5.2 一致性检查

每张系列图生成后检查（按类型）：
- [ ] 冻结特征一致（人物=眼瞳/轮廓/气质；势力=阵营美学；地理=空间氛围；规则=视觉外显；场景=场景基调）
- [ ] 文字渲染正确（无乱码）
- [ ] 设定可辨识（同一设定）

> 如果一致性不达标，在提示词的 HARD CONSTRAINTS 块中强化冻结特征描述，重新生成。

## 6. 降级机制

| 问题 | 降级策略 |
|:-----|:---------|
| 文字乱码 | 精简文字内容，每层≤15字；或减少文字层数 |
| 设定不一致 | 强化 HARD CONSTRAINTS 中的冻结特征描述 |
| 主体扭曲/损坏 | 添加"主体结构正常、细节清晰、形态完整"约束 |
| **模式A太像参考图（洗稿感）** | 切换为模式B：用放开吸收公式只吸收画风，提示词补回构图和主体描述 |
| **模式B画风吸收不足** | 放开吸收范围：删掉"仅排除"限制，允许更自由传导；或切换为模式A让参考图主导 |
| **模式B参考图影响过强** | 将目标描述提到提示词最前面+用量化词+用禁止词"完全不使用[参考图色彩]" |
| **提示词与参考图矛盾** | 检查放权维度：模式A不写画风/构图/光影；模式B不写配色。消除矛盾描述 |
| 整体翻车 | 降级为模式C纯文生图，放弃参考图 |

## 9. 迭代

如果用户对生成结果不满意：

1. 诊断问题维度——是文字渲染问题、设定一致性问题、还是画面整体问题
2. 调整对应提示词块
3. 重新生成（文件名递增 v2, v3...）
4. 更新提示词记录

常见调整方向：

| 用户反馈 | 诊断 | 调整方向 |
|:---------|:-----|:---------|
| 文字乱码 | 文字层过多或过长 | 精简文字，每层≤15字 |
| 设定不像 | 冻结特征描述不够 | 强化 HARD CONSTRAINTS |
| 气质不对 | LOCKED COMPOSITION 姿态描述不准 | 调整姿态和视角描述 |
| 背景太抢 | ENVIRONMENT 块过重 | 简化背景，增加主视觉占比 |
| 整体偏暗 | 光影描述不够 | 调整 ENVIRONMENT AND LIGHTING 块 |
| 太像参考图 | 模式A放权过度 | 切换为模式B，补回构图和主体控制 |
| 不像参考图风格 | 模式B吸收不足 | 放开吸收范围，删掉"仅排除"限制；或切换为模式A |
| 参考图风格没体现 | 提示词太详细压过参考图 | 精简提示词，在放权维度删除描述词 |

> 迭代模式（快速路径）：用户要求修改已生成图时跳过 Step 0/1，直接读 `素材/视觉设计方案.md` 上一版方案，进入 §2-§9 修改对应维度重新生成。
