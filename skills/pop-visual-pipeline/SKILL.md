# pop-visual-pipeline

> 小说视觉化安装器。**v4.2.0：状态来源收敛为 `状态.md`，路由上移至专家提示词**——pipeline 只负责初始化、导入、三态迁移与状态维护；下游 asset/style/art-bible 同步改读 状态.md。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 做什么

pipeline 只负责安装、导入与状态维护，不承担实际生产——初始化或导入时生成或重建 `状态.md`（唯一状态总账）、执行三态写入迁移，并按状态片段把 agent 指向对应子 skill；**日常视觉路由与意图判定上移专家提示词**（两段式架构：基建层必做，派生层按需）。

输入：本项目名称或当前项目目录（mode=fresh/import/resume）
输出：标准化目录结构、`状态.md`（唯一状态总账），以及可选的 `视觉项目总控.html` 展示面板

**核心价值**：把"**查原文、定画风、产出美术设定集即为基建**"这条铁律固化在状态与导入流程中——visual 群原本是 7 个没有顺序约束的分散 skill，会出现"尚未确定画风就先绘制封面"的乱序问题。

**日常路由不经过本 skill**：用户说"继续视觉/出封面/出OC/出漫画"时，主 agent 按**专家提示词阶段地图**调度——先过意图判定确认本次目标（cover/oc/comic/full/asset-only，不默认推漫画），再读取 `状态.md` 获取状态片段（phase/intent/next_step/就绪态），然后按两段式阶段地图（基建层查原文、定画风、美术设定集必做；派生层按需）与就绪检查直接选择 skill。各子 skill 按自身 SKILL.md 执行，pipeline 不参与每轮路由。

### 状态.md（薄机器状态，唯一状态总账）

该文件写入项目根目录，agent 每轮只读取它获取状态片段。模板见 `templates/状态.md`，内容如下：

```markdown
mode: fresh            # fresh/import/resume
phase: init            # init/0/1/2/3/4/5/6
intent: 待确认         # cover/oc/comic/full/asset-only（意图确认值）
project_type: 独立      # 起点/番茄/独立（写作专家项目探测自源项目 状态.md）
next_step: Phase 0: 按意图档位读小说提取视觉资产
project_name: 未命名项目
book_name: 待指定
genre: 待指定
style_base: 待Phase 1指定
core_char: 待Phase 2指定
created_at: --
updated_at: --

## 就绪态（[x]=就绪 / [ ]=未就绪；就绪判定查文件系统）
基建就绪: 资产提取[ ] 画风基准[ ] 美术设定集[ ]
派生就绪: 封面[ ] 人物OC[ ] 场景[ ] 漫画[ ]

## 最近产出
- {Phase名}: {产出文件路径} | {时间}
```

## 怎么操作（规程全内联）

### Step 0 初始化（state=init 且无已有文件）

本步只打地基：创建标准目录、生成 状态.md 并自检。

**1. 项目空间探测**（用 LS 扫描项目根）：若根目录存在 `状态.md`，则为写作专家项目（起点或番茄）——按内容标记判定：含 `## 书目` 与 `立项就绪`/`世界就绪` 者为起点，含 `## 底牌就绪` 与 `## 阶段完成情况` 者为番茄；若存在原文 `正文/ch*.txt`，则 import 走 Step 1；若存在 `原料/小说原文/`（单个完整 txt），则为独立小说项目，走 init；若用户指定路径，则为临时模式，走 init。判定结果写入 状态.md 的 `project_type` 字段。

**2. 🚪 意图判定（前置步骤，决定基建档位）**：由 `AskUserQuestion` 或书面提问确认本次目标，将 intent 写入 状态.md 的 `intent` 字段，整条流程按档位路由——`cover` 制作封面或场景图（轻量档：场景资产表、视觉符号、画风；刊物角色可跳过双角度定妆）｜`oc` 制作人物 OC 或立绘（轻量至中档：角色档案、身份卡、画风；可跳过双角度定妆）｜`comic` 制作漫画或连载（完整档：深度角色档案、画风定标、身份卡、双角度定妆）｜`full` 全套视觉工程（完整基建）｜`asset-only` 只提取资产（最轻档，只执行 asset，不进入派生层）。**未明确时不默认漫画，须回问用户**——只有明确说"做漫画或连载"才走 `comic` 完整档。

**3. 创建标准目录**（LS 确认，不存在则创建；分区口径见 `references/落盘规范.md`）：

```
{项目}/正文/
{项目}/素材/视觉资产/      # 基建真源：设定档案（asset 产出）
{项目}/素材/风格/           # 基建真源：画风决策 + 冻结定标图
{项目}/素材/ref-cache/      # 基建真源：Pinterest 参考图
{项目}/漫画/assets/characters/   # 漫画工程：定妆生产参考
{项目}/成品/                # 三态-成品：用户确认的对外发布图
{项目}/测试/                # 三态-测试：未确认候选/变体/定标/定妆初稿
{项目}/_过程/               # 三态-过程：原始图/脚本/任务清单/提示词记录
```

> **不得**再建 `素材/视觉/` 扁平目录；候选、定标、复现一律按三态写入（见红线 6）。

**4. 生成 状态.md**：读取 `templates/状态.md` 并写入项目根目录，按「状态更新协议 §1」填充：`mode=fresh`｜`phase=init`｜`intent=意图确认值`｜`project_type=探测值`｜`project_name`｜`book_name`/`genre=待指定`｜`created_at`/`updated_at=当前时间`｜`next_step=Phase 0: 按意图档位读小说提取视觉资产`。**展示面板（可选）**：仅当老板要看可视化面板时，按 `templates/视觉项目总控.html` 套用 状态.md 的值导出 html——agent 不读取 html。

**5. 自检并进入 Phase 0**：确认 9 个标准目录存在、状态.md 已生成且字段正确、phase=init 且 next_step=Phase 0。通过后按专家提示词阶段地图路由至 `pop-visual-asset` 执行 Phase 0（基建层）；pipeline 不参与后续每轮路由。

### Step 1 导入/续写（检测到已有项目文件，state=import/resume）

**import 遵循"补齐不重做"原则：已有资产保留，不覆盖重建。**

**1. 资产清点**（扫描项目根）：检查 `正文/ch*.txt`（小说原文）、`素材/视觉资产/[角色名]角色档案.md`（资产提取已完成）、`素材/风格/画风决策.md`（画风已定）、`素材/美术设定集.md`（基建真源）、`成品/` `测试/` `_过程/`（已有派生图）与 `漫画/`（已有漫画产出）。

**2. 旧目录三态迁移（存量项目必做）**：检测到旧结构目录时，按 `references/落盘规范.md` §七迁移表归位，**不得留在旧位置**。核心映射：`generated-images/`（原始 UUID 生成图）→`_过程/原始图/`；`归档/旧版产出/`（未确认旧版图）→`测试/{类型}/`；`归档/中间产物/`与`归档/工作脚本/`→`_过程/脚本任务/`；`素材/视觉/`内确认对外图→`成品/{类型}/`（加`-final`）、未确认候选→`测试/`；`素材/视觉设计方案.md`→`_过程/提示词记录.md`；`素材/风格/`未冻结定标图→`测试/画风定标/`、已冻结定标图→原位保留（基建真源）。迁移后更新 状态.md 的 `phase`/`next_step` 与就绪态为三态路径，并将本次动作写入 `_过程/迁移记录.md`。

**3. 生成或更新 状态.md 并过意图判定**：若有散落资产而无 状态.md，则读取模板 `templates/状态.md` 生成并按清点结果填充；若已有 状态.md，则按「状态更新协议」读取并更新。`intent` 为空或未确认时，用 `AskUserQuestion` 询问本次目标（见 Step 0 意图判定）；已确认则沿用，不重复询问。

**4. 判定 Phase 决策**（按清点结果）：有正文、无资产或画风或设定集→**init**（从 Phase 0 补做）｜有资产、无画风或设定集→**phase1**（补做 Phase 1 定画风）｜有资产与画风、无设定集→**phase2**（补做 Phase 2 产美术设定集）｜有美术设定集（基建完整）→**phase3+**（基建就绪，按需进入派生层）｜有基建且有派生图→按用户意图进入派生层路由。

**5. 基建缺口补做**：基建层（Phase 0/1/2）有缺口时须补齐才能进入派生层——缺资产→`pop-visual-asset`｜缺画风→`pop-visual-style`｜缺美术设定集→`pop-visual-art-bible`。已有资产须归位到标准目录，不得散落。

**6. 更新 状态.md**：按 `references/状态更新协议.md`（通用字段与 phase 推进）更新 `phase`/`mode`/`updated_at`/`next_step` 与就绪态，已完成的阶段标注 `[x]`。

### Step 2 日常路由（不经常驻循环）

**日常视觉路由不经过本 skill**——用户说"继续视觉/出封面/出OC/出漫画"时，主 agent 按**专家提示词阶段地图**调度，pipeline 不参与每轮路由。调度顺序：**先过意图判定确认本次目标**（cover/oc/comic/full/asset-only，不默认推漫画），再**读取 `状态.md`** 获取状态片段（phase/intent/next_step/就绪态），然后按下方「阶段地图」与就绪检查直接选择子 skill。pipeline 只在初始化、导入、三态迁移与状态维护时被调用。

> 「阶段地图」即下方 Phase 路由表——它是专家提示词路由的唯一口径（与 `skill.json` 的 `skills` 数组一致），pipeline 初始化完成后即交回给专家提示词使用。

### Phase 路由表（阶段地图 · 专家提示词路由口径）

> **两段式架构**：Phase 0-2 是**基建层**（必做，顺序不可跳），Phase 3-6 是**派生层**（按需，在基建就绪后任意触发）。

| Phase | 调用Skill | 定位 | 前置检查 | 产出 |
|:--|:--|:--|:--|:--|
| **0** | `pop-visual-asset` | 查原文 | state=init/import+正文文件就绪 | `素材/视觉资产/`（角色档案+场景资产表+视觉符号库+IP视觉DNA） |
| **1** | `pop-visual-style` | 定画风 | 资产就绪 | `素材/风格/画风决策.md`（选定基准+配色+风格串）+ **画风定标图** |
| **2** | `pop-visual-art-bible` | 产美术设定集 | 资产+画风就绪 | `素材/美术设定集.md`（画风/人物/场景/符号/一致性五篇合一，全下游唯一真源）+ **复现资产（定妆图/场景图）** |
| **3** | `pop-visual-cover` | 封面图 | 基建就绪 | 候选→`测试/封面/`，确认→`成品/封面/` |
| **4** | `pop-visual-oc` | 人物OC | 基建就绪 | 候选→`测试/{类型}/`，确认→`成品/{类型}/` |
| **5** | `pop-visual-cover`(场景) | 场景图 | 基建就绪 | 候选→`测试/场景/`，确认→`成品/场景/` |
| **6** | `pop-visual-comic` | 漫画 | 基建就绪 | `漫画/`（定妆图+分镜+漫画页+HTML） |

> **派生层触发（按 intent）**：Phase 3-6 非线性，由 intent 决定去向——`cover`→Phase3/5，`oc`→Phase4，`comic`→Phase6，`full`→loop 3-6，`asset-only`→停在 phase0。

## 🚪 首次对话引导（onboarding）

首次触发视觉专家（无任何视觉项目、非续写）时，先在回复中**直接粘贴 `references/onboarding-guide.md` 全文**以建立认知（声明本次为功能介绍与引导、未执行任务），再用一到两句话补充"报书名与形态即可开始"；用户已明确要开始制作时，跳过引导直接执行。派生层不单独引导，统一由本 pipeline 总入口负责。

---

## 执行模式

**由主 agent 直接执行**。Step 0/1 的初始化与导入均由主 agent 直接执行；子 skill 的实际生产环节由主 agent 读取其 SKILL.md 后按规程操作，或（派生层 phase3-6）派发子 agent 执行——子 agent 的指令须显式要求读取对应 SKILL.md，不得凭记忆"扮演"。pipeline 自身无产出，不存在可派发的只读子任务。日常路由交由专家提示词，pipeline 不做常驻循环。

---

## 红线

1. **读取协议**：日常每轮对话的第一件事是读取项目根目录的 状态.md，获取当前 phase 与 intent，再按阶段地图（专家提示词口径）调度；不得跳过读取 状态.md 直接开始生产。`状态.md` 是唯一状态总账，不得另建 project-state.md，也不得读取 html 获取状态。
2. **pipeline 只负责路由，不承担实际生产**——所有产出由下游 skill 生成。pipeline 不直接提取资产、不选画风、不产出美术设定集、不画图、不生成漫画。
3. **基建依赖链与就绪检查不可跳**——资产未就绪不得进入定画风，画风未就绪不得进入美术设定集；进入派生层（Phase 3-6）前须验证美术设定集（`素材/美术设定集.md`）存在且签核 ✅ 已认可、画风决策签核 ✅ 已认可。未签核即报错中止，并提示先执行基建、完成设定集冻结。
4. **美术设定集是唯一真源**——派生层（cover/oc/comic）只消费美术设定集，不得各自重建人物、场景、符号与画风。视觉事实改动须回到 art-bible 升级设定集版本。
5. **意图判定前置，不默认推漫画**——intent 为 `cover`/`oc`/`asset-only` 时不自动进入漫画；未明确意图时回问用户，不得假设用户奔漫画去。
6. **三态写入强制（`references/落盘规范.md`）**——所有派生产出按生命周期写入：候选→`测试/{类型}/`，确认→`成品/{类型}/`（加 `-final`），脚本、原始图、任务清单→`_过程/`。不得再写扁平 `素材/视觉/`，不得将 UUID 命名的生成图堆放到 `generated-images/`，不得使用 `-V1`/`--v1` 版本变体。

## 速查表

| 文件 | 读取时机 | 核心内容 |
|:--|:--|:--|
| `状态.md`（项目根） | 每次对话第一件事 | 唯一状态总账（mode/phase/intent/next_step、就绪态、最近产出） |
| `references/状态更新协议.md` | phase 完成后更新 状态.md 时（含 Step 0/1 执行） | 通用字段更新、phase 推进与就绪态规范（单源） |
| `references/落盘规范.md` | 任何写入、迁移或命名时 | 三态分离、统一命名、版本 final 标记、skill 映射与旧目录迁移表 |
| `templates/视觉项目总控.html` | 仅老板要看可视化面板时 | 由 状态.md 的值套用模板导出的展示面板，agent 不读取 |
| `references/onboarding-guide.md` | **首次触发视觉专家时输出** | 首次对话引导语（功能全景、意图判定与引导第一步） |
