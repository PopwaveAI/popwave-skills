# 视觉管线 · 文件夹分区落盘规范

> 本文件是 **pop-visual-pipeline 定义、全 visual 子 skill 必须遵守** 的落盘唯一权威源。v2.0.0
> 目的：根治「过程文件 / 测试文件 / 成品确认文件」不分、同图多版本难区分、跨 skill 命名不统一的乱象。
> v2.0.0：补齐视频（pop-video-comic / pop-comic-content 出片）与内容（pop-comic-content 文本三件套）两条子管线，覆盖漫画自体系命名，全链路统一。

---

## 一、核心原则：三态分离（生命周期 = 最高分区维度）

视觉产出按「生命周期」分三态落盘，**全 skill 统一遵守**：

| 三态 | 目录 | 定义 | 人看不看 | 可清理 |
|:--|:--|:--|:--|:--|
| **成品** | `成品/` | **用户确认的对外发布图**（封面/OC卡/画册页/势力地理规则场景卡） | ✅ 给人看/分享 | ❌ 保留 |
| **测试** | `测试/` | **未确认的候选/变体/定标/定妆初稿** | ⚠️ 仅中间审阅 | ✅ 可清理 |
| **过程** | `_过程/` | **中间产物**（生成脚本/任务清单/原始图/提示词迭代记录） | ❌ 不给人看 | ✅ 可清理 |

> 基建真源（`素材/`）与漫画工程（`漫画/`）、视频工程（`视频/`）、内容物料（`内容/`）不属三态，属"生产参考/自体系/内容成品"，见 §四 §五。

• **`测试/` 也容纳 `画册页/` 子目录**（画册页主视觉候选独立归类，避免与人物/规则候选混淆）。
• 视频属 `视频/` 自体系：`preview/` `frames/` `audio/` 是过程，`成品-*.mp4` 是成品（须带 `-final`）；内容属 `内容/` 自体系：三件套确认后即内容成品。

---

## 二、为什么（命中乱象）

老板实测「苟在诸天」项目发现四项乱象，本规范逐一根治：

1. **`素材/视觉/` 扁平大杂烩** → 封面/OC/画册页/定妆/场景全塞一个目录 → 拆为顶层 `成品/` `测试/` `_过程/` 三态。
2. **`generated-images/` 脱离规范** → image_generate 原始图按 UUID dump → 收敛到 `_过程/原始图/`。
3. **`归档/` 事后人为补救** → 旧版/脚本/任务清单被手动归档 → 规范内定义 `测试/`（旧版候选）与 `_过程/`（脚本任务）的归属。
4. **版本命名不统一** → `-v1/--v1/-V1` 混用、同名不同内容 → 统一 `vN` + `-final` 标记（§三）。

## 三、统一命名规范（全 skill 强制）

### 3.1 文件名公式

```
{实体类型}-{实体名}-{用途}-v{版本}.{ext}
```

- **实体类型**：`封面` `OC` `势力卡` `地理卡` `规则卡` `场景卡` `画册页` `定妆` `定标` `复现` `场景`
- **实体名**：角色/势力/地名/规则/场景名（如 `李玄` `琉璃寺` `菩提城`）
- **用途**：`主视觉` `正` `侧` `长图` `多视角` 等（非必有）
- **版本**：统一小写 `v1` `v2` `v3`… 递增，**禁止 `-V1`/`--v1`/`v1.0` 等变体**
- **ext**：图片统一 `.png`（发布用底图），`-长图.png` 为 HTML 截图拼合形态

**画册页主视觉**（HTML 组装版候选底图）统一用 `画册主视觉` 作用途：`OC-借香他化-画册主视觉-v2.png`（落入 `测试/画册页/`），确认后组装 HTML → `成品/画册页/OC-借香他化-画册页-v2-final.html` + `-长图-final.png`。

### 3.1b 视频与内容命名（自体系，遵循同名版本+final 法则）

| 产出 | 命名公式 | 示例 |
|:--|:--|:--|
| 漫画视频成品 | `第{章节N}-v{版本}-final.mp4` | `第1章-v1-final.mp4` |
| 配音版视频 | `第{章节N}-配音-v{版本}-final.mp4` | `第1章-配音-v1-final.mp4` |
| 视频候选/预览 | `preview/` 帧，`-preview-v{版本}` 标版本 | `t_02.0-preview-v1.png` |
| 内容三件套 | `口播脚本.md` `种草安利笔记.md` `短视频推广文案.md`（确认后即内容成品，无版本） | — |
| 漫画定妆图 | `char-{角色}-v{版本}-{正/侧}.png` | `char-李玄-v1-front.png` |

### 3.2 版本与成品标记

- 同一实体所有历史版本**平铺保留**：`OC-李玄-v1.png` / `-v2.png` / `-v3.png`
- **用户确认后**：最终版复制到 `成品/` 并加 `-final`：`成品/OC/OC-李玄-v3-final.png`
- `-final` 是**唯一成品态标记**；`测试/` 内不标 final，`_过程/` 内不讨论版本
- 封面/视频同理：确认版必须带 `-final`，未标 `-final` 的封面/视频一律视为候选，不得留在 `成品/`

### 3.3 与小说侧命名不重名（跨管线隔离）

视觉顶层目录与小说写作管线（起点/番茄）顶层**完全不撞**：

| 视觉侧（本规范） | 小说侧（起点/番茄） |
|:--|:--|
| `成品/` `测试/` `_过程/` `漫画/` `视觉项目总控.html` | `素材/` `设计/` `正文/` `审核/` `项目总控.html` `project-state.md` |

- `正文/` 是**唯一共享**目录（小说写、视觉读），其余顶层各自独立。
- `素材/` 虽共用顶层，但视觉只写子目录 `视觉资产/` `风格/` `ref-cache/` 与文件 `美术设定集.md`，与小说侧扁平的 `素材/*.md`（用户意图/赛道调研/文风锚定）**不重名、不混淆**。
- **禁止视觉 skill 新建与小说侧重复的顶层目录名**（不得建 `设计/` `审核/` 等）。

## 六、通用铁律

1. **三态不混落** — 未确认图进 `测试/`，确认对外图进 `成品/`，脚本/原始图/任务清单进 `_过程/`。禁止把三种文件塞同一目录。
2. **版本统一 `vN`，成品标 `-final`** — 禁止 `-V1`/`--v1`/`v1.0` 变体；`-final` 是唯一成品态标记。
3. **不建重复顶层目录名** — 不得与小说侧 `素材/设计/正文/审核` 重名；不得与兄弟产出目录重名。
4. **基建真源只读消费，改动回 skill 升级版本** — 派生层只消费 `素材/美术设定集.md` 等冻结真源，禁止各自重建。
5. **`_过程/` 默认 gitignore / 不提交** — 过程产物不进版本库，避免污染。
6. **视频/内容自体系同样遵循版本+final** — 视频成品必须是 `第{N}章(-配音)-vN-final.mp4`，禁止裸名 `成品.mp4`；`preview/frames/audio/` 是过程不进成品态。<br>内容三件套确认后即在 `内容/`，是文本成品（无版本），未确认不写入 `内容/`。

## 七、旧结构迁移规则（step1-import 复用）

迁移旧项目到新结构时，按下表归位：

| 旧位置 | 旧内容 | → 新位置 |
|:--|:--|:--|
| `generated-images/` | 原始 UUID 生成图 | `_过程/原始图/` |
| `归档/旧版产出/` | 未确认旧版图 | `测试/{类型}/` |
| `归档/中间产物/` `归档/工作脚本/` | 任务清单/脚本 | `_过程/脚本任务/` |
| `素材/视觉/` 内确认对外图 | 封面/OC/画册页 | `成品/{类型}/`（加 `-final`） |
| `素材/视觉/` 内未确认候选 | 定标/变体 | `测试/` |
| `素材/视觉设计方案.md` | 迭代记录 | `_过程/提示词记录.md` |
| `素材/风格/` 未冻结定标图 | 画风定标 | `测试/画风定标/` |
| `素材/风格/` 已冻结定标图 | 画风真源 | 保留原位（属真源） |
| `视频/成品.mp4` `视频/成品-配音.mp4` | 裸名视频 | 版本化 `视频/第{N}章(-配音)-v1-final.mp4` |
| `视频/preview/` `视频/frames/` `视频/audio/` | 视频过程 | 保留原位（属视频自体系过程） |
| `内容/` 内三件套 | 已确认文案 | 保留原位（内容成品） |
| `测试/{人物/规则/势力}/…-画册页(-长图).(png,html)` | 画册页候选 | 迁 `测试/画册页/`，主视觉底图改 `-画册主视觉-vN` |
