# step1 · 导入/续写已有项目

> 本文件是 pop-visual-pipeline 第二步执行指令。检测到已有项目文件（state=import/resume）时执行。

## 目标

已有项目扫描 → 资产归位 → 调度子 skill reconstruct 补跑 → 落地 Phase 决策。

## 执行

### 1. 资产清点

扫描项目根目录，清点已有内容：

| 已有关键文件 | 说明 |
|:-------------|:-----|
| `正文/ch*.txt` | 小说原文 |
| `素材/视觉资产/[角色名]角色档案.md` | 资产提取已完成 |
| `素材/风格/画风决策.md` | 画风已定 |
| `素材/美术设定集.md` | 美术设定集已定（基建真源） |
| `素材/视觉/*.png` | 已有派生图 |
| `漫画/` | 已有漫画产出 |

### 2. 文件归位 + 生成/更新视觉项目总控.html

- 若项目已有散落资产但无总控 → 读取模板生成总控，按清点结果填充 STATE
- 若已有总控 → 直接读取，更新为最新状态

### 2.5 🚪 意图闸口（import 时确认档位）

> 若总控 `intent` 字段为空或未确认，用 `AskUserQuestion` 询问本次目标（cover/oc/comic/full/asset-only，见 step0-init §1.5 意图表）。已确认则沿用，不重复问。

## 3. 落地 Phase 决策

按清点结果判断当前 phase：

| 清点结果 | 落地 phase | 下一步 |
|:---------|:----------|:-------|
| 有正文，无资产/画风/美术设定集 | **init** | 无基建，从 Phase 0 补跑 |
| 有资产，无画风/美术设定集 | **phase1** | 补跑 Phase 1 定画风 |
| 有资产+画风，无美术设定集 | **phase2** | 补跑 Phase 2 产美术设定集 |
| 有美术设定集（基建完整） | **phase3+** | 基建就绪，按需进派生层 |
| 有基建+已有派生图 | 按用户意图 | 派生层按需路由 |

### 4. 基建缺口补跑

若基建层（Phase 0/1/2）有缺口，按顺序调度对应子 skill 补跑：

- 缺资产 → `pop-visual-asset`（Phase 0）
- 缺画风 → `pop-visual-style`（Phase 1）
- 缺美术设定集 → `pop-visual-art-bible`（Phase 2）

### 5. 更新总控

用 SearchReplace 更新 `phase`、`mode`、`updated_at`、`next_step` 字段，并把已完成的 phase circle 标记为 `done`。

## 红线

- 基建层缺口必须补齐，不能带着缺口进派生层
- 已有资产必须归位到标准目录，禁止散落
- import 是"补跑不重做"——已有资产保留，不覆盖重建
