# pop-write

> 正文写作引擎 v1.0.0。由 test-write(v8.1.1) 改造，去 test 专属（包配方/设定包引用），对齐统一管线新路径（卷舞台/章纲/白描卡/状态快照/DNA）；文风兜底继承 pop-fanqie-write（23份按赛道）。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 做什么

输入：本章章纲（3章）+ 近5张白描卡 + 状态快照 + 文风DNA + 设定注入（每章≤3维度≤1500字）

输出：`正文/ch{NNN}.txt`（2000-2500字/章）+ 创作记录

**硬约束链**：本章章纲🔒（叙事原子序列+事件串+出线口+锚点区）→ 白描卡/状态快照🔒（过去事实+禁止漂移）→ DNA约束（3-5条笔触）→ 类型声明（防风味漂移）

**执行模式**：主agent直执写作+落盘。输入完备性缺口审查/章纲事实vs状态快照冲突比对可派子agent（verification）只读审计回报，主agent据此判execution.mode并渲染落盘。

---

## 怎么操作（SOP全内联）

### Step 1：消费输入（抽取本章写作包）

按优先级消费5类基础输入+DNA条件输入，缺一项记入缺口：

**①用户本轮要求（最优先）**：覆盖默认取值。明确：把X写成Y/当前章位/续写或重写/特殊约束。用户要求与状态快照冲突时以用户要求为准，但必须在创作记录里标注冲突。

**②近5张白描卡（全量读，场景连续性锚）**：`产出/白描卡/ch{NNN-5}~ch{NNN-1}.md`（review产出，~300-500字/张，read_policy=full-required，不得用摘要替代）。抽取：事件白描（叙事流回溯锚）/关键数据🔒（不可改事实）/爽点·钩子（已兑现爽点+已埋钩子）/人物关系变化。

**③状态快照（全量读，跨章状态锚）**：`产出/状态快照.md`（read_policy=full-required）。抽取：未回收钩子台账/角色当前状态表/禁止漂移清单。

**④章纲（读3章，向前锚）**：`卷纲/章纲/ch{NNN}-章纲.md`（pop-outline产出，每章一文件，read_policy=3-segments）。只读前1+本章+后1三份（首章读本章+后2；后1未产出读前2+本章）。每份含：章型/剧情梗概/章节目的+叙事原子序列（4-6原子）+线账本+锚点区。**向前推进由本章章纲决定**：

- 叙事原子序列=结构骨架：4-6原子按序渲染一个不丢，每原子内部事件串的料逐条落地
- 出线口=线状态达成：每原子渲染完，其线状态变化须在正文中可见
- 线账本=跨章连续性：本章末各线状态与后1章线账本起点衔接
- 锚点区=plot锁定信息：爽点/章末钩子L级/POV/关键数据/出章面板硬锚全兑现
- 前1章章纲=衔接校验；后1章章纲=钩子指向校验
- 章纲事件串未覆盖的细节（对白原文/环境描写/过场）是write发挥空间，但不得与章纲及锚点区确立的事实矛盾

**事实冲突处理**：章纲事实性字段（年龄/等级术语/人名）与状态快照/近5章正文冲突时，以状态快照为准，写作包"冲突标注"记录。本章章纲缺失（outline未组装到本章）=缺口，走缺口处理。

**⑤最近正文（按需读）**：`正文/ch{NNN-1}.txt`（full-if-targeted）。场景连续性由近5张白描卡承担；需更细原文细节按需读目标文件。

**⑥文风DNA输入（存在时必读，缺失时必须兜底）**：

| 优先级 | DNA源 | 触发条件 |
|:--|:--|:--|
| P0 | `素材/文风锚定.md` | 存在即用（项目指定） |
| P1 | 上一章白描卡`## 本章DNA执行包` | review产出，有则优先 |
| P2 | `references/文风兜底/`按赛道选一 | 以上均不存在时，必须选一个，禁止跳过 |

兜底规则：从`references/文风兜底/`按`立项/01-立项PRD.md`赛道标签选一个（西幻/仙侠/都市/灵异/悬疑/女频），加载其通用维度+对应场景卡。执行报告标注"兜底文风：{文件名}"。缺失态禁止跳过DNA直接写作。

读取规则：有执行包时优先按执行包加载（章型卡/笔触目标/章内套路）；无执行包时按本章章型加载对应场景卡+通用维度；DNA源过大时只读目录/对应章型卡/章内笔触/单章套路/角色口癖隔离。

**设定注入（每章≤3维度≤1500字，按章型按需）**：按章型从 pop-stage 产出文件按需读取，禁止全文注入。每维度≤500字。

必选（每章）：

| 文件路径 | 提取内容 |
|:--|:--|
| `设计/角色库/角色库.md` | 本章有对话角色的语言指纹+行为模式+关系张力 |
| `设计/全书设定/类型风味基线.md` | 类型声明+风味基线表——类型味方向锚，杜绝漂移 |

按章型再选≤1个：

| 章型 | 文件路径 | 提取内容 |
|:--|:--|:--|
| 战斗章 | `设计/力量体系.md` + `设计/全书设定/战斗系统.md` | 力量边界+分阶战斗形态+战斗底层规则 |
| 日常章 | `设计/卷舞台/卷N-舞台.md` | 本卷舞台的势力格局+地图区域+矛盾核心 |
| 探索章 | `设计/全书设定/物理规则.md` + `设计/全书设定/地理建筑.md` | 力量法则+空间法则+区域信息 |
| 危机章 | `设计/全书设定/危机敌人矛盾.md` | 危机体系+敌人生态+矛盾轴 |
| 社交章 | `设计/全书设定/政治经济.md` + `设计/全书设定/民风民俗.md` | 权力结构+文化质感 |
| 成长章 | `设计/金手指.md` + `设计/力量体系.md` | 金手指限制+阶位突破规则 |

注入规则：角色库+类型风味基线必选，再按章型选≤1个；每文件只提取本章相关段落（≤500字）不全文注入；提取内容写入写作包"设定状态"字段。

**X体验层注入（可选，改编项目）**：项目存在`素材/改编计划.md`时按章型注入X耦合（战斗/日常/剧情），每章至少1处参与动作/对话/决策。不存在时跳过，不自行编造。

**缺口处理**：近5张白描卡/状态快照明显缺关键事实时，停止并要求先执行pop-review产出。用户要求继续则execution.mode降为draft或trial。

**抽取本章写作包**：

```markdown
## 本章写作包
execution.mode:
- 把 X 写成 Y：
- 当前章位：
- 上一章白描：（叙事流回溯锚）
- 钩子台账：（本章可回收/不可提前吞并）
- 角色当前状态：（主角/配角当前立场）
- 读者已知信息池：（信息差类型，写信息不穿帮）
- 关键数据🔒：（写错=bug）
- 本章章纲：（叙事原子序列+线账本+锚点区要点）
- 后1章章纲：（钩子指向校验用，仅记章末线状态+核心事件一行）
- 可用燃料：
- 用户本轮新增要求：
- 类型声明：（当前作品类型+保持什么味+禁止漂移到哪）
- DNA约束：（3-5条本章实际执行的笔触约束）
- 文风DNA执行：（DNA源/模式/章型/笔触目标/章内套路/可见反馈/禁止误用；兜底标注"兜底文风：{文件名}"）
- 对话锚点：（本章有对话角色的语言指纹——句式偏好/用词偏好/对话标志2个）
```

**execution.mode判定**：formal=上一章白描卡+状态快照+本章章纲（3章读取完成）+最近正文+用户要求齐全且达标（DNA源齐全或已兜底）；draft=必读输入有缺口但用户要求继续；trial=快速试做不落盘。**缺本章章纲/状态快照不得标formal。**

**门禁（进入Step 2前）**：写作包完整｜execution.mode已判定｜章纲3章读取完成、叙事原子+线账本+锚点区已锁定｜章纲事实冲突已比对状态快照｜类型声明已注入｜DNA约束3-5条已选定｜对话锚点已提取或确认"本章无对话"｜缺口已记录。

### Step 2：渲染正文+落盘+创作记录

按叙事原子序列渲染2000-2500字：逐原子兑现内部事件串+出线口达成+锚点区兑现+章末钩子分级落章+创作记录落盘。

**正文规则**：

- 开场120字内出现目标、异常、压力、反馈或主动动作之一
- 主角至少完成一次动作闭环：压力/诱因→判断→主动动作→阻碍升级→可见反馈→收益/损失→新压力
- **本章章纲必兑现**：叙事原子序列按序渲染（4-6原子一个不丢，原子间自然过渡不生硬跳切）；每原子内部事件串的料逐条落地；每原子出线口达成；锚点区全兑现。不能只铺氛围
- **事件串物理缝合**：章纲事件串只锁结果不锁时序时，write负责补齐物理链（谁的手/什么时机/物件从哪来），补的拍服从前后因果。章纲有物理洞=补缝合拍并在创作记录标注
- **事实冲突以状态快照为准**：章纲事实与状态快照冲突时以状态快照为准+创作记录"冲突标注"
- 关键爽点必须外显（旁人反应、资源变化、局势翻转、敌人误判），不能只由作者总结"他赢了"
- 不提前吞并状态快照未回收钩子台账里未到期的钩子
- 结尾必须留下主动钩子或威胁逼近，不用自然停顿收尾
- 判定链/系统数值一律自然段内联呈现（【】格式），禁弹窗式/代码块

**DNA落地**（不是事后润色，而是参与本章生成）：

| DNA项 | 在正文中的体现 |
|:--|:--|
| 笔触目标 | 叙事距离、句式、段落呼吸、感官顺序、对话引导方式 |
| 主角主动方式 | 主角必须做出选择或动作 |
| 爽点外显方式 | 旁人反应、资源变化、局势翻转、敌人误判 |
| 叙事人格 | 旁白站位和判断顺序 |
| 句子气口 | 长短句、独句段、信息先后 |
| 信息释放 | 先给结果还是先给过程，哪些暂不解释 |
| 章内套路 | 起笔、第一信息变化、压力/诱因、主角动作、阻碍升级、可见反馈、章末钩 |
| 可见反馈 | 敌人失态、旁观者改判、资源/信息变化、威胁逼近 |

**对话落地**：每个有台词的角色必须从对话锚点取语言参数（句式偏好/用词偏好/对话标志），不凭记忆写对话。对话锚点缺失时从`设计/角色库/角色库.md`按需读取语言指纹。write负责"对话内容对+角色语言指纹对"，review负责"对话质量好不好看"。

**落盘**：正文写入`正文/ch{NNN}.txt`。文件名固定，对话只回摘要/钩子/创作记录，不把正文全文放进对话。

**验收门禁**（落盘后必跑）：

| 项 | 验收方式 |
|:--|:--|
| 正文存在 | `正文/ch{NNN}.txt` 存在 |
| 汉字字数达标 | exec 跑 `scripts/word-count.ps1 -Path 正文/ch{NNN}.txt`；纯汉字2000-2500；脚本stdout原文贴进创作记录 |
| 创作记录 | `templates/chapter-record.tpl.md` 格式填写完整 |

**新增事实处理**：write不维护任何库文件。新增事实只在创作记录里列"新增事实待review"清单，由review落库。write只声明不落库。

**下一步（硬后继）**：正文落盘后必须执行pop-review。review是write的硬后继，未执行review不得写下一章。

## 红线

1. **章纲必兑现**：叙事原子序列按序渲染（4-6原子一个不丢）；每原子内部事件串逐条落地、出线口达成；锚点区爽点/POV/关键数据/出章面板任一缺失=不合格，review打回。
2. **事实冲突以状态快照为准**：章纲事实性字段与状态快照/近5章正文冲突时，以状态快照为准。章纲事实错误不经write放大传染。
3. **状态连续性**：关键数据🔒/禁止漂移清单写错=bug；未到期钩子不得提前吞并。
4. **每章爽点≥1**：爽感公式必须落地且有爆发感；连续2章无爽点=不合格。
5. **DNA不跳过**：文风DNA缺失时必须选兜底，禁止裸写。
6. **字数门禁**：落盘后必跑word-count.ps1，纯汉字2000-2500为合格；脚本stdout贴进创作记录，禁用模型自报字数。
