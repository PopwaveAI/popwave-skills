# 正文写手 · Prose Writer

**这个技能只做一件事：把一章正文写出来。**

它的规则是**通用**的——不绑定任何平台、任何流派、任何题材。它只认两件事：

| 认什么 | 一句话 |
|---|---|
| **语言层** | 这段文字**通不通**——病句／碎句／跳／上下句描述错误，**一条都不许有** |
| **叙事层** | 这一章**有没有内容**——读完它，故事往前走了没有 |

**风格上的事完全自由。** 长短句、对白多寡、叙述驱动还是对话驱动、冷还是热，**各种写法都行**——本技能对风格**只画像、不判定**（依据：8 本不同风格长篇的实测包络，跨度 3–94 倍，统计上不可分）。**明令禁止**：以「句子太短／段太短／对白太多」为由改文（见第四章 4.4）。

---

## 一、触发边界（写死在这里，不靠临场判断）

### ✅ 触发

| 用户说什么 | 走哪个模式 |
|---|---|
| 「写第 8 章」「写下一章」「开始写正文吧」 | **写新章**（第四章 · 路径 A） |
| 「**接着写／续写／继续／把这段接下去／后面还没写**」（前面**已有正文**，**含只写了一半的半截稿**） | **接续**（第四章 · 路径 B） |
| 「第 3 章重写一下」「这段润色」「把这几个问题改掉」 | **改稿模式**（第五章） |
| 「这章正文帮我检查一遍」「跑一下门禁看看有没有问题」 | **体检模式**（第六章） |

### ❌ 不触发

| 用户说什么 | 该去哪 |
|---|---|
| 「帮我想个题材」「给我个脑洞」「这本书该怎么改」「哪个题材能火」 | 立项／诊断类技能 |
| 「写大纲」「做人物档案」「排情绪曲线」「出章节细纲」「写写作规则文档」 | 立项类技能（这些是**规划**，不是正文） |
| 商业文案、视频脚本、公文材料（**凡不是小说的**） | 通用写作流程（不是小说正文） |
| ⚠️ **单篇短篇小说、微型小说——算小说正文，触发本技能**（形态＝短篇，参数按 form-guide 取，不是"章节正文"也无妨） | —— |

> **判据一句话**：用户要的是**能直接读的成段正文**（或对已有正文动刀）——触发；要的是**规划、设定、文档、清单、表格**——不触发。
>
> **⚠️ 边界情形**：「把第 3 章这段对话改一下」「结尾再狠一点」——**算，走改稿模式**。改的是正文文字，用的是同一套规则。

## 二、第一次使用：从这里开始

> 这一节写给第一次用本技能的人。**不需要懂术语，也不需要先做准备。**

### 1. 你只要说一句话

> 「写第 1 章，女主穿越到古代当丫鬟，靠一手好厨艺翻身」　← 长篇连载
> 「**我这段写了一半，接下去**」（把半截稿贴过来）　← 接续
> 「写个短篇：一个修表匠等一个二十年没来的人」　← **文学短篇**（形态不同，参数自动跟着变）
> 「接着往下写第 3 章」（前面已经把前文发过来了）
> 「这章读着不顺畅，帮我改一遍」

技能会自己往下走，**不会拿一张表让你填**。

### 2. 手上有什么都行（**这是本技能最要紧的一点**）

**它不挑来历。** 下面四种情况都能写，你不需要为了用它去补材料：

| 你手上有什么 | 它会怎么办 |
|---|---|
| **① 有细纲**（每章要发生什么都写好了） | 照着细纲写，最省事、最准 |
| **② 有设定/大纲，没有细纲** | 它先替你把这一章"要看什么、发生几件事"推出来，写给你看，你说不对再改 |
| **③ 只有前文正文**（想接着往下写，**哪怕只写了一半**） | 它先读前文（**半截稿就读那半截**），接住**语气／视角／未完成项**，再从断点接上去 |
| **④ 只有一句方向**（"写个沙雕穿越开头"） | 它先定这一章演什么，再动笔 |

> **缺料的时候它不会停下来问你。** 它会先按自己的判断做出来，**并且告诉你"这块是我推的，不是你给的"**——你看完改哪一项说哪一项。

### 3. 你会拿到什么

**一份纯正文**：一个章节标题 ＋ 落在**形态对应字数区间**内的正文（**区间由形态定**，见第三节判断 2；平台向连载是 2200-2800），**没有别的东西**。

写前准备、自检清单、章节备注这些工序记录，它**不会塞进正文文件里**——那些另存（见第四章第 7 步）。你把 `第XX章.md` 单独发给任何人，他从头读到尾，**只看到小说**。

### 4. 术语表（看不懂的词在这里查）

| 词 | 白话解释 |
|---|---|
| **事件单元** | 一章里有**几件不同的事**。一件＝谁想要什么 → 结果怎样。**一章要有 2-4 件**；只有 1 件＝"整章就讲了一件事" |
| **回合** | 一件事里的交锋次数：谁向谁施压 → 对方怎么回 → 局面变了什么。**和"事件"不是一回事**，一件事能有 3 个回合 |
| **本章的变化** | 读完这一章，什么**不可逆地变了**（处境／关系／认知／状态）。只补一条新信息＝原地踏步，不算变化 |
| **前进力** | 章末让读者知道"**接下来要面对什么**"。不是必须写悬念句——一次决定、一个未完成动作、一句反常的话都算 |
| **形态** | 这本小说是"什么形态"——长篇连载／系列单元剧／单本长篇／文学短篇……**决定参数**（字数、每章装几件事、怎么收）。**类型（题材）不影响参数**，只影响选风格档 |
| **断点** | 续写时前文停在哪儿：**章间**（前一章写完）／**章内·段间**（停在整段）／**章内·句中**（停在半句话）。三类接法不同 |
| **接缝测试** | **续写的质量判据**：七问——语气跳不跳／视角人称时态一致吗／称呼用语一致吗／前文抛出的接住了吗／有没有「重来一遍」感／**事实与前文对得上吗**／**这半章是靠「演」还是靠「讲」** |
| **风格档 A–E** | 文风档位（叙述驱动／心理流／短句碎切／对白驱动／长句对白）。**没有哪一档更好**，只看适不适合这本 |
| **承接测试四问** | 逐句自检：① 有信息吗／看得出要干什么吗 ② 接得上吗／中间那几步在不在 ③ 指得清吗 ④ 对得上吗 |
| **四类语言硬伤** | 病句／碎句／跳／上下句描述错误。**任何风格、任何题材都不允许出现** |
| **死线** | 一票否决的规则。不过就直接重写那一段，不做局部遮掩 |

## 三、动笔前的两个判断（材料 ＋ 形态）

### 判断 1 · 材料适配（手上有什么，决定怎么走）

> **为什么要这一层**：本技能常常是**半路接手的**——大纲和细纲可能是别的技能做的、可能是你自己写的、也可能压根没有。写正文的规则不依赖那些东西，但它**需要知道"这一章该发生什么"**。缺料不是问题，**装作没缺料才是问题**。

### 判路（每次写新章前，第一件事）

按下面顺序查，**命中即走该路，不往上翻**：

| 路 | 命中条件（有一个就算） | 走法 |
|---|---|---|
| **A · 有细纲路** | 找到章节细纲文件里本章条目 ／ 施工细账里本章的事件单元表与回合表 ／ 用户直接贴了本章要写什么 | 照细纲兑现（第四章 第 2 步全跑） |
| **B · 有设定无细纲** | 有大纲 ／ 有设定文档 ／ 有人物档案 ／ 有写作规则文档，但**没有本章细纲** | **先现推本章任务，再写**（下方 B 路补件） |
| **C · 只有前文** | 没有任何规划文件，但**有正文**——**完整章节或只写了一半的半截稿都算** | 读前 2-3 章（**半截稿就读那半截**）→ 接住前文留下的东西 → 现推本章任务 → 写。**半截稿走第四章·路径 B 接续五步** |
| **D · 只有方向** | 什么都没有，只有一句"写个 XX 的开头" | 先定这一章演什么（一段提案）→ 现推本章任务 → 写 |

### 缺件补偿三原则（**B／C／D 路必守**）

1. **不阻塞**：缺件不停下来问。按已有材料往下推，直接出稿。
2. **显式声明**：推出来的东西必须标出来——交付时说一句「**本章的〔核心变化／事件单元／回合〕是我按你给的〔大纲／前文〕推的，不是你给的**」。用户可以否，可以改。
3. **落成实物**：推出来的结论**写进文件**（`.learnings/` 下的写前准备），不留"模型记得"。下一章还要用。

### B／C／D 路的"补件"是什么（**动笔前必须先有**）

| 补件 | 内容 | 依据 |
|---|---|---|
| **① 本章的变化** | 谁想要什么 → 结果 → 结束时**什么不可逆地变了**？只补新信息＝布景，不算变化 | 细纲（A 路）／AI 从大纲与前文推（B/C/D 路） |
| **② 事件单元 2-4 个** | 逐条写「形态（推力/探察/代价）→ 谁想要什么 → 结果 → 结束状态变了哪项」。**至少 1 个由主角主动发起** | `references/scene-beats.md` §七 |
| **③ 回合（派生量）** | **每个事件单元 1-3 个 → 全章 2-12 个、典型 4-6**（**不单设门槛**，判定只认「每单元至少 1 个真回合」）。每个回合「施压方 → 被压方 → 回应 → 局面变化（筹码/信息/关系/物理）」。**相邻回合必须变一项** | `references/scene-beats.md` |
| **④ 开头落点** | 开头几段要落在**一件已经发生或正在发生的事**上，不是铺垫 | `references/prose-rules.md` 死线 3 |
| **⑤ 风格档 A–E** | 从五档里选一档，写进章节备注；相邻章不跳档 | `references/benchmark-writing.md` 第三节 |

> **②③ 数不够 → 不要靠描写灌水**，回头合并章、引进新单元、或者把这一章的任务改小。**这是本技能最常出问题的地方**（实测：回合数 6 项全达标、事件单元仍是 1，用户仍判"一整章就讲一件事"）。

### 材料从哪读（优先级从高到低，**有就读，没有就跳过**）

```
项目里的写作规则文档              → 本书定制的规则（腔调/称谓/禁忌）★若存在，优先级最高
项目里的章节细纲文档              → 本章条目（A 路）
.learnings/施工细账_卷N.md        → 事件单元表 / 回合表 / 伏笔台账
项目里的大纲文档                  → 全局走向、本章在全书里的位置
项目里的情绪／节奏规划表           → 本章的情绪任务
.learnings/CHARACTERS.md          → 所有角色当前状态（等级/位置/生死）
.learnings/LOCATIONS.md           → 已出现地点
.learnings/PLOT_POINTS.md         → 已发生情节与待回收伏笔
.learnings/STORY_BIBLE.md         → 世界观设定与规则
上一章正文                         → 上一章内容，确保衔接
```

> **这一串是"能读多少读多少"，不是"必须读齐"**。哪一份不存在就跳过那份——**但这不影响动笔**，只影响"你推的部分有多少"。文件缺失时按上方的缺件补偿走。
>
> **文件命名不统一没关系**：判路看的是**内容**（这份是不是细纲／是不是设定），不是文件名。文件名与本清单不同时，按内容判。

### 判断 2 · 形态识别（**这是什么形态的小说，决定参数**）

**为什么要有这一步**：**规则通用 ≠ 参数通用**。"每章 2-4 件事、2250 字、章末最大变化"是**长篇连载（平台向）**的参数，**不是所有小说的参数**。把参数当规则，就会用连载的节奏去写一篇文学短篇。

| 形态 | 单章／单篇字数 | 每章事件单元 | 章末要求 |
|---|---|---|---|
| **长篇连载 · 平台向** | 2000-3000 | **2-4** | 前进力 ＋ **章末那件最大** |
| **文学向连载 ／ 单本长篇** | 3000-6000 | 1-3 | 前进力（**不要求"章末最大"**） |
| **系列单元剧**（一集一案） | 3000-8000 | **1 主案 ＋ 0-2 支线** | **本案收束 ＋ 引子**，不必是主线悬念 |
| **文学短篇**（独立成篇） | **整篇 3000-20000** | **整篇 1 个核心变化** | **可以完全收束，不要求"翻页"** |
| **微型小说 ／ 闪小说** | **整篇 300-1500** | 1 个瞬间／1 个转折 | 点到即止；留白即结尾 |
| **散文体 ／ 书信体 ／ 日记体** | 由形式定 | 按形式 | 按形式 |
| **儿童 ／ 青少年文学** | 500-3000 | 1-2 | **温和前进力**；不制造惊悚式悬念 |
| **短章文艺向**（单章千字级） | **1200-2000** | **1-2** | 可停在**情绪或意象**上，不必是冲突 |

**怎么判**（命中即用，不往上翻）：① 用户明说 → ② 项目规划文件（总字数 ÷ 章数）→ ③ 量**前 3 章实际字数的中位数**对号入座 → ④ 都没有：按用途判，仍不定就问一句「**这是能一直写下去的长篇，还是讲完就完的一篇**」。
**判完必须声明依据**：交付时带一句「本章按〔形态〕取参数：字数 X、事件单元 Y（依据：…）」。**判错，用户改一句就回来了。**

> **⚠️ 门禁报告出现「⚠️ 内置默认（2200-2800）」＝ 形态没判。** 那是**平台向连载**的档位，不是通用默认值。
> **完整表（含各形态的写法提示、形态不明时的完整判法）见 `references/form-guide.md`。**

## 四、写正文（**两种路径**：新起一章 ／ 接续已有正文）

### 路径分流（第一件事）

| 手上是什么 | 走哪条 |
|---|---|
| 只有细纲／设定，或要**新起一章** | **路径 A · 写新章**（下面第 0～7 步，最常用） |
| **已有正文**（完整章节，**或只写了一半的半截稿**），要往下写 | **路径 B · 接续六步**（本节末） |

---

### 路径 A · 写新章（最常用的路径）

**七步，按序走。** 前三步是"写之前的功课"——**跳过它们，问题会在写完之后以十倍的代价回来。**

### 第 0 步 · 判路

跑第三章的判路表，确认走 A／B／C／D。**顺手记下"哪些材料缺"**（写完之后要声明）。

### 第 1 步 · 写前必读

按第三章「材料从哪读」的清单**能读多少读多少**。

> **本技能的工具会自检**：读不到细纲不代表报错，代表你走 B/C/D 路——**去补件，不要去找用户要文件**。

### 第 2 步 · 写前分析（**八项，逐项过，不许跳**）

| # | 项 | 判据 / 动作 |
|---|---|---|
| **1** | **本章的变化定位**（**排在最前**） | 谁想要什么 → 结果 → 结束时**什么不可逆地变了**？① **改变 > 补充**（只补新信息＝原地踏步）② 答不出 → **本章是水章，本章任务要重排** |
| **2** | **本章在全书里的位置** | 它承接什么、推进什么、给后面留什么？**从大纲／前文读；没有规划文件就跳过** |
| **3** | **事件单元规划**（**先于回合**） | 2-4 个，逐条写「形态（推力/探察/代价）→ 谁想要什么 → 结果 → 结束状态变了哪项」。**< 2 ＝素材撑不起一章**；**≥1 个必须由主角主动发起** |
| **4** | **回合规划**（**派生量，不单设门槛**） | **每个事件单元 1-3 个 → 全章 2-12 个、典型 4-6**；判定只认「**每单元至少 1 个真回合**」。逐个写「施压方 → 被压方 → 回应 → 局面变化」。**相邻回合写不出"差在哪"＝同层重复**，重排，**不许靠描写与对白稀释** |
| **5** | **开头落点** | 开头几段落在**一件已经发生／正在发生的事**上。**唯一硬要求：进入变化**（死线 3）。写法任选（见 4.2），**不限定某一种** |
| **6** | **结尾落点** | 章末要知道"下一章从哪接"。**唯一硬要求：留下前进力**（死线 4）。**不要求写成悬念句**（见 4.3） |
| **7** | **场景规划** | 3-5 个场景；每场给**三件套**（空间 ＋ 物件 ＋ 光/声/温度任一），且**只给一次** |
| **8** | **风格档 A–E ＋ 句段节奏** | 按 `references/benchmark-writing.md` 第三节**选定风格档**（A 叙述驱动／B 长句心理流／C 短句碎切／D 对白驱动／E 对话驱动长句），写进章节备注；**邻章不跳档**（跳档无场景边界＝读者会觉得"跳"） |

> **⚠️ 首章的加测两项（仅第 1 章，缺一即返工）**：① 开头几段**已经进入变化** ② 主角 **≥1 次主动行动**。**缺一不得靠加描写弥补。**

#### 位置类问题的返工入口（**别回正文挪句子**）

**节奏／位置的问题，返工入口是回写前准备重排动作序号，不是回正文挪句子**——挪句子会把上下句的描述关系弄断。三类根因，改法方向不同：

| 根因 | 症状 | 改法 | 判类问句 |
|---|---|---|---|
| **甲类** | 关键信息来得太晚 | **往前搬** | 读者在关键变化之前被消耗在哪了？ |
| **乙类** | 压力全堆在一处 | **往后挪** | 同上 |
| **丙类** | 同一句里塞了两件事（既揭底又留扣） | **拆成两句** | —— |

### 第 3 步 · 写前三个中间产物（**缺一不许动笔**）

依据 `references/prose-rules-supplement.md` **S7.1**：**这不是"写后挑错"，是"写前不给它出现的机会"。**

| 产物 | 治什么 | 做法 | 缺了会怎样 |
|---|---|---|---|
| **① 动作链** | 治「**跳**」 | 逐场列关键动作的**物理顺序**，相邻两步**显式标注四类过渡**（姿态变更／空间位移／取物／时间跳转）。**标不出来的地方就是「跳」**，当场补步骤 | 读者照着做一遍会发现中间少了"起身／下床／走到水盆边" |
| **② 信息增量表** | 治「**碎**」 | 逐场列**每一轮**（一次对白来回／一个叙述回合）改变了什么（新事实／立场变化／关系推进／物理变化）。**写不出增量的那一轮＝「碎」**，删掉或换内容 | 对白变成没信息的乒乓球，读着热闹、手里是空的 |
| **③ 字数配额表** | 治「**写不到**」 | 跑 `scripts/plan_word_quota.py`，把总字数**分摊到每一场**，整表贴进写前准备 | 实测第一稿稳定差 **18%-35%**，每次都要 3-5 轮扩写才达标 |

**字数为什么必须排**——**字数不是一个可写的单位，段数才是**：

```
字数 = 段数 × 均段字数
叙述驱动（A/B）＝ 26.8 字/段   ｜   对白驱动（D）＝ 20.5 字/段
→ 2250 字需要 84-110 段；一拍（施压→回应→局面变化）≈ 65 字 ≈ 3 段
```

**三条硬规则**：
1. **写前分摊**（重头场 ×1.2-1.3、过渡场 ×0.8），**写后只做验收**——与"位置是排出来的"同一条纪律。
2. 某场差额 > 20% → **回本表补「场上另外几个人各自的反应」与对白来回**，**不回正文加形容词**（实测：历次扩写补的全是别人的反应，**没有一次是补描写**）。
3. 全章写完跑 `--check` 对账，把实测值回填。

**模板**：`templates/chapter-template.md`（写前准备三表 ＋ 自检表，直接抄）。

### 第 4 步 · 撰写

先读 `references/my-methodology.md` 注入作者个人写法锚点（**骨架未填时跳过，不得代填**）。

**两层分工**：**写什么**——发生了什么、谁跟谁过不去、最后变成什么样——在写前分析里已经定死，写作期**只做兑现**；**怎么写成字**——句、段、描写、用词——走**通用文笔规则**，与题材无关。

#### 4.1 结构：这一章装得下几件事

| 项 | 要求 |
|---|---|
| **事件单元** | **2-4 个**（一章几件不同的事）；**至少 1 个由主角主动发起**——全章都由他人推动＝主角没有存在感 |
| **回合** | 每单元 1-3 个；相邻回合必须变一项（筹码／信息／关系／物理），四项都不变＝同层重复，**不计入** |
| **章末那件事** | **必须是本章最大的一次变化**（压力最大／代价最高／变化最狠），它同时承担前进力 |
| **撑不起一章时** | **与相邻章合并**，或**引进新单元**（加人物／加压力／加反转）——**不要把一件事拆碎、也不要靠描写和对白稀释到目标字数** |

> **字数、场景数、回合数三项达标 ≠ 事件数达标。** 在这三项全过的情况下，"一整章就讲一件事"照样会发生——**几个旧指标都会把这一项盖住**。

#### 4.2 开头：只要"进入变化"，写法任选

**唯一硬要求**（`references/prose-rules.md` 死线 3）：**开头必须已经进入变化。** 读者读完开头几段，要能看出「**某件事正在发生**／**某个状态已经变了**」——而不是在听背景交代。

**起手式清单（任选、可组合，也可以用清单外的）**：

| 起手式 | 起手式 |
|---|---|
| **动作中开场**——从正在发生的动作切入 | **危机时刻**——从最危险的那一瞬切入 |
| **反常情境**——先摆一个不合常理的事实 | **谜团／异常**——从无法解释的现象切入 |
| **一句惊人的话**——让人物先开口 | **信任崩塌**——从关系断裂那一刻切入 |
| **时间压力**——从倒计时切入 | **两难选择**——从必须做的决定切入 |
| **重大发现**——从"某件事被揭开"切入 | **预叙**——先说结局，再回头讲 |
| **日常切面**——从一个具体的生活动作切入（**前提是它立刻发生变化**） | **对话切入**——从一句有分量的话开始，**不解释、不铺垫** |

**风险较高的起手式**（不是禁止，是**若用，必须在前几段内立刻转入变化**）：

| 起手式 | 风险在哪 |
|---|---|
| 天气／景物开场 | 与故事无关，读者没有耐心 |
| 日常流程（起床、刷牙、出门） | 没有变化，读不出要干什么 |
| 回顾上章（"上一章说到……"） | 读者已经知道，浪费时间 |
| 背景倾倒（先介绍这座城市／这个体系） | 讲述而非展示，没有行动 |
| 无信息寒暄（"你好""吃了吗"） | 没有张力，也不推进任何东西 |

> **判据只有一条**：**进入变化了吗。** 与它是不是"钩子"无关——**本技能不要求你把开头写成悬念**。

#### 4.3 结尾：要有前进力（**不要求写成悬念句**）

**唯一硬要求**（`references/prose-rules.md` 死线 4）：**章末必须留下前进力。** 读者读完这一章，要知道「**接下来要面对什么**」。

**这些都算有前进力**（任选）：

- 一个刚出现的麻烦 ／ 一句反常的话
- 一个已经做出、但代价还没付的决定
- 一个未完成的动作（门刚被推开，没写推门的人是谁）
- 关系或处境已经变了，而后果还没来
- 一个刚被抛出、本章内没有回答的问题（**这是其中一种，不是必须的一种**）

**这些算原地收尾**（要改）：

- 把本章的矛盾**全部**收拾干净，然后总结一句
- 用抒情／感慨／点题收尾
- 用"接下来会发生什么呢"这类**空问句**收尾（不问具体的事）
- 以景物描写收尾，不给任何新状态

> **判据一句话**：**"下一章要从哪里接？"——答得出来，就是有前进力。** 答不出，回写前分析第 6 项重排。

#### 4.4 文笔层 · 死线级硬约束（**每次动笔必须执行**）

| 动作 | 内容 |
|---|---|
| **通读真源** | `references/prose-rules.md`（《通用小说正文写作规则》，**文笔层唯一真源**）：叙述策略 A1-A12 ＋ 规则 1-42（**26 条死线**）。**标"死线"的任一不过，直接重写相关段落，不做局部遮掩** |
| **叠加本地条款** | `references/prose-rules-supplement.md`（与原文分开存放以免污染原件；**冲突时以本文件为准**）：**S1 正文零破折号**（`——`／`—`／`–` 任一出现即不合格，**改写句子，不是换标点凑数**；**规划类文档不受此限**）／S2 问句标点全书统一／S3 信息承载／S4 场景具现／S5 句长节奏／S6 风格档与通用硬伤／**S7 碎跳闭环** |
| **风格只画像，硬伤才判定** | 风格六项（对白占比／均段长／均句长／短句率／碎句链／短对白链）**一律只报数、不判定**——8 本正例包络跨度 3–94 倍，统计不可分。**明令禁止**：不得以"句子太短／段太短／对白太多"为由改文 |
| **唯一通用底线** | **四类语言硬伤**：**病句／碎句／跳／上下句描述错误**——用户二次确认为「**通用型错误，任何风格类型的正文里都不允许出现**」。判据＝**承接测试四问**（① 有信息吗／看得出要干什么吗 ② 接得上吗／中间那几步在不在 ③ 指得清吗 ④ 对得上吗）。**逐段举证，禁止打勾** |
| **去 AI 味** | **写的时候就避开，别等写完再改**——按 `references/revision-methods.md` 第三节四层诊断（词汇层／句式层／结构层／情感层）。**禁用清单是唯一真源 `scripts/ai-flavor-lexicon.json`**（v1.29.23 改制，此前四份副本交集仅 3 词）：37 个 AI 词 ＋ 3 个语境词 ＋ 4 条句式模板＝**命中即 FAIL**；认知直述＝**提示项**（看有无物象承载）；比喻＝**只报数**。查清单 `python scripts/chapter_stats.py --lexicon`，写后跑 `chapter_stats.py` 自动机检。**这是底线，不是加分项** |

> **⚠️ 「短」怎么算**——用户点名要规避的四类里含「短」，但**「短」本身不是错**：
> - **风格层**：句子短、段落短、对白多——**只报数，不改文**（这是用户拍过的板：各种写法都行，8 本样本实测跨度 3–94 倍）
> - **硬伤层**：**错的是"短到读不出东西"**——半截句、行尾无终止标点、一句话被切成接不上的碎片。**判据仍然是承接测试四问**，**不是句长阈值**
> - 机器能判的只有 S6.3 的确定性错误（半截句／行尾无终止标点等），**语义上的"短到读不懂"由模型逐段举证**
>
> **「碎」≠ 句子短**——判据是「**意图可见 ＋ 逻辑可见**」。（同为 12 行连续短对白：一本算碎，另一本不算，因为那是审讯、答一句对方脸色黑一分。）
> **「跳」＝ 动作级缺环**——不是场景级跳跃。**唯一判据动作＝照着做一遍，中间步骤在不在。**

#### 4.5 字数

**字数区间由形态定**（第三节判断 2）：平台向连载 2000-3000／文学向连载与单本长篇 3000-6000／单元剧 3000-8000／文学短篇按整篇算。**没有一个通用的字数。**

**兜底默认 2200-2800 字**——那是**平台向连载**的档位，也是 `check_chapter_wordcount.py` 的内置默认；报告里会标「⚠️ 内置默认」，**看到它就说明形态没判**。

**区间可改，三种办法（v1.29.16）**：① 项目里放 `.learnings/立项参数.json`（形如 `{"单章字数": {"min": 2500, "max": 3500}}`，脚本会**自动向上找到**，适合给某一部书定死口径）；② 命令行 `--min/--max`；③ `--range-config <分档表 json> --genre <名称>`。
**报告会逐章打印「来源」**——看到「内置默认」就说明前三层都没命中，不是"没报错就等于对"。

- **项目或用户另有要求时，以要求为准**——短篇、纸媒章、单元剧的长度差别很大，脚本可传参改区间：`python scripts/check_chapter_wordcount.py 第XX章.md <下限> <上限>`
- **写前已排配额，此处只做兑现**——写不到就回第 3 步的表补反应与来回，**不补形容词**
- 超出上限则删**无功能元素**（**删元素，不删事件**）

### 第 5 步 · 写后处理（**每章必做**）

| 顺序 | 步骤 | 操作 |
|---|---|---|
| 1 | **格式化** | `python scripts/format_chapter.py <章节文件>`——头部多余 `---` 合并／正文内 Markdown 残留清理／ASCII 直引号 → 全角成对引号 |
| 2 | **逐场字数对账** | `python scripts/plan_word_quota.py --check 第XX章.md --actual <各场字数>` → 回填写前配额表。**任一差额 > 20% 的场按"补反应不补形容词"改**。**禁止只报一个总数**——总数达标掩盖得住某一场的空 |
| 3 | **字数校验** | `python scripts/check_chapter_wordcount.py <章节文件>`（默认 2200-2800，**会自动读项目的 `.learnings/立项参数.json`**；**只算正文**） |
| 4 | **文字修订** | 按 `references/revision-methods.md` 五节依次过：情感化改写 → 逻辑优化（因果链 A→B→C 有没有断）→ **去 AI 味四层诊断** → 通俗化 → 校对 SOP。**这一步在自检之前做**，改完再取数才准 |
| 5 | **本章变化核对** | 本章**不可逆地变了**什么？只补新信息不算；答不出＝本章是水章，回第 2 步 |
| 6 | **结构与文笔双重自查** | 见第 6 步（甲层 → 乙层） |
| 7 | **客观指标取数** | `python scripts/chapter_stats.py <章节文件>` 取数。**退出码非 0 即不合格**（只判确定性错误） |
| 8 | **遮蔽测试** | **遮住本章所有含引号的行**，只读剩下的叙述，自问「在哪／谁在场／围绕什么物件／局面变了什么」。脚本报告里已列出所有 **连续 ≥3 行纯对白**的位置，逐段遮读。读不出来＝信息全压在对话里，**修法是把那条信息挪回叙述，不是把对白写长** |
| 9 | **原创性核对** | 若本章有参考原文：**不得有原句或近义复述**（改的是结构与表达，不是换词）。若是自己原创：确认没有整段搬运外部文本 |
| 10 | **记录更新** | 见第七章（长线连续性） |

### 第 6 步 · 两层自查（**禁止打勾，必须举证**）

> **为什么强调这一点**：清单式打勾**一定失效**。三次实测——26 项全打勾仍留 9 处病句；自检表只列到第 34 条，42 条里的**第六节整节（8 条死线）没进表**；甲层 5 项全过、回合数 6 项达标，**仍被判"一整章就讲一件事"**。
> **规则里全有，却仍会漏——因为"逐条打勾"时人并不会真的逐句读。** 举证法就是把"读"变成动作。

#### 甲层 · 结构层（**先过这层，再修字**）

| # | 检查项 | 判定记录（写具体） |
|---|---|---|
| 甲0 | **事件单元数 2-4**（**最先过这条**）：有**几件不同的事**？逐条列「形态 → 谁想要什么 → 结果 → 结束状态变了哪项」 | |
| 甲1 | **回合数**：有几处交锋？逐条列「施压方→被压方→回应→局面变化」（每单元 1-3 个） | |
| 甲2 | **相邻回合都变了项**：与上一回合差在哪（筹码/信息/关系/物理）？**写不出的行＝同层重复** | |
| 甲3 | **章末那件事最大**：最后那个单元是不是全章压力/代价/变化最狠的？ | |
| 甲4 | **冲突三要素齐**：诉求（不可兼容）／筹码（能让对方付什么）／代价（拒绝的代价本章内显形了吗） | |
| 甲5 | **开头进入变化**：读者读前几段，看得出"某件事正在发生／某个状态已经变了"吗？ | |
| 甲6 | **主角主动行动 ≥1 次**：有没有一件"别人没要求、他自己决定要做"的事？**全章都由他人推动＝平凡感的直接来源** | |
| 甲7 | **跨章道具交接**：上一章结束时关键道具在**谁手上／哪个位置**？本章首次出现时**有没有交接动作**？逐件列「上章末位置 → 本章首位置」 | |
| 甲8 | **逐场字数对账**：每场「计划 vs 实际」。**任一差额 > 20% ＝ 补的是"反应与来回"还是"形容词"**？后者＝注水 | |
| 甲9 | **结尾有前进力**：**"下一章要从哪里接？"**——写出一句具体的答案，写不出＝没收住 | |

**首章加测**：开头已进入变化 ／ 主角主动行动 ≥1 次。

> **甲0 < 2 或甲2 大面积填不出 → 回去重排结构**（合并章／引进新单元），**不要在正文里加水稀释**。
> **回合数 ≠ 事件数**：改稿把回合从 1-2 涨到 6，事件单元仍是 **1**，仍被判"一整章就在讲一件事"。
> **字数、场景数、情绪变化、回合数四项达标，都不等于事件数达标**——几个旧指标全部会把这一项盖住。

#### 乙层 · 文笔层（**逐条给依据，禁止清单式打勾**）

**六步法**：

| 步 | 动作 |
|---|---|
| **① 删减测试**（机械化，不靠判断力） | 列出全章"只出现一次"的细节，逐个问四句（推进动作？改变关系？造氛围？是已登记伏笔？），**四问全否即删且不许补解释**；再把余下的句子**逐句试着删掉**，问"删了读者会误读或掉信息吗"，不会就删。**"这句需要"是写作者的主观，删减测试不认主观** |
| **② 逐句回读** | 每句问"谁对谁做了什么"，靠回读才理清的句子立即标记重写 |
| **③ 逐段追动作** | 每段填"上一动作的结束状态 → 下一动作的起点"；关键道具在哪、在谁手上不得跳跃 |
| **④ 八类高频病句照表查** | ① 主语悬空 ② 同一信息说两遍 ③ 动作与语义冲突 ④ 指代无先行词 ⑤ 搭配生硬 ⑥ 道具位置断链 ⑦ 时间／年数不自检 ⑧ 视角越界 |
| **⑤ 专业逻辑核验** | 凡出现工序、术语、行业规矩、器物结构，逐句自问"**这门手艺的从业者会这么说吗**" |
| **⑥ 全章朗读** | 读不顺的地方就是问题，不辩解 |

（实测反例：「放了一个月的表，机芯不会长出新毛病」——表停一个月，润滑油凝滞、轴尖锈蚀，**恰恰会长新毛病**。行内人一句话就否掉，读者信不过这个师傅，人物就塌了。）

**26 条死线逐条核对**（**列清单前先 grep 出总数，缺一行即视为未完成**）：

视角统一（1）｜开头必须进入变化（3）｜章末必须留下前进力（4）｜台词必须推动文本（8）｜信息分批投放（10）｜特殊文本最小逻辑（12）｜人物行动因果（13）｜重大决定决策链（14）｜人物知识边界（15）｜时间轴清楚（18）｜发现有前文依据（19）｜连续性四项核查（24）｜世界质感一致（25）｜道具链条完整（26）｜句子关系闭合（27）｜句子完整（28）｜行文顺畅（29）｜标点与格式统一（32）｜先删无功能元素（35）｜关键物件链逐项闭合（36）｜信息交接有最后动机（37）｜私密称呼与关键警告完整逻辑（38）｜关键台词按人物口吻完整呈现（39）｜跨场景复查只用随身信息（40）｜修文优先合并碎句和说明（41）｜保留的类型卖点承担功能（42）

**本地附加条款（同样逐条给依据）**：

- **S1 正文零破折号**
- **S3.2 遮蔽测试**（遮住引号行，仍能读出"在哪／谁在场／围绕什么物件／局面变了什么"）
- **S3.4 文书留空栏已被角色"读出来"**（写出差别＋读出什么＋因此做了什么）
- **S4.1 关键动作可复现**（用什么／怎么做／到什么程度／结果；读者合眼能照做）
- **S4.2 无空句**（无泛指替代／评价替代事实／抽象命名）
- **S4.3 场景三件套已给且只给一次**（空间＋物件＋光/声/温度任一）
- **S5.3 承接测试四问**——**逐段举证：位置 → 问题类型 → 原句 → 缺失项 → 修法**。由模型执行（脚本给定位材料 → 逐段四问 → 输出举证表 → 不合格就地改 → **复跑至全过**）
- **S6.1 风格档已声明 ＋ 档内一致**（本章属 A–E 哪档？与上章是否跳档超一倍且无场景边界？）
- **S6.3 确定性错误**（脚本项）：标点错配／标点连用／引号不配对／相邻行重复／叠字／半截句／行尾无终止标点／**跨章对白逐字复现**

> **非死线条目也要过**，可在各步的"问题类型"里带过。**自检记录必须写成四栏表「位置／问题类型／原句／修法」，无问题写"本轮 0 处"，不得留空、不得只写"已核对"。**

#### 丙层 · 其余

- 字数落在目标区间（脚本校验）
- 有情绪／状态的变化，不是一条直线
- 展示而非讲述；无 AI 词与 AI 句式模板（清单真源 `scripts/ai-flavor-lexicon.json`；脚本项「AI 高频词」「AI 句式模板」命中即 FAIL）

- 呼应了前文伏笔，并埋下新伏笔
- 角色／地点／状态与记忆文件一致（无穿帮）

### 第 7 步 · 交付

**交付物＝一份纯正文**：`第XX章.md`。

```
# 第X章：[章节标题]

（正文落在字数区间内，默认 2200-2800 字）
```

**文件里只能有这两样东西。** 下面这些**一律不进正文文件**：

| 内容 | 去处 |
|---|---|
| 文件头字段（本章变化／承接上章／涉及角色地点） | 写前准备文件 |
| **写前准备**（动作链／信息增量表／字数配额表） | 写前准备文件 |
| **章节备注**（本章变化／结尾前进力／伏笔标记／实际字数） | 写前准备文件 |
| **写后自检清单**（甲／乙／丙三层） | 自检留痕文件 |
| 技能路径（`references/`、`templates/`、`scripts/`）／工序话术／内部编号 | **全部删掉** |

**判据**：把 `第XX章.md` 单独发给一个人，他从标题读到结尾，**只看到小说正文**，看不到任何"准备／备注／自检"字样。

> **⚠️ 正向纪律**：「正文只有一节」**不等于**「写前准备可以省」——两者一件都不能少，只是**放在不同文件**里。

**同时必须向用户交代一句**（B/C/D 路）：**哪些是我推的、哪些是你给的**。

### 路径 B · 接续六步（**用户说「接着写／续写／继续」时走这条**）

> **完整版见 `references/continuation-guide.md`。** 这里只留骨架与判据。
> **"写了一半"就是合格输入**——半句、半段、半章、写到第 N 章，**都能接**。

**第 0 步 · 前文体检**（v2.2.0 新增 · **前文不是干净的，别默认它合规**）

对**前文**跑一次 `python scripts/chapter_stats.py 前文.md`，把违规**逐条记下来**：**破折号**／**`「」`包人名**／ASCII 引号／拉丁字母／标点错配／**生理反应套话**（漏跳／呼吸凝滞类——**基准样本自己也带**，见 `reaction-beats.md`）。

> **⚠️ 前文带什么，续文就会跟着带什么**——2026-10-09 实测：样本自带 **3 处破折号 ＋ 17 处 `「」` 包人名**，我把它当成「**这本书的排版特征**」照抄进续文，交付的整章里出现 15 处同样的括号，**用户当场质疑「为什么会出现这个符号」**。
> **纪律**：① **不许把前文的问题当成「这本书的风格」去模仿**——「贴前文」和「抄前文的问题」只差一线；② **动不动前文看交付形态**：只交**片段**→ 不动，但**在说明里报出来**；交**整章**→ **一并清掉**，并写明改了几处。

**第 1 步 · 定位断点**（决定后面怎么做）

| 断点 | 怎么认 | 做什么 | 目标字数 |
|---|---|---|---|
| **章间** | 前文是**完整一章** | 等于写下一章（走路径 A），但**首段须接住前章末尾的前进力** | 一整章区间 |
| **章内 · 段间** | 停在**完整段落** | 把这一章**写完** | 整章区间 **− 已写** |
| **章内 · 句中** | 停在**半句话** | **先补完那句话**（延续其主语与语气），再接段落 | 同上 |

**第 2 步 · 读前文，取四锚**（**取不到别动笔**）
- **语气锚**：风格档 ＋ 跑 `chapter_stats.py` 取均段长／均句长／短句率／对白占比
- **视角锚**：人称 ／ 视角人物 ／ 时态 ／ **称呼习惯**（前文叫「爸」，就不能续成「父亲」）
- **未完成项**：前文抛出去还没接的东西（未答的问题／未完成的动作／代价未付的决定）——**续文至少接住一项**
- **事实锚**（v2.2.0 新增 · **治「写穿帮」**）：从**前文**抄出**时间线**（现在几点／什么季节／距某事多久）／**道具状态**／**空间位置**／**已发生的事实**／**数字与时长**——**凡续文要复述的既有信息，回前文抄，不凭印象**（本轮实录：前文「晚冬＋整整一年」，我写成「从盛夏排到深秋」，与 365 天直接冲突）

**第 3 步 · 接续三不**（**犯一条就是接坏了**）
① **不复述**——不把前文讲过的事再讲一遍；② **不重演**——不重写断点前的场景（**唯一例外**：补完半句话）；③ **不抢用**——不提前用掉后文才该出现的伏笔／反转／新角色（**对前文伏笔台账核**）

**第 4 步 · 写**
走通用文笔规则（同路径 A 第 4 步）。五处不同：① **首段的任务是「接上前文」，不是「章节起手式」**；② 字数按**剩余量**取；③ **风格档沿用前文，不重选**；
④ **能演就别讲**——不许**连续 2 段以上**都由认知动词（她想着／她觉得／她明白／她记得）开头而**没有物理动作**：心理改动作、解说改反应（2026-10-09 用户批评）；⑤ **描写要过删减测试**——每处景物／氛围描写删掉后**读者少不少东西**？**没少＝删**（同上）。

**第 5 步 · 接缝测试**（**「续得好」的判据 · 七问逐条举证，不许打勾**）

| # | 问 | 判据 | 不过怎么办 |
|---|---|---|---|
| **缝1** | **语气跳不跳** | 两侧画像：均段长／均句长／短句率／对白占比**任一差 ≥ 2 倍** ＝ 跳档 | **改续文去贴前文**（不是改前文） |
| **缝2** | **视角人称时态一致吗** | 人称／视角人物／时态／叙述距离，与前文对不对得上 | 统一成前文口径 |
| **缝3** | **称呼用语一致吗** | 搜前文里那个人名**前后 2 字**，看前文怎么叫，续文用同一套 | 统一成前文的叫法 |
| **缝4** | **前文抛出的东西接住了吗** | 第 2 步的「未完成项」，续文**至少接住一项** | 回第 2 步重看 |
| **缝5** | **连读有没有「重来一遍」感** | **删减测试**：删掉续文首段，读者掉不掉信息。**不掉 ＝ 首段在复述** | 删首段或改写首段 |
| **缝6** | **事实与前文对得上吗**（v2.2.0） | 第 2 步「事实锚」逐条核：**时间线／道具状态／空间位置／已发生的事实／数字与时长** | 回第 2 步，逐条改 |
| **缝7** | **靠「演」还是靠「讲」**（v2.2.0） | 有没有连续 2 段以上认知动词开头而无物理动作？每处景物描写**删掉读者少不少东西**？反应套话堆叠（800 字内 2 处）由 `chapter_stats.py` 机器判 | 心理改动作、渲染删掉；套话按 `reaction-beats.md` 四式改 |

> **缝1／缝5 可脚本辅助**：`python scripts/check_seam.py 前文.md 续文.md`（**已过污染测试**：能抓跳档与复述）。
> **缝2／缝3／缝4／缝6／缝7 是语义判定，由模型逐条举证**——**脚本全绿 ≠ 接缝没问题**（2026-10-09：脚本全绿，用户仍判「写的很差」——因为**检查面只有语气，没有事实与呈现**）。

**交付**：章间断点 → 正常 `第XX章.md`；**章内接续 → 只交你新写的那一段**（并说明**从哪一行开始接**），**不重打前文**。
>
> **⚠️ 续写场景的字数校验要按「剩余量」传参**，不能用整章区间——否则片段会被判"字数不足 FAIL"：
> `python scripts/check_chapter_wordcount.py 续写片段.txt 300 500`（区间＝整章目标 − 已写，±20%）
> **2026-10-09 实测**：拿基准样本（短章文艺向）ch001 截断续写，续文 373 字，跑默认区间被判 `[X] 正文字数: 373`——**这个 X 是"形态没判"的信号，不是续文有问题**。

## 五、改稿模式（用户说「这章重写一下」「这段润色」）

**第一件事不是改字，是判根因。** 改错层＝白改（实测：结构层 6 项与文笔层 26 条死线全过，用户仍判"感觉没什么看点"——因为**两套判据里没有一项问"读者读完拿到什么"**）。

| 症状 | 根因层 | 往哪改 |
|---|---|---|
| "整章就在讲一件事"／"很平凡" | **结构层** | 回第 2 步：事件单元 < 2？主角没主动行动过？→ **重排结构**，不是加描写 |
| "读完了手里是空的"／"没什么看点" | **本章变化层** | 回第 2 步第 1 项：本章不可逆地变了什么？答不出＝重排任务 |
| "节奏不对／关键的事来得太晚／前面太磨" | **位置层** | 回第 2 步的位置返工表：**甲类往前搬／乙类往后挪／丙类拆成两句**。**不许回正文挪句子** |
| "碎／跳／病句／上下句对不上" | **文笔层** | 第 6 步乙层的六步法 ＋ 承接测试四问，**逐段举证** |
| "读不顺／短得接不上" | **文笔层** | 先看是不是半截句／行尾无终止标点（脚本可判）；**不是句短就往回改**——按承接测试四问定，**不得以句长改文** |
| "AI 味重" | **文笔层** | `references/revision-methods.md` 第三节四层诊断 |
| 单场字数严重失衡 | **配额层** | 回字数配额表：补"别人的反应与来回"，**不补形容词** |

**改完必做**：① 复跑 `chapter_stats.py`（**改一处可能撞上另一条死线**）② 复跑字数校验 ③ 重跑承接测试四问至全过。

> **改稿的优先级**：结构 > 位置 > 文笔。**结构不对时改文笔＝把力气花在下游。**

## 六、体检模式（用户说「帮我检查一遍」「跑一下门禁」）

**只诊断，不改文**（用户没让改就不改）。

输出一份**四栏举证表**：

| 位置 | 问题类型 | 原句 | 修法建议 |
|---|---|---|---|
| 第 N 段 | 跳（动作缺环） | 「…」 | 补"起身→走到水盆边"两步 |

**必跑**：

```bash
python scripts/chapter_stats.py 第XX章.md            # 确定性错误（FAIL/WARN）+ 风格画像
python scripts/check_chapter_wordcount.py 第XX章.md   # 字数区间
python scripts/plan_word_quota.py --check 第XX章.md --actual <各场字数>  # 逐场失衡
```

**必看**（脚本只定位，判定由模型做）：

- **S5.3 承接测试四问**——逐段过，**禁止打勾**，每条给位置与原句
- **甲层结构**（甲0-甲9）：事件单元数、回合数、相邻回合变项、章末最狠、主角主动行动、跨章道具交接、结尾前进力
- **S3.2 遮蔽测试**：遮住引号行，是否仍读得出"在哪／谁在场／围绕什么物件／局面变了什么"

**三条必须写进报告的话**：

1. **"脚本全绿 ≠ 这章没问题"**——脚本只判确定性错误（破折号／引号／标点／重复／拉丁字母），**语义问题它一条都管不了**。
2. **风格六项只报数、不判定**——不得据此判好坏。
3. **"规则在 ≠ 会执行"**——曾有四条批注全部命中已有死线条款。

## 七、长线连续性（**防穿帮**）

写第 10 章时忘了第 3 章死了的人——这是长篇最常出的问题。**每次写新章前读、写完后更新。**

### 落到哪（**两种落法，按项目现状选**）

| 项目现状 | 落到哪 |
|---|---|
| 已有 `.learnings/`（fanqie-writer 或其他技能建的） | **直接沿用**：`CHARACTERS.md`／`LOCATIONS.md`／`PLOT_POINTS.md`／`STORY_BIBLE.md`／`ERRORS.md`；写前准备进 `施工细账_卷N.md`；自检记录进 `交付自检留痕.md` |

### 每次必记

| 记什么 | 为什么 |
|---|---|
| 新角色 → 角色当前状态（等级／位置／生死） | 防死人复活、等级倒退 |

## 八、写作禁忌与硬规则

### 最高优先级

- **① 首稿默认：AI 先出稿，用户后改。提问是例外，不是流程。**
  收到任何输入（一句方向／素材／前文），**第一个交付物必须是一份完整正文草案，不是问题清单**。
  - **由 AI 直接定稿**（每项附「答案 ＋ 一句依据 ＋ 能换成什么／代价是什么」）：风格档／本章任务／事件单元／回合／开头落点／结尾落点／场景划分。
  - **用户的位置是审稿人，不是答题人**：改哪项说哪项，**只重推受影响的下游项**。
  - **判据一句话**：**你准备发出的这条消息，如果用户只能回「A / B / C」，它就是错的形式**；正确的形式是用户看完能回「对」或「这里改成 X」。
  - **「自主」≠「随便定」**：每项必须给得出依据（用户原话／前文证据／作者锚点）。**给不出依据的，说明它真的需要用户输入——此时才问，且要带上你已有的判断和卡在哪。**
- **② 禁止残留模板标记**：交付文件不得出现 `[ ]` / `待定` / `待补` / `待用户填`。唯一例外是 `references/my-methodology.md` 的个人文风锚点（必须作者本人定）。
- **③ 用户的选择是输入，不是产出**：交付物必须是写出来的实质内容。空表、"待用户填"＝未完成。

### 内容层禁忌

- **每章要有推进**：不连续两章以上原地踏步（没有变化、没有冲突）。
- **本章的变化必须比上一章更狠**（同层＝重复）；**跨章对白逐字复现是硬伤**（已机器化）。
- **展示而非讲述、去 AI 味**——这是「读得下去」的关键。
- **伏笔呼应**：前文埋的线后文要收。
- **人物不蠢**：对手太弱衬托不出主角；设定要有边界，**不开无限制挂**。
- **时间轴清楚**：年数、年龄、季节、往返耗时，写的时候自检。

### 风格层（**不设门槛**）

**「风格自由，错误无自由。」** 用户原话：「**这种不同的方式都可以有的**」（对话文／叙述文／碎切／长句都可）＋「**病句，碎句，跳，上下句描述错误，这种问题是通用不能有的**」。
**禁止以"句子太短／段太短／对白太多"为由改文。**
**风格判断依据**：8 本不同风格长篇的实测画像 ＋ 区间包络与不可分性证明，见 `references/benchmark-writing.md`。

## 九、脚本

五个脚本，都在 `scripts/` 下。**Python 路径**：优先用本机可用的 python3。

```bash
# ① 写前：单章字数配额表（把"2250 字"翻译成每场目标字/段数/建议拍数）
python scripts/plan_word_quota.py --total 2250 --scenes 6 --avg-para 20.5 --weights 1,1.2,1.3,1,1,0.8

# ② 写后：逐场对账（甲8）
python scripts/plan_word_quota.py --check 第XX章.md --actual 206,63,1171,453,137,180

# ③ 格式归一（头部多余 --- 合并／正文内残留清理／ASCII 直引号 → 全角成对）
python scripts/format_chapter.py 第XX章.md

# ④ 字数校验（只算正文，不含元数据/备注/自检清单；后两个参数可改区间）
python scripts/check_chapter_wordcount.py 第XX章.md
python scripts/check_chapter_wordcount.py 第XX章.md 3000 8000
python scripts/check_chapter_wordcount.py --all .            # 整个目录

# ⑤ 客观指标 + 风格画像（退出码 0 = 无 FAIL）
python scripts/chapter_stats.py 第XX章.md
python scripts/chapter_stats.py --all .

# ⑥ 接缝检查（**接续模式必跑**：缝1 语气画像对比 + 缝5 复述检测）
python scripts/check_seam.py 前文.md 续文.md

# ⑦ 本技能自检（收尾必跑）
python prd/self_check.py                 # 四项全跑
python prd/self_check.py --refs          # ① 引用完整性
python prd/self_check.py --frontmatter   # ② SKILL.md 的 YAML 合法性
python prd/self_check.py --words         # ③ 通用性
python prd/self_check.py --lexicon       # ④ 词表真源自检

# ⑧ 上架打包（**要发包时才跑**；门禁不通过则出不了包）
python prd/make_package.py --dry-run     # 只跑两道门禁（私有信息 ＋ 本技能自检）
python prd/make_package.py               # 打 zip 到 dist/（**只清自己的旧包**）
```

| 脚本 | 判什么 | 不判什么 |
|---|---|---|
| `chapter_stats.py` | **只判确定性错误**：破折号／ASCII 直引号／标点错配／标点连用／引号不配对／相邻行重复／叠字／半截句／行尾无终止标点／**跨章对白逐字复现**／**正文含拉丁字母**（FAIL）；半角数字（WARN） | **风格六项只报数不判定**；语义层四问**由模型逐段举证** |
| `plan_word_quota.py` | 逐场字数配额与差额 | —— |
| `check_chapter_wordcount.py` | 字数区间（默认 2200-2800；自动读项目参数／可传参改） | —— |
| `format_chapter.py` | 格式归一 | **不改内容**（破折号等硬伤须回正文改写，换标点凑数会撞死线） |
| `check_seam.py` | **接缝（续写质量）**：缝1 两侧画像对比（差 ≥2 倍报跳档）；缝5 复述检测（续文首段／全文与前文的重叠） | **缝2/缝3/缝4 不判**（语义，由模型举证）；不判正文其余质量 |
| `prd/self_check.py` | **本技能自检**：引用完整性 ＋ SKILL.md frontmatter 合法性 ＋ 通用性（不指向他技能独有文件）＋ 词表真源自检 | 不判正文质量 |

## 十一、与其他技能的关系

### 与 `fanqie-writer`（番茄平台：立项 → 细纲）

**两个独立技能，互不依赖。** 本技能是**通用正文写作**；`fanqie-writer` 是**番茄平台的立项层**（选题 → 大纲 → 人物 → 情绪曲线 → 章节细纲 → 写作规则文档）。**不必二选一**：

| 情况 | 怎么办 |
|---|---|
| **只用本技能** | 你已经有细纲／设定／前文（哪怕是别的技能做的、或自己手写的）→ 直接写正文。**不需要装 `fanqie-writer`** |
| **两个都装** | `fanqie-writer` 走完立项到细纲，到写正文时把项目路径 ＋「写第 X 章」交给本技能接手。接得上——两边共用同一套 `.learnings/` 结构 |
| **用别的技能做的大纲** | 一样能用。本技能的**材料适配层**就是为"半路接手"设计的（见第三章） |

**文件关系：零共享。**（2026-10-09 起）两边同名文件是**各自独立的两份**，改动**互不影响**——改本技能的文件，不需要、也不应该去动 `fanqie-writer` 的同名文件；反之亦然。

> **为什么曾经要求同步**：早期用一个漂移校验脚本（`sync_check.py`）＋ 一份基准文件（`.sync-manifest.json`），把两边同名文件锁成**逐字节一致**，理由是"这些是同一套规则复制了两份"。代价是**改一边必须改另一边**——两个技能被锁成一套，谁也单独演进不了。**用户 2026-10-09 拍板解耦：各自一套，自己改自己的。** 那两个耦合件均已删除。
>
> **代价（如实写明）**：同一条通用规则若两个技能都要改，**要改两遍**。这是解耦的成本，换来的是**两个技能各自独立演进、独立上架、互不干扰**。若将来确实发现某处该保持一致，**手动比对**即可（`diff -r` 就够，不需要专门工具）。

### 上架：各行其是（2026-10-09 起）

**本技能有自己的打包器**——`prd/make_package.py`：读**自己的**版本号（本技能 `SKILL.md`）、
跑**自己的**两道门禁（私有信息扫描 ＋ 本技能自检四项）、产**自己的**包
（`prose-writer-vX.Y.Z.zip`，含 `SKILL.md` ＋ `references/` ＋ `templates/` ＋ `scripts/` ＋ `skill.json` ＋ `README.md`）。

**互不干扰的硬证据**（都实测过）：

| 验的是什么 | 怎么验 | 结果 |
|---|---|---|
| 打包**不删**对方的包 | 两侧各打一次，看输出目录 | 两个 zip **同时存在** |
| 门禁**不依赖**对方 | 把对方技能目录整个移走，再跑本侧门禁 | 本侧**照常全过** |
| 私有信息门禁**不空扫** | 喂一个缺 `SKILL.md` 的目录 | **FAIL**（不是静默 PASS） |

> **⚠️ 关键在于"只清自己的"**：旧做法是"打包前清空输出目录下所有 `*.zip`"——
> 两个技能共用同一个输出目录时，**一方打包会把另一方的包删掉**，那就是互相干扰。
> 现两侧都改成只清与自己包名匹配的那一个。

**私有信息门禁是各自的**：`prd/check_private_terms.py` 两份文件各自维护、
词表当前内容相同但**不要求同步**（因为面对的是同一批开发期样本）。
它含**扫描面覆盖自检**（扫描面 ＋ 排除表 ＝ 目录全部文件）与**锚点断言**
（`SKILL.md` 必须在扫描面里——否则是"空扫"，而空扫会假 PASS）。

### 本技能不收录的部分

`fanqie-writer` 另有一批**平台专属**文件（黄金开篇／悬念钩子／情绪曲线／过审清单／原创性平台治理／番茄管线桥接等），**本技能一份都不收**——本技能的规则是**通用**的，不绑定任何平台。那些文件仍在 `fanqie-writer` 里，用它的时候读得到。

## 十二、收尾自检（每章交完前，逐条过）

1. **脚本三项全跑且无 FAIL**（`chapter_stats.py` / `check_chapter_wordcount.py` / `plan_word_quota.py --check`）
2. **甲层结构全过**（尤其甲0 事件单元 2-4、甲8 逐场对账、甲9 结尾前进力）
3. **乙层承接测试四问逐段举证**（四栏表，无问题写"本轮 0 处"）
4. **交付文件是纯正文**（无准备／备注／自检／技能路径）
5. **本技能自检全过**（`python prd/self_check.py` 退出码 0：引用 ＋ frontmatter ＋ 通用性 ＋ 词表）
6. **记忆已更新**（角色／地点／伏笔／摘要／本章前进力）
7. **已向用户交代**：哪些是 AI 推的、哪些是用户给的（B/C/D 路）；**形态与参数也一并声明依据**
8. **（接续时）接缝测试七问全过**——缝1／缝5 跑 `scripts/check_seam.py`；缝2／3／4／6／7 逐条举证。**另：第 0 步前文体检的违规已按交付形态处置**（交整章 → 一并清掉并写明改了几处）
