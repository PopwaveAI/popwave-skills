# short-body-generator
> 短篇正文生成器。选文风→定模式→逐段生成→去AI味儿。v1.1.0

## 做什么
输入：骨架卡片（自 plot-structurer 流转上下文）
输出：完成草稿 + 流向 reviewer 的流转上下文（正文全文+全部前置卡片）

## 怎么操作（SOP骨架）
> execution.mode: 串行 | 强保障：本 SKILL.md 由 host 层每次 run 强制注入 | 弱保障：steps/ 需 agent 主动 Read

| 步骤 | 做什么 | 产出 | step 文件 |
|:-----|:-----|:-----|:----------|
| 5A | 文风选择。加载5种平台文风，匹配平台→推荐默认→用户确认或上传参考 | 文风确认 | `steps/step1-style-select.md` |
| 5B | 确定生成模式（逐段确认 vs 一键全文） | 模式确认 | `steps/step2-generate-segment.md` |
| 5C | 收集用户额外补充（特殊要求/偏好） | 补充清单 | `steps/step2-generate-segment.md` |
| 5D | 逐段生成+自检+用户确认，付费钩子段特殊标记 | 正文草稿 | `steps/step2-generate-segment.md` |
| 5E | 付费钩子段断点控制+驱动力检查 | 付费钩子到位 | `steps/step3-pay-hook.md` |
| 5F | 去AI味儿流程：自检清单+用户确认 | 去味儿完成 | `steps/step4-deai-check.md` |

## 平台→文风默认推荐
| 平台 | 默认推荐 |
|:---|:---|
| 知乎盐言 | 知性沉稳 |
| 番茄短故事 | 网感快节奏 |
| 每天读点故事 | 情感细腻 |
| 豆瓣阅读 | 文学质感 |
| 小程序/信息流 | 极速钩子 |

## 生成模式
| 模式 | 方式 | 适用 |
|:---|:---|:---|
| 逐段确认（默认） | 每段一次生成→一次自检→一次用户确认 | 用户想控制节奏和方向 |
| 一键全文 | 一次性生成全文→快速逐段自检→一次性展示→用户逐段反馈 | 用户想先看整体效果 |

## 每段自检清单
| 检查项 | 标准 |
|:---|:---|
| 推进了情节或深化了人物？ | 删掉不影响理解→重写 |
| 情绪密度达标？ | 对照弧线表密度标注 |
| 没有偏离脑洞？ | 对照脑洞一句话+导语 |
| AI味儿？ | 总结句/模板句式/过度过渡/抽象描写/AI式对话 |
| 角色一致？ | 主角行为符底线？配角风格符标签？ |

## 红线
| # | 红线 | 违反后果 |
|:-:|:-----|:---------|
| 1 | 生成前必须确认文风，禁止跳过文风选择直接生成 | 文风与平台不匹配 |
| 2 | 付费钩子段必须特殊标记+断点暂停，不能混入普通段 | 钩子位置模糊，付费策略失效 |
| 3 | 每段生成后必须通过自检再交给用户 | 低质量草稿流入下游 |
| 4 | 去AI味儿是必走流程，不可跳过 | 成品AI感重 |
| 5 | 用户参考文本是文风最高优先，覆盖平台默认推荐 | 用户风格诉求被忽略 |
| 6 | 用户在任何后续步骤（评审后/自己重读后）要求改某一段正文，只重写该段，其余段落保持不变 | 整篇重写导致用户之前的逐段确认白费 |
| 7 | 单段重写时仍然走完整自检流程（推进情节/密度达标/不偏离脑洞/AI味儿/角色一致） | 重写段和其余段落质量不一致 |
| 8 | 微调响应格式——如本轮只修改了已有段落的 ≤5 句话，响应仅输出改动段 + 一句说明。不输出钩子分析、创作记录、自检清单 | 响应膨胀，浪费算力 |

## 响应分级

| 用户指令类型 | 响应格式 |
|:---|:---|
| 明确确认（"继续""可以""ok""没问题"） | 只输出下一段正文。不附带创作记录、钩子分析、自检清单 |
| 微调请求（"改一下XX""这里不对"） | 只输出改动段落 + 一句话说明改了什么 |
| 新方向/新段落/首次生成 | 输出正文 + 关键钩子 + 创作记录要点（≤5条） |
