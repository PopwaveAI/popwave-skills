# short-idea-refiner
> 短篇脑洞提炼器。按路径收集输入，提炼两到三个方向，再检验并输出脑洞卡片。v2.2.0：原 steps 三项全部合入单一文件并精炼；执行模式为由主 agent 直接执行。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 做什么
输入：模糊想法、题材方向或例文（三者可能全为空）。
输出：脑洞一句话、脑洞卡片，以及传向 opening-designer 的流转上下文。

**执行模式**：由主 agent 直接执行。本技能是连续创作流程（脑洞、导语、结构）中的对话交互环节，路径判断、方向选择与检验补强全程与用户共同确认决策，没有适合派子 agent 的环节。

## 怎么操作（规程全部直接写在本文件内）

### Step 1 收集输入与判断路径
从 platform-orientation 的流转上下文或用户发言中提取：【选定平台】【文章性质】【用户意向】（题材、目标、改编诉求）【原始想法】（可能为空）。

| 用户说了什么 | 路径 | 处理 |
|:--|:--|:--|
| 有模糊想法（"我有个大概的想法……"） | A | 让用户说出想法："不用讲得太清楚，模糊也没关系，一句话就行" |
| 只有方向没有想法（"想写言情但不知道写什么"） | B | 用两到三个问题收窄偏好：甜、虐还是先虐后甜？现代还是古言？特别想写的职业或场景？ |
| 带了例文、榜单或链接 | C→A | 先解析例文的核心卖点（脑洞一句话、题材、流派标签）与可对接的风格要素，再走路径 A，例文风格的参考权重随之提升 |

### Step 2 拉取热点与提炼方向
**2a 热点拉取**（按优先级）：①用户提供的素材（榜单截图、链接或例文）；②WebSearch（`"{平台名} {题材} 热门 2026 品类趋势"`）；③知乎智慧故事（WebFetch `https://www.zhihu.com/zhihui/story`）。从中提取信号：哪些子方向在涨、哪些在退，以及近期爆款关键词。**热点仅作参考信号，不替代创作决策。**

**2b 路径A直接提炼**：基于原始想法、平台热点趋势、题材适配度与改编潜力，生成两到三个脑洞方向，并按推荐度排序。每个方向包含脑洞一句话、为什么好（两到三条）与注意事项（如有）；带例文（路径 C）时，"为什么好"须额外说明其与例文的风格关联。

**2c 路径B先出方向菜单**：呈现一张四到五个子方向的表（子方向、热度🔥1-5、竞争高中低、改编潜力⭐1-5、范例脑洞一句话），等用户选定偏好后，再生成两个脑洞方向。

**2d 邀请榜单**（路径 A 与 B 通用）："如果你最近看到觉得不错的短篇，或关注的热门榜单，可以发给我参考，我能更好判断读者口味。没有也没关系。"

### Step 3 检验与输出脑洞卡片
**3a 检验**（逐条判定；**至少两项通过方可进入下一步**，未全部通过时，给出两到三条补强建议供用户选择改进方向）：

| 检验项 | 判定 |
|:--|:--|
| 让人想听下去吗？ | 通过/不通过 |
| 有反常识、反预期的元素吗？ | 通过/不通过 |
| 能在三分钟内讲清吗？ | 通过/不通过 |

**3b 脑洞卡片**：脑洞一句话、题材、流派标签、目标平台、适配性质、核心冲突、预期反转或爽点、检验结果（逐项通过/不通过）、热点参考（品类趋势摘要）。

**3c 流转上下文**（传向 short-opening-designer）：选定平台、文章性质、核心约束、选定脑洞方向、脑洞一句话、题材、流派标签、检验结果、热点参考。

**3d 写入**：保存为 `step2-脑洞提炼.md`。

## 红线
| # | 红线 | 违反后果 |
|:-:|:-----|:---------|
| 1 | 不替用户写脑洞，只给选择供用户决策 | 用户无参与感，后续不认可 |
| 2 | 检验标准至少两项通过方可进入下一步 | 不合格脑洞流入后续步骤 |
| 3 | 热点数据仅作参考信号，不替代创作决策 | 追逐热点写出同质化内容 |
| 4 | 跨平台一稿多投时提醒平台差异 | 开篇钩子逻辑混乱 |
