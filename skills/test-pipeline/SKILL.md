# pipeline（设定包改编·一次性安装器）

> v8.0.0：从"每次加载的常驻路由"瘦身为**一次性安装器**——Step 2 路由循环/主agent执行协议/Phase5-6写审循环/产出真实性门禁全部上移专家提示词（会话契约+阶段地图+灵活调度），本 skill 只管安装/导入/包校验/强度选择/缺口分析/补跑调度。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 做什么

| 职责 | 说明 |
|:--|:--|
| 一次性安装（fresh） | 建目录 + 落盘 `状态.md`（薄机器状态）+（可选）导出展示面板 + 包校验 + 创意X采集 + 改编强度A/B/C选择 |
| 一次性导入/续写（import/resume） | 资产扫描→归位→缺口分析→落地Phase→状态重建→补跑调度 |
| 状态文件维护 | `状态.md` = 唯一机器状态源，agent 只读它的状态片段；`.html` 为仅供老板查看的展示面板，按需导出，**agent 不参与渲染也不读** |

**日常路由不经此skill**：用户说"继续写/下一步/写正文/审核"时，主agent按**专家提示词规则2**的阶段地图与灵活调度直接选 skill（默认顺序：立项→世界→角色→剧情→正文→审核；关键门禁：包配方齐、改编强度已选、产过真实性门禁），各 skill 按自身 SKILL.md 干活。pipeline 不写正文、不做内容转换、不常驻。

**执行模式**：主agent直执——初始化/导入交互（资产清点、包校验、强度选择）由主agent完成；生成任务由主agent加载对应子skill执行。**禁止派发子agent执行技能生成任务**。

## 怎么操作（SOP全内联）

### Step 0：导入/续写模式

> 触发条件（任一满足即进入）：①用户说"导入/续写/已有/接续/迁移" ②Step 1初始化时检测到`正文/`或`设计/`已有文件 ③项目目录已有内容但无项目总控.html。
> 理念：pipeline是调度员不是制造者——只做资产清点、文件归位、缺口分析、补跑调度；深度内容转换（正文反推/设计补建）由主agent加载对应skill的reconstruct模式完成。

**0a 资产扫描**：LS扫描项目目录（或用户指定的源目录）→输出**原始资产清单**（文件名+位置+内容摘要1句话）。

**0b 资产归位**（只做文件名/目录归位，不做内容结构标准化）：

| 用户文件（模糊匹配） | → 标准位置 | 标准文件名 | 对应Phase |
|:--|:--|:--|:--|
| *意图*/*方向*/*想法*/用户口述 | `素材/` | 用户意图.md | Phase 0 |
| *参考答案*/*设定包*/*包配方* | `素材/` | 参考答案-{书名}/（含包配方.md） | Phase 0 |
| *文风*/*DNA*/*笔触*/*风格* | `素材/` | 文风锚定.md | Phase 3→3.5（可选） |
| *decon*/*拆书*/*力量分析* | `素材/` | decon-lite-{书名}.md | 建包底稿 |
| *骨架*/*体系*/*力量*/*设定大纲* | `设计/` | 力量体系.md+动力引擎.md | Phase 3 |
| *立项*/*PRD*/*六要素*/*种子*/*创意* | `立项/` | 01-立项PRD.md | Phase 1 |
| *金手指*/*外挂* | `设计/` | 金手指.md | Phase 3.5 |
| *主线*/*剧情大纲*/*主线候选* | `设计/` | 主线.md | Phase 4 |
| *角色库*/*NPC*/*配角* | `设计/角色库/` | 角色库.md | Phase 3.5 |
| *卷纲*/*大纲*/*分幕* | `卷纲/` | 卷一-卷纲.md | Phase 4 |
| *章白描*/*章纲*/*章节规划* | `卷纲/` | 卷一-幕N-章白描.md | Phase 4 |
| *正文*/*章节*/ch*/第*章 | `正文/` | ch{NNN}.txt | Phase 5 |
| *白描卡*/*本章记录* | `产出/白描卡/` | ch{NNN}.md | Phase 6 |
| *状态快照*/*状态*/*快照*/*进度* | `产出/` | 状态快照.md | Phase 6 |

操作：匹配不上的文件归"未分类资产"询问用户映射；.docx等异构格式转.md（Read内容→Write标准位置标准文件名）；正文文件统一编号（`第一章.txt`/`chapeer1.md`→`正文/ch001.txt`）；询问用户是否保留原文件。

**文件来源标记**（每个归位文件记入总控产出表）：

| 来源标记 | 含义 | 后续处理 |
|:--|:--|:--|
| `user-original` | 用户已有文件，直接归位 | ⚠️需校验，后续可调度skill校验 |
| `pipeline-relocated` | pipeline做了格式转换（.docx→.md等） | ⚠️需校验 |
| `skill-generated` | 对应skill正向产出 | 正常消费 |
| `skill-reconstruct` | 对应skill reconstruct模式产出 | 正常消费 |

**0c 缺口分析**：归位完成后对照依赖链逐Phase检查：

| Phase | 就绪判定 |
|:--|:--|
| 0 | 用户意图.md + 设定包（包配方5表）都有且5表齐 |
| 1 | 立项/01-立项PRD.md（六要素+配方继承表） |
| 3 | 力量体系.md + 动力引擎.md + 全书设定/11文件 |
| 3→3.5 | 文风锚定.md（可选） |
| 3.5 | 金手指.md + 角色库/角色库.md |
| 4 | 主线.md + 卷纲/卷一-卷纲.md + 卷纲/卷一-幕*-章白描.md |
| 5 | 正文/ch*.txt |
| 6 | 产出/白描卡/ + 产出/状态快照.md |

正文进度检测：`正文/`有文件→提取最大章节号，current_chapter=下一章待写（如ch001~ch015→ch016）。质量来源检测：user-original/pipeline-relocated→⚠️需校验；skill-generated/skill-reconstruct→✅已验证。输出**缺口报告**。

**0d 落地Phase决策**（根据缺口报告+正文进度）：

| 条件 | mode | 落地Phase | 说明 |
|:--|:--|:--|:--|
| 正文有+白描卡有+状态快照有 | resume | Phase 5（续写下一章） | 状态完整直接接续 |
| 正文有+状态文件缺失 | resume | 先0f调度review reconstruct→Phase 5 | 需补建状态文件 |
| 正文无+Phase 4就绪 | import | Phase 5（开始写） | 设定+剧情完整 |
| 正文无+Phase 3.5就绪 | import | Phase 4（plot） | 缺剧情 |
| 正文无+Phase 3就绪 | import | Phase 3.5（character） | 缺角色库 |
| 正文无+Phase 1就绪 | import | Phase 3（world） | 缺世界设定 |
| 正文无+Phase 0就绪 | import | Phase 1（adapt） | 缺立项 |
| 全无 | fresh | Phase 0 | 从零开始（走Step 1初始化） |

→向用户展示：资产清单（含来源标记）+缺口报告+落地Phase建议+补跑建议清单（0f），**用户确认后**进0e。

**0e 状态文件重建**：`状态.md`不存在→按「状态.md 模板」创建；已存在→SearchReplace更新。字段：mode（fresh→import/resume）、phase（init→落地Phase）、current_chapter、改编强度、就绪态（已就绪Phase标`[x]`、落地Phase标`[进行中]`）。**展示面板可选**：仅当老板要看可视化面板时，按 `templates/项目总控.html` 套用 状态.md 值导出 html——agent 只写 状态.md，不参与渲染 html，也不在每轮读它。

**0f 调度skill补跑**（pipeline不自行做内容结构标准化/正文反推/设计文档补建，只识别缺口+调度skill+汇报结果）：

| 缺口类型 | 调度skill | reconstruct做什么 |
|:--|:--|:--|
| 有正文+缺白描卡/状态快照 | review | 批量回溯审核已有正文→逐章白描卡+状态快照 |
| 缺Phase 1-4设计文档 | 对应skill（adapt/world/character/plot） | 读已有文件→按skill方法论校验+补全→输出标准格式 |
| 已有设计文档但来源=user-original | 对应skill（用户确认后按需调度） | 读已有文件→按skill方法论校验→标注缺口或确认达标 |

- **review reconstruct**：主agent加载test-review的reconstruct模式执行正文反推。采样：≤10章全审 / 11-30章最近5章+每5章取1章 / >30章最近5章+第一章+每10章取1章。产出：`产出/白描卡/ch{NNN}.md`+`产出/状态快照.md`。
- **设计文档补跑**：按依赖链顺序补跑（world→力量体系+动力引擎+全书设定；character→金手指+角色库；plot→主线+卷纲+幕N章白描）。用户已有正文但缺剧情文档→plot reconstruct从正文反推；用户选跳过plot直接续写（降级模式）→在状态快照手动指定下一章核心事件。
- **不调度的情况**（pipeline自行处理）：素材层文件（用户意图.md/参考答案-{书名}/等按标准分节简单重组即可）；文风锚定.md缺失需用户先跑pop-dna-style（非reconstruct场景）。
- **补跑建议清单**（输出给用户）：逐文件一行——文件名：来源=…，状态=…，建议=正常消费/补跑XX skill。用户三选：正常接续/按需补跑/全量补跑。

**Step 0质量门**：原始资产清单已生成｜资产归位完成（含来源标记）｜缺口报告已生成｜落地Phase已确定并经用户确认｜状态.md已创建/更新｜补跑建议清单已展示。

### Step 1：初始化（fresh模式）

**前置检测**：执行任何创建前先LS扫描项目目录——`正文/`有章节文件或`设计/`有.md文件→跳转「Step 0 导入/续写」；目录为空或仅有`状态.md`→继续本步。

1. **创建目录结构（一次性）**：素材/（含downloads/、知识沉淀/）+设计/（含全书设定/、角色库/）+卷纲/+立项/+产出/（含白描卡/）+正文/+审核/。创建后LS自检全部存在（缺一=初始化失败，补创后才继续）。
2. **创建 状态.md**：按「状态.md 模板」写入项目根（mode: fresh / phase: init / current_chapter: ch000 / 改编强度: 待选 / 全部Phase标[ ]）；再简建README.md。展示面板可选：老板要求时按模板导出 html。
3. **包校验（Phase 0门禁，缺表=拒绝启动）**：①定位包：用户指定书名→先查项目`素材/参考答案-{书名}/`，无则查全局`D:\popwave-skills\knowledge-base\设定包\{书名}\` ②校验包配方：Read`{包路径}/包配方.md`逐项确认5表齐全（卷幕骨架/节奏参数/颗粒度/爽点配方/角色配置）③不合格处理：缺表/无包→提示用户二选一——用test-research建包（需源书txt）/换一个已建好的包；**禁止凭记忆/通用知识顶替包** ④包定位到项目：全局包→提示可复制进项目（或记录全局路径直接消费）。
4. **创意X采集（轻交互，一次问完，已给则跳过）**：①创意X：一句话脑洞即可（想要的世界/金手指/主角方向，任一维度都行）②赛道方向（可省，默认从X推断）③对包参数的覆盖意向（可省，默认全继承）。
5. **改编强度选择（必问，禁止默认）**：用户输入X后呈现三档让其选择：

| 强度 | 改什么 | 保留什么 |
|:--|:--|:--|
| **A 改演员** | 主角/敌人/盟友/剧情事件/开篇场景 | 世界/地理/势力/力量体系/金手指 |
| **B 改世界观** | A全部+地理/势力/世界观/时代引擎 | 力量体系/金手指 |
| **C 全改** | B全部+力量体系/金手指 | 仅商业架构 |

用户不确定→推荐：X与包力量体系机制差异大（如盗贼→心灵异能）时推荐C；只换人物不换世界时推荐A。强度未选=不进入Phase 1。

6. **落盘**：`素材/用户意图.md`（X原文+包路径含包配方5表确认状态+改编强度A/B/C+覆盖意向）→更新 状态.md（phase=1、改编强度、素材就绪态）→路由Phase 1（加载test-adapt按其SKILL.md执行）。

**Step 1质量门**：目录齐全+状态.md落盘｜包配方5表齐全（或已提示建包）｜用户意图.md落盘（X+包路径+强度）。

## 红线

1. **只安装不生产**——pipeline不写正文/不设计/不审核；深度内容转换（正文反推/设计补建）调度对应skill的reconstruct完成。
2. **就绪判定查文件系统**——Phase推进条件=产出文件存在（不信口头声明）；依赖链（包→PRD→设定→角色→剧情→正文）不可跳。
3. **包准入门禁（Phase 0）**——包配方5表齐全才启动，缺表=拒绝并提示建包/换包；禁止凭记忆或通用知识顶替包。
4. **改编强度必问**——X采集后必须呈现A/B/C三档让用户选择，禁止默认；强度未定=不进入Phase 1。
5. **状态源**——`状态.md`=唯一机器状态源，agent 每轮只读/写它；`项目总控.html` 为仅供老板查看的展示面板，按需导出，**agent 不读 html**、不承担渲染成本。
6. **user-original/pipeline-relocated 资产必须标⚠️需校验**——未经对应skill校验的设计层用户文件不得直接消费。
7. **读取协议**——读取skill文件用`Get-Content -Encoding UTF8 -Raw`，Read工具有行数限制会截断丢内容。
