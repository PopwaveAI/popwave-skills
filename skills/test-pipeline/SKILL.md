# pipeline

> 设定包改编管线总控。v7.0.0：steps 两件（step0-import/step1）全合入单文件精炼——导入/续写与初始化流程内联，SKILL.md 自包含零跳转；pipeline只做路由不干活。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 做什么

输入：设定包（`KB/设定包/{书名}/`或项目`素材/参考答案-{书名}/`，含包配方5表）+ 用户创意X + **改编强度A/B/C** + 项目名（mode=fresh/import/resume）

输出：标准化目录结构 + `项目总控.html`（唯一状态文件）

**管线一句话**：包配方（商业架构质量锚）× 创意X（DNA替换）× 改编强度A/B/C（改多少）→ 改编计划 → 世界 → 角色 → 剧情 → 正文 → 审核。

**执行模式**：主agent直执——总控只路由不干活；导入资产清点/初始化/改编强度选择均需用户交互，生成任务由主agent加载对应子skill执行。**禁止派发子agent执行技能生成任务**。

---

## 怎么操作（SOP全内联）

### Step 0：导入/续写模式

> 触发条件（任一满足即进入）：①用户说"导入/续写/已有/接续/迁移" ②Step 1初始化时检测到`正文/`或`设计/`已有文件 ③项目目录已有内容但无项目总控.html。
> 理念：pipeline是调度员不是制造者——只做资产清点和文件归位，深度内容转换（正文反推/设计补建）由主agent加载对应skill的reconstruct模式完成。

**0a 资产扫描**：LS扫描项目目录（或用户指定的源目录）→输出**原始资产清单**（文件名+位置+内容摘要1句话）。

**0b 资产归位**（只做文件名/目录归位，不做内容结构标准化）：

| 用户文件（模糊匹配） | → 标准位置 | 标准文件名 | 对应Phase |
|:--|:--|:--|:--|

| *参考答案*/*设定包*/*包配方* | `素材/` | 参考答案-{书名}/（含包配方.md） | Phase 0 |
| *文风*/*DNA*/*笔触*/*风格* | `素材/` | 文风锚定.md | Phase 3→3.5（可选） |
| *decon*/*拆书*/*力量分析* | `素材/` | decon-lite-{书名}.md | 建包底稿 |
| *骨架*/*体系*/*力量*/*设定大纲* | `设计/` | 力量体系.md+动力引擎.md | Phase 3 |
| *立项*/*PRD*/*六要素*/*种子*/*创意* | `立项/` | 01-立项PRD.md | Phase 1 |
| *金手指*/*外挂* | `设计/` | 金手指.md | Phase 3.5 |
| *主线*/*剧情大纲*/*主线候选* | `设计/` | 主线.md | Phase 4 |
| *角色库*/*NPC*/*配角* | `设计/角色库/` | 角色库.md | Phase 3.5 |
| *卷纲*/*大纲*/*分幕* | `卷纲/` | 卷一-卷纲.md | Phase 4 |
| *章白描*/*章纲*/*章节规划* | `卷纲/` | 卷一-幕N-章白描.md | Phase 4 |
| *正文*/*章节*/ch*/第*章 | `正文/` | ch{NNN}.txt | Phase 5 |
| *白描卡*/*本章记录* | `产出/白描卡/` | ch{NNN}.md | Phase 6 |

操作：匹配不上的文件归"未分类资产"询问用户映射；.docx等异构格式转.md（Read内容→Write标准位置标准文件名）；正文文件统一编号（`第一章.txt`/`chapeer1.md`→`正文/ch001.txt`）；询问用户是否保留原文件。

**文件来源标记**（每个归位文件写入总控html产出表，后续skill消费时据此决定信任程度）：

| 来源标记 | 含义 | 后续处理 |
|:--|:--|:--|
| `user-original` | 用户已有文件，直接归位 | ⚠️需校验，后续可调度skill校验 |
| `pipeline-relocated` | pipeline做了格式转换（.docx→.md等） | ⚠️需校验 |
| `skill-generated` | 对应skill正向产出 | 正常消费 |
| `skill-reconstruct` | 对应skill reconstruct模式产出 | 正常消费 |

**0c 缺口分析**：归位完成后对照依赖链逐Phase检查：

| Phase | 就绪判定 |
|:--|:--|
| 0 | 用户意图.md + 设定包（包配方5表）都有且5表齐 |
| 1 | 立项/01-立项PRD.md（六要素+配方继承表） |
| 3 | 力量体系.md + 动力引擎.md + 全书设定/11文件 |
| 3→3.5 | 文风锚定.md（可选） |
| 3.5 | 金手指.md + 角色库/角色库.md |
| 4 | 主线.md + 卷纲/卷一-卷纲.md + 卷纲/卷一-幕*-章白描.md |
| 5 | 正文/ch*.txt |
| 6 | 产出/白描卡/ + 产出/状态快照.md |

正文进度检测：`正文/`有文件→提取最大章节号，current_chapter=下一章待写（如ch001~ch015→ch016）。质量来源检测：user-original/pipeline-relocated→⚠️需校验；skill-generated/skill-reconstruct→✅已验证。输出**缺口报告**（哪些Phase已就绪/缺失+每个文件的质量来源标记）。

**0d 落地Phase决策**（根据缺口报告+正文进度）：

| 条件 | mode | 落地Phase | 说明 |
|:--|:--|:--|:--|
| 正文有+白描卡有+状态快照有 | resume | Phase 5（续写下一章） | 状态完整直接接续 |
| 正文有+状态文件缺失 | resume | 先0f调度review reconstruct→Phase 5 | 需补建状态文件 |
| 正文无+Phase 4就绪 | import | Phase 5（开始写） | 设定+剧情完整 |
| 正文无+Phase 3.5就绪 | import | Phase 4（plot） | 缺剧情 |
| 正文无+Phase 3就绪 | import | Phase 3.5（character） | 缺角色库 |
| 正文无+Phase 1就绪 | import | Phase 3（world） | 缺世界设定 |
| 正文无+Phase 0就绪 | import | Phase 1（adapt） | 缺立项 |
| 全无 | fresh | Phase 0 | 从零开始（走Step 1初始化） |

→向用户展示：资产清单（含来源标记）+缺口报告+落地Phase建议+补跑建议清单（0f），**用户确认后**进0e。

**0e 状态文件重建**：`项目总控.html`不存在→读`templates/项目总控.html`写入项目根；已存在→SearchReplace更新。STATE标记替换：mode（fresh→import/resume）、phase（init→落地Phase）、chapter（ch000→current_chapter）、project_name、updated_at。circle+badge：已就绪Phase的circle从pending改done，落地Phase从pending改current，已有资产对应badge从❌改✅。

**0f 调度skill补跑**（pipeline不自行做内容结构标准化/正文反推/设计文档补建，只识别缺口+调度skill+汇报结果）：

| 缺口类型 | 调度skill | reconstruct做什么 |
|:--|:--|:--|
| 有正文+缺白描卡/状态快照 | review | 批量回溯审核已有正文→逐章白描卡+状态快照 |
| 缺Phase 1-4设计文档 | 对应skill（adapt/world/character/plot） | 读已有文件→按skill方法论校验+补全→输出标准格式 |
| 已有设计文档但来源=user-original | 对应skill（用户确认后按需调度） | 读已有文件→按skill方法论校验→标注缺口或确认达标 |

- **review reconstruct**（正文有且白描卡或状态快照缺失时）：主agent加载test-review的reconstruct模式执行正文反推。采样策略：≤10章全审 / 11-30章最近5章+每5章取1章 / >30章最近5章+第一章+每10章取1章。产出：`产出/白描卡/ch{NNN}.md`（每章一张，单章剧情记录）+`产出/状态快照.md`（replace，跨章聚合）。
- **设计文档补跑**（落地Phase>1且前置设计文档缺失或来源user-original时）：按依赖链顺序补跑——力量体系+动力引擎（world｜输入PRD力量体系方向+已有世界设定）；全书设定/10文件（world｜PRD世界方向+骨架+已有世界设定）；金手指（character｜PRD人物方向+骨架+已有设定）；角色库（character｜PRD人物方向+骨架+全书设定+已有正文）；主线（plot｜PRD起因·经过方向+已有设定）；卷纲+幕N章白描（plot｜力量体系+动力引擎+角色库+金手指+全书设定+已有正文）。用户已有正文但缺卷纲+章白描→plot reconstruct从正文反推；用户选跳过plot直接续写（降级模式）→在状态快照手动指定下一章核心事件，write按其指导续写，后续可补跑plot生成正式卷纲+章白描。
- **不调度的情况**（pipeline自行处理）：素材层文件（用户意图.md/参考答案-{书名}/等按标准分节简单重组即可）；文风锚定.md用户已有直接归位，缺失需用户先跑pop-dna-style（非reconstruct场景）。
- **补跑建议清单**（输出给用户）：逐文件一行——文件名：来源={user-original/pipeline-relocated/skill-reconstruct}，状态={✅已验证/⚠️需校验/❌缺失}，建议={正常消费/补跑XX skill}。用户三选：正常接续（接受当前文件质量）/按需补跑（指定哪些文件调度skill校验补全）/全量补跑（所有"需校验"文件都过一遍对应skill）。

**Step 0质量门**：原始资产清单已生成｜资产归位完成（文件名+目录归位+来源标记已标注）｜缺口报告已生成（含质量来源标记）｜落地Phase已确定并经用户确认｜总控html已创建/更新（mode+phase+chapter+circle+badge全部正确）｜补跑策略已确定（review reconstruct/设计文档补跑/用户选择跳过）｜补跑建议清单已展示给用户。

完成后回「路由循环」继续路由；需补跑则先执行reconstruct任务再路由。

### Step 1：初始化（fresh模式）

**前置检测**：执行任何创建前先LS扫描项目目录——`正文/`有章节文件或`设计/`有.md文件→跳转「Step 0 导入/续写」；目录为空或仅有`项目总控.html`→继续本步。

1. **创建目录结构（一次性）**：素材/（含downloads/、知识沉淀/）+设计/（含全书设定/、角色库/）+卷纲/+立项/+产出/（含白描卡/）+正文/+审核/。创建后LS自检全部存在（缺一=初始化失败，补创后才继续）。
2. **创建项目总控.html**：读`templates/项目总控.html`写入项目根，SearchReplace更新project_name/created_at/updated_at/genre（未指定保留"待指定"）；再简建README.md。
3. **包校验（Phase 0门禁，缺表=拒绝启动）**：①定位包：用户指定书名→先查项目`素材/参考答案-{书名}/`，无则查全局`D:\popwave-skills\knowledge-base\设定包\{书名}\` ②校验包配方：Read`{包路径}/包配方.md`逐项确认5表齐全（卷幕骨架/节奏参数/颗粒度/爽点配方/角色配置）③不合格处理：缺表/无包→提示用户二选一——用test-research建包（需源书txt）/换一个已建好的包；**禁止凭记忆/通用知识顶替包** ④包定位到项目：全局包→提示可复制进项目（或记录全局路径直接消费）；包内有文风锚定类文件一并登记。
4. **创意X采集（轻交互，一次问完，已给则跳过）**：①创意X：一句话脑洞即可（想要的世界/金手指/主角方向，任一维度都行）②赛道方向（可省，默认从X推断）③对包参数的覆盖意向（可省，默认全继承）。
5. **改编强度选择（必问，禁止默认）**：用户输入X后呈现三档让其选择（附清晰说明）：

| 强度 | 改什么 | 保留什么 |
|:--|:--|:--|
| **A 改演员** | 主角/敌人/盟友/剧情事件/开篇场景 | 世界/地理/势力/力量体系/金手指 |
| **B 改世界观** | A全部+地理/势力/世界观/时代引擎 | 力量体系/金手指 |
| **C 全改** | B全部+力量体系/金手指 | 仅商业架构 |

用户不确定→推荐：X与包力量体系机制差异大（如盗贼→心灵异能）时推荐C；只换人物不换世界时推荐A。强度未选=不进入Phase 1，先问清楚再推进。

6. **落盘**：`素材/用户意图.md`（X原文+包路径含包配方5表确认状态+**改编强度A/B/C**+覆盖意向）→更新总控html（phase=1、genre、素材就绪态、改编强度）。

**Step 1质量门**：目录齐全+总控html落盘｜包配方5表齐全（或已提示建包）｜用户意图.md落盘（X+包路径+强度）。下一步Phase 1：调度test-adapt（读其SKILL.md执行），路由见「路由循环」。

### Step 2：路由循环（每次对话开始时）

1. 第一件事读项目根 `项目总控.html`：mode（fresh/import/resume）+ phase + 各就绪态
2. 对照「Phase路由表」路由到对应Phase执行
3. Phase完成后更新html（phase、updated_at、对应就绪态STATE标记、产出表），向用户一句话汇报（本Phase产出+下一步），用户无异议继续下一Phase

### 主agent执行协议（所有Phase通用）

1. Read 对应skill的 `SKILL.md` 全文（该skill引用的执行文件一并读）
2. 提炼红线+操作要点，按skill的SOP执行（消费项目输入文件→生成→落盘）
3. **产出真实性检查**（Phase推进门禁，防空转）：
   - Phase 1→3：改编计划含X DNA替换矩阵+剧情类比切换策略；PRD含六要素+改编继承表（质量锚声明）
   - Phase 3→3.5：力量体系晋阶表有档位+全书设定11文件非空
   - Phase 4→5：卷纲含幕框架5行+核心张力映射表5行；首幕章白描每卡≥150字含对话锚/动作锚+锚点9行；首幕章纲每章叙事原子4-6个+plot锚点区齐全（Step3七查绿灯）
   - 检查不通过=停留当前Phase，向用户报告缺口
4. 更新 项目总控.html，衔接下一Phase

> 禁止派发子agent执行技能生成任务；主agent直接执行全部环节。

### Phase 5/6 写审循环

- 每次写1章（write）→ 审1章（review）。review打回→write按打回清单修改→重审
- write向前锚=本章章纲（读3章）；review沉淀白描卡+状态快照后，write续写下一章（消费近5张白描卡+快照+章纲）
- 用户说"继续写/下一步"=推进下一章循环；批量请求>8章拆批
- 本幕章白描写完 → 提示用户：plot按幕产下一幕章白描→Step2.5组装章纲（产前读状态快照吸收正文偏差）再继续写；卷一5幕全完 → plot产卷二卷纲+幕1章白描+章纲（复用同skill流程换卷）

### 异常处理

- **包缺失/配方缺表**：任何Phase发现 → 中断，提示建包或换包（「Step 1初始化」§3）
- **正文已有但无白描卡**（import残留）：调度 test-review 的 reconstruct 模式重建
- **设计文档缺失**（import残留）：对照Phase就绪检查，缺哪个补跑哪个skill

## 红线

1. **读取协议**：每次对话第一件事读项目总控.html获取当前phase→按路由表调度。禁止跳过读html直接干活。
2. **pipeline只做路由不干活**——所有产出由下游skill生成，不直接写正文/创意/审核。
3. **包准入门禁**：Phase 0必须验证包配方5表齐全，缺表=拒绝启动并提示建包。包缺失/不合格不得凭记忆或通用知识顶替。
4. **改编强度必问**：Phase 0用户输入X后必须呈现A/B/C三档让其选择（A=改演员/B=改世界观/C=全改），禁止默认。强度未定=不进入Phase 1。
5. **主agent直接执行所有环节**——执行前Read对应skill的SKILL.md全文（含其引用的执行文件），禁止派发子agent执行技能生成任务。
