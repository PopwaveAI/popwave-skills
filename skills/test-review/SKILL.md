# review

> 设定包改编·章节审核引擎。v5.0.0：新增**第0.5审 X 符合性**——按 `素材/改编计划.md` X体验层检查 X 是否深耦合（战斗/日常/剧情）+事件是否原创（禁止复用包事件），X 浮于表面或换名复用包事件=打回。

---

## 做什么

输入：`正文/ch{NNN}.txt` + `卷纲/卷一-幕N-章白描.md` 本章白描卡 + `产出/状态快照.md` + 包`包配方.md`（硬对齐达标线节）

输出：

| 产出 | consumer | 内容 |
|:--|:--|:--|
| 审核结论（对话内） | 用户 | 三审结论+达标率+打回/通过 |
| `产出/白描卡/ch{NNN}.md` | write | 事件白描/关键数据🔒/爽点·钩子/人物关系变化/本章DNA执行包 |
| `产出/状态快照.md`（更新） | write | 未回收钩子台账/角色当前状态表/禁止漂移 |

---

## 怎么做（SOP骨架）

### Step 1：一次过三审 → `steps/step1-audit.md`

①配方符合性（锚点兑现/爽点密度/钩子分级，对照包配方达标线）→ **②X符合性（X体验层深耦合+事件原创性，照改编计划）** → ③质量+充足性（正文质量+设定/情感充足性）→ ④沉淀双文件。打回只列清单不重写。

### Step 2：导入重建（仅import模式） → `steps/step2-reconstruct.md`

已有正文无白描卡时，按批次扫描重建白描卡+状态快照。

---

## 红线

1. **配方符合性是第0审**：白描卡兑现（白描段+锚点全落地）/爽点≥0.9章/钩子率100%——任一不达标即打回，其他审不用做。
2. **X 符合性是第0.5审**：X 浮于表面（战斗/日常/剧情耦合未落地）或换名复用包事件=打回，**改编引擎专属**。
3. **沉淀双文件必落盘**：白描卡+状态快照是write续写的唯一状态源，缺=write断粮。
4. **review不重写正文**：只诊断+打回清单，修改由write执行。
5. **单章≤8章切片**：批量审核时超8章强制拆批。
