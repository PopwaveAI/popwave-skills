# review

> 设定包改编·章节审核引擎。v7.0.0：steps 两件全合入单文件精炼；执行模式明确——三审纯只读审计可派子agent，沉淀双文件落盘归主agent。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 做什么

输入：`正文/ch{NNN}.txt` + `卷纲/卷一-幕N-章白描.md` 本章白描卡 + `产出/状态快照.md` + 包`包配方.md`（硬对齐达标线节）

输出：

| 产出 | consumer | 内容 |
|:--|:--|:--|
| 审核结论（对话内） | 用户 | 三审结论+达标率+打回/通过 |
| `产出/白描卡/ch{NNN}.md` | write | 事件白描/关键数据🔒/爽点·钩子/人物关系变化/本章DNA执行包 |
| `产出/状态快照.md`（更新） | write | 未回收钩子台账/角色当前状态表/禁止漂移 |

**执行模式**：子agent审计+主agent落盘——第0/0.5/1审是纯只读审计（读正文/白描卡/状态快照/包配方/改编计划→对照判定），可派子agent（verification）执行并回报三审报告；第2审沉淀双文件由主agent落盘。reconstruct模式逐章扫描/快速提取同理可派子agent，状态快照汇总与落盘归主agent。主agent直执全流程同样合法。

## 怎么做（SOP全内联）

### Step 1：一次过三审

输入：`正文/ch{NNN}.txt`、`卷纲/卷一-幕N-章白描.md`本章白描卡、`产出/状态快照.md`、包`包配方.md`（硬对齐达标线节+表2/表4）、`素材/改编计划.md`（X体验层）。

**第0审·配方符合性（不达标直接打回，后续审不做）**——对照本章白描卡+包配方逐项打钩：

| 检查项 | 达标线 |
|:--|:--|
| 白描卡兑现 | 白描段（场景/事件/对话锚/动作锚/情绪转折/钩子落点）+锚点（爽点/POV/X耦合/关键数据🔒）全兑现，缺任一=打回 |
| 爽点密度 | ≥0.9/章（本章锚点标注的爽感公式必须落地且有爆发感） |
| 章末钩子 | 100%有钩+分级标注正确（L1-L5） |
| 节奏物理量 | 蓄力≤2段、大爽点前有压力铺垫、事件密度达标 |
| 偏离项 | PRD配方继承表标⚠️的参数按X取值放行，其余按包 |

达标率<90% → 打回清单（缺什么+怎么改）交write，流程结束。

**第0.5审·X符合性（改编引擎专属，不达标打回）**——对照`素材/改编计划.md`X体验层逐项检查本章X是否深耦合：

| 检查项 | 达标线 |
|:--|:--|
| X战斗耦合（战斗章） | 本章战斗是否用X独特方式（如心灵窃取=偷招式/植入假记忆/读心预判），禁止写成包式打斗 |
| X日常耦合（日常/过渡章） | X在日常的表现与代价（如读心社交困境/窃忆道德代价/灵能侵蚀）是否落地 |
| X剧情耦合（剧情推进章） | X与主线耦合点（如身份危机/被夺舍恐惧/记忆真伪）是否推进 |
| X参与度 | X必须参与动作/对话/决策，不能只是背景设定提及 |
| 事件原创性 | 本章核心事件是否从X核心张力重推，禁止复用包事件（换名复用=打回） |

X浮于表面或复用包事件 → 打回清单交write，流程结束。

**第1审·质量与充足性（合并快审）**：①状态连续性——关键数据🔒/禁止漂移清单逐条比对（人名/数值/已死角色/已废设定），写错=bug打回②钩子台账——未到期钩子是否被提前吞并③正文质量——代入感（活人感/熟悉感）/画面感/对白指纹/类型味（对照类型风味基线）/微观技法落地④充足性——设定引用是否够（该用的设定没用=单薄）/情感线是否欠账⑤字数——2000-2500字区间。

**第2审·沉淀双文件（通过后必落盘）**：

白描卡`产出/白描卡/ch{NNN}.md`（模板`templates/ch{NNN}.tpl.md`）：

```markdown
## 事件白描（叙事流，300-500字）
## 关键数据🔒（人名/数值/不可改事实）
## 爽点·钩子（已兑现爽点公式+新埋钩子+分级）
## 人物关系变化
## 本章DNA执行包（章型卡/笔触目标/章内套路——write下一章消费）
```

状态快照`产出/状态快照.md`（模板`templates/产出/状态快照.tpl.md`，增量更新）：未回收钩子台账（+本章新钩-已回收钩，标预期回收章）/角色当前状态表（立场/位置/关系增量）/禁止漂移（新死亡角色/新废设定/新硬事实追加）。

**产出**：对话内输出三审结论（配方达标率/质量评级/通过或打回清单）+双文件路径。打回只列清单不重写。批量审核>8章拆批执行。

### Step 2：导入重建（reconstruct，仅import/续写模式）

触发：pipeline导入模式0f调度，或用户说"回溯审核""批量审稿"。目标：对已有正文逐章回溯审核，生成逐章白描卡+状态快照，为续写提供状态基础。与正常review的区别：输入是多章正文（采样）+已有设定文件；审核为简化版（跳过"要求用户修改"，只做信息提取+沉淀）；产出逐章白描卡+状态快照生成（审核结论对话内输出）；落盘必须formal（为续写提供基础）。

**采样策略**：

| 章数 | 采样策略 |
|:--|:--|
| ≤10章 | 全部逐章审核（章数少，全审保证质量） |
| 11-30章 | 最近5章全审+其余每5章取1章采样 |
| >30章 | 最近5章全审+第一章+每10章取1章采样 |

采样章节做完整审核（信息提取+正向符合性简化+正文质量简化）并为每章建白描卡；非采样章节只快速提取关键信息（角色状态/设定/伏笔/章末钩子）汇聚进状态快照。

**执行步骤**：

1. **读取已有正文**：LS扫描`正文/`目录获取章节文件列表，确定最大章节号，按采样策略确定审核范围。
2. **读取已有设定文件（按需，不存在跳过对应检查不阻塞流程）**：`设计/力量体系.md`（力量体系一致性）/`设计/金手指.md`（主角行为与金手指限制一致性）/`设计/角色库/角色库.md`（角色一致性）/`设计/全书设定/`10个最小闭环文件（世界观一致性）/`素材/文风锚定.md`（笔触DNA一致性）/`卷纲/卷一-幕N-章白描.md`（剧情符合性）。
3. **逐章审核（采样章节，简化版）**：
   - **信息提取（每章必做）**：核心事件（2-3句概括）/角色状态变化（位置/能力/资产/心态/关系）/新揭示的设定规则/新登场角色/章末钩子/伏笔埋设与回收。
   - **正向符合性（简化）**：主角动作闭环（压力→判断→动作→反馈）✓/✗；越级不付代价✓/✗；金手指规则违反✓/✗。不检查与施工卡对照（导入模式可能无施工卡）。
   - **正文质量（简化）**：AI味检测（15项patterns+高疲劳词3级+结构性4项，每项检出给具体位置）+字数检查。不做好看度4问（回溯审核只提取信息，不做主观评价）。
   - **产出白描卡**：每章一张`产出/白描卡/ch{NNN}.md`（模板`templates/ch{NNN}.tpl.md`，~300-500字）——事件白描（3-5句）+关键数据+爽点·钩子（含信息差类型）+人物关系变化（可选）。审核结论对话内输出不落盘，格式：

```markdown
# 审核-chNNN（reconstruct）
## 一、信息提取（核心事件/角色状态变化/新揭示设定/新登场角色/章末钩子/伏笔埋设回收）
## 二、正向符合性（简化）（动作闭环/越级不付代价/金手指规则 ✓✗）
## 三、正文质量（简化）（AI味问题项+位置 / 字数）
## 四、来源标记（审核模式：reconstruct / 采样类型：全审/采样/快速提取）
```

4. **汇总生成状态快照**：参照`templates/产出/状态快照.tpl.md`生成`产出/状态快照.md`（replace模式，覆盖旧版），开头标注"本快照由批量回溯审核生成，采样章节已完整审核，非采样章节仅提取关键信息"。续写锚点：write读近5张白描卡（场景连续性）+状态快照（钩子/角色/禁止漂移）即可续写。
5. **落盘后检查**：所有采样章节白描卡已落盘｜状态快照已生成（含钩子台账/角色状态/禁止漂移）｜未产出任何旧文档（审核报告/剧情累计卡/current-state/小说快照/review-沉淀/压缩归档）。

**回复**：本次采用skill（reconstruct模式）+execution.mode（formal）+回溯审核完成（审核范围ch001~ch{N}与策略/采样章数X章全审+Y章快速提取/产出N张白描卡+状态快照）+总体质量判断（可用/需修改/问题较多）+主要问题1-3条+下一步（建议执行test-write续写第{N+1}章）。reconstruct是独立模式，完成后回到pipeline路由。

## 红线

1. **配方符合性是第0审**：白描卡兑现（白描段+锚点全落地）/爽点≥0.9章/钩子率100%——任一不达标即打回，其他审不用做。
2. **X 符合性是第0.5审**：X 浮于表面（战斗/日常/剧情耦合未落地）或换名复用包事件=打回，**改编引擎专属**。
3. **沉淀双文件必落盘**：白描卡+状态快照是write续写的唯一状态源，缺=write断粮。
4. **review不重写正文**：只诊断+打回清单，修改由write执行。
5. **单章≤8章切片**：批量审核时超8章强制拆批。
