# write

> 设定包改编·正文写作引擎。v8.0.0：steps 两件全合入单文件精炼；执行模式明确——主agent直执写作+落盘（harness子agent通道为审查型无法落盘），输入缺口审查可派子agent。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

---

## 做什么

输入：本章章纲（3章）+ 近5张白描卡 + 状态快照 + 文风DNA + 设定库精选注入（每章≤3维度≤1500字）+ X体验层

输出：`正文/ch{NNN}.txt`（2000-2500字/章）+ 创作记录

**硬约束链**：本章章纲🔒（叙事原子序列+事件串+出线口+plot锚点区）→ 白描卡/状态快照🔒（过去事实+禁止漂移）→ DNA约束（3-5条笔触）→ 类型声明（防风味漂移）

**执行模式**：主agent直执写作+落盘——当前harness子agent通道为审查型（purpose枚举只verification/research/critique/implementation-check，harness自动注入只读约束，子agent无法落盘，参照起点write v4.2.2实测口径）；Step 1的输入完备性缺口审查/章纲事实vs状态快照冲突比对可派子agent（verification）只读审计回报，主agent据此判execution.mode并渲染落盘。

---

## 怎么操作（SOP全内联）

### Step 1：消费输入（抽取本章写作包）

按优先级消费5类基础输入+DNA条件输入，缺一项记入缺口：

**①用户本轮要求（最优先）**：覆盖以下各类默认取值（如"把第3章重写得更狠/续写下一章/开篇样章"）。明确：把X写成Y/当前章位/续写或重写/特殊约束。用户要求与状态快照冲突时以用户要求为准，但必须在创作记录里标注冲突。

**②近5张白描卡（全量读，场景连续性锚）**：`产出/白描卡/ch{NNN-5}~ch{NNN-1}.md`（review产出，~300-500字/张，read_policy=full-required，不得用摘要替代）。抽取：`## 事件白描`（叙事流回溯锚，正文不得与其已确立事实矛盾）/`## 关键数据`（🔒不可改事实，写错=bug）/`## 爽点·钩子`（已兑现爽点+已埋钩子，续写接应）/`## 人物关系变化`（写互动对齐）。

**③状态快照（全量读，跨章状态锚）**：`产出/状态快照.md`（read_policy=full-required）。抽取：`## 未回收钩子台账`（遵守预期回收，不提前吞并未到期钩子）/`## 角色当前状态表`（主角/配角当前立场，对话互动不漂移）/`## 禁止漂移`（人名/数值/已死角色/已废设定硬清单，写错=bug）。

**④章纲（读3章，向前锚）**：`卷纲/章纲/ch{NNN}-章纲.md`（plot Step2.5产出，每章一文件，read_policy=3-segments）。只读**前1+本章+后1**三份（本章为项目首章时读本章+后2章；后1章未产出时读前2+本章）。每份含：章型/剧情梗概/章节目的+**叙事原子序列**（4-6原子，每原子使命+内部事件串+出线口）+线账本+**plot锚点区**（锚点9行直拷——爽点/章末钩子/POV/X耦合/关键数据🔒/出场人物/本章线动作/出章面板）。**向前推进（下一章写什么）由本章章纲决定**：

- 叙事原子序列=结构骨架：4-6原子按序渲染一个不丢，每原子内部事件串的料逐条落地
- 出线口=线状态达成：每原子渲染完，其线状态变化须在正文中可见
- 线账本=跨章连续性：本章末各线状态（悬/收）与后1章线账本起点衔接
- plot锚点区=plot锁定信息：🔒锚全兑现（爽点落点/章末钩子L级/POV/关键数据/出章面板硬锚）
- 前1章章纲=衔接校验（开头接得上）；后1章章纲=钩子指向校验（章末钩往后1章核心事件对）
- 章纲事件串未覆盖的细节（对白原文/环境描写/过场）是write的发挥空间，但不得与章纲及plot锚点区确立的事实矛盾

**事实冲突处理**：章纲事实性字段（年龄/等级术语/人名）与状态快照/近5章正文冲突时，**以状态快照为准**，写作包"冲突标注"记录——禁止把章纲事实错误写进正文。本章章纲缺失（plot未组装到本章）=缺口，走缺口处理。

**⑤最近正文（按需读）**：`正文/ch{NNN-1}.txt`或用户指定锚定正文（full-if-targeted）。场景连续性由近5张白描卡承担；需更细原文细节（对话原文/具体描写）按需读目标文件，不得凭对话历史替代。

**⑥文风DNA输入（存在时必读）**：DNA源=`素材/文风锚定.md`（项目指定）或`KB/文风DNA/`（内置兜底）。触发条件（任一满足即启用）：`素材/文风锚定.md`存在（续写模式适用）/上一章白描卡存在`## 本章DNA执行包`（正向模式review产出）/用户本轮明确要求某文风DNA。**缺失态**（以上均不存在）：必须从`KB/文风DNA/`按`立项/01-立项PRD.md`赛道标签选一个内置兜底（深渊主宰=西幻/夜无疆=玄幻修仙/诡秘之主=西幻诡秘流/捞尸人=民俗恐怖/东京医途=都市），加载其通用维度+对应场景卡，**必须选一个，禁止跳过DNA直接写作**；执行报告标注"兜底文风：{书名}"；trial模式由用户声明风格。读取规则：上一章白描卡有执行包时优先按执行包加载（本章章型卡/笔触目标/章内套路）；无执行包时按本章章型加载对应场景卡+通用维度；DNA源过大时只读目录/对应章型卡/章内笔触/单章套路/角色口癖隔离，不要把整份DNA当剧情事实库。

**禁止默认读取**（index-only/full-if-targeted）：`立项/01-立项PRD.md`（仅缺口处理时按需）/`设计/全书设定/`（按下方注入表按需）/`卷纲/卷一-卷纲.md`（战略层plot自留，幕级信息已沉淀进章白描卡幕头）/未被执行包、文风锚定或已选定兜底指向的其他DNA文件。仅当用户明确指定或处理缺口时可读，且必须在创作记录"已读输入"里如实标注。

**设定库精选注入（每章≤3维度≤1500字，按章型按需）**：world产出11个最小闭环文件，write按章型按需读取对应文件，禁止全文注入。每维度≤500字。

注入规则：角色库+类型风味基线必选，再按章型选≤1个；每文件只提取本章相关段落（≤500字）不全文注入；提取内容写入写作包"设定状态"字段；读注入表外文件必须在创作记录"已读输入"里如实标注原因。

**X体验层注入（改编引擎，每章按章型）**：从`素材/改编计划.md`的X体验层按章型注入，确保X深耦合进正文不浮于表面——战斗章（combat_reversal/confrontation_pressure）注X战斗耦合（如心灵窃取=偷敌人招式/植入假记忆/读心预判，禁止写成包式打斗）；日常/过渡章（exploration_gain）注X日常耦合（如读心社交困境/窃忆道德代价/灵能侵蚀）；剧情推进章（reveal_hook/high_tier_display）注X剧情耦合（如身份危机/被夺舍恐惧/记忆真伪）。每章至少注入1处对应X耦合写入写作包"X体验层"字段；`素材/改编计划.md`缺失时标注缺口，不自行编造X耦合；自检：正文中X必须参与动作/对话/决策，不能只是背景设定提及。

**缺口处理**：近5张白描卡/状态快照明显缺关键事实时——不自行翻库补写；停止并要求先执行test-review产出本章白描卡/更新状态快照；用户要求继续试写则execution.mode降为draft或trial。

```markdown
## 本章写作包
execution.mode:
- 把 X 写成 Y：
- 当前章位：
- 上一章白描：（从上一章白描卡引用叙事流，续写不得与之矛盾）
- 钩子台账：（从状态快照，本章可回收/不可提前吞并）
- 角色当前状态：（从状态快照，主角/配角当前立场）
- 读者已知信息池：（从状态快照钩子台账的信息差类型，写信息不穿帮）
- 关键数据🔒：（从上一章白描卡，写错=bug）
- 本章章纲：（叙事原子序列+线账本+plot锚点区要点，向前推进的唯一来源；原子数/线数/逐锚清单记入创作记录）
- 后1章章纲：（钩子指向校验用，仅记章末线状态+核心事件一行）
- 可用燃料：
- 用户本轮新增要求：
- 类型声明：（从类型风味基线.md注入——当前作品类型+保持什么味+禁止漂移到哪，写作全程锚定此声明，杜绝类型味漂移）
- X体验层：（从素材/改编计划.md按章型注入——本章X战斗/日常/剧情耦合1处，X必须参与动作/对话/决策）
- DNA约束：（列3-5条本章实际执行的笔触约束，来自素材/文风锚定.md的通用维度+场景卡；缺失态来自KB/文风DNA/选定兜底的通用维度+场景卡）
- 文风DNA执行：（未启用填"未启用"；启用时列DNA源、模式、章型、笔触目标、章内套路、可见反馈、禁止误用；缺失态兜底标注"兜底文风：{书名}"）
- 对话锚点：（从角色库或状态快照角色状态表提取本章有对话角色的语言指纹——句式偏好/用词偏好/对话标志2个。本章无对话填"本章无对话"）
```

**写作包硬约束**：`本章章纲`是向前推进的硬约束（叙事原子+事件串+出线口+plot锚点区全兑现）；`关键数据🔒`/`角色当前状态`不得违反（状态快照禁止漂移）；`钩子台账`未到期钩子不得提前吞并；`DNA约束`必须3-5条且正文里能看出来；`文风DNA执行`必须来自上一章白描卡执行包（若有）或`素材/文风锚定.md`（无执行包时）或KB选定兜底（缺失态）——不得临场把整本参考小说的特殊桥段当通用规则。

**execution.mode判定**：formal=上一章白描卡+状态快照+本章章纲（3章读取完成：前1+本章+后1）+最近正文+用户要求齐全且达标（`素材/文风锚定.md`存在则DNA源也齐全；缺失态已从KB选定兜底）；draft=必读输入有缺口但用户要求继续；trial=快速试做，不落盘。**缺本章章纲/状态快照不得标formal**。

**门禁（进入Step 2前）**：本章写作包已抽取完整｜execution.mode已判定｜章纲3章读取完成、叙事原子序列+线账本+plot锚点区已锁定（向前唯一来源）｜上一章白描/钩子台账/角色状态/关键数据已从近5张白描卡+状态快照引用｜章纲事实冲突已比对状态快照（冲突项以状态快照为准并已记入冲突标注）｜类型声明已从类型风味基线.md注入（类型+保持什么味+禁止漂移到哪）｜DNA约束3-5条已选定｜如启用文风DNA，已锁定章型/笔触目标/章内套路/可见反馈/禁止误用｜对话锚点已提取（本章有对话的角色及语言指纹参数）或已确认"本章无对话"｜缺口已记录或已要求plot组装/review修复。

### Step 2：渲染正文+落盘+创作记录

按叙事原子序列渲染2000-2500字：逐原子兑现内部事件串（料全落）+出线口达成+plot锚点区🔒兑现+17微观技法+章末钩子分级落章+创作记录落盘。

**正文规则**：

- 开场120字内出现目标、异常、压力、反馈或主动动作之一。
- 主角至少完成一次动作闭环：压力/诱因→判断→主动动作→阻碍升级→可见反馈→收益/损失→新压力。
- **本章章纲必兑现**：叙事原子序列按序渲染（4-6原子一个不丢，原子间自然过渡不生硬跳切）；每原子内部事件串的料逐条落地；每原子出线口达成（线状态变化在正文可见）；plot锚点区🔒全兑现（爽点/章末钩子L级/POV/X耦合/关键数据/出章面板硬锚）。不能只铺氛围。
- **事件串物理缝合**：章纲事件串只锁结果不锁时序时，write负责补齐物理链（谁的手/什么时机/物件从哪来），补的拍服从前后因果——章纲有物理洞（如物件凭空出现）=补缝合拍并在创作记录标注，不得写出物理断裂。
- **事实冲突以状态快照为准**：章纲年龄/等级术语/人名与状态快照/近5章正文冲突时，以状态快照为准+创作记录"冲突标注"。
- 可用燃料必须落到动作、物件、权限、组织反应、技术细节、钱、身份或信息差里。
- 关键爽点必须外显（旁人反应、资源变化、局势翻转、敌人误判等），不能只由作者总结"他赢了/他变强了"。
- 不提前吞并状态快照未回收钩子台账里未到期的钩子。
- 结尾必须留下主动钩子或威胁逼近，不用自然停顿收尾；章末钩=章纲线账本章末翻转态。
- 判定链/系统数值一律自然段内联呈现（【】格式），禁弹窗式/代码块。

**DNA落地（DNA约束+文风DNA执行——不是事后润色，而是参与本章生成）**，选定的约束必须能从正文里看出来：

| DNA项 | 在正文中的体现 |
|:--|:--|
| 笔触目标 | 叙事距离、句式、段落呼吸、感官顺序、对话引导方式 |
| 主角主动方式 | 主角必须做出选择或动作 |
| 爽点外显方式 | 旁人反应、资源变化、局势翻转、敌人误判 |
| 叙事人格 | 旁白站位和判断顺序 |
| 句子气口 | 长短句、独句段、信息先后 |
| 信息释放 | 先给结果还是先给过程，哪些暂不解释 |
| 章内套路 | 起笔、第一信息变化、压力/诱因、主角动作或判断、阻碍升级、可见反馈、章末钩 |
| 可见反馈 | 敌人失态、旁观者改判、资源/信息变化、组织/权限变化、威胁逼近 |

执行要求：每个启用的章型至少改变一处"章内展开方式"，不能只替换形容词；每章必须有≥1条可见反馈；强嫁接只迁移章内套路和笔触手感，不迁移原作专有名词、设定词、角色口癖；禁止把DNA源中的开篇专用机制、特殊高光章、丑角台词当全书通用逻辑。

**对话落地**（写作包"对话锚点"必须落地到正文对话）：

| 对话锚点项 | 在正文中的体现 |
|:--|:--|
| 句式偏好 | 该角色说话的句式长度/类型与锚点一致（锚点说"短句为主"→不写长句） |
| 用词偏好 | 该角色用词层级与锚点一致（锚点说"市井方言"→不写书面语） |
| 对话标志 | 该角色的2个对话标志至少在对话中体现1个 |

执行要求：有对话的章节，每个有台词的角色必须从对话锚点取语言参数，不凭记忆/直觉写对话；对话锚点缺失（状态快照角色状态表未提取）时从`设计/角色库/角色库.md`按需读取该角色语言指纹；角色库也没有时标注缺口并在创作记录里声明，不自行编造语言风格。**write负责"对话内容对+角色语言指纹对"，review负责"对话质量好不好看"**——write保证信息密度够、功能复合、角色没OOC；潜台词层次、节奏精修、动作插入质量由review按对话六要素检查后给修正方向；write写完即落盘，不自行反复打磨对话。

**落盘**：正文写入`正文/ch{NNN}.txt`——路径固定为`正文/`，不得写到项目根或其他目录；文件名固定`ch{NNN}.txt`（NNN为3位数字章节号），不得自创别名；对话只回摘要、钩子和创作记录，不把正文全文放进对话；trial模式不落盘，仅对话内。

**验收门禁**（落盘后必须跑，查文件系统不信口头）：

| 项 | 验收方式 |
|:--|:--|
| 正文存在 | `正文/ch{NNN}.txt` 存在 |
| **汉字字数达标** | exec 跑 `scripts/word-count.ps1 -Path 正文/ch{NNN}.txt`；脚本统计**纯汉字**（[\u4e00-\u9fff]，不含标点/空格/英文/数字/markdown标记），判定区间 2000-2500 汉字；**脚本 stdout 原文一行必须完整贴进创作记录**，判定以脚本输出为准——禁转述、禁心算、禁引用生成侧统计 |
| 创作记录 | `templates/chapter-record.tpl.md` 格式填写完整 |

脚本路径解析：skill 安装目录下 `scripts/word-count.ps1`；脚本不存在或执行失败时回退 PowerShell 内联统计，仍须贴实测命令输出原文。FAIL → 修补正文后重跑，重跑输出覆盖前次记录。

**新增事实处理**：write不在write内维护任何库文件（角色库/全书设定/卷纲/状态快照）。写作过程中产生的新增事实、人物变化、设定变化：只在对话创作记录里列"新增事实待review"清单（声明），不落盘到任何库文件，由后续test-review读取本章正文+创作记录后决定是否落库——write只声明，不落库（消解"write无库读取权却要判断新增"的矛盾）。

**回复**（模板`templates/chapter-record.tpl.md`）：必填——本次采用skill：test-write / execution.mode / 第N章-{标题}已写入{文件名} / 摘要 / 章末钩子 / 创作记录（已读输入、兑现的白描卡锚点、使用的燃料、执行的DNA约束、执行的文风DNA约束、新增事实待review清单、下一步建议执行review）。

**下一步（硬后继）**：正文落盘并回复后**必须执行test-review**——review是write的硬后继，未执行review不得写下一章；review负责四维审核+产出本章白描卡+更新状态快照（跨章聚合）；write只在创作记录中声明"新增事实待review"清单，不自行落盘任何库文件；pipeline Phase 5完成后自动路由到Phase 6 review，agent不得跳过。

## 红线

1. **章纲必兑现**：叙事原子序列按序渲染（4-6原子一个不丢）；每原子内部事件串逐条落地、出线口达成；plot锚点区爽点/POV/X耦合/关键数据🔒/出章面板任一缺失=不符合plot设计，review打回。
2. **事实冲突以状态快照为准**：章纲事实性字段（年龄/等级术语/人名）与状态快照/近5章正文冲突时，以状态快照为准，创作记录"冲突标注"里记冲突——章纲事实错误不经write放大传染。
3. **状态连续性**：关键数据🔒/禁止漂移清单写错=bug；未到期钩子不得提前吞并。
4. **每章爽点≥1**：爽感公式必须落地且有爆发感；连续2章无爽点=不合格。
5. **DNA不跳过**：文风DNA缺失时必须选KB兜底，禁止裸写。
6. **字数门禁**：正文落盘后必须跑 `scripts/word-count.ps1` 统计纯汉字，2000-2500 汉字为合格；脚本 stdout 原文贴进创作记录，禁用模型自报字数。FAIL 修补后重跑。
