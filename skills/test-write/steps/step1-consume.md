# Step 1：消费输入

本步骤消费 write 的 5 类基础输入，并在项目启用文风DNA时消费本章DNA执行包，抽取本章写作包。引用 PRD §4.1（骨架）、§4.2（owner/read_policy）、§4.5（execution.mode）。

## 1. 必读输入（5 类基础输入 + DNA 条件输入）

按优先级消费，缺一项记入缺口：

### 1.1 用户本轮要求（优先）

用户本轮口头/文字要求是最优先输入，覆盖以下三类的默认取值。例如"把第 3 章重写得更狠"、"续写下一章"、"开篇样章"。

- 明确：把 X 写成 Y / 当前章位 / 续写或重写 / 特殊约束。
- 若用户要求与状态快照冲突，以用户要求为准，但必须在创作记录里标注冲突。

### 1.2 近5张白描卡（全量读，场景连续性锚）

路径：`产出/白描卡/ch{NNN-5}~ch{NNN-1}.md`（review 产出，单章历史，~300-500字/张）。read_policy = full-required（近5张）。

必须全量读取，不得用摘要替代。抽取"过去发生了什么"（近5章场景连续性）：
- `## 事件白描`：叙事流回溯锚，写正文时不得与其中已确立事实矛盾。
- `## 关键数据`：🔒 不可改事实，写错=bug。
- `## 爽点·钩子`：各章已兑现的爽点 + 已埋钩子，续写要接应。
- `## 人物关系变化`：近5章角色关系变化，写互动对齐。

### 1.2b 状态快照（全量读，跨章状态锚）

路径：`产出/状态快照.md`（review 产出，跨章状态聚合）。read_policy = full-required。

必须全量读取，抽取"当前状态"：
- `## 未回收钩子台账`：写本章时遵守预期回收，不提前吞并未到期钩子。
- `## 角色当前状态表`：主角/配角当前立场，写对话和互动时对齐，不漂移。
- `## 禁止漂移`：不可改事实硬清单（人名/数值/已死角色/已废设定），写错=bug。

### 1.3 章白描（读3段，向前锚）

路径：`卷纲/卷一-幕N-章白描.md`（plot产出，N=本章所属幕）。read_policy = 3-segments。

**读法**：打开本章所属幕文件，只消费**前1章+本章+后1章**三张白描卡（本章为幕首章时读本章+后2章；幕末章时读前2章+本章）。每卡含150-250字叙事白描（画面/事件/对话锚/情绪转折/钩子落点）+锚点6行。

**向前推进（下一章写什么）由本章白描卡决定**：
- 白描段=本章剧情的全部信息——场景、事件推进、对话锚/动作锚直接落笔，情绪转折与钩子落点必须兑现
- 锚点段：爽点🔒（公式类型+落点）+章末钩子🔒（L级）+POV+X耦合（1处参与动作/对话/决策）+关键数据🔒（写错=bug）
- 前1章卡=衔接校验（开头接得上）；后1章卡=钩子指向校验（章末钩子往后1章的核心事件对）
- 白描卡未覆盖的细节（具体对白/环境描写/过场）是write的发挥空间，但不得与白描段确立的事实矛盾

本章卡缺失（plot未产到本章）=缺口，走§4缺口处理。

### 1.4 最近正文（按需读）

路径：`正文/ch{NNN-1}.txt`（上一章）或用户指定锚定正文。read_policy = full-if-targeted。

场景连续性由近5张白描卡承担；如需更细的原文细节（对话原文/具体描写），按需读目标正文文件，不得凭对话历史替代。

### 1.5 文风DNA输入（存在时必读）

**DNA源文件**：`素材/文风锚定.md`（项目指定）或 `KB/文风DNA/`（内置兜底）

触发条件（任一满足即启用DNA）：

- `素材/文风锚定.md` 存在（最简路径，续写模式适用）。
- `产出/白描卡/ch{NNN-1}.md` 存在 `## 本章DNA执行包`（正向模式review产出）。
- 用户本轮明确要求使用某个文风DNA。
- **缺失态**：以上均不存在时，**必须从 `KB/文风DNA/` 选一个内置兜底文风DNA**（按项目赛道/题材匹配），不得跳过DNA直接写作。

读取规则：

- **优先级**：若上一章白描卡存在 `## 本章DNA执行包`，优先按执行包加载（执行包指定了本章章型卡、笔触目标、章内套路）。
- **无执行包时**（续写模式或review未产出执行包）：直接从 `素材/文风锚定.md` 按本章章型加载对应场景卡 + 通用维度。按需读取与本章章型相关的场景卡、笔触约束、章内套路、角色/口癖隔离；不要把整份 DNA 当剧情事实库。
- 如果 DNA 源过大，只读取目录、对应章型卡、章内笔触、单章套路、角色/口癖隔离。
- **缺失态兜底**：`素材/文风锚定.md` 不存在时，从 `KB/文风DNA/` 选一个内置兜底文风DNA（深渊主宰=西幻/夜无疆=玄幻修仙/诡秘之主=西幻诡秘流/捞尸人=民俗恐怖/东京医途=都市），按`立项/01-立项PRD.md`赛道标签匹配，加载其通用维度+对应场景卡。**必须选一个，禁止跳过DNA。** 执行报告标注"兜底文风：{书名}"。trial模式由用户声明风格，执行报告标注。

## 2. 禁止默认读取

以下文件 read_policy 为 index-only 或 full-if-targeted，write 不得默认读取：

- `立项/01-立项PRD.md`（立项定型快照，仅缺口处理时按需读取）
- `设计/全书设定/`（11个最小闭环文件，按设定库精选注入规则按需读取——见下方注入表）
- `卷纲/卷一-卷纲.md`（战略层，plot自留；write不读——幕级信息已沉淀进章白描卡幕头）
- 未被 `本章DNA执行包`、`素材/文风锚定.md` 或 `KB/文风DNA/`（已选定的兜底）指向的其他文风DNA文件

仅当用户明确指定或处理缺口时才可读取，且必须在创作记录"已读输入"里如实标注。

### 3.3 注入规则

- 角色库+类型风味基线必选（每章），再从按章型表选≤1个文件
- 每个文件只提取本章相关段落（≤500字），不全文注入
- 提取内容写入本章写作包的"设定状态"字段
- 如本章需读取设定库精选注入表外的文件，必须在创作记录"已读输入"里如实标注原因

### 3.4 X 体验层注入（改编引擎，每章按章型）

> 改编引擎专属：从 `素材/改编计划.md` 的 X 体验层（战斗/日常/剧情耦合）按章型注入，确保 X 深耦合进正文，不浮于表面。

| 章型 | 注入 X 体验层 |
|:--|:--|
| **战斗章**（combae_reversal/confroneaeion_pressure） | X战斗耦合——如心灵窃取=偷敌人招式/植入假记忆/读心预判，禁止写成包式打斗 |
| **日常/过渡章**（exploraeion_gain） | X日常耦合——如读心社交困境/窃忆道德代价/灵能侵蚀 |
| **剧情推进章**（reveal_hook/high_eier_display） | X剧情耦合——如身份危机/被夺舍恐惧/记忆真伪 |

- 每章至少注入 1 处对应 X 耦合，写入本章写作包"X体验层"字段
- `素材/改编计划.md` 缺失时标注缺口，不自行编造 X 耦合
- X 耦合自检：正文中 X 必须参与动作/对话/决策，不能只是背景设定提及

## 4. 缺口处理

如果近5张白描卡/状态快照明显缺关键事实：

- 不自行翻库补写。
- 停止并要求先执行 test-review 产出本章白描卡/更新状态快照。
- 若用户要求继续试写，execution.mode 降为 draft 或 trial。

## 5. 抽取本章写作包

从 4 类输入抽取，不扩展成章纲表：

```markdown
## 本章写作包
execution.mode:
- 把 X 写成 Y：
- 当前章位：
- 上一章白描：（从上一章白描卡引用叙事流，续写不得与之矛盾）
- 钩子台账：（从状态快照，本章可回收/不可提前吞并）
- 角色当前状态：（从状态快照，主角/配角当前立场）
- 读者已知信息池：（从状态快照钩子台账的信息差类型，写信息不穿帮）
- 关键数据🔒：（从上一章白描卡，写错=bug）
- 本章白描卡：（白描段全文引用+锚点6行，向前推进的唯一来源）
- 后1章白描卡：（钩子指向校验用，仅记核心事件一行）
- 可用燃料：
- 用户本轮新增要求：
- 类型声明：（从类型风味基线.md注入——当前作品类型+保持什么味+禁止漂移到哪，写作全程锚定此声明，杜绝类型味漂移）
- X体验层：（从素材/改编计划.md按章型注入——本章X战斗/日常/剧情耦合1处，X必须参与动作/对话/决策）
- DNA约束：（列 3-5 条本章实际执行的笔触约束，来自素材/文风锚定.md的通用维度+场景卡；缺失态来自 KB/文风DNA/ 选定兜底的通用维度+场景卡）
- 文风DNA执行：（未启用填"未启用"；启用时列 DNA源、模式、章型、笔触目标、章内套路、可见反馈、禁止误用；缺失态兜底标注"兜底文风：{书名}"）
- 对话锚点：（从角色库或状态快照角色状态表提取本章有对话角色的语言指纹——句式偏好/用词偏好/对话标志2个。本章无对话填"本章无对话"）
```

- `本章白描卡` 是向前推进的硬约束：白描段的场景/事件/对话锚/动作锚/情绪转折/钩子落点必须兑现，锚点段的爽点/POV/X耦合/关键数据🔒必须落地。
- `关键数据🔒`/`角色当前状态` 不得违反（状态快照禁止漂移）。
- `钩子台账` 里未到期的钩子不得提前吞并。
- `DNA约束` 必须列 3-5 条，且正文里能看出来。来源为 `素材/文风锚定.md` 的通用维度和对应场景卡；缺失态来源为 `KB/文风DNA/` 选定兜底的通用维度和对应场景卡。
- `文风DNA执行` 必须来自上一章白描卡的本章DNA执行包（若有）或直接从 `素材/文风锚定.md` 提取（无执行包时）；缺失态从 `KB/文风DNA/` 选定兜底提取；不得临场把整本参考小说的特殊桥段当通用规则。

## 6. execution.mode 判定

- formal：上一章白描卡 + 状态快照 + 本章白描卡（3段读取完成）+ 最近正文 + 用户要求 齐全且达标；若 `素材/文风锚定.md` 存在，DNA源也齐全；缺失态已从 `KB/文风DNA/` 选定兜底。
- draft：必读输入有缺口但用户要求继续。
- trial：快速试做，不落盘。

缺上一章白描卡/状态快照不得标 formal。

## 7. 门禁

进入 step-2 前必须满足：

- [ ] 本章写作包已抽取完整。
- [ ] execution.mode 已判定。
- [ ] 本章白描卡3段读取完成（前1+本章+后1），白描段+锚点已锁定（向前唯一来源）。
- [ ] 上一章白描/钩子台账/角色状态/关键数据已从近5张白描卡+状态快照引用。
- [ ] 类型声明已从类型风味基线.md注入（类型+保持什么味+禁止漂移到哪）。
- [ ] DNA约束 3-5 条已选定（来源：`素材/文风锚定.md`；缺失态来源：`KB/文风DNA/` 选定兜底）。
- [ ] 如启用文风DNA，已锁定章型、笔触目标、章内套路、可见反馈和禁止误用项。
- [ ] 对话锚点已提取（本章有对话的角色及其语言指纹参数）或已确认"本章无对话"。
- [ ] 缺口已记录或已要求 review 修复。

## 8. 下一步

门禁通过后，读取 `steps/step2-write.md` 开始写正文。
