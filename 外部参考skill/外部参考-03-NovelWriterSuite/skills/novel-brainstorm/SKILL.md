# Novel Brainstorm —— 创意构思

## 功能

通过结构化对话，把用户脑里散乱的灵感收敛成 5 个可写入 `story.md` 的核心要素：

1. **一句话简介**（logline）—— 让人一句话听懂这本书在讲什么
2. **核心矛盾**（central conflict）—— 全书最大的对立
3. **30 章承诺**（first-30-chapter promise）—— 读者在前 30 章会得到的爽感 / 情绪体验 / 信息回报
4. **市场定位**（market positioning）—— 同题材爆款对照 + 读者画像 + 差异化卖点
5. **文风方向**（style direction）—— 五大类型选一（详见 `references/style-types.md`）

完成后更新 `story.md` 和 `status.md`，明确进入 worldbuilding 阶段的准备就绪状态。

## 前置条件

- vault 中必须存在 `story.md` 且 frontmatter 完整（说明已跑过 `novel-init`）
- 如果没跑过 init，先告诉用户："请先初始化项目，说'开始写小说'触发 novel-init"

## 工作流

### Step 0 - 加载现状

读取 `story.md` 看哪些部分已经填了。**已填的部分不要重新讨论**，除非用户主动要改。

### Step 1 - 收敛 logline

用一次对话收敛出"一句话简介"。不要照搬影视行业的 logline 模板（角色+目标+阻碍）——网文 / 长篇小说的 logline 更像 elevator pitch。

引导问题：
- "如果你只有一句话告诉读者这本书在讲什么，会怎么说？"
- 如果用户给的太抽象（比如"一个少年的成长故事"）→ 追问"成长成什么样？什么让这个少年特别？"
- 如果用户给的太长（超过 30 字）→ 帮他砍

**判定标准**：一句话能让一个陌生读者决定是否想看 → 合格。

### Step 2 - 锁定核心矛盾

分三类（用 `AskUserQuestion` 给选项）：
- **人 vs 人**：主角和反派 / 主角和阵营 / 主角和家庭
- **人 vs 环境**：末日 / 体制 / 自然 / 时代
- **人 vs 自己**：成长 / 救赎 / 接受 / 突破

挑出主矛盾后追问：
- "这个矛盾在第 1 章就出现，还是会铺垫一段？"
- "矛盾的终极解决会发生在哪卷？"
- "矛盾解决后，主角是变成了什么？"

### Step 3 - 设计 30 章承诺

> 这是网文最关键的概念之一。AI-NWA 把它叫"前 30 章承诺"——读者在追前 30 章时，作者向他们承诺会给到什么。
> 没有 30 章承诺 = 读者不知道为什么追下去。

引导用户写出 3-5 条"承诺"。每条要满足：
- **具体可识别**：不是"主角成长"这种空话，而是"主角第 1 章被仇人羞辱，第 10 章正式打脸"
- **可兑现节奏**：哪章前必须给到第 1 个爽点；哪章前必须给到第 1 次反转
- **悬念阶梯**：第 1 章钩子是什么，第 5 章升级悬念是什么

参考模板（写入 story.md 的 ## 30 章承诺）：

```markdown
## 30 章承诺

1. **第 1 章**：主角{身份}遭遇{核心困境}，确立"想要 X 但被 Y 阻碍"的全书母题
2. **第 5 章**：主角获得{关键能力/资源/盟友}，让读者看到"有戏"
3. **第 10 章**：第一次打脸 / 翻盘 / 报仇雪恨
4. **第 20 章**：进入新格局（升级 / 进入更高世界 / 揭开更大谜团）
5. **第 30 章**：交付第一个完整的"小目标周期"——读者得到一次完整的"被压抑→爆发"
```

### Step 4 - 市场定位

引导问题：
- "同题材里你最喜欢的 3 本书是？"（让用户列）
- "你想跟它们一样还是不一样？哪里一样，哪里不一样？"
- "你的目标读者是男性 / 女性 / 不限？年龄段？"
- "想发哪个平台？"（起点 / 番茄 / 晋江 / 知乎 / 其他 / 不发表）

**关键产出**：一个对比表，列入 story.md：

```markdown
## 题材定位

**类型**：{原 frontmatter 中的 genre + sub-genre}

**目标平台**：{platform}
**目标读者**：{画像}

**对标作品**：
- 《{book-a}》：{学这本书的什么}，{不学的什么}
- 《{book-b}》：{学什么}，{不学什么}

**差异化卖点**：
- {1-3 条本书相对对标作品独有的东西}
```

### Step 5 - 文风方向

读取 `references/style-types.md` 给用户看 5 大文风类型概览。**不要照搬完整描述**，只给名字 + 一句话 + 一个例子让用户选。

```
请从下面 5 种文风方向中选 1-2 个（可以混搭）：

A. 动词驱动型 - 短句快节奏、信息密集（参考：《大奉打更人》《诡秘之主》）
B. 克制典雅型 - 情感内敛、留白艺术、古典韵味（参考：《琅琊榜》《庆余年》）
C. 幽默吐槽型 - 内心戏丰富、现代梗、自我消解（参考：《我师兄实在太稳健了》）
D. 热血燃向型 - 金句频出、对抗性强、情绪高涨（参考：《斗破苍穹》）
E. 悬疑压抑型 - 氛围营造、信息差、层层揭秘（参考：《诡秘之主》《盗墓笔记》）
```

**重要**：选完后**不要**在这一步定义具体的文风规则（句长 / 禁用词 / 段落长度等）。那是 `novel-style-engine` 的事。这一步只锁"方向"。

把方向写入 `story.md` 的 `## 文风方向` 段：

```markdown
## 文风方向

**主方向**：{A. 动词驱动型}
**辅方向**：{C. 幽默吐槽型}（可选）

**细化方式**：投喂样本 + 运行 `novel-style-engine` 抽取具体规则
```

### Step 6 - 写回 story.md

把 Step 1-5 的产出写回 `story.md` 的对应段落。注意：

- **保留 frontmatter 完全不动**
- **如果某段已经有内容**，先和用户确认是覆盖还是合并
- **写完后给用户看一遍完整的 story.md**，让他确认或修改

### Step 7 - 更新 status.md

把 status.md 的"当前阶段"改为 `brainstorm-done`，"当前任务"改为 `等待 worldbuilding`。

### Step 8 - 给下一步建议

```
✅ 创意构思完成。story.md 已更新。

建议下一步：
1. 搭建世界观 → 说 "构建世界观" 或 "加一个地点"
2. 创建主角 → 说 "加主角" 或 "加角色"
3. 投喂文风样本（可与 1/2 并行）→ 说 "学这个文风" + 粘贴样本
4. 直接设计卷纲 → 说 "做卷纲"（建议先把世界观和主角搭起来再做）
```

## 与其他 skill 的边界

- **不创建任何 entity 文件**（不写 characters/、worldbuilding/、plot/ 下任何东西）
- **不定义具体文风规则**（句长、禁用词、段落长度等）——那是 `novel-style-engine`
- **不写卷纲、不写章纲**——那是 `novel-plot` / `novel-chapter`
- **不做市场调研的网络搜索**——v0.1 只用用户提供的信息 + LLM 已有知识

## 错误处理

- **用户跑偏到具体设定**（比如开始细说魔法体系）：礼貌打断"这个非常好，先记下来，等会儿在 worldbuilding 里展开"，把记下来的内容写到一个临时 `story.md` 末尾的 ## 待办备忘 段。
- **用户想跳过某一步**（比如不想填 30 章承诺）：可以跳，但在 story.md 对应段写 "(skipped)" 而不是留空，方便后续追溯。
- **用户每个问题都很模糊**：要给具体的二选一引导（如"那这本书的核心是'变强'还是'救赎'？"），不要无限追问。
