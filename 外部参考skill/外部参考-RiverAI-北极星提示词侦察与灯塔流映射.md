# 外部参考：River's AI 提示词侦察报告与灯塔流映射

> 侦察日期：2026-09-11
> 侦察对象：River's AI（rivereditor.com 出品，AI 桌面写作应用）
> 侦察目的：拿到 River's AI 用于长篇/系列写作的提示词，支撑 200 万字网文的北极星（灯塔流）写作法
> 结论先行：**内部 system prompt 拿不到；官方把提示词逻辑公开成了 970 篇文章 + 318 个工具页，这是"拿提示词"的正路，且已拿到最核心三篇全文。**

## 一、侦察结论：拿得到什么，拿不到什么

### 拿不到：产品内部 system prompt

- River's AI 是闭源商业应用（AI Desktop，类 Notion + AI），登录后可用，核心 system prompt 不公开。
- 全网搜索未发现社区泄露（GitHub / 论坛 / 社交媒体均无命中）。
- 不采用 prompt injection 套词：绕过产品防护不可行也不该做。

### 拿得到：官方公开的"提示词思维"

River's AI 的营销结构决定了它的提示词是半公开的：

- 资源站 rivereditor.com/resources 有 **970 篇文章 + 318 个工具页**。
- 每篇文章 = River's AI 某个功能/流程的提示词逻辑，被改写成教学文（作者 Chandler Supple）。
- 每篇文章开头都写明"River's AI helps you ..."，即该功能对应的提示词目标。
- 工具页（/tools/）只有功能描述，无 prompt 正文；文章（/guides/、/blogs/）有完整方法论与练习模板，需自己改写成 prompt。

## 二、转换逻辑：英文"Book/Series" → 网文"卷/全书"

River's AI 的系列方法论是为"多本书"设计的。200 万字网文天然是多卷结构，映射规则：

| River's AI 概念 | 网文对应 | 说明 |
|---|---|---|
| Book（一本书） | 一卷（30-80 万字） | 每卷有独立起承转合 + 卷末阶段性高潮 |
| Series（整个系列） | 全书（200 万字） | 全书一条北极星终点线 |
| Book Question | 本卷问题 | 卷内解决，给读者阶段满足 |
| Series Question | 全书问题 | 终局才答，跨卷吊胃口 |
| Series Ending Vision | 北极星终点（锁根六要素） | 终局画面、主角终态、情绪落点 |
| Series Bible | 设计库/人物库/剧情库 | 最小必要文档，删死重 |
| Series Finale | 最终卷（冲刺期） | 盘点全部伏笔，Triage 分流 |

## 三、核心方法论提炼（可直接转成提示词）

### 3.1 北极星终点（Series Ending Vision）

写第一卷（开局）前必须知道终点，但不需要每个细节，只需要形状：

1. **高潮时刻**：终局对决/选择/事件，2-3 句话写清形状。
2. **关键人物**：谁在场。终局关键人物必须早期登场、全程发展。
3. **主角终态**：终局的主角是谁，与开局差在哪，能做什么以前不能做的。
4. **情绪落点**：读者合上书时的感受（热血/释然/怅然/圆满），先定情绪再写过程。
5. **非解决清单**：必须回收的伏笔、必须回答的问题，其余皆可灵活。
6. **终局画面**：最后一个场景/意象，给全文一个"写向它"的靶子。

配套双问题：

- 本卷问题：`Will [主角] [完成眼前目标]?` —— 卷内必须给答案。
- 全书问题：`Can [主角] [需要成长才能达成的终极挑战]?` —— 全书写向它。
- 本卷问题答了（满足感）+ 全书问题没答（期待感）= 读者追下一卷。

### 3.2 埋种清单（第一卷/第一幕该种什么）

1. 全书级剧情线：引入但不解决，甚至不全揭示（预言、逃脱的宿敌、主角不自知的能力）。
2. 后期关键的角色特质：第 5 卷靠"鼓舞他人"赢，第 1 卷就要露端倪。
3. 会加深的关系：挚友/导师/对手/恋人/宿敌，第 1 卷定基调。
4. 后期重要的世界细节：地名、规则、历史顺嘴埋，不 info-dump。
5. 主题问题：全书表面之下真正在问什么，第 1 卷发问，终卷回答。
6. 主角起点：清楚展示"现在是谁"，供读者衡量成长。

**第一卷不要种**：第 3 卷才用得到的世界观前置、后期才登场的角色、纯铺垫无满足、晦涩到重读都抓不住的彩蛋。

### 3.3 系列圣经（做减法的资产分级）

**定位**：是工具，不是产品。功能优先，不做完美文档。能答问题、省时间就是好的。

| 层级 | 内容 | 网文对应 |
|---|---|---|
| Tier 1 必须记 | 角色硬信息（外貌/年龄/关系）、时间线、世界规则 | 人物库硬信息 + 法则 + 时间线 |
| Tier 2 应该记 | 伏笔/未解支线/铺垫记录、关键场景布局、配角出场表 | 剧情库 + 伏笔账本 |
| Tier 3 有空再记 | 冷门世界观细节、灵感素材 | 调研采风 |
| Tier 4 别记 | 一次性角色、每次出场服装、永不引用的家谱 | 直接删 |

**维护规则**：

- 写完一卷后 1-3 小时更新，别边写边停。
- 五分钟后规则：加一条记录超过 5 分钟、且以后不会引用，就跳过。
- 一年没翻过的章节直接删，是死重。
- 已有项目补记录时只补 Tier 1，别回溯性完美化。

**世界规则必须记"做不到什么"**（比"能做到什么"更重要）：第 1 卷不能传送，第 3 卷就不能突然用传送解决问题。

### 3.4 终局盘点（卷末回看 / 最终卷）

**盘点法**：列全所有伏笔/人物弧/未解问题，逐个判级。

**Triage 三级分流**（对每个元素问两句）：

- 读者没看到会感觉被背叛吗？→ 必须解决 / 尽量解决 / 可留空
- 直接影响全书问题或主角弧吗？→ 必须解决 / 尽量解决 / 可留空

**终局三幕结构**：

- Act 1 汇聚（25%）：现状、最高 stakes、明确目标、集结、不归点、最后平静。解决小支线。
- Act 2 升压（50%）：赶向终局、边推进边收次级线、兑现或反转预言、牺牲与至暗时刻。只留全书问题。
- Act 3 高潮（25%）：答全书问题、主角完成弧、宿敌了结、余波、新常态、短 epilogue。

**情感兑现五技法**：回call开头（对比成长）、赢在成长而非作者硬给、苦甜代价（胜利有成本）、关系兑现、首尾呼应。

**五大雷区**：烂尾（高潮只占 20%）、epilogue 过长、天降神兵（没铺垫的解法）、忘收主线、角色崩坏。

## 四、转写为灯塔流可用的 Prompt 结构草案

### Prompt A：北极星锁根（Phase 2 seed 用）

```
你是本项目的北极星规划器。目标：为 200 万字网文锁定"终点形状"，不做全本细纲。
输入：主角立身 / 世界内核 / 篇幅量级（卷数估算）。
输出六要素（各 2-3 句，非完整细纲）：
1. 高潮时刻：终局对决/选择的形状
2. 关键人物：终局谁在场，谁必须早期登场
3. 主角终态：终局与开局差在哪
4. 情绪落点：读者合卷感受
5. 非解决清单：必回收伏笔/必答问题
6. 终局画面：最后场景意象
再输出双问题：
- 本卷问题（第一卷内答，给满足感）
- 全书问题（终卷才答，跨卷期待）
检查：六要素缺一不可；双问题不能含糊；不得展开卷级细纲。
```

### Prompt B：设计库维护（日常资产管理用）

```
你是本项目的资产分级器。目标：维持最小必要文档，删除死重。
输入：新增事实 / 待记录项。
判级：
- Tier 1 必须记：角色硬信息、时间线、世界规则（含"做不到什么"）
- Tier 2 应该记：伏笔、未解支线、关键场景、配角出场
- Tier 3 有空再记：冷门细节
- Tier 4 删：一次性的、永不引用的
规则：加一条超过 5 分钟且以后不引用 → 跳过；一年没翻过的章节 → 标记删除。
输出：更新条目 + 判定理由（一句话）。
```

### Prompt C：卷末回看（Phase 5e 用）

```
你是本项目的终局盘点器。目标：盘点当前卷与全书进度的伏笔/人物弧/未解问题。
输入：剧情库 / 伏笔账本 / 方向总表 / 本卷正文。
步骤：
1. 列全所有伏笔与未解问题（含来源卷章）
2. 逐个 Triage：读者会感觉被背叛吗？直接影响全书问题吗？
   → 必须解决 / 尽量解决 / 可留空
3. 对照方向总表：本卷质变点是否兑现
4. 输出：已回收 / 待回收 / 新增埋设 三张清单
```

## 五、对灯塔流的具体补强点

1. **seed 环节**：北极星六要素已落位，补上"本卷问题/全书问题"双问输出。
2. **设计库**：资产分级（Tier 1-4）可并入现有"资产来源标记"体系，作为"引用分级"维度。
3. **5e 卷末回看**：加入 Triage 三级分流，替代泛泛的"检查伏笔"。
4. **开篇环节**：埋种清单（6 类种子 + 4 个不要）可直接做检查项。
5. **世界法则**：明确"做不到什么"优先于"能做到什么"，写入 world skill。
