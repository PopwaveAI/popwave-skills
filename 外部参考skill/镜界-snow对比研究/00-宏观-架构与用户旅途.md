# 00-宏观：镜界（Mirroric）skill 系列的架构与用户旅途

> 研究对象：`外部参考\镜界的skill` 16 个 AgentSkill + 1 份系统提示词。本文档是宏观层通读结论，用于立项后续的逐 skill 微观对比。落盘日期：2026-09-08。

## 一、一句话定位

镜界是**"工作台"式**的创作应用：核心不是"一个会写文的模型"，而是**一套结构化知识库 + 类型化字段 + 可编程工具 + 审查闭环**的组合体。16 个技能各自管一块职责，靠系统提示词统一路由、靠审查闭环保证质量、靠工具操作把决定真正落到数据上。

对比 snow 系列（"管线+状态机"式），镜界是**"分工+闭环"式**：没有严格的阶段状态机（2a→2g），而是围绕"规划→写作→审查→沉淀"的一个章节循环 + 若干横向专项。

## 二、三层架构

```
┌ 层3 应用框架层 ── 11 创作向导(Onboarding) / 12 创作工具管理(增删查改)
│     职责：一次性的初始化沉淀 + 长尾的工具/规则/技能管理
│
├ 层2 创作主链路 ── 10 世界观设定 / 05 人设设计（设计先行）
│               → 02 章节规划 / 03 章节写作 / 01 章节节奏 / 06 黄金三章（执行）
│     职责：先定"世界与人物"，再进入"规划→写作"，节奏与开篇是横切质量器
│
├ 层1 审查闭环 ── 04 角色一致性 / 08 长篇连续性 / 09 设定一致性 / 07 去AI味
│     职责：四把尺同时审一个产物，结果走仲裁，不直接改文
│
└ 层0 工具操作层 ── 13 图像生成 / 14 画布构图 / 15 关系图谱 / 16 番茄榜单
      职责：把"想"变成"能操作的数据"，或把"市场"接进来（16）
```

**系统提示词是总纲**，16 个技能是被它调度的零件。总纲里承载了：身份气质、核心规则、写作手艺（动笔前三问+已内化的审美直觉）、正文质量底线、审查闭环、任务路由原则、SubAgent 阵容、可用技能清单、工具使用准则、工作区路径规则、项目级用户规则。

## 三、用户旅途（Onboarding → 每章循环）

```
【项目初始化】 用户旅途第 1 站
  11 创作向导：根决策(题材/目标读者/故事承诺) → 会进书名的结构项 → 元数据(书名/分类/标签/简介)
                → 写作行为约束 → 设定加深 → AgentSkill 能力配置
  12 创作工具管理：长尾的 AgentRules / AgentSkill / SubAgent / Workflow 管理（非Onboarding专用）
  ↓ 产出沉淀到：novel 元数据 / AgentRules / 工作区资料 / 已装技能

【世界与人物】 用户旅途第 2 站（首喷）
  10 世界观设定：力量体系(先边界后名字)→体系自洽→地图扩展与剧情绑定→势力格局→资源经济→设定节奏→设定钩子
  05 人设设计：配角功能位/反派模板/群像管理（主角标签/类型/命名/内核）
  ↓ 产出：世界观条目、角色档案、势力档案

【每章循环】 用户旅途第 3 站（重复）
  02 章节规划 → 03 章节写作 → 01 章节节奏(横切) → 07 去AI味(收尾横切)
  ↓ 正文写入后 → 自动委派审查 SubAgent

【审查闭环】
  04 角色一致性 / 08 长篇连续性 / 09 设定一致性（三把内容尺）→ 通过即交付
  07 去AI味（文字尺，输出前/审查时）
  ↓ 发现问题 → 修正 → 最多2轮 → 仍有问题 AskUser

【开篇校准】 用户旅途第 4 站（只在前几章）
  06 黄金三章：落差→特权信息→还小账立新标

【可视化与市场】 用户旅途横向站
  13 图像生成 / 14 画布构图 / 15 关系图谱 / 16 番茄榜单（标杆认知/开篇拆解/文风仿写）
```

## 四、贯穿全程的关键设计（最值得留意的手笔）

1. **三层数据结构分离（最重要的架构思想）**
   - `元数据` → novel 资源本身（书名/分类/标签/简介）
   - `写作行为约束` → AgentRules（可执行、可复用、一条管一个维度、AI 后续都参考）
   - `故事事实` → 工作区资料（世界观/角色/势力/大纲，勿写成 AgentRule）
   - `可复用流程` → AgentSkill（全局可复用、不硬编码故事事实）
   - 红线：**不把故事事实写成 AgentRule，不把 AgentSkill 当资料**。三类载体各管各的，这是镜界有条理的根因。

2. **工具即写入**：不是"AI 说保存了"就完，"必须调用对应工具真实写入"，失败要报原因不让文字冒充成功。这保证了蓝图真正落地到持久数据。

3. **事实优先级（统一裁决链）**：已发布正文 → 最新章节事实提取 → 角色卡 → 世界书 → 伏笔记录 → 大纲 → 用户临时要求。一致性四把尺共用同一条链。**用户临时要求和既有事实冲突时必须指出，不静默覆盖**。

4. **写前状态包 + 写后事实提取**：每章动笔前核对时间线/空间线/角色状态/关系/道具/信息边界/伏笔/世界规则；写后只提取"正文明确发生"的事实，不把大纲当既成事实。形成"规划→写→提取→喂给下一章"的连续闭环。

5. **审查闭环克制**：审查产物是"位置/问题/严重性/改法/状态更新"，只给方向和最小修法，不替作者写文；通过才交付，最多 2 轮。

6. **SubAgent 分工**（编年史者/正文写手/内容核验/文风润色/资料收集）正是 snow 系列要"审查不落盘子agent"对标的分工池。

## 六、宏观红黄灯

- **绿灯（可直接借鉴）**：三层数据载体分离 / 事实优先级统一链 / 写前状态包+写后提取的闭环 / 审查只给方向不改文 / 工具即写入。
- **黄灯（与 snow 冲突，需取舍）**：镜界无阶段状态机、无卷循环，靠"章节循环+横切专项"；snow 是"卷→幕→章"强状态机。**不可整体换皮**，只抽"提示词级的写法"。
- **提示：** 镜界 16 个技能是"应用内 AgentSkill"，本质是工作台可复用流程；snow 是管线 skill。两者形态不同，微观对比应重点挖**每条提示词的度量值、判别式、示例**，而非搬运框架。
