# 11-创作向导 vs pop-snow-seed（立项 / Onboarding）

> 镜界「11-创作向导」vs snow 的 pop-snow-seed（统一管线立项）微观对比。snow 侧：seed 六步流水线（问诉求→定调研清单→调研→归集取材·卖点源→融合→定稿交接）+ 14 维融合立项稿（力量体系/金手指/世界观骨架等），强在**调研强制 + 终点优先 + 14 维融合成稿**。镜界这里是**Onboarding 结构化提问引擎 + 元数据/规则/事实载体分流**，强在"怎么问、怎么沉淀到正确载体"。

---

## 一、镜界该 skill 有哪些提示词（全拆）

**核心定位**：负责确认并沉淀基础写作规则、作品元数据与稳定故事边界；**故事事实写入对应工作区资源**；不得一次性穷举问题，不得未经确认覆盖已有内容。**AgentSkill 是全局可复用工作流，不是作品规则或故事事实**（执行产生的内容要写回正确载体）。

**不适用分支**：用户只问技术/不涉及创作 / 已初始化未要求重导 / 具体写作任务走对应 AgentSkill / type 为 material 时。

**工作流程（7 步）**：

1. **前置准备：先读，再问**——读 `/novel` 元数据、列 AgentRules、列全局 AgentSkill、浏览工作区资料；把待办记下来（哪些约束缺失/哪些资料可提炼成 AgentRule/哪些资料应补充而非新建）。
2. **选择创作模式附件**：按 type（fanfic/sequel/original）分流程；original 还分"从零原创/仿写"。
3. **决定问什么**：题材优先看已有 category/tags/简介；**按「根决策 → 会进书名的结构项 → 作品元数据 → 其余写作约束」分轮提问**。
4. **区分元数据、规则与故事事实（载体分流三分类）**：
   - 作品元数据（书名/分类/标签/简介）→ `/novel` 资源本身
   - 写作行为约束（不写露骨/第三人称单POV/每章字/反降智/章末钩）→ **AgentRules**（一条管一个维度，可执行可复用）
   - 故事事实（人设/世界观/力量体系/势力格局/谜题真相）→ **工作区资源**（不写成 AgentRule；若需 AI 严格遵循可再提炼一条 AgentRule，但事实载体仍是资源）
   - 大纲轨道：先确认**篇幅量级与分卷**（每卷大致章节范围），每大纲是独立轨道，标题表用途。
5. **AgentSkill 能力配置与设定加深**：不预装全部；按当前缺口选最匹配的，一个缺口装一个，AskUser 确认后才 install。
6. **提问原则**：必须用 AskUser；按依赖顺序分轮（一轮 2-3 题，不抛整张清单）；每问题给 2-4 个 options 且一个标 `recommended:true`；"你来定"时给建议但先请求确认；发现新旧冲突直接指出让用户选，不平均处理。
7. **完成与回报**：完成标准 = **"改起来贵不贵"**（全书稳定、后期难改的基础决策已确认并沉淀即完成；角色势力支线可留白）。brief 回报（建了哪些规则/写了哪些元数据/装了哪些 skill/哪些缺口）+ SuggestNextAction 一次。

**默认建议**：章节字数 2000-3000（±10%）/ 风格清晰克制有画面 / 第三人称单 POV 严格信息边界 / 节奏每章一变化+章末钩子 / 禁忌不降智不强行误会不AI腔。

**边界**：不替用户无依据补全设定 / AgentSkill 不存故事事实不替代 AgentRules / 不硬编码小说故事事实（涉及作品上下文先读或问）。

---

## 二、snow 对应环节定位

pop-snow-seed：立项流水线。snow 强在**"融合」输出物**（14 维融合立项稿：把调研、取材、卖点源融成可直接开工的立项稿）+ **调研强制**（必须先调研，终点优先）。

## 三、值得深挖的学习点（snow 可吸收）

### 🟢 A 级
| # | 镜界提示词 | 为什么值得学 | snow 现状 / 吸收方式 |
|:-:|:--|:--|:--|
| A1 | **载体分流三分类（元数据→novel / 写作约束→AgentRule / 故事事实→工作区资源）** | snow 有"定死断言"但**没把"该装进哪个容器"分得这么清**。很多定死在 seed 里该进"基层文化 to 产出"却写成议事，或反把可执行规则和事实混一层。三分层让立项物各归其位 | seed 定稿交接加"载体标签"：每项产出标注→元数据/规则/事实；杜绝"故事事实写成写作规则" |
| A2 | **依赖分层提问（根决策→结构项→元数据→约束）+ 一轮 2-3 题 + recommended & allow_free_text** | snow seed 的"问诉求"是一次性对话收效，没做**依赖分层**。根决策先行决定后续问题定制（男频玄幻→第三人称单 POV+4-5 千字；悬疑→严格信息边界），能降低问题数量、防"先铺零碎后定方向" | seed 问诉求改分层：先根决策（题材目标读者故事承诺）→ 再会进书名的结构项 → 再到元数据与写作约束；一轮 2-3 题 |
| A3 | **完成标准 = 改起来贵不贵** | snow 立项可能追求"一次成稿" → 容易过度设计。镜界："全书稳定后期难改的基础决策确认即完成，角色势力支线可留白" — 防止 on-boarding 通胀 | seed 增加"完成边界"声明：定死难改项 ✅，可渐进项直接留白，不为了"完整"拖长立项 |
| A4 | **不预装全部能力，按缺口装、一个缺口一个最匹配 skill** | snow 的管线是"一次性搭全套"（pipeline 初始化全目录），镜界主张"按缺口装能力防冗余"。对"能力过多反而难路由"有参考 | 供批判吸收：snow 管线初始化后应做"能力瘦身"，场景驱动地依赖而非默认全读 |

### 🟡 B 级
| # | 学习点 | 吸收方式 |
|:-:|:--|:--|
| B1 | 先读再问（提问前已收集元数据/规则/skill/资料） | snow seed 已"问诉求前调研"，无需新增 |
| B2 | 大纲轨道先定篇幅量级与分卷 | 对应 snow 卷纲"定战略定范围定方向"，可吸收"量级锚点" |
| B3 | 章节字数默认 ±10% 允许区间 | 与 01 的 B3 呼应，review 字数区间校验 |
| B4 | 元数据（分类/标签/简介/书名）单独管理 | snow 无作品元数据概念，可作为立项稿的补充输出块 |

## 四、snow 反补镜界 / 交汇点

- **snow 更强**：调研强制 + 终点优先（把"赛道定位"前置）+ 14 维融合成稿（一次性产出可开工立项稿）。镜界强在**互动的得分且**（AskUser 分层）与**载体分流**。
- 合并：镜界的"分层提问 = seed 的第一步（问诉求的工程化）"；镜界的"载体分流 = seed 定稿交接的规范化"；seed 仍是立项主体，镜界是把它打磨成可交互、可落位的工业流程。

---

## 五、结论 / 吸收建议

**最值得吸收 3 点**：载体分流三分类（元数据/规则/事实各归其位）、依赖分层提问 + 一轮 2-3 题给 recommended、完成标准 = 改起来贵不贵（防立项通胀）。这三条把 seed 从"一次性成稿"升级为"可交互、可沉淀、不冗长"的立项引擎；作品元数据可作为 seed 立项稿新增的一个输出块。
