# 14-画布构图 vs snow（无直接对应 → 可迁移的信息架构原则）

> 镜界「14-画布构图指南」vs snow 可视化能力微观对比。snow 侧：pop-visual-pipeline 的可选 html 展示面板 / 内容卡 / 视觉工程，但**没有"结构化画布"这一形态**。镜界这里的对象是"工作区内可视化画布"（节点/连线/纸色的布局排版），**snow 无 1:1 对应环节**——但它的构图法则本质是**信息架构调用**，可迁移到 snow 的 html 面板、全书日志/卷绪、内容卡等一切"把复杂关系可视化"的输出。

---

## 一、镜界该 skill 有哪些提示词（全拆）

**总纲**：画布好不好看不取决于内容多细，取决于**结构一眼能不能读出来**；给的是可执行版式规则，不是审美形容词。

**路径**：用通用 Read/Create/Write/Edit/Remove 操作 `/canvas/{name}`（nodes/edges），画布名唯一即路径键。

**摆位几何事实**：网格步长列距 400/行距 248；便签默认 280×168；引用节点 256×62；相邻两列净空 120px。

**构图规则（13 条）**：
1. 只用 col/row，不用 x/y（x/y 会被当手工钉死，不参与重排）。
2. 主干沿 row=0 从左到右，col 序=时间/因果序；**一件事一张画布**。
3. **主干必须是节点最多的那一行**（重排把最多节点的层当骨架；主干不是最多行会把支线当骨架打乱顺序）。
4. 支线分行不混行（后文/影响/后果 → row+1；动因/伏笔/暗线前情 → row-1；同一行不叙两条线）。
5. 一行最多 6 个节点；超过分幕（幕后标题用 stone 便签放主干上方且不连线）。
6. 同一行只放同一类节点（引用高 62/便签高 168，混排行高参差留空洞）。
7. 有边的两节点尽量同行相邻或同列上下（连线从最靠近的边射出；非要斜连中间留空）。
8. **边类型=语义不混用**（timeline 主干推进/causal 跨行因果/relationship 只用于人物/foreshadow_payoff 伏笔→章节 长虚线/association 兜底；**一张图 >3 条 association 说明结构没想清楚，回去重分行**）。
9. 不是每条关系都要画线（线越多越糊；同行相邻列够表先后就不用连）。
10. label 长度按边给（同行相邻仅 120px 净空，>6 中文字会盖死线，只有跨行长边可到 10 字；只给"不看会误解"的边写 label）。
11. **纸色是分组不是装饰**（sand 主干事件/sage 设定规则背景/rose 冲突风险代价"要出事"/stone 元信息幕后备注；**一张画布 ≤3 色，主干统一 sand**，四色全用变调色板）。
12. 便签正文 1-3 行写清一件事就停，长内容放进资源正文，画布上只留引用节点。
13. 资源已存在就用引用节点，别抄成便签（引用更矮整齐，可点开看原文）。

**四模板**：节拍时间线（伏笔-1/主干0/影响+1）/ 伏笔兑现表（伏笔-1 → 章节0，foreshadow_payoff 自动挪到兑现章正上方）/ 人物关系星座（配角 row0 最多→骨架，主角 row+1 单节点自动居中）/ 因果树（causal 父在上子在下，分叉>6 分幕）。

**收尾**：连完所有边写一次 `<layout>=auto`；hand 改过的节点脱离网格，不再参与重排——完成后**停手，不逐个 Write 微调**。

**交付前自检 + 反模式**：主干是不是最多行/有没有超6/association 是否>3/label 是否过6/是否还留 x/y 摆/纸色是否>3 种主干是否 sand/最后是否 layout auto；以及满屏 association、20 节点一行、混排行、每条边都写 label、用 x/y 精修、拼 id、长设定塞便签。

## 二、snow 对应环节定位

无 1:1 环节。最近似：pop-visual-pipeline 的 html 展示面板 / 内容卡 / 卷绪可视化。差异：镜界是"数据驱动 + 约束重排"的画布，snow 是"html 手写面板"。

## 三、值得深挖的学习点（snow 可迁移）

### 🟢 A 级（信息架构方法论，可迁移到任何可视化输出）
| # | 镜界法则 | 为什么值得学 | snow 迁移到哪 |
|:-:|:--|:--|:--|
| A1 | **支线分行不混行+行内同色同类型**（后文+1/前情-1；一行一条线） | 可视化最忌"大杂烩"。把"主线/支线、因果/伏笔、设定/冲突"分层排布，读者瞬间看清结构 —— snow 的 html 面板/卷绪也应分层呈现而非堆叠 | snow 可视化（html 面板/全书日志卷绪/内容卡）：按"时间主线-因果支线-伏笔暗线"分层排布，不要单一大列表 |
| A2 | **纸色=分组不是装饰（≤3 色、主干主色统一）** | 颜色是语义不是美化。snow 可视化常过度用色当装饰；镜界明确"纸色表达角色（事件/设定/冲突/元信息），主干统一" | snow html 面板配色规则：颜色承载语义分层，主干一类色，冲突/风险用警示色，总色≤3 |
| A3 | **不是每条关系都画线 / association>n 说明结构没想清楚** | 过度连线的反面是"全连接图=什么都没说"。snow 关系可视化也易堆线 | snow 关系/因果可视化加"线数量预算"，超预算=需回重塑结构 |
| A4 | **资源已存在用引用节点，长内容放正文（便签 <1 行摘要）** | 面板只留"指针"，细节进正文 —— 防止可视化承载过载 | snow html 面板：节点只放一行摘要，长内容折叠/链接到资源正文 |
| A5 | **一行最多 N 节点 + 单图只讲一件事** | 防"一张图什么都装"，控制信息密度便于移动端阅读 | snow 可视化按"一件事一张图"拆分，控制每面板节点数 |

### 🟡 B 级
| # | 学习点 | 迁移 |
|:-:|:--|:--|
| B1 | 主干是节点最多的层（重排以此为骨架） | 镜像"主结构应选最重一条支作为锚"，迁移到 html 布局"主模块为首屏" |
| B2 | label/便签字数预算（净空 120px≤6 字） | 迁移到内容卡：文案字数是按版式算的，不是审美 |

## 四、snow 反补镜界 / 交汇点

- snow 的 html 面板是**自由布局**，镜界画布**约束重排**（确定性）。两者互补：约束重排省心但不够自由；html 自由但要自己管结构。snow 可视化可借镜界的**语义分层/颜色语义/密度预算/指针化**四原则，而不是复用它的重排机制。

---

## 五、结论 / 吸收建议

snow 无对应 outlet 要照搬；**迁移 5 条信息架构原则**到 snow 可视化（html 面板/卷绪/内容卡）：支线分层不混行、纸色/颜色=语义分组≤3 色、关系线数量预算、节点指针化（长内容进正文）、一张图一件事+节点数上限。可作为 snow 可视化输出的「版式红线」，替代纯审美描述。
