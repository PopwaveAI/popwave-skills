# 15-关系图谱 vs snow（无直接对应 → 关系数据溯源方法论）

> 镜界「15-关系图谱指南」vs snow 微观对比。snow 侧：角色间关系散存于 stage 角色长档 / 全书日志的关系状态 / 关系变化记录，**无独立的"图上关系"体系**。镜界这里是"实体有向关系图谱"（character/faction/skill/item…）的建查删规范，snow **无 1:1 对应环节**——但"关系必须可溯源到证据章节 + 变化不叠新"是通用的关系管理纪律，可迁移到 snow 的角色库关系字段与全书日志"关系变化"。

---

## 一、镜界该 skill 有哪些提示词（全拆）

**核心目标**：记录实体之间的**有向关系**；可从正文抽出已写关系，也可先在写剧情前设计关系网。**每条关系都必须有 `chapter_id` 和 `proof`**。

**路径/操作**：建立走 Create，查询走 GraphSearch/Read，删除走 Remove；**已建立的关系不可改写**——要改就 Remove 掉重 Create。

**必填 7 字段**：source_type/target_type（实体类型）/ source_id/target_id（从 Read/GraphSearch 原样复制，禁拼 id）/ relation_type（合法值由 source→target 组合决定）/ **chapter_id** / **proof**。

- **chapter_id**：这条关系挂靠的章节。已确立的填**确立它的那一章**（人物第 3 章相认、现在写第 40 章，仍填第 3 章）；设定阶段、正文还没写到的，填计划揭示它的那一章。
- **proof 写依据，不写结论**：有场面就概括情节（"两人雨夜互报家门，认出对方腕上同款胎记"）；设定阶段可写设计依据。**"他们是兄妹"不是 proof（那是 relation_type 已表达的东西）**。

**合法关系类型**：只有 table 列的组合合法，不存在的建不了（返回 invalid_relation_type + 合法值）。**读法：`A --type--> B` 读作「A 是 B 的 <type>」，类型名描述 source 身份**。三类偏离：**[对称]**（两端可互换，同对实体只建一条）/ [反读]（类型描述 target：`subordinate`、`alter_ego` 仅两个）/ [动词]（动词短语按字面 read）。给了 character→character / →faction / →skill / →item、faction→faction、skill→skill、item→item、creature→creature 的完整类型表，"最容易放反的四个"（subordinate/alter_ego/master_disciple/predator）。

**建之前先查**：同对实体同类型只建一次（先 GraphSearch 展开 source，重复建=同一句话三遍）。关系变化时（结盟转敌对、师徒决裂）**不在旧关系上叠新**：Remove 旧 + Create 新，或两条都留但各自指向不同证据章节（前提是能说清描述不同阶段）。

**反模式**：proof 写结论 / chapter_id 填当前章 / 方向随手填（四反）/ 给每对角色都连一条（角色表做成全连接图）/ 中文 relation_type / 拼 id。

---

## 二、snow 对应环节定位

无 1:1 环节。最近似：stage 角色长档的关系字段 + 全书日志"关系状态/动了哪些线"的记录。snow 的角色关系是**文字记录**，镜界是**结构化有向图**。

---

## 三、值得深挖的学习点（snow 可吸收）

### 🟢 A 级
| # | 镜界提示词 | 为什么值得学 | snow 现状 / 吸收方式 |
|:-:|:--|:--|:--|
| A1 | **每条关系必带 chapter_id（确立它的那章）+ proof（依据，非结论）** | snow 记录"关系变化"记得住"变了"，但常**记不清"在第几章、因什么确立"**。chapter_id（确立章）+ proof（原文场面依据）让关系**可回查、可核验**，是"正文驱动"的记忆深化 | 进 stage 角色库/全书日志关系字段：每个关系状态 = 类型 + **确立章节** + **具体依据（一个可直接复查的场面）**，而非只写"现在是盟友" |
| A2 | **关系变化不叠新（Remove+Create 或两关系指向不同证据章，须说清阶段）** | snow 全书日志"只留最新"replace 会**抹掉关系的阶段历史**。镜界允许"两条同一对象的关系各指不同证据章"来保留"曾敌对后来结盟"的时序 | 进全书日志关系记录：关系变化保留"旧阶段证据章↓新阶段证据章"，而非单纯覆盖，供追查剧情连续性 |
| A3 | **proof 写依据不写结论** | "关系是 X"是重复类型；要让任何查验者能凭依据复核。snow 审一致性时最缺的就是"这条关系凭什么成立" | 进 review 一致性核验时可用：角色关系谓时须能举出具体场面依据，否则标记待补 |

### 🟡 B 级
| # | 学习点 | 吸收方式 |
|:-:|:--|:--|
| B1 | 只建有情节意义的关系（不做全连接图） | 进角色库关系管理：非情节关系不入档，防信息过载 |
| B2 | 对称/反读/动词读法（类型描述 source 身份） | 数据建模严谨性，snow 不必全盘搬；可作为关系字段枚举的参考 |
| B3 | 建前先查去重（同对同类型一次） | 进角色库维护：关系重复检测 |

## 四、snow 反补镜界 / 交汇点

- snow 的**当前态快照 + 退出档案**回收机制，若接入镜界的"变化不叠新、按证据章保留阶段"，能形成"关系时序 + 历史沉淀"的完整闭环；镜界缺 snow 的衰退管理（旧关系清理），可互补。
- 无冲突，镜界的图谱是数据结构层，snow 的文字记录是内容层，可合并为"内容记变化 + 图/字段记溯源"。

---

## 五、结论 / 吸收建议

**最值得吸收 2 点**：①关系字段带入 **chapter_id（确立章）+ proof（具体场面依据）**，可回查可复核；②关系变化**不覆盖、保留阶段证据章**（Compat 改动进全书日志/角色库）。"只建有情节意义关系 + 建前去重"作为角色库维护纪律。
