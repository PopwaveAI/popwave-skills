# 画布构图指南

画布好不好看，不取决于内容写得多细，取决于**结构一眼能不能读出来**。这份指南给的是可直接执行的版式规则，不是审美形容词。

## 路径

画布没有专用工具，全部走通用的 Read / Create / Write / Edit / Remove。画布名唯一，它本身就是路径键：

| 目标 | 调用 |
|---|---|
| 有哪些画布 | `Read {"path": "/canvas"}`；`?search=` 匹配 name / description |
| 一张画布的概况 | `Read {"path": "/canvas/{name}"}` |
| 现有节点 | `Read {"path": "/canvas/{name}/nodes"}`；`?search=` 匹配 title |
| 现有连线 | `Read {"path": "/canvas/{name}/edges"}`；`?search=` 匹配 label |
| 摆位摘要 | `Read {"path": "/canvas/{name}/layout"}` |
| 新建画布 | `Create {"path": "/canvas", "fields": {"name": "主线时间线"}}` |
| 放一个节点 | `Create {"path": "/canvas/{name}/nodes", "fields": {...}}` |
| 连一条线 | `Create {"path": "/canvas/{name}/edges", "fields": {...}}` |
| 挪节点 / 改标题 / 改纸色 | `Write {"path": "/canvas/{name}/nodes/{node_id}", "fields": {...}}` |
| 改便签正文 | `Edit {"path": "/canvas/{name}/nodes/{node_id}/content", ...}` |
| 删节点 / 删线 / 删画布 | `Remove {"path": ...}` |
| 打开给用户看 | `Write {"path": "/canvas/{name}/open", "value": true}` |
| 收尾重排 | `Write {"path": "/canvas/{name}/layout", "value": "auto"}` |

画布名唯一，可以从 `active_workspace_target` 或 `/canvas` listing 拿到后直接拼 `/canvas/{name}`。`/canvas/{name}` 本身可写 `name` 与 `description`；边只支持创建和删除，不支持改写。

**先打开再动手。** 要在某张已有画布上作业时，先 `Write /canvas/{name}/open` = `true` 把它打开到用户面前，用户才看得见你在画什么。

**节点 id 不要自己拼**：从 nodes listing 的 `entries[].path` 或 Create 响应的 `path` 原样复制。连边尤其容易在这里出错 —— 先记下每个 Create 返回的 `node_id`，连线时直接用。

## 字段

**节点**（`Create /canvas/{name}/nodes`）：`type` 必填，取 `reference` 或 `sticky`；两种类型的必填项不同。

| type | 必填 | 说明 |
|---|---|---|
| `reference` | `ref_type` + `ref_id` | 指向已有资源。`title` 是资源标题的缓存，传了会被忽略 |
| `sticky` | `content` | 便签正文。允许空串，但字段不能省；`title` 可选，作便签抬头 |

`ref_type` 取值：`character`、`faction`、`skill`、`item`、`location`、`chapter`、`foreshadowing`、`creature`、`outline`、`document`。`ref_id` 从对应集合的 listing 原样复制 —— 指向不存在的资源返回 `invalid_reference`，节点不会建出来。

摆位字段：`col` + `row`，或 `near`（已有节点 id）+ `direction`（`right` / `left` / `above` / `below`）。`color` 只对便签生效，取值 `sand` / `sage` / `rose` / `stone`。`width` / `height` 可选。`x` / `y` 见第 1 条，别用。

**边**（`Create /canvas/{name}/edges`）：`source_node_id`、`target_node_id`、`type` 必填，`label` 可选。`type` 取值见第 8 条。

## 先看清场地

动手前必须先 `Read /canvas/{name}/nodes` 读取画布现有节点（节点多时按 `offset`/`limit` 翻页取全）。空画布才从 `col=0, row=0` 起步；画布上已有东西时，先判断已有的主干在哪一行、占了哪些列，再决定新内容接在后面还是另起一行。

`Read /canvas/{name}/layout` 的 `off_grid` 是被用户手动拖动过、不参与重排的节点数。这个数不为 0 时，重排不会动它们，只会绕开它们。

几何事实（摆位时按这些数算，不要凭感觉）：

| 项 | 数值 |
|---|---|
| 网格步长 | 列距 400、行距 248 |
| 便签默认尺寸 | 280 × 168 |
| 引用节点默认尺寸 | 256 × 62 |
| 相邻两列的净空 | 120px（边标签就骑在这段上） |

## 一、摆位

1. **只用 `col`/`row`，不要用 `x`/`y`。** 只有严格落在网格点上的节点才参与 layout 重排；用 `x`/`y` 摆的节点会被当成「用户手工摆的」永久钉死，之后只能当障碍物。坐标由系统算，保证不重叠 —— 你只描述方位。挨着某个已有节点放时用 `near` + `direction`（`right`/`left`/`above`/`below`），其余一律 `col` + `row`。
2. **主干沿 `row=0` 从左到右**，`col` 序就是时间顺序 / 因果顺序。一张画布只讲一件事。
3. **主干必须是节点最多的那一行。** 重排算法把节点最多的那一层当作骨架原样保留（数量打平时取最上面一层），其余层围着它重新分列。主干如果不是最多的那行，整理布局会把支线当骨架，把你的故事顺序打乱。
4. **支线分行不混行**：结果、影响、后果放 `row=+1`；动因、伏笔、暗线、前情放 `row=-1`。同一行不叙两条线。
5. **一行最多 6 个节点。** 6 列约 2400px 宽，在典型画布区里适配全图后缩放已经掉到 0.4 上下，便签正文接近看不清；再多就只剩色块。超过就分幕：把一幕的标题写成 stone 便签，放在该段主干上方且**不连线**，下一幕从新的列继续。
6. **同一行只放同一类节点。** 引用节点高 62、便签高 168，混排会让行内基线参差、行下方留出大片空洞。

## 二、连线

7. **有边的两个节点尽量同行相邻或同列上下。** 连线从两节点最靠近的那条边射出；斜着放的两个节点，线会从角上斜穿出去，很容易压到旁边的卡片。非要斜连时，把中间那格留空。
8. **边类型就是语义，不要混用**：
   - `timeline`：主干推进（实线带箭头）
   - `causal`：跨行因果（实线带箭头）
   - `relationship`：只用于人物之间（无箭头）
   - `foreshadow_payoff`：起点是伏笔节点、终点是章节节点（长虚线）
   - `association`：兜底。**一张图里超过 3 条 association，说明结构还没想清楚**，回去重新分行，别用关联线糊住。
9. **不是每条关系都要画线。** 线越多结构越糊；能靠「同一行、相邻列」表达的先后关系，就不必再连一条 association。

## 三、文字与配色

10. **label 长度按边长给。** 同行相邻两节点之间只有 120px 净空，label 超过 6 个中文字就会把整段线盖死；只有跨行、跨多列的长边才可以写到 10 字。只给「不看 label 就会误解」的边写 label。
11. **纸色是分组，不是装饰**（节点的 `color` 字段）：
    - `sand`：主干事件节拍
    - `sage`：设定、世界规则、背景信息
    - `rose`：冲突、风险、代价、代表「要出事」
    - `stone`：元信息 —— 幕标题、备注、待办
    一张画布不超过 3 种色，主干统一 `sand`。四色全用会变成调色板，不是结构图。
12. **便签正文 1–3 行**，写清一件事就停；长内容放进资源正文，画布上只留引用节点。
13. **资源已存在就用引用节点，别抄成便签。** 引用节点更矮更整齐，用户还能点开看原文。

## 四、四个可直接照抄的模板

### 节拍时间线

```
row=-1   [伏笔]        [伏笔]
row= 0   [Beat0]─[Beat1]─[Beat2]─[Beat3]─[Beat4]     ← timeline，主干，sand
row=+1        [影响]              [代价]              ← causal，rose
```

主干先摆满（`Create /canvas/{name}/nodes`，`fields` 为 `{"type":"sticky","content":"...","color":"sand","col":N,"row":0}`），再挂上下两行，最后连边，收尾写一次 layout。

### 伏笔兑现表

```
row=-1   [伏笔A]   [伏笔B]   [伏笔C]
row= 0   [第3章]─[第7章]─[第11章]─[第15章]     ← 引用节点，节点最多 → 成为骨架
```

每条 `foreshadow_payoff` 由伏笔指向它兑现的那一章。重排会把每个伏笔挪到兑现章节的正上方 —— 你不需要自己算列。

### 人物关系星座

```
row= 0   [配角1] [配角2] [配角3] [配角4] [配角5]     ← 引用节点，节点最多 → 骨架
row=+1              [主角]                          ← relationship 连向各配角
```

单节点的那一层会被放到所有邻居的列均值上 —— 主角自然居中。别反过来把主角单独放 `row=0`，那样骨架会选错行。

### 因果树

```
row= 0   [起因]
row=+1   [结果A]  [结果B]
row=+2   [余波A1] [余波A2]
```

只用 `causal`，父在上、子在下；同一层分叉超过 6 个就分幕。

## 五、收尾

连完所有边后写一次 layout：

```json
Write {"path": "/canvas/{name}/layout", "value": "auto"}
```

返回的 `moved` 是被挪动的节点数，`0` 表示已经没有可优化的摆位。

然后**停手**。不要再逐个 Write 坐标微调 —— 手改过的节点会脱离网格，下次重排就不再参与。

## 六、交付前自检

- 主干是不是节点最多的那一行？
- 有没有一行超过 6 个节点？
- `association` 是不是超过 3 条？
- 有没有 label 超过 6 字却挂在相邻两节点之间？
- 是不是还有节点用 `x`/`y` 摆？
- 纸色是不是超过 3 种，主干是不是统一 `sand`？
- 最后写过一次 `/canvas/{name}/layout` = `auto` 了吗？

## 反模式

- 满屏 `association`：什么都连一下，等于什么都没说。
- 20 个节点排成一行：用户得横向滚三屏才看得完。
- 便签和引用节点混在同一行：行高参差，像排版事故。
- 每条边都写 label：标签互相叠住，连线全被盖掉。
- 用 `x`/`y` 精修坐标「让它更整齐」：越修越乱，且从此不参与重排。
- 凭 id 拼节点路径：id 只能从 listing 的 `entries[].path` 或 Create 响应的 `path` 复制。
- 把长段设定塞进便签正文：便签只显示前几行，剩下的白写。
