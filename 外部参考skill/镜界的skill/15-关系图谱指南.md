# 关系图谱指南

关系图谱记录实体之间的有向关系。可以先从正文抽出已经写到的关系，也可以在写剧情之前先把人物关系网设计出来。每条关系都要有 `chapter_id` 和 `proof`。

## 路径

关系没有专用的写入工具，建立走 `Create`，查询走 `GraphSearch` 与 `Read`，删除走 `Remove`。

| 目标 | 调用 |
|---|---|
| 建立一条关系 | `Create {"path": "/relations", "fields": {...}}` |
| 顺着某个实体展开关系网 | `GraphSearch {"type": "character", "id": "<id>"}` |
| 全部关系 listing | `Read {"path": "/relations"}` |
| 按条件过滤 | `Read {"path": "/relations?source_type=character&relation_type=ally"}` |
| 单条关系详情 | `Read {"path": "/relations/{id}"}` |
| 某章产生的关系 | `Read {"path": "<章节 path>/relations"}` |
| 删除一条关系 | `Remove {"path": "/relations/{id}"}` |

`Read /relations` 支持的过滤参数：`source_type`、`source_id`、`target_type`、`target_id`、`relation_type`、`chapter_id`。

**已建立的关系不可改写。** 没有 `Write` 或 `Edit` 路径 —— 要改就 `Remove` 掉再重新 `Create`。

**所有 id 都必须原样复制**，来自之前的 `Read` listing（`entries[].path`、`entries[].id`）或 `GraphSearch` 结果。不要根据角色名、ID 格式或记忆拼 id；拼出来的 id 建成的关系会指向不存在的实体。

## 必填字段

`Create /relations` 的七个字段全部必填：

| 字段 | 说明 |
|---|---|
| `source_type` / `target_type` | 实体类型，见下表 |
| `source_id` / `target_id` | 实体 id，从 Read / GraphSearch 原样复制 |
| `relation_type` | 合法值由 `source_type → target_type` 组合决定，见下表 |
| `chapter_id` | 这条关系挂靠的章节 id |
| `proof` | 关系成立的依据（正文场面或设定说明，不要只重复 relation_type） |

实体类型取值：`character`、`faction`、`skill`、`item`、`location`、`chapter`、`foreshadowing`、`creature`。

### chapter_id 与 proof

`chapter_id` 是这条关系挂靠的章节：已经在正文里确立的，填确立它的那一章（人物第 3 章相认、现在写第 40 章，仍填第 3 章）；还在设定、正文还没写到的，填计划揭示它的那一章。id 从 Read 原样复制。

`proof` 写依据，不写结论。正文里有场面就概括情节（「两人在雨夜互报家门，认出对方腕上同款胎记」）；设定阶段可以写设计依据（「同父异母，开篇尚未相认」）。「他们是兄妹」不是 —— 那是 `relation_type` 已经表达过的东西。

## 合法关系类型与方向

只有下列组合存在合法关系类型，表里没有的组合（如 `character → location`）建不了关系。`relation_type` 必须用精确的 snake_case 英文值，不接受中文。

猜错不会静默写坏数据：`Create` 会返回 `invalid_relation_type`，并把该组合的全部合法值列在错误信息里。`GraphSearch` 的 `relation_type` 是可选过滤：不知道就省略，禁止猜测；传错返回 `invalid_relation_type`，hint 列出合法值。

### 读法：`A --type--> B` 读作「A 是 B 的 <type>」

**类型名描述的是 source 的身份**，不是 target 的。建之前把这句话读出来验证一遍，读不通就是 source / target 放反了。

三类偏离这条默认读法的，下表用记号标出：

- **[对称]** —— 两端可互换，谁做 source 都成立。同一对实体只建一条，不要正反各建一条。
- **[反读]** —— 类型名描述的是 target，读作「B 是 A 的 <type>」。只有 `subordinate` 和 `alter_ego` 两个（历史约定，改了会重解释存量关系）。
- **[动词]** —— 类型名是动词短语，按字面读，source 是主语。

### character → character

| 类型 | 读作 |
|---|---|
| `family` | A 与 B 有血缘/亲属关系 **[对称]** |
| `sibling` | A 与 B 是兄弟姐妹 **[对称]** |
| `friend` | A 与 B 是朋友 **[对称]** |
| `enemy` | A 与 B 敌对 **[对称]** |
| `lover` | A 与 B 是恋人 **[对称]** |
| `colleague` | A 与 B 是同事/同门 **[对称]** |
| `parent` | A 是 B 的父母 |
| `grandparent` | A 是 B 的祖辈 |
| `master_disciple` | A 是 B 的师父 |
| `subordinate` | **B 是 A 的下属** —— A 是上级 **[反读]** |
| `alter_ego` | **B 是 A 的化身/马甲** —— A 是本体 **[反读]** |

### character → faction

角色恒为 source，方向由实体类型确定。

| 类型 | 读作 |
|---|---|
| `member` | A 是 B 的成员 |
| `leader` | A 是 B 的首领 |
| `founder` | A 是 B 的创始人 |
| `ally` | A 是 B 的盟友 |
| `enemy` | A 是 B 的敌人 |

### character → skill

| 类型 | 读作 |
|---|---|
| `learned` | A 已学会 B **[动词]** |
| `mastering` | A 正在学 B **[动词]** |
| `mastered` | A 已精通 B **[动词]** |
| `creator` | A 是 B 的创造者 |

### character → item

| 类型 | 读作 |
|---|---|
| `owner` | A 是 B 的持有者 |
| `user` | A 是 B 的使用者 |
| `creator` | A 是 B 的制造者 |
| `former_owner` | A 是 B 的前持有者 |

### faction → faction

| 类型 | 读作 |
|---|---|
| `ally` | A 与 B 结盟 **[对称]** |
| `enemy` | A 与 B 敌对 **[对称]** |
| `subordinate` | **B 是 A 的下属组织** —— A 是上级组织 **[反读]** |

### skill → skill

| 类型 | 读作 |
|---|---|
| `prerequisite` | A 是 B 的前置技能（先学 A 才能学 B） |
| `branch` | A 是 B 的分支流派（B 是主干） |
| `evolves_to` | A 进化为 B **[动词]** |

### item → item

| 类型 | 读作 |
|---|---|
| `part_of` | A 是 B 的组成部分（B 是整体） |
| `evolves_to` | A 进化为 B **[动词]** |

### creature → creature

| 类型 | 读作 |
|---|---|
| `prey` | A 是 B 的猎物 —— **B 捕食 A** |
| `predator` | A 是 B 的天敌 —— **A 捕食 B** |
| `evolves_to` | A 进化为 B **[动词]** |

`prey` 与 `predator` 互为反向，同一组捕食关系任选一个方向建一条即可，不要两条都建。

### 最容易放反的四个

- `subordinate`：**source 是上级**。张三是李四的下属 → source 填李四。
- `alter_ego`：**source 是本体**。「克莱恩」是「愚者」的本体 → source 填克莱恩。
- `master_disciple`：**source 是师父**。张三拜李四为师 → source 填李四。
- `prey` / `predator`：**`predator` 的 source 是捕食方**。狼吃羊 → `狼 --predator--> 羊`，或等价地 `羊 --prey--> 狼`。

## 建之前先查

同一对实体、同一类型的关系只建一次。动手前先 `GraphSearch` 展开 source 实体，看这条关系是不是已经在了 —— 重复建立会在图谱里堆出多条等价边，用户看到的是同一句话说三遍。

角色关系变化时（结盟转敌对、师徒决裂），不要在旧关系上叠新的：`Remove` 旧关系、`Create` 新关系，或者两条都留下但各自指向不同的证据章节 —— 前提是你能说清楚它们描述的是不同阶段。

## 反模式

- **proof 写成结论**：`proof: "他们是敌人"` 等于没写依据。
- **chapter_id 填当前章**：关系在第 3 章确立却记成第 40 章，之后按章节回查关系全乱。
- **方向随手填**：`subordinate` / `alter_ego` / `master_disciple` / `predator` 是最容易放反的四个，建之前按「A 是 B 的 X」读一遍。
- **给每对角色都连一条**：只建对情节有意义的关系，不要把角色表做成全连接图。
- **中文 relation_type**：`"师徒"` 建不了，必须写 `master_disciple`。
- **拼 id**：id 只能从 Read 或 GraphSearch 结果复制。
