# 设定文档 · 统一模板 v1

> 从属：小说设定总SOP（小说设定-SOP.md）。
> 定位：这份是所有"设定文档"共用的统一母版。每份具体设定文档（世界画像/法则/格局/主角设计…）都必须长成这个四段式骨架，再往后面填该份独有的内容节。
> 状态：模板。先套到现有四份 + 新文档，多份验证后固化，遇反例再改。

---

## 前言：为什么定这个模板

现有设定文档各自有结构（有的"产出SOP"有的"怎么生成"），但不统一，读起来要先读整篇才知道"这份变量哪、想的时候怎么想"。四段式把每一份都拆成同一个骨架，让它：

- **好查**：想知道"这份是什么"看①，想知道"怎么想"看②；
- **好产**：①-④照顺序走完就是一份完整设定；
- **好验**：SOP（④）里嵌验收基准，不再单设质量节；
- **好扩**：②思考逻辑特意留下推演痕迹，给 agent 举一反三，不只照模板填空。

---

## 统一四段式骨架

每份设定文档都从这四个 `##` 开始，顺序固定：

```
# {文档名} · {它在设定里的角色}（{锁根/骨架/展开}）

> 目录锚（一条定位 + 链路位置）

## ① 文档定位        （这份文档是什么 / 何时产 / 依赖谁 / 产出给谁）

## ② 思考逻辑        （填的时候脑子怎么转 / 挖到多深算好 / 怎么推演出来的）

## ③ 文档内容         （实际写进小说 / 结构 / 表格 / 2+跨赛道案例）

## ④ 产出SOP         （动工时一步步怎么产 / 每步产出 / 验收基准）

## （该份独有的后续节：弱世界观变体 / 与相邻设定边界 / 参考文献…）
```

`##` 下再按需分 `###`。以下逐节定义。

---

## ① 文档定位（它是什么，静态定义）

**这节只答"是什么"，不解释怎么填。**

- {锁根/骨架/展开}：它在链路里的角色（锁根=最高根，骨架=框架，展开=血肉）。
- 回答哪个问题：一句话讲清这份"回答什么"（如"这世界长啥样""强怎么构成"）。
- 链路位置：第几步？依赖谁？产出给谁？
- 一句话落点：读者/agent 用一句话能说出"这份文档管什么"。

> 判据：写完①，读者知道"这份是什么、跟谁衔接"，但完全不知道"怎么填"——怎么填是②。

## ② 思考逻辑（怎么想，动态方法）

**这节讲"填的时候脑子怎么转"，是最该被 agent 学走的部分。**

- 先想A再想B：填这份的大脑顺序，不是文档顺序。
- 判据 / 问法：挖到多深算深？用什么问法把内容逼出来（验收基准反推式）。
- **推演痕迹（关键）**：写清这份是怎么被推演出来的——比如"世界法则 = 一条能量链：基石（总能源）→ 物资（资源）→ 对抗系统（怎么赢）× 养成线（怎么长）"。**这是思考的源头，比结果更值得保留。** 它教 agent 举一反三，不只照字段填空。
- 挖多深够：合格线——填到哪一层算挖到底，不满哪层算浅。

> 判据：①是"是什么"，②是"怎么想"。一份合格的②，读的人能模仿它的思路，即使换一个完全不同的题材也能照这个推法想出来。

## ③ 文档内容（写进小说 / 结构 / 案例）

**这节是产物本体——实际写进小说的结构、表格、框架。** 关键是泛化性：

- **结构 / 表格 / 框架**：这份设定长什么样（字段、分档、条目）。
- **案例 ≥2 个、跨赛道**：用**两个以上、不同赛道**的知名书把这份结构填满（如遮天＋诡秘），证明结构不是只配一个赛道、而是通用。
  - 模板类：梦幻例子给"同类最佳"；再给一个不同赛道证明泛化（如世界画像给遮天＋深渊主宰）。
  - 每个案例填同样结构，横向对比能看出"同一个骨架，换个赛道长成两本书"。

> 判据：③读完，顺手拿一个没写过的赛道（如现代都市 OR DND），能照着结构把这份填出骨架来——证明它泛化，不只服务于原案例赛道。

## ④ 产出SOP（怎么一步步产 + 验收）

**这节是执行清单：照它走完，一份设定就产出了。** 验收直接合进来，不单设"质量要求"节：

```
## ④ 产出SOP（照做，每步带验收基准）

1. 步骤1  …  → 【验收基准】过这个才算过
2. 步骤2  …
3. …
N. 收尾  → 【验收基准】一句话读出这份管什么
```

- **每步一个验收基准**：嵌在步骤末尾，用一个"是/否"判断"这步做完了没有"。
- 验收基准是"能指认的"：不是"要合理"，是"读者能不能在地图上指出谁的地盘""能不能一句话讲清最被抢的是什么"——能指认才叫过。
- 生产与验收合一：不再有单独的"质量要求"章节，验收在每一步出现。

> 判据：照④走一遍，产出能通过每一步的验收基准，这份设定就算绿；某步过不了验收基准，回②补齐料再走。

---

## 该份独有的后续节

以上四节是所有设定文档的**强制底座**。四节之后的节按该份需要加：

- 弱世界观变体（都市/言情/纯爱用降维版）
- 与相邻设定的边界（这份和相邻份各管什么，怎么不重叠）
- **待处理问题（这份眼下还没定/存疑/待实测的，集中收在这，防技术标记散乱）**
- 深挖方法的参考来源（research 补强，列来源）
- 版本沿革 / 未实测清单

这些是"加分"，不强制；四段是"底座"，强制。

### 「待处理问题」填法

每一份设定文档，把**这张还悬着的问题**集中收在一处，避免散布成 `v6.1实验性`、`技术标记`、`未来篇` 这类散落的记号——它们全归位到这：

```
## 待处理问题（这份眼下还没定 / 存疑 / 待实测）

- [ ] 某个具体问题（如：层数偏离 3-2-1 是否合法）
      → 为什么悬着（如：真实书拗不过）
      → 等谁定（如：等真实案子实测）
```

规则：

- 每行一个**能被独立回答**的问题，不堆陈述。
- 标注它**悬在哪、等谁定**——这样后面 agent 或老板拿新案子一撞就知道"这个可以划掉了"。
- 已解决的顺手划勾，别让待办清单变成历史账。

## 模板本身怎么验收

| 验收项 | 问什么 | 合格线 |
| --- | --- | --- |
| 四段齐 | 每份是否固定有①定位②思考逻辑③内容④SOP | 是——不是"有的有有的没有" |
| ①不问怎么填 | 定位节是否不含"怎么填" | 是——怎么填全在② |
| ③有2+跨赛道案例 | 内容节是否≥2个不同赛道案例 | 是——证明泛化，不单配一个赛道 |
| ②有推演痕迹 | 思考逻辑节是否写清"怎么推演出来的" | 是——保留 agent 举一反三的可能 |
| ④验收合一 | SOP是否把验收基准嵌进每步、不再单设质量节 | 是——生产与验收同步 |

> 判定：把任何一份设定文档（世界画像/法则/格局/主角设计）套进四段，四个底座全有、验收能过，模板就成立；遇到套不进的，改模板而不是改文档。
