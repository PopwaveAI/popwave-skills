# 用词规范-SOP（所有产出通用）

> 用途：约束所有 agent 的所有产出——回复、文档、skill、PRD、报告，一律照此用词。
> 位置：`新流程探索/sop文档/` 一级目录，与立项创意-SOP、小说设定-SOP 平级。
> 消费对象：写任何文字的 agent。写完先自查，过了第 5 节再交付。
> 定位：沉淀稿。本文档自己就按这套标准写，是活样板。2026-09-09 老板实测复盘后固化。

---

## 1. 这套标准是什么（是A，不是B）

**这是一套用词规则，不是文风偏好。** 它管三件事：规则怎么写、概念怎么定义、判断怎么给。

- 它是**行为指令**：每条都能照做、能检查，不写感受评价。
- 它不反对口语，反对两类词：**自造黑话**（引擎/耦合/闭环）和**装饰性比喻**（画卷/乐章/孵化器）。
- 它不限制写法自由：短句、直说、动词开头，都鼓励。

> 判据：把本文档给没读过的人看，任何一句都能照做、不用追问，才算过关。

---

## 2. 六条书写标准

### 2.1 规则写成行为指令

写"做什么/不做什么"，一条一个动作，不写感受评价。

- 差：`保持段落结构清晰`——是感受，执行者不知道怎么办。
- 好：`叙事段 40-120 字（3-5 行手机屏）`——可执行，可检查。

### 2.2 新概念出现即定义，用"是A，不是B"锁边界

第一次出现就写清它是什么、不是什么。

- 差：`AgentSkill 管理创作流程`——没说清和规则、和小说设定有什么区别。
- 好：`AgentSkill 是应用内全局可复用的 AI 工作流程，不是作品规则，也不是故事事实`。

### 2.3 判断给基准，不给形容词

写"以什么判断"，不写"要高质量、要合理"。

- 差：`描述要准确`——怎么算准确？没有判断标准。
- 好：`60% 以上叙事段<40 字 → 段落过碎，触发返工`——有数字，可判定。

### 2.4 行业词直接用，不自造也不降格

已有的词直接叫（agent/skill.json/AskUser），不造黑话，也不改成生活比喻（管饭/撒盘边）。

- 差：`剧情引擎负责推演`——自造词。
- 好：`剧情推演在 plot 环节做`——已有的词直说。

### 2.5 一段一义，短句为主

一段只讲一件事，短句直说，动词开头，能删就删。

### 2.6 禁 AI 腔

不写：值得注意的是 / 总而言之 / 首先其次再者 / 由此可见 / 综上所述 / 在当今社会 / 众所周知。

---

## 3. 装饰性比喻黑名单（直接禁）

- 禁「XX器 / XX引擎」自我定位：`剧情引擎`→剧情推演、`画风测试引擎`→画风测试。技术命名 `-engine` 除外。
- 禁空洞流程名词：`闭环`→完成/收束/循环，`全链路`→整条流程；拼图/发生器/孵化器/熔炉/淬炼/乐章/画卷/乐高/车间/摸高 → 删掉或换直述。
- 禁装饰性比喻链：不写"构建X生态""打通X链路""结晶沉淀""保驾护航"；改成谁做了什么、产出什么。

## 4. 常用黑话替换表（写作用词，人话优先）

| 黑话 | 换成人话 |
| --- | --- |
| 落盘 | 写入/存档 |
| 消毒 | 去AI味 |
| 闭环 | 完成/收束/循环 |
| 闸/闸门 | 检查 |
| 门禁 | 检查条件 |
| 锚定/锚点 | 落点（指剧情功能时）/以X为基准（指判断时） |
| 耦合 | X类互动/绑定 |
| 引擎 | 具体环节名直说（推演/测试/生成） |
| 参数单 | 输入清单/请求内容 |
| 机器状态源 | 状态总账 |
| 回执 | 确认 |
| 注入 | 传入/喂给 |
| 沉淀 | 写成文档/存下来 |

> 固定用法例外：文档状态标签「沉淀稿」在本目录已统一使用，保留，不按表替换。

## 5. 交付前自查（验收基准）

写任何东西前，过这五问：

1. 规则句能不能照做？——每条都是"做什么/不做什么"，没有感受词。
2. 新概念定义了吗？——第一次出现都有"是A，不是B"。
3. 判断有基准吗？——有数字、有"以什么判断"，不给形容词。
4. 有黑名单词吗？——第 3 节黑名单、第 4 节替换表各过一遍。
5. 有 AI 腔吗？——第 2.6 条的词一个不出现。

> 判据：五问全过才交付。发现黑话，按第 4 节换人话；换不掉的，删掉重写。

---

## 6. 怎么维护

- 发现新黑话 → 往第 3 节黑名单加一行。
- 发现新误用 → 往第 4 节替换表加一行。
- 本文档自身违反标准 → 当场改正，本文档是活样板。
