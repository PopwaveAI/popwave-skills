# 灯塔流 × 涌现流：mirror 工作流从根子上换方向的方案对齐

> 状态：思路对齐稿，未动任何 skill。老板拍板方向：灯塔流为主候选，涌现流一并看。本文回答四个问题：当前工作流（雪花流）痛点是什么、灯塔流如何设计、和雪花流区别在哪、第一性原理优势在哪；末尾列落地影响与待对齐问题。

---

## 1. 当前工作流的根子：一次规划到底

mirror 现状（老板所称"雪花流"）的链路：

```
立项 → 需求卡（五字段）→ 故事脉络（五元素）→ 篇幅推导（总字数→卷数N→质变点N+1→地图N→矛盾N）
→ 锁根设定（世界画像/法则/格局、主角设计）
→ 卷级剧情（主线脉络→拆卷→单元循环→全书卷纲一次排完）
→ 章纲 → 写作 → 审查存档
```

根子特征：

- **一次规划到底**：从一句话想法直接膨胀到"全书 N 卷的单元表"，中间不分叉、不回头。
- **先锁后写**：写第一章之前，全书骨架已被锁死；卷纲硬约束（单元表 6 内容要素、卷级旅程弧、爽点 9 类）在全书层执行。
- **连续细化**：每个环节都是上一层下游的确定性细化，上一层定了下一层只能照填。

这个结构接近雪花法（Snowflake）的"连续放大"，本质是**设计先行 / 大纲先行**：把全书当作一个设计对象，先设计完再施工。

## 2. 痛点：认知最浅时，做最重的决策

不是"规划"本身错，是**决策时序错**。立项时对"这本书到底是什么"的认知最模糊，却要做全书最大粒度的决策（卷怎么切、每卷打谁、每单元填什么）。具体痛点：

1. **前期决策不可逆压力大**：立项锁的卷数 N、单元表、质变点，写起来发现不对，返工成本极高（SOP 自称"核心设定锁根，近乎不可逆"）。
2. **信息稀释**：认知最浅时铺最多的设定；大量规划内容（单元表、伏笔台账）可能永远用不上——书写扑了、方向变了，前期投入全废。
3. **临场性死亡**：写章期本应"临场造"，骨架已锁死后只能照填，人物和情节的涌现空间被框架焊死。
4. **读者验证滞后**：网文的命根子是开篇三章能不能留人，当前流程把它排到最后（opening 在 plot 之后），先把几十万字世界观定完才写——产品验证被无限推迟。
5. **变更传导难**：写 20 章后想调主角，全书卷纲、单元表、伏笔台账全要联动改。
6. **token 浪费**：规划了一堆用不上的东西，AI 长连载每本书都是这个成本。

共同根子一句话：**决策时机和信息量错配——在信息量最小的时刻，做信息量要求最大的决策。**

## 3. 第一性原理：延迟锁定（just-in-time locking）

网文长连载的稳定性，来源不是"全书大纲"，是两个东西：

- **根**（不可变的小集合）：主角立身、世界内核、结局方向、风格承诺——定义"这本书是什么"，必须立项锁死。
- **连续性账本**（可变的记忆）：已发生的事实、已建立的设定——保证后文不打架。

规划的价值 = 预测的准确度；规划的代价 = 决策时的信息量（越早越少）＋ 锁死后的弹性丧失。

**最优策略不是"一次规划到底"，而是"信息量足够时才锁"——延迟锁定**：

- 锁的时机 = 该决策能用上的最新时刻（写到这一卷之前，才有这一卷的真实信息）。
- 锁的粒度 = 即将被消费的粒度（要写卷纲才定单元，要写章纲才定节拍）。
- 没锁的保持开放，允许涌现、允许后补（伏笔可以回溯埋设，账本支持）。

## 4. 灯塔流设计：根 + 方向总表 + 滚动规划 + 账本

**灯塔（立项只锁四样）**：

1. 主角立身三件（什么人 / 凭什么脱颖而出 / 读者记住什么）。
2. 世界内核（双层失衡一句话：旧失衡被压＋新失衡撕破）。
3. 结局方向（从 X 翻成 Y 的质变，不锁路线）。
4. 篇幅量级（总字数量级 + 卷数量级，如 8-12 卷的方向，不锁死切法）。

**方向总表（半固定，全书只有这一张）**：每卷一句话——质变点 ＋ 卷末对手 ＋ 爽点类型标签。只到"方向"，不到"单元"。这张表就是灯塔的灯柱序列，保证长篇不迷失、卷末不悬空。

**滚动规划（弹性，只细化即将写的部分）**：

- 卷级：只有"当前卷 ＋ 下一卷"细化卷纲（单元表 / 旅程弧 / 6 内容要素），写卷纲时才执行卷级硬约束。
- 章级：只有"当前章 ＋ 接下来几章"细化章纲。
- 写完一卷，回看账本 + 方向总表，再定下一卷的卷纲。

**账本（兜底）**：小说日志（白描卡 / 状态快照）＋ review 三源审查——已发生的事实只从账本取，后文引用不回看前期规划；伏笔在账本上标注"跨卷钩子"，随时可补。

流程变成：

```
立项（只锁根 + 方向总表一句话）→ 黄金三章/开篇（读者验证前置）
→ 卷循环：细化当前卷卷纲 → 章纲 → 写作 → 审查存档 → 回看账本 → 定下一卷
```

## 5. 灯塔流 vs 雪花流（差异表）

| 维度 | 雪花流（当前） | 灯塔流 |
|:--|:--|:--|
| 决策时机 | 认知最浅时做全书最大决策 | 延迟锁定：信息足够才锁 |
| 全书大纲 | 立项即定（N 卷单元表全排完） | 只定方向总表（每卷一句话） |
| 卷纲 | 全书一次性排完 | 滚动：当前卷 + 下一卷 |
| 规划粒度 | 自上而下连续细化到底 | 上锁下滚：只细化即将写的部分 |
| 可逆性 | 前期决策近乎不可逆 | 方向总表随时可调，只沉没已写内容 |
| 连续性保障 | 靠前期规划（伏笔台账） | 靠账本（已发生事实）+ 审查 |
| 失败成本 | 前期规划全部作废 | 只有已写的内容沉没 |
| 临场空间 | 单元表焊死 | 章纲临场做，涌现与后补允许 |

一句话：雪花流是"连续细化"（一层套一层到底），灯塔流是"分层锁定"（按信息量分级锁，锁了就稳定，没锁的保持开放）。

## 6. 涌现流设计（先写后补）

**涌现流（pantser / discovery writing）**：不设全书大纲，从黄金三章直接开写，设定靠 review 边写边回填。

设计：

- 只锁两样：主角立身一句话 + 文风承诺（没有这两样没法下笔）。
- 黄金三章先行：直接写，把"这本书的味道"试出来——人物自己长，情节自己冒。
- 回填：每写完一章，review 把新事实回填账本，设定从账本里长出来（不是事前设计）。
- 方向感：可留一个模糊灯塔（结局方向一句话），但不设路线、不排卷。

风险：

- 长篇崩率高：没有卷级方向，中期容易迷失、卷末悬空。
- 连续性压力全压给 review：每一章都要和账本对，审查环节变成瓶颈。
- 收益：活感最强，人物行为不受框架绑，开篇最快。

## 7. 灯塔流 vs 涌现流：怎么选

- 共同点：都反对"立项定全书"，都把写作的涌现空间还回去。
- 区别：灯塔流仍要方向总表 + 滚动卷纲（有结构、有节奏、有卷末对手）；涌现流完全不设路线（纯临场）。
- 定位：**灯塔流是涌现流的"安全版"**——保留涌现弹性（只锁根、滚动规划），加上方向锚（方向总表、卷末对手）防止长篇迷失。
- 建议：AI 长连载走灯塔流（稳定兜底）；涌现流适合单卷试味、中短篇、或人工操作。两者不互斥：灯塔流的"当前卷"内部可以局部涌现。

## 8. 落地影响清单（仅列，未动手）

当前 mirror 环节在灯塔流下的改动方向：

- **onboarding**：删篇幅推导的"N 卷锁死"语义，改为量级方向；方向总表（每卷一句话）可能在此或 plot 首轮产。
- **plot（卷级）**：从"全书卷纲一次排完"改为"滚动两卷"；单元表/旅程弧/爽点硬约束降为卷级细化时执行。
- **outline / write / review**：基本不动；review 的账本职责加重（状态快照承载方向总表进展）。
- **剧情产出-SOP / 篇幅与卷规划-SOP**：卷定义与 N 推导的"锁死"语义改为"量级方向"。
- **小说日志**：状态快照升级为"账本"（含方向总表进度、跨卷钩子）。
