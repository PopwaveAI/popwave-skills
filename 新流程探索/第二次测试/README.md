# 第二次测试 · 多赛道零上下文直出

## 这次测什么

不给任何项目上下文，只发一句话，让模型直接写某个赛道的小说第一章。目的是量两个数：

1. 模型"裸直出"的文笔自然度水位，对比人类作者产出平均数。
2. 各赛道之间的差异，看哪些赛道是模型自带腔调就够，哪些必须外部固化撑。

## 和第一轮测试的区别

| | 第一轮（链路测试） | 第二轮（直出测试） |
|:--|:--|:--|
| 输入 | 立项＋设定＋章纲＋文风 DNA | 一句话 |
| 测的是 | 整流水的产出质量 | 模型自身的水位 |
| 变量 | 多，层层叠加 | 只留模型和参数 |

## 怎么用

```
python run_test.py --dry-run     # 只看计划，不花钱
python run_test.py --smoke       # 冒烟：跑 1 稿，确认链路通
python run_test.py               # 按 .env 跑全部
python run_test.py --genres 武侠,克苏鲁航海 --runs 5
python run_test.py --no-skip     # 已有稿子也重跑
```

参数和赛道清单都改 `.env`，改完直接跑，不用改脚本。

跑完之后两步收尾：

```
python analyze.py                # 出对比表（--detail 看逐稿）
python merge_md.py --clean-txt   # 合成 md，并删掉中间 txt
```

`merge_md.py` 只在 md 确实写出来、而且稿数对得上时才会删 txt。以后想留着 txt 就不加 `--clean-txt`。

## 目录里有什么

| 文件 | 作用 |
|:--|:--|
| `.env` | API key、模型、生成参数、赛道清单。**不进 git** |
| `.env.example` | 模板，不含真 key |
| `run_test.py` | 跑稿主脚本 |
| `analyze.py` | 读 manifest 出对比表 |
| `merge_md.py` | 把每个赛道的多稿合成一个 md，可选顺带清掉 txt |
| `输出/manifest.jsonl` | 每次调用的参数、耗时、token 用量、文本形态指标 |
| `输出/{模型}/{赛道}/{赛道}.md` | 该赛道全部稿合成一份，正文＋折叠的思考过程 |

中间产物 txt 默认在合成后清掉，`manifest.jsonl` 里 `file` 字段指的还是旧路径，看的时候按 `{赛道}__r{NN}__raw.txt` 这个名字去 md 里找对应那稿就行。

## 两个关键设置

**`SEND_SYSTEM_PROMPT=0`** 是这次测试的核心开关。设 0 就完全不发 system message，只有一句 user prompt，这是"真·零上下文"。设 1 会把 `SYSTEM_PROMPT` 发过去——想测"带某段提示值多少钱"时用它做对照。

注意：应用内那条路径（点界面直出）做不到真正零上下文。我核过日志，武侠那一轮的请求里带了 7 个提示模块，`SOUL.md` 里那张"网文写作模式"六行表是进过上下文的。所以**应用内直出和这里的 API 直出不是同一个口径**，两组数据要分开看，别混着比。

**赛道成对设置**。清单里 1-2、3-4、5-6、7-8 是配对的，左边中文语料饱和，右边长尾。上一轮"武侠直出好看"这件事，很可能有相当一部分是武侠在中文语料里最饱和。不做成对，测出来的差异会分不清是"模型强"还是"语料多"。

## 评分前必须做的两件事

**第一，看形态指标再评。** 每稿都自动量了半角引号数、markdown 标记数、破折号数。上一轮有一份直出稿混进了 64 个半角引号和 8 处 markdown 加粗，读起来刺眼，但那不是文笔问题。评文笔要看 `__clean.txt`，形态单独记一笔。

**第二，去掉来源标记再评。** 同赛道的稿子打乱、隐去模型名和稿序，最好再混进 3 到 5 本人书的开篇段落作基准。否则"这是 deepseek 写的"会先入为主。

`manifest.jsonl` 里有一栏 `tail_chatter`，标记这稿结尾是不是挂了模型的助手话术（比如"要不要接着往下写"）。评之前先把它裁掉。

## 已知坑

- 半角引号在 raw 输出里很常见，这是模型原生写法，不是坏事，但读之前先过 `__clean.txt`。
- 思考模型会在 `reasoning_content` 里返回思考过程，脚本会单独存成 `__thinking.txt`。思考过程是重要证据（上一轮那 9399 字符的思考块里能直接看到方案否决和选型），别丢。
- `max_tokens` 设的 8000，写 3000 字章节够用。如果发现稿子被截断（`finish_reason` 是 `length`），往上加。
