# 批量文字改造 · 改造须知

> 本文件是执行每个 skill 改造时的唯一作业标准。开工前必读，改完按第八节自检。
> 立此文件的原因：`pop-write` 已完成样板，后续 42 个 skill 照同一个标准执行。

## 一、目的

清掉规程文字里的**语病**与**语域降档**。不改条款内容、不改文档结构、不动机器可读件。

为什么要改：进上下文的文字会被正文调用当作形态样本来放大。规程带病，正文跟着带病。

## 二、开工前必读（定标准用）

`d:\popwave-skills\新流程探索\第二次测试\pop-write改写\` 下三份，读完全部再动手：

1. `SKILL-改后.md` —— 书面语版的样子，改完的语域要跟它一致。
2. `改动清单-上.md`、`改动清单-下.md` —— 逐句四列对照（原文｜改后｜语域修正｜病类），看清颗粒度。

## 三、只改什么

**只改 skill 自己的规程与说明文字**：规程句、判据句、流程叙述句、字段说明句、命令前后的说明文字。

**判断只有一个：这句话压缩了吗？** 压缩了就展开成完整句子（补主语、补动作、把生造词换成平常说法），同时把语域收到书面。没压缩就原样留着。

## 四、三样不许动

1. **条款内容与结构**：不新增条款、不删除条款、不合并章节、不调换段落顺序、不改表格列。
2. **机器可读内容**：路径、命令、脚本名、字段名、枚举值、数字阈值、占位符（`{NNN}`、`{情绪}·{分值}`）、库条目、数据行。
3. **禁改文件**：`skill.json`、`scripts\**`（`.py`/`.ps1`/`.json`）、`CHANGELOG.md`、`agents/*.yaml`、`assets/**`、根 `README.md`/`QUICKSTART.md`/`faq.md`、`_meta.json`、任何 `.json`。

## 五、段级边界（改的文件里，这些段落不碰）

- **逐字原样素材**：`pop-write/references/夜无疆.md`、`微微一笑很倾城.md` 的例文与 blockquote；各包的 `长档样例-*.md`。
- **库条目与数据行**：情绪打分表的锚定剧情行、套路库条目、内容模板库条目、番茄标签库条目、世界观与力量体系模板库条目。**只清说明文字与消费纪律，不动条目本身。**
- **禁词表数据**：被列的禁词本身。
- **代码块内的命令、路径、字段名、阈值。**
- **术语与枚举**：情绪名、钩子 6 类、爽点 9 类、`去AI味:{档名}|PASS`、`{情绪}·{分值}`。
- **历史记录段**：`## 来源`、`## CHANGELOG` 一类只记来龙去脉的段落不改，只登记在清单里注明"未改，理由：历史记录"。

## 六、语域纪律（书面语，不是口语）

| 禁 | 改 |
|:--|:--|
| 你自己、你要 | 无主语祈使句，或"本环节""该步骤"作主语 |
| 看着办、点了事、搞定、一坨 | 酌情处理、读取了事、完成 |
| 四样东西、几道 | 四项输入、数项 |
| 落盘、消毒、跑一遍 | 写入、去 AI 味、执行一次 |
| 写死、挑一份、点开看 | 固定、择取一份、按需查阅 |
| Know-Gap、Pack、Worth、Deepen、SOP、宿主、直执、重铸、分层消费、解剖维度、语感主师、锚定、蒸 | 换成中文平常说法，或展开成一句完整的话 |

硬约束用「须」「不得」；一般说明用陈述句。

## 七、两条格式纪律

1. popwave 的 `SKILL.md` **没有 frontmatter**。不得新增 frontmatter，不得改首行 `# 标题`。
2. 小段用 Edit，全量重写用 Write（Write 前先 Read 全文）。

## 八、判定与自检

改每一句时问三问，改完抽检也问三问：

| 问 | 不通过 | 通过 |
|:--|:--|:--|
| **谁**（主语在不在） | 「缺了取、别硬写」 | 「取材成功即采用；取材失败，不得勉强成文」 |
| **做什么**（动作在不在） | 「心智前置·意识层」 | 「动笔前须完成的检查」 |
| **凭什么判断**（依据或正反例在不在） | 「描述要准确」 | 「超过六成不足四十字，判定为 FAIL」 |

改完跑一遍反例扫描，下列词应为 False：

```
Know-Gap|Pack|Worth|Deepen|SOP|宿主|直执|重铸|分层消费|解剖维度|语感主师
看着办|点了事|搞定|一坨|你自己|写死|资料门|落盘|消毒|跑一遍|挑一份|点开看|四样东西|你要
```

三段合起来就是第六节语域纪律表的全部词，一段不落。批4-5 教训：只扫生造词表会漏掉语域表里的词（`写死`、`资料门` 曾漏网）。

命中不等于违规，先看落点：落在**库条目、术语名、枚举值、代码块、历史记录段**的，按第四、五节保留，登记在清单的「未改动」里；落在**说明文字**的，改掉。

## 九、产出与落点

每个 skill 产出两样，落在 `d:\popwave-skills\新流程探索\第二次测试\批量文字改造\{skill名}\`：

1. `SKILL-改后.md`（或对应文件名-改后.md）—— 改后全文。
2. `改动清单.md` —— 四列逐句对照：原文｜改后｜语域修正｜病类。改动超过 80 个单元时拆成 `改动清单-上.md` 与 `改动清单-下.md`。

**不要覆盖 skill 目录里的原文件。** 覆盖、git 提交、C 盘同步由主流程统一执行。

## 十、落盘必校验

改完用 PowerShell 的 UTF-8 回读，检出改动独有的关键字符串：

```powershell
$c = Get-Content -Path "改后文件绝对路径" -Raw -Encoding UTF8
$c.Contains("本次改动独有的关键字符串")   # True = 真写进磁盘
```

禁止用默认编码的 `Select-String`，禁止只信工具返回的"成功"回执。
