# pop-visual-cover

> 网文封面与场景视觉资产生成器。两种起点，同一个终点。v2.0.0：将 steps 四部分全部合入 SKILL.md 单文件并精炼，规程全内联。完整版本历史见 [CHANGELOG.md](CHANGELOG.md)。

## 做什么

输入：小说项目文件、视觉需求（封面、场景图或素材）与可选的参考图或原文。
输出：生成的图片或视频、设计方案文档与提示词记录。

核心价值：帮助用户把模糊的画面变成可执行的参考图与参考点，再翻译为模型提示词。**两道用户对齐门禁**确保方向不跑偏。

**三段流程**：
1. 用户意图 →（意图分析加 Pinterest 搜索，或走原文理解管线）→ **门禁A：选图并对齐参考点，或理解确认**
2. 参考图与参考点 →（设计画面差异）→ **门禁B：方案对齐**
3. 确认方案 →（参考点驱动提示词策略）→ API 生成

## 模型说明

| 生成内容 | 工具/方式 | 说明 |
|:-----|:---------|:-----|
| 静态图片（Seedream 5.0 Pro） | `image_generate` 工具 | 文生图/图生图/多图输入，无 API Key |
| 动态视频（Seedance 1.0 Pro） | `generate.py video` | 需显式设置 `ARK_API_KEY` 环境变量，不内置 key |

Seedream 5.0 Pro 画面不再泛白，简洁精确优于堆砌。支持文生图、图生图、多图输入。文字用双引号包裹。

## 执行模式

**门禁交互由主 agent 直接执行，只读侦察可派发子 agent**：门禁A（选图对齐或理解确认）与门禁B（方案对齐）是用户多轮交互确认环节，由主 agent 直接执行；Pinterest 搜图与图片分析、原文解构与上下文补全（WebSearch）等只读类工作可派发子 agent 执行并回报结果，再由主 agent 整合写入；提示词翻译与生成执行属于工具调用，由主 agent 直接执行。

## 怎么运作（规程全内联）

### Step 0: 意图分析、搜图与选图对齐（封面/素材模式）

**模式分支（开始前先判定视觉模式）**：用户提供小说原文，或说"场景图/场景画面/原文场景"时，进入**场景图模式**，走 Step 0-Scene 理解管线（不走 Pinterest 搜图）；其他情况（封面或素材）继续本步。

**设计哲学**：封面设计的起点不是"分析小说"，而是**理解用户想要什么样的视觉感觉**——用户脑中可能已有画面却说不清楚，agent 的任务是帮助用户把模糊的画面变成可执行的参考图与参考点。**参考图是设计的起点，不是辅助**：先搜图、选图、对齐参考点，再出方案——参考图决定设计方向，不是方案定了再找图配。

**1. 用户意图分析**：

- **提取视觉意图**：赛道、**IP 背景**（是否基于已有 IP？源 IP 是什么？）、气质关键词、目标读者画像、视觉类型（封面、场景图或素材）、视觉模式、书名。**IP 背景是意图分析的第一维度**——无法从书名和描述判断是否同人时，**须问用户**："这本小说是否基于某个已有 IP？"（同人或改编的视觉设计须以源 IP 视觉 DNA 为基准，或有意偏离，详见 `references/novel-visual-design.md` §IP 背景理解）
- **同人或改编的 IP 视觉 DNA 提取**：若 `素材/视觉资产/IP视觉DNA.md` 已存在（pop-visual-asset 产出），则直接读取并跳过搜索；否则依次执行：①识别源 IP（从书名、角色名或世界观术语）；②用 WebSearch 搜索 `[源IP名] official art style character design`；③提取 4 个维度的视觉 DNA（源 IP 画风、角色经典形象、世界观视觉符号、标志色）；④在 Pinterest 搜索中加入 IP 维度（以源 IP 官方美术作为参考图候选，如 "One Piece fanfiction cover art"）；⑤决定设计方向：以源 IP 画风为基准，或有意偏离（如"海贼王同人但走暗黑写实"，以海贼旗、恶魔果实纹路等世界观符号为基准，偏离原作画风）。
- **视觉模式判定**：提到"封面/上架/书架"时进入封面图模式（视觉钩子驱动，书名是营销工具）；提到"场景/氛围/概念图/参考图"时进入普通素材模式（纯视觉，无文字要求）；未明确时询问用户。判定后在门禁A 呈现时**明确标注视觉模式**，让用户确认。
- **目标读者画像（这一步决定画风方向）**：同一赛道下，不同读者画像对应的画风完全不同——12-18 岁少女→日系动漫卡通可爱（"精致动漫风格，可爱明亮"）；18-25 岁女性→韩系唯美精致插画（"韩系数字插画，唯美精致，韩剧海报质感"）；25-35 岁女性→精美写实电影质感（"精美写实风格，电影海报质感，成熟精致"）；男性读者→暗黑热血概念艺术（"概念艺术风格，视觉冲击力强"）。**检查条件：无法判断目标读者画像时，须问用户"你的目标读者是哪个年龄段"，不得默认"甜宠就等于可爱卡通"**——18-35 岁女性读者期待的甜宠是韩剧唯美质感，不是儿童读物插画。
- **关键词理解**：抽象词（邪典、暗黑、帅气、恐怖、诡异、治愈、热血）用 WebSearch 搜索视觉化定义：`[抽象词] 视觉设计 特征` 或 `[抽象词] 风格 类型 分类`。

**2. 搜图方案**：

- **拆分搜索维度**（从用户意图拆出 2 至 3 个维度）：**风格维度**（抽象氛围词，必搜的核心维度，如 `sweet romance novel cover aesthetic`）、**角色维度**（角色身份、职业或特征，封面有角色时搜，如 `billionaire romance couple book cover`）、**IP 维度**（用户提到的 IP 名，有 IP 指向时必搜，如 `black myth wukong character art`）。无 IP 指向时用"角色加风格"两维；有 IP 指向时三维全开；**总量控制在 6 张以内**。
- **同一维度多表达并行**：每个中文概念翻译成 **2 至 3 个不同的英文表达**，每种搜 1 至 2 张——Pinterest 是视觉搜索引擎，同一中文概念用不同英文表达时返回的子方向差异极大（如"甜宠"→`korean romance novel cover design` 韩系暖色温馨、`sweet romance book cover aesthetic` 欧美清新明亮、`romance couple sunset illustration` 氛围梦幻光效；一轮 3 个表达即一次覆盖概念的多个子方向）。
- **执行搜索**：
  ```powershell
  $env:BRIGHTDATA_API_KEY="<key>"
  python "../pop-visual-shared/scripts/pinterest_search.py" "[英文表达]" --max-results 2 --download --limit 2 --output-dir "[输出目录]"
  ```
- **图片分析**：对下载的每张 Pinterest 图用 Read 工具查看，提取画风、构图与配色特征，并标注**所属维度与子方向**。

**3. 🚪 门禁A：选图并对齐参考点（强制暂停点，不得跳过）**：

- **呈现参考图**：给出参考图列表（图片、所属维度、风格特征一句话、子方向）与小说核心（赛道、目标读者与审美偏好、核心卖点一句话 USP），请用户选一张最喜欢的，然后告知"你参考它的什么？"
- **对齐参考点（核心环节，不固定选项，由用户选择，可多选）**：□全面参考（整体感觉像这样，但不是照抄——保留画面主体，改书名和必要差异）□色系（颜色、色调）□构图（布局、空间层次、人物位置）□画风（笔触、质感、色彩系统、光影氛围、人物精致度）□光影氛围（光效、氛围、空气感）□字体风格（字体类型、排版风格）□其他。**用户的选择决定后续设计方案与提示词的写法。**
- **不得自主进入 Step 1**，须等用户明确回复参考点。回复的处理方式："选 pin_003，只要色系和构图"→记录组合参考点，进入 Step 1；"都不太满意，再搜一下 X 风格"→补充搜索，更新呈现后重新等待；"我喜欢 pin_003 的色系加 pin_005 的构图"→记录多图参考点，进入 Step 1。
- **写入**到 `_过程/提示词记录.md`：用户意图（赛道、目标读者、核心卖点、气质关键词）、Pinterest 参考图表（图片文件、所属维度、搜索表达、风格特征）、用户选择（选中参考图、参考点、提示词策略）与用户反馈。

### Step 0-Scene: 原文理解管线（场景图模式）

**设计哲学**：场景图的核心不是"生成"，而是**"理解"**。封面图从"用户想要什么感觉"出发——Pinterest 搜图、选图、对齐参考点；场景图从"这段文字在讲什么"出发——解构原文、补全上下文、选取瞬间。**理解不到位时，提示词再精确也是"精确地画错了"。** 原文是文学叙事，画面是视觉叙事，从文学到视觉须经过理解层。

**0. 视觉资产检查（优先路径）**：如果 `pop-visual-asset` 已提取过资产，可直接读取以加速理解管线。用 LS 扫描 `素材/视觉资产/`：

| 资产文件 | 消费方式 | 替代的原流程 |
|:---------|:---------|:-------------|
| `场景资产表.md` | 读取可定格帧清单→原文解构直接引用已有帧，跳过手动拆帧 | 动作序列分解 |
| `[角色名]角色档案.md` | 读取维度二（外貌演变）与维度九（视觉设计参考）→角色规格直接引用 | 角色视觉规格提取 |
| `视觉符号库.md` | 读取标志色、器物与意象→供环境元素和材质细节参考 | 环境元素清单与材质细节库 |
| `IP视觉DNA.md`（同人时） | 读取 4 个维度的 DNA→供上下文补全的 IP 背景参考 | 热门 IP 路径的 WebSearch |

资产完整性校验：帧清单是否覆盖用户指定的章节范围｜角色档案的维度二与维度九是否有内容｜文件头部是否有"采样范围"标记。资产缺失时回退到原流程（原文解构与 WebSearch），并提示用户可先运行 `pop-visual-asset`。

- **优先读取 `素材/视觉资产/` 下的资产文件**（pop-visual-asset 产出）：场景资产表用于帧解构，角色档案用于角色规格，视觉符号库用于环境材质，IP视觉DNA 用于 IP 背景。
- **角色本体身份以 `pop-visual-art-bible` 产出的「美术设定集·人物篇」为唯一真源**：封面只要出现角色，就读取 `素材/美术设定集.md` 的人物篇作为角色本体（剪影、色彩、细节、记忆落点、冻结提示词），本模式只负责把角色放进封面构图，**不得重建角色身份**。美术设定集缺失时，提示先执行 `pop-visual-art-bible`。
- **档位说明（cover 意图即轻量基建）**：Pipeline 语境下，cover 只须基建到美术设定集即可派生，**不强制双角度定妆**；如需角色参考图，使用 art-bible 产出的**单张**定妆图作为图生图参考即可。
- 有资产时，原文解构变为"从资产帧清单中选取并补充"，上下文补全可直接引用角色档案的维度四（人际关系）与维度七（他人评价）。

**1. 原文解构**（把原文从"文学叙事"拆解成"视觉素材"；已读场景资产表时变为"从资产帧清单中选取并补充缺失帧"）：

- **动作序列分解**：把原文的连续动作拆成可定格的帧（帧编号、动作内容、涉及角色、视觉要素）——不是所有帧都适合绘制，后续 §3 选取最佳帧。
- **角色视觉规格提取**：提取每个角色的外观规格（衣着、体型、姿态、材质、异变、发光等特殊特征、情绪与动作状态）；原文只提供部分信息，缺失部分在上下文补全中查找。
- **环境元素清单**（元素、前景中景远景位置、视觉特征）与**材质细节库**（材质、原文描述、颜色质感透明度、是否发光流动变化）。
- **安全转换（内容审核预检）**：检测原文中可能触发 AI 内容审核的描述，转换为视觉等效但安全的表达。常见规则如下——"无头/断头/脖颈以上空空"→"面部完全隐入兜帽阴影中，看不见面容"；"裸露胸口有裂隙"→"胸口有发光的裂纹纹路"；"沾满鲜血"→"手上覆着金色粉末或光尘"；"尸体/残肢"→"散落的光尘或消散的轮廓"；"异变肉体"→"衣袍下隐约透出非常态的光芒"。**原则：保留视觉氛围（诡异、神圣、危险），只替换触发审核的具体描述。** 转换结果在门禁A 呈现，让用户确认；用户可否决转换并要求保留原描述（生成时可能触发审核拦截，须告知风险）。

**2. 上下文补全**（原文无法提供的信息通过外部来源补全——小说是有上下文的：角色是谁、前因后果、读者印象与文字体验决定画面怎么画）：

- **分级判定**（用书名与角色名搜索）：百科、NGA 或知乎有讨论时为热门网文（agent 自动进行网页搜索）；搜索结果少于 3 条时为冷门网文（agent 搜索并由用户补充缺失信息）；无搜索结果时为原创小说（从项目文件读取或由用户输入）。
- **热门 IP 路径**（网页搜索）：

| 搜索目标 | 搜索关键词模板 |
|:-------------|:-------------|
| 角色身份（定位、身份、能力） | `[书名] [角色名] 角色介绍` |
| 场景上下文（前因后果、场景含义） | `[书名] [章节号/情节关键词] 剧情 解读` |
| 读者印象（读者对角色的感情） | `[书名] [角色名] 读者评价` |
| 小说基调（整体氛围、文风特点） | `[书名] 书评 风格 氛围` |

> 搜到社区讨论（NGA、知乎、贴吧）时优先提取，读者原话比百科总结更有参考价值。
- **冷门 IP 路径**：先执行上述搜索，搜到多少用多少，缺失的关键信息向用户提问（"[角色A]在书里是什么定位？读者对他什么感情？这个场景前面发生了什么？后面会怎样？这段文字想传达什么体验？"——用户可简短回答）。
- **原创小说路径**（从项目文件读取，如有写书 pipeline）：角色设定查 `设计/角色库` 或 `设定/人物`；世界观查 `设计/力量体系.md` 与 `设计/动力引擎.md`；剧情查 `卷纲` 或 `产出/剧情累计卡.md`。无项目文件时直接向用户提问（格式同冷门路径）。
- **补全后形成上下文信息清单**：角色身份、前因后果、读者印象、文字体验、小说基调（每项标注来源：web、用户或文件）。

**3. 叙事瞬间选取**（基于 §1 解构的帧与 §2 补全的上下文，选取**最该绘制的那个瞬间**）：

- **帧评估**：对每一帧评估叙事含义、情感强度、视觉潜力与读者共鸣（各 1 至 5 分）。
- **选取原则**：选帧不是选"最好看的画面"，而是选**最能传达这段文字核心体验的瞬间**——情感峰值（这段文字的情感最高点在哪一帧）｜叙事关键（哪一帧承载最核心的叙事信息）｜读者共鸣（读者读到这里最想"看到"哪个画面）｜视觉张力（哪一帧构图潜力最强）。**典型选择：动作交接点（前一动作刚完成、后一动作将开始）通常视觉张力最强——既保留前因的暗示，又预示后果的方向。**
- **选取结果**：选定帧、选取理由、叙事含义与情感基调。

**4. 🚪 门禁A：理解确认（强制暂停点，不得跳过）**：场景图的门禁A 不是"选图加对齐参考点"，而是**理解确认**——向用户呈现 agent 对原文的完整理解，让用户确认或纠正（方向跑偏的根因不是生成能力不够，而是理解偏差）：

呈现理解报告——原文引用｜角色身份（每个角色：身份、定位与读者印象）｜场景上下文（前因、这段文字在讲什么、后果）｜文字体验（这段文字传达的核心情感与氛围）｜选定瞬间（帧描述与选取理由）｜安全转换（如有：原文→安全描述与视觉等效说明）｜视觉元素清单（角色、环境、材质、光源），请用户确认或修正。

**不得自主进入 Step 1。** 回复的处理方式："理解正确，继续"→记录并进入 Step 1｜"身份不对"→修正并更新报告｜"不要选这帧，选另一帧"→更新选定帧｜"安全转换不对，原文就是这个意思"→保留原描述（告知审核风险）｜"补充一下上下文"→补充并更新报告。

写入到 `_过程/提示词记录.md`：原文、角色身份、场景上下文、文字体验、选定瞬间与理由、安全转换、视觉元素清单、用户反馈。

**5. [可选] 视觉风格参考搜索**：理解确认后可执行 Pinterest 搜索以获取视觉风格参考——艺术风格（`[小说基调] concept art` 或 `[赛道] scene illustration`）｜角色形象（有 IP 且已有形象时：`[角色名] fanart` 或 `[书名] character art`）｜场景参考（`[场景类型] concept art` 或 `[环境关键词] illustration`）。搜索到的参考图作为**风格参考**（类似封面图的参考点即"画风"），不是画面内容的来源——画面内容由理解层决定。结果呈现给用户选择（同封面图门禁A 的选图流程），选定后记录参考点即画风。

### Step 1: 设计方案（基于参考图+参考点 / 场景图基于理解层产出）

**设计哲学**：不是"从零设计一个画面"，而是**基于参考图与参考点，设计需要改动或差异化的部分**——把"参考图保留什么、自己改什么"翻译成用户能看懂的方案。

1. **读取选图记录**：读取 `_过程/提示词记录.md` 的「选图与参考点记录」，提取选中参考图、参考点、提示词策略与用户意图（赛道、目标读者、核心卖点）。
2. **视觉模式决定设计方法论**（按 Step 0 判定的视觉模式读取对应模式文件）：

| 视觉模式 | 设计方法论 | 必读文件 |
|:---------|:---------|:---------|
| 封面图 | 视觉钩子设计（6 种钩子类型与构图骨架库） | `references/mode-cover.md` 与 `references/novel-visual-design.md` 全文 |
| 普通素材 | 纯视觉设计，无文字约束 | `references/mode-scene-art.md` |
| 场景图 | 整体性视觉设计（基于理解层产出） | `references/mode-scene.md` 与 Step 0-Scene 理解层产出 |

> **场景图设计要点**：设计输入是理解层产出（选定瞬间、视觉元素、上下文、情感基调），不是参考图与参考点；设计方法为：构图方案（角色站位、视线、空间纵深）→光影方案（光源方向、色温、明暗分配）→色彩方案（主色、辅色、点缀）→焦点设计（第一眼看哪、视线如何流动）；若可选风格参考搜索中用户选了 Pinterest 画风参考图，则参考点即画风，提示词在画风维度放权。**与封面的关键区别**：封面基于"参考图差异"设计，场景图基于"理解层转化"设计。
3. **参考点决定设计范围**（参考点维度交给参考图，设计方案不需要描述）：

| 参考点 | 设计方案需要描述的 | 不需要描述的（交给参考图） |
|:-------|:-----------------|:-------------------------------|
| 全面参考 | 仅需要改的部分（书名与必要内容差异） | 画面、色系、构图、画风、光影、字体 |
| 色系 | 画面内容、构图、画风、光影、字体 | 配色 |
| 构图 | 画面内容、配色、画风、光影、字体 | 构图布局 |
| 画风 | 画面内容、构图、字体 | 画风质感（笔触技法、色彩系统、光影氛围、人物精致度） |
| 光影氛围 | 画面内容、配色、构图、画风、字体 | 光源设计 |
| 字体风格 | 画面内容、配色、构图、画风、光影 | 字体类型、排版风格 |
| 色系与构图 | 画面内容、画风、光影、字体 | 配色与构图 |

4. **设计画面内容差异**（参考图中没有但封面需要的元素）：**书名文字**（内容、分行方式、大致位置，字体风格交给参考图或用户指定）｜**内容差异**（参考图是海滩漫步但小说是都市客厅→设计场景替换；参考图已贴合小说场景→可能只需换书名）｜**视觉钩子**（从小说 DNA 推导出的独特卖点如何融入或替换参考图画面）。**检查条件：参考点为全面参考时，设计方案应尽量少改动参考图画面，最多改书名加少量内容差异，不是"基于参考图重新设计一个不同画面"。**
5. **目标读者画像校验**：设计方案的画风描述须与 Step 0 确定的画像一致——18-35 岁女性→精致成熟韩剧海报质感，**不是卡通，也不是 Q 版**；12-18 岁少女→可爱明亮日系动漫；男性读者→视觉冲击力概念艺术。**检查条件：出现与画像矛盾的画风词（如给 18-35 岁女性读者写"Q 版""卡通"）须修正。**
6. **形成设计方案文档**：读取 `templates/design-plan.tpl.md` 模板，追加到 `_过程/提示词记录.md`。须包含：参考图与参考点（选中的图与参考点）｜画面差异描述（相对参考图改了什么、保留了什么）｜目标读者画像（年龄层与审美偏好）｜书名排版（内容、分行、大致位置）｜提示词策略预览（告诉用户生成时怎么处理参考图）。
7. **🚪 门禁B：方案对齐（强制暂停点，不得跳过）**：向用户呈现完整设计方案（**全部用通俗语言，不使用技术 prompt**）——参考图与参考点（保留或改动）｜画面描述（2 至 3 句话，重点说明"和参考图有什么不同"）｜目标读者（年龄层、审美偏好、画风校验）｜书名排版（内容、分行、位置）｜生成策略（参考图用法与提示词不控制的维度），请用户确认或调整。**不得自主进入 Step 2。** 将方案对齐记录（完整设计方案与用户反馈）写入 `_过程/提示词记录.md`。

### Step 2: 生成资产

**核心**：Step 2 的核心不是"写提示词"，而是**根据用户在门禁A 选的参考点，决定提示词在哪些维度放手、哪些维度控制**。**铁律：用户选了什么参考点，提示词就在那个维度放弃控制权，交给参考图**——不得既说"参考色系"又写"暖粉七成"，自相矛盾时模型听提示词而不听参考图。

**1. 读取确认方案**：视觉类型（封面、场景图或素材）、画幅与尺寸、参考图路径（如有）、用户选定参考点、设计方案中的画面描述（仅差异部分）、目标读者画像（校验画风方向）。

**2. 参考点→提示词策略**：

- **视觉模式决定提示词结构**（按视觉模式读取 `references/mode-cover.md`、`mode-scene-art.md` 或 `mode-scene.md`）：

| 视觉模式 | 提示词结构 | 文字处理 |
|:---------|:---------|:---------|
| 封面图 | 整体氛围框架、画面内容（由远及近）、书名文字（融入画面）与风格 | 书名用双引号包裹，有材质质感 |
| 普通素材 | 整体氛围框架 + 画面内容 + 风格 | 无文字要求 |
| 场景图 | 整体氛围框架（基于情感基调）、画面内容（选定瞬间的角色、环境与材质，按空间层次）与风格 | 无文字要求（除非用户要求加标题） |

- **策略决策核心**：

| 用户参考点 | 提示词控制的维度 | 放权的维度（交给参考图） | 生成方式 |
|:---------------|:---------------|:---------------------------|:---------|
| 全面参考 | 仅差异部分（书名与必要内容差异） | 画面、色系、构图、画风、光影、字体 | 图生图，最小改动 |
| 色系 | 画面内容、构图、画风、光影、字体 | 配色 | 图生图，不写配色 |
| 构图 | 画面内容、配色、画风、光影、字体 | 构图布局 | 图生图，不写构图 |
| 画风 | 画面内容、构图、字体 | 画风质感（笔触技法、色彩系统、光影氛围、人物精致度） | 放开吸收，只排除具体场景内容与人物长相 |
| 光影氛围 | 画面内容、配色、构图、画风、字体 | 光源设计 | 图生图，不写光源 |
| 字体风格 | 画面内容、配色、构图、画风、光影 | 字体类型、排版风格 | 图生图，不写字体 |
| 色系与构图 | 画面内容、画风、光影、字体 | 配色与构图 | 图生图，不写配色与构图 |
| 无参考图 | 全部维度 | 无 | 纯文生图（V3结构化提示词） |

- **分策略写法**：
  - **策略一：全面参考**——参考图作 `image` 参数传入，提示词**只描述需要改的部分**："在参考图基础上仅做以下调整：1. 书名改为'[书名]'，用[字体类型]，[材质质感]，[位置] 2. [其他必要差异]。保持参考图的整体画面、色调、构图、画风不变。"核心原则：不抢画面控制权，任务是"微调"而非"重画"。**实测注意：全面参考容易"太像原图"（洗稿感），用户反馈太像时，转向更细粒度的参考点组合（如只参考色系与构图）。**
  - **策略二：单一维度参考**——参考图作 `image` 参数，提示词在放权维度不写、在控制维度详写：**色系参考**→不写任何颜色或色调词（配色完全交给参考图），详写画面内容、构图、光影、画风、字体；**构图参考**→不写人物位置、空间布局、层次安排；**画风参考**→使用放开吸收公式（见下）；**光影参考**→不写光源类型、方向、强度；**字体参考**→不写字体类型、材质、排版，仅用双引号包裹书名内容。
  - **策略三：组合维度参考**——多维度组合时，提示词在**所有选定的放权维度**都不写，在**剩余控制维度**详写（如色系与构图→只写画面内容、光影、画风、字体）。
  - **策略四：纯文生图（无参考图）**——使用 V3 结构化提示词，控制全部维度。
- **画风参考 = 放开吸收公式**（实测画风传递显著增强，对比"精确分离公式"画风吸收被抑制）：
  ```
  参考这张图的画风质感、色彩系统和光影氛围：柔和数字插画笔触，painterly soft-focus质感，人物精致细腻的画风，[色彩倾向描述]，[光影氛围描述]。
  仅排除图中具体场景内容和人物长相——场景里的物品、环境元素、人物五官长相不参考。
  以下画面内容完全由本段描述决定：[目标画面详细描述]
  ```
  **关键原则**：①**正向吸收**——明确列出要吸收的要素：画风质感（笔触技法、渲染方式）、色彩系统（色调倾向、饱和度、明暗）、光影氛围（光源、氛围、空气感）、人物精致度，吸收要素要落到具体词，不写"参考风格"这种模糊词；②**最小排除**——只排除两样：**具体场景内容**（场景物品、环境元素）与**人物长相**（五官、脸型），姿态、服饰、构图、色彩都允许由参考图自然传导；③明确声明"以下画面内容由描述决定"，保证主体内容（书名、人物、构图）由提示词控制。**不得在提示词里堆"不参考"清单**（人物、姿态、服饰、场景、构图、配色全部排除即为没参考，实测画风吸收被抑制）。
- **多图参考处理**：用户可指定多张参考图，各取不同参考点（如"pin_003 的色系加 pin_005 的构图"）——每张参考图作为 `image` 参数传入（Seedream 支持多图输入），提示词中明确标注每张图的参考范围，交叉维度在两个维度都放权："参考图A：仅参考其[色系特征描述]；参考图B：仅参考其[构图特征描述]；以下画面内容由本段描述决定：[画面内容、画风、光影、字体]"。

**3. 翻译为模型提示词**：读取 `../pop-visual-shared/references/seedream-prompt-guide.md` 获取提示词写法，按 §2 确定的策略执行翻译。

> **画风 DNA 来源**：从 `skills/pop-visual-style/references/文风DNA-library.json` 取画风的 `dna` 与 `constraint` 字段。按赛道用 `suggested_genres` 筛选，取 `recommended_lighting` 检查光照兼容性（柔美风格不得使用 LT1 减法照明）。详见 `skills/pop-visual-style/references/lighting-composition-templates.md`。

> **核心原则**：Seedream 5.0 Pro/5.0 lite 画面不再泛白，简洁精确的提示优于堆砌华丽词汇。用自然语言连贯描述，不堆叠关键词。

- **V3 结构化提示词公式**（纯文生图或控制维度全写时）。核心发现（5.0 Pro A/B 实测）：纯文生图的质量瓶颈在于提示词缺少"结构信息"——参考图生图效果好，是因为参考图提供了构图骨架、配色比例与字体版式；纯文生图要达到同等质量，须在提示词中**显式编码这三层结构**：
  ```
  整体氛围框架（画面是绝对主体）+ 画面内容（远景→前景按层次）+ 文字（最后描述，融入画面）+ 风格
  ```
  **翻译规则**：①先整体氛围——用一句话定调画面的主体性与整体色彩权重（"画面是绝对主体""X 色占七成为底"）；②画面内容按空间层次从远到近逐层描述（每层包含内容与光照）；③文字最后描述——书名放在画面内容之后，明确"叠于画面[位置]"而非"独占空间"；④文字融入策略——描述文字与画面的物理交互（"底部笔画被前景碎石遮挡""部分笔画被飘散粒子和雾气融合"）；⑤配色用"成数"不用百分比（模型理解"玄黑七成"，但无法计算"70%"）；⑥指定单一主光源（写"为画面唯一主光源"，避免多光源混乱）；⑦字体要写材质（书名用双引号包裹，加字体类型与材质质感：鎏金、金石碑刻、飞白枯笔）；⑧文字尺寸不超过三成（写"占画面高度两成"，而非"四成"或"七成"）；⑨风格词放末尾（用"X 风格"句式收尾）；⑩文化元素极简（定场诗字号不超过书名的五分之一，印章不超过画面百分之一）；⑪中文提示词不超过 400 字。**放权维度的翻译规则：某维度交给参考图时，该维度不写任何描述词**（如色系参考→"暖粉""暖黄""暖色调"全部删除）。
- **Seedance 提示词翻译**（可选，用户要求视频封面时）：公式为 `主体 + 动作（慢、连贯） + 场景 + 光影 + 镜头语言 + 风格 + 画质 + 稳定性约束`。规则：动作写慢写碎（"缓慢""轻柔""连贯"）｜镜头语言明确（推、拉、摇、移、环绕、跟随，加景别）｜须加入稳定性约束（五官清晰、面部稳定、不扭曲、人体结构正常）｜须加入画质词（4K、超高清、无闪烁）｜中文不超过 500 字
- **反向强化技巧**（参考图影响过强、目标方向被参考图覆盖时）：①将目标描述提到提示词最前面（增加权重）；②使用量化词（"占比不低于 40%""大面积"）；③使用禁止词（"完全不使用[参考图的色彩]""禁止[参考图的技法]"）；④用具体色名替代笼统描述（"朱砂红"而非"红色"）。
- **参考图技术注意事项**：`image` 参数须使用 **data URI 格式**（`data:image/png;base64,<base64数据>`，不得传裸 base64）；本地图片转换：用 `base64.b64encode(open(path,'rb').read()).decode()` 再拼 `data:image/{mime};base64,` 前缀；多图输入时每张图分别标注参考范围。

**4. 确定参数**：

| 引擎 | 参数 |
|:-----|:-----|
| Seedream | model=`doubao-seedream-5-0-pro-260628`（默认，质量最优）；size 按画幅（总像素≤236万，如 1125x1500）；watermark=`false`（网文封面通常不需要水印）；response_format=`url`（返回URL，脚本自动下载）；image=参考图 data URI（有参考图时传入） |
| Seedance | model=`doubao-seedance-1-0-pro-250428`；ratio 按画幅映射（3:4/16:9/9:16等）；duration=`5`（可选4-10）；resolution=`1080p`；camera_fixed=`false`（允许运镜） |

**5. 执行生图**（统一 `image_generate` 工具，不直连 API；图生图时传参考图路径保证参考点策略生效）：
```text
# 文生图（无参考图）
image_generate(prompt='提示词内容', size='1125x1500', output='测试/封面/封面-{书}-v1.png')

# 图生图（有参考图，按参考点策略）
image_generate(prompt='提示词内容', size='1125x1500', ref_image='成品/复现/复现-{实体}-vN-final.png', output='测试/封面/封面-{书}-v1.png')
```
多图参考：按工具能力传入多张参考图路径，提示词中说明各图参考点。视频生成不在 `image_generate` 工具范围——如需封面动态化，走 `generate.py video` 子命令（需显式设置 `ARK_API_KEY` 环境变量，脚本不内置 key）。

**输出目录与成品确认**（三态写入见 `../pop-visual-pipeline/references/落盘规范.md`）：封面或场景的**候选图**统一输出到 `测试/封面/`（不存在则创建）；**用户确认后**把达标图复制到 `成品/封面/`（加 `-final`）；未确认前一律留在 `测试/`，不得直接写入成品目录。

**品牌水印（必做）**：图片生成后用共享水印脚本叠加半透明 `popwave.cn` 小字水印（工程化后处理，**不进提示词**，避免污染 Seedream 文生图）：
```
python skills/pop-visual-shared/scripts/watermark.py '测试/封面/封面-{书}-v1.png'
```
默认右下角 alpha=80（约 31% 不透明，低调可见）；**幂等**——脚本通过元数据标记自动跳过已含水印的图，重复运行不叠加；校验：执行完成后再次运行 `watermark.py <图>`，应输出"已含水印，跳过"，确认水印已加。

**6. 降级机制**（生成后根据用户反馈降级；降级无需再次通过门禁，调整参考点组合直接重新生成）：

| 问题 | 降级策略 |
|:-----|:---------|
| 太像参考图（全面参考时洗稿感） | 收窄参考点：从"全面参考"降为"色系与构图"，提示词补回画风与内容描述 |
| 放权维度失控（如色系参考但颜色偏了） | 该维度从放权降级为控制：提示词补回配色描述，参考图只保留其他维度 |
| 画风吸收不足（不像参考图） | 放开吸收范围：删掉"仅排除"限制，允许更自由传导；或切换为全面参考 |
| 构图不满意（参考图构图约束过强） | 构图维度从放权降级为控制：提示词补回构图描述 |
| 全面翻车 | 降级为纯文生图（V3结构化提示词），放弃参考图 |

**7. 回写提示词记录并自检**：生成完成后在 `_过程/提示词记录.md` 末尾追加（模型、参考点、参考图路径、提示词策略、完整提示词、尺寸、输出路径、状态✅）。自检清单：提示词未超字数限制（Seedream 不超过 400 字，Seedance 不超过 500 字）｜**参考点放权维度检查**（用户选了"色系"→提示词中无颜色词；选了"构图"→无布局词）｜提示词用自然语言连贯描述，不是关键词堆叠｜API 执行成功，图片或视频已保存｜**品牌水印已叠加**（每张生成图运行 watermark.py，再次运行输出"已含水印，跳过"以校验幂等）｜提示词记录已回写｜候选图写入 `测试/封面/`，确认后已复制到 `成品/封面/`（加 `-final`）。

**8. 迭代**：用户不满意时，依次执行——①诊断问题维度（是放权维度偏了，还是控制维度描述不够）；②调整参考点组合（收窄或放宽参考范围）；③按新策略重新翻译提示词；④重新生成（文件名递增，v2、v3……）；⑤更新记录。常见调整：太像原图→收窄为具体维度参考，补回更多控制；颜色不对→色系从放权降级为控制，或更换参考图；构图不好→构图降级为控制；画风不像→放开吸收范围，删掉"仅排除"限制，或检查吸收要素是否落到具体词；整体气质偏→更换风格描述（用风格控制公式）；人物变形→添加"五官清晰、人体结构正常"约束；字体太素→使用字体控制公式 `[书名]+[字体类型]+[材质/质感]+[色彩层次]`

### 迭代模式（快速路径）

**当用户要求修改已生成的图片时**，**跳过 Step 0 和 Step 1**，直接执行：

1. 读取 `_过程/提示词记录.md` 获取上一版设计方案+提示词记录
2. 识别用户要求的变更点
3. 直接进入 Step 2，在上一版提示词基础上修改对应维度
4. 执行 API 生成（文件名递增 v2, v3...）
5. 回写提示词记录

> 仅当用户明确要求"重新设计""换方向"或"换赛道"时，才回到完整三段流程。

## ❌ 铁律

| # | 铁律 | 违反后果 |
|:-:|:-----|:---------|
| ❌1 | **先搜图选图再出方案** — 须先搜参考图、由用户选图并对齐参考点，再设计方案 | 设计方向跑偏 |
| ❌2 | **两个门禁不可跳过** — 门禁A 与门禁B 须等用户确认后才能继续 | 方向跑偏，浪费生成次数 |
| ❌3 | **参考点放权一致性** — 用户选了什么参考点，提示词就在那个维度放弃控制权（画风参考即放开吸收，只排除具体场景内容与人物长相，不得堆"不参考"清单） | 提示词与参考图矛盾 |
| ❌4 | **设计方案须三态写入** — 选图记录、参考点、设计方案和提示词写入 `_过程/提示词记录.md`；候选图写入 `测试/封面/`，确认后复制到 `成品/封面/`（加 `-final`） | 无法迭代优化 |
| ❌5 | **场景图须经过理解管线** — 用户提供原文时，须经过原文解构→上下文补全→叙事瞬间选取→门禁A | 理解偏差，精确地画错画面 |
| ❌6 | **对外产出必加品牌水印** — 封面或场景图生成后须运行 `watermark.py` 叠加 `popwave.cn`（幂等，再次运行输出"已含水印，跳过"）；不得跳过此步 | 发布图无溯源，品牌曝光丢失 |
