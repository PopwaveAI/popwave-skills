# short-platform-orientation
> 本技能为短篇平台定位器，流程依次为：摸底三问、平台深度匹配、输出定位卡片。v2.1.0 将三个步骤全部合入单文件并精炼；执行模式为由主 agent 直接执行。

## 职责范围
输入：作者意向，含题材倾向、核心目标、现有想法三项，三项均可能为空。
输出：平台定位卡片、传递给 idea-refiner 的流转上下文，以及**项目总览.md 完整内容**（该文件由主 agent 创建）。

**执行模式**：由主 agent 直接执行。全程以问答方式与作者交互，依次完成摸底、匹配、定位确认三个阶段，不存在适合派发子 agent 的环节。

## 怎么操作（规程全内联）

### Step 1 快速摸底（三问）
作者意向明确时跳过摸底：已说平台与题材者，确认后即展开该平台该题材；只说了题材者，做该题材的跨平台对比；什么都没说者，执行摸底三问。三问为：①题材倾向——悬疑、言情、重生穿越、规则怪谈、年代、现实情感、脑洞，还是尚未想好？②核心目标——快速签约拿稿费、打磨品质冲击改编、两者兼顾，还是练手？③现有素材——已有成型想法，还是从零开始？
产出：题材方向、目标意图（签约、品质或兼顾）与现有想法（有无及其内容）。

### Step 2 平台深度匹配
基于题材与意图，深度展开一至两个最适合的平台（数据以 `references/platform-rules.md` 与 `genre-guide.md` 为准），其余平台以一句话简述，例如"XX平台对YY题材不友好，因为……"。
每个展开的平台按八个维度说明：签约门槛与速度、目标读者画像、该题材的平台表现（属头部还是边缘）、子方向推荐（最值得做的细分方向）、开篇铁律（前多少字或句须达成什么效果）、付费钩子模式（有无、断在哪、怎么断）、改编潜力（短剧、漫剧）、风险注意。两个候选平台按这八个维度列出对比表，展示优劣，供作者选择。

### Step 3 输出定位卡片与流转上下文
1. **定位卡片**（格式参照 `templates/platform-card.tpl.md`）：由对比表提炼出【平台】，依下表自动推导出【文章性质】，并列出【签约门槛】【核心读者】【开篇铁律】【付费钩子模式】【改编方向】【风险提示】。作者方向与平台性质明显冲突时，卡片须标注风险警告，但不强制阻止。
2. **流转上下文**：【选定平台】【文章性质】【核心约束】（由平台铁律、开篇要求、付费模式合成）【用户意向】（题材、目标、改编诉求）【原始想法】（模糊想法，可能为空）。
3. **写入** `step1-平台定位.md`，并流转到 `short-idea-refiner`。

## 项目总览.md 模板

首次执行 Step 3 时，须**将以下格式的 `项目总览.md` 完整内容返回给主 agent**；后续所有 Step 均按此格式返回更新后的内容：

```markdown
# 项目总览

> 更新日期：YYYY-MM-DD ｜ 当前阶段：Step N 名称

## 流程进度

<!-- STAGE_TABLE_START -->
| ID | Step | 状态 | 摘要 |
|:--|:--|:--|:--|
| S1 | 平台定位 | 🟡 | — |
| S2 | 脑洞提炼 | ⬜ | — |
| S3 | 开篇设计 | ⬜ | — |
| S4 | 剧情结构 | ⬜ | — |
| S5 | 正文生成 | ⬜ | — |
| S6 | 评审 | ⬜ | — |
<!-- STAGE_TABLE_END -->
```

**状态约束：**
- 状态仅三种：`⬜` 表示未开始，`🟡` 表示进行中，`✅` 表示完成。
- **有且仅有一个 Step 处于 🟡 状态**
- `STAGE_TABLE_START` 与 `STAGE_TABLE_END` 两个标记不得删除。
- ID（S1 至 S6）不得改动。
- 用户跳过某 Step 时，须标记为 `✅ 已跳过`，不得保留 `⬜`。

## 平台与性质推导
| 平台 | 自动性质 |
|:---|:---|
| 番茄短故事 | 快节奏爽文 / 网感强 / 下沉市场 |
| 知乎盐言故事 | 知性深度 / 社会洞察 / 反转导向 |
| 每天读点故事 | 情感治愈 / 暖甜 / 短剧感 |
| 豆瓣阅读 | 文学质感 / 慢热 / 长尾品质 |
| 小程序生态 | 信息流钩子 / 极致快节奏 |
| 七猫 | 精品网文 / 保底导向 |

## 红线
| # | 红线 | 违反后果 |
|:-:|:-----|:---------|
| 1 | 不做跨平台通稿，只深度展开一至两个最适合的平台 | 信息稀释，作者无法做出决策 |
| 2 | 不替作者做最终决定，只展示优劣，由作者选择 | 作者投错平台后会归咎于本技能 |
| 3 | 平台数据以 `references/platform-rules.md` 为准，不得自行发明规则 | 误导作者 |
| 4 | 遇到实时性政策问题时，须如实告知作者前往后台确认 | 过时信息会导致签约失败 |
