# short-text-deconstructor
> 本技能为短篇拆文分析器，流程依次为：选深度、拆结构、拆角色、拆开篇、拆文风、评价、影响后续。v2.1.0 将七个步骤全部合入单文件；例文分析可派子 agent 执行，深度选择由主 agent 直接执行。
## 职责范围
输入：用户上传的例文全文（文本、PDF 或截图文本）。
输出：拆解报告（含结构分析、角色分析、开篇拆解、文风画像、九维评价、对后续 Step 的影响），以及流向各 Step 的影响信号。

## 子 agent 文件协作协议（方案 B）
当本 Skill 由子 agent 运行时（受限环境）：
1. 将拆解报告全文写入临时目录：`{tempDir}/deconstruct-{runId}.md`（tempDir 由主 agent 在调用时传入）。
2. 不返回报告全文，只返回结构化元数据：
   ```
   { "file": "{tempDir}/deconstruct-{runId}.md", "lines": N, "bytes": N, "head": "前16字符", "tail": "后16字符" }
   ```
3. 主 agent 校验：文件存在、字节数与行数匹配、head 与 tail 匹配，三项均通过后以 Move-Item 归位到项目目录。
4. 校验失败时，由主 agent 重新调用子 agent 重试。
## 执行模式
例文读取与各模块分析属于只读工作，可派子 agent 执行：按方案 B 将报告临时写入磁盘并返回元数据，主 agent 校验后归位；Step 0 的深度选择需要用户交互，由主 agent 直接执行。
## 定位
本技能独立于主线 Step 1-6，用户可在任何阶段触发。拆解完成后恢复主线，并将结论应用到各步骤。
## 怎么操作（规程全内联）
> execution.mode: 串行

### Step 0 确认拆解深度
1. 触发时须先暂停当前主线流程，并告知用户："收到，我先暂停当前的[当前Step名称]，专注拆解这篇例文。拆完后结论会应用到后续步骤。"
2. 询问意图："你想从这篇例文里学什么？"（四个选项：①完整拆解、②只学开篇、③学文风句式、④参考题材人设）
3. 默认①完整拆解（未明确选择时按①执行）。按选定深度执行，跳过无关步骤：

| 选项 | 输出模块 | 执行/跳过 | 适用场景 |
|:---|:---|:---|:---|
| ① 完整拆解 | 结构、角色、开篇、文风、评价 | Step 0 至 6 全部执行（无跳过） | 想全面学习一篇精品 |
| ② 只学开篇 | 导语公式、黄金三句、付费钩子 | Step 0、3、6（跳过 1、2、4、5） | 开篇不知道怎么写 |
| ③ 学文风句式 | 文风画像 | Step 0、4、6（跳过 1、2、3、5） | 想模仿某作者的笔触 |
| ④ 参考题材人设 | 结构分析、角色分析 | Step 0、1、2、6（跳过 3、4、5） | 找同类题材的切入点 |

### Step 1 结构分析
- **平台判断**：对照 platform-rules.md，依据人称（第一人称或第三人称）、段落长度、付费钩子明显度、开篇风格（知乎知性沉稳、番茄网感快、每天情感细腻等）判断平台归属。
- **题材分类**：归类 genre-guide.md 的题材大类，并标注子方向。
- **结构模板匹配**：对照 structure-guide.md 匹配六种模板（反转剥洋葱体、单元爆破体、经典三幕式、情绪爆发体、双线螺旋嵌套体、单点爆破循环体），并检查题材专属套路（追妻七步法、知乎冲突堆积法、终局锚点法、规则怪谈循环爆破法）。
- **弧线还原**：反向还原例文的剧情弧线，输出五列表（段落、字数、核心事件、信息释放、情绪走向），并标注付费钩子的位置与类型；格式与 plot-structurer 的弧线表一致，仿写时可直接复用。
### Step 2 角色分析
- **主角公式判断**（对照 character-card.md）：公式 A 五维（外在标签、内在反差、渴望、软肋、底线、小缺点）；公式 B 成长弧光（初始缺陷、挫折、认知崩塌、行为改变、结局蜕变）；公式 C 3+1（一个特点、一个能力、一个弱点、一个象征物）。
- **主角人设还原**：按判断出的公式还原，格式与 plot-structurer 一致。
- **配角清单**：列出所有有名有姓的配角，每人标注叙事功能、出场节点、活人标签，格式与 plot-structurer 一致。
### Step 3 开篇拆解
输出格式对标 opening-designer 的导语分析框架。
- **导语公式判断**：判断导语属于悬念前置、情绪爆发、对话开头、身份共鸣、反转、画面切入中的哪一类（对照 golden-three.md）。
- **黄金三句拆解**：将前三句逐句列表（句序、功能、原文引用），第 1 句的功能为甩冲突、拉近距或留钩子。
- **付费钩子还原**：位置（占全文百分比）、类型（信息缺口、情绪最高点、决策时刻、反转预告）、断点内容（引用原文）。
### Step 4 文风画像
量化抽取文风特征，正文生成器可直接将该画像作为自定义文风选项：

| 特征 | 抽取方法 |
|:---|:---|
| 平均句长 | 全文字数/句数 |
| 段落长度 | 全文字数/段数 |
| 对话占比 | 对话字数/总字数 |
| 描写密度 | 描写段落字数/总字数（高表示描写主导，中表示描写与叙事均衡，低表示叙事为主） |
| 独有词汇/句式 | 例文高频特有词汇、句式模式、标点习惯 |
| 情绪表达方式 | 直接陈述、动作替代或对话承载 |

输出贴合 writing-styles.md 的风格描述格式，并标注与五种标准文风的异同。话术："这篇例文的文风可以概括为：{总结描述}。最接近【{标准文风名称}】，差异主要在{差异点}。正文生成时可选'用这篇的文风'。"
### Step 5 评价
用 short-reviewer 的九维评分框架评分（九维、综合、等级；等级为现象级、爆款区、潜力带、过关线、危险区、别急着投）。
- **亮点** 2 至 3 条（每条一句话并作简短展开，精品例文侧重"为什么它成了"）；**不足** 1 至 2 条。
- **定位**：拆文评价为"样本分析"，评审为"诊断"，两者不冲突；例文质量明显偏低时须标注，但不得模仿。
### Step 6 汇总报告与影响标注
1. **汇总报告**：按 `templates/deconstruct-report.tpl.md` 的格式汇总五个模块（结构、角色、开篇、文风、评价），保存到 `参考资料/拆解报告-{例文标题}.md`。
2. **影响标注**：按下表标注。
3. **恢复主线流程**："拆解完成，已保存到 参考资料/拆解报告-{例文标题}.md。拆解结论已记录，后续步骤会在相应节点应用。现在回到[暂停的Step名称]。"

## 对后续Steps的影响
| 步骤 | 影响 | 应用方式 |
|:---|:---|:---|
| Step 1 平台定位 | 拆解出的平台作为直接确认项或强烈推荐项 | 不再展开多平台对比分析 |
| Step 2 脑洞提炼 | 拆解出的题材用于在该品类中寻找变体或升级方向 | 参考例文的子方向延伸 |
| Step 3 开篇设计 | 拆解出的导语公式用于推荐同类公式，或展示不同公式作为对比 | 作为对比项出现 |
| Step 4 剧情结构 | 拆解出的弧线与角色作为基础框架，微调后使用 | 复制弧线结构并调整变量 |
| Step 5 正文生成 | 拆解出的文风画像作为一个独立的自定义文风选项 | "用这篇的文风" |
| Step 6 评审 | 拆解出的评价作为例文与作品各维度差距的参照 | 同维度对标 |

## 红线
| # | 红线 | 违反后果 |
|:-:|:-----|:---------|
| 1 | 拆文不替代评审：例文评价是"样本分析"，评审是"诊断" | 把例文标准直接套用到用户作品 |
| 2 | 例文质量明显偏低时标注但不模仿 | 劣质例文的套路被复刻 |
| 3 | 拆解结论应如实反映例文特征，不做过度美化 | 用户对例文产生不切实际的预期 |
| 4 | 暂停主线流程时须告知用户，拆解完成后恢复 | 主线流程状态丢失 |
