# 一、起点长篇产线（pop-qidian-*）—— 工程级长线

> 总逻辑：**项目总控.html → 按 Phase 0-6 路由**。各阶段产物层层继承（PRD→设定→角色→剧情→正文→审核），正中长线连载痛点。

### 1. pop-qidian-pipeline（总控）【骨架】
- **功能定位**：起点管线总控，路由调度不干活。
- **机制**：读 `project-state.html`（或项目总控.html）状态 → 按状态路由到 seed/world/character/plot/write/review；`step0-import.md` 处理导入/续写。
- **红线**：以状态为准，不跳过状态直接推进。
- **衔接**：消费 project-state；触发下游各子 skill。

### 2. pop-qidian-seed（立项）【骨架】
- **功能定位**：三步立项——灵感收集（问答+调研+种子候选）→ 种子碰撞（六要素骨架+PK）→ 立项 PRD 定型（六要素故事）。
- **机制小巧思**：**明确产出 `立项/01-立项PRD.md`**，作为 world/character/plot 各自展开的工程源；不只拍脑袋定题材，走"灵感→调研→碰撞→定型"实证。
- **红线**：立项 PRD 未成型不展开下游。

### 3. pop-qidian-world（世界构筑）【骨架】
- **功能定位**：消费立项 PRD 的「世界+力量体系」方向句 → 展开力量体系四层 + 动力引擎六组 + 7 维度因果链（类型风味基线/物理规则/战斗系统/政治经济/民俗/地理/势力/危机）→ 11 个最小闭环文件落盘。支持创作/拆解/融合三模式。
- **红线（v4.1.1+）**：战斗系统**必须 4 拍节奏（试探→对抗→转折→收尾）**，禁一击制胜；**碾压型力量（如请神）必须配风险窗口/时限/副作用**，防止战斗被跳过。

### 4. pop-qidian-character（角色库）【骨架，无 steps】
- **功能定位**：消费立项 PRD「人物」方向句 + world 力量体系 + 动力引擎 → 自行展开主角深度卡 + 金手指 + 按分幕批量塑造角色卡。
- **机制**：角色库.md 是 write 的唯一角色源；角色必须能支撑主角成长/关系张力/剧情冲突。
- **红线**：缺 steps 编排标注。

### 5. pop-qidian-plot（剧情白描）【骨架】
- **功能定位**：消费立项 PRD「起因/经过/结果」+ world 设定 + character 角色库 → 主线 + 卷纲 + 章锚点表。
- **机制小巧思**：
  - 卷纲以**幕功能位为轴**：每幕只有一个功能位/一条主压力/一个主收益；剧情线服务幕功能。
  - **「不能抢的后续收益」列**——防前置幕透支后续高潮爽点。
  - **长线债务管理**（埋的线/还的线 + 触发条件）；剧情子线改为**事件种子池**（主线/支线暗线/世界观三类，每条一句话、量大而定体小，让幕纲自由选取）。
  - 白描卡 150-250 字/章，write 读 3 段不读全卷。

### 6. pop-qidian-write（正文）【较完整，step-2-write.md】
- **功能定位**：将剧情锚点渲染为 2000-2500 字章节正文。
- **机制小巧思**：
  - **6 章型骨架 × 7 节拍**；每章加载**爽点引擎 + 爽点链条矩阵**（references，必加载）。
  - 笔触 DNA：读 `素材/文风锚定.md` + 上一章 DNA 执行包统一文风。
  - 落盘 `产出/正文/ch{NNN}.md`；模板 `templates/chapter-record.tpl.md`。
- **红线**：动笔前必回查 SKILL.md「知识地图」；章型定义.md 为写崩级必读；爽点引擎/链条为每章必加载。
- **衔接**：消费 plot 白描/设定库/角色库/文风锚定；被 review 消费。

### 7. pop-qidian-review（审核）【较完整，step-1-audit.md】
- **功能定位**：章节多轮审核（剧情/设定/人物/文笔）。
- **机制小巧思**：**三种执行模式**——`formal` 正式审稿落盘 / `draft` 缺材料生成临时判断 / `trial` 快速体感不落盘。前置必读：正文 + 上一章白描卡 + 状态快照 + 骨架/设定。
- **产出**：审稿判断 + 状态快照（连续写作状态记录）。

### 8. pop-qidian-research（调研/燃料）【骨架】
- **功能定位**：pipeline Phase 0 自动触发赛道定位调研；用户给力量体系参考书时启用 9 表拆书。
- **红线**：**不提供完整小说，只做题材机制/参考书拆解/燃料档**；参考书→decon-plot 剧情拆解。
- **衔接**：产出燃料供 seed/plot/write。

# 二、番茄长篇产线（pop-fanqie-*）—— 快节奏连载

> 与起点的差异定位：番茄走**快节奏/高事件密度/单元剧外壳+长线内核**；起点走工程长线。

### 1. pop-fanqie-pipeline（总控）【骨架，steps 空】
- **功能定位**：番茄管线总控，读项目总控路由。
- **注意**：steps/ 目录为空，编排细节待补。

### 2. pop-fanqie-seed（种子/创意）【骨架，无 steps】
- **功能定位**：三阶段创意引擎——七维底牌摸底 → 市场调研 → 改编策略 → 双轨发散 → 结构化打磨 → **黄金首章**。
- **产出**：创意.md + ch001.md。
- **机制小巧思**：首章直出，追读从开头起。

### 3. pop-fanqie-world（世界构筑）【骨架，无 steps】
- 从创意生长全书设定，供给 plot 层。细节待补。

### 4. pop-fanqie-character（角色库）【骨架，无 steps】
- 消费 plot 分幕出场清单 + 全书设定，按幕批量塑造角色，产出角色库.md（角色唯一源）。

### 5. pop-fanqie-plot（剧情白描）【较完整，step2/step3.md】
- **功能定位**：番茄叙事引擎——本卷设定快照 → 分支剧情线 → 分幕设计 → 按幕白描。
- **机制小巧思**：
  - **幕内四段式模板**（起承转合，每段填具体内容）。
  - 每幕多故事弧线：主线 + 情感/关系 + 战斗/成长；**多视角安排**（敌人/旁观者/配角）。
  - 结构要素表：核心地点 ≤3、核心出场人物 ≤6、成长节点 ≥1；**每幕推进 2-3 条分支线**；场景表 6-10 场景/幕。
  - 落盘 `设计/第一卷剧情/剧情白描.md`（含设定快照/分支线/分幕/场景表/卷末钩子）。

### 6. pop-fanqie-write（正文）【较完整，step2.md 内容有限】
- **机制**：2000-2500 字/章、**单章一句一换行**；落盘 `产出/正文/ch{NNN}.md`。

### 7. pop-fanqie-review（审核）【较完整，step1.md 内容有限】
- 读 plot 骨架 + 正文 → 生成审稿样本；完整四步流程待 SKILL.md 原文展开。

# 三、短篇产线（short-*）—— 从脑洞到可发 7 件套

> 总逻辑：**平台定位 → 脑洞 → 开篇 → 剧情 → 正文 → 评审**，串行推进；`text-deconstructor` 可随时插入。

### 1. short-platform-orientation（平台定位）【完整】
- **机制**：摸底 3 问 → 平台深度匹配 → 定位卡片 + 项目总览.md。**只深度展开 1-2 个最适合平台，不做跨平台通稿**；平台数据以 references/platform-rules.md 为准。
- **状态机**：只有一个 Step 为 🟡进行中，状态仅未开始/进行中/完成。

### 2. short-idea-refiner（脑洞）【完整】
- **机制**：A有想法/B只有方向/C带例文 三路径；C 先解析例文卖点再走 A。检验至少 2 项通过才进阶。
- **小巧思**：热点仅作参考；跨平台一稿多投提醒平台差异。

### 3. short-opening-designer（开篇）【完整】
- **机制**：卖点主轴 → 6 种导语公式择最优 → 黄金三句 → 完整导语 → 付费钩子策略。
- **小巧思**：**导语 ≠ 正文第一句，是平台展示页上的故事简介**；最后一句必须最强悬念/钩子；不做背景交代/抒情议论。

### 4. short-plot-structurer（剧情）【完整】
- **机制**：4 种结构模板（知乎反转体/番茄单元剧体/经典三幕式/情绪爆发体）→ 剧情弧线 → 角色设计 → 骨架卡片。
- **小巧思**：**先定剧情再配角色（角色是剧情的函数）**；角色 ≤5 个有名有姓，功能重复配角合并。

### 5. short-body-generator（正文）【完整】
- **机制**：选文风 → 定模式 → 逐段生成 + 自检 + 用户确认；付费钩子段特殊标记+断点暂停；**去AI味是必走流程**。
- **小巧思**：用户参考文本优先级 > 平台默认文风；只重写指定段保持其余不变。

### 6. short-reviewer（评审）【完整】
- **机制**：**9 维评分**（钩子密度/节奏控制/付费钩子/角色塑造/结局收束/文风适配/情绪张力/商业驱动/AI味儿）+ 亮点不足 + 分维诊断 + 改进方向。
- **小巧思**：只诊断不修改；**AI味仅参考不纳入评分**；每条诊断必配建议。

### 7. short-text-deconstructor（拆文）【完整，独立侧线】
- **机制**：四拆解深度（完整/只学开篇/学文风句式/参考题材人设）→ 结构/角色/开篇/文风/9维评价 → 结论**反哺后续 Steps**。

# 四、拆书与文风（pop-decon-* + pop-dna-style）—— 向爆款学习

> 总逻辑：**下载源书 txt → 征询范围维度 → 维度拆解 → 立项 PRD**；绝不在无原文时凭空拆。

### 1. pop-decon（拆书入口）【完整】
- **机制**：下载 txt → 征询"拆什么范围？拆哪些维度?" → 路由 dimension/design-pack/prd。**禁止未征询就全量跑**；提醒"先第一卷少量测试再拓展"。
- **红线**：禁止跳过原文直读；无源文件不可启动。

### 2. pop-decon-design-pack（章节设计包，可选加速器）【完整】
- **机制**：双维度可选——输出格式 `precision`（v4 设计包 3 层+1 区）/ `fast`（瘦身白描卡 4 段式）× 处理方式 `quality`（每章 1 子agent）/ `performance`（每 30 章 1 子agent）。
- **红线**：precision 模式必须有 scene/POV/🔒/感官锚点；未确认模式擅自执行退回。
- **产出**：`设计包v4/chXXX-设计包.md` / `白描卡/chXXX.md`。

### 3. pop-decon-dimension（维度拆解）【完整】
- **机制小巧思**：**7 维度联合拆解**（plot/romance/character/power/world/beat/style）——所有维度检索词合并一次 Grep → 命中章去重形成**联合锚点池** → 每章只读一次同时提取所有维度。⏱ 省算力是卖点。
- **红线**：无 chXX 证据=编造；关键数值必须 🔒 锁死。

### 4. pop-decon-prd（全书立项设计）【完整】
- **机制**：拆书=逆向破解；**PRD 只综合已有数据不产生新数据**。产出含逆向破解总结/商业可行性/连载规划/风险预警/启动清单。
- **红线**：核心假说必须有 chXX 证据；不得与维度数据矛盾。

### 5. pop-dna-style（文风 DNA 提取与重构）【完整】
- **机制俏思**：两阶段——Stage1 采样提取笔触 DNA；Stage2 用世界画风+用户需求综合重构 v2。
- **红色细节**：**三段式产出（操作特征 + 完整段落 blockquote + 反面教材 AI 护栏）**；淘汰"金句碎片化"（AB 测试完整段落+反面教材优于原文直灌）；采样场景定向覆盖 ≥8 种；**只学笔触不学内容**；v1 部署 `素材/文风锚定.md`。
- **门禁**：原文存在性前置（参考书 txt 必须存在）。

# 五、AI 味治理（pop-ai-reduce + lite）—— 差异化主钩子

### pop-ai-reduce-lite（表层降噪器·已实装）【完整】
- **功能定位**：表层降噪器不是润色器。不改角色感受/情节推进/场景描写，只改套话外壳。
- **单轮 4 步**：
  1. **结构骨架**：模板头尾→场景化（`随着夜幕的降临`→`天擦黑`）；打散"首先/其次/最后"三段式，最弱段压成 1-2 句。
  2. **句长随机化**：15-25 字均匀区插入 ≤5 字极短句；**只在自然转折/动作切换处插，因果链时间流中间不插**（小巧思：否则读者脑补关联叙事受损）；全文 ≤3 处。
  3. **字符清理**：破折号 ≤1个/500字（只留列举/必要转折）；英文引号全量转中文，引号内文字不动；只拆模板对仗（"不仅…而且"），文学表达不碰。
  4. **过渡词口语化**：词表替换（明确指出→说白了）；用口语词补位保留衔接不删断。
- **可测量（杀手锏）**：内置 `analyze_metrics.mjs` 实算——字数保留率 ≥85%（硬底线，低则回查 1 轮）/ 6 桶句长分布 / 15-25 连击 max_streak / 破折号密度 / 英文标点 / "不是…而是"正则。
- **残余AI味预估算法**：0.40 基准 + 命中加分（破折号>1/百字+0.05；不是而是>1/五百字+0.10；句长集中+0.10；英文引号+0.05；对仗+0.10；概括式内心>3处+0.10；金句升华+0.05）。分级：≤0.45 可不深度 / 0.45-0.65 建议 / >0.65 强烈建议深度。
- **红线**：一轮完成禁止迭代；一次一章；台词跨段连击是切分伪影跳过；验证必须用内置脚本禁用自写；禁用"写完发现残留返工"。
- **产出**：双文件 `{章节}_纯文.txt` + `{章节}_报告.txt`；同名自动 `_v2/_v3` 防覆盖。
- **衔接**：跑完询问是否深度 pop-ai-reduce。
- **深层说明**：深度 18 技法（情感过滤/Telling转Show/句式破模/留白/意象/伏笔回收/反高潮…）方法已 12 轮朱雀实测（单一技法=新规律，2-4 层叠才显著降），落地中。

# 六、视觉产线（pop-visual-*）—— IP 视觉唯一真源

> 总逻辑：**pipeline 路由 → asset 提取资产 → style 定画风 → art-bible 视觉真源 → cover/oc/comic 派生**；shared 共享底层组件。

### 1. pop-visual-pipeline（总控）【骨架】
- **机制**：Phase 0-6 路由——0 初始化/意图 → 1 asset 资产 → 2 style 定标 → 3 art-bible → 4 cover → 5 oc → 6 comic。
- **红线**：总控只路由不干活；前一 Phase 未过门禁不推进。
- **注意**：示例记忆提到 project-state 状态可视化，待证。

### 2. pop-visual-asset（资产提取）【完整】
- **机制**：从小说原文 ETL 提取 4 类视觉资产——**角色档案/场景资产表/视觉符号库/IP 视觉 DNA**；支持创作/拆解/独立小说项目 + **增量更新**。

### 3. pop-visual-style（画风 DNA 库）【完整】
- **机制**：37 种画风 DNA + 3 光照模板 + 6 段式提示词结构；画风能力从派生任务中**剥离解耦**，下游 cover/oc/comic 复用，消除重复定义。

### 4. pop-visual-art-bible（美术设定集·唯一真源）【较完整】
- **机制**：消费 asset + style DNA + 用户需求 → 统一 Art Bible **八篇合一**（画风/人物/场景/视觉符号/势力/地理/规则/一致性复现）；下游 cover/oc/comic 只消费不重建 → **一致性从源头保证**。
- **注意**：SKILL.md 摘要提及 10 条铁律，原文待读。

### 5. pop-visual-cover（封面/场景图）【较完整】
- **机制**：双起点——①用户意图→Pinterest 搜参考→选图对齐参考点→设计方案；②原文→解构→上下文补全→叙事瞬间选取→理解确认→设计方案。
- **画风设计**：封面=广告非插画，0.3 秒识别赛道；四层信息架构（标题/主视觉/赛道符号/作者名）。

### 6. pop-visual-oc（OC 设定卡）【较完整】
- **机制**：从原文采样设定 → 五类实体卡（人物/势力/地理/规则/场景）。

# 十、Library 知识库

## A. 元素卡库：10 族 54 卡
数据源：《深渊主宰》ch001-015 + R5 跨书扩展 + R5A 灵异补足。

| 族 | 卡数 | 一句话定位 |
|---|---|---|
| 战斗族 | 6 | 一战一解法，章内不重复 |
| 情感族 | 6 | 甜必衬酸，纯甜无酸禁用 |
| 对话族 | 6 | 情报中转站，谈出下一步 |
| 世界观科普族 | 5 | 情境引入+落回主角双闸防出戏 |
| 成长收获族 | 6 | 数值弹幕是心跳，福祸锯齿波 |
| 施压族 | 7 | 结尾不解决问题，悬念即产品 |
| 收线族 | 7 | 线是情绪结账，威名靠世界侧写 |
| 探索族 | 4 | 观察→推断→行动，金手指变现主场 |
| 打脸族 | 3 | 蓄压→挑衅→打脸三段式 |
| 都市日常族 | 4 | 人间烟火落地感，暖源+参照+伏笔接口 |

- **卡结构**：卡名+适用+节拍序列+拍义填法+写法要点+线效果+源书溯源。
- **核心机制**：章纲生成路径 = 章型配方 → 逐块选卡 → 落拍填料 → 块间串线。
- **跨赛道接线**：恐怖事件五段式（氛围→异象→高潮→兑现→复盘）跨 3 书成立，是施压族+收线族的组合升级，非独立第 11 族。
- **警示**：开局卡 ≠ 全阶段通用；中段会出现开局期没有的新块。

## B. 文风 DNA 槽位协议
- **核心**：文风 DNA=赛道"笔触形态层"，与赛道特色"内容风味层"**平级、物理不融合**——DNA 管"怎么写"，赛道特色管"写什么词"，避免 write 被名词带偏句式。
- **三段式产出**：操作特征（条件式指令）+ 完整段落（1-3 段 blockquote）+ 反面教材（AI 护栏）。
- **三层结构**：①笔触基底（跨书复用）②场景卡分档（按事件分量，匹配战斗密度）③卷级演变曲线（同战斗，遭遇战碎段快杀 vs 决死战长句铺陈）。
- **write 消费协议**：读本章命中场景卡三段式 → 读本卷演变曲线 → 按事件分量选档 → **5 章滑窗去重**（近期高频笔触自动规避防单调）。

## C. 赛道设定集
- **4 个已成型旗舰包**：西幻dnd（源《深渊主宰》）/ 仙侠争霸（《遮天》）/ 都市修仙（《重生之都市修仙》）/ 灵异恐怖经营（《我有一座冒险屋》，深度采样试点中）。

- **赛道定义模型**：赛道 = 题材 × 玩法 × 情绪价值。题材 11 类 × 玩法 10 族。

## D. skill-赛道包维护规范
- **基准样本**：西幻dnd（结构标杆）。
- **包标准结构**：readme/changelog/使用手册/立项/赛道特色/文风DNA/力量与战斗/世界观/角色库/剧情库。
- **六层 DNA**：结构/机制/内容/风味/笔触/素材。
- **红线**：目录 100% 对齐西幻dnd；单文件 ≤15KB；去专名；三处索引同步。
