## 0. 一句话卖点

**popwave 的改编不是"仿写仿个形"，而是"抄商业架构、不抄皮/机制/人/事件"——用 X DNA 替换矩阵把你看中的爆款书，一股脑换成你的世界观和主角重新长出来；结构节奏可考，情节人物全员原创。**

## 1. 用户痛点：写书的人，最怕的两头

| 痛点 | 表现 | 后果 |
|---|---|---|
| **原创没人气** | 自己憋的世界观+剧情，写出来没人看、不赚钱 | 白写几万字，数据一塌糊涂 |
| **跟风又像抄** | 照着爆款写"仿写文"，题材/机制/人名/剧情都对得上原书 | 读者骂、平台判、法律风险；**作者不敢承认是仿的，心态崩** |

> 卡在两个极端中间：既想要爆款书"为什么火"的商业内核，又不想要"照搬抄袭"的原罪。市面上教"仿写"的，大多只教抄形；教"原创"的，又放弃了可验证的商业框架。popwave 用"改编委托"同时解这两头。

## 2. 关键认知：爆款书能拆成"质量锚"和"原创层"两层

| 层 | 是什么 | 改编处理 |
|---|---|---|
| **质量锚（照搬）** | 四段式大结构、质变点位分布、卷末收益三件套、首三章功能位、欲望半径四段放大、节奏参数、爽点配比 | **原样保留**——这是"它为什么火"的机制内核，不逐字抄正文 |
| **原创层（全换）** | 题材皮、世界观、力量体系机制、金手指形态、人物全员、具体事件 | **从头推**——这是"抄了就出事"的内容层 |

> 卖点核心：**把"抄没抄"变成"抄哪层"的工程问题**。结构层合法继承，内容层彻底原创。这层认知是整套 test 改编家族的根基，下面是它的落地机制。

## 3. 反面教材：为什么"换书名+换人名"必翻车（我们敢说这是坑）

- **"换皮不换骨"**：只把主角名字、地理名、力量名替换，剧情事件、冲突模式、升级路线全照抄——读者三章就识破，平台版权判定也抓你结构雷同。
- **"全新硬编"**：彻底抛开爆款书，凭空造世界观+剧情——白白丢掉已被市场验证的商业节奏，回到"自嗨"老路。
- 正确做法是**分层**：下面第 4 节。

## 4. 机制：三层实操，把"借鉴"变成"改编"（test-adapt · 工程级）

### 4.1 强度 A/B/C 三档：先选改多少，再由用户拍板
- 对同一本爆款书，适配不同胆量/需求：
  - **A 改演员**：主角、敌人、盟友、剧情事件、开篇场景替换，保留世界/地理/势力/力量体系/金手指。→ 适合"同世界换人换事"，风险最低。
  - **B 改世界观**：保留力量体系/金手指，重写地理/势力/世界观/时代引擎。→ 适合"重设舞台"。
  - **C 全改**:只留商业架构，力量体系/金手指也从 X 重写。→ 适合"彻底换机制"，原创度最高。
- **铁律**：呈现 A/B/C 三档并让用户选择，**不能默认跳过**。冲突项≤3 个直接列清单问一次，不反复打断。

### 4.2 X DNA 替换矩阵：逐维度替换，防"只换形"
- 单张矩阵表把爆款书按 6 个维度（主角/敌人盟友/剧情事件/开篇场景/地理势力世界观/力量体系金手指），逐格对照"包PRD的设定"→替换为"X 的新设定"。
- **小巧思**：不复制包的原话人设，而按"包该维度的核心设定角色"替换为 X 的新设定——落点是"这个位置承担什么功能"，不是"这个人物叫什么"。

### 4.3 剧情类比切换：只抽冲突模式，不抽事件
- 三步：提取原包核心张力（每卷/幕的冲突模式一句话）→ 推导 X 的核心张力 → 把每卷功能位映射到新事件 DNA。
- 示例：原包"小人物在乱世靠信息差求生+初触超凡" → 可切换为 X 的"偷 vs 被偷"冲突。**功能位保留，事件从 X 核心张力、新世界、新角色重推。**
- **铁律**：映射表内禁止出现原包具体事件/台词/道具/人名——这会滑向"换名复用"。

### 4.4 X 体验层三耦合：X 不是设定，是正文里的引擎
- 改编计划必须产出 X 的三种"进入正文"的机制：
  - **战斗耦合**：X 在战斗中怎么打（例：心灵窃取=偷招式/植入假记忆/读心预判）。
  - **日常耦合**：X 在日常里的表现与代价。
  - **剧情耦合**：X 与主线的核心耦合点。
- **小火要**：让"你的创意 X"不只活在设定库，而是被写进战斗、日常、剧情的每一处——解决"X 只是标题、正文看不见"的通病。

## 5. 可测量 / 门禁：这不是玄学，是有硬验收的

| 门禁 | 口径 | 意义 |
|---|---|---|
| **包前置** | 动笔前必须读包配方表 1 + 包立项 PRD 全文，禁止 limit 截断；无包报错中止 | 杜绝"读几段就开始瞎编" |
| **六要素讲成故事** | 世界/力量/人物/起因/经过/结果，必须能讲成一个完整故事，有递进阶梯+爽点落点+追读欲 | 立项不是堆设定 |
| **改编继承表** | PRD 末尾列出保留的质量锚 + 用户拍板的偏离项（含原因+影响） | 偏离可审计、可回溯 |
| **冲突项 ≤3 一次拍板** | 与包结构参数冲突时（如 X 要慢热但包蓄力≤2段）逐项列清单，用户一次选 | 不在流程里反复打断 |

## 6. 深度：全链路对"改编"的接力（不只是立项层）
- popwave 的改编不只停在立项：**test-world** 按强度保留/重写力量体系+11 文件；**test-character** 保留 28 人规模/6 配置位/四层反派梯度，人物 100% 原创；**test-plot** 用核心张力映射表重推逐章事件；**test-write/review** 每章校验 X 体验层落地 + 事件原创性。→ **改编是整条管线的纪律，不是开头一次选择**。

---

## 7. 操作顺序（专业克制，不一次吃全）
先选强度 A/B/C（决定改多少）→ 产出 X DNA 替换矩阵 + 改编继承表 → 立项 PRD 定六要素方向 → 交给 world/character/plot 接力 → write/review 每章校验原创边界。**不急着一口气"全重写"，用强度档位控制每一步的改动范围。**
