## 0. 一句话卖点

**popwave 不给你"读后感式设定"，而是把一本成功书拆成 9 张规则表、转写成一整套 28 文件的"设定包"——包自带结构、引用和加载规则，像 skill 一样自描述、可消费、可回溯到 chXX。**

## 1. 用户痛点：想学爆款，但书太大、拆不动、拆完也没用

| 痛点 | 表现 | 后果 |
|---|---|---|
| **原著太大** | 百万字长篇，逐章读不现实、记不住细节 | 拆书=走马观花，学了个寂寞 |
| **拆了不会用** | 看一堆"写作技巧总结"，还是不知道力量体系怎么分阶、节奏怎么排 | 干货埋在信息堆里，无法直接喂给写作 |
| **凭感觉拆** | 靠记忆/书评/网上二手数据重构"爆款配方" | 拆错、编造，误导后续创作 |

> 核心难点不是"读"，是"读→结构化→可复用"的工程化。popwave 用"9 表拆解 → 转写 28 文件 → 包=skill"把一本书变成**可直接被世界/剧情/正文环节消费的设定包**。

## 2. 关键认知：一本着作=一张可复制的"包配方"

把成功书当成**一套参数系统**，而不是一条故事线。故事线是一次性的，参数系统才是可复用的商业内核：

| 拆出的层 | 对应"参数" | 有什么用 |
|---|---|---|
| 力量体系 | 主养成线阶位/子养成线/交叉规则 | 世界/角色照着搭 |
| 剧情节奏 | 爽点密度/钩子率/卷幕骨架 | plot 照着排章节 |
| 开篇解剖 | 首三章功能位/情绪节拍 | write 知道怎么开篇 |
| 金手指深度 | 三约束/成长路线 | 角色金手指照着设计 |
| 角色配置 | 28 人规模/6 配置位/反派梯度 | character 照着建库 |

> 卖点：爆款书=**可测量的规则**，不是"感觉它火"。它"为什么火"拆成 9 张表，每张都能复用。

## 3. 反面教材：为什么"拆书"拆不出来（我们敢说这是坑)

- **光拆剧情不拆规则**：只记录"主角从弱到强干了啥"，没拆出力量体系怎么分阶、成长代价怎么滚滚。→ 学到的是"一个故事"，不是"一套能复用的引擎"。
- **二手数据堆砌**：用网上的书评、论坛"设定整理"拼凑，不是从原文采样。→ 拆出来是别人的理解，还可能编造。
- **拆完成死文件**：拆出几十个 md 堆在一起，世界/角色/剧情环节不知道该读哪一个、按什么顺序读。→ "拆了白拆"。

## 4. 机制：三层实操，把"一本书"变成"一个包"（test-research · 工程级）

### 4.1 9 表拆解：从原文抽硬数据
- 9 张表：力量体系 / 剧情节奏 / 情绪弧线 / 人称视角 / 开篇解剖 / 势力格局 / 金手指深度 / 世界危机引擎 / 动力引擎。
- **表 1 必须拆到规则级**：主养成线≥4 阶 + 子养成线≥2 条 + chXX 出处；不看名字看"它一套规则怎么运转"。
- **小巧思**：表 9 动力引擎纯拆"驱动逻辑/运转机制/代价结构/范式归类/合一性"，不混进剧情。→ 拆的是"世界为什么动"，不是"主角干了啥"。

### 4.2 包配方 5 张参数表：硬对齐层的唯一真源
- 从 9 表蒸馏出 5 张"亲写可复制参数表"：表1卷幕骨架 / 表2节奏参数 / 表3颗粒度参数 / 表4爽点配方 / 表5角色配置。每张都有取值 + 仿写规则（抄什么/换什么）。
- **参数数值化铁律**：禁止"快/慢/多"这类模糊词，爽点密度/钩子率/敌分级/子养成线条数全部带数字。→ 参数越具体，下游 writer 越不容易跑偏。
- **5 表齐全才准入**：缺任一表=包不合格，管线拒绝启动。推断处标注降权。

### 4.3 转写 28 文件：把表变成可消费的包
- DL5 把 9 表转写为七文件夹：立项 / 赛道特色 / 力量与战斗 / 世界观 / 角色库 / 剧情库 / 补充参考。
- 战斗表现拆 5 件（通用层/凡人期/超凡期/神明级/特殊条件战），按主角等级段按需加载。→ write 时不用一次读一个大文件。

## 5. 可测量 / 门禁：包质量有硬门槛，不是"能拆就合格"

| 门禁 | 口径 |
|---|---|
| **原文存在性** | 动拆前必须验证 txt 存在、非空、读过正文；不存在报错中止，禁止凭记忆/书评/二手数据重构 |
| **9 表完整** | 9 张表全齐，表 1 规则级、带 chXX 出处 |
| **5 参数表齐全** | 缺任一表=包不合格，管线拒启动 |
| **参数数值化** | 全数字，禁"快/慢/多"；推断处显式标注降权 |
| **单文件≤15KB** | 防 agent 过载（中文 UTF-8 每 3 字节 1 字符口径） |
| **top≥5 本** | 赛道调研质量门禁（借≥3+避雷≥3+细分≥3） |

## 6. 深度：包=skill，包自带"加载协议"
- 一个包是一个**自描述知识单元**：文档按"消费者×加载时机"分层，world/character/plot/write 各自按协议读自己需要的文件，不冗余加载。
- **包内置映射节**：所有 test 系 skill 的包侧读取路径都以包配方的映射节为准，结构变异包也能被正确消费。→ 包不是文件堆，是**可编程的设定资产**。

## 7. 操作顺序（不贪快）
先验证原文存在（门禁）→ 拆 9 表（重点表1规则级）→ 转写 28 文件 → 蒸馏 5 参数表（数值化）→ 落包配方含映射节 → 交下游逐步消费。**拆书较耗算力，建议先第一卷少量测试再全量。**
