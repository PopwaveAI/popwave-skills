## 0. 一句话卖点

**popwave 把"快节奏、有爽点"从"感觉"变成"过不过门禁"——战斗按场次计密度、七查自检绿灯才交正文、卷纲列出"不能抢的后续收益"，从剧情层就锁死读者追读欲。**

## 1. 用户痛点：网文规划阶段，最容易"前紧后松"

| 痛点 | 表现 | 后果 |
|---|---|---|
| **剧情队** | 开头高潮、中间注水、后面乏力 | 追读断崖、读者流失 |
| **爽点不均** | 有的章全是铺垫、连续几章零冲突 | 读者划走 |
| **前悔透支** | 卷一就把后卷的高潮/爽点、敌人底牌用光了 | 后期无爆点可写 |
| **战斗没密度** | 几十章不打一场、或一章塞无数场 | 节奏崩、战斗疲劳 |

> 核心难点不是"能不能编剧情"，是"规划阶段就让密度可量化、可验证"—别等写了几十章才发现节奏崩了。popwave 用"核心张力映射 + 七查门禁 + 防抢盘收益"在立案层就卡死节奏。

## 2. 关键认知：爽感要"在首页可检查"，不能"等写完才知道"

| 层 | 换算成可检查的"量" |
|---|---|
| 战斗 | 按"场次"计密度，不是"有没有战斗章" |
| 冲突 | 零冲突章占比 ≤10%，且不许连续 2 章零冲突 |
| 爽点 | 每章 ≥0.9 个、有爆发感（本质：锚点爽感公式必须落地） |
| 节奏 | 蓄力≤2 段 / 信息≤3 段 / 情绪≤2 段（默认快节奏线） |
| 收益 | 卷纲显式列出"不能抢的后续收益" |

> 卖点：把"爽不爽"由读者说了算，改成"立项时就能自检"。第 3 节是反面教材。

## 3. 反面教材：为什么"排剧情"常常排崩（我们敢说这是坑)

- **只列"发生了啥"不列"密度"**：一章一个高潮点，但分布没检查 → 开头爽、中段干、结尾瘫。
- **战斗当章节数不当场次**：一章塞 3 场(对手/目/空间各不相同)却算"s含战"，或被"同战场多点击杀"强行算成多场→密度统计失真，看不出"已经很久没打真的了"。
- **猎人用尽**：卷一就把后卷 BOSS 当垫脚石、把最终爽点提前兑现 → 后期没东西可给读者。

## 4. 机制：让剧情规划"可自检"（test-plot · 工程级）

### 4.1 核心张力映射表：剧情唯一的推导源
- Step1 从包幕1张力提炼"冲突模式"一句话 → 映射本书 X 核心张力 → Step2 逐章事件从"幕 X 张力轴 × 本章前情 × 角色库人物动机"现推。
- **铁律**：映射表内禁出现包具体事件/台词/道具/人名。→ 事件原创不靠"别抄"，靠引擎重推。

### 4.2 Step2.5 章纲组装：叙事原子 4-6 锚定正文
- 白描卡 × 元素卡库 → 章纲。拼装五步：读下发 / 选族 / 填槽 / 现编细节 / 记账+门禁。
- 每章叙事原子 4-6 个、全章料≥40 条、量化料≥1/3、白描卡🔒锚 100% 落位、线账本达成目标。
- **小巧思**：正文结构不是 write 现场编的，是 plot 锁定"叙事原子序列"，write 只负责把情境写得好看 → 章章结构可预期。

### 4.3 七查快爽自检门禁：绿灯才交 write
每幕强制门禁，查 7 项：
1. **战斗密度按场次计**：硬底线≥1 场/5 章，目标线≥1 场/3 章，无战间隔≤5 章，首杀≤ch0004。
2. **零冲突章** ≤10%，禁止连续 2 章零冲突。
3. **成长收获**：每段有主角的所得（数值/技能/资源/认知）。
4. **钩子**：章末有追读钩子。
5. **节奏红线**：默认快节奏（蓄力≤2段/信息≤3段/情绪≤2段）。
6. **对齐**：与包配方/幕功能位/角色库一致。
7. **章纲密度 + 事实核验**：实测字段对照状态快照，防错误传染。

> 亮点：**战斗按"场次"计** = 一场=独立对手+独立目的+独立空间；一章 3 段小遭遇=3 场；同目的同战场多点击杀=1 场；旁观无关打斗不计；高烈度智斗算冲突不算战斗场次。→ 密度统计精确，不被粗颗粒"含战章"糊弄。小书下限可降 60%。

### 4.4 卷纲防抢后续收益：不给未来"透支"
- 卷纲显式列出"不能抢的后续收益"，Step2 自检强制确认未提前兑现。
- 角色登场/退场章对齐角色库；卷末收益三件套、质变点位、后续爆点全部保护。→ 让读者有理由追到下一卷。

## 5. 可测量 / 门禁：节奏全带数字

| 门禁 | 口径 |
|---|---|
| 战斗场次 | 硬底≥1/5章、目标≥1/3章、无战间隔≤5章、首杀≤ch0004 |
| 零冲突章 | ≤10%，禁连 2 章零冲突 |
| 爽点密度 | ≥0.9/章，锚点爽感公式落地且爆发 |
| 叙事原子 | 每章 4-6 个；章料≥40 条；量化料≥1/3 |
| 收益保护 | "不能抢的后续收益"未提前兑现 |
| 七查绿灯 | 全过才交付 write |

## 6. 深度：章纲=情节层的"质量刹车"
章纲组装层的门禁让 **plot 在正文渲染前就把密度、冲突、钩子、事实全部过一遍**——不是写完再修，而是在剧情规划阶段用绿灯/红牌控制节奏。这是"快爽自检"作为可证卖点的核心。

---

## 7. 操作顺序
先靠核心张力映射表重推主线(事件原创) → 按幕写白描卡(含锚点9行) → Step2.5 组装章纲(原子4-6+料计) → 每幕跑七查门禁 → 绿灯才交 write → 写审循环里每章 review 复核。**节奏自检在规划阶段,不在写完后悔。**
