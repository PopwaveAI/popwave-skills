## 0. 一句话卖点

**popwave 让连载"越写越稳"——每章沉淀"白描卡 + 状态快照"双文件，用"禁止漂移硬清单 + 事实以快照为准"锁死人名/等级/已死角色/已废设定，长篇几十万字后人物、设定、伏笔一个都不崩。**

## 1. 用户痛点：长篇写作真正的地狱不是开头，是中后期

| 痛点 | 表现 | 后果 |
|---|---|---|
| **记不住** | 30 万字后记不清谁死了、谁还欠着谁、伏笔埋哪了 | 前后矛盾、穿帮 |
| **崩设定** | 角色年龄/等级/关系在后续章节悄悄变 | 读者出戏、口碑崩 |
| **伏笔雪崩** | 埋下的线不收、钩子不还 | 读者被吊死,追读断 |
| **续写失忆** | 上章写了啥,下章衔接不上 | 章节断层 |

> 核心难点不是"写得好不好",是"几十章后的连续性"。popwave 用"双文件记忆(白描卡+状态快照)+ 写-审循环"把"我记得"变成"系统替我记着"。这是长篇能写完、能连载的核心基础设施。

## 2. 关键认知：连载的"记忆"要外置，不能靠作者脑内

| 记忆载体 | 存什么 | 谁写 | 谁读 |
|---|---|---|---|
| **白描卡** | 事件白描/关键数据🔒/爽点钩子/人物关系变化 | review 沉淀 | write 续写读前3章 |
| **状态快照** | 未回收钩子台账/角色当前状态/禁止漂移 | review 沉淀 | write/review 跨章校验 |
| **创作记录** | write 产生的新增事实声明(待 review 落库) | write 声明 | review 决定是否落库 |

> 卖点:把"作者靠脑子记住整本书"改成"双文件是全书唯一的记忆真源"。write 只声明、review 才落库,权限边界清楚,防 write 越权写乱库。第 3 节反面教材。

## 3. 反面教材:为什么"纯靠作者记"必崩(我们敢说这是坑)

- **一个人脑背整本书**:中后期人名、等级、伏笔全靠回忆 → 必然穿帮,越写越乱。
- **写-审耦合在一个环节**:写完就发,没人核对"上一章谁说死了、这一章怎么又活了"。
- **重写后状态不回填**:修改了正文,但角色状态/伏笔台账没同步 → 下一次续写又错。

---

## 4. 机制:让连载"减号漂移"(test-review / test-write · 工程级)

### 4.1 写-审循环:一章一沉淀
- **每写1章→审1章**。review 达标率<90% 直接打回(先配方符合性,再做其余审)。
- 通过后沉淀双文件:白描卡(事件白描/关键数据🔒/爽点钩子/人物关系变化)+ 状态快照(未回收钩子台账/角色当前状态/禁止漂移)。
- write 续写下一章时读"近 3 章章纲 + 状态快照",向前锚稳定。

### 4.2 事实以快照为准:错误不传染正文
- write 渲染时,章纲里的事实字段(年龄/等级术语/人名)与状态快照/近5章正文冲突 → **以状态快照为准**。
- 创作记录中记录冲突,**禁止把章纲事实错误原样写进正文**。→ 拦截"组装层错一个数字,写着写着全章跟着歪"的传染链。

### 4.3 禁止漂移硬清单:不可改事实锁死
- 状态快照含"禁止漂移"清单:人名/地名/阶位数值/已死角色/已废设定。**写错等于 bug**。
- 小巧思:把"不可改"和"可更新"分开——活状态(角色位置/当前关系)可更新,死事实(已死/已废/人名)禁止动。→ 既保证灵活性又锁死底裤。

### 4.4 review 不重写正文,只诊断+打回
- 红线:review 不重写正文,只列出打回清单(由 write 改)。打回只列清单,不代写。→ review 是质检员+状态沉淀器,不吞 write 的写作控制权。

### 4.5 批量回溯:已有正文也能重建双文件
- reconstruct 用于导入/续写:<10章全审;11-30章最近5章全审+其余每5章取1;>30章最近5章全审+第一章+每10章取1。非采样章节快速提取关键信息汇入状态快照。
- → 已有几十章正文、状态文件全丢的项目,也能快速补出双文件继续连载。

## 5. 可测量 / 门禁:连续性可验收

| 门禁 | 口径 |
|---|---|
| review 达标率 | <90% 直接打回 |
| 状态快照 | 含未回收钩子台账 + 禁止漂移清单 |
| 事实冲突 | 以状态快照为准,错误不写进正文 |
| write 权限 | 只声明新增事实,review 才落库 |
| 回溯覆盖 | ≤10全审/11-30采样/31+采样+首末 |

## 6. 深度:双文件是"续写不失忆"的真源
长篇能连载,前提是"系统替你记着整本书的呼吸"。白描卡管"这章发生了什么",状态快照管"世界里谁还活着、谁欠谁、什么已死",写-审循环保证每章都回填。这是 test 管道能把"一本书写到几百万字仍不崩"的底层能力。

---

## 7. 操作顺序
写1章 → 审1章(七审含事实/爽点/原创)→ 达标沉淀双文件 → 续写下一章读近3章+快照 → 冲突以快照为准 → 卷/全书阶段做批量回溯校验。**不是写完就发,是每章都回写记忆、下章都读记忆。**
