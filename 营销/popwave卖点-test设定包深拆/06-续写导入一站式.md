## 0. 一句话卖点

**popwave 的管线原生于 fresh / import / resume 三种模式——你不需要从零开始，已有大纲、正文、角色库都能归位进同一管线，自动识别缺口、标注来源、补跑缺失环节，续写旧项目和开新书一样顺。**

## 1. 用户痛点：写书人最痛的一刻，是"换工具/丢进度"

| 痛点 | 表现 | 后果 |
|---|---|---|
| **换工具搬家难** | 已有大纲/正文/角色库在别的软件里,导不进新体系 | 要么重写、要么不用 |
| **续写不知道卡在哪** | 忘了写到哪一章、哪个环节没配齐 | 无从下手、乱续 |
| **旧项目状态丢失** | 白描卡/状态快照没存,几十章后没法续 | 连续性断、前功尽弃 |
| **流程无头绪** | 不知道下一步该用哪个 skill | 来回瞎试 |

> 核心难点不是"写",是"管理项目状态 + 接续已有资产"。popwave 用"项目总控.html + 三种 mode + 来源标记 + 自动补跑"把"开新书"和"续写旧项目"统一成一条无缝管线。

## 2. 关键认知：项目状态的"真源"是一份总控文件,不是一个目录散件

| 载体 | 记什么 | 谁读 |
|---|---|---|
| **项目总控.html** | mode/phase/chapter/项目名/更新时间/各就绪态 | 每次 run 先用它定位"当前在哪、缺什么、下一步" |
| **来源标记** | 每个文件的来源(user-original/pipeline-relocated/skill-generated/skill-reconstruct) | 决定哪类文件要校验、哪类可直接消费 |
| **缺口报告** | 导入时自动生成的缺项清单 | pipeline 据此调度补跑 |

> 卖点:把"项目现在在哪、还差什么、下一步干嘛"从作者脑内搬到一份可视化总控。续写旧书不再靠记忆,靠总控。

## 3. 反面教材:为什么"换工具续写"常翻车(我们敢说这是坑)

- **从零迷信**:强行"新书必须从 seed 起",把已有大纲/正文丢一边 → 白白重写、还丢设定。
- **乱导入**:把旧文件无脑拷进来,不分来源 → 不知道哪些是作者原稿、哪些是生成品,出了问题无从担保。
- **续写失忆**:没有总控/快照,旧项目已写 30 章但状态文件丢了 → 只能重新读过或放弃。

---

## 4. 机制:让"续写"像"开新书"一样顺(test-pipeline)

### 4.1 三种 mode:开新/续写/导入一条管线
- **fresh**：标准从 seed 起。
- **import**：扫描已有文件 → 原始资产清单 → 文件归位 → 来源标记 → 缺口分析 → 落地 Phase 决策 → 状态文件重建。
- **resume**：基于项目总控继续推进。

### 4.2 来源标记:质量分账,谁的可信谁的可改
- 4 类来源：**user-original / pipeline-relocated（作者原稿/搬移）需校验；skill-generated / skill-reconstruct（系统生成）可直接消费**。
- → 导入旧项目时用户一眼知道哪些是已有真稿、哪些是重建的、哪些还需校验,信任有据。

### 4.3 自动补跑:缺什么调度什么
- 导入发现缺白描卡/状态快照 → 调 test-review reconstruct；缺设计文档 → 按依赖链调度 adapt/world/character/plot 补跑。
- **reconstruct 支持"有正文但缺状态文件"的回溯** → 旧项目不需重写,自动补齐系列。

### 4.4 Phase 就绪门禁:不达标就停,不假推进
- Phase 1→3 查改编计划(含 X DNA 矩阵/剧情类比)与 PRD；Phase 3→3.5 查力量体系晋阶表/全书设定非空；Phase 4→5 查卷纲/章纲/白描卡/plot 锚点/七查绿灯。
- → 管线不是机械推进,每阶段检查真实产出,避免"看似走完实际没内容"。

---

## 5. 可测量 / 门禁:项目状态可验收

| 门禁 | 口径 |
|---|---|
| 项目总控 | 唯一状态文件,记录 mode/phase/chapter/各就绪态 |
| 来源标记 | 4 类来源,影响校验/消费策略 |
| 缺口报告 | 导入自动生成缺项清单 |
| Phase 门禁 | 上游产出真实性达标才放行下一阶段 |

## 6. 深度:总控=管线的"方向盘"
pipeline 只做路由不干活,每次 run 先用项目总控定位"当前在哪、缺什么、下一步该干哪个 skill"。这使"开新书 / 续写 / 导入旧项目"三种场景共用同一套衔接逻辑,是 test 家族能工程级运行的中枢。

---

## 7. 操作顺序
读项目总控定位 → 选 mode(fresh/open/import/resume)→ 若 import:扫描→归位→标来源→缺口分析→落地 Phase→重建状态 → pipeline 依 Phase 路由(expert-sub-step)→ 每阶段过就绪门禁 → 写审循环 → 回写总控。**从"我在哪"开始,不是从"我该写啥"开始。**
