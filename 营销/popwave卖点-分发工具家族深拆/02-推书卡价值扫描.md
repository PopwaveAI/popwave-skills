# 推书卡价值扫描 · 机制级卖点深挖（pop-recommend）

> 性质：原材料，非对外稿。对标 `../popwave卖点/01-去AI味.md` 样板颗粒度。「一个卖点一文档」第 02 号。
> 依据：pop-recommend 的 SKILL.md + `steps/step2.md` + `templates/reading-metrics.tpl.json` 等 + `popwave卖点-逐skill拉片/08-分发工具家族.md`。

## 0. 一句话卖点

**popwave 把"推荐一本书"做成可审计的评分工程：100 章只精读 30-40 章（三阶段价值扫描），每个判断绑定 evidence_id 可溯源到原文、spoiler 三级控制不剧透，6 维量化评分输出推荐区间，判定唯一产出 review.json——不是"我读过这本书所以好"，是"每条判断都有证据、每个分数都可算"。**

## 1. 用户痛点：推书推荐"空泛、像剧透、读不完"

| 痛点 | 表现 | 后果 |
|---|---|---|
| **AI 读不完** | 全书逐章摘要太重，模型上下文爆 | 推书退化成"开头几章感受" |
| **推荐无依据** | "这本书很好"没有原文背书 | 读者不信任 |
| **成了剧透** | 亮点/缺点剧透了关键情节 | 新读者体验破坏 |
| **评分太主观** | 星级凭感觉 | 读者无法横向比较 |

> 核心焦虑：推书卡的信任来源不是"看过"，而是"每个判断可溯源、每本书可比"。

## 2. 关键认知：把"读过"升级成"扫描过的有证据的评审"

高质量推书 = 三阶段价值扫描（骨架+锚点+阅感采样）控制阅读成本 + 证据链闭环（判断绑定 evidence_id 原文≥50字）保证可信 + spoiler 三级控制保护新读者 + 6 维量化评分给出可算的推荐区间。

## 3. 反面教材：无源推荐与逐章剧透

- **逐章摘要**：读完全书太重，产出却散，AI 记不住重点。
- **无证据卖点**："人物塑造好"但给不出原文段落，读者无法核验。
- **推荐=剧透**：把 major 级关键情节抖出来，新读者被毁。
- **评分拍脑袋**：星级没有维度拆分和计算口径，无法比较。
> 正确做法：见第 4 节——三阶段扫描 + 证据链 + spoiler 分级 + 6 维可算评分。

---

## 4. 机制：三阶段扫描 + 证据链闭环 + spoiler分级 + 6维评分 + review.json唯一输出

### 4.1 三阶段价值扫描（核心，100章只精读30-40章）
Phase 1 骨架扫描：首章+每卷首尾+尾章约 15-20 章 → `structure-map.json`；Phase 2 锚点深读：highlight/controversy/character/relationship 相关章约 10-15 章 → `anchor-pool.json` + `evidence-ledger.json`；Phase 3 阅感采样：全书均匀 5-8 章，6 维度量化打分 → `reading-metrics.json`。**红线：禁止逐章摘要，只围绕价值锚点精读。**

### 4.2 证据链闭环（核心，小巧思）
每个 strength/controversy/character 必须引用证据台账，excerpt≥50 字。评审生成从 `anchor-pool.json` 和 `evidence-ledger.json` 提取判断——**禁止无证据的卖点或争议**。

### 4.3 spoiler 三级控制（小巧思）
推书只服务新读者，只能消费 **safe + mild** 锚点：synopsis 只用 safe；strength/character/controversy 的 mild 内容做模糊化（去掉具体情节，保留趋势）；**major 级禁止进入推荐判断**。

### 4.4 6 维量化评分 + 推荐区间
维度 = characters/plot/prose/relationships/world/pacing。base_score = 6 维均值；strengths≥3 且 controversies≤2 等条件触发 audience_bonus；最终输出 score_low/high、stars_low/high、grade、verdict——**不是星级，是区间+等级**。

### 4.5 受众画像拒绝泛泛（小巧思）
audience 必须输出 recommended 和 avoid，每条是具体读者画像，禁止"喜欢 XX 的读者"的泛泛描述——结合 strengths/controversies/reading_metrics 综合判断。

### 4.6 review.json 唯一输出 + 5 JSON 工作稿
Phase1 产出 4 个 JSON 工作稿，Step2 消费合成 `review.json`，红线：**review.json 是唯一评审输出，禁止生成 input+draft 双 JSON 重复**。下游 Step3 HTML 直接读 review.json。

### 4.7 5 条红线构成强质量门禁
读取用 `Get-Content -Encoding UTF8 -Raw`；禁止逐章摘要必须三阶段扫描；所有判断绑定 evidence_id；review.json 唯一输出；Step 文件链式加载禁止跳。

---

## 5. 可测量 / 门禁

| 门禁 | 口径 |
|---|---|
| **精读量** | 30-40/100 章，不到即重 |
| **证据绑定** | 每判断引用 evidence_id，excerpt≥50字 |
| **spoiler 门禁** | 仅 safe+mild，major 禁入 |
| **6维评分** | base_score 均值 + audience_bonus 规则 |
| **唯一输出** | review.json，禁双 JSON |

## 6. 深度：推书卡是"阅读→推荐"的信任转化层
被分发环节消费，产出可分享的自包含 HTML 推书卡。**营销价值**：它把"我读过所以推荐"升级成"扫描过的、每个判断有原文证据、不剧透的工程化评审"——信任可被复现。

---

## 7. 操作顺序（先扫，再锚，再算，再审）
Phase1 骨架扫描→Phase2 锚点深读（含证据台账）→Phase3 阅感采样打分→Step2 消费 4 个 JSON 合成 review.json（绑证据+spoiler分级+算6维评分）→Step3 读 review.json 渲染 HTML 推书卡。

## 9. 竞品差异锚（一句话）
市面推书 = 逐章摘要太重 / 无证据 / 剧透 / 凭感觉打分；popwave 推书卡 = **三阶段扫描省算力 + 证据链可溯源 + spoiler分级保护新读者 + 6维可算推荐区间 + review.json唯一判定**。
