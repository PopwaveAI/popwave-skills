## 0. 一句话卖点

**popwave 番茄引擎先定义"读者是谁"再写作：一个 12 岁小学生、手机竖屏滑动、每 30 秒要看到新内容、连续 3 段纯氛围就划走——爽感有公式（压力→突破/弱→强/未知→揭示/被欺→反击），节奏有物理量（事件间隔 ≤20 行 / 多感官 ≤3 行 / 情绪 ≤2 行 / 事件密度 8-12 个每章），"写得爽"从玄学变成能逐条检查的生产指标。**

## 1. 用户痛点：爽文作者最怕"作者自嗨"

| 痛点 | 表现 | 后果 |
|---|---|---|
| **共鸣错位** | 按自己喜欢/自己水平写，读者读不进 | 数据差、追读崩 |
| **无从判断"够不够爽"** | 写完了说不清这章爽点足不足、节奏行不行 | 只能凭感觉，反复重写 |
| **节奏忽快忽慢** | 有的章挤爆、有的章拖沓 | 读者划走，弃书 |

> 核心焦虑：爽文写手需要一个**客观到能对答案的尺子**——否则"写得爽"永远靠运气。番茄家族把读者模型捞出来当尺子，让每个写作决策都有"读者会怎么反应"的根据。

## 2. 关键认知：读者不是"抽象读者",是"可建模的滑动行为"

把读者具象成 **12 岁小学生 + 手机竖屏 + 滑动阅读 + 30 秒耐心 + 3 段氛围上限**，所有写作决策都有行为参照系：
- 手机滑动 → 信息要短、要密，每段要有"为什么我没划走"。
- 30 秒新内容 → 事件密度要高，不能连着几段纯氛围。
- 连续 3 次纯氛围就退出 → **纯氛围段是退书炸弹**，必须限行数。
> 卖点：**不是"写好文"，是"写给一个 12 岁的人、在他刷手机的第 30 秒、让他不划走"**——读者模型是可执行的读者定义。

## 3. 反面教材："写得厉害"为什么爽文翻车

- **作者自嗨型**：用高深的情绪描写、长句渲染氛围——书桌文学，没人追。
- **空爽无铺垫**：主角无缘无故赢了，没有"压力→突破"的因果——读者觉得假、没爽感。
- **无果爽点**：爆发后直接跳下一事件，不给反馈/余韵——"赢了个寂寞",爽不起来。
> 正确做法：看第 4 节——用爽感公式 + 节奏物理量把"爽"拆成可测量的触发结构。

## 4. 机制：爽感公式 × 节奏物理量 × 三段式闭环，三件套量化"爽"

### 4.1 番茄读者模型（写作前先定义读者）
- **12 岁小学生 / 手机竖屏 / 滑动阅读**：判断一切"会不会被划走"。
- **30 秒 / 连续 3 次纯氛围退出**：纯氛围是退书炸弹。

### 4.2 爽感公式：四类"被欺→反击"最短路径
| 公式 | 本体 | 本质 |
|---|---|---|
| **压力 → 突破** | 长期压力一次翻盘 | 蓄力释放 |
| **弱 → 强** | 被轻视者实力揭晓 | 层级反转 |
| **未知 → 揭示** | 谜底揭晓那一刻 | 信息差兑现 |
| **被欺 → 反击** | 委屈 → 反杀 | 情绪释放 |
- **铁律：爽感必须有铺垫，无铺垫爽感=空爽。**

### 4.3 节奏物理量（番茄被反复引用的量化参数）
| 量 | 口径 |
|---|---|
| 事件间隔 | **≤20 行**（不让读者等太久） |
| 多感官场景 | **≤3 行**触发一次 |
| 情绪表达 | **≤2 行**（情绪不啰嗦） |
| 事件密度 | **8-12 个 / 章** |
| 爽感 | **≥1 个 / 章** 且有爆发感 |

### 4.4 爽感三段式闭环（承接 05、07，全家族复用的爽感结构）
- 所有爽感爆发后必须三段式：**爆发（≤3 行）/ 反馈（≤2 段）/ 余韵（≥1 段）**。
- 反例：爆发后直接跳到下一事件，没有反馈和余韵。

## 5. 可测量 / 门禁：读者反应可以被量化验收

| 量 | 口径 | 意义 |
|---|---|---|
| **事件密度** | 8-12 个/章 | 防拖沓 vs 防挤爆 |
| **爽感≥1** | 每章有触发+爆发+后果 | 防"水章" |
| **爆发≤3行** | 爽点爆发不拖沓 | 防"爆而不爽" |
| **纯氛围≤3行/≤3次** | 连续纯氛围=退书炸弹 | 防止读者划走 |

## 6. 深度：读者模型是全家族一切数字的源头
- **write** 靠它选章型/爽感引擎；**world** 靠它定战斗"快打"节奏；**review** 靠它查节奏密度、爽感闭环、主动性——整个番茄管线按同一把"读者尺"看所有产出。
- **营销价值**："你买的不是一个写作工具，是一整套建在'读者会怎么滑手机'上的量产爽文方法论"。
