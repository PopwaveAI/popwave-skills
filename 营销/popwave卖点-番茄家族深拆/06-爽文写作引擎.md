## 0. 一句话卖点

**popwave 番茄爽文写作引擎：写每章不从头想结构，先选 6 种章型之一、套 7 节拍骨架、自动锁密度约束、配 5 种爽感引擎，再用 章型×爽感×技法 三联动收口——正文 2000-2500 字是硬卡口（超 2500 裁、超 3000 废、靠脚本 API 自动裁剪），最后交付一张带动作链/多感官/爽感/技法四指标的可审计面板。**

## 1. 用户痛点：每章都从零开始，质量和节奏没法保证

| 痛点 | 表现 | 后果 |
|---|---|---|
| **结构随缘** | 每章开头现想，章型/节奏不统一 | 有的章密有的章平，读者难追 |
| **爽点靠灵感** | 爽点时有时无、爆发没爆发感 | 有的章爽有的章水 |
| **字数常失控** | 越写越长，注水 | 拖节奏、掉追读 |

> 核心焦虑：篇篇不同的章节要有"**统一但可变**"的生产骨架——结构层由章型/节拍/密度锁住确定性，表达层交给技法，让"这一章是爽文该有的样子"成为机制默认，而非碰运气。

## 2. 关键认知：爽文章节能被"骨架化"，且骨架要硬到能当门禁

番茄爽文大量重复的结构（打脸/突破/揭示）其实能抽象成**章型+节拍+密度约束**：先选"这章要让读者爽到哪个点"，就锁定了骨架和密度；字数、AI 味、好看度再用硬卡口兜底。**骨架化不是套路化**——骨架决定"这一章该完成什么、该多长"，具体表达交给技法/笔触。

## 3. 反面教材："自由发挥"式写作为什么不稳定

- **每次从零想结构**：章型/节奏各写各的，风格飘、密度不稳。
- **爽点碰运气**：有时爆爽有时水，读者追读忽高忽低。
- **字数失控**：写长失控、注水，拖垮节奏（违反番茄 ≤20 行/8-12 事件的节奏物理量）。
> 正确解法：看第 4 节——章型/节拍/密度/爽感/字数全机制化。

## 4. 机制：5 大件把"这章怎么写、写多长、写到多爽"全部锁死

### 4.1 6 种章型骨架：番茄爽文场景标准化
- 章型：**opening_shift / exploration_gain / confrontation_pressure / combat_reversal / high_tier_display / reveal_hook**。
- 每种 = 适用条件 + 读者期待 + 主动行为类型 + **7 节拍骨架**。
- 卖点：写每章不是从头想结构，是先选章型再按节拍填充。

### 4.2 7 节拍骨架 + 密度约束：章与章之间有节奏可复用、可锁定
- 每种章型 7 个节拍，节拍功能通用、笔触绑在 DNA 模板（节拍定功能，笔触定味道）。
- **密度约束自动锁定**：combat_reversal 必须有战斗且占比 ≥30%；opening_shift/confrontation_pressure 各有系统/信息差密度要求；**前 5 章不允许连续 2 章无战斗章型，且至少 1 章是 combat_reversal**。
- 小巧思：开篇节奏和战斗密度被机制锁住，**减少"写得太平"的风险**。

### 4.3 5 种爽感引擎：每章至少触发 1 个，且三段式闭环
- 5 种：**打脸循环 / 压力突破 / 未知揭示 / 小爽沿途 / 即时奖励**。
- 触发规格：打脸循环要求对方轻视 ≥2 层且翻盘 ≤3 行；压力突破要求突破 ≤3 行；小爽沿途要求每 3-5 事件有 1 个小爽。
- **三段式闭环（承接读者模型第 01）**：爆发（≤3 行）/ 反馈（≤2 段）/ 余韵（≥1 段）——避免"假爽"（爆发后直接跳下一事件）。

### 4.4 章型 × 爽感 × 技法 三联动：三层都有机制约束
- 写前必须选：章型（锁骨架）+ 爽感引擎（锁情绪点）+ 微观技法（锁表达工具）。
- **每章最多选 3 类技法，每类只选 1-2 个子技法落地**。
- 16 类微观技法分 3 大层：通用 5 类（信息差博弈/后果链设计/人设微操/节奏微操/预期违背）+ 情境 6 类 + 流派专属 5 类；每种含子技法、适用章型、使用步骤、注意事项、反例。

### 4.5 字数硬限制 + API 自动裁剪：长度是卡口，不是建议
- 正文 **2000-2500 字**，不含交付面板、不含 markdown 标记。
- **超 2500 必须裁剪；超 3000 废章重写**。
- `scripts/wordcount_check.py` 调 DeepSeek API 按优先级裁剪：环境描写 → 人物外貌 → 内心独白 → 铺垫段，**最后删对话**。
- 卖点：**正文长度不是建议值，是硬卡口**，避免写长失控。

### 4.6 交付面板四指标：每章产出可审计
- 字段：章号/章名/章型/字数/核心事件/爽感引擎/微观技法/**动作链数量/多感官场景数量**/章末钩子/推进 L2 线/笔触 DNA/前章钩子回收。
- 硬指标：战斗章动作链 ≥5、日常章 ≥3；每章多感官 ≥2、战斗章 ≥3。
- 卖点：review 和用户都能看到每章的写作指标，**不是黑箱产出**。

### 4.7 AI 味 15 项 pattern + 好看度 4 问（写后质检，与审核共用）
- AI 味 15 项 pattern（二分对比/开场清嗓子/伪洞察铺垫/浅层分析尾缀/重要性吹嘘/模糊归因/假强动词/同义词循环/机械节奏/情绪直给 等）+ 高疲劳词 S/A/B 三级（S 即标/A≥2 标/B≥3 标)，每项引用原文 + 给方向。
- 好看度 4 问（有没有往下翻的劲/最抓人的画面台词/哪里无聊/代入感够不够）每问必须给具体证据。

## 5. 可测量 / 门禁：一章写没写好，面板说了算

| 门禁/参数 | 口径 | 意义 |
|---|---|---|
| **章型+节拍** | 6 章型 7 节拍对齐 | 结构确定性 |
| **战斗密度** | combat_reversal 战斗占比≥30% | 防太平 |
| **爽感≥1+三段式** | 每章触发；爆发≤3行/反馈≤2段/余韵≥1段 | 防假爽 |
| **字数 2000-2500** | >2500 裁 / >3000 废（脚本核） | 防注水 |
| **动作链/多感官** | 战斗章动作链≥5、多感官≥3 | 质感可审计 |

## 6. 深度：写引擎是整条番茄产线的"渲染层"
- 它消费 plot 白描 + 读者模型 + 文风 DNA；它产出被 **review 审核**（章型/节拍/爽感/字数/主动性见 07）；三联动技法库被 write 直接调用。
- **营销价值**："这一章是不是爽文该有的样子"不用赌——**结构由章型/节拍/密度锁死，长度由硬卡口兜底，好坏由交付面板暴露**。"

---

## 7. 操作顺序（先选型，再填充，后质检）
选章型 → 套 7 节拍骨架 → 锁密度约束 → 配爽感引擎 → 三联动选技法 → 写正文（字数脚本核）→ 填交付面板 → 交 review。**先定型再写，写完按卡口和面板收尾。**
