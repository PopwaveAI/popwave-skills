## 0. 一句话卖点

**popwave 番茄审核引擎：四步闭环（正向符合 → 正文质量 → 反向充足 → 剧情沉淀），把"番茄底线"固化成硬门禁——字数/钩子/节奏/章型/合规一票否决、战斗按 world 4 拍查节奏与代价、主角主动性量化到 A/B/C 三级——结论只在对话内输出，落盘只留"白描卡(存发生)+状态快照(存状态)"双文件连续记忆。**

## 1. 用户痛点：写完一章，没人把关、也留不下记忆

| 痛点 | 表现 | 后果 |
|---|---|---|
| **写完就跑偏** | 正文脱线/违规/主角被动，没人揪 | 越写越歪，审核时大改 |
| **记录是负担** | 每章一份长报告，续写没人看 | 记录空转 |
| **钩子/状态丢** | 埋的钩子忘了收、角色状态变没记 | 前后矛盾、断篇 |

> 核心焦虑：番茄爽文要求高（字数/密度/合规/主动性），若没有**硬门禁 + 轻沉淀**，写完就失控。审核要同时解决"把关严"和"沉淀轻"。

## 2. 关键认知：审核 = 硬门禁判断 + 轻量连续记忆

- **硬门禁**：把"番茄该有的样子"（字数/钩子/节奏/章型/合规/战斗节奏/主动性）固化成可 REJECT 的检查项，不靠感觉。
- **轻沉淀**：结论对话内讲、不落盘报告；只落**白描卡（append·历史）+ 状态快照（replace·当下）**两个文件养全书连续记忆，喂续写。

## 3. 反面教材：又重又空的审核为什么是坑

- **重报告堆积**：每章 1000+ 字 verdict/报告，没人回看，纯负担（番茄 v4.11 已废）。
- **只查设定不查底线**：审了设定一致性，却放过字数超限、主动被动乱穿、政治红线命中。
- **无连续记忆**：埋的钩子不记账、退场角色不清理、事实漂移没人管——续写断片。
> 正确做法：看第 4 节——四步闭环 + 番茄底线门禁 + 主动 ABC + 双文件记忆。

## 4. 机制：四步闭环，把"番茄审核"做成硬卡 + 轻记忆

### 4.1 四步审核闭环
**Step1 正向符合**（主线/设定/角色/爽感闭环/番茄底线）→ **Step2 正文质量**（AI 味/笔触 DNA/好看度）→ **Step3 反向充足**（剧情白描/设定库/角色卡/燃料库是否足以续写）→ **Step4 剧情沉淀**（更新双文件）。
- 卖点：review 不只挑错，是判断"能不能继续写下一章"。

### 4.2 番茄底线门禁：一票否决，一视同仁
- **字数** 2000-2500（不准超 2500）。
- **章末钩子必须是主动决策型**。
- **节奏密度 8-12 个事件/章**；章型 7 节拍对齐；前后章衔接；章名 ≥10 字。
- **合规红线**：政治敏感 / 红线词 / 未成年保护 / 价值观命中 → **直接 REJECT**。
- 卖点：番茄向写作的硬标准被固化到审核门禁。

### 4.3 6 章型 7 节拍对齐检查（承接 write 章型真源）
- 检查本章章型归属 / 7 节拍完整 / 章型-内容匹配，读取 write 的 `references/章型定义.md` 对照判定。
- **红线：6 章型 7 节拍对齐是上游升级的下游卡口，缺一项不得通过**——write/review 共享章型真源，前后端不脱节。

### 4.4 战斗可写性审核（承接 world 的 4 拍节奏）
- 战斗章检查 **4 拍节奏"压迫→反转→碾压→余波"**、主角是否付可见代价、画风是否匹配力量体系、能力是否在规则边界内。
- **越界能力直接 REJECT**。

### 4.5 主角主动性审核：防止剧情推着主角走
- 检查：主角 ≥1 个主动决策？核心事件是否主角主动触发？行动是否推进自己目标？
- **主动性等级：A 主动出击 / B 主动应对 / C 被动推着走；连续 2 章 C 级 = REJECT 级警示**。
- 卖点：番茄爽文"主角主动出击"被量化到每章审核（承接读者模型 01 的"主角性"）。

### 4.6 多视角覆盖审核（承接 plot 非主角视角要求）
- 检查本幕 3-5 章是否 ≥1 段非主角视角；视角切换是否服务信息差/悬念/格局；单章非主角视角篇幅 ≤30%。

### 4.7 双文件叙事记录：白描卡存"发生"，状态快照存"状态"
- **剧情白描流水账（append-only）**：每章追加白描入口，每章约 3-5 句叙事流，100 章约 1 万字，无需三档压缩。
- **状态快照（replace）**：未回收钩子台账 / 角色当前状态表 / 禁止漂移。
- 卖点：全书连续记忆 = append 历史 + replace 当下，**既可读又可追踪**，续写不断片。

### 4.8 钩子台账含信息差类型：爽点/悬念储备可视化
- 记录：钩子 / 埋设章 / **信息差类型** / 预期回收 / 状态。
- 信息差类型：读者知·主角不知（**爽点储备**）或 主角知·读者不知（**悬念储备**）；**超 3 章未回收标红**。

### 4.9 审核结论对话内输出：不做冗余报告
- v4.11 起，审核结论只对话框内输出，不落盘 report/verdict；落盘只更新白描卡 + 状态快照。废除了审核报告 / verdict / 剧情累计卡 / current-state / review 沉淀等冗余文档。

## 5. 可测量 / 门禁：番茄审核有硬卡，不是走过场

| 门禁/参数 | 口径 | 意义 |
|---|---|---|
| **番茄底线** | 字数/钩子主动型/8-12 事件/章名≥10字/合规一票否决 | 硬标准固化 |
| **6 章型 7 节拍** | 缺一项不得通过 | 前后端同一真源 |
| **战斗 4 拍** | 压迫→反转→碾压→余波；代价/边界 | 防越界 |
| **主动 ABC** | 连续 2 章 C 级 REJECT | 防被动主角 |
| **多视角 ≤30%** | 每幕≥1 段非主角视角 | 承接 plot |
| **钩子台账** | 超 3 章未回收标红 + 信息差类型 | 爽点/悬念可见 |

## 6. 深度：审核是番茄产线"最后一关 + 记忆库"
- 它倒查 **plot 纲兑现 + write 章型/爽感/字数 + world 4 拍 + character 状态表**；它产出的双文件被 **pipeline 消费（进度/当前章）+ write 续写消费（状态快照）**。
- **营销价值**："把关严（硬门禁）+ 沉淀轻（双文件）"双管齐下——**一章过不过审、埋的钩子还差几个没收、角色现在什么状态，全部可看可追踪**。"

---

## 7. 操作顺序（先四步，再沉淀）
Step1 正向符合 + 番茄底线 → Step2 正文质量 → Step3 反向充足 → Step4 更新白描卡（append）+ 状态快照（replace）。**结论对话里讲完就散，落盘的只有双文件。**
