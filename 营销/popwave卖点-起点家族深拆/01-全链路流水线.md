## 0. 一句话卖点

**popwave 起点流水线：一条把"写长篇网文"从"我跟 AI 随便聊"变成"可预期、可回溯、不跑偏的工程生产线"的主线编排器——54 个 skill 多 agent 按阶段串联，每一层吃掉上一层的产出，进度、状态、文件流转全部看得到。**

## 1. 用户痛点：单点工具好用，一串联就散

| 痛点 | 表现 | 后果 |
|---|---|---|
| **工具碎片化** | 立项用一个、写世界用一个、写正文用一个、审核又一个 | 设定在 A 里改，B 不知道；切来切去丢上下文 |
| **AI 乱跑流程** | 直接让它"写一章"，它跳过立项/世界/角色硬编 | 写了 30 章发现力量体系前后矛盾、人物 OOC，推倒重来 |
| **不知道卡在哪/下一步** | 写不下去时说不清是缺设定、缺角色还是缺剧情 | 盲目补料，越补越乱 |

> 核心焦虑：写长篇最贵的不是"写不出",是"写崩了才发现"——成本在做完 30 章之后引爆。pipeline 要解决的就是"让生产过程可预期，让崩点早点可见"。

## 2. 关键认知：AI 写作应从"对话式"升级为"流水线式"

单次 prompt 能造段落，造不出一本 200 章还自洽的长篇。长篇的敌人是**累积的上下文漂移**——每一层都要消费上一层冻结好的结论，而不是重新发明。
pipeline 的答案是：**把创作拆成有明确输入/输出的生产节点，用"管道契约"约束每一层的产出格式与落盘路径，让数据像流水线一样单向流转。**

## 3. 反面教材：直接"一段 prompt 写一章"为什么必崩

- **上下文爆炸**：越多设定塞进单次对话，模型越抓不住重点，前后矛盾越密。
- **各写各的**：没有统一管道契约，同一个项目在多个会话里产出路径、文件名、owner 职责混乱，互相找不到。
- **无进度可言**：写了一部分不知道完成度，续写时不知道要从哪捡。
> 正确解法：看第 4 节。

---

## 4. 机制：三层编排，把"失控的对话"变成"受控的产线"

### 4.1 54 skill 多 agent 按阶段串联（formal/draft/trial 三态执行）
- 主线编排器按项目阶段把 study→seed→world→character→plot→write→review 等 agent 串起来。
- **执行模型三态**：`formal` 完整落盘 / `draft` 半成品继续补 / `trial` 快速试跑不落盘。→ 可以先试方向，再决定要不要正式写，省 token。
- **强弱加载**：SKILL.md 只留核心骨架，step 文件按需深读、reference 按需加载。→ 每层只把真正需要的规则读进上下文，防爆炸。

### 4.2 Phase → Stage 多层状态机：明确输入/输出/跳级条件
- Phase（study/seed/world/character/plot/write/review）+ Stage 细分（如 Phase 1 内 S1/S2）。
- 每个节点有明确输入、输出、状态标记和**跳级条件**。→ 用户永远知道下一步该做什么；失败时知道卡在哪一步、要补什么资料。

### 4.3 跨 skill 数据流转 + 章节进度追踪
- 路由依赖上下游消费：world 产设定→character 角色库→plot 卷纲/章锚点→review 白描卡/状态快照。
- 执行完回写**项目进度记录**：版本、耗时、进度条、文件生成清单、完成状态。→ 连载进度可视，续写不重复造。

### 4.4 管道契约统一约束
- 文件命名、产出路径、owner 职责由管道契约统一规定，跨 agent 输出路径按项目设计。
- **小巧思**：不是"各 agent 各自为战"，而是"每个环节在固定店铺上货、固定货架取货"——下游永远知道上游把料放在哪。

---

## 5. 可测量 / 门禁：进度和状态不是口说

| 指标 | 口径 | 意义 |
|---|---|---|
| **进度条 + 版本号** | 每个 phase 完成回写版本/耗时/文件清单 | 继续写作时知道"写到哪、还差什么" |
| **产出真实性门禁** | Phase0→1 前验证：采样段落存在 + 文风锚定≥500 字原文引用 | 防止"假装拆过书"就往下走 |
| **跳级条件显式** | 每 Stage 标清输入齐否才放行 | 阻止跳过关键层硬编 |

## 6. 深度：流水线是干线，不是孤岛
- 起点家族 8 个 skill 全部挂在这条干线上，互相 consume/produce；同一套 Chapter 进度、同一套状态快照贯穿 write/review/续写。
- **营销价值**：买的不只一个"写大纲"的工具，而是一套**从立项到过审的完整装配线**——单点工具给不了"全链路完成度"。

---

## 7. 操作顺序（专业克制，不一把梭）
先初始化项目（目录/索引/状态文件）→ 按 Pipeline Phase 路由到具体 skill → 每层消费上游产出、落盘 → 回写进度 → 续写时靠状态快照续行。**不急着一口气全自动，用阶段闸门控制每一步再往下走。**

## 9. 竞品差异锚（一句话）
市面"AI 写小说"= 单次对话给你一段文，切走就丢上下文；popwave 起点流水线 = **Phase/Stage 状态机 + 管道契约 + 进度追踪 + 配套 7 个生产 skill**，把单点输出升级为可预期、可回溯的工程产线。
