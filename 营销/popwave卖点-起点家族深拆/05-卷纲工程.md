## 0. 一句话卖点

**popwave 卷纲工程：主角剧情由用户拍板（交互式卷纲决策）、敌人/爽点/债务都被量化钉死（敌人阶梯表 + 不抢后续收益 + 章锚点"轨道+留白"）——长篇连载不透支、剧情不跑偏、主角永远被逼着行动。**

## 1. 用户痛点：写长篇最怕的三件事

| 痛点 | 表现 | 后果 |
|---|---|---|
| **大纲被动手脚** | AI 自己编出与立项矛盾的故事 | 主线跑偏，返工 |
| **爽点提前透支** | 前卷把后面才该给的高潮提前用完 | 后卷乏力，追读崩 |
| **主角被动挨打** | 剧情推着他走，不是他推着剧情走 | 读者觉得憋屈，弃书 |

> 核心焦虑：卷纲是长篇的"脊柱"。脊柱断了/弯了，后面每章都跟着歪。用户最需要的是**可控性（我拍板）+ 不透支（债务管理）+ 有结构（爽点/敌人量化）**。

## 2. 关键认知：卷纲是"债务管理"，不是"剧情流水账"

好卷纲 = 提前约定"每根线什么时候还（收束）、哪些爽点只能留给后卷（不透支）、主角每一步被什么逼着走（压力源）"。卷纲定战略、定范围、定方向，具体剧情交给幕纲自由发挥——**卷纲管"欠债与还债"，幕纲管"怎么写这一卷"**。

## 3. 反面教材：卷纲的两条死路

- **大纲是主角清单**：只写"第 3 卷主角去秘境、遇到圣女、拿神器"——没有债务、没有压力、没有"不能抢的后续收益"，后卷自相矛盾。
- **卷纲过度锁死**：把每章该写的细节全定了，写正文的人被条条框框捆死 → plot 过度约束 write，写法空间没了。
> 正确做法：看第 4 节——定框架、定债务，给白描留发挥空间。

## 4. 机制：交互决策 + 分层铺排 + 章锚点，把卷做成"可质检的工程"

### 4.1 交互式卷纲决策（R1-R5）：用户主导剧情走向
- 正式写卷纲前先走 5 轮交互：R1 卷终点定位、R2 关底 Boss、R3 核心爽感优先级、R4 剧情节奏参考、R5 NPC 登场与分幕走向。
- **小巧思**：核心轮 R1-R3 必答、R4-R5 可跳；每轮给结构化选项+自定义入口，**不能开放式提问**（开放=用户没抓手）。
- 卖点：用户不是在终点/Boss/爽感/节奏/NPC 上全盘接受 AI 的卷纲，而是**自己拍板方向**。

### 4.2 主线从 PRD 方向句展开：不跑偏
- plot 不自行发明方向，而是消费立项 PRD 的"起因/经过/结果"方向句，展开 `设计/主线.md`。
- 包含阶段推进链、卷级敌人阶梯、因果链、跨卷伏笔、全书卷级目录；**每卷目录只给战略定位，不抢后续收益**。

### 4.3 卷级目录 +"不抢的后续收益"（债务管理核心）
- 每卷目录含：卷定位、主压力、主收益、卷末爽点、**"不抢的后续收益"**。
- 卷级目录是广度设计，不写幕章细节；后卷写到时再递归深化。
- **小巧思（关键差异化）**：显式标注"哪些爽点只能给前卷、哪些必须留给后卷"，从机制上防止前卷透支后卷高潮——"每卷都知道什么叫不能抢"。

### 4.4 敌人阶梯表：成长与敌人强绑定
- 逐卷标注卷级敌人、量级、敌人类型、主角需要的成长、打完后状态。
- **量化铁律**：敌人量级递增 + 类型轮换 + 因果链连通；主角打完一个敌人，**必须获得打下一个敌人的必要条件**。
- 卖点：主角变强不是凭空升级，是**被敌人逼出来的成长**。

### 4.5 幕级套路决策五步：每幕都有结构引擎
- 分幕前必须走：选演绎框架 → 选内容引擎 → 定卷内递进范式 → 定章配比 → 设计高潮与幕末/卷末钩子。
- 框架管主线排布、引擎管剧情驱动、递进范式管强度曲线、章配比防主线摊薄、高潮钩子管追读。

### 4.6 2-3 候选方向 + 差异化对手：用户有选择权
- 幕纲前先产 2-3 个候选方向（幕定位/核心体验/情感弧线/对手/剧情梗概/情感钩子/幕末质变）。
- **小巧思**：候选必须用**不同对手类型**（数值型/机制型/信息型/关系型/系统型），避免"同对手换皮"。

### 4.7 活跃层建设：写剧情不现编
- 白描前先建本幕活跃层：地点、NPC、组织、资源（从世界设定推导并追加到全书设定）。
- **小巧思**：白描中出现的具体地名/NPC 名/组织名，必须先在活跃层落盘——降低剧情漏洞、防人物随意出现。

### 4.8 白描核心质量门禁：白描是完整故事弧，不是梗概
- 需含 2-4 条故事弧线、主角主动驱动、幕末质变、多视角叙事、资源获取活动、成长分散、挫折与前期爆发。
- 自检三项：主角是否主动 / 故事容量够不够 / 危机循环是否完整。

### 4.9 精彩度五问自检（卷纲能质检）
- 全卷四层设计完必须答：读者追读理由 / 意外性 / 情感投入 / 爽感密度 / 卷末高潮。
- **量化红线**：爽感密度要求 **≥60% 章节有爽感节点 且 强度逐幕递进**；任一问不过就重做对应层，不得进章锚点表。

### 4.10 章锚点表"轨道 + 留白"（边界控制核心）
- 全卷一张表，每章 4 个硬锚点 + 3 个软指导：
  - **硬锚点（write 必须遵守）**：章型、核心事件、爽感节点、章末钩子。
  - **软指导（write 可调，调整须说明原因）**：主角变化、爽感因子、章名。
- **卖点核心**：锁住轨道、开放写法——plot 不越权替 write 写细节，减少"大纲过度约束写作"的矛盾。

### 4.11 章型与爽感引擎匹配：每章都知道读者要什么
- 6 种章型：opening_shift / exploration_gain / confrontation_pressure / combat_reversal / high_tier_display / reveal_hook，各配推荐爽感引擎（未知揭示 / 打脸循环 / 压力突破…）。
- 用章型控制节奏波形，**避免连续写同类内容**。

### 4.12 低压区 + 旁观者放大爽感（可复用情绪结构）
- 翻盘前必须有**低压区蓄力**：当众羞辱/被当废物/被碾压/被背叛，厚度 1-3 段约 **200-600 字**。
- 爽点爆发后必须有**旁观者放大**：围观群众/嘲讽者/权威者。翻盘越爽低压区越厚，但**不超过 3 段**。

### 4.13 危机叠加设计：主角被世界逼着动
- 危机多维交织（生存/情感/社会/认知/资源），**至少 1 维带倒计时或不可逆后果**形成"结构性强制"。
- 升级路径：不安试探 → 正面冲突 → 生死/命运对决。

## 5. 可测量 / 门禁：卷纲过关才放行写正文

| 门禁/参数 | 口径 | 意义 |
|---|---|---|
| **爽感密度** | ≥60% 章节有爽感节点 + 强度逐幕递进 | 排除"水卷" |
| **敌人阶梯** | 量级递增 + 类型轮换 + 因果连通 | 排除同型连打 |
| **烦感度五问** | 追读/意外/情感/爽感/高潮五维全过 | 卷纲可质检 |
| **低压区** | 1-3 段 / 200-600 字，不超过 3 段 | 爽感有蓄力曲线 |

## 6. 深度：卷纲是全链条的"脊柱"
- 卷纲被 **write 逐章消费（章锚点硬锚点强制遵守）**、被 **review 逐章对照（施工卡 beat 逐条核对）**。
- **营销价值**：可控（用户拍板）+ 不透支（债务管理）+ 有结构（量化边界）三合一——"把几十万字的长篇，压在一条不断、不弯、不抢跑的骨架上"。

---

## 7. 操作顺序（先交互，再铺排，后钉锚点）
R1-R5 用户拍板方向 → 主线从 PRD 方向句展开 → 卷级目录+债务标注 → 敌人阶梯表 → 幕级套路五步+候选方向 → 活跃层 → 白描 → 五问自检 → 章锚点表。**用户拍板在最先，"不抢后续收益"贯穿全程。**

## 9. 竞品差异锚（一句话）
市面大纲工具= 线性流水账（无法控/会透支/结构与正文脱节）；popwave 卷纲工程 = **用户拍板的交互决策 + 不抢后续收益的债务管理 + 敌人阶梯表 + 章锚点"轨道+留白"**，把第一卷的规划做成可质检、不透支、可消费的工程。
