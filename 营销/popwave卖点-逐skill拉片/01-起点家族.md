# 01 · 起点家族 · 营销点拉片

> 覆盖 skill：pop-qidian-pipeline / seed / world / character / plot / write / research / review（8 个，~123 文档）
> 定位：长篇网文全链路流水线——从立项、世界、角色、剧情到写作、审核的完整闭环。

---

## pop-qidian-pipeline

### 营销点 1：54 skill 多 agent 编排与管线调度
- 来源：`SKILL.md`
- 机制：pipeline 作为主线编排器，按项目阶段把 study、seed、world、character、plot、write、review 等 agent 串联。执行模型支持 formal/draft/trial：formal 完整落盘，draft 补全继续，trial 快速试跑。强弱加载机制让 SKILL.md 保持核心骨架，step 文件按需深读，reference 按需加载，避免上下文爆炸。文件命名、产出路径、owner 职责由管道契约统一约束。
- 营销角度：不是"一个 skill 帮你写书"，而是"整套网文生产流水线"。用户买的是从立项、世界、角色、剧情到写作、审核的完整闭环，减少来回切换工具与丢设定的问题。

### 营销点 2：跨 skill 数据流转与章节进度追踪
- 来源：`SKILL.md`
- 机制：pipeline 路由依赖上游产出与下游消费，如 world 产出设定文件，character 产出角色库，plot 产出卷纲/章锚点，review 产出白描卡与状态快照。执行完成后回写项目进度记录，包含版本、耗时、进度条、文件生成清单、完成状态。跨 skill 输出路径按项目设计，避免各 agent 各自为战。
- 营销角度：适合连载写作中的进度管理。用户可以看到从立项到正文、审核、续写的全链路完成度，系统也会自动追踪文件是否已生成、是否已消费。

### 营销点 3：Phase 到 Stage 的多层状态机
- 来源：`SKILL.md`
- 机制：pipeline 将创作拆为阶段与子阶段。常见阶段包括 study、seed、world、character、plot、write、review；Stage 再细分，例如 Phase 1 内包含 S1/S2 等。每个阶段有明确输入、输出、状态标记与跳级条件，Stage 之间形成状态流转，避免用户或 agent 乱跑流程。
- 营销角度：把 AI 写作从"随便聊"变成"可预期流程"。用户知道下一步该做什么，失败时也知道卡在哪一步、需要补什么资料。

## pop-qidian-seed

### 营销点 1：单轮问答式立项引擎
- 来源：`SKILL.md`
- 机制：seed 不是先让用户填复杂表格，而是通过一轮问答收集创作意图，再输出立项核心文档。其核心是把"写什么、为什么写、怎么写"压缩成可执行结构：赛道方向、核心爽点、力量体系、主角设计、开局设计。立项完成后，世界、角色、剧情后续依赖这些输出。
- 营销角度：用户不需要成为项目管理专家，只要回答几个关键问题，就能得到完整立项基础。卖点在于"少交互、高产出"。

### 营销点 2：六要素立项法
- 来源：`SKILL.md`
- 机制：seed 用六要素组织立项：赛道方向、核心爽点、力量体系、主角设计、开局设计、故事纲领。每个要素都不空谈，而是落到可消费文件，如力量体系、金手指、主角深度卡、主线任务链、故事大纲。后续 world、character、plot 都围绕这些结构展开。
- 营销角度：这就是"6 个文件把一本书立项清楚"。用户能直观看到立项不是文字堆砌，而是生产流水线的前置数据层。

### 营销点 3：故事纲领与情绪节拍
- 来源：`SKILL.md`
- 机制：故事纲领从立项方向中抽取，用于定义开篇、核心事件、主角成长、情绪节奏与追读机制。它不是完整章节，而是后续 plot 展开主线、卷纲、章锚点的前置蓝图。情绪节拍则帮助后续设计何时打脸、何时反转、何时爆发。
- 营销角度：适合强调"开篇即高能""节奏有设计"。卖点在于 seed 不只是概念，而是给后续剧情与写作提供节拍表。

### 营销点 4：金手指合成公式
- 来源：`SKILL.md`
- 机制：金手指设计不是随机生成，而是由"核心欲望 + 初始处境 + 可成长维度"组成。种子层会先明确主角要什么、为什么现在得到金手指、金手指如何服务成长，并检查是否与主角欲望和初期处境耦合。
- 营销角度：金手指不是外挂说明书，而是剧情发动机。卖点在于金手指能制造决策困境、资源缺口、身份风险与后续升级空间。

### 营销点 5：开场场景树
- 来源：`SKILL.md`
- 机制：开场场景树用于定义主角初始处境、触发事件、情绪锚点和第一幕目标。它帮助判断第一章不是"世界观说明"，而是主角必须行动的理由。
- 营销角度：适合卖点"第一章有强钩子"。卖点在于把开局从灵感变成可执行的场景树，保证主角开局不是被动挨打，而是被逼行动。

## pop-qidian-world

### 营销点 1：7 维因果链世界观生成
- 来源：`SKILL.md`
- 机制：world 不生成散乱设定，而是从类型风味基线出发，围绕地理、社会、历史、信仰、危机、势力、力量体系展开因果推演。每个设定会回答"它如何影响其他设定"，形成世界自洽。输出会落到全书设定文件，供后续 plot、character、write 消费。
- 营销角度：卖点是"世界不是设定集，而是因果网"。用户获得的世界能自然生成冲突、势力、资源与危机。

### 营销点 2：世界设计原则九宫格
- 来源：`SKILL.md`
- 机制：world 的设计过程围绕九宫格展开，包括世界定位、地理结构、社会结构、历史断层、信仰体系、权力结构、资源分布、势力格局、危机引擎。九宫格不是模板填空，而是判断世界是否成立：它能否提供生存压力、社会冲突、资源竞争、历史阴影与等级压迫。
- 营销角度：适合强调"世界有深度"。卖点在于世界不是背景板，而是主角成长、势力冲突与剧情升级的源泉。

### 营销点 3：势力格局设计
- 来源：`SKILL.md`
- 机制：world 输出势力结构时，会明确势力层级、利益冲突、地盘分布、与主角关系和潜在危机。势力不是名字列表，而是后续剧情冲突的来源。主角的敌人、盟友、资源、背叛与升级阻力，都可以从势力格局中衍生。
- 营销角度：卖点在于"势力能自动生成剧情"。用户不需要从头想反派和盟友，系统可从世界设定中自然生成势力线。

### 营销点 4：力量体系与全书设定文件
- 来源：`SKILL.md`
- 机制：world 负责把力量体系嵌入世界规则中，确保升级、限制、代价、社会地位和剧情冲突一致。力量体系不是独立等级表，而是与地理、资源、势力、危机绑定。输出文件成为 plot 敌人阶梯、character 角色能力、write 战斗与成长反馈的共同依据。
- 营销角度：卖点在于"力量体系有边界"。系统会保证主角不能随意升级，必须通过资源、代价、规则与世界交互变强。

## pop-qidian-character

### 营销点 1：攀登者人格分类法
- 来源：`SKILL.md`
- 机制：character 将主角和配角按行动偏好、目标结构、情绪触发和成长路径分类。角色不是模板脸，而是由行动逻辑驱动：他们面对危机时是挣扎、逃避、算计、守护、复仇还是妥协，都会影响后续剧情表现。
- 营销角度：卖点在于"角色像真人，因为会按自己的逻辑行动"。系统可保证角色在不同情境下行为一致。

### 营销点 2：关系张力网络
- 来源：`SKILL.md`
- 机制：character 不只是单人卡，而是生成角色关系网。每个角色与主角有明确关系、互动模式、冲突来源和情感状态。关系会推动剧情：信任可被利用，保护会引发牺牲，仇恨会制造复仇线。
- 营销角度：卖点在于"角色不是工具人，而是关系引擎"。系统能自动生成羁绊、背叛、牺牲与误会等剧情动力。

### 营销点 3：角色弧光与成长轨迹
- 来源：`SKILL.md`
- 机制：角色成长不是"升级加数值"，而是身份、能力、价值观和关系变化。系统会追踪主角如何从起点状态变化到下一阶段状态，并检查新成长是否与前期事件因果相连。
- 营销角度：卖点在于"成长有记忆点"。用户能获得从起点到当前状态的角色轨迹，确保主角变强但不 OOC。

### 营销点 4：反派/配角行为一致性
- 来源：`SKILL.md`
- 机制：character 输出反派和配角的行为模式、欲望结构、威胁等级和关系绑定。反派不是"下一关 BOSS"，而是有目标、有手段、有弱点、会主动推进冲突的角色。配角也有关系位置和互动模式，不会只在场景里传设定。
- 营销角度：卖点在于"反派像真对手"。系统能保证敌人动机、手段和代价与主角压力匹配，避免无脑反派。

## pop-qidian-plot

### 营销点 1：交互式卷纲决策
- 来源：`steps/step-0-interactive.md`
- 机制：plot 在正式写卷纲前先通过 R1-R5 轮交互确认用户选择。R1 卷终点定位，R2 关底 Boss，R3 核心爽感优先级，R4 剧情节奏参考，R5 NPC 登场与分幕走向。核心轮 R1-R3 必答，R4-R5 可跳过。每轮必须提供结构化选项和自定义入口，不能开放式提问。
- 营销角度：卖点在于"用户主导剧情走向"。用户不是被动接受完整大纲，而是在终点、Boss、爽感、节奏、NPC 上选方向。

### 营销点 2：主线从 PRD 方向句展开
- 来源：`steps/step-1-material.md`
- 机制：plot 不自行发明故事方向，而是消费立项 PRD 的"起因/经过/结果"方向句，展开设计/主线.md。主线包含阶段推进链、卷级敌人阶梯、因果链、跨卷伏笔和全书卷级目录。每卷目录只给战略定位，不抢后续收益。
- 营销角度：卖点在于"主线不跑偏"。系统以立项方向为起点，防止 plot 层自己编出与立项矛盾的故事。

### 营销点 3：卷级目录与"不抢后续收益"
- 来源：`steps/step-1-material.md`
- 机制：每卷目录包含卷定位、主压力、主收益、卷末爽点和"不抢的后续收益"。卷级目录是广度设计，不写幕章细节；后卷写到时再递归深化。其作用是防止前卷提前透支后卷爽点。
- 营销角度：卖点在于"长篇连载不透支"。系统会标注哪些爽点只能给前卷，哪些必须留给后卷，避免全卷结尾靠透支续航。

### 营销点 4：敌人阶梯表
- 来源：`steps/step-1-material.md`
- 机制：敌人阶梯表逐卷标注卷级敌人、量级、敌人类型、主角需要的成长和打完后状态。要求敌人量级递增、类型轮换、因果链连通。主角打完一个敌人后，必须获得打下一个敌人的必要条件。
- 营销角度：卖点在于"成长与敌人强绑定"。系统保证主角变强不是凭空升级，而是被敌人逼出来的成长。

### 营销点 5：幕级套路决策五步
- 来源：`steps/step-2-act.md`
- 机制：分幕设计前必须走套路决策层：选演绎框架、选内容引擎、定卷内递进范式、定章配比、设计高潮与幕末/卷末钩子。框架决定主线排布，引擎决定剧情驱动，递进范式决定强度曲线，章配比防止主线摊薄，高潮钩子决定追读。
- 营销角度：卖点在于"每幕都有结构引擎"。幕纲不是简单概括，而是从框架、引擎、节奏到钩子的完整设计。

### 营销点 6：2-3 候选方向 + 差异化对手
- 来源：`steps/step-2-act.md`
- 机制：幕纲设计前会先产出 2-3 个候选方向，每个方向有幕定位、核心体验、情感弧线、对手、剧情梗概、情感钩子和幕末质变。候选必须使用不同对手类型，如数值型、机制型、信息型、关系型、系统型，避免"同对手换皮"。
- 营销角度：卖点在于"用户有选择权"。系统不是直接给唯一答案，而是给多条可比较的剧情路线。

### 营销点 7：活跃层建设
- 来源：`steps/step-2-act.md`
- 机制：白描前必须先建立本幕活跃层，包括地点、NPC、组织、资源。这些具体信息从世界设定中推导，并追加到全书设定文件。白描中出现的具体地名、NPC 名、组织名必须先在活跃层落盘。
- 营销角度：卖点在于"写剧情不现编"。系统要求先建活跃层，降低后续剧情漏洞和人物随意出现的问题。

### 营销点 8：白描核心质量门禁
- 来源：`steps/step-2-act.md`
- 机制：剧情白描是幕纲核心环节，需包含 2-4 条故事弧线、主角主动驱动、幕末质变、多视角叙事、资源获取活动、成长分散、挫折与前期爆发。自检三项：主角是否主动、故事容量是否够、危机循环是否完整。
- 营销角度：卖点在于"白描不是梗概，是完整故事弧"。系统会强制主角驱动、多弧线和幕末变化，避免只写事件列表。

### 营销点 9：精彩度五问自检
- 来源：`steps/step-2-act.md`
- 机制：全卷四层设计完成后必须执行五问：读者追读理由、意外性、情感投入、爽感密度、卷末高潮。任一问不通过就重做对应层，不得进入章锚点表。爽感密度要求≥60% 章节有爽感节点，且强度逐幕递进。
- 营销角度：卖点在于"卷纲能被质检"。系统不只是生成卷纲，还要求卷纲通过追读、意外、情感、爽感和高潮五维检查。

### 营销点 10：章锚点表"轨道 + 留白"
- 来源：`steps/step-3-chapters.md`
- 机制：章锚点表是全卷一张表，每章包含 4 个硬锚点和 3 个软指导。硬锚点为章型、核心事件、爽感节点、章末钩子；软指导为主角变化、爽感因子、章名。硬锚点 write 必须遵守，软指导 write 可调整，但调整后需说明原因。
- 营销角度：卖点在于"既控制剧情，又保留写法空间"。系统锁住轨道，write 负责细节表达，减少 plot 过度约束写作的矛盾。

### 营销点 11：章型与爽感引擎匹配
- 来源：`references/通用剧情模式.md`
- 机制：plot 使用 6 种章型匹配读者期待：opening_shift、exploration_gain、confrontation_pressure、combat_reversal、high_tier_display、reveal_hook。每种章型对应一种推荐爽感引擎，如 opening_shift 用未知揭示，confrontation_pressure 用打脸循环，combat_reversal 用压力突破。
- 营销角度：卖点在于"每章都知道读者要什么"。系统用章型控制节奏波形，避免连续写同类内容。

### 营销点 12：低压区与旁观者放大爽感
- 来源：`references/通用剧情模式.md`
- 机制：翻盘前必须有低压区蓄力，如当众羞辱、被当废物、被碾压、被背叛，厚度参考 1-3 段，约 200-600 字。爽点爆发后必须有旁观者放大：围观群众、嘲讽者、权威者。翻盘越爽，低压区越厚，但不超过 3 段。
- 营销角度：卖点在于"爽点不是突然爆发，而是有蓄力曲线"。系统能把打脸循环做成可复用的情绪结构。

### 营销点 13：危机叠加设计
- 来源：`references/通用剧情模式.md`
- 机制：危机不是单点来源，而是生存、情感、社会、认知、资源多个维度交织。至少 1 个维度必须有倒计时或不可逆后果，形成"结构性强制"。危机升级从不安试探，到正面冲突，再到生死/命运对决。
- 营销角度：卖点在于"主角是被世界逼着行动的"。系统通过多维危机制造紧迫感和持续追读。

### 营销点 14：金手指巧思设计
- 来源：`references/通用剧情模式.md`
- 机制：金手指不能只是数据翻译器，必须产生决策困境、使用博弈、风险代价、信息差武器、自生长能力或成长节奏控制器。游戏入侵流特别强调面板不只在战斗用，还要在社交、探索、谈判中产生博弈。
- 营销角度：卖点在于"金手指是剧情发动机"。系统把金手指从能力说明升级为冲突生成器。

### 营销点 15：三赛道专属剧情模式
- 来源：`references/修仙流剧情模式.md`、`references/悬疑流剧情模式.md`、`references/末世流剧情模式.md`
- 机制：plot 对不同赛道叠加专属节奏与爽点。修仙流重长弧蓄力，3-5 章修炼铺垫后 1 章大爽点爆发，爽点集中在越级碾压、打脸宗门、秘境突破。悬疑流重慢揭示，3-5 章揭开一层真相，每层揭示制造更大谜。末世流重每章生存压力、资源掠夺、人性考验和物资收益。

### 营销点 1：四档调研引擎
- 来源：`SKILL.md`
- 机制：research 按触发条件切换四档：燃料+题材机制、decon-lite 9表拆书、赛道定位调研、decon-plot 剧情拆解。燃料档用于找可入场面的写作燃料和题材机制；decon-lite 用于拆解参考书力量体系、剧情节奏、情绪弧线、金手指、危机和动力引擎；赛道定位用于调研市场；decon-plot 用于拆解参考书剧情结构，服务 seed 和 plot。
- 营销角度：卖点在于"调研不是泛泛搜索"。系统按创作阶段提供不同深度，从燃料、参考书拆解到赛道和剧情拆解。

### 营销点 2：燃料三要素
- 来源：`steps/step-1-find.md`
- 机制：每条燃料必须落到事件形状、主角操作点、可外显爽点。事件形状说明什么事件、什么场面、如何触发；主角操作点说明主角如何主动介入；可外显爽点说明读者能直接看到的爽感。缺要素即不合格。
- 营销角度：卖点在于"燃料能直接写成章节"。系统不保存空泛灵感，只保存能转化为剧情、行动和爽点的材料。

### 营销点 3：题材机制分流
- 来源：`steps/step-1-find.md`
- 机制：参考书中的武学招式、系统面板、诡异规则、职业数值、战斗升级路径、组织运营模型等先作为内容机制处理。能进入本书的转成可触发事件+主角操作点+可外显爽点；不能直接迁移的写入 content-mechanics；疑似文风特征禁止交给 soul/write。
- 营销角度：卖点在于"机制不乱贴文风"。系统区分内容机制、题材机制和文风特征，避免把参考书技巧误用为风格模板。

### 营销点 4：decon-lite 9表拆书
- 来源：`steps/step-decon-lite.md`
- 机制：decon-lite 先验证原文 txt 存在，再采样前 300 章：前 10 章全文、11-100 章关键词、100 章后每 25 章、境界过渡期必采。接着拆 9 表：力量体系结构、剧情节奏、情绪弧线、人称视角、开篇解剖、势力格局、金手指深度、世界危机引擎、动力引擎提取表。表 1 必须拆到规则级，表 9 必须包含驱动逻辑、运转机制、代价结构。
- 营销角度：卖点在于"参考书拆解到规则级"。系统不是泛泛总结，而是提取力量体系、节奏、金手指、危机和动力引擎的可迁移规则。

### 营销点 5：decon-lite 质量门禁
- 来源：`steps/step-decon-lite.md`
- 机制：落盘前检查 9 表完整性、表 1 规则级深度、表 6 势力分层、表 7 金手指深度、表 8 世界危机引擎、表 9 动力引擎三组成、爽点间隔是否有章数、开篇第 1 句是否有原文摘录、采样范围是否声明。不合格必须补拆。
- 营销角度：卖点在于"拆书有质量控制"。系统保证参考书拆解可追溯、可验证、可复用。

### 营销点 6：赛道定位调研
- 来源：`SKILL.md`
- 机制：赛道调研由 pipeline Phase 0 自动触发，产出素材/赛道调研.md，消费方为 seed 1d 和 plot 三源合流。其作用是为主角赛道定位提供市场参考。
- 营销角度：卖点在于"开书前就有赛道分析"。系统帮助作者判断哪些赛道、题材、机制更有读者基础。

### 营销点 7：decon-plot 剧情拆解
- 来源：`SKILL.md`
- 机制：decon-plot 对参考书进行 6 维度拆解：力量体系对比、金手指设计对比、Boss 战设计、爽感场景拆解、分幕转折手法、NPC 登场效果。每个维度都标注消费方，例如力量体系对比服务 seed S1，Boss 战设计服务 plot R2，NPC 登场效果服务 character C1。
- 营销角度：卖点在于"参考书剧情也能结构化复用"。系统把爽点、Boss、NPC、分幕手法变成下游可消费设计素材。

## pop-qidian-review

### 营销点 1：正向符合性检查
- 来源：`steps/step-1-audit.md`
- 机制：review 先对照施工卡检查核心事件 beat。施工卡承诺 2-4 个 beat，review 逐条对照正文是否兑现。若全部兑现进入设定一致性检查；有偏离但主线未丢，则标注偏离；主线丢失则废章。设定一致性检查力量体系、金手指规则、骨架一致性、天赋约束、世界观规则、势力格局。
- 营销角度：卖点在于"AI 不会写偏题"。系统把施工卡承诺和正文兑现逐项对照，减少剧情跑偏。

### 营销点 2：设定一致性检查
- 来源：`steps/step-1-audit.md`
- 机制：review 检查主角能力是否越级、等级是否与骨架一致、金手指使用是否符合"梗×机制×限制"、越级是否付出代价、攀登逻辑是否断裂、金手指是否喧宾夺主让坐标系失去意义、世界观规则是否自洽、势力关系和实力数值是否一致。不合格项会标注违反点，必要时废章。
- 营销角度：卖点在于"设定不漂移"。系统能发现越级不付代价、金手指破坏坐标系、世界观规则冲突等问题。

### 营销点 3：爽感闭环检查
- 来源：`steps/step-1-audit.md`
- 机制：review 检查本章主推爽感类型的触发段、爆发段、后果段是否齐全。三者缺一即废章。该机制强制每章爽感有结构，不只是主角赢了，而是"被轻视—被压制—准备—翻盘—对方失态/后果"完整闭环。
- 营销角度：卖点在于"爽感有结构"。系统确保每一章爽点不是随机出现，而是有触发、爆发和后果。

### 营销点 4：AI 味 15 项 pattern 检测
- 来源：`steps/step-1-audit.md`
- 机制：review 内化 no-ai-slop 检测，逐项检查二分对比、开场清嗓子、伪洞察铺垫、浅层分析尾缀、重要性吹嘘、模糊归因、假强动词、同义词循环、否定列举、戏剧性碎片化、机械节奏、修辞铺垫、假深刻结尾、总结重述结尾、情绪直给。每项检出必须给原文引用、pattern 编号和修正方向，并区分 AI slop 与作者个人风格。
- 营销角度：卖点在于"AI 味检测不空泛"。系统能定位具体句子、类别和修改方向，而不是只说"有 AI 味"。

### 营销点 5：高疲劳词 3 级检测
- 来源：`steps/step-1-audit.md`
- 机制：高疲劳词分 3 级。S 级如蝼蚁、蚍蜉、瞳孔骤缩、全场哗然等，单章出现即标注；A 级如冷笑、嘴角上扬、眼中闪过等，单章≥2 次标注；B 级如不禁、不由得、霎时间等，单章≥3 次标注。
- 营销角度：卖点在于"高频词自动预警"。系统能发现反复使用的疲劳词，避免正文变得套路化。

### 营销点 6：结构性问题 4 项检测
- 来源：`steps/step-1-audit.md`
- 机制：review 检查描写堆叠、信息重复、对话死板、破折号滥用。连续 3 行以上纯感官描写无动作推进，同一信息一章出现 2 次以上，连续 6 行以上纯对话无动作，单章破折号≥5 处或连续段落使用，均会标注并建议修正。
- 营销角度：卖点在于"结构问题能定位"。系统不只检查词，还检查段落结构、信息密度和对话节奏。

### 营销点 7：对话质量 6 项检查
- 来源：`steps/step-1-audit.md`
- 机制：对话检查信息密度、潜台词、节奏、动作插入、功能复合、个性区分。系统引用 `pop-qidian-write/references/通用技法/对话六要素.md` 作为标准。判定标准为 6 项全通过合格，1-2 项不通过标注修正方向，3 项以上不通过建议 write 修改本章对话。
- 营销角度：卖点在于"对话可质检"。系统能把"角色说话像作者传声筒"这种问题定位到具体段落。

### 营销点 8：好看度 4 问
- 来源：`steps/step-1-audit.md`
- 机制：review 回答四问：这章有没有让人想往下翻的劲、最抓人的画面/台词是什么、哪里无聊了、代入感够不够。每问必须给具体证据。找不到记忆点时，标注"无记忆点"；无聊段落会给出具体位置，如"第 3-5 段屋顶夜景描写偏长"，并建议删、压缩、插入动作或换场景。
- 营销角度：卖点在于"好看度有证据"。系统不泛泛说还行，而是定位具体段落和具体修改方向。

### 营销点 9：反向充足性检查
- 来源：`steps/step-1-audit.md`
- 机制：review 审完正文后反向评估参考资料是否足以指导下一章。检查大纲/施工卡、设定库、角色卡、燃料库四个维度。缺项会给出补强建议，例如建议 plot 补下一章施工卡、world 补设定、character 补角色卡、research 补燃料。
- 营销角度：卖点在于"下一章不是临场硬编"。系统检查后续创作资料是否充足，提前发现资料缺口。

### 营销点 10：双文件叙事记录
- 来源：`SKILL.md`
- 机制：review 只沉淀白描卡和状态快照。白描卡存"发生"，每章新增，只增不改，约 300-500 字，包含事件白描、关键数据、爽点·钩子、人物关系变化。状态快照存"状态"，每章 replace 更新，包含未回收钩子台账、角色当前状态表、禁止漂移。
- 营销角度：卖点在于"剧情记录极简但完整"。系统用两个文件承担全书累计记录，白描卡做历史，状态快照做当下。

### 营销点 11：白描卡轻量化
- 来源：`steps/step-2-commit.md`
- 机制：白描卡控制在约 300-500 字，禁止展开成 1500+ 字长文档。细节写不下的留在库文件。格式包括事件白描 3-5 句、关键数据一行式、爽点·钩子含信息差类型、人物关系变化可选。
- 营销角度：卖点在于"记录不拖沓"。系统保证剧情记录服务于续写，而不是变成二次创作长文。

### 营销点 12：状态快照 replace 更新
- 来源：`steps/step-2-commit.md`
- 机制：状态快照每章 replace 更新，不追加。内容包括未回收钩子台账、角色当前状态表、禁止漂移。钩子回收后状态标"已回收·chXXX"，超 3 章未回收标红，信息差类型标注读者/主角哪方已知。角色状态表只保留活跃角色，龙套/已退场角色移除。
- 营销角度：卖点在于"跨章状态不膨胀"。系统自动清理退场角色，避免状态表无限增长。

### 营销点 13：禁止漂移清单
- 来源：`steps/step-2-commit.md`
- 机制：状态快照中的禁止漂移从白描卡关键数据和卷纲提炼，包括人名、地名、阶位数值、已死角色、已废设定。写错即 bug。
- 营销角度：卖点在于"关键事实不漂移"。系统把不可改事实抽出来，供 write 后续写作强制执行。

### 营销点 14：Reconstruct 批量回溯审核
- 来源：`steps/step-reconstruct.md`
- 机制：reconstruct 用于导入/续写模式，对已有正文逐章回溯审核，生成逐章白描卡和状态快照。采样策略为≤10 章全审，11-30 章最近 5 章全审+其余每 5 章取 1 章，>30 章最近 5 章全审+第一章+每 10 章取 1 章。全审章做简化版四步审核，非采样章快速提取关键信息。
- 营销角度：卖点在于"旧稿也能快速续写"。系统能把未审核正文转成白描卡和状态快照，为续写提供基础。

### 营销点 15：审核轻量化
- 来源：`CHANGELOG.md`
- 机制：v3.9.0 后 review 只沉淀剧情白描，即白描卡+状态快照，废除审核报告、剧情累计卡等冗余沉淀物。审核结论只在对话内输出，不落盘。
- 营销角度：卖点在于"审核不拖文件"。系统不产出沉重报告，只沉淀 write 真正需要的白描卡和状态快照。
