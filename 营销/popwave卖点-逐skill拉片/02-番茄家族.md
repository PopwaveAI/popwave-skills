# 02 · 番茄家族 · 营销点拉片

> 覆盖 skill：pop-fanqie-pipeline / seed / world / character / plot / write / review（7 个）
> 定位：番茄短篇爽文引擎——读者模型/爽感公式/节奏物理量/双文件记忆

---

## pop-fanqie-pipeline

### 营销点 1：Phase 调度 + 路由循环，一次对话自包含推进
- 来源：`SKILL.md`、`steps/step1.md`
- 机制：Pipeline 通过 Phase 调度表把用户意图、Seed、World、Plot、Character、Write、Review 串起来；v3.13.0 后新增"路由循环"：读 `project-state.md` → 对照 Phase 调度表路由 → 按 state 更新方法落盘，Phase 调度表与 state 更新方法合入 SKILL.md，每次对话零跳转。
- 营销角度：用户不用在多个 skill 间反复切换，对话里就能自动推进项目。

### 营销点 2：导入/续写模式，从旧稿或笔记重建管线
- 来源：`steps/step0-import.md`
- 机制：导入模式处理已有项目、用户笔记或自由格式输入，可继续已有项目；配套标准内容结构表把自由输入转换为管线标准结构，缺失分节标注"⏳待补"，不编造。
- 营销角度：旧稿、笔记、碎片设定都能导入，降低"从空白开始"的门槛。

### 营销点 3：7 阶段 Phase 流水线，项目可见可追踪
- 来源：`SKILL.md`、`steps/step1.md`
- 机制：Phase 0 用户意图 → Phase 1 Seed → Phase 2 World → Phase 3 Plot → Phase 3.5 Character → Phase 4 Write → Phase 5 Review。Project-state 可追踪项目名、创建/更新时间、phase、mode、current_chapter、阶段完成情况、底牌就绪状态、创意摘要、最近产出和下一步操作。
- 营销角度：用户随时知道"写到哪了""下一步该干什么""哪些准备还没就绪"。

### 营销点 4：Phase 进度 HTML 可视化
- 来源：`templates/project-state.html.tpl`、`scripts/generate-state-html.py`
- 机制：`generate-state-html.py` 从 `project-state.md` 解析字段，替换 HTML 模板占位符，生成 `project-state.html`。页面包含阶段进度条、底牌就绪卡片、创意摘要、最近产出表格和下一步操作。
- 营销角度：项目状态不是文本，而是一份可打开的可视化仪表盘。

### 营销点 5：底牌就绪机制，避免创作盲目推进
- 来源：`SKILL.md`、`scripts/generate-state-html.py`
- 机制：Pipeline 用"底牌"追踪用户意图、赛道调研、参考书下载、笔触 DNA、decon-lite 等前置资源就绪状态。ready 为就绪，skipped 为跳过，not-ready 为未就绪。
- 营销角度：不是"开始写"，而是"准备好再写"，降低设定混乱和写崩概率。

### 营销点 6：16 类标准文件结构，导入输入自动标准化
- 来源：`references/import-structures.md`
- 机制：定义 16 个标准文件的分节结构，如用户意图、赛道调研、文风锚定、设计/创意、力量体系、地图、势力、危机、角色库、剧情白描、状态快照等。缺失分节标注"待补"，非 md 文件先读取内容再按标准格式写入 md。
- 营销角度：用户自由输入也能被转成管线可消费的标准化素材。

### 营销点 7：管道亲和（Pipeline Affinity）认知引导
- 来源：`references/onboarding-guide.md`
- 机制：面向用户的第一次引导语强调"你只要有个'想写什么'的念头"，剩下的立项、世界观、逐章成文、自查把关由 Pipeline 陪你走完；提供"从零立项、搭世界观、逐章成文、自查把关"四个玩法入口。
- 营销角度：把复杂管线包装成"一个念头启动，系统陪你写完整"。

### 营销点 8：剧情沉淀轻量化，双文件叙事记录收束
- 来源：`SKILL.md`、`steps/step0-import.md`、`steps/step1.md`、CHANGELOG.md
- 机制：v3.12.0 起，Pipeline 作为调度器同步 review 的轻量化沉淀：Phase 5 产出双文件——`审核/剧情白描流水账.md`（append-only，存"发生"）和 `审核/状态快照.md`（replace，存"状态"），审核结论只在对话内输出。
- 营销角度：管线不只是写到正文，还能沉淀连续记忆，防止后续章节断片。

## pop-fanqie-seed

### 营销点 1：三阶段创意引擎，从一句话到可试读首章
- 来源：`SKILL.md`、`steps/step1.md`、`steps/step2.md`、`steps/step3.md`
- 机制：Step1 做用户意图摸底、赛道调研、策略组装；Step2 做三核心故事纲领、金手指三要素合成、主角轮廓、世界观骨架；Step3 产出黄金首章。三阶段串行，用户一句话方向可逐步打磨成完整创意和首章。
- 营销角度：用户不用自己想大纲，seed 从方向一路推到可试读正文。

### 营销点 2：七维底牌摸底，启动前确认创作资产
- 来源：`templates/Phase1-模板.md`
- 机制：启动前确认 7 个维度：笔触参考书、力量/体系参考书、赛道经典参考、现有设定、情绪基调偏好、全书最大卖点、是否需要推荐书单。有就填，没有就跳过，不影响继续推进。
- 营销角度：像启动前的"准备清单"，避免空白页焦虑。

### 营销点 3：市场校准清单，避免撞车并提取爽点类型
- 来源：`templates/Phase1-模板.md`
- 机制：产出 `素材/市场校准.md`，包含借鉴点清单、避雷点清单、爽点类型清单、赛道格局。借鉴点和爽点类型都标注来源，用于后续策略组装和发散校验。
- 营销角度：不只是"写得好"，还能避开市场常见坑，找到差异化爽点。

### 营销点 4：策略组装卡，按维度借、改、融合参考书
- 来源：`templates/Phase1-模板.md`
- 机制：每条策略卡固定 7 个字段：改编维度、借参考书什么、改参考书什么、用什么爽点、融入用户什么元素、情绪基调、2-3 种展开玩法，以及为什么有意思。
- 营销角度：用户参与创意合成，AI 不只是代写，而是帮用户"改得更好"。

### 营销点 5：10 选 1 双轨创意展示，王道 + 猎奇并行
- 来源：`templates/Phase1-模板.md`
- 机制：创意方向生成 10 个方向，其中 5 个王道赛道 + 5 个猎奇赛道。每个方向都有"一句话描述 + 画面 + 为什么有意思 + 市场定位 + 立项评估"。
- 营销角度：既给稳妥爆款，也给出圈脑洞，用户选择空间大。

### 营销点 6：金手指三要素合成，创意 × 机制 × 限制
- 来源：`references/showcase.md`
- 机制：金手指必须三要素：创意提供形式，机制提供动力，限制提供张力。铁律是"只加限制不加代价"，限制=使用条件/边界/冷却，代价=扣寿命/扣记忆等负反馈。
- 营销角度：金手指不是越怪越好，而是有边界、能制造期待、读者会愿意看解锁。

### 营销点 7：主角从金手指反推，而非先拍脑袋设人
- 来源：`references/design-guide.md`
- 机制：主角设定采用"从金手指反推"流程：什么人最适合金手指 → 职业/性格推导记忆点 → 从金手指限制推导缺点 → 从金手指本质推导危机 → 从进化方向推导成长弧线。
- 营销角度：人物不是凭空出来，而是和金手指、世界观、危机绑定，后续写作更顺。

### 营销点 8：金手指进化方向设计，支撑 3-5 章独立剧情
- 来源：`references/design-guide.md`
- 机制：对金手指核心机制做 4 个维度变换：换对象、换后续动作、反转、升维。从中选 3 个差异最大的质变型分支，要求每个分支能独立支撑 3-5 章剧情。
- 营销角度：金手指不是单点设定，而是能持续生长剧情引擎。

### 营销点 9：金手指本质设计，从"能力是什么"推到"世界为什么允许它"
- 来源：`references/design-guide.md`
- 机制：金手指本质分三层：表层（能力做什么）→中层（与世界什么规则挂钩）→底层（进化到尽头触及什么真相）。关系类型包括工具关系、共生关系、闭环关系。
- 营销角度：金手指不只是外挂，而是世界观逻辑的一部分，世界观和主角命运互相绑定。

### 营销点 10：世界观从金手指推导，避免世界设定和创意脱节
- 来源：`references/design-guide.md`
- 机制：世界观分三步推导：金手指存在的前提是什么世界 → 世界怎么运转 → 金手指在世界规则中的挂钩点。世界自洽四问包括能力来源、触发条件、作用边界、世界机制如何执行。
- 营销角度：世界不是独立设定，而是被金手指撑起来的因果世界。

### 营销点 11：番茄简介写作法，展示创意而不是解释创意
- 来源：`references/synopsis-guide.md`
- 机制：简介要求 150-300 字，第一人称散文体，必须包含创意展示、限制暗示、第一个爽点期待感，至少 2 句角色台词，情绪弧线是从被动到主动。
- 营销角度：简介不是设定说明书，而是"故事开头的第一段钩子"。

## pop-fanqie-world

### 营销点 1：类型风味基线，杜绝"声明西幻却写出中式味"
- 来源：`steps/step3.md`、`steps/step4.md`
- 机制：world 新增维度0，消费创意.md 声明的"世界类型+风味基调"，展开为命名体系、器物清单、社会符号参考系。力量体系、地图、势力、危机、配角等命名和器物都必须符合该基线。
- 营销角度：类型一致性不是口号，而是可检查、可执行、可打回的门禁。

### 营销点 2：轻量原则推导，所有设定回溯创意源头
- 来源：`steps/step3.md`、`steps/step4.md`
- 机制：从创意.md 核心条款推导 3-5 条世界设计原则，每条必须回溯创意.md 具体条款。地图、势力、危机每个维度的关键设定后续必须回溯至少 1 条原则。
- 营销角度：设定不是堆设定，而是创意主线的投影。

### 营销点 3：力量体系四层结构，战斗设定可写
- 来源：`steps/step3.md`、`steps/step4.md`
- 机制：力量体系分四层：世界源力量、主养成线位阶、子养成线、交叉规则。主养成线 5-7 阶，每阶标注社会地位参照、战斗可写性 4 拍节奏、战斗画风；碾压型力量必须有约束，如启动前风险窗口、启动后时限、启动中副作用。
- 营销角度：力量体系不是名词堆叠，而是写到战斗章都能用的战斗参数。

### 营销点 4：势力攀登方式，角色行为逻辑有根
- 来源：`steps/step3.md`
- 机制：势力展开表新增"攀登方式/生存逻辑"和"对赌角色"。每个势力标注"这个势力的人靠什么活、怎么往上爬"，并在主角对赌行为中扮演资源、信息、障碍或对手。
- 营销角度：反派和配角不是空壳工具人，而是从势力生存逻辑里长出来的角色。

### 营销点 5：危机四源 + 倒计时感，压力从设定中自然涌现
- 来源：`steps/step3.md`、`steps/step4.md`
- 机制：危机展开表分终极危机和阶段性危机，每条标注来源层面、回溯原则、预计爆发卷和触发条件。核心原则是危机从力量体系、势力、地图推导，而不是随机加灾难。
- 营销角度：危机不是外部补丁，而是世界运转到一定阶段必然产生的问题。

### 营销点 6：分 3 段落盘，每个维度自检通过才推进
- 来源：`steps/step3.md`
- 机制：Step3 分三段：Part1 骨架层（力量体系 + 地图）、Part2 实体层（势力 + 危机 + 配角）、Part3 导航层（各卷设定切片）。每段都有好坏标准自检，通过才落盘进入下段。
- 营销角度：世界构筑不是"一次性生成"，而是分段检查、分段落地。

### 营销点 7：各卷设定切片，plot 按卷按需消费
- 来源：`steps/step3.md`、`steps/step4.md`
- 机制：world 产出 `各卷切片.md`，每卷标注力量范围、地理范围、势力范围、危机范围、核心配角、卷末设定边界和回溯原则。plot 层从切片中取本卷设定，而不是读全部世界设定。
- 营销角度：长卷设定被切成可消费模块，后续写剧情时不用重新翻全书设定。

## pop-fanqie-character

### 营销点 1：分幕驱动建角色库，出场谁就塑谁
- 来源：`SKILL.md`、`steps/step2.md`
- 机制：从 `设计/第一卷剧情/剧情白描.md` 的 2c 分幕设计中提取出场角色清单，去重后按分幕设计建角色库。建库规模由分幕设计驱动，不预设数量。
- 营销角度：角色库按需生成，不会凭空制造一堆不用的角色卡。

### 营销点 2：攀登方式类型，角色行为逻辑由势力生存逻辑推导
- 来源：`steps/step2.md`、`CHANGELOG.md`
- 机制：每个角色标注攀登方式类型：有资源型 / 没资源型 / 爬到顶层型 / 掉下来型。主角、配角、反派都必须回溯所在势力的生存逻辑，不凭空编性格。
- 营销角度：角色不是"人设词堆出来"，而是从世界势力生态中长出来的。

### 营销点 3：角色三问自检，消灭工具人角色
- 来源：`steps/step2.md`
- 机制：每个角色必须通过三问：①有独立欲望吗？②行为逻辑由攀登方式推导吗？③和主角有冲突必然性吗？任一不过必须重做该角色卡。
- 营销角度：角色库不是填充任务，而是确保每个出场角色都有自主行为和冲突。

### 营销点 4：角色关系网三张表，关系是剧情冲突的地基
- 来源：`steps/step2.md`
- 机制：角色库新增关系网：纵向关系（跨阶层/跨势力，如剥削/依附/反叛）、横向关系（同阶层/同势力，如竞争/联盟/暗合作）、主角关系图谱（盟友/对手/羁绊/利用）。
- 营销角度：角色不是孤立卡片，而是能直接转化为剧情冲突的关系网。

## pop-fanqie-plot

### 营销点 1：按幕白描，推演密度高于推演整卷
- 来源：`steps/step2.md`、`steps/step3.md`
- 机制：plot 不是先写整卷大纲，而是按幕逐个推演。每幕 8-12 章，产出五段式叙事梗概、非主角视角段落、场景表、幕末钩子、分支线标注、主角力量成长线和本幕结构要素表。
- 营销角度：剧情不是一次性生成，而是逐幕保鲜，防止中后期密度下降。

### 营销点 2：本卷设定快照，把骨架设定改成可写地图
- 来源：`steps/step2.md`
- 机制：plot 先从 world 的 `各卷切片.md` 圈出本卷范围，再充实为本卷设定快照。地图区域必须填充盘踞势力、内部矛盾、区域间矛盾；角色必须标注核心欲望、势力归属、关系张力。
- 营销角度：写剧情时不是空读设定，而是拿一份"可直接写白描的实地图"。

### 营销点 3：≥6 条分支剧情线，主线 + 支线 + 暗线网状推进
- 来源：`steps/step2.md`
- 机制：每卷至少 6 条分支剧情线，比例为主线 1-2 条 + 支线 3-4 条 + 暗线 1-2 条。每条线必须有起、止、涉及势力、涉及地图，支线还必须标注和主线的关系。
- 营销角度：剧情不是单线推进，而是多条线交织，推动力和信息量更强。

### 营销点 4：四段式起承转合，拒绝标签化幕纲
- 来源：`steps/step2.md`
- 机制：分幕起承转合升级为四段式模板：起（起始状态 + 打破事件 + 新危机 + 读者钩子）、承（手段 + 阻力 + 中途获得）、转（方案打破 + 意外反转 + 被迫新决策）、合（破局 + 大爽点 + 幕末质变 + 新危机钩子）。
- 营销角度：幕纲不是标题，而是有冲突、反转和爽点的具体故事单元。

### 营销点 5：多弧线交织，每幕至少 2 条故事弧线
- 来源：`steps/step2.md`
- 机制：每幕要求 2-4 条故事弧线交织，主线弧线、情感/关系弧线、战斗/成长弧线各自有独立核心事件和独立爽点。弧线之间在场景中交织，不是只推主线。
- 营销角度：一章节奏不靠单一线强撑，而是多线共同产生爽感和压力。

### 营销点 6：多视角叙事，制造信息差和压迫感
- 来源：`steps/step2.md`
- 机制：每幕至少 1 个非主角视角段落，由敌人、旁观者或其他角色视角切入，制造信息差、展现压迫感或增加情感层次。plot 自检"不是主角猜到"，而是有明确切镜头安排。
- 营销角度：多视角不是炫技，而是让读者看到主角看不到的信息。

### 营销点 7：卷纲精彩度五问，落盘前必须自评
- 来源：`steps/step2.md`
- 机制：整卷白描写完后执行五问：①读者追读理由≥2 个；②意外性≥2 个转折；③情感投入≥1 个锚点角色；④爽感密度≥60% 章节有爽点；⑤卷末高潮最精彩。5 问全部通过才落盘。
- 营销角度：plot 不只是"搭结构"，还要保证结构本身好看。

### 营销点 8：本幕结构要素表，给 write 的轻量导航
- 来源：`steps/step2.md`
- 机制：每幕白描中新增结构要素表：核心地点（≤3 个）、核心出场人物（≤6 个）、核心战斗、成长节点、资源获取、关系变化、伏笔回收/埋下。
- 营销角度：剧情白描不是虚的，而是能直接指导正文章节写什么。

## pop-fanqie-write

### 营销点 1：6 种章型骨架，番茄爽文场景标准化
- 来源：`references/章型定义.md`、`steps/step2.md`
- 机制：章型从 4 种升级到 6 种：opening_shift、exploration_gain、confrontation_pressure、combat_reversal、high_tier_display、reveal_hook。每种章型对应使用条件、读者期待、主动行为类型，以及 7 节拍骨架。
- 营销角度：写每一章不是从头想结构，而是先选章型，再按节拍骨架填充。

### 营销点 2：7 节拍骨架，章与章之间有节奏可复用
- 来源：`references/章型定义.md`
- 机制：每种章型 7 个节拍，节拍功能定义通用，笔触绑定在笔触 DNA 模板中。例如 combat_reversal 要求内部压制段 ≤3 段 + 爆发段 ≤3 行；opening_shift 以现实常识、异常逼近、机构失效、章末钩子推进。
- 营销角度：番茄章的爽感不是偶然，而是节拍结构自带。

### 营销点 3：密度约束自动锁定，战斗/系统/冲突不再随机分布
- 来源：`references/章型定义.md`
- 机制：选章型后自动锁定密度约束。combat_reversal 必须有战斗且占比 ≥30%；opening_shift、confrontation_pressure 都有系统交互或信息差密度要求；前 5 章不允许连续 2 章无战斗类章型，且至少 1 章是 combat_reversal。
- 营销角度：开篇节奏和战斗密度被机制锁住，减少"写得太平"的风险。

### 营销点 4：5 种爽感引擎，每章至少触发 1 个
- 来源：`references/爽点引擎.md`、`steps/step2.md`
- 机制：5 种爽感引擎为：打脸循环、压力突破、未知揭示、小爽沿途、即时奖励。打脸循环要求对方轻视 ≥2 层且翻盘 ≤3 行；压力突破要求突破 ≤3 行；小爽沿途要求每 3-5 事件有 1 个小爽。
- 营销角度：爽点不是单靠灵感，而是有触发条件、爆发长度和后果闭环。

### 营销点 5：爽感三段式闭环，避免"假爽"
- 来源：`references/爽点引擎.md`
- 机制：所有爽感爆发后必须三段式：爆发（≤3 行）、反馈（≤2 段）、余韵（≥1 段）。反例是爆发后直接跳到下一事件，没有反馈和余韵。
- 营销角度：读者看到的不是主角"赢了"，而是赢之后世界、对手、主角状态都发生变化。

### 营销点 6：爽感公式对齐番茄读者模型
- 来源：`references/爽点引擎.md`
- 机制：爽感公式参考番茄读者模型，强调 12 岁小学生滑动阅读：压力→突破、弱→强、未知→揭示、被欺→反击。核心原则是爽感必须有铺垫，无铺垫爽感=空爽。
- 营销角度：爽点设计有读者模型支撑，不是作者自嗨。

### 营销点 7：章型 × 爽感 × 技法三联动
- 来源：`references/章型定义.md`、`references/爽点引擎.md`、`references/微观技法索引.md`、`steps/step2.md`
- 机制：写前必须选章型、选爽感、选微观技法。章型锁骨架，爽点引擎锁情绪点，技法索引锁表达工具。每章最多选 3 类技法，每类技法只选 1-2 个子技法落地。
- 营销角度：从结构到情绪再到语言，三层都有机制约束。

### 营销点 8：16 类微观技法，通用/情境/流派专属分层
- 来源：`references/微观技法索引.md`、`references/通用技法/信息差博弈.md`、`后果链设计.md`、`人设微操.md`、`节奏微操.md`、`预期违背.md`
- 机制：16 类技法分 3 大类：通用技法 5 类，如信息差博弈、后果链设计、人设微操、节奏微操、预期违背；情境技法 6 类；流派专属 5 类。每种技法有子技法、适用章型、使用步骤、注意事项和反例。
- 营销角度：技法库不是泛泛写作建议，而是可按场景调用的"正文零件"。

### 营销点 9：字数硬限制 + API 自动裁剪
- 来源：`steps/step4.md`、`scripts/wordcount_check.py`
- 机制：正文字数要求 2000-2500 字，超过 2500 必须裁剪，超过 3000 废章重写。字数统计不含交付面板、不含 markdown 标记。脚本会调用 DeepSeek API 按优先级裁剪：环境描写、人物外貌、内心独白、铺垫段，最后删对话。
- 营销角度：正文长度不是建议值，而是硬卡口，避免写长失控。

### 营销点 10：交付面板带动作链、多感官、爽感、技法四指标
- 来源：`steps/step5.md`
- 机制：交付面板字段包括章号、章名、章型、字数、核心事件、爽感引擎、微观技法、动作链数量、多感官场景数量、章末钩子、推进 L2 线、笔触 DNA、前章钩子回收。战斗章动作链 ≥5，日常章 ≥3；每章多感官场景 ≥2，战斗章 ≥3。
- 营销角度：每章产出可审计，review 和用户都能看到写作指标。

### 营销点 11：AI 味检测 15 项 pattern + 高疲劳词 3 级
- 来源：`SKILL.md`、`steps/step1.md`
- 机制：AI 味检测包含 15 项 pattern，如二分对比、开场清嗓子、伪洞察铺垫、浅层分析尾缀、重要性吹嘘、模糊归因、假强动词、同义词循环、机械节奏、情绪直给等。高疲劳词分 S/A/B 三级，S 级单章出现即标注，A 级 ≥2 次标注，B 级 ≥3 次标注。
- 营销角度：审核不是"看着像 AI"，而是逐条定位原文并给出修正方向。

### 营销点 12：好看度 4 问，强制给证据不泛泛而谈
- 来源：`steps/step1.md`
- 机制：正文质量检查包含好看度 4 问：有没有让人想往下翻的劲？最抓人的画面/台词是什么？哪里无聊了？代入感够不够？每问必须有具体证据，不能只说"还行"。
- 营销角度：审核不只查设定和技法，也直接审"好不好看"。

## pop-fanqie-review

### 营销点 1：四步审核闭环，正向 → 质量 → 反向 → 沉淀
- 来源：`SKILL.md`、`steps/step1.md`、`steps/step2.md`
- 机制：Step1 正向符合性检查主线、设定、角色、爽感闭环和番茄底线；Step2 正文质量检查 AI 味、笔触 DNA 和好看度；Step3 反向充足性检查剧情白描、设定库、角色卡、燃料库；Step4 剧情沉淀更新双文件。
- 营销角度：review 不只是改错，而是判断"能不能继续写下一章"。

### 营销点 2：番茄底线门禁，字数、钩子、节奏、合规一视同仁
- 来源：`SKILL.md`、`steps/step1.md`
- 机制：番茄底线检查包括：字数 2000-2500 字，不准超过 2500；章末钩子必须是主动决策型；节奏密度 8-12 个事件/章；章型 7 节拍对齐；前后章衔接；章名格式 10 字以上；政治敏感/红线词/未成年保护/价值观命中任一直接 REJECT。
- 营销角度：番茄向写作的硬标准被固化到审核门禁里。

### 营销点 3：6 章型 7 节拍对齐检查，write 章型体系被 review 承接
- 来源：`SKILL.md`、`steps/step1.md`
- 机制：review 1f 检查本章章型归属、7 节拍完整性和章型-内容匹配，要求读取 write 的 `references/章型定义.md` 对照判定。红线规定 6 章型 7 节拍对齐是上游升级的下游卡口，缺一项不得通过。
- 营销角度：review 和 write 共享章型真源，前后端不会脱节。

### 营销点 4：战斗可写性审核，承接 world 的 4 拍节奏
- 来源：`SKILL.md`、`steps/step1.md`
- 机制：战斗章必须检查 4 拍节奏"压迫→反转→碾压→余波"、主角是否付出可见代价、战斗画风是否匹配力量体系、能力使用是否在规则边界内。越界能力直接 REJECT。
- 营销角度：战斗章不只是"打起来"，而是有节奏、有代价、有边界。

### 营销点 5：主角主动性审核，防止剧情推着主角走
- 来源：`SKILL.md`、`steps/step1.md`
- 机制：检查主角是否至少 1 个主动决策、核心事件是否由主角主动触发、行动是否推进自己的目标。主动性等级分为 A 级主动出击、B 级主动应对、C 级被动推着走，连续 2 章 C 级为 REJECT 级警示。
- 营销角度：番茄爽文的核心"主角主动出击"被量化到每章审核。

### 营销点 6：多视角覆盖审核，承接 plot 的非主角视角要求
- 来源：`SKILL.md`、`steps/step1.md`
- 机制：review 检查本幕 3-5 章是否至少 1 段非主角视角段落，视角切换是否服务信息差/悬念/格局展示，单章非主角视角篇幅是否 ≤30%。
- 营销角度：多视角不是可有可无，而是正文质量门禁的一部分。

### 营销点 7：双文件叙事记录，白描卡存"发生"，状态快照存"状态"
- 来源：`SKILL.md`、`steps/step2.md`
- 机制：剧情白描流水账 append-only，每章追加白描入口；状态快照 replace，保存未回收钩子台账、角色当前状态表、禁止漂移。白描卡每章约 3-5 句叙事流，100 章约 1 万字，无需三档压缩。
- 营销角度：全书连续记忆由 append-only 流水账 + replace 状态快照组成，既可读又可追踪。

### 营销点 8：钩子台账含信息差类型，爽点储备可视化
- 来源：`steps/step2.md`
- 机制：未回收钩子台账记录钩子、埋设章、信息差类型、预期回收、状态。信息差类型标注读者知/主角不知（爽点储备）或主角知/读者不知（悬念储备），超 3 章未回收标红。
- 营销角度：钩子不只是"埋了"，还能继续产生爽点或悬念。

### 营销点 9：审核结论对话内输出，不做冗余报告
- 来源：`SKILL.md`、`steps/step2.md`、CHANGELOG.md
- 机制：v4.11.0 起，审核结论只在对话内输出，不落盘审核报告/verdict。落盘只更新白描卡和状态快照，废除了旧版审核报告、verdict、剧情累计卡、current-state、review-沉淀等冗余文档。
- 营销角度：review 轻量化后更专注"判断正文 + 沉淀连续记忆"。
