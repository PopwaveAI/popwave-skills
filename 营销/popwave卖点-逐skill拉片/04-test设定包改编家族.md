# 04 · test 设定包改编家族 · 营销点拉片

> 覆盖 skill：test-adapt / character / lite / pipeline / plot / research / review / world / write（9 个，~69 文档）
> 定位：设定包改编引擎——把一本成功书转成标准化设定包，再以「抄商业架构、不抄皮/机制/人/事件」为边界，按用户创意 X 反向改编成新书。

---

## pop-test-adapt

### 营销点 1：X DNA 替换矩阵，X 创意驱分支出，包只当商业架构锚
- 来源：`SKILL.md`
- 机制：`test-adapt` 的改编计划产出核心是 X DNA 替换矩阵：逐维度对照包 PRD，按改编强度决定保留、类比切换或重写。维度包括主角、敌人/盟友、剧情事件、开篇场景、地理/势力/世界观、力量体系/金手指。原包 DNA 不是简单抄人设，而是按「包 PRD 该维度的核心设定」替换为 X 的新设定。
- 营销角度：把「仿写标杆」升级为「按创意改编」，用商业架构保证商业可信度，同时把题材、机制、人物、事件全交给 X 驱动。

### 营销点 2：改编强度 A/B/C 三档选择，改多少由用户决定
- 来源：`SKILL.md`
- 机制：用户输入 X 后，必须呈现 A/B/C 三档并选择，不能默认跳过。A 改演员：主角、敌人、盟友、剧情事件、开篇场景替换，保留世界、地理、势力、力量体系、金手指。B 改世界观：保留力量体系/金手指，重写地理、势力、世界观、时代引擎。C 全改：只保留商业架构，力量体系/金手指也从 X 重写。
- 营销角度：同一个成功包，用户既可以做「同世界换人换事」，也可以做「彻底换机制」，不需要重新设计一条完整管线。

### 营销点 3：抄商业架构，不抄皮/机制/人/事件，原创性有边界
- 来源：`SKILL.md`
- 机制：改编分界明确规定质量锚照搬、原创层全换。质量锚包括四段式大结构、质变点位分布、卷末收益三件套、首三章功能位、欲望半径四段放大、节奏参数、爽点配比。原创层包括题材皮、世界观、力量体系机制、金手指形态、人物全员、具体事件。
- 营销角度：用户最关心的「会不会抄袭」被制度化解：学商业架构，不抄具体内容。

### 营销点 4：包配方+立项 PRD 全文强制读取，禁止凭记忆动笔
- 来源：`SKILL.md`
- 机制：红线要求动笔前必须读包配方表和包立项 PRD 全文，且禁止 limit 截断。无包则报错中止，不凭记忆写。包是改编质量锚，六要素立项 PRD 负责给出深度与颗粒度标杆。
- 营销角度：杜绝「读了几段就开始瞎编」，把标杆书的商业结构先硬对齐，再逐层替换。

### 营销点 5：剧情类比切换策略，只抽冲突模式不抽事件
- 来源：`steps/step2-adapt.md`
- 机制：剧情类比切换分三步：提取原包核心张力（每卷/幕的冲突模式）→ 推导新 X 核心张力 → 把每卷功能位映射到新事件 DNA。功能位保留，事件从 X 核心张力、新世界、新角色重新推演。例如原包「小人物在乱世靠信息差求生+初触超凡」，可切换为 X 的「偷 vs 被偷」冲突。
- 营销角度：避免把「参考某本书」变成「照搬剧情」，用户得到的是事件级全新推导。

### 营销点 6：X 体验层三耦合，X 不是包装而是正文机制
- 来源：`steps/step2-adapt.md`
- 机制：改编计划必须产出 X 体验层，包括战斗耦合、日常耦合、剧情耦合。战斗耦合写 X 在战斗中的独特表现，例如心灵窃取可表现为偷敌人招式、植入假记忆、读心预判。日常耦合写 X 在日常中的表现与代价，剧情耦合写 X 与主线的核心耦合点。
- 营销角度：解决用户「X 只是设定，没写进正文」的痛点，让创意直接变成战斗、日常、剧情中的可用机制。

### 营销点 7：改编继承表，偏离哪里声明哪里
- 来源：`SKILL.md`、`steps/step2-adapt.md`、`templates/立项/01-立项PRD.tpl.md`
- 机制：PRD 末尾必须附改编继承表，列出四段式大结构、质变点位、卷末收益三件套、首三章功能位等质量锚，以及用户拍板的偏离项。偏离项需要写原因和影响，保留「抄商业架构，不抄皮/机制/人/事件」的声明。
- 营销角度：商业架构继承表和偏离声明并行，用户既能守住节奏，也能把 X 创意合法下沉到设计层。

### 营销点 8：六要素立项 PRD 一次定方向，项目起点明确
- 来源：`SKILL.md`、`steps/step2-adapt.md`、`templates/立项/01-立项PRD.tpl.md`
- 机制：adapt 不产工程级设计文档，只产出 `素材/改编计划.md` 和 `立项/01-立项PRD.md`。PRD 要求包含世界、力量体系、人物、起因、经过、结果，并附带改编继承表。验收红线是六要素必须能讲成一个故事，具备递进阶梯、爽点落点、追读欲。
- 营销角度：立项不是空泛方向，而是能直接交付给下游 world/character/plot/write 的立项依据。

### 营销点 9：冲突项≤3 个一次拍板，不反复打断
- 来源：`steps/step1-collect.md`
- 机制：如果 X 与包结构参数冲突，例如 X 要慢热但包蓄力≤2 段，则逐项列出冲突清单，用户一次性拍板：覆盖包，记入偏离声明；改 X，不记偏离。冲突项≤3 个直接列清单问一次，不反复打断。
- 营销角度：降低用户沟通成本，把「创意冲突」转成一次拍板，而不是无限对话。

## pop-test-character

### 营销点 1：角色配置规格保留，人物 100% 原创
- 来源：`SKILL.md`
- 机制：character 保留表 5 全项：约 28 人规模、核心配角 6 配置位、反派四层梯度、主角三定位、攀登 4 类标注、欲望半径四段。原创层是全换人物，人名、关系、事件不得与包重复。
- 营销角度：角色库有标杆骨架，但内容层全部原创，避免「角色移植感」。

### 营销点 2：主角重写、敌人盟友类比切换，作者不用担心继承包袱
- 来源：`SKILL.md`、`steps/step1-library.md`
- 机制：主角从 X 全新推导身份、欲望、行动，三定位结构照搬。敌人/盟友按改编计划做类比切换：同功能位换事件 DNA，包敌人的功能位保留，人物全换。配置规格保留，人名和关系全换。
- 营销角度：主角有 X 的原创性，敌人/盟友又不会脱离原包功能位，结构不会散。

### 营销点 3：金手指三约束，避免金手指变成万能外挂
- 来源：`SKILL.md`、`templates/金手指.tpl.md`
- 机制：金手指必须满足三项：key 非生成器，赋能不越级，限制显性。A/B 强度保留包金手指机制，只换风味；C 强度从 X 重写金手指形态，但三约束照搬。模板结构为定义、机制、赋能范围、限制与代价、成长路线、商业逻辑。
- 营销角度：金手指不再「越级解决问题」，而是被限制、代价和成长路线绑死。

### 营销点 4：~28 人规模±20%，角色版图不靠脑补
- 来源：`SKILL.md`、`steps/step1-library.md`
- 机制：包总表多少人，本书就多少人，允许±20%。角色总表列角色名、定位、阵营、攀登方式类型、等级坐标、引入章、最后出场章。反派必须标退场章和退场方式。
- 营销角度：全书角色规模被量化，不会写到后面发现反派不够、配角没位置。

### 营销点 5：核心配角 6 配置位，团队结构有商业锚
- 来源：`SKILL.md`、`steps/step1-library.md`
- 机制：核心配角保留 6 个配置位：情感主锚、女主、政治联姻线、盟友暧昧线、温情符号、战友牺牲位。人物全换，但配置卡规格保留。
- 营销角度：角色库不是随便堆人，而是按商业关系结构排布。

### 营销点 6：四层反派梯度，让对手节奏有章法
- 来源：`SKILL.md`、`steps/step1-library.md`
- 机制：反派按层级铺：街头层、城市层、卷末 BOSS、跨卷大反派。反派退场章要写入角色总表，角色总表最后一列就是「最后出场章」。跨卷反派 3-5 个，作为全书常驻敌人。
- 营销角度：敌人不是随机出现，而是有退场计划、有阶段功能、有全书尺度。

### 营销点 7：等级坐标必须挂力量体系档位，拒绝悬空数值
- 来源：`SKILL.md`、`steps/step1-library.md`
- 机制：每个角色的等级坐标必须能对上本书力量体系档位，起点档和终点档两端写清。角色库模板也要求等级坐标对齐力量体系主养成线。
- 营销角度：角色不是独立词条，而是挂在整条力量成长线上，后续 plot/write 都能消费。

### 营销点 8：欲望半径四段放大，主角成长路线可追踪
- 来源：`SKILL.md`、`steps/step1-library.md`
- 机制：主角欲望按四段放大：护一人→护一城→护一域→定秩序。每段都要标注预计卷。
- 营销角度：主角成长不只是变强，而是执念范围逐步放大，形成清晰升级路径。

## pop-test-lite

### 营销点 1：单文件 360 行写作引擎，极简结构
- 来源：`SKILL.md`、`skill.json`
- 机制：test-lite 是超轻量单文件写作 skill，无 steps/templates/references 资源分层，全部方法论自包含于 SKILL.md。覆盖原创小说、同人、剧本/动态漫脚本、纯世界观构筑。
- 营销角度：不需要复杂目录和文件结构，用户能快速启动轻量创作实验。

### 营销点 2：五维角色卡+灵魂场，角色不只靠标签
- 来源：`SKILL.md`
- 机制：五维角色卡包括基本身份、核心人格、灵魂场、语言指纹、关系网络与成长弧。灵魂场要求 3-5 条不可违背的行为铁律，例如「朋友有难必救」「不主动伤及无辜」「承诺必兑」。
- 营销角度：角色不是「善良、勇敢、聪明」的标签堆叠，而是被「不能做什么」钉住，后面剧情才有张力。

### 营销点 3：3:1 pacing，解决正文流水账
- 来源：`SKILL.md`
- 机制：3:1 比例要求约 3 份摘要对应 1 份完整演绎，锚点冲突要情绪摇摆，能写成完整叙事段。正文默认形式是一条不间断连续流，不按场景拼块。除真实时空跳转外，禁止用分割线、空白或「却说/话说」切段。
- 营销角度：把「太多交代、太少现场」的问题修掉，章节更像连续剧情流。

### 营销点 4：五档风格温度，控制文本强度
- 来源：`SKILL.md`
- 机制：五档从 1 calm daily 到 5 full unhinge，分别对应不同句子长度和场景分布。长文分布参考：1 档 15-20%、2 档 35-45%、3 档 20-30%、4 档 8-15%、5 档 1-3%。转换规则明确：1→2 自然，2→3 需触发事件，3→4 需冲突爆发，直接 1 跳 4/5 被禁止。
- 营销角度：写作不是全程高能，而是有日常、紧张、高潮、失控的强度曲线。

### 营销点 5：反 AI 13 纹，机械感文字有明确识别标准
- 来源：`SKILL.md`
- 机制：13 条包括堆叠比喻、句式节奏单一、AI 套话、空泛程度副词、点述结构、段落长度均匀、完美信息传输、情绪模板重复、章节模板化、等距时间线、场景碎片化、全知心理、感觉替代思考等。补充技法包括语义熵注入、节奏打断、通感。
- 营销角度：不只是「去 AI 味」提示，而是逐条指出写作会暴露 AI 痕迹的具体位置。

### 营销点 6：感官锚系统，抽象概念能落到身体感
- 来源：`SKILL.md`
- 机制：感官锚构造公式为：精确时间/频率 + 具体身体部位 + 非日常物理类比 + 可量化变化趋势。例如丹田气旋逆转导致左手食指指尖发麻，麻的时间比上次长。
- 营销角度：力量、恐惧、代价等抽象概念不再靠解释，而靠可感知信号传达。

### 营销点 7：长篇状态管理，30 万字后也有账本
- 来源：`SKILL.md`
- 机制：长篇状态管理包含六个状态文件：arc-status、foreshadows、used-tropes、established-facts、character-state、next-hook。每章固定加载 arc-status、foreshadows、next-hook、character-state 约 1500 字符上下文。
- 营销角度：长篇写作最痛的不是开头写不出，而是中后期记不住伏笔、事实和人物状态。

### 营销点 8：五维场景识别，从短章到长篇都能路由
- 来源：`SKILL.md`
- 机制：场景识别按五维进行：场景类型、长度、类型、视角、温度。长度分为短 3k-30k、中 30k-100k、长 100k+、单章 2k-5k。同人还需区分类型、CP tier、canon anchor。
- 营销角度：同一个轻量引擎能处理原创、同人、剧本、世界观、长篇等不同需求。

## pop-test-pipeline

### 营销点 1：改写·续写·导入一站式，旧项目也能接上
- 来源：`SKILL.md`、`steps/step0-import.md`
- 机制：pipeline 支持 fresh、import、resume 三种 mode。导入模式会扫描已有文件，做原始资产清单、文件归位、来源标记、缺口分析、落地 Phase 决策、状态文件重建。
- 营销角度：用户不一定要从零开始，已有大纲、正文、角色库都能归位进同一管线。

### 营销点 2：项目总控.html，当前 Phase 一目了然
- 来源：`SKILL.md`、`steps/step0-import.md`、`templates/项目总控.html`
- 机制：`项目总控.html` 是唯一状态文件，记录 mode、phase、chapter、项目名、更新时间和各就绪态。Phase 进度用圆形节点展示，ready 状态用 badge 标记。导入模式下还自动生成缺口报告和落地 Phase 建议。
- 营销角度：用户随时知道「项目现在卡在哪」「下一步该写什么」「哪些文件还没就绪」。

### 营销点 3：Phase 路由表，从立项到审核自动串联
- 来源：`SKILL.md`
- 机制：pipeline 按 Phase 0 包校验→Phase 1 adapt 立项→Phase 3 world 世界→3.5 character 角色→4 plot 剧情→5 write 正文→6 review 审核推进。Phase 4 产出主线、卷纲、幕白描、章纲；Phase 5 读 3 章章纲渲染；Phase 6 沉淀白描卡和状态快照。
- 营销角度：创作被拆成明确阶段，用户不必自己判断下一步该用哪个 skill。

### 营销点 4：主 agent 直接执行，不派发子 agent
- 来源：`SKILL.md`
- 机制：pipeline 只做路由不干活。执行前必须读对应 skill 的 SKILL.md 和 phase 涉及的 step 文件，提炼红线和操作要点后执行。禁止派发子 agent 执行技能生成任务。
- 营销角度：用户不用担心任务被拆成碎片，pipeline 自己吃掉复杂性，交付完整阶段结果。

### 营销点 5：Phase 就绪门禁，不达标就停在当前阶段
- 来源：`SKILL.md`
- 机制：Phase 1→3 检查改编计划是否含 X DNA 替换矩阵、剧情类比切换策略，PRD 是否含六要素和改编继承表。Phase 3→3.5 检查力量体系晋阶表、全书设定文件是否非空。Phase 4→5 检查卷纲、章纲、白描卡、plot 锚点区和七查绿灯。
- 营销角度：管线不是机械推进，而是每阶段检查真实产出，避免「看似走完，实际没内容」。

### 营销点 6：写审循环，write 一章、review 一章
- 来源：`SKILL.md`
- 机制：每次写 1 章后审 1 章。review 打回，write 按打回清单修改并重审。write 向前锚是本章章纲，读 3 章章纲推进；review 沉淀白描卡和状态快照后，write 续写下一章。
- 营销角度：连载不是写完就丢，而是每章都有审核和沉淀，形成「写作→审核→续写」的稳定节奏。

### 营销点 7：来源标记，外部文件质量可追溯
- 来源：`steps/step0-import.md`
- 机制：归位文件标注 user-original、pipeline-relocated、skill-generated、skill-reconstruct 四种来源。user-original 或 pipeline-relocated 的设计层文件需校验，skill-generated 或 skill-reconstruct 可直接消费。
- 营销角度：导入旧项目时，用户可以知道哪些文件是已有的、哪些是重建的、哪些还需要校验。

### 营销点 8：导入模式补跑，缺什么调度什么
- 来源：`steps/step0-import.md`
- 机制：导入时如果发现缺白描卡/状态快照，调度 test-review reconstruct；如果缺设计文档，则按依赖链调度 adapt/world/character/plot 补跑。reconstruct 支持有正文但缺状态文件的回溯。
- 营销角度：旧项目不需要完全重写，pipeline 能自动识别缺口并调度对应 skill 补全。

### 营销点 7：核心张力映射表，引擎层的唯一推导源
- 来源：`steps/step1-mainline.md`

### 营销点 8：卷纲防抢后续收益，避免剧情提前用完

- 机制：X 体验层从改编计划按章型注入。战斗章注入 X 战斗耦合，日常章注入 X 日常耦合，剧情推进章注入 X 剧情耦合。每章至少 1 处，X 必须参与动作、对话、决策。
- 营销角度：X 不只是设定库词条，而是每章都必须落地成正文行为。

### 营销点 5：设定库精选注入，每章≤3 维度≤1500 字
- 来源：`steps/step1-consume.md`
- 机制：设定库不是全文加载，而是按章型按需注入。每章最多 3 维度，每维度≤500 字，总计≤1500 字。角色库和类型风味基线必选，再按章型选择战斗、日常、探索、危机、社交、成长等文件。
- 营销角度：世界设定被精准喂到需要的章节，避免信息过载和记忆污染。

### 营销点 6：文风 DNA 缺失态兜底，裸写被禁止
- 来源：`steps/step1-consume.md`、`steps/step2-write.md`
- 机制：文风 DNA 存在时，按上一章白描卡执行包或素材/文风锚定加载；缺失时从 KB/文风DNA/选内置兜底，按赛道标签匹配，例如深渊主宰、夜无疆、诡秘之主、捞尸人、东京医途等。
- 营销角度：写正文必须有文风约束，避免把不同参考书风格混写。

### 营销点 7：write 只声明，review 才落库，权限边界清楚
- 来源：`steps/step2-write.md`
- 机制：write 在写作中产生的新增事实、人物变化、设定变化，只在创作记录中声明「新增事实待 review」，不落盘到任何库文件。后续由 review 读取正文和创作记录后决定是否落库。
- 营销角度：防止 write 越权写乱角色库、设定库或卷纲。

### 营销点 8：战斗章分层加载战斗表现，写法直接可复用
- 来源：`steps/step1-consume.md`
- 机制：战斗章注入包参考答案 `力量与战斗/战斗表现/`5 件。通用层每战必读，包括六要素、战前规划卡、红线；按主角当前等级段选读凡人期、超凡期或神明级；特殊条件战按需叠加。结构变异包路径以包配方映射节为准。
- 营销角度：不同等级段和特殊战斗条件有专属写法层，write 直接消费。

### 营销点 9：2000-2500 字/章，正文字数有红线
- 来源：`SKILL.md`
- 机制：write 输出固定为 `正文/ch{NNN}.txt`，每章 2000-2500 字。输出正文，不附带长段创作细节，创作记录单独输出。
- 营销角度：连载章节长度稳定，不会写成过短片段或过长爆章。
