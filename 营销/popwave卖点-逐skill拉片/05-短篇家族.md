# 05 · 短篇家族 · 营销点拉片

> 覆盖 skill：short-platform-orientation / idea-refiner / opening-designer / plot-structurer / body-generator / reviewer / text-deconstructor（7 个，~80 文档）
> 定位：短篇创作全流程——平台定向→脑洞→开篇→结构→正文→评审→拆文，逐环节都有量化约束和门禁。

---

## pop-short-platform-orientation

### 营销点 1：6 大平台自动性质推导表
- 来源：`SKILL.md`
- 机制：内置 6 大平台（番茄短故事 / 知乎盐言故事 / 每天读点故事 / 豆瓣阅读 / 小程序生态 / 七猫）的自动性质映射表，每个平台一句话定性。番茄=快节奏爽文/网感强/下沉市场；知乎=知性深度/社会洞察/反转导向；每天读点故事=情感治愈/暖甜/短剧感；豆瓣=文学质感/慢热/长尾品质；小程序=信息流钩子/极致快节奏；七猫=精品网文/保底导向。
- 营销角度：作者无需自己判断平台调性，skill 内置「平台×性质」速查表，开箱即用。解决「选平台时两眼一抹黑」的痛点。

### 营销点 2：3 问摸底 + 智能跳过条件
- 来源：`steps/step1-survey.md`
- 机制：只需 3 问——题材倾向 / 核心目标 / 现有素材——完成摸底。若作者已带明确意向（如「想写悬疑投番茄」），直接跳过摸底进入匹配。三种跳过条件：已说平台+题材→直接匹配；已说题材但没平台→直接跨平台对比；什么都没说→进入摸底。
- 营销角度：极致高效，已有明确意向的用户 1 步到位，无意向用户 3 问快速收敛。解决「一问一答太累」的痛点。

### 营销点 3：平台深度匹配 8 维度展开 + 对比表格
- 来源：`steps/step2-match.md`
- 机制：对被选中的 1-2 个平台，每个展开 8 个维度：签约门槛与速度 / 目标读者画像 / 该题材在平台表现 / 子方向推荐 / 开篇铁律 / 付费钩子模式 / 改编潜力 / 风险和注意。最终输出 2 平台对比表格 + 其余平台一句话简述。
- 营销角度：不只是「推荐平台」，而是做 8 维深度对比分析，让作者拿到一份可落地决策报告。解决「选平台时信息不透明」的痛点。

### 营销点 4：红线规则——不做跨平台通稿
- 来源：`SKILL.md` 红线
- 机制：红线 #1：只深度展开 1-2 个最适合的平台，不做跨平台通稿。红线 #2：不替作者做最终决定，展示优劣让作者选。红线 #3：平台数据以 references/platform-rules.md 为准，不发明规则。红线 #4：遇到实时性政策问题如实告知。
- 营销角度：设计哲学是「辅助决策不替代决策」，保护作者体验。作者对决策有最终控制权，不会怪 AI。

### 营销点 5：6 大平台完整规则库
- 来源：`references/platform-rules.md`
- 机制：每个平台含基础参数（字数要求、付费模式、分成比例）、目标读者画像（年龄/性别/心理特征）、调性要求（关键词+具体描述）、热门品类（含子方向）、开篇铁律（精确到字/句数）、付费钩子特征（断点策略）、格式注意。数据包括：番茄 100% 收益、60%-70% 过签率、最快 1 小时出结果；知乎 50% 分成、千字 30-100 元、约 30%-40% 免费比例；每天读点故事 VIP 保底 1000 元/篇。
- 营销角度：知识库级别的行业标准数据，不只是通用建议，而是精确到百分比的实操数据。解决「不了解平台规则」的痛点。

### 营销点 6：品类写作指南（5 大品类 × 子方向）
- 来源：`references/genre-guide.md`
- 机制：5 大品类（悬疑/惊悚 / 现代言情 / 玄幻仙侠 / 都市现实年代 / 脑洞规则怪谈），每个品类含赛道特征（含具体增长率数据：悬疑男频+194%、玄幻言情+109%、纯年代文-56%）、热门子方向列表、陷阱警告、范例脑洞。例：规则怪谈被称为「2026 年增长最快的交叉品类」。
- 营销角度：每个品类有赛道数据 + 陷阱警告 + 范例脑洞，给作者一套「什么能写、什么不能写」的导航仪。

### 营销点 7：项目总览.md 状态表
- 来源：`SKILL.md`
- 机制：Step 3 输出 `项目总览.md`，内含 6 步状态追踪表（S1-S6），三种状态（⬜未开始 / 🟡进行中 / ✅完成），严格约束「有且仅有 1 个 Step 为 🟡」，支持跳过标记（✅已跳过）。
- 营销角度：内置项目进度管理系统，跨 skill 流转全程可追踪。解决「不知道现在走到哪一步」的痛点。

### 营销点 8：定位卡片 + 流转上下文双输出
- 来源：`steps/step3-output.md`
- 机制：输出两份结构化文件——定位卡片（6 字段：平台/文章性质/签约门槛/核心读者/开篇铁律/付费钩子模式/改编方向/风险提示）+ 流转上下文（5 字段：选定平台/文章性质/核心约束/用户意向/原始想法）。所有字段标准化模板，确保后续 skill 无缝消费。
- 营销角度：不只是给出建议，而是产出结构化的「待办卡片」，流水线衔接无缝。解决「建议说完就没了，后续 skill 接不上」的痛点。

## pop-short-idea-refiner

### 营销点 1：3 条路径自动分流
- 来源：`SKILL.md` / `steps/step1-gather-input.md`
- 机制：自动判断作者处于哪种状态：A 路径（有模糊想法）→ 说出想法→热点→榜单→提炼→检验→输出；B 路径（只有方向）→ 收窄偏好→热点→方向菜单→等共鸣→提炼→检验→输出；C 路径（带例文）→ 先解析例文卖点→风格权重提升→走 A 路径。
- 营销角度：不管用户给什么输入（一句话想法 / 一个方向 / 一个例文），都能自动识别并走最优路径。解决「用户不知道从哪说起」的痛点。

### 营销点 2：路径 B 的 4-5 子方向菜单
- 来源：`steps/step2-refine-directions.md`
- 机制：路径 B（只有方向）时，输出 4-5 个子方向菜单，每个含：热度（🔥1-5 星）、竞争（高/中/低）、改编潜力（⭐1-5）、范例脑洞。用户选择偏好后再生成 2 个脑洞方向。
- 营销角度：用户不必凭空想，给一个方向就展示具体子方向供选择，降低决策负担。解决「不知道什么方向热门」的痛点。

### 营销点 3：三阶段热点拉取策略
- 来源：`steps/step2-refine-directions.md`
- 机制：按优先级拉取热点信号：①用户提供的素材（榜单截图/链接/例文）→②WebSearch 按格式 `"{平台名} {题材} 热门 2026 品类趋势"` →③WebFetch 知乎智慧故事。提取信号：哪些子方向在涨、哪些在退、近期爆款代表作品关键词。
- 营销角度：不只是通用建议，而是主动拉取实时市场数据，结合用户素材做精准推荐。解决「不知道现在什么题材好写」的痛点。

### 营销点 4：3 项脑洞检验门禁
- 来源：`steps/step3-verify-output.md`
- 机制：每个脑洞方向必须通过 3 项检验：①让人想听下去吗？②有反常识/反预期的元素吗？③能在 3 分钟内讲清吗？至少 2 项通过才进入下一步，否则给出 2-3 个补强建议。
- 营销角度：质量门禁设计，不合格脑洞不流入后续步骤，避免「垃圾创意浪费时间」。

### 营销点 5：脑洞卡片 7 字段结构化输出
- 来源：`templates/idea-card.tpl.md`
- 机制：输出含 7 个区块：脑洞速览（6 字段）/ 核心冲突 / 预期反转爽点 / 检验结果（✅/❌ 逐项）/ 热点参考 / 补强建议 / 流转上下文。完整记录每个决策节点的数据。
- 营销角度：不只是给一句话脑洞，而是产出完整卡片，包含检验过程和补强建议，每一步都有据可查。

### 营销点 6：红线——不替用户写脑洞
- 来源：`SKILL.md`
- 机制：红线 #1：不替用户写脑洞，给选择让用户决策。红线 #2：检验标准至少 2 项通过才进入下一步。红线 #3：热点数据仅作参考信号，不替代创作决策。红线 #4：跨平台一稿多投时提醒平台差异。
- 营销角度：设计哲学是「辅助创作不替代创作」，用户始终是决策者，增强参与感和信任感。

### 营销点 7：路径 C 例文风格权重提升
- 来源：`steps/step1-gather-input.md`
- 机制：用户带例文时，先提取例文核心卖点（脑洞一句话/题材/流派标签），标注风格要素，进入路径 A 时例文风格作为参考权重提升。
- 营销角度：支持「仿写」场景——用户上传一篇喜欢的小说，skill 自动分析其风格并融入新创意生成。

## pop-short-opening-designer

### 营销点 1：卖点主轴 6 种候选 + 优先级标注
- 来源：`steps/step1-sell-point.md`
- 机制：先确认「卖什么」而非「怎么写」。列出 2-3 个卖点候选：悬疑（「我要知道真相」）/ 情感（「我会心疼」）/ 爽（「看得解气」）/ 反转（「没想到是这样」）/ 身份共鸣（「这不就是我吗」）/ 猎奇（「还有这种事」）。每个标注优先级（⭐1-5），用户确认后形成主轴。
- 营销角度：卖点先行，确保所有后续内容围绕同一个核心卖点展开。解决「写偏了」的痛点。

### 营销点 2：6 种导语公式 + 平台匹配表
- 来源：`steps/step2-choose-formula.md`
- 机制：6 种公式：①悬念前置（惊人结果 + 「但事情没这么简单」 + 更大疑问）→适配知乎 ⭐⭐⭐⭐⭐；②情绪爆发（强烈情绪词 + 具体事件 + 「那一刻我明白了」）→适配每天读点故事 ⭐⭐⭐⭐⭐；③对话开头（带引号的话 + 谁说的 + 后果）→适配知乎/每天；④身份共鸣（精准身份标签 + 扎心困境 + 「你是不是也」）→适配番茄 ⭐⭐⭐⭐⭐；⑤反转（常规认知 + 「但我发现」 + 完全相反的真相）→适配知乎 ⭐⭐⭐⭐⭐；⑥画面切入（具体画面/动作 + 时间地点 + 「不对劲」）→适配每天/豆瓣 ⭐⭐⭐⭐⭐。自动匹配表：5 平台 × 3 优先推荐公式。
- 营销角度：6 种公式覆盖所有平台，每平台 3 个优先推荐，开箱即用。解决「不知道开篇怎么写」的痛点。

### 营销点 3：黄金三句三要素法
- 来源：`steps/step3-golden-three.md`
- 机制：每句有独立功能：句 1 甩冲突（反常事件/绝境宣示/强烈情绪/身份反差/直接亮结果）→句 2 拉近距（具体感官细节：动作/触感/声音/气味，必须是「摄像机能拍到的东西」）→句 3 留钩子（暗示走向 + 最强未解谜题）。生成 2-3 组，每组标注公式/读者心理/平台适配度。
- 营销角度：三要素法 + 感官细节强制要求（「不能是抽象描写，必须是摄像机能拍到的东西」），确保每句都有明确功能。

### 营销点 4：100-200 字导语字数约束 + 补句禁忌
- 来源：`steps/step4-full-opener.md`
- 机制：最小 100 字 / 最大 200 字，黄金三句占比 60-80%。补句规则：知乎/番茄可选（三句话已足够），每天读点故事/豆瓣建议加一句。三类绝对禁忌：交代背景 / 抒情议论 / 解释说明。
- 营销角度：精确到字数的约束 + 三类禁忌，给作者一套明确的「什么能写、什么不能写」的开篇规范。

### 营销点 5：付费钩子 4 类型 + 平台差异化
- 来源：`steps/step5-pay-hook.md` / `references/golden-three.md`
- 机制：4 种钩子类型：①信息缺口（刚抛出重大悬念时不让知道答案）→适用于悬疑/猎奇；②情绪最高点（情感投入达最高时戛然而止）→适用于情感/虐；③决策时刻（主角面临重大选择时停在选择前）→适用于反转/身份共鸣；④反转预告（暗示即将发生反转但不透露内容）。各平台差异化：知乎=信息缺口型/反转预告型；番茄=爽点预告型/决策时刻型；每天=情绪最高点型。
- 营销角度：付费钩子不只是「断在付费点」，而是按类型精确匹配平台，解决「断点策略不明」的痛点。

### 营销点 6：红线——导语是广告语不是正文
- 来源：`SKILL.md`
- 机制：红线 #1：导语不是正文第一句话——是平台展示页上的故事简介。红线 #2：不做「交代背景」「抒情议论」「解释说明」——3 个致命禁忌。红线 #3：导语最后一句话必须是最强的悬念或钩子。红线 #4：一稿多发多个平台时提醒导语需按平台重写。红线 #5：导语确定前不进入 plot-structurer。
- 营销角度：严格区分「导语」和「正文开篇」的概念，避免作者混淆。解决「把正文开篇当导语写」的常见错误。

### 营销点 7：黄金三句 vs 黄金三句范例
- 来源：`references/golden-three.md`
- 机制：三种平台的黄金三句完整范例：番茄（重生爽文）→句 1 立冲突/句 2 拉近距/句 3 定调性；知乎（悬疑）→句 1 立冲突/句 2 拉近距（樟脑丸和雨水混在一起的霉味）/句 3 定调性（「别告诉女儿」）；每天读点故事（情感）→句 1 立冲突/句 2 拉近距（眼泪砸在手机屏幕上盖住四个字）/句 3 定调性（云很白像第一次约会）。
- 营销角度：每个平台都有完整范例，不只是公式描述，而是可直接模仿的成品。

## pop-short-plot-structurer

### 营销点 1：4 种结构模板 × 平台/题材匹配表
- 来源：`SKILL.md` / `steps/step1-select-template.md` / `references/structure-guide.md`
- 机制：4 种模板：知乎反转体（1-3 万字，第一人称 + 层层剥洋葱 + 结尾大反转）/ 番茄单元剧体（6000-15000 字，每单元一个完整爽点）/ 经典三幕式（全平台通用，建立日常→冲突升级→最终对决）/ 情绪爆发体（5000-8000 字，情绪线为主事件为副）。7 个平台×题材组合的推荐表，每个组合给出推荐模板 + 原因。
- 营销角度：不是通用结构模板，而是精确匹配平台×题材×卖点主轴，每个组合都有理由。解决「不知道用什么结构」的痛点。

### 营销点 2：剧情弧线 6 字段 + 免费/付费分段
- 来源：`steps/step2-arc-design.md`
- 机制：每段包含 6 个字段：本段功能 / 核心事件 / 信息释放（读者知道什么/不知道什么）/ 情绪走向（什么→什么）/ 付费钩子嵌入（标注 opening-designer 确定的付费钩子位置）/ 字数。免费/付费分段，每段功能不重复，信息释放递进。
- 营销角度：不只是画结构，而是精确到每段的信息释放策略和情绪走向，相当于给正文生成器一张「导航地图」。

### 营销点 3：剧情动作差异化规则（3 条通用规则）
- 来源：`steps/step2-arc-design.md`
- 机制：规则 1：相邻段落核心事件类型不得重复——任意两段如果核心事件属于同一类别，即使内容不同也视为重复。规则 2：收束段从最后情绪高峰到结尾的跨度控制——中间最多只能隔 1 个段落，收束段字数不超过逆转段的 90%。规则 3：反转/高潮工具的类型多样性——同一种「推进方式」超过 2 次必须换机制，分类 6 种（当众对质/私下摊牌/物证发现/第三方意外介入/角色自身认知变化/时间压力）。
- 营销角度：用可量化的规则保证剧情质量，避免「重复事件」和「拖沓收束」这两个常见短板。

### 营销点 4：角色 ≤5 个 + 配角功能 5 类
- 来源：`SKILL.md` / `steps/step3-character-design.md` / `references/character-card.md`
- 机制：短篇铁律：角色不超过 5 个有名有姓的。主角四维深度构建：欲望（Want）/ 软肋（Need）/ 执念/创伤（Wound）/ 反差（Contrast）。配角 5 种功能分类：对手/反派（必须有可理解动机）/ 镜像/对照（凸显主角成长）/ 信息源（不能只出场一次）/ 情感锚（代表正常世界）/ 催化剂（推动关键决定）。功能重复的配角必须合并。
- 营销角度：角色设计的量化约束（≤5 人）+ 5 种功能分类，确保每个角色都有不可替代的叙事价值。

### 营销点 5：角色密度合并检查规则
- 来源：`steps/step3-character-design.md`
- 机制：弧线表确认后、角色设计完成后逐段检查：每段弧线引入的新角色数量与全篇角色总数的比率。如果某段弧线引入 ≥2 个新角色→检查是否可提前出场或合并。全篇角色数超过上限时按优先级合并：①功能重叠的配角优先合并；②只出场 1 次的角色优先合并；③无独立台词的角色优先合并。合并后验证：每个角色至少碰撞主角的一个维度（渴望/软肋/底线/内在反差）。
- 营销角度：角色合并不是随意删减，而是有严格的优先级和验证标准，确保合并后的角色仍有功能价值。

### 营销点 6：骨架卡片 4 项完整性自检
- 来源：`steps/step4-output-card.md`
- 机制：输出骨架卡片后做 4 项自检：角色总数 ≤5 / 付费钩子与剧情弧线对齐 / 总字数在模板范围内 / 每段情绪走向有起伏。未通过项返回对应步骤修正后再落盘。
- 营销角度：自动生成前有自检门禁，确保交付物质量。解决「结构卡里藏了错误但没发现」的痛点。

### 营销点 7：红线——角色服务于剧情
- 来源：`SKILL.md`
- 机制：核心原则：短篇的核心是「情节节奏和情绪释放」，不是人物深度。逻辑链：「这个反转需要什么样的人设来撑？谁来承受这个情绪爆发效果最有力？」——角色是剧情的函数。红线 #1：角色不超过 5 个有名有姓的。红线 #2：不在人设上铺陈过多——每维度一句话。红线 #3：功能重复的配角必须合并。红线 #4：剧情弧线钩子位置必须与付费钩子策略对齐。红线 #5：骨架确定前不进入 body-generator。
- 营销角度：设计哲学是「剧情驱动而非人物驱动」，适合短篇场景。解决「角色太深导致篇幅被挤占」的痛点。

## pop-short-body-generator

### 营销点 1：5 种文风 + 平台默认匹配
- 来源：`SKILL.md` / `steps/step1-style-select.md` / `references/writing-styles.md`
- 机制：5 种文风：知性沉稳（知乎）/ 网感快节奏（番茄）/ 情感细腻（每天读点故事）/ 文学质感（豆瓣）/ 极速钩子（小程序/信息流）。每种文风含完整特征表（叙事视角/语言特点/节奏控制/情绪表达/钩子策略）、开头范例 3 种、句式节奏、关键写作法则。用户上传参考文本时，自动提取句长/对话比例/描写密度/特有词汇，覆盖平台默认推荐。
- 营销角度：不仅是平台默认文风，还支持用户自定义文风（上传参考文本），解决「平台默认文风不是我要的」的痛点。

### 营销点 2：逐段生成 + 自检清单（5 项）
- 来源：`steps/step2-generate-segment.md`
- 机制：逐段生成：生成前读蓝图（核心事件/信息释放策略/情绪走向/密度目标）→生成时标注段号/字数→持续引用前序设定（主角五维/配角标签/导语/黄金三句）→生成后自检 5 项：①推进了情节或深化了人物？②情绪密度达标？③没有偏离脑洞？④ AI 味儿？⑤角色一致？每段生成后停止，等待用户确认。
- 营销角度：逐段确认模式让作者全程掌控节奏，不是一次性生成完就扔给用户。

### 营销点 3：一键全文模式
- 来源：`steps/step2-generate-segment.md`
- 机制：两种模式：逐段确认（默认）→每段一次生成→一次自检→一次用户确认；一键全文→先生成全文→快速逐段自检→一次性展示→用户逐段反馈。一键全文后用户可在任何段说「第三段重写」「收束太弱」「付费钩子不够狠」，skill 翻回对应段重写，保持其他段不变。
- 营销角度：两种模式满足不同用户偏好——控制型 vs 效率型。

### 营销点 4：付费钩子段特殊处理 + 驱动力检查
- 来源：`steps/step3-pay-hook.md`
- 机制：识别所有付费钩子段，做策略对齐确认：①断点类型是否与 opening-designer 一致；②断点位置偏差是否在允许范围内（≤ ±3% 全文）；③断点处的信息缺口是否与设计一致。驱动力强度分三级：强（必须知道后续）/ 中（想知道但不急）/ 弱（可读可不读）。驱动力为中或弱时给出补强建议。
- 营销角度：付费钩子设计跨 skill 对齐校验，防止两个 skill 的设计脱节。解决「正文生成后发现钩子类型不对」的痛点。

### 营销点 5：去 AI 味儿 7 类痕迹识别
- 来源：`steps/step4-deai-check.md`
- 机制：7 类 AI 痕迹：①总结感（终于/从此/这一夜/或许/也许）；②模板句式（高频率跨作品通用描写模板）；③过度过渡（与此同时/紧接着/话音刚落/然而）；④抽象描写（没有可验证细节的情绪概括句）；⑤ AI 式对话（对话信息密度过高/多人物语言风格无差别）；⑥百科口吻（叙事中途突然切换为解释/定义/说明模式）；⑦全文总结句（「她终于明白/他感到/他意识到/她明白了」等内心独白标签）。全文扫描阈值：内心独白标签每 5000 字≤1 次；百科解释密度全文≤2 处；段落对称性（连续 3 段以上字数高度一致±20 字）。
- 营销角度：AI 去味儿不只是「感觉不像 AI」，而是有明确的 7 类症状 + 量化阈值 + 修改方向。解决「AI 味儿难判断」的痛点。

### 营销点 6：响应分级（3 级）
- 来源：`SKILL.md`
- 机制：3 级响应：①明确确认（「继续」「可以」「ok」「没问题」）→只输出下一段正文，不附带创作记录/钩子分析/自检清单；②微调请求（「改一下 XX」「这里不对」）→只输出改动段落 + 一句话说明；③新方向/新段落/首次生成→输出正文 + 关键钩子 + 创作记录要点（≤5 条）。单段重写仍走完整自检流程。
- 营销角度：智能响应分级——用户说「继续」就只给正文，不废话；微调只改改动的地方。解决「AI 回复太长太啰嗦」的痛点。

### 营销点 7：红线——只重写该段，其余保持不变
- 来源：`SKILL.md`
- 机制：红线 #6：用户要求改某一段正文，只重写该段，其余段落保持不变。红线 #7：单段重写时仍走完整自检流程。红线 #8：微调响应格式——只修改了 ≤5 句话时，响应仅输出改动段 + 一句说明，不输出钩子分析/创作记录/自检清单。
- 营销角度：保护用户逐段确认的投入——改一段不影响其他段，不会让用户「改一段白费」。

## pop-short-reviewer

### 营销点 1：9 维评分框架
- 来源：`SKILL.md`
- 机制：8 个评分维度 + 1 个 AI 味儿参考维度：钩子密度（对标弧线表密度标注）/ 节奏控制（对标弧线表「读者知道/不知道」列）/ 付费钩子（对标 opening-designer 策略）/ 角色塑造（对标主角五维+角色清单）/ 结局收束（对标弧线收束段设计）/ 文风适配（对标 writing-styles.md）/ 情绪张力（对标弧线情绪走向）/ 商业驱动（综合评估）/ AI 味儿（仅作参考，不纳入评分）。
- 营销角度：不只是「好/不好」的评价，而是 8 维逐项打分 + 对标前置卡片数据，每维都有明确的评分标准。

### 营销点 2：6 级等级 + 行动建议
- 来源：`SKILL.md`
- 机制：9.0-10 = 现象级（编辑抢着签）；8.0-8.9 = 爆款区（微调一两处就能投）；7.0-7.9 = 潜力带（底子对，修完能上 8）；6.0-6.9 = 过关线（能投但竞争激烈）；5.0-5.9 = 危险区（脑洞或执行有问题）；5.0 以下 = 别急着投（建议从脑洞或平台重新考虑）。
- 营销角度：等级体系直接关联「要不要投」的行动建议，作者看完就知道下一步该做什么。

### 营销点 3：对标差距模式（仿写场景）
- 来源：`steps/step2-diagnose.md`
- 机制：如果加载了拆文报告（来自 short-text-deconstructor），每个维度评分后追加「对标差距」列——当前作品与例文在该维度的分差。分差 ≥2.0 的维度标记为🔴，进入重点诊断。对标报告仅展示差距，不替代独立评分。
- 营销角度：内置「对标分析」模式，支持仿写场景下的差距分析。解决「不知道自己的作品和参考例文差在哪」的痛点。

### 营销点 4：审方法规——只诊断不修改
- 来源：`SKILL.md`
- 机制：红线 #1：只诊断不修改——不替用户直接改正文。红线 #2：每条诊断必须配建议方向，不能只说「XX 不行」。红线 #3： AI 味儿不纳入评分，仅作参考标注。红线 #4：分维诊断必须对标具体的前置卡片数据。
- 营销角度：设计哲学是「诊断不越界」，保持用户对作品的最终控制权。

### 营销点 5：子 agent 文件协作协议（方案 B）
- 来源：`SKILL.md`
- 机制：当由子 agent 运行时：①将诊断报告全文写入临时目录；②不返回报告全文，只返回结构化元数据（file/lines/bytes/head/tail）；③主 agent 校验：文件存在 + 字节数/行数匹配 + head/tail 匹配 → Move-Item 归位；④校验失败：主 agent 重新调用子 agent 重试。
- 营销角度：解决子 agent 环境下文件传输出的工程问题，确保产出不丢。

### 营销点 6：可选评审范围
- 来源：`steps/step1-load.md`
- 机制：默认全篇 9 维诊断。用户可指定：①只评审某几个维度（如「只看钩子和节奏」）；②只看某一段（如「只看付费钩子断点那段」）；③只看 AI 味儿。
- 营销角度：灵活度极高，可以只看「这一段」或「这一个维度」，支持精准诊断。

### 营销点 7：评审报告模板（6 区块）
- 来源：`templates/review-report.tpl.md` / `steps/step3-report.md`
- 机制：总览卡片（评分/等级/一句话总评）/ 亮点（2-3 条）/ 不足（1-3 条）/ 分维诊断（8 维一行摘要 + 问题维度详细展开）/ AI 味儿参考（仅作参考）/ 总结（综合评分/等级/结论/最强武器/最弱一环）。
- 营销角度：结构化输出，不只给评分，还给出「最强武器」和「最弱一环」的对比分析。

## pop-short-text-deconstructor

### 营销点 1：4 种拆解深度 + 步骤跳过逻辑
- 来源：`SKILL.md` / `steps/step0-choose-depth.md`
- 机制：4 种深度：①完整拆解（结构 + 角色 + 开篇 + 文风 + 评价）→ 全部步骤；②只学开篇（导语公式 + 黄金三句 + 付费钩子）→ 跳过 1/2/4/5；③学文风和句式（文风画像）→ 跳过 1/2/3/5；④参考题材和人设方向（结构分析 + 角色分析）→ 跳过 3/4/5。默认完整拆解。触发时暂停当前主线流程，拆完后恢复。
- 营销角度：灵活度极高，用户只需一句话「拆解这篇」，skill 问想学什么维度就输出什么。解决「只想学开篇不想学全篇」的痛点。

### 营销点 2：结构分析——平台判断 + 题材分类 + 模板匹配 + 弧线还原
- 来源：`steps/step1-structure.md`
- 机制：平台判断（4 个依据：人称/段落长度/付费钩子/开篇风格）→ 题材分类（6 大类）→ 结构模板匹配（6 种：反转剥洋葱体/单元爆破体/经典三幕式/情绪爆发体/双线螺旋嵌套体/单点爆破循环体）→ 弧线还原（和 plot-structurer 的弧线表格结构一致，可复用）。标注题材专属套路（追妻七步法/知乎冲突堆积法/终局锚点法/规则怪谈循环爆破法）。
- 营销角度：不只是「拆解结构」，而是还原出可复用的结构模板 + 弧线表格，为仿写直接复用。

### 营销点 3：角色分析——3 种主角公式
- 来源：`steps/step2-character.md`
- 机制：3 种主角公式判断：①公式 A（五维）：外在标签 + 内在反差 + 渴望 + 软肋 + 底线 + 小缺点；②公式 B（成长弧光）：初始缺陷→挫折→认知崩塌→行为改变→结局蜕变；③公式 C（3+1）：1 特点 +1 能力 +1 弱点 +1 象征物。按公式还原主角人设，配角标注叙事功能/出场节点/活人标签。
- 营销角度：不只说「这个主角有什么特点」，而是判断其使用了哪种公式，为后续创作提供可复用的人设模板。

### 营销点 4：开篇拆解——导语公式 + 黄金三句 + 付费钩子
- 来源：`steps/step3-opening.md`
- 机制：导语公式判断（6 种：悬念前置/情绪爆发/对话开头/身份共鸣/反转/画面切入）→ 黄金三句拆解（每句标注功能 + 原文引用）→ 付费钩子还原（位置/类型/断点内容）。输出格式对标 opening-designer 的导语分析框架。
- 营销角度：把例文开篇的「写法」逆向工程出来，不只是分析「写得好」，而是分析「为什么好」。

### 营销点 5：文风画像——6 维量化特征
- 来源：`steps/step4-style.md`
- 机制：6 个量化维度：平均句长（字数/句数）/ 段落长度（字数/段数）/ 对话占比（对话字数/总字数）/ 描写密度（描写段落字数/总字数，分高/中/低）/ 独有词汇/句式（高频特有词汇/句式模式/标点习惯）/ 情绪表达方式（直接陈述 vs 动作替代 vs 对话承载）。标注与 5 种标准文风的异同点。
- 营销角度：量化文风特征，不只是「感觉像」，而是可测量的数据。正文生成器可直接将此画像作为自定义文风选项。

### 营销点 6：影响后续 Steps 的映射表
- 来源：`SKILL.md` / `steps/step6-impact.md`
- 机制：拆解结论直接影响后续 6 个 Steps：Step1 平台定位→拆解出的平台=直接确认或强烈推荐；Step2 脑洞提炼→拆解出的题材→在该品类找变体/升级方向；Step3 开篇设计→拆解出的导语公式→推荐同类或展示不同公式作为对比；Step4 剧情结构→拆解出的弧线和角色→作为基础框架微调；Step5 正文生成→拆解出的文风画像→作为自定义文风选项；Step6 评审→拆解出的评价→作为例文 vs 作品各维度差距参照。
- 营销角度：拆文结论不只是「分析报告」，而是直接融入后续创作流程，每个环节都能受益。

### 营销点 7：红线——拆文不替代评审
- 来源：`SKILL.md`
- 机制：红线 #1：拆文不替代评审——例文评价是「样本分析」，评审是「诊断」。红线 #2：例文质量明显偏低时标注但不模仿。红线 #3：拆解结论应如实反映例文特征，不做过度美化。红线 #4：暂停主线流程时告知用户，拆完后恢复。
- 营销角度：明确区分「拆解分析」和「质量评审」的边界，避免用户误以为「这个例文好所以我必须模仿」。
