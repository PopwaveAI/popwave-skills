# 06 · 视频家族 · 营销点拉片

> 覆盖 skill：pop-video-brand / pop-video-comic（2 个，~26 文档）
> 定位：确定性视频渲染——HTML 动效时间线 + Playwright 逐帧 + ffmpeg 合成 + TTS 配音，全程不走 AI 视频，文字与 UI 精确可控。

---

## pop-video-brand

### 营销点 1：确定性渲染管线，不走 AI 视频
- 来源：`SKILL.md`
- 机制：品牌素材包（规范+截图+logo/吉祥物）→ 叙事脚本 → HTML 动效时间线 → Playwright 逐帧渲染 → ffmpeg 合成 H.264 MP4 → 火山 TTS 口播配音 + BGM 混音。全程 HTML 元素驱动，文字与 UI 精确可控，不依赖 Seedance/GenerateVideo 等 AI 视频生成。
- 营销角度：解决「AI 视频文字扭曲、版式失控、成本不可控」的痛点，定位为可审计、可复现、品牌合规的视频生产工具。

### 营销点 2：预览闸门机制，成片返工率大幅降低
- 来源：`SKILL.md`、`steps/step3-render.md`
- 机制：Step 3 先以 `--mode preview` 在关键时间点抓 8-12 张预览帧（如 0.5s/2.0s/3.5s/7.0s/9.6s/15.0s/22.0s/28.0s/30.0s），逐张 Read 审查构图、文案合规、元素重叠/溢出/错位。只有通过预览校验，才进入 `--mode full` 全量渲染。
- 营销角度：把「渲染后发现文案错位」的风险前置到草稿阶段，避免整片返工。

### 营销点 3：6 步素材驱动脚本创作法，94% 时间花在「想」
- 来源：`steps/step1-script.md`、`references/brand-video-method.md`
- 机制：提炼真相 → 立定立意 → 选择角度 → 铺设结构 → 逐镜写作（画面+口播+字幕）→ 闸门自检。核心信条是「先想清楚，再写分镜」，脚本不是素材模板填空，而是从素材反推用户痛点、证据点和差异化。
- 营销角度：不是「套模板出片」，而是「从素材里提炼品牌核心主张」，保证视频有明确叙事方向。

### 营销点 4：标准五场景结构，30-40s 片长可拆解
- 来源：`references/brand-video-method.md`
- 机制：开场 A（4-5s，建立共鸣）→ 产品核心 B（6-7s，亮主价值）→ 证据/闭环 C（6s，截图证明）→ 扩展差异 D（6s，拉开差距）→ 收尾 CTA E（6-8s，品牌+转化）。每场景只服务立意，不推进立意的功能位直接砍掉。
- 营销角度：解决「视频结构散、卖点不集中」的问题，给非专业用户一套可直接复用的片长结构。

### 营销点 5：口播≤30 字/句，TTS 知性灿灿 2.0 默认音色
- 来源：`steps/step1-script.md`、`steps/step5-tts.md`、`scripts/tts_generate.py`
- 机制：每个镜头三件套——画面、口播、字幕。口播承担叙事主线，要求口语化、像人说话，≤30 字/句；TTS 默认使用知性灿灿 2.0（`zh_female_cancan_uranus_bigtts`），基于火山语音「豆包语音合成大模型」，支持 `--speech-rate/--loudness-rate/--pitch-rate` 微调。
- 营销角度：解决「AI 配音机器感、口播像念说明书」的问题，让口播更像真实人在讲品牌故事。

### 营销点 6：Sky Bubble 品牌色板与文案口径速查
- 来源：`references/sky-bubble-palette.md`、`steps/step2-timeline.md`
- 机制：色板严格限定为 Sky Bubble CSS 变量：主蓝 `#2F64FF`、泡泡青 `#26D7E8`、波浪紫 `#7B59FF`、主墨 `#141824`、正文 `#343B4D`、画布白 `#FBFDFF`、线框 `#DCE8F2`。文案口径速查包含品牌定位、核心条、功能链、禁用对照，禁止自创配色或夸大文案。
- 营销角度：解决「产品视频撞脸、品牌识别不一致」的问题，把色板和文案口径直接锁进渲染管线。

### 营销点 7：一个价值点、3-4 张截图，信息过载门禁
- 来源：`SKILL.md`、`steps/step0-inventory.md`
- 机制：Step 0 盘素材时按「每支视频只讲一个价值点、最多 3-4 张界面图」铁律，圈定主价值点、截图清单、是否使用团队故事图。Tag 应服务于一个卖点，不把所有截图塞进一支片。
- 营销角度：解决「产品功能太多、视频讲不清楚」的问题，强制单支视频只讲一个核心价值点。

### 营销点 8：闸门自检，文字也能讲清一支视频
- 来源：`steps/step1-script.md`、`references/brand-video-method.md`
- 机制：写完脚本后，删掉所有画面描述和动效说明，只看字幕+口播稿件，逐条核对：开头 3 秒是否有钩子、每句是否推进立意、文案是否全部来自品牌口径、删掉品牌名后是否还像真人说话、收尾是否有明确 CTA。任一为否，回对应小节重写。
- 营销角度：用「仅看文字能否成立」检查视频脚本，避免分镜很漂亮但叙事空泛。

### 营销点 9：含 BGM 的可选配混音管线
- 来源：`steps/step6-mix.md`
- 机制：用 ffmpeg 将配音轨与可选 BGM 混入无音轨版视频。口播音量 1.0，BGM 音量 0.3-0.5 不压人声；BGM 做淡入淡出（开头 0.8s 淡入，结尾 2.5s 淡出）。若需精确对齐，可使用 `adelay`/`amix` 逐句定位，品宣口播通常整段铺在画面上即可。
- 营销角度：一支片子自带口播、BGM、音量比例、淡入淡出等参数，解决「配音视频嘴部听不清、BGM 喧宾夺主」的问题。

### 营销点 10：imageio-ffmpeg 完整二进制保障渲染稳定性
- 来源：`SKILL.md`、`steps/step4-encode.md`、`scripts/encode.py`
- 机制：使用 `imageio-ffmpeg` 自带的完整版 ffmpeg，含 libx264，能处理标准 PNG 输入并合成 H.264 MP4。系统精简版 ffmpeg 仅能处理 scale/fps 滤镜，不够用；encode 脚本默认输出 30fps、CRF 18、libx264、yuv420p、faststart。
- 营销角度：降低「ffmpeg 环境差异导致合成失败」的风险，保证从帧序列到 MP4 的成品稳定性。

### 营销点 11：视频成品预设 1920×1080、30fps、H.264 MP4
- 来源：`SKILL.md`、`steps/step4-encode.md`
- 机制：最终视频规格为 1920×1080、30fps、H.264 + yuv420p，并通过 `ffmpeg probe` 核对分辨率、时长、fps 与 H.264 编码；时长对不上时，说明 timeline 边界有误，需要回查 Step 2。
- 营销角度：不是随机导出截图视频，而是输出明确可交付的横版品宣视频 MP4。

### 营销点 12：火警排查标记：一个价值点、3-4 张截图、确定性渲染、先预览后出片
- 来源：`SKILL.md`
- 机制：铁律四连：品牌合规要求必须读品牌规范、色板严格用 Sky Bubble、文案用品牌口径；一支视频只讲一个价值点、最多 3-4 张截图；禁止 Seedance/GenerateVideo 等 AI 视频；Step 3 必须先抓预览帧再全量渲染。
- 营销角度：不是单点功能，而是从素材、脚本、动效、渲染、配音到混音的完整品宣质量控制体系。

## pop-video-comic

### 营销点 1：漫画转 PPT 放映式短视频，先脚本后出片
- 来源：`SKILL.md`、`steps/step2-script.md`
- 机制：漫画页（page1~N.png）+ `页面配置.json` → 模型读图自理解 → 口播脚本 → edge-tts 配音 → HTML+ffmpeg 合成。Step 2 产出 `口播脚本.md` 后必须停下来等老板确认，确认后才进 Step 3 配音与 Step 4 合成。
- 营销角度：解决「漫画改视频后方向跑偏、口播与画面错位」的问题，把脚本确认做成闸门。

### 营销点 2：读图为主、配置文字兜底，拦截页不断管
- 来源：`SKILL.md`、`steps/step1-understand.md`
- 机制：模型直接 Read 漫画页，产出每页画面白描、氛围标签、镜头感；若单页被安全审查拦截，则用 `页面配置.json` 该页文字锚点补全画面理解，并标注 `[读图被拦截，配置文字兜底]`，禁止因读图失败中断管线。
- 营销角度：解决「安全审查拦截导致漫画视频断片」的痛点，保证一页被拦也不影响整体出片。

### 营销点 3：每句口播绑定 page{N}，时长与字幕同步
- 来源：`SKILL.md`、`steps/step2-script.md`
- 机制：脚本中每句口播明确标注对应 `page{N}`，字段包括 `seq/page/text/emotion/est_sec`，估算时长按约 4-5 字/秒计算。这样后续配音、字幕和画面逐页对齐，避免口播与漫画页错位。
- 营销角度：解决「漫画转视频后字幕不同步、画面与旁白脱节」的问题，让每句口播都有明确画面对应。

### 营销点 4：免费 edge-tts 配音，无需 API Key
- 来源：`SKILL.md`、`steps/step3-tts.md`、`scripts/tts_generate.py`
- 机制：使用 edge-tts 按口播脚本逐句生成人声，支持 `zh-CN-YunxiNeural`（男声）、`zh-CN-XiaoxiaoNeural`（女声）等中文音色；脚本会解析口播句格式，并输出 `时长清单.json`，为后续视频合成提供每句时长。
- 营销角度：解决「配音需要额外开通 API Key 和充值」的门槛问题，降低漫画短视频批量生产门槛。

### 营销点 5：场景化 60 秒结构，钩子先行
- 来源：`steps/step2-script.md`
- 机制：脚本结构为：[钩子 0-5s] 开场 1-2 句，抓注意力（设问/悬念/反差）→ [展开 5-50s] 按页推进，每页对应 1-2 句口播，情绪线递进 → [收尾 50-60s] 钩子留白/悬念，引导追读。目标总时长约 60 秒，总字数约 240-300 字。
- 营销角度：不是随意切页，而是按短视频节奏设计钩子、展开和收尾，更适合短视频传播。

### 营销点 6：Ken Burns 推拉规则，静态图不再僵化
- 来源：`steps/step4-render.md`
- 机制：每帧从「起始缩放/位移」缓动到「结束缩放/位移」；竖屏图采用缓慢推近（zoom in）或平移（pan），避免静止画面；缩放范围控制在 1.0→1.15 以内，避免观感怪异。
- 营销角度：解决「漫画视频像幻灯片放映」的问题，让静态漫画页通过推拉产生节奏。

### 营销点 7：输出命名规范，成品版本化+final
- 来源：`SKILL.md`、`steps/step4-render.md`
- 机制：确认后视频命名 `第{N}章-v{版本}-final.mp4`；配音版为 `第{N}章-配音-v{版本}-final.mp4`。`preview/frames/audio/` 属于过程文件，不直接当成品；成品采用最终版本化命名，避免多版本混淆。
- 营销角度：解决「最终视频找不到、误删候选帧」的问题，让输出文件天然可追溯。

### 营销点 8：素材清单结构化，图片尺寸与文字锚点同屏准备
- 来源：`steps/step0-collect.md`
- 机制：Step 0 扫描漫画章目录，确认 `output/page1~N.png`、`页面配置.json`、`index.html`、OC/封面图等素材；读取 `页面配置.json` 提取每页文字锚点，并用 PIL 读取图片尺寸，记录到 `素材清单.md`。
- 营销角度：解决「漫画页和台词配置分散」的问题，把图片、文字锚点、封面、尺寸信息集中到素材清单中。

### 营销点 9：中文字体强制显式设置，避免字幕乱码
- 来源：`SKILL.md`、`steps/step4-render.md`
- 机制：视频合成时显式设置中文字体，可选 `Noto Sans CJK SC` / `WenQuanYi Micro Hei`，禁止默认字体。字幕叠加在图片下方或底部，不遮挡画面关键信息。
- 营销角度：解决「漫画字幕在不同系统或浏览器中显示异常」的问题，保证漫画短视频的中文可读性。

### 营销点 10：5 条铁律构成质量门禁
- 来源：`SKILL.md`
- 机制：先脚本后出片；读图为主、配置文字兜底；每句口播绑定具体页；视频合成走确定性渲染，不走 AI 视频；视频成品版本化+final。违反任意一项，都会导致口播方向跑偏、画面错位、成片不可追溯或成本不可控。
- 营销角度：不是单点「漫画转视频」，而是从素材、脚本、配音、渲染到落盘的质量门禁。
