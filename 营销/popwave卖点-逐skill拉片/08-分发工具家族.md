## pop-content-card

### 营销点 1：三层×三维度对齐，内容价值不衰减
- 来源：`SKILL.md`、`steps/step1-content.md`、`steps/step2-visual.md`
- 机制：内容方法论定义「三可」（可截图×可套用×可回看），信息架构通过 68 字段×8 项校验传导，视觉模板把数据转为 0.5 秒可感知的版式呈现。任何脱离三可的工程检查，如「字段数对但不可截图」，都视为不通过。
- 营销角度：解决「卡片字段齐全但读者不收藏」的问题，让每一层设计都服务于内容价值。

### 营销点 2：68 字段 JSON 模板，一一对应 HTML 母版
- 来源：`steps/step1-content.md`、`steps/step2-visual.md`
- 机制：桥段型 JSON 包含 60 个内容字段 + 8 个账号字段，字段名与 HTML 母版占位符 `{{...}}` 一一对应。生产后必须先校验字段完整性、非空、素材句三层、正误对照、名场面、封面钩子、结局、感官覆盖，任一不通过不得进入 Step 2。
- 营销角度：解决「手写 HTML 容易漏字段、渲染后出现残留占位符」的问题，用数据驱动模板填充。

### 营销点 3：四素材类型 × 四套 5 页结构，内容类型自带版式
- 来源：`SKILL.md`、`references/content-method.md`
- 机制：桥段型为封面→公式+素材句→正误对照→名场面→收束地图；字句型为封面→分类清单A→分类清单B→分类清单C→使用指南；人设型为封面→人设公式→素材句→正误对照→弧光+收束；写法型为封面→原理拆解→正误对照→实战示范→检查清单。
- 营销角度：用户只输入主题，系统自动匹配素材类型和 5 页结构，降低结构设计成本。

### 营销点 4：6 套锁死色板，切 body class 即可换风格
- 来源：`SKILL.md`、`steps/step2-visual.md`、`templates/html/master-template.html`
- 机制：默认 `theme-warm`，可选墨韵调、青碧调、赤金调、暮紫调、极夜调。用户通过切换 `<body>` 的 class 切换风格，禁止手改 `:root` 变量或内联写死颜色。
- 营销角度：解决「设计师手动调 CSS 导致色彩混乱」的问题，用风格池保证色彩一致性。

### 营销点 5：8 项自检门禁，内容质量可核验
- 来源：`steps/step1-content.md`、`references/content-method.md`
- 机制：字段完整性、字段非空（每个 value ≥5 字）、素材句三层（物件/动作+感官+情绪暗示）、正误对照差异（好例比坏例多一层细节）、名场面三要素（选择+代价+情绪反差）、封面钩子句、结局可套用、感官覆盖（≥3 种感官通道）。任一不通过，回 Step 1 补内容。
- 营销角度：解决「素材卡写出来空洞、读者不收藏」的问题，用结构化门禁保证内容质量。

### 营销点 6：素材句三层结构：物件/动作 + 感官细节 + 情绪暗示
- 来源：`references/content-method.md`
- 机制：每条好素材句包含三层：物件/动作（具象载体）+ 感官细节（让读者「看到」）+ 情绪暗示（不直说但读者「感觉到」）。坏例只有概念和直白情绪，好例通过具体物件、动作、感官传达情绪。
- 营销角度：解决「网文素材只会堆形容词」的问题，让素材句具备可截图、可套用价值。

### 营销点 7：正误对照标准，好例比坏例多一层细节
- 来源：`references/content-method.md`
- 机制：坏例停在概念，如「心跳好快，手都在发抖」；好例多一层具体到物件/动作的细节，如「指甲陷入掌心，疼意让她回过神来」「她没抬头，只是用余光确认他手上还戴着那枚素戒」。好例必须比坏例多一层具体细节。
- 营销角度：让读者通过对照直接学会写法，而不是只看到抽象评价。

### 营销点 8：1080×1920 竖版 5 页 HTML 长图，手机可读
- 来源：`SKILL.md`、`steps/step2-visual.md`、`references/visual-density.md`
- 机制：输出 1080×1920 竖版 HTML 长图，默认 5 页；通过浏览器打开后支持打印导出 PDF。视觉层要求手机缩略图能读出标题和主要素材词，内容不会因压到页脚而不可读。
- 营销角度：解决「图文内容在手机上难扫读」的问题，把素材卡做成适合移动端传播的长图结构。

### 营销点 9：单页占比 75%-85%，避免空页和贴底
- 来源：`steps/step2-visual.md`、`references/visual-density.md`
- 机制：每页主内容占比目标为 75%-85%；低于 70% 会显得「空」，高于 90% 容易贴底、压迫、手机不好读。处理顺序是先给问题页加单页 class，压缩问题页的模块间距、内边距、行高，不直接缩小全篇字号。
- 营销角度：解决「模板太密看不清、太空不显内容」的问题，用密度门禁保证阅读体验。

### 营销点 10：字号体系服务于手机阅读
- 来源：`references/visual-density.md`
- 机制：封面核心词 140-156px，页面主标题 56-58px，正文/素材句 28-30px，卡片小标题 26-27px，素材标签/微卡 21-22px，封面 kicker 36px。若用户说「小」，先增字号；若同时要密度，优先加厚模块和增加素材槽，而不是拆页。
- 营销角度：解决「小字密密麻麻、手机看不清」的问题，明确字号层级，确保移动端可读。

### 营销点 11：字句型 45-60 条短句，量大但每条独立可读
- 来源：`references/content-method.md`
- 机制：字句型 5 页结构，P2-P4 每页 15-20 条短句，总量 45-60 条；P5 改为使用指南。核心原则是「量大但每条必须独立可读」，每条都尽量做到可截图、可改写、可套用。
- 营销角度：解决「内容型素材卡看起来单薄」的问题，通过清单结构提升保存和回看价值。

### 营销点 12：封面钩子句公式：具体物件/动作 + 情绪张力
- 来源：`references/content-method.md`
- 机制：好封面钩子不是抽象题材名，而是「分手后重逢的每一步，都是旧账本上的标记」「她删了他所有联系方式，却记得他生日的天气预报」「他签下收购她父亲公司的协议，血滴在文件上」。公式为：具体物件/动作 + 情绪张力。
- 营销角度：解决「封面只有题材标签、读者不想点开」的问题，用具体意象制造点击欲。

### 营销点 13：模块复用，8 种模板模块对应不同「可」
- 来源：`references/visual-density.md`
- 机制：公式卡服务「可套用」，引用栈服务「可截图」，正误对照服务「可套用」，场景纸服务「可回看」，清单网格服务「可截图」，结局卡服务「可套用+可回看」，收尾卡服务「可回看」。模块不是装饰，而是读者行为路径。
- 营销角度：解决「模板只有好看没有功能」的问题，每个模块都绑定读者能截图、套用或回看的价值。

### 营销点 14：模板母版，不改结构不增模块
- 来源：`SKILL.md`、`steps/step2-visual.md`
- 机制：必须复制 `templates/html/master-template.html` 母版改槽位，禁止从空白写 HTML；禁止增删页面、不改 CSS、不加新模块；只能用 `{{...}}` 占位符替换内容。填充后必须检查无 `{{...}}` 残留、页脚安全区、密度达标。
- 营销角度：解决「每次手写模板导致结构漂移」的问题，用母版+占位符保证稳定出品。

## pop-recommend

### 营销点 1：三阶段价值扫描，100 章只精读 30-40 章
- 来源：`SKILL.md`
- 机制：Phase 1 骨架扫描：首章+每卷首尾+尾章约 15-20 章，产出 `structure-map.json`；Phase 2 锚点深读：highlight/controversy/character/relationship 章约 10-15 章，产出 `anchor-pool.json`+`evidence-ledger.json`；Phase 3 阅感采样：全书均匀采样 5-8 章，6 维度量化打分，产出 `reading-metrics.json`。禁止逐章摘要，只围绕价值锚点精读。
- 营销角度：解决「AI 读完整本书不现实、逐章摘要又太散」的问题，用抽样+锚点控制阅读成本。

### 营销点 2：证据链闭环，所有判断绑定 evidence_id
- 来源：`SKILL.md`、`steps/step2.md`
- 机制：每个 strength/controversy/character 必须引用证据台账，excerpt≥50 字。评审生成阶段从 `anchor-pool.json` 和 `evidence-ledger.json` 提取判断，禁止无证据的卖点或争议。
- 营销角度：解决「推书推荐空泛、没有原文依据」的问题，让每个推荐判断都能溯源到原文证据。

### 营销点 3：spoiler 三级控制，safe + mild 才可消费
- 来源：`SKILL.md`、`steps/step2.md`
- 机制：推书卡只服务新读者，所有判断只能消费 safe 或 mild 级别锚点。synopsis 只使用 safe 级别信息，不产生剧透；strength、character、controversy 中的 mild 内容必须做模糊化处理，去掉具体情节，保留趋势描述。major 级别内容禁止进入推荐判断。
- 营销角度：解决「推书推荐变成剧透」的问题，保证新读者不被关键情节剧透。

### 营销点 4：6 维量化评分 + 推荐区间
- 来源：`SKILL.md`、`steps/step2.md`、`templates/reading-metrics.tpl.json`
- 机制：6 维度包括 characters、plot、prose、relationships、world、pacing。从 `reading-metrics.json` 提取评分，计算 base_score（6 维均值），再根据 strengths≥3 且 controversies≤2 等条件计算 audience_bonus；最终输出 score_low/score_high、stars_low/stars_high、grade 和 verdict。
- 营销角度：解决「推书推荐太主观」的问题，用量化评分给读者一个可比较的判断框架。

### 营销点 5：9 页独立设计语言，每页都有独立视觉人格
- 来源：`steps/step3.md`、`references/recommend-layout-guide.md`
- 机制：P1 封面=Cinematic Poster 电影海报，暗色渐变底+超大衬线书名+金线引言+底部版权标签；P2 hook=Swiss Grid 瑞士极简；P3 synopsis=Magazine Editorial 杂志页；P4 characters=Profile Spread 人物特写；P5 chemistry=Infographic 信息图；P6 structure=Horizontal Timeline 时间线；P7 selling_points=Feature Showcase 黑底展示；P8 risks=Dashboard 仪表盘；P9 verdict=Back Cover 封底。
- 营销角度：解决「推书卡同质化严重」的问题，9 页不是重复排版，而是 9 种独立视觉范式。

### 营销点 6：5 种主题色板，按题材自动适配
- 来源：`references/recommend-layout-guide.md`
- 机制：文学/言情默认 literary-red，仙侠/玄幻用 ink-blue，都市/现实用 warm-paper，悬疑/科幻用 dark-modern，青春/校园用 diary-orange。主题色只控制色板，不改变页面排版。
- 营销角度：解决「推书卡视觉与题材不匹配」的问题，让不同题材自动获得合适的气质。

### 营销点 7：受众画像拒绝泛泛描述，必须具体到读者类型
- 来源：`SKILL.md`、`steps/step2.md`
- 机制：audience 字段必须输出 recommended 和 avoid，每条必须是具体读者画像。禁止泛泛的「喜欢 XX 的读者」，必须结合 strengths、controversies、reading_metrics 综合判断。
- 营销角度：解决「推荐人群太宽、读者不知道适不适合自己」的问题，把受众判断落到具体画像。

### 营销点 8：5 个 JSON 工作稿，评审唯一输出是 review.json
- 来源：`SKILL.md`、`steps/step2.md`、`templates/`
- 机制：Phase 1 产出 `structure-map.json`、`anchor-pool.json`、`evidence-ledger.json`、`reading-metrics.json` 等工作稿，Step 2 消费这些 JSON 合成 `review.json`。红线规定禁止生成 input+draft 两个重复 JSON，review.json 是唯一评审输出。
- 营销角度：解决「评审中间稿混乱、输出不一致」的问题，让最终推书判断只从唯一 JSON 生成。

### 营销点 9：5 个 JSON 模板，阶段产出自带结构
- 来源：`SKILL.md`、`templates/`
- 机制：`structure-map.tpl.json` 承载 metadata/positioning/structure/deep_read_candidates；`anchor-pool.tpl.json` 承载 anchor_id/type/title/judgement/mechanism/boundary/chapter_id/spoiler_level/evidence_ids；`reading-metrics.tpl.json` 承载 sampled_chapters/dimensions/reading_experience/warnings；`review.tpl.json` 承载最终推书评审结构。
- 营销角度：解决「AI 每次产出 JSON 格式不一致」的问题，用模板固化结构，便于下游评审和 HTML 渲染。

### 营销点 10：review.json 唯一输出，禁止双 JSON 重复
- 来源：`SKILL.md`、`steps/step2.md`
- 机制：红线要求 review.json 是唯一评审输出，禁止生成 input+draft 两个重复 JSON。评审生成后直接消费 review.json 进入 Step 3 HTML 渲染。
- 营销角度：解决「中间稿与最终稿分裂」的问题，减少人工校对和版本混乱。

### 营销点 11：HTML 模板自包含，双击浏览器打开
- 来源：`SKILL.md`、`steps/step3.md`
- 机制：Step 3 读取 `templates/recommend-card.tpl.html`，将 review.json 转为 `window.__BOOK_DATA__`，替换 `{{TITLE}}` 和 `{{REVIEW_DATA}}` 两个占位符，落盘为 `{书名}-读者推书-v1.html`。
- 营销角度：解决「HTML 文件依赖外部资源导致分享失效」的问题，输出可自包含、可打开的推书卡。

### 营销点 12：5 条红线构成强质量门禁
- 来源：`SKILL.md`
- 机制：读取协议用 `Get-Content -Encoding UTF8 -Raw`；禁止逐章摘要，必须用三阶段价值扫描；所有判断绑定 evidence_id；review.json 是唯一评审输出；Step 文件链式加载，禁止跳过。
- 营销角度：把「如何读小说、如何避免剧透、如何保证推荐有证据」固化为执行纪律。

## pop-research

### 营销点 1：四档位独立调研，pipeline 各阶段都有对应供给
- 来源：`SKILL.md`
- 机制：赛道定位调研由 pipeline Phase 0 自动触发，产出 `素材/赛道调研.md`，供给 seed 1d+plot 三源；decon-lite 在用户给出力量体系参考书时触发，产出 `素材/decon-lite-{书名}.md`，供给 plot 三源+seed 1d-0+world；采风针对 write 写作质感缺口，产出 `素材/知识沉淀/{主题}-采风.md`；三界框架为 seed/plot 深层需求服务。
- 营销角度：不是孤立工具，而是 pipeline 上游的独立调研能力，直接服务种子、剧情、世界和写作质感。

### 营销点 2：赛道定位调研四轮搜索，门禁门槛明确
- 来源：`SKILL.md`
- 机制：S2 四轮搜索包括：赛道格局（top5-8 核心卖点）、读者偏好（借鉴点+避雷点）、赛道演变（细分蓝海）、对标分析。S3 落盘 `素材/赛道调研.md`，S4 质量门禁要求 top≥5 本+借鉴≥3 条+避雷≥3 条+细分≥3 方向。
- 营销角度：解决「选题调研凭感觉、结论太浅」的问题，用四轮搜索和门禁保证赛道结论可落地。

### 营销点 3：decon-lite 九表拆解，表 1 必须拆到规则级
- 来源：`SKILL.md`
- 机制：表 1 力量体系结构拆到规则级：主养成线、子养成线、交叉规则、出处章节；表 2-5 覆盖节奏/情绪/人称/开篇；表 6 势力格局；表 7 金手指深度；表 8 世界危机引擎；表 9 动力引擎提取表，包括驱动逻辑、运转机制、代价结构、范式归类、合一性评估。质量门禁要求 9 表全完整。
- 营销角度：解决「参考书拆书只拆骨架、不拆规则」的问题，把设定和力量体系拆成可直接消费的工程级结构。

### 营销点 4：三界框架 17 维度，压力源不遗漏
- 来源：`references/三界框架SOP.md`
- 机制：社会界 6 维（权力结构、经济体系、法律制度、文化传统、阶层关系、组织势力）+ 自然界 6 维（地理环境、气候条件、资源分布、生态系统、疾病疫情、自然灾害）+ 超自然界 5 维（力量体系、规则禁忌、存在层级、超自然组织、超自然历史）。每个维度都有调研问题、调研方法、产出和压力源方向。
- 营销角度：解决「世界观调研漏维度、社会/自然/超自然压力混在一起」的问题，用三界框架系统化发现压力源。

### 营销点 5：压力源 6 字段转化，从调研到剧情压力
- 来源：`references/三界框架SOP.md`
- 机制：每个压力源包含 6 字段：来源界属、具体描述、显性表现、对主角的压力方式、可量化指标、交叉可能性。显性表现必须是读者能看到的场景，不能只是抽象描述；可量化指标用于衡量压力大小或紧迫程度。
- 营销角度：解决「调研是信息堆砌、剧情压力出不来」的问题，把资料直接转化成可驱动主角行动的压力源。

### 营销点 6：交叉困境 6 种类型，强调道德张力
- 来源：`references/三界框架SOP.md`
- 机制：同界内交叉 3 种：社会界内部、自然界内部、超自然界内部；跨界交叉 3 种：社会×自然、社会×超自然、自然×超自然。每个交叉困境必须含交叉类型、困境描述、道德张力、可衍生剧情线；质量红线要求交叉困境≥3 个，且至少 1 个跨界困境。
- 营销角度：解决「剧情冲突只是两个困难叠加」的问题，强制生成真正的两难选择。

### 营销点 7：退化预警机制，防止调研越来越浅
- 来源：`references/调研深度标准.md`
- 机制：连续 3 次同一界无需求 → 标记 `degradation_warning: true`；连续 3 次调研压力源数量=3（刚好及格线）→ 标记 `quality_decline: true`；连续 2 次调研交叉困境无跨界 → 标记 `cross_boundary_missing: true`。当触发预警时，强制重新审视无需求界，判断是真实无需求还是偷懒跳过。
- 营销角度：解决「pipeline 连续调研后质量滑坡」的问题，把退化风险提前标记出来。

### 营销点 8：3 轮搜索策略，广度-深度-交叉验证
- 来源：`references/调研深度标准.md`
- 机制：第 1 轮广度搜索，按三界框架维度逐个搜索，目标覆盖所有涉及维度；第 2 轮深度搜索，针对关键压力源深挖案例、流程步骤、数据数值；第 3 轮交叉验证，确认数据准确性、补充案例、搜索交叉困境素材。要求不少于 2 轮、不超过 3 轮。
- 营销角度：解决「调研只做表面搜索、不深挖案例」的问题，保证压力源和困境有具体支撑。

### 营销点 9：无需求处理不跳过，必须逐类说明理由
- 来源：`references/调研深度标准.md`、`references/三界框架SOP.md`
- 机制：某个调研维度被判定为无需求时，不能只写「不相关」，必须记录 `{界名} · {维度名}：无需求`，并写出具体理由。若理由不合格，如没有说明为什么不相关，会被退回。
- 营销角度：解决「调研中随便跳过维度、造成设定盲区」的问题，确保不涉及的界和维度也有明确说明。

### 营销点 10：深度等级 3 档，适配不同 pipeline 需求
- 来源：`references/调研深度标准.md`
- 机制：种子级供 seed，要求三界全量、涉及的所有界和所有维度，压力源≥5 个、交叉困境≥3 个且含 1 个跨界；场景级供 plot，要求单界深入、压力源≥3 个、交叉困境≥2 个；缺口级供 pop-novel，只补缺失信息，压力源≥1 个，交叉困境不强制。
- 营销角度：解决「调研深度一刀切」的问题，按种子、剧情、补缺不同场景调整覆盖范围。

### 营销点 11：内容标准强制要求案例、流程、数据
- 来源：`references/调研深度标准.md`
- 机制：每篇知识沉淀必须包含至少一项具体内容：具体案例（真实历史事件或同类作品案例）、流程步骤（机制运作的具体步骤）、数据数值（可量化指标）。纯抽象描述如「社会存在阶层压迫」不合格。
- 营销角度：解决「调研报告写得很像概念卡片」的问题，强制加入案例、步骤和数值，让调研能真正支撑创作。

### 营销点 12：4 个脚本分工明确，覆盖搜索、爬取、批量和标准化
- 来源：`scripts/` 目录及文件头部注释
- 机制：`download_novel.py` 是统一入口，覆盖搜索、测试、爬取、验证、交付；`crawl_novel.py` 负责章节列表页到逐章正文爬取；`batch_download.py` 从 book_list.json 批量下载；`download_text.py` 支持直接 TXT/ZIP 下载、本地文件导入、网页文本提取并标准化为 UTF-8 TXT。
- 营销角度：解决「工具脚本分散、用户不知道从哪个入口开始」的问题，提供统一下载入口，也保留批量和标准化能力。

- 来源：`steps/step-1-design.md`

- 来源：`steps/step-1-design.md`、`SKILL.md`

- 营销角度：解决「规则太多、重点被稀释」的问题，只保留真正会导致技能注册、执行或交付断裂的约束。

## tool-download-webnovel

### 营销点 1：三阶段 SOP，Phase 1 失败后强制进入 Phase 2
- 来源：`SKILL.md`
- 机制：Phase 1 脚本自动搜索，执行 `python3 scripts/download_novel.py`，根据 status 进入不同分支；status=error 时强制进入 Phase 2；Phase 2 至少尝试 3 组关键词：`{书名} {作者} 笔趣阁`、`{书名} txt 下载`、`{书名别名}`，找到章节列表页或直链后用 `--source-url` 传入脚本重新下载；Phase 3 验证 JSON status、warnings、preview 和 poor_quality 状态。
- 营销角度：解决「脚本搜不到就直接放弃」的问题，用 web 搜索兜底提升成功率。

### 营销点 2：三级质量状态，success/success_with_warnings/poor_quality
- 来源：`SKILL.md`、`scripts/download_novel.py`
- 机制：`success` + warnings=[] 直接交付；`success_with_warnings` 检查 warnings 内容，确认 preview 正文正确后交付；`poor_quality` 检查 contamination_found、chapters_missing、chapters_truncated，决定换源重下或 `--resume` 补爬。
- 营销角度：解决「下载完不知道质量如何」的问题，用三级状态让交付决策可执行。

### 营销点 3：内容污染检测，自动扫描尾部和跨书污染
- 来源：`SKILL.md`、`scripts/download_novel.py`
- 机制：下载后自动扫描内容污染并截断尾部垃圾；同时通过 FOREIGN_CONTENT_MARKERS 检测其他小说混入内容，例如「司马随生」「叶伤寒」「八歧大蛇」「比特币」「区块链」等与目标小说无关的内容。
- 营销角度：解决「下载下来的 TXT 夹杂广告、其他小说或无关内容」的问题，让交付文本更干净。

### 营销点 4：防盗占位符检测，chapters_truncated 自动统计
- 来源：`SKILL.md`、`scripts/download_novel.py`
- 机制：ANTILEECH_MARKERS 检测「正在手打中」「手打中」「请稍后刷新」「正在更新中」「内容正在加载」「请刷新页面」等防盗占位符，并统计 chapters_truncated。脚本输出 JSON 状态后，用户可以通过占位符数量判断章节是否被截断。
- 营销角度：解决「章节内容被反爬占位符截断、但用户不知道缺了多少」的问题，让缺失信息可量化。

### 营销点 5：章节连续性校验，chapters_missing 自动统计
- 来源：`SKILL.md`
- 机制：JSON 状态字段包含 chapters_missing，用于章节编号连续性检测缺失数。Phase 3 中如果 poor_quality 或章节缺失明显，可决定换源重下或 `--resume` 补爬。
- 营销角度：解决「下载完发现章节号断档、整本不完整」的问题，用连续性校验判断交付完整度。

### 营销点 6：默认排除付费墙正版网站，搜索安全门禁
- 来源：`SKILL.md`、`scripts/download_novel.py`
- 机制：默认排除起点/晋江/纵横等付费墙正版网站。PAYWALL_DOMAINS 包含 qidian.com、jjwxc.net、zongheng.com、17k.com、kanshu.com、zhulang.com 等 12+ 域名，避免搜索/爬取付费墙网站产生截断内容。
- 营销角度：解决「误搜付费墙网站，下载内容残缺还浪费算力」的问题，把合规与质量门禁内置到工具中。

### 营销点 7：反爬 User-Agent 轮换池，降低抓取失败
- 来源：`scripts/download_novel.py`
- 机制：USER_AGENTS 包含 5 个主流浏览器 UA，覆盖 Chrome/Windows、Chrome/Mac、Firefox/Linux 等常见环境；抓取时通过轮换 UA 降低被封禁概率。
- 营销角度：解决「网页抓取稳定性差、频繁触发人机验证」的问题，提高章节列表页和章节页获取成功率。

### 营销点 8：多策略下载，覆盖直链、列表页、TXT/ZIP 和网页提取
- 来源：`SKILL.md`、`scripts/` 文件头部注释
- 机制：统一入口支持：`python download_novel.py "书名"` 搜索下载；`--workers 16` 并发处理；`--source-url` 跳过搜索直接用 URL；`--direct` 用于直链 TXT/ZIP；`crawl_novel.py` 支持章节列表页爬取并提取正文；`download_text.py` 支持本地文件导入和网页文本提取。
- 营销角度：解决「不同网站格式不同、工具只能处理一种来源」的问题，覆盖直链、列表页、网页正文、本地文件等常见场景。

### 营销点 9：断点续爬，失败章节自动补抓
- 来源：`SKILL.md`
- 机制：JSON 状态字段包含 chapters_failed，HTTP 失败章节数可用于判断是否补抓；当 chapters_failed>0 时，使用 `--resume` 补爬。该机制让下载失败章节可以单独恢复，不重跑整本书。
- 营销角度：解决「整本书下载失败后必须从头再来」的问题，用断点续爬降低重试成本。

### 营销点 10：`--content-selector` 手动指定 CSS 选择器
- 来源：`SKILL.md`
- 机制：参数 `--content-selector` 可手动指定正文 CSS 选择器，用于非标准页面或章节正文结构异常的网页。脚本 `crawl_novel.py` 也提供 `--chapter-selector` 参数，用于指定章节链接选择器。
- 营销角度：解决「不同网站章节正文结构不同、自动选择器可能失效」的问题，给用户可控选择器。

### 营销点 11：9 个 JSON 状态字段，下载结果可追踪
- 来源：`SKILL.md`
- 机制：JSON 状态字段包括 status、chapters_crawled、chapters_failed、chapters_truncated、chapters_missing、contamination_found、paywall_warnings、warnings，覆盖成功、失败、防盗占位符、章节缺失、污染、付费墙警告和警告消息。
- 营销角度：解决「下载过程黑盒、交付时不知道发生了什么」的问题，用 JSON 状态让每本书的下载过程可审计。

### 营销点 12：6 个下载参数，控制搜索、直链、反转、限量和付费墙
- 来源：`SKILL.md`
- 机制：`--author` 用于作者名，辅助搜索和文件名；`--source-url` 跳过搜索直接用 URL；`--direct` 将源 URL 识别为直链 TXT/ZIP；`--reverse` 反转章节顺序；`--resume` 断点续爬；`--limit N` 只爬前 N 章用于测试；`--content-selector` 手动指定正文 CSS 选择器；`--include-paywall` 允许付费墙网站，默认排除。
- 营销角度：解决「下载参数复杂、用户不知道怎么用」的问题，把常用参数集中到工具入口中。
