# 拉片01 · 端到端产线：「选一个专家，把创作管线跑到底」

> 性质：原材料，非对外稿。沿「去AI味」样板颗粒度逐层挖机制。
> 依据：全量盘点 + 起点/番茄/短篇三线 pipeline 深读。（标注⏱=需补原文证据）

---

## 0. 一句话卖点

**popwave 不是"会聊天的 AI"，是"能出成品的 AI 产线"——从一句模糊想法，一路推进到能过审投稿的正文，中间每个节点都有明确下一步，不卡壳、不空档、不丢上下文。**

## 1. 用户痛点：通用 Chat-AI 在写网文时有 4 个致命断层

| 断层 | 表现 | 后果 |
|---|---|---|
| **连续性断层** | 聊完这一轮，下一轮 AI 忘了之前设定 | 人物/世界观前后打架 |
| **流程断层** | 只有"写"，没有"先立项→设定→剧情→写→审"的步骤 | 细节靠临场编，长线崩 |
| **标准断层** | 写出来不知道好不好 | 追读/过审没把握 |
| **衔接断层** | 产出是对话气泡，不是可管理文件 | 没法复盘/复用/继续 |

> 卖点本质：把"聊天"升级为**有状态、有流程、有标准、有文件**的工程。

## 2. 解决骨架：三线产线 + 阶段继承

popwave 实际落地了 3 条产线，各有定位：

| 产线 | 定位 | 阶段链 |
|---|---|---|
| **短篇**（short-*） | 从脑洞到可发，7 件套最齐 | 平台定位→脑洞→开篇→剧情→正文→评审 |
| **番茄长篇**（pop-fanqie-*） | 快节奏连载，高事件密度 | 种子→世界→角色→剧情→正文→审核 |
| **起点长篇**（pop-qidian-*） | 工程级长线，适合连载规划 | 立项→世界→角色→剧情→正文→审核 |

**机制小巧思（三线共性）**：
- **每阶段输出是"文件"不是"气泡"**——`立项PRD.md / 世界设定 / 角色库/剧情白描/正文chNNN.md / 状态快照`，文件即状态。
- **阶段层层继承**：下游只消费上游已产文件，不重复立设定 → 连续性与一致性从架构上保证。
- **pipeline 只路由不干活**：总控读状态→派给对应 skill，子 skill 各司其职 → 可插拔、可单独调用。

## 3. 端到端不空档的机制（逐阶段举证）

### 阶段① 立项/脑洞（点火）
- **短篇**：短路 platform-orientation 摸底 3 问→**只深度展开最适合的 1-2 个平台（不做跨平台通稿）**→定位卡。随后 idea-refiner 三路径（A有想法/B只有方向/C带例文）把模糊想法收紧成"一句话脑洞+热点参考"，检验 ≥2 项通过才进阶。
- **番茄/起点**：seed 走"七维摸底→市场调研→改编策略→双轨发散→结构化打磨"→直接产 **黄金首章 ch001 / `立项/01-立项PRD.md`**。
- 小巧思：**首章/立项直出**，不是攒一堆设定才开始——读者追读从开头起，作者开工就有抓手。

### 阶段② 设定/世界（立骨架）
- world：消费立项方向句 → 力量体系四层 + 动力引擎六组 + 7 维度因果链 → 11 最小闭环文件。
- **红线**：战斗 4 拍节奏（试探→对抗→转折→收尾），禁一击制胜；碾压型力量必有风险窗口/时限/副作用。
- 小巧思：设定不是摆设，是**可被剧情消费的设定库**——供 plot/write 取料。

### 阶段③ 角色（定人设）
- character：主角深度卡 + 金手指 + 按分幕批量塑造；**角色库是 write 的唯一角色源**。
- 小巧思：人设单点受控，跨章不跑偏（配合拉片05 漫画不崩脸的同一哲学）。

### 阶段④ 剧情白描（立骨再填肉）—— 50% 注意力所在
- 番茄 plot：本卷快照→分支剧情线→分幕设计；**幕内四段式（起承转合）+ 每幕 2-3 条分支线 + 场景表 6-10 场景/幕**。
- 起点 plot：主线 + 卷纲（幕功能位轴）+ 章锚点表；白描卡 150-250 字/章。
- 小巧思：**先白描定因果，再渲染**——避免"灵感硬挤写崩"，长线有结构兜底。

### 阶段⑤ 正文渲染（出成品）
- write：6 章型骨架 × 7 节拍 + 爽点引擎 + 笔触 DNA；落盘 `正文/chNNN.md`；短篇走逐段生成+自检。
- **2000-2500 字/章**，有篇幅把控；读近 3 段白描，不强读全卷（省算力 + 聚焦本章）。

### 阶段⑥ 审核（质检闸门）—— "能过审"的保障
- 起点 review：**三种模式**（formal 正式落地 / draft 临时判断 / trial 快速体感不落地）；前置必读正文+上一章白描卡+状态快照。
- 番茄/短篇 review：四步审核 / 9 维评分（钩子密度/节奏/付费钩子/角色/结局/文风/张力/商业/AI味）。
- 短篇 review 红线：**只诊断不修改、AI味仅参考不纳入评分、每条诊断必配建议**。

## 4. 连续性保障机制（"不丢上下文"的工程证据）

- **状态快照 + 剧情白描卡双文件**（review/write 间传递）——跨章连续性的"记忆体"。
- **状态机**（short-platform-orientation）：**全项目有且仅有 1 个 Step 为 🟡进行中**，状态仅"未开始/进行中/完成"3 态 → 永不重复、永不打架。
- **章锚点表 / 事件种子池**：把"要写什么"提前落表，write 不靠临场拍脑袋。

## 5. 可测量 / 门禁（"不是玄学"的工程严谨）

- 短篇评审给 **X.X/10 分 + 是否推荐提交**。
- 番茄 plot 结构要素硬约束：核心地点 ≤3、出场人物 ≤6、成长节点 ≥1、每幕 2-3 分支。
- start 计划 plot 快爽自检：战斗 1 场/3-5 章、冲突禁连 2 章零、成长 3 章滑窗 ≥1、钩子每幕 ≥2。

## 6. 对外话术种子（原材料）

- "别人让你跟 AI 聊着写，popwave 让你在一条产线上把一章写到位。"
- "从'我不知道写啥'到'这一章能过审'，中间每一步它都替你铺好了。"
- "设定、角色、剧情、正文、审核——备份在文件里，你的创作资产永远是自己的。"

## 7. 竞品差异锚

通用 Chat-AI = 气泡式对话（无状态、无流程、无标准）；popwave = **文件式产线 + 状态继承 + 质检闸门**，把"创作"沉淀为可持续推进的资产。
