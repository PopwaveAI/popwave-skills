# 拉片05 · 漫画跨章不崩脸：「人设一致性的工程保证」

> 性质：原材料，非对外稿。颗粒度对标「去AI味」样板。
> 依据：pop-visual-comic + art-bible + oc + asset + shared 深读。

---

## 0. 一句话卖点

**AI 生图最大的硬伤是"这一章主角长这样，下一章换张脸"。popwave 的漫画不是每页碰运气重画，而是先用「美术设定集唯一真源 + 双角度定妆图 + 冻结提示词 + 分层记忆」锁死角色长相，跨章、跨卷不崩脸。**

## 1. 用户痛点：AI 漫改的"崩脸综合症"

| 痛点 | 现象 |
|---|---|
| 脸崩 | 同一主角这章和上章不是一个人 |
| 画风飘 | 每章画风像不同作者 |
| 设定飞 | 服装/标志/势力徽记前后不一致 |
| 重画成本 | 每章全靠手调提示词对齐，费时费力 |

> 卖点本质：把"AI 生图的随机性"用**工程约束**摁住，让人设成为可复用的稳定资产。

## 2. 第一原理：一致性要从源头锁，不是每页临场救

- 每次都在单张图上"尽量保持"主角长相，是治标。**真正的一致性靠"先立真源，再让所有页都引用同源"。**

## 3. 核心机制①：美术设定集唯一真源（Art Bible）

- 上游 asset 从原文提取 **4 类视觉资产**（角色档案/场景资产表/视觉符号库/IP 视觉DNA）。
- style 定 **画风 DNA**（37 种可选）。
- art-bible 把两者 + 用户需求综合成 **八篇合一的 Art Bible**（画风/人物/场景/视觉符号/势力/地理/规则/一致性复现）。
- **小巧思**：Art Bible 是**唯一真源**，下游 cover/oc/comic **只消费不重建** → 一致性从源头保证，全 IP 不打架。

## 4. 核心机制②：双角度定妆图（正面/侧面锁脸）

- **双角度 OC 定妆图**：同一角色先出正/侧两个角度，把五官、发型、服装细节固定。
- **小巧思**：单角度定妆不可靠，双角度等于"立体锁脸"——给后续生图一个可对照的基准脸。

## 5. 核心机制③：冻结提示词（主/辅提示词锁风格）

- **冻结提示词**：把"人设 + 画风"固化为主提示词，每页生成都引用。
- **小巧思**：冻结 = 卡通图标转为直接可图，而非每次手写"同样的描述"——减少自由发挥导致的漂移。

## 6. 核心机制④：分层记忆机制（记忆四文件）

- 漫画跨章的"记忆"不是一次性，而是**分层**保存（记忆四文件）：
  - 人物记忆 / 画风记忆 / 场景记忆 / 设定记忆。
- **小巧思**：分层 = 不同变更 只更新对应层，不重写全局；支持**增量定妆**保人设——某层改动了，其它层不动。

## 7. 编排串起整个一致性

完整管线（pop-visual-comic / pipeline）：
初始化画风 + 双角度 OC → **导演卡定稿（含场景采摘）** → 生成审核 → 多格漫画页直出。
- **导演卡**：像是"分镜脚本 + 置景清单"，提前把每格拍什么、谁出场、什么景定好——减少临场随机。
- 生成审核：出图后校验是否忠实，不忠打回。

## 8. 配套：画风稳定性测试（comic-test）

- 对画风 DNA 做**三组固定内容测试（场景/角色/多格剧情）**→ 逐画风验证是否稳定执行 → **通过判定表**。
- **小巧思**：不凭单张图判断风格稳不稳，用固定内容测多张才定论——把"画风能不能用"变成可验收项。

## 9. 对外话术种子

- "你见过每章主角都换脸的 AI 漫画吗？popwave 先锁住这张脸，再画一百章都是同一个人。"
- "既有首发，背后是一套真源 + 定妆 + 冻结提示词 + 分层记忆的工程，不是运气的图。"
- "主角长相进过定妆，跨章跨卷不崩——这一张能一直用下去。"

## 10. 竞品差异锚

- 通用 AI 生图/文生图：每次独立出图，人设随机飘。
- popwave：**美术设定集唯一真源 + 双角度定妆 + 冻结提示词 + 分层记忆 + 导演卡 + 画风测试**——人设一致性是工程保证，不是碰运气。
